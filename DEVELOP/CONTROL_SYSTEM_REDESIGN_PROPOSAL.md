# 操縦系操作の再設計提案

## 0. この文書の位置づけ

本書は、戦闘ビューと軌道計画ビューの操作を、初見でも理解しやすく、同じ入力から同じ結果を予測
しやすい形へ再設計するための提案である。現行仕様を記録する `SPEC.md` ではなく、採用判断前の設計案
として扱う。

調査対象は、2026-08-15 時点の `src/game/input/`、`src/game/player/`、`src/game/camera/`、
`src/game/plan/`、HUD、`DEVELOP/SPEC.md` である。

## 1. 結論

標準操作には、**アシスト操縦**を採用するのがよい。

- プレイヤーは「どちらへ向きたいか」「どちらへ加速したいか」を入力する。
- 姿勢制御コンピュータが、その指令を実際の RCS トルクへ変換する。
- 機体の慣性、回転の遅れ、推力、燃料消費、損傷、軌道力学、弾道は現在の物理計算を維持する。
- 戦闘の基本操作は、右ドラッグによる照準、`WASD`+`Q/E` の並進、左クリックの射撃へ集約する。
- 押下時間や連打間隔で意味が変わる操作と、画面に現れない持続状態は標準操作から除く。
- 長時間・高精度の軌道変更は、マニューバノードと既存の動力飛行自動実行へ任せる。
- 現行の直接 RCS 操作は「上級操縦」として残せるが、初回導線と標準ヘルプからは分離する。

これにより、プレイヤーが最初に学ぶ循環は次の一つになる。

> 右ドラッグで向く → `WASD`+`Q/E` で動く → 左クリックで撃つ

ゲームの難しさは「入力装置の解読」ではなく、相対速度、射線、燃料、軌道変更の判断から生まれるべき
である。

## 2. 現状で混乱を生む要因

### 2.1 操作の総数より、状態と基準系の組み合わせが多い

現行の標準操作には、6方向並進、6方向回転、4段階出力、回転制動、微調整、進行方向ホールド、
姿勢リセット、視点追従、照準ズーム、推力ラッチ、ターゲット選択、時間加速がある。各操作を単独で
覚えても、次の状態の組み合わせによって同じキーの結果が変わる。

| 状態 | 結果へ与える影響 |
| --- | --- |
| 推力ラッチ | キーを離しても噴射が続くか |
| RCS 回転制動 | 回転入力を離した後に止まるか |
| 進行方向ホールド | 自動で機首が戻るか、手動回転で解除されるか |
| 微調整 | 同じ回転キーの効き方 |
| 並進出力4段 | 同じ並進キーの加速度 |
| 視点のRCS追従 | 機体を回したときに画面も回るか |
| 戦闘／マップ | `WASDQE` が噴射か Δv 編集か |
| 時間加速 | 入力が実行可能か、無視されるか |

問題はキー数だけではない。プレイヤーが「今どの状態か」を頭の中で掛け合わせないと、次の一手を
予測できないことにある。

### 2.2 短い入力に隠れた別の意味がある

並進キーは、通常は「押している間だけ噴射」だが、0.3秒以内の連打では「離しても噴射を続ける」に
変わる。解除方法も、再度の連打、逆方向入力、対になるキーの同時押し、操作不能状態への遷移と複数ある。

この方式には次の問題がある。

- 意図しない連打でも、継続噴射が始まる。
- キーを離すという自然な停止操作が効かない場合がある。
- ラッチを知らないプレイヤーには、不具合や入力取りこぼしに見える。
- タッチ、キーボードリピート、フレーム落ちをまたいで操作感を一致させにくい。
- 緊急停止を別途覚えなければならない。

基本操縦では、タップ速度によって指令の寿命を変えない方がよい。

### 2.3 視点と機体を別々に回す必要がある

現在は左ドラッグがカメラ、`I/K/J/L/U/O` が機体姿勢を担当する。射撃では、カメラで状況を見ながら、
別の6キーで機首を照準へ合わせる必要がある。さらに視点追従の ON/OFF によって、姿勢入力に対する
画面の動きまで変わる。

これは宇宙船らしい自由度を表現できる一方、初見のプレイヤーには「見たい方向」「撃ちたい方向」
「進みたい方向」が三つの別操作として現れる。まず動いて撃つ段階には負担が大きい。

### 2.4 操作説明と実装の間に不一致がある

現状は、プレイヤーが正しい説明へ到達しても混乱を解消できない箇所がある。

- `SPEC.md` 冒頭は並進をフレーム基準、`F` をターゲット基準切替として説明するが、現在の
  `PlayerThrottle` は機体座標系で推力を作り、`F` は進行方向姿勢リセットとして使う。
- `SPEC.md` は射撃を Space／左クリック、ゲーム内ヘルプは Space／右クリックと説明する。一方、現在の
  `PlayerFire` が直接読むのは射撃キーであり、マウスクリックは選択、カメラ、プロパティ表示へ配送される。
- ゲーム内ヘルプは38行あり、戦闘、マップ、タッチ、表示の説明が一枚に混在する。

仕様、表示、実装を一度に揃えない限り、キー配置だけを変更しても「予想可能」にはならない。

### 2.5 高度な機能が基本操作と同じ階層にある

ラジエーター左右、太陽電池パドル左右、第二ターゲット、カメラロール、カメラパン、計画軌道の座標系、
直接 RCS ロールは有用だが、「動いて撃つ」ための必須操作ではない。現在は基本操作と同じヘルプ、同じ
キーボード面へ並び、初見時に重要度を判別しにくい。

## 3. 設計目標と非目標

### 3.1 設計目標

1. キーを離せば、そのキーによる継続指令も終わる。
2. 入力の結果が、連打間隔や過去の隠れたトグルに依存しない。
3. 通常の戦闘では、画面、機首、操縦軸が同じ向きとして理解できる。
4. 入力を受け付けない場合は黙って無視せず、理由と回復方法を同じ場所に示す。
5. 戦闘と軌道計画は、見た目、ポインタの役割、操作説明を明確に分ける。
6. 初回プレイでは「向く、動く、撃つ」だけを教え、高度な機能は必要になった場面で示す。
7. タッチでも同じ操作概念を使い、キーボードを画面上に複製しない。

### 3.2 非目標

- 軌道力学、姿勢力学、燃料、損傷、弾道を簡略化しない。
- `W` を「軌道を上げる」のような結果指定にはしない。軌道変更の意味はノード計画で学ばせる。
- 機体を瞬時に回転・停止させない。アシストも実際の RCS 能力と燃料の範囲で働く。
- すべての機能へ一つの画面・一つの操作方式から到達させようとしない。
- 設定変更を前提にしない。最も理解しやすい方式を標準値にする。

## 4. 検討した三案

| 案 | 内容 | 長所 | 短所 | 判断 |
| --- | --- | --- | --- | --- |
| A. 現行整理 | キーを維持し、ヘルプと表示だけ整理 | 実装変更が小さい | 視点と姿勢の分離、隠れた状態が残る | 応急処置 |
| B. アシスト操縦 | 方向指令を姿勢制御が実 RCS へ変換 | 直感性と物理性を両立しやすい | カメラと姿勢制御の実装変更が必要 | **推奨** |
| C. 完全指示型 | 対象や軌道をクリックし、自動操縦だけで移動 | 最も簡単 | 手で飛ばして撃つ楽しさが薄れる | 標準には不採用 |

B案は、ゲームの物理を保ったまま、プレイヤーの担当を「各軸のトルク生成」から「操縦意図」へ一段
引き上げる。実在の宇宙機でも、操縦入力を飛行制御計算機がスラスター指令へ変換するため、世界観とも
矛盾しない。

## 5. 推奨する標準戦闘操作

### 5.1 一つの操縦フレーム

通常時は、カメラを機体後方へ追従させ、機体の左右・上下と画面の左右・上下を一致させる。ロールは
姿勢制御が動径方向を上として自動的に整える。動径方向と機首がほぼ平行になる特異姿勢では、軌道面法線を
代替の上方向に使う。

プレイヤーが一時的に周囲を見る場合だけ自由視点へ移り、自由視点を終えると操縦フレームへ滑らかに戻す。
自由視点中も並進軸は変えない。見る方向を変えたことで `A/D/Q/E` の意味が変わってはならない。

### 5.2 デスクトップの基本割り当て

| 入力 | 標準操作 | 規則 |
| --- | --- | --- |
| 右ドラッグ | 機首を向ける | ドラッグ量で目標姿勢を動かし、RCS が実姿勢を追従させる |
| `W` / `S` | 前進 / 後退 | 機体の機首方向 / 後方へ、押している間だけ加速 |
| `A` / `D` | 左 / 右へ並進 | 画面と一致する機体左右軸で、押している間だけ加速 |
| `Q` / `E` | 上 / 下へ並進 | 画面と一致する機体上下軸で、押している間だけ加速 |
| 左クリック / Space | 射撃 | 押している間だけ発射。キャンバス上でだけ反応 |
| Shift 長押し | 精密操作 | 並進出力と姿勢応答を一時的に20〜30%へ下げる。離すと必ず通常へ戻る |
| `F` | 進行方向へ向く | 目標姿勢を一度だけプログレードへ設定。持続ホールドにはしない |
| `T` | 照準付近をターゲット指定 | 指令照準に最も近い有効対象を第一ターゲットへ設定 |
| `Z` 長押し | 照準ズーム | 離すと通常画角へ戻る |
| 中ドラッグ | 一時自由視点 | 機体指令と独立して周囲を見る。離すと追従視点へ戻る |
| ホイール | 追従距離 | 現行の距離ズームを維持 |
| `R` | 装填 | 現行どおり |
| `M` | 軌道計画へ移る / 戻る | ビューと操作文脈を明示的に切り替える |
| `,` / `.` | 時間加速を下げる / 上げる | 画面上の時間操作も常設する |
| Esc | 最前面を閉じる / 一時停止メニュー | 現行のオーバーレイ規則を維持 |

最初のチュートリアルで教えるのは、右ドラッグ、`WASD`+`Q/E`、左クリック、Shift までとする。
`F`、`T`、`Z`、`R`、`M`、時間加速は、それぞれ必要になる場面で初めて案内する。

### 5.3 姿勢指令の振る舞い

右ドラッグは直接トルクを加えるのではなく、「到達したい姿勢」を更新する。

- ドラッグを止めると目標姿勢も止まり、機体はそこへ収束する。
- 入力を離した後も角速度が増え続けることはない。
- 収束速度は RCS 能力、慣性モーメント、燃料、損傷に従う。
- 目標姿勢と実際の機首は別マーカーで表示し、機体が追従中か故障で追従できないかを区別する。
- 手動ロールは標準操作から外し、必要なら上級操縦だけに置く。

これにより Dzhanibekov 効果を含む姿勢物理そのものは失われない。制御中の自機には安定化が働き、制御を
失った機体やデブリには従来どおり自由回転が現れる。

### 5.4 並進指令の振る舞い

- 並進は常に押している間だけ有効とし、ダブルタップ・ラッチ・全軸緊急停止を廃止する。
- 複数軸の同時入力は正規化し、斜め入力だけ総加速度が増えないようにする。
- 標準出力は艦種ごとに一つの「戦闘出力」として調整する。4段階の数字キーは標準操作から外す。
- 精密な接近は Shift 長押し、長時間の大きな軌道変更はマニューバ計画で行う。
- 実際の推力方向は現在の機体姿勢に従う。旋回中は、指令方向と実推力方向を短いベクトル表示で示す。
- キーを離したフレームで推力指令をゼロにする。噴射音とプルームも同じ状態を正本として同期する。

### 5.5 廃止または上級操縦へ移すもの

| 現行機能 | 標準操作での扱い | 理由 |
| --- | --- | --- |
| 並進ダブルタップラッチ | 廃止 | キーを離す＝停止を常に成立させる |
| 対キー同時押しの全軸緊急停止 | 廃止 | ラッチ廃止により不要 |
| RCS 回転制動トグル | 常時有効 | 通常操縦では角速度ゼロを暗黙の目標にする |
| 微調整トグル | Shift 長押し | 隠れた持続状態を一時入力へ変える |
| 進行方向ホールド | `F` の一回指令へ統合 | リセットとホールドの二概念を一つにする |
| 並進出力1〜4 | 艦種別の戦闘出力一つ | 状態を減らし、精密操作は Shift へ任せる |
| `I/K/J/L/U/O` の直接回転 | 上級操縦へ移動 | 標準では照準操作と姿勢操作を統合する |
| 視点追従 `G` | 標準は常時追従 | 見え方を変える持続状態をなくす |
| カメラロールキー | 標準から除外 | 自動ロール基準に統一する |
| 第二ターゲットの時間依存選択 | 標準戦闘から除外 | `T` の連打回数・間隔で役割を変えない |
| 展開物の数字キー | 機体図またはステータス操作へ移動 | 基本操縦と異なる保守操作であるため |

上級操縦では、現在の直接 RCS 回転、制動 OFF、手動ロール、出力段を残してよい。ただし設定画面で
「上級操縦: 直接 RCS」を明示的に選んだ場合だけ有効にし、標準ヘルプへ混在させない。

## 6. カメラとターゲット操作

### 6.1 戦闘ビュー

- 右ドラッグは機体の目標姿勢を操作し、カメラだけを回さない。
- 中ドラッグだけが一時自由視点を操作する。終了すると操縦フレームへ戻る。
- 永続的な「視点のRCS追従」切替は置かない。
- 左クリックはキャンバス上での射撃専用にする。HUD 上のクリックは発射へ伝播させない。
- `T` は指令照準に最も近い対象を第一ターゲットへ設定する。連打で第二ターゲットへ意味を変えない。
- ターゲット解除は TARGET パネルの明示ボタンで行う。撃破された対象は自動解除する。
- 戦闘中の詳細プロパティは TARGET パネルの「詳細」から開き、右クリックの役割を増やさない。

### 6.2 軌道計画ビュー

軌道計画ビューは地球儀・3Dエディタに近い規則へ統一する。

| 入力 | 操作 |
| --- | --- |
| 左クリック | 対象またはノードを選択。空の予測軌道ならノードを配置 |
| 左ドラッグ | 空域では視点回転、ノード／ハンドルでは対象を編集 |
| 中ドラッグ／二本指ドラッグ | パン |
| ホイール／ピンチ | ズーム |
| 右クリック／長押し | 対象のコンテキスト操作 |
| ダブルクリック／ダブルタップ | 対象へフォーカス |

ビュー上端に「軌道計画」と表示し、戦闘中の機体入力が停止していることを常に示す。ビュー切替時は、
押下中の射撃、並進、姿勢指令を必ず破棄する。

### 6.3 Δv 編集と計画実行

標準操作では `WASDQE` を Δv 編集へ流用しない。選択中ノードの3軸ハンドルと数値入力を正規の操作とする。
これにより、ビューが変わると同じ移動キーの物理的意味まで変わる問題を避ける。キー編集は上級ショート
カットとして残せるが、必須操作にはしない。

ノード選択中は、次の一方向の作業列を画面下へ出す。

> ノードを置く → Δv を調整 → 自動実行を予約 → ノードへ時間加速 → 姿勢変更 → 点火 → 完了

既存の `PlanExecutor` は、姿勢変更、点火待ち、燃焼、微調整まで既に扱える。この機能を右クリックの
プロパティ項目に埋めず、計画パネルの主要操作「自動実行を予約」として表へ出す。`instant` は
CREATIVE／デバッグ用途として別枠へ分離する。

実行状態は `予約`、`姿勢変更`、`点火待ち`、`燃焼`、`微調整`、`完了／中断理由`のいずれかを常時表示する。
手動入力が自動実行を中断するときは、入力前に状態を消すだけでなく「手動操作により自動実行を中断」と
中央付近へ短く表示する。

## 7. 時間加速時の安全規則

現在のように、操作不能な倍率で入力を黙って無効化すると、故障と区別できない。標準操作では次の規則へ
統一する。

1. 戦闘ビューで並進、姿勢、射撃を入力したら、時間加速を即座に等倍へ戻す。
2. 同じ押下を等倍になったフレームから有効にし、押し直しを要求しない。
3. 等倍へ戻るときは、短い音と `時間加速解除 — 操縦入力` を一度だけ表示する。
4. 軌道計画ビューの編集入力は時間加速を解除しない。編集は実機指令ではないためである。
5. ビュー切替、操作対象変更、ポーズ、ウィンドウの入力ゲートでは全ての一時指令を破棄する。

この規則により「入力したのに何も起きない」と「ワープを下げたら過去の入力が突然再開する」の両方を
防げる。

## 8. タッチ操作

キーボードの12方向ボタンをそのまま並べず、同じ操縦意図をタッチ向けの形へ変換する。

- 左スティック: 画面基準の左右・上下並進。
- 左側の前進／後退ボタン: 機首方向・後方への並進。
- 右スティック: 目標姿勢の変更。離すと現在の目標姿勢を保持する。
- FIRE: 押している間だけ射撃。
- 精密: 押している間だけ精密操作。
- TARGET: 指令照準に近い対象を指定。
- ZOOM: 押している間だけ照準ズーム。

これで、現行の並進6ボタン＋回転6ボタンを、2スティック＋用途の明確なボタンへ置き換えられる。
ラッチやタップ回数による第二動作は使わない。軌道計画中は戦闘スティックを隠し、計画用のハンドルと
下部作業列だけを表示する。

## 9. 画面フィードバックと学習導線

### 9.1 入力結果を中央で確認できるようにする

戦闘画面中央には、常に次の最小限の情報を置く。

- 薄灰: 現在の機首方向。
- オレンジ: 指令した目標姿勢。追従中だけ表示する。
- 短い6方向インジケーター: 現在入力中の並進方向だけを点灯する。
- `精密`、`燃料なし`、`RCS損傷`、`時間加速中`など、操作結果を変える状態だけを状態語として表示する。

色は `UI_DESIGN_REFERENCE_V6.md` の規則に従い、通常状態をモノトーン、現在の指令を Accent、完了を
Secondary accent とする。常時すべてを発光させない。

### 9.2 ヘルプを文脈別に分ける

38行の一枚表を廃止し、次の3面へ分ける。

1. **戦闘の基本**: 向く、動く、撃つ、精密操作、ターゲット。
2. **軌道計画**: 視点、ノード配置、Δv、実行予約、時間加速。
3. **上級・機体管理**: 直接 RCS、展開物、座標系、診断。

通常の `H` では現在のビューに対応する面だけを開く。別の面はタブから選べるが、自動的に混在させない。

### 9.3 初回チュートリアル

文章を先に読ませず、入力と結果を一つずつ体験させる。

1. 右ドラッグで白い姿勢目標へ機首を合わせる。
2. `W` で100m先のゲートへ近づき、離して噴射が止まることを確認する。
3. `A/D/Q/E` でゲート中心へ微修正する。
4. 左クリックで静止標的を撃つ。
5. `T` で移動標的を指定し、LEADへ射撃する。
6. 別の短い章で、ノードを一つ置いて自動実行する。

成功するまで次の操作説明を出さない。完了済み説明は縮小し、プレイ画面を覆わない。

## 10. 実装上の責務案

入力イベントから物理量までを一つのクラスで解釈せず、次の境界に分ける。

```text
キーボード／マウス／タッチ
          ↓
      Input（生入力）
          ↓
CombatPilotInput（現在のビューに対応する操縦意図）
          ↓
 PilotCommand（並進軸・目標姿勢・精密・射撃）
       ↙       ↘
FlightAssist   CombatCamera
     ↓
実推力・実トルク → 既存の姿勢／軌道物理
```

- `Input` は押下、ポインタ差分、クリックを収集するだけにする。
- `CombatPilotInput` は標準／上級の割り当てと、戦闘ビューであることを解釈する。
- `PilotCommand` はそのフレームの一時的な指令で、ビュー切替時に残らない。
- `FlightAssist` は目標姿勢から実 RCS トルクを作る。燃料と能力を迂回しない。
- `PlayerThrottle` は、ダブルタップなどの入力ジェスチャではなく、推力生成と燃料消費へ責務を絞る。
- `CombatCamera` は実姿勢と一時自由視点を表示するが、機体指令の正本を持たない。
- キー表示、ヘルプ、チュートリアルは同じ操作定義からラベルを得て、手書きの対応表を複製しない。

上級操縦を残す場合も、別の `PilotCommand` 生成器として実装し、物理処理を二重化しない。

## 11. 段階的な導入案

### Phase 0 — 正本の一致と観察

- 実装、`SPEC.md`、ゲーム内ヘルプの不一致を解消する。
- 現行方式で、誤ラッチ、意図しない回転、ヘルプ表示回数、操作不能ワープ中の入力を観察する。
- 新旧方式を比較できる開発用切替を用意する。

この段階は挙動を変えず、比較の基準を作る。

### Phase 1 — 予測不能な状態の除去

- 並進ラッチと緊急停止を削除する。
- RCS 制動を標準では常時有効にする。
- 微調整を Shift 長押しへ変える。
- ビュー切替、操作対象変更、入力ゲートで一時指令を必ず消す。
- 時間加速中の操縦入力で等倍へ戻す。
- ヘルプを戦闘／計画／上級へ分割する。

これは、アシスト姿勢が未完成でも先に投入できる最小改善である。

### Phase 2 — アシスト操縦の縦切り実装

- 右ドラッグ → 目標姿勢 → RCS トルク → 実姿勢 → 追従カメラを一つの流れで実装する。
- 左クリック射撃、中ドラッグ自由視点、`T` の単一ターゲット選定を同時に揃える。
- `I/K/J/L/U/O`、`G`、RCS制動トグル、進行方向ホールドを標準ヘルプから外す。
- 指令姿勢と実機首、入力中の並進方向を HUD へ出す。

カメラだけ、姿勢だけを先に切り替えると一時的にさらに分かりにくくなるため、この段階は一つの縦切りで
導入する。

### Phase 3 — 軌道計画の作業列化

- `WASDQE` の Δv 編集を標準操作から外す。
- ノードハンドルと数値入力を主要操作にする。
- 既存の動力飛行自動実行を「自動実行を予約」として計画パネルへ出す。
- 実行フェーズと中断理由を常時表示する。

### Phase 4 — タッチと上級操縦

- タッチを2スティック方式へ置き換える。
- 上級操縦を設定から選べるようにし、現行ユーザーの移行経路を確保する。
- 必要ならゲームパッドを同じ `PilotCommand` へ接続する。
- 保存データの旧トグル値は上級操縦でだけ復元し、標準操縦では無視する。

## 12. 評価方法と受け入れ基準

8〜12人の未経験者に、説明を読ませず次の課題を順番に行ってもらう。

1. 100m先のゲートへ移動して停止する。
2. 静止標的へ機首を向けて発射する。
3. 横移動しながら移動標的へ射撃する。
4. 進行方向へ姿勢を戻す。
5. マニューバノードを一つ作り、自動実行を予約する。

記録するのは完了時間、誤入力数、ヘルプを開いた回数、「なぜ動いている／回っているか分からない」と
発言した回数である。標準操作の受け入れ基準を次とする。

- 課題1〜2を80%以上の参加者が、ヘルプなし・各60秒以内で完了する。
- キーを離した後の意図しない継続噴射は0件。
- 通常状態の自機で姿勢入力を止めた後、角速度が増え続ける事例は0件。
- 課題3までに必要な操作を、5分後に80%以上の参加者が再現できる。
- 戦闘入力が無効な理由を、表示から全員が特定できる。
- マップでの Δv 編集後、どの軸をどちらへ変えたかを80%以上が説明できる。

既存方式に慣れた参加者も別群で確認し、上級操縦への切替、セーブ復元、主要機能への到達不能がないことを
検証する。

## 13. 先に行う最小改善

全面改修へ入る前でも、次の6項目は効果が高く、設計の後戻りが少ない。

1. 並進ダブルタップラッチを廃止する。
2. 標準では RCS 制動を常時 ON にする。
3. 微調整をトグルから Shift 長押しへ変える。
4. ビュー切替と時間加速時の指令クリア規則を一本化する。
5. `SPEC.md`、実装、ゲーム内ヘルプの射撃・座標系・`F` の説明を一致させる。
6. ヘルプを現在のビューに必要な操作だけへ分割する。

この最小改善だけでも「離したのに動く」「同じキーなのに前回と違う」「説明どおりに動かない」という
三つの大きな混乱を先に除去できる。その後にアシスト操縦を導入すれば、改善効果を段階ごとに測定できる。
