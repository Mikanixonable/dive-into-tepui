# DEVELOP/ — 仕様と規約の一次情報

**コードの現状はコードだけが語る。** ここに置くのは、コードからは読み取れないもの — 「どう振舞う
べきか」(仕様)と「どう書くべきか」(規約)だけである。コードを追認するだけの文書は置かない。

| 文書 | 何が書いてあるか | 対応する問い |
| --- | --- | --- |
| [SPEC/](SPEC/) | ゲームがどう振舞うべきか(分野別) | 「本来どうあるべきなのか」 |
| [CODING-RULE.md](CODING-RULE.md) | 設計方針・命名規則・コメント規約・テスト | 「何と名付け、どう書くのか」 |

## SPEC/ の位置づけ

- SPEC/ は **確定した意図** を書く。**常にコードより先行していなければならない** — 新機能は
  SPEC/ を更新してからコードを書く(手順は `/modify-feature`)。
- 未確定のもの・構想段階のものは SPEC/ に書かない。
- 古くなった記述は歴史的経緯を残さず削除・更新する。「以前は」「旧」の類を残さない。

## コードの構造を知りたいとき

保持関係(誰が何を持っているか)と per-frame の呼び出し順は、文書としては保存していない。
必要になった時点でコードから調べる:

- `/ownership` — インスタンスの保持関係と状態の正本
- `/callstack` — per-frame の呼び出し依存木
- `/overview` — 全体像の掴み方(どこから読み始めるか)

## その他

  なければ読むだけ)。
