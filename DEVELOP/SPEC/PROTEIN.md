# タンパク質型の敵

タンパク質型の敵は、実在する立体構造をもとにした表示と、機能部位を個別に破壊できる戦闘状態を持つ。
構造の微細な揺らぎは表示上の生命感を与えるが、ゲームの軌道・衝突・命中判定を変更しない。

## 出現

- タンパク質型の敵は、実体化の準備が整うまで出現を遅らせてよい。これは通常の出現(COMBAT.md
  「敵の波状攻撃」)でもセーブ復元(SAVE.md)でも同様である。
- 準備が整っていない間、その敵は戦闘・衝突判定・残存機カウントのいずれにも存在しない。準備が
  整い次第、実体化する。
- 実体化に要るデータの取得は、**その体を選べる画面が開いた時点で始める。** 起動時にまとめて
  取りに行くことはしない — どの体を使うかはステージによって決まり、その周回で使わない体の取得が
  起動そのものを遅らせてはならない。
- 遅延はプレイヤーの操作性を損なわない範囲に収まらなければならない — 選んでから置くまでの間に
  取得が済むことを想定し、戦闘の最中に不自然な間が空いてはならない。

## 表示

- タンパク質型の敵の名前は、そのタンパク質固有の名称(例: ルビスコ、ATPシンテターゼ)を冠する。
  陣形内での役割・識別番号などの既存の識別要素は、この固有名称に付け足す形で残してよい。
- リボンは Cα 主鎖を N 末端から C 末端へ辿る。鎖が変わる箇所と、隣接する Cα が 8 Å を超えて離れる
  座標欠損だけで切断し、αヘリックス・βストランド・coil の境界では中心線を連続させる。
- αヘリックスは幅 2.0 Å、厚さ 0.4 Å の扁平な oval、βストランドは幅 2.0 Å、厚さ 0.4 Å の
  rectangle、coil は直径 0.4 Å の円形 rope とする。βストランドの C 末端側は最後の2残基で最大2倍へ
  広がって矢印へ収束する。N 末端側とαヘリックスには矢印を付けない。
- リボン断面の幅方向はカルボニル酸素の方向を優先して鎖全体で連続に定め、退化した箇所では鎖に沿って
  平行移動する。**隣接する断面が180°反転してはならない。**
- リボンの表面は滑らかな陰影の、金属的でないマットな材質とする。
- 分子表面は、半径 1.4 Å の溶媒分子が入り込めない領域の境界とする。穴・裏返り・自己交差の無い
  閉じた面として見えなければならない。
- 表面の色は Chain(鎖別)、B-factor、rainbow、二次構造、Component(構成要素の役割別)から選べる。
  分子模型は元素色、シルエットは表面の電荷または疎水性を使う。
  - Chain の鎖別色は ColorBrewer Set2 の8色を使う。1文字の鎖 ID はアルファベット順に割り当てて
    9鎖目から循環し、それ以外の ID は同じ ID が常に同じ色になるよう割り当てる。リガンドは
    元素別の色を保つ。
  - Component は構成要素(chains・entities をまとめた生物学的な役割)ごとに色を定める。役割の
    数によらず、隣接する役割同士の色が近づいて見分けにくくなってはならない。
  - 新しく生成するタンパク質は、リボン表示と Chain の鎖別色を既定とする。保存済みの着色選択は
    そのまま復元し、着色情報を持たない・または現行の選択肢にない保存データは鎖別着色として
    復元する。
- 表示形態を変えても、衝突形状は静止したリボン形状を使い続ける。表示用の表面、原子、リボンの微細な
  変位は衝突・命中判定へ反映しない。

## 構造の揺らぎ

- 揺らぎは構造データから求めた低周波の集団運動と残基単位の局所運動を重ね合わせる。
- 残基単位の変位は Cα の弾性ネットワークと B-factor 由来の RMSF を根拠にする。ヘリックス・シートの
  剛性の高い領域より、ループ・末端の変位が大きく見える。
- **同じ敵は、いつ見ても同じように揺らぐ。** 揺らぎは敵と表示時刻だけから決まり、フレームレート・
  時間加速・巻き戻しの履歴に依存しない。
- 遠くの敵ほど揺らぎは粗くてよいが、**粗さの切り替わりが目に見えてはならない** — 境目で往復せず、
  切り替わった瞬間に形が飛ばない。近距離での構造の読み取りを損なわない。
- 同じ残基の変位は原子、結合、リボン、表面へ対応付ける。部位の発射位置も対応する残基の平均変位に
  追従する。
- 敵の integrity、軌道、衝突形状、弾の命中判定は揺らぎから独立している。
- 揺らぎの表示は描画設定でオン/オフを切り替えられる([RENDERING.md](RENDERING.md) 参照)。オフの間は
  静止した構造で表示し、integrity・軌道・衝突形状・命中判定への影響はオンのときと変わらない。
- integrity が critical フェーズへ入ったときは、表示上の揺らぎだけを増幅する。物理的な振幅や衝突形状を
  増幅してはならない。

## 戦闘状態

- タンパク質敵は、構造全体の integrity と、複数の機能部位の HP を持つ。
- 各機能部位は、結合界面・核心部・修飾部位といった種別ではなく、残基番号やドメイン名など、その
  タンパク質の実際の構造に基づく生物学的な名称を持つ。
- 各機能部位は、生物学的な名称とは別に、HUD表示専用の一意な英語略号を持つ。略号もフルネームと
  同様、実際の構造に基づく(例: 残基番号を用いた `His93` 形式)。
- 機能部位は独立して損傷・無効化できる。無効化した攻撃部位は発射元の候補から外れ、残った機能部位が
  順番に攻撃を担当する。
- 部位への命中は部位の HP と構造全体の integrity の双方へ影響する。部位に依存しない命中と接触は
  integrity だけへ影響する。
- 構造全体の integrity が尽きたら撃破する。部位の破壊だけでは撃破としない。
- phase は `intact`、`exposed`、`dissociated`、`critical` のいずれかである。結合界面の無効化で
  exposed、結合界面と全攻撃部位の無効化で dissociated、核心部の無効化または integrity 25% 以下で
  critical へ遷移する。critical は表示揺らぎの増幅と構造状態の表示へ反映する。
- integrity が 65% 未満になった場合、修飾スロットは空状態になる。修飾状態は攻撃ダメージなどの効果へ
  反映される。
- integrity、部位 HP、phase、修飾状態はセーブ／ロードで保持する。旧形式の全体 health しかないデータは
  integrity の初期値へ変換する。

## 未確定の案

**決定事項ではない。** 「どの拡張性を残すべきか」を判断するための材料。

- ATP合成酵素型の120°ステップ回転、キネシン型の歩行、ヘモグロビン型のアロステリック開閉を攻撃機構へ
  使う。実在の周期はゲームの秒スケールへ圧縮する。
- B-factor から求めた RMSF の大きいループを被弾しやすくし、ダメージ倍率を高くする。
- 部位命中時の integrity への部分ダメージを廃止し、部位破壊の順序戦略を強める。維持する場合は、部位と
  integrity の二層を併用する理由を別途確定する。
