# RENDERING — 描画

画面に何を、どの順で、どのくらいの精度で描くかの仕様。HUD/UI 側のデザイン規約は [UI-DESIGN.md](UI-DESIGN.md)。

## 描画パイプライン

1フレームの描画は5段階を順に経て画面へ出る。

1. **Gバッファパス**: 光を受ける不透明な物体(自機・敵機・デブリ・薬莢などの標準的な艦艇メッシュ)
   についてのみ、深度・法線・粗さを書き出す。
2. **ライティングパス**: Gバッファの法線・粗さ・深度と太陽の方向・強さから、拡散反射光と鏡面反射光の
   強さを計算して書き出す。値は1を超えうる(HDR)。
3. **マテリアルパス**: ライティングパスが出した拡散反射光・鏡面反射光に、物体自身の色(アルベド)・
   金属度・反射率を掛け合わせて最終的な陰影を求め、共有の描画先へ書き込む(このパスが最初に
   その描画先をクリアする)。
4. **ワールドパス**: 天体・軌道線/軌跡線・ビルボード(噴射炎・RCS 噴射・フラッシュ・太陽など)・
   星野・天球グリッドなど、光を受けず自分で陰影を完結させる(または陰影を受けない)物体を、
   マテリアルパスと同じ描画先の上に透過合成で描き足す。マテリアルパスが不透明な艦艇の深度を
   先に書き込んでいるため、透過物体は艦の手前・奥を正しく判定して重なる。
5. **合成パス**: ここまでの描画先を画面へコピーする。露出を掛け、線形の色空間から画面表示用の
   色空間へ変換するのはこの段階だけ。

## 露出とトーン

- 画面に出る前の内部描画はすべて、値が1を超えうる明るさ(HDR)で行われる。
- 合成パスで一律に **露出 0.72** を掛けてから画面色へ変換する。露出は場面によって変化しない固定値。

## 描画品質設定

- **表示のオン/オフ**: 消えたことが見た目で分かる要素だけが対象になる — 小天体の点群(小惑星帯・
  トロヤ群・ヒルダ群・カイパーベルト・散乱円盤)、惑星の環(本体表面に落ちる環の影も含めて消える)、
  オーロラ、大気の縁の発光(リムライト)。
- **解像度倍率**: 画面解像度に対する描画解像度の比率。
- **LOD バイアス**: 天体の見かけの大きさの判定に一律で掛かる係数。天体メッシュの分割段階の選択と、
  「見かけが小さすぎて球として描くのをやめる」しきい値の両方が、この1つの数値で連動して動く。
- **アンチエイリアス**: 切り替えても即座には反映されず、次回起動時から効く。
- 設定はブラウザに保存され、次回の起動でも引き継がれる。

## デバッグ表示

開発者向けに、画面の最終出力をパイプライン内の中間結果へ差し替えて表示する機能([Esc] メニューの
描画設定タブから選ぶ)。候補は次の7種類。

- **オフ**: 通常の画面(合成パスの通常出力)。
- **法線**: Gバッファの法線をそのまま可視化する。
- **粗さ**: Gバッファの粗さをグレースケールで表示する。
- **深度**: Gバッファの深度を、近平面〜遠平面の間で **対数的に** 0〜1へ写像して表示する(線形に
  写像すると、戦闘ビューの近平面2m・遠平面6,000万mという比では画面のほとんどが白一色になり
  読めないため)。
- **拡散反射光** / **鏡面反射光**: ライティングパスがそれぞれ計算した明るさを(露出のみ掛けて)
  そのまま表示する。
- **マテリアル**: マテリアルパスの出力(最終陰影)だけを、他の描画と合成せず単独で表示する。

どれを選んでもパイプラインの各段階は省略されず、通常のフレームで実際に起きていることがそのまま
見える。選択状態は保存されず、ページを読み込み直すたびに必ず「オフ」へ戻る。

## 負荷計測ウィンドウ

- [F3] キーまたは [Esc] メニューの「負荷を表示」項目で開閉する(起動時から表示したい場合は URL
  クエリパラメータ `?perf=1` を使う)。
- ウィンドウが開いている間だけ計測が行われ、閉じている間はゲームの負荷に一切影響しない。
- 内容は 0.5 秒ごとに更新される。
- 常時表示される行: fps・フレーム時間・時間加速倍率。
- 折りたたみ式のグループ: フレーム時間 / update 内訳 / 描画 / 計画軌道 / 予測 / シミュレーション /
  暦キャッシュ / 表示 / エンティティ / メモリ。
- update 内訳グループは、update 処理の区分ごとの所要時間が1行ずつ並ぶ。そのフレームで一度も
  通らなかった区分も 0.0ms の行としてそのまま表示され、行自体が消えることはない。
- 描画グループには、CPU 側で描画命令の発行に要した時間に加えて、GPU 側の各パス(Gバッファ/
  ライティング/マテリアル/ワールド/合成)ごとの実際の処理時間が個別の行として並ぶ。前者と後者は
  別の数値であり、食い違うことがある。GPU 側の計測に対応していない環境では「未対応」と表示される。
- 時間を表す行は 16.7ms(60fps 相当)を基準にした棒グラフで、件数・レートを表す行(予測の
  ステップ数など)は基準を持たず平均値・最大値として表示される。

## 画面上の大きさに基づく詳細度(LOD)

- 球として描く天体のメッシュは、粗い/中間/細かいの3段階の分割を持ち、見かけの直径に応じて自動的に
  切り替わる。どの段階も、その見かけの直径の範囲では輪郭の丸め誤差が画面上1px以内に収まるように
  選ばれており、最も細かい段階は見かけの直径がおよそ6万pxに達するまで有効(画面いっぱいに天体が
  映るような近さでも崩れない)。
- 見かけの直径が2px未満になった天体は、球としては描かれない。
- 視等級が肉眼限界(6等)より明るい惑星(金星・木星・水星・火星・土星・天王星)は、戦闘ビューでは
  球ではなく、星と同じカメラ追従シェル上に置かれた単色の輝点として、見かけの明るさ3段階
  (明/中/暗)で表示される。マップビューへ切り替えると実位置・実半径・実姿勢の球へまるごと
  入れ替わる。海王星・準惑星・大型小惑星・彗星核・すべての衛星はこの輝点表示を持たず、戦闘ビューでは
  事実上見えない。
- 環の帯は実際の幅で描き分けが変わる: 幅1,500km以上の帯は塗りつぶした帯として描かれ、それ未満の
  帯(名前の付いた細い環)は線として描かれる — 塗りつぶしのままだと画面上でサブピクセル幅に
  痩せたときに消えてしまうため。線として描かれる帯は、画面上の幅が1pxを下回るほど比例して暗く
  なっていく(幅のある帯より明るく見えてしまわないようにするため)。

## 浮動小数点精度の扱い(浮動原点)

- 描画時の座標は、その瞬間アクティブなカメラの位置を原点とした相対座標へ変換してから GPU へ渡す。
  低軌道の近さでも、マップビューで太陽系スケールまで引いたときでも、GPU 側の精度が原点からの
  絶対座標をそのまま扱うと不足するため。
- 進行方向を向くビルボードなど相対速度を要する描画は、自機の速度を基準にした相対速度を使う。
- 太陽以外の遠方天体(月・惑星)は、戦闘ビューでは実際の距離ではなく、見かけの角直径を保ったまま
  圧縮した距離に置いて描く。マップビューでは実 ECI 位置・実スケールで描かれる。表示位置は圧縮する
  一方、深度(遮蔽判定)だけは真の距離に基づいて計算し直す — そうしないと、天体そのものが近距離
  ですれ違う自機・敵機・弾薬・基地を、実際の位置関係とは無関係な圧縮位置で遮蔽/非遮蔽してしまう。
- 軌道線・軌跡線の頂点も、カメラ近傍に置いた基準点からの差分として GPU へ渡す。基準点は、線を
  引き直すたび、またはカメラがその基準点から一定以上離れるたびに更新される。この結果、戦闘ビューの
  至近距離(1pxあたり数cm)でカメラを動かしても、軌道線の位置が浮動小数の丸めでふらつくことはない。
- 戦闘ビューの近平面・遠平面は常に2m・6,000万mで固定。マップビューは逆に、近平面・遠平面ともに
  ズーム距離(カメラから注視点までの距離)に応じて連動して変わる: 近平面はズームインするほど
  手前へ寄り、遠平面はズームアウトするほど1.5×10¹⁰m〜1×10¹⁶mの範囲まで広がる — どちらも
  固定の距離で物体を切り取らないようにするため。星・天球グリッドを乗せた球殻の半径は遠平面に
  よらず一定(遠平面の下限よりわずかに内側)に固定されており、マップビューをどれだけズーム
  アウトしても、画面の隅も含めてその球殻の外へ出ることはない。

## 地球の描画

- 地表は実写の写真テクスチャ(地表+雲)を貼ったスフィアで、雲は別の層としてではなく地表側に
  合成して描く(雲を別のシェルとして浮かせると、水平線付近で地表と衝突して乱れるため)。
- 雲の影は、雲のテクスチャを太陽方向へずらした位置から参照して地表を減光する近似で表現する
  (地球に固定した近似のため、太陽の実際の方向へ厳密には追従しない)。
- 大気は幾何形状ではなく、視線方向から毎ピクセル計算する解析的な効果として描く(高度400km未満に
  不透明な物体を複数重ねて置くと、近平面2mという浅い視野角ではちらつきが避けられないため)。
  - 地表付近の近接ヘイズは Beer-Lambert 則による減光。
  - 地平線の縁の発光(リムライト)は高度20〜340km・スケール高90kmの指数減衰で、地球本体による
    遮蔽を解析的な光線と球の交差判定で反映する。上限高度(340km)は通常飛行高度(420km)より
    低く抑えてあり、カメラがこの発光域へ入り込むことはない。
  - どちらも太陽光の入射角に応じて明暗が付くため、昼夜境界(ターミネーター)をまたぐ薄明が
    自然に生じる。
- オーロラは磁極を囲む緯度およそ±67°の波打つカーテンで、両極それぞれ2層(計4枚)。下端は緑、
  上端は紫から黒(加算合成のため透明に近づく)へフェードする。自転に追従し、ゆっくり明滅する。
- 天体(地球に限らず月・惑星も含む)は、自分自身の真の位置から見た太陽方向で自ら昼夜の陰影を
  計算する。戦闘ビューでは実位置とは異なる場所・距離に描かれる天体があり、シーン共通の光源では
  太陽の当たる向きを正しく表現できない(惑星ではずれが最大 179° に達しうる)ため。夜側にも
  最低限の明るさが残り、真っ暗にはならない。艦艇メッシュ(自機・敵機・デブリなど)はこれとは別に、
  太陽の可視率(地球や月による遮蔽で連続的に決まる)に応じて暗くなる — ただし太陽光は最低でも
  概ね4%、環境光は最低でも概ね35%が残り、完全な暗闇にはならない。本影・半影は幾何から連続的に
  定まり、月の影に入った場合も同様に減光する。

## 環の描画

- 環の各帯は、固定の不透明度ではなく、光学的な厚み(垂直光学的深さ)・散乱アルベド・散乱位相の
  各パラメータから、太陽光の入射角と視線角に応じた減光・散乱光を毎ピクセル計算して描く。
- 実際の幅が1,500km以上の帯は塗りつぶした帯として、それ未満の帯は線として描く(「画面上の
  大きさに基づく詳細度」参照)。線として描かれる帯も、太い帯と同じ陰影・散乱の計算を受ける。
- 環は本体メッシュの自転位相には追従しない姿勢で描かれる(海王星のように環の一部だけが経度方向に
  濃い構造を持つ場合、本体の自転に追従させると不自然に周回して見えてしまうため)。
- 環が本体の表面に落とす影は、その天体の陰影計算のうち太陽から直接届く光の成分だけを暗くする
  (夜側にも残る最低限の明るさには影響しない)。

## 軌道線・軌跡線の描画

- **サンプリング密度**: 解析楕円(整数の解析解で描く軌道線)は最大2,048点まで細分でき、低軌道
  (周長およそ42,000km)では1セグメントがおよそ20km、弦のたるみ(サジッタ)は数mまで低下する。
  離心率0.5を超える軌道は近日点付近の頂点密度を上げてサンプリングする。離心率0.98以上の軌道は
  楕円として描くこと自体を諦める。
- **積分結果からの軌道線**(予測軌道・計画経路・過去の履歴)は、隣接するサンプル間を両端の速度を
  接線とする滑らかな曲線で補間して描く。長期間の表示(28日)でサンプル間隔が粗くなっても
  (低軌道でおよそ1,210秒間隔)、たるみは補間なしなら約1,517kmに達するところを約6.2kmまで
  抑えられる。
- 折れ線は再帰的に分割され、画面上のたるみがおよそ0.5pxに収まることを目標に分割の細かさが
  決まる。マップビューでズームしても、軌道線と実際の軌道のずれが画面上で拡大することはない。
  分割はカメラに近い区間ほど細かくなるため、注視点まわりでカメラを回転させて粗い区間が手前へ
  回り込んだときも、その場で分割をやり直す。
- 分割には頂点数の上限があり、上限に達すると軌道線全体が一様に粗くなるだけで、画面に映る区間だけを
  残して映らない区間が丸ごと描かれなくなることはない。カメラの近平面より手前(視点の後方)へ回り
  込んだ区間は、そのぶんの細分に頂点を浪費しない — 戦闘ビューのように曲線の一部が視点のすぐ後ろを
  通る場面でも、見えている区間の解像度が犠牲にならない。
- 破線の間隔は画面上で一定に保たれ、ズームしても間隔が伸び縮みしない。
- **実線と破線の意味**: 実線は「これから確実に起こる、または既に起きた」軌道(積分された将来予測・
  過去の履歴・解析楕円)、破線は「要求されているだけでまだ確定していない」もの(編集中の
  マニューバ計画の経路)を表す。
- 自機の軌道は常に1本の線でのみ表示され、解析楕円と積分された予測線が同時に並んで見えることは
  ない(戦闘ビューでは解析楕円、マップビューでは積分された予測線)。実際に積分された範囲を超えて
  さらに先まで表示が必要なときは、積分の先端から二体軌道として延長して描く。
- **重なったときの手前・奥の順**(奥から手前へ): 登録天体の参照楕円 < 自機の軌道 < 副ターゲットの
  軌道 < 主ターゲットの軌道 < マニューバ計画の経路 < 積分された予測軌道。ランデブー相手の軌道は
  自機の軌道とほぼ一致しがちで、計画経路は編集中のものが優先され、予測軌道はそれが代わりを
  務める解析楕円より必ず手前に来る、という優先度で並べてある。
- **色**: 副ターゲットの軌道はシアン、主ターゲットの軌道はオレンジ、敵機の通常の軌道は目立たない
  灰色(ターゲット指定時のハイライトが際立つように)。マニューバ計画の経路は白。
- 軌道線は必ずその天体・軌道の中心を通って描かれるが、天体本体のメッシュは不透明かつ深度を
  書き込んで先に描かれるため、線は自然に本体へ隠れる(区間ごとの除外処理は不要)。
- 登録天体の参照楕円は、天体までの距離に応じて不透明度が連続的に変わる: 惑星は 100万〜1,000万km、
  衛星は 50万〜100万km の範囲で線形にフェードインし、それぞれの下限距離未満では非表示、上限距離
  以上で完全表示(不透明度 0.1)になる。遠方の天体にごく薄い線が常時見えている状態と、近づいた
  天体の周りに突然線が浮かんで見える状態の両方を避けている。衛星の参照線は、自機がその衛星の
  惑星系(地球系を除く)にフォーカスしているときだけ表示される — 全衛星の線を常時描くと内側
  太陽系が線で埋まってしまうため。地球系の月の線だけは常時表示の例外。

## 星野と天球シェル

- 恒星(背景の星)は、実写の星空写真を貼った、カメラに追従する球殻として描く(1恒星ずつ個別の
  幾何形状としては描かない)。
- 太陽はカメラから見た方向(実位置とカメラ位置の差)に、一定の表示距離を置いたビルボードとして
  描く。マップビューで広く引くとカメラが地球から最大45億m離れうるため、地心方向のまま置くと
  視差により実位置から最大1.7°ずれ、実位置に対応するラベルと像が合わなくなるため。マップビューで
  十分に近づくと、太陽は実位置・実半径のメッシュへ入れ替わる。
- 天球グリッド(赤道面・黄道面それぞれの基準円・30°間隔の緯経線・両極マーカー)は、恒星の球殻と
  同じ半径に揃えて描かれ、面(赤道・黄道)ごとに、基準円・極マーカー・グリッドの3種類を独立に
  表示切り替えできる(計6通り)。既定はすべて非表示。グリッドは緯度0°の行(基準円と同じ緯度)と
  両極も含めて、すべての緯線を同じ交点十字で表す。

## WebGPU / three.js 上の制約

実装に使っている描画基盤(WebGPU 上で動く three.js)の性質による制約。

- ループ状に閉じた線や、点のサイズ指定は使えない。線は端点を重ねて手動で閉じた普通の折れ線として
  描き、点のような表示は三角形ベースのスプライトで代用する。
- 加算合成のマテリアルは透過を明示しないと効かない。
- 頂点データやインスタンスの変換は、確保済みのバッファへ直接書き込んで更新しなければならない。
  ジオメトリやその属性そのものを差し替えても、描画には反映されず古い内容のまま描かれ続ける。
- 特定の GPU 側の処理に失敗すると、例外は出ないまま画面がまるごと黒くなることがある(その
  フレームの描画命令全体が無効になるため)。原因の手がかりはブラウザ側のログにしか出ない。
- ヘッドレス環境でのスクリーンショット撮影には GPU 関連の特別な起動オプションが必要で、不安定な
  ため複数回の試行が要ることがある。
- 視錐台の外を描画しない仕組み(カリング)は基本的に有効なまま使う。無効化してよいのは、カメラに
  追従して常に画面内に留まる球殻(星・天球グリッド)、頂点バッファを直接書き換えていて包含球が
  自動更新されない線(軌道線・軌跡線)、インスタンスが共有ジオメトリの包含球よりはるかに広い
  範囲へ散らばる描画(点群など)に限る。
