# RENDERING — 描画

画面に何を、どの順で、どのくらいの精度で描くかの仕様。HUD/UI 側のデザイン規約は [UI-DESIGN.md](UI-DESIGN.md)。

## 描画パイプライン

1フレームの描画は9段階を順に経て画面へ出る。

1. **影パス**: 太陽の直射光を遮る不透明なメッシュ(艦艇・基地・デブリなど)を、太陽方向を向いた
   平行投影のライト空間へ、深度だけの絵として描き出す。天体の球と惑星の環は式で解けるので、
   ここには描かない。
2. **Gバッファパス**: 光を受ける不透明な物体(自機・敵機・デブリ・薬莢などの艦艇メッシュと、
   天体の球)についてのみ、深度・法線・粗さを書き出す。
3. **遮蔽パス**: 画素ごとの位置へ太陽の直射光がどれだけ届くかを1枚の透過率として書き出す。
   遮蔽するのは (a) 天体の球、(b) 惑星の環の帯、(c) 艦艇・基地・デブリなどのメッシュ の3種で、
   複数の遮蔽は透過率の積で合成する。**太陽は点ではなく円盤として扱われるので、どの遮蔽源でも
   影の境界は半影の幅でぼける** — 天体の球は円盤の重なり面積から、環の帯は帯の縁が太陽円盤を
   横切る割合から、メッシュは遮蔽物までの距離に比例するぼかし幅から、それぞれ連続に決まる。
   影の濃さは、半透明な環では帯の光学的厚みに、不透明なメッシュでは完全な遮蔽になる。
   **遮蔽度は不透明物の陰影だけでなく、前方描画で描かれる環と大気にも同じ1つの値として掛かる。**
   したがって土星の影は環を横切る境界がぼけ、日食のときは月の影が地球の大気にも落ちる。
4. **ライティングパス**: Gバッファの法線・粗さ・深度と太陽の位置・強さ、遮蔽パスの透過率から、
   拡散反射光と鏡面反射光の強さを計算して書き出す。値は1を超えうる(HDR)。
5. **マテリアルパス**: ライティングパスが出した拡散反射光・鏡面反射光に、物体自身の色(アルベド)・
   金属度・反射率を掛け合わせて最終的な陰影を求め、共有の描画先へ書き込む(このパスが最初に
   その描画先をクリアする)。背景の星野もこのパスが、不透明物より先に描く。
6. **大気パス**: 大気を持つ天体について、視線と大気層の交差から内部散乱と透過率を求め、
   不透明の絵の上へ画面いっぱいに重ねる。大気は幾何形状としては存在せず、この1段だけが持つ。
7. **ワールドパス**: 惑星の環・小天体の点群・ビルボード(噴射炎・RCS 噴射・フラッシュ・太陽など)
   など、光を受けず自分で陰影を完結させる(または陰影を受けない)物体を、マテリアルパスと同じ描画先の
   上に透過合成で描き足す。マテリアルパスが不透明な艦艇の深度を先に書き込んでいるため、透過物体は
   艦の手前・奥を正しく判定して重なる。
8. **合成パス**: ここまでの描画先を画面へコピーする。トーンマッピングを掛け、線形の色空間から
   画面表示用の色空間へ変換するのはこの段階だけ。あわせて、Gバッファの深度を画面の深度バッファへ
   複製する(次の段が深度テストへ使う)。
9. **3D UI パス**: 軌道線・軌跡線・天球グリッド・縮尺グリッド・Δv ギズモを、合成後の画面へ描き足す。
   これらは3D空間の位置を持つが物理的な明るさを持たない表示物なので、露出もトーンマッピングも
   受けず、指定した色がそのまま画面へ出る。不透明な物体には隠れるが、環・大気・オーロラ・噴射炎の
   ような透ける物体には隠れない。

## 露出とトーン

**画面に出るものは、物理量として描くものと表示値として描くものの2つに分かれる。**

- **物理量として描くもの**(天体・艦艇・環・大気・太陽・惑星の輝点・噴射炎・爆発・オーロラ・
  小天体の点群): 明るさは「その物体がいまいる場所で受けている光の量」と「その物体の反射率
  (アルベド)」から決まる。天体・艦艇はアルベドだけを持ち、明るさそのものは持たない。
- **表示値として描くもの**(軌道線・軌跡線・天球グリッド・縮尺グリッド・Δv ギズモ): 3D空間の
  位置を持つが物理的な明るさを持たない。指定した色がそのまま画面へ出る。

物理量として描くものだけが、次の露出とトーンを通る。

- 画面に出る前の内部描画はすべて、値が1を超えうる明るさ(HDR)で行われる。
- 明るさの基準は物理量で決まる。**太陽に正対した反射率1の完全拡散面を1天文単位で照らしたときの
  明るさが、画面上の白**になる。したがって画面に出る明るさは、その面の反射率(アルベド)そのものに
  なる。手で合わせた明るさ係数は持たない。
- 露出は場面によって変化しない。1天文単位より太陽に近ければ明るく、遠ければ暗く写る。
- 白を超える明るさ(太陽面・鏡面反射のハイライト・噴射炎・爆発)は切り落とさず、なだらかに白へ
  近づける。中間調の色相・彩度はそのまま保たれる。

**ゲームプレイのために物理から意図的に外す例外は、その表示物の仕様へ個別に明記する**(例:
ガンサイトズーム中のマズルフラッシュ減光 — [COMBAT.md](COMBAT.md))。ここに書かれた規則は、
そうした明示的な例外を除いたすべてに掛かる。

## 描画品質設定

- **表示のオン/オフ**: 消えたことが見た目で分かる要素だけが対象になる — 小天体の点群(小惑星帯・
  トロヤ群・ヒルダ群・カイパーベルト・散乱円盤)、惑星の環(本体表面に落ちる環の影も含めて消える)、
  オーロラ、大気、メッシュの影(艦艇・基地・デブリが落とす影。天体の球と環が落とす影は消えない)。
- **解像度倍率**: 画面解像度に対する描画解像度の比率。
- **LOD バイアス**: 天体の見かけの大きさの判定に一律で掛かる係数。天体メッシュの分割段階の選択と、
  「見かけが小さすぎて球として描くのをやめる」しきい値の両方が、この1つの数値で連動して動く。
- **アンチエイリアス**: 切り替えても即座には反映されず、次回起動時から効く。
- 設定はブラウザに保存され、次回の起動でも引き継がれる。

## デバッグ表示

開発者向けに、画面の最終出力をパイプライン内の中間結果へ差し替えて表示する機能([Esc] メニューの
描画設定タブから選ぶ)。候補は次の10種類。

- **オフ**: 通常の画面(合成パスの通常出力)。
- **法線**: Gバッファの法線をそのまま可視化する。
- **粗さ**: Gバッファの粗さをグレースケールで表示する。
- **深度**: Gバッファの深度を、近平面〜遠平面の間で **対数的に** 0〜1へ写像して表示する(線形に
  写像すると、戦闘ビューの近平面2m・遠平面2兆mという比では画面のほとんどが白一色になり
  読めないため)。
- **影**: 影パスが描いたライト空間の深度マップを、そのままアトラスの割り付けごと表示する。
- **遮蔽**: 遮蔽パスが出した太陽の直射光の透過率をグレースケールで表示する。
- **拡散反射光** / **鏡面反射光**: ライティングパスがそれぞれ計算した明るさを、通常出力と同じ
  トーンマッピングだけを通して表示する。
- **マテリアル**: マテリアルパスの出力(最終陰影)だけを、他の描画と合成せず単独で表示する。
- **大気**: 大気パスが重ねる内部散乱だけを、下地と合成せず単独で表示する。

どれを選んでもパイプラインの各段階は省略されず、通常のフレームで実際に起きていることがそのまま
見える。選択状態は保存されず、ページを読み込み直すたびに必ず「オフ」へ戻る。

## 負荷計測ウィンドウ

- [F3] キーまたは [Esc] メニューの「負荷を表示」項目で開閉する(起動時から表示したい場合は URL
  クエリパラメータ `?perf=1` を使う)。
- ウィンドウが開いている間だけ計測が行われ、閉じている間はゲームの負荷に一切影響しない。
- 内容は 0.5 秒ごとに更新される。
- 常時表示される行: fps・フレーム時間・時間加速倍率。
- 折りたたみ式のグループ: フレーム時間 / update 内訳 / 描画 / 計画軌道 / 予測 / シミュレーション /
  暦キャッシュ / 表示 / エンティティ / メモリ。
- update 内訳グループは、update 処理の区分ごとの所要時間が1行ずつ並ぶ。そのフレームで一度も
  通らなかった区分も 0.0ms の行としてそのまま表示され、行自体が消えることはない。
- 描画グループには、CPU 側で描画命令の発行に要した時間に加えて、GPU 側の各パス(影/Gバッファ/
  遮蔽/ライティング/マテリアル/大気/ワールド/合成/3D UI)ごとの実際の処理時間が個別の行として並ぶ。前者と後者は
  別の数値であり、食い違うことがある。GPU 側の計測に対応していない環境では「未対応」と表示される。
- 時間を表す行は 16.7ms(60fps 相当)を基準にした棒グラフで、件数・レートを表す行(予測の
  ステップ数など)は基準を持たず平均値・最大値として表示される。

## 画面上の大きさに基づく詳細度(LOD)

- 球として描く天体のメッシュは、粗い/中間/細かいの3段階の分割を持ち、見かけの直径に応じて自動的に
  切り替わる。どの段階も、その見かけの直径の範囲では輪郭の丸め誤差が画面上1px以内に収まるように
  選ばれており、最も細かい段階は見かけの直径がおよそ6万pxに達するまで有効(画面いっぱいに天体が
  映るような近さでも崩れない)。
- 見かけの直径が2px未満になった天体は、球としては描かれない。そのうち惑星だけは、戦闘ビューで
  星と同じカメラ追従シェル上に置かれた単色の輝点へ置き換わる。輝点の明るさは天体ごとに固定した
  段階を持たず、その惑星がいま受けている光の量から毎フレーム決まる
  ([CELESTIAL.md](CELESTIAL.md) 9.4)。マップビューへ切り替えると実位置・実半径・実姿勢の球へ
  まるごと入れ替わる。
- 環の帯は実際の幅で描き分けが変わる: 幅1,500km以上の帯は塗りつぶした帯として描かれ、それ未満の
  帯(名前の付いた細い環)は線として描かれる — 塗りつぶしのままだと画面上でサブピクセル幅に
  痩せたときに消えてしまうため。線として描かれる帯は、画面上の幅が1pxを下回るほど比例して暗く
  なっていく(幅のある帯より明るく見えてしまわないようにするため)。

## 浮動小数点精度の扱い(浮動原点)

- 描画時の座標は、その瞬間アクティブなカメラの位置を原点とした相対座標へ変換してから GPU へ渡す。
  低軌道の近さでも、マップビューで太陽系スケールまで引いたときでも、GPU 側の精度が原点からの
  絶対座標をそのまま扱うと不足するため。
- 進行方向を向くビルボードなど相対速度を要する描画は、自機の速度を基準にした相対速度を使う。
- 天体はどのビューでも実 ECI 位置・実スケールで描く。見かけの大きさが視点の切り替えやズームで
  飛ぶことはなく、深度もその真の位置のものなので、天体と近距離ですれ違う自機・敵機・弾薬・基地との
  遮蔽関係は実際の位置関係とそのまま一致する。
- 深度は反転(近平面が1・遠平面が0)して32bit浮動小数点で保持する。これにより、深度から復元した
  画素ごとの位置の相対誤差が距離によらず一定になる — 遠方の天体でも、その画素における太陽の方向と
  距離を差分ベクトルとして正しく引ける。
- 軌道線・軌跡線も同様で、戦闘ビューの至近距離(1pxあたり数cm)でカメラを動かしても、線の位置が
  浮動小数の丸めでふらつくことはない。
- 戦闘ビューの近平面・遠平面は常に2m・2兆mで固定(遠平面は、球として描かれる天体のうち
  見かけ直径が2pxを超える最遠のもの — 最大の恒星 — が入る距離)。マップビューは逆に、近平面・遠平面ともに
  ズーム距離(カメラから注視点までの距離)に応じて連動して変わる: 近平面はズームインするほど
  手前へ寄り、遠平面はズームアウトするほど1.5×10¹⁰m〜1×10¹⁶mの範囲まで広がる — どちらも
  固定の距離で物体を切り取らないようにするため。星・天球グリッドを乗せた球殻の半径は遠平面に
  よらず一定(遠平面の下限よりわずかに内側)に固定されており、マップビューをどれだけズーム
  アウトしても、画面の隅も含めてその球殻の外へ出ることはない。

## タンパク質立体構造

- Ribbon 表示の中心線は Cα 原子を N 末端から C 末端へ辿る。鎖が変わる箇所と、隣接する Cα 間が
  8 Å を超える座標欠損で分離し、αヘリックス・βストランド・coil の境界では連続させる。
- 断面の向きはカルボニル酸素の方向を優先して鎖全体で連続に定め、その方向が退化する箇所では
  直前の向きを中心線に沿って平行移動する。隣接する断面が180°反転してはならない。
- αヘリックスは幅 2.0 Å・厚さ 0.4 Å の扁平な oval、βストランドは幅 2.0 Å・厚さ 0.4 Å の
  rectangle、coil は直径 0.4 Å の円形 rope とする。oval と rope の断面は12分割し、中心線は
  1残基あたり12分割する。
- βストランドの C 末端側は最後の2残基で、shaft の最大2倍の幅へ広がって先端へ収束する矢印とする。
  N 末端側とαヘリックスには矢印を付けない。
- Ribbon の表面は smooth shading を使い、金属度 0・粗さ 0.68 の非金属でマットな反射とする。
- Ribbon の着色には、鎖、B-factor、entity、残基順、二次構造、構成要素の役割による既存の選択肢を
  すべて残し、論文図向けの鎖別色を追加する。論文図向けの鎖別色は ColorBrewer Set2 の8色を使い、
  1文字の鎖 ID はアルファベット順に割り当てて9鎖目から循環し、それ以外の ID は同じ ID が常に
  同じ色となるよう割り当てる。リガンドは元素別の色を保つ。
- 新しく生成するタンパク質は Ribbon と論文図向けの鎖別色を既定とする。保存済みの有効な着色選択は
  そのまま復元し、着色情報を持たない保存データは鎖別着色として復元する。
- 衝突判定には表示用とは別に固定した Ribbon 形状を使う。表示形状や材質を変更しても、衝突メッシュの
  三角形、外接半径、静止球と移動球の命中結果を変えない。

## 地球の描画

- 地表は実写の写真テクスチャ(地表+雲)を貼ったスフィアで、雲は別の層としてではなく地表側に
  合成して描く(雲を別のシェルとして浮かせると、水平線付近で地表と衝突して乱れるため)。
  地表が持つのはアルベドだけで、昼夜の陰影も影も他の天体・艦艇とまったく同じ経路から来る。
- 雲の影は、雲のテクスチャを太陽方向へずらした位置から参照して地表を減光する近似で表現する
  (地球に固定した近似のため、太陽の実際の方向へ厳密には追従しない)。
- 大気は幾何形状ではなく、画面空間のフィルタ(大気パス)として毎ピクセル計算する解析的な効果
  として描く。
  - 地表は、視線が地平線に近いほど厚い大気を通して見え、白く霞んでいく。
  - 地平線の縁は薄く発光し、地球本体に隠される側では途切れる。発光する層は通常飛行高度より
    内側に収まっていて、カメラがその中へ入り込むことはない。
  - どちらも太陽光の入射角に応じて明暗が付くため、昼夜境界(ターミネーター)をまたぐ薄明が
    自然に生じる。もやは下地から光を奪い、そこへ散乱した光を戻す — どちらも太陽の当たり方に
    比例するので、夜側では地表がそのまま見える。
  - 明暗は入射角だけでなく、その点の遮蔽度にも比例する。日食のときは月の影が大気にも落ち、
    影の中を通る視線では散乱もリム光も暗くなる。
- オーロラは磁極を囲む緯度およそ±67°の波打つカーテンで、両極それぞれ2層(計4枚)。下端は緑、
  上端は紫から黒(加算合成のため透明に近づく)へフェードする。自転に追従し、ゆっくり明滅する。
- 天体(地球に限らず月・惑星も含む)も艦艇メッシュ(自機・敵機・デブリなど)も、同じ1つの光源
  ・同じ反射モデルで描く。太陽は点光源として扱い、画素ごとにその位置と太陽との差分ベクトルから
  向きと距離を引くので、**太陽から遠い天体ほど暗い**(木星圏の天体は地球圏より暗く見える)。
- 影は、その画素の位置に太陽の直射光がどれだけ届くかで決まる。本影・半影は太陽円盤と遮蔽天体円盤の
  重なりから連続的に定まり、地球の影でも月の影でも土星の環の影でも、艦艇のメッシュが自分の構造や
  隣の艦へ落とす影でも、同じ1つの仕組みで暗くなる。
  太陽光は最低でも概ね4%が残り、完全な暗闇にはならない。夜側には方向を持たない環境光も残る。

## 環の描画

- 環の各帯は、固定の不透明度ではなく、光学的な厚み(垂直光学的深さ)・散乱アルベド・散乱位相の
  各パラメータから、太陽光の入射角と視線角に応じた減光・散乱光を毎ピクセル計算して描く。
- 実際の幅が1,500km以上の帯は塗りつぶした帯として、それ未満の帯は線として描く(「画面上の
  大きさに基づく詳細度」参照)。線として描かれる帯も、太い帯と同じ陰影・散乱の計算を受ける。
- 環は本体メッシュの自転位相には追従しない姿勢で描かれる(海王星のように環の一部だけが経度方向に
  濃い構造を持つ場合、本体の自転に追従させると不自然に周回して見えてしまうため)。
- 環が本体の表面に落とす影は、遮蔽パスが画素ごとに求める透過率として、太陽から直接届く光の
  成分だけを暗くする(夜側にも残る最低限の明るさには影響しない)。**帯の縁が落とす影の境界は
  硬くならず、太陽円盤が環面へ落とす広がりのぶんだけ半影でぼける** — カッシーニの間隙のような
  帯の切れ目も、縁のぼけた明るい帯として本体表面に出る。
- 環が本体の影へ入るときも、本体表面と同じ透過率で暗くなる。**したがってその境界も半影を持ち、
  環を横切る影の縁が段差にならない。** 環のフラグメントは自分が乗っている帯からは遮蔽を受けない。

## 軌道線・軌跡線の描画

- **曲線として見えること**: どのビュー・どのズームでも、軌道線・軌跡線は折れ線ではなく滑らかな
  曲線として見える。ズームインしても線と実際の軌道のずれが画面上で拡大することはなく、注視点
  まわりでカメラを回しても、戦闘ビューのように曲線の一部が視点のすぐ後ろを通る場面でも、見えて
  いる区間が角張ったり途中から丸ごと欠けたりしない。離心率0.98以上の軌道だけは、楕円として
  描くこと自体を諦める。
- **積分結果からの軌道線**(予測軌道・計画経路・過去の履歴)は、サンプル点の間も実際に飛ぶ経路に
  沿って描く。表示期間を延ばしてサンプル間隔が粗くなっても、点を直線で結んだ形には見えない。
- **解析楕円**(自機・敵・基地・登録天体の軌道)は、常にその瞬間の軌道要素から描かれ、対象の
  現在位置を必ず通る。噴射中も摂動で軌道要素が動いている間も、以前に描いた形が残って対象から
  離れていくことはない。
- 破線の間隔は画面上で一定に保たれ、ズームしても間隔が伸び縮みしない。
- **実線と破線の意味**: 実線は「これから確実に起こる、または既に起きた」軌道(積分された将来予測・
  過去の履歴・解析楕円)、破線は「要求されているだけでまだ確定していない」もの(編集中の
  マニューバ計画の経路)を表す。
- 自機の軌道は常に1本の線でのみ表示され、解析楕円と積分された予測線が同時に並んで見えることは
  ない(戦闘ビューでは解析楕円、マップビューでは積分された予測線)。実際に積分された範囲を超えて
  さらに先まで表示が必要なときは、積分の先端から二体軌道として延長して描く。
- **重なったときの手前・奥の順**(奥から手前へ): 登録天体の参照楕円 < 自機の軌道 < ターゲットの
  軌道 < マニューバ計画の経路 < 積分された予測軌道。ランデブー相手の軌道は自機の軌道とほぼ
  一致しがちで、計画経路は編集中のものが優先され、予測軌道はそれが代わりを務める解析楕円より
  必ず手前に来る、という優先度で並べてある。
- **色**: ターゲットの軌道はオレンジ、敵機の通常の軌道は目立たない灰色(ターゲット指定時の
  ハイライトが際立つように)。マニューバ計画の経路は白。
- 軌道線・軌跡線は**表示値**であって物理的な明るさを持たないので、露出とトーンマッピングを
  受けない — 指定した色がそのまま画面へ出る(「露出とトーン」節)。
- 軌道線は必ずその天体・軌道の中心を通って描かれるが、天体本体のメッシュは不透明かつ深度を
  書き込んで先に描かれるため、線は自然に本体へ隠れる(区間ごとの除外処理は不要)。深度を書かない
  透ける物体 — 環・大気・オーロラ・噴射炎 — には隠れず、その手前を通って見える。自分で陰影を
  完結させる不透明物(太陽の球・弾薬ビーコン)も同じく線を隠さない。
- 登録天体の参照楕円は、天体までの距離に応じて不透明度が連続的に変わる: 惑星は 100万〜1,000万km、
  衛星は 50万〜100万km の範囲で線形にフェードインし、それぞれの下限距離未満では非表示、上限距離
  以上で完全表示(不透明度 0.1)になる。遠方の天体にごく薄い線が常時見えている状態と、近づいた
  天体の周りに突然線が浮かんで見える状態の両方を避けている。衛星の参照線は、自機がその衛星の
  惑星系(地球系を除く)にフォーカスしているときだけ表示される — 全衛星の線を常時描くと内側
  太陽系が線で埋まってしまうため。地球系の月の線だけは常時表示の例外。

## タンパク質敵の微細運動

- タンパク質敵の表示運動は、構造生成時に保存した **Motion Asset** を唯一の入力とする。Motion Asset は
  Cα 原子の弾性ネットワークから求めた ANM の正規モード、固有値、B-factor 相対較正値、残基・原子・表面・
  アンカーの対応表を持つ。従来の成分ごとの剛体平行移動や、構造全体を回す演出はこの経路では使用しない。
- 各敵 ID は固有の決定的 seed を持つ `ProteinMotionController` を所有する。表示時刻から 24 個の
  overdamped OU モード係数を直接サンプルするため、フレームレートや seek の履歴に依存しない。同じ残基の
  変位は Cα 周辺の原子・結合・リボン・表面・リガンドへ補間して適用する。
- 変位は構造データと同じ object-local Å 単位で StorageBuffer へアップロードし、親 group の `coordinateScale`
  が一度だけ表示単位へ変換する。CPU アンカーも対応する1つ以上の残基変位の平均を同じ座標系で加える。
  従って表示マーカーと頂点変形は一致する。
- Motion は表示専用であり、敵の軌道状態、衝突メッシュ、命中判定、ゲームプレイ用の半径・形状を変更しない。
  active site marker と攻撃原点は表示上の残基変位へ追従するが、`closestSite` による命中判定は静的アンカーを使う。
  表示モード切替や render object rebuild では既存 Controller と binding を再利用し、破棄時に GPU binding を解放する。
- 詳細度は見かけの大きさを直接求められない同期経路ではカメラとの距離を半径で正規化して決める。near=24、
  medium=12、far=4、marker=0 モードを使い、medium/far は Controller の決定的な更新間引きを行う。marker は
  残基バッファをゼロにして、遠方で不要な微細変形を計算しない。
- 頂点法線は毎frame再計算せず、表示gainを `(0, 1]` に制限した小変位近似として静的法線を使う。Motion Assetは
  B-factorが有効な場合だけ `physicalRmsAngstrom` を名乗り、1MBNのように入力B-factorが全て0の場合は
  `uncalibrated-display` / `displayRmsAngstrom` として、任意の表示振幅を物理較正値とは扱わない。

## 星野と天球シェル

- 恒星(背景の星)は、実写の星空写真を貼った、カメラに追従する球殻として描く(1恒星ずつ個別の
  幾何形状としては描かない)。
- 太陽は実位置・実半径のメッシュとして描き、その周りへ実半径に比例した大きさのグローを重ねる
  (肉眼で見た太陽が視直径そのものより大きく滲んで見えるのに合わせるため)。グローは戦闘ビューでのみ
  重ね、マップビューでは重ねない — 太陽へ十分に近づいたとき、グローの平面が画面を埋め尽くして
  しまうため。
- 天球グリッド(赤道面・黄道面それぞれの基準円・30°間隔の緯経線・両極マーカー)は、恒星の球殻と
  同じ半径に揃えて描かれ、面(赤道・黄道)ごとに、基準円・極マーカー・グリッドの3種類を独立に
  表示切り替えできる(計6通り)。既定はすべて非表示。グリッドは緯度0°の行(基準円と同じ緯度)と
  両極も含めて、すべての緯線を同じ交点十字で表す。
- 天球グリッドとは別に、自機/カメラの位置を通る固定平面として「黄道面」「赤道面」「月軌道面」
  「月赤道面」の縮尺グリッドがあり、それぞれ交点十字だけの目盛り線をズーム段階に応じた縮尺で
  描く。4種は互いに異なる色を持ち、独立にON/OFFできる。既定はすべて非表示。

## WebGPU / three.js 上の制約

実装に使っている描画基盤(WebGPU 上で動く three.js)の性質による制約。

- ループ状に閉じた線や、点のサイズ指定は使えない。線は端点を重ねて手動で閉じた普通の折れ線として
  描き、点のような表示は三角形ベースのスプライトで代用する。
- 加算合成のマテリアルは透過を明示しないと効かない。
- 頂点データやインスタンスの変換は、確保済みのバッファへ直接書き込んで更新しなければならない。
  ジオメトリやその属性そのものを差し替えても、描画には反映されず古い内容のまま描かれ続ける。
- 特定の GPU 側の処理に失敗すると、例外は出ないまま画面がまるごと黒くなることがある(その
  フレームの描画命令全体が無効になるため)。原因の手がかりはブラウザ側のログにしか出ない。
- ヘッドレス環境でのスクリーンショット撮影には GPU 関連の特別な起動オプションが必要で、不安定な
  ため複数回の試行が要ることがある。
- 視錐台の外を描画しない仕組み(カリング)は基本的に有効なまま使う。無効化してよいのは、カメラに
  追従して常に画面内に留まる球殻(星・天球グリッド)、頂点バッファを直接書き換えていて包含球が
  自動更新されない線(軌道線・軌跡線)、インスタンスが共有ジオメトリの包含球よりはるかに広い
  範囲へ散らばる描画(点群など)に限る。
