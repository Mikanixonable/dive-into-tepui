# UI-DESIGN — HUD の見た目・配置・操作の仕様

HUD(画面に重なる操作パネル・ウィンドウ・ボタン・入力欄・タッチ操作)の見た目・配置・操作の
規約の正本。コードより先行する。

---

## 1. 七原則(全判断の上位規範)

個別の見た目の趣味より、この7つの一貫性を優先する。判断に迷ったらここへ戻る。

1. **一責務一 UI。** 1つのウィンドウ/パネルは1つの問いに答える。「このパネルは何を答えるものか」
   を一文で言えないなら分割する。
2. **状態は見た目の有無でなく状態そのもので持つ。** 表示の開閉・有無を読み取って状態を判定する
   実装をしない。状態は必ず「点灯/選択」「押下中」「無効」「非表示」「折りたたみ」「クリップ」
   の付け外しで表す。
3. **開く/閉じる/重なりの規則は一箇所に集約する。** ESC・外側クリック・排他・入力遮断の判断を、
   個々のウィンドウ/パネルがそれぞれ勝手に決めない。
4. **見た目はトークンからのみ導く。** 色・透明度段階・余白・角丸・フォントサイズ・トランジション
   は有限のデザイントークン集合から選ぶ。値の直書きを禁止する(§2)。
5. **レイアウトは流し込み+変数、固定 px は最終手段。** 位置は「レール/常設計器/中央モーダル/
   画面固定バッジ」の4種の置き場のどれかに属させる(§5)。同じ長さを複数箇所へ書き写さない。
6. **タッチは第一級入力。** すべての操作はタッチだけで完結できる。タップ最小寸法は44px。ホバーは
   装飾であり情報を持たない。この原則は DOM ボタンだけでなく画面投影のピック判定にも適用する
   (§6)。
7. **名前は責務を言い切る。** 実装から乖離した名前・多義的な名前・歴史的経緯を示す名前は見つけ
   次第改名する。改名は痕跡を残さない(「旧」「以前は」の類を書かない)。

## 2. トークン — UI の見た目とゲーム世界の色は別管理

**「HUD/パネル/ウィンドウ/ボタン/タッチ UI がどう見えるか」と「ゲーム世界そのものの色(マーカー・
演出・軌道線・船体)」は別の関心事であり、それぞれ別々に一元管理する。両者は互いを参照しない**
——UI 側がゲーム世界の色をたまたま流用するような近道を作らせないため。

### UI トークン

UI のデザイントークンは1箇所だけで定義し、他のあらゆる都合から独立している。持つもの:

- **色** — 基調のアクセント色(オレンジ系、`#ff6a00`)、警告色(危険な数値の読み上げとターゲット
  ロックの強調表示が共有する専用の赤系1色)、面と縁のグレー階調4段、文字色4段、アクセントの
  薄膜4段と縁2段、中立の薄膜4段、落とし影・全画面幕・ゲージ地色・グロー混合率。
- **文字サイズ8段**と書体。**マーカーのグリフサイズは文字サイズと独立した専用スケール**
  (グリフの見た目の大きさは字の読みやすさでなく形そのものにチューニングするため)。
- **角丸4段、余白6段、トランジション速度2段。**
- **タップ最小寸法**(`--hit-target-min`、44px)と**セーフエリア余白**(ノッチ・ホーム
  インジケータの回避)。
- **Δv 編集の軌道3軸色**(プログレード=青/ノーマル=緑/ラジアル=赤、`--axis-prograde`/
  `--axis-normal`/`--axis-radial`)——**これが唯一、DOM と 3D 描画の両方で同じ色を共有する
  トークン**。3D 描画にしか現れない色はここに置かない——複数箇所が同じ値であることを保証したい
  ときだけトークンへ上げる。

UI トークンは画面のどこからでも同じ名前で読めるよう、CSS のカスタムプロパティとして一括で
注入される(HUD の内側に限らない——タッチ操作用の仮想パッドは HUD の DOM 階層の外にあるが、
同じ変数を参照する)。

### ゲーム世界の色

ゲーム世界の識別色・演出色(方位マーカー・爆発/噴煙/弾・軌道線・船体、ステージ演出色)は UI
トークンとは別に一元管理する。UI の色をそこに置かず、そこの色を UI へ流用しない。

### 全体のトーン

**フラットな暗色基調** — ほぼ黒に近いパネルに1px の明るい縁取りだけを持たせ、影を使わない。

マーカーと軌道線も同じ規約に従う——**基調はモノトーン(自機軌道は薄灰、計画軌道は白、
プログレード/ボアサイトは薄灰)とし、注意を引く対象だけをオレンジで示す**(ターゲットマーカーと
その軌道、LEAD、ノード/BURN、弾薬)。**唯一意図された第二の色がシアン**(`#00c8ff`)で、
第二ターゲット専用(第二ターゲットの軌道線・敵一覧の行・マーカーの記号に使い、画面上でオレンジと
同時に出現しても混同しないよう選ばれている)。警告色の赤は、危険な数値の読み上げとターゲット
ロックの強調表示の**両方が共有する1色**で、2種類の赤を持たない。

**軌道3軸マーカー(プログレード/レトログレード/ノーマル/アンチノーマル/ラジアルイン・アウトの
記号)だけが、モノトーン+注意色の既定から明示的に外れて3色になる**——Δv 編集ギズモ(3D 矢印と
DOM パネルの数値入力)と同じ軸を指すマーカーが、ギズモと違う色で「どの軸か」を示すと読み違いの
もとになるため。新しいマーカーを追加するときはこの例外を広げない(モノトーン+注意色を既定の
ままにする)。

### 配色は選べる

設定メニューから配色(テーマ)を選択できる。選択は画面へ即座に反映され、次回起動後も保持される。
ゲーム世界側の表示のうち UI トークンを参照するもの(戦闘ターゲットの軌道線の強調表示など)も、
切り替えた配色に追従する。

### リテラル直書きの禁止

**HUD/タッチ UI/ポップアップの見た目は、必ずトークンを経由して組み立てる。** 直書きした色・
文字サイズ・角丸・余白・トランジションを残さない。書き分けの作法は `CODING-RULE.md` 1.12。

## 3. ウィジェット — 操作できる部品は10種に閉じる

**押せる/切り替えられる/入力できる DOM を自作しない。** 定義済みの10種の部品**以外**の対話要素
を新規に作らない。足りない振る舞いが要るときは、既存のどれかを拡張するか、新しい部品として同じ
語彙へ追加する。

| 部品 | 何をするか |
| --- | --- |
| ボタン | 単発クリック。点灯/無効の表示は呼び出し側が与える——ボタン自身は状態を反転しない。点灯型トグルもこのボタンに点灯状態を外から与える形で表現し、別の部品を持たない。 |
| トグルスイッチ | 見出し + ON/OFF のトラック+ノブ型スイッチ。2値専用。 |
| セグメントコントロール | 見出し + 排他選択ボタン列。**3択以上専用**(2値の ON/OFF には使わない)。同じ選択肢を渡し続けても作り直さない(押しかけの操作を消さないため)。「今どれでもない」状態(全消灯)も表せる。 |
| ホールドボタン | 押している間だけ真になる状態を持つ。呼び出し側が毎フレーム読む。 |
| 閉じるボタン | ✕ の閉じるボタン。専用の1実装だけを持つ。 |
| 値入力 | 数値/文字/検索入力の唯一の実装。下記の確定/破棄規約を持つ。 |
| メーター | HP/温度/電力などのバー。常に左から右へ満ちる。危険域は専用の警告色に切り替わる。 |
| タブバー | セグメントコントロールと同じ排他選択だが、パネルの表示面そのものを切り替える用途専用。 |
| スライダー | 範囲入力の唯一の実装。動くたびに即時通知する(値入力の確定契約とは別物)。 |
| 開閉トグル | 縦方向の開閉トグル。対象の表示/非表示を開閉状態で切り替える。閉じている向きの記号(▸)と開いている向きの記号(▾)を、縦方向の開閉すべてで共通に使う。 |

対話要素はすべて次の共通の下地の上に乗る:カメラドラッグへのクリック伝播を止める、タッチ環境
でだけ要素自身の寸法をタップ最小寸法まで広げる(マウス操作では間隔を保つため広げない、隣接
要素のヒット領域を侵す疑似要素の拡張もしない)、クリック後はポインタ操作ならフォーカスを外し
キーボード操作は残す。共通の見た目は、HUD の外(タイトル画面や仮想パッド)でも同じ部品を組める
ように、HUD 専用の場所に閉じない。

### 状態語彙は閉じた集合

**部品の状態は「点灯/選択」「押下中」「無効」の3つだけ。** 新しい状態名を増やさない(「選択中」
「有効」「保持中」に相当する別名を作らない)。ホバーは文字/縁がアクセント化するだけで、独自の
状態を持たない。

**「クリップ」はこの状態語彙に含まれない、プロパティウィンドウ(§4)だけが持つ固有の状態**
(📌 で「一時ウィンドウの排他枠から外れ、外側クリック/ESC で閉じなくなる」)。ピン留めが要る
対象はプロパティウィンドウだけであり、他の部品へこの概念を広げない。

### 確定/破棄の規約

**値入力は Enter=確定・Escape=破棄・blur=確定が唯一の規約。** 打鍵ごとの検証や通知は行わない
(編集途中の値を黙って書き換えないため)。**確定は前回確定した値から変わっているときだけ発火する**
——フォーカスして何も打たずに blur するだけの操作で、呼び出し側の状態(計画ノードなど)を編集
扱いにしない。Escape で戻す先は既定で「確定済みの値」——**「空にする」を選べるのは検索欄に限る**
(なんとなく Escape でクリアする挙動を他所へ広げないため)。数値欄で非数値・空欄のまま確定しよう
とした場合は破棄として扱う。

**唯一の例外は絞り込み入力**(打鍵ごとに一覧を再描画する必要がある検索欄)——確定でしか通知
しない値入力の契約とは別の要求のため、生の入力欄を使ってよい。新しい即時フィルタ入力を作る
ときも同じ形を踏襲する(ただしキー入力の伝播だけは必ず自分で止める、次項)。

### 入力欄は必ずキー入力の伝播を止める

ゲーム側はキー入力を画面全体で監視しているので、HUD の入力欄で伝播を止めなかった打鍵はそのまま
ゲーム操作になる(検索欄に `w` と打つと機体が噴射する)。テキスト・数値入力・スライダーはすべて
キー入力の伝播を止める——新しい入力系の部品を足すときもこれを踏襲する。

## 4. オーバーレイ — 重なりは一箇所が裁く

**モーダル・ポップアップ・ウィンドウは必ず共通の管理下に置く。** 重なり順(最前面が誰か)・ESC の
配送先・項目ショートカットの配送先・外側クリックでの自動クローズ・入力遮断は、この管理を経由
してのみ決まる。個々のオーバーレイが画面全体へ独自のキー入力・クリック監視を張ることはない
(唯一の例外は入力そのものを扱う層と、ゲーム開始前のタイトル画面)。

- オーバーレイは「モーダル」「ポップアップ」「ウィンドウ」の3種に分かれる。それぞれが宣言する
  4つの性質: ESC で閉じるか、外側クリックで閉じるか、開いている間ゲーム世界への入力を完全に
  遮断するか(遮断しないモーダルは、背後を覗き見させたい一時停止メニューのような用途)、排他
  グループ(同じ名前を持つオーバーレイは同時に1つしか開かない)。
- **ESC は最前面から、閉じられるオーバーレイを1つだけ閉じる。** 何も開いていなければ一時停止
  メニューを開く。
- **項目ショートカット(メニュー項目に割り当てたキー)も最前面から順に配送し、一致した
  オーバーレイが1つだけそれを実行する。** テキスト入力へフォーカスがある間はどこにも配送しない。

### ESC の意味は2つだけ

1. **入力欄にフォーカスがある間** — その欄の編集を破棄する。
2. **それ以外** — 最前面のオーバーレイを閉じる。何も開いていなければ一時停止メニューを開く。

ESC の振る舞いはこの2つに固定し、個々のオーバーレイが独自の ESC 判断を持たない。

### コンテキストメニュー = 使い捨て、プロパティウィンドウ = 継続観察

**その場で1つ選んだら消えるコンテキストメニュー**(ESC・外側クリックで閉じる、入力は遮断しない)
と、**対象を継続観察・操作するプロパティウィンドウ**(ドラッグで動かせ、📌 でクリップして常設
できる)は役割が異なる。**同じ対象への右クリックは、戦闘ビューかマップかを問わず必ずプロパティ
ウィンドウを開く。** コンテキストメニューが残るのは、プロパティを持たない空域への右クリックだけ。
新しい右クリック対象を追加するときも、プロパティを持つ対象(艦・天体・基地・ノードなど)は必ず
プロパティウィンドウ、プロパティを持たない対象だけコンテキストメニューに倒す。

プロパティウィンドウの一時ウィンドウ(📌 されていないもの)は高々1枚——新しく開いた/クリップを
外したウィンドウが前の一時ウィンドウを追い出す。同じ仕組みで、系のモーダル(ヘルプ・一時停止・
セーブブラウザなど)は同じ排他グループに属し、同時に1つしか開かない。

## 5. レイアウト — 置き場4種

**画面上の全パネル/オーバーレイは、次の4種のどれか1つに属する。**

1. **レール** — マップ系パネルの縦積み。中身は通常の縦フローで積み、絶対座標を持たない。畳める。
   マップビューと戦闘ビューはそれぞれ自分専用の左右一対のレールを持ち、片方を畳んでも表示中で
   ない側のレールには影響しない。
2. **常設計器**(戦闘ビュー専用のレール)——艦のステータス/軌道情報/ターゲット情報/敵一覧の
   常設パネルが並ぶ(§8)。レールと同じ縦フロー・畳み規則(レール単位・パネル単位の二段)に
   従うが、各パネル自身の高さに上限がかかる点が異なり、超えた分はパネル内スクロールになる
   (上限値はブレークポイントごとに再定義される、この置き場固有の寸法)。戦況を隠しすぎない
   よう、狭い/低い画面でも一定高さに収まる。
3. **中央モーダル** — 画面全体を覆う/画面中央に寄せる全画面 UI(ドックビュー・セーブブラウザ・
   結果画面・ヘルプ・一時停止メニューなど、§8)。
4. **画面固定バッジ** — ①②のいずれにも属さない、置き場を持たない単発の表示(ビュー切替
   バッジ・全体ステータスバー・マップのスケールバー・視点リセットの案内・ヒント・トースト、
   §8)。

**絶対座標(上下左右の固定位置)の直書きが許されるのは、置き場に参加しない④画面固定バッジと、
③中央モーダルの中央寄せそのものだけ。** ①②に乗るパネル自身は通常のフローに従ったままで、
置き場のコンテナ側だけが絶対座標を持つ。ある要素をどの種に属させるか迷ったら、「動かせる/
畳める/レイアウトに参加すべきか」で判断する——参加すべきなら①か②、一点固定でよいものだけ④。

### ブレークポイント

幅は「コンパクト」(700px未満)/「中間」(700〜1100px)/「ワイド」(1100px超)の3クラス、
「粗いポインタ」(タッチなど)/「低い」(高さ500px未満)の2軸を直交として持つ。

レール幅・戦闘パネル高さ上限のように、ブレークポイントごとに値が変わる寸法がある
(`--rail-w-left`/`--rail-w-right`/`--combat-panel-max-h`)。閾値と寸法をどこに定義し、
参照側がどう読むかは `CODING-RULE.md` 1.12。

### 表示/非表示と折りたたみは別軸

**ゲーム状態由来の表示/非表示**(自機が無い、戦闘ビューでない、ターゲットが無い、など)と、
**利用者自身の折りたたみの選択**は別軸で扱い、互いを上書きしない。折りたたみの選択は永続化
され、次回起動後も保持される。**隠れている間に折りたたみを変更しても、再表示時にその状態の
まま出てくる。**

### ビューポート変化への追従は1箇所へ集約する

画面回転・アドレスバー伸縮・仮想キーボードでの再配置が要る要素(ドラッグ可能なウィンドウ・
ポップアップの再クランプなど)は、一元管理された実効ビューポート高さとセーフエリア変数
(`--vvh`/`--safe-t`/`--safe-r`/`--safe-b`/`--safe-l`)を参照する。3D 描画の解像度合わせは
レイアウトの関心事ではないので対象外。

## 6. タッチ — 第一級入力

すべての操作はタッチだけで完結できる。ジェスチャの合成規約: 長押し=右クリック相当、二本指
ドラッグ=パン、指の間隔の変化(ピンチ)=ズーム、ダブルタップ(またはブラウザ標準のダブル
クリック)=ダブルクリック相当。マウス由来のクリックとタッチ由来の合成クリックは同じ扱いで、
どちらが発生源かで振る舞いは変わらない。長押し中は押している位置に視覚的なフィードバック
(リング)を出す。

タップターゲットは最小44px(`--hit-target-min`)。タッチ環境でだけ、要素自身の寸法でこの最小
寸法を確保する(マウス操作では間隔を保つため広げない、隣接要素のヒット領域を侵す疑似要素の
拡張もしない——タッチ環境で行/列が伸びるのは正しい挙動として許容する)。**この原則は DOM
ボタンだけでなく画面投影されたピック判定にも適用する**——マップ上のオブジェクト・ノード・
軌道昇交点/降交点アイコンなど、画面へ投影してから距離でヒット判定するあらゆる箇所は、主たる
ポインタが粗い(タッチ)かどうかでピック半径を切り替える。

**ホバーは装飾であり情報を持たない。説明をホバーだけに依存させない**(タッチではホバーを読め
ない)。ボタンの意味・キー割り当ては常に可視のラベル文字列で示す。

## 7. やってはいけないことの一覧

1. **表示の有無や開閉を、見た目のプロパティを直接比較して判定する。** 状態は必ず状態そのもの
   (クラスの付け外し)で持つ(§1原則2)。
2. **画面全体へ独自のキー入力・クリック監視を張る**(入力そのものを扱う層と、ゲーム開始前の
   タイトル画面を除く)。
3. **生の対話要素の自作**(定義済み10種の部品の内部実装と、ファイルピッカー用の隠し入力、
   絞り込み入力(§3 の唯一の例外)を除く)。
4. **旧状態語彙**(「選択中」「有効」「保持中」に相当する状態名を新設して使う)。

ゼロ件であることを変更のたびに保つ。書き方の側の禁止事項(リテラル直書き・裸の `vh`・
ブレークポイント値の直書き)は `CODING-RULE.md` 1.12 が持つので、そちらも併せて当てる。

## 8. HUD の画面・パネル一覧

### 常設パネル(戦闘ビュー)

いずれも自機が存在しない間は畳まれる。

- **艦のステータス**(右レール) — RCS制動/並進出力/微調整/進行方向ホールド/視点のRCS追従/
  弾薬の各行を表示する。常時表示の操作ボタンとして再装填/進行方向リセット/視点のRCS追従切替/
  ターゲット選択を持つ(いずれもキー割り当て済み)。タッチ環境でのみ、スロットル1〜4を選ぶ
  専用の操作列が追加で表示される。
- **軌道情報**(左レール) — 自機の基準天体/高度/速度/遠地点(AP)/近地点(PE)/軌道傾斜角
  (INC)/周期(PRD)/動圧/機体温度を表示する。マップビューでは畳まれる。**天体・艦・基地など
  任意対象の軌道要素は、右クリックで開くプロパティウィンドウの「軌道」欄に一本化されており、
  この常設パネルに重複して出さない。**
- **ターゲット情報**(右レール、ロック時のみ表示) — 戦闘ターゲットをロックしている間だけ表示
  する。対象名/装甲/距離/接近速度/相対速度のみを表示し、**軌道要素と相対軌道傾斜角はここに
  出さない**(プロパティウィンドウを見るよう促す案内行を末尾に持つ)——ターゲットの全情報が
  読める場所を1つに保つための切り分け。
- **敵一覧**(右レール) — 生存中の敵を距離順に列挙する。同じ波(ウェーブ)に属する敵は
  「第N波 ×件数」の1行にまとめ、その波の最も近い個体の距離で表示する——大量発生する波状攻撃
  でも1隻ごとの行に埋もれない。見出しに出撃数/撃破数のバッジを持つ。

### 常設バッジ・スケール

- **全体ステータスバー** — 自機の有無に関わらず常時表示する。経過時間(MET)/時間加速倍率/
  ノードへの自動ワープ状態を示す。
- **マップのスケールバー** — マップビューで、カメラの現在の注視深度における画面上の距離の
  目安(定規)を表示する。ズームに追従し、同じ天体に注視点を保っている限りパンだけでは目盛りの
  読みは変わらない。
- **ビュー切替バッジ** — ゲームタイトル/バージョン、現在のモード名、現在のビュー(戦闘/
  マップ/ドック)を表示する。クリックで開くドロップダウンは、**現在のビューと、今遷移できない
  ビューを除いた選択肢だけ**を列挙する——選んでから拒否されることがない。

### モーダル

- **ヘルプ** — 操作の対応表を1つ持つ。**タッチジェスチャの行(長押し=右クリック相当/二本指
  ドラッグ=パン/ピンチ=ズーム/ダブルタップ=フォーカス移動)を先頭に、キーボードの行をその後に
  並べる**——タッチのみのプレイヤーも同じ表からすべての操作にたどり着けるようにするため。
- **一時停止メニュー** — 「一般」「描画」の2つのタブに分かれる。「描画」タブは画質・表示の
  オン/オフ設定に加え、デバッグ表示(開発用の描画バッファの中身を選んで確認する選択肢)を
  持つ。BGM 音量スライダーと「タイトルへ戻る」の操作を持つ。**開いている間もマップ/カメラの
  背景入力は素通りする**(完全な入力遮断はしない)——一時停止中でも見回しができる。他の全画面
  モーダルと同じ排他グループに属し、同時に1つしか開かない。
- **結果画面** — 勝利/敗北/スコアアタック終了を示す全画面表示。**ESC でも外側クリックでも
  閉じられない**——「再出撃」「タイトルへ」のどちらかの選択でしか離脱できない。

### 通知

**トースト**はステージ開始時のブリーフィングなど、ある程度の時間表示され続ける通知。**ヒント**
は操作が拒否された理由などを一時的に示す短いメッセージ。いずれも画面固定バッジの一種で、
レール/常設計器/中央モーダルのいずれにも属さない。

## 9. 判断に迷ったら

ここに定めのない判断(トグルの統合可否、置き場の帰属、色の例外を広げるかどうか)は、既存の
一貫性を優先する。それでも決まらない新しい論点は、ユーザーに確認してから進める(推測で進めない)。
