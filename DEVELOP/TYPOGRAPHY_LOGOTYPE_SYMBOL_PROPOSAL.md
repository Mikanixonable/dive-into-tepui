# タイポグラフィ・ロゴタイプ・記号体系 改修案

## 文書の位置づけ

本書は、`dive-into-tepui` の文字と記号を2020年代のWebゲームとして再設計するための提案である。
現行実装の説明ではなく、書体ライセンスの確定と実画面での比較を経て採否を決める設計案とする。
採用して実装した時点で、確定した規則を `DESIGN-RULES.md` と `theme.ts` へ移し、本書には候補比較と
移行記録だけを残す。

対象は次の4領域である。

1. タイトル、HUD、ウィンドウ、ラベル、数値表示の書体と組版
2. `Dive into Tepui` のロゴタイプとサブタイトル
3. UIアイコンとゲーム世界のマーカー記号
4. Webフォントの配信、ライセンス、容量、検証方法

---

## 1. 結論

全画面を等幅書体で統一する現行方式をやめ、用途ごとに声色を分ける。

| 系統 | ラテン文字・数字の本命 | 日本語の本命 | 担当する文脈 |
| --- | --- | --- | --- |
| Neutral Sans | Helvetica Now | 中ゴシックBBB | 通常UI、本文、ウィンドウ、主要タイトル |
| Editorial Serif | ITC Garamond Condensed | リュウミン | 古典性を出す副題、章扉、静かな説明画面 |
| Console Mono | IBM Plex Mono | 原則として通常和文書体、真の固定桁だけHackGen | CUI、ログ、座標、デバッグ、機器表示 |
| Symbols | 独自SVG | 独自SVG | アイコン、マーカー、照準、軌道上の点 |

書体は装飾テーマではなく、情報の文脈を表すものとして使う。通常画面は Helvetica 系と古典的な
和文ゴシックによるニュートラルな骨格を保ち、明朝・Garamond・等幅書体は意味のある場面にだけ
限定する。これにより、簡素でクールな通常UI、古典的なブランド表現、機械的な計器表示を同じ画面内で
混同せず共存させる。

商用書体の契約前に実装検証を始める場合は、次の無償構成を使う。

| 系統 | 無償の検証用構成 | 注意点 |
| --- | --- | --- |
| Neutral Sans | OSの Helvetica 系 + Zen Kaku Gothic Antique | WindowsではHelveticaの同一性を保証できない |
| Editorial Serif | Cormorant Garamond Light/Regular + Zen Old Mincho | Apple Garamondの完全な代替ではない |
| Console Mono | IBM Plex Mono + Zen Kaku Gothic Antique | 日本語を含む厳密な固定桁には使わない |
| Fixed-grid Console | HackGen Regular単独 | 真に2:1の欧文/和文幅が必要な画面だけに限定する |

無償構成を最終版として採用することもできるが、Helveticaの造形をブランドの中核に据えるなら、
`Arial` や新しいUI書体を「ほぼ同じもの」として扱わず、Helvetica NowのWebライセンスを本命とする。

## 2. 目指す印象

### 2.1 基本語彙

- **簡素** — 文字そのものを読ませ、発光、外枠、過剰な斜体、疑似未来文字で雰囲気を作らない。
- **古典的** — 1970〜1990年代の企業印刷物や初期デジタル製品に通じる、落ち着いた骨格を使う。
- **精密** — 数字、単位、軌道記号は桁が追いやすく、位置が不用意に揺れない。
- **選択的に機械的** — CUIらしさは、システムが話している場面にだけ現れる。
- **2020年代のWeb** — 小画面、可変サイズ、可変フォント、SVG、タッチ、フォント容量を前提にする。

### 2.2 避ける印象

- UD書体をブランドの主書体にした、説明的で公共サイン的なルック
- 全画面がプログラミングフォントで表示される、均質な「開発者ツール」感
- 9px前後の極小文字、広すぎる字間、細すぎる本文による疑似SF感
- ピクセル書体、OCR風書体、斜線入り数字を通常UIに広げたレトロフューチャー
- Unicode記号や絵文字のフォント差を、そのままアイコンデザインとして受け入れること
- Sans、明朝、Monoを、変化を付ける目的だけで同じ階層に混在させること

## 3. 現状と変更理由

現行の `FONT_FAMILY` は `JetBrains Mono`、`HackGen`、システム等幅の順で、HUD、タイトル、
ウィンドウ、通常本文までほぼすべてを等幅書体にしている。これは軌道値やコンソールには合うが、
画面全体に同じ機械音声を与え、タイトル、通常説明、機器出力の階層差を弱めている。

現行の文字サイズは9〜34pxの8段であり、9〜11pxが多くのラベルに使われる。高密度HUDであっても、
操作判断に必要な文字を9pxへ置く設計はやめ、11pxは補助情報の下限、12〜14pxをラベルの通常域、
14〜16pxを一般文の通常域にする。

現行ビルドのフォント出力は6ファイル、約7.9MBで、HackGenのBold WOFF2破損を補うためレガシー
WOFFも残っている。書体変更は造形だけでなく、フォント配信を整理する機会として扱う。

現行マーカーは「実体=塗り」「方向=矢印」「軌道上の点=中空」という良い意味分類を持つ一方、
`▲`、`⊙`、`◈`、`⬡` などのUnicode字形へ依存する。字面、ベースライン、線幅がフォントごとに変わる
ため、意味分類を保ったままSVGへ移す。

## 4. 書体システム

### 4.1 Neutral Sans — 通常UIの標準語彙

#### ラテン文字と数字

本命は **Helvetica Now** とする。Helveticaの中立性を保ちながら、小サイズ用 `Micro`、本文用
`Text`、見出し用 `Display` を持つため、同じ骨格のまま表示サイズに合わせた選択ができる。
可変版を契約できる場合は、ウェイト、字幅、オプティカルサイズを1ファイル内で運用する。

- タイトル: Helvetica Now Display、400を基準。背景が静かな場合だけ300を許可する。
- ウィンドウ題名: Helvetica Now Text、500。
- 一般文: Helvetica Now Text、400。
- 小ラベル: Helvetica Now Micro、500。
- 数値: 使用中のサイズ系統を維持し、`tabular-nums` と `lining-nums` を有効にする。

数字だから自動的に等幅書体へ切り替えない。通常の速度、距離、HP、日時はHelveticaの表形式数字を
使い、コンソールまたは計器という文脈があるときだけMonoへ切り替える。

#### 日本語

本命は **中ゴシックBBB** とする。字面がやや小さく、かなに伝統的な抑揚があり、現代UD書体の
均一で大ぶりな印象から距離がある。本文、小見出し、キャプションを一書体で安定して組める。

中ゴシックBBBは一つの太さを個性として使い、擬似Boldで階層を作らない。日本語の強調は、サイズ、
色、余白、罫線で作る。より太い日本語が不可欠な場面は、別書体を即時追加せず、まず中ゴシックBBBの
実画面で判断する。

無償の検証用には **Zen Kaku Gothic Antique** を使う。古典的かつオーソドックスな字形を持ち、
OFLで自己配信できる。これはライセンス確定前の有力候補だが、中ゴシックBBBと同一の見た目ではない。

#### 推奨スタック

商用構成の概念例:

```css
--font-ui:
  "Helvetica Now Text", "Helvetica Neue", Helvetica, Arial,
  "A P-OTF Gothic BBB Pr6N", "Hiragino Kaku Gothic ProN", "Yu Gothic",
  sans-serif;
```

無償検証構成の概念例:

```css
--font-ui:
  "Helvetica Neue", Helvetica, Arial,
  "Zen Kaku Gothic Antique", "Hiragino Kaku Gothic ProN", "Yu Gothic",
  sans-serif;
```

実際のCSSファミリー名は納品されるWebフォントの仕様に合わせる。OSにHelveticaが存在することを
最終版の前提にはせず、Windows、Androidを含む同一性が必要なら必ずWebフォントを配信する。

### 4.2 Editorial Serif — 古典性を加える副語彙

#### ラテン文字

本命は **ITC Garamond Condensed Light / Book** とする。Appleが1984〜2002年頃に用いた
Apple Garamondは、ITC Garamondを約80%幅に凝縮し画面向けに調整した系統であり、求める
「90年代のApple製品に見られる細い古典的なラテン文字」の直接的な参照になる。

ただし、Apple Garamondそのものを出所不明のファイルから取得して同梱しない。正規に提供されている
ITC Garamond Condensedを契約するか、無償検証では **Cormorant Garamond Light / Regular** を使う。
無償書体をCSSの横圧縮で似せることはしない。横画・縦画・セリフまで歪むためである。

使用箇所は短い副題、章名、ロード画面の一文、エンディング、静かな説明画面に限る。HUDの一般文、
ボタン、警告、数値には使わない。細いウェイトは原則24px以上とする。

#### 日本語

本命は **リュウミン L / R** とする。本文から見出しまで使える標準的な明朝で、活字由来の古典性を
持ちながら奇抜ではない。ラテン側がGaramondになる場面の日本語副題、章扉、短い叙述に使う。

無償検証には **Zen Old Mincho Regular** を使う。通常UIを明朝へ置き換えるのではなく、Sansの画面に
一箇所だけ静かな対比を作る。

概念例:

```css
--font-editorial:
  "ITC Garamond Std Condensed", "Cormorant Garamond", Garamond,
  "A P-OTF Ryumin Pr6N", "Hiragino Mincho ProN", "Yu Mincho",
  serif;
```

### 4.3 Console Mono — 機械が話す場面

本命は **IBM Plex Mono** とする。企業機器・研究機関・初期コンピューティングに通じる背景を持ち、
JetBrains Monoよりも「コードエディタ専用」の印象が弱い。OFLで自己配信できる。

使ってよい場面:

- システムログ、通信ログ、コマンド入力、デバッグ表示
- 生のECI座標、エフェメリス時刻、診断コード、ファイル形式のプレビュー
- 桁位置そのものが意味を持つ表、チェックサム、ID
- 機体内の端末を演出する専用画面

使わない場面:

- 通常のボタン、ウィンドウ題名、ヘルプ本文
- 単に数字が含まれるだけのHUD値
- ブランドロゴ、ステージタイトル、勝敗画面

日本語を含む「CUI風の文章」はIBM Plex Monoのラテン文字と通常和文ゴシックを組み合わせてよい。
実際に全角1文字=半角2桁の固定グリッドが必要な場合だけ、欧文と和文を一体設計したHackGen Regularを
その領域全体に適用する。現行HackGenのBoldは使用せず、パッケージの壊れたWOFF2を継承しない。

```css
--font-console:
  "IBM Plex Mono", "Zen Kaku Gothic Antique", "Hiragino Kaku Gothic ProN",
  monospace;

--font-console-grid:
  "HackGen", monospace;
```

### 4.4 書体選択の順序

書体は次の順で決める。

1. **文脈** — Neutral / Editorial / Console のどれか。
2. **表示サイズ** — Display / Window / Body / Label のどれか。
3. **文字種** — ラテン、数字、日本語のどのフォールバックが字形を担当するか。

文字種から先に決めない。「数字だからMono」「日本語だから常に同じゴシック」という運用を避ける。

## 5. サイズと組版

現在の `FONT_XXS`〜`FONT_3XL` の物理サイズ名だけでは用途が分からないため、実装時は意味名の
ロールトークンを追加する。既存サイズトークンを直ちに全廃せず、移行中はロールから物理サイズを参照する。

| ロール | 推奨サイズ | 行高 | 標準ウェイト | 主用途 |
| --- | --- | --- | --- | --- |
| Brand XL | `clamp(40px, 7vw, 72px)` | 0.95〜1.05 | Sans 400 / Serif 300〜400 | タイトル、ロゴ表示 |
| Display L | `clamp(28px, 4.5vw, 48px)` | 1.05〜1.15 | 400 | ステージ名、結果見出し |
| Window | 14〜16px | 1.25〜1.4 | Latin 500 / Japanese 400 | ウィンドウ・パネル題名 |
| Body | 15〜16px | 1.55〜1.75 | 400 | 説明、ヘルプ、会話、設定 |
| HUD | 13〜14px | 1.35〜1.5 | 400〜500 | 常設HUD、短い値と名称 |
| Label | 12〜13px | 1.25〜1.4 | 500 | 軸名、単位、短い補助語 |
| Micro | 11px | 1.25〜1.35 | 500 | 非操作的・補助的な短文のみ |

### 5.1 サイズ運用

- 9pxと10pxを新規UIに使わない。既存箇所はLabelまたはMicroへ統合する。
- 長文は16pxを基準にし、ゲームHUDの密度が必要な箇所だけ13〜14pxへ下げる。
- 明朝と細いGaramondは24px未満で使わない。長い本文へ使う場合はRegularを選ぶ。
- モバイルでタイトルを単純縮小せず、`clamp()`と専用改行で構図を維持する。
- 文字が収まらない場合、最初に文言、レイアウト、幅を見直し、最後の手段としてサイズを下げる。

### 5.2 字間

- `TEPUI` のHelvetica見出し: `-0.03em`〜`0`を比較し、文字ごとにカーニングを確認する。
- 小さな英大文字ラベル: `0.06em`〜`0.10em`。現行の固定2.5pxのような過大な字間をやめる。
- 日本語本文: `0`。日本語へ欧文と同じトラッキングを適用しない。
- 日本語の短いタイトル: 最大`0.04em`。空けること自体を未来感の表現にしない。
- CUI: 原則`0`。等幅セルをletter-spacingで壊さない。

### 5.3 数字と単位

通常の数値表示は次を基本とする。

```css
font-variant-numeric: tabular-nums lining-nums;
```

- 桁が更新される値は表形式数字、文章中の数字は比例数字を選べる。
- マイナスはハイフン `-` ではなくマイナス記号 `−`、乗算は `×` を使う。
- 単位は値より1段小さくしてよいが、11px未満にしない。
- `km/s`、`m/s²`、`Δv`、`Ω`、`ω`、`μ` を候補書体すべてで実測する。
- 小数点、コロン、斜線、括弧の位置がラテンと日本語のフォールバック境界で跳ねないか確認する。

## 6. 文脈・サイズ・文字種の適用表

| 表示 | ラテン文字 | 数字 | 日本語 | 記号 |
| --- | --- | --- | --- | --- |
| メインロゴ | Helvetica Now Display | 原則使わない | ロックアップ外の副題だけ | 独自SVGのみ |
| ステージタイトル | Helvetica Now Display | 同じSans | 中ゴシックBBB、静かな章扉だけリュウミン | 必要最小限 |
| 古典的な副題 | ITC Garamond Condensed | 比例数字 | リュウミン | セリフ書体内の約物 |
| ウィンドウ題名 | Helvetica Now Text | 同じSans | 中ゴシックBBB | SVGアイコンを併置可 |
| 一般文・ヘルプ | Helvetica Now Text | 比例数字 | 中ゴシックBBB | 文字として必要な約物だけ |
| HUD値 | Helvetica Now Micro/Text | 表形式数字 | 中ゴシックBBB | 単位・数学記号は文字 |

警告や危険状態は書体を変えず、色、アイコン、文言で表す。危険時だけ太い・斜体・等幅へ変えると、
状態変化によって文字幅が動き、読み取りを妨げる。

## 7. ロゴタイプ

### 7.1 正式表記

ブランド名の正式なラテン表記は **DIVE INTO TEPUI** とし、ロゴでは全大文字を基本とする。
文章内の製品名は `Dive into Tepui` と書ける。`TEPUI` を主語、`DIVE INTO` を導入句として階層化する。

```text
DIVE INTO
TEPUI
```

### 7.2 Primary Lockup

- `TEPUI`: Helvetica Now Display Regular、ロゴ全高の約72%。
- `DIVE INTO`: Helvetica Now Text Medium、`TEPUI` の約22〜26%の文字高、`0.12em`前後の字間。
- 左端を基本として揃え、`DIVE INTO` の行幅を無理に `TEPUI` と一致させない。
- `TEPUI` は既定カーニングから始め、`TE`、`EP`、`PU`、`UI` の4組だけを目視調整する。
- 文字を切断する、`E`を三本線アイコンにする、`I`を軌道線にする、といった恒久的な改変はしない。
- オレンジは文字全体ではなく、短い基準線、点、ステージ番号など二次要素に限定する。
- 白地は黒、暗色地は白の単色を正本にする。グロー、押し出し、グラデーションを正本へ含めない。

### 7.3 Heritage Lockup

90年代Appleの印刷物を思わせる静かな変化が必要な画面では、`TEPUI` をHelveticaのまま保ち、
`DIVE INTO` または一行の英語副題だけをITC Garamond Condensed Lightへ替える。ブランドの中心まで
Garamondへ替えないことで、通常版と同じ製品だと分かる。

日本語副題を添える場合はリュウミンRを使う。英語Garamondと日本語明朝を同じ行で細かく混植せず、
別行に分けてベースラインと行間を設計する。

### 7.4 最小表示と余白

- 横組みロックアップの最小幅: 144px。
- 144px未満では `TEPUI` 単独の簡略版を使う。
- 周囲の最小余白 `X` は `DIVE INTO` の大文字高とする。
- favicon、アプリアイコン、16〜32pxの表示に文字ロゴを縮小しない。専用のシンボルを別途設計する。

### 7.5 ロゴの納品形式

表示の同一性を保つため、確定ロゴはテキストではなく最適化したSVGパスとして納品する。ただし、
Webフォント契約とロゴへのアウトライン利用は同じ権利とは限らない。採用書体のDesktop/Logo利用条件を
確認してからアウトライン化し、元フォントファイルをリポジトリへ置かない。

## 8. 記号とアイコン

### 8.1 三つの記号層を分ける

1. **UI icon** — 閉じる、保存、展開、照準、設定など、操作を示すSVG。
2. **World marker** — 実体、方向、軌道上の点を示すゲーム固有SVG。
3. **Typographic symbol** — `Δv`、`−`、`×`、`°`、`Ω`など、文章・数式の一部として組む文字。

アイコンフォントは導入しない。フォントの読み込み失敗が操作記号の欠落へ直結し、SVGよりも線幅、
色、アクセシビリティ、複数サイズの制御が難しいためである。

### 8.2 UI iconの造形規則

- 正本は `viewBox="0 0 24 24"` のSVG。
- 基本ストロークは1.5、強調状態は色または面で示し、線幅を頻繁に変えない。
- 直線はsquare cap、幾何形はmiter joinを基本とし、自然な曲線だけround joinを使う。
- 16px表示では専用の簡略パスを許可し、24px版を機械縮小して細部を潰さない。
- 塗りつぶしは選択中、危険、実体のいずれかに意味を持つ場合だけ使う。
- 装飾目的の斜線、二重枠、六角形をすべてのアイコンへ付けない。
- アイコン単独の操作には可視ラベルまたはアクセシブル名を付ける。SVG自体は原則`aria-hidden`。
- ヒット領域44pxと見た目の24pxを分離する。

### 8.3 World markerの意味体系

現行の意味分類は維持し、Unicode字形だけを置き換える。

| 族 | 造形規則 | 例 |
| --- | --- | --- |
| 実体 | 中心を持つ塗り形 | 船=楔、天体=円、弾薬=切欠き付き四角 |
| 方向 | 軸または鏃を持つ | 方位矢印、ターゲット方向、法線方向 |
| 軌道上の点 | 中空の閉形 | 遠近点=菱形、AN/DN=上下三角、ノード=二重菱形 |
| 予測・ゴースト | 破線または開いた形 | 予測船、ゴースト位置 |
| 危険・衝突 | 交差または欠損 | 衝突点、再突入、遮蔽 |

具体的な再設計:

- `▲` ship: 上向き文字ではなく、機首方向を持つ左右対称の楔形SVG。
- `⊙` / `⊗` prograde/retrograde: 同径の円に点/十字を組み、線幅と中心位置を共通化する。
- `◎` / `◉` radial: prograde族と混同しないよう、外円に短い放射目盛を加える。
- `△` / `▽` AN/DN: 同じ三角を回転した対として作り、ラベルなしでも対だと分かるようにする。
- `◇` apsis: 正方形を45度回転した単純な中空形。AP/PEは隣接ラベルで区別する。
- `◈` maneuver node: apsisの内側に小円を加え、同じ族の上位概念として見せる。
- `⬡` burn point: 六角形に短い進行方向ノッチを加え、単なるSF装飾の六角形にしない。
- `✕` impact: 2本線の交差に外側の警告弧を加え、閉じるアイコンとの混同を避ける。

色は現行の「モノトーン基調 + 注意対象だけオレンジ」と軌道3軸色の例外を維持する。形だけでも族を
識別でき、色だけでも状態を補助できる二重符号化にする。

### 8.4 タイポグラフィ記号

文章や数式の一部である記号はSVGへしない。`Δv`、`Ω`、`ω`、`μ`、`±`、`−`、`×`、`°`は周囲の
書体で組み、ベースラインとウェイトを合わせる。絵文字表示になり得る記号、装飾的な星、色付き絵文字を
UIアイコンとして使わない。

## 9. デザイントークン案

物理サイズだけでなく、書体の役割をトークンにする。

```css
--font-ui: ...;
--font-ui-display: ...;
--font-editorial: ...;
--font-console: ...;
--font-console-grid: ...;

--type-brand-xl-size: clamp(40px, 7vw, 72px);
--type-display-l-size: clamp(28px, 4.5vw, 48px);
--type-window-size: 15px;
--type-body-size: 16px;
--type-hud-size: 14px;
--type-label-size: 12px;
--type-micro-size: 11px;
```

実装では `theme.ts` を唯一の定義元とする現行規則を維持する。`FONT_FAMILY` 一つを全用途へ使う方式を、
`FONT_FAMILY_UI`、`FONT_FAMILY_DISPLAY`、`FONT_FAMILY_EDITORIAL`、`FONT_FAMILY_CONSOLE` の役割へ
分ける。CSS側も `--font-ui` などを読む。

太さも `400`、`500`、`700` の数値を各CSSへ散在させず、採用書体が実際に持つウェイトだけを
トークン化する。存在しないウェイトの合成を見逃さないよう、検証時は `font-synthesis: none` を使う。

## 10. Webフォント配信とライセンス

### 10.1 基本方針

- 外部CDNへの実行時依存を増やさず、原則として自己配信する。
- WOFF2だけを配信し、WOFF、TTF、OTFを本番バンドルへ含めない。
- UI Sansを初期読込し、EditorialとConsoleは使用画面に応じて遅延読込する。
- ラテンは必要な文字セットへサブセットし、日本語はライセンスが許す配信方式を使う。
- 日本語を静的サブセットする場合、固定UI文言だけでなくユーザー入力名、単位、記号、保存データの表示を
  含めて欠落方針を決める。任意入力文字はシステムフォールバックを許容する。
- UI本文は `font-display: swap`。確定ロゴはSVGなので、ロゴ表示をフォント読込へ依存させない。
- 初期画面で取得するフォントは5ファイル以下、合計3.5MB以下を目標とする。
- 全ルートで取得するフォント総量は5MB以下を目標とする。

### 10.2 ライセンス確認項目

| 用途 | 必要な確認 |
| --- | --- |
| 通常のWeb表示 | 配信ドメイン、月間PV、自己ホスト可否、CDN指定 |
| GitHub Pages等の公開 | 登録可能なドメイン、ステージングURLの扱い |
| PWA・オフライン | Webライセンスでキャッシュ/埋め込みが許されるか |
| 将来のアプリ化 | App/Game embeddingライセンスが別途必要か |
| SVGロゴ | アウトライン化、商標・ロゴ利用、改変の可否 |
| サブセット | フォント改変、文字削除、WOFF2変換の可否 |
| リポジトリ | 公開リポジトリへフォントバイナリを置けるか |

Helvetica Now、ITC Garamond、中ゴシックBBB、リュウミンは、購入したDesktopフォントをそのまま
Webへ同梱できるとは限らない。Web、ロゴ、アプリ、サブセットを別の利用形態として確認する。

OFL書体もライセンスファイルと著作権表示を配布物へ残し、改変版へ予約名を使わない。法的判断が必要な
箇所は提供元の契約文を正とする。

## 11. 実装計画

### Phase 0 — 書体見本と契約判断

1. 実際のゲーム文言を使う比較ページを作る。
2. 商用本命と無償構成を、同じサイズ・行高・色で切り替えられるようにする。
3. Helvetica Now / 中ゴシックBBB / ITC Garamond Condensed / リュウミンの見積と利用条件を確認する。
4. 本番を商用構成にするか、無償構成にするか決定する。

比較ページには最低限、次を含める。

```text
DIVE INTO TEPUI
ORBIT / TARGET / MANEUVER / APPROACH
0123456789  00:19:42  −12.4°  7.50 km/s  Δv  Ω  ω  μ  ×4
軌道要素　近点高度　目標への接近速度　マニューバ実行まで
吾輩は猫である。名はまだ無い。宇宙船は地球の影へ入った。
```

### Phase 1 — 意味トークンの導入

1. `theme.ts` に4つの書体ロールと意味サイズを追加する。
2. `FONT_*` の既存利用を、画面単位で意味ロールへ移す。
3. HUD本文をNeutral Sansへ変更し、CUI対象だけ明示的なクラスでMonoへ戻す。
4. 9〜10pxの既存箇所を列挙し、Label/Microへ統合する。
5. `DESIGN-RULES.md` に確定した書体選択規則と禁止事項を移す。

主な変更対象:

- `src/main.ts`
- `src/game/theme.ts`
- `src/game/hud/skeleton-style.ts`
- `src/game/hud/panel-content-style.ts`
- `src/game/input/touch.ts`
- `src/game/stage-select.ts`
- `DEVELOP/DESIGN-RULES.md`

### Phase 2 — ロゴタイプ

1. Primary / Heritage / TEPUI単独の3ロックアップを実寸で比較する。
2. カーニングと和文副題の位置を確定する。
3. ライセンス確認後にSVGパスへ変換する。
4. ローディング、ステージ選択、結果画面へ同じアセットを使う。
5. favicon/アプリアイコン用の独立シンボルは、文字ロゴ確定後に設計する。

### Phase 3 — 記号のSVG化

1. `marker-glyphs.ts` の意味キーと3族分類を維持する。
2. 文字値をSVGパス定義またはSVGアセットIDへ段階的に置き換える。
3. UI iconとWorld markerを別ディレクトリ、別APIにする。
4. 16 / 24 / 32pxと、画面投影用の実寸で線幅を検証する。
5. 記号名、ラベル、`aria-label`を字形から独立させる。

### Phase 4 — 配信最適化

1. 使用ウェイトと文字集合を確定する。
2. WOFF2のみを出力し、現行HackGenパッケージ由来の壊れたBoldとWOFFを除く。
3. 初期UI、Editorial、Consoleのロード境界を分ける。
4. `document.fonts.check()` と実測幅で、フォールバックや擬似ウェイトを検出する。
5. リリース検証へフォントファイル数、転送量、形式の上限を追加する。

## 12. 検証基準

### 12.1 画面

- 375×667、667×375、768×1024、1280×720、1440×900で確認する。
- macOS Safari/Chrome、Windows Chrome/Edge、Android Chromeで確認する。
- 100%、125%、150%、200%ズームで、文字切れとパネル重なりがない。
- フォント読込前後でボタン幅やHUDの位置が大きく跳ねない。
- タイトル、ウィンドウ、本文、ラベル、CUIの5階層を、色を消しても見分けられる。

### 12.2 文字

- ラテン大文字・小文字、数字、ひらがな、カタカナ、常用漢字、ゲーム固有語を確認する。
- `I/l/1`、`O/0`、`S/5`、小数点、コロン、マイナス、斜線を実値表示で確認する。
- 日本語の句読点、括弧、長音、促音が小サイズで痩せない。
- `Δv`、ギリシャ文字、上付き2、度記号が別フォントへ不自然に落ちない。
- `font-synthesis: none` の状態で、必要ウェイトがすべて読める。
- 固定桁Consoleでは、半角2文字と全角1文字の幅を実測する。

### 12.3 記号

- 記号だけで「実体・方向・軌道点」の族を判別できる。
- モノクロ表示でも、選択、危険、無効の状態が形または付加要素で分かる。
- 16pxで線が欠けず、24pxで意図しない太さにならず、高DPIでぼけない。
- マーカーの見た目サイズと44pxのタッチ判定が独立している。
- 閉じる、衝突、ターゲット解除など、似た交差記号を取り違えない。

### 12.4 完了条件

- 通常UIがMonoに依存せず、Console用途だけがMonoを明示している。
- 9〜10pxの操作・判断用テキストが残っていない。
- ロゴが1つのSVGアセットから全画面へ供給される。
- World markerがUnicode字形のフォント差へ依存しない。
- 本番で使用する全フォントのライセンス、ファイル、ウェイト、ロード元が一覧化されている。
- 初期フォント5ファイル/3.5MB、全体5MBの目標を満たすか、超過理由が記録されている。
- `DESIGN-RULES.md` と `theme.ts` が確定した規則を反映している。
