# 05. UI・入力・基準座標系

<p align="center">
  <img src="../.github/readme/orbital-ui.svg" alt="慣性系と回転系を切り替える軌道 UI" width="100%">
</p>

Dive into Tepui の UI は、一般的な「ゲーム HUD」に加えて、**軌道・座標系・予測時間・注視対象を操作する計器**としての役割を持ちます。このため、UI、入力、カメラ、基準座標系を一緒に読むと全体像が掴みやすくなります。

## 1. UI は2層ある

### 共通 UI

`src/hud/` はゲーム意味をできるだけ持たない UI の器です。

- HUD ルート
- オーバーレイ
- ウィンドウ
- ウィジェット
- パネル
- ドラッグ
- モーダル
- レイアウト
- 数値整形

などを扱います。

### ゲーム固有 UI

`src/game/hud/` は、

- 軌道情報
- 操作対象
- ターゲット
- マニューバー
- 座標系
- 建造
- ステージ固有表示

など、ゲームの意味を知る UI です。

## 2. なぜ分けるか

例えば「ドラッグ可能なウィンドウ」は共通部品です。

一方「軌道要素を表示するウィンドウ」はゲーム固有です。

この2つを同じ場所へ書くと、共通 UI が軌道力学やステージを import し始め、再利用も境界も崩れます。

## 3. Input は生の入力を集める

`src/input/input.ts` は、ブラウザから来るキーボード・マウス・タッチ入力を集約します。

ここでは、

- 押下中キー
- 押した瞬間
- クリック
- ダブルクリック
- 右クリック
- ドラッグ
- パン
- ホイール
- ピンチ
- ロール
- 長押し

を扱います。

### Input はゲーム意味を知らない

Input 自身は「T はターゲット切替」とは知りません。

知っているのは物理的なキーコード・ポインタイベントです。

## 4. エッジ入力と連続入力

入力には2種類あります。

### 連続

押している間ずっと効くもの。

- 推力
- 姿勢操作
- カメラ回転
- Δv 長押し調整

### エッジ

押した瞬間だけ効くもの。

- ビュー切替
- ターゲット切替
- ポーズ
- 射撃トリガ
- ノード削除

これらを同じ「isDown」で扱うと、一回押したつもりの切替が毎フレーム連打されます。

## 5. ポインタ操作

マウスとタッチは完全に同じ入力ではありません。

Input は、

- 左ドラッグ
- 右クリック
- 中ボタンパン
- 二本指パン
- ピンチズーム
- 二本指回転
- 長押し
- ダブルタップ

をブラウザイベントから共通の操作量へ変換します。

## 6. フォーカス喪失

ゲーム入力では「keyup が届かない」問題が重要です。

ブラウザがフォーカスを失ったり、macOS の Command 操作を挟んだりすると、キーが押しっぱなしとして残る場合があります。

Input は、

- blur
- pagehide
- visibilitychange

などで押下状態を解除し、操作が暴走しないようにします。

## 7. GameInputRouter

`src/game/input/game-input-router.ts` は、生入力をゲーム機能へ優先順位付きで配ります。

各機能は `GameInputPort` として、

- 有効条件
- 連続操作
- コマンド
- 独自押下処理

を宣言します。

### 先着で消費する

同じキーが複数機能に割り当たる可能性があるため、優先順位を持ちます。

先に有効なポートが入力を消費したら、後続へ同じ入力を渡しません。

## 8. 入力モード

ポーズ、モーダル、建造中などでは、通してよい入力が違います。

`gameInputMode()` は、

- camera
- construction
- world
- simulation

の各入力群を通すか決めます。

これにより「確認ダイアログが開いているのに背後の宇宙船も動く」といった事故を防ぎます。

## 9. Viewer はセーブごとの視点

`src/game/viewer/viewer.ts` は視点状態の根です。

代表的な所有者は、

- `ViewSelection`
- `CameraSelection`
- `NavTargetSelection`
- `OrbitGuideSelection`
- `OrbitReferenceSelection`
- `PredictPanelSelection`
- `EntityDisplaySelection`

です。

## 10. ViewSelection

戦闘ビューとマップビューのような「どの見方を選んでいるか」を持ちます。

ビューは表示上の選択ですが、セーブごとに残るため Viewer 側の正本です。

## 11. CameraSelection

戦闘とマップでは、必要なカメラ状態が違います。

CameraSelection はそれぞれの視点を持ち、ビューを切り替えても片方の状態を失わないようにします。

## 12. カメラと描画カメラ

プレイヤーが選んだ論理カメラ状態と、Three.js の Camera オブジェクトは同一ではありません。

論理状態から、そのフレームの、

- 位置
- 向き
- 投影
- near / far
- スケール

を導出し、描画装置へ渡します。

## 13. MapFrame と CombatFrame

表示には「どの座標系で世界を見るか」が必要です。

戦闘ビューは自機近傍の操作に向き、マップビューは大域的な軌道関係を見るためのフレームを使います。

`game/view/` の Frame 系は、表示座標を決める重要な入口です。

## 14. 慣性系

慣性系では、星や軌道面が基本的に空間へ固定され、天体がその中を動きます。

軌道の物理的な向きや長期変化を見るときに分かりやすい基準です。

## 15. 公転回転系

二天体を結ぶ方向が画面上で固定される回転系です。

地球–月系なら、

- 地球
- 月
- L1
- L2

の相対関係を見やすくできます。

CR3BP の理解とも相性がよい表示です。

## 16. 自転系

天体表面へ固定された回転系です。

地表上の経度や、C22 のように天体固定方向が重要な現象を見るときに意味があります。

## 17. 表示原点と回転を分ける

マップビューでは、

- どこを原点にするか
- どの回転を適用するか

は別の選択です。

例えば「月中心だが地球–月方向を固定」といった表示が可能になります。

原点と回転を一つの enum に潰すと組み合わせが増えたとき拡張しにくくなります。

## 18. サンプル時刻ごとの変換

軌道線の各点は異なる未来時刻を表します。

回転座標系で軌道線を描くとき、全点へ「現在時刻の回転」を同じように掛けると誤ります。

各点は**その点自身の時刻**で座標変換する必要があります。

これは回転系 UI の非常に重要な点です。

## 19. 予測パネル

予測表示では、

- どの座標系
- どの期間
- どの時刻中心
- どの時刻表記

を見るかが視点状態になります。

一方、予測計算そのものの物理状態はモデル側です。

## 20. OrbitReference

軌道要素は「どの中心天体に対して測るか」で値が変わります。

`orbit-reference.ts` と Viewer の OrbitReferenceSelection は、UI でどの基準へ対する軌道要素を見るかを扱います。

## 21. FrameControls

座標系選択 UI は、単なるドロップダウンではありません。

対象の天体系・カメラ・予測パネル・現在選択可能な anchor を解決し、無効な組み合わせを避けます。

## 22. Marker

画面上のマーカーは 3D オブジェクトそのものではありません。

3D 世界の点を CameraFrame で画面へ投影し、

- 画面内
- 画面外
- 背面
- 重なり
- 優先度

などを処理して表示します。

## 23. 軌道線と UI

軌道線は 3D シーンにありますが、操作 UI と密接に関係します。

クリック位置から軌道線上の時刻を求めてノードを置く場合、描画された線とモデル上の予測が一致していなければなりません。

そのため、表示線の点列を入力解釈が読むことはありますが、線自体をモデルの正本にはしません。

## 24. HUD のモーダル

確認ダイアログ、設定、建造など、複数のオーバーレイが同時に入力を奪うと競合します。

`OverlayManager` は、どの UI が現在入力を占有しているかを統合します。

## 25. タッチ UI

画面上の操作パッドはブラウザの「生入力装置」ではなくゲーム UI です。

そのため `src/input/` ではなくゲーム HUD 側へ置かれます。

タッチ操作が生成した入力は、最終的にキーボード等と同じゲーム操作へ合流します。

## 26. UI 変更で壊しやすい境界

### DOM ハンドラでモデルを直接変更

フレーム位相が崩れます。

### Viewer と Settings の混同

セーブを変えても残るべき値と、セーブごとに変わる値が混ざります。

### 現在時刻で全軌道点を変換

回転系で未来軌道が歪みます。

### HUD が Render の内部資源を読む

画面表示の都合が GPU 実装詳細へ依存します。
