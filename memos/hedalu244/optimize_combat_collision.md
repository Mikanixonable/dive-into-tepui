# Dynamic 物体どうしの衝突の軽量化 — 階層グリッドと交戦圏

対象コミット: `9802a677`(行番号・実測はこの時点)。

## 目的

物体どうしの接触(`EntityContactPhysics`)の broad phase は 27 近傍の一様グリッドで、セル一辺を
「全参加者の平均変位 Δ̄ を引いた到達量 半径+|Δ−Δ̄| の最大値の 2 倍」に取っている。
**一辺が全参加者の最大値で決まる**ため、到達量の大きい個体が1つ混じるだけで、密集した薬莢の
絞り込みが丸ごと効かなくなる。到達量を大きくする個体は3種類あり、どれも普通の戦闘で現れる。

- **弾。** 初速 1,000 m/s なので ×4(substep 幅 1/15 s)で変位 67 m → 一辺 140 m。
- **基地。** 当たり半径 715 m(`src/assets/models/baseCollision.json` の外接球)→ 一辺 1.4 km。
- **遠方の物体。** 半周先の薬莢は相対 −15 km/s → 一辺 0.4〜1.7 km。しかも数がいれば平均 Δ̄ を
  引きずり、近くの薬莢の到達量まで押し上げる。

node 実測(下表。`tests/dist` の `SpatialGrid` と `resolveSphereCollision` を直に呼び、
直線で 1 substep 進めた集団に対する 1 substep の費用。集団の中身は「見積り」節)では、
連射中に ×4 へ上げると候補ペアが **417 → 38,470 件/substep**、費用は 0.3 → **5.9 ms** になる。
基地が 5 km 以内にいれば ×1 でも **58,000 件・8.8 ms**。破片(fragment)は `collides=false` なので
参加者ではなく、この退化は破片の数ではなく**薬莢の密集 × 到達量の大きい個体**の組で起きる。

修正後は、到達量の大きい個体が何体いても密集した薬莢どうしの候補は薬莢の到達量だけで決まり、
交戦圏(後述)の外にある物体は接触の参加者にならない状態にする。

## 決めたこと

**1. 交戦圏は「自機と基地を中心とする半径 30 km の球の和」で、重なる球は1つにまとめる。**
30 km は既に弾の消滅(`bullet.ts:20`)・ステージ00 の敵の離脱(`enemy.ts:60`)・敵の射撃可否
(`enemy.ts:342`)が同じ値で使っている距離で、SPEC も「交戦圏」の語をこの意味で使いながら定義を
持っていなかった。中心を自機と基地にするのは、この2種だけが操作対象(`Controllable`)であり、
遊ぶ人が観測するのはその周囲だけだから。敵は自機しか撃たず、弾は自機から 30 km で消えるので、
中心から 30 km 超の物体どうしの接触は観測されない。
重なる球を1つにまとめるのは、2つの自機が互いの交戦圏に入っているとき、両者の接触を
どちらか一方の交戦圏で 1 回だけ解くため — 物体を最寄りの中心へ割り当てる形だと、境界を挟んだ
2体(自機どうしを含む)の接触が永久に解かれない。
**覆すなら:** 中心を自機だけにする → 手順1 の文面と手順4 の `base.ts:207` の行を落とす。
半径を変える → 手順4 の定数だけ。

**2. 交戦圏は座標系ではなく、「所属の判定」と「到達量の基準変位」だけを供給する。**
グリッドの近傍関係は同一時刻の位置の差で決まり、慣性系を平行移動しても変わらない。
座標系に依存するのは到達量 半径+|Δ−Δ̄| の Δ̄(区間の基準変位)だけで、これはベクトル1本。
ゆえに座標変換関数もブランド型も要らず、位置は今までどおり ECI の `state.r` のままグリッドへ
入れる。提案2の「交戦圏との相対速度で評価する」は、**Δ̄ を参加者の平均から交戦圏の中心の変位へ
置き換えること**そのものであり、手順4 に畳む。
**覆すなら**(交戦圏ローカル座標のブランド型を導入する): 増えるのは変換モジュールと型だけで
候補ペア数は 1 件も変わらないので、この計画では採らない。

**3. 実装順は 階層グリッド → 交戦圏。** 提案の「3 だけでは効かない(ECI で薬莢が 8 km/s で
動くため)」は成り立たない — 現行が既に平均変位を引いているので、薬莢どうしの到達量は今も
数 m である。効かないのは逆で、**交戦圏だけでは弾が混じった時点で一様グリッドが退化する** — 弾の到達量
67 m(1,000 m/s × 1/15 s)は基準を自機の変位に変えても変わらないので、一辺は 134 m のまま。両方が要り、階層グリッドは
仕様変更を伴わず node のテストで正しさを閉じられるので先に置く。交戦圏はその上で、
(a) 遠方の物体を参加者から外し、(b) 中心の変位を基準にして平均の引きずりを消す。
実測では (b) が効くのは「遠方の薬莢 100 体」の行だけ(階層+平均 52,830 件 → 階層+自機 8,081 件)。
**覆すなら**(交戦圏を先にする): 手順の並びを 1 → 4 → 2 → 3 にする。手順4 の到達量の式は
そのまま `contactCellSize` の Δ̄ の置き換えになる。

**4. 基準変位は交戦圏の先頭の中心(entities の並びで最初の自機/基地)の変位。** 複数中心の
平均にすると、逆行ですれ違う2つの自機の交戦圏で平均が 0 になり両方の雲が粗い段へ落ちる。
先頭に固定すれば少なくとも一方の雲は細かい段に残る。

**5. 30 km の持ち主は交戦圏モジュールにし、`bullet.ts:20` と `enemy.ts:60` の定数を消す。**
CODING-RULE 1.6「同じ値へ入口を2つ作らない」。弾の消滅が「操作対象の自機からの距離」で
測られている(`simulator.ts` が `player?.state.r` を渡す)ことは変えない。
**覆すなら:** 手順4 の `bullet.ts` `enemy.ts` `wave-attack.ts` の行を落とす。

**6. 交戦圏の所属は substep 終端の位置(`state.r`)で決める。** 境界をまたぐ substep の接触は
その回は解かれないが、30 km を横切る物体は弾(消える)か敵(ステージ00 では消える)であり、
どちらも SPEC の「交戦圏の外へ出た」規則に従う側。

**7. 物体どうしの接触のワープ倍率ゲートは消し、「交戦できる倍率でなければ交戦圏が無い」に
一本化する。** 「天体との接触は常に解くが物体どうしは ×4 以下でだけ解く」という規定は、交戦圏の
存在条件に倍率を含めれば SPEC からもコードからも要らなくなる — 物体どうしの接触は交戦圏の中で
だけ解かれ、交戦圏が無ければ参加者も接触代理も無い。高倍率での挙動は変わらない(解かれないのは
同じ)。ベルトの鎖の運動そのものは `belt.update`(`player.ts:312`)が毎フレーム別に進めていて
接触のゲートに乗っていないので、影響を受けない。敵の射撃のゲート(`enemy.ts:334` の
`canShipAct`)はそのまま — 射撃を交戦圏の所属で決めるかは別の判断。
**覆すなら:** 手順4 の `sim-speed-manager.ts` `game.ts` `simulator.ts:70-79` の行と
`engagementZones` の `canEngage` 引数を落とし、`if (canResolveEntityContacts)` を残す。

**8. 弾の消滅は「自機からの距離」のままにし、交戦圏の所属には寄せない。** 所属で消すと、
高倍率へ上げた瞬間に飛翔中の弾が全部消える。弾は交戦の層のものなので消えてよい挙動ではあるが、
`checkLoss` の腕(`playerPos`)を交戦圏へ差し替える変更が全個体に及ぶので、この計画では触らない。
**覆すなら:** `bullet.ts:109` の距離判定を交戦圏の所属に替え、`DynamicSystem.cleanup` と
各 `checkLoss` に交戦圏を渡す手順を手順4 の後ろに足す。

### 手順 2. オクターブ階層の空間グリッドを `math/` に足す

#### 目的

到達量が桁で異なる要素を1つの一辺で扱うから最大値に引きずられる。要素ごとに
「一辺 ≥ 2×到達量 になる最も細かい段」へ登録し、ペアの列挙は**細かい側の要素が自分の段と
それより粗い全ての段の 27 近傍を引く**形にすれば、密集した小さい要素どうしの候補はその要素の
到達量だけで決まる。正しさの根拠: ペア (a, b) が区間内で接触するなら終端の距離は
ρa + ρb ≤ 2·max(ρa, ρb) ≤ 粗い側の段の一辺 なので、粗い側は細かい側の 27 近傍に必ず入る。
**この時点で挙動は変えない**(新しいモジュールとテストだけ。使うのは手順3)。

#### 変更が必要な箇所

| ファイル | 何をするか |
| --- | --- |
| `src/math/spatial-grid.ts` | 同じ段の中でペアを各 1 回だけ列挙する `pairsInto` と、セル添字で 27 近傍を引く `appendCellNeighborsInto` を足す。既存の `insert` / `neighborsInto` は `attractors.ts:67-68` が使うので残す |
| `src/math/hierarchical-spatial-grid.ts`(新規) | 段ごとに `SpatialGrid` を持ち、`insert(item, pos, reach)` と `pairsInto(out)` を提供する。段の器は `reset` で使い回す(`SpatialGrid` は器を作り捨てず `cells.clear()` で使い回していて、N = 2,000 ではそれだけで 3.43 → 2.49 ms/substep の差がある) |
| `tests/math/spatial-grid.test.ts` | `pairsInto` が「距離 ≤ 一辺 の全ペアを含み、同じペアを二度返さない」ことを全数探索と突き合わせる |
| `tests/math/hierarchical-spatial-grid.test.ts`(新規) | 到達量を 4 桁(0.2 m〜1 km)に散らした点群で、「距離 ≤ ρa+ρb の全ペアを含む」「同じペアを二度返さない」「段が 3 つ以上あるとき 2 段以上離れたペアも落ちない」「負の座標をまたぐ」「reset 後に前回の要素が残らない」を全数探索と突き合わせる |

```ts
// src/math/spatial-grid.ts に足す
// セル添字 (cx, cy, cz) を含むセルとその26近傍に登録済みの要素を out の末尾へ追加する。
appendCellNeighborsInto(cx: number, cy: number, cz: number, out: T[]): T[];
// 27近傍の内側にある順不同ペアを、各1回ずつ out へ平らに詰める(out[2k], out[2k+1] が1組)。
// out は呼び出し側が所有し、既存内容は捨てる。
pairsInto(out: T[]): T[];

// src/math/hierarchical-spatial-grid.ts
// 到達量が桁で異なる要素を、一辺 minCellSize·2^k の段へ振り分けて登録し、中心距離が到達量の和
// 以下になりうる全ペアを列挙する一様グリッドの階層。
export class HierarchicalSpatialGrid<T> {
  constructor(minCellSize: number);
  // 全段を空にする。段の器は使い回す。
  reset(): void;
  // 要素 item を、一辺が 2·reach 以上になる最も細かい段の、pos の属するセルへ登録する。
  // reach は有限で 0 以上でなければならない。
  insert(item: T, pos: Vec3, reach: number): void;
  // 中心距離が到達量の和以下になりうる順不同ペアを、各1回ずつ out へ平らに詰める
  // (out[2k], out[2k+1] が1組)。out は呼び出し側が所有し、既存内容は捨てる。
  pairsInto(out: T[]): T[];
}
```

同じ段のペアを各 1 回にするには、セルの自分自身(バケット内の後続)と、添字が辞書順で正の
13 方向の隣接セルだけを引く。段をまたぐペアは細かい側からだけ引くので、順序のガードは要らない。
粗い段のセル添字は、段の一辺が 2 の冪の比なので細かい段の添字から `Math.floor(cx / 2^d)` で
求まり、要素の位置を持ち直す必要はない。

- `grep -n "neighborsInto\|insert(" src/game/dynamic/attractors.ts` が着手前と同じ(既存 API を壊していない)。

### 手順 4. 交戦圏を組み、その中でだけ接触を解く

#### 目的

参加者を交戦圏ごとに分け、交戦圏ごとに独立して解く。到達量の基準変位を参加者の平均から
交戦圏の中心の変位に置き換え、遠方の物体が数で平均を引きずる経路を断つ。どの交戦圏にも
入らない物体は参加者にならない。物体どうしの接触だけをワープ倍率で止めていたゲートは消し、
「交戦できる倍率でなければ交戦圏が組まれない」に一本化する — 交戦圏が無ければ参加者も
接触代理も無い。×4 超で解かれないのは今までどおりで、挙動は変わらない。

  readonly engagementAnchor: boolean;
  readonly state: KinematicState;
  readonly prevState: KinematicState;
}

### 却下したが、条件が変われば戻ってくるもの

- **交戦圏ローカル座標のブランド型。** 近傍関係は平行移動で変わらないので、候補ペアは 1 件も
  減らない。交戦圏の中で位置そのものを回転系で扱う必要が出たとき(例: 基地固定の座標で
  ドッキングの接触を解く)だけ戻る。
- **参加者の速度による自動クラスタリング(中心を置かない交戦圏)。** 遠方の密集(半周先の薬莢
  100 体で残る 5,000 件)まで細かい段に置けるが、substep ごとのクラスタリングの値段と、
  クラスタの割れ方が substep ごとに変わる不安定さがある。「参加者」が中心の無い場所に
  数百体たまり続ける構図(複数の自機を別々の軌道に置いて長時間戦う)が実際に起きたら戻る。
- **到達量に三次掃引の弦からの膨らみを足す。** LEO の 1/15 s では g·dt²/8 ≈ 5 mm で、最小一辺
  1 m に埋もれる。substep 幅が伸びる高倍率で物体どうしの接触を解くようになったら要る。
