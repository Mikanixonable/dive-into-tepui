# 2球体の接触判定を1つの判定器へ

## この計画の前提

- **`Asteroid` 型(`GameEntity` の派生クラス)は廃止済みで、存在しない。** 本文書では `Asteroid` を
  扱わない。
- **大気は天体ごとのパラメータになっており、焼失(連続量の状態判定)と衝突(離散事象の掃引判定)は
  既に別の判定として分かれている。** この計画が扱うのは**衝突側の幾何だけ**で、焼失には触れない。
- 着手時点で、天体接触の判定は `ContactPhysics` / `checkLoss` 系 / `PredictedArc.checkSurfaceReach`
  の3箇所に分かれたままでよい。**この計画は判定を呼ぶ箇所を減らさない** — 呼ばれる先の実装を
  1つにし、点で代用している1箇所(`Bullet.checkLoss`)を掃引へ揃えるだけ。
- **掃引の入口は `sphere-contact.ts` の `sweptSphereContact` へ集約済み。** `reachedBody` は
  幾何を持たず、`resolveSphereCollision` と同じ入口を呼ぶ。近似の選択は、速度を渡すか渡さないかで
  呼び出し側が握ったままになっている(第二段階でここを判定器の内側へ移す)。

## この計画は2段階に分かれ、間に別の作業が入る

| 段階 | 内容 | いつ |
|---|---|---|
| **第一段階** | 判定器の入口を1つにし、`reachedBody` から幾何を抜き、弾の点判定を線形掃引へ揃える。**挙動が変わるのは弾の地表到達だけ** | 判定箇所の統合よりも**前** |
| **第二段階** | 判定器の内部の最適化。解法の選択を判定器が自律的に行う | 判定箇所の統合よりも**後**。単一モジュール内で閉じるので独立に着手できる |

第一段階を先に置くのは、**判定箇所の統合が「1つの判定器」を前提にする**ため。第二段階を後ろに
置くのは、**判定回数が確定してから精度と費用の釣り合いを決める**ため。

# 第一段階: 判定器の集約

## 1. 目的

`physics/sphere-contact.ts` に、**同じ問い**に答える関数が2つ入っている。

| | `sweptSphereToi` | `sweptHermiteSphereToi` |
|---|---|---|
| 経路の近似 | 端点を結ぶ**線分** | 端点の速度を接線に取る**三次エルミート** |
| 解き方 | 2次方程式の閉形式 | 相対位置を3次ベジエへ変換 → 制御点凸包の箱判定 → 左右再帰細分(深さ32)→ 24 反復の二分法 |
| 開始時の重なり | null(呼び出し側の離散 solver へ委譲) | null(同上) |

**同じ「移動する球どうしがこの区間で触れたか」を、別の近似で解いている。** 呼び出し口が
揃っていないと、どちらの近似で解かれたかが呼び出し元ごとに固定され、精度と費用の釣り合いを
判定器が握れない。

そのうえ `Bullet.checkLoss` は、同じ問いを**区間の終端1点**(`containingBody`)で代用している。
掃引を省いた近似なので、**同じ問いに対する解き方が3つある**ことになる。

**この節はコードから引いた調査時点のスナップショットであり、正本ではない。** 判断材料として
置いてあるだけなので、食い違ったらコードを信じる。

### 2-5. この計画への含意

- 掃引を呼ぶ口は `sweptSphereContact` 1つに集約済み。点で代用している口が `Bullet.checkLoss`
  に1つ残っており、**第一段階の残りはそこだけ**(5章の表と一致する)。
- **`Bullet.checkLoss` の `containingBody` は射程内。** 問うている問いは他の3経路と同じ

  変えてから同列に扱う** — 点判定のまま残すと、判定器を1つにしたあとも「この経路だけ別の
  解き方」が残る。**これにより第一段階は完全な純リファクタではなくなる**(弾の地表到達だけ
  挙動が変わる)が、許容する。
- **これは仕様違反の是正でもある。** `DEVELOP/SPEC/ORBIT.md`「天体表面への到達判定」は
  「1ステップの直前の状態と直後の状態を結ぶ経路全体を曲線として掃引し」「両端の状態だけを
  個別にチェックするのではない」「対象は…登録されている全ての天体」と述べていて、弾を除外して
  いない。線形掃引へ変えると `DEVELOP/SPEC/COMBAT.md`「弾の衝突判定はサブステップ間を
  線分 vs 球で判定し、高速弾がすり抜けることを防ぐ」とも揃う。
- 2-4 の二重判定と、×4 超で `ContactPhysics` が走らない非対称は、どちらも判定を**呼ぶ側**の
  問題であり、`unite_predict_simulation_v2.md` の担当。この計画は触れない。なお同文書の
  2-1-3 は、ワープゲートを分割したあとに `Bullet.checkLoss` の天体判定そのものを削除する
  方向を採っている — ここで掃引へ揃えるのは、それまでの間この経路だけが別の解き方で
  残らないようにするため。

## 3. 判定器の責務(達成すべき契約)

> **2球体の接触判定器は1つだけ存在し、2球体の半径と移動前後の状態を受け取り、その区間で
> 接触するか否か・接触の瞬間の状態・法線を(できるだけ正確に近似して)返す。**

- **どう解くか(線分近似で足りるか、より高次で解くべきか)は判定器の内部に隠蔽される。**
  接触の種別(剛体どうし / 天体)でも、時間加速帯でも、呼び出し元でもない — 精度と費用の
  釣り合いは判定器自身が持つ問題。
- **外から渡すのは解くのに必要なパラメータだけ。** 加えてよいのは、費用最適化のために必要な
  場合の**おおよその要求精度**まで。
- **どのペアを判定にかけるか(broad phase)は判定器の外側の責務。** 呼び出し側が空間グリッド
  なり成員判定なりで絞ってから渡す。判定器自身が持ってよいのは、1ペアに対する安価な早期棄却
  (narrow phase の入口)だけ。

# 第二段階: 解法の自律選択(最適化)

**単一モジュール(`sphere-contact.ts`)の内側で閉じるので、他の作業とは独立に着手できる。**
ただし**判定回数が確定してから**着手する — 何回呼ばれるかが決まる前に、1回あたりの費用を
削る意味がない。

## 9. 目的(第二段階)

第一段階で外に出した「判定モード」の引数は、**責務の置き場所として間違っている。**
どの近似で解くかは、呼び出し元が知っていることではなく、判定器がその1歩の幾何から決めること。

さらに、線形近似は粗い刻みで急速に悪化する(10-1)。呼び出し元が固定のモードを選ぶ形では、
「通常の刻みでは線形で足りるが、粗い刻みでは足りない」という**同じ呼び出し元の中の差**を
表現できない。

## 10. 誤差の構造(第二段階の判断材料)

### 10-1. 線分化の誤差は両側に出る — 支配的なのは偽陽性

線分と真の曲線のずれには符号が2通りあり、**どちらも大きさは同じオーダー**である。
1歩でその天体まわりに掃く角を θ = ω·h(ω = |r × v| / |r|²)とすると、

```
弦と弧の最大乖離 ≈ r · θ² / 8
```

- **区間が近点を跨がないとき**(周回している通常の状態): 円弧の弦は中心に近いので、弦は弧より
  **天体側**にある。→ **偽陽性**。本当は逸れているのに交差と判定する。
- **区間が近点を跨ぐとき**: 真の最接近点は弦より天体側にある。→ **偽陰性**。既存テスト
  `Hermite swept sphere: 弦は外れていても曲線が膨らんで届く通過を捕まえる` が押さえている配置。

**物体はたいてい重力源のまわりを周回しているので、実地で支配的なのは前者(偽陽性)。**

### 10-2. 「半径を膨らませて偽陰性を消す」案は採らない

膨張量 `|Δv|·h/8 = a·h²/8 = ω²r·h²/8 = r·θ²/8` は 10-1 の乖離と**同じ大きさ**なので、
支配的な偽陽性側の誤差をちょうど**2倍にするだけ**になる。片側へ寄せる補正では解決しない。
**誤差そのものを小さくするしかない。**

(broad phase で安全側に半径を膨らませるのは別物 — あちらは通す候補が増えるだけで判定器の
答えを変えない。ここで棄却しているのは**答えそのものを歪める**膨張である。)

### 10-3. 近似の次数と誤差

| 近似 | 誤差のオーダー | 備考 |
|---|---|---|
| 線分(弦) | **O(h²)** = `r·θ²/8` | サジッタ項がそのまま残る。`collision-response.ts` と、第一段階のあとは弾の地表到達が使っている |
| 二次 | O(h³) | サジッタ項を落とす。摂動・空気抵抗を無視すれば軌道は二次曲線なので、ここで大半が取れる |
| 三次エルミート | O(h⁴) | いま `reachedBody` が使っている。二次からの上積みは小さい |

### 10-4. θ の実測値(どの近似で足りるかを決める量)

| 場面 | h | θ = ωh | `r·θ²/8`(r = 6791 km) |
|---|---|---|---|
| 実シミュレーション 通常(`SUBSTEP_MAX_DT`) | 20 s | 0.0225 rad | **430 m** |
| 実シミュレーション 最高ワープ(131072 ÷ 60fps ÷ `SUBSTEP_MAX_COUNT` 64) | 34.1 s | 0.0384 rad | **1.25 km** |
| 弧 最小刻み(`ARC_MIN_STEP_DT`) | 40 s | 0.045 rad | **1.7 km** |
| 弧 28日表示の粗化刻み | 121 s | 0.136 rad | **15.7 km** |

θ は `|r × v|·h / |r|²` で数演算で出せるので、**判定器が自分で「線分で足りるか」を決める基準として
使える**。いずれの値も地球半径 6371 km に対しては小さいが、`r·θ²` が二乗で効くため、
**粗い刻みほど急に悪化する**。判定器の内部で刻みに応じて次数を上げる余地があるのはこの非線形性のため。

### 10-5. 解法1回あたりの費用(棄却される遠い相手の経路、演算数で数える)

| | 演算数 |
|---|---|
| エルミート解法の棄却経路 | `isFinite` 9 + 制御点構築 36 + `axisDistanceSq` × 3 = 30 + 合計と比較 4 ≈ **70** |
| 線形解法の棄却経路 | `c` 6 + `aa` 5 + `bb` 5 + 判別式 4 + 比較 ≈ **21** |

**解法を線形へ倒すだけでは 70 → 21(3.3×)** にしかならず、しかも 10-3 のとおり精度を落とす
取引になる。**軽量化の主因は解法の選択ではない** — この計画で解法を触るのは、責務の置き場所を
正すため(9章)であって、性能のためではない。

## 11. 達成目標(第二段階)

1. **判定器の入口から判定モードの引数が消えている。** 呼び出し元が解法を選ぶ箇所が `src/` に 0 件。
2. 判定器が、その1歩の θ から `r·θ²/8` を出し、要求精度と比べて解法を選ぶ。要求精度は既定値を
   持ち、必要なら呼び出し側が上書きできる引数にする。
3. **モード指定なしで、第一段階の時点の両モードそれぞれと同等以上の精度が出る。**
   要の回帰は `Hermite swept sphere: 弦は外れていても曲線が膨らんで届く通過を捕まえる` が
   **モード指定なしで通ること**。
4. `tests/physics/sphere-contact.test.ts` で `sweptHermiteSphereToi` / `sweptSphereToi` を
   名指ししている件が、新しい入口へ向け直されている。

## 12. 手順(第二段階、着手順)

1. 判定器の内部で、その1歩がその天体まわりに掃く角 `θ = |r × v|·h / |r|²` を出す。
2. `r·θ²/8`(10-1 の乖離)が要求精度を下回るなら線形の閉形式で答え、上回るなら次数を上げる。
3. 上げる先の候補は**二次**(10-3 — 誤差 O(h³)、摂動を無視すれば軌道は二次曲線なのでここで
   大半が取れる)。三次エルミートを残すか置き換えるかは実測で決める。
   **具体的な解法は未定** — 二次の場合、球中心との距離が t の4次式になるので、制御点凸包での
   棄却 + 数回の反復で根を詰める形が素直。
4. 判定モードの引数を消す。テストを新しい入口へ向け直す。
5. `typecheck` + `test:physics` + 実行時確認。

## 13. リスクと落とし穴(第二段階)

| リスク | 影響 | それが露見する場所 |
|---|---|---|
| 精度を**下げる**方向に判定器が線形を選ぶ | いま三次で解いている `reachedBody` の経路が線形に落ち、**周回中の物体が偽陽性で天体に当たったことになる**(10-1 の支配的な誤差) | 10-3 の表を基準に、**上げる方向にしか動かさない**。要求精度の既定値は、いまエルミートで解いている経路の精度を下回らない値にする |
| θ の算出に**その天体の中心からの相対位置**ではなく ECI 位置を使う | 地球以外を周回している物体で θ が桁違いに小さく出て、粗い刻みでも線形が選ばれる | 月周回・小天体周回での掃引。判定器は既に2球体の相対位置を持っているので、そこから出せば取り違えようがない |
| 二次近似の根の探索が、**エルミート実装が持っている「区間の途中だけ球を通過する」拾い上げ**を落とす | 端点が両方とも表面外の通過を見逃す。すり抜けが復活する | `Hermite swept sphere: 弦は外れていても曲線が膨らんで届く通過を捕まえる` と `Hermite swept sphere: 制御点の箱ごと球から離れた天体は null` の2件。**モード指定なしで通ることが合格条件** |
| 「軽くするために」解法を線形へ倒す | 10-5 のとおり 3.3× にしかならず、精度を落とす取引になる。**軽量化の主因は解法ではない** | この計画の目的は責務の置き場所であって性能ではない。性能の判断材料は判定回数の側にある |
| 要求精度を呼び出し側が上書きできる引数にしたとき、**誰も渡さない引数**になる | 使われない一般化。読み手が「何を渡すべきか」を判断できないまま残る | 上書きの必要が実際に生じるまで**引数を作らない**。既定値だけで始める |

- `npm run test:physics` — 毎段階(`src/physics/` を直接触る)。
- **第一段階の合格条件は「既存のテストが1件も書き換わらずに通ること」。** 挙動を変えるのは弾の
  地表到達だけで、そこはテストが覆っていない。

  - 28日表示の粗い刻みの弧が、天体表面の手前で不当に打ち切られないこと。
