### S2. 不変条件A — ドラッグを分解してから角度へ渡す(**実施済** `a698f95d`)

**実施した内容.** `src/math/polar-euler.ts` に `eulerAfterDrag` を新設し、
`camera-orientation.ts` の `turn()` がそれを通すようにした。`focus-camera.ts` は渡す値が
画面上の変位であることを名前で示すだけ(回転キーは今までどおりドラッグと同じ変位へ畳む)。

**計画から変えた点が2つある.**

1. **仰角側の縮小を、1次の `× cos θ` ではなく厳密に積分した。** `dθ = dragY·cos θ` は
   「仰角を `asinh(tan)` で写した座標(メルカトル図法の緯度)を `dragY` だけ平行移動する」ことの
   1次近似で、厳密形のほうが**両方の増分が状態に依らなくなる** — ドラッグの往復が元の向きへ
   厳密に戻り(既存テストが要求している)、`POLAR_PITCH_LIMIT` へ当たる不連続も無くなる。
   実装量は同じ2行。
2. **回帰テストの置き場を `tests/math/` から `tests/game/camera-orientation.test.ts` へ移した。**
   不変条件A は「オイラー操作とクォータニオン操作が局所的に一致する」ことなので、両方の経路を
   持つ `CameraOrientation` の層でないと書けない。

**実測した効き(微小ドラッグに対する視線の変位を、画面の右軸・上軸へ射影した値).**

| 条件 | クォータニオン | オイラー(修正前) | オイラー(修正後) |
| --- | --- | --- | --- |
| 仰角0・ロール0・右 | (−1, 0) | (−1, 0) | (−1, 0) |
| 仰角0・ロール45°・右 | (−1, 0) | (−0.71, **0.71**) | (−1, 0) |
| 仰角60°・ロール0・斜め | (−1, 1) | (**−0.5**, 1) | (−0.5, 0.5) |
| 仰角60°・ロール45°・斜め | (−1, 1) | (**0.35**, 1.06) | (−0.5, 0.5) |

修正後はすべて向きが一致する(大きさは `cos θ` 倍 — B3 で決めたとおり)。

**既存テストを1つ書き換えた.** 「オイラー入力の往復は元の向きへ戻る」は方位・仰角・ロールを
**同時に**往復させていたが、ドラッグの分解はロールの向きに合わせて決まるので、往路で積んだロールが
復路の分解を変える。**クォータニオン側の同種のテストが既に軸を1つずつに分けている**(同じ制限)ので、
そちらへ揃えた。方位+仰角の同時往復は厳密に戻るため、ケースとして残してある。

### S3. `ReferenceFrames` に「回転軸」の口を1つ開ける

**目的.** 2.6 の面を軸へ解くとき、天体・機体・役割を同じ1本の式で扱う。

`frameRotationAt`(`reference-frames.ts:88`、private)が返す `FrameRotation.omega` が、公転なら
軌道面法線、自転なら自転軸(逆行は符号)を向いている。**機体・役割もここで `h = rel × relVel` から
組まれている**(`:104`)ので、機体の軌道面法線を別経路で求める必要がなく、
`FocusCameraConfig` へ新しい注入を足さずに済む。

| ファイル | 何をするか |
| --- | --- |
| `src/game/celestial/reference-frames.ts` | `frameAxisAt(rotatingWith, t, source): Vec3 \| null` を public で足す。`omega` の長さが 0 近傍なら `null`、そうでなければ `norm(omega)` |
| `tests/game/` | 地球の自転 → 自転軸、月の公転 → 白道法線、自転モデルを持たない天体 → null |

**毎フレーム呼ばれる**(極軸の導出に使う)ので、`displayTime` 単位のキャッシュが要るかを
実測で確かめる(K3)。

### S4. `camera/reference-plane.ts` を新設する

**目的.** 「どの面か」という値(型・照合キー・候補の導出・表示名・軸への解決・セーブ変換)を
1モジュールへ。`rotation-follow.ts`(同計画 手順2 の成果物)と同じ形で作り、同じ構造的
インターフェースで `CelestialSystem` を受ける — **`three/webgpu` を型グラフへ引き込まないため**
(同計画 D4 と `focus-target.ts:26-29` のコメント)。

**置き場の判断.** `rotation-follow.ts` へ同居させず別モジュールにする。候補の**導出**は双対だが、
値としては別の軸の選択(回転の固定先 vs 面)で、`rotation-zone.ts` と `anchor-zone.ts` を畳まない
のと同じ理由(同計画「触らないと決めたもの」)。**導出の中身は共有できる**ので、
`rotation-follow.ts` から「フォーカス対象に紐づく回転源の列挙」を export して両者が使う。

| 何を | 内容 |
| --- | --- |
| 型 | `CameraReferencePlane = { kind: 'ecliptic' } \| FrameRotationSource`。`'spin'` が赤道面、`'revolution'` が公転面 — **`FrameRotationSource` をそのまま再利用**するので S3 の `frameAxisAt` へ直接渡せる |
| 照合キー | `referencePlaneKey(plane): string`(同計画 R2 と同じ理由で必要) |
| 候補の導出 | `availableReferencePlanes(focus, celestial, frameAnchors, t)`。純関数。**2.6 の順**(赤道面 → 公転面 → 黄道面)で返し、**主星が恒星の公転面は落とす**。フォーカスが機体・固定点なら中心天体の赤道面を先頭に |
| 軸への解決 | `planeNormal(plane, ...)` — 黄道面は `ECL_POLE_ECI`、それ以外は `frameAxisAt`。**2.7 の向き揃え**(黄道北とのなす角が 90° を超えたら反転。90°±ε の帯では反転しない)をここで1回だけ掛ける |
| セーブ変換 | 旧 `'ecliptic' \| 'equator' \| 'moonOrbit'` → 黄道面 / `{kind:'spin', id:'earth'}` / `{kind:'revolution', id:'moon'}`(2.9) |
| 表示名 | 2.10 の綴り。対象名は同計画 手順3 の `object-name.ts` から引く |
| `tsconfig.test.json` | `include` へ足す |
| `tests/game/reference-plane.test.ts`(新規) | 候補導出6ケース(`camera_control_spec.md` 2.6 の表が期待値の正本)、逆行自転天体での向き揃え、旧セーブ形式の3値 |

### S6. 真上/真横/視点リセットをプリセットとして書き直す

| 場所 | 何をするか |
