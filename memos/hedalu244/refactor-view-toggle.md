# ビュー二重化の解消 — 戦闘/マップの経路分けとカメラ統合の計画

作業ブランチ `refactor-view-toggle`。コード計測はすべて **b4e600e8** 時点。

## 目的

「戦闘ビューかマップビューか」という1つの状態が、いま4つの形で現れている。

1. **正本の分散。** ViewManager.worldView が正本と宣言されているのに、CameraSystem
   `_overviewMode`・PlanEditor `_editMode`・TouchControls のマップフラグが同じ値の鏡像を持ち、
   ViewManager.applyChrome() が毎遷移で配って回っている(`setMapMode(open: boolean)` 3箇所)。
2. **引数の漏出。** `overviewMode: boolean` が src/ の **39ファイル・176出現**に散り、
   多くの受け手が `if (!overviewMode) return;` で自分をゲートしている(targeter の3メソッド、
   celestialMarkers.syncSubLabels、linePickables.refresh、mapPickables.refresh、
   mapActions の5メソッド)。ビューを固定すると通らない行がモジュール半分に及ぶものがある。
3. **game.ts の2責務同居。** update/sync/handleInput の約230行が、共通処理・マップ専用・
   戦闘専用を行単位で混在させている。ゲートが呼び手と呼び先に割れているため、
   **どの行がどのビューのものか読めない。**
4. **カメラの二重実装。** ChaseCamera(144行)と MapCamera(623行)は「注視対象を中心に置く
   軌道カメラ」という同じ責務の別実装で、ドラッグ回転は**画面上の挙動が同一**なのに符号系だけ
   逆に書かれている(後述の差分表)。操作項目(回転モード・座標系・投影)がパネル化された今、
   違いの本体は「何を追えるか」と数値設定に縮んでいる。

この構造は既に実害を出している: **戦闘ビューの [N] 自動ワープと [Del] 計画破棄は現在死んでいる。**
commit ff17e7ee がビュー分離の際に `editor.handleInput` をマップ専用にゲートしたが
(game.ts:477)、editor 側の該当分岐は `!editMode`(=戦闘ビュー)でしか通らないため、
両ビューのどちらでも実行されなくなった。SPEC/GAME.md はマップ退出時に
「[N] で直近ノードへ自動ワープ」とヒントを出すと定めており、仕様違反の回帰である。

修正後に期待される状態: ビューの正本は ViewManager の1箇所、カメラの実装クラスは1つ
(+ガンサイト)、game.ts のフレーム処理は「共通」を地の文に、ビュー固有を CombatView /
MapView の2具象への固定位置の呼び出しにし、`overviewMode` という語彙が src/ から消える。

## 達成目標

1. `grep -rn "overviewMode" src/` が **0件**(現在 39ファイル・176出現)。
2. `grep -rn "setMapMode" src/` が **0件**(現在 CameraSystem・PlanEditor・TouchControls の3定義)。
3. `src/game/camera/` のカメラ実装クラスが統合カメラ1つ + GunsightCamera のみ。
   `chase-camera.ts` / `combat-camera-system.ts` が存在しない。
4. game.ts の update/sync/handleInput/handlePointerInput の中に、ビュー分岐が
   activeView を選ぶ 1 getter 以外に無い(`isMapView` の grep で確認)。
5. 戦闘ビューで [N] 自動ワープと [Del] 計画破棄が効く(実機で hint 表示を確認)。
6. 戦闘ビューで操作対象以外(天体・他艦)へフォーカスでき、太陽系スケールまでズームアウト
   できる(実機確認)。
7. マップビューの操作が手順3の仕様どおり: ドラッグ・パン・平行投影・画角・基準面ジャンプは
   不変で、意図した変更はホイール感度(0.0018→0.0015)と回転ゾーンの選択肢
   (フォーカス由来へ)だけ(実機確認)。
8. ホイールズーム感度の定数が src/ に **0.0015 の1箇所**(`grep -rn "0.0012\|0.0018" src/game/camera/`
   が 0件)。
9. マップビューで機体をフォーカスすると 12 m まで寄れ、[G] で姿勢追従が効く(実機確認)。
10. 旧セーブが例外なく読み込める。マップ視点は復元され(回転追従が新選択肢に無い場合は
    慣性系へ)、戦闘視点は既定へ落ちる(D3)。
11. 各手順で `npm run typecheck`、src/game/ に触れた手順で `npm run test:game` が通る。
    main へ送る際は全テスト(/send-pr)。

## 現状の差分表(手順3・4・5 の判断材料)

## 手順

### 手順1. 戦闘ビューの [N]/[Del] を復旧する(実施済み 8b1e939b — 実機確認のみ残)

typecheck・test:game 161件 通過済み。**残工程**: 実機で戦闘ビューの [N] hint
(「ノードへ自動ワープ開始」/「マニューバノードがありません」)と [Del]
(「マニューバ計画を破棄」)、マップビューの WASDQE Δv 編集が変わらないことを、
手順4以降の実機確認バッチと合わせて見る。

### 手順2. ビュー正本を ViewManager の1箇所にする(実施済み 71143dc1)

typecheck・test:game 161件 通過済み。ViewManager の cameraSystem 依存も外した。
起動と [M] 切替の実機確認は手順4以降のバッチで見る。

### 手順3. 仕様を確定する(実施済み cf917cd2)

CONTROLS.md(視点カメラ/基準フレーム/ビュー固有の操作/[G]表)・MAP.md(§2 カメラの
フォーカス・§3 カメラ区画の回転ゾーン)・GAME.md(§9.3・未確定の案)を更新済み。


### 手順4. 統合カメラを組み、マップ側を新仕様へ合わせる(実施済み b549131e)

typecheck・test:game 161件 通過。ヘッドレス実機確認(dev サーバ + CDP、creative マップ)で
起動例外ゼロ・地球フォーカスの回転ゾーンが「解除/太陽-地球回転座標系/地球-月回転座標系/
地球自転座標系」・全切替とホイール/ドラッグ無事故を確認済み。**残工程**: 機体フォーカスでの
12 m ズームと [G]、感度 0.0015 の操作感、切替時に視点が跳ばないことの目視は、手順5後の
実機確認バッチで見る。smoke:browser は docs/(旧ビルド)配信のため判定に使えない(既知)。

### 手順5. 戦闘ビューを統合カメラへ切り替え、ChaseCamera を消す(実施済み)

typecheck・test:game 161件・test:render 18件 通過。ヘッドレス実機確認(creative で配置→[M]):
[N] hint(手順1復旧)・[G] OFF⇄ON・リセット hint・ズームアウト/ガンサイト/[M]往復とも
実行時例外なし。付随修正: 星殻の倍率を両ビュー拡大殻に統一(戦闘の遠距離ズームで殻が near の
内側に入るため。殻は視点中心なので見え方は不変)。clearFocusIf は**マップ側だけに残した** —
戦闘インスタンスは対象消滅時に fallToOrigin でなく hold が仕様のため(計画表の「両インスタンスへ」
を上書き)。**残工程**: ドラッグ・ロール・感度の操作感、[G]切替や再ロードで視点が跳ばないこと、
恒星が far で消えないことの目視はユーザーの実機で。WebGPU デバイスロストが出るヘッドレスランが
あるが、ズーム単体・旧ビルドでは 0 件で再現がコード経路に紐付かず、既知の不安定と判断。

### 手順6. game.ts を共通 + CombatView + MapView に割る(実施済み)

typecheck・test:game 161件 通過。ヘッドレス実機(マップ操作一式・配置→[M]→[N]/[G]/リセット/
ズームアウト/ガンサイト/[M]往復)が実行時例外 0 件。game/world-view.ts(4フックの口)+
combat-view.ts + map-view.ts を新設し、受け手ゲート8箇所を route 化で削除、mapPickables /
linePickables に clear() 新設。赤道交点は「求め直されなければ自動的に隠れる」機構に寄せて
show 引数ごと削除。displayWindowManager.sync / frameControls.sync / syncSubLabels /
linePickables.refresh は syncPanels フック(軌道線同期の後・マーカー衝突解決の前)へ移動。

### 手順7. 残る overviewMode を掃く(実施済み bf0fe874)

grep: overviewMode / setMapMode とも src/ 0 件(達成目標1・2)。横断署名は view: WorldView、
on/off の実体は意味名(occludeByBodies / active / mapAmbient / mapView)へ。HUD パネルは
viewManager を読む。PlanEditor の editMode は ViewManager の遅延評価導出になり、applyChrome の
配布先は hud / touch / displayWindow.forceCurrent の3つだけになった。typecheck・test:game・
test:render・ヘッドレス実機(戦闘一連)通過。

### 手順8. 残骸整理と改名(実施済み 38d6171c / ead32317)

MapCamera → FocusCamera(focus-camera.ts)、OVERVIEW_CAMERA_* → FOCUS_CAMERA_*、セーブ型改名
(キーは不変)、frameRoleAnchorId を physics/frame へ移動、chase 残名と焼け残りコメントの整理、
hideInOverview → hideInMapView。typecheck・test:game・test:render・ヘッドレス実機 通過。
