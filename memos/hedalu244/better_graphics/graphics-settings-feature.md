# 描画品質設定 — 全体・分野・詳細の3層と、画面空間の段の追い込み（要件定義と計画）

**計画ファイル。** `/run-plan` で上から実施し、完了した手順はこの文書から消す。要件は 2026-10-12 に `/add-feature` で詰めた。

**実施の前提**: 手順1〜4 は、局所反射のブランチを拡散側のブランチと合わせた後（`screenspace-specular.md` 手順4）に始める。
手順5 の実測は、さらにパス順の組み直し（`screenspace-source.md`）の後 — 組み直しで GPU の行が変わる。

**拡散側の計画書 `screenspace-diffuse.md` は、拡散側のブランチで大きく進んでいて古い。判断の根拠にしない**（ユーザー）。
拡散側の段の作り・品質の物差し・負荷の予算は、合わせた後のコードと、そのとき拡散側で生きている計画から取る。

---

## 目的

描画品質設定を、**知識のない人が1つ選ぶだけで済む簡潔さ**と、**好みや機械の負荷に合わせて値ごとに選べる自由度**の両方を
最大限に持つ形へ作り直す。

今の設定は2つの欠点を同時に持つ。

- **影は自由度が高いが、初見に優しくない。** 影マップの枠の数・解像度・精細さの3項目がプリセットなしで並んでいる。
- **積雲は簡潔だが、自由度がない。** 雲頂を探す刻みの数と、縁を締める二分の回数という独立な2つの値が、「積雲の精細さ」1項目の
  段に押し込められている（`src/render/opaque-cloud-surface-renderer.ts` の `SAMPLING_OF_DETAIL`）。

**目指すのは両立** — 独立に効く値は独立なノブとして出し（影の形）、その組はプリセットとして名付けてまとめる（積雲の形）。
あわせて、新しく作った画面空間の描画（近傍の拡散光・局所反射）の各段の値を、品質と負荷の引き換えとして実測で決める。

進める順は **型 → 設定パネル → 値**（ユーザー）。設定の値とプリセットを決める型を先に作り直し、設定パネルをそれに合わせて
作り直し、最後に各プリセットの値を決める。

## 決めたこと

### ユーザーが決めたこと（2026-10-12）

1. **3層にする** — 全体のプリセット → 分野のプリセット → 分野の詳細の値（ノブ）。対象は描画品質設定の全項目。
2. **全体は 低 / 中 / 高 / カスタム。カスタムを選んだときだけ、分野の行が現れる。** 初見の人には全体の1行しか見えない。
3. **分野は （オフ）/ 低 / 中 / 高 / カスタム。カスタムを選んだときだけ、その分野の詳細の値が現れる。** 分野のプリセットの
   ボタンは詳細の値の外に置く。オフは、消せる分野だけが持つ。
4. **カスタムは明示的に選んだ状態として持ち、値から推し量らない。** 調整の結果がたまたまプリセットと同じ値になっても
   カスタムのままで、詳細の値は閉じない。
5. **カスタムへ移ったときは直前の値を写して始め、プリセットへ移ると調整は捨てる。** カスタムの値を分野ごとに覚えておくことは
   しない。
6. **露出補正とフィルムのルックは「好み」として、プリセットの外に置く。** いつでも表示され、どのプリセットを選んでも変わらず、
   変えてもプリセットの点灯に影響しない。
7. **詳細の値の形**: 歩数や段数など 10〜15 段程度の整数はスライダー、解像度は離散の候補を原則にする。
8. **下位の値を持たない単独のトグル**（小天体の点群・惑星の環・レンズ効果・タンパク質の敵の揺らぎ）は分野のプリセットを
   持たせず、全体がカスタムのとき「表示する要素」としてトグルのまま並べる。
9. **遮蔽と照り返し（近傍の拡散光）も、走査の値を独立なノブとして出す。** 拡散側の古い計画にある「人間向けの設定は方式と
   精細さだけ」は覆る。
10. **負荷を実測してプリセットの値を決めるのは、画面空間（遮蔽と照り返し・映り込み）だけ。** 雲・影・大気ほかは、今の
    プリセットの値をそのまま流用する。

### この計画で決めたこと（覆してよい）

- **5 の規則を全体の層にも当てる。** 全体をカスタムへ移すと、各分野は直前の全体のプリセットが選んでいたものから始まる。
  カスタムから全体の 低 / 中 / 高 へ移ると、分野ごとの選択とその詳細の値はすべて捨てられる。確認は挟まない — UI-DESIGN の
  確認は船体破棄のように世界へ取り消せない結果を残す操作のためのもので、捨てた調整は作り直せる。
- **オフからカスタムへ移ったときは、その分野の「中」の値から始める。** オフは写す値を持たないため。
- **どの層でも、点灯しているのは常にいま選ばれている1つ。** 今の SPEC の「どのプリセットとも一致しなければ全消灯」は、
  カスタムを明示の状態にしたことで要らなくなる。
- **詳細の値にするのは、今の段の表が段ごとに変えている値。** 段で変わらない隠れた定数（積雲の影のタップ数 `SHADOW_TAPS`、
  映り込みの当たりを締める回数 `REFINE_STEPS`、レンズ効果の段数 `LEVELS` など）はノブにしない。映り込みの均しの段数だけは
  手順5 の実測で段ごとに変える価値があると分かったときに足す（局所反射の計画から引き継いだ候補）。
- **カスタムでは、プリセットが避けている組も選べる。** 積雲の刻みを 2〜3 本にすると手前と奥の雲頂が2枚の層に重なって見える
  （`SAMPLING_OF_DETAIL` のコメント）が、それも選んだ人の引き換えとして許す。プリセットはそうした組を選ばない。
- **効かない状態の詳細の値も選べる。** 大気がオフの間の巻雲、積雲の立体がオフの間の刻みの数なども無効にせず、選んだ値は
  効く状態になれば効く（UI-DESIGN「まとめトグルの規約」と同じ考え方）。
- **積雲の刻みと二分の回数は、シェーダへ展開するのをやめて uniform の回数で回す**（手順3）。今は値が変わるたびにマテリアルを
  組み直すので、スライダーを動かすたびにフレームが止まる。遮蔽と照り返し・映り込み・大気の走査は既に uniform の回数で
  回っていて（`hemisphere-scan.ts:95,117`・`reflection-trace.ts:99`・大気の `steps`）、それに揃える。
- **保存は新しい鍵へ移し、旧い鍵は移行元として読む**（`tepui.panelCollapsed` → `.v2` と同じ形、`src/settings/user-settings.ts`）。

### 採らない案

- 全体の層を持たず、分野の行を常に並べる — 不採用（ユーザー）: 初見で行が10前後並ぶ。
- カスタムの値を分野ごとに覚え、カスタムへ戻すと前回の調整が戻る — 不採用（ユーザー）。
- 露出補正とフィルムのルックをプリセットに残す — 不採用（ユーザー）: 露出を変えるだけでプリセットが消灯する。
- 数値のノブをすべて離散の候補にする / すべてスライダーにする — 不採用（ユーザー）: 上の 7 の原則。
- 表示する要素を1つの分野（オフ / オン / カスタム）にまとめる — 不採用（ユーザー）: レンズ効果だけ切るのに1段深くなる。
- 遮蔽と照り返しを「精細さ（低 / 中 / 高）」の段のまま残す — 不採用（ユーザー）。
- プリセットとの一致から点灯を導く — 不採用: 調整した値がたまたまプリセットと一致した瞬間に詳細の値が閉じる。
- 積雲の立体のオフを、刻みのスライダーの 0 として含める — 不採用: オフは刻みの軸の上の点ではなく、雲頂を描くかどうかという
  別の選択（CODING-RULE 1.6「並列な選択肢は boolean でなく union で持つ」— 独立した2つの状態を1つの軸へ畳まない）。
- スライダーを離したときだけ反映する — 不採用（今は）: ループを uniform にすれば要らない。手順3 で費用が増えると分かったら
  再検討し、そのときはスライダーの規約（UI-DESIGN §3）を変えるのでユーザーに問う。
- 保存の鍵を変えず、中身の形で新旧を見分ける — 不採用: 新旧のビルドを同じ origin で行き来すると、旧いビルドが新しい形を
  読めず既定へ落とし、それを書き戻して新しい設定を消す。

## 設定の持ち方

- **保存するのは選び方**（案: `GraphicsSelection`）— 全体の選択（低 / 中 / 高 / カスタム）、全体がカスタムなら全分野の選択
  （プリセット名か、カスタムの詳細の値一式）と表示する要素のオン / オフ、そして好み。
- **描画側が読むのは、選び方を解いた平らな値一式**（今の `GraphicsSettingsData`）。解くのは純関数1つ。分野・ノブ・プリセット・
  全体との対応は1つの表（今の `GRAPHICS_OPTIONS` の後継）から導き、項目を足すときは表へ書き足すだけで型・解き方・保存の
  検証・パネルの並びが決まる、という今の性質を保つ。
- **解いた値一式は、選び方が変わらない限り同じ参照を返す。** `src/render/scene.ts` の `syncFrame` は値一式を参照の同一性で
  比べ、変われば `rebuildForGraphics` と解像度の掛け直しを走らせる — 毎フレーム解き直すと影マップなどの GPU 資源を毎フレーム
  捨てる。案: `src/settings/` に、選び方の `StoredSetting` から解いた値を出す読み取り専用の `SettingValue<GraphicsSettingsData>`
  を置き、選び方の参照で覚える。`Launcher`・`Run`・`scene.ts` が受け取る型は今のまま変わらない。
- **置き場**（ARCHITECTURE R10）: 表・選び方の型・解き方・保存文字列との変換・旧形式の読み替えは `src/render/`、保存先の読み書きと
  解いた値の購読は `src/settings/`、パネルは `src/hud/panels/`。作り直すと `graphics-settings.ts` は lint の max-lines（500 行）を
  超える見込みなので、表・選び方・旧形式の読み替えでファイルを分ける（分け方は CODING-RULE 1.2 で手順2 に決める）。
- **2択の項目の部品は手順4 で決める。** 点光源 / 球光源・一様球 / テクスチャ・実写 / 生成は今セグメントコントロールで並んで
  いて、映り込みの追跡の解像度（1/2 / 1）も2択になるが、UI-DESIGN §3 はセグメントコントロールを3択以上専用としている。`/ui-design` に照らしてトグルスイッチにするかを決める
  （今の並びを規則を弱める根拠にしない）。
- **値を1つ書き換える操作**: パネルとツールは「ノブのキーと値」を渡し、それを含む分野をカスタムへ（直前の値を写して）、全体を
  カスタムへ移したうえで値を書き換える。render-lab の `setGraphicsOption` もこれを通るので、ツールから値を変えるとパネルは
  カスタムとして点灯する。render-lab のケースが持つ差分（`Partial<GraphicsSettingsData>`）は、解いた値の上へ今どおり重ねる。

### 保存の形と読み替え

- 鍵は `tepui.settings.graphics.v2`。新しい鍵が無ければ、旧い鍵 `tepui.settings.graphics` の値を読み替える。
- **旧い保存値の意味は凍結する。** 読み替えは、旧い既定（今の `QUALITY_PRESETS.high`）と旧い段の表（今の
  `SAMPLING_OF_DETAIL`・`TOTAL_SAMPLES_OF_QUALITY`・`SCAN_TIERS`・`TRACE_TIERS` の値）の写しを読み替えの側に持って行う。手順5 で
  新しい値を決めても、旧い保存値が指す絵は変わらない。
- 読み替えは、旧い値一式を旧い既定の上へ重ね、分けた段を旧い段の表どおりのノブの値へ展開したあと、好みの2つを好みへ移し、
  残りをこう選ぶ:
  1. 全体の 低 / 中 / 高 のどれかを解いた値と一致すれば、その全体のプリセット。
  2. 一致しなければ全体はカスタムにし、分野ごとに、分野のオフ（有無の値が偽）ならオフ、分野のプリセットのどれかと一致すれば
     そのプリセット（高 → 中 → 低の順に見る。中と高が同じ値の分野ではどちらでも絵は同じ）、どれとも一致しなければカスタムで
     その値。
  3. 雲の分野がオンで積雲の精細さがオフだった値は、積雲の立体をオフにし、刻みと二分は雲の「高」の値（6・3）にする — オフの段の
     0・0 はスライダーの範囲の外。
- 保存値の検証は今の性質を保つ — 知らないキーは読まず、欠けた分野や候補外・範囲外の値は既定（全体「高」が選ぶもの）で埋め、
  壊れた文字列は既定へ落とす。スライダーの値は範囲内の刻みに乗った整数だけを受け入れる。

## SPEC へ書く要点（手順1 の下書き）

`DEVELOP/SPEC/RENDERING.md`「描画品質設定」を、項目の箇条書きから3層の構成へ書き直す。書くのは振舞いで、キー名・型は書かない。

- 描画品質設定は「全体のプリセット」「分野のプリセット」「分野の詳細の値」の3層で選ぶ。全体のプリセットを1つ選ぶだけで
  済み、好みや機械の負荷に合わせたい人は分野ごと・値ごとに選べる。
- 全体のプリセット（低 / 中 / 高 / カスタム）の 低 / 中 / 高 は、各分野のプリセットと表示する要素のオン / オフを一括で選ぶ。
  カスタムを選んだときだけ分野ごとの選択が現れる。カスタムへ移ると、直前の全体のプリセットが選んでいたものから始まり、
  低 / 中 / 高 へ移ると分野ごとの選択は捨てられる。
- 分野のプリセット（消せる分野はオフ / 低 / 中 / 高 / カスタム、ほかは 低 / 中 / 高 / カスタム）も同じ規則で、カスタムのときだけ
  詳細の値が現れる。オフからカスタムへ移ると中の値から始まる。
- カスタムは選んだ状態そのもので、値から推し量らない。どの層でも、点灯しているのは常にいま選ばれている1つ。
- 品質と負荷を独立に引き換える値は、詳細の値として1つずつ選べる。1つの値に複数の独立な値を束ねた段は持たない。
- 好み（露出補正・フィルムのルック）は品質と負荷の引き換えではないので、どのプリセットにも含まれず、常に選べる。
- 分野ごとの詳細の値と、それを上げ下げしたときの見え方（今の箇条書きの記述を分野の下へ移し、新しい値 — 雲頂を探す刻みの
  数・縁を締める二分の回数・大気の標本数・遮蔽と照り返しの走査の値・映り込みの追跡の解像度と歩数 — の見え方を足す）。
- 分野をまたいで効かなくなる値: 大気がオフなら巻雲と半透明の積雲も描かれない。積雲の立体がオフなら積雲の影も落ちない。
  効かない状態の値も選べ、効く状態になれば効く。
- どの値も切り替えたその場の画面へ反映される。設定はブラウザに保存され、以前の形で保存された設定は同じ絵になる選択へ
  読み替えて引き継ぐ。

`DEVELOP/SPEC/UI-DESIGN.md`「設定タブの詳細面」へ足す:

- 描画タブは上から、好み・全体のプリセット・（全体がカスタムのとき）分野の行と表示する要素・（分野がカスタムのとき）その分野の
  詳細の値。現れる / 消えることで内容の高さが変わったときも、内側タブの切り替えと同じくウィンドウをビューポート内へ収め直す。
- 詳細の値の部品: 10〜15 段程度の整数（歩数・段数・標本数）はスライダーに今の値を数字で添え、解像度と少数の候補は
  セグメントコントロール、名前で選ぶ多数の候補はプルダウン、オン / オフはトグルスイッチ。

あわせて `screenspace-specular.md` 手順6 の問い「SPEC の描画設定の節に『映り込みの精細さ』がまだ無い」は、この書き直しで
閉じる（精細さの段ではなく、追跡の解像度と歩数として書く）。

## 変えない挙動（手順2〜4）

手順2〜4 は描画の結果を変えない。変えてよいのは、プリセットの点灯の判定（一致から明示へ）、パネルの構成、露出補正と
フィルムのルックがプリセットに含まれなくなること、保存の形だけ。

- 全体の 低 / 中 / 高 のそれぞれで、描画側が受け取る値が今の `QUALITY_PRESETS` と同じ（好みを除く。分けた段は段の表どおりの
  ノブの値に解かれる）。
- 今の形で保存された設定を読むと、同じ値に解かれる。好みの2つの保存値も引き継がれる。
- 積雲の刻みと二分を uniform の回数で回しても、同じ回数なら同じ絵になる。

## 達成目標

## 局所反射のつまみと負荷の材料（局所反射の計画から移した）

| つまみ | 今の値 | 効くもの |
| --- | --- | --- |
| ぼかし（均し）のオン / オフ | プリセット 低 / 中 / 高 = オフ / オフ / オン（仮置き） | オフでは粗い面の像が 1 px の点描になる。均しは「映り込みの均し」の行の全部（960×540 で 0.7〜1.0 ms） |
| 均しの段数 | `REFLECTION_LEVEL_COUNT` = 7（高さ 540 px の描画バッファでの数。高さが倍になるごとに1段足す） | 段1つごとに描画の固定費がかかる（13 → 7 段で均しが 32% 減った）。減らすと、広く一様な粗い面が遠くの物体を映す構図でまだらが戻りうる。`tools/render-lab-reflection-levels.mjs` がこの行を文字列で読む |
| 追跡の歩数 | 低 16・中 32・高 48（仮置き） | 1歩あたりはマテリアルの 0.01〜0.03 倍。追跡の行は固定費（全解像度のシェーディング入力の読み出しと深度の縮小）が支配的 |
| 追跡する深度の解像度 | 低・中は 1/2、高は全解像度（仮置き） | 細い物体の取りこぼしと、当たり位置の精度。変えると深度の描画先を確保し直す |

- **変えないこと**: 裾を切る量（b = 0.2）と均しの広さ（s = 1）は段によらず同じにする — 粗さとぼけ方の対応（像の縁の幅が対照の
  0.5〜2倍）を段で変えない。
- 費用の目標（組み直し前の読み方）: 「映り込み」「映り込みの均し」「陰影の合成」の median の和が、同じ session の「マテリアル」の

## リスクと落とし穴

| リスク | 影響 | 露見する手順 |

| 保存済みの設定を読み替えずに形を変える | 既存の利用者の設定が黙って既定へ戻る | 手順2 — 実在の文字列を読むテスト |
