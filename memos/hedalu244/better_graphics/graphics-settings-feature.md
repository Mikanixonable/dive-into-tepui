# 描画品質設定 — プリセットの階層化と詳細設定、精細さの段の追い込み（計画）

**計画ファイル。** `/run-plan` で上から実施し、完了した手順はこの文書から消す。**実施は、局所反射のブランチを拡散側のブランチと
合わせた後か、main へ送った後の別 PR。** 手順1 で要件を詰めるまで、この文書は方針と材料だけを持つ。

---

## 目的

描画品質設定は、各項目が低 / 中 / 高のプリセットに束ねられ、プレイヤーが選べる自由度が実質3択しかない。**3択はプリセットとしての
自由度であり、詳細設定として細かい調整ができるべきで、設定項目のプリセットは階層化されるべき**（ユーザー）。これは局所反射に
限らず、既に実装されている影・雲・大気・近傍の拡散光を含む一般の問題として扱う。

あわせて、近傍の拡散光と局所反射の「精細さ」の各段の値を、品質と負荷の引き換えとして実測で決める。2つは同じ画面空間の描画で、
まとめて追い込む（ユーザー）。

## 決めたこと

**ユーザーが決めたこと。**

- 3択は全体のプリセットの自由度に留め、詳細設定で項目ごとの値を細かく調整できるようにする。プリセットは階層化する。
- 対象は描画品質設定の全体（影・雲・大気・近傍の拡散光・局所反射ほか）。局所反射の計画では扱わない。
- 近傍の拡散光と局所反射の精細さの段の調整・負荷の追い込みは、この計画でまとめて行う。

**決まっていないこと**（手順1 でユーザーに問う）。

- 階層の形 — 全体のプリセット → 分野ごとのプリセット → 詳細の値、の3層にするか、全体のプリセット → 詳細の値の2層か。分野の
  切り方（今の `GRAPHICS_GROUPS` を使うか）。
- 詳細設定に出す値の形 — 今の選択肢（オン / オフ・段）のままか、連続値を出すか。
- 今の SPEC「個別に変えた結果がどのプリセットとも一致しなければ、どのプリセットも選ばれていない状態として示す」を、階層ごとに
  どう示すか。
- 保存済みの設定の読み替え — 今の保存値を新しい形へどう移すか。

## 局所反射のつまみ（局所反射の計画から移した材料）

調整のつまみになりうるのは次の4つ。今は「ぼかし」だけが独立した描画設定で、歩数と解像度は「映り込みの精細さ」1項目の段に
束ねている（`src/render/pipeline/reflection-pass.ts` の `TRACE_TIERS`）。

| つまみ | 今の値 | 効くもの |
| --- | --- | --- |
| ぼかし（均し）のオン / オフ | 描画設定 `screenSpaceSpecularDenoise`。プリセット 低 / 中 / 高 = オフ / オフ / オン（仮置き） | オフでは粗い面の像が 1 px の点描になる。均しは「映り込みの均し」の行の全部（960×540 で 0.7〜1.0 ms） |
| 均しの段数 | `REFLECTION_LEVEL_COUNT` = 7（高さ 540 px の描画バッファでの数。高さが倍になるごとに1段足す） | 段1つごとに描画の固定費がかかる（13 → 7 段で均しが 32% 減った）。減らすと、広く一様な粗い面が遠くの物体を映す構図でまだらが戻りうる |
| 追跡の歩数 | 低 16・中 32・高 48（仮置き） | 1歩あたりはマテリアルの 0.01〜0.03 倍。追跡の行は固定費（全解像度のシェーディング入力の読み出しと深度の縮小）が支配的 |
| 追跡する深度の解像度 | 低・中は半解像度、高は全解像度（仮置き） | 細い物体の取りこぼしと、当たり位置の精度 |

**変えないこと**: 裾を切る量（b = 0.2）と均しの広さ（s = 1）は精細さによらず同じにする — 粗さとぼけ方の対応（像の縁の幅が対照の
0.5〜2倍）を段で変えない。段数を減らす段は、同じ規則のまま上の段を省く形にする。

## 負荷の目標（局所反射の計画から移した材料）

- 局所反射の費用の目標は、「映り込み」「映り込みの均し」「陰影の合成」の median の和が、同じ session の「マテリアル」の 3.5 倍以下
  （精細さ中、ぼかしオン）。測り方は `node tools/render-lab-measure.mjs 3 reflection`（構図は `leo-metal` と `bay-metal`、段は
  オフ / 低 / 中 / 高 / 中・ぼかしオフ。p50 の3巡の中央値）。session ごとに絶対値が 3〜4 割ずれるので、比べる2つは同じ session で
  交互に測る。
- 最後の実測（Intel gen-12lp、960×540、精細さ中）: 比は `leo-metal` 3.20〜3.57、`bay-metal` 3.11〜3.31（像の元を鏡面込みにしていた
  版）。像の元を一様な反射にした版はマテリアルが約 0.1 ms 軽く、分母が減って比は 3.69 / 3.54 と上がって読める（和は減る）。
  ぼかしオフの比は 1.9 / 1.6 前後。
- 照り返しの源と映り込みの像の元のパス順の組み直し（`screenspace-source.md`）で、行が変わる（「陰影の合成」が消え「映り込みの像の元」
  が足される）。**比の分母と分子をどう読むかを、手順4 の前にユーザーに問う** — たとえば「映り込みに関わる増分 / 映り込みオフの
  マテリアル」。

## 達成目標

1. 描画品質設定が階層化され、全体のプリセットを選んだあとに項目ごとの値を変えられる。プリセットとの一致の示し方が SPEC どおり。
2. 保存済みの設定が、新しい形へ読み替えられて引き継がれる（`npm run test:settings`）。
3. 近傍の拡散光と局所反射の精細さの各段の値が、実測の表（品質の物差しと負荷）を根拠に決まり、その表が commit メッセージにある。
4. 負荷の目標を、手順4 の前に決めた読み方で満たす。

## 手順

### 手順 1. 要件を詰める

**目的** — 「決まっていないこと」をユーザーに問い、SPEC へ書く文面を決める。全項目を棚卸しして、どれをどの階層に置くかを決める。

**変更が必要な箇所**

| ファイル | 変更 |
| --- | --- |
| この計画 | `/add-feature` で要件定義書へ置き換える（棚卸しと、保存形式・UI の調査はサブエージェントへ） |
| `DEVELOP/SPEC/RENDERING.md` | 「描画品質設定」の節の品質プリセットの記述（`/modify-feature`） |
| `DEVELOP/SPEC/UI-DESIGN.md` | 設定タブの描画面の記述（`/modify-feature`） |

**達成条件と検証**

- 全項目（`src/render/graphics-settings.ts` の `GRAPHICS_OPTIONS`）の階層と、詳細設定に出す値の形が表になっている。
- SPEC の更新が `docs(spec):` で単独に commit されている。

### 手順 2. 設定のデータを階層化する

**目的** — プリセットの階層と詳細の値を、1つの正本のデータで持つ。

**変更が必要な箇所**（手順1 で確定させる）

| ファイル | 変更 |
| --- | --- |
| `src/render/graphics-settings.ts` | 項目の定義・`QUALITY_PRESETS`・`matchingGraphicsPreset`・`parseGraphics` / `formatGraphics` |
| `src/settings/` | 保存値の読み替え |
| `tests/settings/` | 読み替えとプリセットの一致の判定 |

**達成条件と検証**

- `npm run typecheck` / `npm run test:settings`。今の形で保存された値を読むと、同じ描画の結果になる。

### 手順 3. 設定パネルを組み直す

**目的** — 階層と詳細設定を、ゲームの設定タブと render-lab の両方に出す（`/ui-design`）。

**変更が必要な箇所**

| ファイル | 変更 |
| --- | --- |
| `src/hud/panels/graphics-panel.ts` | 階層の表示と詳細設定 |
| `tools/render-lab/main.ts` | render-lab の描画設定パネル（同じ `GraphicsPanel` を組んでいる） |

**達成条件と検証**

- `npm run typecheck` / `npm run test:settings` / `npm run verify:ui-style`。ゲームの設定タブと render-lab で、プリセットを選んでから
  詳細の値を変えられ、一致の示し方が SPEC どおり。

### 手順 4. 精細さの段を実測で決める

**目的** — 近傍の拡散光と局所反射の精細さの各段の値を、品質と負荷の引き換えで決める。

**変更が必要な箇所**

| ファイル | 変更 |
| --- | --- |
| `src/render/pipeline/reflection-pass.ts` | `TRACE_TIERS`（仮置きの TODO を実測で置き換える） |
| `src/render/pipeline/screen-space/reflection-denoise.ts` | 段で均しの段数を変えるなら、上の段を省く形で |
| `src/render/pipeline/screen-space/screen-space-pass.ts` | `SCAN_TIERS`（拡散側の判断材料に従う） |
| `src/render/graphics-settings.ts` | 段の値と、各プリセットの値 |
| `tools/render-lab-measure.mjs` | `reflection` と `screen-space` の軸 |

**達成条件と検証**

- 段ごとに、品質の物差し（局所反射は `node tools/render-lab-reflection-levels.mjs` の縁の幅・まだら・像から遠い輝点と、
  `node tools/render-lab-reflection-flicker.mjs` の塊の揺れ）と負荷の表を並べ、段の値を決めた根拠を commit メッセージに残す。
  精細さを下げたときに、局所反射の縁の幅が対照の 0.5〜2 倍・まだらが粗さ0.05の帯の2倍以下を満たせなくなる帯がどの粗さからかを
  含める。
- 負荷の目標（手順4 の前に決めた読み方）。

### 手順 5. プリセットの値を見直す

**目的** — 階層化したプリセットの各段の値を、全項目で見直す。

**変更が必要な箇所**: `src/render/graphics-settings.ts` の各項目のプリセット。

**達成条件と検証**

- `npm run typecheck` / `npm run test:settings`。各プリセットで render-lab の撮影を1組ずつ撮り、プリセットの間で絵と負荷が単調に
  並ぶ。

## リスクと落とし穴

| リスク | 影響 | 露見する手順 |
| --- | --- | --- |
| 保存済みの設定を読み替えずに形を変える | 既存のプレイヤーの設定が黙って既定へ戻る、または読めない値で落ちる | 手順2 — 今の形の保存値を読むテスト |
| 段ごとに裾を切る量や均しの広さを変える | 精細さで粗さとぼけ方の対応が変わり、局所反射の像が段ごとに別物になる | 手順4 — 縁の幅の表を段ごとに並べる |
| 負荷を別の session で比べる | 3〜4 割のずれで、段の差を読み違える | 手順4 — 同じ session で交互に測る |
| 詳細設定を増やして、プリセットとの一致の判定が壊れる | プリセットを選んだのに「どのプリセットでもない」と示される、またはその逆 | 手順2・3 — 一致の判定のテストと、パネルの表示 |
