# 露出とレンズエフェクト

**前提は [`pipeline.md`](pipeline.md)。** とくに §1-5(明るさの目盛り)。
出力段(`render-pipeline.ts`)の中身が担当範囲。

**最優先はトーンマッパの露出調整**(§1)。それ以外(§2 以降)は絵のリッチ化であって、
急がない。

---

## 1. 露出 — **最優先**

**逆二乗則が実装されたことにより、木星圏などが真っ暗になってしまった。**

いまの目盛りは「1 天文単位で π」に固定で、出力段は露出係数を持たない(1 を渡す)。
つまり**画面の白は 1 天文単位に固定されている。** 太陽から遠ざかれば絵はそのぶん暗くなり、
木星(5.2 AU)で 1/27、土星(9.6 AU)で 1/92、海王星(30 AU)で 1/900。
トーンマッピング(Khronos PBR Neutral)は **0.08 未満を `x → 6.25x²` で潰す強いトウを持つ**ので、
そこへ落ちた絵は黒へ吸われる。

**論点: 固定露出のまま行くのか、順応を入れるのか。**

- **仕様は現在「露出は場面によって変化しない」と明記している**(`DEVELOP/SPEC/RENDERING.md`
  「露出とトーン」)。**変えるならコードより先にそこを直す**(`/modify-feature`)。
  実装に合わせて後から書き足さない。
- 候補は (a) 太陽からの距離だけで決まる静的な露出(場面ではなく位置の関数なので、
  同じ場所では常に同じ絵になる)、(b) 画面の輝度からの自動露出(眼順応)、
  (c) プレイヤーが選ぶ段(カメラの露出補正)。
- **(a) は「太陽から遠い天体ほど暗い」という物理を画面上で潰してしまう。**
  暗いこと自体は正しい帰結なので、**どこまでを正しさとして残し、どこからを見やすさのために
  曲げるのかを決めるのがこのファイルの仕事。**

**トーンカーブの最終決定もここで行う。** Khronos PBR Neutral を続けるか、トウの強さを変えるか。
**較正ケース(`albedo` / `saturn`)の期待値は目盛りの側の話なので、曲線を変えても崩さない。**

## 2. 順序

```text
露出 → ブルーム → レンズフレア/グレア → トーンマッピング → sRGB
```

**ブルームは最小限。** グローの代用にしない — **グローは大気散乱として実装する**
([`atmosphere.md`](atmosphere.md))。ここが持つのは**レンズ由来のもの**だけで、
**由来で分ける。**

対象は HDR 化済みの発光体。**再突入プラズマは既に動圧という物理量から強度を引いている**
(`REENTRY_GLOW_MIN_Q` / `_FULL_Q`)ので、検証の基準ケースに使える。

## 3. レンズフレアとスミア

**欲しいのはフレアとスミア。** どちらも実在のレンズ/センサに由来する像であって、
大気やボリュームの発光とは別物。

### 3-1. 太陽が 1px を切る問題

**本作では、遠くから見た太陽が極めて小さな点として描かれうる**(1px に満たない場合もある)。
**フラグメントシェーダーのみで実装すると、ラスタライズによって太陽のエフェクトが大きく
ちらつきうる。**

**太陽が十分に小さいときには、太陽とそれ以外でカメラエフェクトを組み合わせるべきである
可能性がある** — 太陽については画面内の位置と放射照度を解析的に持っているのだから、
ラスタライズされた画素を読まずにフレアを合成できる。分ける閾値と、分けた側と分けない側の
つなぎ目で絵が飛ばないことが論点。

**これは惑星の輝点スプライトと同じ問題の族である**(等級 +6 がかろうじて見える表示応答を
1 つだけ持つ)。同じ扱いに寄せられるか要検討。
