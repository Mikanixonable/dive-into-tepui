# 雲影の 2 つのアーティファクトを断つ(実施済み)

**全手順を実施した。** 残っているのは、何をなぜ決めたか・どこまで届いたか・次に触る人が
踏みうる穴だけ。手順そのものは commit が持つ。

積雲の殻が落とす影に出ている **(1) ブロック状の格子と雲頂の自己遮蔽**、**(2) 東経 90°〜180° の
1 象限にだけ出る同心円** を消す。どちらも遮蔽関数が雲の場を読む 1 箇所
(`src/render/pipeline/sun-occlusion.ts` の `cumulusTransmittance`)に由来する。

## 目的

**出ていたもの**

1. 影の縁に場の texel(赤道 9.8 km)の格子がそのまま出る。雲の無い空の下にも薄い影が乗る。
   雲頂に自分自身の影が落ちて暗くなる。
2. 北極を真上から見下ろす構図で、東経 90°〜180° の 1 象限にだけ同心円が出る。
   雲の影を切ると消える。

**目指した状態**

- 影のシルエットが殻のシルエットと一致する。雲の無い空の下は影を落とさない。
  雲頂は自分自身の影で暗くならず、雲どうしの影(`DEVELOP/SPEC/RENDERING.md`「雲の描画」)は残る。
- どの構図・どの経度でも同心円が出ない。**消えた理由を 1 つ名指しできる**(隠すのではなく断つ)。

**SPEC の差分は無い。** 「雲は影を落とす」「どの距離からでも破綻しない」は既に規定済みで、
ここで直したのは実現側の欠陥。

## 決めたこと

1. **雲影の実装方式は変えない — 遮蔽関数の 4 つ目の源のまま。** 発端の見立て「巨大な天体(に
   付随する雲)を遮蔽マップに乗せた結果」は成り立たない。シャドウマップが集めるのは
   `SUN_SHADOW_CASTER_LAYER` の Mesh だけで(`src/render/pipeline/sun-shadow-casters.ts` の
   `expandVisibleCasters`、`sun-shadow-maps.ts` の `lightCamera.layers.set`)、天体の球も積雲の
   殻も `markLitOpaque` で `LIT_OPAQUE_LAYER` **だけ**に置かれている
   (`src/render/celestial-surface.ts`・`src/render/cumulus-shell.ts`)。`lit-layer.ts` の
   `SUN_SHADOW_CASTER_LAYER` の注記も「天体の球はここへ入れない」と明記している。
   - つまり **案 1(遮蔽バッファ経由で雲をサンプリングする)は既に実装されている姿**であり、
     **案 2(天体全体を遮蔽マップに入れるのをやめる)は対象が無い** — 視錐台の外へ CSM の
     texel は 1 枚も振られていない。ブロック状の格子はシャドウマップの texel ではなく、
     **雲の場そのものの texel**。
2. **粒(`gradientNoise`)は影には入れない。** 殻が粒を引くのは 1 画素 1 回だが、影は光路の
   タップごとに要る。実測(`opaque_cloud.md`)で粒は G バッファパスの増分の大半を占めており、
   6 タップぶん足すと遮蔽パスが数倍になる。
   代わりに **影が読む雲の形を「粒で均した被覆率 + 場の雲頂」へ揃え**、粒ぶんの食い違いは
   自己遮蔽の判定で吸収する。覆すなら、影でも粒を引くことになり遮蔽パスの費用が数倍になる。
3. **場は明示 LOD で引く。** 光路のタップの uv は画面の隣接画素と連続でないので、暗黙 LOD が
   選ぶ mip 段には意味が無い。段は画面 1 px の実寸と光路 1 歩の長さの粗いほうから引く。
4. **殻と影が共有する「雲の形」の置き場は `src/render/cloud/cumulus-shape.ts`。** 2 箇所が
   同じ場を別の規則で読んでいたことが (1) の原因なので、片方だけ動かせない形にした。

## 分かったこと

**2 つのアーティファクトは同じ 1 つの原因から出ている。** 遮蔽パスが雲の場を読む
`this.cumulusField`(`sun-occlusion.ts`)は、`THREE.DataTexture` の 1×1 の写しでノードを組んで
`.value` を毎フレーム差し替えている。`DataTexture` の既定は **NearestFilter + ClampToEdge**
で、three の WGSL 生成器はノードを組んだ時点のテクスチャを見て `textureSample` と
`textureLoad` を選ぶ(`WGSLNodeBuilder.isUnfilterable` は min/mag が Nearest なら真を返し、
`generateTexture` は真なら `generateTextureLod` = **整数座標の `textureLoad`** を出す)。
**生成された WGSL は `.value` を差し替えても変わらない。**

- **ブロック状の格子** = 補間の無い texel フェッチ。場の 4096×2048 の texel がそのまま出る。
- **同心円** = `generateTextureLod` が uv を整数座標へ直すときに使う巻き関数も
  ClampToEdge。`sphereMeshUv` の u は東経 90°〜180° で負になるので、その象限だけが場の
  0 列目へ張り付き、値が緯度だけの関数になる。極を見下ろすと同心円に見える。

`earth-polar` の「遮蔽」表示で、この象限だけに同心円が出ることと、雲の影を切ると遮蔽が
一様に 1.0 になることを確認した。写しの契約を揃えて mip 段を明示に変えると、同心円は消え、
地表へ落ちる影から場の格子も消えた。

**そのあと分かったこと**

- **mip 段は受け手の面の傾きぶん伸ばす必要がある。** 画面 1 px が覆う実寸を視距離だけから
  引くと、掠める構図で段が細かすぎてエイリアスが出る。
- **光路のタップ 6 回は、恒星が低いと影を縞へ割る。** 1 つの雲の影が、タップの間隔ぶん離れた
  短い破線の列になる。タップを 24 回へ増やすと消えるので、原因はタップの間隔。
  **場をぼかす幅の下限を光路 1 歩の長さの 2 倍へ置くと、費用を増やさずに縞が埋まる。**
  等倍では隣り合うタップの覆う範囲が接するだけで、縞が残る。

## 達成目標(すべて到達)

1. `earth-polar` の「遮蔽」表示に同心円が 1 本も出ない。**済** — 影のグラフは描画品質設定の
   段で形が変わらない(低設定は積雲の影そのものを切る)ので、段ごとの確認は要らなかった。
2. 同心円の原因を名指しできる。**済** — 「分かったこと」。写しのフィルタが Nearest だったため
   整数座標の `textureLoad` が焼き込まれ、その巻き関数が ClampToEdge だった。
3. `earth`・`earth-oblique` の「遮蔽」表示で、場の texel の格子が影の縁として読めない。**済**
4. 太陽が高い構図で、殻の雲頂の透過率が 1.0 になる。**済**
5. 雲どうしの影は残る。**済** — `earth-terminator` で、雲塊から反太陽側へ影が長く伸びる。
6. 雲が描かれていない空の真下の地表に影が落ちない。**済** — `earth-oblique` の「遮蔽」が
   雲のある場所だけ暗い。地球の矩形平均輝度は 27.8 → 30.3 へ戻り、薄い影が消えたぶん明るくなった。
7. 「遮蔽」パスの増分が +0.1 ms 以内。**済** — +0.03 ms(「実測」)。
8. `npm run typecheck`・`npm run test:render`。**済**

## 残る課題

- **低い太陽での影は、光路 1 歩ぶんのぼかしで柔らかくなる。** タップ 6 回の間隔を 1 タップが
  埋めるので、影の縞は消える代わりに縁が甘い。タップを 24 回へ増やすと縁は締まるが、遮蔽パスは
  4 倍近くになる(`opaque_cloud.md` の費用の穴と同じ話)。
- **`src/render/cloud/condensation.ts` の `CLOUD_TOP_SPAN`(14000)は、
  `cumulus-shape.ts` の同名の定数(15000)と別物。** 生成側の雲頂の高さの目盛りで、場の G が
  張る高さではない。同じフォルダに同名で違う値が並んでいるので、いずれ名前を分ける。

## 実測(全手順の実施後)

`npm run render-lab` の `earth`(960×540、GPU パス時間の中央値 [ms])。同じ機械で
`opaque_cloud.md` が測った値と並べる。

| | G バッファ | 遮蔽 |
|---|---|---|
| 着手前(`opaque_cloud.md`) | 4.16 | 1.02 |
| 全手順の実施後 | 4.15 | 1.05 |

**遮蔽パスの増分は +0.03 ms**(基準機換算 +0.006 ms)。達成目標 7(+0.1 ms 以内)を満たす。
場のフェッチ回数はタップ 6 回 + 受け手の柱 1 回の計 7 回へ増えたが、mip 段が全タップで揃って
テクスチャキャッシュが効くため、増分はほぼ相殺されている。

`earth-polar` の遮蔽パスは 1.12 ms(地球が画面いっぱいに写るので受け手の画素が多い)。

## 採らない案(再提案しないため)

| 案 | 却下理由 |
| --- | --- |
| 雲を `SUN_SHADOW_CASTER_LAYER` へ入れて CSM で影を落とす | 解析源との二重計上になる。枠は艦の塊へ密着させる設計で、惑星規模の遮蔽器を入れると texel が 1 枚も足りない(`opaque_cloud.md` の「採らない案」と同じ結論) |
| 天体の一部が見えているときに天体全体を遮蔽マップから外す | **入っていないので対象が無い**(決めたこと 1) |
| 影のタップでも粒(`gradientNoise`)を引く | 費用(決めたこと 2)。粒ぶんの食い違いはマージンで吸収する |
| 場のテクスチャの解像度を上げる | 配信サイズが 13.6 MB からさらに増える。ブロック状の格子の原因は解像度ではなく読み方 |
| 本番のプロシージャルテクスチャへ移るまで放置する | 場の読み方の欠陥は差し替えても残る。可視範囲のテクスチャに替えても、暗黙 LOD と巻きの問題は同じ形で出る |
