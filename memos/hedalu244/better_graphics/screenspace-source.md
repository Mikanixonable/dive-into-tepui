## 目的

「パイプラインの中で複雑な計算を二度しない」「一致すべきものは一度だけ計算する」。今の照り返しの源
（`ScreenSpacePass.emittedRadiance`）は、ライティングの前に恒星（描画設定によらず点光源）・天体照・環境光を自前で
求め直している。ライトプリパスと二重の計算で、恒星の光源モデルのように一致すべきものが食い違う。源をライトプリパスの
後に置き、その照度を使い回す。

組み直したあとのパス順（ユーザーが決めた）:

```
G バッファ（と影・天体照の写し）
→ ライトプリパス（近傍補正を光源として足さない）
→ 照度から照り返しの源を作る → 近傍の拡散光（走査・均し・拡大）で近傍補正 ΔE を求める
→ 照度と ΔE から映り込みの像の元を作る → 局所反射（追跡と像・均し）
→ 本マテリアル（照度・ΔE・局所反射を合成して、共有の描画先へ書く）
→ 大気 → …
```

映り込みの像の元は ΔE の後に作る — 局所反射が近傍の拡散光の結果を読めるように。像の元から ΔE を抜いた映り込みは、
遮られた隅の面が明るく浮き、品質を容認できなかった（`screenspace-specular_backlog.md`）。

あわせて、照り返しの源の反射率に、映り込みの像の元と同じ「粗い面ほど足す鏡面反射率」を入れる（ρ = 拡散色 + r × R、
r は知覚的粗さ、R は鏡面反射率）。照り返し側に入れるデメリットは無く、絵は良くなる方向に変わる見込み（ユーザー）。

## 決めたこと

**ユーザーが決めたこと。**

- 上のパス順。原理は「パイプラインの中で複雑な計算を二度しない」「一致すべきものは一度だけ計算する」。
- 照り返しの源に粗い鏡面（r × R）を入れる — 積極的に検討する（手順2 でユーザーが判定する）。
- 実施は拡散側のブランチと合わせた後、拡散側の手順9 の前（2026-10-12）。
- **デバッグ表示「拡散照度」の読み方は (a)**（2026-10-12）— 近傍補正を含んだ和を描画先として持たない。道具と撮影は「拡散照度」（遠方光だけになる）と
  「拡散照度補正」（ΔE）を別々に読み、和が要るところでは自分で足して 0 以上に切る（`tools/render-lab-screen-space-blind-8-16.mjs` の土台の作り方が前例）。
  表示名は、意味が変わったことが名前で分かるもの（例: 「遠方の拡散照度」 — 鏡面の「直接 / 遠方の鏡面照度」と揃う）に改める。描画バッファの解像度の、
  拡大済みの補正項の描画先は残る（`screenspace-diffuse.md` の決めたこと 39 — 時間方向の蓄積がこの補正項だけを蓄積する）。(b)（像の元の描画に和を書かせる）は
  映り込みがオフのフレームで和が消え、拡散側の表示が映り込みの設定に引きずられる。(c)（表示で 2 枚を足す）は CODING-RULE 4.3 の例外が要り、数を読む道具は
  どのみち書き換える。
- 組み直しで照り返しの源に起きる、恒星のモデル（点 → 描画設定のモデル）と render-lab の対照の球光源の違いは、微々たるものか、
  差が出るケースが無いかのどちらかなので、個別には確かめない。

**自分が決めたこと**（覆すと括弧内の手順が変わる）。

- **照り返しの源は走査の解像度のまま、今と同じ G バッファの画素で照度を読む**（手順4b）。今の採り方と同じになり、縮小の段も
  全解像度の描画先も要らない。平均（前置フィルター）にするかは拡散側の判断 — 平均すると、奥行きの違う面をまたぐ所で前後の面を
  混ぜる（走査は走査の画素ごとに深度を1点だけ読むので、平均した源と深度が食い違う）。覆すなら、手順4b で全解像度の源を作って
  縮小する形にし、VRAM が全解像度1枚ぶん増える。
- **照り返しの源と映り込みの像の元は、同じ関数で放射輝度を求める**（手順2・4c）— `(拡散色 + r × R) / π × 照度 + 自己発光`。
  2つの違いは、照度に ΔE を足すかと、解像度だけ。関数は `material-pass.ts` の `specularReflectanceAt` の隣に置く。
- **映り込みの像の元は専用の描画にし、映り込みがオフのフレームは描かずに描画先を空へ戻す**（手順4c）。
- **本マテリアルは、映り込みの「オフ / 均す前 / 均した」の3つを構築時に組んで持ち替える**（手順4c）— 今の陰影の合成の2枚に
  オフを足した形。設定の切り替えでシェーダを組み直さない。
- **GPU の行は「陰影の合成」を消し、「映り込みの像の元」を局所反射の前に足す**（手順4c）。並びは実行順。
- **デバッグ表示「マテリアル」（`keep`）は外す**（手順4c）— 描画先が無くなる。本マテリアルは共有の描画先へ直接書き、結果は
  「通常」と後段の表示で見える。
- **デバッグ表示「拡散照度」は ΔE を含まなくなる**（手順4a）。読み方はユーザーが決めた (a)（上）。近傍補正込みの照度をこの表示や
  `readFloat('diffuse')` で読んでいる所は、手順4a で書き換える — 2026-10-12 の grep で、撮影は `tools/render-lab/bay-cases.ts` の `bay-earth-*-diffuse`・
  `bay-earth-radius-*`・`bay-quality-*`・`bay-radius-*px` と `bounce-cosine-case.ts` の `bounce-cosine-diffuse`、数を読む道具は
  `render-lab-screen-space-metrics.mjs`（窓の比と負の照度の数 — 拡散側の達成目標3・5）・`render-lab-screen-space-negative-irradiance.mjs`（`diffuse = e + c` の照合）・
  `render-lab-screen-space-blind-8-16.mjs`（土台 = diffuse − correction）・`render-lab-screen-space-chain-metrics.mjs`（クレイ）・`screen-space-lab.mjs`（正しさの組の
  `diffuse`）・`screen-space-reference.mjs`・`screen-space-variance.mjs`（窓の比）。どれも例外を出さずに誤った値になるので、着手時に
  `readFloat('diffuse'`・`'diffuse'`・`debugTarget: 'diffuse'` を grep し直して件数を照合する。

## 変えない挙動

`DEVELOP/SPEC/RENDERING.md` の描画パイプライン・描画品質設定・デバッグ表示の節と、近傍の拡散光・映り込みの記述から。

**保存する挙動**（全手順の後に1つずつ当てる）:

- 近くの物体の映り込みの見え方 — 映り込みのケース（`leo-metal*`・`bay-metal*`・`reflection-ladder*`）の撮影が、組み直す前の組と
  封筒内（像の元の照度は今も ΔE を含むので、違いは半精度の足し算の順だけ）。
- 近傍の拡散光は拡散反射光だけに関わり、太陽の直射光と鏡面反射光を遮らない。
- 描画設定「遮蔽と照り返し」（3択）・「近くの物体の映り込み」・「ぼかし」のどの組み合わせでも描け、切られた段は何も作らず、
  その段のデバッグ表示が黒として見える。
- デバッグ表示は通常のフレームで作られた中間バッファを生成順に直接映し、GPU の計測は各描画段を実行順の行で示す。

**直す挙動**（手順と、何がどう変わるか）:

- パイプラインの順（SPEC の 4〜7 段）— 手順3 で SPEC を先に直す。
- 照り返しの源の反射率に r × R が入る — 粗い金属の面が照り返しを返すようになる（手順2。ユーザーが判定）。
- 照り返しの源の恒星が描画設定のモデル（既定は球）になる。render-lab の対照の球光源が源に入る（手順4b。ユーザーの判断で個別には
  確かめない）。
- 照り返しの源が、近さの打ち切りの外の面にも書かれる（手順4b）— 走査は受け手から 4 m 以内しか読まず、受け手は打ち切りの内側
  だけなので、変わるのは打ち切りの縁の受け手だけ。
- デバッグ表示「拡散照度」が ΔE を含まない（手順4a）。「マテリアル」が無くなる（手順4c）。

## 達成目標

1. 照り返しの源が光源を求めない — `src/` で `emittedRadiance` が0件、`ScreenSpacePass` の構築が `SunSource` を受けない。
2. 近傍補正が光源の列に無い — `src/` で `DiffuseCorrectionSource` が0件。ΔE を照度へ足すのは本マテリアルと映り込みの像の元の
   2か所で、どちらも同じ関数を通す。
3. 陰影の合成パスと `keep` の描画先が無い — `src/` で `ShadingCompositePass`・`keepTexture` が0件。
4. 「変えない挙動」の保存する挙動がすべて成り立ち、拡散側の撮影の封筒外は「直す挙動」で説明できる。
5. 手順1 と同じ構図・同じ session の計測で、組み直しの対象の行（ライティング・照り返し源・マテリアル・映り込みの像の元・
   陰影の合成）の和が、映り込みのオン・オフの両方で減る。
6. `DEVELOP/SPEC/RENDERING.md` の描画パイプラインの節が新しい順になっていて、コードより先に `docs(spec):` で commit されている。
7. デバッグ表示と GPU の行が新しい実行順に並び、`npm run test:render` が通る。

## 手順

### 手順 1. 組み直す前の負荷を測り、近傍補正の加算を単独で測る

**目的** — 「パス数と負荷の見積り」の近傍補正の加算を実測で置き換え、組み直しの前後を比べる基準を作る。この時点で挙動は変えない。

**変更が必要な箇所**（プローブ。commit しない）

| ファイル | 変更 |
| --- | --- |
| `src/render/gpu-timings.ts` | 仮の行「近傍補正の加算」 |
| `src/render/pipeline/light-prepass.ts` | 光源ごとに `gpu.beginPass` を呼ぶ所で、近傍補正の光源だけ仮の行へ計上する |

**達成条件と検証**

- `node tools/render-lab-measure.mjs 3 reflection` と `node tools/render-lab-measure.mjs 3 screen-space` を同じ session で回し、
  ライティング（近傍補正を除く）・近傍補正の加算・近傍拡散写しと源・マテリアル・映り込み・映り込みの均し・陰影の合成の表を、この計画の

  この commit を戻し、手順4b の源の式から r × R を除く。

### 手順 3. SPEC の描画パイプラインの節を直す

**目的** — パス順の変更は SPEC の描画パイプラインの節（13段階の 4〜7 段）を変える。コードより先に直す（`/modify-feature`）。

### 手順 4a. 近傍補正をライトプリパスの光源から外し、マテリアルで照度へ足す

**目的** — ΔE を足す場所を移す。今のパス順のまま行える（マテリアルは走査の後）。この時点で最終像は変えない（半精度の
足し算の順を除く）。「決めたこと」のデバッグ表示「拡散照度」の扱いを、着手前に拡散側と決めておく。

**変更が必要な箇所**

### 手順 4b. ライトプリパスを近傍の拡散光の前へ移し、照り返しの源をその照度から作る

**目的** — 照り返しの源の光源の評価をなくす。源はライトプリパスの照度を、走査の画素に対応する G バッファの画素で読む。

### 手順 4c. 映り込みの像の元を専用の描画にし、局所反射を本マテリアルの前へ移して陰影の合成を畳む

**目的** — 局所反射の合成を本マテリアルの中で1回にし、`keep` の描画先と陰影の合成パスを無くす。映り込みがオフのフレームは
