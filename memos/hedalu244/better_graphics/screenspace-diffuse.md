# 近傍拡散補正の再調整 — 算法を固めてから標本数を詰める（計画）

**計画ファイル。** `/run-plan` で上から実施し、完了した手順はこの文書から消す。各手順で採った案・
採らなかった案の実測は、その手順を消すときに「判断材料」の節へ書き足す。

---

## 目的

画面に写った近傍の構造が拡散照度へ与える補正 `ΔE = E_near_bounce − E_blocked_far`（塞がれた天体照と
一様な環境光を引き、塞いでいる面の自発光と一回反射を足す、符号付きの拡散照度）の**画質を、処理時間
あたりの効率で選んだ算法で作り直し、最後に許容負荷へ標本数を合わせる。**

### 補正を別のバッファに分けている理由

ライティングパスが求める拡散照度は、法線・材質・影の縁といった画素単位の細部を持つ。一方 ΔE は、
物体の輪郭と折れ目を除けば、受け手のまわり半径 4 m の半球にわたる積分なので低周波である。ΔE だけを
別のバッファへ出しているのは、**この低周波性を使って、少ない標本・低い解像度で求めた補正を、細部を
壊さずに空間方向へ均し・拡大するため**である（光源の数によらず走査を 1 回にすることも理由だが、
これは達成済みで、この計画では動かさない）。

したがって均し・デノイズ・拡大はどれも「少ない標本から基準を近似する手段」であり、その価値は、
**同じ処理時間で標本を増やしただけの補正（均しなし）より基準に近いか**でしか測れない。これに負ける
均しは入れない。

### 基準と、品質の2つの軸

**基準 B** — ある推定量（走査の算法: 標本の置き方・可視性の判定・重み・天体照の答え方）について、
処理時間を度外視して標本を増やしてモンテカルロ推定を収束させ、均し・拡大をすべて切った、全解像度の
補正。スクリーンスペースを使わない光線追跡が物理的な真値だが、画面外と背面が見えないのは原理上の
限界なので、この計画では扱わない。

品質は2つの軸で測る。

1. **収束先の品質** — B そのものの見た目と、荷室（`bay`）の解析値との差。重み・可視性の判定・天体照の
   答え方を変えると B 自体が変わる。
2. **近似の品質** — 実用の標本数・解像度・均し・拡大で作った補正の、B との差。偏り・粒（細かい
   誤差）・ムラ（数画素〜数十画素の斑）に分けて測り、**ムラを粒より重く見る。** 均しがノイズを
   消しきらない半径で掛かり、1 標本の外れ値を斑や四角へ広げるなら、均さないほうが良い。
   四角い斑・輪・暈・境界の漏れといったアーティファクトが見えないことは前提。

### 進め方の原則

- 標本数・処理時間を増やせば品質が上がり、減らせば軽くなるのは自明なので、それを比較にしない。
  候補は**同じ時間での品質**か**同じ品質での時間**で比べる。候補ごとに標本数を振って
  （時間, 誤差）の曲線を描き、曲線どうしを比べる。
- **算法を先に固め、標本数を詰めるのは最後。** 推定量（収束先を決める）→ 基準の確定 → 均し →
  多重スケール → 標本数、の順に進める。後段の評価は前段の出力に依存する。
- 案の出どころによらず、同時間・同品質の比較で逆効果なら採らない。

変えないもの（どの手順の後も保つ）:

- 設定「遮蔽と照り返し」がオフの絵、太陽直射と影、鏡面照度（どの設定でも補正は鏡面へ掛からない）。
- 拡散の遮られ方が光の来る向きに従うこと — 地球を左右へ動かすと、凹部の暗い側も同じ向きへ動く。
- 照り返しが返す面の明るさ・色・向かい合い方に連続に従い、一回だけ返ること。照り返しは送り手の面が
  受け手から張る角度に比例し（真横で連続に 0）、遮蔽は送り手の向きによらない。
- 走査は光源の数とモデルによらず 1 回。人間向けの設定は「方式（オフ / 遮蔽 / 遮蔽と照り返し）」と
  「精細さ（低 / 中 / 高）」だけ。
- 同じ入力を同じフレームで描けば同じ画像になる。時間方向の蓄積（前フレームの履歴）は持たない。
- 走査の解像度で投影半径 `r_px ≤ 1` の受け手の補正は厳密に 0、`1 < r_px < 2` は補正全体へ一度だけ
  `smoothstep(1, 2, r_px)` を掛ける。

レンズ効果・グロー・太陽光の遮蔽はこの計画の対象外。局所反射（鏡面の近傍像）は別計画で扱う。

## 決めたこと

覆すときは、各項目の括弧内の手順が変わる。

### K1. 基準 B の作り方（手順1・2・4）

- 走査の段を「解像度 1（描画バッファと同じ）・均しの半径 0（中心だけ）」にし、スライス数 × 歩数を
  増やした通常経路で描く。**B のための分岐は足さない** — 段の値だけで作る。解像度 1 では拡大が恒等に
  なり、半径 0 の均しは中心の重み 1 だけになる（手順1で恒等であることを float の読み戻しで確かめる）。
- 1 フレームの走査は GPU の打ち切り（Windows の TDR は既定 2 秒）に掛からない大きさに留める。見積り:
  960×540 の全解像度で片側 8 歩 × 3 スライス（48 標本/画素）が 51〜54 ms なので、16 スライス × 16 歩
  （512 標本/画素）は約 0.55 s。これを超える収束が要るなら、**ブルーノイズのずれ（seed）だけを変えた
  K フレーム**の raw を float で読み戻して平均する。
- 収束の判定: seed を変えた独立な B と B′ の差の知覚誤差 P（K2）が、現在の中設定の P の 1/10 以下。
  さらに歩数を倍にした B の差も同じ条件を満たす（接平面の切片は歩数で収束先が動くので、スライス方向
  だけでは足りない）。
- B は推定量を変えるたびに作り直し、作ったコミットのハッシュを添えて保存する。保存先は
  `E:\dive-into-tepui-shots\ssd-reference\<ハッシュ>\`（C: は計画時点で空きが 0〜200 MB しかない）。
- 解析値（`tools/render-lab/bay-cases.ts:258-273`）は距離重み `W = 1 − (d/R)²` を含まない。推定量そのものの
  偏りは、W = 1 にした一時版の B と解析値の差で読み、W ありの B と W = 1 の B の差は、距離による減衰という
  設計の効きとして別に記録する（ユーザーが収束先の見た目として判断する）。

### K2. 品質の指標（手順1・2）

撮影は `bay` 系のケースと角度（評価の組は手順2で固定する）。**誤差 e は同じセッションで撮った候補と
B の差**で取る。

- **帯域の分解** — 通常表示の sRGB 画像を Oklab へ写した差 e（L・a・b の3成分 — 照り返しの色のムラも
  数える）を、ガウスの差で周期 2・4・8・16・32・64 px のオクターブの帯へ分け、帯ごとの RMS b_j を並べる。
  **粒 = 周期 2〜4 px の帯、ムラ = 周期 8〜64 px の帯。** 走査の解像度 1/4 の raw を拡大した 4 px の塊は粒に、
  5×5 の均しが作る 15〜25 px の斑はムラに入る。
- **知覚誤差 P（候補を並べる軸）** — 帯の RMS を、その帯の空間周波数での視覚のコントラスト感度で重み付けた
  和 `P = sqrt(Σ_j (w_j · b_j)²)`。w_j は Mannos–Sakrison のコントラスト感度関数を最大 1 に正規化した値で、
  帯の周波数 [cycles/deg] は画面の画素密度 ppd [px/deg] を帯の周期 [px] で割って出す。感度は数 cycles/deg で
  最大になり高い周波数で落ちるので、**同じ分散なら、数十画素のムラを 1〜2 画素の粒より重く数える。**
  ppd は手順2の較正で決める（初期値は、ユーザーが render-lab を見ている画面の横の画素数 ÷ 視野角）。
- **偏りと分散の切り分け（診断）** — 候補を seed を変えて 2 回撮り、2 枚の平均と B の差を偏り（均しの
  ぼけ・推定量の違い）、2 枚の差を分散（残った粒とムラ）として、それぞれ帯に分ける。
- **偏り** — 解析値のある窓（P_in・P_out・P_base・P_bleed・P_glow）の 5×5 平均の、B と解析値に対する差。
  線形の拡散照度（float の読み戻し）で読む。
- **境界の漏れ** — 深度・法線の境から 2 px 以内の面の画素での e の RMS（既存の指標の定義を引き継ぐ）。
- **ちらつき** — カメラを少しずつ動かした連続フレームで、候補の差分と B の差分の差の平均絶対値。
  静止したノイズ模様が面に対して泳ぐ分だけを数える。
- **有界性** — 拡散照度 + 補正 < 0 の画素のうち、表示で 1 LSB 以上暗く出るもの（float の読み戻し）。
- **費用** — 照り返し源・走査・均し・拡大の各行の GPU 時間の p50（マテリアル行に対する比）。比べる候補は
  **同じページで交互に**測る（ページを読み直すと同じビルドでも 0.6〜1.04 倍ぶれる）。

どの指標も、背景と、**どの候補の解像度でもフェードの外にある画素**（走査の解像度 1/4 で `r_px > 2`）
だけで測る。B は全解像度なので、1/4 の候補がフェードで 0 にする遠くの画素にも補正を持つ — そこを
誤差に数えると、解像度の比較が遠景の扱いだけで決まる。

指標は視覚の代理なので、候補を採るときは、誤差を 8 倍に強調した画像を必ず目で見る。

### K3. 合否の点はユーザーの目視で較正する（手順2・7）

手順2で、B・均す前の raw（中設定）・いまの中設定（均し後）・標本数を振った raw の列を並べ、ユーザーが
「許容できる粒」「許容できないムラ」を選ぶ。まず ppd を、ユーザーの目視の順序と P の順序が揃う値に決め、
その上で境の P と、ムラの帯の RMS を合否の点 P\*・M\* とする。
いまの中設定（均し後）はムラが強く不合格、均す前の raw は粒が多いが質は良い、という現時点の評価が、
較正の最初の2点になる。

### K4. 比べ方（手順3〜7）

- 候補は、標本数（スライス × 歩数、均しの本数）を振った 4 点以上で（費用, P）の曲線を描く。
  **均しを持つ候補には、必ず「均しなしで標本を増やしたもの」を対照として並べる。**
- 採る条件は、予算（K5）の範囲で曲線が既存案の曲線より下にあること（同じ時間で P が小さい）。
  1 点ずつの比較には効率 `1 / (P² · T)` を使う（モンテカルロの効率 1 / (分散 × 時間) を、均しの偏りを含む
  誤差へ広げたもの）。
  差がセッション間のぶれ（手順1で測る）以内なら同等とみなし、単純なほうを採る。
- 算法の候補は捨てる前提の一時コードで比べ、**採った案だけを commit する。** 候補を切り替える
  仕掛け（大域変数・未使用の分岐）は commit に残さない。

### K5. 負荷の予算（手順7）

960×540・`bay`・同じページで交互に測った p50 の、マテリアル行に対する比。

| 精細さ | 遮蔽と照り返し | 遮蔽 |
| --- | --- | --- |
| 低 | 3.5 倍以下 | 3 倍以下 |
| 中 | 5 倍以下 | 4 倍以下 |
| 高 | 8 倍以下 | 7 倍以下 |

中の値はこれまでの目標を引き継ぐ。低と高は、中の 0.7 倍と 1.6 倍を目安に置いた（精細さの段は
「上げるほど重くなる」ことだけが決まっている）。1080p の中間 target は一時 target 込みで中 32 MiB 以下、
高 64 MiB 以下。「修正前の何割」という目標は、修正前がどのコミットを指すかが曖昧なので置かない。

### K6. 計測の入口を commit する（手順1）

これまでの候補の比較・float の読み戻し・同じページでの交互の計時は、どれも commit されない一時の
パッチ（大域変数、クロージャをたどって LabView を掴む仕掛け）で行われ、再現できない。再調整は今後も
起きるので、次の入口を本番のコードと render-lab へ残す。

- 走査の段（解像度・スライス数・歩数・均しの半径）を値として与える入口。本番は精細さの表の値を渡し、
  render-lab は任意の値を渡す。**人間向けの設定は増やさない。**
- ブルーノイズのずれ（seed）を与える入口。本番は常に 0。
- render-lab から、補正の各 target（raw・均した後・拡大後）と拡散照度を float で読み戻す API。
- GPU の行「近傍拡散復元」を「均し」と「拡大」に分ける（均しの費用を単独で測れないと、均しと標本数の
  同時間比較ができない）。

### K7. 標本の置き方（手順3）

いまの走査は、歩 k の画面距離を `ρ = max(((k + j)/N)² · R, 1)` とし、ずれ j は画素ごとの blue noise
1 つを**全スライス・両側・全歩で共有**している（`src/render/pipeline/screen-space/hemisphere-scan.ts:91-94,119`）。
床を 1 走査画素にしているので受け手の画素そのものは読まないが、加算のずらしではないため、半径の小さい
受け手では歩が同じ画素に重なる。中設定（片側 4 歩）で計算すると、R = 3 px で 4 歩中 1.8〜2.4、R = 6 px で
1〜1.4 歩が直前と同じ画素を読み直す（重複は `newly` のビット演算で二重には数えないが、読みが無駄になる）。
また j を全スライスで共有するので、1 画素の中の全方向が同じ半径の列を読み、スライスを増やしても半径方向の
ずれは平均されない。

直し方の候補（手順3で同時間比較して決める）:

- **加算のずらし** — `ρ = ρ_min + ((k + j_ik)/N)² · (R − ρ_min)`、ρ_min = 1 走査画素。XeGTAO は二乗の配分の
  後に 1.3 px を足し（「中心の画素を読まないための最小距離」）、HBAO は `1 + 乱数 × 歩幅` で最初の歩を 1 texel 以上
  離す。床で潰さないので、歩のずれがそのまま画素の違いになる。
- **歩とスライスごとのずれ** — XeGTAO と同じく `j_ik = fract(j + (i + k·S)·φ)`（S はスライス数、φ は黄金比の
  逆数）。各歩は自分の層 [k/N, (k+1)/N) に留まったまま、1 画素の中で方向ごと・歩ごとにずれが変わり、スライス
  方向の平均で半径方向のずれも均される。SAO は、隣り合うタップが同じ画素へ落ちると分散が増えてちらつくと
  報告している。
- **歩数の頭打ち** — 片側で読める異なる画素の数（軸方向で ⌊R⌋、斜めで ⌊0.707R⌋）を超える歩を読まない。
  余った予算をスライスへ回すかは、同時間比較で決める。
- **照り返しの源の前置フィルター** — 照り返しの源は、走査の画素 1 つにつき G バッファの 1 画素（4×4 の中の
  1 つ）を読んでいる。明るい細部を当てたり外したりすることが、暗い所で強い照り返しを 1 標本だけ拾う
  外れ値の源になりうるので、4×4 の平均を源とする案を比べる。

いまの走査の各画素の半径は blue noise で画素ごとに違うので、決定的な等間隔の歩みが作る同心円の模様は
原理的には出ない。ただし小さい R で床と丸めが多くの j を同じ画素へ潰すため、奥へ遠ざかる面で「読める
異なる標本の数」が R の整数の境で段になり、等高線状の帯が出うる（未確認。手順3で見る）。

### K8. 天体照の答え方（手順4）

拡散の補正が天体照を引く式は、受け手ごとに 1 回求める天体照 E_p（球光源の Snyder の式 + 天体の像の
mip 1 回の読み + 満ち欠け）に、塞がれた割合 f_p を掛ける比推定である
（`src/render/pipeline/lighting/planet-light-source.ts:198-215`、`src/render/pipeline/lighting/sphere-light.ts:15-33`）。
**拡散では LTC を使っておらず（LTC は鏡面だけ）、高い光源の評価は標本ごとでもスライスごとでもなく
画素ごとに 1 回**である。スライスごとには球冠の範囲（atan・acos・cos 2 回）と楔の重み（acos）、歩ごとには
塞いだ扇形の球冠との重なり（popcount 3 回）が、天体のスロット 2 つぶん走る。

「天体を十分遠い光源とみなし、塞がれた向きの光を、比推定と球光源の式を通さずテクスチャの読み 1 回で
答える」案は、省ける費用がこの画素ごと・スライスごとの分だけなので、**まず外したときの時間を測る。**
比推定（Heitz, Hill, McGuire 2018）は、遮られないときの照度を解析的に求めて塞がれた割合だけを推定するので、
ライティングと引く量が同じ式で揃う。向きごとの読み（SSDO、GTAO の曲げた法線 + 前置フィルターした環境
マップ）へ替えると、この揃いを失う代わりに何が速くなるかを数字で示す必要がある。

- 天体照にかかる処理（受け手の E_p、照り返し源の天体照、球冠と楔、歩ごとの重なり）を定数に置き換えた
  版と同じページで交互に測り、走査 + 照り返し源の時間の 10% 未満しか省けないなら、この案は実施しない。
- 10% 以上なら、答え方を変えた版を作り、(a) 省けた時間、(b) B どうしの差（完全に塞がれた内隅で
  ライティングの天体照と引く量が食い違う残り、`E_far = 0` の面で ΔE ≠ 0 になる画素）を測る。速くて
  差が目立たなければ近似として採る。速いが差が目立つなら、ライティング側の答え方を見直す別計画を立てる。
  大差ないか遅くなるなら採らない。
- 結果を変えない省略（使っていないスロットの評価、`select` で両方の枝を評価している天体の像の読み）は、
  同じ比較で効きが測れたときだけ入れる。

小天体の偏り（中設定の moon-open が 0.68、解析値 1.00）もこの手順で扱う。スライスを 16 本にしても
0.72〜0.78 に留まる一方、距離重みを外して歩数を増やすと 1.000 に収束した実測がある。距離重みは遮りを
弱める側にしか働かないので、遮りすぎの原因は歩数（切片の粗さ）か、1 扇形より小さい球冠と丸めのずれの
どちらかである。手順2の B で切り分け、B（収束した値）にも偏りが残るなら、64 扇形・球冠の塞がれ方を
切片の連続した角度範囲との重なりで測る案を、B の偏りと費用で比べる。

### K9. 均しの候補（手順5）

- **D0 均しなし** — 対照。走査の解像度のまま拡大だけする。
- **D1 いまの 5×5** — 走査の解像度でガウス（σ = 1 走査画素）× 平面の距離 × 法線の重み。平面の距離を
  **全解像度 1 画素の footprint で割っているのに、タップは 4〜8 全解像度画素離れている**
  （`src/render/pipeline/screen-space/correction-reconstruction.ts:86-107`）ため、曲面では中心の 1 タップへ潰れ、
  拡大で走査画素の raw が 4×4 の塊として出る。
- **D1′** — D1 の平面の許容をタップの距離に比例させる（深度の勾配で許容を広げる、SVGF と同じ考え方）。
- **D2 確率的なタップ** — 半径 r の円盤に置いた K 本のタップを画素ごとに blue noise で回し、ガウスの重み ×
  平面 × 法線で均す（NVIDIA REBLUR の空間段は、画素ごとに回した 8 本の Poisson 円盤を適応的な半径で使う）。
  同じ時間で広い半径へ外れ値を散らし、四角ではなく細かい点にする。
- **D3 二段** — D2 の後に小さい密な均し（3×3）で、D2 が残すタップの粒を消す。
- **D4 多段の小さい均し** — エッジを見る 5 タップを間隔 2 で数回、最後に間隔 1 で掛ける（Godot の SSIL は既定
  4 段、AMD CACAO は既定 2 段）、または間隔を倍にしていく à-trous を 2〜3 段。à-trous は孤立した明るい画素を
  十分に均せないと原論文（Dammertz 2010）が述べているので、外れ値の多い `bay-dark` で比べる。
- 拡大は、いまの 2×2 の双一次 × 平面 × 法線を基本とし、**拡大をライティングの読みへ畳んで全解像度の
  補正 target をなくす案**（全解像度の拡大がマテリアル行の 1.2〜1.4 倍を占める）を、結果が同じまま
  速くなるかで比べる。畳むなら、全解像度の補正 target とそのデバッグ表示はなくなる（存在しない中間
  バッファは見せなくてよい）。

外れ値を均す前に切る（中心を除いた近傍の最大での clamp・3×3 の中央値・輝度の逆数 `1/(1+L)` の重み）は
偏りを作る（輝度の逆数の重みは凹関数の平均なので必ず暗い側へ寄り、分散の大きい所ほど暗くなる）ので、
上の候補で外れ値が四角や斑として残るときだけ候補に足し、足した偏りを B に対して測る。
単一フレームで効く分散の案内（SVGF の 7×7 の空間分散で輝度の差の許容を決める重み）も、平面と法線の
重みで境界の漏れが残るときの候補とする。

### K10. 多重スケール（手順6）

一次の可視性（手前の遮りの後ろを数えない）は、方向ごとの走査でも標本が疎なら取りこぼされ、スライス
どうしでは共有されない。それでも画素ごとのずれで平均すると品質は保たれる（1 方向 1 標本に近い Alchemy AO
が例）。スクリーンスペースは奥へ続く壁と棒を区別できず遮りを多めに見積もるので、スケールをまたぐ
可視性を取りこぼして漏れる分は、誤差の向きとして打ち消し合う側にある。**そこで「一次の可視性を
スケールをまたいで保てない」ことは多重スケールを禁じる理由にしない。** 採るかは、収束先の見た目と
同時間比較で決める。

- **スケールの分け方** — 距離の帯で分ける。2 段なら近い帯 [0, R/4] を走査の解像度 1/4 のまま（または
  1/2）、遠い帯 [R/4, R] を 1/8〜1/16 で走査し、帯ごとの画面上の半径（走査画素）を揃える。各帯は自分の
  扇形ビットで帯の中だけの一次の可視性を取り、スライスの回転を帯ごとに π/(スライス数 × 帯数) ずらす。
- **遠い帯の最初の切片は帯の内側の境の視線から始める** — いまの走査は受け手自身を最初の標本とみなして
  受け手から最初の標本までを接平面で埋めるので、遠い帯でそれをすると近い帯の構造を二重に数える。
- **帯の合成** — スカラーの AO と違い色付きの符号付き補正なので max は使えない。候補は
  (a) 前から奥への重ね合わせ: 近い帯が塞いだ余弦測度の割合 α_near（補正 target の空いている a に置く）で
  `ΔE = ΔE_near + (1 − α_near)·ΔE_far`、(b) 単純な和、(c) 平均。**収束した値（B_MS）どうしで比べて決める。**
  (a) が本命: 2 つの遮りの真の塞がれ方は max(A_a, A_b) ≤ A_ab ≤ A_a + A_b の間にあり、遮りどうしが無相関なら
  `1 − A_ab = (1 − A_a)(1 − A_b)`（Kontkanen & Laine 2005 の AO の合成）。色は voxel cone tracing（Crassin 2011）の
  前から奥への合成 `c ← c + (1 − α)·c₂` と同じ形になる。(b) は重なった向きを二重に数え、(c) は帯が分け合う
  距離の範囲に対してどの帯の効きも半分にする。MSSAO はスカラーで `1 − (1 − AO_max)(1 − AO_avg)`、HBAO+ は
  2 帯の線形の重み付き和、GTAO は遠方の焼き込みとの min を使う。
- **合成の順** — MSSAO は、粗い段ごとに 3×3 の双方向の均し → 深度・法線で重み付けた拡大 → 細かい段と合成、
  を繰り返し、粗い段ほど何度も均される（最も細かい段は均さない）。これと、帯ごとに均して足すだけの案を
  比べる。拡大する前に粒をほぼ消しておかないと、拡大で粒が大きなムラになる。
- **大半径のキャッシュの外れ（狙い (2)）だけなら、走査を分けずに読みを粗くする案もある** — SAO は深度の
  縮小列（回した格子で 1 画素を選ぶ点標本）を距離に応じた段で読み、大半径の読みのキャッシュの外れを O(r) から
  定数にして、帯域の改善と合わせて 7 倍速くした（XeGTAO も同じ縮小列を使う）。この走査は深度・法線・照り返しの
  源を読むので、3 つを同じ画素から選ぶ縮小列が要る。多重スケールと同じ時間の P で比べる候補にする。
- **先に一次の可視性の効きを測る B_A** — 片側 1 歩（ずれた半径の標本 1 つ）× 多数のスライスの段で作った
  基準。方向の中でも一次の可視性を捨てた Alchemy AO 型の推定量の収束先で、**段の値だけで作れる（コードを
  変えない）。** B_A と B の差が許容範囲なら、帯の中では一次の可視性を保つ多重スケールの漏れはそれより
  小さいと見込める。許容できないほど違うなら、B_MS の比較で帯の数を増やす案に重みを置かない。
- **第二の基準 B_MS** — 全帯を全解像度・均しなし・標本を増やして収束させた多重スケールの推定量。
  B_MS と B の差（光の漏れ）を目視と解析値で見て、許容できるときだけ次へ進む。進んだら、多重スケールの
  実用の構成の誤差は B（主）に対して測り、B_MS との差で「収束先の違い」と「近似の誤差」を分けて読む。

多重スケールで狙うのは、(1) 大半径のぼんやりした効きと小半径の締まった効きの両立、(2) 大半径の
走査がテクスチャのキャッシュを外す費用の削減、(3) 大半径を高解像度で求めることによる疎な粒の削減、
(4) 大半径の粒を均しきるのに要る費用の削減。品質の向上と費用の調整が混ざるので、(1)(3) は同じ時間の
P で、(2)(4) は同じ P の時間で読む。

### 採らない案（問題が残るもの）

同じ案を再提案しないために、問題だけを残す。

| 案 | 採らない理由 | 残る問題 |
| --- | --- | --- |
| 標本の画素の接平面の角 footprint だけを塞ぐ（標本の間を埋めない） | 遮蔽が読んだ画素の割合まで痩せ、歩数を倍にするたびに遮蔽がほぼ倍になる | なし（接平面の切片で間を埋めている） |
| 照り返しを面積の form factor × 1/pdf で積む | 1 標本の重みが半球 2π を超え、raw の最大が遠方光の数千倍の明るい斑になる | 照り返しは方向の測度で積む。1 標本の寄与は π × 源の放射輝度で頭打ち |
| 自己遮蔽を避ける閾値 | 斜めに見た壁の足元を数十 cm 捨てる | 余弦重みの測度が地平の近くで 0 になるので閾値は要らない |
| 小天体をスライスと球冠の弦の当たり外れで数える | 当たった画素だけ天体照そのものを超えて引く | 楔の補間の比推定で有界。小天体の影が方位の離れたスライスの地平で決まることが目立つなら、光源の方位に揃えた走査を足す別計画（走査数が光源数に依存する） |
| 空の天体照スロットごとに走査のマテリアルを分ける | `bay` で 12〜20% 減るが、切り替えのたびに 1 方式約 3 秒のコンパイル、2 天体では効かない | — |
| 走査の解像度に位置と法線の案内 target を足す | 1080p 中設定の中間 target が 35.6 MiB で上限を超え、復元は速くならなかった | — |
| 均しの縦横分離 | 境界の漏れが悪化した | — |
| 時間方向の蓄積 | 同じ入力で同じ画像にならず、静止した絵がちらつく | 空間だけで収める |
| 深度の標本を一定の厚みの板として奥へ押し出す | 単層の深度から真の厚みは得られず、厚み（1.1 m・2 m）が絵合わせの自由度になる | 奥へ続く壁と棒を区別できず、遮りを多めに見積もる（K10 の漏れと打ち消し合う側） |

### 判断材料（実測）

- 精細さの段（走査の解像度 1/4、スライス × 片側の歩数）は低 2×3・中 3×4・高 4×6。1/2 と 1/4 × スライス 1〜4 ×
  歩数 2〜8 の行列では、同じ標本数なら 1/4 でスライスを増やすほうが指標が良いか同等で、費用はおよそ半分。
  スライスを増やすと連続フレーム差が減り、歩数を増やすと増える。片側 3 歩は近接の照り返しを 17〜28% 過小に
  見積もる。
- 中設定の費用（マテリアル行に対する比）: 遮蔽 5.0 倍、遮蔽と照り返し 5.4〜5.6 倍。内訳は照り返し源 0.4、
  走査 2.5、均しと拡大 2.4（全解像度の拡大が 1.2〜1.4）。1080p の中間 target は全段 18.8 MiB。走査の費用は
  ほぼ標本数に比例し、結果を変えない省略の余地は小さい（位置の復元を丸ごと消しても 0.88〜0.91 倍）。走査の
  うち標本を読むだけで約 0.28、切片への分割で約 0.3 を占める。
- 全解像度で 8 本の確率的なタップの均しは、密な 5×5 より、解析値のある窓の誤差の標準偏差が 2〜5 倍悪かった
  （当時の基準は均した高設定で、同時間比較でも収束した基準でもない。K9 の D2 はこの結果を、B に対する
  同時間比較で測り直す）。
- 計測は Intel HD Graphics 520。ページの読み直しで同じビルドでも 0.6〜1.04 倍ぶれ、Chrome のセッションが
  違うと閾値に乗った画素の raw が 2 通りに分かれる（同じセッションの中では決定的）。
- 中設定の P_in / P_out（遮蔽 / 遮蔽と照り返し）: overhead .381/.522、open .516/.867、corner .060/.060、
  moon-open .680/.988、moon-corner .051/.051。高: overhead .386/.532、open .614/.982、corner .055/.058、
  moon-open .748/1.070、moon-corner .037/.040。解析値は `tools/render-lab/bay-cases.ts:258-273`
  （遮蔽 .32/.64/0/1.00/0、遮蔽と照り返し .49/1.06/0/1.38/0）。
- `bounce-cosine`（源の余弦 1 / 0.5 / 0）の照り返しの比は、有限の面光源の解析値で受け手の中心 1 / 0.58 / 0、
  受け手全体 1 / 0.37 / 0.05。いまの走査はこれに 0.07 以内。
- `r_px` が数 px の受け手では、標本の画素への丸めで補正が 1 歩ごとに E の約 4% 揺れる。
- 中設定の +X 壁の内側 0.25〜0.95 m の遮蔽の比 0.15〜0.38 は 2 スライスの楔の補間による（8 × 96 で解析値 × 距離
  重みに一致）。
- 復元後に拡散照度 + 補正 < 0 の画素が 16 組の readback で約 2300 px（大半は完全に遮られた隅の遮蔽方式と、
  曲面で 30° 以内の法線の天体照を混ぜる分）。PNG の量子化の外で確かに負なのは 0〜2 px。
- 最初の `measure` はシェーダのコンパイルで約 57 s かかり、CDP の要求ごとの待ち時間 60 s
  （`tools/chrome-session.mjs:102`）で落ちることがある。

## 達成目標

### 品質

1. 中設定の最終構成が、評価の組のどのケースでも P ≤ P\*、ムラの帯の RMS ≤ M\*（K3）。低・高も
   ムラ ≤ M\*（低は粒で妥協し、ムラでは妥協しない）。P は低 ≥ 中 ≥ 高。
2. 均し・拡大を持つ最終構成は、同じ時間の「均しなしで標本を増やしたもの」より P が小さい。小さくならない
   均しは入っていない。
3. 距離重み W = 1 の B の P_in / P_out が解析値から、大きい天体で ±0.06、小天体（moon-*）で ±0.10 以内。
   外れるなら、その理由（画面外・背面など原理上の限界）を判断材料に書いてある。中設定の最終構成は
   B（W あり）から ±0.06 以内。
4. 誤差を 8 倍に強調した画像に、四角い斑・同心円や等高線の帯・`bay-truss` の梁から 4 px より外の暈・
   `bay-edge` の直線の段差がない。
5. 拡散照度 + 補正 < 0 で表示が 1 LSB 以上暗くなる画素が 0。

### 保つもの

6. 同一フレームのデバッグ「鏡面照度」が、方式オフ / 遮蔽 / 遮蔽と照り返しの相互比較で差 0（`leo-metal`・
   `bay-metal` を含む）。
7. オフの撮影組が、着手前に撮った組に対して `render-lab:compare` の封筒外 0 件。
8. 地球を左右へ動かすと、負の補正が同じ向きへ動く（`bay-earth-overhead` / `-open` / `-corner`）。
9. 走査の描画命令は光源の数とモデルによらず 1 本（多重スケールなら帯の数だけ）。`r_px ≤ 1` の画素は
   raw・復元後とも厳密に 0 で、1〜2 px の距離スイープに段差がない。
10. 人間向けの設定が「方式」と「精細さ」だけ。見た目の調整定数（固定厚み・独立したフェード開始・最小天体角・

    受け手全体 1 / 0.37 / 0.05）の ±0.10 以内。
