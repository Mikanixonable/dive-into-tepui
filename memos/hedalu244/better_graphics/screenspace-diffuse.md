# 近傍拡散補正の再調整 — 算法を固めてから標本数を詰める（計画）

**計画ファイル。** `/run-plan` で上から実施し、完了した手順はこの文書から消す。各手順で採った案・
採らなかった案の実測は、その手順を消すときに「判断材料」の節へ書き足す。

---

## 目的

画面に写った近傍の構造が拡散照度へ与える補正 `ΔE = E_near_bounce − E_blocked_far`（塞がれた天体照と
一様な環境光を引き、塞いでいる面の自発光と一回反射を足す、符号付きの拡散照度）の**画質を、処理時間
あたりの効率で選んだ算法で作り直し、最後に許容負荷へ標本数を合わせる。**

### 補正を別のバッファに分けている理由

ライティングパスが求める拡散照度は、法線・材質・影の縁といった画素単位の細部を持つ。一方 ΔE は、
物体の輪郭と折れ目を除けば、受け手のまわり半径 4 m の半球にわたる積分なので低周波である。ΔE だけを
別のバッファへ出しているのは、**この低周波性を使って、少ない標本・低い解像度で求めた補正を、細部を
壊さずに空間方向へ均し・拡大するため**である（光源の数によらず走査を 1 回にすることも理由だが、
これは達成済みで、この計画では動かさない）。

したがって均し・デノイズ・拡大はどれも「少ない標本から基準を近似する手段」であり、その価値は、
**同じ処理時間で標本を増やしただけの補正（均しなし）より、偽の構造を作らずに基準に近いか**でしか
測れない。これに負ける均しは入れない。低周波性が効くのは、均しが真値をぼかす偏りが小さいことに対して
であって、**誤差のうち均しの半径より粗い成分は均しでは減らない**（K2）。

### 基準と、品質の2つの軸

**基準 B** — ある推定量（走査の算法: 標本の置き方・可視性の判定・重み・天体照の答え方）について、
処理時間を度外視して標本を増やしてモンテカルロ推定を収束させ、均し・拡大をすべて切った、全解像度の
補正。スクリーンスペースを使わない光線追跡が物理的な真値だが、画面外と背面が見えないのは原理上の
限界なので、この計画では扱わない。

品質は2つの軸で測る。

1. **収束先の品質** — B そのものの見た目と、荷室（`bay`）の解析値との差。重み・可視性の判定・天体照の
   答え方を変えると B 自体が変わる。
2. **近似の品質** — 実用の標本数・解像度・均し・拡大で作った補正の、B との差。誤差が画面に見えている粒で
   説明できるか（正直さ）と、誤差と粒そのものの小ささ（S/N）の2軸があり、区間スコア S で1つに並べる
   （K2）。いまの粒の大きさでは正直でないことによるムラが見た目を大きく下げているが、見えない大きさまで
   誤差が小さければ多少の食い違いは許す。均しがノイズを消しきらない半径で掛かり、1 標本の外れ値を斑や
   四角へ広げるなら、均さないほうが良い。四角い斑・輪・暈・境界の漏れも偽の構造に入る。

### 進め方の原則

- 標本数・処理時間を増やせば品質が上がり、減らせば軽くなるのは自明なので、それを比較にしない。
  候補は**同じ時間での品質**か**同じ品質での時間**で比べる。候補ごとに標本数を振って
  （時間, 誤差）の曲線を描き、曲線どうしを比べる。
- **物差しは 2 つ。** 品質を数で測るための**収束先 B**（K1 — 実機の時間を度外視して収束させる）と、同じ時間・
  同じ品質で比べる相手の**愚直な曲線** — 実機で動く範囲で、いまの段のスライスだけを増やした均しなしの
  （費用, S）の表（手順2の `compare` の既定の候補）。均しや多重スケールの候補は、この曲線より下に来て初めて採る。
- **算法を先に固め、標本数を詰めるのは最後。** 推定量（収束先を決める）→ 基準の確定 → 均し →
  多重スケール → 標本数、の順に進める。後段の評価は前段の出力に依存する。
- 案の出どころによらず、同時間・同品質の比較で逆効果なら採らない。
- **期待の薄い案に時間を使いすぎない。** K7・K9・K10 で候補を本命・条件付き・期待が薄いに分け、期待が
  薄い案は 1 点の計測で早く棄てる（K4）。

変えないもの（どの手順の後も保つ）:

- 設定「遮蔽と照り返し」がオフの絵、太陽直射と影、鏡面照度（どの設定でも補正は鏡面へ掛からない）。
- 拡散の遮られ方が光の来る向きに従うこと — 地球を左右へ動かすと、凹部の暗い側も同じ向きへ動く。
- 照り返しが返す面の明るさ・色・向かい合い方に連続に従い、一回だけ返ること。照り返しは送り手の面が
  受け手から張る角度に比例し（真横で連続に 0）、遮蔽は送り手の向きによらない。
- 走査は光源の数とモデルによらず 1 回。人間向けの設定は「方式（オフ / 遮蔽 / 遮蔽と照り返し）」と
  「精細さ（低 / 中 / 高）」だけ。
- 同じ入力を同じフレームで描けば同じ画像になる。時間方向の蓄積（前フレームの履歴）は持たない。
- 走査の解像度で投影半径 `r_px ≤ 1` の受け手の補正は厳密に 0、`1 < r_px < 2` は補正全体へ一度だけ
  `smoothstep(1, 2, r_px)` を掛ける。

レンズ効果・グロー・太陽光の遮蔽はこの計画の対象外。局所反射（鏡面の近傍像）は別計画で扱う。

## 決めたこと

覆すときは、各項目の括弧内の手順が変わる。

### K1. 基準 B の作り方（手順2・4・6）

- 走査の段を「解像度 1（描画バッファと同じ）・均しの半径 0（中心だけ）」にし、スライス数 × 歩数を
  増やした通常経路で描く。**B のための分岐は足さない** — 段の値と seed だけで作る。解像度 1 では拡大が恒等に
  なり、半径 0 の均しは中心の重み 1 だけになる（均しは raw とビット一致、拡大は補正のピークの 0.08% 以内 — 判断材料）。
- **B は実機の時間を度外視して収束させる物差しで、1 フレームの GPU の打ち切り（Windows の TDR は既定 2 秒）を
  理由に標本を減らさない。** モンテカルロの標本を複数のパスに分け、パスごとに seed（ブルーノイズのタイルの
  2 次元のずれ）を変えて撮り、あとから平均する。1 パスは打ち切りに掛からない大きさ（1 パスのスライス × 片側の
  歩数 ≤ 256。960×540 の全解像度で片側 8 歩 × 3 スライスが 51〜54 ms なので、256 で約 0.3 s）に留める。
- **方向はパスの数で稼ぐ。** スライスの向きは画素ごとの回転で決まり、パスごとに回転が変わるので、1 パスの
  スライス数は収束先を変えず、画素の方向の総数は 1 パスのスライス数 × パス数になる。遮るものの有無は方向で
  大きく変わるので、雑音の大半は方向から来る。**歩数は収束先を動かす**（地平と接平面の切片は歩の置き方に
  非線形に依る）ので、方向とは別に確かめる。
- seed はタイルの 64 × 64 通りの整数のずれを、2 次元の黄金比の列（R2 列）の順に重複なく使う — どのパス数で
  止めても、画素ごとに読むタイルの位置が一様に散る。手順1の 1 次元の斜めのずれは 64 通りで打ち止めになり、
  それ以上パスを重ねても収束しない。seed (0, 0) は本番と同じ絵。
- パスは偶数番目と奇数番目の半分ずつに分けて和を保存する。**半分どうしの差が B の残りの雑音を測る**（B 自身の
  雑音の約 2 倍。追加の撮影は要らない）。パスを足すときは保存した和へ続きから足す。
- 収束の判定は、**まず複雑な 1 撮影（`bay`）だけで行い**、満たした（1 パスのスライス, 歩数, パス数）で残りの
  撮影を作る:
  1. **雑音** — 半分どうしの差の G（K2）が、いまの中設定（均しなし）の B に対する誤差の G の 1/10 以下で、差の
     R(s)（K2）がどの帯でも最も細かい帯の R(1) の 1.5 倍以下（収束しきらない粗い構造がない）。R の水準そのものは
     見ない — 残りの雑音は、照り返しの源を稀にしか拾わない画素の斑で裾が重く、どの帯の R も一様に 1 を超える
     （判断材料）。斑の大きさは G が測る。満たさなければパスを倍にする。
  2. **歩数** — 1 パスのスライス数とパス数を揃えて歩数だけを倍にした B₂（1. を満たすもの）との差の G が、
     同じく 1/10 以下。満たさなければ B₂ を B とし、歩数をさらに倍にして繰り返す。打ち切りの予算を越えるなら
     1 パスのスライスを半分にしてパスを倍にする（比べる 2 つは同じ 1 パスのスライス数で）。
  残りの撮影にも 1. を当て（半分どうしの差は追加の撮影なしに出て、比べる中設定を 1 枚撮るだけ）、満たさない撮影は
  パスを倍にする。後のセッションで足すとセッションのモードが混ざるが、その差（G 約 0.0003）は閾より十分小さい。
- **B は平均の表示であって、表示の平均ではない。** パスで平均するのは合成前の線形の輝度（HDR。補正に対して線形）で、
  その平均へ本番の合成（露出・トーンマップ・色の LUT・出力の色空間）を 1 回掛け、8 bit へ丸める前の float で読む。
  表示は非線形なので、表示を平均すると 1 パスの分散に依る偏りと 8 bit の丸めの偏り（最大 0.5 LSB、Oklab の L で約 0.002）
  が残って収束先が 1 パスの設定で動き、等輝度線の弧と筋として出る。これは収束の条件の閾（中設定の G の 1/10 ≈ 0.0016）と
  同じ大きさで、半分どうしの差には出ない（判断材料）。候補は画面と同じ PNG で撮る。
- 評価では描画設定の antialias（SMAA）を切る — 8 bit の表示に掛かって誤差を縁の向こうへ混ぜ、B の合成にも掛からない
  （レンズ効果を切るのと同じ理由）。
- **再現手順**（推定量を変えて B を作り直すたびに、この順で。`<名前>` は作ったコミットの短いハッシュ）:
  1. `node tools/render-lab-screen-space-metrics.mjs reference --name <名前> --entries bay --slices <S> --steps <T> --passes <N>`
  2. `node tools/render-lab-screen-space-metrics.mjs reference --name <名前>-steps2x --entries bay --slices <S> --steps <2T> --passes <N>`
  3. `node tools/render-lab-screen-space-metrics.mjs check <名前> <名前>-steps2x`（1. と 2. の条件の表）
  4. 満たさなければ、1〜3 を `--passes` か `--steps` を倍にして繰り返す（同じ名前へ続きから足す）。
  5. `node tools/render-lab-screen-space-metrics.mjs reference --name <名前> --slices <S> --steps <T> --passes <N>`
     （全撮影。済んだ撮影は飛ばす）
  前回の（S, T, N）は「判断材料」にある。
- B は推定量を変えるたびに作り直し、作ったコミットのハッシュを添えて保存する。保存先は
  `E:\dive-into-tepui-shots\ssd-reference\<ハッシュ>\`（撮影組と同じ E:。C: は空きが 1 GB 未満）。
- 解析値（`tools/render-lab/bay-cases.ts:258-273`）は距離重み `W = 1 − (d/R)²` を含まない。推定量そのものの
  偏りは、W = 1 にした一時版の B と解析値の差で読み、W ありの B と W = 1 の B の差は、距離による減衰という
  設計の効きとして別に記録する（ユーザーが収束先の見た目として判断する）。

### K2. 粒は相対的にましでムラが悪く見える理由と、品質の指標（手順2〜7）

**観察**（2026-09-26 のユーザーの目視） — 低・中・高のどの段でも、均す前の raw（走査の解像度 1/4 の粒）は
S/N の悪い画像として、均した後より**相対的に**良く見える。均した後は、画素ごとの誤差が小さくなったのに、
ムラ（数画素〜数十画素の斑）が偽の構造に見える。段どうしでは、収束先に近い高ほど良く見える。ただし、
どの段のどちらもまだ PR に足る品質ではない。

**周波数の重みでは説明できない** — 総和 1 の非負の重みを画素によらず掛ける均しは、`|K(f)| ≤ Σ|w| = 1` なので、
平均 0 の定常な誤差のパワースペクトルをどの周波数でも増やさない。したがって「帯ごとの誤差を視覚の感度で
重み付けて足す」形の指標（前の版の知覚誤差 P、Chizhov らの知覚誤差、CSF で重み付けた RMS）は、同じ標本の
均した後を均す前以下に評価し、重みや視距離をどう選んでも観察の順に並ばない。均しが誤差を増やせるのは、
平面・法線の重みが画素ごとに変わって、ある標本の重みの列和（その標本を読む出力画素の重みの和）が 1 を
超えるとき（外れ値が斑に広がる仕組み）と、表示の非線形（トーンマップの頭打ち）を通した後だけである。

もう1つの事実: 均しは、その支持（半径）より粗いスケールの誤差を減らさない（そこでは `K(f) ≈ 1`）。粗い
スケールの誤差を減らせるのは、独立な標本を増やすこと、1 標本の分散を下げること、画素間で誤差を負に相関
させること（ブルーノイズ）の3つだけで、均しは支持より細かい粒を消すだけである。

**仮説**

- **H1 見えている不確かさとの食い違い（主仮説）** — 見る人は、画像の最も細かい粒からその画像の不確かさを
  読み、それより粗い起伏がその不確かさで説明できるかで、雑音か実在の構造かを分ける。白色の誤差なら、
  s×s で平均した誤差は画素の粒の 1/s で、粒の大きさがそのまま粗い起伏を説明する（正直なノイズ）。均しは
  粒を消すが支持より粗い誤差を残すので、粒が縮んだ分だけ、粗い起伏が粒で説明できない確かな構造に変わる。
  統計の言葉では、推定値が自分の誤差より小さい不確かさを表示している（過信）。**問題は周波数ではなく
  スケールをまたいだ整合で、粒より 1 段粗いだけの斑でも、粒で説明できなければ偽の構造になる。**
  裏付け: 定常なガウスで均した白色雑音は、D1 の実装の欠陥が無くても、粗いスケールで粒の 3〜6 倍の誤差を
  残す（判断材料の理想化した計算）。ユーザーは以前の別プロジェクトで、均した絵へ白色・ブルーノイズを
  足すと良く見えることを確かめている（不確かさを広げて粗い誤差を容認させる、写真の粒状フィルタと同じ効果）。
- **H2 外れ値と表示の非線形（副仮説）** — 照り返しの重い裾（暗い所で明るい源を 1 標本だけ拾う）は、均す前は
  1 走査画素の光点で、表示のトーンマップ（`neutralToneMapping`）の頭打ちで重みが抑えられる。線形の照度で
  均すと、外れ値のエネルギーが頭打ちされずに周りへ広がり、斑になる。表示の頭打ちは、生の粒に対しては
  暗黙の頑健な平均として働いていて、線形の均しがそれを外している。手順2で確かめる（K3）。

**2つの軸と、1次元の順位** — 品質には、正直さ（誤差が画面に見えている不確かさの範囲に収まるか）と、
小ささ（誤差と不確かさそのもの = S/N）の2軸がある。いまの粒の大きさでは、正直でないことによるムラが
見た目を大きく下げているが、誤差が見えない大きさまで小さければ、多少正直でなくても許せる。確率予測の
検証では、これを「較正を保ったうえで鋭さを最大にする」と呼び（Gneiting, Balabdaoui, Raftery 2007）、両方を
1つの数で測るのが適正スコア（予測した分布が真の分布に一致するときだけ期待値が最小になるスコア）である。

- 「不確かさを超えた分を絶対値で数える」（|誤差| − 3σ）だけでは、σ の大きい白色雑音が最良になる。適正
  スコアの1つの**区間スコア**（Winkler 1972、Gneiting & Raftery 2007）は、中心 (1 − α) の区間 [l, u] と
  観測 y に対して `(u − l) + (2/α)·(y が区間を外れた距離)` で、区間の幅の項が大きい σ を罰する。係数 2/α は
  適正であるための値で、見た目に合わせて選ぶ重みではない。
- 区間の水準を全部で平均した CRPS（連続順位確率スコア）は選ぶ値を持たないが、理想化した計算で密な均しを
  raw より良く並べ、観察と合わない。区間スコアも k = 1（68% の区間）では同じく密な均しを良く並べる。見る人は
  確率予測の検証の平均より重く過信を罰していて、3σ の区間スコアは、t が raw の粒より十分小さい（ムラが
  見えている）いまの状態で観察の順に並ぶ（判断材料）。
- 見えない大きさの食い違いを許すため、外れた距離から、表示で見えない差 t を引く。

**指標** — 誤差 e は、同じセッションで撮った候補と B の、通常表示の sRGB 画像を Oklab へ写した差。L・a・b の
成分ごとに測って和を取り、照り返しの色のムラも数える。撮影の組は K11。e を全解像度の箱の平均の差で帯
`d_s = ē_s − ē_2s`（s = 1, 2, 4, …, 32 画素）と残り ē_64 に分ける。

- **粒の雑音と c_s** — 粒は、候補が独立な標本を持つ一辺 m の画素（走査の解像度の逆数。全解像度なら 1、1/4 なら 4）
  ごとの白色雑音を、本番の拡大と同じ画素の中心の合わせ方で全解像度へ双一次に拡大したものとみなす。c_s は、その
  単位分散の雑音の帯 d_s の、拡大の位相（画素座標 mod m）ごとの標準偏差で、ツールが撮影と同じ寸法の雑音で数値で
  求める。m は候補の段から決まる値で、見る人に合わせる重みではない。全解像度の白色雑音の c_s を 1/4 の候補に
  当てると、正直な拡大した raw でも R(8〜32) が 2.2〜3.3 に出て、超過が幅の 5 倍になる（判断材料）。
- **粒の大きさ g(x)** — 粒の帯 d_m を c_m で割った値の絶対値の、各画素の周りの 32×32 の窓（8×8 の区画ごと）での
  中央値を、正規分布の標準偏差へ直したもの（÷ 0.6745）。中央値にするのは、外れ値が g を膨らませて近くの斑を
  「説明できる」側へ入れないため（最も細かい帯の MAD で雑音の大きさを推す Donoho の推定と同じ）。帯 1・2・4 の
  推定の最大で m を画像から決める読み方は、全解像度の白色雑音で 2 画素の粒を選び、外れ値が帯 4 へ広がると g を
  4 割膨らませたので採らない（判断材料）。
- **区間スコア S（候補を並べる軸）** — 各帯で粒が説明できる幅を `u_s(x) = c_s(x)·g(x)` とし、
  `S = mean_x Σ_s [ 2k·u_s(x) + (2/α)·max(0, |d_s(x)| − k·u_s(x) − t) ]`（和は全部の帯と残り）。
  k = 3、α = 2(1 − Φ(3)) ≈ 0.0027（2/α ≈ 741）。第1項（幅）は粒の大きさ、第2項（超過）は粒で説明できない
  偽の構造と外れ値。単位は Oklab の差で、小さいほど良く、誤差も粒も無ければ 0。雑音を足すと幅の項が
  増えるので、S は雑音を足しても下がらない。幅と超過の2つの項も別に記録する。誤差が粒そのもの（正直な白色
  雑音）でも超過は 0 にならず、理論値は幅の 9.4%（g の推定の揺らぎのぶん、実測はその 1.1〜1.3 倍）。
  t は表示で見えない差。初期値はユーザーの見立ての sRGB 8 bit で 10 階調前後（Oklab の L は灰色で sRGB の
  階調にほぼ比例し、1 階調 ≈ 0.0032〜0.0037）で、手順2で測って置き換える（K3）。
- **R(s)** — `sqrt(Σ_x d_s² / Σ_x u_s²)`（L 成分）。1 なら粒の雑音どおり（正直）、1 より下ならブルーノイズ（粗い
  スケールで打ち消し合う）、1 より上なら粒で説明できない粗い誤差がある。候補ごとに曲線で並べる診断。
- **G** — e のベクトルの RMS（画素単位の S/N）。診断。
- **裾の重さ（H2 の診断）** — 粒の帯で `|d_m| > 3·u_m` の画素の割合（正規分布なら 0.27%）。1 画素の外れ値は
  帯 d_1 で 2×2 の隣へも広がるので、外れ値の画素の割合の 2〜3 倍に出る。
- **偏りと分散の切り分け（診断）** — 候補を seed を変えて 2 回撮り、2 枚の平均と B の差を偏り（均しの
  ぼけ・推定量の違い）、2 枚の差を分散として、それぞれの R(s) を描く。
- **偏り** — 解析値のある窓（P_in・P_out・P_base・P_bleed・P_glow）の 5×5 平均の、B と解析値に対する差。
  線形の拡散照度（float の読み戻し）で読む。
- **境界の漏れ** — 深度・法線の境から 2 px 以内の面の画素での e の RMS（既存の指標の定義を引き継ぐ）。
- **ちらつき** — カメラを少しずつ動かした連続フレームで、候補の差分と B の差分の差の平均絶対値。
  静止したノイズ模様が面に対して泳ぐ分だけを数える。
- **有界性** — 拡散照度 + 補正 < 0 の画素のうち、表示で 1 LSB 以上暗く出るもの（float の読み戻し）。
- **費用** — 照り返し源・走査・均し・拡大の各行の GPU 時間の p50（マテリアル行に対する比）。比べる候補は
  **同じページで交互に**測る（ページを読み直すと同じビルドでも 0.6〜1.04 倍ぶれる）。

どの指標も、背景と、**どの候補の解像度でもフェードの外にある画素**（走査の解像度 1/4 で `r_px > 2`）
だけで測る。B は全解像度なので、1/4 の候補がフェードで 0 にする遠くの画素にも補正を持つ — そこを
誤差に数えると、解像度の比較が遠景の扱いだけで決まる。

S は視覚の周波数特性も、見る人の好みから合わせる重みも持たない（k は慣習の 3σ、2/α は適正さから決まり、
t は見えるかどうかの測定）。S も視覚の代理なので、候補を採るときは、誤差を 8 倍に強調した画像を必ず目で見る。

### K3. S を観察で確かめ、t を測る（手順2）

S の形は K2 で決まっていて、見る人に合わせて動かすのは t だけ。手順2で次を行う。

1. **確かめる（ユーザーの新しい手間なし）** — ユーザーがすでに付けた順（どの段でも raw が均した後より良く、
   段どうしは高ほど良い）を、いまの低・中・高の raw と均した後の 6 枚の S が再現するか。再現しなければ S を
   直すまで手順3へ進まない（第一の疑いは g の読み方 — どの帯の粒を不確かさとみなすか）。
2. **t を測る** — 3 ケース（`bay`、`bay-dark`、`bay-earth-open`）で、いまの中設定（均し後）の誤差を縮めた
   `B + a·e_D1`（a = 1, 1/2, 1/4, 1/8。Oklab）を作り、ユーザーが偽の構造（ムラ）が見えなくなる a を選ぶ。
   見えないとされた最も強い刺激で、`|d_s| − 3u_s` の 99 百分位を t とする。見えるとされた最も弱い刺激の
   超過がそれより十分大きいことを確かめる。
3. **外れ値（H2）を確かめる** — 同じケースで、いまの中設定（線形の照度を均す）と `B + K∗e_raw`（同じ raw の
   誤差を、表示の空間で、D1 と同じ大きさの定常なガウス K で均す）を並べ、良いほうを選んでもらう。後者が
   明らかに良く、`bay-dark` の裾の重さがガウスの数倍なら、外れ値の手当て（K9）の入口を開ける。

刺激は描画のコードを変えずにオフラインで作り、ユーザーには中身を伏せた名前（ケースごとに並べ替え、
対応表は別ファイル）で**等倍で**見せる（縮小すると粒が均されて見え方が変わる）。置き場は
`E:\dive-into-tepui-shots\ssd-stimuli\<ケース>\`。H1 と周波数の重みを刺激で切り分けることはしない —
周波数の重みが観察を説明できないことは K2 の議論で示されていて、H1 はユーザーの以前の経験が裏付けている。

### K4. 比べ方（手順3〜7）

- 候補は、標本数（スライス × 歩数、均しの本数）を振った 4 点以上で（費用, S）の曲線を描く。**均しを持つ
  候補には、必ず「均しなしで標本を増やしたもの」を対照として並べる。**
- 採る条件は、予算（K5）の範囲で曲線が既存案の曲線より下にあること（同じ時間で S が小さい）。1 点ずつの
  比較には効率 `1 / (S² · T)` を使う（正直な白色雑音なら S は標本数の平方根に反比例して減るので、
  モンテカルロの効率 1 / (分散 × 時間) と同じ形になる）。差がセッション間のぶれ（手順2で測る）以内なら
  同等とみなし、単純なほうを採る。
- **期待が薄い案は早く棄てる** — K7・K9・K10 で「期待が薄い」とした案は、中設定の標本数と代表の
  パラメータ 1 点だけを `bay` と `bay-dark` で測り、同じ時間の本命の点より S が悪ければ（差がセッション間の
  ぶれを超えれば）そこで棄て、標本数もパラメータも振らない。本命より良ければ、本命と同じく曲線を描く。
  構造のスケールに依存する案は、K11 の条件でだけ棄てる。
- **予想と外れたときは代表値で決めない** — K11 の内訳と地図で由来を考察し、判断材料に書いてから採否を決める。
- 算法の候補は捨てる前提の一時コードで比べ、**採った案だけを commit する。** 候補を切り替える
  仕掛け（大域変数・未使用の分岐）は commit に残さない。

| 低 | 3.5 倍以下 | 3 倍以下 |
| 中 | 5 倍以下 | 4 倍以下 |

### K7. 標本の置き方（手順3）

いまの走査は、歩 k の画面距離を `ρ = max(((k + j)/N)² · R, 1)` とし、ずれ j は画素ごとの blue noise
1 つを**全スライス・両側・全歩で共有**している（`src/render/pipeline/screen-space/hemisphere-scan.ts:91-94,119`）。
床を 1 走査画素にしているので受け手の画素そのものは読まないが、加算のずらしではないため、半径の小さい
受け手では歩が同じ画素に重なる。中設定（片側 4 歩）で計算すると、R = 3 px で 4 歩中 1.8〜2.4、R = 6 px で
1〜1.4 歩が直前と同じ画素を読み直す（重複は `newly` のビット演算で二重には数えないが、読みが無駄になる）。
また j を全スライスで共有するので、1 画素の中の全方向が同じ半径の列を読み、スライスを増やしても半径方向の
ずれは平均されない。

直し方の候補（手順3で同時間比較して決める）。どれも費用がほとんど増えない**本命**:

- **加算のずらし** — `ρ = ρ_min + ((k + j_ik)/N)² · (R − ρ_min)`、ρ_min = 1 走査画素。XeGTAO は二乗の配分の
  後に 1.3 px を足し（「中心の画素を読まないための最小距離」）、HBAO は `1 + 乱数 × 歩幅` で最初の歩を 1 texel 以上
  離す。床で潰さないので、歩のずれがそのまま画素の違いになる。
- **歩とスライスごとのずれ** — XeGTAO と同じく `j_ik = fract(j + (i + k·S)·φ)`（S はスライス数、φ は黄金比の
  逆数）。各歩は自分の層 [k/N, (k+1)/N) に留まったまま、1 画素の中で方向ごと・歩ごとにずれが変わり、スライス
  方向の平均で半径方向のずれも均される。SAO は、隣り合うタップが同じ画素へ落ちると分散が増えてちらつくと
  報告している。
- **歩数の頭打ち** — 片側で読める異なる画素の数（軸方向で ⌊R⌋、斜めで ⌊0.707R⌋）を超える歩を読まない。
  余った予算をスライスへ回すかは、同時間比較で決める。
- **照り返しの源の前置フィルター** — 照り返しの源は、走査の画素 1 つにつき G バッファの 1 画素（4×4 の中の
  1 つ）を読んでいる。明るい細部を当てたり外したりすることが、暗い所で強い照り返しを 1 標本だけ拾う
  外れ値の源になりうるので、4×4 の平均を源とする案を比べる。

**標本の置き方は、偽の構造の元になる粗いスケールの誤差を減らせる数少ない手段**（K2）なので、候補は
S だけでなく粗い帯の R(s) でも比べる。ずれがブルーノイズで、補正が隣の画素と似た積分なら、
誤差は画素間で負に相関して R(s) < 1 になり、均さずに粗い誤差が減る。歩とスライスごとのずれは、画素間の
ブルーノイズの並びを保つ形で足す（1 つのブルーノイズに定数を足して 1 で割った余りを取っても空間の並びは
保たれる — 時間方向に黄金比を足して動かすのと同じ）。手順2で raw の R(s) を測り、1 に近い（誤差が白色で、
ブルーノイズのずれが誤差の並びまで届いていない）なら、誤差そのものをブルーノイズへ寄せる標本の置き方
（Heitz ら 2019: Owen スクランブルした Sobol 列を、画素ごとのスクランブルと順位の小さい表で配る）を**条件付き**の
候補に足す。

いまの走査の各画素の半径は blue noise で画素ごとに違うので、決定的な等間隔の歩みが作る同心円の模様は
原理的には出ない。ただし小さい R で床と丸めが多くの j を同じ画素へ潰すため、奥へ遠ざかる面で「読める
異なる標本の数」が R の整数の境で段になり、等高線状の帯が出うる（未確認。手順3で見る）。

### K8. 天体照の答え方（手順4）

拡散の補正が天体照を引く式は、受け手ごとに 1 回求める天体照 E_p（球光源の Snyder の式 + 天体の像の
mip 1 回の読み + 満ち欠け）に、塞がれた割合 f_p を掛ける比推定である
（`src/render/pipeline/lighting/planet-light-source.ts:198-215`、`src/render/pipeline/lighting/sphere-light.ts:15-33`）。
**拡散では LTC を使っておらず（LTC は鏡面だけ）、高い光源の評価は標本ごとでもスライスごとでもなく
画素ごとに 1 回**である。スライスごとには球冠の範囲（atan・acos・cos 2 回）と楔の重み（acos）、歩ごとには
塞いだ扇形の球冠との重なり（popcount 3 回）が、天体のスロット 2 つぶん走る。

「天体を十分遠い光源とみなし、塞がれた向きの光を、比推定と球光源の式を通さずテクスチャの読み 1 回で
答える」案は、省ける費用がこの画素ごと・スライスごとの分だけなので、**まず外したときの時間を測る。**
比推定（Heitz, Hill, McGuire 2018）は、遮られないときの照度を解析的に求めて塞がれた割合だけを推定するので、
ライティングと引く量が同じ式で揃う。向きごとの読み（SSDO、GTAO の曲げた法線 + 前置フィルターした環境
マップ）へ替えると、この揃いを失う代わりに何が速くなるかを数字で示す必要がある。

- 天体照にかかる処理（受け手の E_p、照り返し源の天体照、球冠と楔、歩ごとの重なり）を定数に置き換えた
  版と同じページで交互に測り、走査 + 照り返し源の時間の 10% 未満しか省けないなら、この案は実施しない。
- 10% 以上なら、答え方を変えた版を作り、(a) 省けた時間、(b) B どうしの差（完全に塞がれた内隅で
  ライティングの天体照と引く量が食い違う残り、`E_far = 0` の面で ΔE ≠ 0 になる画素）を測る。速くて
  差が目立たなければ近似として採る。速いが差が目立つなら、ライティング側の答え方を見直す別計画を立てる。
  大差ないか遅くなるなら採らない。
- 結果を変えない省略（使っていないスロットの評価、`select` で両方の枝を評価している天体の像の読み）は、
  同じ比較で効きが測れたときだけ入れる。

小天体の偏り（中設定の moon-open が 0.68、解析値 1.00）もこの手順で扱う。スライスを 16 本にしても
0.72〜0.78 に留まる一方、距離重みを外して歩数を増やすと 1.000 に収束した実測がある。距離重みは遮りを
弱める側にしか働かないので、遮りすぎの原因は歩数（切片の粗さ）か、1 扇形より小さい球冠と丸めのずれの
どちらかである。手順2の B で切り分け、B（収束した値）にも偏りが残るなら、64 扇形・球冠の塞がれ方を
切片の連続した角度範囲との重なりで測る案を、B の偏りと費用で比べる。

### K9. 均しの候補（手順5）

**均しの価値と代償** — joint bilateral は、ただぼかして粒を消すのではない。「位置と法線の似た周りの画素は
似た収束先を持つ」という推定のもとで、周りの画素が見つけた標本を取り込み、仮想の標本数
`N_eff = (Σw)² / Σw²` を増やして収束先へ近づける。代償は2つ: (1) 隣り合う出力画素が同じ標本を共有するので
誤差が相関し、粒で説明できない粗い構造になる（H1）。(2) 位置と法線が似ていても収束先が違う境界をぼかす。
支持より粗いスケールの誤差はどの均しでも減らない（K2）ので、支持は広く取り、隣と共有する標本を少なくする。
拡大すると粒は小さなムラになり、これは避けられない（多重スケールでも同じ）ので、粒を消し切ることより、
N_eff を増やして粒のコントラスト（S/N）そのものを下げることが目的になる。

- 密な 5×5（σ = 1 走査画素）は N_eff ≈ 12 だが、隣の出力画素とほぼ全てのタップを共有する。
- 面積 A の円盤から K 本を画素ごとに回して読む疎なタップは、N_eff ≈ K で、隣と共有するのは約 K/A。残る
  誤差は白色に近い粒のまま（ディザのように、不確かさを粒として残す）。
- 疎な段を、段ごとに半径を広げ、回転を独立にして重ねると、N_eff は段ごとに掛け算で増え（K₁·K₂）、費用は
  足し算でしか増えない。密な段を重ねても N_eff は増えるが、共有も増えて粗い構造になる。

理想化した計算（判断材料）では、t が raw の粒より十分小さい（t = 0）とき、raw より S が小さいのは疎な 1 段
（8 本・半径 8 で raw の 0.75 倍）だけで、密な 5×5 は 6.7 倍、2 段は疎でも密でも 2〜3.5 倍に悪化する。t が粒の
0.05 倍になると、密な 5×5 は 2.2 倍のまま、疎な 1 段は 0.35 倍、2 段は疎（0.14 倍）も密（0.11 倍）も大きく下がって
並ぶ。t が 0.2 倍では密な均しの食い違いも t の下に入り、密な 2 段が最良になる — 誤差が十分小さければ多少正直で
なくても許せる、という観察の形になっている。**どの段の均しが良いかは、手順2で測る t と raw の粒の比で決まる。**

**本命**

- **D2 疎なタップ** — 半径 r の円盤に置いた K 本（中心を含み、黄金角の螺旋など）を画素ごとにブルーノイズで
  回し、平面の距離 × 法線で重み付ける。平面の距離の許容はタップの距離に比例させる（D1 の欠陥を直したもの。
  深度の勾配で許容を広げる SVGF と同じ考え方）。NVIDIA REBLUR の空間段も、画素ごとに回した 8 本の Poisson
  円盤を適応的な半径で使う。振るのは K（4 / 8 / 12）、r（走査の画素で 2〜12）、段の数（1 / 2 / 3）。
  判断材料の「8 本の確率的なタップは 2〜5 倍悪い」は窓の誤差の標準偏差で測ったもので、正直さも同時間比較も
  測っていない。
- **拡大** — いまの 2×2 の双一次 × 平面 × 法線を基本とし、**拡大をライティングの読みへ畳んで全解像度の
  補正 target をなくす案**（全解像度の拡大がマテリアル行の 1.2〜1.4 倍を占める）を、結果が同じまま
  速くなるかで比べる。畳むなら、全解像度の補正 target とそのデバッグ表示はなくなる（存在しない中間
  バッファは見せなくてよい）。多重スケール（K10）を採るなら、拡大の鎖はそこで決め直す。

**条件付き**（手順2・3の測定で入口を開ける）

- **D6 ブルーノイズの誤差だけを消す小さい均し** — raw の R(s) が細かい帯で 1 より十分下（K7）なら、誤差の
  多くが細かいスケールにあるので、3×3 程度の均しが粗い誤差をほとんど残さずに粒を消す（Georgiev & Fajardo
  2016、Heitz & Belcour 2019 の前提）。
- **外れ値の手当て** — 手順2で表示の空間で均した刺激が明らかに良く、裾の重さがガウスの数倍で、多重スケール
  （K10）で大半径の輝点が粗い層の画素の中の平均に入った後でも輝点が残るとき（手順6）。
  捨てる情報の少ない順に試す。少ない標本のうちに中央値や clamp で切ると、得た標本を捨てるだけになりやすい。
  1. **源で減らす** — 照り返しの源の前置フィルター（K7）。偏りを作らずに外れ値の元の分散を下げる。
  2. **圧縮した空間で平均する** — 重み `1 / (1 + L/L_ref)`（Karis 2013。圧縮してから平均して戻すのと同じ）。
     凹関数の平均なので暗い側へ偏り、分散の大きい所ほど暗くなるが、生の粒を画面で見たときに目が受け取る
     平均（表示の頭打ちを通した平均）も同じ向きに寄っている。
  3. **平均の中央値（median of means）** — 近傍をいくつかの組に分けて組ごとに平均し、組の平均の中央値を
     取る。組を大きくするほど組の平均の分布が対称に近づくので偏りは 0 へ向かい、裾が軽い所では平均に近い
     効率を保つ（Buisine ら 2021 は、Gini 係数で組の数を画素ごとに変えて裾の軽い画素の効率の損を抑える）。
     「ある程度均してから中央値」を定式化したものにあたる。
  4. **近傍の最大での clamp・3×3 の中央値** — 最後の手段。

  Zirr ら 2018 の再重み付け（明るさの段ごとに標本を分けて積み、裏付けの足りない明るい段の重みを下げる。
  標本を増やせば偏りは消える）は、段の数だけ target が要るので、1〜3 で外れ値が残るときだけ考える。
  どれを足しても、足した偏りを B に対して測る。
- **分散の案内**（SVGF の 7×7 の空間分散で輝度の差の許容を決める重み） — 平面と法線の重みで境界の漏れが
  残るとき。

**期待が薄い**（K4 の早期棄却: 中設定の 1 点だけを測る）

- **D1 いまの 5×5** — 比べる基準として残すだけ。平面の距離を**全解像度 1 画素の footprint で割っているのに、
  タップは 4〜8 全解像度画素離れている**（`src/render/pipeline/screen-space/correction-reconstruction.ts:86-107`）
  ため、曲面では中心の 1 タップへ潰れ、拡大で走査画素の raw が 4×4 の塊として出る。
- **D1′ 平面の許容を直した密な 5×5** — 欠陥は消えるが、隣との共有は残る。
- **D3 D2 の後に密な 3×3** — 密な段が隣との共有を戻す。
- **D4 密な多段**（Godot の SSIL・AMD CACAO の 5 タップの多段、密な à-trous） — 同上。à-trous は孤立した
  明るい画素を十分に均せないと原論文（Dammertz 2010）も述べている。
- **D5 半分だけ均す**（`α·X + (1 − α)·K∗X`） — 実際の雑音を残して正直さを保つが、N_eff を増やさない。
  理想化した計算で疎なタップに劣る。

### K10. 多重スケール（手順6）

一次の可視性（手前の遮りの後ろを数えない）は、方向ごとの走査でも標本が疎なら取りこぼされ、スライス
どうしでは共有されない。それでも画素ごとのずれで平均すると品質は保たれる（1 方向 1 標本に近い Alchemy AO
が例）。スクリーンスペースは奥へ続く壁と棒を区別できず遮りを多めに見積もるので、スケールをまたぐ
可視性を取りこぼして漏れる分は、誤差の向きとして打ち消し合う側にある。**そこで「一次の可視性を
スケールをまたいで保てない」ことは多重スケールを禁じる理由にしない。** 採るかは、収束先の見た目と
同時間比較で決める。

**どのスケールの間にもある同じ形の問題** — 解像度を下げると、画素が減るぶん 1 画素あたりの標本と均しの
タップが安くなるが、その解像度より細かい構造を見落とし、拡大すると粒が偽の構造になる。いまの 1/4 で
走査して拡大する構成は、この問題を両側で抱えている。

- **細かい側** — 1/4 の走査は最初の標本が 1 走査画素（4 全解像度画素）より外で、受け手からそこまでは
  接平面で埋めるだけなので、4 全解像度画素より小さい構造（接地の影、細い溝）を持たず、代わりに拡大した粒が
  小さなムラとして入る。
- **粗い側** — 大半径の効きは低周波なのに、1/4 の画素ごとに少ない歩で求めるので、疎らな輝点（遠くの明るい
  照り返しの源を 1 標本だけ拾う）が残り、1/4 の均しでは消しきれない。もっと粗い解像度なら、同じ費用で
  1 画素あたり数十倍の標本を取れ、輝点は画素の中の標本の平均（正直な箱の平均）に入る。粗い画素のブロックは
  拡大するとムラになるが、その層が収束していれば問題にならない。粗い層の利点はキャッシュではなく画素数に
  ある — 読みが走査の約 1 割（判断材料）であることは、この利点を小さくしない。

**構造: 公比 q の層** — 解像度 q^l（l = 0, 1, …, L − 1。l = 0 は全解像度）の L 枚の層に、画面距離の帯を
受け持たせる。各層は自分の画素の単位で同じ幅の帯 [ρ_a, ρ_a/q] を走査するので、層 l は全解像度の画素で
[ρ_a·q^(−l), ρ_a·q^(−l−1)] を受け持ち、帯は隙間なく並ぶ。1 層あたりの歩の数はほぼ同じで、費用は層の画素数
（q^(2l) に比例）で決まるので、半径を広げるほど粗い層へ回ってほとんど費用が増えない。最も内側の層は
画面距離 1 画素から、最も外側の層は投影半径 R_px まで数える。R_px が層の内側の境に届かない受け手は、その層を
飛ばす。

- **q と L は独立でない** — 同じ最大半径を覆うのに、q = 1/4 なら 1・1/4・1/16 の 3 枚が要るかもしれないが、
  q = 1/8 なら 1 と 1/8 の 2 枚でいまの 1/4 より大きな半径を楽に覆う。q = 1/2 は層が多く、拡大の段も増えるが、
  拡大 1 段の比が小さいので拡大で失うものが少ない。q と L は組で、同時間・同品質の比較で決める。
- **初めに比べる組**（K4 の早期棄却の 1 点を当て、生き残りの標本数と帯の境を振る）: 単一 1/4（手順5の最良の
  D2 を掛けた対照）、q = 1/4 の {1, 1/4}・{1/4, 1/16}・{1, 1/4, 1/16}、q = 1/8 の {1, 1/8}・{1, 1/8, 1/64}、
  q = 1/2 の {1, 1/2, 1/4, 1/8, 1/16}。構造のスケールに依存する選択なので、K11 の過適応の注意が全部掛かる。
- **層の入力** — 各層は自分の解像度の深度・法線・照り返しの源の縮小を読む（SAO の縮小列と同じもの。大半径の
  読みもキャッシュに当たる）。深度と法線は同じ代表の画素から取り、照り返しの源は縮小のときに平均する（K7 の
  前置フィルターを層ごとに一般化したもの）。点で取るか平均するかは、粗い層の境界の漏れと S で比べる。
- **帯の内側の境** — 最も内側の層以外は内側の境から数え始める。いまの走査は受け手自身を最初の標本とみなして
  受け手から最初の標本までを接平面で埋めるので、外の層でそれをすると内の層の構造を二重に数える。
- **帯の境は画面距離で切る** — 世界の距離で切ると、手前の受け手ほど細かい層の帯が広くなり、費用が画面の
  奥行きで決まる。
- **拡大と合成の鎖** — 最も粗い層から順に、その層の raw を D2 で均し、次に細かい層の解像度へ深度・法線で
  重み付けて拡大し、その層と合成する。全解像度では、拡大・全解像度の層の走査・合成を 1 つの描画にまとめ、
  全解像度の target を増やさない（いまの拡大の target をそのまま使う）。全解像度の層は均さずに重ねるのを
  基本とし（そのスケールで実際に標本を取った合理的な粒で、拡大に由来する偽の構造を不確かさへ入れる。
  合成の雑音を足すのと違い、誤差を増やさずに情報を足す。もちろんこの粒も弱いほうが良い）、疎な 1 段を掛ける
  案も比べる。合成した後にもう一度均す MSSAO の順は、粗い層の誤差を細かい層の不確かさで説明できなくするので
  期待が薄い。
- **層ごとの標本の配り方** — 粗い層の残った雑音は拡大で大きなムラになり、S の超過で重く罰されるので、粗い層ほど
  1 画素あたりの標本を多くしてよい（安い）。配り方は（費用, S）の曲線で決める。

**帯の合成** — スカラーの AO と違い色付きの符号付き補正なので max は使えない。候補は
(a) 前から奥への重ね合わせ: 内の層が塞いだ余弦測度の割合 α で
`C_l = ΔE_l + (1 − α_l)·拡大(C_(l+1))`（最も粗い層は C = ΔE）、(b) 単純な和、(c) 平均。**収束した値
（B_MS）どうしで比べて決める。** (a) が本命: 2 つの遮りの真の塞がれ方は max(A_a, A_b) ≤ A_ab ≤ A_a + A_b の
間にあり、遮りどうしが無相関なら `1 − A_ab = (1 − A_a)(1 − A_b)`（Kontkanen & Laine 2005 の AO の合成）。色は
voxel cone tracing（Crassin 2011）の前から奥への合成 `c ← c + (1 − α)·c₂` と同じ形になる。(b) は重なった向きを
二重に数え、(c) は層が分け合う距離の範囲に対してどの層の効きも薄める。MSSAO はスカラーで
`1 − (1 − AO_max)(1 − AO_avg)`、HBAO+ は 2 帯の線形の重み付き和、GTAO は遠方の焼き込みとの min を使う。

**第二の基準 B_MS** — 全層を全解像度・均しなし・標本を増やして収束させた多重スケールの推定量。構成ごとに
作ると高いので、比較の後に残った 1〜2 構成でだけ作る。B_MS と B の差（光の漏れ）を目視と解析値で見て、
許容できるときだけ採る。採るなら、実用の構成の誤差は B（主）に対して測り、B_MS との差で「収束先の違い」と
「近似の誤差」を分けて読む。

### K11. 評価の組と、少ないケースへの過適応（手順2・5〜7）

いまの `bay` は、壁に囲まれた凹みと、太さの揃ったトラスの柱の繰り返しと、薬莢を除けば平面だけで、いろいろな
スケールの溝や谷を持たない。同じ場面でも、カメラの距離を変えるだけで画面に占める AO の大きさは変わる。
撮影のケースを増やしすぎると撮影に時間がかかり、E: も食う。**必要なケースだけを撮り、少ないケースに多様な
状況を詰める。**

- **溝の梯子（新しいケース 1 つ）** — 床に、幅と深さが公比 2 で並ぶ U 字の溝（3 cm〜2 m の 7 段）と、太さの
  違う寝かせた円柱（半径 5 cm・20 cm・80 cm。円柱と床の間の楔は 0 から半径までの全部のスケールの谷を持ち、
  円柱の面は曲面の受け手になる）を置く。撮影は 3 つ: 地球照を真上に置いた遮り、光る帯を溝の列に沿わせて
  恒星と天体照を切った照り返し（暗い所の輝点）、そして遮りの撮影をカメラの距離 0.4 倍・2.5 倍で撮った 2 枚。
  1 枚で 7 オクターブの構造のスケールを持ち、距離を変えると同じ構造が層の境をまたいで動く。
- **`bay` の距離を振る** — 全景を、いまの距離の 0.5 倍・2.5 倍でも撮る（同じ場面なので作る手間はない）。
- **網羅の確かめ** — ツールが、撮影ごとの投影半径 R_px（全解像度の画素）のオクターブごとの画素数と、溝の梯子の
  溝の画面上の幅を出す。調整に使う組は、R_px が 4〜512 画素のどのオクターブにも十分な画素を持ち、比べる
  どの q の層の境の両側にも画素がある。
- **調整用と確認用に分ける** — 調整用は `bay`・`bay-dark`・`bay-earth-open`・`bay-bounce`・溝の梯子の遮り
  （既定の距離と 0.4 倍・2.5 倍）・溝の梯子の照り返し。確認用は `bay` の 0.5 倍・2.5 倍、溝の梯子を別の方位と
  1.6 倍の距離から撮った 1 枚、`bay-truss`、`bay-edge`。解析値のケース（`bay-earthshine` の P_in / P_out・
  `bounce-cosine`）は正しさの確かめで、調整にも確認にも数える。**構造のスケールに依存する選択**（層の公比・
  層の数・帯の境・均しの半径とタップの数・層ごとの標本の配り方）は、確認用の組でも着手前より S が小さく、
  調整用で選んだ順が確認用で逆転しないときだけ採る。
- **予想と外れたときは代表値で決めない** — S が理論・理想化した計算・目視の予想と外れたら、採否を決める前に
  (1) ケースごとの S、(2) 帯ごとの超過（どのスケールの偽の構造か）、(3) 幅と超過のどちらの項か、(4) 超過の
  画素の地図と誤差の強調画像、を見て、それが何に由来するか（特定の構造のスケール、1 つの明るい源、境界、
  画面の縁）と、ケースに依るのかを考察し、判断材料に書いてから決める。早期棄却（K4）でも、構造のスケールに
  依存する案は、調整用の組のうち距離の違う撮影の両端で負けたときだけ棄てる。
- **容量と時間** — 撮影組・B・刺激は E: に置く。B は 1 撮影 960×540 の RGBA float で約 8 MB。調整用と確認用は
  合わせて 15 撮影以内（正しさの確かめとちらつきのフレームは別）に収める。

### 採らない案（問題が残るもの）

同じ案を再提案しないために、問題だけを残す。

| 案 | 採らない理由 | 残る問題 |
| --- | --- | --- |
| 標本の画素の接平面の角 footprint だけを塞ぐ（標本の間を埋めない） | 遮蔽が読んだ画素の割合まで痩せ、歩数を倍にするたびに遮蔽がほぼ倍になる | なし（接平面の切片で間を埋めている） |
| 照り返しを面積の form factor × 1/pdf で積む | 1 標本の重みが半球 2π を超え、raw の最大が遠方光の数千倍の明るい斑になる | 照り返しは方向の測度で積む。1 標本の寄与は π × 源の放射輝度で頭打ち |
| 自己遮蔽を避ける閾値 | 斜めに見た壁の足元を数十 cm 捨てる | 余弦重みの測度が地平の近くで 0 になるので閾値は要らない |
| 小天体をスライスと球冠の弦の当たり外れで数える | 当たった画素だけ天体照そのものを超えて引く | 楔の補間の比推定で有界。小天体の影が方位の離れたスライスの地平で決まることが目立つなら、光源の方位に揃えた走査を足す別計画（走査数が光源数に依存する） |
| 空の天体照スロットごとに走査のマテリアルを分ける | `bay` で 12〜20% 減るが、切り替えのたびに 1 方式約 3 秒のコンパイル、2 天体では効かない | — |
| 走査の解像度に位置と法線の案内 target を足す | 1080p 中設定の中間 target が 35.6 MiB で上限を超え、復元は速くならなかった | — |
| 均しの縦横分離 | 境界の漏れが悪化した | — |
| 時間方向の蓄積 | 同じ入力で同じ画像にならず、静止した絵がちらつく | 空間だけで収める |
| 深度の標本を一定の厚みの板として奥へ押し出す | 単層の深度から真の厚みは得られず、厚み（1.1 m・2 m）が絵合わせの自由度になる | 奥へ続く壁と棒を区別できず、遮りを多めに見積もる（K10 の漏れと打ち消し合う側） |
| 均した後に合成の粒を足す（写真の粒状フィルタ、動画符号化の film grain synthesis のように） | ユーザーが以前の別プロジェクトで試し、見た目は良くなった（H1 の裏付け）。ただしこのリポジトリはリアル指向なので、見える範囲に嘘の雑音を混ぜて許容の幅を広げるより、雑音そのものを小さくする | 拡大に由来する偽の構造は、全解像度の層が実際に標本を取った粒で不確かさへ入れる（K10） |
| 帯ごとの誤差を視覚の感度（CSF）で重み付けた知覚誤差を、候補を並べる軸にする | 定常な均しをつねに均す前以下に評価し、観察（均した後のムラが許せない）と逆の順に並べる（K2） | 誤差の大きさと正直さは区間スコア S で測る |
| 区間の水準を平均した CRPS、または 1σ の区間スコアを並べる軸にする | 理想化した計算で密な均しを raw より良く並べ、観察と逆（K2） | 3σ の区間スコアを使う |

## 達成目標

### 品質

1. 低・中・高の最終構成の S が、調整用と確認用の組（K11）のどのケースでも、同じ段の着手前の構成（均し後）と着手前の raw の
   両方より小さく、S は低 ≥ 中 ≥ 高。中の最終構成を、ユーザーが等倍で見て PR に足る品質と判定する。
2. 均し・拡大を持つ最終構成は、同じ時間の「均しなしで標本を増やしたもの」より S が小さい。小さくならない
   均しは入っていない。
3. 距離重み W = 1 の B の P_in / P_out が解析値から、大きい天体で ±0.06、小天体（moon-*）で ±0.10 以内。
   外れるなら、その理由（画面外・背面など原理上の限界）を判断材料に書いてある。中設定の最終構成は
   B（W あり）から ±0.06 以内。
4. 誤差を 8 倍に強調した画像に、四角い斑・同心円や等高線の帯・`bay-truss` の梁から 4 px より外の暈・
   `bay-edge` の直線の段差がない。
5. 拡散照度 + 補正 < 0 で表示が 1 LSB 以上暗くなる画素が 0。

### 保つもの

6. 同一フレームのデバッグ「鏡面照度」が、方式オフ / 遮蔽 / 遮蔽と照り返しの相互比較で差 0（`leo-metal`・
   `bay-metal` を含む）。
7. オフの撮影組が、着手前に撮った組に対して `render-lab:compare` の封筒外 0 件。
8. 地球を左右へ動かすと、負の補正が同じ向きへ動く（`bay-earth-overhead` / `-open` / `-corner`）。
9. 走査の描画命令は光源の数とモデルによらず 1 本（多重スケールなら帯の数だけ）。`r_px ≤ 1` の画素は
   raw・復元後とも厳密に 0 で、1〜2 px の距離スイープに段差がない。
10. 人間向けの設定が「方式」と「精細さ」だけ。見た目の調整定数（固定厚み・独立したフェード開始・最小天体角・
    最小ローブ角）が 0 件。
11. 推定量を変えた手順（3・4・6）の後も raw の補正が有界: 天体照だけの「遮蔽」で blocked / E_p > 1 の画素と、
    `E_far = 0` の面で ΔE ≠ 0 の画素が 0、照り返しは照り返し源の最大の π 倍以下（float の読み戻し）。扇形の
    ビットと球冠の範囲は同じ丸めのずれで丸め、単独の切片へ最低 1 扇形を与えず、距離重みはビットに掛けない。
12. `bounce-cosine` の源の余弦 1 / 0.5 / 0 の照り返しの比が、有限の面光源の解析値（受け手の中心 1 / 0.58 / 0、
    受け手全体 1 / 0.37 / 0.05）の ±0.10 以内。

- 最後の拡大をライティングの読みへ畳むかを、結果が同じまま速くなるかで決める（畳む前後の拡散照度の float の
  読み戻しが半精度 2 ulp 以内で一致し、その行の時間が消える）。
- 外れ値の手当て（K9 の条件付き）は、採った構成でも `bay-dark` と溝の梯子の照り返しに輝点が残るときだけ足し、
  足す前後の B に対する偏り（解析値の窓と G）と、裾の重さ・S を並べる。
- 採るなら: 天体照だけの「遮蔽」で blocked / E_p > 1 の画素、`E_far = 0` の面で ΔE ≠ 0 の画素が 0。地球を
  動かしたときの向き（達成目標8）。走査の描画命令は層の数だけ（達成目標9）。1080p の中間 target が K5 の
  メモリ予算以内。
- `npm run typecheck` / `npm run check:boundaries` / `npm run test:render`。
- commit（採ったときだけ）: `feat(render): 近傍拡散補正を公比 <q> の <L> 層で求めて重ねる`。採らないときは
  `docs(memo): 計画から実施した手順 6 を消し、多重スケールを採らない実測を書く`
