# 半透明雲表現 — 大気散乱へミー散乱場を足す(計画)

**巻雲(B)と積雲の中間調(R)を、大気パスの単散乱ミーの「殻」として解く。既存の
`atmosphere-pass.ts` の改造。** 相方は [`opaque_cloud.md`](opaque_cloud.md)(積雲の不透明部分を
G バッファと遮蔽へ立てる新規実装)。**優先度は相方が上** — 不透明部分のほうが視覚効果が強く、
多重散乱の極限(Lambert)は大気散乱シミュレーションでは実現できないから。手順 1(巻雲)は
相方と独立に進められるが、手順 2(積雲の低層殻)は相方の手順 1 完了を前提にする。

## 呼称

| 呼称 | 意味 |
|---|---|
| **積雲** | 場の R(被覆率)+ G(雲頂高度)が表す雲塊(積雲〜積乱雲、層積雲の板。台風の眼壁・螺旋帯も)。旧称: 不透明雲・厚い雲 |
| **巻雲** | 場の B(鉛直光学的厚み τ)が表す上層の薄い雲(巻雲・巻層雲、台風の吹き出しの傘)。旧称: 半透明雲・薄い雲 |
| **不透明雲表現** | 積雲の不透明部分を G バッファ + 遮蔽で描く(相方の計画) |
| **半透明雲表現** | 巻雲と積雲の中間調を大気パスのミー散乱で描く(この計画) |

## 目的

いまの巻雲は `celestial-surface.ts:63-67` が 1 − exp(−τ) を地表アルベドへ焼き込む板で、
`DEVELOP/SPEC/RENDERING.md` の「高い雲は、地上より遅く夜を迎える」(:410-411)・薄く繊維状に
透ける見え(:350-352)・入射光の夕焼け色が出ない。積雲の中間調(被覆率 0..1 の縁)は、相方の
計画で G バッファへ移った時点で二値化・ディザに潰れる — **G バッファに不透明しか載せられない
制約は変わらないので、中間調そのものはこちら(大気の単散乱)が引き受ける。** 生成側が持つ
中間調の情報を捨てないための実装がこの計画。

大気パスの器で解けるのは物理の側から立つ: τ ≲ 1 の薄い層は単散乱で足りる。殻の放射輝度は
大気と同じ器 — `sunRadianceAt`(Chapman の太陽光路透過率 × 遮蔽 × 地平線)× 単一散乱アルベド ×
位相関数 × (1 − exp(−τ/μ))。巻雲は氷晶で可視の吸収がほぼ無く ω₀ ≈ 1、位相は前方に強い
HG(g ≈ 0.8。地球のミーの既定と同じ)。**ここでしか出ないもの**: 入射の夕焼け色(高い雲が
昼夜境界の先 √(2Rh) = 357 km(h = 10 km)まで太陽に照らされる)、日食の影が雲へ落ちること、
本物のアルファでの重なり。

**分岐は要らない。** 積雲の不透明部分は相方が G バッファへ深度を書くので、大気パスの積分は
その手前で勝手に止まる(`atmosphere-pass.ts:218-223` の far = min(surfaceT, opaqueDist))。
「半透明部分だけを場から切り出す」処理は書かない。同じ理由で、巻雲の下に積雲の塔という
重なりも追加の仕組みなしに合う。

**SPEC の差分は無い**(:410-411 等、既に規定された挙動の実現)。

### 入力の契約(場)

- `src/assets/cloud-field.png` — 実写 8k_clouds を推定分離した仮テクスチャ。正距円筒

  `npm run cloud-lab:separate`。
- 将来、生成側の場(全球 39.1 km/texel + cap 8.5 km/texel)へ差し替える。並びは同じなので
  読む側は動かない想定。
- 配信サイズ +10.9 MB は生成側・軽量化側の残件で、この計画では扱わない。

### 崩せない制約

| 制約 | この計画への効き方 |
|---|---|
| パス構成(10 本)は再構成しない。触るのは各フィルタの中身だけ | 殻は大気パスの天体ループの中身へ挟む。パスは増やさない |
| サンプル数は実行時の値、積分は動的ループ(展開すると 5 倍遅い) | 殻はサンプルを消費しない — 解析の交点 2 つで区間を切って挟む。予算配分(`atmosphereDraws`)は据え置き |

| 遮蔽の入口は 1 本 | 殻が受ける遮蔽は `sunRadianceAt` 内の既存の `transmittance` 呼びが解く(日食が雲に落ちる) |

| 太陽系全域で破綻しない | 遠景は mipmap 越しの平均 τ になり、焼き込みと同じ見えへ跳ばず退化する |

## 決めたこと

覆すならどの手順が変わるかを併記する。

1. **巻雲の殻は全球 1 枚、高度 10 km。** 実際の巻雲は極域 3〜8 km、温帯 5〜13 km、熱帯
   6〜18 km — まず 1 枚で近似し、緯度依存は要ると分かってから足す。上層の帯表
   (`circulation.ts` の UPPER_BANDS)は既にこの高度(≈200 hPa)前提。→ 覆すと手順 1 の定数。
2. **殻は厚み 0 の球面として交差し、掠め視線は光路長 2√(2RΔh)(Δh = 1 km で 226 km)の
   Chapman 型上限で頭打ちにする**(τ/μ は水平で発散する)。層 [h₀, h₁] の厳密交差はしない。
   → 覆すと `cloud-scattering.ts` の交差式。
3. **積雲の R→τ 変換は τ = −ln(1 − min(c, 0.98))**(c = 1 で τ ≈ 3.9 の頭打ち)。根拠:
   焼き込みが c を不透明度としてスクリーン合成していた式と連続で、移行前後の見えが繋がる。
   → 覆すと手順 2 のみ。
4. **積雲の低層殻は高度 2 km**(雲底 1 km と、中間調が多い縁の代表高度)。→ 覆すと手順 2 の
   定数 1 つ。
5. **手順 2 は相方の手順 1 完了後に着手する。** (a) 不透明部の深度打ち切りが無いと積雲全体が
   単散乱の灰色で写り、(b) 焼き込みに残る R とも二重になる。→ 覆せない(物理と順序の制約)。
6. **場を持たない天体(mars)のスロットには 1×1 黒テクスチャを結ぶ。** TSL は静的展開なので
   実行時分岐で殻を消せない — τ = 0 が自然に無効化する。→ 覆すと `BodySlot` の設計。
7. **殻の式は新規 `src/render/pipeline/cloud-scattering.ts` へ切り出す。** `atmosphere-pass.ts`
   は既に 441 行で、パスには「区間を殻で切って挟む」配線だけを残す。→ 覆すと手順 1 のファイル表。
8. **負荷の合格線は F3「大気」行 +0.3 ms(高設定、殻 2 枚)。** 相方と合わせ雲全体 +1.0 ms の
   内数。→ 覆すと達成目標 5。

## 達成目標

1. render-lab の `earth-terminator` で、昼夜境界の夜側に雲だけの明るい帯が写り、入射が
   夕焼け色を帯びる。
2. 相方完了後の斜視構図で、ディザ粒の縁が中間調の靄で繋がって見え、G バッファに乗った積雲の
   塔は殻越しに透けない(積分が深度で止まる)。
3. `celestial-surface.ts` の焼き込み合成から B(巻雲)の項が消える(相方も完了していれば
   `cloudOpacityAt` ごと消え、albedoScale は地表のみの較正になる)。
4. 深宇宙の構図で大気の GPU 時間が 0 のまま。
5. F3「大気」増分 ≤ 0.3 ms(高設定、殻 2 枚)。
6. `npm run typecheck`・`npm run test:render`・`npm run test:game` が通る。
7. ヘッドレス本番ビルド(creative ステージ)の地球矩形平均輝度が移行前後で同水準(±数 %)。

## 手順

### 手順 1. 殻散乱の器を作り、巻雲を載せる

**目的**: 天体ループの各スロットへ「球殻 1 枚の単散乱」を挟む器(交差・場の読み・輝度)を
`cloud-scattering.ts` に新設し、まず巻雲(B、h = 10 km、ω₀ ≈ 1、HG g = 0.8)を載せる。同じ
commit で焼き込みの B 項を外し、albedoScale を測り直す — 二重表現を 1 フレームも作らない。

殻を掠める視線は交点が 2 つになる。区間ごとに: 手前の大気区間 → 殻の透過率と放射輝度 →
奥の区間 → 下地、の順で既存の合成規約(手前層の透過率を掛けて足す)に載せる。

**変更が必要な箇所**

| ファイル | 何をするか |
|---|---|
| `src/render/pipeline/cloud-scattering.ts`(新規) | 殻交差 — `raySegment`(`atmosphere-pass.ts:199-231`)と同じ「半径² − 垂線距離²」の形で解く(b² − c 形は惑星間距離のカメラで f32 桁落ちし縞になる)。正距円筒の読み(姿勢適用・wrapS Repeat)。輝度式と掠め上限(決めたこと 2) |
| `src/render/pipeline/atmosphere-pass.ts` | :31-41 `BodySlot` へ殻 uniform(高度・場テクスチャ・姿勢・有効 τ スケール)、:131-141 スロット生成、:383-404 `setDraws` の書き込み。:181-193 のループ内で区間を殻で切り、:191-192 の規約どおり透過率へ乗算・内部散乱へ加算。殻交点が far = min(surfaceT, opaqueDist)(:218-223)を超えた画素は殻を捨てる。輝度は :339 `sunRadianceAt` を殻上の点で呼ぶ(使うのは slot の center と optics だけなので式はそのまま成立する) |
| `src/render/atmosphere.ts` | draw 構造体へ殻パラメータを足す。サンプル配分(:114 `allocateSamples`)は据え置き |
| `src/game/celestial/solar-system/earth-system.ts` | 殻パラメータと場テクスチャの供給。テクスチャ実体は地表の読み(`celestial-surface.ts:50-55`)と共有 — 4096×2048 RGBA ≈ 33 MB 級の VRAM を二重に持たない |
| `src/game/celestial/celestial-system.ts` | :517-525 `syncAtmosphere` で殻情報 + 姿勢を `setDraws` へ流す。`clouds` トグルのオフで殻を外す |
| `tools/render-lab/lab.ts` :349 / `tools/render-lab/cases.ts` :116 | render-lab の atmospheres 供給へ殻を足す |
| `src/render/celestial-surface.ts` | :63-67 の合成から B 項を外す(相方が先に R を外していれば `cloudOpacityAt` ごと削除)。albedoScale の再測は `earth-system.ts:136-143` |

- `npm run typecheck`・`npm run test:render`・`npm run test:game`。
- `npm run render-lab`(対話。**撮影はテクスチャの読み込みを待たないので、目視はこちらで行う**)
  の `earth-terminator`: 夜側の明るい帯と入射の夕焼け色。`earth`: 巻雲のベールが霞みの中に居る
  (白浮きしない)。水平線を掠める視線で明るいリングが出ない(掠め上限の検算)。
- mars を写す構図で火星大気に雲が出ない(1×1 黒の確認)。
- 深宇宙の構図で F3「大気」が 0 のまま。
- F3「大気」増分 ≤ 0.15 ms。
- ヘッドレス本番ビルドの地球矩形平均輝度が前後 ±数 %(実行ごと ±200 LSB 級で揺れるため

### 手順 2. 積雲の中間調を低層殻へ載せる

**前提: 相方([`opaque_cloud.md`](opaque_cloud.md))の手順 1(積雲の焼き込み外し + 不透明
シェル)が完了していること**(決めたこと 5)。

**目的**: R を τ = −ln(1 − min(c, 0.98)) で低層殻(h = 2 km)のミーへ載せる。積雲の縁の中間調が
ディザ粒の間を埋める靄になり、生成側が持つ中間調の情報が絵に出る。不透明部分は G バッファ深度が
積分を打ち切るので分岐しない — 不透明部の画素では殻の交点が深度の奥になり寄与が自然に消える。

**変更が必要な箇所**

| ファイル | 何をするか |
|---|---|
| `src/render/pipeline/cloud-scattering.ts` | 殻 2 枚目の呼び出し(場のチャンネルと τ 変換だけが違う) |
| `src/render/pipeline/atmosphere-pass.ts` | スロットの殻を 2 枚へ(uniform 追加。ループ内の挟み込みは同じ器) |
| `src/game/celestial/solar-system/earth-system.ts` | 低層殻のパラメータ供給 |

**達成条件と検証**
- `npm run typecheck`・`npm run test:render`・`npm run test:game`。
- `npm run render-lab`(対話)の斜視構図(相方の手順 3 が新設する `earth-oblique`): ディザ粒の
  縁が靄で繋がる。不透明の塔が殻越しに透けない。
- 中間調の多い領域の輝度が焼き込み時代より過剰に濃くない(二重計上チェック — ヘッドレス
  本番ビルドの地球矩形平均輝度 ±数 %)。
- F3「大気」増分が手順 1 比 +0.15 ms 以内(2 枚計 0.3 ms 以内)。

## 見積り

- GPU: 殻 1 枚 ≈ レイマーチのサンプル 2 点分(交差の解析 + 場 1〜2 タップ + 輝度式)。高設定は
  大気全体 24 サンプルで 1.5 ms → 1 サンプル ≈ 0.06 ms → 殻 1 枚 ≈ 0.12 ms、2 枚 ≈ 0.25 ms。
  雲の無い画素は交差判定だけで抜け、深宇宙では 0。数字は F3「大気」の実測で置き換える。
- 実装規模: 新規 `cloud-scattering.ts` ≈ 150 行級(同型の前例 — `sun-occlusion.ts` の環の帯
  1 源 ≈ 80 行 + 場の読みと掠め上限)。`atmosphere-pass.ts` への加筆は uniform と配線で
  ≈ 60 行級。

## 採らない案(再提案しないため)

| 案 | 却下理由 |
|---|---|
| 大気のサンプル点でミー密度をテクスチャ変調 | サンプル間隔(直下 7 km、水平線 150 km)が層の厚み 1 km に届かず、視線角でちらつく |
| 積雲の不透明部分を τ→∞ の殻で描く | 単散乱で灰色にしかならない(HG g ≈ 0.8 は後方 0.1 以下)。多重散乱の極限は相方の Lambert が担う |
| 「半透明部分だけ」を場から切り出して殻へ渡す | 不要な分岐。不透明部は G バッファ深度が積分を打ち切る |
| world パスの半透明 | 大気の霞みを受けず、水平線視で τ 2.7〜7 ぶん白く浮く。大気の上(夜光雲 80 km)にだけ許される |
