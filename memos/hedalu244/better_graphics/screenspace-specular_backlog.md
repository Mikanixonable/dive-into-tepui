# 局所反射 — まだ手を付けていない改善案と、容認しなかった案

局所反射（近くの物体の映り込み）で**採らなかった案・条件付きで先送りした案・評価して容認しなかった案**を集めたもの。
**判断が覆るまで着手しない。** 着手の条件を満たしたときに初めて読む。

コードの現況はコードが原本。ここにあるのは「これから何を足しうるか」と「同じ案を再び試さないための記録」だけ。

## 1. 映り込みの中の精度（光沢・ハイライト・指向性）

**着手の条件**: ユーザーから「映り込みの中の精度が気になる」類の要望が出たときだけ。ユーザーの判断なしに着手しない。

映り込みの像の元は、当たった面を反射率 `拡散色 + r × R`（r は知覚的粗さ、R は鏡面反射率）のランバート面とみなした放射輝度
`(拡散色 + r × R) / π × 照度 + 自己発光` に決めている。映り込みの中の物体はハイライトを持たない。採った理由（ユーザー）:

- アドホックだが、一様な反射への落とし込みとして妥当な近似に見える。
- 鏡面を入れても、指向性の点で物理的に正しいものにはならない。
- 鋭いハイライトによるブロック状のちらつきを防ぐ手段として、十分速く実装が楽。

**忘れてはいけないこと。**

- **像の元へ鏡面を単純に入れるだけでは、ちらつきが戻る。** 受け手の鏡面ローブに比べて小さく明るいハイライトに ray が当たる確率は
  （ハイライトの立体角）/（ローブの立体角）で、`leo-metal` の配置では約 5 × 10⁻⁴。均しのカーネルの数十画素で当たる回数の期待値は
  0.01〜0.03 回で、まれな1回が期待値の数十倍の明るさで来る。事後縮小列は 1画素の当たりを段 k で 2^k の格子に揃った一辺 2^(k+1) px
  の四角へ広げ、トーンマップで四角ごと飽和する。鏡面を入れた像の元では `leo-metal-flicker` の2列目の球に白いブロックが16枚中9枚
  出て、塊の揺れの最大は 102.4（像の元を一様な反射にすると 6.2）。**エネルギーを保つ空間の均しでは、当たる回数の期待値が1を大きく
  下回る限り明滅は消えない** — 消せるのは、的を大きくする・エネルギーを捨てる・的を直接標本化する、の3系統だけ。
- **像の元の鏡面は物理的に正しい指向性にならない。** マテリアルの鏡面はカメラへの視線とのハーフベクトルで求めた値で、追跡した
  ray の向きの値ではない。カメラから見たハイライトの位置と、受け手から見たハイライトの位置は別の場所にある（隣り合う球では
  法線で数十度ずれる）。

### 1-1. 事前縮小列から filtered importance sampling で像を読む

的を大きくする系統。当たった点の像を、像の元の縮小列から ray ごとに選んだ段で読み、小さく明るい的に当たる回数の揺らぎを減らす。
像のぼけ方は変えない（ローブを、事後縮小列が均す標本の数で割った大きさだけをぼかす）。

- 段: 標本の立体角 Ω_s = 1 / (N × pdf) の円錐が当たり距離 d で張る径を画面へ写し、その log2 に偏り β を足す —
  `log2(2 × d × tan(√(Ω_s / π)) × 焦点距離 / (−z_hit)) + β`（Colbert & Křivánek 2007。Stachowiak 2015 も同じ形）。pdf は選んだ向きの
  VNDF の密度 D(h)·G1(v) / (4·N·V) に、裾を切った分の 1 / (1 − b) を掛けたもの。N はその受け手を事後縮小列が均す標本の数 4^ℓ
  （ℓ はその ray の d から、事後縮小列の段を選ぶのと同じ式で求めた段）。つまみは β だけ。
- 見積り: `leo-metal` で、カーネルあたり4回当てるのに要るぼかしはローブ半径の約 25%、実効のローブ幅は √(1 + 0.25²) ≈ 1.03 倍。
  当たる回数の期待値 0.03 → 4 で、相対的な揺らぎ 1/√λ は 5.8 → 0.5。費用は、段を5程度に限ってマテリアルの 0.5 倍まで（13段の
  縮小列と像の読み出しで 0.395 ms、マテリアルの約 0.88 倍だった）。
- 縮小は**手前の層だけを平均する**（いちばん手前の面から ray thickness 以内。奥行きの矩形 RG32F と放射輝度の矩形 rgba16f を MRT で
  2枚の atlas に描く）。単純な平均では、当たった球の後ろの地球が像へ混ざり、`leo-metal` の像の色が地球の向きで振れた（B−R の
  振れ幅 54.5 → 4.1）。過去の実装は `git show d8a2d6c68^:src/render/pipeline/reflection-pass.ts`。
- 落とし穴: N を事後縮小列と別の式で求める（ぼかしすぎか、ちらつきが減らない）。VNDF の密度に 1 / (1 − b) を掛け忘れる（段が
  約 0.16 段ずれ、β の掃引に吸収されて気付かない — 式で確かめる）。追跡と像のパスが読むテクスチャが、atlas 2 × 2 を足して WebGPU の
  保証する16枚を超えないか数える。

### 1-2. 当たった面と受け手の粗さの比で、像の元の鏡面を混ぜる

エネルギーを捨てる系統。当たった面のローブが受け手のローブより十分細いときだけ鏡面を落とし、光沢面に映る光沢面のハイライトは
残す（Kaplanyan & Dachsbacher 2013 の正則化と同じ考え）。

- `I = (1 − λ) × M0_一様 + λ × M0_鏡面`、`λ = smoothstep(q0, 2 × q0, α_hit / α_recv)`（α は粗さの2乗。比はローブ半幅 2α の比と同じ）。
  いちばん滑らかな面（粗さ 0.0525）が映るとき、鏡面がそっくり消える受け手の粗さは q0 = 0.25 で 0.105 以上、q0 = 0.5 で 0.074 以上。
  `leo-metal` のハイライトの構図（受け手0.25、当たった面0.05）は比 0.044 で、どちらでも λ = 0。直接の鏡面だけでなく遠方の鏡面
  （天体照の像）も混ぜる。
- λ は像を読む4点ごとに求めて混ぜてから双線形に足す — 先に双線形に混ぜた粗さで求めると、面の縁で隣の面の粗さがにじむ。
- 像の元が2枚になり、マテリアル（またはその構成の像の元のパス）の出力が1枚増える。当たった面の α は一様な像の元の α に詰め、
  追跡と像のパスが G バッファの粗さを読む数を増やさない。読むテクスチャの数を数える。

### 1-3. 画面空間の追跡より正確なレイトレーシング

的を直接標本化する系統の手前にある、追跡そのものの置き換え。画面に写っていない面（白い立方体の裏面など）が映らない、画面空間の
追跡の限界も同時に外れる。

## 3. 将来の追い込みの候補

main へ送る前には行わない。絵の破綻ではなく、正確さの追い込み。

### 3-1. ray thickness が近くの物体を奥へ厚くしている疑い

ray thickness は当たった面の奥行きの5%（球の奥行き 24 m で 1.2 m、球の半径の3倍）で、球の後ろを抜ける ray も当たりになる。
粗さの段のケースで、発光球の像の明るさの和は対照の 1.26（粗さ0.05）〜1.92（0.3）倍で、期待値（1/アルベド ≈ 1.0〜1.2）を粗い帯ほど
超える。像の頂の行も、対照・真値より 7〜11 px 奥に出る（粗さ0.2〜0.3。均す前から 6〜11 px あり、像の上縁の ray thickness の偽の
当たりと符合する）。厚みを奥行きの比でなく当たった面の大きさ（画素の footprint）に結び付ける、当たった点の奥行きと ray の奥行きの
差で重みを落とす、などを、和の比と `bay-metal` の取りこぼしの両方で比べて決める。画面端・距離のフェードと hit tolerance も同時に
追い込む。

### 3-2. 追跡の起点の高さ（`originLift`）

- 起点の画素を出るまで当たりを取らない手当ては、平らな面では起点の高さが覆うので冗長。外すと同じ画素の中の接地物に当たれる。
- 面が視線とほぼ平行な縁の画素で、2次の項の倍率を根拠なく2倍で打ち切っている（コードの TODO）。
- 式は「G バッファの法線 = 深度の面の法線」を前提にし、補間法線・ノーマルマップとの差を覆わない。
- cosθ が法線の誤差より小さい極端な grazing では、反射の向きが面の下へ潜りうる（標本の向きにも同じ問題がある）。
- カメラへ向かう ray では、手前の刻みの z と今の画素の深度を比べるので、手前へせり上がる面で誤判定がありうる（撮影では未発生）。

### 3-3. 均しの縮小を tent にする（Jimenez 2014）

**着手の条件**: 均しの縮小の四角い段差が見えたとき。2×2 の箱の縮小を双線形で読む今の均しでは、1画素の当たりが格子に揃った四角へ
広がる。tent は四角を丸めて格子への吸着を弱めるだけで、明滅そのもの（1 の当たる回数の揺らぎ）は消さない。

## 4. 拡散側に関わる記録

- `BlueNoise.atScreenPixel` は 8bit の値を k/255 で読み、0 と 1 の両端を含む。局所反射の向きの標本だけは層の中心
  （`centeredAtScreenPixel`、(k + 0.5)/256）で読むように直し、`u.y = 1` の孤立した `w = 0` の穴が消えた。拡散側・大気・雲は k/255 の
  まま — 端点の偏りがあるかは拡散側で判断する。
