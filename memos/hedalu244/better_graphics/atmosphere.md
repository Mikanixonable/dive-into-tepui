# 大気散乱 — 残件

**前提は [`pipeline.md`](pipeline.md)。**

視線に沿った積分のヘルパ(`src/render/ray-march.ts`)は [`volume.md`](volume.md) の
オーロラ・プルームと共有する前提で切ってある。大気パスがその最初の利用者。

---

## 1. 残っている作業 — 実機での負荷の実測と調整

**この開発環境では測れない。** ヘッドレス Chrome は GPU タイムスタンプに対応せず
(`gpuSupported: false` で全パス 0)、CPU 時間はコマンド発行に埋もれて信号にならない
(`earth` ケースで オフ 6.5ms / 低 4.7ms / 中 5.2ms / 高 6.0ms と、オフが最も遅い順に出る)。

- **測り方**: 実機で負荷確認ウィンドウを開き、パス別 GPU 時間の「大気」行を読む。
  構図は LEO(大気が画面を覆う)と深宇宙(大気が見えない)の 2 つ。
  段は描画設定の「大気」で オフ/低/中/高 を切り替える。
- **予算**: LEO 構図で 高 1.5ms 以下 / 中 1ms 以下 / 低 0.5ms 以下。深宇宙構図でほぼ 0。
- **超えたときに削る順**: サンプル点の数(`COARSE_STEPS` / `FINE_STEPS`、線形に効く)→
  同時に描く天体の数(`MAX_ATMOSPHERE_BODIES`)→ サンプル点ごとの遮蔽の評価
  (`sunRadianceAt` の `sunOcclusion.transmittance`。これが 1 サンプルあたり最も重い)。
- **削るときも絵の狙いは変えない。**

見積り(未実測): 1920×1080 = 2.07e6 画素 × 16 サンプル × 約 150 演算(密度 2 種の exp +
位相 2 種 + 太陽光路の Chapman 4 回 + 遮蔽球 4 スロット)≈ 5.0e9 演算。5 TFLOPS 級 GPU で
**約 1.0ms**。

## 2. 実装が置いている前提

**覆すときはここから読む。**

1. **濃い表現を受ける天体は「カメラ位置の大気の濃さを最も強く作っている 1 体」。**
   カメラの向きは見ない — 地表から空を見上げて地面が視錐台に無くても空色は出るべきで、
   「画面内に写っているか」を条件にすると破綻する。「大気を持つ/持たない」の二値も使わない —
   ほぼ 0 の希薄な大気を設定した天体が近くにあるとき、二値では地球の大気を奪ってしまう。
   比較は**対数消散係数**で行う(素の `exp` は惑星間距離で下位溢れし、全天体 0 の比較が
   不定になる)。
   **限界**: この基準は「その場の濃度」であって「画面上の見かけの寄与」ではない。希薄大気の
   天体の地表近くから遠い地球のリムを望む構図では希薄側が勝つが、全天体に単層表現が常設される
   ので絵は退行しない。
2. **単層表現は品質設定に依らない土台で、全大気天体(スロット 4)に常設する。** 品質設定の段は
   「主天体に足す濃い表現」の選択であって、土台の有無ではない。
3. **濃い表現の重みは、第 1・第 2 候補の対数消散係数の差だけから決まる純関数で、状態を
   持たない。** 差が 0 の入れ替え点では両候補とも重み 0(単層のみ)で一致するので、順位が
   毎フレーム入れ替わっても絵は変わらない。ヒステリシスは検証が困難でステートがバグの温床に
   なるため採らない。拮抗帯では絵が単層寄りになるが、そこは「どちらの大気も同程度に支配的」な
   場所なので許容する。
4. **描画用の密度は、レイリーとミーがそれぞれ 1 本のスケールハイトを持つ 2 成分の指数。**
   物理の区分指数モデル(`EARTH_ATMOSPHERE` の 20 層)とは一致させない — 描画は描画の分布で
   よい。**成分ごとにスケールハイトを分けるのは LEO の絵に効く** — 地球のエーロゾルは 1.2km で
   地表に貼り付くのに対し分子は 8.0km なので、1 本に潰すと高度 20km の縁が白く濁って青が出ない。
   裾は、地平線方向の光学的厚みが閾値を切る高度で解析的に打ち切る。楕円体は考えず球で組む。
5. **サンプル点の遮蔽は天体の球だけ。メッシュの影は大気に落とさない。** メッシュは積分範囲に
   対して十分小さく、サンプル点がたまたまメッシュ影に入ることがアーティファクトになる。一方、
   大気に落ちる天体の影(日食の月)は品質に効くので残す。遮蔽器の選別は既存のまま —
   `environment-scene.ts` が「最大遮蔽率 1% 未満を捨て、視半径上位 4 体」で既に刈っており、
   水星の太陽面通過はここで落ち、日食の月は残る。**新たな選別機構は作らない。**
6. **太陽光路の透過率は解析で解く。LUT は作らない。** 視線の光学的厚みに使う Chapman 近似が
   そのまま太陽方向にも使えるので、二重積分にならない。**視線側が近似なのに太陽側だけ厳密に
   しても釣り合わない。**
7. **品質の段の値は保存された設定を読む鍵。** 段を足すときも既存の値を動かさない — 番号を
   詰め直すと、保存済みの設定が黙って別の段を指す。**ラベルに実装手法を出さない** — SPEC は
   観測できる質と負荷の段としてだけ書いてある。

## 3. 踏むと無言で壊れる道

**式を足すときにここを当てる。**

| 落とし穴 | 影響 | 見つけ方 |
|---|---|---|
| **空きスロット(半径 0・中心が原点)へ実スロットと同じ式を通すと、0 除算と下限>上限の `clamp` から NaN が湧く。`select` は選ばれない枝も評価するので、枝の中の発散も残る。散乱へ 0 を掛けても NaN は消えない** | 絵に画素単位の黒い斑点が出る(値は滑らかなのに合成結果だけが壊れるので、原因を透過率側に探すと外す) | 式を足したら、半径・スケールハイト・区間長へ床が張ってあるかを見る。斑点が出たら合成前の色を単独で映して切り分ける |
| TSL グラフは静的展開なので、サンプル数 × 遮蔽 4 スロットの二重ループが巨大な WGSL になり、パーサの再帰上限や命令数で**シェーダが無言で消える**(JS 例外なし、コンソールに検証エラーのみ) | 大気だけが絵から消える | render-lab で絵が出ないときは必ずブラウザコンソールを見る。累積は式の入れ子ではなく `toVar` への代入で組む |
| 濃さの比較を素の `exp` でやると惑星間距離で下位溢れし、全候補 0 の比較が不定になる | 深宇宙で主天体の選択がフレームごとに揺れる | 選択関数に `Math.exp` が無いこと |
| フェード重みを順位(離散値)や真偽から出すと、入れ替え点で重みが不連続になる | 拮抗点を跨いだ瞬間に絵がポップする | 重みが対数消散係数の差の連続関数(差 0 で両候補が一致)かを見る |
| 適応刻みの境界が等高線状のバンディングになる | LEO 構図のもやに帯が出る | render-lab `earth` の目視。刻みへのジッタ導入で逃げられる |
| `QuadMesh` は固定直交カメラで描かれるため、`projMatrixInverse` / `viewToWorld` の手書き同期を崩すと**平行投影のマップビューだけ**壊れる | マップビューで大気が歪む/消える | マップビューでの目視 |
| render-lab はテクスチャ読み込みを待たず、この環境では GPU タイムスタンプも効かない | 単色の絵や 0ms を回帰と誤読する | 負荷は実機でのみ読む |
| 品質の段の値を振り直すと、保存値が黙って別の段を指す | 高を選んでいた利用者が中に落ちる | 段を足すときに既存値の意味が変わらないことを見る |
| 複数天体の大気が画面上で重なったときの合成順 | 重なった構図でだけ前後が不自然(極めて稀) | 濃さ順(= 視点に近い順)で合成しているか |

## 4. 採らなかったもの

- **雲そのもの**はマテリアルパス内の 2 層サンプリングのまま(単独で切れるトグルだけがある)。
  `earth.ts` の UV ずらしによる雲影もそのまま — 雲高度 ~1e4 m での半影幅 93 m に対し雲テクスチャは
  4.9 km/テクセルで、ぼかすべき構造が存在しない。
- **多重散乱**は持たない(単散乱 + 環境光の代用)。
- **楕円体の大気**(球で組む)。
- **下地を波長ごとに減衰させること。** 合成のアルファは 1 つしか無いので、透過率は3成分の平均で
  代表させてある。内部散乱の色は波長ごとに出るので空の青も夕焼けの赤も成立するが、**厚い大気
  越しに見る地表が赤へ寄る**ぶんだけは表せない。直すには色ごとの合成係数(二重ソースブレンド)か
  合成の2回描きが要り、どちらも積分の評価回数を倍にするか合成先を増やす。
- **大気を持つ天体は earth と mars の 2 行だけ。** 金星・タイタンは光学パラメータの出典を
  当ててから足す(当てずに置いた値は、無いより悪い)。
