# 大気散乱 — 実装計画

**前提は [`pipeline.md`](pipeline.md)。**

**このファイルはパイプラインを触らない。** パスの位置(マテリアルパスの後、world の前)・合成先
(HDR 共有ターゲットへ前乗算アルファ)・読む物(G バッファ深度・遮蔽)は既に確定しており、
どの手順もこれを変えない。`setBody` の引数形だけは天体の複数化ぶんだけ広がるが、これは式の
一般化に伴う uniform の増減であって、パス構成の変更ではない。

大気以外の半透明(オーロラ・プルーム)は [`volume.md`](volume.md)。発光体なので同じ
アルゴリズムには乗らない。**視線に沿った積分のヘルパだけは共有する前提**で、大気パスが
その最初の利用者になる(手順5)。

---

## 1. 目的

いまの大気は近似の寄せ集めで、式が現実の構造を持っていない:

- **もやは Beer–Lambert 一本**(`HAZE_TAU0 = 0.34`)。散乱の積分ではない。
- **夕焼けは `vec3(1, 0.4, 0.1)` の固定補間。** 光路長から導いていない。
- **リム光は高度勾配を持たない**(視線とシェルの交点高度が定義上常に 340km なので、指数減衰が
  定数 1 個に潰れている)。
- **もやが大気天体以外の不透明面にも掛かる**(判定が「シェルの内側か」だけなので、再突入する
  破片が地表と同じ光学的厚みで白む)。
- **天体が `'earth'` に決め打ち**(`environment-scene.ts` の `syncAtmosphere`)。火星に大気を
  持たせる道が無い。

これを 2 層の構造へ作り直す:

- **土台: すべての大気天体に、指数密度から導いた解析 Beer–Lambert の単層表現を常設する。**
  品質設定に依らず 2 位以下の天体はこれで描かれ、望遠級ズームで火星を見るような構図でも
  大気が消えない。
- **付加: 最も支配的な 1 天体だけに、品質設定に応じた濃い表現を足す** —
  シェル(多層の簡易表現)か、視線に沿った散乱積分か。指数関数的な密度分布を前提にするので
  「大気圏の上端の界面」が LEO 視点で見えることがなく、もやの範囲判定もリムの勾配も式から
  自然に出る。

## 2. 決めたこと

ユーザーが覆せる形で並べる。覆すとどの手順が変わるかを添える。

1. **濃い表現を受ける天体は「カメラ位置の大気密度へ最も強く寄与している 1 体」。**
   カメラの向きは見ない — 地表から空を見上げて地面が視錐台に無くても空色は出るべきで、
   「画面内に写っているか」を条件にすると破綻する。「大気を持つ/持たない」の二値も使わない —
   ほぼ 0 の希薄な大気を設定した天体が近くにあるとき、二値では地球の大気を奪ってしまう。
   密度は連続量なので、希薄な大気は薄い寄与としてしか勝てない。
   比較は**対数密度 `ln ρ0 − h/H`** で行う(素の `exp` は惑星間距離で下位溢れし、全天体 0 の
   比較が不定になる)。
   **限界も含めて決める**: この基準は「その場の濃度」であって「画面上の見かけの寄与」ではない。
   希薄大気の天体の地表近くから遠い地球のリムを望む構図では希薄側が勝つが、全天体に単層表現が
   常設されるので絵は退行しない、として受け入れる。
   — 覆すと手順4の選択関数が変わる。
2. **単層の Beer–Lambert 表現は品質設定に依らない土台で、全大気天体(スロット 4)に常設する。**
   品質設定の段(簡易/シェル/積分)は「主天体に足す濃い表現」の選択であって、土台の有無では
   ない。 — 覆すと手順3・7・8が変わる。
3. **濃い表現(シェル/積分に共通)は、第 1・第 2 候補の対数密度差だけから決まる重み
   `w = smoothstep(0, Δ0, Δ)` で単層表現へ薄まる。状態(ヒステリシス・時間フェード)を
   持たない** — 差が 0 の入れ替え点では両候補とも w = 0(単層のみ)で一致するので、順位が
   毎フレーム入れ替わっても絵は変わらない。ヒステリシスは検証が困難でステートがバグの温床に
   なるため採らない。拮抗帯では絵が単層寄りになるが、それは「どちらの大気も同程度に支配的」な
   場所なので許容する。 — 覆すと手順4が変わる。
4. **描画用の密度は、レイリーとミーがそれぞれ 1 本のスケールハイトを持つ 2 成分の指数。**
   物理の区分指数モデル(`EARTH_ATMOSPHERE` の 20 層)とは一致させない — 描画は描画の分布で
   よい。**成分ごとにスケールハイトを分けるのは LEO の絵に効く** — 地球のエーロゾルは
   1.2km で地表に貼り付くのに対し分子は 8.0km なので、1 本に潰すと高度 20km の縁が白く
   濁って青が出ない。層に区切らない指数のままなので界面は生じない。無限遠まで裾を持つが、
   地平線方向の光学的厚みが閾値を切る高度で解析的に打ち切る(打ち切り高度はパラメータから
   導出し、界面は視認限界以下)。楕円体は考えず球で組む。 — 覆すと手順3・6の式が変わる。
5. **サンプル点の遮蔽は天体の球だけ。メッシュの影は大気に落とさない。** メッシュは積分範囲に
   対して十分小さく、サンプル点がたまたまメッシュ影に入ることがアーティファクトになる。一方、
   大気に落ちる天体の影(日食の月)は品質に効くので残す。現行の呼び形
   `sunOcclusion.transmittance(p, { rings: false, meshNormal: null })` をそのまま使う。
   遮蔽器の選別も既存のまま — `environment-scene.ts` が「最大遮蔽率 1% 未満
   (`MIN_OCCLUDED_FRACTION`)を捨て、視半径上位 `MAX_OCCLUDERS` = 4 体」で既に刈っており、
   水星の太陽面通過はここで落ち、日食の月は残る。**新たな選別機構は作らない。**
   — 覆すと手順6のサンプル評価が変わる。
6. **太陽光路(サンプル点→太陽)の透過率は 2D LUT**(高度 × 太陽天頂角、起動時に CPU で
   有大気天体ぶん生成)。視線積分の中で二重積分を回さないため。`render/blackbody.ts` の
   「起動時に一度だけ積分して 1D テクスチャで渡す」前例に倣う。 — 覆すと手順6だけが変わる。
7. **品質設定 `atmosphere` は真偽から 4 択(オフ/低/中/高)へ置き換える。** 値の符号は
   最初から 0=オフ / 1=低 / 2=中 / 3=高 と決めておき、手順7では未実装の「中」を
   選択肢に**置かない**(効かない選択肢を置かない規約)。手順8で 2 を挿入する — 後から
   番号を振り直すと保存値が黙って別の段へ化けるので、欠番を先に確保する。プリセットは
   手順7時点で low=低 / medium=低 / high=高、手順8で medium=中 へ更新。オフは
   手動選択のみ。保存済みの旧 boolean は検証で棄却されて既定へ落ちる(一度だけ設定が戻る。
   許容する)。**ラベルに実装手法(Beer–Lambert・シェル・積分)を出さない** — SPEC は
   観測できる質と負荷の段としてだけ書いてある。 — 覆すと手順7・8が変わる。

## 3. 達成目標

計画全体の合格条件。全手順の実施後にここを 1 つずつ当てる。

- 大気の見えが、天体ごとの指数密度とレイリー/ミーのパラメータだけから決まる。
  `src/render/pipeline/atmosphere-pass.ts` に `SUNSET_COLOR` / `HAZE_TAU0` / `RIM_MIN_H` /
  `RIM_SCALE_H` / `RIM_BRIGHTNESS` が **grep で 0 件**。
- `syncAtmosphere`(`src/game/celestial/environment-scene.ts`)の中に文字列 `'earth'` が無い。
- リムが高度勾配を持つ — render-lab `earth` ケースで、縁の明るさが高度方向へ連続に減衰して
  見える(一様な帯ではない)。単層表現でも成り立つ(最接近高度の指数が出す)。
- 大気の外の不透明面が霞まない — `earth` ケースへ置いた高高度の小球が白まない。
- 品質設定パネルの「大気」が オフ/低/中/高 の 4 択で、それぞれ 絵から消える /
  全天体が単層 / 主天体に多層シェル / 主天体に積分 になる。効かない選択肢が無い。
- どの品質段でも、2 位以下の大気天体に単層表現が付いている — 火星入りレジストリで LEO から
  望遠相当のズームで火星を見て確認。
- 主天体の入れ替わりでフレーム間の絵の飛びが無い — 地球⇄火星を跨ぐカメラ移動を実機で見る
  (シェル・積分の両段で)。
- 大気パスの GPU 時間(積分・1080p・LEO 構図)が実機の負荷確認ウィンドウで **1.5ms 以下**
  (見積り §5。実測で外れたらこの数字を実測へ置き換えて再判定する)。
- パスの位置・合成先・読む物が変わっていない(冒頭の制約)。

## 4. 手順

### 手順 3. 単層表現の常設 — **品質「低」の絵が完成**

- **目的**: 現行のリム+もやの式を、パラメータ表から導いた単層表現で置き換え、**全スロットへ**
  適用する。単層表現: 視線の最接近高度の指数から解析近似した光学的厚み τ で、奪う量
  (α = 1 − e^−τ)と戻す量(レイリー β の色 × (1 − e^−τ) × 日照)を出す。色付き(夕焼け)は
  太陽光路の τ を同じ解析近似で引いて波長別に落とす — 固定色の補間を持たない。
  これでリムの高度勾配・大気外の面が白まないこと・固定色の削除がこの時点で成立し、
  2 位以下の天体にも大気が付く。
- **変更が必要な箇所**:

  | ファイル | 何をするか |
  |---|---|
  | `src/render/pipeline/atmosphere-pass.ts` | `setBody` → `setBodies`(固定 4 スロットの uniform。TSL グラフは静的展開なのでスロット数はコンパイル時固定)。式の差し替え(全スロットをループで評価、遠い天体から順に合成)。`SUNSET_COLOR` / `HAZE_TAU0` / `RIM_*` を削除 |
  | `src/render/atmosphere-params.ts` | 単層表現が読む導出量(打ち切り高度・τ の解析近似係数)を足す |
  | `src/game/celestial/environment-scene.ts` | `dominantAtmosphere` を、対数消散係数の降順で最大 4 体返す形へ広げる |
  | `tools/render-lab/lab.ts` | `setBody` 呼び出しを新しい形へ |
  | `tools/render-lab/cases.ts` | `LabCase.atmosphere` の型を新しい形へ(earth / earth-eclipse ケース) |

- **達成条件と検証**: `npm run typecheck`。
  `grep -E "SUNSET_COLOR|HAZE_TAU0|RIM_MIN_H|RIM_SCALE_H|RIM_BRIGHTNESS" src/` が 0 件。
  `npm run render-lab:shot` の `earth`: リムに高度勾配があり、ターミネーター側の色が
  波長別の減衰から出ている。`earth-eclipse`: 影の斑が現行同等に落ちる。`earth` ケースへ
  高高度(大気外)の小球を足し、白まないこと。実機のマップビュー(平行投影)でも大気が出る
  (`projMatrixInverse` の手書き同期を壊していないことの確認)。

### 手順 4. 主天体の選択とクロスフェード機構

- **目的**: 濃い表現(手順6・8)を受ける主天体の指定と、その重み
  `w = smoothstep(0, Δ0, Δ)`(Δ = 第 1・第 2 候補の対数密度差)の配管を先に作る。
  **w は現在のカメラ位置だけの純関数で、状態を持たない**(決めたこと 3)。この時点で w の
  消費者はまだ居ないので、**絵は変えない** — 検証はデバッグ表示で行う。
- **変更が必要な箇所**:

  | ファイル | 何をするか |
  |---|---|
  | `src/game/celestial/environment-scene.ts` | 対数密度差から w を算出して渡す(純関数) |
  | `src/render/pipeline/atmosphere-pass.ts` | 主天体スロットと w の uniform を受ける |
  | `src/render/pipeline/debug-target.ts` ほかデバッグ表示の該当箇所 | 「大気」デバッグ表示へ w の数値(またはグレースケール)を出す |

- **達成条件と検証**: `npm run typecheck`。実機のデバッグ表示で、地球 LEO では w ≈ 1、
  地球⇄火星の中間(拮抗帯)へフォーカスを置くと w が連続に 0 へ落ちるのが読める。
  順位入れ替え点を跨いでも w の値が跳ばない。

### 手順 5. 不均等サンプルの積分ヘルパ

- **目的**: レイマーチングの器を大気の式から切り出して先に作る。サンプル点の刻みが不均等でも
  正しく積分できる形(区間ごとに `τ += σ(中点)·Δs`、透過率は累積 `exp(−τ)`、内部散乱は
  透過率×ソース項の累積)を、媒質を知らないヘルパとして持つ。[`volume.md`](volume.md) の
  オーロラ・プルームが後で同じ器を使う前提の形にする(σ とソース項をコールバックで受ける。
  サンプル数はコンパイル時固定、刻み幅は実行時の式)。**この時点で挙動は変えない**(利用者は
  まだ居ない。検証ケースだけが呼ぶ)。
- **変更が必要な箇所**:

  | ファイル | 何をするか |
  |---|---|
  | `src/render/pipeline/ray-march.ts`(新規) | 積分ヘルパ本体 |
  | `tools/render-lab/cases.ts` | 検証ケース `march-slab` を追加: 一様媒質の板をヘルパで描き、解析解 `exp(−τ)` と比べる。等間隔と偏らせた刻みの 2 構図で同じ値になることまで見る |

- **達成条件と検証**: `npm run typecheck`。`npm run render-lab:shot` の `march-slab` を
  `window.renderLab.measure` で読み、透過率の画素値が解析値との誤差 1% 未満、かつ等間隔と
  不等間隔で一致する。

### 手順 6. 主天体を積分で描く — **品質「積分」の絵が完成**

- **目的**: 本題。主天体の濃い表現として、指数密度 + レイリー/ミー単散乱の視線積分を実装する。
  もや・リム・夕焼け・太陽グローが 1 つの式から出る。合成は
  `mix(単層表現, 積分, w)` — 手順4の重みがここで初めて絵に効く。
- **中身**:
  - 視線区間は「カメラ(または打ち切り半径との交点)→ 不透明面(G バッファ深度)または
    打ち切り半径の遠側」。打ち切り半径は残余光学的厚み < 閾値になる高度から導出。
  - 刻みは適応: 局所スケールハイトと現在高度から次の一歩を決める(地表に近いほど・密度が
    濃いほど細かく)。手順5のヘルパに乗せる。
  - サンプル点ごとに: 密度(指数)× 位相関数(レイリー + Henyey–Greenstein)× 太陽光路の
    透過率(LUT)× 天体の影(`sunOcclusion.transmittance`、球のみ — 決めたこと 5)。
  - 太陽方向の視線ではミーの前方散乱が大気由来のグローになる(レンズ由来のグローは出力段の
    持ち物のまま、由来で分ける)。
  - 合成は現行と同じ前乗算アルファ(色 = 内部散乱の積分、α = 1 − 視線透過率)。
- **変更が必要な箇所**:

  | ファイル | 何をするか |
  |---|---|
  | `src/render/pipeline/atmosphere-pass.ts` | 積分経路の追加と w による合成 |
  | `src/render/atmosphere-lut.ts`(新規) | 太陽光路透過率の 2D LUT(高度 × 天頂角余弦)を起動時に有大気天体ぶん生成し、テクスチャで渡す |
  | `tools/render-lab/cases.ts` | ターミネーターを跨ぐ構図 `earth-terminator` を追加 |

- **達成条件と検証**: `npm run typecheck`。`npm run render-lab:shot` で: `earth` — リムの
  高度勾配が単層より滑らかに伸び、地表のもやが視線ごとの実光路になっている。
  `earth-terminator` — 昼夜境界の橙が光路長から出る。`earth-eclipse` — 影の斑がリムとも
  もやにも落ちる。絵が単色でも壊れた印ではない(render-lab はテクスチャを待たない)。
  シェーダが消えたらブラウザコンソールの WGSL 検証エラーを見る。

### 手順 7. 品質設定の接続 — オフ/低/高

- **目的**: `atmosphere` トグルを choice へ置き換え、手順3(低 = 単層)と手順6(高 = 積分)を
  品質設定で選べるようにする。「中」(値 2)は未実装なのでまだ選択肢に置かない(決めたこと 7)。
  あわせて雲のトグルを足す。
- **変更が必要な箇所**:

  | ファイル | 何をするか |
  |---|---|
  | `src/render/graphics-settings.ts` | `atmosphere` を choice(0=オフ / 1=低 / 3=高。presets low=1, medium=1, high=3)へ。`clouds` トグル(element 群)を追加 |
  | `src/game/celestial/environment-scene.ts` | choice を読んで pass へ経路を渡す形へ。雲トグルを earth ビューへ配る |
  | `src/render/pipeline/atmosphere-pass.ts` | 経路の切り替え(オフ = 全スロット無効 / 低 = w を 0 に固定 / 高 = 手順6) |
  | `src/render/earth.ts` | 雲の合成を切れるようにする(uniform 1 本) |

- **達成条件と検証**: `npm run typecheck`。実機の設定パネルで「大気」が 3 択になり、オフで
  消える・低で全天体単層・高で手順6の絵になる(LEO 開始ステージの地平線で見る)。
  旧 boolean 入りの localStorage で起動し、既定へ落ちること。雲オフで render-lab `earth` の
  地表から雲が消える。

### 手順 8. 品質「中」の追加 — 中間段の絵が完成

- **目的**: mid 帯の GPU 向けに、高度の違う同心球 3 面との交点で単層と同じ式を評価して重ねる
  多層シェル表現を主天体の濃い表現として実装し、choice へ値 2 として挿入する。ジオメトリは
  足さず画面空間のまま(パス構成不変)。積分と同じく `mix(単層, シェル, w)` で薄まる。
- **変更が必要な箇所**:

  | ファイル | 何をするか |
  |---|---|
  | `src/render/pipeline/atmosphere-pass.ts` | シェル経路の追加(3 面の交点評価) |
  | `src/render/graphics-settings.ts` | choice へ 2=中 を挿入。presets medium=2 へ |

- **達成条件と検証**: `npm run typecheck`。実機で「大気」が 4 択になり、中で低より
  リムに階調が付き、高より軽い。同構図で 低→中→高 と切り替えて明るさのオーダーが
  揃っている(段の切替はユーザー操作なので飛び自体は許容)。地球⇄火星のカメラ移動で中の段でも
  ポップしない。

### 手順 9. 負荷の実測と調整

- **目的**: 見積り(§5)を実測へ置き換え、予算(1080p・LEO 構図で積分 1.5ms 以下)へ収める。

## 5. 見積り

- **積分(最悪 = LEO で大気が画面を覆う構図)**:
  1920×1080 = 2.07e6 画素 × 24 サンプル × 約 150 演算(密度 exp + 位相 2 種 + LUT 1 フェッチ +
  遮蔽球 4 スロット)≈ 7.5e9 演算。5 TFLOPS 級 GPU で **約 1.5ms**。予算はこれを上限とし、
  超えたら手順9でサンプル数(線形に効く)と遮蔽スロットの評価(約 1/3 を占める)から削る。
- **単層(簡易)**: 現行実装と同構造・全 4 スロットぶんなので現行見積りの
  **0.2〜0.5ms**(pipeline.md の未実測見積りを引き継ぐ。手順9で実測に置換)。
- **シェル**: 単層と同じ式 × 主天体 3 面ぶんの追加なので単層の 2〜3 倍、**1ms 未満**。
- **LUT**: 256(高度)× 128(天頂角)× rgba16f = **256KB/天体**、有大気 2 天体で 512KB。
  生成は 256×128 点 × 光路あたり 128 ステップ ≈ 4.2e6 回の exp 評価 ≈ 起動時 **数十 ms × 天体数**
  (1 回きり。フレーム中の再生成はしない)。

## 6. リスクと落とし穴

| リスク | 影響 | それが露見する場所 |
|---|---|---|
| TSL グラフは静的展開なので、サンプル数 × 遮蔽 4 スロットの二重ループが巨大な WGSL になり、パーサの再帰上限や命令数で**シェーダが無言で消える**(JS 例外なし、コンソールに検証エラーのみ) | 大気だけが絵から消える | 手順6。render-lab で絵が出ないときは必ずブラウザコンソールを見る。和は `sumOf` の平衡木で畳む |
| 密度比較を素の `exp` でやると惑星間距離で下位溢れし、全候補 0 の比較が不定になる | 深宇宙で主天体の選択がフレームごとに揺れる | 手順2・4。対数で比べる実装かをレビューで見る(選択関数に `Math.exp` が無いこと) |
| フェード重みを順位(離散値)や真偽から出してしまうと、入れ替え点で重みが不連続になる | 拮抗点を跨いだ瞬間に絵がポップする | 手順4。重みが対数密度差の連続関数(Δ=0 で両候補の重みが一致)かをレビューで見る。手順6・8 で拮抗点にカメラを置いて目視 |
| w の消費者が手順6まで居ないため、手順4の配管ミスがその場で絵に出ない | 手順6で初めて発覚し、原因の切り分けが遠くなる | 手順4。デバッグ表示で w の値そのものを読む検証を省かない |
| 適応刻みの境界が等高線状のバンディングになる | LEO 構図のもやに帯が出る | 手順6。render-lab `earth` の目視。刻みへのジッタ導入で逃げられる |
| 単層とシェルと積分の較正がずれ、段の切替や w のフェードで明るさのオーダーが跳ぶ | クロスフェードが「連続」にならない | 手順6・8。同構図で段を切り替えて比較。フェードは拮抗帯の目視 |
| `atmosphere` の boolean → choice 化で、保存済み設定が検証に落ちて黙って既定へ戻る | ユーザーの設定が一度リセットされる(許容と決めた) | 手順7。旧値入りの localStorage で起動して確認 |
| choice の値を後から振り直すと、保存値が黙って別の段を指す | 積分を選んでいた利用者がシェルに落ちる | 手順8。値 2 を欠番として先に確保してある(決めたこと 7)。挿入時に既存値の意味が変わらないことをレビューで見る |
| `QuadMesh` は固定直交カメラで描かれるため、`projMatrixInverse` / `viewToWorld` の手書き同期を setBodies 改修で崩すと**平行投影のマップビューだけ**壊れる | マップビューで大気が歪む/消える | 手順2。マップビューでの目視を検証に含めてある |
| render-lab はテクスチャ読み込みを待たず、この環境では GPU タイムスタンプも効かない(supported=false で全パス 0) | 単色の絵や 0ms を回帰と誤読する | 手順6・9。負荷は実機でのみ読む |
| 大気の外へ出た視線の early-out を入れ忘れると、大気の無い構図(深宇宙)でも全画素が積分を回す | 大気が見えない場面で 1.5ms 払い続ける | 手順6・9。深宇宙構図で大気行がほぼ 0 になることを見る |
| 複数天体の単層表現が画面上で重なったときの合成順 | 重なった構図でだけ前後が不自然(極めて稀) | 手順3。カメラ距離の遠い順に合成する実装かをレビューで見る |
