# 露出

**前提は [`pipeline.md`](pipeline.md)。** とくに §1-5(明るさの目盛り)。
出力段(`render-pipeline.ts`)がトーンマッパへ渡す露出係数と、それに引きずられる明るさの
置き場所が担当範囲。**レンズ由来の像は [`lens.md`](lens.md)。**

---

## 1. 何が問題か

**逆二乗則が実装されたことにより、木星圏などが真っ暗になってしまった。**

いまの目盛りは「1 天文単位で π」に固定で、出力段は露出係数を持たない(1 を渡す)。
つまり**画面の白は 1 天文単位に固定されている。** 太陽から遠ざかれば絵はそのぶん暗くなり、
木星(5.2 AU)で 1/27、土星(9.6 AU)で 1/92、海王星(30 AU)で 1/900。
トーンマッピング(Khronos PBR Neutral)は **0.08 未満を `x → 6.25x²` で潰す強いトウを持つ**ので、
そこへ落ちた絵は黒へ吸われる。

太陽に正対したアルベド 0.3 の面(典型的な天体表面・艦の外殻)が画面へ出る値:

| 太陽からの距離 | 露出なし(いま) |
| --- | --- |
| 1 AU | 139/255 |
| 5.2 AU(木星) | 2/255 |
| 9.6 AU(土星) | 0/255 |
| 30 AU(海王星) | 0/255 |

**木星から先は実質的に黒。** これが直したいことのすべて。

---

## 2. どう順応させるか

**決着**:

- **順応する。** 「露出は場面によって変化しない」という現行仕様は書き換える。
- **部分順応にする** — 「太陽から遠い場所ほど暗い」は画面に残す。潰すのは黒へ吸われることだけ。
- **基準は段階的に実装する。** いま要るのは外延天体が見えることなので、**太陽からの距離**から
  引く。画面の輝度からの眼順応は将来入るかもしれないが、**仕様には基準を明言しない** —
  どちらで引いても仕様が嘘にならない書き方にする。
- **露出補正はプレイヤー向けの HUD ではなく、影の解像度と同じ描画設定のパラメータとして持つ。**

**形**: 基準点が受けている放射照度 `E` に対し、`e = max(1, (E₀/E)^k)`(`E₀` は 1 天文単位での
放射照度)。距離で書けば `e = max(1, (d/AU)^{2k})`。

**`max(1, …)` が効いている** — 1 天文単位より内側では順応しない。これで:

- **1 天文単位の絵がいまと 1 ピクセルも変わらない。** 較正(表示値 = アルベド)がそのまま残る。
- 太陽へフォーカスしても(`E → ∞`)露出は 1 で止まり、画面が真っ黒にならない。
  距離を丸める必要も、上限を置く必要も無い。**ゼロ除算も NaN も構造的に起きない。**
- 仕様の「1天文単位より太陽に近ければ明るく写る」をそのまま残せる。書き換えるのは遠い側だけ。

**`k` は要求から決まる。** 「太陽に正対したアルベド 0.3 の面が、海王星軌道でも sRGB で
50/255 を下回らない」を満たす最小の `k` は 0.796 なので **`k = 0.8`**。結果:

| 太陽からの距離 | 露出 `e` | アルベド 0.3 の面 |
| --- | --- | --- |
| 1 AU | 1 | 139/255(変わらない) |
| 5.2 AU(木星) | 14 | 95/255 |
| 9.6 AU(土星) | 37 | 81/255 |
| 30 AU(海王星) | 231 | 54/255 |

**遠いほど暗いことは 139 → 95 → 81 → 54 として残る。** 表示値の比は距離の -0.4 乗。

## 3. 露出を入れると一緒に効いてしまう3つの穴

**露出は画面全体に掛かるので、「位置に依らない定数として置かれている明るさ」がすべて
一緒に持ち上がる。** 先に塞がないと、外側で絵が黒から白へ壊れ方を変えるだけになる。

### 3-1. 環境光が位置に依らない定数である

`AMBIENT_IRRADIANCE` は 1 天文単位での直射の 9.3% として手で置かれた定数で、**位置によらず
一定に足されている。** アルベド 0.3 の面への寄与は表示値 0.0279 で、これは:

- 木星圏では直射(0.0111)の **2.5 倍**
- 海王星圏では直射(0.00033)の **84 倍**

つまり**外側の絵はいますでに「太陽光」ではなく「定数の環境光」で照らされている。**
そこへ露出 231 を掛けると 6.4 になり、**夜側まで真っ白になる。**

**実測(手順2 時点、環境光を直す前)**: `render-lab` へ `outer-5au` / `outer-10au` /
`outer-30au`(アルベド 0.3 の灰色球と艦1隻。恒星の距離だけが違う)を足して撮ると、球の最も
明るい画素は **3つとも sRGB (1, 8, 21)** で、1 LSB も違わない。**照度が 36 倍違っても絵が
変わらない** — 直射ではなく定数の環境光だけで光っているから。青いのは環境光の色そのもの。

**環境光の正体は地球照 — 地球が反射した光なのだから、地球から遠ざかれば距離の二乗で薄れる。**
**それだけを入れる。** これは露出とは独立に正しい修正であり、先に入れてよい。

**⚠ ここは最小限にとどめる。** 環境光は [`arealight.md`](arealight.md) がより物理的な表現へ
**丸ごと置き換える予定**で、ここでやるのはそれまでの延命でしかない。作り込むほど、置き換える
ときに捨てる量が増える。**次のどれもやらない**:

- 地球以外の天体の反射を足す(木星圏では木星が照らす、土星圏では土星が、など)
- 方向を持たせる / 位相角を掛ける / 遮蔽を受けさせる
- 多重散乱・星明かり・大気の輝きを分けて持つ
- 減衰の形を立体角の厳密解にする — **距離の二乗で足りる**

**地球が無いレジストリでは環境光は 0 になる。** 地球照なのだから、地球が無ければ届かない。
本影の中を埋めるぶんは恒星光側(直射に対する割合)が別に持っているので、ここが 0 でも
本影が真っ黒にはならない。

**実測(手順3 のあと、露出を入れる前)**: `outer-5au` の球の最も明るい画素が sRGB (12, 8, 2)、
`outer-10au` が (3, 2, 0)、`outer-30au` が (0, 0, 0)。**外側は本来これだけ暗い。** 1 天文単位の
較正ケース(`albedo` / `leo` / `saturn`)は 1 画素も動いていない。

### 3-2. 星野と小天体の点群は、手で置いた明るさで描かれている

星殻は実写写真をそのまま貼ったもので、**物理的な輝度の目盛りに載っていない。**
露出 231 を掛ければ天の川が白い雲になり、空の地の部分まで灰色に浮く。
小天体の点群も同じで、描画半径 3e7 m の灰色の点という**読ませるための表現**。

**どちらも露出を受けない。** 順応で明るさが変わってはならない固定の背景として扱う。

### 3-3. 惑星の輝点は、実体の球と同じ倍率でなければならない

輝点の表示応答(等級 +6 がかろうじて見える)は 1 天文単位で較正されているので、露出を掛けると
外側で明るくなりすぎる。**それでも輝点は露出を受けなければならない** — 見かけ直径 2px で
実体の球と入れ替わるので、**片方だけ露出を受けると切り替えの瞬間に露出の倍率ぶん明るさが飛ぶ。**

星殻(受けない)と輝点(受ける)が食い違うのは承知のうえで選ぶ。
**星殻の輝度を物理スケールへ載せれば、この例外は消える。**

---

## 4. 完了条件

- **1 天文単位の絵が変わっていない。** 較正ケースの期待値がそのまま通る。
- **木星圏・土星圏・海王星圏で、太陽に照らされた面が黒へ潰れていない。**
- **どこまでが物理でどこからが順応かが決めてあり、記録されている**(§2 の表)。
- 露出の規則が `DEVELOP/SPEC/RENDERING.md` と一致している。
- トーンカーブの最終決定。Khronos PBR Neutral を続けるか、トウの強さを変えるか。
  **較正ケース(`albedo` / `saturn`)の期待値は目盛りの側の話なので、曲線を変えても崩さない。**

# 実装計画 — 距離による部分順応

## 目的

**外延天体圏で絵が黒へ潰れるのを止める。** §2 の形(`e = max(1, (d/AU)^1.6)`)で露出を入れ、
そのために先に塞がなければならない §3 の穴(環境光の定数・星野の固定明るさ)を塞ぐ。

**1 天文単位の絵は 1 ピクセルも変えない。** 較正はこの計画の前後で不変。

## 決めたこと

**どれもユーザーが覆せる。覆されたときにどの手順が変わるかを併記する。**

1. **1 天文単位より内側へは順応しない**(`max(1, …)`)。§2 の理由による。
   **覆すと**(内側でも順応させると)、較正ケースの期待値・ゼロ除算の扱い・仕様の
   「近ければ明るく写る」の 3 つが同時に動く。手順1・4 が変わる。
2. **`k = 0.8`。** 「アルベド 0.3 の面が 30 AU でも sRGB 50/255 を下回らない」から出した値で、
   趣味の値ではない。**覆すなら要求のほうを書き換える**(手順1の仕様と手順6の検証が変わる)。
3. **順応の基準点は「カメラの注視点」。** 戦闘視点では自機、マップビューではフォーカス対象。
   カメラ位置ではない — マップビューではカメラが太陽系の外にいることがあり、そこを基準にすると
   露出が発散する。**覆すなら手順3・4 の基準点の取り方が変わる。**
4. **時間的な追従を持たない(瞬時)。** 位置の関数なので、**同じ場所では常に同じ絵**になる。
   移動による変化は連続なので段差にならない。段差になるのはマップビューのフォーカスを
   切り替えた瞬間だけで、それは視点の切り替えそのものが段差である。
   **覆すなら**(時定数を入れるなら)露出モジュールが履歴と `dt` を持つことになり、
   決定性が失われる。手順4 が変わる。
5. **環境光を露出より先に直す**(手順3 → 手順4 の順)。逆順にすると、途中の状態で
   **夜側が昼側より明るい絵**になる。
6. **星野と小天体の点群は露出を受けない。** §3-2 の理由。**惑星の輝点は受ける**(§3-3)。
   **覆すと**(輝点も外すと)2px の切り替えで明るさが飛ぶ。
7. **環境光の修正は「地球からの距離の二乗で薄れる」だけにする。**
   [`arealight.md`](arealight.md) が丸ごと置き換える予定なので、ここは延命。
   他の天体の反射・方向・位相・遮蔽・立体角の厳密解は**入れない**(§3-1 の列挙)。
   **覆すと**手順3が `arealight.md` の仕事を先取りし、置き換えるときに二重に捨てることになる。

## 達成目標

- **1 天文単位の絵が変わっていない** — `render-lab` の `albedo` ケースの最も明るい画素が
  sRGB (241, 231, 215)、`saturn` ケースの環と本体の比が 0.20、`leo` ケースの外殻の画素値が
  123.1(いずれも ±1 LSB)。
- **太陽に正対したアルベド 0.3 の面が、5.2 AU / 9.6 AU / 30 AU で sRGB 95 / 81 / 54(±8)。**
  1 AU の 139 と並べて、**遠いほど暗いことが数値として残っている。**
- 星野の明るさがどの距離でも変わらない。
- 描画設定に「露出補正」があり、段を変えると画面全体の明るさが変わる。
- 環境光が地球からの距離で減衰している — 低軌道では従来どおりで、外惑星圏では消える。
- `npm run typecheck` / `npm run test:physics` / `npm run build` が通る。

## 手順

### 手順4. 露出を通す

**目的**: この計画の本体。基準点の放射照度から露出を引き、トーンマッパへ渡す。
あわせて星野と小天体の点群を露出から外す(§3-2)。**同時にやる** — 片方だけだと外側の空が
白く浮いた絵になる。

**変更が必要な箇所**

| ファイル | すること |
| --- | --- |
| `src/render/pipeline/exposure.ts`(新規) | 露出係数の正本。基準点と恒星から `e = max(1, (E₀/E)^0.8)` を引き、トーンマッパへ渡す係数と、露出を受けない側が自分の色へ掛ける逆数を持つ |
| `src/render/pipeline/render-pipeline.ts` | `Exposure` を所有し、`toneMapped()` が `float(1)` の代わりにその係数を渡す。`render()` の中で毎フレーム引き直す。`applyGraphics` で露出補正を受ける |
| `src/game/celestial/environment-scene.ts` | 手順3で組んだ基準点を `exposure.setReference()` へも渡す。**同じ点を2度組まない** |
| `src/render/stars.ts` | 星殻の材質色へ露出の逆数を掛ける。`Billboard` と同じく基準色を別に持ち、毎フレーム掛け直す |
| `src/game/celestial/point-field-view.ts` | 同じ扱い。群ごとの基準色を持ち、露出の逆数を掛ける |

**踏む地雷**

- **較正が動いたら配線が間違っている。** 1 天文単位では `e = 1` になるので、`albedo` /
  `leo` / `saturn` の画素値は **1 LSB も動いてはならない。**
- 恒星を持たないレジストリでは、恒星が「描画原点から 1 天文単位」に置かれる。基準点もその
  近くになるので `e = 1` で通る。**壊れないことを確かめる**(クリエイティブステージ)。
- 露出はトーンマッパの中で掛かる(`neutralToneMapping(color, e)`)ので、**HDR ターゲットの
  half float(上限 65504)には影響しない。** 太陽面 4.62e4 に 231 を掛けた値もシェーダの
  f32 の中で完結する。
- デバッグ表示(拡散照度・鏡面照度・マテリアル・大気)も同じ `toneMapped()` を通るので、
  自動的に同じ露出が掛かる。**それでよい** — 通常表示と見比べるためのものなので。
- 模式図スタイルはトーンマッパを通らない。**露出の影響を受けないことを確かめる。**

**達成条件と検証**

- `npm run typecheck`。
- `albedo.png` / `leo.png` / `saturn.png` が 1 LSB も変わらない。
- `outer-5au.png` の球が **95/255 前後**、`outer-30au.png` が **54/255 前後**。
- 星野が写るケースで、距離を変えても星野の明るさが変わらない。
- 模式図スタイルの `leo` が白背景の輪郭図のまま。

### 手順5. 露出補正を描画設定へ足す

**目的**: 順応の結果へプレイヤーが段を掛けられるようにする。影の解像度と同じ、描画設定の
パラメータとして持つ。

**変更が必要な箇所**

| ファイル | すること |
| --- | --- |
| `src/render/graphics-settings.ts` | `exposureCompensation` を `choice` で足す。group は `basic`、items は `[[0.25,'−2'],[0.5,'−1'],[1,'±0'],[2,'+1'],[4,'+2']]`(EV 段)、presets は 3 面とも `1` |
| `src/render/pipeline/render-pipeline.ts` の `PIPELINE_GRAPHICS_KEYS` | 足す(描画テスト環境から切り替えられるようにするため) |

**踏む地雷**: 表の並びの規約は「粗いほうから順に」だが、露出補正には粗い/細かいが無い。
**暗いほうから順に並べる。**

**達成条件と検証**

- `npm run typecheck`。
- 描画設定パネルに「露出補正」が出て、段を変えるとその場で画面の明るさが変わる。
- `render-lab` の描画設定からも切り替えられる。
- 段を ±0 以外にすると、品質プリセットが「どれも選ばれていない」表示になる
  (表の作りからの帰結。**そうなることを確認する**であって、直さない)。

### 手順6. 実機で確かめて締める

**目的**: `render-lab` はケースを切り出した静止画しか出さない。**手で置いた明るさで描かれて
いる残りのもの**(噴射炎・爆発・オーロラ・惑星の輝点)が外側の露出に耐えるかは、実機でしか
見えない。

**やること**

1. `npm run dev` で、外惑星圏へ移動できるステージ(またはクリエイティブステージ)を開く。
2. 木星圏・土星圏で、**噴射炎・被弾フラッシュ・惑星の輝点**を出して白く飛んでいないか見る。
3. マップビューでフォーカスを地球 → 海王星と切り替え、**段差が許せる範囲か**を見る
   (時間追従を持たない決定の帰結。許せないなら決めたこと 4 をユーザーへ差し戻す)。
4. 白く飛ぶものがあれば、**この計画では直さず** `volume.md` へ1行で記録する
   (手置きの明るさの問題であって、露出の問題ではない)。
5. `npm run typecheck` / `npm run test:physics` / `npm run build`。

**達成条件と検証**

- 上の 2・3 を見た結果が §3 の下へ1〜3行で記録されている。
- **main へ送るので、変更箇所によらず全部回す**: `npm run typecheck` /
  `npm run test:physics` / `npm run build`。

## 見積り

**GPU**: 追加のパスもターゲットも無い。トーンマッパへ渡す係数が定数 1 から uniform になるだけで、
**1 画素あたり乗算 3 回。** 星野と点群の色は CPU 側で毎フレーム書くので、シェーダは増えない。
**計測に出ない水準。**

**CPU**: 1 フレームあたり、距離 1 回・`Math.pow` 1 回・`THREE.Color` の乗算 2 回。

**コード量**: `exposure.ts` が約 50 行。他は各ファイル数行ずつ。

**数値の導出**(手順6 の検証はこれと突き合わせる):

- 露出 `e = (d/AU)^{2k}`、`k = 0.8` → 木星 `5.2^1.6 = 14`、土星 `9.6^1.6 = 37`、
  海王星 `30^1.6 = 231`。
- 表示値は `アルベド × (AU/d)² × e = アルベド × (d/AU)^{-0.4}`。アルベド 0.3 なら
  1 AU で 0.30、木星 0.155、土星 0.122、海王星 0.077。
- トーンカーブは 0.08 以上で `x − 0.04`、0.08 未満で `6.25x²`。sRGB へ直すと
  **139 / 95 / 81 / 54**。
- `k` の下限: 海王星で 50/255 を保つには `0.3 × 900^{k−1} ≥ 0.0751` → `k ≥ 0.796`。

## リスクと落とし穴

| リスク | 影響 | 露見する場所 |
| --- | --- | --- |
