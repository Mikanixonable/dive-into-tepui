## 目的

`screenspace-base` には、別のマシンで並走している拡散側の改善が入る前の、品質の低い拡散補正項が混ざっていて、パス順の組み直しも
残っている。このまま main へは送れない。点検 → push → 拡散側との調整 → パス順の組み直し → main の順に進める（ユーザー）。

`DEVELOP/SPEC/RENDERING.md` の局所反射の振舞い（滑らかな面に近くの物体が映り、天体照と環境光の像を置き換え、粗い面ほどぼけ、
十分に粗い面では見えない。拡散光の遮蔽量を像の代わりに使わない。描画設定「近くの物体の映り込み」「ぼかし」。デバッグ表示と GPU の
行）は実装済みで、仕様の追記は要らない。

## 決めたこと

**ユーザーが決めたこと。**

- main へ送る前に、`/comment-cleanup` と `/refactor` を通し、remote へ push して拡散側と調整し、パス順を組み直す。
- 精細さの段の調整と負荷の追い込みは、拡散側とまとめて別の計画（`graphics-settings-feature.md`）で行う。
- 映り込みの像の元は `(拡散色 + r × R) / π × 照度 + 自己発光`（r は知覚的粗さ、照度は近傍補正込み）。映り込みの中の精度を上げる
  手段には、指示なしに着手しない（`screenspace-specular_backlog.md`）。
- **対照の球光源は残し、置いた枠だけを組む**（`41760f13b`）。粗さの段のケースの対照（`reflection-ladder-lights`）は、局所反射の
  像が光源として正しく積分した鏡面像に似ているかを測る唯一の物差し。ライトプリパスは光源を「事前コンパイルする列」と「寄与を持った
  最初のフレームでマテリアルを組む列」で受け、球光源の枠は後者に入る（ゲームの起動の事前コンパイルが組む照明のマテリアルは 5 枚）。
  パス順の組み直しでライトプリパスを書き換えるときも、この2列を保つ。

**自分が決めたこと**（覆すと括弧内の手順が変わる）。

- **`render-pipeline.ts` の分割（lint の max-lines 500 に対し 627 行）はパス順の組み直しの後に回す**（手順5）。組み直しが同じ実行順の
  コードを書き換え、拡散側のブランチも同じファイルを触るので、先に分けると合わせるときの衝突が増え、組み直しで書き直すことになる。
- **映り込みの均しは、縮小列（`screen-space/reflection-reduction.ts` の `ReflectionReduction` — 段を組み、受け手の面に載る分を読む）と、
  段を選んで均す側（`reflection-denoise.ts` の `ReflectionDenoise`）に分けた**（`d3f0b9426`）。縮小列の画素の形式（代表の面・被覆率）は
  縮小列の中に閉じる。tools の表は `REFLECTION_LEVEL_COUNT` を `reflection-denoise.ts` から文字列で読むので、定数を動かすときは
  `tools/render-lab-reflection-levels.mjs` も直す。

## 前提として守る契約

パス順の組み直し（手順5）で書き直すまで、合わせる作業（手順4）でも崩さない。

- **一致すべき値は一度しか計算しない。** 遠方鏡面と像に掛ける鏡面反射率 `R`（`material-pass.ts` の `specularReflectanceAt`）は、陰影の
  合成の1つの式で一度だけ読む。置換重み `w` と `w × I` は映り込みの描画先の同じ texel に詰め、1回の均しで `w̄` と `(w × I)‾` を得る。
- **合成**: 画素の最終の陰影は `keep + R × ((1 − w̄) × S_far + (w × I)‾)`。`keep = 拡散 + R × S_direct + 自己発光`。ライトプリパスは鏡面を、
  置き換えない直接の分 `S_direct`（太陽・対照の球光源）と、置き換える遠方の分 `S_far`（天体照・環境光）の2枚に分けて書き、どちらへ
  書くかは光源が宣言する。`w = 1` で遠方鏡面がそっくり像へ入れ替わり、miss の `w = 0` では遠方鏡面を変えない。
- **局所反射の判定は幾何だけを見る。** `w` と当たる点は、深度と G バッファの法線・粗さだけで決める。遠方光も拡散側の target も
  読まない。鏡面の遮りを拡散の遮蔽から作らない。時間方向の蓄積（前フレームの履歴）を使わない。
- **拡散側との境界。** `1 − w̄` を掛けるのは遠方鏡面だけで、拡散の寄与・照度バッファの拡散・近傍補正・直接の鏡面には触れない。
  局所反射は拡散側の中間 target（照度補正・照り返しの源・その縮小や均し）を読まず、拡散側とファイル・target・GPU の行を共有しない。
  **ただし像の元はマテリアルパスが照度バッファの拡散（近傍補正を含む）から作る** — 拡散側の変更で、局所拡散光が照度バッファの外で
  足されるようになったら、像の元にも同じものを入れる。像の元から近傍補正を抜いた映り込みは、遮られた隅の面が明るく浮き、品質を
  容認できなかった。
- **デバッグ表示と GPU の行。** 局所反射の中間 target はすべてデバッグ表示を持ち、ボタンは生成順（パス順）に並ぶ（`DEBUG_TARGETS` と
  `tests/render/debug-target.test.ts`）。GPU の行は描画段ごとに実行順（`GPU_PASS` と `tests/render/gpu-timings.test.ts`）。描画設定で
  切られた段のデバッグ表示は黒。

## 検証の物差し

- **render-lab のケース**: `materials`（`leo-metal*`。ハイライトの構図 `leo-metal-flicker-<k>` は乱数のタイルをずらした16枚、
  `leo-metal-raw-flicker-<k>` はぼかしオフ）、`bay`（`bay-metal*`、`bay-metal-flicker-<k>`）、粗さの段のケース `reflection-ladder`・
  対照の `reflection-ladder-lights`・チェッカーの発光板の `reflection-ladder-checker`（床は粗さ 0.05〜0.6 の10本の金属の帯。環境光・
  レンズ効果・アンチエイリアスを切り、映り込みをオンに固定する）。
- **表とちらつき**: `node tools/render-lab-reflection-levels.mjs <組の dir>`（像の縁の幅の対照・予測・真値に対する比、像の明るさの頂と和、
  まだら、チェッカーの縁、像から遠い輝点）。`node tools/render-lab-reflection-flicker.mjs <組の dir>`（画素の揺れと 8 × 8 px の塊の揺れ）。
- **負荷**: `node tools/render-lab-measure.mjs 3 reflection`。比べる2つのビルドは同じ session で交互に測る（session ごとに 3〜4 割ずれる）。
- **基準の撮影の組**（`.render-lab-shots/`、git に入らない）: `ssr-before-1` / `-2`（`3e646383`、局所反射の着手前、各67枚、2組は md5 一致）、
  `ssr-step9i`（`f9d56706c`、157枚。今の局所反射）、`ssr-refactor`（`d3f0b9426`）と `ssr-sphere-lights`（`41760f13b`）はどちらも
  157枚が `ssr-step9i` と md5 一致。
- **読むときの落とし穴**: アンチエイリアスはデバッグ表示にも掛かり、孤立した1画素をにじませる（1画素単位で読む撮影は `antialias: 0`）。
  像の明るさの和は、トーンマップを戻してから比べる（8bit の表示値のまま足すと、薄く広げた像が点描の半分以下に読める）。

## 手順

### 手順 4. 拡散側のブランチと合わせる

**目的** — 拡散側の改善（照り返しの走査と均し方）を取り込み、局所反射と同居させる。**拡散側のブランチ名と、どちらへ取り込むかを
ユーザーに確かめる。**

**変更が必要な箇所**（衝突しうる所。拡散側のブランチを fetch してから確定させる）

| ファイル | 見ること |
| --- | --- |
| `src/render/pipeline/render-pipeline.ts` | 実行順・`compile()` の段表・デバッグ表示の合成・`rebuildForGraphics` |
| `src/render/pipeline/screen-space/screen-space-pass.ts` / `diffuse-correction.ts` / `lighting/diffuse-correction-source.ts` | 近傍補正の足し方 — 照度バッファの拡散の外で足すようになっていたら、像の元にも入れる（「前提として守る契約」の拡散側との境界） |
| `src/render/pipeline/debug-target.ts` / `tests/render/debug-target.test.ts` | ボタンの並びを生成順へ |
| `src/render/gpu-timings.ts` / `tests/render/gpu-timings.test.ts` | 行の並びを実行順へ |

| `tools/render-lab/*`・`tools/render-lab-measure.mjs` | ケースと計測の軸 |

`(k + 0.5) / 256` で読むように直した）。拡散側・大気・雲に端点の偏りがあるかは拡散側の判断。

**達成条件と検証**

- `npm run typecheck` / `npm run test`（合わせると全層に及ぶ）/ `npm run check:boundaries`。
