## 目的

`screenspace-base` には、別のマシンで並走している拡散側の改善が入る前の、品質の低い拡散補正項が混ざっていて、パス順の組み直しも
残っている。このまま main へは送れない。点検 → push → 拡散側との調整 → パス順の組み直し → main の順に進める（ユーザー）。

`DEVELOP/SPEC/RENDERING.md` の局所反射の振舞い（滑らかな面に近くの物体が映り、天体照と環境光の像を置き換え、粗い面ほどぼけ、
十分に粗い面では見えない。拡散光の遮蔽量を像の代わりに使わない。描画設定「近くの物体の映り込み」「ぼかし」。デバッグ表示と GPU の
行）は実装済みで、仕様の追記は要らない。

## 前提として守る契約

パス順の組み直し（手順5）で書き直すまで、合わせる作業（手順4）でも崩さない。

- **一致すべき値は一度しか計算しない。** 遠方鏡面と像に掛ける鏡面反射率 `R`（`material-pass.ts` の `specularReflectanceAt`）は、陰影の
  合成の1つの式で一度だけ読む。置換重み `w` と `w × I` は映り込みの描画先の同じ texel に詰め、1回の均しで `w̄` と `(w × I)‾` を得る。
- **合成**: 画素の最終の陰影は `keep + R × ((1 − w̄) × S_far + (w × I)‾)`。`keep = 拡散 + R × S_direct + 自己発光`。ライトプリパスは鏡面を、
  置き換えない直接の分 `S_direct`（太陽・対照の球光源）と、置き換える遠方の分 `S_far`（天体照・環境光）の2枚に分けて書き、どちらへ
  書くかは光源が宣言する。`w = 1` で遠方鏡面がそっくり像へ入れ替わり、miss の `w = 0` では遠方鏡面を変えない。
- **局所反射の判定は幾何だけを見る。** `w` と当たる点は、深度と G バッファの法線・粗さだけで決める。遠方光も拡散側の target も
  読まない。鏡面の遮りを拡散の遮蔽から作らない。時間方向の蓄積（前フレームの履歴）を使わない。
- **拡散側との境界。** `1 − w̄` を掛けるのは遠方鏡面だけで、拡散の寄与・照度バッファの拡散・近傍補正・直接の鏡面には触れない。
  局所反射は拡散側の中間 target（照度補正・照り返しの源・その縮小や均し）を読まず、拡散側とファイル・target・GPU の行を共有しない。
  **ただし像の元はマテリアルパスが照度バッファの拡散（近傍補正を含む）から作る** — 拡散側の変更で、局所拡散光が照度バッファの外で
  足されるようになったら、像の元にも同じものを入れる。像の元から近傍補正を抜いた映り込みは、遮られた隅の面が明るく浮き、品質を
  容認できなかった。
- **デバッグ表示と GPU の行。** 局所反射の中間 target はすべてデバッグ表示を持ち、ボタンは生成順（パス順）に並ぶ（`DEBUG_TARGETS` と
  `tests/render/debug-target.test.ts`）。GPU の行は描画段ごとに実行順（`GPU_PASS` と `tests/render/gpu-timings.test.ts`）。描画設定で
  切られた段のデバッグ表示は黒。

## 手順

### 手順4 の結果（2026-10-12、`1a86f266f`）

- 衝突は 6 ファイル。像の元は、0 以上に切った照度バッファの拡散（近傍補正込み）から作る（`material-pass.ts` — 拡散側が負の照度を 0 に切っていた）。
  デバッグ表示の合成は拡散側が `debug-composites.ts` へ分けていたので、映り込みの表示はそこへ移した。「マテリアル」は `keep` を映し、「鏡面照度」は
  「直接の鏡面照度」「遠方の鏡面照度」に分かれた。GPU の行は、拡散側が分けた近傍拡散の行（写しと源・走査・代表縮小・帯縮小・合流・均し・拡大・パス平均）の
  後に、ライティング・マテリアル・映り込み・映り込みの均し・陰影の合成。`render-pipeline.ts` は 492 行。
- 検証: `npm run typecheck`、`npm run test:render`（279/279）、`npm run test:settings`、`npm run check:boundaries`。映り込みを切ると render-lab の全ケースが
  落ち着いて撮れ、致命的なイベントは 0 件。
- **見つけた問題 — 映り込みの追跡が、この機械（Intel HD 520）では毎フレーム決定的でない。** 映り込みをオンにすると `leo` で毎フレーム約 2,500 画素が
  最大 74 LSB 揺れ、`npm run render-lab:shot` が「did not settle」で止まる（`leo-metal-reflection`・`bay-metal-reflection`・`reflection-ladder*` の 5 ケース）。
  `origin/screenspace-base` を単独でビルドしても同じで、マージ由来ではない。デバッグ表示で段を遡ると、深度・法線・像の元・追跡の深度は毎フレーム一致し、
  raw の置換重みで約 1,100 画素が当たりと外れ（0 と 255）のあいだで入れ替わる — 揺れは追跡の当たり判定で生まれる。入れ替わりは 2 フレーム周期でなく
  不規則で、精細さの段（深度の縮小 1/2・全解像度）に依らない。別のマシンでは 157 枚が md5 一致していたので、GPU やドライバに依る未定義の値か、
  シェーダの組み方に依る。ゲームでは、この GPU で映り込みがちらつく。
- 未確認: 「変えない挙動」の手順4 の項と、`bay-moon-corner` の粗さ 0.05 の板に映る隅がデバッグ表示「拡散照度」と同じ明暗で写ること（上の問題で、
  この機械では映り込みの撮影を比べられなかった）。手順4.5 で当てる。
- 拡散側へ伝えること（`BlueNoise.atScreenPixel` は 8bit の値を k/255 で読み、0 と 1 の両端を含む）は、`temporal-denoise.md` の手順4（フレームごとの seed）へ入れた。

### 手順 4.5. 映り込みの追跡を毎フレーム決定的にする

**目的** — 同じ入力から毎フレーム同じ映り込みを描く。ゲームでのちらつきを消し、この機械で映り込みの撮影を比べられるようにする（`screenspace-source.md` の
前後比較に要る）。直すのは決定性だけで、映り込みの期待値は変えない。

**手掛かり**（手順4 の結果）— 揺れは raw の置換重み（追跡の当たり判定）で生まれ、入力のデバッグ表示は一致している。疑う順:

1. 追跡のシェーダの未定義の値 — 範囲外の `textureLoad`（WebGPU は範囲外の読みの値を定めない）、初期化しない変数、ループの `Break` の後に読む値。
   線分が画面の外から始まる画素、`exitFraction` の端の扱い、二分の `low` と `high` の初期値を当たる。
2. three の TSL が出す WGSL — Node で `WGSLNodeBuilder` とスタブの renderer から生成して読む（生成の前に `setRenderTarget` しないと MRT の出力が落ちて
   空のシェーダになる）。
3. 1・2 で見つからなければ、追跡を段階的に削った一時版（歩数の固定・二分を外す・`Break` を外す）で、どこを外すと揺れが消えるかを二分探索する。

**変更が必要な箇所** — `src/render/pipeline/screen-space/reflection-trace.ts`（見込み）。

**達成条件と検証**

- 映り込みをオンにした `leo` の連続 8 フレームの差が 0（精細さ 低・中・高）。手順4 の診断に使った一時スクリプト（連続フレームを撮って差の画素を数える）で測る。
- `npm run render-lab:shot` が全ケースで完走する。
- 映り込みの期待値を変えていない — 修正の前の多フレーム平均と、修正の後の 1 フレームが近い（揺れの分を除いて差が無い）。
- 「変えない挙動」の手順4 の項と、`bay-moon-corner` の隅。
- `npm run typecheck` / `npm run test:render`。commit（`fix(render): 映り込みの追跡を毎フレーム同じ結果にする`）。
