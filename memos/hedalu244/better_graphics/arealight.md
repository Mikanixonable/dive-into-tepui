# エリアライト — 太陽の球光源と、天体照

**これは計画ファイルである。** 着手順の手順書であり、現状の解説ではない。
前提となる描画基盤の骨格は [`pipeline.md`](pipeline.md)(とくに §1-3 責務境界、§1-5 明るさの
目盛り、§2 パスの構成)。**この文書は、そこを読まなくても着手できるだけの事実を本文へ埋めてある。**

---

## 目的

**光源が「位置と半径を持つ点」のままで、有限の立体角を持たない。** その帰結として 3 つの嘘が
同時に画面へ出ている。

1. **影の中が物理的に嘘をついている。** 不透明物に完全に遮られた画素でも、恒星の直射光が
   基準強度の 4% 残る(`SHADOW_MIN_SUN`)。影の中で法線の情報が失われるのを防ぐために置かれた
   代用だが、**露出が入って絵が HDR らしくなったことで、この床がそのまま見えるようになった。**
   同じ場面で惑星の環は `sunOcclusion.transmittance()` を直に読んでいて床を持たないので、
   **本体表面と環とで影の中の暗さが食い違っている。**
2. **天体照が方向も位相も持たない定数になっている。** `AMBIENT_IRRADIANCE` は「低軌道での
   明るさに合わせた手書きの定数 × 地球からの距離の逆二乗」で、地球が居ないレジストリでは 0。
   方向を持たないので、影の中に法線の陰影が戻らない。位相も遮蔽も持たないので、
   **地球が食に入っていても地球照が同じ強さで届く。**
3. **太陽が点のままなので、視半径が効く場面で破綻する。** 1 天文単位では視半径 0.266° なので
   拡散に関しては点で足りるが、水星近日点(0.86°)・恒星の近傍では終端がおかしくなる。
   鏡面はもっと早く破綻する — **粗さの小さい金属面では、点光源の GGX がハイライトをほぼ
   消してしまう**(本来は太陽の円盤がそこに映る)。

**この 3 つは重要度と実装の難しさが真逆を向いている。** 効くのは天体照(低軌道で地球は全天の
31% を占める)だが、難しいのも天体照(球面の一部しか光っていない)。太陽の球光源化は効き目が
限られるかわりに、**一様球という最も単純な形**で、しかも**天体照がそのまま流用する積分器**に
なる。だから**太陽を先に、天体照を後から段階的に**進める。

## 決めたこと

**どれもユーザーが覆せる。** 覆したときにどの手順が変わるかまで書く。

### D1. 影の床(`SHADOW_MIN_SUN`)は消す。影の中の法線は天体照が担う

不透明物による遮蔽は 0 まで落とす。**手順 1 と手順 4 の間、影の中は方向を持たない環境光だけに
なり、いまより情報が減る** — これは受け入れる。埋め合わせは手順 4 以降。
覆すなら手順 1 が丸ごと消え、手順 5-1 の完了条件から「床が 0 件」が落ちる。

### D2. パス構成は 10 段のまま。ライティング段の内部を光源ごとの描画命令へ割る

**「光源ごとに別のパスにすれば疎結合になるか」への答えは「なる。ただしパイプラインの段は
増やさない」。** ライティング段は 1 つのまま、内部で

- 照度バッファ(拡散・鏡面の MRT 2 枚)を 0 でクリアし、
- 光源 1 つにつきフルスクリーン 1 枚を**加算合成**で描く

という形にする。GPU 計測の行もデバッグ表示の候補も増えない(どちらも「ライティング」1 行の
まま)。光源の種類ごとにマテリアルが独立するので、**種類を足す = ファイルを足して描画命令を
1 本増やす**だけになる。

**採らなかった案: 1 枚の描画命令のまま、設定と光源数の組み合わせごとにマテリアルを作り分ける**
(遮蔽パスが環あり/なしの 2 枚を持つのと同じ形)。G バッファを 1 回しか読まない利点はあるが、
**光源の本数がフレームごとに変わるので、組み合わせの数だけシェーダを持つことになり、
初めて木星圏へ入った瞬間にコンパイルで詰まる。** 加算合成なら本数が変わっても
シェーダは変わらない。**この問題は、加算合成が MRT で効かないと分かった場合に戻ってくる**
(そのときは光源の上限本数ぶんのスロットを常に展開し、空きスロットを強度 0 で回す)。

**光源別のデバッグ表示は足さない。** 片方の設定を「なし」にすればもう一方だけの絵が出る。

### D3. 太陽の鏡面は LTC を採る。代表点近似(Karis の球光源)は採らない

代表点近似は太陽(視半径 0.266°)には十分だが、**天体照(低軌道の地球で視半径 70°)では
破綻する。** 太陽用と天体照用で別の近似を持つと、切り替わる場所で絵が飛ぶ。**積分器は 1 つに
する。** 覆すなら手順 3 が軽くなり、手順 5-2 が別実装になる。

**LTC は自前で書く。** three は `LTC_Evaluate` / `LTC_Uv` を `three/tsl` からも `three/webgpu`
からも公開していない(`RectAreaLightNode` の内部にしか無い)。**`three/src/…` の深い import は
してはならない** — `three/webgpu` のビルドとは別に three のノード実装がもう 1 部バンドルへ入る。

**LTC の係数表も自前で焼く。** `three/addons/lights/RectAreaLightTexturesLib.js` は素の `three`
(= `three.module.js`)を import しているので、**実行時に読むと three のコアビルドが丸ごと
バンドルへ入る**(いま `src/` に素の `three` からの import は 0 件)。表そのものは 64×64 の
RGBA なので、**`tools/` の生成スクリプトで半精度へ焼いてモジュールへ書き出す**
(`npm run export-assets` と同じ扱い。半精度 = 32 KB、base64 で約 44 KB)。

### D4. 光源リストの打ち切りは「1 LSB を動かせない光源を捨てる」で決める

**チューニング値を置かない。** 判定は次のとおり:

- 天体 b が基準点(カメラの注視点)へ届ける放射照度 `E_b`。
- 明るさの目盛りは「1 天文単位で π」(`SUN_IRRADIANCE_1AU`)で、**太陽へ正対したアルベド A の
  完全拡散面が 1 天文単位で表示値 A になる**ように取ってある。したがってアルベド A の面が
  この光源から受け取る表示値は `A · E_b / SUN_IRRADIANCE_1AU`、そこへ露出係数
  (順応 × 露出補正)が掛かる。
- トーンカーブ(Khronos PBR Neutral、0.08 未満は `x → 6.25x²`)の傾きは全域で 1 以下なので、
  **入力の増分より出力の増分が大きくなることはない。**
- 8bit sRGB の最小段は、暗部で線形 `3.0e-4`(sRGB 符号値 1/255 → 線形 0.000304)。

よって **`A_max = 1` として `E_b · 露出係数 / SUN_IRRADIANCE_1AU < 3.0e-4` を満たす天体は、
画面のどの画素も 1 LSB 動かせない。** これを下回る天体は光源リストから外す。
**閾値を割った瞬間の切り替わりが見えないことが、式そのものから保証される** — ヒステリシスは
要らない。

実際に当ててみると: 低軌道で地球 `E=0.56`、閾値 `9.4e-4` → 採る。同じ場所で月 `E=5.2e-6` →
捨てる。エウロパ軌道で木星 `E=4.4e-4`、閾値 `6.6e-5`(順応 `5.2^1.6 = 14.3` ぶん下がる)→ 採る。
同じ場所でイオ `E=2.5e-6` → 捨てる。**倍率 6.7 倍で残るので、この閾値は空振りしていない。**

**スロットは 2 本。** 閾値を上回る天体が 2 体を超える構図は、低いイオ周回軌道(イオ本体 +
木星)のような場合に限られる。

### D5. 天体照は「位相係数つきの一様球光源」から始める。点光源は書かない

ユーザーの当初案では 5-1 が「位相角付き点光源」だが、**手順 3 で書く一様球の拡散の閉じた解は、
距離が大きくなると逆二乗の点光源へ自動的に縮退する。** 別に点光源の経路を書くと、
低軌道(球)と月軌道(点)の間で式が切り替わり、そこで絵が飛ぶ。**同じ式が両方を覆うので、
点光源のぶんだけコードが減る。**

放射輝度は、遠方で「ランバート球の全放射強度」と一致するように取る:

```text
Φ(α) = [sin α + (π − α) cos α] / π           (位相関数、Φ(0) = 1)
L̄(α) = (2/3) · A · E_b · Φ(α) / π            (球の一様な放射輝度)
E     = π · L̄ · sin²θ · (立体角のクリップ項)   (θ = asin(R/d))
```

`A` はボンドアルベド(色つき)、`E_b` はその天体がいまいる場所で太陽から受けている放射照度、
`α` は天体から見た太陽と受け手のなす角。**遠方では `E → (2/3)·A·E_b·Φ(α)·(R/d)²` になる。**

**既知の偏り: 接触極限(`d → R`)でこの近似は真値の 2/3 になる。** 一様球は、実際には
直下点へ集中している輝度を球面へ均してしまう。低軌道の地球で真値の約 6 割。**これを直すのが
手順 5-3(テクスチャ付きランバート球)であり、それまでは受け入れる。**

### D6. 受け手の BRDF(衝効果)は、当面やらない

**これは「決めないまま先送り」ではなく「やらない」という結論である。**

実在の天体表面は衝効果(opposition surge)を持ち、ボンドアルベドをそのまま拡散反射率に使う
ランバート近似では位相角 0 付近が `(2/3)·q` 倍に暗くなる(エンケラドゥスの幾何アルベドが
1.4 と 1 を超えるのはこれ)。**いまはこれを正しい帰結として受け入れており、アルベドを盛って
埋めない。**

やらない理由は 2 つ。**(a)** ここへ手を付けた時点で「変更はライティングパスに閉じる」が崩れる —
衝効果は視線に依存するので、照度バッファが「どの向きからどれだけ来たか」しか運ばないという
分業が通らなくなり、**恒星の直射だけを別の口で受け手へ渡す**必要が出る。**(b)** この計画の
達成目標のどれも、衝効果を必要としていない。

**やるとしたら、そのときの形は決まっている。** 衝効果の幅(数度)は太陽の視直径(1 天文単位で
0.53°)より一桁広く、天体照(低軌道で 70°)に対しては積分で均されて消える。したがって
**「恒星の直射には衝効果つきの BRDF、面光源にはランバート」**という切り分けが成り立ち、
面光源の LTC 積分はランバートのまま残せる。族としては Oren–Nayar が正しい(マイクロファセットの
影と相互反射から導かれるので、光源方向への持ち上がりと縁の平坦化が同時に出る)が、
衝効果そのもののスパイクまで欲しいなら Hapke の SHOE / CBOE が要る。

**再検討する条件: 満月に近い構図(位相角 5° 以下)で天体が写真より暗いことが、実際に不満に
なったとき。**

## 達成目標

**全手順の実施後、次がすべて満たされていること。**

1. `SHADOW_MIN_SUN` が `src/` から 0 件。
2. `AMBIENT_IRRADIANCE` / `AMBIENT_COLOR` / `AMBIENT_REFERENCE_DISTANCE` /
   `ambientIrradianceAtDistance` が `src/` と `tools/` から 0 件。**値を持つ `THREE.AmbientLight`
   も 0 件**(`environment-scene.ts` の `lightingAnchor` は値を持たない置物なので残る)。
3. 描画設定に「太陽の光源モデル」と「天体照の光源モデル」の 2 項目が独立して並び、
   **どちらを切り替えてもその場で絵が変わり、負荷確認ウィンドウの「ライティング」行の数字が
   動く。** パスの行は増えていない(10 行のまま)。
4. `render-lab` の `albedo` ケース(アルベド 1 の白球を 1 天文単位)の最も明るい画素が
   **全手順を通して sRGB (241, 231, 215) のまま**。`saturn` ケースの環と本体の比が 0.20 のまま。
5. 低軌道で、艦の地球を向いた面と宇宙を向いた面の明るさが桁で違う。
6. 高度を上げると天体照が滑らかに弱まり、**光源リストから落ちる瞬間の画素値の変化が 1 LSB 以下。**
7. 木星圏で艦を照らす木星照が、地球圏の地球照より暗い(距離依存が式に入っている証拠)。
8. 三日月形に見える位置で天体照が弱く、**光の来る向きが偏る**(単なる明るさの位相変調ではない)。
9. デバッグ表示「遮蔽」で真っ黒な画素に、デバッグ表示「拡散反射光」の太陽ぶんが出ていない。
10. 地球が食に入っている間、地球照が弱まる。
11. `npm run typecheck` と `npm run test:physics` が通る。

## 手順

手順 1(影の床を捨てる)は実施済み(commit f61a03c3)。`ship-selfshadow` で自己影の
太陽向き面が下がり(R 29→5 など、暖色の床ぶんが消えた)、`saturn-shadow` の環の影の帯でも
床が消えた。`albedo` は前後で完全一致。本影内の本体表面には描画テスト環境の既定の環境光
(2〜4 LSB)だけが残り、環境光を受けない環との差はその環境光ぶん — 手順 5-1 で消える。

手順 2(ライティング段を光源ごとの描画命令へ割る)は実施済み(commit 22d40d93)。
5 ケースの突き合わせは最大 ±1 LSB(和を fp16 へ丸める回数が 1 回増えたぶんの量子化)で一致。
MRT の加算合成は両添付に効いている(効いていなければ艦の鏡面か夜側が丸ごと崩れる)。
実装上の形: 光源のマテリアルは `material.mrtNode` を持ち、`renderer.setMRT` は使わない
(renderer 側 MRT はブレンド既定が NoBlending になり加算が effかないため)。加算は
`CustomBlending` の One/One(lens-pass.ts と同じ)。`GPU_PASS.lighting` は描画命令ごとに
申告し、計測側が同一パスの複数回ぶんを足し合わせる(行は 1 行のまま)。

手順 3(太陽を一様球光源にし、描画設定へ載せる)は実施済み(commit d0eaa493)。実装で
確定したこと:

- **LTC の 8 角形の巻き方向**: 基底 `(u, v, axis)` 右手系で **φ を負に回す**(受け手から見て
  反時計回り)。逆に巻くと形状係数が地平線上の光源で 0 になり、**鏡面だけが静かに消える**
  (拡散は正常なので気付きにくい。アルベドが黒く鏡面で見えている材質だけが黒へ落ちる)。
  閉じた解・LTC とも CPU の数値積分と突き合わせ済み(真上で F=sin²σ 厳密一致・余弦則一致・
  地平線下 0、クリップ域も 6 桁一致)。
- **albedo 較正**: 拡散は球光源でも厳密一致(全可視の枝が点光源と同じ式)。最も明るい画素は
  (241,231,214)→(240,231,214) と R だけ 1 LSB 下がる — 粗さ 1 の鏡面が GGX→LTC 近似へ
  変わったぶんで、D3(積分器を 1 つにする)の帰結として受け入れた。なお着手前の実測値も
  計画の (241,231,215) ではなく (241,231,214) だった(B の 1 LSB は計画の計算誤差)。
- **metal-highlight**: 「点光源では消える」は曲面では成り立たない(球面上には必ず鏡映点が
  ある)。差はハイライトの大きさに出る(球光源のほうが太陽の円盤ぶん太い)が、露出が飽和する
  構図では面積差 1 割程度に留まる。ケースは曲率のゆるい大鏡 + 0.31 天文単位の構図へ調整した。
- **sun-close の終端**: 明側の半影の減光は出る。終端を越えた先の照り返しは、この構図では
  終端がリムに寄るため画素未満。
- 実機の負荷確認ウィンドウの数字の変化は未確認(render-lab は gpuSupported: false)。
  **実機での確認は残件。**

手順 4(光源リストを選び、環境光の強さを物理式へ差し替える)は実施済み(commit e227a283)。
実装で確定したこと:

- `AMBIENT_*` 一式は `src/` `tools/` から 0 件。`leo` の影の帯は (6,22,42)→(82,87,100) —
  手書きの青い定数が、地球の色つきアルベド由来の明るい照度へ替わった。`outer-*` は
  ケース内の灰色球が光源になり環境光が 0 でなくなった。
- **閾値のつまみ検証は不成立と判明**: 閾値(D4)は game 側 `planet-light.ts` にだけあり、
  描画テスト環境はケースが書いた光源をそのまま流す(ECI を持たないので選定を通らない)。
  outer の灰色球は d≈3R で式の上でも閾値を割らない(割るのは 47,000 天文単位)。閾値の
  1 LSB 保証は式の導出そのもので担保し、**実機での目視は残件**。食の弱まりも同じく
  game 側の経路(`sunlitFactor`)なので lab では見えない — **実機残件**。
- 実写テクスチャ天体の光源色は celestial-textures.ts の `averageHue`(緯度重み付き平均色、
  実測)× ボンドアルベド。地球は EARTH_TEXTURES 側に持つ(雲合成後の実測)。
- **アルベド 1 較正の期待値は sRGB (240, 229, 210) へ更新**(環境光の項が消えたぶん。
  albedo ケースは光源を置かない構図にした — 較正が 1 本の光だけで読める)。
- 天体照は方向を持たないので、**天体が自分の夜側を照らす**(地球の夜側が明るめに出る)。
  5-1 の向きつきの式(cosβ のクリップ)で自然に消える見込み。

手順 5-1(天体照に向きと位相を与える)は実施済み(commit fe547daf)。実装で確定したこと:

- スロット 1 本が LightSource 1 つ(描画命令 1 本)になる形にした。ambient-source.ts は削除。
  点光源近似の GGX は太陽の点光源モードと共有(`lighting/ggx.ts`)。
- 色は `albedoOf()` ではなく新設の `lightSourceAlbedoOf()` — `albedoOf()` は実写テクスチャを
  持つ天体(地球・木星など)を表に持たず既定の灰色を返すため、テクスチャの実測平均色
  (celestial-textures.ts の `averageHue`)× ボンドアルベドで補った。
- 検証: earthshine の天体照だけで照らされる画素は「なし」トグルで (48,56,73)→(0,0,1)

### 手順 5-2. 天体照を、位相角に応じた等価円盤の LTC へ上げる

**目的.** 一様球では表せない「光っているのは球面の一部だけ」を、**位相角に応じて位置と面積が
ずれる等価な円盤**で表す。**5-1 では出ない「光の来る向きの偏り」がここで出る。**

**等価円盤の定義**(これが `pipeline.md` から引き継いだ「等価な円盤の意味が取れていない」への
答えである):

- 受け手の点から見て、天体は半頂角 `θ = asin(R/d)` の錐を張る。そのうち**照らされている部分**
  (終端線で切られた月형の領域)を 1 枚の円盤で代表する。
- **円盤の向き**: 受け手から、照らされた領域の**測光重心**へ向かう向き。重心は天体中心から
  太陽直下点の側へ `c(α)·R` だけずれる。`c(α)` はランバート球の輝度分布の一次モーメントで、
  **起動時に一度だけ数値積分して 33 段の表にする**(`render/blackbody.ts` がプランクの式 ×
  等色関数を起動時に積分して 256 段の表を組むのと同じ形)。
- **円盤の面積**: 見かけの円盤の面積 × `(1 + cos α)/2`(照らされた部分の投影面積比)。
- **放射輝度**: 全放射強度 `(2/3)·A·E_b·R²·Φ(α)` をその円盤の立体角で割ったもの。
  **こう取れば、5-1 の一様球と全放射照度が一致する** — 変わるのは向きと広がりだけで、
  明るさの総量は変わらない。
- 円盤は**面積を合わせた 8 角形**として手順 3 の LTC 積分へ渡す(4 角形では視半径 70° の
  低軌道で形が足りない)。

**これは一様球ではないので LTC の標準的な適用範囲の外にある。** 承知の上で採る近似であり、
**`crescent` ケースでの妥当性の確認が必須。**

**変更が必要な箇所.**

| ファイル | 何をするか |
| --- | --- |
| `src/render/pipeline/lighting/lambert-phase-table.ts`(新規) | `Φ(α)` と重心オフセット `c(α)` の 33 段の表を起動時に組む。`render/blackbody.ts` の表の組み方に揃える |
| `src/render/pipeline/lighting/planet-light-source.ts` | 上の等価円盤を組み、手順 3 の LTC 積分へ渡すモードを足す |
| `src/render/graphics-settings.ts` | `planetLightModel` へ `[2,'等価円盤']` を足す。プリセットは high=2 |
| `tools/render-lab/cases.ts` | `crescent` を位相角違い(30° / 90° / 150°)で 3 本に増やす |

**達成条件と検証.**

- `npm run typecheck` が通る。
- `npm run render-lab:shot` の `crescent-*`。
  - **「球光源」と「等価円盤」で、艦の面ごとの明るさの比が変わる**(総量は変わらない)。
    位相角 150° では、太陽側の縁を向いた面だけが明るい。
  - 位相角 0° の極限(`earthshine`)では両モードの絵が一致する(`c(0) = 0`、
    `(1 + cos 0)/2 = 1` なので式が同じものへ落ちる)。**一致しなければ実装が間違っている。**
- 実機で「等価円盤」を選ぶと「ライティング」の数字が上がる。

## 参考: なぜ「大きさを持つ光源」が要るのか

| 光源 | 視点 | 視半径 | 立体角 | 全天比 |
|---|---|---|---|---|
| 太陽 | 1 天文単位 | 0.266° | 6.8e-5 sr | 5.4e-6 |
| 太陽 | 水星近日点 0.31 天文単位 | 0.86° | 7.1e-4 sr | 5.6e-5 |
| 地球 | 低軌道 420 km | **70.0°** | **3.90 sr** | **31%** |
| 地球 | 静止軌道 | 8.6° | 0.071 sr | 0.56% |
| 地球 | 月軌道 | 0.95° | 8.6e-4 sr | 0.007% |
| 木星 | エウロパ軌道 | 11.5° | 0.126 sr | 1.0% |

**同じ地球が低軌道では全天の 31% を占め、月軌道では点光源と区別がつかない。** 近距離用と
遠距離用に別モデルを持つのではなく、**距離とともに連続に縮退する 1 つのモデル**でなければ、
遷移する場所で絵が飛ぶ(D5)。

**アルベドの出典に注意する。** レジストリの 101 天体すべてにボンドアルベドが入っているが、
幾何アルベドしか公表の無い天体は H–G 系の位相積分 `q = 0.290 + 0.684 G` で直したもので、
11 体は分類の代表値(`render/celestial-albedo.ts` に「分類既定」と明記)。
**天体を光源にすると、この値がそのまま光源の強度になる。**

**天体照の遮蔽(天体照が艦の構造で遮られること)はここでは扱わない。**
[`screenspace.md`](screenspace.md) が引き取る。
