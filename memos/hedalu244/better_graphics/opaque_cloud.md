# 不透明雲表現 — 積雲を G バッファと遮蔽へ立てる(計画)

**積雲を、地表アルベドへの焼き込みから、G バッファへ深度を書く不透明メッシュと遮蔽関数の源へ
移す。新規実装。** 相方は [`translucent_cloud.md`](translucent_cloud.md)(巻雲と積雲の中間調を
大気パスのミー散乱で描く改造)。**着手はこちらが先** — 視覚効果が最大で、相方の手順 2(積雲の
低層ミー)がこの計画の手順 1 の完了を前提にする。

**前提のパイプラインは [`pipeline.md`](pipeline.md) が持つ。** 光を受ける不透明メッシュを描く
パスは G バッファパス 1 本(マテリアルパスは全画面板ポリでの合成)で、G バッファが素材の全情報
(法線・粗さ・ベース色・金属度・自己発光)を画面サイズで持つ。**手順 3 の視差レイマーチが走るのも
そこ 1 回だけで、「両パスで同じ深度が書けるか」の整合は問題にならない。**

## 呼称

| 呼称 | 意味 |
|---|---|
| **積雲** | 場の R(被覆率)+ G(雲頂高度)が表す雲塊(積雲〜積乱雲、層積雲の板。台風の眼壁・螺旋帯も)。旧称: 不透明雲・厚い雲 |
| **巻雲** | 場の B(鉛直光学的厚み τ)が表す上層の薄い雲。旧称: 半透明雲・薄い雲 |
| **不透明雲表現** | 積雲の不透明部分を G バッファ + 遮蔽で描く(この計画) |
| **半透明雲表現** | 巻雲と積雲の中間調を大気パスのミー散乱で描く(相方の計画) |

## 目的

いまの積雲は `celestial-surface.ts:63-67` の `cloudOpacityAt` が地表アルベドへ焼き込む、高さの
無い板 1 枚で、影は u 方向へ 0.001 ずらすだけの固定近似(同 :21-23, 131-134)。
`DEVELOP/SPEC/RENDERING.md` が要求する挙動のうち、立体感(:355-357)・積雲の粒(:368)・
太陽高度で伸びる影(:408-409)・艦との前後関係が出ず、大気との一体(:405-407)は焼き込み任せ。

この計画で、積雲を **G バッファへ深度を書く不透明メッシュ(殻 → 視差レイマーチ)** と
**遮蔽関数の源** へ移す。深度が書かれた瞬間に、大気の霞み(大気パスは G バッファ深度で区間を
切って「下地 × 透過率 + 内部散乱」を解く)・艦との前後・影の受け手化が追加の仕組みなしに揃う。

**不透明を Lambert で描くのは物理の側から立つ。** 厚い雲の白さは多重散乱の産物で、単散乱
アルベド ≈ 1・τ→∞ の層の反射輝度は位相関数に比例し、HG(g ≈ 0.8)は後方(太陽を背に見下ろす
構図)で 0.1 以下 — 単散乱に濃いミーを置いても灰色にしかならない。Lambert(アルベド 0.7〜0.9)は
厚い雲にとって「粗い近似」ではなく「多重散乱の極限」に近く、**大気散乱シミュレーションでは
実現できない見えをここが担う。** これが相方より優先度が高い理由。

**SPEC の差分は無い。** 巻雲・積雲の名指し(RENDERING.md:350-352)を含め挙動は既に規定されて
おり、この計画は実現する側。

### 入力の契約(場)

- `src/assets/cloud-field.png` — 実写 8k_clouds を推定分離した仮テクスチャ。正距円筒
  4096×2048・8bit RGB(赤道 9.8 km/texel)、v = 0 が北。R = 積雲被覆率 0..1、
  G = 雲頂高度 0..1(= 0..15000 m。8bit なので 59 m 刻み)、B = 巻雲 τ 0..1。
  再生成は `npm run cloud-lab:separate`。
- **被覆率は中間調を持つ。** 生成側(`src/render/cloud/condensation.ts:47` の
  smoothstep(0.62, 0.80, …))も分離側(`tools/cloud-lab/separation-pipeline.ts:328-332`、
  clamp のみ)も二値化していない。場の契約は「階調は光学的厚みではなく被覆率で持つ。texel より
  細かい縁と二値化は描画側の担当」。
- **いまの場の実測値**(`src/assets/cloud-field.png`、緯度余弦で重み付けた面積平均):
  被覆率の平均 0.1253(R < 0.05 が面積の 51%)、薄い雲まで合成した地表の平均輝度 0.2457。
  飽和帯 0.25..0.45 は「二値化が被覆率の平均を動かさない」条件から選び、覆われずに残る地表の
  平均輝度 0.1937・殻が覆う 0.1274 から `albedoScale = 1.0536` が出る。**場を差し替えたら
  この 4 つを測り直す。**
- 将来、生成側の場(全球 39.1 km/texel + cap 8.5 km/texel)へ差し替える。チャンネルの並びは
  同じなので読む側は動かない想定。**G(雲頂)の読み手はこの計画が最初。**
- 配信サイズ +10.9 MB(8k_clouds.jpg 2.78 MB → cloud-field.png 13.6 MB)は生成側・軽量化側の
  残件で、この計画では扱わない。

### 崩せない制約

| 制約 | この計画への効き方 |
|---|---|
| パスの本数と並びは変えない。触るのは各パスの中身だけ | 「雲パス」は作らない。雲は `LIT_OPAQUE_LAYER` のメッシュとして G バッファパスへ乗せる — 再構成後、不透明メッシュを描くパスはここだけ |
| 深度は G バッファ 1 枚。反転 Z(near = 1, far = 0)・32bit float。「画素ごとの位置復元の器」 | 視差レイマーチの深度書きも反転 Z のまま。G バッファは **samples 0**(MSAA は再構成で廃止済み)。マテリアルパスの板ポリがこの深度を共有ターゲットへ複製するので、雲の深度は world パスの前後判定へも追加の仕組みなしに届く |
| 遮蔽の入口は `SunOcclusion.transmittance()` 1 本、合成は透過率の積 | 雲影は 4 つ目の源として足す。`SUN_SHADOW_CASTER_LAYER` には入れない — 天体球と同じく解析源との二重計上になる |
| 明るさの目盛り(1 AU で π、表示値 = アルベド)。手置きの明るさ禁止 | 雲は標準マテリアルの白アルベドで描き、明るさは光源列から出る。銀縁などを足すなら放射量から導ける形(縁の透過を τ から解析で出して Lambert へ足す)に限る |
| 太陽系全域で破綻しない | 遠景では粒が 1 px を切って消え、mipmap 平均の分布だけが残る形へ跳ばず退化する |

## 決めたこと

覆すならどの手順が変わるかを併記する。

1. **中間調の扱いは「上下に飽和 + 残った中間調をディザ」を既定にする。** G バッファには不透明
   しか載らないので二値化は避けられない。飽和の閾値は手順 1 の実験で決め、相方の低層ミーが
   入ったら飽和下限を上げて中間調を靄側へ譲る調整余地を残す。→ 覆すと手順 1 の discard 式だけ。
2. **ディザは `BlueNoise.atScreenPixel()`(画面固定・時間不変)の自前 discard を第一候補に
   する。** three の `alphaHash` は閾値を `positionLocal` から引き(雲に張り付くが)、リポジトリの
   「動くノイズは静止画でちらつく」作法と別系統。src に `alphaHash` の使用例は無い。手順 1 で
   両方を並べて決める。→ 覆すと手順 1 のみ。
3. **殻は `CelestialSurface` と別クラス(新規 `src/render/cumulus-shell.ts`)。**
   `CelestialSurface` は 1 マテリアル + 単一メッシュ集合の前提(`syncLod`/`hide`/`dispose`)で、
   第 2 集合を押し込むより並べるほうが素直。LOD は `screen-lod.ts` の `SPHERE_LOD_LADDER` と
   共有単位球を流用する。→ 覆す(統合する)と手順 1 のファイル表と手順 3 の置き場。
4. **大気の中から雲を見る場面(再突入終盤・着陸)は要件に入れない。** 入れるなら殻の間を実際に
   レイマーチするボリューム(64 段 × 光路 6 段で 1080p ≈ 4 ms 級)+ 時間的再投影が要り、規模が
   1 桁変わる。SPEC の未確定の案(RENDERING.md:508)のまま置く。→ 覆すとこの計画全体が別物。
5. **負荷の合格線は、雲の描画全体(相方との合計)で +1.0 ms(高設定)。** 大気 1.5 ms との
   釣り合いから置いた値で、実測が出たら見直す。→ 覆すと達成目標 6 と各手順の検証値。
6. **他天体には載せない(地球のみ)。** ただし読み口は場の契約だけに依存させ、天体固有の定数を
   埋め込まない。→ 覆すと earth-system 相当の供給行が増えるだけ。
7. **着手はパイプライン再構成の完了後。** 再構成が、不透明メッシュを描くパスを G バッファ 1 本へ
   まとめ、G バッファへベース色・金属度・自己発光を載せ、MSAA を廃す。→ 覆す(再構成を待たずに
   着手する)と、手順 3 の見積りが倍になり、「2 パスで同じ深度が書けるか」の確認と、書けなかった
   ときの変位メッシュへの切替判断が手順 3 へ戻る。

## 達成目標

1. `celestial-surface.ts` の焼き込み合成から R(被覆率)の項が消える — 読むのは B のみ
   (相方も完了していれば `cloudOpacityAt` ごと消える)。
2. `CLOUD_SHADOW_OFFSET_U` が `src/` から 0 件になる(grep)。
3. デバッグ表示「深度」で、雲のシルエットが G バッファ深度に出る。
4. render-lab の斜視構図(手順 3 で新設)で積雲の塔の側面と雲頂の起伏が写り、
   `earth-terminator` で雲影が昼夜境界へ近いほど長く伸びる。
5. 粒(detail)が場の texel(赤道 9.8 km)より細かく出て、遠景では 1 px を切って消える。
6. F3 の増分が「G バッファ + 遮蔽」合計で +1.0 ms 以内(高設定、雲が画面を覆う構図)。
   マテリアルパスは板ポリ 1 枚なので、雲の有無では動かない。
7. `npm run typecheck`・`npm run test:render`・`npm run test:game` が通る。
8. albedoScale 再較正後、ヘッドレス本番ビルド(creative ステージ)の地球矩形平均輝度が移行前と

## 手順

### 手順 3. 視差レイマーチで雲頂の起伏を立てる

**目的**: 殻を最大雲頂(15 km)に置いたまま、画素ごとに視線を高さ場(G)へ下ろして交点を探し
(8〜16 タップ)、交点の深度を `depthNode` で書き、法線を高さ場の勾配から出す。塔の側面・斜視の
視差・水平線のシルエットが出る。雲に当たらない視線は discard され、奥の地表が見える。

**最初に確かめること**: メッシュのマテリアルで画素ごとの深度を書く前例がリポジトリに無い
(`depthNode` の既存例はいずれもフルスクリーン quad の深度複製:`render-pipeline.ts:248`・
`overlay-pass.ts:60`・再構成後のマテリアルパスの板ポリ)。three r185 では `material.depthNode` が
MRT より優先され(`NodeMaterial.js` の setupDepth。G バッファの MRT に `depth` キーは無いので、
再構成でベース色などが増えたあとも競合しない)道はあるはずだが、**G バッファパスで反転 Z の
規約のまま深度が書けることを最初に確かめる。** 書けなければ射影格子の変位メッシュ(画面格子
256² ≈ 6.5 万頂点を殻へ射影し高さ場で変位、ディザで穴)へ切り替え、この手順を書き直す。

**確かめるのは 1 パスぶんでよい** — 再構成でメッシュを描くパスが G バッファ 1 本になり、
マテリアルパスの板ポリはその深度を読んで複製するので、2 パスで同じ深度を書き合わせる必要が無い。

**変更が必要な箇所**

| ファイル | 何をするか |
|---|---|
| `src/render/cumulus-shell.ts` | レイマーチ本体(8〜16 タップ)、`depthNode`、勾配法線。手順 1 の一枚板 discard を置換 |
| `tools/render-lab/cases.ts` | 斜視構図 `earth-oblique` を追加(:625-629 `earthCenterBelowHorizon` の margin を振るだけ。関数 1 つ + `CASES` へ 1 行) |

**達成条件と検証**
- `npm run typecheck`・`npm run test:render`。
- `npm run render-lab` の `earth-oblique`: 塔の側面が見える。デバッグ表示「深度」で雲の
  シルエットが地表と別の値で出る。
- 実機で艦を雲の高度へ置き、前後関係が正しい。
- F3「G バッファ」増分が手順 1 比 +0.6 ms 以内(レイマーチはこのパスでだけ走る)。

### 手順 4. 高周波 detail を足す

**目的**: 場の texel(赤道 9.8 km)より細かい粒(実際の積雲の粒は 1〜2 km)と雲頂の起伏を、
天体固定の 3D ノイズで足す。占有判定を「被覆率 − detail > 0」へ、雲頂高度を同じ detail で変調へ。
粒は場の解像度に依らないので、遠景でも同じ細かさで残り、1 px を切って消える(跳ばない)。

**高周波を生成側と描画側のどちらが担うかは未決**(生成側がどこまで高解像になるか不明)。ただし
**雲頂より下の形状は場が何も教えてくれない**(雲頂場は頂の高さだけを持つ)ので、レイマーチの
側面が柱状にならないための detail は、生成側の解像度に依らずこの手順が持つ。生成側が高周波を
持ったら、占有側の detail の振幅(定数 1 つ)を縮めて譲れる形にしておく。

**変更が必要な箇所**

| ファイル | 何をするか |
|---|---|
| `src/render/cumulus-shell.ts` | detail 項の追加(占有・雲頂変調・ディザ閾値との合成)。texel 角で段を落とす作法は `circulating-noise.ts:12-26` に倣う |
| `src/render/cloud/gradient-noise.ts` | 流用(リポジトリの 3D ノイズはこれだけ)。変更は要っても公開範囲の調整程度 |
| `src/game/celestial/celestial-entity/point-entity.ts` | 粒を帯の流れに乗せる(`Circulation.carry`、`circulation.ts:105`)なら `syncTime` の配線が要る — `Circulation` は現状 cloud-lab でしか生成されておらず、ゲーム本体への初導入になる。乗せない(静止した粒)ならこの行は不要 |

**達成条件と検証**
- `npm run typecheck`・`npm run test:render`(point-entity を触れば `npm run test:game` も)。
- `npm run render-lab` の `earth-oblique`: 粒が場の texel より細かく、雲頂の頭がでこぼこで、
  シルエットと影の両方に出る。
- 引きの構図(`earth`)で粒が消えても分布の見えが跳ばない。
- F3 増分が手順 3 比 +0.2 ms 以内。

## 採らない案(再提案しないため)

| 案 | 却下理由 |
|---|---|
