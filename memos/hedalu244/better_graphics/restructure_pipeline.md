# パイプライン再構成 — G バッファへ素材を載せ、マテリアルパスを板ポリ合成にする(計画)

**G バッファを「深度・法線・粗さ」から「素材の全情報(+ベース色・金属度・自己発光)」へ拡張し、
マテリアルパスを全メッシュの再描画から全画面板ポリ 1 枚の合成へ置き換え、MSAA を廃止する。**
[`opaque_cloud.md`](opaque_cloud.md)(不透明雲)の前段 — この再構成が入ると、雲の視差レイマーチは
G バッファパスの 1 回で済む。大気パス以降(大気・world・レンズ・合成・3D UI・AA)は触らないので
[`translucent_cloud.md`](translucent_cloud.md) は影響を受けない。

## 目的

いまのパイプラインは、光を受ける不透明メッシュ(LIT_OPAQUE_LAYER)を毎フレーム 2 回
ラスタライズしている。G バッファ(`gbuffer.ts:83-98`)が深度・法線・粗さを描き、マテリアルパス
(`material-pass.ts:93-110`)が**同じ全メッシュをもう一度描いて**、そのとき初めて素材
(アルベド・金属度・自己発光)を得て照度と掛け合わせる。素材が G バッファに無いことだけが
2 回目の描画の理由で、頂点変換・ラスタライズ・マテリアルグラフの評価が丸ごと重複している。

この形は、画素ごとに重いマテリアルで倍払いになる。不透明雲の視差レイマーチ(8〜16 タップ)は
G パスとマテリアルパスの両方で走り、さらに「両パスで同じ深度が書けるか」という整合の確認まで
背負う(opaque_cloud.md 手順 3 の冒頭がそれ)。

再構成後は:

- **G バッファ** が素材の全情報をスクリーンサイズで書き出す(MRT 4 枚 + 深度、samples 0 のまま)。
  メッシュを描くパスはここだけになり、素材は画素ごとに一度だけ確定する。
- **マテリアルパス** は「星野(背景メッシュ)+ 全画面板ポリ 1 枚」になる。板ポリは照度 2 枚と
  G バッファの素材を掛けて最終陰影を出し、G バッファ深度を共有ターゲットへ複製する
  (world パスの透明物が深度テストへ使う — この責務は従来どおりマテリアルパスが持つ)。
- **MSAA は設定項目ごと廃止。** G バッファが samples 0 である以上(境界の法線を平均すると
  どちらの面でもない向きになる)、遮蔽・照度・大気は既に縁の中間調を持てない。板ポリ化で
  マテリアルパスの縁も消えると、MSAA の効き先は world パスの透明物(噴射炎・ビルボード)の縁
  だけになり、HDR ターゲット 4 標本ぶんのメモリ・帯域に見合わない。縁は最終段 AA(FXAA/SMAA)と
  解像度倍率が担う。

## 決めたこと

覆すならどの手順が変わるかを併記する。

1. **チャンネル構成は「法線 RG16F(現行)/ 粗さ R8(現行のまま)/ ベース色+金属度 RGBA8
   (rgb=ベース色、a=金属度)/ 自己発光 RGBA16F」の 4 枚 MRT。** 金属度をベース色の α へ
   載せるのは、合成式が両者を常に同時に読むことと、粗さの既存読者(`shading-sample.ts`・
   デバッグ表示)を一切触らずに済むため。WebGPU の attachment 数上限 8・合計バイト上限
   maxColorAttachmentBytesPerSample = 32 B(既定)に対し、この構成は 4 枚 ≈ 24 B
   (制限の数え方では rgba8unorm が 8 B と数えられる)で収まり、将来の残り枠は 8 B。
   → 覆す(金属度を別枚・RG8 詰めなど)と手順 2 のフォーマットと手順 4 の読み口だけ。
2. **ベース色は線形 8bit で始める。** 暗部のバンディングが見えたときだけ -srgb 符号化か
   R10G10B10A2 へ切り替える(表示変換の二重掛かりの罠は `render-pipeline.ts:158-160` の
   コメントが前例)。→ 覆すと手順 2 の 1 行。
3. **自己発光は RGBA16F。** 現行でも自己発光は共有 HDR ターゲット(RGBA16F)へ出ているので、
   半精度で表現域の後退は無い。RG11B10 は機能フラグ依存のため採らない。→ 覆すと手順 2 の 1 行。
4. **照度プリパスへ畳んで 1 パス化はしない**(照度プリパスが直接最終陰影を出す形にしない)。
   拡散/鏡面のデバッグ表示と、「光源 1 つ = 全画面 1 枚の加算」という器(`light-prepass.ts`)を
   保つため。→ 覆すと手順 4 が light-prepass の書き換えへ変わり、拡散/鏡面のデバッグ表示を失う。
5. **星野は従来どおりマテリアルパスの先頭にメッシュで描き、板ポリは far(深度クリア値 0)の
   画素を discard して星野を残す。** 星野は depthWrite/depthTest とも false
   (`stars.ts:33-41`)なので、板ポリが書く深度と干渉しない。→ 覆す(板ポリの後に深度テストで
   描く)と material-pass 内の順序 1 箇所。
6. **MSAA 廃止(手順 3)を板ポリ化(手順 4)より先に置く。** 板ポリ化の commit を
   「絵が変わらないはず」の前後比較(縁込み)で検証できるようにするため。→ 覆す(順を入れ替える)
   と手順 4 の検証が縁を除外した比較になるだけ。
7. **デバッグ表示へ 3 種(ベース色・金属度・自己発光)を足す。** 手順 2 の検証手段を兼ねる。
   → 覆すと手順 1 の SPEC 差分と手順 2 の表から該当行が消え、手順 2 の検証を撮影比較で代替する。

## 達成目標

1. 光を受ける不透明メッシュのラスタライズがフレームあたり 1 回(G バッファパスのみ)になる —
   `material-pass.ts` から `scene.traverse` と LIT_OPAQUE_LAYER の描画が消える。
2. grep `msaa` が `src/`・`tools/` の `.ts` から 0 件になる。
3. デバッグ表示「ベース色」「金属度」「自己発光」に中身が写る。
4. 再構成の前後で絵が変わらない: ヘッドレス本番ビルド(creative ステージ)の地球矩形平均輝度が
   ±数 %、render-lab 主要ケース(earth・基地・艦)の目視が一致。縁の中間調が消えるのは
   手順 3 の意図した差で、これだけは除く。
5. F3 の「G バッファ」+「マテリアル」の合計が再構成前と同水準(+0.2 ms 以内)。
6. `npm run typecheck`・`npm run test:render` が通る。
7. (帰結の確認)メッシュを描くパスが G バッファだけになり、opaque_cloud 手順 3 の
   「2 パスで同じ深度を書けるかの確認」が不要になる。

## 実測

**手順 4 の実測**(同上):「マテリアル」が earth 0.502→0.168 ms・ship-cluster 0.272→0.130 ms・
ship-crowd 0.442→0.139 ms で、構図のメッシュ数に依らずほぼ一定になった。「G バッファ」+
「マテリアル」の合計は再構成前(手順 2 以前)の earth 1.198 / ship-cluster 0.446 /
ship-crowd 0.711 ms に対して 0.768 / 0.319 / 0.401 ms。CPU 側の render も ship-crowd で
13.8→11.8 ms。絵は render-lab の全ケースで平均輝度が ±0.11 % 以内、画素差はほぼ全て 0〜1 LSB
(ベース色 8bit の量子化)で、8 LSB を超えるのはケースあたり 20 画素未満の z ファイト境界のみ。

**手順 3 の実測**(同上):「マテリアル」が earth −0.234 ms・ship-cluster −0.069 ms・
ship-crowd −0.085 ms。「ワールド」は変わらず(±0.001 ms)。絵の差は縁だけで、画素が変わったのは
全体の 0.3〜3.4 %、平均輝度の変化は −1.5 % 以内。

**手順 2 の実測**(render-lab 960x540 / p50、`window.renderLab.measure`):「G バッファ」が
earth +0.156 ms・ship-cluster +0.072 ms・ship-crowd +0.077 ms(いずれも達成条件の +0.2 ms 以内)。
「マテリアル」は ±0.01 ms で変わらず、通常表示は before と画素単位で一致した。

実装規模: `gbuffer.ts` +30 行 / `render-pipeline.ts` ±20 行 / `material-pass.ts` 書き換え
(−60/+40 行)/ `graphics-settings.ts` −5 行 / `debug-target.ts` +4 行 / `lab.ts` −1 語 /
`RENDERING.md` ±20 行。

## リスクと落とし穴

| リスク | 影響 | 露見する場所 |
|---|---|---|
| MRT 置換で `emissive` / `diffuseColor` に値が入らない(three のバージョン差で setup 中の代入が出力へ乗らない) | ベース色・自己発光が黒のまま手順 4 で絵が壊れる | 手順 2 のデバッグ表示(基地の窓明かり)。入らなければ mrt ノードへ直接結ぶ形へ切替 |
| MRT 合計が maxColorAttachmentBytesPerSample(既定 32 B)を超える | 起動時に WebGPU validation error | 手順 2 の起動。現構成 ≈24 B で収まる(決めたこと 1)。将来の残り枠 8 B |
| ベース色 8bit 線形の暗部バンディング | 暗い艦体・夜側に段 | 手順 4、render-lab 目視。対策は決めたこと 2(-srgb 符号化の二重変換の罠に注意) |
| 板ポリの far 判定(深度クリア値 0)を誤る | 星空が消える/全面星空になる | 手順 4、目視で即発覚 |
| 板ポリの depthWrite 漏れ / depthNode 結び忘れ | world パスの透明物が自艦を貫く | 手順 4、実機の噴射炎 |
| autoClear・クリア色の状態リーク | 以降のパスの絵が壊れる | 手順 4(退避/復帰の作法は `light-prepass.ts:57-76` に倣う) |
| 合成式が three 内部とずれる(1/π の落とし・max(0) 抜け・F0 0.04 の取り違え) | 全体が π 倍明るい/金属の色ずれ | 手順 4、平均輝度の前後比較と金属艦体の目視 |
| `render-lab:shot` はテクスチャ読み込みを待たない/memos の baseline.json を書き換える | 単色撮影を「壊れた」と誤認・commit 汚染 | 全手順。目視は対話 render-lab、撮影後に作業ツリー確認 |
| ヘッドレス比較の実行ごとの揺れ(±200 LSB 級) | 一致判定の誤り | 手順 4。画素差ではなく地球矩形の平均輝度で見る |
