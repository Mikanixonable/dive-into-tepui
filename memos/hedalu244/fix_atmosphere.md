# 大気を天体のパラメータにし、焼失と衝突を分ける

## この計画の前提

- **`Asteroid` 型(`GameEntity` の派生クラス)は廃止予定であり、この計画に着手する時点では
  既に存在しない。** 本文書では `Asteroid` を扱わない。
- 着手時点で、天体接触の判定は `ContactPhysics` / `GameEntity.checkLoss` / `PredictedArc.checkImpact`
  の3箇所に分かれたままでよい。**この計画は判定箇所の統合をしない** — 焼失と衝突を「別の現象」
  として分けるところまでを担う。

---

# 1. 目的

## 1-1. 大気が地球にハードコードされている

`physics/atmosphere.ts` は大気を地球のものとして固定している。

| 箇所 | 地球への固定 |
|---|---|
| `burnUpBody` | `if (body.id !== 'earth') continue;` — id 文字列で地球以外を弾く |
| `atmosphericDensity` | Vallado の地球テーブル(0〜1000 km)をモジュール定数として持つ |
| `dragAccel` | `len(r) - R_EARTH` — **ECI 原点からの距離**から地球平均半径を引く |
| `airspeed` | `EARTH_OMEGA` を Y 軸まわりに適用。同じく ECI 原点前提 |
| `player/thermal.ts` | `atmosphericDensity(len(r) - R_EARTH)` と `airspeed(r, v)` を同じ前提で呼ぶ |
| `player.ts` の高度警報 | `earthAltitudeOf(this.state.r)` |

**大気の有無と厚みは天体ごとの固有パラメータであるべきで、定数であってはならない。**
既定レジストリでは地球が ECI 原点に静止しているのでこの前提は成り立っているが、それは偶然で
あって設計ではない。帰結が 1-5 の B。

## 1-2. 焼失と衝突が同じ「margin」に混ざっている

**この2つは別の現象である。**

| | 焼失 | 衝突 |
|---|---|---|
| 何が起きているか | 大気を持つ天体の大気圏に入り、加熱と動圧に耐えられなくなる | どんな天体にもある固体表面への剛体接触 |
| 事象の性質 | **連続量による状態**(濃い空気の中にいる) | **離散的な事象**(表面に触れた瞬間) |
| 相手 | 大気を持つ天体だけ | 全天体 |
| 将来 | 熱シミュレーションによる精緻化 | 相対速度による着陸の成立 |

いま両方が `checkLoss` の中で `margin` という同じ形の数値として並んでおり、**どちらの現象なのかが
コードから読めない**。余裕(margin)の値は種別ごとにばらばらで、根拠も揃っていない。

| 書かれている場所 | 地表到達の margin | 大気での焼失の margin |
|---|---|---|
| `GameEntity.checkLoss`(基底) | 0 | `DEBRIS_REENTRY_ALT` = 95 km |
| `Player.checkLoss` | `PLAYER_MIN_ALT` = 45 km | `PLAYER_MIN_ALT` = 45 km |
| `Enemy.checkLoss` | 無し | `REENTRY_ALT` = 80 km |
| `Bullet.checkLoss` | 0(点判定) | `DEBRIS_REENTRY_ALT` = 95 km |
| `PredictedArc.checkImpact` | 0 | `REENTRY_ALT` = 80 km(持ち主に依らず) |

## 1-3. 焼失の判定は3階層あるべきで、いまは混ざっている

大気による喪失を判定できる精度は、その主体が何を運んでいるかで決まる。

| 主体 | 運んでいるもの | 焼失を判定できる形 |
|---|---|---|
| **自機の実体** | 外殻温度の蓄積・動圧(`ThermalSystem`) | **熱・動圧の物理モデル**。加熱・空力破壊・排熱不全を区別できる |
| **熱シミュを持たない種別の実体**(敵・破片・薬莢・弾・基地・弾薬) | 位置と速度だけ | **大気密度の閾値**という粗い近似 |
| **弧(`PredictedArc`)** | 位置と速度だけ。**姿勢も熱の蓄積状態も運ばない** | **判定しない** |

現状はこの3階層が守られていない。

- **自機の実体が二重に判定している。** `ThermalSystem` の熱・動圧と、`PLAYER_MIN_ALT` の高度
  マージンが並んでいる。同じ現象を、精緻なモデルとその粗い近似が隣り合わせで見ている。
- **弧が焼失を判定している。** 弧は熱シミュレーションを原理的に再現できないので、その判定は
  「実体の喪失点を当てているつもりの、当たらない近似」でしかない。

### 決定: 弧は大気による打ち切りを持たない

**弧が答えるのは「この自由落下の経路が固体表面へ到達するか」だけにする。** 大気を持つ天体に
対しても再突入判定をせず、衝突だけを判定する。

理由:

- 弧は熱の蓄積状態を運んでいないので、実体の喪失点を原理的に当てられない。当てられない量を
  近似で埋めると、**近似の値を実体側と揃え続ける保守が発生する**(現状 `REENTRY_ALT` が持ち主に
  依らず使われているのが、まさにその保守が破綻した形)。
- 後から熱を拡充するとき、**弧に足すべきものが「熱の運搬」1つだけになる**。近似の打ち切りが
  先に入っていると、それを剥がす作業が先に要る。
- `PredictedArc` のコンストラクタが増えず、`burnUpBody` の import も消える。

**受け入れる帰結**(2つとも意図したもの):

- **弧は自機の実際の喪失点より先まで伸びる。** 自機は熱・動圧で先に失われるが、弧は地表まで届く。
  計画軌道の ✕ アイコンは「この軌道が地表へ到達する点」を指すようになる — **喪失点ではない。**
  自機の焼失は HUD の温度・動圧ゲージと警告が別途知らせている。
- **弧が初めて濃い大気の中を積分する。** 現状は 80 km で打ち切られるので、そこから下を弧が
  歩いたことがない。刻みは実シミュレーションと同じ 1 s(`REENTRY_SUBSTEP_MAX_DT`)なので
  実シミュレーションと同じ精度だが、**歩数が増える**(6-4)。

## 1-4. 大気モデルの形 — 密度テーブルは保つ

**「密度を1つのパラメータと閉じた指数式で表す」形は採らない。物理的に成り立たないため。**

密度が指数的に減るのは、等温の層に限って `ρ = ρ₀·exp(-h/H)`、`H = R*T/(M·g)` が成り立つから
であって、**H は温度と平均分子量に比例する**。地球大気の温度は高度に対して単調でなく、
圏界面ごとに勾配が反転する — この直感は正しく、そして**それがこの案を棄却する理由そのもの**。

現行テーブルの H(第3列)を温度から検算すると、完全に一致する:

| 層 | 標準大気の温度 | `0.02927·T` [km] | テーブルの H [km] |
|---|---|---|---|
| 対流圏界面(11〜20 km) | 216.65 K | 6.34 | **6.349**(25 km 行) |
| 成層圏界面(47〜51 km) | 270.65 K | 7.92 | **8.382**(50 km 行) |
| 中間圏界面(86〜91 km) | 186.87 K | 5.47 | **5.382**(90 km 行) |
| 熱圏上部(1000 km) | ≈1000 K・M≈1〜4(H/He へ組成分離) | 100〜400 | **268**(1000 km 行) |

**H は 5.382 〜 268 km(50 倍)を動き、しかも単調でない** — 90 km で最小を取り、その上下で増える。
単一の指数では表せない。実際に H = 7.249 の単一指数を当てると:

| 高度 | 単一指数 / テーブル |
|---|---|
| 0〜80 km | 1.0〜1.2 倍(**この範囲だけなら使える**) |
| 100 km | 2.4 倍 |
| 120 km | 3.3 倍 |
| 200 km | 4.6e-3 倍 |
| 400 km | 3.6e-13 倍 |
| 800 km | 1.2e-34 倍 |

LEO の軌道減衰が**完全に消える**。棄却する。

**他天体を足しやすくする方向としては、テーブルのままで足りる。** 区分指数(層ごとの ρ₀ と H)は
惑星大気の工学モデルが一般に取る形で、金星・火星・タイタンの公表モデルも同じ形をしている。
さらに、**層の数は天体ごとのデータなので、高度 200 km までしか要らない天体は 4〜6 行で済む** —
28 行は地球が 1000 km まで要求しているからであって、モデルの複雑さではない。

## 1-5. 確認されたバグ

### A. `PLAYER_MIN_ALT` が天体に依らない定数として地表到達に効いている

`player.ts:382` は `reachedBody(prev, state, attractors, C.PLAYER_MIN_ALT)` — 45 km の余裕を
**全天体に**適用している。`PLAYER_MIN_ALT` は大気由来の量なのに、大気を持たない天体にも同じ
厚みの殻を作っている。

- **再現**: 自機で月へ接近する。表面まで 45 km を残して喪失する。
- **正しい姿**: 剛体接触・地表到達の余裕は全天体で 0。焼失は大気を持つ天体にだけ効く。

### B. 地球以外を原点とするレジストリで、抗力が海面密度で掛かる

`dragAccel` は高度を `len(r) - R_EARTH` で求める。`atmosphericDensity` は `Math.max(0, alt/1000)`
で負の高度を 0 km に丸めるので、**`len(r) < R_EARTH` の位置はすべて海面密度 1.225 kg/m³ として
扱われる**。

- **再現**: `StageDebugAltSystem`(`stage-debug-alt-system.ts`、主星 `mu = 4e13` / `radius = 3e6 m`)。
  自機の初期位置は表面 + 500 km で `len(r) = 3.5e6 m < R_EARTH = 6.371e6 m` なので高度が負に出る。
- **大きさ**: 軌道速度 `sqrt(4e13 / 3.5e6)` = 3380 m/s、`SHIP_BCINV = 3.3e-3` として
  `a = 0.5 × 1.225 × 3380 × 3.3e-3` = **6.8 m/s²**。その天体自身の重力
  `4e13 / (3.5e6)²` = 3.27 m/s² の **2倍**。周回できない。
- **正しい姿**: 高度はその天体の基準面から測り、密度はその天体自身の大気モデルから引く。
  大気を持たない天体では抗力は恒等的にゼロ。

### C. 高度の基準面が球(平均半径)なので、密度が緯度で最大 45 倍振れる

`len(r) - R_EARTH` は地球を**平均半径 6371.0 km の球**として高度を測る。実際の海面は
扁平率 1/298 の回転楕円体(赤道 6378.137 km / 極 6356.752 km)なので、**同じ真の高度でも
球近似の高度が緯度で ±7 〜 −14 km ずれる**。

真の測地高度 100 km の位置で、球近似が返す高度と、それが与える密度:

| 緯度 | 球近似の高度の誤差 | 密度の比(球近似 / 真値) |
|---|---|---|
| 0° | +7.137 km | **0.297**(3.4 倍薄い) |
| 30° | +1.771 km | 0.740 |
| 45° | −3.582 km | 1.946 |
| 60° | −8.922 km | 5.247 |
| 75° | −12.822 km | **10.43** |
| 90° | −14.248 km | **13.4** |

赤道と極で **45 倍**の開き。再突入の加熱・動圧が緯度によって桁で変わる。

- **正しい姿**: 高度は基準楕円体から測る。**楕円体からの測地高度は閉形式で十分な精度が出る** —
  地心緯度 φ における楕円体の地心半径 `R(φ) = a·b / sqrt(a²sin²φ + b²cos²φ)` を引くだけで、
  真の測地高度との差は **高度 100 km で 1 m 未満、400 km で 2 mm 台**(法線と動径のずれが
  2次で効くため)。演算数は約 10。
  - **`sin φ` は自転軸方向から出る。** 大気は共回転する相手として自転軸を既に必要とするので、
    追加の入力は要らない。

### D. 弧の打ち切り高度が持ち主に依らない

`PredictedArc.checkImpact` は `REENTRY_ALT` = 80 km を持ち主に関わらず使う。自機の実体は
熱・動圧(通常はもっと高い高度)で失われ、基地・弾薬の実体は 95 km で失われる。

- **正しい姿**: 1-3 の決定により、**弧は大気による打ち切りを持たない**。この不整合は
  パラメータを持ち主ごとにすることではなく、判定そのものを削ることで解消する。

### E. 死因が焼失と衝突で分かれていない

- `Stage.recordEnemyDeath` の `cause` は `'killed' | 'reentry' | 'despawn'` で、天体への衝突が
  弾による撃破と同じ `'killed'` に落ちている(`Enemy.collideWith` が相手を区別せず渡すため)。
- 自機側は `'大気圏に突入し機体は焼失した'`(高度マージン)と
  `'天体の地表へ到達し機体は失われた'`(地表到達)が並んでいるが、前者は熱シミュの粗い重複
  (1-3)であり、大気の無い天体では誤って出る。

**自機の熱・動圧側の3つの理由は、現状のまま正しく分かれている**(4-1)。触らない。

### 抗力を掛ける天体を1つに決める

**複数の大気の寄与を足し合わせることは物理的にありえない。** 呼び出し側が1体を選んで渡す。

桁違いに支配する。

# 4. 現状の熱シミュの挙動(**触らない部分**)

`ThermalSystem.checkThermalLimits()` は既に**3つの死因を区別して**返している。

| 戻り値 | 条件 | 自機の理由文 | 大気が要るか |
|---|---|---|---|
| `'heat-aero'` | `hullTemp > MAX_HULL_TEMP` **かつ** `qdyn >= REENTRY_GLOW_MIN_Q`(200 Pa) | 断熱圧縮による加熱で熱防御が飽和し、機体は焼失した | **要る**(= 焼失) |
| `'heat-internal'` | `hullTemp > MAX_HULL_TEMP` **かつ** `qdyn < 200 Pa` | 排熱が追いつかず、機体は熱で機能不全に陥った | **要らない**(射撃・被弾の発熱で軌道上でも起きる) |
| `'dynpressure'` | `qdyn > MAX_DYN_PRESSURE`(35 kPa) | 動圧が構造限界を超え、機体は空力的に分解した | **要る**(= 空力破壊。焼失ではない) |

- `hullTemp` は Sutton–Graves のよどみ点熱流束 `q̇ = SG_CONST·√(ρ/NOSE_RADIUS)·v³` とステファン・
  ボルツマン放射冷却、射撃・被弾の投入熱量を積分した値。
- `qdyn = 0.5·ρ·|v_air|²`。
- 呼び出し口は `updateAltitudeAlarm`(`thermal.ts:142`)の戻り値で、`Player.checkLoss` がそれを読む。

## 4-1. 決定: この3つはそのまま残す

- **`'dynpressure'` は焼失とは別の死因として残す。** 動圧による空力的分解は加熱による焼失とは
  別の現象で、実際に別の閾値で別々に立つ。統合しない。
- **`'heat-internal'` は大気に依らない死因**なので、大気のパラメータ化とは無関係。触らない。
- **削除するのは `burnUpBody(..., PLAYER_MIN_ALT)` による4つ目の分岐だけ。** 理由文の整理も
  文言の変更もしない。この計画は「大気のない天体に対して剛体との衝突より前に死ぬ」バグの修正で
  あって、**死因を粗くする調整ではない**。

## 4-2. 敵の `'burnup'` が表すもの

敵は熱シミュを持たないので、密度閾値ひとつが**加熱と動圧の両方をまとめて**代理する。
`'burnup'` という名前が「加熱だけを見ている」と読まれないよう、`const.ts` の閾値のコメントに
その旨を書く。

## 5-3. 抗力の費用

- **選択**: 3-2 の表のとおり、実シミュレーション側 5.8 万回/フレーム + 弧側 6 万回/フレーム。

## 5-4. 楕円体高度の費用

`R(φ) = a·b / sqrt(a²sin²φ + b²cos²φ)`、`sin φ = dot(r_rel, pole)/|r_rel|`。
乗算 6・除算 2・平方根 2・内積 3 ≈ **13 演算**。現状の `len(r) - R_EARTH`(平方根 1 + 減算 1)
に対して +11 演算だが、`dragAccel` は1歩に1回しか呼ばれないので、
5.8 万回 × 11 = **64 万演算/フレーム**。**無視できる。**

## 5-5. 弧が余分に踏む歩数(1-3 の決定の帰結)

- 弧の打ち切りが 80 km から地表まで下がる。この帯の刻みは `REENTRY_SUBSTEP_MAX_DT` = 1 s
  (高度が `REENTRY_SUBSTEP_ALT` = 200 km 以下)。
- 典型的な再突入(LEO からの降下)で 80 km 以下に留まる時間は、抗力による減速を含めて
  **数百秒のオーダー** → **数百歩**。
- interactive 枠 = `ARC_STEP_BUDGET` 600 × `ARC_INTERACTIVE_RATIO` 0.5 = **300 歩/フレーム**。
  余分な歩数はその降下の実時間に分散するので、1フレームあたりでは予算内に収まる。
- 収まらなくても壊れない — 弧は追い越されて読まれなくなり、その個体は実シミュレーションの
  積分へ落ちる。
- **ただし実測が要る**: 減速して終端速度で落ちる場合(艦の終端速度は海面で
  `sqrt(2g/(ρ·bcInv))` = **69.7 m/s**)、30 km から地表まで 430 秒 = 430 歩が積み増される。

## 段4. 死因を分ける

1. `Stage.recordEnemyDeath` の `cause` へ `'burnup'` / `'collision'` を足し、`'reentry'` を
   `'burnup'` へ改名する。`stage.ts:252` の三項演算子を `Record<cause, string>` による
   網羅的な引き当てへ直す。
2. `Enemy.checkLoss` は `'burnup'`、`Enemy.collideWith` は相手が `Attractor` なら `'collision'`、

統合で解消する事項であって、この計画の担当外。**ここで無理に揃えない。**

**完了条件**: `typecheck` + `test:physics` + 実行時確認(敵のヒントが焼失と衝突で出し分かる)。
