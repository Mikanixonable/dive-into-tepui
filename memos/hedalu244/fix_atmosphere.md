**段0〜段4は実施済み(commit a88e2329 / 01033188 / 7041f8c6 / 3a11ca40)。**
残っているのは第7章の「残工程」1件だけ。

# 1. 目的

## 1-1. 大気が地球にハードコードされている(解消済み)

`physics/atmosphere.ts` は大気を地球のものとして固定していた。id 文字列で地球以外を弾き、
Vallado のテーブルをモジュール定数として持ち、高度を **ECI 原点からの距離** から地球平均半径を
引いて求め、`EARTH_OMEGA` を Y 軸まわりに適用していた。

**大気の有無と厚みは天体ごとの固有パラメータであるべきで、定数であってはならない。**
既定レジストリでは地球が ECI 原点に静止しているのでこの前提は成り立っていたが、それは偶然で
あって設計ではない。帰結が 1-5 の B。

## 1-2. 焼失と衝突が同じ「margin」に混ざっている(解消済み)

**この2つは別の現象である。**

| | 焼失 | 衝突 |
|---|---|---|
| 何が起きているか | 大気を持つ天体の大気圏に入り、加熱と動圧に耐えられなくなる | どんな天体にもある固体表面への剛体接触 |
| 事象の性質 | **連続量による状態**(濃い空気の中にいる) | **離散的な事象**(表面に触れた瞬間) |
| 相手 | 大気を持つ天体だけ | 全天体 |
| 将来 | 熱シミュレーションによる精緻化 | 相対速度による着陸の成立 |

## 1-3. 焼失の判定は3階層あるべきで、いまは混ざっている(解消済み)

大気による喪失を判定できる精度は、その主体が何を運んでいるかで決まる。

| 主体 | 運んでいるもの | 焼失を判定できる形 |
|---|---|---|
| **自機の実体** | 外殻温度の蓄積・動圧(`ThermalSystem`) | **熱・動圧の物理モデル**。加熱・空力破壊・排熱不全を区別できる |
| **熱シミュを持たない種別の実体**(敵・破片・薬莢・弾・基地・弾薬) | 位置と速度だけ | **大気密度の閾値**という粗い近似 |
| **弧(`PredictedArc`)** | 位置と速度だけ。**姿勢も熱の蓄積状態も運ばない** | **判定しない** |

### 決定: 弧は大気による打ち切りを持たない

**弧が答えるのは「この自由落下の経路が固体表面へ到達するか」だけ。** 大気を持つ天体に
対しても再突入判定をせず、衝突だけを判定する。

理由: 弧は熱の蓄積状態を運んでいないので実体の喪失点を原理的に当てられず、当てられない量を
近似で埋めると **近似の値を実体側と揃え続ける保守が発生する**(`REENTRY_ALT` が持ち主に依らず
使われていたのが、まさにその保守が破綻した形)。後から熱を拡充するとき、**弧に足すべきものが
「熱の運搬」1つだけになる**。

**受け入れた帰結**(2つとも意図したもの):

- **弧は自機の実際の喪失点より先まで伸びる。** 計画軌道の ✕ アイコンは「この軌道が地表へ到達
  する点」を指す — **喪失点ではない。** 自機の焼失は HUD の温度・動圧ゲージと警告が知らせる。
- **弧が初めて濃い大気の中を積分する。** 刻みは実シミュレーションと同じ 1 s なので精度は同じだが、
  歩数が増える。

## 1-4. 大気モデルの形 — 密度テーブルは保つ(決定済み)

**「密度を1つのパラメータと閉じた指数式で表す」形は採らない。物理的に成り立たないため。**
スケールハイトは温度と平均分子量に比例し、地球大気の温度は高度に対して単調でない。現行
テーブルのスケールハイトは **5.382 〜 268 km(50 倍)を動き、しかも単調でない** — 90 km で
最小を取る。7.249 km の単一指数を当てると 400 km で 3.6e-13 倍、800 km で 1.2e-34 倍になり、
LEO の軌道減衰が完全に消える。

**他天体を足しやすくする方向としては、テーブルのままで足りる。** 区分指数は惑星大気の工学モデルが
一般に取る形で、金星・火星・タイタンの公表モデルも同じ形。層の数は天体ごとのデータなので、
高度 200 km までしか要らない天体は 4〜6 行で済む。

## 1-5. 確認されたバグ(A〜E とも解消済み)

### A. `PLAYER_MIN_ALT` が天体に依らない定数として地表到達に効いていた

`reachedBody` へ 45 km の余裕を**全天体に**適用し、自機は月面の 45 km 上空で喪失していた。
剛体接触・地表到達の余裕は全天体で 0 が正しい。

### B. 地球以外を原点とするレジストリで、抗力が海面密度で掛かっていた

`dragAccel` が高度を ECI 原点からの距離で求め、`atmosphericDensity` が負の高度を 0 km へ丸めるため、
地球平均半径より内側の位置がすべて海面密度 1.225 kg/m^3 として扱われていた。
`StageDebugAltSystem`(主星 mu = 4e13 / radius = 3e6 m)では抗力 6.8 m/s^2 がその天体自身の
重力 3.27 m/s^2 の 2 倍になり、周回できなかった。

### C. 高度の基準面が球(平均半径)なので、密度が緯度で最大 45 倍振れていた

真の測地高度 100 km で、球近似の高度が赤道 +7.137 km / 極 -14.248 km ずれ、密度比が
赤道 0.297 / 極 13.4 — **45 倍**の開き。再突入の加熱・動圧が緯度によって桁で変わっていた。

### D. 弧の打ち切り高度が持ち主に依らなかった

1-3 の決定により、判定そのものを削ることで解消した。

### E. 死因が焼失と衝突で分かれていなかった

`Stage.recordEnemyDeath` の cause が killed / reentry / despawn の3種で、天体への衝突が弾に
よる撃破と同じ killed に落ちていた。

# 3. 現状の熱シミュの挙動(**触っていない部分**)

`ThermalSystem.checkThermalLimits()` は3つの死因を区別して返す。**この3つはそのまま残っている。**

| 戻り値 | 条件 | 自機の理由文 |
|---|---|---|
| heat-aero | 外殻温度が上限超 **かつ** 動圧 >= 200 Pa | 断熱圧縮による加熱で熱防御が飽和し、機体は焼失した |
| heat-internal | 外殻温度が上限超 **かつ** 動圧 < 200 Pa | 排熱が追いつかず、機体は熱で機能不全に陥った |
| dynpressure | 動圧 > 35 kPa | 動圧が構造限界を超え、機体は空力的に分解した |

- **dynpressure は焼失とは別の死因。** 動圧による空力的分解は加熱による焼失とは別の現象で、
  実際に別の閾値で別々に立つ。統合しない。
- **heat-internal は大気に依らない死因**なので、大気のパラメータ化とは無関係。

敵は熱シミュを持たないので、密度閾値ひとつが**加熱と動圧の両方をまとめて**代理する。
burnup が「加熱だけを見ている」と読まれないよう、`const.ts` の閾値のコメントに明記した。

# 7. 残工程

## 段5. ECI 原点の球で高度を測っている残り2箇所を天体基準にする

達成目標 3 は密度の経路では達成したが、**ECI 原点と地球平均半径から高度を出す形が `src/` に
1件残っている。** 加えて、レビュー中に同じ前提に立つ箇所をもう1つ見つけた。どちらも計画の
変更箇所の表に無かったので、**この計画では触っていない。**

### 7-1. `wave-attack.ts:249` — 敵の出現高度のクランプ

stage00 の敵の出現位置を「大気圏上限 +10 km」より上へ持ち上げるクランプが、ECI 原点からの
距離から地球平均半径を引いて高度を出している。**ゲームバランスの配置であって密度の測定では
ない**ので、緯度による +7 / -14 km のずれは 10 km の余裕に埋もれる。`enemy-generator.ts` も
同様に地球平均半径を使っており、stage00 のウェーブ生成は全体が地球固有の内容になっている。

**判断が要る**: 目標 3 の文面どおり 0 件にするか、「stage00 の地球固有な配置は対象外」と
目標の側を書き換えるか。前者なら `nearestAtmosphereBody` と `ellipsoidAltitude` へ寄せる。

### 7-2. `adaptiveSimulationMaxStep` の再突入域の境界

`simulator.ts:175` と `predicted-arc.ts:165` が、再突入域での刻みの細分化を **ECI 原点を中心と
する半径「地球平均半径 + 200 km」の球**で判定している。この細分化は大気の密度が 1 スケール
ハイトで桁が変わることを理由に存在するので、**大気を持つ天体の基準面から測るべき量**である。

**これは 1-1 と同じ欠陥の最後の1つ**で、いま実際に効いている:

- `StageDebugAltSystem` では全状態がその球の内側に入る(主星の半径 3e6 m、自機は 3.5e6 m)ので、
  **再突入域でもないのに刻みが常に 1 s へ張り付く**。高いワープ倍率で 1 フレームに数秒かかる
  (性能の問題であって、積分の正しさは損なわれない)。
- 大気を持つ天体が原点でないレジストリでは、逆に**細分化が効くべき場所で効かない**。

**直し方**: 半径の閾値ではなく、大気天体1体と「その大気の基準面からの高度」を渡す形へ変える。
`adaptiveSimulationMaxStep` は状態列と半径を受け取る純粋関数なので、`ellipsoidAltitude` を
使う形にすれば固有名は消える。動径速度から境界到達までの時間を出す部分は、天体中心からの
相対位置・速度で組み直す。

**この段だけで typecheck + test:physics + `StageDebugAltSystem` の実行時確認まで通ること。**
