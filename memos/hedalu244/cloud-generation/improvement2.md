# 雲生成の第二次改善 — 目視評価にもとづく計画

**目標は、cloud-lab の生成(被覆率・雲頂高度・薄い雲の 3 チャンネル)を実写 8k_clouds と並べて見たとき、
前線・気団・気候の構造が読める絵になること。** 第一次改善(`2fda5139` まで)は帯状平均・階調・雲頂の
分位といった統計を実写へ寄せたが、目で見比べると品質が足りない。ユーザーの採点(100 点満点)は
**前線帯 0・被覆率 50・雲頂高度 20・薄い雲 70・合成 40。** この版は**判定を目視に置き、数値は目視の
訴えを裏付ける物差しに限る。** 基準値はすべて `2fda5139` で `npm run cloud-lab:compare` を回した
実測(2026-09-04)。

## 計測の物差し

`npm run cloud-lab:compare`(`tools/cloud-lab-compare.mjs`)が全球(正距円筒 1024×512 = 39 km/texel)と
地域別 cap(正射影・半径 20° = 8.5 km/texel、中央 362×362)を撮り、実写(実写計)と `npm run
cloud-lab:separate` の分離成分(実写厚 = 厚い雲、実写薄 = 薄い雲。**分離は輪郭検出として働く癖があり、
実写厚は高周波へ、実写薄は滑らかな板へ偏る**)を同じ面へ再標本化して、帯状平均・階調・行方向スペクトル・
構造テンソル・地形の箱・雲頂の分位を印字する。画像は `.cloud-lab/compare/` に残る。
`npm run cloud-lab:shot` は全ビューを 0 h と 25 h で `.cloud-lab/shots/` へ撮る。目視の見比べは
**`npm run cloud-lab`(dev サーバ、liveReload)で定数を直接書き換えて行う** — 再ビルドは十数秒で、
compare のように本番ビルド(2.5 分)を挟まない。

**厚い雲の大きな構造の基準は実写計に取り、実写厚は使わない。** 実写厚は分離が高周波を取り出したもので、
3000 km 超の濃淡(乾燥帯の晴れ)を持たない。手順 3 で 合成 vs 実写計 のスペクトルと晴れの割合を物差しへ
足す。**雲頂の基準は気象学の事実だけ**(実写にも分離にも雲頂は無い): 厚い雲の大半は 3 km 以下、深い対流は
数 %、塔は圏界面(熱帯 17 km・極 9 km)まで届き、金床は台風の芯だけ。

**撮影の非決定性は最大 3 LSB ≈ 0.012。** これ未満の差を意味と読まない。

## 目的 — 目で見て違うところ

**1. 前線帯(0 点)。** 前線を、低気圧の芯から南西(南半球で北西)へ 1800 km 伸びる**細長い気圧の谷**
(異方ガウス)として気圧へ足している。これは気象学的にあり得ない — 前線は低気圧の周りに気団の衝突として
生じるもので、前線そのものが低気圧ではない。帰結として: (a) 谷に沿って強い風が平行に吹き、渦の風と
合わない。(b) 他の谷・気圧帯と単に足し合わさるので、交差した所に鞍点状の風向きや異常な風速が出る
(`wind-0h.png` の筋状の色、`translucent-0h.png` の南半球の斜めの筋)。(c) 形が一定の平行移動で、
低気圧の大きさ・寿命・隣の低気圧と相互作用しない。**全面的に作り直す。**

**2. 被覆率(50 点)。** 網目(細胞の壁)の質感が入ったのは良いが、(a) 実写は雲の少ない所では網目、多い所では
粒(細胞の芯)へ滑らかに移る — 生成は全域が網目。(b) 被覆率 0.1〜0.3 の**平坦な灰色の面**が広くある
(沈降域の層積雲の板 `DECK_*` と、対流の活発度が 0 に落ちた所)。これは分離が削り切れなかった巻雲らしさを
模倣した形で、薄い雲と二重に掛かって「雲の無い所」を無くしている。

**3. 雲頂高度(20 点)。** 全体が均質(cap の中央値 3.2〜3.9 km、四分位幅 2.4〜2.9 km)で、起伏は被覆率と
同じ網目だけ。粒状・柱状の盛り上がりが無く、塔は極まれな 1 texel の白点(縁 0.027〜0.072 の smoothstep が
峰の頂点だけを拾う)。亜熱帯東岸沖とサハラに 9 km 超が 5.5〜6.6% 立つ(目標 ≤ 1%)。

**4. 薄い雲(70 点)。** 前線の谷の移流で異常な筋が出ている。それを除いても低周波が足りず一様に見える
(実写薄 `globe-veil.png` は大陸規模の晴れ間を持つ)。中緯度の上層の流れ(亜熱帯ジェット 33°/日 ≈ 30 m/s)
は再生で速すぎる。

**5. 合成(40 点)。** 情報の複雑さは増したが、世界のどこを切り取っても同じ質感で、低周波が足りない。
±60° の晴れ(< 0.06)は 実写計 29.7% に対し合成 17.7%。気候要素が弱い: サハラの合成 0.055(実写計 0.006)、
中央アジアは平均 0.206 で実写計と同じだが、実写は黒地に明るい雲が点在するのに対し生成は一様な灰色。
チリ沿岸の層積雲が海岸線で終わる様子が無い(合成 チリ 0.268 / アンデス東 0.101 で向きは合うが、板が
滑らかな灰色で海岸の縁が読めない)。

**6. 調整の自由度。** ノイズの段は 周波数 2 倍・振幅 0.65 倍 の等比列に固定され、段ごとの波長と振幅を
個別に置けない。平年雲量と標高の重みは線形で、乾燥帯だけを強く晴らすことができない。

## 決めたこと

| # | 決定 | 根拠 | 覆すとどうなるか |
|---|---|---|---|
| 1 | **前線の谷(尾)は削除し、弱めて残さない** | 谷として足す限り、平行な風・鞍点・足し合わせの異常は消えない。前線は低気圧ではない | — (ユーザーの指示) |
| 2 | **前線は「気団の出身緯度」の圧縮から作る。** 各点から、地表付近の釣り合い風 + 地表の帯の平均風で一定時間だけ風上へ遡り、遡った先の緯度を「出身緯度」として焼く。その勾配の大きさ(何も無ければ 1)が 1 を超えた分 = 気団の境目が押し縮められた所 = 前線で、そこへ上昇流を置く。出身緯度と現在地の緯度の差(暖気の流入 / 寒気の流入)で湿度と対流の活発度を振る | 温度の場を持たなくても、緯度が気団の温度の代理になる。渦の風で運ばれた気団の境目は低気圧の周りを螺旋状に巻き、隣の低気圧の風の和で運ばれるので互いに絡む。同時に、寒気側の乾いた切れ込み(dry slot)と粒立ち、暖気側の板と高い雲頂が同じ量から出る | 上昇流の帯を手で置く(渦の中心から螺旋を描く関数)と、形は出るが隣の低気圧と相互作用しない。手順 4・5 が丸ごと替わる |
| 3 | 出身緯度の追跡は **2 位相を使わず、固定時間(初期値 48 h)で 1 回だけ遡る** | 遡る先は緯度(解析的)でテクスチャを読まないので、2 位相移流が要った「模様が無限に細くなる」問題が無い。位相の混ぜ目で前線が 2 本に分かれて脈打つことも無い | 2 位相にすると前線が周期ごとに薄まる |
| 4 | 追跡の風にだけ地表の帯の平均風の**東向きの成分だけ**を足す。南北の成分は足さない。**湿度・対流の移流の風は変えない** | 東西の流れの南北シアが前線を南西–北東へ傾ける。南北の成分は経度に依らないので、収束する緯度(赤道・±60°)に緯線に沿った圧縮の環を作る — 実測で ±60° の圧縮の中央値が 1.80(足す)→ 1.09(落とす)。湿度の 2 位相移流へ平均風を入れると、位相 A と B が 500 km ずれた別の模様を混ぜることになり全域がぼける | 南北の成分を戻すなら、±60° の環を `FRONT_ONSET` で消す |
| 5 | 前線の上昇流は **緯度 15°→30° で開く門**の中だけに置く | 前線は温帯のもの。門が無いと、貿易風の収束(赤道)で圧縮の環が立ち収束帯が二重になり、台風(15°N)の周りで圧縮が発散して上昇流が飽和した円盤になる | 門を外すなら、赤道の環は圧縮の効き始めを上げて消す |
| 6 | **層積雲の板(`DECK_*`)は削除する。** 冷たい海の層積雲は、平年雲量の非線形な重み(手順 8)で湿度を上げ、沈降で活発度を下げた「粒の弱い閉じた細胞」として、他の雲と同じ伝達関数から出す | 板を伝達関数の外で max すると平坦な灰色になる。実写の層積雲の板は細胞の質感を持つ | 板を残すなら細胞の質感を持たせる。手順 9 が替わる |
| 7 | **対流の活発度は 0 に落とさない**(床 ≈ 0.3)。板になるかどうかは活発度ではなく、対流の**形**(網目 ↔ 粒)と振幅で決める | 活発度 0 の所は粒が完全に消えて平坦な灰色になる。実写の板にも細胞がある(仕様「板として覆った空も一様な白い面ではなく」) | 床を 0 に戻すと平坦な灰色が戻る |
| 8 | **対流の形は「湿度の低周波」で網目から粒へ渡す。** 対流の源を smooth(粒)と cellular(網目)の両形で焼き、凝結の側で 湿度(粒を足す前)の smoothstep で混ぜる。混合で分散が落ちる分は 1/√((1−s)²+s²) で戻す | ユーザーの観察: 実写は被覆率の低い所で網目、高い所で粒。形を決める量は粒より低周波でなければ、粒ごとに形が変わって読めない | 被覆率(伝達関数のあと)で決めると自己参照になるので不可。活発度で決めるなら手順 9 の量を差し替える |
| 9 | **ノイズの段は [周波数, 振幅] の表で持つ。** 等比の `octaves` + `OCTAVE_PERSISTENCE` を捨て、段ごとの texel フェードは `clamp(log2(FADE_START / (texel × f)) + 1, 0, 1)` で個別に取る(等比の表ならいまの式と一致する) | 段ごとの波長・振幅を個別に調整する自由が要る(ユーザーの指示)。3000 km 超の段を 1 つ足すのが、低周波を作るいちばん安い方法 | 等比のままなら、低周波は基準の周波数を下げて段数を増やすしかなく、中間の段の振幅が一緒に動く |
| 10 | **平年雲量の重みは smoothstep の S 字**(乾燥側 0.25 → 湿潤側 0.60 で −0.5..+0.5)にする。線形の重みは捨てる | 線形では砂漠(0.14)を晴らす重みで海(0.55〜0.75)が覆われたまま動かなくなる。乾燥帯だけを強く晴らすには非線形が要る(ユーザーの指示) | 線形に戻すなら、乾燥帯は晴れないか、海が貼り付く |
| 11 | **陸の割合を気候テクスチャの A へ足す**(NASA 標高の海 = 0 から。ぼかし σ 100 km)。使い先は 2 つ: 陸の上で活発度を上げる(大陸の雲は粒立つ)、地形の上昇流の高さへ陸の分を上乗せする(海と陸の比熱の差を、海岸へ吹き込む風が斜面を駆け上がる形で代用。ユーザーの案) | いまの気候テクスチャ(R 気温 / G 平年雲量 / B 標高 200 km ぼかし)からは海岸が読めない。海岸線の対比は実写の目立つ気候要素 | 陸の割合を足さないなら、海岸の対比は平年雲量の非線形な重みだけに頼る(チリは出るが、大陸の粒立ちは出ない) |

## 達成目標

1〜8 は compare の表で、9 は再生と grep で、10 はユーザーの目視で判定する。
「基準」は `2fda5139` の実測。

1. **風の異常が無い**: 気圧の谷が丸い(気圧ビュー)。全球の風ビューで、台風の芯(中心 10° 以内)を除いた
   風速の最大が 30 m/s 以下(手順 2 のあとの基準 17.1 m/s、99 パーセンタイル 13.4 m/s)、
   風向きの鞍点(向きが 4 方向へ分かれる点)が谷の外に無い。
   `grep -n "tail\|FRONT_" src/render/cloud/cyclones.ts` が 0 件。
2. **前線(目視 + 表)**: 北太平洋・北大西洋・南大洋の cap で、低気圧の周りに螺旋状に巻く上昇流の帯があり、
   帯の寒気側に晴れた切れ込みと粒状の雲、暖気側に板状の雲がある。帯の形は低気圧ごとに違い、隣り合う
   低気圧の帯は絡む。**前線ビューに、赤道・±60° の緯度に沿った環が立たない。** 構造テンソルの
   35-60°N・35-60°S の 800 km で、被覆率の卓越する向きが実写厚(N 31°、S 127°)の ±35° 以内
   (基準 N 82°、S 80°)。揃い R は表に出すだけで目標にしない。
3. **平坦な灰色が無い**: ±60° の「のっぺり率」(被覆率 0.06〜0.25 かつ 5×5 texel ≈ 200 km の標準偏差 < 0.02
   の texel の割合)が 2% 以下(手順 2 のあとの基準 被覆率 7.3%。合成 2.8%・実写計 0.4%・実写厚 0.2%)。
   `DECK_` が `src/render/cloud` から 0 件。
4. **晴れた空がある**: ±60° の合成の晴れ(< 0.06)が 25% 以上(基準 17.7%、手順 2 のあと 17.3%、
   実写計 29.7%)。
   合成/実写計 の行方向スペクトルが、3 帯(35-60°N・10°S-10°N・35-60°S)の 3384 km 以上の各波長帯で
   0.5〜2.0(手順 2 のあとの基準 0.53〜1.24: 35-60°N 0.83/0.73/0.58、10°S-10°N 1.24/0.53/0.72、
   35-60°S 1.08/0.83/0.90)。
5. **気候**: サハラの合成 ≤ 0.03(基準 0.055、実写計 0.006)。中央アジアの箱で合成 ≤ 0.21 かつ晴れ(< 0.06)の
   割合 ≥ 40%。チリ沿岸/アンデス東 の合成の比 ≥ 2.0(基準 2.65)、かつ亜熱帯東岸沖の cap で層積雲の縁が
   海岸線から 200 km 以内で終わっている(目視)。帯状平均を引いた corr(被覆率, 平年雲量) が 0.2〜0.5
   (基準 0.157 — 貼り付けすぎない上限)。
6. **雲頂**(cap の被覆率 > 0.3 の texel): 暴風帯 3 cap で ≤ 3 km 40〜60%、3〜7 km 30〜55%、> 9 km 1〜5%、
   > 12 km ≤ 0.5%(基準 北太平洋 46/51/1.8/0.5、南大洋 31/62/1.6/0.0)。亜熱帯東岸沖・サハラで > 9 km
   ≤ 1%(基準 6.6% / 5.5%)。四分位幅 ≥ 2 km(全 cap)、金床 ≤ 25%(台風を除く)。**雲頂ビューで起伏が
   網目ではなく粒(盛り上がり)で、塔が 1 texel の針でない(目視)。**
7. **薄い雲**: 薄い雲ビューに前線の谷の斜めの筋が無い(目視)。±60° の薄い雲(輝度)の晴れ(< 0.06)の割合が
   実写薄の 0.7〜1.3 倍(手順 2 のあとの基準 薄い雲 39.4% / 実写薄 36.8% = 1.07 倍)。6 cap の 薄い雲/実写薄 が 0.5〜2.0(基準 0.37〜1.09)。
8. **退行の枠**: 被覆率/実写厚 の帯状比(±60°)が全帯で 0.4〜1.6(基準 0.93〜1.51)。合成/実写計 の帯状比が
   0.5〜1.5(基準 0.90〜1.32)。白飽和(> 0.94)≤ 2%。
9. **既存仕様と負荷**: 緯度に沿った継ぎ目が立たない・時刻を往復しても同じ空(0 → 72 → 0 h の再生)。
   `grep -rn "KNOB" src/render/cloud` が `CUMULUS_DITHER_KNOB` のみ。ノイズの段の総数(全ノイズの表の
   行数の和)≤ 16(基準 13: 気圧 1・湿度 4・対流 2・上層 4・気団 2)。cloud-lab の再生が目で見て滑らか。
10. **ユーザーの採点**: 前線帯 ≥ 60、被覆率 ≥ 70、雲頂高度 ≥ 60、薄い雲 ≥ 80、合成 ≥ 65。

## 手順

### 手順 5. 前線と気団を雲へ効かせる

**目的。** 圧縮を前線の上昇流に、暖気/寒気の流入を湿度と対流の活発度に結び、前線帯・寒気側の切れ込みと粒・
暖気側の板を出す。活発度の床もここで入れる(粒が消えて灰色になる所を無くす)。

**変更が必要な箇所。**

**追跡時間 `TRACE_SECONDS` の導出。** 並の低気圧(深さ 18 hPa、半径 500〜1100 km)の周りの風は 600 km で
約 15 m/s、角速度 ω = 15 / 6e5 = 2.5e-5 rad/s。圧縮 ≈ 2ωT(ω ∝ 1/r² の差回転)なので、T = 48 h = 1.73e5 s
で 600 km の圧縮 8.6、1200 km(ω 1/4)で 2.2、1500 km で 1.4 — 腕は 1200〜1500 km 伸びる。
T を 2 倍にすると腕は √2 倍。芯では 1 歩の巻きが 4.3 rad(2/3 周)で、`windStep` の弦は直径に収まる。

**環の強さの導出(門と効き始めの根拠)。** ±60° で極偏東風(南向き 1.6 °/日)と偏西風(北向き 2.3 °/日)が
向かい合う。混ぜ幅 15° の中で 48 h に 3.9 °/日 × 2 日 = 7.8° 縮む → 圧縮 1 + 7.8/15 ≈ 1.5。赤道の貿易風
(南北 2.3 °/日 × 2)も同じ 1.6。**効き始め 1.4 では環が薄く残る**ので、緯度の門(15° → 30°)で赤道の環を
消し、±60° の環は前線ビューで見て効き始めを 1.5〜1.7 へ上げるか決める。

**平年雲量の S 字の効き。** 0.25 → 0.60 の smoothstep − 0.5 に重み 0.5: サハラ(0.14)−0.25、アンデス東
(0.43)−0.11、平年並み(0.55)+0.18 → base を 0.18 下げると平年並みが動かない。チリ沿岸(0.65)+0.25、
中央アジア(0.51)+0.10(晴れは陸の粒立ちと低周波の段で作る)。

**負荷。** 段の総数 13 → 15(湿度 +1、上層 +1)。対流の両形は評価を共有すれば +0、`carry` を 2 回にすると
+2 評価(段の総数は増えない)。出身緯度の焼きは 1 texel あたり 気圧 6 読み + 釣り合い風 1 回で、
`weatherAt()` の風の計算と同じ規模が 1 パス増える。`weatherAt()` は写しを 5 読み増やす。
