# 雲生成の改善 — 実写(8k_clouds)との比較にもとづく計画

**目標は、生成の被覆率(厚い雲)が実写の厚い雲成分と、薄い雲(巻雲)が実写の巻雲成分と、
それぞれ同じ統計・同じ種類の構造を持つこと。** 2 つを重ねた合成 vs 実写そのものは、分離を介さない
横断検算として使う。生成時間は現状程度に保ち、調整項目は増やさない(増築の 2 手順だけが例外で、
採否はこの文書の検査で決める)。

## 計測の物差し

`npm run cloud-lab:compare`。実写・合成・被覆率・薄い雲を全球 + 地域別 cap(半径 20° =
8.5 km/texel)で撮り、**実写を厚い雲と巻雲へ推定分離**してから、帯状平均・階調・行方向スペクトルの
表を出す。画像(分離結果含む)は `.cloud-lab/compare/` に残る。

分離のアルゴリズムと調整パラメータは `tools/cloud-separation.mjs`(SEPARATION 表)が持ち、
`npm run cloud-lab:compare`(撮影解像度での再分離)と `npm run cloud-lab:separate`(実写の原寸
4096×2048 での分離。描画用の仮テクスチャ 3 枚を `.cloud-lab/separated/` へ書く)が共有する。
方法: 実写をスクリーン合成 p = veil + thick·(1−veil) とみなし、veil(巻雲の輝度)を「等方な
細かい起伏が弱い画素の、~250 km 窓の重み付き下側パーセンタイル」+「筋状(構造テンソルの
異方性)で暗い画素の残差」で推定してから thick を剥がす。高度の次元は原理的に欠けているので、
次の癖ごと使う:

- **床(下側パーセンタイル)が天井を超える所は、veil を天井に張り付けて超過分だけを厚い側へ
  渡す**(明るく厚い系の上には巻雲の傘も掛かっている、の仮定)。粒ばかりで証拠が乏しい窓だけ
  veil 0 に落とす。
- **判定素材(細かい起伏)は解像度に強く依存する。** 撮影の面(全球 39 km/texel、cap はミップで
  鈍る)では veil 側へ寄りすぎるため、**成分別の正は原寸の分離(`cloud-lab:separate`)にだけ
  置き、compare の実写厚・実写薄の列は傾向の目安に留める。**
- 幅の広い明るい帯(前線・かなとこ、輝度 > 上限)は厚い側に数えられる。
- 図法の歪みは、窓を緯度ごとに 1/cos(lat) で横へ伸ばして吸収する(±60° 内)。スペクトルは
  緯度帯別(波長は帯の中央緯度の周長で換算)と cap(正射影・等スケール)で測る。

本文の基準値はすべて **`5cf7d4a9` + 比較環境の未コミット変更** の時点の実測。**うち成分別
(実写厚・実写薄が絡む値)は分離の初版(等方性判定なし)で取ったもので、分離パラメータの調整が
確定した時点で全基準値を取り直してから着手する**(手順 0 として扱う)。合成 vs 実写計の値は
分離に依存しないのでそのまま使える。

## 目的

実写と生成を成分ごとに比べると、差は 4 系統に分かれる。

**1. 分布 — 濃淡の付きすぎ。** 被覆率/実写厚の帯状比(±60°)は、亜寒帯の帯で 1.85〜2.36、
亜熱帯高圧帯で 0.2〜0.6。地域別 cap では台風域 2.4、北太平洋の暴風帯 3.1、南大洋 1.8 に対し、
層積雲域 0.36、サハラ 0.12。実写厚の緯度コントラストは弱く、±60° で 0.13〜0.36 に収まる。
薄い雲側は湿潤な中緯度でほぼ当たっている(北太平洋 1.4・南大洋 1.1)が、台風域で 2.9 倍過剰、
層積雲域 0.25・サハラ 0.31 と乾燥側の床が無い。

**2. 階調 — 二値化しすぎ。** 実写厚は ±60° の 68% が中間調で、0.94 超は 0.0%(べったり曇った
南大洋ですら cap 平均 0.301)。被覆率は中間調 26.9%、白飽和 14.1%、黒 59%。飽和した塊の内部は
平坦で、実写の「覆われた空にも常にある質感」が無い。

**3. スペクトル — 大きい構造が強すぎ、細かい構造が無い。** 実写厚 vs 被覆率の行方向パワーで、
総観規模(> 400 km)が 2〜13 倍、メソ規模(24〜96 km)が 0.03〜0.5 倍(層積雲域の 24-48 km は
0.05)。実写厚の傾きは浅く 17 km まで連続に減衰する(単一の「粒の大きさ」が無い)のに対し、
生成は 100 km 付近で崖になる。凝結前の湿度場自体も 212-423 km より細かい帯で実写より一桁弱い
(二値化の縁が高周波を部分的に補うため、被覆率のほうが湿度場より高周波が残るほどである)。

**4. 構造の種類 — 実写の厚い成分にあって被覆率に無いもの。** 分離後の厚い成分の見本が
`.cloud-lab/compare/*-thick.png`(これが被覆率の目指す絵)。
- **前線帯**: 数千 km の細長い雲の帯(温暖前線・寒冷前線のコンマ尾)。生成の低気圧は円盤状の
  湿りしか作らない。実写の中緯度でいちばん目立つ構造がこれ。
- **中緯度低気圧の巻き込み**: 実写のオクルージョンは 1〜2 周巻く。生成は移流の変位が
  ω·T ≈ 1.4 rad(周期 20 h × 並の低気圧の角速度)で、渦として読めない。
- **層積雲の細胞**: 亜熱帯東岸沖の deck(閉細胞・開細胞の網目、10〜50 km)がレジームごと欠落。
  沈降が湿度を差し引いて消すが、実際には沈降こそが deck を作る。
- **気団による質感の使い分け**: 実写は寒気側だけが粒々に千切れ、暖気側は滑らかなシールドになる
  (巻雲の傘は分離で veil 側へ剥がれる)。生成の活発度は渦や前線と空間的に噛み合っていない。
- **細かい雲の連続性**: 実写は広い雲から細かい雲までが連続に共存する。生成は「塊(796〜100 km)」
  と「粒(80〜40 km)」の 2 種類しか無い。

全球面(39 km/texel)で細かい雲が無いのは焼きの解像度による設計どおりの脱落で、cap
(8.5 km/texel)では全オクターブが載る。**アーキテクチャの実力比較は cap で行う** — それでも
上記 3・4 の差が残っている、というのが出発点。

## 決めたこと

| # | 決定 | 根拠 | 覆すとどうなるか |
|---|---|---|---|
| 1 | 実写は分離してから成分ごとに比べ、合成 vs 実写を分離を介さない検算に使う | 実写は厚い雲と巻雲が 1 枚に重なっていて、被覆率(この計画の主対象)の目標が巻雲にぼかされる | 覆すなら合成基準の目標だけで進める(被覆率の過剰が 2.4→3.1 倍と過小評価される) |
| 2 | 分離は下側包絡 + 起伏判定のヒューリスティックで、癖(上の物差しの節)ごと受け入れる | 高度の次元が原理的に欠けており、これ以上は推定の精度でなく仮定の押し付けになる | 精度を上げるなら実写の別ソース(高度別の衛星プロダクト)の導入 = アセット追加の増築 |
| 3 | 8k 出力機能は作らない | cap 半径 20° = 8.5 km/texel、12° に絞れば 5.2 km/texel で、実写(赤道 4.9 km/texel)と同格の標本化になり公平な比較は cap で足りる。全球 8k の毎フレーム焼きは負荷上限(1 texel 千〜二千演算)から不可能 | 覆すなら手順 1 の前に「比較用の一回焼き 8k 出力」を追加する |
| 4 | 極域(±60° より外)の実写値は判定に使わない | 8k_clouds は南極内陸(地球で最も晴れる場所)が 0.5〜0.63 と写っており、撮影・加工の癖が支配的 | 覆すなら手順 2 の達成条件に高緯度帯を足す(HUMIDITY_BASE の緯度依存という増築が要る見込み) |
| 5 | 数値目標の比は 0.5〜1.5 の緩い枠に取る | 実写は sRGB 符号の写真で、生成は生の値。トーンカーブの不一致・分離の癖・撮影の非決定性(最大 3 LSB)を枠で吸収する | 締めるなら実写ビューをリニア化(または生成側に sRGB 符号を掛ける)してから全基準値を取り直す |
| 6 | 48 km より細かい構造は生成の目標にしない | texel より細かい縁と二値化は描画側の高周波が担う契約(場は「そこが何割雲か」を滑らかに渡す) | 覆すなら CONVECTION_NOISE の段数増(cap のノイズ費用 +1.5/texel)が要る |
| 7 | 手順 1(伝達関数の改築)をパラメーター調整(手順 2-3)より先に置く | 伝達関数は全ての平均・階調を動かすので、先に調整すると二度手間 | 逆順でも成立するが、手順 1 の後に手順 2 相当の再調整をもう一度行うこと |
| 8 | 調整項目は tier 1-2(手順 1-5)では純増させない | 保守性の劣化を避ける(ユーザー要求)。増えるのは手順 5 の OCTAVE_PERSISTENCE 1 個、手順 6 の層積雲 2 個、手順 7 の前線 1〜2 個だけ | 増築を却下するなら手順 6・7 を落とす(達成目標 3 の層積雲域と目視目標の前線は未達のまま残る) |

## 達成目標

1〜5 は `npm run cloud-lab:compare` の表、6〜8 は目視・数え上げで判定する。

1. **帯状平均**: ±60° の全帯(5.625° 刻み)で 被覆率/実写厚 が 0.5〜1.5(基準: 最悪 2.36。
   層積雲の漏れがある −14〜−31° の 3 帯は 0.4 まで許容)。
2. **階調**(±60°): 被覆率の 0.94 超が 2% 以下(基準 14.1%)、中間調(0.06〜0.94)が 55% 以上
   (基準 26.9%、実写厚 68.0%)。
3. **地域平均**: 6 地域の cap すべてで 被覆率/実写厚 が 0.5〜1.5(基準 0.12〜3.1。層積雲域は
   分母を実写計まで取った 0.074/0.29 = 0.26 でも可とせず、0.5〜1.5 を実写厚 0.203 に対して当てる)。
   薄い雲(輝度)/実写薄 が 0.5〜2.0(基準 0.25〜2.9)。
4. **スペクトル**: 6 地域の cap(実写厚 vs 被覆率)で、48-96 km 帯の比 ≥ 0.4(基準 0.18〜1.8)、
   385 km 以上の各帯の比 ≤ 2.5(基準: 最悪 13.2)。
5. **横断検算**: 合成/実写計 の帯状比(±60°)が 0.5〜1.5 — 分離の癖に合わせ込んでいないことの
   確認(基準: 最悪 2.40)。
6. **構造の目視**(判定はユーザー、見本は `.cloud-lab/compare/*-thick.png`): 北太平洋・南大洋の
   cap に円盤でない伸びた帯構造と巻き込みが見える。亜熱帯東岸沖の cap に細胞質感の deck が出る。
   台風の螺旋と目、粒の残存は壊れていない。
7. **負荷**: cap の 1 texel あたり勾配ノイズ評価数 ≤ 8.5(基準 7.6。段数 × 帯の混ぜ 1.5 ÷ 粗さ²
   の数え上げで判定)。
8. **既存仕様の維持**: 緯度に沿った継ぎ目が立たない・時刻を往復しても同じ空(cloud-lab の再生で
   目視)。

## 手順

**各手順の終わりに `npm run typecheck` と `npm run cloud-lab:compare` を回し、その手順の条件に
加えて、それまでに達成済みの目標が退行していないことを表で確かめる**(調整の循環を防ぐ)。

### 手順 1. 凝結の伝達関数を、飽和しない形へ差し替える(改築・費用ゼロ)

**目的** 被覆率の smoothstep(0.62, 0.80) は幅 0.18 の窓で、総観規模の湿度の振れに対して実質二値化
する。これが「白飽和 14.1% vs 実写厚 0.0%」「塊の内部の平坦さ」「総観規模のパワー過剰」の共通原因。
上端が 1 へ漸近して飽和しない形に差し替え、覆われた空にも湿度の質感が透けるようにする。

**変更が必要な箇所**

| ファイル | 何をするか |
|---|---|
| [condensation.ts](../../../src/render/cloud/condensation.ts) | 47 行の `smoothstep(COVERAGE_ONSET, COVERAGE_FULL, …)` を漸近形へ。候補: t = max(h−onset, 0)/(full−onset) として 1 − exp(−t²)(下端の傾き 0 と上端の漸近を両立、定数は既存 2 個のまま)。形は絵で決める |
| 同上 | 「縁の幅 = 活発度 1 の対流の振れ幅 ±0.12 と同桁」の設計が崩れるので、CONVECTION_GAIN(0.8)を粒の千切れが保たれる値へ取り直す |

**達成条件と検証** `npm run typecheck`。compare で: 被覆率の 0.94 超 ≤ 2%、中間調 ≥ 45%
(55% までは手順 2 の分布調整と合わせて到達)、全球スペクトル(実写厚 vs 被覆率)385 km 以上の
各帯の比が基準から下がる。目視: `.cloud-lab/compare/so-ocean-coverage.png` の cap の雲の内部が
平坦な白でない。`.cloud-lab/compare/typhoon-coverage.png` で螺旋と目が残り、粒が一様な靄に
退化していない。

### 手順 2. 帯状・地域分布の再調整(パラメーターのみ)

**目的** 被覆率の亜寒帯 1.85〜2.36 倍を下げ、亜熱帯 0.2〜0.6 とサハラ 0.12 を底上げする。濃淡の
主因は気圧帯 → 上昇流 → 湿度の経路が強すぎること。薄い雲側は台風域の 2.9 倍を絞り、乾燥域
(サハラ 0.31・層積雲域 0.25)の床を上げる。

**変更が必要な箇所**

| ファイル | 何をするか |
|---|---|
| [weather-model.ts](../../../src/render/cloud/weather-model.ts) | PRESSURE_BAND_AMPLITUDE(8 hPa)↓ か LIFT_HUMIDITY(5)↓ で亜寒帯の過剰を削る。HUMIDITY_BASE(0.246)/ MEAN_CLOUDINESS_WEIGHT(0.5)は**対で**動かす(重みを Δ 動かしたら底上げを −0.690Δ。0.690 は平年の雲量の中央値) |
| 同上 | UPPER_HUMIDITY_BASE(0.227)/ UPPER_MEAN_CLOUDINESS_WEIGHT(0.4)で薄い雲の床と地域差を当てる(上層の移流は独立なので、砂漠上空の巻雲は気象的にも正しい) |
| [condensation.ts](../../../src/render/cloud/condensation.ts) | TRANSLUCENT_ONSET(0.52)/ TRANSLUCENT_GAIN(1.5)を上と一緒に当てる |

**達成条件と検証** compare で: 帯状比(被覆率/実写厚)±60° の全帯 0.5〜1.5(層積雲域 −14〜−31° の
3 帯は手順 6 まで 0.3 許容)、薄い雲/実写薄 6 地域 0.5〜2.0、被覆率の中間調 ≥ 55%。目視: 平年の
雲量ビューと被覆率を並べ、砂漠と海のコントラストが貼り付き(気候図がそのまま出る状態)に
なっていない。

### 手順 3. 中緯度低気圧の巻き込みを強める(パラメーターのみ)

**目的** 実写のオクルージョンは 1〜2 周巻くが、生成は ω·T ≈ 1.4 rad で渦として読めない。巻き込みは
「低気圧の角速度 ω = v/r_c × 移流の周期 T」に比例するので、周期と谷の半径で ≥ π rad へ寄せる。

**変更が必要な箇所**

| ファイル | 何をするか |
|---|---|
| [weather-model.ts](../../../src/render/cloud/weather-model.ts) | ADVECTION_PERIOD(20 h)を 30〜40 h の範囲で試す(伸び全体が一緒に増えるので、背景が筋張らない上限を探す) |
| [cyclones.ts](../../../src/render/cloud/cyclones.ts) | LOW_RADIUS_MIN / LOW_RADIUS_SPAN(800/800 km)を縮めて ω を上げる。LOW_DEPTH(18 hPa)は上げない(上昇流が指数で付いてきて飽和した円盤を書く、実験済みの罠) |

**達成条件と検証** compare で: 全球スペクトル 3384-6769 km 帯(低気圧の規模)の比が 2.6 → 2.0 以下へ
寄り、13537 km 以上の帯の比が下がる。目視: 湿度ビュー(`npm run cloud-lab:shot` の
`humidity-0h.png`)の中緯度低気圧に半周以上の巻き込み。cloud-lab の再生(時刻 0〜72 h)で、位相の
混ぜ目の脈打ち・背景の過剰な筋張りが無い。

### 手順 4. 対流ノイズの細胞化(規模を変えない改築)

**目的** 実写厚の粒は開細胞・閉細胞・網目で、等方な勾配ノイズの斑とは見た目が違う。対流の場の
ノイズに絶対値系の変換(ridged / billowed)を掛けて細胞状の質感にする。評価数は不変なので費用ゼロ。

**変更が必要な箇所**

| ファイル | 何をするか |
|---|---|
| [weather-model.ts](../../../src/render/cloud/weather-model.ts) | 移流前の対流(CONVECTION_NOISE 2 段)を焼く式に変換を入れる。**変換後の平均が 0 に留まる形にする**(例: 1 − 2·\|n\| の段和、または変換後に定数オフセット)— ずれると全球の被覆率が一斉に動く |
| 同上 | CONVECTION_NOISE_AMPLITUDE(0.15)を、変換後の実効振幅が手順 1 の縁と釣り合う値へ取り直す |

**達成条件と検証** compare で: cap 24-48 km / 48-96 km 帯(実写厚 vs 被覆率)の比が北太平洋
0.38/1.13 → どちらも 0.5〜1.5、南大洋 0.51/1.81 も同様。帯状平均が手順 2 の結果から ±0.05 以内。
目視: 収束帯・北太平洋の cap の粒が細胞・網目に見える(見本 `npac-storm-thick.png` の寒気側)。
台風の芯で粒が筋に潰れず残る。

### 手順 5. ノイズのスペクトル傾斜を浅くする(規模を変えない改築・定数 +1)

**目的** 実写厚のスペクトルは浅い傾きで 17 km まで連続に減衰するが、勾配ノイズの段和は振幅 1/2
ずつ(パワー 1/4 ずつ)で急すぎ、湿度場の 212-423 km より細かい構造が一桁弱い。段ごとの振幅比
(persistence)を 0.5 → 0.6〜0.7 に上げ、段数を増やさずに細かい段を持ち上げる。

**変更が必要な箇所**

| ファイル | 何をするか |
|---|---|
| [circulating-noise.ts](../../../src/render/cloud/circulating-noise.ts) | fractalAt の `amplitude.mulAssign(0.5)` を共通定数 OCTAVE_PERSISTENCE へ。端数の段の振幅式(46 行、2 の冪を前提)を persistence の冪へ書き直す — **段数の境目で和が跳ばない性質を保つこと** |
| 同上 | 段和の総振幅が変わるので、正規化するか、weather-model.ts の *_NOISE_AMPLITUDE 4 定数を対で取り直す |

**達成条件と検証** `npm run typecheck`。compare で: 全球スペクトル(実写厚 vs 被覆率)106-212 km
帯の比 0.24 → ≥ 0.4、212-423 km 帯 0.5〜1.5 維持、帯状平均 ±0.05 以内。目視: cloud-lab の cap
半径スライダーを 1〜90° まで連続に動かし、段の出入りで模様が跳ばない(端数段の式の検算)。

### 手順 6. 層積雲の項を凝結に足す(増築・定数 +2)

**目的** 亜熱帯東岸沖の deck(実写厚 0.203〜実写計 0.293 に対し被覆率 0.074)はレジームごと欠けて
いる。沈降域では湿度から差し引くのではなく、平年の雲量が高い場所に限り「低い雲頂の、細胞質感の
板」を出す項を凝結に足す。

**変更が必要な箇所**

| ファイル | 何をするか |
|---|---|
| [condensation.ts](../../../src/render/cloud/condensation.ts) | coverage に層積雲の項を足す。ゲートは沈降(max(−lift, 0))× 湿度の下側の窓(湿度は平年の雲量を既に含むので、気候の条件付けはこれで届くはず)。質感は**焼いてある対流の場を再利用**し(新しいノイズを増やさない)、手順 4 の細胞変換をそのまま使う。上限 0.4 程度に漸近させ、暴風帯の飽和側とは干渉させない |
| [weather-model.ts](../../../src/render/cloud/weather-model.ts) | 湿度の窓では気候の条件付けが足りないと分かった場合だけ、WeatherSample に平年の雲量を素通しで足す(タップは climate 5 タップの中の再利用で済む) |

**達成条件と検証** compare で: 亜熱帯東岸沖 cap の被覆率 0.074 → 0.10〜0.30(実写厚 0.203 の
0.5〜1.5 倍)、被覆率の 0.94 超 ≤ 2% 維持、サハラ・北太平洋・南大洋の平均が ±0.05 以内(漏れの
検出)。目視: 亜熱帯東岸沖の cap に細胞質感の deck(見本 `sepac-subtrop-thick.png`)、雲頂高度
ビューで同じ場所が低い(暗い)。

### 手順 7. 前線帯 — 気圧の谷の異方性(増築・条件付き・定数 +1〜2)

**手順 1〜6 の再計測後、北太平洋・南大洋の cap に伸びた帯構造がまだ見えないときだけ実施する。**

**目的** 実写厚の中緯度でいちばん目立つ「数千 km の細長い雲の帯」は、等方なガウスの谷からは
出ない。谷を移動方向へ伸びた異方形にすれば、風・上昇流・湿度が傾度風の法則を通して一貫に
付いてくる。

**変更が必要な箇所**

| ファイル | 何をするか |
|---|---|
| [cyclones.ts](../../../src/render/cloud/cyclones.ts) | pressureAt の谷を、東進方向の後方へ伸ばした異方ガウス(または 2 中心の重ね)へ。伸ばす軸は既にある移動方向(LOW_DRIFT)から取る |
| — | wind-law・weather-model は変更しない(気圧経由なので自動で追従する) |

**達成条件と検証** compare で全目標(1〜5)維持。目視: 北太平洋の cap に円盤でない帯構造(見本
`npac-storm-thick.png` の前線)。「風」ビューで谷の横切り角が壊れていない(台風の芯で 10° 前後、
中緯度の低気圧で 21〜32°)。気圧の 2 階差分(刻み 0.02 rad ≈ 127 km)より細い峰を作っていないこと
(細いと曲がりが拾えず風が谷を巻かない — 谷の短径を 2 倍の 250 km 以上に保つ)。
