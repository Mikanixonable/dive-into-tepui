# 実写の分離 — 層境界のリファレンス(仮テクスチャ)の現状と残件

## 目的

生成(cloud-generation)と描画(cloud-rendering)の層境界は、**被覆率・雲頂高度・薄い雲(τ)の
3 チャンネル**で、当面変わらない。実写 8k_clouds をこの 3 チャンネルへ推定分離した
「仮テクスチャ」を先に作ることで、

- **下流(描画)** は生成の完成を待たずに、仮テクスチャを入力として実装へ着手できる。
- **上流(生成)** はプロシージャルにこれへ寄せることを責務にできる。

という分担の境界契約を立てる。分離の完璧さは目的ではない — 難が残る部分は上流の実装者への
引き継ぎ注意で足りる。

## 置き場と使い方

- **仮テクスチャ**: `src/assets/cloud-field.png` の 1 枚。R = 被覆率 0..1 / G = 雲頂 0..1
  (= 0..15000 m)/ B = 鉛直光学的厚み τ 0..1 で、**並びは生成側の出力規約**
  (`src/render/cloud/cloud-field.ts` の `CloudField`)**と同じ** — 生成の写しへ差し替えても、
  読む側の成分の割り当ては動かない。正距円筒 4096×2048・8bit(13.6 MB)。v = 0 が北、
  経度原点は 8k_clouds と同じ。
- **読み手**(ゲーム本体と render-lab の両方): R + G は積雲の殻(`src/render/cumulus-shell.ts`)
  と雲影(`sun-occlusion.ts`)、B は `CelestialSurface.clouded` が 1 − exp(−τ) で地表アルベドへ
  焼き込む。描画側の姿は [`../better_graphics/pipeline.md`](../better_graphics/pipeline.md) §2-9、
  生成側に効く契約(二値化の境目・粒・影の光路)は [`improvement.md`](improvement.md)
  「描画側との契約」。
- **再生成**: `npm run cloud-lab:separate`。検分用の veil(巻雲の輝度)と recomposed
  (スクリーン再合成 — 入力と見比べて分離の癖を探す)は `.cloud-lab/separated/` へ出る。
- **目視調整**: `npm run cloud-lab` → http://localhost:8083/separate.html。各段のビュー切り替え、
  スライダー、JSON のコピー/適用欄。規定値は `tools/cloud-lab/separation-pipeline.ts` の
  SEPARATION_PARAMS(すべて uniform なので調整はほぼ実時間)。
- **統計比較**: `npm run cloud-lab:compare`(separate を先に実行)。

## 方法(概要。詳細はコードのコメント)

実写をスクリーン合成 p = veil + thick·(1−veil) とみなした逆算で、GPU(TSL)の多段パス。

1. 構造テンソルの小さい方の固有値 λ2(等方な細かい起伏)が弱い画素を veil 候補に選ぶ
   (指数減衰 — 滑らかでも筋状でも通り、積雲・層積雲の粒だけ落ちる)。
2. 候補の輝度を筋の方向(主固有軸に直交)に沿って伝播・補間し、天井へ非線形に漸近させる。
3. 全画素の輝度のソフト最小値を侵食で広げた「上界」と min を取る — 細かい穴は「そこは veil で
   なかった」証拠として周囲ごと veil を引き下げる。veil ≤ 実写がほぼ保たれ、再合成が崩れない。
4. thick = (p − veil)/(1 − veil)。雲頂は thick の広い濃さ + 細部の増幅による推定。

## 現状評価(`0398ddc9` 時点の実測)

- 実写 0.278 = thick 0.157 ⊕ veil 0.175。再合成は入力に一致。
- veil×thick の相関: 全体 0.691 / 150-600 km 帯 0.596(この 2 値と両平均は GUI と
  `cloud-lab:separate` の出力に常時出る — 調整の相対比較用で、天気そのものの相関があるので
  0 が正解ではない)。
- 目視: veil は低周波 + 筋状の傘、thick は前線・コンマ・粒の場を保持。
  **thick に僅かに巻雲らしい靄が残る**(調整者評)。

**既知の癖 — 生成側はこの仮テクスチャを 100% の目標にしないこと:**

- 高度の次元は原理的に無い。幅の広い明るい帯(前線・かなとこ)は天井超過分が thick 側に乗る。
- 証拠が乏しい(全面が粒の)所は veil 0 に落ちる(保守的)。
- 雲頂高度は輝度からの推定で物理ではない(圏界面の緯度依存なし。底 + 広い濃さ × 利得 +
  細部 × 増幅の 3 定数)。
- 輝度をそのまま被覆率とみなす近似で、sRGB 符号のトーンも未補正。
- 極域(±60° の外)は元テクスチャ自体が信用できない(南極内陸が白く写っている)。
- 上界のソフト最小 + ならしの緩みぶんだけ、雲の穴の中で再合成が僅かに明るくなる。

## 実験の記録: 相関の自動最小化は不採用

座標降下(5 パラメータ、平均 ±20% のガードレール)で帯相関は 0.596 → 0.262 まで下がるが、
下がり方の主因は「veil と thick が共有する靄を veil から thick へ付け替える」ことだった。
本来の目標(thick から巻雲らしさを除く)の逆方向 — **相関は対称な量なのに目標は非対称**なのが
原因で、この目的関数のままの自動調整は採らない。ガードレールは「veil を消して相関だけ下げる」
退化を正しく弾いた(実装のたたき台は残していない。指標の表示だけ残した)。

## 残件候補

- **非対称指標での自動調整**: 「thick 自身の巻雲らしさ」(veil の検出器 — 滑らか/筋状で暗い —
  を thick に適用した応答の総量)を最小化する。「thick へ押し付ける」方向が正しく罰される。
- **雲頂推定の物理化**: 圏界面高度の緯度依存、対流の深さとの対応付け。
- **実写のリニア化**(sRGB 逆変換)と、それに伴う基準値の取り直し(improvement.md の決定 5 と
  セット)。
- **極域の扱いの合意**: 別ソースで補完するか、生成側が極域を独自に決めるか。
- **配信サイズの扱い**: 可逆 8bit 3ch なので 13.6 MB を配信物へ足す(`8k_clouds.jpg` 2.78 MB と
  入れ替わって差し引き **+10.9 MB**)。生成の場へ移れば 0 になる性質のものなので、それまでの
  暫定として許すか、非可逆へ落とすかを決める(`memos/mikanixonable/軽量化/軽量化計画_第五版.md`)。
- 契約(解像度・チャンネル割り当て)が動いたときの再生成と、描画側の読み替えの段取り。
- (必要が出たら)伝播・侵食の反復数の GUI 化(現状はコード内の偶数の定数)。
