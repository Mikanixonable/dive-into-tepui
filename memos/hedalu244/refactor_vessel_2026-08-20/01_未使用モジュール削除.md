以下7ファイルの機能はいずれも**同節に記載がない**(`ペイロード`/`ステージング`/`段間分離`/

## 2. 削除手順

### 対象ファイル一覧(削除)
- `src/game/vessel/payload.ts`
- `src/game/vessel/stages.ts`
- `src/game/vessel/docking-cluster.ts`
- `src/game/vessel/lunar-base.ts`
- `src/game/vessel/habitat.ts`
- `src/game/vessel/module-pick.ts`
- `src/game/vessel/engine-cycles.ts`
- `tests/unit/payload.test.ts`
- `tests/unit/stages.test.ts`
- `tests/unit/docking-cluster.test.ts`
- `tests/unit/lunar-base.test.ts`
- `tests/unit/module-pick.test.ts`

### テストの扱い
- 上記5つの専用テストファイルは削除対象と1対1対応するため、対象ファイルと同時に削除する。
- `tests/unit/advanced-vessel.test.ts` は `engine-cycles.ts`/`habitat.ts` 以外にも
  `facility-runtime.ts`/`aerobraking.ts`/`facility.ts`/`resource-ledger.ts` など生存モジュールを
  扱っているかを個別に確認し、
  - **生存モジュールのテストが含まれる場合**: ファイルは残し、`engine-cycles`/`habitat` に関する
    import と該当テストケースのみを取り除く。
  - **このファイル全体が上記7ファイルのみを対象にしている場合**: ファイルごと削除する。
  実際の判定は削除作業時に `advanced-vessel.test.ts` の中身を読んで行う(このファイルは
  `habitatBalance`/`stepFacilities`/`aerobrakingStep`/`radiatorPerformance`/`ADVANCED_ENGINE_CYCLES`/
  `FACILITIES`/`ResourceLedger` を import しており、少なくとも一部は生存モジュールを扱っている
  可能性が高いため、全削除ではなく部分編集になる見込み)。
- `tests/unit/index.ts` から `registerStages`/`registerPayload`/`registerModulePick`/
  `registerDockingCluster`/`registerLunarBase` の import 文と呼び出し行を削除する。

### 最終確認コマンド(削除前・削除後)
```bash
# 削除前: 本当に src/ から参照されていないことの最終確認
grep -rn "vessel/payload\|vessel/stages'\|docking-cluster\|lunar-base\|vessel/habitat\|module-pick\|engine-cycles" src

# 削除後: 型検査とテストが通ることの確認
npm run typecheck
npm run test:unit
npm run test:physics
```

## 3. 削除の実施方針

CLAUDE.md「改名は痕跡を残さない」原則に準じ、削除は完全に行う。コード・コメント・コミットメッセージ
以外の場所(このメモ含む)にも「かつて実装していた」「削除した」といった経緯を残さない。
`memos/hedalu244/refactoring_todo.md` に本件の項目があれば、完了後は項目ごと消す
(判断根拠は既にこのメモに記録済みのため、CLAUDE.md 側への転記は不要)。

## 要判断事項(ユーザーへの確認が必要)

以下は実装コストの問題ではなく、「この機能を今後実装する可能性があるか」というプロダクト判断が
必要なため、削除実行前にユーザーへ確認する。

1. **7機能(ペイロードベイ・段間分離ステージング・ドッキングクラスタ演算・月面基地適地判定・
   居住区バランス・3Dクリックでのモジュール選択・先進エンジンサイクル)を、今後実装する見込みは
   本当に無いか。** SPEC.md §16 に記載が無いことは「可能性が言及されていない」ことの証拠ではあるが、
   「可能性が無い」ことの証明ではない。特に:
   - `docking-cluster.ts`/`lunar-base.ts`/`habitat.ts` は、CLAUDE.md 記載の「月基地」「ドッキング」
     関連の既存実装(`vessel/base-module.ts`・`game/docking.ts`)と概念的に近く、将来の拡張候補に
     見える。
   - `module-pick.ts` は既存の `assembly-drag-controller.ts`(3D pick で ノード/エッジ/部品を拾う
     実装)と機能が重複・先行実装している可能性があり、単なる死んだ試作か、まだ生かされていない
     設計かの判断が付かない。
2. 上記のいずれかについて「今後も使う可能性がある」との回答があった場合は、CLAUDE.md の指示通り
   `DEVELOP/SPEC.md` §16 へその機能を追記してから、当該ファイルのみ削除対象から除外する。
