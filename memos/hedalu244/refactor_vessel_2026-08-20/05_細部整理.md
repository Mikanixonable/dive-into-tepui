## 5-B. import type記法の不統一

### 事実確認
- `power.ts`(L48)・`thermal.ts`(L66)は関数の引数型注釈でインライン `import('../vessel/vessel').Vessel` を使用。
- `gunnery.ts`は `import { Vessel } from '../vessel/vessel';`(通常のvalue import)だが、`Vessel` は型注釈でのみ使用(`instanceof`等の値としての使用なし)。TypeScriptの自動型onlyインポート除去により実害はない。
- `radiator.ts`/`enemy-ai.ts`は `import type { Vessel } from './vessel';` を先頭で使用。
- **循環の実態**: `vessel.ts` は `power.ts`(`PowerSystem`)・`thermal.ts`(`ThermalSystem`)・`radiator.ts`(`RadiatorSystem`)・`enemy-ai.ts`(`EnemyAi`)をいずれも値としてimportしている。よって `vessel.ts ⇄ power.ts`/`vessel.ts ⇄ thermal.ts`/`vessel.ts ⇄ radiator.ts`/`vessel.ts ⇄ enemy-ai.ts` はすべて循環参照が実在する。
- `tsconfig.json`/`tsconfig.test.json` に `isolatedModules`/`verbatimModuleSyntax`/`importsNotUsedAsValues` の指定なし → `import type` は常にコンパイル時に完全消去される(実行時循環の原因になりえない)。

### 結論
`power.ts`/`thermal.ts` のインライン型import(`import('../vessel/vessel').Vessel`)を先頭の `import type { Vessel } from './vessel';` に書き換えても、型チェック上も実行時循環上も問題は生じない。radiator.ts/enemy-ai.ts と同じ循環構造(`vessel.ts` が value import している)にもかかわらず `import type` で問題なく成立しているのと同条件。

### 変更方法
1. `src/game/vessel/power.ts`: ファイル先頭の import 群に `import type { Vessel } from './vessel';` を追加し、L48の `ship: import('../vessel/vessel').Vessel` を `ship: Vessel` に置換。
2. `src/game/vessel/thermal.ts`: 同様に先頭へ `import type { Vessel } from './vessel';` を追加し、L66の `ship: import('../vessel/vessel').Vessel` を `ship: Vessel` に置換。
3. 他にインライン `import('../vessel/vessel').Vessel` が残っていないか、変更前に両ファイルを全文検索して確認する。
