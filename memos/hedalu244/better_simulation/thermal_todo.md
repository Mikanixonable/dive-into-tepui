# 熱シミュレーションの一般化 — 全個体を温度で扱う

大気の一般化は済んだ(天体ごとのパラメータ・基準楕円体・共回転・密度基準の焼失・抗力由来の
刻み規則)。**残っているのは熱の側だけ**で、熱はいまも自機 1 隻にしか無い。この文書はその
残りを扱う。大局的な目的は `goal.md`。

本文中の数値はすべて `b80f0cf5` のコードで実測したもの。**この文書は計画であって仕様ではない。**
決まったことは `DEVELOP/SPEC/` へ、現状はコードへ書く。

実施の作法: フェーズごとに区切り、各フェーズ末で `npm run typecheck`(`src/physics/` を触った
フェーズは `npm run test:physics` も)が通ること。フェーズ完了ごとにコードレビュー・検証・
コミット。振舞いを変えるフェーズは、書き始める前に `DEVELOP/SPEC/` を直す(`/modify-feature`)。
実施済みのフェーズはこの文書から削除し、やらないと決めたものは `backlog.md` へ移す。

# 第0章 スコープ

**含む**

- **`Simulator` と `GameEntity` の責務の割り直し**(第3章)。熱を全個体へ広げる前に、
  「個体1つを進める」窓口を個体側へ移して `Simulator` を読める大きさに戻す。
- 全 `GameEntity` が温度を持つこと。熱の入り口(空力加熱・衝突・太陽・自機固有の発熱)と
  出口(放射)。
- **エネルギー収支が閉じること** — 物体へ入る熱が、その区間に実際に散逸した力学的エネルギーを
  超えないこと。厳密な全系の追跡はしない(大気側・天体側へ逃げた分は追わない)。
- 密度しきい値による焼失の廃止。焼失を温度一本にすること。
- 発散対策(粗い刻みで抗力が積めない個体の扱い)を、焼失とは**別の規則**として置き直すこと。
- 自機の `ThermalSystem` をその基盤の上へ載せ替えること。

**含まない**

- 熱による部品破壊・性能低下。温度は「上限を超えたら消失」の二値のまま。
- 熱伝導・内部の温度分布。物体は等温の 1 点として扱う。
- **焼失の見た目**。温度に応じた黒体放射・周囲空気の発光は入れたいが、レンダリングの側が
  止まっているので**この計画では触らない**(2-7)。
- 着陸(`design_landing_simulation.md` の担当)。接地した物体の熱は範囲外。

# 第1章 現況 — 何が済み、何が残っているか

## 1-1. 済んだこと(前提。もう手を入れない)

- **大気は天体のパラメータ**(`physics/atmosphere.ts` の `AtmosphereDef`/`Atmosphere`)。
  基準楕円体・自転角速度・区分指数の層を持ち、既定の太陽系では地球だけが持つ。
- **高度は基準楕円体から測る**(`ellipsoidAltitude`)。`R_EARTH` 基準の重複は残っていない。
- **抗力は最も近い大気天体ただ 1 体から**(`nearestAtmosphereBody`)、共回転する大気に対する
  対気速度で掛かる(`airspeed`)。
- **焼失は高度ではなく密度で判定する**(`burnUpBody` + 個体ごとの `burnUpDensity`)。
  `REENTRY_ALT`/`PLAYER_MIN_ALT`/`DEBRIS_REENTRY_ALT` は存在しない。
  **無大気天体には焼失が無い** — `burnUpBody` は `atmosphere === null` の天体を飛ばすので、
  月へ好きなだけ近づける。
- **刻みは抗力から決まる**(`simulation/time-step.ts` の `atmosphericMaxStep`)。剛性の上限
  (λ·dt ≤ `DRAG_STEP_MAX_SPEED_LOSS`)と沈み込みの上限(中間段が密度を e^N 倍以上またがない)の
  小さいほう。`doPreciseReentry` の個体だけがサブステップの内側で細分される(`stepPrecise`)。
- **`dragAccel` は対気速度を反転させない**。1 歩で奪う量を対気速度そのもので頭打ちにする。

**したがって旧計画の Phase 1・2、および「再突入高度の廃止」は実施済み。**

## 1-3. P3 の実測 — いまは「たまたま」安全である

`doPreciseReentry` が false の個体は細分されないので、濃い大気では抗力が刻みに対して剛くなる。
`dragAccel` の頭打ち(λ·dt ≥ 1 で対気速度を消し切る)に触れた歩は、頭打ちが無ければ発散していた歩
にあたる(`tests/perf/exp15`)。**その境界高度と、現行の密度しきい値の対応高度を並べる。**

現行の対応高度: `ENEMY_BURNUP_DENSITY` = 80.0 km、`DEBRIS_BURNUP_DENSITY` = 95.0 km(地球・赤道)。

境界高度 [km](地球・円軌道。**候補A** = `dt > atmosphericMaxStep`、**候補C** = λ·dt ≥ 1):

| ワープ / fps | サブステップ dt [s] | 艦 A / C | 破片 A / C | 弾 A / C |
|---|---|---|---|---|
| ×1 | 20.00 | 52.6 / 47.4 | 59.6 / 54.1 | 33.5 / 28.6 |
| ×16384 低fps | 25.60 | 54.5 / 49.3 | 61.6 / 55.9 | 37.1 / 30.4 |
| ×65536 低fps | 102.40 | **707.1** / 60.0 | **707.1** / 67.4 | **707.1** / 39.6 |
| ×131072 60fps | 34.13 | **137.1** / 51.4 | **137.1** / 58.2 | **137.1** / 32.5 |
| ×131072 低fps | 204.80 | **1527.3** / 65.8 | **1527.3** / 72.7 | **1527.3** / 44.2 |

読み取れることが 2 つある。

1. **現行の 80/95 km は、全ワープ段で候補C の境界(28〜73 km)より外にある。** いま発散しないのは
   地球の大気に合わせて選ばれた数字がたまたま外側にあるからで、他天体の大気では成り立たない。
2. **候補A(`atmosphericMaxStep` をそのまま使う)は採れない。** 沈み込みの上限は密度にも `bcInv` にも
   依らず、円軌道で高度 400 km でも 78.3 s、1000 km で 157.1 s しかない。最高ワープ・低 fps
   (dt = 204.8 s)では**高度 1527 km 以下の全個体が消える** — LEO のデブリが丸ごと消滅する。

沈み込みの上限だけ(密度・`bcInv` に依らない、円軌道):

| 高度 | 200 km | 400 km | 1000 km | 10000 km | 36000 km |
|---|---|---|---|---|---|
| 上限 | 56.8 s | 78.3 s | 157.1 s | 424.5 s | 1098.7 s |

## 1-4. P5 の実測 — いまの受熱はエネルギー保存を破る

Sutton–Graves の受熱は `√ρ·v³`、抗力が散らす力学的パワーは `ρ·v³` に比例するので、**比は 1/√ρ で
増える**。自機(`SHIP_BCINV` = 3.3e-3、`PLAYER_MASS` = 1000、`HEAT_ABSORB_AREA` = 0.9 m²)で:

| 高度 [km] | 60 | 80 | 100 | 120 | 150 | 200 | 420 |
|---|---|---|---|---|---|---|---|
| 受熱 / 散逸 | 0.004 | 0.016 | 0.087 | 0.480 | **2.16** | **6.51** | **70.9** |

**受熱と散逸が等しくなるのは高度 131.7 km。それより上では、抗力が奪った以上の熱が機体に入っている。**
絶対量が小さい(420 km で 158 W、放射冷却の 1 % 未満)ので現行のゲーム挙動には現れないが、
「エネルギー収支を満たす」を要求として立てた以上、これは直す対象になる。

## 1-5. P6 の実測 — 予測弧を辿る間は熱が積まれない

`Simulator.substep` は `followPredicted` が成功した個体を `coarseEntitiesScratch` へ入れずに
`continue` する。そのリストが `stepEnvironment` の対象なので、**予測弧を消費して進んだサブステップ
では熱・電力・ラジエーターが 1 つも進まない。** `Ship` は `predictedForGhost = true` なので自機も
敵もこの経路を通る。

`dd277492`(大気の刻みを抗力から決め、細分をサブステップの外へ出さない)以前は、
`entities.players` を無条件に回していたので全サブステップで進んでいた。**細分の導入に伴う
取りこぼしであり、仕様違反である**(`SPEC/FLIGHT.md`「熱管理」は外殻の熱収支を積分すると定める)。

天体表面への到達は弧自身が `checkSurfaceReach` で打ち切るので、こちらは取りこぼしていない。

## 1-6. P7 の実測 — 質量も半径も熱には使えない

| 種別 | `mass` | `radius` |
|---|---|---|
| 自機 | `PLAYER_MASS` = 1000 | 2.6 m |
| 敵 | 10000 | メッシュのバウンディング球 |
| 弾 | 0.1 | 0.02 m |
| 破片・薬莢 | **0**(試験粒子) | **0 になりうる**(`radius ?? 0`) |
| 弾薬ピックアップ | **0**(試験粒子) | 1.3 m |

`mass` は「剛体接触の換算質量」と明記されたフィールドで、破片・薬莢・弾薬は相手を押さないために
0 を入れている。**熱容量を `mass × 比熱` で出すと、これらの熱容量が 0 になる。** 半径も同じで、
破片は 0 になりうるので `4πr²` から輻射面積を出せない。

## 1-7. P10 の実測 — 細分の内側で天体窓を組み直している

`stepPrecise` は内側の 1 歩ごとに `resolveSurfaceContacts([e], ...)` を呼ぶ。この関数は
**参加者に依らない固定費**(天体窓 101 体の有限判定 + `SurfaceCandidates.reset` の 101 体 ×2 回の
外挿)を毎回払う。1 体のためにそれをやり直している。

| | 内側 1 歩あたり |
|---|---|
| いまの形(毎歩やり直す) | 22,203 ns |
| 問い合わせだけ(窓はサブステップに 1 回) | 243 ns |
| **無駄** | **21,960 ns(91 倍)** |

遠地点 413 km・近地点 55 km の再突入を最高ワープ・低 fps(サブステップ 204.8 s)で降ろすと、
最悪のサブステップで 25 歩(高度 14.0 km)、降下中の平均 7.8 歩。**最悪のサブステップで 0.55 ms、
64 サブステップぶんなら 35 ms/フレームが窓の組み直しに消える。**

これは性能の話に見えて、**責務の置き場所の問題である** — 「この区間に触れうる天体」はサブステップの
持ち物なのに、細分のループがそれを知らないので毎回作らせている。

# 第2章 決めたこと — 7 つの設計判断

## 2-1. 熱は**比量**で持つ。質量も半径も式に現れない

`GameEntity` に持たせるのは次の 5 つ。

```
temperature          [K]           現在温度
specificHeat         [J/(kg·K)]    比熱。0 = 熱を持たない種別
radiatingAreaPerMass [m²/kg]       比輻射面積
emissivity           [-]           輻射率
maxTemperature       [K]           超えたら失われる。既定 Infinity
```

- **`mass` を使わない**理由は 1-6。`specificHeat = 0` が「熱を持たない」を表す(フラグは作らない
  — 大気の `atmosphere?` と同じ方針)。`maxTemperature = Infinity` が既定なので、値を入れない
  種別は焼けない。
- **比量にすると質量が式から完全に消える。** `bcInv = Cd·A/m` が既に比量なので、抗力の散逸も
  空力加熱も比量で書ける。温度の式は
  `dT/dt = (受熱[W/kg] − ε·σ·(A_rad/m)·(T⁴ − T_env⁴)) / c_p` で閉じる。
- **輻射面積を `radius` から導かない。** 破片の半径は 0 になりうる(1-6)。`radiatingAreaPerMass` は
  種別ごとの定数として `game/const.ts` に置く。

## 2-2. 受熱はエネルギー収支から決める。**入る熱は散らした熱を超えない**

入り口は 4 つ。すべて「その区間に散逸した力学的エネルギーのうち、この物体へ入った分」として書く。

1. **空力加熱** — Sutton–Graves(2-6)。**抗力の散逸 `½ρ·s³·bcInv` [W/kg] で頭打ちにする。**
   残りは衝撃波の後ろの大気が持ち去る。
2. **衝突** — 反発で失われる比エネルギー。`½(1−e²)·v_n²` が両者合わせた散逸(比量)で、
   **各側がその半分を受け取る**: `q_side = ¼(1−e²)·v_n²·w_side`(`w` は `collision-response.ts` の
   `shareOfA` がすでに出している逆質量比)。
   - 質量比で配分すると `q = ½(1−e²)v_n²·w_A·w_B` になり、**不動な天体が相手だと両側とも 0** に
     なって、デブリが天体へ衝突しても熱が出ない。半分ずつなら試験粒子が `¼(1−e²)v_n²` を受け、
     天体側の分は追わないまま**合計が実際の散逸を超えない**。
   - 速度変化から出す案(`½|Δv_n|²`)は採らない — 合計が散逸の `(1+e)/(1−e)` 倍(e = 0.4 で 2.33 倍)に
     なり、完全弾性(e = 1)でも 0 にならない。
3. **太陽** — `(1−アルベド)·S·(断面積/質量)·sunlit`。`sunlitFactor` は SRP が**既に払っている**(2-5)。
4. **自機固有** — 射撃・被弾。既存の `pendingHeat` の性質(サブステップ数に依らない一括投入)を
   保ったまま基底へ移す。

**出口は放射だけ**: `ε·σ·(A_rad/m)·(T⁴ − T_env⁴)`。

## 2-3. 焼失は温度一本。密度しきい値は廃止する

`burnUpBody`・`GameEntity.burnUpDensity`・`ENEMY_BURNUP_DENSITY`・`DEBRIS_BURNUP_DENSITY` を
削除し、焼失は `temperature > maxTemperature` だけを見る。
`Enemy` の焼失分岐は死因(`'burnup'`)の記録だけを残して基底へ寄せる。

**判定は細分の内側で行う。** 放射冷却は 1300 K で −96 K/s あるので、サブステップ(最大 204.8 s)の
終端だけを見ると、内側で 1300 K を越えて戻ってきた山を踏み外す。熱を細かく積む理由と同じ理由で、
判定も細かく行う。

## 2-4. 発散対策は**焼失とは別の規則**として、剛性の上限だけで書く

`doPreciseReentry` が false の個体は、**抗力の頭打ちに触れた**(λ·dt ≥ 1)時点で失われる。

- **`atmosphericMaxStep` をそのまま使ってはならない**(1-3 の候補A)。沈み込みの上限は密度にも
  `bcInv` にも依らないので、高ワープでは LEO のデブリを全滅させる。使うのは剛性の項だけ。
- これは物理ではなく**積分器の都合**である。仕様としてもそう書く — 「時間加速がその物体の運命を
  変える」ことを認める代わりに、変わるのは**濃い大気の中にいる物体だけ**、境界は 28〜73 km に
  収まる、と限定する。
- **刻みが十分に短いとき(低倍率)は、先に温度で死ぬ。** 2-6 の平衡温度と 1-3 の候補C 列を
  突き合わせると、破片は 90〜105 km(材質の融点による)、自機は 45〜55 km で限界に達し、
  どちらも候補C の境界(47〜60 km)の外側かそれに接する。
- `doPreciseReentry` は「細分するか」だけを表す属性に戻す。**熱シミュの有無とは相補にしない**
  (`Enemy` が既に反例: 細分するが熱を持たない)。相補性を要求する理由が無い — 細分の可否は費用の
  判断、熱の有無は種別の判断である。

## 2-5. 太陽輻射による加熱は入れる。**費用は既に払われている**

`totalAccel` は SRP のために `sunlitFactor(r, star, occluders)` を **RK4 の 4 段すべてで**、
`srpCoeff ≠ 0` の全個体について呼んでいる。太陽の受熱に要るのはサブステップあたり **1 回**なので、
既に払っている費用の **+25 %** で足りる。弾(`srpCoeff = 0`)だけが新規の支払いになる。

実測: 遮蔽体の窓 101 体で `sunlitFactor` は 942 ns/回。個体 300 なら 1 サブステップあたり 0.283 ms。
**これは SRP が既に 4 倍払っている額である。**

## 2-6. 空力加熱は Sutton–Graves を正本とし、全個体へ一般化する

**一定の η(散逸の一定割合が入る)は採らない。** 判断基準は「物理的に正しく、オーダーとして
無視できないほうを優先する」。Sutton–Graves はよどみ点の対流加熱という実在の機構の相関式で、
一定 η は何の機構も表さない。散逸による頭打ちは**物理的に必要な上限**なので足す。

**曲率半径は一様な球を仮定して `bcInv` と材質密度から導く。** `bcInv = Cd·A/m`、`A = πR²`、
`m = (4/3)πR³ρ_s` より `R = 3Cd/(4·ρ_s·bcInv)`。持つのは材質の量(比熱・密度・輻射率)だけで、
形は `bcInv` が既に運んでいる — 曲率半径を別のフィールドにすると同じ事実が 2 か所に散る。

**実測で現行の自機と一致する。** 材質密度 833 kg/m³(宇宙機の実効密度として妥当)を入れると
曲率半径 0.600 m = 現行の `NOSE_RADIUS`、比受熱面積 9.00e-4 m²/kg = 現行の
`HEAT_ABSORB_AREA/PLAYER_MASS` になる(受熱面積は断面積比の 0.6 倍)。

放射平衡温度 [K] と 受熱/散逸(地球・円軌道。頭打ち適用後):

| 高度 [km] | 自機 T / 比 | 破片 T / 比 | 弾 T / 比 |
|---|---|---|---|
| 50 | 1114 / 0.002 | 2663 / 0.007 | 1917 / 0.002 |
| 60 | 949 / 0.004 | 2266 / 0.013 | 1632 / 0.003 |
| 70 | 815 / 0.008 | 1944 / 0.023 | 1400 / 0.006 |
| 80 | 688 / 0.016 | 1639 / 0.046 | 1180 / 0.012 |
| 90 | 568 / 0.036 | 1344 / 0.101 | 968 / 0.027 |
| 100 | 462 / 0.087 | 1078 / 0.243 | 778 / 0.065 |
| 120 | 328 / 0.480 | 655 / **1.347** | 513 / 0.362 |

破片(アルミ 2700 kg/m³、曲率半径 0.076 m)は、融点 933 K なら約 105 km、鋼の 1700 K なら約 78 km で
限界に達する。**現行の `DEBRIS_BURNUP_DENSITY` = 95 km はその間にあり、材質の融点から自然に
再現される。** 頭打ちは破片で高度 118 km 以上、自機で 132 km 以上に効く。

**弾は熱を持たせない(`specificHeat = 0`)。** `BULLET_BCINV` = 2e-4 は「ほとんど減速しない」ための

## 2-7. 焼失の見た目は変えない

# 第3章 `Simulator` と `GameEntity` の責務の割り直し

**熱を全個体へ広げる前に、ここを片付ける。** P6(弧を辿ると熱が飛ぶ)も P10(細分の内側で窓を
組み直す)も、症状であって原因ではない。原因は **`Simulator` が「個体 1 つを 1 区間進める手順」を
自分の中でばらばらに握っている**ことにある。

## 3-1. いまの形の何が読めないのか

`Simulator`(290 行)が個体ごとに回すループを 4 本持っている。

| ループ | 中身 | 個体どうしの依存 |
|---|---|---|
| `substep` | 重力源の絞り込み → 弧を辿るか積むか → 細分の判断 | **無い** |
| `stepAttitudes` | `att = stepAttitude(att, torque, dt)` | **無い** |
| `stepEnvironment` ループ | 熱・電力・ラジエーター | **無い** |
| `resolveSurfaceContacts` | 天体との接触 | **無い**(SPEC が明記) |

**4 本とも個体どうしに依存が無い。** 依存があるのは物体どうしの接触だけで、それはサブステップの
境界に置くと `SPEC/ORBIT.md` が既に定めている。つまり**この 4 本は 1 本にまとめられる**。

まとまっていないことの帰結が P6 と P10 である。

- `substep` が「弧を辿った個体」を後続のループの対象から外すので、熱が飛ぶ(P6)。
  1 本なら外しようがない。
- `stepPrecise` は 4 本のうち 2 本(積分・環境)と接触を内側で呼び直すが、**窓の組み直しまで
  一緒に呼び直してしまう**(P10)。1 本なら「窓はそのまま、区間だけ細かく」と書ける。

`stepAttitudes` と環境のループは、`Simulator` の責務を 1 つも持っていない — 個体ごとに独立な処理を
`for` で囲んだだけで、囲んだこと自体に意味が無い。

## 3-2. 割り直しの形

**`Simulator` が持つのは「この瞬間に何があるか」と「いつ区切るか」。`GameEntity` が持つのは
「自分を 1 区間進めるとどうなるか」。**

```
Simulator.advance
 └ サブステップの決定(simulationStepDuration / 次イベント時刻)
    ├ この瞬間の天体窓を 1 組だけ組む(重力源の分類・遮蔽体/表面・大気天体・表面候補)
    ├ 個体ごと:
    │   細分数 = e.simulationSubdivision(subDt, 窓)      ← 1 か N
    │   N 回: e.stepSimulation(subDt / N, 窓, ephemeris)  ← 弧を辿るか積む・姿勢・環境・焼失判定
    │         surfaceContactPhysics.resolveOne(e, 窓, activeStage)
    ├ 物体どうしの接触(ここだけが同時性を要求する)
    └ ステージのイベント・回収(cleanup)
```

- **天体窓は 1 サブステップに 1 組。** 細分の内側では組み直さない(P10 の 91 倍が消える)。
  `SurfaceCandidates` の絞り込みは「触れうる相手を落とさない」ことだけが正しさの条件なので、
  サブステップ全体で組んだ窓を内側の短い区間へ使うのは**安全側**である。
- **`GameEntity.stepSimulation(dt, …)` が「弧を辿るか積むか」を内側の分岐として持つ。**
  どちらを通っても姿勢・環境・焼失判定は同じように走るので、P6 は**構造として**起こらなくなる。
- **`stepPrecise` は消える。** 「細分数を答える」と「1 区間進める」に割れば、細分は
  `Simulator` 側の `for` 1 本になる。
- **`resolveOne` を `SurfaceContactPhysics` の公開の口にする。** いまも内部にある関数で、
  1 体ぶんを解くのが本体。リストを受ける口は「窓を組む」ことと混ざっているので分ける。
- `coarseEntitiesScratch`・`preciseEntityScratch` は要らなくなる。

**引数は窓・`ephemeris` を直接渡す。まとめ役のオブジェクト(`*Ctx`)は作らない。** 窓を 1 つの
オブジェクトにするとしても、それは `ArcBodies.resolve` が `{gravity, collision}` を返しているのと
同じ「その瞬間の天体窓」という実体であって、引数の寄せ集めではない。

## 3-3. 受け入れる帰結

- **姿勢が細分の内側で積まれるようになる。** いまはサブステップ 1 回ぶんをまとめて積んでいる。
  細かく積むほうが正確なので劣化ではないが、**答えは変わる**(再突入中の艦の姿勢)。
- **`NanWatchdog` の境界が 4 つから 3 つになる。** いまは 軌道積分 / 姿勢積分 / 天体接触 / 接触 で
  区別できるが、1 本にまとめると前の 3 つが「個体の前進」1 つになる。`backlog.md` 項目 13 は
  この 4 分割を診断の手がかりとして挙げているので、**項目 13 を更新する**。
  姿勢積分は個体の中で完結するので、疑う順序が変わるだけで手がかりを失うわけではない。
- **弧を辿った個体にも天体接触の判定が走るようになる。** いまは弧自身の `checkSurfaceReach` が
  打ち切るので走らせていない。走らせても弧が保証した区間では当たらないが、**弧の窓
  (`mid.collision`)はサブステップの全数窓より狭いので、むしろ取りこぼしが減る**。費用は
  問い合わせ 243 ns/個体。

## 3-4. `Simulator` に残るもの

割り直したあとに `Simulator` が持つのは、**同時性から来るものだけ**になる。

- サブステップの決定(時間送り・次イベント時刻・上限)。
- その瞬間の天体窓を 1 組だけ組むこと。
- 物体どうしの接触とベルト(両者が同じ瞬間にいて初めて意味を持つ)。
- 回収(`cleanup`)と負荷の集計。

これはモジュール冒頭のコメントが既に「二重性はこの 2 点(同時性・刻みの決まり方)に由来する」と
書いていることそのもので、**コメントが主張している構造にコードを合わせる**作業になる。

# 第7章 backlog へ送るもの(この計画ではやらない)

- **焼失の見た目**(2-7)。温度に応じた黒体放射、周囲の空気の発光。レンダリングが動き出してから、
  `memos/hedalu244/better_graphics/` の側で扱う。
- **熱による部品破壊・性能低下。** 温度は「上限を超えたら消失」の二値のまま。
- **熱伝導・内部の温度分布。** 物体は等温の 1 点として扱う。ラジエーターも「面積の上乗せ」であって、
  板自身の温度は持たない。
- **Sutton–Graves 定数の天体依存性。** 金星・火星・タイタンの組成で正しい加熱を出すには定数を
  天体のパラメータへ移す必要がある。`SPEC/ORBIT.md`「未確定の案」に既にある。
- **地球以外の天体の大気の追加。** 現状は地球だけが `atmosphere` を持つ。火星・金星・タイタン・
  木星を 1 層の指数近似で足すのは大気側の作業であって、熱の一般化とは独立。
- **接地した物体の熱。** `design_landing_simulation.md` の 2-3 案A(接地状態)が入ると、
  接地中は積分しないので熱の進め方も決め直しになる。**着陸が先に入ったら、この計画の Phase 4 は
  接地中の扱いを足す必要がある。**
- **非剛体(大気・ガス惑星・プラズマ弾)の接触モデル。** `backlog.md` 項目 14 のまま。
