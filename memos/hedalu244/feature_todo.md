計画軌道を固定し、自機がノードと無関係に計画から逸脱（勝手にthrustした、あるいは曲がり角でthrustしなかった、あるいは蓄積誤差）した場合、警告し「軌道へ戻る／計画破棄」を問う。
また、predictの未来ghostも、「現在視なら表示しない」ということになっているが、予定された現在のプレイヤー位置と実際のプレイヤー位置が異なる場合があるので、適切に判定して表示されるべきだ。

## sfx が鳴る位置を sfx に伝える
マイク位置（activePlayer またはカメラ位置）に応じて音量や定位を調整する。現状は薬莢との衝突音を activePlayer だけが鳴らしているが、これは判定が余計に煩雑になっている。
マイクの概念を追加（マイクの位置はカメラと同等とするか、プレイヤーと同等とするか決めかねるので、どちらからも分離する）物体同士の衝突があったときにはマイクからの距離と向きに応じて音を鳴らす。また、近接通過音もマイクに対する位置に応じて鳴らす（真空中なので本来は無音であるはずだが…）。

## 衝突判定の統一化
実体弾や大気を持たない天体との衝突は船体に対してダメージ、喪失の原因となるが、薬莢との衝突はダメージにならない。これは種別によるものではなく質量と相対速度から定まるものであるから、衝突判定の統一化を行いたい。
薬莢ももし高速で衝突すれば物理的にはダメージになるはずである。
衝突による撃力の計算はphysicsフォルダの責務、撃力をHPに反映するのはgameフォルダの責務である。

hit、collision周りの命名規則の統一もこの時に行う。

`hit` は4つの意味で使われている。(1) 弾丸の命中・被弾(`HitSystem` / `checkBulletHits` /
`hitRadius` / `const.ts` の `*_HIT_*` 十数語。中核は `Ship.attacked`)、(2) 剛体同士の接触
(`SweptSphereHit` / `collision.ts` の `const hit`。中核は `sweptSphereToi`)、(3) 画面上の
クリック当たり判定(`nav-target.ts` / `plan-editor.ts` / `targeter.ts` の `const hit`。中核は
`pickNearest` / `nearestSample`)、(4) 命中までの時間(`enemy.ts` の `timeToHit`)。

(2)(3)(4) はいずれも中核の関数自体が `hit` を含んでおらず、語彙として根を張っていないので
動かすコストは小さい。ただし `feature_todo.md`「衝突判定の統一化」で実体弾・剛体・天体の
接触を1実装へ統合する予定であり、統合すれば語の割り当ても変わる。**実装より先に名前だけ
動かさない** — 統合と同じ変更セットで4つまとめて決める。
