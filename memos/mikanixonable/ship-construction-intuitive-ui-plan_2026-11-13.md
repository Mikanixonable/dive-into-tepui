## 目的

建造は「カタログから手に取り、3D の船体へ置く」操作として既に動いている。船体全体の編集、先端部ごとの
付け替え、回転、対称、複製、設計図、取り消しまで揃っている。足りないのは**機能ではなく、機能への辿り着きやすさ**である。
いまの建造 UI には次の問題がある。

| 観点 | 現状の問題 | 根拠 |
| --- | --- | --- |
| 直感的 | 「置く」状態と「選んで編集する」状態が画面上で区別されない。同じボタン群(回転・端・配置)が状態によって別の対象へ効き、「配置」のラベルは常に同じ | `src/game/hud/panels/ship-construction-panel.ts:203-205, 177`、`src/game/ship/ship-construction.ts:153-160` |
| 直感的 | 置ける場所(接続ノード)は手に持っている間しか出ない。モジュールを選んだだけでは付け替え先が見えない | `src/game/ship/ship-construction-view.ts:249` |
| 直感的 | 候補を指す判定がノード中心への画面距離だけ。モジュールの面を指しても吸着しない | `src/game/ship/ship-construction-pointer.ts:257-263` |
| 直感的 | タップは「直前のフレームで指していた候補」へ置く。指を離すとポインタ位置が消えるので、タップした位置の候補へ置かれる保証がない | `ship-construction-pointer.ts:127-134, 146-150` |
| 直感的 | 手に持ったまま船体をクリックすると、置かずに選択へ切り替わり、手持ちが黙って消える | `ship-construction-pointer.ts:151-158` |
| 直感的 | 置けない理由が 3D 上に出ない(赤い色だけ)。無効な候補の上でドラッグを離すと無言で手放す | `ship-construction-view.ts:261`、`ship-construction-pointer.ts:248-254` |
| 直感的 | どのモジュールが選べるのか、ホバーしても分からない(強調は選択後だけ) | `ship-construction-view.ts:339-350` |
| 機能的 | 右ペインに 手持ち・選択中・候補一覧・性能9項目・履歴・警告・締めのボタン が縦に並び、スクロールしないと「配置」に届かない | `src/game/hud/hud-root.ts:253-296` |
| 機能的 | 狭い画面では「部品」と「性能」が別タブで、カードを手に取ったあと回転・配置のボタンを見るにはタブを切り替える必要がある | `src/game/hud/style/ship-construction-style.ts:164-188` |
| 機能的 | 性能が容量と質量の羅列で、「この船はどれだけ動けるか」(Δv・加速度)が読めない | `hud-root.ts:270-288` |
| 機能的 | `[F]` はヘルプと仕様では「選択中のモジュールへ視点を寄せる」だが、実体は船体全体へ寄せるだけ | `ship-construction.ts:694-697`、`src/game/hud/windows/help-content.ts:195` |
| 美的 | 見出しと性能ラベルだけ英語(`BLD / CONSTRUCTION WORKSPACE`、`MAIN FUEL CAPACITY` 等)で、他は日本語 | `hud-root.ts:237-249, 272-287` |
| 美的 | キー表記をボタン名へ埋め込んでいる(`⟲ [Q]`、`撤去 [DEL]`)。UI-DESIGN.md はキーキャップで隣に添えると定める | `ship-construction-panel.ts:147-177`、`DEVELOP/SPEC/UI-DESIGN.md:152` |
| 美的 | 差分の色が「増=基調アクセント色、減=注意色」。UI-DESIGN.md の HUD の5意味(データ・自分・ターゲット・注意・警告)のどれにも当たらない。質量の増加と推力の増加が同じ色になる | `ship-construction-style.ts` の `.ui-delta[data-delta]`、`UI-DESIGN.md:99-113` |
| 美的 | 対称数のボタンが現在値を持たず(`対称 [X]`)、値は別の行にだけ出る | `ship-construction-panel.ts:150, 201` |

修正後に期待する状態は、次の3文で言える。

- **直感的** — 画面を見れば「いま手に何を持っているか / 何を選んでいるか」「次に押せるものは何か」「どこへ置けるか、置けないなら
  なぜか」が分かる。指した場所へ置かれる。
- **機能的** — 置く・回す・付け替える・撤去するの主要操作が、どの画面幅でもスクロールやタブ切替なしに届く。性能は
  「どれだけ動けるか」まで読める。
- **美的** — 文言・キー表記・色が UI-DESIGN.md の規則に揃い、3D の船体を主役として画面が静かになる。

**仕様は書き換え済み**(`3cec68cb9`)。`DEVELOP/SPEC/` の CONTROLS.md「建造中の操作」、UI-DESIGN.md §8「船体建造」と
「建造中の HUD」、MARKERS.md「建造の接続ノード」、RENDERING.md の建造の項が、この計画の到達点を定めている。以降の手順は
その文面を実装する。

### 範囲に入れないもの

次は今回扱わない。どれも建造を面白くする案として過去に挙がっているが、UI の再構成とは独立に決められる。

- テスト飛行・試射(建造中の時間停止との関係を先に決める必要がある)

- 塗装・進水演出・専用の工廠ビュー

## 変えない挙動

仕様に書かれていて、今回書き換えないもの。全手順のあとで1つずつ当てる。

- 建造の入口は3つ(ドックのクリック/タップ、ドックのプロパティウィンドウ、`[B]`・建造ボタン)。建造中はシミュレーションと
  表示時刻が止まる。(GAME.md 9.3)
- 起点ドックは選べず、動かせず、撤去できない。
- 置いた後も同じモジュールを持ち続ける。候補を選ぶと即座に船体へ反映される。
- 対称配置は側面の新規配置だけで、1つでも置けなければどれも置かない。
- 手持ちが既存のモジュールと体積で重なる位置は置けず、重なる相手が明滅する。
- 健全なコックピットをすべて失う撤去は確認オーバーレイを経て、確定すると建造を終える。
- 「変更をすべて取り消す」は確認オーバーレイを経る。建造終了と ESC は変更を残して閉じる。
- 選択中のモジュールの上から始めたドラッグだけが先端部を掴む。それ以外から始めたドラッグはカメラの回転。
- カードのドラッグ、タッチでのカードの長押し持ち上げ(300 ms)、右クリック・長押しでの手放し。
- キー割り当て(Q/E/R/X/C/Delete/Ctrl+Z/Ctrl+Shift+Z/Ctrl+Y/Tab/1〜6/Enter/F/H/Esc)。
- どの操作にも画面上のボタンがあり、キーボードだけの操作を残さない。
- 候補が無効化または消滅したら、ゴースト・候補表示・ボタン・警告が同じフレームで揃う。
- ゴーストの緑/赤、スナップガイドの円環、差し込みの動き、操作音5種。
- 設計図の保存・改名・削除、履歴の一覧と任意時点へのジャンプ(上限100件)。

**直す挙動**(仕様に無く、実装がたまたま生んでいるもの。直す手順を併記する)。

- タップ/クリックが、押した位置ではなく直前のフレームで指していた候補へ置く → 手順 3。
- 無効な候補の上でドラッグを離すと無言で手放す → 手順 3(理由を出す)。
- 「手放す」ボタンが選択も一緒に解く(名前と挙動の不一致) → 手順 5(状態ごとに「手放す」「選択を解く」へ分ける)。
- `[F]` が船体全体へ寄せる → 手順 7。

## 達成目標

1. 手元バーが、手持ち・選択・どちらも無い、の3状態を文言で言い切り、各状態で表示されるボタンがすべて有効に働く
   (灰色のまま理由が無いボタンが 0 個)。
2. 部品を1つ置くまでの操作が、マウスで「カードを押す → 候補を押す」の2操作、タッチで「カードをタップ → 候補をタップ」の
   2操作で済む。どちらもパネルのスクロールとタブ切替を要さない。
3. タップした位置の候補へ置かれる(直前のホバー位置に依存しない)。
4. モジュールを選んだ時点で、付け替え先の接続ノードが出る。
5. 置けない候補を指すと、理由が 3D 上(ノードの脇)と手元バーの両方に出る。
6. 手に持っている間、船体や空白をクリックしても手持ちが消えない。
7. マウスでモジュールをホバーすると、選べるモジュールが光る。
8. 幅 700 px 未満の画面で、カタログのカードと手元バーと 3D が同時に見える。
9. 性能に Δv と加速度が出て、候補を指すと差分が符号付きで出る。差分に色が付かない。
10. `src/game/hud/` の建造関連ファイルに、英語の見出し文字列(`CONSTRUCTION WORKSPACE`、`3D ASSEMBLY`、`MAIN FUEL CAPACITY`
    など)が 0 件。ボタン名へ埋め込んだキー表記(`[${K.construction`)が 0 件。
11. `[F]` が、選択中のモジュールがあればそのモジュールへ、無ければ船体へ視点を寄せる。
12. `src/game/ship/ship-construction.ts` が、着手時の 993 行より短い。
13. `npm run typecheck`、`npm run test:game`、`npm run test:render`、`npm run check:boundaries`、`npm run smoke:browser` が通る。

### 手順 5. 画面を組み直す

#### 目的

K1・K2・K9・K10・K11 を実装する。主操作を手元バーへ集め、右ペインを3つのタブに分け、文言とキー表記を規則へ揃える。

#### 画面の割り付け

```text
ワイド・中間                                    コンパクト(幅 700 px 未満)
┌────────┬──────────────────┬────────┐          ┌──────────────────┐
│カタログ │                  │船体の状態│          │       3D         │
│ 船名    │       3D         │ 役割     │          ├──────────────────┤
│ タブ    │                  │[性能|候補│          │    手元バー       │
│ カード  │                  │   |履歴] │          ├──────────────────┤
│        ├──────────────────┤ …       │          │ [部品 | 船体]     │
│        │    手元バー       │ 建造終了 │          │ カタログ or 状態   │
└────────┴──────────────────┴────────┘          └──────────────────┘
```

手元バーは建造ワークスペースのグリッドの1セルとして流し込む(絶対座標で置かない)。ガラスの段は左右のペインと同じ

## 却下した案と、残る問題

| 案 | 却下の理由 | 残る問題 |
| --- | --- | --- |
| 未選択のモジュールをそのままドラッグで掴む | 船体の上から始めるドラッグがカメラ回転に使えなくなる。タッチの小画面では1本指ドラッグが回転の唯一の手段 | 付け替えは「選ぶ → ドラッグ」の2段のまま。手元バーの案内とホバー強調で補うが、段数は減らない |
| 候補一覧を廃止する | 仕様が「3D で直接選べない環境のため」に持つと定めている。キーボードだけで候補を選ぶ経路でもある | 一覧は「候補」タブの中に残り、既定では見えない |
| 手に持ったまま ESC で手放す(二段 ESC) | ESC の意味は「入力欄の破棄」と「最前面を閉じる」の2つに固定されている(UI-DESIGN.md §4) | 手放す操作のキーは無いまま(右クリック・長押し・ボタン・カードの再押下で行う) |
| 差分を緑/赤で示す | HUD の5意味に無い色。増減の向きと良し悪しが項目ごとに逆になる | 差分が有利か不利かは、読み手が項目から判断する |
| 接続ノードを 3D の球として描く | 既存の DOM マーカーが「画面上で一定の大きさ」「隠れても消さない」を既に満たしている | ノードは記号のままで、面の大きさや向きは表さない(指している1件だけ円環のガイドが出る) |
