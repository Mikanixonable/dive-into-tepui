### 続行記録（2026-09-23〜24）

Step 1 の取得では、GOES ABI の系列開始・終了を含む 10 分枠だけを選び、各枠の C02/C13 と COD/ACHA/ACTP/ACM がちょうど 1 件ずつ揃わなければ SHA-256 レシートを生成しない。2026-09-24 までに NOAA の必須 9 ケース・405 枠・2430 NetCDF を受領し、hash・時刻・投影・領域の監査を通した。監査で ACM の science field に範囲外の raw 128 が 45 画素見つかり、対応 DQF はすべて 0 だった。これらは品質良好とは扱わず、science field と DQF の積集合 mask から除く。観測指標の地域別分布・絶対許容域と生成画像との照合は未達である。

全枠の地域内画素を製品ごとに集計すると、COD の good DQF かつ有効 science field はケース別に地域格子の約 0.3〜45.9% だった。これは**雲光学厚指標の有効率ではなく**、共通投影・昼夜・雲マスクを適用する前の地域全体を母数とした一次 QC 値である。現行の一律 50% 面積条件をこの値へ直結すれば全ケースが落ちるため、§4.1 の評価可能母数を指標ごとに確定し、無効理由と有効面積を再集計するまでは光学厚の gate を `blocked` とする。

California 2024-05-15 の37枠を独立 ACM の雲クラスへ固定格子 2×2 で対応させた**暫定診断**でも、COD の良品質 science field は雲域の約 1.95% にとどまり、雲域の約 96.9% は COD DQF の「入力欠損・不良」だった。画素中心の 2×2 集計は面積重複・太陽角・雲頂視差を含まないため最終評価値には使わないが、分母の修正だけで 50% へ届くとは見込めない。この系列の光学厚については別の正式製品または独立した観測日・領域を検討し、証拠が揃うまで `blocked` とする。

同じ暫定診断を残りの8ケースにも適用した。独立 ACM 雲域に対する COD 良品質率は、California 2024-07-20 が 1.03%、波状雲 2024-05-28 / 08-25 が 0.38% / 3.79%、深い対流 2024-06-10 / 08-19 が 60.30% / 62.36%、前線 2024-01-18 / 03-05 が 23.06% / 9.38%、地形性雲 2024-06-23 が 41.91% だった。したがって California の日付を既存のもう一例へ替えるだけでは解決せず、波状雲も同様である。一方、品質が異なる系列まで一律に不適格とは判定しない。これらは固定格子画素中心の一次診断であり、面積重複・太陽角・雲頂視差・枠別の支持域を反映した最終 coverage や合否ではない。

NASA CMR 目録では `CLDPROP_L2_VIIRS_SNPP` v1.1 の沿岸セル同日昼間 granule と波状雲同日昼間 granule を特定できた。ただし波状雲の昼間通過は当初の GOES 比較時刻より約 6 時間遅く、同じ雲系の対応を画素と時刻で確かめる必要がある。LAADS 原本 URL の HEAD は 200 を返したが、実際の GET と Range GET は 401 だった。**目録上の存在や HEAD を原本受領とみなさず**、正式な取得経路と認証条件を確認するまで snapshot COD は `blocked` とする。

NASA LAADS の[原本アーカイブ](https://ladsweb.modaps.eosdis.nasa.gov/archive/allData/5111/CLDPROP_L2_VIIRS_SNPP/2019/011/)はダウンロード例に Earthdata Download Token の Bearer 認証を明示し、[S3 直接取得手順](https://ladsweb.modaps.eosdis.nasa.gov/learn/how-to-access-laads-daac-data-files-using-s3-direct-access/)も一時認証情報の取得経路を示す。未認証 GET が失敗した現状で無関係な公開画像を v1.1 原本の代わりに使わない。正規の認証情報を安全に利用できるまでは VIIRS 候補の pixel QA に進めない。

正式な別製品の取得可能性も再調査した。[NASA の CLDPROP C1.1 製品定義](https://atmosphere-imager.gsfc.nasa.gov/continuity/products/cloud/doi-reference)には Aqua MODIS と SNPP VIIRS の同系統 1 km L2 cloud optical properties があり、Aqua の 2024-05-15 California bbox 付近で `CLDPROP_L2_MODIS_Aqua.A2024136.2045.011.2024137153104.nc`（20:45–20:50 UTC）が目録に見つかった。これは GOES と同一センサー/時刻ではないため、認証後の正式原本・画素/QA・雲系の同一性を確認できた場合でも**独立 COD snapshot** に限る。[NASA の LAADS 取得手順](https://ladsweb.modaps.eosdis.nasa.gov/learn/download-files-using-edl-tokens/)は scripted GET に Earthdata token を要求し、この候補への無認証 Range GET も認証画面へ転送された。よって目録上の候補を受領・50%支持域とは数えない。同一製品の [NOAA GOES CODF の別公式 S3 経路](https://www.ncei.noaa.gov/access/metadata/landing-page/bin/iso?id=gov.noaa.ncdc%3AC01508)から取得する案は不足する good 画素を増やさず、公開の [PATMOS-x CDR](https://www.ncei.noaa.gov/products/climate-data-records/avhrr-hirs-cloud-properties-patmos) は約0.1°・日別通過で、10分枠の形態/時系列比較の置換には粗い。後二者は取得可能性と指標適合性を分けて扱う。

描画ラボには雲なし／生成／実写の同一構図を交互に計測し、同一フレームの計測済み GPU pass を合算してから p95 を取る入口を追加した。性能判定の対象 GPU は Apple M4 Pro とする。Headless Chrome 153、960×540、DPR 1、起動時 high 設定での雲なし描画 pass 合計 p95 は試行間で約 39〜79 ms と揺れた。Headed Chrome の pass-level timestamp も得られたが、転送・copy・mip・present 等を含む全フレーム B0 ではない。command-encoder queue marker は Apple Silicon 上で 50 ms 離しても `[0,0]` を返し、この端末には Metal System Trace がない。pass-level 値を全 GPU 時間と呼ばず、§4.5 の**計測範囲を限定した GPU gate**にだけ使う。

近距離 fixture の監査では、従来の `earth-nadir` が地球だけを真下へ動かし、カメラは地平線を向いたままだったことを発見して修正した。250 km・960×540・FOV 50°・medium プリセット（雲 detail は standard）の専用 shot は、対象面で約 432 m/出力 px、2 km 構造で約 4.63 出力 px の投影条件を持つ。ただし medium の `resolutionScale=0.75` を製品と同じ DPR 1 で適用すると内部ラスタでは約 3.47 px / 2 km となり、4 標本条件の画像側にも届かない。DPR と内部解像度を固定して実画面応答を測るまで、C1 の「最小有効間隔の 1/4」の数値と 2 km 合格は `blocked` とする。

その後のコード経路監査では、同 fixture の生成雲は半径約 24.71° の球面 cap を 512 texel 幅で焼き、中心の地表換算標本間隔は約 10.42 km だった。画面の 432 m/px と異なり、**既存の生成場は 2 km を入力として解像できない**。512 cap の単純拡大では 4 標本/2 km に概ね 32768 texel 幅を要し、単一 RGBA8 面だけで約 4 GiB となるため、48 MiB 予算と両立しない。Step 3A の前に局所タイルまたは解析的局所表現を候補として狭い縦切りで検証し、実際の標本間隔と最終画面応答を測る。既存 512 cap の C1 閾値を凍結して 2 km を合格にしない。

C1 ラボ診断は、この shot の実配置と製品 cap 式から中心標本間隔 10,415.8 m、2 km あたり約 0.192 標本、画面上約 4.632 px を計算して記録するようにした。軌跡の解析誤差は約 0.0017 m と別に残すが、生成場の 2 km 応答と C1 全体は `blocked` のままである。性能診断には M4 Pro・8ブロック・全 render query・compute 不在・off/off 誤差・標準近距離 fixture 一致を要求する scoped 判定を追加した。現行の generic earth/high 起動系列は fixture 不一致なので `indeterminate` を返し、全フレーム GPU B0 は `not-measured` のままとする。VIIRS L2 の主光学厚には、公開 Collection 1 定義による品質ビット復号と合成テストを追加したが、v1.1 原本の埋め込み属性と画素で照合するまで実観測の採用には使わない。

その後、計測を `cloud-standard-near-range-250km` shot の medium 設定・960×540 論理画面へ接続した。初回二系列は内部ラスタも 960×540 で、雲ありの増分 p95 が生成雲 56.09 / 58.48 ms、観測雲 38.61 / 41.20 ms だったため、**フル解像度の工学診断**に区別する。render-lab の計測時だけ製品と同じ DPR 1・`resolutionScale=0.75` を適用するよう直し、内部 720×405 を全測定で確認した再測定（Apple M4 Pro、8 ブロック・各 30 フレーム、全 render timestamp 解決）でも、増分 p95 は生成雲 45.99 ms、観測雲 25.74 ms と予算外だった。初回の観測雲経路に一時的な高遅延が見つかったので、生成／観測×雲 off/on の各状態を 30 フレームずつ主計測前に一度だけ捨て計測し、冷準備を別欄へ記録するよう修正した。以後の定常8ブロックでは増分 p95 が生成雲 41.44 ms、観測雲 22.14 ms、off/off 差 p95 が 1.43 ms、1.12 ms、誤差差引後の下限が 40.00 ms、21.02 ms となり、両系統の scoped 3 ms gate は `fail` である。レンズ ON/OFF と雲 ON/OFF の 2×2 診断の差の差は render 合計の p95 が生成雲 30.39 ms、観測雲 16.47 ms、レンズ名の pass p95 は 31.37 ms、19.32 ms だった。これは相互作用の記述値であり、レンズ演算の増分と入力依存待ちをまだ分離しない。全フレーム GPU B0 と CPU・交換時ピークの証拠は未取得である。Step 2A のイベント台帳については、液水と 16 個の放出氷群の総質量および二層風での各軌跡を独立式で検査したが、有限面積の生成場と面積重みが無いため C1 の空間質量 gate は `blocked` のままである。任意時刻 4 点を逆順にも直接再構成する診断では各順の返却イベントは 96 個、輸送の風評価は 15,026 回で一致した。履歴 cache 自体がないため cache miss 数と冷時刻ジャンプの製品上限は未判定で、壁時計値は参考記録にとどめる。VIIRS COD の NetCDF から packed 値・品質属性を読み込む厳格な入口を合成原本で検査したが、公開 file spec の例は v1.0 なので、v1.1 原本の取得・属性確認・画素交差を終えるまで観測比較には採用しない。

2026-09-26 の追加診断では、Apple M4 Pro（`sysctl` 識別）／Chrome WebGPU の Apple Metal adapter 上で、上記の実イベント64×64×2層を描画後に Three WebGPU backend の texture→buffer copy で各層を読み戻した。RG32F の全16,384相別値は CPU upload Float32 bit と一致し、RG16F も全16,384相別 half bit が CPU encode 値と一致した。どちらも相別・層別の bit 不一致0、最大値誤差0、ブラウザ/GPU fatal event 0。返却された生データは RG32F 65,536 byte、RG16F 32,768 byte（この64幅では行ピッチがそれぞれ512/256 byte）。RG16F の正値が零へ丸まった数は下層液水12/862、上層氷8/862でCPU診断と同じ。初回の層1全件不一致は、GPU値でなく比較器が1層のreadbackを全層通算indexで読んだバグと判明し、層内indexへの修正後に再測定した。診断器は今後 bit 不一致を成功扱いせず失敗させる。これは**アップロード後の生テクスチャ値**の検証であり、双線形GPU標本、地理・高度層選択、光路積分、実GPU allocation／転送時 staging／交換ピークの検証ではない。測定JSONはローカルの ignored `.render-lab-shots/cloud-optical-texture-readback/` に出力する。

## 1. 目的と到達範囲

気象衛星と低軌道から見た地球に、現実の雲と同じ生成機序に対応した形状、透明度、鉛直構造、発達と消散を表す。広域の気象配置から数 km のセル・穴・対流塔・繊維までがつながり、動画でも自然に見えることを完成条件とする。

採用するのは、環境の鉛直構造と雲の物質収支を使う縮約モデルである。全球の数値予報や大渦シミュレーションと同等の精度は主張しない。雲系の位置を観測日時へ一致させることではなく、環境条件に対する応答、形態の分布、放射の見え方、時間発展を観測で拘束する。気象量の単位を持つものと、観測から調整した形態パラメータを区別する。

必須形態は、浅い積雲と雲列、海洋層積雲の open/closed cell、深い対流とかなとこ、巻雲、巻積雲・高積雲の鱗状／波状構造、前線の多層雲、熱帯低気圧の雲系とする。地形性の上昇・風下消散も含める。雲中飛行・地上からの見上げ、他惑星の雲、降水粒や雷の可視化は今回の完成条件に含めない。降水・冷気外出流は雲形態へ効く過程として扱う。

### 1.1 Step 1 で仕様へ反映した振る舞い

- 雲の形と大きさは、湿潤層の厚さ、安定度、上昇流、降水、風の鉛直差に応じて変わる。緯度・季節・海陸はその環境の分布を変え、緯線で雲の模様が切り替わらない。
- 対流雲は下層から成長し、上部が水平に広がってかなとこを作る。上層へ放出された氷雲はその高度の流れに従い、親の対流が弱まった後も残存・変形・消散する。低層と上層の風向は同じ場合も異なる場合もある。
- 厚いかなとこの内部、薄い縁、残存する巻雲は連続した濃度と光学的厚さを持つ。氷雲を必ず半透明、液水雲を必ず不透明にはしない。
- 鱗状の小雲塊、波状の配列、繊維状の雲、開いたセルと閉じたセルは、それぞれの環境と形成過程に対応する形として見える。
- 地表側から描く雲、大気内の雲、雲影は同じ立体分布を表し、多層雲の遮蔽、自己陰影、高度による視差、昼夜境界での照明が整合する。
- 通常速度では雲系の成長・輸送・消散が読め、極端な時間加速では時間幅に応じた平均像として自然に変化する。

上記は Step 1 で `DEVELOP/SPEC/RENDERING.md` に反映した。雲と描画品質の関連記述を整理し、上層風向の一律な反転、前線の本数と接続の固定、かなとこの一律な平面化、上層雲の一律な薄さ、海岸線での雲の強制切断、熱帯低気圧の同時個数・必ず温帯化する進路など、観測上の多様性を排除する条件を環境依存の記述へ置き換えた。気候平均を毎時刻の禁止条件にはせず、実装方式・テクスチャ数・GPU パス名は仕様へ書かなかった。

## 2. 設計上の決定

### 2.1 環境、雲の物質、描画用光学量を分ける

最初に定めるのは物理的な意味と更新・導出規則であり、RGBA のチャンネル数ではない。

| 概念 | 最小限必要な量 | 導出・利用 |
| --- | --- | --- |
| 環境プロファイル | 高度 z [m]、気圧 p [Pa]、温度 T [K]、水蒸気比湿 qv [kg/kg]、水平風 u/v [m/s]、大規模上昇速度 w [m/s] | 飽和、浮力、安定度、移流 |
| 放射の境界条件 | 昼夜・太陽入射、下層と上層の温度・湿度、雲の放射特性 | 雲頂の長波冷却と短波加熱 |
| 地表の境界条件 | 海陸、地形、地表温度、熱・水蒸気供給、日変化・季節変化 | 境界層と対流発生条件 |
| 雲の物質 | 液水・氷の質量、同じ相ごとの有効粒径、供給と損失、発生／放出時刻、供給元 | 成長、混相、移流、残存 |
| 雲の形 | 各湿潤層の雲底・雲頂、密度分布、鉛直軌跡、水平変形 | 塔・層・離れたかなとこ・多層構造 |
| 光学量 | 消散係数 [1/m]、単散乱アルベド、位相関数、粒径 | 視線・太陽光路の積分 |

環境は緯度・季節・海陸の prior と、大規模循環・気団・低気圧の偏差から合成する。上下で共通の気象系を持ち、各高度で無関係な乱数風を生成しない。鉛直節点は境界層、逆転層、湿潤層、凍結域、対流流出域を解像する可変配置とし、数を先に固定しない。

Step 2 の実装前の設計 commit で、飽和比湿、仮温度による浮力、凝結高度、対流の平衡高度、逆転層・境界層深さの導出式、境界条件、出典、適用範囲を確定する。CAPE/CIN を名乗る場合は鉛直プロファイルから積分し、単なる活発度の調整値をその名で扱わない。環境は外部から与える縮約場であり、潜熱や降水の全球循環への完全なフィードバックは解かない。雲内の上昇では凝結に伴う加熱と周囲との混合を反映し、乾燥断熱の上昇へ雲水だけを追加しない。環境から雲へ渡す水の供給は収支へ明示し、重なるイベントにも同じ領域・時間の供給を二重配分しない。配分は安定 ID と環境から再構成し、評価順に依存させない。

### 2.2 対流からかなとこへの供給履歴をモデル化する

対流イベントは安定した球面 ID、発生時刻、発生位置、環境に依存する上昇流、上昇中の混合・水相変化を持つ。塔は鉛直軌跡と断面から評価し、すべての高度で同じ二次元 footprint を押し出さない。

上昇流が浮力を失い水平流出する高度で、かなとこへ氷を放出する。対流圏界面は強い安定層として効くが、全対流の雲頂を圏界面へ固定しない。強い対流には有限の overshoot と緩和を許す。水平流出は弱い環境風でも広がり、風下への偏りは環境風と雲系の移動に対する相対速度から生じる。

放出した物質について、以下を同じ履歴から評価する。

- 位置は放出地点から、時間と高度に依存する風・流出速度・沈降速度を積分する。現在の風へ age を掛けるだけで代用しない。
- 液水／氷の変換、凝結・蒸着、蒸発・昇華、降水・沈降を質量の増減として記録する。親から放出した分は親の収支から差し引く。
- 変形は速度勾配と混合から導き、質量を一定に広げれば体積密度が下がる。引き伸ばした分だけ質量を増やさない。
- 親の供給が止まっても残存する。消散速度は温度、相対湿度、粒径に依存する。時間による一律 fade は可視性の数値的な打ち切りに限定する。
- 対流の移動、放出後の物質移流、新しい対流の発生による雲系の伝播は別々に評価する。娘イベントは冷気外出流と環境の不安定・湿潤条件を通して発生させる。

輸送する質量と、表示用の密度変調を分ける。小スケール変調は各イベント／層の水量に整合するよう正規化し、雲の成長をノイズ振幅だけで作らない。かなとこ由来の巻雲に加え、上層の湿潤層内で直接生成する巻雲の供給も別に持つ。

### 2.3 任意時刻から履歴を再構成し、描画履歴へ依存させない

基本方式は、位置・絶対時刻・不変な生成条件から決まるイベントと、その出生／放出からの固定規則による再積分である。全地球の雲セルを永続 CPU オブジェクトにしない。必要領域へ寄与するイベントを索引から列挙し、領域外で生まれて流入する親・放出物も含める。

- 生成 seed、環境の版、地球パラメータ、絶対時刻を生成キーに含める。乱数は安定 ID の hash とし、評価順に依存する PRNG は使わない。
- 積分節点と誤差制御は出生時刻と環境で決め、fps、カメラ、描画品質、前回アクセス時刻で変えない。キャッシュを全破棄しても同じ問いに同じ答えを返す。
- 遡る時間幅は寄与の残量誤差で決める。長寿命の残存氷雲を一定時間で突然切らない。上限外の寄与を残す集約表現も、同じ生成条件から再構成可能にする。
- 親子関係には有限の世代数／継続時間を定め、古い独立した環境強制へ接続する。どの省略も残量誤差と系列統計で検査し、無制限の再帰を作らない。
- 前後二時刻の場は再構成した同じイベントを補間するキャッシュである。異なるノイズ画像のクロスフェードを雲の寿命にしない。
- 地球固定座標で生成し、高度別風は局所接平面から球面上へ積分する。極・日付変更線・タイル境界で ID と軌跡を一致させる。

`render/` が保持するのは表示資源と完全に再生成可能なキャッシュに限定する。純粋な形態生成は表示用の近似として `render/cloud/` 内に置き、時刻問い合わせで再現できない進行状態を追加しない。近似形態を厳密な物理と称して `physics/` へ置かない。Step 2 で再構成の整合性または費用が成立せず永続的な進行状態が必要と判明したら、その時点で方式を再判定する。代替は、immutable な環境入力と物理式を時刻層、再構成不能な雲水・氷水とその履歴をモデル層の一つの所有者、描画への写しを表示導出へ分ける形である。正本の更新は進行位相、直列化は所有者へ置き、任意時刻の表示は所有者の記録・予測から導く。この代替で同じ時刻への再現性を保てない場合は先へ進まない。境界規則や検査を緩めて進めない。

純粋な熱力学・球面輸送の式は時刻層へ分離し、TSL/WGSL 側はその検証済みの式を GPU へ写す。seed・環境版・係数は不変な生成定義として渡し、キャッシュに正本を隠さない。見た目のためのイベント出生分布・形態 kernel は物理層へ入れない。

**配置の例外案:** 人工的な雲模様を生成する `cloud-environment.ts` と `cloud-events.ts` は、物理式を呼ぶ表示用の生成器として `render/cloud/` に置く。この部分は GPU 同期そのものではなく、ARCHITECTURE R2 の装置の責務を越えるため、再現可能という理由だけで規則適合とは扱わない。規則どおりに `game/` の表示導出へ置く場合は、THREE 非依存のイベント宣言を生成して装置へ渡す形になるが、全地球から局所需要へ展開する表示専用の生成器とその GPU 評価を二層へ分割する必要が生じる。Step 2 の設計 commit でこの形の転送量・責務・共有可能な宣言を具体化し、分割しても損なわれないなら規則どおりに配置して変更表も改める。分割が生成式の二重化や装置内部の細部公開を強いる場合だけ、当該二生成器に限定した例外を採る。例外は該当コードに理由付きで明記し、判定があるならその既存の例外機構へ記録して報告する。規則・判定・許可リストは変更しない。物理状態、設定、時刻進行、カメラ履歴による生成変更は例外へ含めない。

### 2.4 雲種と格納形式を切り離す

浅い液水雲、層状・混相雲、深い対流、上層氷雲は、発生源を追跡する分類として使えるが、四つの RGBA 成分へ必ず収める契約にはしない。同じ柱に複数の離れた湿潤層、液水と氷、異なる風で動く構造を共存させる。

すべての寄与に雲底・雲頂または中心高度・厚さと鉛直密度分布を定義する。上層雲自身の高度を親の対流雲頂から独立させ、親が消えても保持する。成分の出入りは質量移送として一度だけ計上する。

Step 2〜3 で候補の疎なイベント表現、少数鉛直基底、タイル化された場を比較し、必要な層の重なり・斜め視線・性能を満たす形式を選ぶ。論理量の独立性、単位、encode/decode の共有は必須。成分数、テクスチャ数、MRT、RGBA16F/RGBA8、2.5D march は手段であり、完成条件にしない。

### 2.5 透明度と明るさは共通の光学評価から決める

有効粒径は相・水量・雲の成熟度に条件付けた観測範囲から導く閉包を Step 2 で選び、粒径分布そのものを解いているとは扱わない。液水・氷それぞれの質量密度／混合比との単位関係を定め、光学・沈降・昇華は同じ粒径閉包を参照する。粒径を変えるために質量を増減させず、供給停止後の粒径・沈降損失・光学的厚さの連鎖を C6 で検査する。液水・氷の量と有効粒径から消散を導き、氷の光学特性には粒形依存の近似を明示する。液水の幾何光学近似では `tau ≈ 3 LWP / (2 rhoWater re)` を基準にし、適用する波長・粒径域を固定する。氷へ同じ係数を無条件に流用しない。

視線透過率は `T = exp(-integral(betaExt ds))`。雲種ごとの不透明度の上限、上層成分の強制的な薄さ、雲量から光学的厚さへの一対一変換を使わない。厚いかなとこの内部から薄い縁・残存巻雲まで連続して扱う。

未解像の被覆率 f と雲内の光学的厚さ tau は別の量とする。単層の基準式は `Tmean = (1-f) + f * exp(-tau)`。複数層の重なりは共通空間サンプルから求め、根拠なく被覆率の積で独立と仮定しない。mip は平均 tau の指数で平均透過率を代用せず、光路方向に応じた近似誤差を測る。

共通密度評価は位置・高度・時刻から消散、散乱、相、密度を返す。地表側の高速近似、大気の積分、影はこれを共有する。雲底／雲頂の範囲だけで積分を絞り、同じ密度の二重描画を避ける。厚い雲には多重散乱の近似、雲同士の影、太陽側の透過を入れる。薄い巻雲は方向性のある散乱を持たせる。明るさを合わせる独立の白色 gain で不足を隠さない。

### 2.6 発生機序ごとに形態を作る

| 形態 | 主な制御因子 | 構造と時間発展 |
| --- | --- | --- |
| 浅い積雲・雲列 | 境界層深さ、湿度、浮力、風のシア | セルの発生消散、条件に応じた列・ロール |
| 閉じた／開いた海洋セル | 逆転層、雲頂冷却、降水、地表供給 | 中心と境界の上昇域の違い、穴の生成と組織の遷移 |
| 巻積雲・高積雲 | 薄い湿潤層、局所的不安定、重力波 | 鱗状の小雲塊、方向・波長のある波状配列 |
| 深い対流 | 浮力、抑制、上昇のきっかけ、混合 | 成長する塔、雲頂バースト、流出への供給 |
| かなとこ・巻雲 | 氷の供給、上層湿度、流出・シア、粒径 | 広がり、繊維化、残存、沈降・昇華 |
| 前線・多層雲 | 温度・湿度の勾配、傾斜した上昇域 | 広い層状域、埋め込まれた対流、乾燥スロット |
| 地形性雲 | 斜面に対する風、安定成層、湿度 | 風上生成・風下消散、条件に応じた風下波 |
| 熱帯低気圧 | 湿潤な渦、収束、鉛直シア | 眼壁・雨帯の対流、上層流出、非対称な雲域 |

緯度からセル径を直接決めない。各形態のサイズ分布は、環境条件で条件付けた観測分布で校正する。降水は open cell の単一の必要十分条件にはせず、雲頂冷却・混合・供給との釣り合いとして近似する。波状雲では物質の風速と波の位相速度を分け、雲が同じ場所で生成消散して見える場合も表す。

海洋セルでは、雲頂の正味長波冷却と短波加熱を温度・湿度・日照・雲の光学特性から診断し、境界層の乱流・連行・水分損失へ結び付ける縮約式を使う。地表フラックスは外部強制、降水・雲頂冷却・混合は雲からの診断として区別する。C8 は冷却、降水、地表供給、連行を一つずつ変える比較に分け、穴率だけでなくセル径・雲量・寿命の条件付き分布を検査する。

波状雲には表示模様と独立した波動 driver を設ける。地形または対流を波源とし、安定度、鉛直構造、水平波数と伝播方向から位相速度・鉛直変位・減衰の縮約関係を定める。湿潤層の上下動による凝結・蒸発を通して雲にする。安定成層の重力波と不安定層のセル対流を区別し、安定度が失われたら同じ重力波式を継続しない。C7 は波源なし、未飽和、安定度変更、物質風のみ変更の対照を含み、波と物質それぞれの軌跡と観測の方向別スペクトルに照合する。式と適用範囲・量的許容域は Step 5 の波状形態を実装する前の独立した設計 commit で選び、結果を見て都合よく決めない。

形態の連続的な混合は必要だが、すべての kernel を全域に少量ずつ足さない。発生条件と水量を先に決め、存在しない雲種に重みを配らない。単一ノイズの閾値・倍率変更で全形態を代用しない。

### 2.7 解像度は地上寸法と投影から決める

標準品質の近距離評価域では 2 km の構造を少なくとも 4 標本で生成・表示する。したがって場を直接標本化する方式では有効間隔を 0.5 km 以下とする。低解像度場の拡大は解像したことに数えない。解析的に生成する方式でも、評価位置・視線積分間隔・画素 footprint を含む応答試験に通す。

広域場と、必要な領域だけを細かくする球面タイルまたは同等の解析的局所表現を使う。フルディスクに近距離と同じ GSD を要求せず、投影後に解像しない構造は面積・透過・散乱の平均へ渡す。cap は可視域の需要を決めるだけで、生成 ID や環境の値を変えない。タイル境界の重複領域と移流の風上領域を確保する。

標準の近距離必須ケースで 2〜8 km 帯を評価対象から外すことは禁止する。1 km 未満の鱗雲要素は今回の解像保証外とし、遠方では小雲塊の分布・配列・被覆の統計として保持する。

## 3. 維持する操作と互換性

- 雲の表示、生成／観測の選択、巻雲・半透明積雲・雲影の表示設定を維持する。
- 積雲の off/coarse/standard/fine は維持する。off は意図的な省略であり、standard の必須機能検査とは分ける。
- 表示設定は物質の生成を変更せず、共通評価結果のどの寄与を描くかを変える。巻雲 off で厚いかなとこまで消えない分類を Step 1 で明文化する。
- 観測雲は adapter を介して静止した分布と外観を維持する。観測から分からない鉛直構造・相は仮定と明示し、気象的な検証の真値へ流用しない。
- 大気散乱・昼夜・露出と統合し、世界位置と表示時刻が同じならキャッシュや視点履歴によって別の雲にならない。

## 4. 全体の合格条件

### 4.1 参照系列と観測条件

海洋セル、深い対流とかなとこ、鱗状／波状雲、中緯度前線と多層雲の四系列を必須とする。熱帯低気圧・地形性雲には別の検証ケースを持つ。各系列に独立した複数の雲系を用意し、調整用と検証用を日付・地域・雲系単位で分離する。近接時刻の別フレームだけを held-out にしない。

通常系列は 6 時間・10 分間隔を出発点とし、対流の立ち上がりには高頻度画像、かなとこ残存には 12〜24 時間の系列を追加する。可視光で比較できない夜間は無効扱いにし、赤外プロダクトによる雲頂・寿命の検証と分離する。可視レンダリング画像の輝度を赤外輝度温度と直接比較しない。

参照 manifest は、出典・ライセンス・取得日時・観測時刻・バンド・処理版・品質 flag・領域・衛星／太陽角・投影・実効 GSD・雲頂視差補正・有効 mask・校正条件を持つ。公開できない原画像は取得手順と検証用 checksum を残す。取得可能性を Step 1A の合格条件にする。製品別の領域全体に対する raw 品質率と、指標の評価可能母数に対する有効率を区別する。COD の評価可能母数は、同時刻の良品質 ACM（DQF=0 かつ science field 有効）の `probably_cloudy`/`cloudy` を COD 格子へ面積重複で対応させた昼間・角度有効領域とする。COD DQF の「晴天につき取得対象外」raw 6 は雲域の証拠に使わず、独立 ACM が雲と判定した領域の raw 14「入力欠損・不良」は欠測として分母に残す。COD の分子は同じ領域で science field 有効かつ DQF good（昼夜ビットを除く品質ビット 0）の面積だけである。雲量指標は別の全有効 ACM 領域を母数とする。母数・最低有効面積・最低有効フレームを観測結果で都合よく下げない。十分な支持域が得られなければ、別の独立観測日・領域または同等の正式製品を取得し直し、その指標を `blocked` とする。

GOES ABI の C02/C13 と COD/ACHA/ACTP/ACM は受領・品質監査する基準系列とし、AHI の仕様値をこれらへ転用しない。**指標の参照製品は分けてよい。** ABI COD が十分な支持域を持たない雲系では、同じ雲系を観測できる NASA VIIRS `CLDPROP_L2_VIIRS_SNPP` などの正式な昼間光学製品を、光学厚の独立した snapshot 参照候補にする。候補 granule の目録上の領域交差だけでは採用せず、原本受領 hash、画素単位の交差、製品固有の品質・太陽角・有効面積を確認してから採用する。極軌道の単一 snapshot に 10 分間隔の系列・lag・寿命を割り当てない。これらの時間指標は GOES の有効な系列で別に判定し、光学厚の独立 snapshot は調整用／検証用を雲系単位で分ける。代替製品が不足する場合は当該指標を `blocked` とし、50% 面積条件を後から下げて通さない。各製品の解像度、時刻、投影、衛星・太陽角、実効 GSD、雲頂視差とセンサ応答を製品メタデータから扱う。画素の採否は science field の `_FillValue`・`valid_range`・列挙値と DQF の両方で決め、DQF=0 だけでは採用しない。ACM の raw 128（受領データで 45 画素）は範囲外として除外し、mask 後の有効面積と欠測率を指標別に記録する。生成側のカメラと照明を観測へ合わせ、単一 RGB を任意の太陽角へ再照明したり、画像ごとに露出を最適化して一致させたりしない。

指標ごとの観測演算子を Step 1 で定義する。(a) 輝度は大気上端のセンサ帯域放射輝度／反射率へ波長応答・太陽角・大気路程を反映して比較する。(b) 光学厚・相・雲頂は同じ定義の物理量を対応する衛星推定プロダクトと比較し、感度が低い層や多層での推定 bias を不確かさへ含める。(c) トーンマッピング済み RGB は形態の検査に使い、放射量の真値にはしない。少なくとも一つの可視帯域について線形の放射出力を用意し、表現できない分光情報を RGB から捏造しない。観測演算子・mask・許容域は一緒に凍結する。可視帯域の大気路程近似は高精度基準に対する誤差と適用する太陽・観測角の範囲を Step 1 で固定し、範囲外の limb・薄明を同じ放射指標で合格にしない。これらの視点の形態・陰影検査は別に維持する。

Step 1A の「取得可能性」は正式原本の受領・hash・製品属性・共同 mask の監査を指す。COD の雲域有効支持率が十分かは、受領・QC と別の**指標別評価可能性ゲート**で判定する。支持域不足でも他の指標と物理・描画の実装は進められるが、COD 比較と「全必須指標で観測適合」の主張は `blocked` のままにする。NASA VIIRS は認証なしの目録・合成ファイル検査を正式原本の代わりにしない。

### 4.2 制御実験による因果関係の検査

| ID | 操作 | 必須の応答 |
| --- | --- | --- |
| C1 | 剛体回転に対応する非発散の球面風、無供給・無損失の有限雲塊 | 解析的な球面移流へ一致し、質量を保存する |
| C2 | 下層を東向きの流れ、上層を北向きの流れにする | 高度別の変位が分離し、放出氷が上層の風下へ運ばれる。風は「吹いていく方向」で指定 |
| C3 | 発達した対流の供給を停止する | 放出済みかなとこが残り、供給停止直後に同時消失しない |
| C4 | 温度と輸送を固定して上層湿度を下げる | 昇華損失が増え、残存氷量・寿命が減る |
| C5 | 地表供給を固定し、境界層上の逆転層を強める | 同じ対流の上昇が抑えられる。深い対流へ自動で貫通しない |
| C6 | 氷量・粒径・厚さを一つずつ変え、供給停止後も追跡する | 質量一定の膨張、粒径から沈降・昇華・光学厚への連鎖が同じ閉包と整合する |
| C7 | 波源・安定度・湿度・物質風を一つずつ変える | 波と物質の軌跡を分離し、波源なし・未飽和などの対照で同じ雲模様が残らない |
| C8 | 海洋境界層の放射冷却・降水・連行・地表供給を一つずつ変える | 参照で拘束した範囲でセルの穴率・組織・寿命が変わる |
| C9 | 低層と上層の二雲層を離して置く | 雲間の空隙、影、視差、異なる風向を保持する |

Step 3A の最小二層 C9 を製品光路へ実装する前の固定診断は、局所接平面で半径 10 km の二円盤を同心に置き、液水層を高度 1–3 km・β=2×10⁻⁴ m⁻¹、氷層を 6–8 km・β=1×10⁻⁴ m⁻¹、3–6 km の空隙を厳密に零とする。中心を通る鉛直光路の解析的相別光学厚は 0.4/0.2、合計 0.6、透過率 `exp(-0.6)=0.5488116361`。鉛直から45°の中心光路では合計光学厚 `0.6/cos(45°)=0.8485281374`、透過率 `0.4280444912`。CPU と GPU の各相・合計光学厚の差は絶対 0.005 以下、空隙内の非零消散と片方の層だけを残した対照で他相の寄与が生じることは許さない。45°の視線・太陽方向で二層の中心高度 2/7 km に対応する地表投影の相対視差・影ずれは解析的に 5 km とし、0.5 km 格子の中心誤差をそれぞれ 0.5 km 以下とする。下層だけ東10 m/s、上層だけ北10 m/s の風を1時間かけた対照では、両層の中心変位は東/北それぞれ36 km、交差軸の偽変位は 0.5 km 以下とする。これは均一な二層の数値・位置ゲートであり、塔、前線多層、観測形態の合格ではない。

C1 の軌跡誤差は、名前付きの標準近距離 fixture（対象の地上位置・カメラ距離と投影・画角・viewport/DPR・standard 品質・評価領域）から算出した**実際の最小有効標本間隔**の 1/4 以下とし、その間隔と数値閾値を測定前に固定する。§2.7 の 0.5 km は標本間隔の上限であり、最小間隔や軌跡閾値そのものではない。相対質量誤差は 1% 以下。供給・損失ありでは `初期質量 + 積算供給 - 積算損失 - 現在質量` の残差の絶対値を、初期質量と総供給の和で正規化して 1% 以下とする。すべての水相で非負性を保ち、負値を clamp して収支誤差を隠さない。空のケースは固定絶対誤差を用いる。誤差床、積分刻み、測定時間を Step 1B の fixture に固定する。

C2〜C9 は一因子ずつ操作する。基準計算は採用式を別の高精度法で評価し、実装自身の出力の写しを正解値にしない。方向・応答符号に加え、量的許容域を解析解、細かい刻みの基準計算、独立した観測系列のいずれかから**各形態の実装前**に固定する。C1〜C6 は Step 2A の輸送・物質・光学の対象、C7/C8 は Step 5 の対象とする。C9 は最小二層の空隙・視差・影を Step 3A の実装前に、前線多層の分布を Step 6 の実装前に別々に固定して判定する。C7/C8 と前線多層 C9 の閾値未確定は Step 3A の単一対流系を止めないが、当該形態を未判定のまま完成に数えない。実装結果を見て期待値を書き換えない。かなとこ面積のピーク時刻など、観測上の傾向は系列分布として比較し、全イベントに同じ順序を強制しない。

### 4.3 画像と動画の評価

雲量、雲内光学的厚さ、形態、時間発展を別々に評価する。可視 RGB から不透明度を正解値として推定しない。光学的厚さ・相・雲頂は品質管理された衛星推定プロダクトと、その不確かさを使う。多層・薄雲・雲縁など推定が不確かな画素は別集計する。

- 2〜8 / 8〜32 / 32〜256 km の空間帯域、方向別パワー、構造のサイズ分布。
- 連結成分の面積、穴率、周長、雲頂の起伏、厚い核と薄い周辺の面積比。
- 校正条件を固定した反射輝度分布、光学的厚さ・相・雲頂の分布。
- optical flow と雲系追跡による移動・変形、成長率、寿命、対流とかなとこの位置差・時間差。
- 時系列を持つ参照に限り、固定座標と移流追従座標の両方で 10 / 30 / 60 / 180 分 lag の相関。単画像の NASA Mawar は形態参照に限定し、時間相関の検証母集団に入れない。

optical flow は発生・消散や多層遮蔽にも反応するため、物理風速の真値とは扱わない。風の正しさは C1/C2 で別に検査する。

各スカラー指標は `D = abs(generated - median(reference)) / max(IQR(reference), uncertaintyFloor)` で正規化する。ヒストグラムには固定 bin の Wasserstein 距離、方向には円周距離を使い、同じスカラー式へ押し込まない。指標・mask・重み・不確かさ床は調整前に manifest へ固定する。

全体完成時は各系列で集約距離を基準実装の 70% 以下、各必須指標を基準より 10% 超悪化させない。各距離には観測の反復・校正誤差から同じ距離空間で評価ノイズ床を定める。基準距離がこの評価ノイズ床以下なら、その指標の相対改善・相対悪化率を要求せず、床以下を維持する。物理単位を持つ uncertaintyFloor と正規化後の距離を直接比較しない。形態ごとに参照の独立雲系間の距離から絶対許容域も固定し、相対改善だけで不自然な結果を合格にしない。基準実装に対応する出力がない新指標は相対比較の対象にせず、観測から固定した絶対許容域を必須とする。欠けた基準を生成 RGB から捏造しない。必須帯域を除外・欠測にして合格数へ数えない。

数値に加え、同条件の画像・動画で、規則的なタイル模様、同時点滅、沸騰するノイズ、塔とかなとこの切断、均一な霞、過剰な縞、雲縁の halo、平面 shell が見えないことを確認する。静止画でのみ細部がある結果は不合格。held-out は調整に使わず、使った時点で別の検証系列を確保する。

### 4.4 解像度、時間、表現間の整合

- 標準近距離の 2 km 入力構造を、生成〜最終画面まで 4 標本以上で扱う。既知形状と周波数 sweep を用い、最終コントラスト・方向性を高解像度基準と比較する。検査画像の拡大で通さない。
- フルディスクや limb の解像しない帯域は footprint に応じて除外可能だが、同じ地上範囲の積分雲量・透過・散乱が高解像度結果を縮小した値と整合する。
- 同じ世界位置・時刻・品質に対して、キャッシュ破棄、カメラ移動、タイル再取得、時刻の正順／逆順／飛び越しで、正規化した密度・透過率の差は `max(2e-3, 測定量子化誤差)` 以下。高度と質量は各単位で別の誤差予算を置く。
- キャッシュ epoch 境界の画像差分 p95 は `max(通常区間差分中央値 * 1.5, 反復撮影で測った絶対ノイズ床)` 以下。実際の発達が境界と重なる場合は、同じ時刻のキャッシュなし基準との誤差で判定する。
- 各論理成分について unit input と混合入力を実 GPU で encode/sample/decode し、漏れは `max(1e-3, 測定量子化誤差)` 以下。成分数にかかわらず、地表・大気・影へ独立に反映される。
- 三描画経路の一致は各光路の高精度基準積分と比較する。異なる方向の光路の二次元 support が一致することは要求しない。雲の三次元 support と高度が共通であることを確認する。

通常時の更新間隔は固定の 2〜5 分へ先に決めず、輸送変位・発達速度・補間誤差から定める。二時刻だけで不足する速い対流はイベントを時刻から直接評価する。極端な時間加速では、中心時刻と時間幅が定義された時間平均を使い、雲面・大気・影で時間標本を共有する。平均密度へ指数を掛けず、各標本で雲・影・下地の相関を保って合成してから平均し、未解像の通過雲を半透明の常設層に変えない。平均像と瞬間像は別の問い合わせで、同じ中心時刻・時間幅なら決定的である。標本不足による逆走を、短寿命構造を無理に追跡することで防がない。

### 4.5 性能・メモリと成立判定

対象 GPU は Apple M4 Pro。Step 1B でブラウザの版、CSS 画面解像度、DPR、内部ラスタ寸法、standard 品質、近距離カメラ、測定系列を固定する。medium・DPR 1 の 960×540 CSS 画面なら `resolutionScale=0.75` を適用した内部 720×405 を計測条件とする。雲なし／雲ありを交互に測り、同一フレームの計測済み描画・compute pass の GPU timestamp、CPU 発行時間、実フレーム遅延、転送量、メモリ、時刻ジャンプの準備待ちを**別の値**として記録する。描画・compute pass を網羅していない系列は GPU gate に使わない。

```text
BcloudScoped = 3.0 ms
BupdateScoped = 2.0 ms
```

標準の定常雲描画に属する計測済み GPU pass の増分 p95 は BcloudScoped 以下、更新フレームの追加 pass 時間 p95 は BupdateScoped 以下を初期目標とする。同じフレーム内で合算してから p95 を取り、pass ごとの p95 を足さない。paired off/off の反復誤差も示し、増分が誤差床へ埋もれる場合は合格・不合格の有意判定を保留する。保守的な増分下限が上限予算を超える場合は、off/off 誤差自体が予算より大きくても `fail` とし、誤差が予算以上の系列を `pass` にはしない。CPU のイベント列挙・履歴再構成・転送・タイル交換、フレーム全体の p95/p99、時刻ジャンプ後の準備待ちは別に測り、雲で増えた遅延と GPU pass 以外の未計測仕事を隠さない。フレーム全体の p95 16.67 ms 以下はアプリ全体の目標として別に報告し、雲なしの時点で超過してもそれだけを理由に雲改修を不合格にしない。基盤側の最適化は別課題として記録する。画質や 2 km 応答を削って性能だけ通さない。

標準の雲所有 GPU メモリはピーク 48 MiB、fine は 72 MiB を初期目標とする。永続分だけでなく、生成中の前後時刻、移流 halo、mip、一時ターゲット、交換時の旧新タイルを含める。CPU のイベント索引・履歴・キャッシュも上限を設定し計測する。概算は `sum(width * height * layers * bytesPerTexel * timeCopies * mipFactor) + buffers + transientPeak`。各候補の実 allocation を Step 3 で列挙する。

この Chrome / Apple Silicon の公開 WebGPU timestamp は、render/compute pass の値を返すが copy/blit と compositor/present を覆わず、試した command-encoder marker も有効な値にならない。全フレーム GPU B0 を取得できない場合は `not-measured` と記録し、**その値を完成の前提にしない**。将来 Metal System Trace 等で実測できれば追加の独立判定に使う。CPU 時間や描画 pass の和を全 GPU 時間へ読み替えない。冷キャッシュ、静止、通常移動、急なカメラ移動、通常時間、高速時間、時刻ジャンプを含めて測る。準備中に別時刻の雲を現在時刻の真値として提示しない。準備待ちの表示と上限は Step 3 で実測して決め、時刻ジャンプを除外した計測だけで完了にしない。

これらの数値は実測前の工学予算であり、視覚目標を削って守る絶対条件ではない。M4 Pro の 250 km・medium 実測で定常 scoped 増分の保守的下限が生成雲 40.05 ms、観測雲 20.51 ms となったため、**3 ms は失敗した初期目標として記録し、Step 3A 試作の着手条件から外す**。最初の局所表現の縦切りでは、同一 250 km 系列に対する新旧 paired 測定で生成・観測の scoped 増分 p95 がそれぞれ現行より 5 ms を超えて悪化しないこと、雲所有ピークの内訳を列挙し暫定 48 MiB へ収まる見通しを示すことを暫定の拡大条件にする。この 5 ms は最終性能合格ではなく、一つ目の試作にだけ許す退行幅である。CPU 発行・実フレーム・タイル交換・時刻ジャンプは別に測り、観測できないものを合格としない。Step 3 で方式・局所表現・最終予算を具体的な測定付きで改訂し、**実装の結果を見た後に閾値を都合よく緩めず**、次の実装・検証より前に判断を記録する。性能判定の対象ハードウェアは Apple M4 Pro から変えない。2 km 解像、因果履歴、多層、共通光学を消して standard と呼ばない。確定した雲の増分予算を Step 7 の最終判定へ使い、アプリ全体のフレーム目標は別に結果を記録する。

## 5. 実施手順

各ゲートは独立してレビュー・必要な修正・検証・commit を行う。実装の依存順は **Step 1A の正式参照受領/QC と Step 1B の比較契約 → Step 2A C1〜C6 の物質／輸送 → Step 3A の局所表現試作 → 単一塔・かなとこ・二層の三描画経路**。観測の支持域不足は該当指標の比較だけを止め、Step 2A/3A の着手を止めない。最小二層 C9 の閾値は二層形態の実装より前に固定する。Step 1C の生成出力との数値比較は Step 3A の出力が存在してから行う。Step 3A は早期の方式成立判定であり全体完成ではない。C7/C8 は Step 5、前線多層の C9 は Step 6 に入る前に各閾値を固定する。性能の最終合格は §4.5 の scoped GPU 増分・実フレーム遅延・転送・メモリ・準備待ちの証拠で判定し、全フレーム GPU B0 の未取得は明記する。実装時はコード規約と層・境界の規則に従い、描画変更では `/rendering-workflow`、ラボの UI 変更では `/ui-design` を適用する。検証は `npm run typecheck` と変更層の回帰テスト。main へ送るときだけ `/send-pr` の全検証を行う。

各描画変更は、固定ケースの before を 2 回撮影してノイズ床を定め、after と比較する。形態改善で意図的に変わる領域と、観測モードなど外観を維持する領域の許容範囲を分ける。画像・動画・計測 manifest はラボの成果物として保存し、コードの現状を説明する文書は作らない。

### Step 3A. 単一対流系の 2 km 構造と全描画経路を実証し、資源方式を確定する

**目的:** 傾いた塔と離れたかなとこを持つ同じ雲を、所要解像度・陰影・予算で描けるか早期に判定する。

方式判定の最初に、既存の連続 3D grain が運べる「雲縁・雲頂の細部」と、512 cap が運べない「独立した 2 km 被覆の穴・小雲塊」を分ける。後者には必要な視野だけへ局所接平面タイルを置く候補を優先し、既存の `CloudFieldSource` と `CloudFieldSampler` を通して地表／大気／影の共通入力へ接続する。250 km fixture の約 414×233 km 視野で 0.5 km 格子なら、1024×512 の RGBA16F 1 面は約 4 MiB だが、二時刻・mip・転送・交換・風上 halo を含むピークは別に実測する。grain の周波数だけを上げて被覆の 2 km 応答を達成したことにはしない。

**画面標本を段階的に判定する:** 現行 250 km・960×540・DPR 1・medium の内部 720×405 では、視野 414×233 km の 2 km 構造は最終ラスタで約 3.47 標本しか持てず、§4.4 の 4 標本を満たせない。250 km のままなら内部ラスタを少なくとも概算 828×466（倍率 0.863 以上）へ上げる必要があり、0.75 比で処理画素は約 1.32 倍になる。局所表現の最初の試作は medium・200 km の専用診断 shot（約 4.34 標本）で始めてよい。これは生成場・sampler・最終画面の 2 km 応答を調べる**実験条件**であり、250 km の製品画質・性能合格の代替ではない。250 km の条件は製品の判定として保持し、内部解像度・視点・品質設定を具体的に選んで再計測するまで `blocked` とする。4 標本条件を結果に合わせて緩めない。

局所タイルの着手条件は、接平面から天体固定座標への写像、cap との合成・継ぎ目、領域外と風上 halo、時刻差分、全光路で同じ `CloudSample` を読む契約を先に決めることとする。1024×512 なら約 0.405×0.455 km/texel で、2 texel halo を含む RGBA16F 一面は約 4.04 MiB、二時刻・staging・mip まで単純に重ねると約 21.5 MiB になるが、既存の全域場・中間面・交換時の重複は含まない。既存 512 cap を拡大補間したタイルでは独立した 2 km 被覆を生み出せないため、物理モデルの状態を局所格子で評価する経路または独立に検証した解析的な局所生成を必要条件とする。座標器だけの未使用モジュールは先行作成せず、共通 sampler への縦切りとともに検証する。最初は地表の単一経路で独立した既知 2 km 被覆を通し、**200 km 診断 shot の native 720×405** の応答、同時刻再現性、境界の継ぎ目を測る。周波数・方向 sweep の高解像度基準と native 画像のコントラスト比、その最低許容値を画像出力を見る前に診断 fixture へ固定し、数値が成立しなければ三経路へ進めない。これは 250 km 画面の合格ではない。大気・影は同じ sampler 契約を保ってから接続する。既に得たレンズ ON/OFF・同期 CPU・GPU timestamp の診断を出発点とし、GPU 演算と待ちを分離できないまま原因を断定しない。3 ms の達成は着手条件にしない。

2026-09-25 の画像出力前に、局所タイルの診断信号と判定を固定する。被覆率は局所東・北座標 [km] に沿う `0.5 + 0.5 cos(2π(east cos θ + north sin θ)/λ)` とし、波数方向 θ は 0°/45°/90°/135°、波長 λ は 1/1.5/2/3/4 km を走査する。高解像基準は同じ解析場を同じカメラ・マテリアル経路で内部ラスタを増やして撮り、native 720×405 へ面積縮小して比較する。主判定の 2 km 波は全4方向で輝度変調振幅が高解像基準の 0.50 以上残ることとする。1/1.5 km は alias と帯域制限の診断、3/4 km は低周波側の連続性確認であり、2 km 主判定の代替にしない。4.34画素/周期の幾何上、理想的な箱平均応答は約0.92だが、0.50は描画・タイル補間の余裕を含む試作ゲートであり、正式250 km画質や物理場の合格ではない。

同日の Step 1B 再集計では、COD-on-ACM の画素中心へ ACM 原本の撮像 UTC と共通 ABI 太陽角式による SZA≤70° mask を適用した。`deep-convection-mexico-2024-08-19` の73枠で、mask 前の評価可能雲域27,951,283画素のうち15,294,802画素を太陽角で除外し、残る画素中心・面積加重 COD good 支持率は44.924%だった。50%の暫定閾値に未達。これは地域境界の多角形 clip、COD/ACM の面積重複、雲頂視差、有効フレーム数をまだ含まない診断値で、最終 COD 指標は `blocked` を維持する。

枠別支持域を独立診断として数えると、同ケースは73枠のうち SZA mask 後に評価可能な雲域が残る39枠、COD good 面積が正の37枠、**暫定50%面積を枠単位で満たすものは0枠**だった。`abi-region.py` の集計結果にもこれらの個数を出すようにした。必要枠数と指標ごとの面積条件はまだ凍結されておらず、この個数を最終合否には転用しない。既存の面積条件のまま COD を時系列の光学厚真値へ使うことはできない。

ACM 四隅を地理 bbox へクリップする境界部分画素の別診断を追加した。Mexico の同じ73枠を再集計すると、従来の中心画素・SZA 面積加重 COD good 率 44.92421256% に対し、bbox 部分重複は 44.92332314% で、差は約 -0.000889 パーセントポイントだった。枠別支持域は引き続き 39/37/0 枠で、50% の不足を境界画素だけでは解消しない。この診断は COD/ACM の画素間面積重複と雲頂視差をまだ扱わず、既存の中心画素 gate を書き換えない。Python 単体テスト25件と実データ開始枠を確認した後、全73枠の再集計を実施した。

COD と ACM の 2×2 入れ子検証は画素中心の一致だけでは不十分なので、画素境界も比較してずれを拒否するようにした。Mexico の実原本1枠では x/y とも境界最大差 7.19×10^-10 rad で、許容 2×10^-9 rad 内だった。これにより固定格子上の親子包含を機械的に確認できるが、地理領域への雲頂視差補正や最終の COD 支持域はなお別ゲートである。

## 6. 工数と再見積もり

以下は実測前の作業分解による幅であり、期限の保証ではない。参照データの待ち時間は含まない。

| Step | 内訳の概算 [h] | 小計 [h] |
| --- | --- | ---: |
| 1 | 仕様 4〜6 + 参照 8〜16 + fixtures/metrics 8〜12 + baseline 4〜6 | 24〜40 |
| 2 | 環境 12〜20 + 収支/履歴 16〜28 + 輸送/再構成 12〜20 + 検証 8〜12 | 48〜80 |
| 3 | 表現/LOD 16〜28 + 光学/三経路 24〜40 + adapter 4〜8 + 計測/検証 12〜20 | 56〜96 |
| 4 | 対流/残存の校正 12〜20 + 親子/輸送 8〜12 + 動画/回帰 8〜12 | 28〜44 |
| 5 | 海洋セル 12〜20 + 鱗状/波状 12〜20 + 校正/検証 8〜12 | 32〜52 |
| 6 | 前線/多層 12〜20 + 渦/地形/広域 12〜20 + 検証 8〜12 | 32〜52 |
| 7 | 最適化/時間加速 12〜20 + matrix 8〜12 + 整理 8〜12 | 28〜44 |
| 合計 | 各 Step の小計の和 | 248〜412 |

Step 2A で履歴再構成の計算量、Step 3A で画素あたり評価数・実 allocation・CPU/GPU 時間から残工数を再見積もりする。表の Step 1 は 1A/1B/1C の合算で、Step 3 は 3A とその後の多形態拡張の合算である。実装費用の式は、`可視タイル数 × texel 数 × 評価イベント数 × 時刻標本数` と `描画画素数 × march 数 × 密度評価費用` を分けて実測係数を入れる。履歴の打ち切り・イベントの上限は観測誤差と最悪負荷の両方で決める。必須形態を削った場合は本計画全体の完了とせず、段階成果として報告する。

## 7. リスクと露出箇所

| リスク | 影響 | 露出・判断する Step |
| --- | --- | --- |
| 環境の代理量へ物理名だけを付ける | 条件を変えても正しい雲が育たない | Step 2、単位・導出式と C4/C5 |
| 供給と残存を補間で代用する | 親塔とかなとこが同時に消える | Step 2/4、C2/C3 と長時間系列 |
| 再構成の過去依存が無限に伸びる | 時刻ジャンプ・冷キャッシュが停止する | Step 2/3、有界化と準備待ち計測 |
| カメラ依存の seed／イベント省略 | 再訪で別の雲になる | Step 2/3/7、破棄・再取得・極境界 |
| 放出元が可視域外で欠落する | 風上タイルから雲が突然現れる | Step 3/4、流入と長寿命ケース |
| 膨張・detail・成分移送で水量が増える | 雲が不自然に厚くなり続ける | Step 2〜4、収支残差 |
| profile が多層・塔の傾きを潰す | 板と切断されたかなとこに見える | Step 3、C2/C9 と斜視・limb |
| 氷を常に薄くする／多重散乱不足 | 厚い核が透ける、灰色か過剰な白になる | Step 3/4、C6 と光学基準 |

| 固定緯度・固定 kernel が形態を支配する | 全球が同じ模様のサイズ違いになる | Step 5/6、環境入替と独立地域 |

## 8. 文献・観測の根拠と使い方

以下は過程と観測条件の根拠であり、上記の実装方式や工学的な許容誤差まで保証するものではない。Step 1〜2 で採用する式・係数ごとの原典と適用範囲を固定する。

- WMO, International Cloud Atlas: [分類](https://cloudatlas.wmo.int/en/cloud-classification-summary.html)、[capillatus](https://cloudatlas.wmo.int/en/species-cumulonimbus-capillatus-cb-cap.html)、[undulatus](https://cloudatlas.wmo.int/en/clouds-varieties-undulatus.html)。形態の同定と、繊維状／波状の区別に使う。
- [A Lagrangian perspective on the lifecycle and cloud radiative effect of deep convective clouds over Africa (2024)](https://acp.copernicus.org/articles/24/5165/2024/)。対流とかなとこの面積・雲頂・寿命の時間差を系列として検証する根拠。
- [Convective controls on anvil cloud evolution in the ICON km-scale global climate model (2026)](https://acp.copernicus.org/articles/26/7105/2026/)。対流の強度・広がりと氷雲への供給を結び付けるモデル検討の根拠。観測真値の代用にはしない。
- [NASA: Open- and Closed-Cell Clouds over the Pacific Ocean](https://science.nasa.gov/earth/earth-observatory/open-and-closed-cell-clouds-over-the-pacific-ocean-43795/)。海洋セルの形態参照と降水との関係。引用元 Stevens et al. (2005), Pockets of open cells and drizzle in marine stratocumulus を Step 2/5 の過程選定で確認する。
- [MODIS Cloud Product](https://modis.gsfc.nasa.gov/data/dataprod/mod06.php)、[光学プロダクトの理論資料](https://modis-images.gsfc.nasa.gov/MOD06_L2/atbd.html)。相・粒径・光学厚・雲頂を分離した観測と不確かさを使う。単一可視画像からの逆算に置き換えない。
- [NASA Cloud Continuity / VIIRS CLDPROP](https://atmosphere-imager.gsfc.nasa.gov/continuity/products/cloud/doi-reference)。GOES ABI COD の支持域が不足する場合の独立した昼間光学厚 snapshot 候補。極軌道 granule を GOES の 10 分系列へ補間して時間指標の真値とはしない。
- [NOAA GOES-R Series 製品資料](https://www.nesdis.noaa.gov/our-satellites/currently-flying/goes-east-west/goes-r-series-data-products)と[ABI L2+ Product Definition and User's Guide](https://www.goes-r.gov/users/docs/PUG-L2%2B-vol5.pdf)。必須 GOES ABI 参照では各 L1b/L2 製品のメタデータと品質 flag を用い、別センサ AHI の公称値を代用しない。

## 9. 完了の定義

制御実験で生成・輸送・成長・消散の因果関係が成立し、独立した観測系列で形態と時間発展が許容域に入り、低軌道の 2 km 構造からフルディスクの分布まで自然に見えること。地表・大気・影の共通光学、観測モードと表示設定、任意時刻の再現性、確定した CPU/GPU・メモリ・準備待ち予算を同時に満たすこと。

型の置換、テクスチャの増設、特定の成分数、統計一項目の改善だけでは完了としない。未計測・欠測・未達を合格へ含めず、画像・動画・収支・時系列・資源の証拠を残して引き渡す。
