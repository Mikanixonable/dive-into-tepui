第4講：Game の中身を読む
――世界・個体・物理・ルールの責務地図

ゲーム進行モデルの正本である Game（src/game/game.ts）の内部構造へ足を踏み入れる。個体管理、多体サブステップ数値積分、太陽系天体、ミッションルールがどのように整然と分担されているかを解き明かす。

1. Game は進行モデルのオーケストレーター

Game クラス自身は、複雑な物理方程式や描画コードを持っていません。時間を進めるための専門サブシステムを束ね、毎フレーム決められた順序で動かすのがその責務です。

2. 1フレームの進行ループ：game.advance()

モデルを進める処理は、advance() の中で次のように無駄なく流れます。 

public advance(dt: number, commands: CommandQueue, pilotControls: PilotControls): void {
  // 1. 出来事ログを空にし、命令を適用する (ポーズ中も命令は消化)
  this.eventLog.clear();
  this.applyCommands(commands);

  // 2. 時間倍率から進めるべきシミュレーション時間 simDt を算出
  const simDt = this.simSpeedManager.stepDelta(dt);
  if (simDt <= 0) return; // ポーズ中は物理とステージを進めない

  // 3. ステージの進行 (敵の湧き、作戦目標の監視、勝敗判定)
  this.stage.update(simDt, this.eventLog);

  // 4. 動的物体の更新 (AIの思考・自機スラスタ推力・多体物理積分)
  this.dynamicSystem.update(simDt, pilotControls, this.eventLog);
}

3. 出来事の伝達役：RunEventLog

モデルと表示のクリーンな疎結合

「敵が撃破された」「弾がシールドに被弾した」「燃料が切れた」といった現象は、物理世界にとっては「そのフレームで起きた一過性の事実」です。

Game はこれを直接画面に描くのではなく、RunEventLog へイベントとして記録します。表示層（GamePresentation）がフレームの後半でこのログを読み取り、対応する爆発パーティクルの発生、効果音の再生、HUDの通知メッセージ表示へと安全に変換します。
