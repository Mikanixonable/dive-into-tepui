# 船の建造：ゲームを面白くする直感的UIの改善案・修正案

作成日: 2026-10-18  
コードのスナップショット: `3737fd7b4`(診断の file:line はこの時点のもの)  
位置付け: **あらゆる前提条件(現行 SPEC・CONTEXT.md の用語定義・MVP 制約・既存アーキテクチャ)を無視してよい**という指示のもとで出した発散案。採用するときは、末尾「覆すことになる前提」を見て仕様側を先に直す。

## 0. 一行で

いまの建造は「**パネルで帳簿をつけると、船が後から生えてくる**」体験になっている。これを「**手で部品を掴んで船にカチッとはめ、その場で船がどう飛ぶか・どこを撃てるかが見え、すぐ試せる**」体験へ反転させる。

## 1. 診断：いまの建造が面白くなりにくい理由

コードから読み取れる事実を、遊びの観点で並べ直したもの。

| # | 事実 | 遊びとしての問題 |
|---|---|---|
| 1 | 入口が「右クリック→船プロパティ→MODULES 一覧→dock のウィンドウ→『船体を建造』」の4段(`src/game/pickable/module-inspection.ts:40-56`, `module-windows.ts:105-113`) | 建造が「隠し機能」になっている。作りたい衝動が入口で冷める |
| 2 | 配置は「リングを1回押して選択→もう1回押して配置」(`src/game/ship/ship-construction.ts:140-156`, 案内文 `hud-root.ts:292`) | 1操作1結果になっていない。部品を「持って置く」手触りがない |
| 3 | 編集できるのはドックから伸びる**1本の枝**だけ。候補は末尾の軸方向1つ + 枝内 cockpit/tank の側面4方向(`ship-construction-rules.ts:62-85`, `ship-construction.ts:303-307`) | 形の決定権がほぼない。誰が作っても「串」になる |
| 4 | 向きは規則が一意に決め、回転・反転・対称の入力口がない(`ship-construction-rules.ts:97-107`) | 「自分が作った」という錯覚が生まれない |
| 5 | 取り消しは「末尾撤去」(LIFO)だけ。任意の部品を外す・付け替える・undo/redo がない(`ship-construction-edits.ts:54-72`) | 失敗が高くつくので試さなくなる |
| 6 | 表示する性能は**建造中の枝の合計**の質量・HP・推力・燃料・発電・放熱だけ。Δv・TWR・重心・推力偏心・射界はない(`ship-construction.ts:372-379`) | 置いた結果の意味が分からない。数字は増えるが「強くなった」実感がない |
| 7 | 干渉判定がない(`placementForSlot` はスロット占有と種別しか見ない) | 物理的に嘘の船が作れてしまい、制約が「要件」として機能しない |
| 8 | 試す手段がない。建造終了→分離→飛ぶ、しか確かめようがない | 作る→試す→直す のループが極端に長い |
| 9 | 建造操作に音・演出がない(`ShipConstruction` に audio 依存なし) | 置いた瞬間の快感がゼロ |
| 10 | 内部 ID がそのまま出る(`建造ドック / module-N`、`construction-3 / 側面 ＋x`。`ship-construction.ts:392`, `ship-construction-rules.ts:50-54`) | 道具ではなくデバッグ画面に見える |
| 11 | ガイドリングの半径は `min(親径,子径)/2`(`ship-construction-candidates.ts:44`)で、径3mのドックなら1.5m。カメラは最低12m離れる | 的が小さく、特にタッチで押しにくい |
| 12 | 建造中に効くキーは ESC だけ(`handleShortcut` 未実装) | 慣れても速くならない |

ゲームデザインメモの言葉で言えば、いまの建造には「**要件が外在し、補助線が引かれているのに、作っているのはプレイヤーだと錯覚させる**」仕掛けが、要件側にも錯覚側にもまだ無い。

## 2. 設計原則

以降の案はすべてこの7つから出している。案を足し引きするときの判定基準にもなる。

1. **3D が主役、パネルは従。** 視線は船に置いたまま作れること。パネルは「選ぶ」「読む」だけにして、「置く」「外す」「回す」は 3D 上で完結させる。
2. **1操作 = 1結果。** 掴む・はめる・外す、がそれぞれ1ジェスチャ。確認を挟むのは取り返しがつかないときだけ。
3. **置く前に分かる。** ホバーした時点で、ゴースト・性能の差分・置けない理由・重心のずれが全部見える。
4. **失敗は安い。** undo/redo、テスト飛行、巻き戻しで「やってみる」の値段をゼロにする。
5. **制約は目に見える要件として出す。** 推力線・重心・射界・反動・日照・放熱視野。「自由にしてよいが、奇妙であるためには理由が要る」を画面上の図形で伝える。
6. **ときめきを演出で保証する。** カチッという音、部品が差し込まれる動き、完成時の発進シーケンス。
7. **繰り返しはツールにする。** 対称・コピー・サブアセンブリ・設計図。同じ操作を3回させたら負け。

## 3. 改善案

規模の小さいものから順に並べる。**A** は今の建造の骨格のまま効くもの、**F** は建造の抽象そのものを作り直すもの。

### A. すぐ効く手触りの修正(骨格は変えない)

#### A1. ドラッグ&ドロップ配置
- カタログのカードを 3D ビューへドラッグすると、ゴーストがカーソルに追従し、近くの候補へ**磁石のように吸着**する。離せば配置。
- クリック派向けに、カードを選んでから候補へ**ホバーするだけで仮選択(ゴースト表示)、1クリックで配置**にする。今の「選択→再クリック」の2段階は廃止。
- 吸着中は候補リングが膨らみ、ゴーストが少し揺れて「ここに入る」を伝える。吸着が外れた瞬間にゴーストは灰色の「浮遊」状態へ戻る。
- 同じ部品を続けて置ける「連続配置」を既定にする(右クリックか ESC で持ち替え解除)。

#### A2. 入口を1手にする
- dock を 3D 上で直接クリック → その場で「ここから建造」の円形メニュー(ラジアルメニュー)。モジュール単体を pickable にする。
- HUD に常設の「建造」ボタン(ショートカット `B`)。押すと最寄りの空き dock へカメラが寄って建造モードへ。
- ESC で抜けた未完成の枝には、3D 上に「建造中」のバッジ(足場のような半透明フレーム)を出し、クリックで再開。

#### A3. 内部 ID を見せない
- 部品は名前と通し番号(「主燃料タンク #2」)、スロットは 3D 上の位置そのもので示す。一覧の「`construction-3 / 側面 ＋x`」は「タンク #2 の上面」に。
- ドック名もユーザーが付けた船名・区画名で出す。

#### A4. 候補を押しやすく・見やすく
- リングを画面上の最小サイズ(例: 44px 相当)で保証する。距離で縮みすぎない。
- リングの代わりに、KSP 型の**接続ノード(光る球)**を基本表示にし、部品を持っている間だけ「この部品が入る所」を強調、入らない所は暗く沈める。
- 遮蔽された候補は、手前の部品を透かして輪郭線で見せる(X 線表示)。

#### A5. キーボード操作
| キー | 動作 |
|---|---|
| `1`〜`5` | カテゴリ切替 |
| `Tab` / `Shift+Tab` | 部品の送り/戻し |
| `Enter` / 左クリック | 配置 |
| `Q` / `E` | 軸まわりのロール(90°、`Shift` で 45°) |
| `R` | 反転(前後) |
| `X` | 対称数の切替(1 → 2 → 4) |
| `Del` / `Backspace` | ホバー中の部品を外す |
| `Ctrl+Z` / `Ctrl+Shift+Z` | undo / redo |
| `F` | ホバー中の部品へカメラを寄せる |
| `Space` | テスト飛行の開始/終了(D1) |
| `H` | 重心・推力線などのオーバーレイ切替(C1) |

画面隅に、いま有効な対称数・回転角・モードを**常時表示**する(KSP の「いま何倍対称か分からない」問題の回避)。

#### A6. 音と手触り
- 吸着: 小さな「カチ」。配置確定: 金属が噛み合う「ガシャン」と、カメラのごく小さな揺れ。外す: ボルトが抜ける音。置けない: 低い短いブザーと、ゴーストが横に小さく震える。
- 部品は瞬間移動で出現せず、0.2〜0.3 秒で接続方向から**差し込まれる**アニメーションで現れる。
- 完成時: 全体が一瞬光り、船名が出る。

#### A7. undo/redo
- 末尾撤去を置き換える。全編集(配置・撤去・回転・付け替え・塗装)を履歴に積む。
- 履歴は画面端に縦のタイムラインとして見せ、任意の時点へ戻れる(TotK の Autobuild 履歴に近い)。

### B. 形を決める自由(編集範囲を広げる)

#### B1. どの部品でも掴める
- 配置済みの部品をクリックで選択、ドラッグで**その部品から先(子孫)ごと持ち上げて**別の場所へ付け替える。
- 中間の部品を外すと、子孫は「浮遊サブアセンブリ」としてゴースト化して手元に残る。置き直すか、破棄するか選ぶ(Cosmoteer の blueprint モードのように、途中で一時的に不整合でもよい)。
- タンクとタンクの間へ割り込み挿入(例: デカプラーを挟む)。接続線にカーソルを当てると「+」が出る。

#### B2. 回転・反転
- 軸接続はロール 90°(細かくても 45°)。TotK が 1° 単位を捨てて 45° に絞ったように、**粗いステップで迷いを減らす**。
- 側面部品は「外向き/内向き」「展開方向」を選べる。

#### B3. 対称配置
- 2 回・4 回の放射対称を最初から用意する(側面4方向スロットと自然に噛み合う)。将来 3・6 方向が入ったら 3・6 回も。
- 対称で置いた部品は「グループ」として一括で外す・塗る。グループ解除も1操作。
- 対称軸は 3D 上に薄い面/軸として常に見せる。

#### B4. コピー・サブアセンブリ・設計図
- 範囲選択 → コピー → 反転貼り付け。
- 「砲塔ユニット」「推進ブロック」など部分構造を名前付きで保存し、カタログの「マイ部品」タブから1個の部品のように置ける。
- 船全体の設計図を保存。ブラウザゲームなので**URL/文字列で共有**できると外で流通する(Factorio のブループリント文字列)。

#### B5. 船体全体を編集対象にする
- 「ドックから伸びる1本の枝」の制限を外し、ドックに繋がっている船体なら全体を編集できる。
- ドックは「建造の起点」ではなく「**部品と資材の搬入口**」という意味付けへ変える(F5 と組み合わせる)。

#### B6. 干渉判定と理由の提示
- 体積がぶつかる配置は赤ゴーストになり、**ぶつかる相手の部品が点滅**する。
- 理由は文で一覧に埋めず、3D 上で原因を指す(Starfield の「未接続モジュールあり」が不評だったのは、原因の場所を指さなかったから)。

### C. 置いた結果が分かる(フィードバック)

#### C1. 重心・推力線・反動の可視化
- 重心(満載)・重心(燃料空)・推力中心を 3D マーカーで重ねる。推力線が重心から外れていると、**回転してしまう向きにトルク矢印**が出る。
- 推力線が重心を貫くとマーカーが「カチッ」と重なって光る。これだけで「2つの点を重ねる」小さなパズルになる(KSP + RCS Build Aid が mod で補った部分を純正で持つ)。
- 燃料が減るにつれて重心がどう動くかを、ホバー中だけ軌跡で見せる。
- **機関砲の反動**: 射撃時の反動トルクを矢印で出し、RCS の総トルクで打ち消せるかをゲージで見せる。デザインメモにある「露出した大砲に RCS がついているだけ」の船を作る動機がここから生まれる。

#### C2. 性能を「どこまで行けるか」の言葉で
- 上部に大きく: Δv、加速度(TWR に相当)、回頭速度、燃焼時間、継戦時間(弾・電力・熱)。
- Δv は数値だけでなく、**行き先のゲージ**に翻訳する。「NRHO → L1 往復 ✓」「月低軌道まで ✓」「地球低軌道 ✗ 残り 320 m/s」。軌道力学を教えずに「肌感覚」で掴ませる、というゲームの芯と一致する。
- 配置前のホバーで、すべての数値に差分(`+120 m/s` を緑、`−0.3 G` を赤)を出す。今の `→ 値 · ±差分` を、色と矢印で一目で読めるようにする。
- 比較する基準を選べる: 「この枝だけ」「船全体」「元の設計と比べて」。

#### C3. 外在する要件をレイヤーで見せる
表示レイヤーを切り替えられるようにする(`H` やボタン)。
- **射界**: 各砲の射界コーン。自船の部品に当たる範囲を赤で。
- **日照/影**: 太陽電池パネルの照射率、自船が落とす影。
- **放熱視野**: ラジエーターが宇宙を向いている割合。
- **排莢・排気**: 空薬莢の排出方向、エンジン排気が自船に当たるか。
- **装甲/HP**: 部品ごとの HP をヒートマップで。

#### C4. 飛行前チェックリスト
- 赤(飛べない)/黄(注意)/緑で集約。例: 「操縦できない(コックピットなし)」「推力が重心からずれている」「RCS 燃料なし」「砲の射界が太陽電池を撃つ」。
- 各項目をクリックすると該当部品へカメラが寄り、部品が点滅する。

### D. すぐ試せる(作る→試す→直す ループ)

#### D1. テスト飛行
- `Space` 一つで、建造中の船を**実物理のテスト空間**へ切り出す(本編の時間は止めたまま)。操縦・射撃・RCS を本物と同じ操作で試せる。
- 標的ドローンや、敵(タンパク質型・組み立て型)の模擬を呼べる。
- もう一度 `Space` で建造画面へ巻き戻る(Besiege の build⇄simulate、KSP の revert to editor)。
- 巻き戻ったとき、**テスト中に壊れた・過熱した・弾切れした部品にマーク**が残る(Poly Bridge の「最初に壊れた部材」マーカー)。

#### D2. その場で試射・試噴射
- 建造画面のまま、部品を右クリック → 「試射」「試噴射」。反動で船が少し回る様子を数秒だけ再生して元へ戻る。

### E. 作ること自体の楽しさ・ときめき

#### E1. 組み付けの演出
- ドックからロボットアームが伸びて部品を運び、溶接の火花が散る。速さは設定で切れる。
- 完成までの組み上がりをタイムラプスで再生できる(SNS に貼れる長さ)。

#### E2. 自分の船にする
- 塗装: 部品ごと/全体の配色、プリセットの配色テーマ(作中の世界観に合わせた民族的な文様など)。
- 船名・識別番号・ノーズアート(デカール)。
- 船名は HUD・マップ・ドッキング時の表示まで一貫して使う。

#### E3. 完成の儀式
- 「建造終了」の代わりに「**進水(発進)**」ボタン。押すとドックのクランプが外れ、RCS で離脱し、カメラが引いて地球と船を一枚の画に収める。
- 初めて作った船の発進だけは特別な演出(BGM の切替など)。

#### E4. 目標と制約で遊ばせる
- 「部品 10 個以内で、敵を 1 体倒して戻ってこい」のような建造チャレンジ。
- 予算・資源・建造時間を入れる場合も、建造画面の上部に「残り資材」バーとして一つだけ見せ、複雑な在庫画面にしない。
- 部品の解禁は「新しい部品が届いた」演出付きで、カタログに NEW バッジ。

### F. 根本の再設計案(建造の抽象を作り直す)

デザインメモの「宇宙船のレゴ/マインクラフトを発明する」「分子模型からアイデアを借りる」「節と梁を作り太らせる」を UI として具体化したもの。A〜E とは独立に検討できる。

#### F1. 結合グラフ式(分子ビルダー)
- 部品を「**原子価(結合の手の数と角度)を持つノード**」として扱う。
  - 直線(2 価)、T 字(3 価)、十字(4 価)、四面体(4 価)、平面六角(6 価)などの**ハブ部品**を導入する。
  - タンク・エンジン・砲などの機能部品は、それぞれ決まった数の手を持つ。
- スナップは格子ではなく**結合角の文法**で決まる。歪みが蓄積しないので、Townscaper のような「格子に見えない格子」を立体で実現できる。
- タンパク質モチーフの敵と、意匠的な韻を踏める(味方は金属の分子模型、敵はタンパク質)。
- UI: 手を持っている部品を掴むと、空いている手から**結合候補の線**が伸びる。近づけると線が太くなり吸着。

#### F2. 骨組み → 自動外装
- プレイヤーは節(ハブ)と梁(トラス)だけを置き、梁の長さは2点を結ぶと自動で決まる。
- 外板・フェアリング・配管・ケーブルはゲームが自動で補間する(Townscaper が建物を自動で生やすように)。
- 外装を「なし/骨組みだけ/フル外装」で切り替えられると、露出したトラス船も、流線型の船も作れる。

#### F3. 主役の部品から作る(要件駆動)
- 最初に「この船で何をしたいか」の主役(砲、大型タンク、ドック、観測機器)を置く。
- ゲームが不足を提案する: 「この砲の反動を打ち消すには RCS があと 2 基必要」「この Δv では L1 まで届かない」。提案は**ゴーストとして置いてあり、クリックで採用、無視してもよい**。
- 「答えは決まっているが、作ったのは自分だと錯覚させる」補助線を、押し付けずに出す方法。

#### F4. 直径クラスと自動アダプター
- 部品を S/M/L の直径クラスに分け、異なるクラスを繋ぐと**アダプターが自動で生える**。KSP の「アダプターを探して挟む」不快な手間を消す。

#### F5. 建造を独立した工廠ビューにする
- 戦闘ビューのオーバーレイではなく、**専用の工廠ビュー**へ移る。背景は基地のドックと地球、照明はスタジオ風。
- 船は台座に固定され、カメラは船の周りを自由に回る(VAB 的)。資材・建造時間・設計図ライブラリ・テスト飛行の入口もここに集める。
- 戦闘中の「応急修理・小改造」は従来どおりその場の小さなオーバーレイで、本格的な建造は工廠で、と役割を分ける。

## 5. 入力デバイス別の操作

| 操作 | マウス | タッチ | キーボード |
|---|---|---|---|
| 部品を持つ | カードをドラッグ / クリック | カードを長押し→ドラッグ | `Tab` で選択 |
| 置く | 候補上で離す / クリック | 候補上で指を離す | `Enter` |
| 回す | ホイール(持っている間) / `Q` `E` | 持ったまま2本目の指でひねる | `Q` `E` |
| 外す | 部品を右クリック→外す / ドラッグして外へ捨てる | 部品を長押し→ゴミ箱へ | `Del` |
| カメラ | 右ドラッグで回転、ホイールでズーム | 2本指で回転・ピンチ | 矢印キー |
| 取り消し | 履歴をクリック | 2本指タップ | `Ctrl+Z` |

タッチでは**部品を持ったままカメラを動かせる**ことを必須にする(LEGO Bricktales が「持ったまま視点を変えられない」で不評だった)。

## 6. 優先順位と段階

| 段階 | 内容 | 効き | 重さ |
|---|---|---|---|
| 1 | A1 ホバー即プレビュー+1クリック配置、A3 ID 非表示、A4 候補の最小サイズ、A6 音と差し込みアニメ | 大(手触りが一変) | 小 |
| 2 | A7 undo/redo、A5 キーボード、A2 入口の短縮、C2 性能バー(Δv・加速・行き先ゲージ) | 大 | 中 |
| 3 | C1 重心・推力線・反動、C4 チェックリスト、B6 干渉判定 | 大(要件が見える) | 中 |
| 4 | D1 テスト飛行と巻き戻し、破損マーク | 最大(ループが閉じる) | 大 |
| 5 | B1 任意の掴み直し、B2 回転、B3 対称、B4 コピー・サブアセンブリ・設計図共有 | 大(形の自由) | 大 |
| 6 | E 系(塗装・進水演出・チャレンジ) | 中〜大(愛着) | 中 |
| 7 | F 系(結合グラフ・自動外装・要件駆動・工廠ビュー) | 未知数(作品の顔になりうる) | 最大 |

段階 1〜3 だけでも「帳簿」から「工作」へ体験が変わる。段階 4 のテスト飛行が入ると、建造が戦闘とつながってゲームのループになる。F 系は試作で手触りを確かめてから判断したい。

## 7. 覆すことになる前提(採用時に先に直すもの)

| 案 | 覆す前提(現行の記述) |
|---|---|
| B5 船体全体の編集 | CONTEXT.md「統合船体の建造」: 一回の建造セッションでは選択 dock から伸びる一枝だけを編集する |
| B1 任意の撤去・付け替え | 同上: 撤去は各分岐の自由端から行う |
| A2 入口の拡張 | 建造の入口は `dock` だけ(`ShipConstruction.start()` が `kind !== 'dock'` を拒否) |
| B3 対称 3・6 回 / F1 結合グラフ | CONTEXT.md「側面アンカー」: 4 方向の離散スロット、3・6 方向は将来仕様 |
| B2 回転 | 配置の transform は規則が一意に決める |
| F4 直径クラス | CONTEXT.md「構造接続edge」: 近い直径の円柱を長軸方向に接続 |
| F5 工廠ビュー | 建造は戦闘ビュー上のオーバーレイ(`ship-construction-mode`) |
| E4 資源・時間 | 旧メモで「資材在庫・消費量・建造時間」は現行仕様の外とされている |

## 8. 設計者に決めてほしいこと

1. **自由度と非自由度のどちらから入るか。** B(自由な形)を先に広げるか、C(要件の可視化)で「制約の中で工夫する」遊びを先に作るか。デザインメモの思想からは C 先行を推す。
2. **ドックの意味。** 「建造の起点」のままにするか、「資材の搬入口」にして船体全体を編集可能にするか(B5/F5)。
3. **テスト飛行はどこまで本物か。** 本編と同じ物理・同じ敵で試せるのか、簡易な標的だけか。巻き戻しをゲーム内で正当化するか(シミュレーター設定など)。
4. **F1 結合グラフを試作するか。** 作品の顔になりうる一方、部品の定義・描画・物理の全部に波及する。小さな試作(ハブ部品 3 種 + トラス)で手触りだけ先に見る、を提案する。
5. **資源・建造時間を入れるか。** 入れるなら、建造画面では「残り資材」一本だけ見せる方針でよいか。
