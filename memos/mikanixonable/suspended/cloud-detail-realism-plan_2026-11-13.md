# 雲の細部のリアリティを上げる計画 — 多尺度の計測ループ・積雲と巻雲の細部・巻雲の影

起点の commit: `d5f696b35`(行番号付きの参照はこの時点のもの)。

## 目的

低軌道から見た雲の細部が現実に見えない。原因は2つで、どちらも「場の texel(低軌道の cap で約 10 km)より
細かい尺度」にある。

- **積雲はワンパターン。** texel より細かい起伏は、一辺 6 km の勾配ノイズ 1 オクターブだけ
  (`src/render/cloud/cumulus-shape.ts` の `CUMULUS_GRAIN_SIZE`、`src/render/cloud/cloud-shape-evaluator.ts`
  の `grainAt`)で、振幅も場所によらず一定。どこを見ても同じ大きさの粒が同じ強さで並ぶ。
- **巻雲は粗い。** 巻雲の殻(`src/render/pipeline/cloud-atmosphere-renderer.ts`)は場の G を双線形で読む
  だけで、texel より細かい構造を一切持たない。筋(繊維)も無い。

現実の雲は、数百 m から数千 km までどの尺度にも濃淡があり(反射率のスペクトルは 0.4〜20 km 以上で
おおむね k^−5/3)、しかも細かい尺度ほど濃淡が場所ごとに偏る(間欠性)— 千切れた縁では細部が強く、
板の内部では弱い。これを「大中小すべての尺度での緩急」と呼ぶ。

この計画は次の4つを満たす。

1. **計測とフィードバックのループを作る。** 描画された雲の画像と、同じ km/px の衛星実写
   (NASA Worldview の 250 m 真色)を同じ物差しで比べ、尺度ごとの距離を数値で出し、履歴に残して
   前回との差を示す。大きい尺度(25〜800 km)は既存の `cloud-lab:compare` が担っているので、
   そこへ 0.5〜500 km を足して、尺度の梯子を 1 本につなぐ。
2. **積雲の細部を多尺度・間欠的にする。**
3. **巻雲に、上層の流れに沿った繊維状の細部を足す。** 筋の向きは雲場に焼く。
4. **巻雲の影を設定ごと仕上げる。** 光路の消散そのものは `d5f696b35` で
   `src/render/pipeline/shadow/cloud-shadow-renderer.ts` に入っているが、影の有無は
   「積雲の影」設定と「積雲の精細さ ≠ オフ」に縛られていて、巻雲だけを描く設定では影が落ちず、
   巻雲をオフにしても巻雲の影が残る。これを「雲の影」設定へ統合して直し、細部とも一致させる。

### SPEC への追記(`03f2ffb88` で `DEVELOP/SPEC/RENDERING.md` へ入れた)

「雲の描画」節の「**雲頂は低い雲の海に柱が立つ形をとる。**」の項の直後へ:

> - **細部はどの尺度でも同じ模様を繰り返さない。** 数百メートルから雲塊の尺度まで、どの尺度にも
>   濃淡があり、ひとつの大きさの粒が一様に並んだ空には見えない。細かい尺度ほど濃淡は場所ごとに
>   偏る — 千切れた縁・塔の頭・雲の少ない空では細部が強く、厚く覆った板の内部では弱い。
>   雲塊の大きさは連続に散り、小さな雲ほど数が多い。
> - **巻雲は繊維でできている。** 上層の流れに沿って伸びた筋と、筋を束ねた帯が、低軌道から見下ろして
>   解像できる細かさ(数百メートル)まで続く。筋の向きはその場所の上層の流れに従い、渦のまわりや
>   板の縁では曲がる。
> - **細部を足しても、広い尺度で見た濃さは変わらない。** 細部は雲場の濃さを場所ごとに配り直すだけで、
>   数十キロの範囲で均した濃さ・被覆は粗い雲場と一致する。雲の無い所に細部だけで雲は生えない。

同節末尾の「雲を描くかどうか、…積雲が影を落とすかは描画品質設定で選ぶ」を「…巻雲をどれだけ細かく
写すか、雲が影を落とすかは…」へ。

「描画品質設定」節:

- 「積雲の影(オフにすると、積雲そのものは見えたまま、それが地表・艦艇へ落とす影だけが消える)」を
  「**雲の影**(オフにすると、雲そのものは見えたまま、積雲と巻雲が地表・艦艇・雲へ落とす影だけが
  消える。積雲の影は積雲の立体を描くときだけ、巻雲の影は巻雲を描くときだけ落ちる)」へ置き換える。
- 「積雲の精細さ」の直後へ「**巻雲の精細さ**: 巻雲の繊維をどれだけ細かく写すか。3段(粗/標準/精細)。
  粗では巻雲は雲場の濃淡だけで描かれ、段を上げるほど細かい筋が写る。品質プリセットでは低が粗、
  中と高が標準になる。」を足す。

### 確定した基準値(手順 2〜6 で記録)

- 改修前の `npm run cloud-detail:compare` の index = **1.814**(`.cloud-detail/history/` へ記録済み)。
  巻雲撮影は 0.5〜1024 km の全帯でパワーが封筒の下、積雲の周期性の超過比は中央値 3.24 で 1 km 段の
  封筒上限 3.10 を超える — 目視の問題が数値に写っていることを確認済み。周期性のピーク尺度は名目の
  6 km ではなく 8-16 km 帯に乗る(オクターブの幾何中心の量子化で、物差しの誤りではない)。
- 改修前の雲 3 パスの GPU 時間(earth・大気 高、積雲標準 × 巻雲オン)= **9.765 ms**
  (表面雲 1.913 + 大気 5.703 + 雲影 2.149)。予算 1.5 ms の増分の分母はこれ。
- `npm run cloud-lab:compare` の基準 index = **0.450**(手順 7〜9 の回帰判定はこれから +0.02)。
- `npm run cloud-detail:compare` は再実行で全項横ばい(決定的)。`.cloud-detail/history/` 最古の
  1 件(14-23-18)は退化封筒の修正前の産物で差分の参照には出ない。
- `render-lab:measure` は npm script を新設(大気の段の表 + earth の雲 3 パスの段の表)。
- **手順 7 で確定**: 雲場の B・A は筋の倍角ベクトル(cos 2θ, sin 2θ)×揃い度、局所の東・北の基底、
  符号付き −1..1。生成は `cirrusFlowFromWindNode(weather.upperWind)`(風速 5 m/s で 0、30 m/s で 1 の
  smoothstep)、実写は veil の構造テンソルの主軸+90°×coherence×厚い積雲での減衰(0.3〜0.7)。観測 PNG
  へは 0..1 畳み、BakedField で ×2−1。`EMPTY_CLOUD_FIELD` = (0,0,0,0)。焼き直し済みの
  `src/assets/cloud-field.png` は RGBA・R/G は旧 PNG と bit 一致、A=0 texel の R/G 保持は実機確認済み。
- `anvil-cirrus-wpacific` の 4 km/px は実写側に無い(観測幅の黒帯とグリントを両方避けられず)。
- 封筒が退化するセル(実写 samples < 2)は判定しない — 点封筒の正規化が距離を破壊するため。

### 物差しの検算に使う文献値

| 量 | 値 | 出典 |
| --- | --- | --- |
| 反射率の 1 次元波数スペクトルの傾き | 200〜400 m より大きい尺度で k^−5/3、それより細かい尺度は β > 3 へ急に滑らか(放射の平滑化) | Davis et al. 1997, J. Atmos. Sci. 54(2) 241 |
| 雲の水平寸法の分布 | N(L) ∝ L^−b、b = 1.66 ± 0.04(0.1〜1500 km) | Wood & Field 2011, J. Climate |
| 周長–面積の次元 | P ∝ √A^D、D ≈ 1.35(1〜1000 km) | Lovejoy 1982, Science 216, 185 |

250 m/px の段は平滑化の折れ目(200〜400 m)に触れるので、最も細かい 1 オクターブ(0.5〜1 km)は
傾きの検算から外す。

## 達成目標

全手順の実施後に 1 つずつ当てる。「封筒」は、同じ種類(積雲主体/巻雲主体)の実写場面の測定値の
最小〜最大に、その幅の 10% の余白を足した範囲。

1. `npm run cloud-detail:compare` が、撮影 → 計測 → 実写との距離 → 履歴(`.cloud-detail/history/`)→
   前回との差の表、までを 1 回で通す。尺度の梯子の表に 0.5 km から 800 km までの全オクターブが並ぶ
   (0.5〜500 km はこの道具、25〜800 km は最新の `.cloud-lab/history/` から)。
2. `npm run cloud-detail:selftest` が通る: 傾き β を既知にした合成場(β = 1.2, 5/3, 2.5)の傾きを
   ±0.1 で取り戻し、1 オクターブのノイズ場で周期性の指標が閾値を超え、多オクターブの合成場では超えない。
   実写の文献検算(b = 1.66 ± 0.3、D = 1.35 ± 0.1)は sanity flag として表に出す — 手順 5 で確定:
   単場面・単段の fit は文献の広いプールの部分集団で、外れ(0.25 km/px の層状場面で分布が縮退し
   b≈0.8〜1.2、粗い段の積雲で b≈2.0〜2.4)は物差しの誤りではなく構造的。物差しの正当性は合成場の
   検査が担い、実写側が壊れていないかの確認に留める(現状 b 11/23・D 14/23 が幅内)。
3. **積雲**(積雲だけの撮影、全場面・全段): 0.5〜20 km の各オクターブの傾き、各オクターブの間欠性
   (帯域通過係数の尖度)、周期性の指標、b と D が、積雲主体の実写の封筒に入る。場面どうしの
   局所統計のばらつきが、実写の場面どうしのばらつきの 0.5 倍以上ある(どの場面も同じ質感、を禁じる)。
4. **巻雲**(巻雲だけの撮影): 0.5〜10 km の各オクターブのパワーと、2〜20 km の構造テンソルの揃い度が、
   巻雲主体の実写の封筒に入る。巻雲の精細さを 粗 → 標準 にしたとき、50 km 四方の平均輝度の比が
   全箱で 1 ± 0.05 に収まる(細部が濃さを変えない)。
5. **巻雲の影**(`7f399d6b4` で実施済み、最後のレビューで再確認する): `tests/render/shadow-select.test.ts` で、(雲の影, 巻雲, 積雲の精細さ) の組ごとに積雲・巻雲の影の
   有無が SPEC の文面どおりになる。render-lab の撮影 `earth-cirrus-shadow`(積雲の精細さ オフ・低い太陽)
   で、巻雲 オン/オフの差分画像に巻雲の下の地表の暗化が出る(ブロック差 6 LSB 超)。
6. 費用: 「決めたこと」の予算を `npm run render-lab:measure` の表で満たす。
7. 回帰: `npm run render-lab:compare`(before 2 組・after 1 組)で地球以外の撮影が全部封筒内。
   `npm run cloud-lab:compare` の index が、手順 5 で取った基準から +0.02 を超えて悪化しない。
8. `npm run typecheck`・`npm run test`・`npm run check:boundaries`・`npm run lint` が通る。

## 手順

### 手順 8 の残り — 積雲の封筒(達成目標 3 の積雲部分)

手順 8 の実装は `35956099f` で commit 済み(多オクターブの細部・段数の uniform 化・量のない柱での省略)。
達成条件のうち、typecheck・test:render(289/289)・render-lab:measure(標準段の増分 +0.40 ms、予算 1.5 ms)・
render-lab:compare の regression は満たした。**cloud-detail:compare の積雲の目標は未達。**

- 改修前 index 1.814 → 改修後 1.789。積雲撮影の家族別の距離は spectrum 0.78 → 0.64、periodicity 0.92 → 0.78、
  shapes 0.74 → 0.58、anisotropy 0.14 → 0.11 と下がり、intermittency 0.96 → 1.18 と variety 0 → 0.15 が悪化。
- 悪化の大半は、雲のほとんど無い撮影(正午の sepac-open・natl-trade、4 km の巻雲)が作る外れ値
  (kurtosis が 100 超、fitSlope)で、細部の調整では動かない。この外れ値が家族の平均を支配する。
- 0.25 km の段の傾き β が実写より平ら(0.8 対 2.1)。画素の寸法の放射が効いている可能性が高く、
  細部の振幅・結合の強さでは動かなかった(振幅の指数 1/2 と結合 1.2 は、縁と間欠性を悪化させた。戻した)。
- peru-sc は実写が一面の層積雲なのに、生成の雲場では晴れ。細部より前の雲場の問題。

残工程(ユーザーの判断が要る): 目標 3 の封筒内化を、(a) 雲場の生成を層積雲の場面へ合わせる、
(b) 外れ値を作る雲の少ない撮影を封筒の判定から外す、のどちらで進めるか。どちらも細部の評価器の外。
→ (b) は `3159027a8` で実施した(29 撮影を固定の一覧で外す)。残るのは (a) と、下の「残工程」の判断。

### ループ 1 回の所要

撮影数 = 6 海域 × 3 時刻 × 3 段 × 3 種類 = 162 枚。改修前の実測で `render-lab:shot` は 103 枚をビルド込みで 2 分以内
(≈ 1.2 s/枚以下)で撮るので、撮影 ≈ 162 × 1.2 s ≈ 3.2 分。計測は 1 枚あたり 512² の FFT ×1 と帯域通過 6
オクターブ × ぼかし 2 回(箱ぼかし 3 回の近似で O(画素数))≈ 0.3 s として、(162 + 実写 24) × 0.3 s ≈ 1 分。
1 回 ≈ 5 分。

### 描画の費用

雲頂の殻は画素あたり (march + refine) 回の雲頂判定と法線の 3 回の雲頂評価で、標準段は 6 + 3 + 3 = 12 回、
いまは 1 回につきノイズ 1 回。細部は生きているオクターブの数 N だけノイズが増える。低軌道(画素 ≈ 0.4 km)
では 4 画素の規則で 1.6 km 以上のオクターブ(8・4・2 km)が全振幅、1 km が途中 → N ≈ 3.5、標準段の上限 4
なので画素あたり 12 × 3.5 = 42 回(改修前の 3.5 倍)。影は 6 タップ × (積雲 N + 巻雲 M) 回、タップの代表幅
(光路 1 歩 × 2、低軌道の低い太陽で数 km)がオクターブを打ち切るので N, M ≈ 2 → 24 回(改修前 6 回)。
巻雲の殻は視線あたりの交点 2 つ × M ≈ 3.5 → 7 回。手順 5 の改修前の実測値に、これらの倍率を掛けた値を
予算と比べ、実測が出たら置き換える。
