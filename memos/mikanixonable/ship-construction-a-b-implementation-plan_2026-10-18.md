## 目的

いまの建造は「パネルで部品と位置を選び、ボタンで1個ずつ足す」作業で、作った手応えがない。
これを「**部品を手に取り、3D の船体へはめ、掴んで付け替え、回し、取り消せる**」体験へ変える。
範囲は二つ。

- **A(手触り)**: ホバーで即プレビュー・1クリック配置・ドラッグ&ドロップ、建造の入口を1手に、
  内部識別子を見せない表記、画面上で一定の大きさの接続ノード、建造中のキー操作、操作音と差し込みの動き、
  取り消し・やり直し。
- **B(形の自由)**: 船体全体を編集対象にし、どのモジュールでも先端部ごと掴んで付け替え・撤去・
  割り込み挿入できる。90° 単位のロールと前後反転、側面への2回/4回対称配置、先端部の複製、
  設計図(セーブデータごと)、体積の重なり判定。

仕様が先行する(AGENTS.md)。手順 1 で `DEVELOP/SPEC/` を、手順 2 で `CONTEXT.md` を書き換え、
それぞれ単独で commit してからコードへ進む。書く文面は各手順に全文を載せる。

## 達成目標

全手順の実施後に、1つずつ当てる。

1. 戦闘ビューで、操作対象の船体の建造ドックを左クリック(タップ)すると建造が始まる。`[B]` と常設の建造ボタンでも始まる。
2. カタログのカードを押して手に取り、マウスで候補ノードを指すとゴーストと性能の差分が出て、**1クリック**で置ける。置いた後も同じ部品を持ち続ける。
3. カードを 3D 画面へドラッグし、候補の上で離すと置ける。タッチではカードを長押ししてからドラッグでき、持ったまま別の指でカメラを回せる。
4. 配置済みモジュールをクリックで選び、もう一度その上からドラッグすると、先端部ごと別の候補へ付け替えられる。候補以外で離すと元に戻る。
5. 選択中のモジュールを `[Delete]` かパネルの「撤去」で、先端部ごと外せる。起点ドックは選べない。
6. タンクとタンクの継ぎ目を指してデカプラーを置くと、間に割り込み、後ろ側がデカプラーの反対側へ付き直る。
7. `[Q]`/`[E]` で 90° ずつロール、`[R]` で前後反転(両端に取り付け面があるものだけ)できる。手に持ったものにも、選択中の配置済みモジュールにも効く。
8. `[X]` で対称数が 1→2→4 と巡り、太陽電池をタンクの側面へ4つ同時に置ける。1か所でも埋まっていれば置けない理由が出る。
9. 選択中のモジュールの先端部を `[C]` で複製して手に取り、別の場所へ新品として置ける。
10. 置こうとした位置が既存のモジュールと体積で重なると候補が赤くなり、重なる相手のモジュールが明滅する。
11. `Ctrl+Z`/`Ctrl+Shift+Z`(macOS では `⌘`)で取り消し・やり直しができ、パネルの履歴一覧の項目を押すとその時点へ戻る。「変更をすべて取り消す」で建造開始時の船体へ戻る(確認あり)。
12. 選択中の先端部を名前付きで設計図に保存でき、同じセーブデータで別のステージを始めても設計図タブに出る。セーブデータの複製・分岐・書き出し→読み込みで設計図も付いていく。
13. 健全なコックピットを全て失う撤去・付け替えは確認を経てからだけ行われ、確定すると建造が閉じる。
14. パネル・候補一覧・履歴のどこにも `module-3`・`construction-7`・`dock-left` のような内部識別子が出ない。
15. 置く・外す・吸着・不可・建造終了で、それぞれ聞き分けられる操作音が鳴る。置いたモジュールは接続方向から短く差し込まれて現れる。
16. ロール・反転した船体を手動セーブ → 読み込みしても、向きが保たれる。旧記録(向きの印が無い記録)は従来どおり読み込める。
17. `npm run typecheck` / `npm run check:boundaries` / `npm run lint` / `npm run test` / `npm run build` / `SMOKE_CONSTRUCTION=1 npm run smoke:browser`(`?stage=creative`、`SMOKE_CREATIVE_PRESET=base`)が通る。`tools/boundary-allowlist.json` は `{}` のまま。

## 見積り

時間ではなく、毎フレームの負荷と記憶量。実装後は実測(`?perf=1` のデバッグ情報、`npm run perf` 系)で置き換える。

| 項目 | 導出 | 見積り |
| --- | --- | --- |
| 全候補の列挙(手持ちがある間、毎フレーム) | モジュール数 N=40 として、面 2N + 側面 4×(コックピット・タンク数 ≈ 20) + 継ぎ目 ≈ N = 80 + 80 + 40 = 200 候補。各候補の占有判定で接続 E ≈ 40 本を走査 → 200 × 40 = 8,000 回の比較 × 約 10 ns | 約 0.08 ms |
| 試し置き(指している候補が変わったときだけ) | 写し O(N)=40 モジュール + 適用 + `totals()` + 重なり: 手持ちの円柱数 h × 残りの円柱数 P。P ≈ コックピット 36 + 他 39 × 1.5 ≈ 95。単体モジュール h≈2 → 190 組、大きな先端部 h≈40 → 3,800 組 × 約 0.5 µs | 単体 約 0.1 ms / 最大 約 1.9 ms(変化したフレームだけ) |

## 却下した案と、残る問題

- **設計図をそのランの記録(スナップショット)に入れる** — 却下: ユーザーの決定(セーブデータごと)。スナップショットにも入れると、古いセーブを読み込んだときに一覧が巻き戻る問題が残るので、両方には持たない。
- **文字列・URL での設計図の共有** — 今回の範囲外(保存先の決定に含まれなかった)。入れるなら `location.*` を読める `launcher/` に受け口を置く必要がある。
- **全候補で重なりを判定して色を付ける** — 却下: 見積りで毎フレーム数十 ms。全候補の色は規則だけで決める(D13)。
- **ESC で手持ちだけ手放す二段の ESC** — 却下: 共通オーバーレイ管理の ESC の規約から外れる(D5)。
