## 0. この文書の目的

「月軌道の基地から艦を出し、地球低軌道などで敵と接触・戦闘し、基地へ帰投する」サイクルを、プレイヤーが
ストレスなく回せるようにする。今回の範囲は **軌道上へのものの配置と操作、自動操作(自動航行)** である。

ユーザーの要求(原文の要旨):

1. 「軌道」を配置できるオブジェクトにする。設定した軌道へ基地から艦を自動で向かわせる。投入にかかる時間
   などの要件に合わせて、ホーマン遷移・二重楕円遷移・低エネルギー遷移・大気による減速などから遷移を選べる。
2. 軌道をターゲットにできる。
3. 軌道の特定の位相をターゲットにできる。
4. 軌道遷移は原則として自動で行う。
5. 特定の軌道や物体に投入・ランデブーするための遷移軌道を作れる。

この文書は、これらをコードベースの現状に照らして **発展・補完・修正** した案である。
このファイルだけを読んだ実装者が文脈を再現できることを基準に書く。

## 1. 決まっていること

### 1.1 ユーザーが決めたもの(2026-10-18 の問答)

| 項目 | 決定 |
| --- | --- |
| 自動遷移の実行モデル | **有限推力の実燃焼。** 自動操縦が姿勢を向け、推力・燃焼時間・燃料消費を伴って噴射する。燃焼誤差は自動で補正する |
| 対象の艦数 | **複数艦を並行して派遣できる。** 操作対象でない艦も自分の航行指令で自動航行する |
| ランデブーの終端 | **対象の種類で切り替える。** 敵・敵の軌道へは交戦距離の手前で相対速度を合わせて停止し、手動戦闘へ渡す。基地・味方艦へはドッキング可能な距離まで自動で寄せ、接続の確定はプレイヤーが行う |
| 適用範囲 | **CREATIVE で先行。** ステージへの展開は後の段階 |
| 自動燃焼と時間加速 | **自動操縦の燃焼は全倍率で継続する。** ×4 制限は手動操作・射撃・交戦にだけ残す |
| 配置する軌道の性質 | **理想化した参照軌道。** 軌道要素と位相を時刻の関数として持つ。J2 による昇交点・近点の永年歳差だけを反映し、大気で減衰したりずれたりしない |
| 帰投後の給油 | **基地のタンクから移送する。** 基地の燃料は有限。CREATIVE では基地を満タンにする操作を持つ |
| 低エネルギー遷移 | **後の段階で導入する。** まず直接遷移系(ホーマン・二重楕円・位相合わせ・ランベルト・大気減速)を完成させる |
| 推進系の諸元 | **宇宙工学的に正確かを再検証する。** → 本書 §7 に検証結果と選択肢を載せた。採否は未決 |

### 1.2 計画を書く側が決めたもの(覆してよい)

各項目の理由は本文の該当節にある。

| 項目 | 決定 | 節 |
| --- | --- | --- |
| 「軌道」オブジェクトの名前 | **軌道標識**(英: orbit slot)。軌道の形・向きと、その上を進む1つの位相点を持つ | §4.1 |
| 「軌道」と「位相」のターゲットの統一 | ターゲットにできるのは軌道標識そのもの。航行指令の側で「位相を問わず投入」か「位相点へ投入」かを選ぶ | §4.2 |
| 遷移方式の選ばせ方 | 方式を先に選ばせない。**制約(到着期限・Δv 上限・大気を使うか)を選ぶと、方式名つきの候補が Δv と到着時刻の図に並ぶ。** 方式で絞り込むこともできる | §4.4 |
| 計画の表現 | プレイヤーに見せる計画は **今のインパルス(マニューバノード)のまま**。有限燃焼への変換と誤差補正は自動操縦が担う | §4.5 |
| 自動航行の単位 | 艦ごとに1つの **航行指令**(英: navigation order)。目標・制約・選んだ候補・進行状態を持ち、艦の計画(ノード列)を生成し直す主体になる | §4.3 |
| 求解の決定性 | 求解は「求解を始めた時刻の状態」だけから決まる。求解が終わるまでシミュレーション時刻は出発時刻を越えない | §6.5 |
| 「理想実行(瞬間置換)」の扱い | 既存の自動実行(`'instant'`)は CREATIVE の検証用に残し、既定は新しい「自動操縦」にする | §4.5 |

### 3.2 欠けているもの(= 今のストレスの原因)

1. **遷移ソルバが無い。** ランベルト・ホーマン・位相合わせの実装はどこにも無い(`src/physics/lambert-sphere.ts` は
   測光、`intercept.ts` は弾の見越し)。月→LEO の遷移は、プレイヤーがノードを手で置き Δv を W/S/A/D/E/Q で
   調整するしかない。
2. **自動実行は瞬間置換(テレポート)だけで、CREATIVE 限定。** `executeInstantNodesUpTo` が状態を
   `motion.reset` で置き換える(`modular-ship.ts:343-350`)。燃料を消費しない。`Stage.executesPlans` は
   CREATIVE だけ true(`creative-stage.ts:49`)。
3. **操作対象でない艦は何もできない。** `updateControls(null, …)` を受けて点火済みブースター以外の指令が
   消える(`dynamic-system.ts:211-218`, `modular-ship.ts:510-513`)。並行派遣の経路が無い。
4. **推力は ×4 以下でしか働かない**(`MAX_PHYS_SIM_SPEED = 4`, `sim-speed-manager.ts:9`)。数日〜数ヶ月の
   航行を有限燃焼で行うと、燃焼のあいだずっと ×4 以下へ落とすことになる。また手動推力はフレームごとに一定値で
   積まれ(`throttle.ts:168-189`)、燃焼の開始・終了を時刻で区切る仕組みが無い。
5. **Δv の予算を計算する関数が無い。** 計画は燃料を参照しない。
6. **計画は操作対象の艦のものしか育たず、表示期間に縛られる。** 計画弧は表示中の計画だけが伸び
   (`plan-display.ts:132`)、ノードを置ける範囲は表示期間まで(`plan.ts:177-183`)。3日の遷移を組むには
   表示期間を3日以上にする必要がある。期限切れ・達成判定も操作対象だけ(`plan-node-rules.ts`)。
7. **ターゲットにできるのは天体・ラグランジュ点・艦・基地だけ**(`nav-target-presenter.ts:187-208`)。
   軌道や位相点はターゲットにならない。ターゲットは視点(`NavTargetSelection`, `src/game/viewer/`)で、
   進行の規則からは読めない(ARCHITECTURE R4)。
8. **近接運用の支援が無い。** ドッキングの誘導は無く、相対速度 1 m/s・距離 3 m まで手で寄せる。
9. **給油の手段が無い。** 基地に接続すると修理はされるが、燃料は移らない。
10. **月軌道の基地から始まるステージが無い。** 基地は CREATIVE の配置パネルからしか置けない。

- ドッキングの接続点間距離: SPEC(GAME.md 7.1)は 1.0 m 以下、コードは 3 m(`ship-docking.ts:7`)。
- ノード達成判定: SPEC(PLAN.md 11.1)は長半径相対誤差 2%・離心率差 0.02・面差 2°、コードはその 1/3

## 4. 提案の骨格

要求を次の5つの部品に分ける。**目標・制約・方式・実行を別々にする**のは、低エネルギー遷移・スウィングバイ・
漸増接近・回収物の質量といった後続の要求が、どれも「方式を1つ足す」「制約を1つ足す」で済むようにするため。

```
 [軌道標識]  [艦・基地・敵]            ← 目標になれるもの(§4.1, §4.2)
        \       /
      [航行指令]  目標 + 到達条件 + 制約     ← 艦ごとに1つ(§4.3)
            |
      [遷移ソルバ]  方式ごとの候補生成 → 全力モデルで補正 → 候補一覧(§4.4, §6)
            |  選んだ候補
      [計画(ノード列)]  今のマニューバノードのまま(§4.5)
            |
      [自動操縦]  ノード → 有限燃焼、燃焼後に残りを解き直す、終端誘導(§4.5, §4.6)
```

### 4.1 軌道標識(要求1の「配置できる軌道」)

**定義**: プレイヤーが配置する、質量も当たり判定も持たない参照軌道。基準天体・軌道の形と向き・その上を進む
1つの位相点を持つ。

- **時刻の関数として決まる。** 基準天体の重力定数と、元期の平均軌道要素(半長軸 a、離心率 e、傾斜角 i、
  昇交点赤経 Ω、近点引数 ω、元期の平均近点角 M₀)から、任意の時刻の位置・速度を返す。
- **J2 の永年歳差だけを反映する**(ユーザー決定)。基準天体が J2 を持つとき(CELESTIAL.md「形状と重力場」)、
  p = a(1−e²)、n = √(μ/a³) として
  - dΩ/dt = −(3/2)·n·J2·(R/p)²·cos i
  - dω/dt = (3/4)·n·J2·(R/p)²·(5cos²i − 1)
  - dM/dt = n·[1 + (3/4)·J2·(R/p)²·√(1−e²)·(3cos²i − 1)]
  (R は J2 の基準半径。出典: Vallado §9.6 の一次の永年摂動)。太陽同期の軌道標識は太陽との角度を保ち、
  モルニヤ傾斜角(63.4°)の標識は近点が動かない。**大気による減衰・第三体摂動・短周期変動は反映しない。**
- **ラグランジュ点まわりの周期軌道**(ハロー・NRHO・リヤプノフ・DRO など)も軌道標識にできる。この場合は
  基準天体の代わりに系(主星・副星)と族の1メンバーを持ち、軌道ガイドと同じく **その瞬間の実際の天体位置で
  組んだ回転座標系** に載せ、位相点は族メンバーの周期で進む。CR3BP の理想解なので、その上に乗った艦は
  現実の摂動でずれていく(ORBIT.md「多体重力」— ずれは保持機動の対象で、§9 の未確定案)。
- **作り方(入口)**
  1. 空域の右クリック → 「軌道標識を配置」。物体配置パネル(GAME.md 9.1)のフォームを流用し、種類に
     「軌道標識」を足す。軌道要素方式とラグランジュ点方式、プリセット、検証、プレビューはそのまま使う。
  2. 艦・敵・基地・天体の公転線・軌道ガイド線の右クリック → 「この軌道から軌道標識を作る」。その瞬間の
     接触軌道要素(艦)またはガイドの族メンバー(ガイド線)を写し、位相は対象の現在位相に揃える。
     敵の軌道を写せば「敵の軌道へ先回りする」ができる。
  3. CREATIVE ではプリセット(LEO 400 km・静止軌道・太陽同期・月低軌道 100 km、NRHO)を一発で置ける。
- **表示**: マップでは解析的な楕円(族メンバーは閉曲線)を、自艦・敵・基地とは別の色の細い実線で描き、
  位相点を専用の記号で示す。名前を付けられる。軌道物体一覧に「軌道標識」の区画を足す。戦闘ビューでは
  ターゲットに選ばれているときだけ描く。
- **持ち主と保存**: 軌道標識の台帳はモデル層(進行)にあり、セーブに入る。航行指令から id で参照される
  ので、視点ではなく進行に置く(ARCHITECTURE R4)。

**なぜ「理想化した参照軌道」か**: 目標が勝手に減衰したり崩れたりすると、プレイヤーが置いた「到達すべき軌道」が
置いた時点の意味を失う。J2 歳差だけを残すのは、太陽同期・臨界傾斜角といった「軌道の性格」そのものが
J2 歳差で定義されていて、これを外すと標識が名前どおりに振る舞わないため。

### 4.2 ターゲット(要求2・3)

- **ターゲットにできるものに軌道標識を足す。** 航法ターゲット(COMBAT.md「ターゲット指定」)は1つのまま。
  軌道標識がターゲットのとき、相対昇交点・降交点(△▽)、再接近点(✧、ここでは標識の位相点との最接近)、
  軌道分析パネルの接近タブが標識に対して働く。射撃・照準補助の基準にはならない(天体と同じ「航法基準のみ」)。
- **「軌道の特定の位相」は2つの意味に分けて扱う。** ユーザーの要求文はどちらにも読める。
  - (a) **動く位相点** — 標識の位相点そのもの(= その軌道を回る仮想の衛星)。「その軌道のその位置に、
    その時刻にいる」ことを要求する。ランデブーと同じ問題になる。
  - (b) **軌道上の固定した場所** — 近点・遠点・昇交点・指定した真近点角。「到着時にその場所を通過する」
    ことを要求し、到着時刻は問わない。
  (a) は標識のターゲット指定で、(b) は航行指令の到達条件として選ぶ(§4.3)。
- **航行指令はターゲット(視点)を読まない。** 指令を作る瞬間に、UI がターゲットの id を指令へ写す。
  進行の規則が視点を読まないという ARCHITECTURE R4 を守るため、そして指令中にプレイヤーが別のものを
  ターゲットにしても航行が乱れないようにするため。
- 軌道線ウィンドウ(既存)に軌道要素の表示と「軌道標識を作る」「ターゲットに設定(標識のとき)」
  「ここへ向かわせる…」を足す。

### 4.3 航行指令(要求1・4・5の中心)

艦ごとに高々1つ持つ「どこへ・何を守って行くか」の指令。艦の計画(ノード列)を作り直す主体になる。

- **目標の種類**(対象と到達条件から決まる)

  | 目標 | 到達条件 | 終端(ユーザー決定) |
  | --- | --- | --- |
  | 軌道標識・位相を問わない | 軌道の形と向き(a, e, i, Ω, ω)が標識に許容誤差内で一致する | 投入した時点で完了 |
  | 軌道標識・位相点 | 標識の位相点に、相対距離・相対速度の許容内で到達する | 位相点の近傍で保持 |
  | 軌道標識・固定した場所 | 指定した場所(近点・遠点・交点・真近点角)を通過する時点で軌道が一致する | 投入した時点で完了 |
  | 敵 | 敵の後方または下方の **待機点**(既定 10 km、交戦圏 30 km の内側)で相対速度をほぼ 0 にする | 待機点で保持し、手動戦闘へ渡す |
  | 味方艦・基地 | ドッキング軸上の **接近点**(既定 200 m、相対速度 0.3 m/s 以下)まで寄せる | 接近点で保持し、接続の確定はプレイヤーが行う(GAME.md 7.1 の「自動吸着は行わない」を守る) |
  | 天体(重力源) | 指定高度・傾斜角の周回軌道 = その場で作った軌道標識と同じ扱い | 投入した時点で完了 |

  待機点の 10 km は、敵の射撃が始まる交戦圏の内側で、かつ自機の機関砲(弾速 1,000 m/s)で 10 秒程度の
  弾着になる距離として置いた既定値(プレイヤーが指令で変えられる)。操作対象でない艦の待機点は §4.6。
- **制約**(プレイヤーが選ぶ。§4.4 の候補の絞り込みに使う)
  - 到着期限(または「最速」「最省燃料」の両端)
  - Δv の上限(既定: その艦が今使える Δv から、帰路の予備を引いた値。予備の割合は指令で変えられる)
  - 大気を使うか(エアロブレーキを候補に入れるか)
  - 最低近地点高度(大気を使わないときの安全限界)
  - 出発時刻の最早(基地からの発進準備・待ち合わせ用)
- **進行状態**: 求解中 → 出発待ち → 航行中(弾道/燃焼/修正) → 終端接近 → 保持(到着) → 完了、
  および 中止・失敗(燃料不足・焼失の予測・接触・目標の消滅)。状態と次の出来事までの残り時間は、航行一覧
  (§5.3)と艦のプロパティウィンドウに出る。
- **計画との関係**: 指令は、選ばれた候補をノード列として艦の計画へ書く。指令の進行中にプレイヤーが計画を
  手で編集したり手動で噴射したりしたら、指令は **中断**(自動操縦が止まる)し、「指令を再開(解き直す)/
  指令を取り消す」を問う。PLAN.md 未確定案「計画軌道からの逸脱の警告」をここで実現する。
- **複数艦**: どの艦も自分の指令で並行に航行する(ユーザー決定)。操作対象を切り替えても他艦の航行は続く。
- **持ち主と保存**: 指令は艦(`ModularShip`)が計画と並べて持ち、艦と一緒に直列化する(R11/R12)。

### 4.4 遷移方式と候補の選ばせ方(要求1の「適切な遷移軌道を選択」)

**修正点**: 要求文は「積荷の要件に合わせて遷移を選択」だが、方式名(ホーマン・二重楕円…)を先に選ばせると、
プレイヤーは軌道力学の知識を要求される。ゲームデザインのメモにある「軌道力学を教えず肌感覚で掴ませる」に
合わせ、**選ぶのは制約、出てくるのは方式名つきの候補**にする。

- 候補は「Δv(または消費する推進剤の質量)」を縦軸、「到着時刻」を横軸にした散布図と、一覧表の両方で示す。
  図では **パレート最適(より早く、より安いものが他に無い)な候補を強調**し、制約を外れる候補は淡色にする。
- 各候補には方式名を付ける: 「ホーマン遷移」「二重楕円遷移(中間遠点 ○○ km)」「位相調整(N 周待ち)」
  「直接遷移(ランベルト)」「大気減速(N パス)」、後の段階で「低エネルギー遷移」。
- 一覧の列: 方式・出発時刻・到着時刻・所要時間・合計 Δv・燃焼回数・到着後の残り Δv・最大の加熱率と
  動圧(大気減速のとき)・注意(「帰路の Δv が足りない」「近地点が大気圏内」など)。
- 候補を選ぶと、その計画軌道が破線でマップに重なる(今の計画軌道の描き方、PLAN.md 5)。
- 方式名のチップで絞り込める(「大気減速だけ」など)。上級者は方式を名指しできる。

**方式ごとの役割**(詳しい解き方は §6)

| 方式 | いつ候補に出るか | 時間と Δv の性格 |
| --- | --- | --- |
| ホーマン遷移 | 同じ基準天体の近円軌道どうし | 2回の燃焼で最小に近い Δv。所要は遷移楕円の半周 |
| 二重楕円遷移 | 半径比が大きい(約 11.94 超)とき | 半径比 15.58 超では必ずホーマンより安い。中間遠点を上げるほど安く遅い |
| 位相調整 | 位相点・物体ランデブーで、同じ軌道か近い軌道にいるとき | 待つ周回数 N を増やすほど安く遅い |
| 直接遷移(ランベルト) | 上記に当てはまらない一般の場合(楕円目標・面変更込み・月⇄地球) | 出発時刻と飛行時間を走査し、早い〜安いの帯ができる |
| 大気減速 | 目標の基準天体が大気を持ち、到着が高いエネルギーから下りるとき(月→LEO の主役) | 捕獲 Δv をほぼ 0 にする代わりに、加熱・動圧の危険と数日〜数週間の時間がかかる |
| 低エネルギー遷移(後の段階) | 地球⇄月(太陽-地球系の外回り) | 3〜4ヶ月かけて数十〜150 m/s 級。窓は約 29.5 日ごと |

### 4.5 自動操縦(要求4)

- **計画はインパルスのまま、実行は有限燃焼。** 自動操縦はノード1つを「ノード時刻を中心とする燃焼」に変換する。
  燃焼時間はロケット方程式で求める(推力 F、有効排気速度 vₑ = F/ṁ、燃焼前質量 m₀ として
  Δt = (m₀·vₑ/F)·(1 − e^(−Δv/vₑ)))。開始時刻 = ノード時刻 − Δt/2 を初期値とし、燃焼中の推力方向は
  「残りの必要速度変化」の方向へ向け続ける(必要速度誘導。燃焼前の弾道と、目標とするノードの絶対状態の
  差を随時解き直す)。
- **燃焼の前に姿勢を向ける。** 燃焼開始の前に、自動操縦が RCS で機首(主推進の向き)を燃焼方向へ回す。
  回頭に要る時間は艦のトルクと慣性から見積もり、燃焼開始より前に終わるよう余裕を取る。
- **燃焼後は残りを解き直す。** 有限燃焼・摂動・推力誤差による残差は、各燃焼の後に、その時点の実際の状態から
  後続のノード列を解き直して吸収する(中間軌道修正)。修正の燃焼が小さすぎる(既定 0.1 m/s 未満)なら
  省く。これにより「計画どおり飛べたか」をプレイヤーが気にする必要がなくなる。
- **全倍率で燃焼を続ける**(ユーザー決定)。燃焼の開始・終了・姿勢変更の開始は「あらかじめ分かっている出来事」
  として刻みを区切り(ORBIT.md「時間の進み方と時間加速」)、燃焼中の艦は時間加速倍率によらない一定の細かさで
  積分する。**倍率を変えても燃焼結果が変わらない**(INVARIANTS §2)。そのため、自動操縦の姿勢制御も
  倍率によらない同じ規則で積分する。手動の噴射・射撃・交戦の ×4 制限はそのまま残る。
- **燃料が足りないときは出発しない。** 候補の時点で到着後の残り Δv を出し、出発時に再確認する。
  航行中に足りなくなったら(被弾でタンクを失うなど)指令は失敗し、通知する。
- **操作対象の艦でも、操作対象でない艦でも同じに働く。** 操作対象の艦が自動操縦中にプレイヤーが手動で
  噴射・回転したら、自動操縦は中断する(§4.3)。
- **既存の「自動実行(瞬間置換)」は残す。** 計画の実行モードは「なし / 自動操縦(既定) / 理想実行(瞬間置換・
  CREATIVE のみ)」の3段になる。理想実行は軌道の検証と、推進系の調整前の動作確認に使う。

### 4.6 終端誘導(要求5の「ランデブー」)

- 遷移の終端は、目標から数十 km の **終端入口** で遷移ソルバから終端誘導へ引き継ぐ。
- 終端誘導は Clohessy-Wiltshire(Hill)方程式の2インパルス解を初期推定にし、実際の力モデルで補正する
  (§6.4)。こうのとり式の漸増接近(後方の保持点 → 下方からの R-bar 接近 → 接近点)を手順として持つ。
- **敵へ**: 後方または下方の待機点まで寄せて相対速度をほぼ 0 にし、保持する。操作対象の艦が待機点に着いたら
  時間加速を等倍へ戻し、「交戦位置に到着」を通知する。操作対象でない艦は、敵に撃たれるかどうか(§9 Q4)が
  決まるまで、交戦圏の外(既定 40 km)の待機点で止めて通知だけ出す。
- **基地・味方艦へ**: ドッキング軸の延長上の接近点まで寄せ、保持する。そこから先はプレイヤーが寄せて
  接続を確定する。**接近点から接続までを補助する表示**(接続軸からのずれ・距離・相対速度・確定条件の充足)
  を戦闘ビューに出す(§5.4)。

### 4.7 基地からの発進と帰投、給油

- **発進**: 基地にドッキング中の艦に航行指令を出すと、確定時に接続を解除して分離し(既存の `undock`、分離
  速度 8 m/s)、基地から安全距離(既定 1 km)まで離れてから最初の燃焼に入る。分離から最初の燃焼までの
  待ちは候補の出発時刻に含める。
- **帰投**: 艦の右クリック → 「基地へ帰投」。最寄り(または指定)の基地を目標にした航行指令を作る。
- **給油**: 健全な dock または docking_port で基地と接続している間、基地のタンクから艦のタンクへ燃料を
  移送できる。燃料の種別(主推進/RCS)ごとに、艦側の空き容量と基地側の残量の小さい方を移す。操作は
  艦またはモジュールのプロパティウィンドウの「給油」。CREATIVE の設定パネルに「基地の燃料を満タンにする」
  を足す。
- ドッキングで2つの船体が1つになったとき、能力の集計は統合船体全体で行われる(CONTEXT.md「統合船体の
  能力集計」)。「基地のタンクから艦のタンクへ」は、統合船体の中で **どのタンクがどちらの元の船体に
  属していたか** を区別する必要がある。今のドッキングは接続前の船という単位を保持しない(GAME.md 7.1)ので、
  給油の対象は「操作中のコックピットから見て dock の向こう側にあるタンク群 → こちら側のタンク群」と定義する。
  **ここは SPEC の判断が要る**(§9 の確認事項 Q3)。

## 6. 遷移ソルバの設計(実装者向け)

### 6.1 共通の流れ

1. **二体近似で候補を量産する。** 各方式の解析式またはランベルト解で、Δv と到着時刻を素早く見積もる。
2. **候補を絞る。** 制約を外れるもの・パレート劣位のものを落とし、上位の数件(既定 8 件)を残す。
3. **全力モデルで補正する。** 残った候補を、実シミュレーションと同じ力モデル(`PredictedArc` と同じ積分)で
   伝播し、終端の残差を微分補正(射撃法)で消す。補正後の Δv・時刻を候補に書き戻す。
4. **計画のノード列に落とす。** 補正後の各燃焼の「噴射直後の絶対状態」がそのままノードになる(§3.1)。

### 6.2 解析的な方式(同じ基準天体)

研究調査の結果(出典: Curtis "Orbital Mechanics for Engineering Students" 6章、Vallado 6章)。

- ホーマン: a_t = (r₁+r₂)/2、Δv₁ = √(μ/r₁)·(√(2r₂/(r₁+r₂)) − 1)、Δv₂ = √(μ/r₂)·(1 − √(2r₁/(r₁+r₂)))、
  所要 π√(a_t³/μ)。
- 二重楕円(中間遠点 r_b): a₁ = (r₁+r_b)/2、a₂ = (r_b+r₂)/2、
  Δv₁ = √(2μ/r₁ − μ/a₁) − √(μ/r₁)、Δv₂ = √(2μ/r_b − μ/a₂) − √(2μ/r_b − μ/a₁)、
  Δv₃ = √(2μ/r₂ − μ/a₂) − √(μ/r₂)(逆向き)、所要 π√(a₁³/μ) + π√(a₂³/μ)。
  r₂/r₁ < 11.94 ではホーマンが常に安く、15.58 超では任意の r_b > r₂ で二重楕円が安い。
  r_b を数点(例: r₂ の 1.5・3・10 倍)取って候補にする。
- 面変更: Δv = 2v·sin(Δi/2)。速い点ほど高いので遠点で行うのが基本で、出発燃焼へ数度だけ配分するのが最小。
  配分は数値で最適化する(閉形式なし)。
- 位相調整: 同じ円軌道(周期 T)上で位相差 Δφ を N 周で吸収する調整軌道の周期は T·(1 ∓ Δφ/(2πN))。
  異なる高度の目標へは、遷移時間 t₁₂ のあいだに目標が進む角(リード角)α = n₂·t₁₂ だけ目標が先行する瞬間に
  出発する。待ち時間 = (Δφ₀ − α + 2πk)/(n₁ − n₂)、窓の周期 = 2π/|n₁ − n₂|。

適用条件: 二体・同一面・円軌道。J2・第三体・大気で崩れるので、どれも §6.1 の 3 で補正する前提の初期推定。

### 6.3 一般の方式(ランベルト)

- 解法: Izzo (2015) "Revisiting Lambert's problem"(Celest. Mech. Dyn. Astr. 121:1–15)。単周回は Householder
  反復で約2回、多周回は最大周回数 N_max に対し 2N_max+1 本の解。
- 走査: 出発時刻 t₀ と飛行時間 TOF の格子で、目標を t₀+TOF まで伝播した位置に対しランベルトを解き、
  コスト = |出発 Δv| + |到着 Δv| を評価する(ポークチョップ図)。位相点・物体ランデブーは到着位置が時刻で
  決まるのでそのまま、固定した場所への投入は到着点の真近点角を走査変数に足す。
- 月⇄地球: 地球中心の二体ランベルトでは月近傍の初期推定が弱い。月の影響圏で双曲線を継ぐ(パッチド・
  コニック)初期推定を作り、全力モデルでは区間を分けた多重射撃で補正する。
- 補正: 初速度 v₀ に対する終端位置の感度 Φ_rv = ∂r_f/∂v₀(状態遷移行列の位置対速度の区画)を有限差分で求め、
  δv₀ = −Φ_rv⁻¹(r_f − r_target) で反復する。遷移角 180° 付近と整数周の付近では Φ_rv が悪条件になるので
  その候補は落とす。

### 6.4 終端(数十 km 以下)

- Clohessy-Wiltshire 方程式(x 動径外向き、y 進行方向、z 面外、n = √(μ/a³)):
  ẍ = 3n²x + 2nẏ、ÿ = −2nẋ、z̈ = −n²z。2インパルス解は Δv₁ = −Φ_rv⁻¹Φ_rr·r₀(到着で Δv₂ を打って相対速度を
  消す)。飛行時間が周期の整数倍に近いと発散するので、半周〜1周未満を選ぶ。
- 手順の型(こうのとりの実績、JAXA HTV 資料): 目標の後方の保持点 → 下方へ移って R-bar(動径方向)から接近 →
  途中の保持点 → 接近点。距離ごとの相対速度の上限を持つ(例: 数 km で m/s、接近点で 0.3 m/s 以下)。
- 円でない目標(敵が楕円軌道)では CW の誤差が大きいので、短い区間ごとに全力モデルで解き直す。

### 6.5 求解の実行と決定性

- 求解は **求解を始めた時刻の状態だけ** から決まる。求解は1フレームで終わらない(全力モデルの伝播を含む)ので、
  フレームあたりの歩数の予算を持つ段階的な仕事として進める(`Predictor` の `ARC_STEP_BUDGET` と同じ考え方)。
- **求解が終わるまで、シミュレーション時刻は「求解の基準時刻 + 出発までの最短の猶予」を越えない。**
  これを出来事の時刻として刻みを区切り、越えそうなら時刻の進みを止めて待つ。こうしないと、時間加速が速いほど
  求解中に時刻が出発時刻を過ぎ、解き直しが起こり、倍率で結果が変わる(INVARIANTS §2)。
- 反復回数・許容誤差・格子は固定値で、フレームの分け方に依らない。
- 燃焼後の解き直し(§4.5)も同じ規則に従う。次の燃焼までの猶予が十分に長い位置で解き直す。
- 計算量の見積もり: 3日の月→地球の弧を刻み 40〜200 s で全力モデル伝播すると数千歩(約 5,000 歩)。
  補正1回に、本伝播1本と感度の有限差分3本(初速度の3成分)で4本 → 補正 5 回 × 候補 8 件で約 80 万歩。
  今の予測予算(1フレーム 600 歩)と同じ予算では 60 fps で約 20 秒かかる。予算を数倍に取るか、
  Web Worker へ移す(`src/physics/` は THREE 非依存なので移せる)ことになる見込み。最初は主スレッドの予算方式で
  作り、1歩の実測時間を測ってから決める。候補の上位だけを補正する(§6.1 の 2)のは、この費用を抑えるため。

### 6.6 大気減速

- 1パスの Δv の見積もり(薄い大気の近似): Δv ≈ ρ_p·v²·(C_D A/2m)·√(2π r_p H)
  (ρ_p 近点の密度、H スケールハイト、r_p 近点半径)。初期推定に使い、実際の値は全力モデル(大気抵抗込み)の
  伝播で求める。
- 熱: よどみ点熱流束 q = k·√(ρ/R_n)·V³(Sutton-Graves、地球 k = 1.7415×10⁻⁴)。今の熱モデル(ORBIT.md「熱と
  焼失」)が既にこれを使っている。**候補の評価では、予測の弧に沿って艦の熱収支も積分する**(今の予測の弧は
  熱を持たない — ORBIT.md「予測の弧は熱を持たず」)。候補が艦の温度上限 1,300 K と動圧上限 35 kPa の何割に
  達するかを出し、既定で 80% を超える候補は落とす。
- 形: (1) 直接遷移の近地点を大気の上層(地球で 90〜130 km)に置き、1パスで高い楕円へ捕獲する
  (揚力を持たない艦では1パスで LEO に入れるのは回廊が狭すぎる — 調査結果)。(2) 遠地点で近地点高度を
  調整しながら複数パスで遠地点を下げる(エアロブレーキ)。(3) 目標の遠地点に着いたら近地点を上げる燃焼で
  円軌道化する(調査例では約 80 m/s)。パス数と日数が候補の「所要時間」に入る。
- 回廊(浅すぎると抜け、深すぎると焼ける)は艦の弾道係数と大気密度に強く依存するので、近地点高度を
  走査して決める。

### 6.7 低エネルギー遷移(後の段階)

- 太陽-地球系の外回り(遠地点 100万〜150万 km、太陽の潮汐で近点を上げ下げする)弾道遷移。所要 3〜4ヶ月、
  機体側 Δv は数十〜150 m/s 級(Parrish et al., NTRS 20200011549。CAPSTONE・GRAIL の実績)。
- 窓は朔望月(約 29.5 日)ごとに巡る。リアルタイムの厳密解は重いので、月の位相と太陽方向をキーにした
  事前計算の表から初期推定を引き、全力モデルで補正する。
- 表の作り方(CR3BP・双円制限四体での探索、焼き込み形式)は別の計画書にする。

### 7.2 直し方の選択肢

どれを採るかは **ユーザーの判断**(§9 Q1)。

- **案 A(実在の化学推進に揃える)**: LH2/LOX の Isp 450 s(vₑ 4.4 km/s)、推進剤の嵩密度 361 kg/m³、
  推進剤質量比 0.9、モジュールの乾燥質量を実在の数 t 級にする。既定戦闘船の一例:
  コックピット 9 t・タンク(乾燥 5 t + 推進剤 58 t)・主スラスタ 2.5 t / 1.6 MN・その他 2.5 t で、
  満載約 77 t・乾燥約 19 t、**Δv ≈ 4.4 × ln(77/19) ≈ 6.2 km/s**、満載で 21 m/s²・空で 84 m/s²。
  NRHO→LEO の推進捕獲は片道約 3.7 km/s、大気減速を使えば約 0.6〜0.9 km/s なので、**往復を推進捕獲だけでは
  回せず、大気減速か給油が要る** — 方式の選択がそのまま遊びになる。
  影響: 質量が約 75 倍になるので、RCS トルク(24 kN·m/モジュール)・回頭の速さ・接触の運動量・ベルトの物理・
  加速度の段の意味がすべて変わる。戦闘の手触りの再調整を伴う大きな変更。
- **案 B(排気速度だけ現実寄りに、質量は今の尺度)**: 質量・寸法の尺度は変えず、Isp と推進剤量の比だけを
  「Δv が数 km/s」になるよう調整する(例: vₑ 4.4 km/s、推進剤 600 kg、乾燥 430 kg で Δv ≈ 3.8 km/s)。
  燃料が判断材料になる効果は案 A と同じで、手触りへの影響は推進剤の減り方だけ。ただし「6 m のタンクに
  600 kg」という容量の不整合は残る。
- **案 C(SF の先進推進として設定し直す)**: 核熱(vₑ 8 km/s)や核融合(数十〜100 km/s)を設定として採り、
  プルームの仕様(水蒸気)も変える。Δv が 30 km/s を超えると月⇄LEO では方式の差が燃料に出にくい。

**計画を書く側の推奨**: 自動航行の実装(P1〜P4)は推進系の数値に依存しない作りにする(vₑ は推力と消費率から
導出するだけ)。そのうえで、**推進系の再調整は独立した計画書として扱い、まず案 B で Δv を数 km/s にして
遊びを確かめ、案 A へ進むかを後で決める**。案 A は戦闘の手触りの全面的な再調整を伴うため、自動航行と
同じ変更に混ぜない。

### 7.3 推進系で、自動航行のために必ず要るもの

案によらず次は必要(P2 に含める)。

- 有効排気速度 vₑ = F/ṁ(ṁ = 消費率 × 単位あたり質量)を、推力を持つモジュールの集計から導く。
- 艦の Δv 予算 = vₑ·ln(m₀ / (m₀ − m_p))(m_p は使える主推進剤の質量)。RCS は別勘定。
- 燃焼で推進剤が減れば質量が減り、同じ推力で加速度が上がる(今の `throttle.ts:176` は推力 ÷ 現在質量で
  既にそうなっている)。
- 戦闘用 RCS タンクの推進剤質量 0 は、案を決めるときに併せて直す。

## 12. 採らなかった案

- **方式を先に選ばせる UI**(要求文どおり「ホーマン」「二重楕円」を選んでから解く)。不採用: プレイヤーに
  軌道力学の知識を要求する。方式名のチップでの絞り込みとして残した(§4.4)。
- **計画を有限燃焼の区間(開始時刻・燃焼時間・向き)で表す。** 不採用: 今の計画はノード=絶対状態で、
  予測・表示・保存・編集 UI がそれに乗っている。既定の加速度(20 m/s² 以上)では燃焼時間が数分で、有限燃焼の
  損失は燃焼後の解き直しで吸収できる。案 A で加速度が下がり燃焼が長くなったら再検討する。
- **自動航行を瞬間置換(今の自動実行)の拡張で済ませる。** 不採用: ユーザーが有限推力の実燃焼を選んだ。
  検証用の理想実行として残す。
- **軌道標識を仮想の衛星として実際に積分する。** 不採用: ユーザーが理想化した参照軌道を選んだ。
  目標が減衰すると置いた意味が失われる(§4.1)。
- **軌道標識を `DynamicEntity` として足す。** 不採用: 積分も接触も持たないものを Simulator と接触解決に
  載せることになり、`DynamicEntity` の能力旗と直列化の分岐が増える。
- **軌道ガイド線そのものをターゲットにする。** 不採用: ガイド線は表示時刻に合わせて引き直す参照で、位相を
  持たない(サブエージェント調査)。ガイド線から軌道標識を作る入口にした(§4.1)。
- **航行指令が航法ターゲット(視点)を直接読む。** 不採用: 進行が視点を読むことになる(ARCHITECTURE R4)。
- **燃焼のたびに時間加速を ×4 以下へ落とす。** 不採用: ユーザー決定。複数艦では頻繁に止まる。
- **低エネルギー遷移を最初から含める。** 不採用: ユーザー決定。

## 13. 落とし穴

- **燃焼の決定性**: 自動操縦の燃焼と回頭を、時間加速倍率で刻みが変わる経路(今の手動推力のようにフレームごと
  一定値)で積むと、倍率で最終軌道が変わる。燃焼中の艦は倍率によらない刻みで積む(§4.5)。P2 の達成条件の
  数値比較で必ず確かめる。
- **求解中の時刻の進み**: §6.5 の待ちを入れないと、高倍率で求解中に出発時刻を過ぎて解き直しが連鎖する。
- **J2 下の軌道要素の比較**: 艦の接触軌道要素は J2 の短周期変動で揺れる(LEO で長半径が km 級)。軌道標識は
  平均要素なので、到達判定を接触要素の瞬時値で行うと「一致しない」が続く。許容誤差を短周期変動より大きく
  取るか、1周平均で比べる。
- **月⇄地球の初期推定**: 地球中心の二体ランベルトは月近傍で弱い。パッチド・コニックと多重射撃が要る(§6.3)。
- **熱を持つ予測**: 大気減速の候補評価で熱収支を積むと、予測の弧の計算量が増える。候補の上位だけに行う。
- **操作対象でない艦の予測の長さ**: 今は表示期間までしか伸びない。航行指令の弧は需要と無関係に伸ばす(§8)。
- **ターゲットの消滅**: 目標の敵が撃破・消滅したら指令は失敗として止まり、艦はその場の軌道で漂う。黙って
  別の対象へ切り替えない(COMBAT.md「ターゲットは自動選定・自動再選定を行わない」と揃える)。
- **推進系の数値**: 案を決めないまま P3 を作ると、Δv がほぼ無限なので候補の比較が「時間だけ」になり、
  遊びとしての確認ができない。P3 の確認では理想実行と、Δv 上限の制約を手で絞ることで代用する。
