# UI・デザイン改善計画 第四版

この文書は単体で読めるように書いてある。前提知識は「本リポジトリは TypeScript + Three.js WebGPU の
ブラウザゲームで、HUD は DOM オーバーレイであり、見た目のトークンは `src/game/theme.ts` に一元化
されている」ことのみ。実地確認はコミット `1c074a6b` 時点のコードによる。

`UI・デザイン改善計画_第三版.md` の8施策(トークン一元化・タッチ入力・破損修復・ウィジェット統一・
オーバーレイ統一・レイアウト再構築・責務分割・タッチ到達性)はすべて完了済みで、本計画はその後に
残っている**トークン運用の不具合**と**配色の視認性**を対象にする。第三版のスコープ(骨格・責務分割)
とは独立に着手できる。

## 0. 前提調査で棄却した項目

着手前にコードを読み、以下は**実装済みで問題がなかった**ため対象から外した。理由を記録するのは、
同じ指摘を再提案させないため。

- 「メーターの地色 `#222222` がトークンを経由しないリテラル」という指摘 — 誤り。
  `src/game/theme.ts:255` の `BAR_BG` は正しくトークン化されており、`--bar-bg` として注入され、
  `widget-style.ts:91` 等はすべて `var(--bar-bg)` 経由。ただし**別の不具合**(`--bar-bg` が
  `themeCssVariables()` に未登録で配色切替に追従しない、および `vessel-panel.ts` が `DANGER`
  定数を直接インラインスタイルへ焼き込んでいた)は実在したため、コミット `16995432` で修正済み。
- 「フラット基調の方針とトーストの `box-shadow` が矛盾する」という指摘 — 誤り。`grep -rn box-shadow
  src/game/hud/` で確認したところ、影は**浮遊層(ウィンドウ・ポップアップ・トースト)にのみ**
  `var(--shade-1)` 経由で一貫して使われており、常設レール/パネルには使われていない。レール(平面)と
  ウィンドウ(浮遊)を影の有無で描き分ける意図的な二層設計であり、矛盾ではない。

## 1. 目的

既定配色 `fluorescent-red-blue`(と `fluorescent-pink-dawn-blue`)は、アクセント色と警告色
(`error`)の RGB距離が31〜37(0〜441の尺度)しかなく、選択中の強調表示と危険表示が実質同じ赤に
見える。この点を直す。

(ライブ配色切替に追従しない `--bar-bg`・`vessel-panel.ts` の放熱板表示は前段の手順で修正済み。)

## 決めたこと

1. **警告色そのもの(`DARK_SEMANTIC.error`)は変えず、代わりに衝突している2プリセットの
   `accent`/`accentNear` を、警告色から離す。** 警告色は「危険な数値の読み上げとターゲットロックの
   強調表示の両方が共有する1色」という規約(`DEVELOP/SPEC/UI-DESIGN.md` §2)がある専用色で、10
   プリセット中8つは既にこの色と十分離れている(RGB距離62〜199)。2プリセットだけがたまたま
   警告色に近い赤を選んでいるので、直すのはプリセット側と判断した。ユーザーが逆(警告色側を動かす)
   を望むなら手順2の対象を入れ替えるだけで済む。

## 達成目標

- `fluorescent-red-blue`・`fluorescent-pink-dawn-blue` の `accent` と、対応する `error`(いずれも
  `tone: 'dark'` なので `DARK_SEMANTIC.error`)の RGB距離が60以上になっている(既存は31・37で、
  選択強調と危険表示が実質同じ赤に見えていた)。
- `npm run typecheck` が通る。

**注記(手順2実施中に判明)**: 全11プリセットを実際に計算すると、`red-orange-turquoise`(距離62)・
`sagebrush`(距離70)・`matte-red`(light配色、対応する `LIGHT_SEMANTIC.error` との距離59)も
80未満だった。ただしこれらは31・37ほど致命的な近似ではなく(特に `matte-red` はマットな暖色地の
配色で警告色も暗い赤へ変わるため、彩度・明度の違いで見分けやすい)、当初の目的(選択強調と危険表示が
「実質同じ赤」に見える2プリセットの解消)には該当しない。全プリセット一律80以上を狙うと3プリセット
追加の配色調整が要り、本計画のスコープを超えるため、目標は上記2プリセットの解消に絞った
(判断はユーザーが上書き可能——広げるなら新しい手順として追加する)。

## 手順

### 手順2. 警告色に近い2プリセットのアクセント色を離す

**目的**: `fluorescent-red-blue`(既定配色)と `fluorescent-pink-dawn-blue` の `accent` を、警告色
`#ff4f5e` からRGB距離60以上へ離す。選択中の強調表示(アクセント色)と危険表示(警告色)を画面上で
見分けられるようにする。`accentNear`(ホバー色)も同じ色相を保ったまま追従させる。

**変更した箇所**(実施済み):

| ファイル | 変更内容 |
| --- | --- |
| `src/game/theme.ts:59-61`(`fluorescent-red-blue`) | `accent: '#ff3155'`(距離31)→ `'#ff0090'`(距離93、赤からマゼンタへ)。`accentNear: '#ff6b82'` → `'#ff59b7'`(同方向へ追従)。`description` の「赤と青」→「マゼンタと青」。 |
| `src/game/theme.ts:63-65`(`fluorescent-pink-dawn-blue`) | `accent: '#ff2d6c'`(距離37)→ `'#ff0080'`(距離86)。`accentNear: '#ff6f96'` → `'#ff59ac'`。`description` から「朱色寄りの」を削除(マゼンタへ寄ったため)。 |
| `src/game/theme.ts:49-98`(`THEME_PRESETS` 全体) | 上記2件以外は変更しない(達成目標の注記のとおり)。 |

**達成条件と検証**:
- `npm run typecheck` が通る。
- 距離計算ワンライナーで両プリセットが60以上であることを確認済み(`fluorescent-red-blue`: 93、
  `fluorescent-pink-dawn-blue`: 86)。
- `npm run dev` で `Arcade Pulse`(`fluorescent-red-blue`)を開き、艦ステータスのアクセント表示
  (選択中のタブ等)と、部品HPを危険域まで下げたときの警告表示を並べて目視し、別の色として
  見分けられることを確認する。

## 見積り

- 手順1: `theme.ts`・`vessel-panel.ts` の2ファイル、増減とも10行未満の変更。実測でなく変更行数からの見積り。
- 手順2: `theme.ts` の2プリセット定義行のみ。色の最終値決定に検証スクリプトの実行(数秒)×試行回数が
  かかるが、コード変更自体は数行。
