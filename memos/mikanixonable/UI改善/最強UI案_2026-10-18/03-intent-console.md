# 案03 INTENT CONSOLE — 意図で指揮し、選択肢を「地形」として選ぶ

動くモック: [`03-intent-console.html`](./03-intent-console.html)(単一ファイル。ブラウザで開くだけ)

## 1. 一行コンセプトと、解く問題

**プレイヤーは「どの方向へ何 m/s」ではなく「あれに会合する」「背後に付く」「降りる」と意図を示す。
システムは答えを1つ押し付けず、取りうる答えの全体を「出発時刻 × 所要時間」の地形として見せる。
プレイヤーは地形の上の1点をドラッグして選び、ゴースト軌道がそれに追従する。**

### いまの UI の根本問題

現行のマップビューは、ノードを置き、PRO/RET・NRM/ANM・IN/OUT の3軸を W/S/A/D/E/Q で
手回しして、軌道線が目的地に届くかを目で見ながら探る(`DEVELOP/SPEC/PLAN.md` §4)。
これは **「解を探す」作業を、最も情報の乏しい入力(3軸の数値)でやらせている**。問題は3つある。

1. **意図が UI に存在しない。** 「あの敵に会いたい」という目的はプレイヤーの頭の中にしかなく、
   画面にあるのは Δv の成分だけ。目的と手段の翻訳を毎回人間がやる(KSP で一番心が折れるところ)。
2. **選択肢の広がりが見えない。** 今出発するのが良いのか、あと20分待つほうが安いのか、急ぐと
   いくら高いのか — 時間窓の概念が、ノードを動かして試すまで分からない。1点ずつしか見えない。
3. **コストが Δv 1本に潰れている。** このゲームは近距離戦と軌道遷移が同じシミュレーションの異なる
   時間スケールなので、遷移の良し悪しは Δv だけでなく**所要時間(戦闘までの猶予)と被弾リスク**でも決まる。
   現行 UI はその多目的性を一切見せない。

## 2. 体験の描写 — LEO で敵に会合し、背後から撃つまで

> 自機は高度 400 km、補給コンテナ C-1 が前方。その先、守るように敵ペプチド P-03 が浮かぶ。

| 時刻 | プレイヤーの行動 | 画面で起きること |
| --- | --- | --- |
| T+0:00 | 敵 P-03 をクリック | 放射メニューが開く。**会合 / 迎撃 / 占位 / 離脱 / 降下**。敵には「迎撃」が薄く縁取られる(推薦ではなく既定の強調) |
| T+0:03 | 「占位(背後 600 m)」を選ぶ | メニューが畳まれ、右にチャートが現れる。横=出発時刻、縦=所要時間。色=Δv、赤い斜線=被弾リスク |
| T+0:05 | チャートを眺める | **谷が1本、浮かんでいる**。谷底は出発 +38 分/所要 46 分あたり。その右上は急ぐほど暗い(高い)。左の帯は「いま」の線に塗りつぶされていく — **窓が閉じていく** |
| T+0:08 | 谷の近くをドラッグ | 軌道図にゴースト(細い水色の線)が追従し、出発バーンと到着点が動く。Δv 予算バーのオレンジが伸縮する |
| T+0:12 | 「リスク上限」スライダを 50% に絞る | 赤斜線の外側が暗転し、谷が**欠ける**。さっきの谷底は使えなくなり、少し高くつく別の谷へ移る必要が見える |
| T+0:15 | `C` で「前線」タブへ | 同じ候補が「所要時間 × Δv」の散布図になり、色がリスク。**どれも他に劣らない点**(パレート非劣解)だけ白縁で光る。点をつまむと地形側の点も動く |
| T+0:20 | 前線から「少し遅いが安全で安い」点を選ぶ | 敵の前方弧を避け、背後から入り込む経路。到着点は敵の死角の中 |
| T+0:22 | `Enter` で確定 | 2つのノードに展開され、「実行中の計画」に T-mm:ss のカウントダウンが並ぶ。`N` で次バーンの直前まで時間加速 |
| T+0:40 | バーン、慣性航行、到着バーン | **ここから先は現行の戦闘ビュー**。背後 600 m から、残した Δv 予備で撃つ |

要点は T+0:05 と T+0:12 にある。**「最適解はこれです」とは誰も言わない。** プレイヤーは地形の形そのものから、
「窓が開くのを待つ」「リスクを飲んで急ぐ」「燃料を温存する」の選択肢を自分で読み取る。

## 3. 構成要素

### 3.1 意図(Intent)— 「何をしたいか」を示す入口

| 意図 | 求めるもの | チャートの縦軸 | 数理(モック) |
| --- | --- | --- | --- |
| 会合 | 対象と同位置・同速度 | 所要時間 | 2インパルス。Lambert + 到着バーン |
| 迎撃 | 対象の位置を通過(最小 Δv) | 所要時間 | 出発バーンのみ。到達時の相対速度を表示 |
| 占位 | 対象の背後 600 m に付く | 所要時間 | 会合と同じだが目標点が対象の背後 |
| 離脱 | 高い軌道へ逃れる | 遠地点高度 | 近地点で順行バーン(ヴィス・ヴィーヴァ) |
| 降下 | 大気ブレーキで降りる | 近地点高度 | 逆行バーン。深く入るほど速く・熱く |

- **入口は2つ。** (a) 天体をクリックして放射メニュー、(b) `Ctrl+K` / `/` のコマンドパレット。
  パレットは「かいごう」「迎撃 P-03」「降下」などを空白区切りで AND 絞り込みする。
  熟練者は手を離さずに意図を打ち込め、初心者は絵で選べる。
- 放射メニューは **5方向固定(位置が筋肉記憶になる)**。数字キー 1〜5 でも選べる。
- 対象の無い意図(離脱・降下)は自機をクリックしても出る。対象が要る意図は自機では無効化される。

### 3.2 選択肢の地形(Choice Terrain)— 「どんな選択肢があるか」

- **地形タブ**: 横=出発時刻(いまから)、縦=所要時間。色=Δv(明るい=安い)、白い等高線=一定 Δv ごと。
  赤い斜線=被弾リスクの高い領域。薄い白点=非劣解の「尾根」(選びはしない目印)。
- **前線タブ**: 横=所要時間、縦=Δv、色=被弾リスク。非劣解は白縁。リスク上限スライダで制約を動かせる。
- **「いま」の線**: 左側は過去の出発時刻なので暗く塗られ、時間とともに右へ進む。点がその線に押される。
  「待てば安くなる」「待つと窓が閉じる」を、時間加速の実時間感覚として体に入れる。
- **ホバー**: カーソル位置の Δv・所要・リスクを下に1行だけ出す(ホバーは装飾であり、情報はクリック後の
  読み出しにも必ず出る — UI-DESIGN 原則6を守る)。

### 3.3 読み出し・Δv 予算・エキスパート層

- **選んだ計画**: 出発までの時間、所要、Δv(出発/到着)、被弾リスク、目標点とのずれ。
- **Δv 予算バー**: [残り(緑)][この計画(橙の斜線)][使用済み(灰)] と、**戦闘用予備**の黄色い目盛り。
  計画が予備を割ると文字が黄、予算を超えると赤になり、確定ボタンが無効になる。
- **エキスパート層**(折りたたみ): 出発時刻・所要・PRO 補正・RAD 補正の4本のスライダと、ノード表。
  補正量は意図の解に**上乗せ**される(0 に戻すボタンあり)。補正すると到着時のずれが即座に増える —
  手でいじると会合が外れることを、数字で体験できる。モックでは補正 PRO +30 / RAD −20 m/s で
  280 km 外すことを確認済み。
- **実行中の計画**: 確定済みノードのカウントダウン。確定後はゴースト線がオレンジ破線に変わる。

### 3.4 状態遷移

```
 IDLE ──天体クリック/パレット──> PICKING(放射メニュー)
   ^                                  │ 意図を選ぶ
   │                                  v
   │                            PLANNING(地形 + ゴースト)
   │      Esc(破棄)                 │  ドラッグ / スライダ / Tab 切替 / リスク上限
   ├─────────────────────────────────┤
   │                                  │ Enter(確定)
   │                                  v
   └──────── 完了 <────────── COMMITTED(ノードを実行待ち。N で次バーンへ)
```

## 4. ビジュアル言語

- **色**: 暗い背景に、ゴーストは水色の細線、確定は橙の破線。橙(#ff6a00)は「プレイヤーが選んだもの」だけに
  使う。敵はマゼンタ、友軍は青。地形の色は低 Δv=明るい黄白 → 青緑 → 深い藍(高 Δv)の一方向に並べ、
  虹色は使わない。リスクは**色相でなく斜線パターン**で重ねる(色覚の差でも読める)。
- **補助線は引くが目立たせない**: 標的の予測経路は点線の淡い橙、出発前の慣性航行は白い点線、
  脅威圏は 5〜10% の塗り。常に見えるのは「いまの位置」と「選んだ線」だけ。
- **動き**: 放射メニューは 0.18 秒でバネ状に展開。「いま」の線は連続して進む。点が線に押される動きは
  アニメーション無しの即時反応(窓の閉じる感触を邪魔しない)。
- **文字**: 数値は等幅、見出しは字間を詰めない小さめのキャプション。1画面に出す数値は読み出しの6つ程度。
- **音(提案)**: メニューの選択音は短い1音、点が谷の底を通る瞬間にだけ微かな低い共鳴音、窓が閉じ切った時に
  1回だけ鈍い音。リスクが上限を超える領域に入ると、点が触れた瞬間に擦れた音。1970 年代風の世界観では
  計算機の「確定」を電気式リレーの音にできる(世界観案との接点)。

## 5. この案だから可能になるゲーム性

1. **時間窓が遊びになる。** 「待てば安い」と「待つと敵が動く」が、チャートと時間加速の組合せで直接見える。
   無限耐久・スコアアタックで、出発のタイミングを読む熟達の軸が生まれる。
2. **多目的の選択が日常になる。** 速さ・燃料・安全を毎回天秤にかけるので、**同じ敵でも毎回違う解**を選ぶ。
   パレート前線は、設計者が「不自由度」(燃料と時間窓の制約)を置くための直接の道具になる。
3. **敵が地形を変える。** 敵の前方弧(死角が背後にある)という戦術情報が、そのまま地形の赤斜線として
   現れる。敵の配置や武装を変えると、地形の形が変わる = **敵設計が UI の絵として確かめられる**。
4. **「戦闘用予備」が戦略の資源になる。** 予算バーの予備目盛りは、遷移でどこまで使うか、戦闘に何を残すかを
   常に意識させる(高倍率の時間加速中は撃てないという現行の制約とも噛み合う)。
5. **群像劇・遅延指令への土台。** 意図は「何を・いつまでに」の記述なので、遠隔の艦に意図だけを送り、
   光速遅延後に計画が展開される形に自然に伸ばせる(案「艦隊管制」との接点)。

## 6. 既存の前提をどう破るか、破って何を得るか

| 前提(現行 SPEC/方針) | この案での扱い | 得るもの |
| --- | --- | --- |
| 計画の入力は**ノードの Δv 3軸の手動編集**(PLAN.md §4) | 主入力を「意図 + 地形上の点」へ。3軸は**エキスパート層**へ降格(補正として残る) | 入口の敷居低下。目的と手段の翻訳を機械に任せる |
| **最適遷移を自動生成しない**という方針 | 「最適解」は出さない。代わりに**全候補の地形を出す**(下記の論点) | 方針を保ったまま、探索の苦役だけを取り除く |
| 「計画軌道は折れ線(ノード)だけ」 | 計画は「意図 + 選択点 + 補正」から導出される。確定時にノードへ展開 | 計画の意味(何を狙ったか)が残る |
| UI は数値パネルが縦に並ぶ(七原則1「一責務一 UI」) | 地形チャートは1つの問い「どの出発・所要の組み合わせが取れるか」に答える。読み出しは別パネル | 原則は守る。問いの単位が「パラメータ」から「選択肢の集合」へ変わる |
| ホバーは装飾(原則6、タッチ第一級) | ホバーは補助のみ。クリック/タッチ後の読み出しに同じ数値が出る | 原則を破らずに、マウスでは素早く読める |

### 「最適遷移を自動生成しない」との両立 — 論点

この方針の核は、おそらく次のどれかだ(作者に確認したい。モックでは3つ全てを満たすようにした)。

- (A) **作っているのはプレイヤーだと錯覚させる**(作者の言葉): 答えを渡されると「やらされている」感が出る。
- (B) **自由度でなく不自由度を設計する**: 選択肢が多すぎると、ゲームは設計ではなく計算になる。
- (C) **軌道力学を学ぶ過程そのものが遊び**: 解が出ると、なぜそうなるかを学ぶ機会が消える。

案03の立場は「**答えは出さず、地形を出す**」だ。

1. **「最適」ボタンは存在しない。** 画面のどこにも「おすすめ」「最適」の文字を置かない。
   非劣解は薄い白点(尾根)と、前線タブの白縁として**存在を示すだけ**で、クリックしても自動では選ばれない。
2. **何を最適とするかは、プレイヤーが重み付けする。** Δv・所要・リスクの3目的は互いに衝突し、
   上限スライダと点の位置で重みが決まる。唯一の最適は存在しない(多目的最適化の前線そのもの)。
3. **地形は事実で、助言ではない。** チャートが出すのは「この組み合わせならこのコスト」という写像であり、
   「だからこうしろ」ではない。プロの管制官が見る図(NASA/ESA のミッション設計で使うポーキーチャート)は
   まさにそういう道具で、人間が谷底を選ぶ。
4. **「谷へ吸着」は既定でオフの弱い補助。** オンでもドラッグ中の近傍の谷へ**45% だけ**寄せる。
   「補助線は引くが目立たせず、作っているのは自分だと錯覚させる」の実装形。吸着の存在を設定で選ばせる。
5. **ゲームごとの設定にできる。** 高難度ステージでは尾根・リスク陰影・等高線を段階的に隠せる。
   「地形」を見せる量そのものが、不自由度の設計パラメータになる。

## 7. 実装の見取り図

### 7.1 層の割り当て(現行 ARCHITECTURE の規則に沿って分けるなら)

| 役割 | 置き場の目安 | 内容 |
| --- | --- | --- |
| 純粋計算 | `src/physics/` | Lambert(万有変数・多周)、二体伝播、被弾リスク積分、パレート抽出。**描画・DOM を知らない** |
| 意図の定義 | `src/game/` | 意図→チャート軸・評価関数・ノード展開。計画データ(意図 + 選択点 + 補正) |
| 描画 | `src/render/` | マップ上のゴースト、脅威圏の扇形。チャートは DOM の canvas |
| HUD | `src/hud/` 相当 | 放射メニュー、チャート、読み出し、予算バー、パレット |

(正確な置き場は ARCHITECTURE.md の規則に従って決める。上は役割の分け方の目安。)

### 7.2 難所

1. **Lambert の頑健性。** 0周は万有変数 + 二分法で十分(モックで全格子 1,632 点を伝播し直し、終点誤差 1 km 超は 0 件)。
   本番は多周解、180 度近傍の特異点(平面が定まらない)、3次元(傾斜・節線)が必要。Izzo (2015) の
   解法が現実的。ゲームでは「解なし」領域を地形の黒塗りで素直に見せればよい。
2. **二体近似の外側。** J2 / C22 / 大気抗力 / 太陽放射圧 / 月の摂動を含む実軌道では、Lambert の解は
   **初期推定**にすぎない。本番は「Lambert → 数値シューティングで補正」の二段にし、チャートは格子の
   各点で補正まで走らせる(重い)。**格子を粗く、選択点だけ高精度**にする段階化が必須。
   シスルナ(L1〜L5)は三体なので Lambert が成立せず、別の意図(「L1 ハロー軌道へ」)を別実装にする。
3. **計算量。** 格子 48×34 で 1.6k 点 × 経路サンプル 8〜36 点の Kepler 伝播。モックは数十 ms で回る。
   本番は Web Worker に出し、選択点の周辺だけ増分計算する。「いま」の線で窓が閉じるぶんは再計算不要
   (格子は意図開始時の時刻に固定している)。
4. **被弾リスクの定義。** モックは「脅威圏内かつ敵の前方弧にいる時間」を積分した仮の値。本番では
   敵の実際の射程・照準性能・火器管制のモデルを使う必要がある。**リスクの定義は敵 AI 側が持つ**べきで、
   UI が独自計算してはいけない(責務の逆転)。
5. **地形の 3 次元化。** 軌道面外の遷移(面変更)が入ると、2軸のチャートに載らない。「離脱/降下」のように
   意図ごとに軸を定義し、面変更は別意図(「面を合わせる」)にする。

### 7.3 段階的な導入順

1. **第一歩(1〜2 日)**: 「会合」だけを実装。対象を右クリックして意図を選ぶと、Hohmann 近似の
   ポーキーチャートが出て、1点を選ぶとノード2つが置かれる。既存のノード編集はそのまま使える
   (エキスパート層は既に存在する)。
2. 迎撃・占位を追加(同じ Lambert を使い回す。目標点だけ変わる)。
3. 被弾リスクを敵から取得し、リスク陰影を重ねる。
4. コマンドパレット(意図のほか既存コマンドも載せる。後から他の UI の入口になる)。
5. 前線タブとリスク上限スライダ。
6. 摂動を含む補正計算と、離脱/降下。最後に本番の多周 Lambert。

## 8. リスクと反論、他案との組み合わせ

### 8.1 想定される反論

- **「ポーキーチャートは初見で読めない」**: その通り。KSP の Transfer Window Planner を知らない人にとって
  は暗号に近い。→ 対策: 点を動かすとゴーストが動く**因果の即時性**が教材になる。チュートリアルは
  「谷に点を置け」の1行。色は「明るい=安い」の一方向のみで凡例を常に出す。それでも理解に5〜10分は要る。
- **「結局プレイヤーは谷底を選ぶだけで、考えない」**: 谷底が常に正解になるのは Δv 1目的のときだけで、
  3目的ではそうならない。ただし、リスクと所要の重みが敵の強さで均されるステージでは、解が自明になりうる。
  → 敵・燃料・時間窓の設計で「自明な谷底」が無いようにするのがステージ設計の仕事になる。
- **「現行方針と矛盾する」**: §6 の通り、(A)(B)(C) のどれを重視するかで評価が分かれる。(C)(学習)を最重視する
  なら、エキスパート層と等高線を最初に見せて、意図メニューを後から開放する導線にする。
- **「戦闘のスピード感に合わない」**: 計画は戦闘中ではなく戦闘の**前**の段階の道具として設計している。
  戦闘中の素早い再計画には、パレット + 前回選んだ意図の再実行(「同じ意図をもう一度」)が要る(未実装)。
- **「Lambert の解は実軌道で外れる」**: 二段化(7.2-2)で解決する。ずれは確定後も計画線と比較して見える。

### 8.2 他案との組み合わせ(深入りしない)

- **シームレスズーム**: 意図の対象を、ズームアウトしたマップ上のどこからでも掴める。地形の点を動かす操作は
  ズームレベルに依存しない(時間スケールの連続性と相性が良い)。
- **相対運動計器**: 到着後の最終接近(背後 600 m の維持)を、意図メニューで「占位」と選んだ後に
  相対運動計器へ引き渡す。両者の境界は「ランデブーまでは地形、そこからは計器」。
- **世界観ダイエジェティック**: 執政官の結晶が「意図」を受け取る語りに変換できる(「承知した。会合の窓を
  3 つ見つけた」)。ただし**窓の数を数えて数字で告げるのは禁止** — 助言になってしまう。
- **艦隊管制**: 意図は艦隊の各艦に配る単位にそのままなる。群像劇では意図だけ送り、遅延後に展開する。
- **状況適応 HUD**: 戦闘中は地形を隠し、パレットの1キー再実行だけを残すなど、文脈で入口の重さを変える。
- **分子模型建造**: 建造は別の「意図」(船体を何に変えたいか)として同じパレットに載せられる。

## 9. 5軸での自己評価(甘くしない)

評価軸: 直感性・一般性・美学的美しさ・視認性・一貫性。5段階(5=最高)。

| 軸 | 点 | 根拠 |
| --- | --- | --- |
| 直感性 | **3** | 放射メニューと「点を動かすとゴーストが動く」は直感的(4相当)。だが**ポーキーチャートの読み方**は学習が要り、「窓が閉じる」「谷」の概念を一度飲み込む必要がある。初見で意図を選んで確定までは行けるが、「なぜその点なのか」の理解は遅れる。 |
| 一般性 | **4** | 意図という抽象が、会合・迎撃・離脱・降下・将来の「面合わせ」「L1 へ」へ同じ形で拡張できる。チャートの2軸+色という枠は多くの遷移に使える。一方で**三体問題・低推力・面外遷移**では地形が2軸に収まらず、意図ごとに作り込みが要る(5にならない理由)。 |
| 美学的美しさ | **4** | 地形(等高線+パターン)は「見えない構造が見える」美しさがあり、ゴーストが追従する動きも気持ちよい。ただしリスクの赤斜線は画面の中で最も強い要素で、「補助線は目立たせず」の思想と引っ張り合う。静かな状態(地形を隠す)も用意すべき。 |
| 視認性 | **3** | 1画面に「軌道図・チャート・読み出し・予算」と情報が多く、チャートの色+斜線+等高線+尾根点の4層は密度が高い。色は一方向の連続量で、リスクはパターンで分けたので色覚差には強いが、チャートの文字(10.5px)は小さく、タッチ(原則6の44px)ではドラッグ精度が足りない。狭い幅では縦に伸びて地形と軌道図が同時に見えなくなる。 |
| 一貫性 | **3** | 意図→地形→確定→ノードの流れ自体は一貫している(ノードは意図の展開結果)。しかし「放射メニュー・パレット・チャート・スライダ」と入力の様式が4種混在し、現行の Tepui Glass のパネル語彙とも新旧が並ぶ。エキスパート層との往復(補正が上乗せ)も説明が必要。 |

総評: 単独では 3.4 点。**一般性と美しさは高いが、学習コストと情報密度が足を引っ張る。**
直感性と視認性は「相対運動計器」「状況適応 HUD」案との併用で上げられる(8.2)。

## 付録: モックの近似と注意

- 軌道は2次元・同一面・円軌道の二体。自機・補給コンテナ・敵・ドックはすべて円軌道で、
  Lambert は 0周・順行のみ。**時間と位置は合っていて、絵として嘘をついていない。**
- 径方向の表示は強調している(高度 0.62 乗のスケール)。実距離の比ではない。脅威圏も誇張した値(1500 km)。
- 被弾リスクは「脅威圏内 × 敵の前方弧 ±約70°の時間積分」の仮のモデル。降下の所要時間と周回数は見積り式。
- 計算の検証: 全格子 1,630 点の Lambert を伝播し直して、終点誤差 1 km 超は 0 件(抜き取りでは 1e-10 km 級)。補給コンテナへの会合は確定後に
  0 m で成功し、補正を入れると外れる(PRO+30/RAD−20 m/s で 280 km)。
- **試せる操作**: 天体クリック→放射メニュー(1〜5)、`Ctrl+K` / `/` のパレット、チャートのドラッグ、
  地形/前線の切替(`C`)、リスク上限、谷へ吸着、エキスパート層のスライダ、`Enter` で確定、
  確定後は実際にバーンして会合(時間加速 ×10〜300、`N` で次ノードへ)。
