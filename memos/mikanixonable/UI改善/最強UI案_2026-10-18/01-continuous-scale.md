# 案01 連続スケール — ひとつの連続した空間と時間(Powers of Ten)

> リファレンス(動くモック): `01-continuous-scale.html`(同じフォルダ。ダブルクリックで開ける)

## 1. 一行コンセプトと、解く問題

**戦闘ビューとマップビューの切替を廃止し、ホイール1本で「自機の数 m 先」から「地球–月系」までを
シームレスに往復する。ズームの深さがそのまま時間の流れを決め、画面下端の時間軸は「掴んで引くと、
全物体が未来へ動く」。**

### いまの UI の根本的な問題

README は「近距離戦と軌道遷移は別ゲームではなく、同じシミュレーションの異なる時間スケール」と
言うが、UI はその逆を体現している。

- 戦闘ビューとマップビューは **別の画面**で、M キーで切り替わる。切り替えた瞬間にプレイヤーの
  頭の中の座標系・縮尺・時間感覚が全部リセットされる。
- 時間加速は `,` `.` で **スケールと無関係に**上げ下げする。「×64 にしたまま戦闘ビューに戻って
  撃てない」「×1 のまま軌道遷移を待ち続ける」といった、スケールと時間のミスマッチをプレイヤーの
  注意力で補っている(GAME.md §4: 推進・射撃は ×4 以下、交戦圏も ×4 以下のときだけ存在する)。
- 未来を知るには、マップビューへ行き、マニューバノードを置き、数値パネルを読む。**「あと何分後に
  どこで最接近し、そのとき日陰か、撃てるか」を一目で掴む手段がない。**
- 数値を読んで頭で相対運動を組み立てる負担が大きい。相対運動は本来 **形** で見えるもの
  (後述の相対経路)。

この案はその根を「スケールと時間を、別々の設定値ではなく、ひとつの軸の両面にする」ことで断つ。

## 2. 体験の描写 — LEO で敵と会合して撃破するまで

モックの初期配置を使う(自機 TEPUI-1 は高度 400 km の円軌道、PEP-α は約 62 km 後方・やや低い軌道で、
約 49 分後に 5.7 km まで接近する。最接近は自機の日陰区間の出口にあたる)。

1. **起動。** 数 m の視野で、自機の船体(タンク・太陽電池・ラジエータ・砲)だけが見える。
   画面中央に自機、下に地球の青い気配、左右に水平に走る自機の軌道線(= 地平線)。時間は ×1。(モックでは起動時に、ここから会合圏まで自動で引くイントロが走る。操作すると止まる。)
2. **ホイールを引く。** 船体がみるみる小さくなり、写実の絵が **チェブロンのアイコン**へ、さらに
   **光点**へ溶ける。格子が 10 m → 100 m → 1 km と十進で切り替わる。画面右の軸で、現在位置を示す
   白い三角が上へ動き、**時間加速の点も同時に右へ動く**。×1 → ×2 → ×4 と上がり、交戦圏(30 km)の
   縁を過ぎたところで、画面端に「**交戦圏 30 km · ≤×4**」の橙の破線円が現れる。
3. **会合圏(視野半径 ~100 km)。** 左に PEP-α の光点(ペプチドの鎖のアイコン)。その軌跡が
   **自機に対する相対経路**としてピンクの曲線で描かれ、自機の下 5.7 km を滑り抜ける様子が
   曲線ひとつで読める。曲線上に「+17m」「+33m」の時刻目盛、最接近点に紫の印「最接近 5.68 km」。
   時間は ×64 で流れ、敵はするすると近づく。
4. **未来を掴む。** 下端のタイムラインに、距離の曲線・射撃可能区間(赤)・日照/日陰(琥珀/藍)が
   並んでいる。曲線の谷(最接近)が射撃可能の帯の中にあり、そこが藍(日陰)から琥珀(日照)へ
   変わる境目だと分かる。プレイヤーは時間軸を **掴んで右へ引く**。画面全体が藍紫に色づき
   「FUTURE +41m40s」の帯が出て、**全物体がその時刻の位置へ動く**。敵は自機のすぐ下にいて、
   太陽電池の面が日向へ出る寸前だ。指を離すと、世界は現在へ滑らかに戻る。
5. **決める。** 「最接近へ」(N キー)を押すと、時間加速が自動で上がり、**接近とともに自動で
   減速**して交戦圏の縁で ×4 に落ち着く。ホイールを手前に回すと視野が 16 km へ寄り、敵が鎖の
   アイコンとして交戦圏の縁に入ってくる。距離 12 km の射程リングを越えた瞬間、照準の見越し点が
   橙で現れる。
6. **撃つ。** さらに寄ると PEP-α が鎖の **ビーズの連なり**(活性部位が赤、結合部位が青)として
   見える。W/S で軌道を微修正し、Space で連射。命中ごとに部位が暗転し、「命中 3/5」「撃破」。
7. **見渡す。** 数字の 5 キーで、ひと息に地球–月系へ引く。ラグランジュ点 L1〜L5、月軌道、
   地球の影の帯、「LEO 戦域」という桃色の小さな輪。さっきの戦闘は、その輪の中の一点だった。

## 3. 構成要素

### 3.1 スケール軸(セマンティックズームの5層)

視野半径 R = 8 m 〜 60 万 km を、ひとつの連続変数 `lr = log10(R[m])` で扱う。層は区切りではなく
**見せ方の重み付けが滑らかに入れ替わる帯**であり、層の名前は目安として右の軸と画面上部に出る。

| 層 | 視野 | 主役の表示 | 答える問い |
| --- | --- | --- | --- |
| 機体 | ~300 m | モジュールの写実(タンク/パネル/砲/推進器、噴射炎)。敵はペプチドの鎖 | どこが壊れた・何が展開している |
| 近接戦闘 | ~30 km | 照準・見越し点・射程リング・PRO/RET 記号・敵の部位 HP | 当たるか・間合いはどうか |
| 会合圏 | ~500 km | **自機に対する相対経路**、時刻目盛、最接近点、交戦圏の円 | いつ・どこで・どれだけ近づくか |
| 軌道 | ~2 万 km | 軌道線、地球、地球の影、日照、護衛コンステレーションの輪 | どの軌道に乗っていて、いつ日陰か |
| 地球–月系 | ~60 万 km | 位相図: 月軌道、L1〜L5、「LEO 戦域」の輪 | 全体の舞台はどこで、どこへ向かうか |

表示の抽象度は **画面上の大きさ(px)** で決まる。物体は大きさに応じて「写実 → アイコン → 光点」へ
**アルファで重ねて**切り替わる(モックの `drawBody`)。条件分岐でパッと入れ替えず、必ず中間
状態を通る — ここが「層」でなく「連続」であることの肝。

座標系も連続的に変形する。**近: 自機中心で地球が常に下**(LVLH。動径外が上、進行方向が右)
→ **遠: 地球中心の慣性系**。回転の混ぜ合わせは視野 ~1000 km 〜 1 万 km、中心の移動は
~2000 km 〜 2 万 km で行う。LVLH の利点は、相対運動が「ただの 2D の動き」になること。

### 3.2 スケール⇄時間の連動則(この案の核)

右の軸は **左半分が空間のスケール、右半分が時間加速**で、1枚の図に両方を載せる。

```
 視野(対数)      時間加速の段 L(×2^L)
 地球–月  10⁵km ┤                          ● ← 現在値(白い縁取りの点)
                │                       ／
 軌道    10⁴km ┤                   ／   ← 推奨曲線(水色の実線)
                │               ／       上限曲線(同・点線)= 推奨 +3 段
 会合圏  100km ┤          ／
                │       ／
 交戦圏  30km ┤╌╌╌╌╌┤ ← ここから内側は上限が ×4(橙の領域 = 武器域)
 近接    1km  ┤▒▒▒▒│
 機体    10m  ┤▒▒▒▒│
                └──┴──┴────┴──────
                 ×1  ×4  ×16   …  ×4k
```

**規則(モックの実装どおり)**

1. **推奨段 = f(視野)。** 視野を広げると自然に上がる(10 km で ×2、100 km で ×64、
   1 万 km で ×1024、60 万 km で ×6 万〜13 万。月の公転 27 日が約 40 秒で回る)。画面に映る相対運動が、おおむね同じ速さに
   見えるように決めた経験則で、物理則ではない。
2. **武器域の閉じ込め。** 視野半径が交戦圏(30 km)以下のとき、上限は常に ×4。**ズームインは
   戦闘時間への「コミット」になる。** 現行 SPEC の「交戦圏は ×4 以下のときだけ存在する」を、
   プレイヤーが暗記するルールから **ズームという操作の自然な帰結**に変える。
3. **接近減速。** 目標との接近が近づくと、残り時間が画面上 8 秒を切らないよう上限を絞る
   (`log2(接触までの時間 / 8)`)。交戦圏に入った敵がいれば、視野によらず ×4 まで落とす。
   画面のタグに「接近減速」「交戦圏」と **理由が出る**(黙って遅くしない)。
4. **連動 ⇄ 固定(L キー)。** 「固定」にすると時間倍率はズームに追従しない(上限だけは効く)。
   `,` `.` は連動時には推奨段への ±バイアス、固定時には直接の段。
5. **ワープ。** N(最接近へ)/ Enter(掴んだ時刻へ)で自動ワープ。残り時間に比例して減速し、
   ×1 で到着する。ゴーストは到着点を指したまま「近づいてくる」。

### 3.3 未来を掴むタイムライン

画面下端の帯。横軸は **現在から先の時間**で、その長さ(ホライズン)も **スケールに連動する**
(機体 ~90 秒、会合圏 ~1 時間強、軌道 ~5 時間、地球–月 ~数十日)。時間のズームがもうひとつの
軸として付くのではなく、空間のズームに従属する。

```
 NOW   +10m     +20m     +30m     +40m     +50m     +60m
 │      │        │        │        │        │ ╭最接近 5.68 km @+49m╮
 目標   ╲___                          ╲___╱▔▔▔            ← 距離(対数, 30km/12km の閾値線)
 距離        ▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔
 射撃   ·········░░░░░░░░░▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░         ← ░=交戦圏内 ▓=射程 12km 内
 日照  自機 ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒░░░░░░░░    ← ▒=日陰(藍) ░=日照(琥珀)
       目標 ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒░░░░░░░░
```

- **掴んで引く**: どこを押してもその時刻へカーソルが飛び、ドラッグで追う。掴んでいる間は
  シミュレーション時計を止める(「GRAB」)。
- **ゴースト**: 全物体の位置を `Orbit.at(t)` で **その時刻へ解析的に**引く(二体軌道は閉じた式)ので、
  倍率に関わらず滑らかで、再積分しない。カメラも掴んだ時刻の自機に追従し、世界全体が藍紫の
  トーンになる。現在の自機は「NOW」の破線輪(画面外なら縁マーカー)で残る。
  現在 → 掴んだ時刻の走破区間は紫の太線。
- **離す**: 現在へ戻る(約 0.3 秒の減衰)。**ピン留め(F)**すると、ホライズンを保ったまま時間が
  流れ続け、未来が「進行する現在」として並走する。**ワープ(Enter)**でそこへ飛べる。
- **最接近(会合窓)** のラベルは **クリックで掴む位置へジャンプ**する。
- 噴射(W/S/A/D)を押している間、ゴーストも軌道も **リアルタイムで書き換わる**。「この噴射で
  最接近が 5.7 km → 3.1 km になり、射撃可能区間が 9 分延びる」が、手を動かしながら見える。
  (ノードを置いて数値を読む、の代わり。)

### 3.4 状態遷移(操作の見取り図)

```
        ホイール/軸ドラッグ/1〜5/ピンチ
  ┌────────────────────────────────────┐
  │          スケール lr (連続)         │──→ 連動則 ──→ 時間加速 L ──→ 武装可否/射撃可否
  └────────────────────────────────────┘                    ↑
                                                             │ 交戦圏・接近減速・武器域(上限)
  タイムライン: [通常] ──pointerdown→ [GRAB: 時計停止, ゴースト追従]
                  ↑                        │pointerup
                  │                        ├─ ピン無 → [戻る(0.3s)] → [通常]
                  └──── Esc ←──────────────┤
                                           └─ ピン有 → [PIN: 時計は進む, オフセット保持]
  Enter/N → [WARP: 残り時間比例の自動減速] → 到着 → [通常]
```

## 4. ビジュアル言語

**色は意味に1色**。同じ色は別の意味に使わない。

| 色 | 意味 | 例 |
| --- | --- | --- |
| シアン `#7fe8ff` | 自機・自軌道 | 自機のチェブロン/光点、自軌道線、シアンの時間加速点 |
| マゼンタ `#ff3d9a` | 敵 | PEP-α/β、相対経路、護衛の輪(現行の既定アクセントを継承) |
| オレンジ `#ff7a1a` | 武装・交戦圏 | 交戦圏の破線円、射程リング、見越し点、武器域 |
| ラベンダー `#b8a4ff` | 未来・ゴースト | FUTURE の帯、走破区間、最接近のマーカー、画面縁の薄い光 |
| 琥珀 / 藍 | 日照 / 日陰 | タイムラインの日照レーン、地球の影、「日陰」ラベル、日陰時の自機の暗化 |

- **形**: 自機は進行方向を指すチェブロン、敵は六角形(ペプチドの鎖を思わせる)、護衛は小さな四角。
  写実モードでは、自機はモジュールの寄せ集めに見え(タンク・パネル・ラジエータ・砲)、敵は
  アミノ酸のビーズの鎖が脈打つ。日陰では自機の面が暗くなり、縁だけがシアンで光る。
- **動き**: ズームは対数で指数減衰(`1 - exp(-dt·k)`)。キー 1〜5 は長めの慣性(Powers of Ten の
  「降下」)、ホイールは短め。高倍率では **流れ星の尾**(直近 ~0.7 実秒ぶんの軌道を尾にする)で
  瞬間移動に見えないようにする。
- **文字**: 等幅。ラベルは **配置を衝突回避**(右上→右下→…→引き出し線付きの遠い位置)し、
  混んでいる時は優先度の低いものから落とす。画面全体で 11 px を下限にする。
- **層キャプション**: 層をまたぐたびに画面上部に「会合圏 — 相対運動と最接近を読む」が 1.6 秒だけ
  浮かぶ。
- **音(提案)**: スケールに応じた **レイヤー**。機体層は金属の共鳴と RCS、近接戦闘は推進と
  発砲、軌道層は低域のドローン、地球–月は無音に近い。ズーム中は **ローパスのスイープ**と
  ピッチの連続変化(望遠鏡のピントのような)で、層の入れ替わりを耳でも感じる。時間加速段が
  上がるたびに、周期の短いクリックを少しずつ上げる(×4 以下は無音)。

## 5. この案だから可能になるゲーム性

- **「スケールを選ぶこと」が戦術になる。** 近寄れば戦闘に入れるが時間は等倍に縛られる。遠ざかれば
  時間は速いが武装は使えない。戦闘から離脱する・敵の会合を待つ・先に最接近を見て位置取りを
  変える、が **ズームの上下**で表現される。
- **「待つ」が楽しくなる。** 会合窓に向けてのワープ中も、画面は相対経路を滑る敵の点で満たされる。
  「ただ時間を飛ばす」退屈が「接近の絵を眺める」に変わる。
- **噴射のプレビューが先に来る。** 未来ゴーストが噴射中に動くため、「撃てる位置関係に入るために
  何 m/s 必要か」を計器ではなく形で試行錯誤できる。不確かさを消すのではなく、操作の応答として
  見せる。
- **複数の舞台が同じ軸に載る。** 将来の群像劇(並列に船を出す)、光速遅延(指令の遅れ)、
  宇宙農場(L1 の太陽電池)は、いずれも **「遠い場所のイベントを、時刻を指定して眺める」**構造を
  持つ。タイムラインと位相図の層がそのまま受け皿になる。
- **日陰・日照が戦術情報になる。** 世界観(コンスルの結晶が光で動く)と噛み合い、日陰では電力が
  限られることを時間軸が先に教える。

## 6. 既存の前提をどう破るか、破って何を得るか

| 破る前提 | 破って得るもの |
| --- | --- |
| 戦闘ビューとマップビューは別画面(M で切替) | 「同じシミュレーションの異なる時間スケール」を UI 自体で体現。切替時の頭のリセットが消える |
| 時間加速は倍率キーで手動 | 時間がスケールに追従。ミスマッチ(「×64 のまま撃とうとした」)が構造的に起きにくい |
| ×4 以下でしか撃てないという規則を暗記する | ズームイン = 戦闘へのコミット、という身体的な理解に置き換わる |
| 未来はマップビューでノードを置いて数値を読む | 時間軸を掴んで全物体の未来を見る。数値なしで会合・日照・射撃可否を一目で |
| 数値パネルを読んで相対運動を組み立てる | 相対経路の「形」を読む。数値は補助 |
| 表示切替はビュー単位 | 表示の抽象度は物体の画面上の大きさ単位。物体ごとに独立して連続変化 |
| 画面上部にステータスバー(ビュー・倍率・時刻) | ステータスバーは残るが、倍率とスケールは右の軸で「関係」として見せる |

## 7. 実装の見取り図

### モック(`01-continuous-scale.html`)で実際にやっていること

- Canvas2D 1枚(シーン)+軸とタイムライン用に Canvas2D 2枚。単一ファイル・外部依存なし。
- 全物体を「エポック状態 + Kepler 伝播」(二体、平面)で持つ。`Orbit.at(t)` が **任意時刻の位置・速度**を
  返すので、ゴースト・最接近の探索・日照判定・相対経路がすべて同じ関数の呼び出しで足りる。
  噴射は状態ベクトルから要素を引き直す。
- 巨大な円(地球の縁、軌道線)は **可視範囲の弧だけを多角形で描く**(`drawEarth` / `orbitPath`)。
  座標が数万〜数億 px になる近接スケールでも Canvas が壊れない。
- 近接スケールの座標は `世界座標 − 自機位置` を倍精度で引いてから px にする(浮動小数の桁落ち対策)。
- ラベルは `place()` で衝突回避(矩形を登録して空きを探す)。
- 実機の 3D(WebGPU)でなく 2D だが、スケール連続性の構造(座標の連続変形、アルファの重ね合わせ、
  連動則、ホライズン)は 3D でもそのまま使える。

### 本実装へ向けた難所

1. **倍精度と描画の分離。** 物理は float64、描画は「カメラ相対 + float32」。three.js でのカメラ
   相対レンダリング(logarithmic depth か、層ごとの別カメラ)を前提にする。
2. **3D の見せ方。** 写実の船(GLB)→ アイコン(ビルボード)→ 光点(Points)の `LOD` を
   画面上のサイズで連続的にクロスフェードする。three.js の LOD は離散切替なので、
   マテリアル側の opacity を自前で補間する。
3. **ガイド線の生成コスト。** 相対経路・ゴーストの標本化は物体数 × サンプル数。2 体軌道で足りる
   範囲は解析、**J2・大気抵抗・太陽放射圧を含む本物のソルバ** ではキャッシュ+予測積分(別スレッド)
   が必要。現行の「未来予測は無推力の自由落下」(ORBIT.md)は、そのままタイムラインの前提にできる。
4. **連動則の係数。** モックの表は目で決めた。実プレイでの調整が要る。
5. **タッチ。** 2 本指ピンチ = スケール、1 本指ドラッグ = タイムライン。右の軸は親指で届く
   向きに寄せる(モックにもピンチは入っている)。

### 最小の第一歩(段階導入)

1. **時間加速の「上限」だけをズームに連動させる**(推奨ではなく上限)。UI はステータスバーの
   小さな表示のみ。交戦圏との整合が取れていることを確かめる。
2. 既存マップビューの下端に、**最接近 1 本だけのタイムライン**を足し、掴むと全物体の位置を
   その時刻へ動かす(ゴーストはマップ上のみ)。
3. 戦闘ビューのホイールで **マップ縮尺へ連続的に移行**(ビュー切替キーは残す)。層ごとの表示
   (アイコン化)は、この段階で入れる。
4. M キーによるビュー切替を撤廃し、座標系の連続変形(LVLH → 慣性)を入れる。

## 8. リスクと反論、他案との組み合わせ

### リスクと反論

- **「ズームで時間が変わるのは驚く」**: 最大のリスク。緩和策は(a)理由タグを必ず出す、
  (b)連動 ⇄ 固定の逃げ道、(c)軸の図で関係を常に見せる。それでも「画面を引いたら勝手に
  早送りになった」という事故は起こりうる。**初回だけ誘導(イントロ)** を入れる価値がある。
- **「精密な操作ができない」**: 武器域(≤ ×4)では推進・射撃の操作感は従来と同じ。広域の「見る」
  操作でだけ時間が飛ぶ。
- **「ズームが連続だと迷子になる」**: 層キャプション、右の軸、キー 1〜5 のジャンプで位置を
  見失わせない。
- **「ゴーストを出すと画面が情報で溢れる」**: モックの会合圏(視野 100 km)では、5〜6 km の
  接近が 20 px に収まり、ラベルが詰まる。**これは実測で確かめた弱点。** ラベル衝突回避で
  ある程度は救えるが、根本には「接近が近いほど、その場へ自動でズームする」支援が要る。
- **「世界観(結晶 = 一人称)と合わない」**: 俯瞰のスケール移動は神の視点。他案(ダイエジェティック)
  との折衷が必要(後述)。
- **「軌道の物理が正確でないと、ゴーストがウソをつく」**: 二体のゴーストは、摂動のある本実装との
  乖離が時間とともに広がる。ホライズンを延ばすほど誤差が出る点は、**ゴーストの「にじみ」**
  (誤差楕円)で見せる余地がある(モックでは未実装)。

### 他案との組み合わせ

- **相対運動計器**: 会合圏層の「相対経路」を、そのまま RPO 計器(V-bar/R-bar)として昇格できる。
  この案のスケール軸と、その案の計器を同じ画面に置くのは自然。
- **意図ベース指揮**: 未来ゴーストを「命令の結果のプレビュー」として使える(「あそこへ行け」と
  指したとき、全物体がどう動くか)。タイムラインが命令の確認画面になる。
- **世界観ダイエジェティック**: 光学結晶のモチーフと合わせ、スケール軸を「結晶の焦点距離の
  ダイヤル」のように見せる。ズームそのものを結晶の「焦点を変える」操作として語れる。
- **艦隊管制**: 複数艦をタイムラインのレーンに積む。ゴーストが艦隊の同時刻の配置になる
  (群像劇の時系列同期に近い)。
- **状況適応 HUD**: スケールを状況判断のひとつとして使える(狭い視野ほど戦闘用の表示)。
- **分子模型建造**: 層の最も内側(機体層)の下に、モジュール単位の建造層が続けられる。
  「機体 → モジュール → ボルト」へのさらなるズーム。

## 9. 5軸での自己評価(甘くしない)

評価軸は直感性・一般性・美学的な美しさ・視認性・一貫性。「一般性」は「ステージ・モード・
プレイヤーの違いを超えて、同じ仕組みで通用するか」と解釈した。

| 軸 | 点 | 根拠 |
| --- | --- | --- |
| 直感性 | **3** / 5 | ホイールとドラッグは誰でも分かる(+)。だが「ズームが時間を決める」「時間軸を掴むと未来が見える」は初見では推測できず、モックでも説明の凡例なしには気付きにくい。初回の誘導が前提。 |
| 一般性 | **4** / 5 | LEO 戦闘、軌道遷移、CREATIVE、将来の群像劇・光速遅延・農場経営まで同じ軸で受けられる。一方、**ビュー固有の高精度操作(建造や照準の微調整)** はこの案だけでは担えない。 |
| 美学的な美しさ | **4** / 5 | Powers of Ten の「降下」と、写実 → アイコン → 光点の連続変化は本質的に美しい。色は意味 1 色で統一。減点は、モックの会合圏層がラベルとリングで **騒がしく**なる場面(視野 100 km の最接近付近)があること。 |
| 視認性 | **3** / 5 | 色・サイズ・コントラストは確保したが、**スケールをまたぐ表示は混雑のピークを避けられない**(会合圏の中心付近、20 px に 4〜5 要素)。小画面(タッチ)ではさらに悪化する。接近時の自動ズーム支援がなければ 3 止まり。 |
| 一貫性 | **4** / 5 | 「ひとつの軸(スケール) → 時間 → 武装可否」という単一の因果で全体が説明でき、色も 1 色 1 意味。減点は、座標系の連続変形(LVLH → 慣性)で **中間で見え方が変わる** 区間と、「連動」と「固定」という 2 つのモードがあること。 |

## 10. 参考(実在するもの)

- **『Powers of Ten』**(Charles & Ray Eames, 1977): 10 の冪で視点を引く映像作品。名称と「1 本の軸で連続的に」の着想元。
- **セマンティックズーム(semantic zooming)**: Perlin & Fox「Pad」(1993)に始まる、拡大率で
  情報の **表現そのもの**が変わるズーム。地図アプリで日常的に使われている。
- **Supreme Commander**(2007)の「ストラテジックズーム」: 引くと兵がアイコンになる RTS。この案の
  写実 → アイコンの連続切替の先行例。(時間は連動しない。)
- **Kerbal Space Program** のマップビュー・タイムワープ: 軌道・マニューバーノードの表示と、
  高度による時間加速の上限(大気圏内などで物理加速に制限)。本案が最も強く意識している基準点。
  ただし KSP は **ビュー切替式**で、時間は手動。
- **Google Earth** の時間スライダ(過去の衛星画像)、**Universe Sandbox**: スケールと時間を
  ひとつの画面で動かす。
- **NASA の RPO / ISS 接近運用**: 目標を基準にした LVLH 座標(V-bar / R-bar)と Clohessy–Wiltshire の
  相対運動。相対経路の読み方の根拠。
- **Bret Victor「Up and Down the Ladder of Abstraction」**(2011): 抽象度を連続的に上下して、
  同じ対象の因果を見るインタラクションの擁護。
- **Edward Tufte**(『The Visual Display of Quantitative Information』): スパークラインと
  small multiples の考え方。タイムラインの小さなレーン(距離・射撃・日照)を同じ時間軸に積む
  設計の根拠。
- **Outer Wilds**: 「時間のループ」を体験の中心に置いたゲーム。この案が時間を **見る** UI を
  持つことと対比できる。
- **リポジトリ内**: `DEVELOP/SPEC/GAME.md` §4(時間加速 ×1〜×33554432、推進・射撃 ×4 以下)、
  `DEVELOP/SPEC/COMBAT.md`(交戦圏 半径 30 km)、`DEVELOP/SPEC/ORBIT.md`(時間加速は時計の速さだけを
  変える)。この案の連動則は、これらをプレイヤーが覚える規則ではなく、UI の構造として表す。
