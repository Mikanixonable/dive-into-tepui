# 案07 — 分子模型のように組む建造 UI(Molecular Builder)

動くモック: `07-molecular-builder.html`(同じディレクトリ。ダブルクリックで開く)

## 1. 一行コンセプト

**モジュールは原子、接続は結合。結合角が形に必然性を与え、組むたびに「重心・推力線・トルク・Δv」が図で見える建造 UI。**
ドッキングは「2つの分子が結合する」、分離は「結合を切る」。敵のタンパク質モチーフも同じ言語で描く。

### いまの建造 UI の根本的な問題

作者の memo(`ゲームデザイン.md`)は、建造の抽象化についてこう悩んでいる。

- KSP は径アダプターで積むだけ。もっと自由で、かつ「一からモデリングするしんどさ」がない抽象化が要る。
- Townscaper は歪んだ格子でどこに置いても収まるが、建物は縦にしか伸びない。宇宙船は立体で、歪みが蓄積する。
- 「分子模型とかからアイデアを借りるしかないか」。
- 自由度ではなく**不自由度**を設計する。補助線は引くが目立たせない。

現行仕様(`ASSEMBLY.md` / `CONTEXT.md`)の建造は「接続軸に沿って直列追加」と「cockpit/tank の中央に4方向の離散スロット(3・6方向は将来仕様)」で、次の弱さを持つ。

1. **形に意味がない。** 直列に積むだけなので、重心・慣性・推力線を意識する理由が生まれない。
2. **結果が数値でしか分からない。** Δv や TWR はパネルの数字で、「推力線が重心から外れたら回る」は試験飛行して初めて気づく。
3. **建造・ドッキング・破壊・敵の表現がバラバラ。** 同じ「部品のつながり」なのに、4つの別の見せ方をしている。

この案の答えは1つ: **「部品のつながり(グラフ)」を唯一の視覚言語にして、建造・合体・分離・損傷・敵をすべてそれで描く。**

## 2. 体験の描写

LEO での会合戦闘の前、月 L1 のドックで次の出撃に向けて船を組む場面。

1. **構え。** パレットから「タンク L」を掴む。船のあちこちに点線の短い棒(未結合手)が見え、掴んだ瞬間にそれらが黄色く光る。
   まだ触っていないのに「ここにしか付かない」ことが分かる。
2. **吸着。** カーソルをコクピットの左の手へ近づけると、タンクが磁石のように引かれて、指より一瞬早く正しい角度でカチッと収まる(ゴースト)。
   結合点に「90°」の弧が出て、既にある結合との関係が分かる。どこへ置いても、はみ出さず、ねじれず、収まる。
3. **差分。** ゴーストの横に小さなチップが出る。
   `Δv ▲+457 m/s / TWR ▼0.19 / 推力線ズレ ▲2.15 m / ⚠外乱トルクが RCS を超える`。
   同時に、船の重心マーカーから「追加後の重心」(水色の点線の円)へ細い線が伸び、青い点線の推力線が斜めに傾く。
   **置く前に、置いた後の姿が見える。**
4. **確定。** 離すと結合の棒が現れ、右パネルの数字が一斉に更新される。判定欄が緑の「◎ 推力線が重心を通る」から橙の「△ RCS で保持可 余裕 39%」に変わる。
   推力線と重心の間に赤い寸法線 `ズレ 2.27 m`、重心まわりに赤い円弧の矢印 `τ 340 kN·m`、その下に RCS で打ち消せる範囲の緑の帯。**矢印が帯からはみ出していたら、それは直す必要がある。**
5. **試験噴射。** Space で短く噴かす。ズレを放置した船は、画面の中心で重心を軸にくるくる回りながら加速し、軌跡が弧を描く。RCS 姿勢保持を ON にすると、緑の帯の内側なら小さな噴射で押し返して直進する。
6. **直す。** 反対側にも同じタンクを足す。トルクがゼロになり、赤い矢印が消えて推力線が緑になる。最初の枝は履歴ツリーの別の枝として残る(戻って別案を試せる)。
7. **結合。** 機首のドックを貨物に向けて「貨物と結合」。貨物の開いた結合手と船のドックの結合手が近づき、結ばれる。質量・重心・Δv が一気に更新され、チップで先に見えていた通りの値になる。
8. **戦闘中。** 被弾で太陽電池の結合が切れて分離する、あるいはエンジンが脱落する。戦闘 HUD にも同じ推力線と重心が出て、**「なぜ機体が回り出したか」が建造画面で見たのと同じ図で分かる。**

## 3. 構成要素

各要素が答える問いを併記する。

| 要素 | 答える問い | 実装メモ |
| --- | --- | --- |
| 部品パレット(原子) | 何がつなげられるか。価数・結合角は。 | 各部品に「価数 + 幾何」を表示。アイコンの周りに未結合手の点線 |
| 未結合手(点線の棒) | どこに置けるか。 | 構え中は全て発光。カーソルから最も近い1本だけ脈動 |
| 磁石スナップ + ゴースト | 置いたらどうなるか。 | 結合手同士の最近傍に吸着。向きは結合角が決める(自由回転は無い) |
| 結合角の弧と数値 | なぜその向きか。 | 親原子の結合手の間隔(180°/120°/109.5°/90°/60°)を弧で表示 |
| 差分チップ | 良くなるか悪くなるか。 | 置いた後を同じ計算で先に出し、差を ▲▼ と色で。質量は中立色 |
| 重心 CoM / 推力中心 CoT | 重心と推力はどこか。 | KSP の CoM/CoT の記号を踏襲。ゴーストの CoM は水色の点線 |
| 推力線(合力の作用線) | 推力は重心を通っているか。 | 実線矢印 + 長い破線。ズレは寸法線で |
| トルク矢印と RCS 帯 | 回るか。止められるか。 | 赤い弧の長さ=トルク、緑の帯=RCS 制御力。はみ出し=不足 |
| 慣性主軸(楕円) | どの軸が回しやすいか。 | 質量分布の主軸と扁平率。細長いほど長軸まわりが回しにくい |
| 判定バー(◎△✕) | 結局どうなのか。 | 3段階の一言と色。数値を読まなくて済む入口 |
| 分子式 | この船は何か。 | `Cp·TK₂·Th·Rc·Dk` のように部品数で表す。共有・比較・検索に使える |
| 環の数 | 剛性はあるか。 | 閉環=トラス。環があるほど曲げに強い、とするゲーム上の約束 |
| 履歴ツリー(反応経路) | 別案へ戻れるか。 | 節=状態、色=Δv の増減、クリックで跳ぶ。Ctrl+Z で枝が分かれる |
| 貨物・分離 | 合体と分離は何をするか。 | 開いた結合手同士を結ぶ。分離は結合の棒を切る。分離体は漂流 |

### 結合の言語(価数と幾何)

結合手の本数と角度を「部品の性格」にする。結晶化学の言葉を借りるが、覚えるのは3種類だけで十分。

```
 末端 (1価)        直線 (2価)       三方 (3価)       四面体 (4価)      六方/八面体
 ●—               —●—               ●<               ●+               ✳
 エンジン,RCS,    タンク,ドック,     ノード,           コクピット        ハブ
 太陽電池         梁                分岐              (3D では 109.5°)  (3D では 90°×6)
```

- **末端(1価)**: エンジン、RCS、太陽電池。つないだ先がない。「付ける物」。
- **直線(2価)**: タンク、ドック。胴体を延ばす。
- **三方・四面体・八面体(3・4・6価)**: 枝分かれ。胴体を分岐させる。
- **モック(2D)**: 四面体は十字 90°、八面体は六方 60° で代用した。**3D 版では四面体は 109.5°、八面体は 90° が6本。** 結合周りの回転(二面角)はスクロールで 60° 刻みに選ぶ。

### Townscaper の「歪みが蓄積する」問題への答え

memo の悩みは「宇宙船は立体なので歪んだ格子は簡単には思いつけない、歪みが蓄積してしまう」だった。
分子には既に答えがある。**価数ごとの標準角だけで、空間を歪みなく埋める格子が存在する**(四面体角ならダイヤモンド格子、八面体角なら立方格子、三方角なら六角網)。
グリッドを敷かなくても、結合角だけで格子が創発する。そして閉じない環(例: 角度の合わない環)は「歪み」として現れ、これをそのまま**構造の弱さ(ひずみ)というゲーム上の不自由度**にできる。
Townscaper が「見えない歪んだ格子」で気持ちよさを隠したのに対し、こちらは「見える結合角」で必然性を示す。

### ドッキング・分離・損傷は結合の言語で統一

| 操作 | 結合の言葉 | 画面で起きること |
| --- | --- | --- |
| 建造 | 原子を結合手に付ける | 吸着 → 結合の棒が生える |
| ドッキング | 2つの分子の開いた結合手を結ぶ | 貨物が結合手の向きに回頭 → 近づく → 結ぶ |
| 分離 | 結合を切る | 棒をクリック/選択 → 2つの分子に分かれて漂流 |
| 被弾 | 結合が切れる/原子が落ちる | 戦闘 HUD でも同じ棒が切れて分離する |
| 撃破した敵の回収 | 敵の分子の結合手に結ぶ | 回収もドッキングと同じ |

既存仕様のグラフ(ShipAssembly、dock/docking_port、建造接続と通常のドッキング接続の区別)はそのまま載る。ここでは「建造接続」「ドッキング接続」を棒の太さ・色で区別するだけでよい。

## 4. ビジュアル言語

- **形**: ball-and-stick(球と棒)。HGS の分子模型と同じ、一目で「つながり」が読める記法。
  部品は役割ごとの形(コクピット=球、タンク=カプセル、エンジン=ベル、RCS=小さな球、太陽電池=板)で、棒は両端の部品の色が半分ずつ。
- **色**: 部品の色は CPK 風に「役割=元素」で固定する(コクピット=橙、タンク=青、エンジン=赤、RCS=緑、太陽電池=黄、ノード=灰、ドック=白)。
  解析は別系統の色で: 重心=黄(KSP と同じ)、推力=赤〜橙、予測=水色の点線、安全=緑、警告=橙、危険=赤。**部品色と解析色は混ぜない。**
- **動き**: 吸着は 0.1 秒の素早い補間(磁石)、結合手は 1.5 Hz の緩い脈動。数値の ▲▼ は変化のあった行だけが色づく。試験噴射の回転は物理どおり。
- **文字**: 数値は等幅、単位は小さく薄く。判定は大きな一言(◎△✕)で先に伝える。分子式は下付き文字。
- **音**(提案): 吸着は小さな「コツ」、切断は短い「パキッ」。トルクが RCS を超えたとき、置く瞬間に低いうなり。
  補助線はあくまで目立たせず、結合そのものを主役にする。
- **補助線の階層**: 常時=重心・推力線・判定、構え中のみ=未結合手・ゴースト・差分、オンデマンド=慣性主軸・RCS 帯(ボタンで切替)。

## 5. この案だから可能になるゲーム性

1. **形に必然性が生まれる(不自由度の設計)。** 価数と角度の制約が、「こう付くしかない」を作る。
   KSP の「積めば飛ぶ」でなく「バランスを取る」遊びになる。左右対称が美しいのは、物理的にも正しいから。
2. **RCS を遠くに置く理由がある。** トルクは「力 × 腕の長さ」なので、RCS はコクピット近くより端に置くほど効く。図で効きが見えるので、教えなくても分かる(memo の「軌道力学を教えず肌感覚で掴む」と同じ方針)。
3. **ダメージが形の物語になる。** エンジンが落ちる、タンクが外れる = 推力線が動く、重心が動く、回り出す。戦闘中の「なぜ?」に建造画面と同じ図で答えられる。
4. **改造が試行錯誤になる。** 履歴ツリーは「化学の反応経路」。分岐を残して比べられる。
   「Δv は欲しいが TWR は落としたくない」を、ゴーストと差分で何度でも往復できる。
5. **分子式が共有・取引の単位になる。** 「Cp·TK₂·Th·Rc₂·Dk」のような短い名前で船を呼べる(CREATIVE での共有、将来の船団管理)。
6. **敵とのつながり。** 敵のタンパク質モチーフ(ペプチド)は、主鎖 N–Cα–C と側鎖という「原子と結合」でできている。
   自機と敵が**同じ文法で描かれる**ので、戦闘中に「敵のどこを切れば発射部が外れるか」が結合の図として読める。
   弾で結合を切る、という撃ち方がそのまま「分離」になる。`ASSEMBLY.md` の「発射部・中核・構造部」の役割も、結合の図に色で載せられる。
   (モックの右下に、同じ描画で敵ペプチドを置いて切断を試せるようにした。中核★から外れた発射部の塊は「射撃不能」になる。)

## 6. 既存の前提をどう破るか

| 既存の前提 | この案の破り方 | 得るもの |
| --- | --- | --- |
| 建造は接続軸に沿って直列追加(`ASSEMBLY`/`CONTEXT`) | 価数と角度を持つグラフ(木 + 環) | 形に必然性。枝・環・対称が使える |
| スロットは cockpit/tank の4方向、3・6方向は将来 | 全部品が自分の結合手を持つ。数は部品ごと | 拡張が部品定義だけで済む。グリッドが不要 |
| 数値パネルを読んで判断する | 図が先、数値は後 | 判断の速さ。KSP を知らない人にも伝わる |
| 船は「完成してから」飛ばす | 組む途中でも試験噴射できる | 試行の往復が速い。**失敗が図で分かる** |
| 敵・建造・ドッキングは別の見せ方 | すべて結合の図 | 学習コストが 1/3。ゲーム全体の一貫性 |
| 補助線を出さない | 補助線を**図として主役**にする | 建造画面は「道具のふり」でなく「実験室」になる |

「補助線を目立たせない」「作っているのはプレイヤーだと錯覚させる」という作者の方針とは緊張がある。
この案では、結合そのものを主役の造形にして、補助線(重心・推力線・トルク)は**部品の一部のように見える**ことを目指す。
重心は「船のおへそ」、推力線は「エンジンの尾」、トルクは「船が持つ癖」として読める見せ方にする。
常時出す補助線は3つ(重心・推力線・判定)だけ。それ以外は構えた時・押した時にだけ出す。

## 7. 実装の見取り図

### データモデル

- `ModuleDefinition` に `bondSites: { dir: Vec3, kind: 'axial' | 'side' }[]` を追加する。価数と幾何は、この配列から決まる。
- 既存の「接続グラフ(ShipAssembly の edge)」はそのまま使い、edge に `bondSite` の添字を持たせる。
- 建造接続とドッキング接続は edge の `kind` で区別する(既存仕様と同じ)。

### 計算(`src/` 内で純粋関数として切り出すのが望ましい)

- 質量中心 = Σ mᵢ rᵢ / M(結合部の構造質量も入れる)。
- 慣性テンソル = Σ mᵢ(|rᵢ|²I − rᵢrᵢᵀ) + 各部品の自己慣性。**主軸は 3×3 の対称行列を Jacobi 法で固有分解**(部品数が数十なら毎フレームでも問題ない)。
- 推力の合力と合トルク: Fᵢ と rᵢ × Fᵢ の和。合力の作用線の重心からのズレ = |τ| / |F|。
- RCS の効き: 各 RCS の 3軸への寄与(r × t の各成分 × 推力)の和。モックは 2D の1軸。
- Δv = Isp g₀ ln(m₀/m₁)(複数エンジンは推力加重の実効 Isp。混載は近似)。
- 「置いた後」の計算は、グラフを複製して1原子足して同じ関数に通す。部品数が数十なら 1ms 未満。

### 描画・DOM

- 船の描画は three.js のシーンに分子を置く(ball-and-stick は InstancedMesh で、棒は半色グラデーション)。
- 解析オーバーレイ(CoM・推力線・トルク弧・慣性楕円体)は、深度テスト無効の別レイヤー(Line2、スプライト)。
- ゴーストは半透明のコピー。差分チップは DOM(UI-DESIGN.md の Tepui Glass)で、カーソル近傍に追従。
- 右パネルの数値は DOM。トルクゲージは小さな Canvas2D。
- 履歴ツリーは SVG。スナップショットはグラフの JSON(既存のセーブ形式がそのまま使える見込み)。

### 難所

1. **3D のスナップ操作。** 結合の周りの回転(二面角)をどう選ぶか。提案: 吸着後にスクロール/ドラッグで 60° 刻み、他の結合と衝突する角度は自動で飛ばす。タッチでは長押し + ドラッグ。
2. **見えない結合手。** 3D では奥の結合手が隠れる。提案: 構え中は船を半透明にし、結合手を前面に出す。視点を自動でスナップ先へ寄せる。
3. **解析オーバーレイの混雑。** 重心・推力線・トルク・RCS・慣性が重なる。モックでも既に混み気味。レイヤー切替と、構え中/確定後での出し分けが必須。
4. **物理との整合。** 建造画面の「トルク」と実際の剛体姿勢制御(RCS の割当・推力ベクタ)が食い違うと信頼を失う。**計算は戦闘のシミュレーションと同じ関数を共有する。**
5. **分子式の可読性。** 部品が10種を超えると式が長い。`Cp·TK₂·…` の下位表記や、機能群(推進群・タンク群)へのまとめが必要。

### 段階的な導入順(最小の第一歩から)

1. **差分チップだけ。** 既存の建造 UI で、確定前に Δv/TWR/質量の差を出す。計算関数の導入と、ゴーストの差分表示だけで体験が変わる。
2. **重心・推力線の表示。** CoM・CoT・推力線・ズレの寸法線。数値ではなく図で「ズレ」を見せる(この時点でほぼ KSP の CoM/CoT 相当の価値)。
3. **未結合手と磁石スナップ。** 既存の 4 方向スロットを「結合手」として見せて、点線の棒 + 吸着に置き換える。
4. **トルク矢印 + RCS の効き + 試験噴射。** 上の計算を剛体姿勢制御と共有し、建造画面で短い試験噴射をできるようにする。
5. **履歴ツリー + 分岐。** 既存の undo をツリーにする。
6. **敵と戦闘 HUD への展開。** 敵の結合図と、戦闘中の推力線/重心の表示。

| 反論 | 応答 |
| --- | --- |
| 「分子模型」は教育的すぎて、宇宙船の格好よさを損なうのでは | 見た目は ball-and-stick でも、出撃後の船は通常のモデルで描く。建造画面だけを「実験室」にする。ザンジバル/ペルシャ風の意匠は結合部品(棒)の装飾で入れられる |
| 結合角に縛られて自由がなくなる | それが狙い(不自由度の設計)。ただし価数 4・6 の部品と環化があれば、立体の自由は十分ある。「どこに置いても収まる」を満たすのは結合手が複数あるからで、置ける場所が全く無いのは「結合手が足りない」状態として明示する |
| 重心・推力線は KSP の VAB で既に見られる | 数値と記号の小さな表示としてはある。この案は、(1) ゴーストで置く前に予測、(2) トルクと RCS 範囲を並べて「止められるか」を図に、(3) 試験噴射を同じ画面で、の3点を組み合わせる |
| 複数エンジン・複数燃料・イオン混載の Δv は近似で、正確でないと信頼を失う | モックは近似(推力加重の実効 Isp)。本実装では燃料系統とステージ(booster 点火後は停止不可)を扱う Δv 計算を別途用意し、近似の場合は「≈」を付ける |
| 3D の結合周りの回転選択が面倒 | 吸着の 90% は回転を選ぶ必要がない(対称部品)。非対称なものだけスクロールで 60° 刻み。ゴーストでその場で確認できる |
| タッチで細かい結合手を狙えない | 結合手の吸着半径を大きく取り、候補の切替(次の結合手へ)をボタンにする |

### 他案との組み合わせ方(踏み込みすぎず)

- **シームレスズーム**: 船にズームインすると船体がそのまま分子として見え、ズームアウトすると点になる。建造画面と戦闘画面が同じ描画で連続する。
- **相対運動計器**: 推力線とトルクの図は、そのまま姿勢計器(「いま噴くと回る」)の説明にもなる。
- **意図ベース指揮 / 艦隊管制**: 分子式は船団管理のアイコンの下書きになる。複数の分子が結合している状態を「編隊」や「連結」と呼べる。
- **世界観ダイエジェティック**: 主人公は光学結晶の LLM「執政官の結晶」。**結晶は格子であり、結合の言語は結晶の言語**なので、建造画面を「結晶の内部で組まれる模型」とすれば世界観に繋がる。1970年代風の技術水準にも、卓上の分子模型は似合う。
- **状況適応 HUD**: 戦闘 HUD が損傷時に建造画面の解析図を自動で呼び出す(推力線がズレた時だけ出す)。

## 9. 5軸での自己評価(甘くしない)

| 軸 | 点 | 根拠 |
| --- | --- | --- |
| 直感性 | **4** | 「磁石で吸着」「ズレたら赤い矢印」は説明不要。減点は、トルク・慣性主軸・RCS 帯の意味が初見では読めないこと。判定バー(◎△✕)で入口を作ったが、細部は学習が要る。3D の二面角選択も未検証 |
| 一般性 | **3** | 建造・ドッキング・分離・損傷・敵まで同じ言語で貫ける(広い)。一方で効くのは建造画面が中心で、マップや戦闘の通常時の操作性は改善しない。「船がグラフである」というこのゲームの前提に強く依存する |
| 美学的美しさ | **4** | ball-and-stick は一目で分かる造形で、対称な船が物理的にも美しくなる点が良い。減点は、解析線が重なると雑然とすること、「理科教材」に寄るリスク。モックでも CoM 周辺が混む |
| 視認性 | **3** | 判定・ズレの寸法線・色の三段(緑/橙/赤)は読みやすい。しかし画面に出る情報量が多く(重心・推力線・トルク・RCS 帯・慣性楕円・差分チップ・右パネル)、小さい画面では重なる。レイヤー切替が本実装では必須 |
| 一貫性 | **4** | 建造・合体・分離・損傷・敵が同じ棒と球で描かれ、色の意味も部品色と解析色で分かれている。減点は、マップ/戦闘の他の HUD(軌道線やレティクル)は別の言語のままで、そこはこの案だけでは繋がらないこと |

総評: **「建造を理解させる」という1点では最強に近いが、ゲーム全体の UI を覆う案ではない。** 他案(特にシームレスズームと状況適応 HUD)と組むことで、一般性の 3 を引き上げられる。

## 10. 参考(実在のもの)

- **KSP(Kerbal Space Program)**: VAB/SPH の CoM(重心)・CoT(推力中心)・CoL(揚力中心)の表示。1.11 以降の Δv 表示(Delta-V アプリ)。
  この案はこれらを「置く前の予測」と「トルクで止められるか」へ拡張する。
- **Townscaper(Oskar Stålberg)**: どこへ置いても収まる不規則格子の気持ちよさ。この案は格子を隠す代わりに結合角を見せる。
- **Besiege**: 部品をつないで機械を作る。結合の自由度の高さと、「作って即試験」の往復の速さ。
- **Space Engineers / Avorion**: ブロック建造の宇宙船。推進の配置が機体挙動を決める手触り。この案は建造の抽象化を「ブロック」から「原子と結合」へ替える試み。
- **分子模型(HGS など)**: 球と棒、価数ごとの結合角。VSEPR(価電子対反発)理論による標準角(180°/120°/109.5°/90°)。
- **結晶格子(ダイヤモンド構造・立方格子・六方格子)**: 結合角だけで歪みなく空間を埋める格子の実例。
- **Foldit**: タンパク質構造を動かして「ひずみ」を減らす遊び。「ひずみ=不自由度」の着想元。
- **タンパク質の主鎖(N–Cα–C、φ/ψ 角)と二次構造(αヘリックス、βシート)**: 敵のモチーフと自機の分子を同じ言語で描く根拠。
- **Tufte の small multiples / Before–After**: 差分を並べて比べる表示。ゴースト + ▲▼ の考え方。
