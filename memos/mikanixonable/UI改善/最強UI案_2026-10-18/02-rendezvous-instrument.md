# 02 会合計器(Rendezvous Instrument)

> 動くモック: [`02-rendezvous-instrument.html`](./02-rendezvous-instrument.html)(ブラウザで開くだけ。外部依存なし)

## 1. 一行コンセプトと、解く問題

**「相対運動を"読む"のでなく"見る"。** ターゲット中心の Hill(LVLH)座標で、自機の未来の相対軌道・弾の軌道・
撃てる時間帯を、噴射する前に1枚の図として見せる計器を、戦闘ビューの主役に据える。

### いまの UI の根本的な問題

現行 UI は「パネルに数値が並ぶ」KSP 型で、戦闘の核心である**相対速度と相対軌道**を、プレイヤーが
数値から頭の中で組み立てる前提になっている。

- 軌道力学では、**直感に反する動き**が常態である。前へ噴くと上へ膨らみ、あとで後ろへ流れる。
  上へ噴くと、半周期後に後方へずれる。ターゲットの真後ろから「まっすぐ近づく」ことすら、ほとんど
  できない。
- これを数値(距離・相対速度・接近率)で読ませると、プレイヤーは試行錯誤の副作用で燃料と時間を失い、
  学習も進まない。**学習の失敗が、ゲームの面白さに届く前の関門になっている。**
- 射撃も同じ。見越し射撃は「相対速度 + 弾の曲がり + 飛翔時間」の合成で、LEAD マーカーが出ても
  「なぜそこなのか」「どれだけ動くと外れるのか」が見えない。

この案は、**同じ物理を、頭の中の計算から画面上の形へ移す。** 数値は残るが補助に下がる。

## 2. 体験の描写 — LEO で敵と会合して撃破するまで

モックのシナリオ A に対応する(自機はターゲットの後方 6.5 km、相対速度 約 11 m/s)。

1. **戦闘ビューに入ると、画面の主役は「会合図」** になる。中心にペプチド型の敵(橙)、左に自機
   (白い矢)。青い曲線が「このまま噴かなかったときの自機の相対軌道」で、2分ごとに点が打たれている。
   曲線は大きな弧を描き、敵の近くを**約 300 m 外して**通り過ぎるように見える。曲線上の輪の脇に
   `TCA 09:32 / 189 m`(最接近の時刻と距離)が出ている。
2. 右のダイヤルでは、緑の帯(射撃窓)が機首の少し左にある。まだ照準が窓の外で、「窓外 左へ 0.64°」。
   **G を押す(自動見越し)**と、機首が窓の中心に吸い付き、帯が白い照準ぶれ帯を包んで
   「◉ 射撃窓の中 / 命中見込み 8〜9割」に変わる。
3. 撃つ。**弾は直線でなく曲線**で飛び、弾の軌跡が会合図に黄色で残る。曲がり方は CW 方程式どおり
   (弾道が緩く弧を描く)。見越し解は緑の細線で事前に描かれていて、弾はそれをなぞる。
4. 外れたとしよう。TCA はまだ数分先。プレイヤーは **W を2回押す**。何も噴いていないのに、
   **マゼンタの破線(ゴースト)**が青い曲線から分かれ、TCA の輪が動く。下のタイムラインでは、
   ゴースト側の TCA が 23 秒早まり、ミス距離が 189 m → 208 m に変わった。「前に噴くと上へ膨らんで、
   かえって遠回りになる」とパネルが言う。プレイヤーは噴射を取り消し、**パッドを下へ**ドラッグして
   ゴーストが敵の輪へ入るのを確かめてから **Enter** で確定する。噴射は一度で済んだ。
5. 時間は流れる。タイムラインの射撃窓の帯が濃くなり、白い◆(撃ちどき)に NOW が近づく。
   ◆の手前で撃ち始め、3発目が敵の輪に入って**命中**。HP 目盛が1つ消える。
6. 3発で撃破。バナーが出て、次の敵(次のシナリオ)が現れる。

プレイヤーが感じるのは「軌道力学を計算した」ではなく、**「軌道が見えている」**感覚である。

## 3. 構成要素(各要素が答える問い)

```
┌───────────────────────────── 会合図(Hill / LVLH) ─────────────┐ ┌─ 照準計器 ─────┐
│  ▲ −R-bar(地心から離れる)                                       │ │ ダイヤル + 数値 │
│                                                                 │ │  窓/LEAD/Vrel   │
│    ← 後方      ○ ENEMY(橙)・命中輪・接触警戒圏 →V-bar(前)   │ ├─ Δv プレビュー ─┤
│        自機 ▷━ 見越し弾道(緑)・射撃窓の扇                   │ │ パッド/確定/取消│
│   青: 予測軌道(CW)   マゼンタ破線: ゴースト   黄: 弾の軌跡     │ │ ヒント(ドリフト)│
│  ▼ R-bar(地球側)                                               │ ├─ 数値(補助)────┤
├────────────── タイムライン(横軸=今からの時間) ───────────────┤ └─────────────────┘
│ 距離  \___/    TCA▲  TCA′▲                                      │
│ 射撃窓 ░▒▒▓▓◆▓▓▒░    ゴースト ░▒▒▓▓▓◆▓▒░                        │
└─────────────────────────────────────────────────────────────────┘
```

| 要素 | 答える問い | 見え方 |
| --- | --- | --- |
| 会合図の軸と距離リング | 敵に対してどこにいる? | ターゲット中心。右=進行方向(V-bar)、上=地心から離れる側、下=地球側。同心円は距離 |
| 青の予測軌道(2分ごとの点) | **このまま行くとどこを通る?** | CW 方程式の厳密解の曲線。10分ごとに文字 |
| TCA の輪と距離・時刻 | いつ、どこまで近づく? | 輪の脇に `TCA mm:ss / 距離`。敵への点線がミスベクトル |
| ゴースト(マゼンタ破線) | **噴いたらどう変わる?** | 未確定の Δv を足した軌道。確定まで実体の軌道は動かない |
| Δv パッド / W S E Q | どう噴く? | 2軸の円形パッド(V-bar × R-bar)。キーは 0.1〜1 m/s 刻み |
| ヒント行(ドリフト・軌道中心) | **なぜそうなる?** | 前へ噴く → ドリフトは Δv の −3 倍、など。数値は現在→ゴーストの対 |
| 提案ボタン(ドリフト止め / 会合コース) | 一手で整えるなら? | 提案はゴーストとして出る。プレイヤーが確定する |
| ダイヤル(機首=真上) | **いま撃てる? 外れるならどっちへ?** | 機首からの角度を弧に展開。緑の帯=当たる射角の窓、白帯=照準ぶれ、`TGT` `LEAD` `Vrel` `−Vrel` のマーカー。倍率は ±1°〜±180° に自動切替 |
| 衝突コーン(橙の点線) | まっすぐ行ったら当たる向きは? | 自機から敵の命中輪への2接線。直線近似だと明記する(曲がると外れる) |
| 射撃窓の扇(緑の面) | 窓の中の弾道束は? | 窓の両端の弾道に挟まれた曲がった扇。両端の間に狙えば当たる |
| 弾の軌跡 | 撃った弾はどこを通る? | 黄の曲線。CW で曲がる |
| タイムライン | **いつ撃てる? いつ撃つのがいい?** | 距離曲線+射撃窓の帯(濃さ=解を狙ったときの命中率)+◆(撃ちどき)+TCA。ホバーすると会合図に未来位置が出る |

### 操作

- **時間は止めない。** 計画中(ゴーストあり)は自動で ×1 に落ちる「計画中スロー」を既定にする。
  (停止は選べるが、戦闘では敵が待たない。)
- **噴射は2段階**: キー/パッドで「保留」を作る → Enter で確定。Esc で取消。確定前は常にゴースト。
- **照準は3通り**: マウス位置 / J・L / G(自動見越し)。G は「ピパーに吸着」で、窓の中心へ向ける。
- **高倍率の時間加速中は射撃不可**(既存の規則どおり)。

### 状態遷移

```
巡航(会合図が主役、窓の帯は薄い)
  └ 窓が開く(タイムラインの帯が濃くなる) → 交戦
       ├ 外れる(TCA 通過) → 離脱/再会合(次の窓まで帯が薄い)
       └ 敵撃破 → 次の目標
Δv 計画: 保留なし ⇄ 保留あり(ゴースト表示・時間は ×1) → 確定 / 取消
```

## 4. ビジュアル言語

- **色は役割で固定**: 橙=敵(既存仕様のアクセント #ff6a00)、白〜水色=自機と相対速度、
  青=実体の予測、**マゼンタ=未確定(ゴースト)**、緑=当たる・撃てる、黄=弾、赤=警戒。
  色だけに頼らず、**ゴーストは破線、窓は面と帯、警告は文字**でも示す。
- **形の意味**(戦闘機 HUD の記号に倣う):
  - `[ · ]` 角括弧+点=ターゲット(`TGT`)
  - ⊕ 十字付き円=見越し点(`LEAD`、ピパー)
  - 翼付き円=相対速度ベクトル(`Vrel`、FPM のターゲット相対版)/ ×付き円=逆向き
  - 帯=窓、白帯=自分のぶれ
- **動き**: 軌道線は常に静止して見えるが、計器の値は連続に変わる。ゴーストは Δv の変化に追従して
  **ぬるっと曲がる**(補間はしない。毎フレームの厳密解が動くだけで、滑らかさは物理が与える)。
- **文字**: 等幅。大きい数字は距離だけ。それ以外は 9〜13 px の補助。1画面に出す語は「TCA」
  「LEAD」「Vrel」など最小限にして、説明はヒント行へ寄せる。
- **音**(本案の追加、モックには無い): 射撃窓に入った瞬間の短いトーン、窓から出るときの下降音。
  噴射確定時はサブベースのパルス。ゴースト操作中は無音(静けさが「計画中」の合図)。

## 5. この案だから可能になるゲーム性

1. **「手前で噴いて会合を整える」が遊びになる。** ゴーストで試せるので、プレイヤーが CW の
   直感を自分で獲得できる。熟練者は一手で TCA を窓の中央へ合わせる「会合芸」を競える。
2. **射撃窓という新しい概念を第一級にする。** 窓は広がったり狭まったり、割れたりする(2つの解)。
   「窓が広いうちに撃つ」「窓が開くまで噴射で待つ」という判断が、数値を読まずにできる。
3. **不自由度の設計に使える。** 窓の幅を決めるのは弾速・照準ぶれ(σ)・敵の大きさ・相対速度。
   これらを武装や敵ごとに変えれば、画面の見た目だけで「この敵は撃ちにくい」が伝わる。
4. **敵 AI の意図が可視化できる。** 敵の「射撃窓を作る接近・射撃姿勢・離脱と再会合」(COMBAT.md の
   敵の4状態)を、敵側の会合図として見せれば、プレイヤーは敵の次の窓を予告として読める。
5. **リプレイと共有。** 会合図は Hill 座標の1枚絵なので、撃破の一連を1枚で保存・共有できる
   (NASA の会合軌道図と同じ読み方)。
6. **学習曲線の短縮。** 新規プレイヤーへの導入は「ゴーストが曲がるのを見る」だけでよく、
   チュートリアル文を減らせる。

## 6. 既存の前提をどう破るか、破って何を得るか

| 既存の前提 | この案での扱い | 得るもの |
| --- | --- | --- |
| UI は数値パネルが主、図は従(DOM の左右レール) | **図が主、数値が従**。Canvas/WebGPU の会合図を戦闘ビューの主役にする | 軌道力学の直感の壁を、読む作業から見る作業へ移せる |
| UI は状態を表示する層(現在の値の鏡) | **未来と仮定を表示する層**(予測・ゴースト・窓) | 噴射前に結果が分かり、試行錯誤のコストが消える |
| 軌道の描画はマップビューの仕事 | 戦闘ビューにも**ターゲット中心の相対軌道**を持ち込む | 「近距離戦と軌道遷移は同じシミュレーションの異なる時間スケール」を、画面で体現できる |
| 戦闘ビューは3D 視点の中で操作する | 3D 視点に加えて**2D の相対図**を並べる(または全面表示に切替) | 3D 視点では見えない「軌道の曲がり」「時間軸」が見える |
| 時間加速は戦闘で使えない | 計画中は ×1 に自動で落ちる | 「止めずに考える」ゲームの緊張を保ちつつ、計画の余裕を作る |
| UI 規約は「Tepui Glass」「パネルのウィジェット11種」 | 会合図・ダイヤル・タイムラインは**ウィジェット11種に無い**。新しい種類として足す | 規約の拡張が必要(要 UI-DESIGN の改訂)。見返りは上記すべて |

## 7. 実装の見取り図

### 計算(src/physics または src/game)

- **CW の厳密解は閉形式**。状態遷移行列(Φ_rr, Φ_rv)は t だけの関数で、一度計算すれば使い回せる
  (モックでは 0.5 秒刻みで 100 秒分をテーブル化)。毎フレーム、予測軌道・ゴースト・TCA を
  数百点評価しても軽い。
- **見越し解**は「位置 p から時間 t で原点へ着くのに要る速度 v_req(t) = −Φ_rv⁻¹ Φ_rr p」を
  t で走査し、`|v_req(t) − v_自機| = 弾速` となる t を探す。解は0〜複数個。
  これが CW 版の見越し射撃(Lambert 問題の線形版)。
- **射撃窓**は、見越し解の周りの射角を 0.1° 刻みで走査し、弾道が命中半径に入るものを
  印付けるだけ(モックで 1 回 0.3 ms)。命中見込みは、窓を照準ぶれの正規分布で重み付けして積分。
- **タイムライン**は、将来の各時刻の状態に対して「見越し解が存在するか」「窓の半幅
  ≈ 命中半径 /(弾速 × 飛翔時間)」を評価し、誤差関数で命中確率に直す。解析式で足りる。

### 実ゲームとの違いと難所

1. **CW は円軌道の線形近似。** 本ゲームは楕円軌道・J2・C22・大気抗力・放射圧を持つ。
   交戦圏 30 km・数分スケールなら CW は妥当だが、**高離心率の軌道(モルニヤ型)では外れる**。
   実装では「基準軌道の厳密な運動(Kepler)+ 相対位置の線形化」か、**実シミュレーションの
   RK4 を先読みで回して Hill 座標へ射影する**(精度優先、コストは増える)のどちらかにする。
   モックは前者の最も単純な形(CW のみ)。UI は「予測の源」を差し替え可能にしておく。
2. **3次元。** モックは面内(V-bar × R-bar)のみ。実装では H-bar(軌道面外)を別ビュー
   (側面図)で同時表示し、パッドを3軸にする。CW の面外成分は単振動なので解析的に足せる。
3. **姿勢と推力。** モックの Δv は瞬時(インパルス)。実ゲームは推力・燃焼時間・姿勢変更がある。
   ゴーストは「燃焼時間 T_b をまたぐ有限推力」の予測へ拡張する(中央差分で足りる)。
4. **敵の機動。** モックの敵は静止。実ゲームでは敵も動くので、会合図は「自機基準」と
   「敵基準」の切替を持つ。敵の予測軌道は仮定(推力ゼロ)で出し、外れた場合の再計算を見せる。
5. **描画。** 会合図は Canvas2D で十分(モックのとおり)。ゲーム本体は WebGPU/Three.js なので、
   DOM オーバーレイの `<canvas>`(UI-DESIGN の置き場に追加)か、別カメラの小さなビューポートで
   描く。高 DPI で線が太るのでラインの太さは CSS px 指定にする。
6. **弾の寿命とパラメータ。** モックの弾速 90 m/s・寿命 100 s・命中半径 60 m・ぶれ 0.5° は
   見た目のための仮値。実機の値は武装データから取る(COMBAT.md の弾寿命は 240 s)。

### 段階的な導入順(最小の第一歩から)

1. **TCA マーカー1個**: 現行の戦闘ビューへ、「最接近の時刻と距離」だけを数値で足す(CW 不要、
   線形近似でも可)。これだけでも価値がある。
2. **相対軌道の予測線**: 敵中心の2D 図を小窓で追加。実 RK4 の先読みを Hill へ射影して描く。
3. **ゴースト**: 既存のマップビューの Δv 編集(PRO/RET・NRM/ANM・IN/OUT)を、
   戦闘ビューの Δv パッドと共通の「保留 Δv」状態にする。
4. **射撃窓+ダイヤル**: LEAD マーカーを窓の帯へ拡張。既存の LEAD(COMBAT.md の「LEAD 偏差
   マーカー」)を置き換える。
5. **タイムライン**と提案ボタン。
6. 敵の予測、H-bar、有限推力。

## 8. リスクと反論

- **「結局、数値を図に置き換えただけで情報量は同じでは?」** — 図は「予測と仮定」を加えている。
  数値は「いま」しか言えない。ゴーストは**現在の数値からは計算しにくい未来**を見せる。
- **「CW は近似で、実機と合わない」** — 合わない箇所を黙って描くと嘘になる。予測の源を
  実シミュレーションの先読みに差し替えられるようにし、**近似の誤差が大きいとき(高離心率、
  長い先読み)は線を薄くして警告**する。ゴーストの確定後に実体と食い違ったら、その差も見せる。
- **「ゲームが簡単になりすぎる」** — 窓の濃さ・確率の定義(照準ぶれ・敵の機動)を武装と敵で
  変えられる。見えるのは窓であって、撃ち方の技量(ぶれを抑える・窓の中で撃ち続ける)は残る。
  補助を目立たせない/出さないモードも作る(「補助線は引くが目立たせず」の方向と衝突しない範囲で)。
- **「2D の図で3D の戦闘が分かるのか」** — 面外成分は H-bar の側面図で補う。3D 視点自体は残るので、
  これは**追加の視点**であって置き換えではない。
- **「画面が詰まる」** — 近接で TCA・ゴースト・ENEMY・刻みの文字が重なる(モックでも出る)。
  ラベルの衝突回避(ENEMY を左へ、ゴーストのラベルを下へ)を入れたが、完全ではない。
  実装では、近接時に会合図を自動で拡大し、重なるラベルは優先順位で間引く。
- **「物理が苦手な人には敷居が高い」** — 敷居は下がるはずだが、V-bar/R-bar の用語は不要。
  UI では「進行方向」「地球側」と日本語で書く(モックもそうした)。

### 他案との組み合わせ方

- **シームレスズーム**: 会合図の縮尺そのものがズームの軸になる。マップの軌道図の拡大が、
  そのまま会合図へつながる(同じ描画を別の座標系で出す)。
- **意図ベース指揮**: 「あの敵と会合しろ」「窓が開いたら撃て」という意図の実行結果を、会合図の
  ゴーストとして先に見せる(指揮の確認画面)。
- **世界観ダイエジェティック**: 会合図は1970年代風の CRT/ホログラムの計器として描ける。
  結晶(執政官)が計算を代行するなら、提案ボタンが「結晶の助言」になる。
- **艦隊管制**: 艦ごとに会合図を持ち、敵基準を共有する。
- **状況適応 HUD**: 窓が開いていないとき会合図は縮小し、窓が開くと拡大・濃くなる。
- **分子模型建造**: 建造とは無関係だが、ドッキング(会合)の最終段階では同じ図が使える。

## 9. 5軸での自己評価(直感性・一般性・美しさ・視認性・一貫性)

採点は5段階、甘くしない。

| 軸 | 点 | 根拠 |
| --- | --- | --- |
| **直感性** | **3** | ゴーストは「曲がる線を見て学ぶ」ので数値よりずっと直感的。だが、そもそも軌道の曲がりが直感に反するため、Hill 座標・V-bar/R-bar・TCA・窓という**概念は覚えてもらう必要がある**。ダイヤルは機首からの角度で、図の座標(世界固定)と別の基準なので、2枚の絵を頭で結ぶ負荷が残る。 |
| **一般性** | **3** | 「ターゲット相対」で働くので、敵戦・ドッキング・ラグランジュ点への会合・拠点への帰還まで同じ図が使える。一方、**建造・艦隊管制・経営・マップでの大域計画**は守備範囲外。CW 近似はシスルナの高離心率域で破れる。 |
| **美しさ** | **4** | 物理(軌道・弾道・窓)をそのまま線と面にしているので、装飾が要らず、1枚の絵として筋が通る。色の役割が固定され、記号は戦闘機 HUD に由来。減点は、**ターゲット近傍が重なって汚れる**こと(モックで実際に出る)と、数値パネルがまだ残っていること。 |
| **視認性** | **3** | 窓の帯・ゴースト・TCA の輪はひと目で意味が取れる。ただし、近接時のラベル衝突、9〜11 px の補助文字、7色の語彙、ダイヤルの自動倍率切替(見た目の縮尺が突然変わる)は、**戦闘の最中には読みづらい**。モックは 1600×900 向けで、小画面ではさらに詰まる。 |
| **一貫性** | **4** | 「色=役割」「破線=未確定」「帯=窓」の規則が会合図・ダイヤル・タイムラインで共通。保留 Δv の状態が一つで、パッド・キー・提案ボタンが同じ状態を動かす。減点は、会合図(Hill)とダイヤル(機首基準)で座標の基準が違うことと、既存の Tepui Glass・11ウィジェットの規約と別系統の部品になること。 |

総評: **戦闘と会合の局面では強いが、ゲーム全体の UI の統一原理にはならない。** 他案(特に状況適応・
シームレスズーム)の中に「戦闘局面の主役」として埋め込むのが、いちばん強い使い方。

## 10. 参考

実在するもののみ。

- **NASA / ISS の会合・近接運用(RPO)**: V-bar 接近と R-bar 接近、およびそれぞれのアプローチ
  楕円・ホップ(跳躍)軌道を、V-bar × R-bar の相対軌道図で示す慣習。シャトルや補給船の接近解析で
  使われる。V-bar は進行方向、R-bar は地球向き(本案は「上=地心から離れる側」に反転して描いた)。
- **Clohessy–Wiltshire 方程式(1960)**、およびその原型の Hill の方程式(1878): 円軌道上の基準点に
  対する相対運動の線形方程式。閉形式の状態遷移行列を持つ(本モックはこれをそのまま使用)。
- **アポロ計画の軌道ランデブー**: CSI(同軌道高度差を作る噴射)・TPI(最終の接近噴射)といった
  段取りで、相対軌道を Hill 座標で図示して計画した。
- **SpaceX Crew Dragon / ソユーズのドッキング表示(Kurs)**: 距離・接近率・姿勢を、ターゲット
  相対の計器で示す。数値と図の併用の実例。
- **戦闘機の HUD**: 速度ベクトル(FPM, flight path marker)・ピパー(LCOS, 射撃照準の見越し点)・
  ASE サークル。**「機首が向く先」と「実際に進む先」が違う**ことを記号の位置の差で示す。
  本案の `LEAD` と `Vrel` はこの対応物。
- **KSP(Kerbal Space Program)**: ナビボールの「ターゲット相対」表示(target prograde/retrograde)、
  ランデブー時の接近マーカー、マニューバノードの予測軌道と接近点(Closest Approach)表示。
  予測を図で見せる先行例で、会合計器の発想の最も近い一般向けの実例。ただし、噴射前に
  戦闘用の射撃窓まで出すものは、筆者の知る限り見ない。
- **Elite Dangerous**: コンバット時の相対速度ベクトルと見越し点(リード)の表示。
  フライトアシストを切ったときの慣性の見え方の例。
- **Outer Wilds**: 自機の「速度合わせ(match velocity)」の機能。相対速度を 0 にする操作を
  1つの動作へまとめる例(本案の提案ボタンの発想)。
- **Tufte**: スパークライン(小さく、文脈の中に置く時系列)・small multiples。
  タイムラインの「距離+窓」を1行に並べる設計の根拠。
