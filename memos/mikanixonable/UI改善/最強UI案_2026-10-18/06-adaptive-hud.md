# 06 適応する HUD — 注意の予算

> 動くモック: [06-adaptive-hud.html](06-adaptive-hud.html)(ブラウザで直接開く。外部依存なし)

## 1. 一行コンセプト

**HUD は「見せるもの」ではなく「プレイヤーの注意という有限の予算を、いま何に使わせるか」を決める装置である。
飛行フェーズ(巡航・会合・交戦・再突入・建造・ワープ)を自動判定し、いまの判断に要る情報だけを中心視野へ、
それ以外は周辺視野の光と細い折れ線へ退かせ、数値は「変わったときだけ」浮かび上がらせる。**

### いまの UI の根本的な問題

現行の戦闘ビュー HUD は、左右のレールに「艦のステータス / 軌道情報 / ターゲット情報 / 敵一覧 / カメラ」が
**常設**で積まれる(`UI-DESIGN.md` §5 の置き場①②、§8)。各パネルは「何の問いに答えるか」で行を絞っており
規律は高い。それでも次の構造的な問題が残る。

1. **常に全部が同じ重みで居る。** 交戦中に軌道要素の離心率を読む人はいないが、パネルは同じ面積を占め続ける。
   逆に会合の最終局面で要る「横ずれ」は、どのパネルにも無く、プロパティウィンドウを開いて探すことになる。
   **パネルの優先度が状況ではなく設計時に固定されている。**
2. **数値を読むことが唯一の入力経路になっている。** 距離・接近速度・熱・燃料はすべて「数字を目で拾い、
   頭の中で変化の向きと速さを組み立てる」必要がある。数字は現在値しか持たず、**傾向と緊急度を持たない**。
3. **危険の知らせ方が一段しかない。** 熱が上がることも、後方から敵が来ることも、日陰に入ることも、
   同じ「パネルの値が変わる」という形でしか届かない。視線が照準から離れた瞬間に、周辺の危険は消える。
4. **「パネルを探す」コストがゼロではない。** 目的の情報へたどり着くまでの探索(視線移動・ウィンドウを
   開く操作)が、そのまま戦闘中の判断遅れになる。

この案は 2〜4 を「縁の発光」「スパークライン」「警報の階層」で、1 を「フェーズ判定による再構成」で解く。
**目標は「パネルを探す」行為をゼロにすること。** 探さなくても、必要なものが必要な場所へ来ている。

## 2. 体験の描写 — LEO で会合から交戦、再突入まで

### 1) 巡航(静かな HUD)

画面はほとんど空いている。中心には細い十字、左上に小さな軌道の輪、左下に燃料・熱・電力の**折れ線が3本**。
数字は無い。右の縁がほんのり青紫に染まり、縁に沿って3つの点が並ぶ — **日陰まで 30 秒の合図**。
点は 10 秒ごとに1つずつ塗りつぶされ、最後の点が埋まると縁の帯が画面へ染み込み、星が明るくなって
太陽電池の折れ線が落ちる。誰も「日陰まで 28 秒」とは言っていない。数字を読まずに、時計が縁にある。

### 2) 会合(中心が精密になる)

遠方のステーションが視界に入ると、HUD が**滑らかに再構成される**(約 0.7 秒。モジュールは瞬間移動せず、
元の位置から新しい位置へ滑る)。中心の右に「会合」が膨らみ、**接近回廊の漏斗**が現れる — 自機を
ステーション中心の座標で見たときの、許される進入範囲(緑)と自機の軌跡(線)。針が緑帯の外へ出ると、
黄色の三角に変わり、助言「進入コリドー逸脱」が静かに出る。燃料と電力は細い折れ線へ縮む。

### 3) 交戦(周辺が敵の方角を教える)

ペプチド型の敵が3機。HUD は再び再構成され、**標的カードが中心へ寄り、武装(残弾の三角列と発砲)が下**へ。
軌道は一本の線へ縮み、熱と燃料も縮む。背後から1機が回り込むと、**左の縁が赤く脈打ち、縁に三角形が
3つ**並ぶ。振り向くと光は画面内へ入り、標的の周りに4隅の括弧が現れて「4.4km ▲200」の数値だけが括弧に
付いて来る。被弾すると、**弾が来た方角の縁**が一瞬赤く閃く。「どこから撃たれたか」を探す必要が無い。

### 4) 再突入(熱が主役になる)

高度が 125 km を切ると、**熱の折れ線が大きく**(数値付き)、軌道が詳細へ、中心右に「再突入回廊」
(熱 × 高度の平面。緑の回廊の中を点が下りる)が出る。下の縁が橙のジグザグで焼け始める。熱 60%
で**注意**(琥珀色の菱形、控えめなチャイム)、85% で**警告**(赤い三角、画面全周の細い赤枠、
繰り返す2音)。**W で引き起こす**と点が回廊へ戻り、熱が下がると警告は「解消」と打ち消し線を引いて
取り下げられる。同時に出ていた「加熱 上昇」の注意は、**上位の警告に包含されて最初から出ていない**
(「抑制中 1 件」とだけ小さく出る)。

### 5) ワープと建造

ワープ中は、残り時間の棒と到着までの秒数だけ。他はほぼ消える。建造では中心が船体、右が部品の置き場、
左下が電力収支に変わる — **戦闘用の情報は一つも出ていない**。

**一周して気づくのは、ずっと「画面のどこを見れば良いか」を考えていなかったこと。**

## 3. 構成要素

### 3.1 フェーズ判定器(HudDirector)

世界の状態から**判定は一箇所**で行う。

| 判定(優先順) | 条件の例 | 上がる/下がる速さ |
| --- | --- | --- |
| ワープ | ワープ中 | 上がる 0.7s |
| 建造 | ドック接続・建造モード | 下がる 3s |
| 再突入 | 高度 < 125 km | 上がる 0.7s |
| 交戦 | 敵が 12 km 以内 | 上がる 0.7s |
| 会合 | 目標ステーションが 15 km 以内 | 上がる 0.7s(重い方) |
| 巡航 | 上のどれでもない | 下がる 3s |

- **エスカレーション(より緊急な段階へ)は速く、デエスカレーション(落ち着く方向)は遅い。**
  敵が一瞬消えただけで巡航へ戻らない(非対称ヒステリシス)。
- 判定の**根拠**を常に1行で見せる(バッジの「判定: 敵 3 機・最寄 4.4 km」)。HUD が変わる理由が分かる
  ことが、予測不能さへの不満を和らげる最初の手段。

### 3.2 計器モジュールと詳細度

計器は固定の部品で、**詳細度 0〜3** のどれで居るかをフェーズが決める。

| 詳細度 | 見え方 | 使いどころ |
| --- | --- | --- |
| 0 | 退く(消える) | 今の判断に関係しない |
| 1 | 周辺: 折れ線のみ、枠なし、小さく | 傾向だけ気に留める |
| 2 | 簡約: 折れ線と見出し。数値は変化時だけ浮かぶ | 見張っておく |
| 3 | フル: 大きな図・数値・助言 | いまの判断に直結 |

モジュール: 燃料 / 熱 / 電力 / 軌道 / 標的 / 会合(接近回廊)/ 再突入回廊 / 武装 / 建造 / ワープ。
それぞれ「**何の問いに答えるか**」を持つ(現行の「各パネルの問い」の流儀をそのまま使う)。

| モジュール | 答える問い |
| --- | --- |
| 燃料・熱・電力 | 「このまま続けて大丈夫か」(傾向と閾値までの余裕) |
| 軌道 | 「いまどこを飛んでいて、日陰や大気はいつ来るか」 |
| 標的 | 「撃てるか」(距離の折れ線と接近率の折れ線) |
| 会合 | 「正しい進入路に居るか」(漏斗と針) |
| 再突入回廊 | 「引き起こすべきか」(熱 × 高度の平面での位置) |
| 武装 | 「あと何発あるか」 |

### 3.3 フェーズ別の既定配置(モックの `LAYOUT` と同じ)

置き場は固定の7つ(左上 TL・左下 BL・右上 TR・右下 BR・中心右 CR・中心左 CL・中心下 CB)で、
フェーズが「どの計器を、どの置き場に、どの詳細度で」置くかだけを決める。

| フェーズ | 中心(CR/CL/CB) | 周辺(TL/BL) |
| --- | --- | --- |
| 巡航 | 標的 d1(デブリの折れ線) | 軌道 d2、燃料 d2、熱 d1、電力 d2 |
| 会合 | **会合 d3**、標的 d2 | 軌道 d2、燃料 d1、電力 d1 |
| 交戦 | **標的 d3**、武装 d2 | 軌道 d1、燃料 d1、熱 d1 |
| 再突入 | **再突入回廊 d3** | **熱 d3**、**軌道 d3**、電力 d1 |
| 建造 | (右上)**建造 d3** | 電力 d3、燃料 d2 |
| ワープ | **ワープ d3** | 燃料 d2、軌道 d1 |

```
 巡航                           交戦                          再突入
┌──────────────────────┐  ┌──────────────────────┐  ┌──────────────────────┐
│[軌道]      巡航      ┊│  │ ─軌道      交戦      │  │[軌道詳細]  再突入    │
│              ┊      ┊│  │      ┌標的────┐      │  │          ┌回廊───┐   │
│      ＋      ┊      ┊│  │ ◀◀   │距離 4.4│      │  │    ＋    │ ╲  ┃赤 │   │
│ [燃料]       ┊      ┊│  │      │接近 ▲  │      │  │          └───────┘   │
│ ─熱  [電力]  ┊      ┊│  │ ─燃料 [武装]         │  │[熱 103%] ▁▂▃▅▇█▇     │
└──────────────────────┘  └──────────────────────┘  └▓▓▓▓橙のジグザグ▓▓▓▓▓┘
  右縁 = 日陰の点                左縁 = 後方の敵                下縁 = 熱
```

### 3.4 周辺視野の言語(縁の発光)

**画面の縁は「画面外の事象の方角と度合い」を伝える専用の面**とする。中心ほど詳細、縁ほど抽象。

| 事象 | 縁での形 | 色 | 強さを決めるもの |
| --- | --- | --- | --- |
| 敵(画面外) | 外縁の光 + **内向きの三角形** | 脅威色(赤) | 近さ × 接近率 |
| 接近物・デブリ | 外縁の光 + **点線の短い線分** | 注意色(琥珀) | 接近率 × 近さ(遠ざかれば消える) |
| ステーション(誘導) | **小さな輪** | 良好色(緑) | 一定(静か) |
| 日陰の到来 | 右縁の**青い帯 + 残り時間の3つの点** | 影の青 | 残り時間 |
| 熱 | 下縁の**ジグザグ線 + 橙の光** | 熱の橙 | 熱の割合(30% 未満は出ない) |
| 被弾 | 弾の方角の縁が 0.6 秒閃く | 脅威色 | 閃光のみ |
| 未確認の警告 | 画面全周の細い枠が脈打つ | 脅威色 | 確認すると止まる |

**色だけに頼らない(冗長符号化)。** 事象の種類は「三角 / 点線 / 輪 / 点の列 / ジグザグ」という**形**でも
区別できる。色覚配慮モード(Okabe-Ito)に切り替えても、形は変わらない。後方の物体は左右の縁へ
出る(前方なら画面内へ入る)。振り向けば光は括弧へ変わる — **縁の光は「そこを向け」という矢印でもある。**

### 3.5 数値は変わったときだけ(ささやき数値 / whisper)

詳細度 1〜2 の計器は、数値を**持続表示しない**。ある閾値を超えて変化した瞬間に、計器の見出しへ
「▼14%」「▲70%」「4.2km」のように橙で**浮かび**、2.6 秒かけて薄れる。変化量の閾値は計器ごと
(燃料 4%、熱 8%、標的距離 0.8 km …)。**数値が読めるのは「変わった直後」だけ**にすることで、
画面上の常時数値を減らし、変化そのものをイベントとして伝える。

### 3.6 スパークライン(Tufte)

燃料・熱・電力・高度・距離・接近率は、**30 秒分の時系列を軸なし・枠なしの折れ線**として示す。

- 正常範囲を**薄い帯**で、閾値を**点線**で、最小・最大を**小さな点**で、現在値を**橙の点**で示す。
- 閾値を越えた区間だけ**線の色が変わる**(注意=琥珀、危険=赤)。越える**前の傾き**で予測できる。
- 数値の代わりに折れ線を使うので、「あと何秒でどうなるか」を**傾きから読む**ことができる。

### 3.7 警報の階層

戦闘機・旅客機のマスターコーション / マスターウォーニングの考え方をそのまま持ち込む。

| 階層 | 見た目 | 音 | 振動 | 消し方 |
| --- | --- | --- | --- | --- |
| **警告 W**(即応) | 赤い三角、塗りつぶし、画面全周の赤枠、**最優先で中心上部** | 繰り返す2音(確認で止まる) | 長め | 状況が解消するまで居座る。確認は音と点滅を止めるだけ |
| **注意 C**(要対処) | 琥珀の菱形、枠線 | 2回のチャイム | 短い | 確認で点滅が止まり、解消で取り下げ |
| **助言 A**(知らせ) | 水色の輪、小さな文字 | 無し | 無し | 解消で消える |

**ノイズの抑制**(モックで再現している規則):

1. **ヒステリシス** — 出る閾値と消える閾値は別(熱 60% で出て 50% で下がる)。境界でのちらつきを防ぐ。
2. **最短継続** — 条件が 0.8 秒続いてから出す(一瞬のスパイクは出さない)。
3. **包含** — 上位の警告が出ていれば、同じ原因の下位は出さない(熱の警告があれば加熱の注意は出ない)。
4. **フェーズによる抑制** — 交戦中は助言を、ワープ中は助言と注意を出さない(エアバスの ECAM が
   離着陸の重要局面で一部の警報を抑止するのと同じ発想)。**警告は決して抑止しない。**
   抑止した件数は「抑制中 N 件」と小さく見せ、隠したことを隠さない。
5. **反復の畳み込み** — 25 秒以内に3回目の同じ警報は「×3」と畳み、フラッシュも音も出さない。
6. **取り下げの可視化** — 解消した警報は消えるのではなく、打ち消し線と「解消」を 1.6 秒見せてから畳む。
   「消えた」が「無かったことになった」と区別できる。

### 3.8 密度ダイヤルと段階的開示

- **密度ダイヤル**(ミニマル / 簡約 / 標準 / フル計器): 詳細度を一律に ±1 ずらす。**ミニマル**は
  交戦でも標的カードが d3→d1 になり縁の発光中心の画面に。**フル計器**は従来 HUD に近い情報量(すべて
  周辺に出す)。好みと環境(タッチの小画面 / 大画面)で選ぶ。
- **習熟度による段階的開示**: 入門(< 40)では各計器に1行の説明(「熱: 赤い帯を越えると船体が傷む」)を出し、
  軌道・熱・電力・再突入回廊は**未開放**。フェーズ遷移と警報の確認を重ねると習熟度が上がり、計器が
  1つずつ開放される(「計器が開放: 熱」)。いちどに全部を渡さず、学習の速さに合わせる。上級者は
  スライダー(または全開放)で最初から開ける。

### 3.9 遷移のルール(予測不能さへの対処)

- **予告**: 候補フェーズが現れた瞬間に、バッジが「→ 交戦 まで 0.7 s」と進行バーを出し、**次の配置の
  縮図**(点線)を現在の縮図の隣に描く。ユーザーは遷移の 0.7〜3 秒前に何が来るかを知る。
- **保留**: バッジの「保留」で遷移を 10 秒止められる。または「HUD の再構成を止める」で、提案だけ表示して
  自動では動かさない。
- **ピン留め**: 計器の「固定」(またはツールバー)で、その計器は**状況に関わらず同じ置き場・フル詳細**
  で居続ける。例えば燃料を固定した人の燃料は、どのフェーズでも同じ場所にある。
- **滑らかに動く**: 計器は消えて現れるのではなく、元の位置から新しい位置へ**滑る**(FLIP アニメーション)。
  目が動きを追える。`prefers-reduced-motion` では動きを省く。
- **同じ計器は同じ姿**: 配置が変わっても、計器の見た目・色の意味・折れ線の向き(上=増える)は不変。

## 4. ビジュアル言語

- **色**: 脅威=赤、注意=琥珀、助言=水色、良好=緑、影=青紫、熱=橙、強調=橙(アクセント)。
  意味は**固定**で、フェーズで変えない。色覚配慮モードでは Okabe-Ito の同じ意味割当てへ差し替える。
- **形**: 三角=脅威(尖りが危険)、菱形=注意、輪=助言/誘導、点の列=時間、ジグザグ=熱。
  **形は色の冗長符号**。モノクロ表示でも読める。
- **動き**: 再構成は 0.75 秒の減速曲線で滑る。警告は 0.6 秒周期の点滅(確認で止まる)。縁の光は近さに
  応じて脈打ちが速くなる。「近い=速い」を全チャンネルで共通化。
- **文字**: 等幅(HackGen)。数値は tabular。見出しは小さく淡く、数値は大きく。**文字は中心へ寄るほど大きい。**
- **音**(ソニフィケーション): 近づくものだけが鳴る。**間隔=距離、高さ=接近率、左右=方位**、
  敵はのこぎり波、味方・ステーションは正弦波。遠ざかるものは鳴らない。警告は繰り返す2音、注意は2回の
  チャイム。音量はダイヤルで調整。再突入では熱で低い音が速くなる。
- **触覚**: 警告と被弾でスマートフォン/ゲームパッドの振動(`navigator.vibrate`)。UI にも小さな「振動」
  インジケータを出す。

## 5. この案だから可能になるゲーム性

1. **「見る」ことが操縦になる。** 周辺の光に従って振り向く、という動作が戦闘の基本動作になる。
   数値を読むゲームから、**方角と傾向を感じるゲーム**へ。
2. **見落としが設計になる。** 日陰・熱・後方の敵のような**ゆっくり来る危険**を、プレイヤーが縁の合図で
   先に感じ取れるか否かが腕前になる。「見えなかった」ではなく「感じなかった」。
3. **段階的な習熟の物語。** 入門では熱の計器すら無く、慣れるに従い計器が開放される。上級者は
   ミニマルへ寄せ、**縁の光だけで飛ぶ**縛りプレイができる。
4. **同じ HUD で近距離戦と軌道遷移の時間スケール差を扱う。** 時間加速やマップへの遷移でも、フェーズの
   延長として HUD が再構成される(ワープ中は予定のノードだけ、等)。
5. **世界観との相性。** 「結晶に光を当てて動く」主人公は、電力が足りないほど**感覚が絞られる**:
   電力が低下するほど HUD が自動的にミニマルへ寄る(電力 → 密度ダイヤルの強制)という演出が成立する。
   (他案の世界観案との組み合わせ候補)
6. **観戦・配信に強い。** 画面が空いていて、危険が縁で示されるので、見ている側にも状況が分かる。

## 6. 既存の前提をどう破るか、破って何を得るか

| 既存の前提(`UI-DESIGN.md`) | この案での扱い | 得るもの |
| --- | --- | --- |
| §5 置き場は4種。レールは**縦積みの常設** | 常設レールを廃し、**7つの置き場へ動的に配置**。置き場そのものは固定 | 状況に応じて面積を配分できる |
| §8 常設パネルは「いまの問いに答える」 | 問いは変えない。**「いまの問い」を状況で選ぶ** | パネルの優先度が固定でなくなる |
| §5「表示/非表示と折りたたみは別軸」 | **ゲーム状態由来の表示(フェーズ)とユーザーの選択(ピン留め)は別軸**として継承 | 既存規則と矛盾しない形で適応を入れられる |
| §1 原則「ホバーは装飾」「情報はラベルで」 | 数値の常時表示を減らす代わりに**見出しラベルと折れ線**を常時残す | 数値の氾濫を避けつつ判読可能 |
| §3 状態語彙は閉じた集合 | 警報の階層(警告/注意/助言)を**新しい状態語彙**として追加する必要がある | 戦闘機・旅客機の流儀に揃う |
| §7 画面全体の独自入力監視は禁止 | 縁の発光は**表示のみで入力を持たない** | 入力規則と衝突しない |
| §8「軌道情報はプロパティウィンドウへ一本化」 | 軌道モジュールは**情報の重複**ではなく、「いまの飛び方」の簡約表示 | 軌道要素の正本は変えない |

**破る価値**: 現行 UI は「間違えない」ことには優れるが、「**探さない**」ことには優れていない。
この案は規約の字面は変えるが、**各要素が答える問いの設計**という本質は保存する。

## 7. 実装の見取り図

### 構成

```
 世界の状態(軌道・敵・熱・電力・模擬時刻)
        │ 読むだけ
        ▼
 HudDirector(判定器)── フェーズ・根拠・次候補・遷移までの残り時間
        │
        ├─ 計器レイアウト(フェーズ × 計器 → 置き場, 詳細度)  … 純粋なデータ
        ├─ 警報エンジン(状態機械: 待機→発報→確認→解消)    … 純粋なデータ + 時間
        └─ 縁イベント集約(画面外の物体 → 縁の位置・強さ・形)
               │
               ▼
 DOM 層: 7つの置き場 + 計器モジュール(詳細度クラスで見え方を切替、FLIP で移動)
 Canvas/WebGPU 層: 縁の発光(全画面1枚)、スパークライン(計器ごと)
 音: WebAudio(接近率の音、警報)、振動: navigator.vibrate
```

- **判定器・警報エンジン・縁集約は DOM を知らない**純粋なロジックにし、`src/game/` 側で単体テストできる形にする
  (CODING-RULE の層の考え方に合わせる)。DOM は結果を描くだけ。
- 縁の発光は**3D 描画の上に1枚のオーバーレイ**(Canvas2D か、WebGPU の後段パス)。画面外の物体の
  投影ベクトルから、画面の縁との交点を求め、放射グラデーションと形(三角・点線・輪)を描く。
  **モックの `drawEdge` がそのまま設計図**。
- 計器の再配置は **FLIP**(移動前後の位置を測って逆変形から戻す)。計器は DOM を保ったまま親の置き場を
  替える。詳細度はクラス `d0〜d3` で内部要素の表示を切り替える。
- 現行のウィジェット11種・状態語彙の中に収まる部品は流用し、**折れ線 / 縁の発光 / 警報帯**の3部品だけ
  新設する。

### 難所

1. **判定の信頼性。** 誤判定で HUD が動くと不快。非対称ヒステリシス・最短継続・保留で緩和するが、
   実プレイデータでの調整が要る(交戦の定義 12 km は敵の速度分布から決め直す)。
2. **スケール表示。** 軌道上の接近速度は m/s から km/s まで幅がある。折れ線は**自動スケール**
   (最小スパンを設けて平坦化を防ぐ)にする。モックでも実装済み。
3. **縁の光の過飽和。** 敵が20機で縁が真っ赤になる。**波(ウェーブ)単位での集約**と
   **強度の飽和・上位 N 件のみ描画**が必要。
4. **タッチ。** 縁の発光は表示のみなので問題ないが、計器のタップ領域(44px)と「固定」の誤操作に注意。
5. **既存仕様との整合。** 現行のパネル折りたたみ・保存(`UI-DESIGN.md` §5)は「ピン留め」へ統合する
   必要がある。

### 段階的な導入順(最小の第一歩から)

1. **縁の発光だけ**入れる(画面外の敵・接近物)。既存の HUD は変えず、既存の「敵一覧」の補助にする。
   これだけで「周辺視野の言語」の価値が検証できる。
2. **警報の階層**(警告・注意・助言と確認・取り下げ)を導入。既存の通知(トースト)を置き換える。
3. **燃料・熱・電力のスパークライン**を既存パネルの数値の隣へ追加し、反応が良ければ数値を
   「変化時のみ」へ。
4. **フェーズ判定器**(まずは交戦/巡航の2つ)と、パネルの**詳細度切替**。再配置はまだしない。
5. **置き場の動的配置**(FLIP)、ピン留め、密度ダイヤル。
6. ソニフィケーション、習熟度による段階的開示、残りのフェーズ。

## 8. リスクと反論

| 反論 | 応答 |
| --- | --- |
| **予測不能に動く UI は苛立つ**(指の下から消える) | ①配置の骨格(7つの置き場、計器の形・色の意味)は**不変**で、動くのは詳細度と置き場の選択だけ。②エスカレーションは速く、デエスカレーションは遅い(戻らない)。③**予告**(進行バーと次の縮図)、④**保留**、⑤**ピン留め**、⑥**滑らかな移動**。それでも不満なら「再構成を止める」で従来の固定 HUD に近づける |
| 「パネルを探すゼロ」は誇張では | **ゼロは理想**。実際には「探す必要が出る頻度を下げる」。ピン留めと密度ダイヤルで、探す人には探せる逃げ道を残す |
| 縁の光はうるさい / 目が疲れる | 強度は近さと接近率で決まり、遠い・遠ざかるものは出ない。画面全周の枠は**未確認の警告のときだけ**。`prefers-reduced-motion` で脈打ちを止める |
| 誤判定で重要な情報が退く | 警告は**どのフェーズでも抑止しない**。ピン留めで重要な計器を固定できる。「判定: ○○」の根拠を常時表示 |
| 色覚多様性 | 冗長符号(形)・Okabe-Ito 配色・音と振動の同時提示 |
| 数値が出ないと不安 | 数値は「変化時」に出る。密度ダイヤルを「フル計器」にすると常時表示。習熟度が低いうちは説明つき |
| 実装コストが大きい | 第一歩(縁の発光のみ)は 1〜2 日規模。後の段階は独立して価値がある |

### 5軸での自己評価(甘くしない)

評価軸は「直感性・一般性・美学的美しさ・視認性・一貫性」。各5点満点。

| 軸 | 点 | 根拠 |
| --- | --- | --- |
| **直感性** | 3 | 縁の光は「光った方を向く」という説明不要の動作で最も直感的(4〜5)。一方、**HUD が勝手に再構成される**ことは初見で戸惑い、「なぜいま消えたか」の学習が要る。判定根拠の表示と予告で緩和しているが、直感性の核は縁の光であってフェーズ判定ではない |
| **一般性** | 4 | フェーズ判定・警報階層・スパークライン・縁の発光は、軌道戦闘以外(飛行・運転・運用監視)にも移植できる汎用の手法。ただし**フェーズの定義と閾値はゲーム固有**で、その調整が毎回要る |
| **美学的美しさ** | 3 | 余白が増え、折れ線と縁の光は静かで美しい(巡航の画面は4〜5)。しかし**交戦・再突入では情報が増えて普通のダッシュボードに寄る**。滑る遷移は美しいが、ゲーム固有の世界観(結晶・ザンジバル風)の色はまだ無く、機能的な美にとどまる |
| **視認性** | 4 | 重要度に応じて大きさ・位置が最適化され、冗長符号で色に依存しない。弱点は、**詳細度1の周辺計器が小さく淡い**ことと、縁の光が前方の物体に使えない(括弧で補う)こと。数値を「変化時のみ」にすると**読み逃し**が起こる |
| **一貫性** | 2 | **この案の最大の弱点。** 「状況で形が変わる」ことと一貫性は本質的に衝突する。同じ計器が場所と大きさを変えるため、「いつもの位置」が無く、位置による記憶(筋肉記憶)が働きにくい。骨格の固定とピンで緩和するが、解消はしない |

### 一貫性と適応の緊張をどう扱うか

「状況で形が変わる」ことは、一貫性(いつも同じ場所に同じものがある)と正面から衝突する。この案は
一貫性を捨てるのではなく、**一貫性の単位を「位置」から「規則」へ引き上げる**。

1. **不変にするもの**: 7つの置き場の場所、計器の見た目と色の意味、折れ線の向き(上=増える)、
   縁の形(三角=脅威、点線=接近物)。**語彙は固定で、使う語を状況が選ぶ。**
2. **変えてよいもの**: 詳細度(0〜3)と置き場の選択のみ。
3. **規則は単純で、予告される**: 「緊急に近いほど中心へ・大きく」。例外は無い。
4. **逃げ道を常に用意**: ピン留め(位置も詳細度も固定)、保留(10秒)、再構成の停止。
   一貫性を求めるプレイヤーは、**自分で一貫性を買える**。
5. **変化の遅さ**: デエスカレーションは遅く、同じ状況が続く間は一切動かない。**「動かない時間」が
   長いほど、動いたときの意味が読み取れる。**
6. **最小の一貫面**: 警報の位置(中心上部)と音は、どのフェーズでも同じ。
   最も重要な情報は決して動かない。

それでも残る一貫性の欠損は、この案のコストとして受け入れる。残るコストが許容できなければ、案としては
**「縁の発光・警報の階層・スパークライン」だけを採り、再構成は採らない**(第一歩〜第三歩)選択もある。

## 9. 他案との組み合わせ方

- **シームレスズーム案**: ズームの段階(近距離戦↔軌道遷移)をフェーズの一種として扱い、ズームに応じて
  詳細度を自動で切り替える。縁の発光はズームに依存せず常に有効。
- **相対運動計器案**: 会合・交戦フェーズの中心の計器(接近回廊の漏斗など)を、より高度な相対運動計器へ
  差し替える。この案は「いつ出すか」を、相対運動計器は「何を出すか」を担当する。
- **意図ベース指揮案**: 意図(「会合する」「離脱する」)がフェーズの**入力**になる。判定が世界の状態から
  でなく、プレイヤーの宣言から決まれば、予測不能さの問題はほぼ消える(最良の組み合わせ)。
- **世界観ダイエジェティック案**: 電力・結晶の状態を、密度ダイヤルの強制と HUD の揺らぎへ接続する
  (電力が低いと周辺が暗くなる、など)。縁の発光は結晶の光へ置き換えられる。
- **艦隊管制案**: 複数艦のうち「いま注目している艦」のフェーズで HUD を決め、他艦は縁の合図
  (警報の階層)でだけ割り込ませる。注意の予算の考え方が最も効く。
- **分子模型建造案**: 建造フェーズの中心を、模型の操作面へ差し替える。建造中は他のフェーズ情報を
  すべて退かせる規則はそのまま使える。

## 10. 参考

実在するものだけを挙げる。

- **F-35 のコクピット**: パノラミックコクピットディスプレイと、ヘルメット装着ディスプレイ。
  情報の優先度に応じた**デクラッター**(不要な表示を消す)の考え方。
- **戦闘機・旅客機の警報**: マスターウォーニング / マスターコーション、警告・注意・助言の3階層、
  「確認(キャンセル)」で音と点滅を止め状況が解消するまで表示を残す考え方。
- **エアバスの ECAM / ボーイングの EICAS**: 飛行フェーズに応じた**警報の抑止**(離着陸の重要局面で
  一部を出さない)、「暗く静かなコクピット」(dark and quiet)の思想、上位警報による下位警報の包含。
- **対地接近警報装置(GPWS)**: 接近率に応じた音声警報(「PULL UP」)。接近率を音で提示する考え方。
- **自動車の駐車センサー**: 距離を音の間隔で伝える最も普及した聴覚インターフェース(モックの音は同じ
  規則に高さ=接近率を足したもの)。
- **Edward Tufte『Beautiful Evidence』のスパークライン**: 単語サイズのデータグラフ。軸と枠を持たず、
  最小・最大・現在値を示す。
- **Mark Weiser & John Seely Brown「Designing Calm Technology」(1995)**: 中心と周辺の区別、
  周辺に退いた情報が必要なとき中心へ移る考え方。
- **Mica Endsley の状況認識(Situation Awareness)理論**: 知覚・理解・予測の3水準。
  折れ線が予測を、縁の光が知覚を助ける設計の根拠。
- **Christopher Wickens のマルチプルリソース理論**: 視覚と聴覚は別の資源を使うため、聴覚(音・振動)へ
  逃がせば視覚の負荷が減る、という考え方。
- **Dead Space**: UI を世界の中(ダイエジェティック)へ置く方法。この案とは別方向だが、世界観案と組む
  ときの参考。
- **Elite Dangerous**: コンバット/アナリシスの**HUD モード切替**と、レーダーの方角表示。この案は
  それを手動切替でなく自動判定にする。
- **Kerbal Space Program**: 現行 UI の比較対象。パネルを開閉して必要な計器を出す流儀(この案の逆)。
- **Okabe & Ito の色覚バリアフリー配色**: 色覚配慮モードの配色の元。
