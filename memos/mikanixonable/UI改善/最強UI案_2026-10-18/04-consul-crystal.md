# 04 執政官の結晶 — 世界観と一体のダイエジェティック UI

リファレンス(動くモック): `04-consul-crystal.html`(同じディレクトリ。ダブルクリックで開く)

## 1. 一行コンセプト

**UI は画面に重なる計器ではなく、紫外光で駆動された光学結晶が投影する「像」そのものである。見るには電力が要り、電力が乏しければ像は遅れ、粗くなり、項目が消える。**

### 解く問題

いまの UI は「パネルに数値が並ぶ」KSP 的 HUD で、次の3つが根本の問題。

1. **メタである。** 暗い宇宙を透かすガラス面は、世界の外から貼られた道具に見える。作者の構想(「補助線は引くが目立たせず、作っているのはプレイヤーだと錯覚させる」「道具のふりをする」)と逆で、補助線そのものが画面の主役になっている。
2. **タダである。** 情報はいくら見ても無料なので、プレイヤーは「全部出す」以外の選択をしない。UI の密度・鮮度・解像度が**遊びの変数にならない**。作者のいう「自由度でなく不自由度を設計する」の素材が、HUD には1つもない。
3. **世界に属していない。** 数万年後の氷期の地球、1970年代風の技術水準、ザンジバル/ペルシャ風の建築、光学結晶に焼かれた LLM という世界設定と、画面の見た目が無関係。HackGen + マゼンタのガラスは、どの世界にも置ける。

この案は UI を**世界内の物**にすることで3つを同時に解く。結晶は電力を食う(2)。結晶は世界に実在する(1,3)。見るという行為に代価が付く。

## 2. 体験の描写

### 設定上の位置づけ

- **結晶 = 執政官の身体。プレイヤー = 執政官の意志。** プレイヤーは結晶の「注意」を握る者で、画面に映るものはすべて結晶が紫外光の下で組み立てて見せている像である。
- 声は結晶の内なる計算で、助言者の語り口でプレイヤーを「consul」と呼ぶ(下記 4.5)。
- UI を持つ唯一の装置が結晶なので、船が複数あっても UI は結晶ごとに1つ。結晶を持たない船は、光通信でつながる別の結晶の像として見える(3.7)。

### 具体的な1場面: LEO で敵と会合して撃破する(モックの流れそのまま)

プレイヤーは**ステータスバーを読んで状況を理解する**のではなく、「像が粗い」「遅い」「項目が欠けている」という**質感そのもの**から、自分が電力的に追い詰められていることを感じる。数字を読む前に、手触りで分かる。

## 3. 構成要素

各要素は「何の問いに答えるか」で整理する。モックの画面配置と対応している。

### 3.1 周縁の星の帯(「結晶はどれだけ生きているか」)

- 画面の周縁を一周する八芒星(ハタム)の連なり。**点灯数が実効電力そのもの**。
- 数値を読まなくても「いま何割で灯っているか」が周辺視で分かる。電力が落ちると星が時計回りに消えていく。
- 四隅には十芒星(ギリフ文様の {10/3})がゆっくり回る。

### 3.2 軌道スコープ(「自分はどこで、何が近いか」)

- ベクタスコープ風の発光線で、地球(極から見た円)・自機の軌道・目標の軌道・太陽の向き・影の円筒を描く。
- **夜側の斜線(ハッチング)**で地球の夜を示し、太陽の記号とペルシャ語の「خورشید(太陽)」「سایه(影)」を置く。日陰がいつ来るかが、地球の絵から直感で読める。
- 自機は太陽電池の翼を持つ小さな三角形で、日照では翼が明るく、日陰では暗い。
- 電力 88% 以上で、地表の緯線・経線の格子が出る(見える微細表示)。

### 3.3 相対運動スコープ(「相手は私に対してどう動いているか」)

- 自機を原点に、半径方向(R↑)と進行方向(V→)で描く Hill 座標のスコープ。目標の像が点で動き、残光(軌跡)が残る。
- 残光は**像の更新ごとに1点**追加されるので、更新が遅いと軌跡がまばらになる。これも電力の質感。
- 電力 50% 以上で出る。それ以下では枠だけが点線で残り、「要電力 ۵۰%」と書かれる。

### 3.4 ニキシー管(「数字で知りたい」)

- 距離・相対速度・最接近までの時間・撃破数。**オレンジ色の発光数字**で、この世界の1970年代風の技術に合わせ、結晶の青紫と対比させる。
- 電力が足りないと**上位の桁だけ**が灯り、最下位の桁は誤った値が混じる(桁の精度が電力に依存する)。

### 3.5 結晶・紫外光・3つの針(「結晶に何が起きているか」)

- 結晶の模型を光らせる。**内部の格子点の灯り**が電力に比例し、紫外光の破線が左から流れ込む。
- 針の計器は「光量(نور)」「蓄電」「受光」の3つ。蓄電の目盛りには赤い危険帯がある。

### 3.6 執政官の声(「いま、何が起きているのか」)

- タイプライター風にフランス語で流れ、下に日本語訳が薄く出る(4.5)。

### 3.7 光路と結晶 II(「遠くのことは、いつの出来事か」)

- 左の結晶 I(自分)と右の結晶 II(L1 の拠点)を結ぶ細い線。問い合わせ(C)を押すと、光の点が往復する。
- 返信は「**N 秒前の発信**」という刻印付きで、メッセージ欄と「II の蓄電 74%(4.2 秒前の値)」という経過時間付きの値として現れる。**値は決して「現在」として出ない**。
- 実世界の比率では月で往復 2.6 秒、L1 では約 10 秒。モックは片道 2.6 秒に圧縮している。

### 3.8 電力の記録(ペンレコーダ)と紙テープ(「この先、電力はどうなるか」)

- ペンが蓄電と光量を描く。右側の**未来の領域**は電力 62% 以上でのみ、日陰の予報(影のハッチング)が見える。それ以下では「未来は見えない」。
- 紙テープは電力 80% 以上で出て、過去の光量を5ビットの穴で刻む(装飾に見えて、実際に値が読める)。

### 3.9 刻印(セーブ・リスポーン)

- 結晶に記憶を刻む行為。**光量 60% 以上でのみ可能**で、蓄電を 14 消費する。
- 画面中央にギリフ文様の星({10/3} と {10/4})が、結晶の中で線を重ねるように描かれる。

### 状態遷移(電力と像の質)

```
要求電力 ──▶ 実効電力 ──▶ 結晶の温まり(τ=0.7s) ──▶ 像の質 q (0..1)
              ▲                                    ├ 更新間隔  16ms … 1.4s
   蓄電が尽きる │                                    ├ 線分数    160 … 14
   (brown-out) │                                    ├ 量子化格子 1 … 9 px
              │                                    ├ 頂点の揺れ 0 … ±5 px
   受光(日照55 │                                    ├ 表示項目   10段階のしきい値

```

## 4. ビジュアル言語

### 4.1 2つの文化の融合

| | 1970年代の技術 | ザンジバル/ペルシャの幾何 |
|---|---|---|
| 発光 | ベクタ表示(オシロ)、ニキシー管、ペンレコーダ、紙テープ | 星形タイル、ギリフ、ムカルナス、扉の彫刻 |
| 構図 | 針の計器、枠付きのパネル | 尖頭アーチの枠(各パネルの上辺)、周縁の連続文様 |
| 動き | 走査・残光・ロール | 文様がゆっくり回る、星が順に灯る |

結晶が**準結晶**であることが両者をつなぐ。ギリフ文様が準結晶的な非周期タイリングを含む(Lu & Steinhardt, 2007)という事実は、「ペルシャの幾何の中に書かれた結晶の LLM」という世界の説得力を、作者が説明しなくても支える。

### 4.2 色

- **結晶の発光**: 電力に応じて**深い紫(低)→ 青白(高)**へ移る。低電力は紫外光で励起された蛍光らしい暗い紫、高電力は白に近い。
- **ニキシー**: オレンジ(#ffaa55 付近)。人間の技術側の色。
- **危険**: 蓄電の低下と危険帯だけに赤。
- **日照/日陰で質感が変わる**: 日照では外光が像を白く洗い、コントラストが約 16% 落ち、右上から暖色の斜光が差す。日陰では背景が深く暗く、発光が滲んで(グロー 1.5 倍)コントラストが最大になる。**電力が豊富な日照ではコントラストが下がり、電力が乏しい日陰では像が鮮やかに滲む**という、取り引きの逆転も狙い。

### 4.3 形と動き

- 線は**二重描き**(太く淡い滲み+細い芯)で蛍光の太さを出し、電力が下がると線が太くなり(焦点がぼやける)、白い芯が消える。
- 更新は**走査**で表す: 更新間隔が 120 ms を超えると、縦の発光線が左から右へ流れ、左は新しい像、右は古い像として**継ぎ目で食い違う**。
- 低電力では: 頂点の揺れ、格子への吸着、ちらつき、稀な欠落(2〜4フレーム)、横走査のロールバー。**すべて「情報の質」の劣化**であって、装飾ではない。

### 4.4 文字

- **フランス語**: 等幅(結晶の声)。公用語であり、声はこれで語る。
- **スワヒリ語の造語/語彙**: 小さな名詞に混ぜる(`kivuli` 影、`jua` 太陽、`lengo` 目標、`mzingo` 軌道)。月のザンジバル系コミュニティの言葉として。
- **ペルシャ語(アラビア文字)**: 影・太陽・光・数字(۰۱۲۳۴۵۶۷۸۹)。しきい値の「要電力 ۵۰%」のように、**ロックされた枠**の数字をペルシャ数字で書く。読めなくても「何かの値」と分かる。
- 日本語は、プレイヤー向けの訳として声の下に**明朝体で薄く**付ける。作者メモの「広東語は明朝体を出したい」と合わせ、**訳注の書体を明朝系に統一**する。
- 注意: スワヒリ語・ペルシャ語・フランス語の文は、実装時に母語話者の校閲が要る(モックの文は筆者が書いた下書き)。

### 4.5 声(語り口)

- 一人称は使わず、「nous」(私たち=結晶とあなた)。プレイヤーを「consul」と呼ぶ。命令せず、**観察と提案**で語る。
- 電力で声が**劣化する**: 高電力では長文(「Elle approche. La fenêtre de tir s'ouvrira dans quelques secondes.」)、低電力では**要約形**(「Tir bientôt.」)に切り替わり、さらに低いと文字の化けと打鍵速度の低下が起きる。ただし短文は化けにくく、**最重要の警告は常に読める**(6.3)。
- 台詞の選び方で状況を教える(教師にならない): 「Vous brûlez la réserve pour un luxe.」(日陰で 90% 以上のまま)、「Le soleil est là. Pourquoi ne pas voir davantage ?」(日照で電力を絞り過ぎ)。
- 合成音声の方針: 実装では**波形合成せず**、母音の短いブリップとテープのヒス音を合わせた「タイプ音+低い声の気配」にする。結晶に焼かれた LLM が人間のように喋らない、という距離感を保つ。

### 4.6 音

- 結晶の起動: 低い共鳴音。電力が高いと倍音が増え、低いと基音だけが残る。
- 更新ごとの微かなクリック(更新間隔が可聴になる)。電力が低いと**間延びした呼吸**のように聞こえる。
- 日陰に入ると耳鳴り風の高周波がわずかに増す。

## 5. この案だから可能になるゲーム性

### 5.1 「見る」ことの経済

電力は戦闘・航行・視認で奪い合う**1つの予算**になる。同じ蓄電を、(a) 推力や武装の熱管理、(b) 結晶の光量に分け合う。作者メモの「昼側は排熱、夜側はバッテリー枯渇」がそのまま UI の取捨選択に重なる。

- **見ない戦術**: 地球の影を通過する間は 15% に絞って息を殺し、日照に出る直前に上げる。
- **見すぎの罰**: 全開で撮り続けると日陰で結晶が暗転し、**一番危ない時に目が見えない**。
- **賭け**: 撃つ瞬間の数秒だけ蓄電を燃やす「瞬き」。

### 5.2 情報の鮮度が武器になる

像は過去の写真なので、**相手の動きは「古い像の外挿」**になる。電力を落とした状態で撃つには、像の遅れを自分で補正する。これは軌道力学を教えずに感覚を鍛える作者の狙い(「あそこは危険だ、ああすると得だ」という肌感覚)と一致する。

### 5.3 日照/日陰が作戦を決める

太陽電池を損傷すると受光が 55 から 22 に落ち、**同じ UI が「日照でも苦しい」状態**になる。パネルの展開や損傷が UI の質感に直結する。戦闘ダメージの視覚的表現を別途用意しなくても、**画面が粗くなる**こと自体が被害の表現になる。

### 5.4 結晶間の光通信と群像劇

- 結晶は数箇所にしか置けず、離れた結晶の状態は**光速遅延**を経て届く。UI には必ず「N 秒前」の刻印が付き、**現在の状態はどこにも出ない**。
- 群像劇(並列に船を出す)で、別の船の状況は別の結晶の像として届き、遅れて見える。作者の「空間的に離れた箇所のイベントで時系列を同期する」を、**画面の時刻差**として表現できる。
- マップビューを「結晶が見ている像」とすれば、光速を超えてカメラを動かす違和感(作者メモ)にも答えが出る。**マップは結晶の内部の想像(予測の投影)**であり、現実の観測ではない、と UI が言い切れる。

### 5.5 セーブ・リスポーン

結晶が数箇所にしかなく、刻印に光量 60% 以上が要る。**どこに結晶を置き、いつ刻むか**が資源配置の問題になる。結晶のない遠地では死に戻りが遠い。リスポーンは「結晶の光の中で目を覚ます」演出になり、ロード画面の代わりにタイトルが投影される。

## 6. 既存の前提をどう破るか、破って何を得るか

| 既存の前提(UI-DESIGN の原則・慣習) | この案での扱い | 得るもの |
|---|---|---|
| UI は常に等しく読める(視認性は無料) | **破る。** 読めること自体が資源 | 不自由度の設計、遊びの変数としての UI |
| 原則4「見た目はトークンからのみ導く」 | 「結晶の質」(q)を**連続パラメータのトークン**として新設し、色・線幅・揺れ・更新間隔をすべて q から導く | 規則の精神(有限の語彙)は保てる |
| 原則1「一責務一 UI」 | 保つ。ただし置き場は「パネル」ではなく「結晶の内の像」になる | 責務の分割は崩さずに世界と一体化 |
| 原則6「タッチは第一級、ホバーは装飾」 | 保つ。拡大した当たり判定を像の外側(アーチの余白)に確保する | — |
| 数値と状態は常に最新 | **破る。** 像は遅れる | 「いつの像か」という時間感覚 |
| ステータスバーの時刻・倍率は常設 | 最低保証層(6.3)として**常設を残す** | 劣化と視認性の両立 |
| マップは神の視点 | 結晶内の予測の投影という位置づけへ | 光速問題と世界観の整合 |

### 6.3 視認性との緊張 — 劣化しても最重要情報は読める

この案の最大の矛盾は、**「電力不足で像が劣化する」ことと「視認性(最強の評価軸の1つ)」が正面から衝突する**ことである。「読めなくなる UI」はゲームでは単なる不親切になりうる。そこで次の規則を**設計原理として**置く。

1. **最低保証層(RTG の灯)を設ける。** 世界設定の RTG(常時 4 の電力)が賄う範囲で、**蓄電%、日照/日陰、光量%** の3つだけは、像の更新周期・揺れ・誤字から切り離し、**遅れなしの平文**で出す(モックでは結晶パネル下端)。結晶が暗転しても、「いま何が起きているか」は分かる。
2. **劣化とは「欠落」と「遅れ」であって「判読不能」ではない。** 揺れは最大 ±5px、格子は最大 9px、文字の揺れは ±1.6px と **上限を固定**する。針・数字・文字の形は崩さない。壊れるのは精度と鮮度。
3. **消える順序を設計する。** 重要度の**低い順に**消える: 地表格子 → 紙テープ → 予測 → 相対運動 → 照準線 → … → 軌道輪と電力計(最後まで残る)。最終段階でも「自分の軌道・蓄電・日照」は読める。
4. **劣化はプレイヤーの選択か、警告を経た結果であること。** スライダーを絞るのは選択。蓄電低下は赤い危険帯と声(「Réserve faible」)で**事前に**知らせ、落ちた後は brown-out(蓄電 15% まで回復を待つ)として明示する。**突然、理由なく見えなくなる**ことは作らない。
5. **遅れには上限がある。** 更新間隔は最大でも約 1.4 秒。像が数十秒止まることはない。
6. **配色の下限。** 最低電力でも線の輝度は一定以上(ちらつきの平均で約 80%)を保つ。
7. **抑制オプション。** 「ちらつき・欠落を抑える」(光過敏への配慮)で明滅・欠落・ロールを切れる。`prefers-reduced-motion` が有効なら既定で抑制する(モックも対応)。さらに**「像の質を固定する」**アクセシビリティモード(電力の消費だけを残し、像の質は一定)も用意し、ゲーム性より優先して提供できるようにする。
8. **視認性そのものを上げる設計は残す。** 高電力では二重描きの白い芯、ニキシーの高コントラスト、大きな針という**最強に読みやすい状態**を実現し、**低電力の劣化との落差**で電力の価値を伝える。

## 7. 実装の見取り図

### 7.1 レンダリング

- **UI をゲーム内の1枚のテクスチャとして描く。** 2D Canvas(または WebGPU の線描画)で結晶の像を描画し、three.js 上の全画面クアッドに貼る。DOM の置き換えではなく、**像の層**を新設する。
- 線は頂点バッファに積み、ポストプロセスで(a) 滲み(二重パス)、(b) 走査線、(c) 残光(前フレームの減衰)を重ねる。モックは Canvas2D のみで実現している。
- ベクタの**揺れと量子化**は頂点シェーダで `hash(seed, id)` から導く。スナップショットごとに seed を更新すれば、更新の間は揺れが固定され、更新のたびに揺れが変わる(モックの方式)。

### 7.2 スナップショットと更新

- ゲームの状態から**像用のスナップショット**(自機・目標の位置、電力値など)を、実効電力から導く間隔で切り出す。描画はスナップショットだけを読む。
- 更新中は旧と新の2つを持ち、走査位置を境に切り替える(モックでは `drawScene(old)` と `drawScene(new)` をクリップで分けて描く)。
- 例外: 最低保証層は**生の状態**を直接読む。

### 7.3 電力モデル

- `実効電力 = min(要求, 受光+RTG)`(蓄電が尽きた場合)、蓄電は `Δ = (受光+RTG-実効)×k`。受光は太陽電池モジュールの展開・損傷・日照(影判定)から既存の電力系が与える。
- 結晶の温まりは1次遅れ(τ≈0.7 s)で、電力を急に上げても像は少し遅れて立ち上がる。

### 7.4 DOM との関係

- 設定画面・プロパティウィンドウ・ヘルプなど「操作と説明」は DOM に残してよい。**戦闘中の情報(状況の理解)だけ**を結晶の像に移す。
- 当たり判定: 像の内側のクリックは「像のどこを指したか」として、世界座標へ逆変換する(既存のピックの考え方)。

### 7.5 難所

- 日本語・フランス語・ペルシャ語の**混在テキストの描画**(Canvas の `fillText` は双方向と整形が環境依存)。ペルシャ語は小さな固定語彙に絞り、ビットマップ化も検討する。
- 揺れ・量子化の上限と、ゲーム画面全体との重ね合わせ(像が世界と食い違う感覚を作り過ぎない)。
- 文様の生成。ギリフは手書きの意匠を基にして、実行時は {n/k} の星多角形と尖頭アーチ曲線の組み合わせに限定する。

### 7.6 導入順(最小の第一歩から)

1. **スナップショット層だけ**を現行 HUD の数値に挟み、更新間隔を電力で変える。見た目はそのまま(体験の核の検証)。
2. 電力予算と蓄電の導入。表示項目のしきい値表(モックの右下のリスト)を現行パネルの「出す/出さない」に適用する。
3. 最低保証層の設計と、劣化の上限(6.3)の確定。
4. 像のレンダラを新設(ベクタ線+二重描き+走査)。現行パネルを順に置き換える。
5. 周縁の星の帯、アーチ枠、ニキシー管、ペン・テープ。
6. 声(フランス語+訳)、タイプ音。
7. 結晶間の光通信と遅延、刻印。

## 8. リスクと反論

| 反論 | 応答 |
|---|---|
| 「見えなくなる UI は不親切。ゲームの最重要要素を不自由にしてよいのか」 | 6.3 の7つの規則で、**不自由は選択に結び付けた上で下限を固定**する。「何が起きたか」は常に分かり、分からなくなるのは「相手が正確にどこにいるか」だけ。 |
| 「新規プレイヤーが最初から劣化を見て混乱する」 | 最初のステージは日照のみ・高電力に固定し、**日陰を最初に体験させる場面**で声が初めて「Lumière baisse」と告げる。チュートリアルは声が担う。 |
| 「重い。ポストプロセスと二重描きで描画負荷が上がる」 | 像は 1280×720 の1枚で十分。モックは Canvas2D でも 60fps。WebGPU 化する場合も線の数は数百。 |
| 「世界観に寄り過ぎて、他の案(相対運動計器など)の機能性を殺す」 | この案は**表現の層**であり、中身は他案と差し替え可能(9)。 |
| 「ちらつきは光過敏に危険」 | 抑制オプションを既定の位置に置き、ちらつきの振幅は最大でも輝度の約 4 割に抑え、欠落は2〜4フレームの単発に限る。像の質を固定するモードを用意。 |
| 「声の言語が多くて作り込みが大変」 | 語彙を小さく固定し、母語話者の校閲を前提にする。文は定型の組み合わせで足りる。 |
| 「タッチ操作で『電力スライダー』が小さい」 | 電力は常設の縦の帯(結晶の脇)を 44px 以上の幅でつまめる形にする。 |

### 他案との組み合わせ

- **相対運動計器**: この案の相対運動スコープを、相対運動計器案の本体に置き換える。電力が高いほど**計器の情報の次元が増える**(位置のみ→速度→予測)という段階化は、そのまま重ねられる。
- **状況適応 HUD**: 状況適応は「出す/出さない」を状況から決めるが、この案では**電力から決まる**。2つを掛け合わせ、「状況が出すべき項目」を「電力が許す範囲で」出す。
- **意図ベース指揮/艦隊管制**: 光通信の遅延で、**命令が届くまでの時間と、届いた後の結果の像**が分離する。結晶を介した指揮の自然な形になる。
- **シームレスズーム**: ズームの縮尺が変わるたび、像のスナップショットが**再合成される**という描写ができ、電力が低いと縮尺の遷移が粗くなる。
- **分子模型建造**: 建造画面は「結晶が建造物を内的に想像している像」として同じ質感で描ける。

## 9. 5軸での自己評価

評価軸は直感性・一般性・美学的美しさ・視認性・一貫性。甘くしない。

| 軸 | 点 | 根拠 |
|---|---|---|
| 直感性 | **4** | 周縁の星の点灯数、像の粗さ、走査の食い違いなど、**数値を読む前に電力の状況が手触りで分かる**。ただし「命中判定は像の位置」という規則と、電力の収支(日照55/消費/RTG4)は学習が要る。 |
| 一般性 | **2** | 世界観(結晶・RTG・1970年代)に強く依存し、他のゲームには移せない。電力で像の質を変える構造は一般化できるが、文様と声は作品固有。このゲーム専用であることを良しとした設計。 |
| 美学的美しさ | **4** | 蛍光する線、ニキシーのオレンジ、アーチと星の文様、走査の食い違いは、既存のどの宇宙ゲーム UI とも違う。モックは主要な美を出せているが、文様の作り込み(ムカルナス、扉の彫刻)はまだ。5 は実機の描画とアセットが揃ってから。 |
| 視認性 | **3** | **最大の弱点**。高電力では最強に読めるが、低電力では意図的に読みにくい。6.3 の最低保証層と上限固定で下限は守るが、「劣化を許す」設計は、本質的に視認性の軸と衝突する。点を上げるには、高電力の読みやすさを磨き、低電力の劣化をさらに抑える必要がある。 |
| 一貫性 | **5** | 色・線・揺れ・更新・声・項目がすべて**1つの変数 q から導かれる**。世界設定(結晶・電力・日照)と見た目が因果でつながっており、例外を作らずに全要素を説明できる。 |

総評: 一貫性と世界観の説得力が突出し、視認性は意図的に代価を払っている。**他案の「見やすさ」を土台に、この案の「世界との一体感」を層として重ねる**のが最も強い。
