# 案05 フライトディレクター卓 — 群像劇のための並列運用 UI

> 対になる動くモック: [`05-flight-director.html`](./05-flight-director.html)(単一ファイル、ダブルクリックで動く)

---

## 1. 一行コンセプトと、解く問題

**「船」ではなく「時間」を主役にした管制卓。横軸=時間、縦=船と基地と結晶。指令は光の波面として広がり、到達するまで船は旧指令で動く。**

### いまの UI の根本的な問題

現行 UI は「いま・ここ・この1隻」の数値パネルである(艦ステータス/軌道情報/ターゲット情報/敵一覧)。
マップビューには時間加速があるが、これは **「1隻の軌道を早送りする道具」** であって、
作者が構想している世界の遊び方 ―

- 船が動くのに **1ヶ月** かかるから **並列でどんどん出したい**
- **群像劇**: 空間的に離れた出来事を時系列で同期させる(終盤の花火・爆発・校内放送)
- **光速の有限性**: 指令は地球〜木星なら10分かかる。「それゲーム化できたら楽しいだろうな」
- 船がやられても人が死んでもゲームが続く(結晶=セーブ/リスポーン、群像劇へ切り替え)

― を載せる器がない。具体的には次の4つが欠けている。

| 欠けているもの | 症状 |
| --- | --- |
| 時間軸の一覧性 | 「次にどの船の何時に何が起きるか」は、船を1隻ずつ開いて軌道を回して調べるしかない |
| 並列運用の注意配分 | 時間加速を上げると、別の船で起きていた交戦に気付かず手遅れになる。加速を下げると退屈 |
| 遅延という不自由度 | マップのカメラは光速を超えて動くし、指令は瞬時に効く。作者自身が「マップモードで光速を超えてぐりぐりは変」と書いている |
| 現場の切替 | 1隻の直接操縦(戦闘ビュー)と、艦隊の運用が同じゲームの中でつながっていない |

この案は **NASA のミッションコントロールが昔から持っている答え** ― タイムライン・コンソール、
フライトディレクターの GO/NO-GO、光時間遅れを前提とした事前コマンド列 ― を、
このゲームの世界観(結晶が管制官、船は数日〜1か月の航海)にそのまま移植する。

## 2. 体験の描写

舞台は D+0。月 NRHO のステーション「ミフラーブ」にある **結晶α**(プレイヤー)の前に、
管制卓が点いている。船は4隻: 貨物タグ「ラ・ペルル」、戦闘艦「アルバ」、L2 の偵察艦「ナジュマ」、
LEO の戦闘機「ティアレ」。

### 場面: 「敵接近」の手前で止まる

1. **再生**(Space)。時間は 12 h/s で流れる。上半分の地図では船が滑り、下半分のタイムラインでは
   再生ヘッドが右へ進む。
2. D+1 01:48、**時間加速が勝手に止まる**。赤い帯「⏰ アルバ 敵接近(対 ハンター#1 60千km圏)」。
   卓は予定時刻の1時間手前で止めた(手前で停止の幅は設定で変えられる)。
3. タイムラインを見る。ラ・ペルルのレーンの先には、**赤い「交戦予測」のバー**(D+2 22:54)と **✖**、
   そこから結晶レーンへ斜めに伸びる白青の光線 ― 「放っておくと喪失する。光が結晶に届くのは 1.3 時間後」と読める。
   アルバのレーンには、3時間後(D+1 06:06)に **予定された噴射**(外縁パトロールへの出発)がある。
4. 打てる手を考える。アルバのレーンには **琥珀色の帯**(指令が効くまで 1.6 h)。出発の前に **間に合う**。
   一方「窓待ち 26.8 h」と出ているナジュマは、そもそも L2 で月の影に隠れて通信できない ― この船には何も送れない。
5. 宛先にアルバ、指令「**迎撃**」、結晶αから送信。**琥珀色の波面** が地図上に広がり、タイムラインには
   結晶レーンからアルバのレーンへ **斜めの琥珀の線** が引かれる(傾きが遅延)。
   アルバの出発計画は、**新しい指令が届いた時点で破棄される**(予測経路が折れる)。
6. 念のため、ラ・ペルルに「**条件付き**: 敵が 25,000 km 以内に入ったら回避」を送る。敵が来なければ何も起きない。
7. 再生。波面がアルバを呑み込んだ瞬間にアルバの予測経路が敵へ曲がり、ログに「指令到達」。
   アルバが先に敵を撃破する(★、D+1 18:42)。**結晶に光が届く 1.6 時間後** に、ログへ
   「アルバ が ハンター#1 を撃破 ― 発生 1.6 h 前」が流れる。ラ・ペルルの回避条件は **発動せずに終わる**。
8. だが、アルバは「迎撃」のままである。**止める指令を送らない限り、次に近い敵(地球側の網ノード)へ飛んでいく**。
   数日後、予測のレーンに「交戦」が連続して現れ、プレイヤーは「旧指令で動き続ける船」の怖さを知る。
   (モックでこの連鎖が実際に再現される。)
9. その間、ティアレの現場は **11〜12 時間遅れ** でしか見えていない。「いまティアレがどうなっているか」は
   原理的に分からない。**だから、前もって条件付き指令を送るしかない** ― これが遊びになる。

(もし何もしなければ、ラ・ペルルは D+2 22:54 に交戦、D+3 02:48 に喪失する。「待機」を送るだけでは
 アルバはバーグに留まるが、ラ・ペルルは間に合わず喪失し、アルバは **敵を討つのが遅れる**。モックで3通りとも試せる。)

### 場面: 同時刻ビュー(群像劇の同期)

ログの「アルバ が ハンター#1 を撃破」(など任意の出来事)をクリックすると、再生ヘッドが **発生時刻** へ跳び、
右上の4枚のタイル(各船の現場)が **同じ時刻** に揃う。各タイルには
「⚡ 閃光が届くまで 1.3 h」「⚡ 閃光を目撃(23 min 前)」と出る。
**同じ爆発が、離れた4か所へ、別々の時刻に届く。** 地図では白青の波面が地球側へ広がっていく。
群像劇の「空間的に離れた箇所から見えるイベントで時系列を同期する」を、そのまま画面にした。

### 場面: 直接操縦へ入って、戻る

B で選択中の船の直接操縦(戦闘ビュー)へ入る。**世界の時計は 1秒=1分 に落ちる**。
他の現場は下段のタイムラインで進み続け、アラームが鳴れば帯が上に出る。
Esc で卓へ戻る。入ること自体がコスト(他の現場の時間が事実上止まる)になるのが肝で、
「撃ちたいから入る」のでなく「ここは自分が撃たないと崩れるから入る」になる。

## 3. 構成要素

画面は **上段=空間(地図+現場タイル+指令)、下段=時間(スイムレーン)** の2段。
各要素は「何の問いに答えるか」で選んでいる。

```
┌ 時間加速 / 手前で停止 / アラーム種別 / 光速 c / 発信・観測結晶 / 視点 ───────────────────┐
├──────────────────────────────────────────────┬───────────────────────┤
│  地図(空間)                                  │ 現場タイル 2×2        │
│  ・地球・月・L1・L2・基地・結晶              │ (同時刻ビュー)        │
│  ・指令の波面(琥珀) / 事象の光(白青)         ├───────────────────────┤
│  ・船の真の位置 と 結晶に見えている遅延像     │ 指令コンポーザ        │
│  ・予測経路(噴射=太い橙)・日陰帯             │ 宛先/指令/目標/条件   │
├──────────────────────────────────────────────┴───────────────────────┤
│ 時間(スイムレーン)  横軸=時間                                          │
│  結晶α ────◆────────────────  (指令の発信点)                          │
│  結晶β ─────────────────────                                          │
│  1 ペルル ──▮──────▮──[交戦]✖──────   ← 噴射/交戦/日陰/通信窓          │
│  2 アルバ ─────▮───────★────────                                      │
│  3 ナジュマ ──────────────────────                                    │
│  4 ティアレ ┃┃┃┃┃┃┃ (LEO は周回で通信窓が細かく切れる)                  │
│  ミナール(L2)                                                          │
│                  ▲ NOW                                                 │
└──────────────────────────────────────────────────────────────────────┘
```

### 3.1 スイムレーン(下段)— 「次に注意が要るのはどの船の何時か」

| 要素 | 見た目 | 答える問い |
| --- | --- | --- |
| 噴射 | 橙のバー(未来は破線の枠) | いつ燃やすか |
| 交戦 | 赤のバー(未来は「交戦予測」) | いつ・どの船が撃ち合うか |
| 日陰 | 青紫の斜線 | いつ電力・視界が落ちるか |
| 通信可能窓 | 各レーン下端の緑のバー(途切れ=赤) | いつ指令を送れるか |
| 光線(琥珀) | 結晶レーン→船レーンへ斜めの線、到達点に◆ | いつ送り、いつ効くか。傾き=遅延 |
| 光線(白青) | 船レーン→結晶レーンへ斜めの線 | 起きた出来事を、結晶はいつ知るか |
| **未着の過去**(シアンの帯) | 再生ヘッドの**左**。幅=その船までの光時間 | **まだ見えていない過去**(ここで何かが起きていても知らない) |
| **指令が効くまで**(琥珀の帯) | 再生ヘッドの**右**。幅=指令の到達時刻まで(遮蔽なら「窓待ち」) | **いまは変えられない未来** |
| アラーム目盛 | ルーラー上の赤い▼ | 次にどこで自動停止するか |

最後の2つが、この案の絵としての核である。**再生ヘッドの左右に、船ごとに幅の違う帯が張り付く。**
遠い船ほど帯が太い。つまり「現在」が1本の線ではなく、船ごとに **幅を持った光円錐の断面** として見える。
Minkowski の時空図を、横軸=時間・縦=船というガント形式に畳んだものである。

### 3.2 地図(上段)— 「いま空間でどうなっているか」

- **指令の波面**: 結晶を中心に、半径 = c × 経過時間 で広がる琥珀の輪。船に当たった瞬間に挙動が変わる。
- **事象の光**: 撃破・爆発の位置から広がる白青の輪(撃破は★の花火)。これが各現場に届く時刻が別々。
- **光の時間定規**: 結晶を中心に「光で +1h, +2h …」の薄い同心円。地図の縮尺そのものが「光時間」で読める。
- **真値と遅延像**: 船の本当の位置(塗り)と、結晶に **いま見えている** 位置(中抜き、「像 −2.7 h」)を線で結ぶ。
  視点切替で「神視点(真値のみ)/ 結晶視点(像のみ)/ 両方」。
- **予測経路**: 選択船は長く、他は短く。噴射区間は太い橙。
- **日陰帯**: 地球・月の影が時間とともに回る(回転座標系なので影が掃く)。

### 3.3 現場タイルと同時刻ビュー(群像劇)

4枚のタイルは **同じ時刻 T** の各船の現場(船を中心にした小地図)。
タイルには「指令遅延」「通信窓なし」「閃光が届くまで」を出す。ログから出来事を選ぶと全員がその時刻に揃う。
クリックでその船を選択、Tab でザッピング(地図が船へ寄る)。

### 3.4 指令コンポーザ

- 宛先(船)・指令(移動/待機/回避/迎撃/帰投)・目標(地図クリックまたは名前)・**条件**。
- 条件: 「敵が R km 以内に入ったら」「燃料が X% を下回ったら」。条件付き指令は **到達後に船が武装し(armed)、
  自分で判断して発動する**。地図には条件の半径が点線で出る。
- **ETA プレビュー**: 「到達予定 D+1 20:12(+3.1 h)」「遮蔽のため窓待ち」「それまで船は旧指令で動きます」を
  送信前に必ず見せる。**送る前に、効くまでの遅延を知らされる** のが公平さ。

### 3.5 時間制御 — Kerbal Alarm Clock を一級市民に

- **自動停止**: 次のアラーム時刻の手前(設定幅)で止まる。アラームの種別 ― 脅威・交戦(敵接近・交戦開始・条件発動) / 喪失・戦果 / 指令・到着 / 噴射 / 通信窓 ― は個別に ON/OFF(既定は前の2つだけ)。
- **アラームの時刻は2種類**:
  - 計画から予測できるもの(噴射・敵接近・交戦開始・到着)は **発生時刻 −設定幅** で止まる。「敵接近」(60千km圏)は交戦の数十時間前に鳴るので、実際に手を打つ猶予はここで生まれる。
  - 予測できないもの(撃破・喪失・条件発動)は **結晶に光が届いた時刻** で止まる。
    **知らない出来事で止まれない**、という遅延の整合性を保つ。
- **N**: 次の注意点へジャンプ(現行の「N 次ノードへワープ」の一般化)。
- 右下の「次に注意が要るのは」に、直近3件が **船の色・内容・カウントダウン** で並ぶ。クリックでその時刻へ。

### 3.6 状態遷移

```
        ┌──────── 再生(時間加速) ────────┐
        ▼                                 │アラームの手前で自動停止
   [卓: 俯瞰] ──指令を送る──▶ [指令が飛行中] ──到達──▶ [船の挙動が変わる]
        │  ▲                      (波面が広がる)
        │  └────── Esc ─────────┐
        └──── B / 船を選んで ────▶ [直接操縦] (世界の時計 1秒=1分、他の現場は進み続ける)
```

## 4. ビジュアル言語

- **色は意味に固定する。** 琥珀=こちらから出る光(指令・噴射)、シアン=こちらに届く光(像・未着)、
  白青=出来事の光(爆発)、赤=脅威(交戦・敵)、緑=通信可能、青紫=日陰、金=戦果(★)。
  船は4色(金・薔薇・ミント・青)で、タイル見出し・レーン見出し・ログの点・地図の記号を貫く。
- **斜めの線は光。** 結晶レーンと船レーンをつなぐ斜線は、傾きが遅延そのもの。凡例が要らない絵にしたい。
- **未来は「ヴェール」と破線。** 再生ヘッドの右はうっすら暗く細かい斜線。予測は破線の枠・薄い塗り。
- **音(未実装)**: 遅延を音にする。指令送信=低いパルス、船に着いた瞬間=微かなクリック(到着の確認音)、
  遠い爆発=結晶に光が届いた瞬間に鳴る無音→遅れて鈍い音。**音の遅れが時刻差を体に覚えさせる。**
- **文字**: 等幅。時刻は `D+2 21:54`、遅延は `+3.1 h` で桁を揃える(Tufte 的に、数字は少なく、位置で読ませる)。
- **世界観との整合(結晶の視点)**: 1970年代の管制室のようなモノクロに琥珀、という素材感に寄せる余地がある。
  モックは暗い宇宙背景のガラス面だが、案としては「計器盤の質感」へ振ってよい(案04のダイエジェティックと組める)。

## 5. この案だから可能になるゲーム性

1. **並列運用が「遊び」になる。** 船を何隻も出し、どの船のどの時刻にどの指令を置くかが主要な意思決定になる。
   KSP の1隻中心から、**艦隊のスケジューリング** へ。
2. **不自由度の設計。** 作者の言う「不自由度を設計する」を、**光速遅延・通信窓・日陰** で実現する。
   遅延は罰ではなく、「先に読んで条件付き指令を置く」という新しい上手さの余地になる。
3. **条件付き指令=意図の事前宣言。** 「敵が 25,000 km に入ったら回避」は、プレイヤーが持つ唯一の遠隔操縦である。
   指令を文として書くので、後で「なぜあの船は逃げたのか」を **読み返せる**(案03 意図ベース指揮と直結)。
4. **結晶の価値が増す。** 結晶は数か所しか置けず、位置が **発信点** と **観測点** を決める。
   α から送るか β から送るかで、同じ船への遅延も通信窓も変わる。結晶をどこに置くか・移すかがそのまま戦略になる。
5. **群像劇のリスポーン。** 船が喪失してもレーンは残り、他のレーンが続く。「やられたらロード」でなく、
   **やられた知らせが遅れて届く**。主人公が「結晶」なので、船を乗り換えても自己同一性が壊れない。
6. **終盤の花火。** 事象の光が全現場へ届く演出(同時刻ビュー)を、システムとして最初から持てる。
   群像劇の終盤に爆発を見る、の下地。
7. **戦闘ビューの意味が変わる。** 入ること自体がコスト(他の現場の時間が止まる)になるので、
   戦闘は「毎回やる作業」でなく **ここぞで入る見せ場** になる。作者の悩み「5分くらい等倍速で撃ちたい」の正当化として、
   「世界の時計を戦闘に預けている」を UI が見せられる。

## 6. 既存の前提をどう破るか、破って何を得るか

| 既存の前提(UI-DESIGN 等) | この案での扱い | 得るもの |
| --- | --- | --- |
| 左右のレールにパネルを縦積み | 画面の半分を **時間軸のスイムレーン** にする | 並列運用の一覧性。パネルを開いて回る必要がなくなる |
| 指令は瞬時に効く | 光速で伝わる。**到達まで旧指令** | 不自由度の源泉。条件付き指令という新しい技能 |
| マップのカメラは自由 | **結晶に見える像** と **真の位置** を分けて描く | 「マップはメタな概念図」という作者の逃げ道を、遊びに変換 |
| 時間加速は倍率を上げ下げする | **イベント手前で自動停止**。倍率は見せ方にすぎない | 加速を上げるのが怖くなくなる。放置と介入のリズム |
| 1隻の船を中心にした UI | 船は **レーンの1本**。1隻を選ぶ操作は切替にすぎない | 群像劇。船が失われても卓は残る |
| 戦闘ビューとマップビューは2モード | 戦闘は **入退場する現場**。卓が常にホーム | 作者の「落ち着くホーム」(松明の灯る場所)を UI が担う |
| 画面は常にプレイヤーの「いま」を見せる | **「いま」は船ごとに幅がある**(光円錐の帯) | 「知らない」が画面に見える。知っていることを知っている感 |

**破らないもの**: 時間を一本の軸に載せること、数値を位置で読ませること(Tufte)、
ゲームは同一のシミュレーションの異なる時間スケール、という README の理念。むしろ時間スケールの違いを
「ズームではなく、レーンの時間幅」で表現するので、**理念はより強く守られる**。

## 7. 実装の見取り図

### 7.1 データ

- **決定論的な1本の予測軌跡(トレース)** を持つ。モックは 0.1 h 刻みで 240 h 分を再計算している。
  指令が増えるたびに先頭から再計算し、再生ヘッドはトレースのインデックスにすぎない。
  - 現行ゲームの RK4・Kepler 軌道は **ゲーム側が既に予測軌道(マニューバーノード)を持っている** ので、
    長期予測はそれを船ごとに並べる形になる。
  - 過去へスクラブして指令を送ったら、**以降の自分の指令を破棄して分岐**(モックの挙動)。
    本実装ではスクラブは再生のレビュー専用にし、指令は現在時刻にしか送れなくするのが妥当。
- **イベント**は「(種別, 船, 発生時刻, 位置, 光が結晶に届く時刻)」のリスト。予測軌跡から抽出する。
  種別: 噴射開始/終了、日陰入出、通信窓開閉、交戦開始/終了、到着、喪失、撃破、指令到達、条件発動。
- **指令**は `{宛先, 発信結晶, 発信時刻, 内容, 条件?}`。船の側に **受信キュー** と **条件の待機リスト** を持つ。
  到達判定は「|船−結晶| ≤ c × (t − 発信時刻) かつ 視線が通る」。モックの2本の式はこれだけ。
- **視線**は球2つ(地球・月)との線分交差で判定。通信窓・遮蔽待ちはここから出る。

### 7.2 描画

- **下段スイムレーン** は Canvas2D で十分(モック同様)。レーン数×区間数は高々数百。
  本実装では WebGL 化の必要はなく、**DOM を使わない方が速い**。ホバーは自前のヒットテスト。
- **地図** は three.js の既存マップビューに **オーバーレイ層** として波面・像・光の時間定規を足す。
  波面は半径が毎フレーム変わる円(LineLoop)でよい。像はスプライト。
- **現場タイル** は同じシーンを別カメラで描く(RenderTarget)。モックは Canvas2D の簡易描画。
  4〜8枚の小さな RenderTarget は、解像度を落とせば既存のレンダラで足りる見込み。
- **自動停止** は時間加速ループ側に「次のアラーム時刻」を持たせ、1フレームの進行幅をそこで切るだけ。

### 7.3 難所

1. **予測軌跡の再計算コスト**: 指令のたびに全船を長期予測すると、高精度摂動(J2/C22/抵抗)では重い。
   → 予測は **低精度で別スレッド(Worker)**、再生は実シミュレーション、という二重化が要る。
   二つのずれが目立たないよう、予測は「破線=目安」として描く(モックもそう)。
2. **戦闘との整合**: 直接操縦の結果が予測へ反映されない。モックはあえて反映していない。
   本実装では入った時点で **その船の予測を捨てて実シミュレーションに切替**、出るときにまた予測を張る。
3. **時間の解像度**: LEO は周期 1.5 h、月までの航海は数日〜1か月。1本の時間軸に載せると LEO が潰れる。
   モックは LEO を誇張して周期 8 h にしている。本実装ではレーンを **ズーム可能な二段**(月間/軌道周回)に分ける。
4. **光速のゲーム値**: 実際の光速では地月で 1.3 秒。ゲーム内では **c を縮める** ほかない。
   モックの既定は 32,000 km/h(地月 12 h)。**スライダーと「実 c」ボタン** で遅延ゼロとの違いを体験させる。
   作者の挙げた「地球〜木星で10分」の世界(木星への遠征)では実 c でも遊べる。
5. **予測の公平さ**: モックの予測は **全知**(敵の動きまで真値で読む)。本来は結晶が持つ情報(遅延像)から
   推定すべき。→ **予測にも「確からしさの帯」** を持たせる案(7.4 の第5段)。

### 7.4 段階的な導入順(最小の第一歩から)

1. **(最小)** 既存の時間加速に **「次のイベント手前で自動停止」** と「次に注意が要るのは」リストを足す。
   イベントは既存の軌道予測(ノード到達・近接・SOI 変更)から出す。**遅延も波面もまだ要らない。**
2. 下段に **スイムレーン** を足す(噴射・近接・日陰の3種から)。ここまでは光速抜き。
3. **光速遅延の導入**: 指令の波面、通信窓、ETA プレビュー、条件付き指令。CREATIVE モードに ON/OFF を置く。
4. 現場タイル・同時刻ビュー(群像劇)、事象の光。
5. 予測の確からしさ(結晶が知る情報に基づく推定)、結晶の移設、音。

## 8. リスクと反論、他案との組み合わせ方

### リスクと反論

| 反論 | 応答 |
| --- | --- |
| 「射撃ゲームなのに管制卓なんて地味」 | 卓は **戦闘の入口** と割り切る。直接操縦は現行の戦闘ビューがそのまま担う。卓は戦闘の前後を面白くする |
| 「遅延は面倒なだけ」 | 遅延は **ETA を送る前に必ず見せる**。条件付き指令が効く場面を序盤から作り、「前もって備える快感」を最初に与える。設定で OFF(実 c)にできる |
| 「情報過多」 | 初期は **レーン1本・注意点1つ** から。アラームの種別は絞れる。**モックの自己評価でも視認性は 3 点**(次節)。月周辺の記号の重なりは課題 |
| 「船が1隻の序盤に意味が薄い」 | 序盤は **1隻でも「時間軸+自動停止」の価値** がある(第一歩)。並列の価値は2隻目から立ち上がる |
| 「予測が当たらないと信頼を失う」 | 予測を破線・薄塗りで描き、**確からしさの帯**(第5段)を持たせる。当たらないことを遊びに変える |
| 「戦闘に入ると他が止まるのは不自然」 | 世界の時計を戦闘に預けている、と **画面で明示**(時計表示が ×60 になる)。作者の悩みの一つの正当化になる |

### 他案との組み合わせ方(踏み込みすぎず)

- **案01 シームレスズーム**: スイムレーンは時間軸、ズームは空間軸。**直交する**ので同居する。
  タイルを押すと、そのままその船へズームイン → 戦闘ビュー、という導線が自然。
- **案02 相対運動計器**: 直接操縦へ入った後の計器として。卓は計器を持たず、計器は卓を持たない。
- **案03 意図ベース指揮**: 条件付き指令は意図の最小形。意図の文法を増やせば、この案の指令コンポーザがそのまま意図エディタになる。
- **案04 世界観ダイエジェティック**: 卓を結晶の視点の計器盤として描く。**遅延像=結晶が実際に受け取る光学像** という整合が取れる。
- **案05(本案)×状況適応 HUD**: 卓の情報量を状況で絞る(平時は2〜3行、交戦前は拡大)。視認性の弱点をここで補う。
- **案07 分子模型建造**: 建造にも時間がかかる。建造・生産のレーンを同じ時間軸に足すと、農場経営まで同じ卓で扱える。

## 9. 5軸での自己評価(甘くしない)

評価軸は **直感性・一般性・美学的美しさ・視認性・一貫性**(各5点満点)。

| 軸 | 点 | 根拠 |
| --- | --- | --- |
| **直感性** | **3** | 「横軸=時間」「斜線=光」は一度覚えれば直感的だが、**光円錐の帯**(再生ヘッドの左右の帯)は説明なしでは読めない。ガント表は多くの人に馴染みがあるのが救い。遅延そのものが初見には異物で、ETA プレビューの文言に助けられている |
| **一般性** | **4** | 時間軸は **ゲームの全局面**(航海・建造・生産・脅威の周期)に使える。LEO 戦から農場経営まで同じ卓で扱える。弱点は、単発の遭遇戦・直接操縦中心の局面では卓の価値が薄いこと |
| **美学的美しさ** | **3** | 斜めの光線と、地図に広がる琥珀の波面は美しい。一方、モックは **月周辺の記号とラベルが重なり**、全体は「計器卓として整っている」止まりで、詩的な美しさまでは届いていない。地図の余白が大きく、画面が「密と疎」に分かれている |
| **視認性** | **3** | 色の意味は固定でき、「次に注意が要る」リストは強い。ただし **情報密度が高く**、下段のレーンに斜線・帯・バー・目盛が重なると、初見は読み取りが重い。小さい画面(1280×720)ではコンポーザが縦に潰れる |
| **一貫性** | **4** | 色(琥珀=出る光、シアン=届く光、白青=事象)と形(斜線=光、帯=不確かさ)を、地図・タイムライン・タイル・ログの全てで貫けた。弱点は、**直接操縦(戦闘スタブ)** の描画語彙が卓と別になっていること |

**総評**: 概念の一貫性と一般性は強いが、**初見の直感と画面の密度**が課題。第一歩(自動停止+注意点リスト)から入れて、
光円錐の帯は **チュートリアルで一度だけ説明する** のが現実的。

## 10. 参考(実在のもののみ)

- **NASA ミッションコントロール(ヒューストン)**: フライトディレクターが各担当へ GO/NO-GO を問う運用。
  コンソールは担当ごとに時間軸と警報を持つ。**ここで言う「卓」は、この役割の最小形。**
- **深宇宙探査の運用(片道光時間)**: 火星ローバー等は **1日分のコマンド列を事前にまとめて送り、ローバーが自律的に実行する**。
  条件付き指令の発想はこれと同型。
- **Kerbal Alarm Clock(KSP の MOD)**: マニューバーノード・SOI 変更などを指定して、時間加速を手前で止める。
  本案はこれを一級市民に格上げしたもの。
- **RemoteTech(KSP の MOD)**: 信号遅延と、事前に積んだコマンド(フライトコンピュータ)で動かす仕組みを持つ。
  遅延を遊びにした先行例。
- **KSP のマニューバーノード/時間ワープ**: 現行ゲームも踏襲している参照元。
- **Homeworld**: 戦術マップで艦隊を一覧し、3D の現場へ入る切替(**俯瞰と現場の往復**)。
- **FTL**: 一時停止して命令を出す運用。時間を止めて考える快感。
- **Highfleet**: マップ上で航路を引き、戦闘へ入る。**「航海」と「戦闘」の二層** の先行例。
- **Duskers**: 遠隔のドローンをコマンドで操作し、カメラ越しの限定された情報で判断する。
  **遅れて届く限定情報** という体験の近縁。
- **Minkowski の時空図**(特殊相対論の教科書): 光円錐を斜線で示す。
  **スイムレーンの斜線と帯** はこの図をガント形式に畳んだもの。
- **Tufte「small multiples」**: 現場タイル(同じ形式の小さな図を並べて比較する)の根拠。
- **ガントチャート**: スイムレーンの母型。
