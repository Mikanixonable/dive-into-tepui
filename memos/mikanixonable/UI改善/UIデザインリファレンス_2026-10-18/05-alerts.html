04警報の規則

警報は状態なので、出る条件と同じだけ「取り下げる条件」を持つ。条件が閾値の近くで揺れても灯が明滅しないように、入る閾値と戻る閾値を分ける(ヒステリシス)。

ヒステリシスの動き — 温度の例

  1. ① 910 K を越えて注意に入る。② 903 K へ戻っても、戻る閾値(800 K)を下回るまで注意のまま(灯は明滅しない)。③ 1,170 K 以上で警告へ昇格(未確認で点滅・音)。
  2. ④ 1,070 K を下回って警告から注意へ降格(音なし。確認済みなら確認済みのまま)。⑤ 800 K を下回って取り下げ(解除の通知を3秒)。この図は上の閾値表と同じ規則で描いている。

並べ方・確認・点滅・取り下げ

  1. 並べ方。レベル降順(警告 → 注意)、同じ段では発生が新しいものが上。同じ項目が警告へ昇格したら、注意の帯は消えて警告の帯1枚になる(1項目1枚)。帯は最大2枚で、溢れた分は「他に注意 n 件」へ畳む。灯の件数は畳んだ分も含めた集計。
  2. 確認(マスター確認 B)。全警報を確認済みにして、点滅と繰り返しの警報音を止める。帯は確認ボタンを外した静かな1行になり、行動の列は残す(条件がある間は「何をすればよいか」が要る)。確認は解除ではなく、新しい警告や昇格は再び未確認で出る。注意は確認しなくても8秒で帯が灯だけへ畳まれる。
  3. 点滅を止める条件。未確認の WARNING 灯だけが点滅する(1Hz、steps(1))。確認・条件の解消・降格のいずれかで止まる。帯は点滅しない(点滅する要素は画面に1つ)。注意は点滅しない。
  4. reduced-motion。点滅しない。未確認の警告灯は塗りつぶしの赤、確認済みは淡い面+縁で分かれるので、動きなしでも未確認と確認済みが区別できる。音は視覚の設定と無関係に維持する。上の「動きを減らす設定で見る」で確かめられる。
  5. 取り下げ。戻る閾値を下回り、最短保持(3秒)が過ぎたら、灯・帯・行の色が同時に消える。警告から戻った項目だけ「✓ … 警報を解除」の通知を3秒出す。喪失(結果画面)に至った瞬間は全警報を消し、結果画面が引き取る。
  6. 1つの判定。判定は「物理量 → レベル」の純関数1つに寄せ、灯・帯・行・メーターの目盛り・警報音がその結果を読む。警報の状態は導出なので保存しない(ロード直後は確認済みで再開し、音を鳴らさない)。
  7. 警報にしないもの。被弾そのもの(音と閃光)・操作の拒否・状態切替の確認・時間加速・NODE WARP の残り。これらは出来事か状態表示であって、対処を促すものではない。

警報灯は SPEC に無い新しい要素。画面から見える挙動が変わるので、実装の前に /modify-feature で SPEC を更新し、docs(spec): の単独 commit にする(CLAUDE.md の運用規則)。

書き足す先書くこと
DEVELOP/SPEC/UI-DESIGN.md §8「通知」「トースト2種」の記述を、5層(警報灯・警報帯・通知・案内チップ・行内状態)とブリーフィングへ書き換える。状態は条件で消え、出来事は時間で消えるという振り分けの規則、警報帯の最大枚数と並び、確認、点滅、reduced-motion。
DEVELOP/SPEC/UI-DESIGN.md §8「常設バッジ・スケール」全体ステータスバー警報灯(CAUTION/WARNING の2灯・件数・点滅の条件)をバーの構成要素として足す。表示専用で、§3 の「11種に閉じる」ウィジェットの集合は増えない。
DEVELOP/SPEC/UI-DESIGN.md §2 色 / §5 置き場注意色・警告色を2段の意味色として明記(現行は警告色1色)。通知・警報帯・案内チップは④画面固定バッジに属する(置き場は増えない)。
DEVELOP/SPEC/FLIGHT.md 「危険域」(温度70%・動圧50%)1段の「赤色」と「警告ヒントと警告音」を、注意/警告の2段・ヒステリシス・確認の規則へ。現行の記述(警告ヒントと警告音)に対応する出来事が src/ に見当たらないので、SPEC が先行している状態を実装で埋める。
DEVELOP/SPEC/CONTROLS.md 「ゲーム進行」マスター確認キー(B)を足す。タッチは帯の確認ボタン。
DEVELOP/SPEC/AUDIO.md警報音を、注意(1回)・警告(確認まで繰り返し)へ。現行は altAlarm が高度のしきい値ごとの一度きり。
DEVELOP/SPEC/GAME.md §2.1・§9.4変更不要。「喪失理由はヒントとして通知される」(§9.4)は通知(拒否型)と読み替えられる。結果画面があるステージでは結果画面が理由を示す。

08改修の手順

  1. 判定を1か所へ寄せる(見た目は変えない)。閾値表を持つ alarm-evaluator.ts を作り、orbit-panel.ts・vessel-panel.ts・status-panel.ts が直書きしている 0.7/0.5/0.2/0.3 をそこから読ませる。まず1段のまま、満タンの弾薬が赤くなる誤りだけ直る。
  2. 行内状態を2段にする。.ix-v.is-caution/.is-warning と .ix-gauge の2本目の目盛りを入れ、ui-danger を置き換える(01 の規則そのもの)。
  3. 通知を層に分ける。HintKind の warn を拒否型へ改め、高度などの状態の警告を Notifier から外す。通知を下部中央へ移し、案内チップ(PLN の4段階)とブリーフィングのカードを作る。
  4. 警報帯と灯を入れる。hud-alert.ts と TopBar の灯、最大2枚・並び・「他に n 件」。まだ確認は無く、注意・警告の帯が出る・消えるところまで。
  5. 確認・点滅・音・解消の通知。キー B、未確認だけ点滅、reduced-motion、alarmRaised/Escalated/Cleared の出来事から警報音を鳴らす。最後に PROX の判定(非ターゲットの最接近)を足す。
  6. SPEC を先に更新する。手順3以降は画面から見える挙動が変わるので、その前に07の表のとおり SPEC を更新して docs(spec): の単独 commit にする。
