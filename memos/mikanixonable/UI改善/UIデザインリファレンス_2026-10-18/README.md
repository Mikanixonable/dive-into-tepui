# UI デザインリファレンス(2026-10-18)

ゲーム UI の改修に使うためのデザインリファレンス。**現行の画面を撮影したものを出発点に、ゼロベースで設計し直した
改修後の姿**を、ゲームと同じトークン・同じウィジェットの CSS で組んだ HTML で示す。各ページは「現行」「改修案」
「比較(ワイプ)」を切り替えられ、注記がそのまま実装の指示(どのファイルの何を変えるか、どの SPEC の節に影響するか)になっている。

入口は [`index.html`](index.html)。ブラウザでファイルを開くだけで見られる(`node_modules` があれば書体も HackGen で出る)。

## 2. 現行 UI の監査(撮影した画面から確かめた事実)

1. **主役色の過負荷** — 既定配色の主役色が、セクション記号・ON 表示・主要ボタン・メーターの塗り・選択中のタブ・
   レールの開閉・HLP バッジを兼ね、しかも警告色とほぼ同色(RGB 距離 31)。満タンの燃料と 40/40 の弾薬が危険と同じ赤で出る。
2. **値の切れと折返し** — 右レールで艦ステータスの値が右端で切れ、ターゲットの「装甲」が縦に折れる。
3. **ショートカット表記が4通り** — `<kbd>P</kbd>`、`1–4`、ラベル内の `[7]`、ボタン内の `[F]`。
4. **状態の表し方が3通り** — 文字色の On/Off、トグルスイッチ、点灯ボタン。
5. **上部の全体ステータスが重い** — 820×100px の2行に、見出しばかりが並ぶ。
6. **中央の衝突と、撃つ判断の遠さ** — 自機の周りで弾薬・PROGRADE・×3 の文字が重なる。距離・接近速度は右レールにある。
7. **艦ステータスの責務過多** — 計器・モード・弾薬・展開部品・タッチ用推力段・操作ボタンが1枚に同居。
8. **マップの下部タイムラインが巨大** — 960×280px。期間ピル2段に対し、時間を掴む操作は細いスライダー1本。
9. **案内が文章の帯** — 計画モードの案内が長文で中央上部を塞ぐ。
10. **スマホ横持ちで崩れる** — 上部ステータスと HLP が重なり、値が「…」で切れ、案内帯が物体一覧に重なる。

## 3. 改修の原則

1. **色は意味で引く。** 中立=データ / 主役色=自分(自機・自分の選択・自分が掛けているモード) / 第二色=ターゲット /
   注意(amber+△)・警告(red+▲)。正常値は色を持たない。
2. **1行の文法。** `[ラベル] [メーター] [値 単位] [キー]`。値は切らない・折り返さない。縮むのはメーター → ラベルの順。
3. **状態は形で、キーは1種で。** ON/OFF は状態ピップかトグル。ショートカットはキーキャップ1種。
4. **強弱は3段。** 主読み値(パネルの答え)/行/補足。
5. **周辺は静かに、撃つ判断は照準の近くへ。**
6. **警報は1箇所。** 上部の警報灯と中央上部の警報帯だけ。案内はキーと語の短いチップ。
7. **既存の基盤は変えない。** Tepui Glass(ガラス面3段)・ウィジェット11種・置き場4種・ブレークポイントはそのまま。
   新しい色の値を1つも増やさず、既存トークンへの「意味の別名」だけを足す。

## 4. 土台(foundation/)

| ファイル | 中身 | 由来 |
| --- | --- | --- |
| `build.mjs` | 下の3つを書き出すスクリプト | — |
| `themes.js` | 配色プリセット11種の CSS 変数 | `src/theme.ts` の `themeCssVariables()` の出力そのもの |
| `tepui-base.css` | ガラス面・状態・ウィジェット11種・レイアウト寸法 | `src/hud/style/common-ui-style.ts` が注入する CSS と `src/game/hud/style/layout-tokens.ts` |
| `current/` | 現行画面のスクリーンショットと部品の切り抜き | `docs/` のビルドをヘッドレス Chrome で撮影 |
| `ref.css` | 改修案の部品 `.ix-*`(と、リファレンスの外枠 `.rf-*`) | 手書き。値は既存トークンだけから導く |
| `ref.js` | 現行/改修案/比較の切替・注記ピン・配色切替・背景 | 手書き。ゲームへは移さない |

ソースが変わったら作り直せる:

```sh
node memos/mikanixonable/UI改善/UIデザインリファレンス_2026-10-18/foundation/build.mjs            # トークンと共通 CSS
npm run build && node memos/mikanixonable/UI改善/UIデザインリファレンス_2026-10-18/foundation/build.mjs --capture  # + 現行画面の撮影
```

`themes.js` と `tepui-base.css` は実ソースから書き出しているので、トークンを変えると改修案の見た目も追従する。
`ref.css` の `.ix-*` は、ゲームへ移すときに `src/` のスタイルモジュールへほぼそのまま写せる形で書いてある(移し先は 01 の §07)。

## 5. 改修の順序

小さく入れられて効果の大きい順。どの段も単独で入れられる。

1. **トークンに意味の別名を足し、セクション記号とメーターを中立へ**(01 §01・§04)— 見た目の変化が最も大きく、
   コードの変更は `src/theme.ts` と `widget-style.ts` に収まる。既定プリセットの衝突もここで解く。
2. **行の文法とキーキャップ**(01 §02・§03、04)— `combat-panel-rows-style.ts` の `.row.metric` を grid に変え、
   ラベル内の `[7]` 書きをキーキャップへ。値の切れ(監査2)が消える。
3. **艦ステータスを責務で分ける**(04)— パネル構成の変更なので、SPEC UI-DESIGN §8 の更新が先に要る。
4. **上部ストリップと警報灯**(02・05)— 全体ステータスバーの作り直し。SPEC §8 の更新が要る。
5. **照準まわりの読み値と武装の帯**(02)。
6. **マップの時間軸**(03)— 挙動が変わるので SPEC MAP / PLAN の更新が要る。
7. **ウィンドウ・モーダル、スマホ横持ち**(06・07)。

画面から見える挙動を変える段(3〜7)は、`/modify-feature` の手順で SPEC を先に更新してから実装する。

## 6. 決めていないこと

リファレンスでは片方の案で描いたが、採るかどうかは決めていないもの。

| 論点 | リファレンスの案 | 該当 |
| --- | --- | --- |
| 既定の配色プリセット | 既定の Arcade Pulse は主役色と警告色が衝突している(RGB 距離 31)。プリセットを替えるか、既定の主役色を動かす | 01 §01 の検査表 |
| 提案トークンの名前 | リファレンスでは `--ix-*`。ゲームへ入れるときの名前(`--role-own` など)は未定 | 01 §07 |
| 警報の閾値 | 入る/戻るの2値(ヒステリシス)を提案。既存値は「注意に入る」へ温存し、戻る値と警告側は新設 | 05 §04 |
| 警報の確認キー | `B`(`C` は進行方向ホールドと衝突するため) | 05 |
| 距離・接近速度の二重表示 | 照準の脇とターゲットパネルの両方に出す。ターゲットパネルから外す選択もある | 02 |
| 艦のステータスに動圧・船体温度を置くか | 置いた(操縦中に推力と並べて見たいため)。SPEC §8 では環境の危険は軌道パネルの問いで、二重になる | 04 注記 11 |
| 戦闘中の時間加速の段 | ×1・×4 だけを押せる段にし、残りは ▾ に入れる | 02 |
| マップの表示範囲 | 期間ピルの常時表示をやめ、時間軸の両端の掴み手から開く。PLAN §9 の更新が要る | 03 |
| 時間軸のトラック | スライダーの派生として足す。ウィジェット11種の閉じた集合に触れる(UI-DESIGN §3) | 03 |
| 物体一覧の分類 | ボタン列をプルダウンへ。MAP.md の更新が要る | 03 |
| 計画モードの案内 | 5秒で消える通知をやめ、モードの間だけ出し続けて最初のノードで消す。UI-DESIGN §8・PLAN §3 の更新が要る | 03・05 |
| スマホの計器シート | 置き場4種に新設せず、「レールが coarse かつ short のときに取る別の姿」とする。UI-DESIGN §5 に1文の追記が要る | 07 |
| タンパク質敵の機能部位の記号 | `▲/△/▽` を `◆/◇/×` へ(注意・警告の記号と衝突するため) | 04 |
| 破壊的な確認のフォーカス | 確定ボタンではなく取消へフォーカスを渡す | 06 |
| 「タイトル画面に戻る」 | 確認を挟むか(現行は直接戻る) | 06 |
| プロパティウィンドウの「キャンセル」項目 | ✕・ESC と重複するので廃止。SPEC §8 の `[Esc]` キャンセルの例示を更新する | 06 |

## 7. 作業中に見つかった現行の不具合

リファレンスを作る途中で、現行のコードや SPEC との食い違いとして見つかったもの。リファレンスとは独立に直せる。

- **弾薬が満タンでも赤い** — `src/game/hud/panels/vessel-panel.ts` の `ammo.mags < 4` が、開始直後(予備2連)から真になる。
- **タッチのパッドがセーフエリアを無視する** — `src/game/hud/touch-controls.ts` の3つの `@media` が `left: 6px; bottom: 6px` で上書きし、`--safe-*` を捨てている。
- **レールの開閉ボタンがタッチで 30px のまま** — `.rail-toggle` が coarse でも広がらない(UI-DESIGN §6 の 44px に反する)。
- **ESC メニューの項目が常に1列** — SPEC §8 は中間〜ワイド幅で2列。
- **ターゲット中の対象のプロパティウィンドウが主役色の面** — SPEC §4 は第二色。
- **危険域のヒントと警告音が見当たらない** — FLIGHT.md は温度 70%・動圧 50% で出すと書くが、`src/` には高度の `altitudeWarned` しか無い。
- **敵一覧の見出しの件数** — SPEC は「出撃数/撃破数」、実装は `remainingCount / totalCount`。
- **タッチで軌道計画を確定する操作と、ESC メニューを開く常設ボタンが見当たらない** — 案内は「[M] で確定」だが、タッチの M はビュー切替。
- **ブレークポイントの閾値が SPEC とコードで違う** — SPEC は 700 / 1100px、`src/hud/breakpoints.ts` は 760 / 1184px。
