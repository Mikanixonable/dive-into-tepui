## 0. この提案の要点

1. **先に焼き込みを間引いて予算を空ける。** 今は表示時刻が変わるたび(=毎フレーム)と、カメラが動いて cap の
   置き方が変わるたび(=低軌道では毎フレーム)に、天気の中間場 5 枚と雲場 1 枚を焼き直している。
   表示時刻の量子化キー 2 枚を補間する方式と cap の置き直しのヒステリシスで、等倍時の焼き込み回数を桁で減らす。
2. **低軌道の見た目を直す。** ディザの砂目、全球で同じ 6 km の粒(砂丘状の起伏)、光学的厚みによらず同じ白さ、
   高さ 15–16 km に固定された巻雲殻をやめる。代わりに、解像できる形は幾何の縁で、解像できない分は半透明で描く。
   雲の種類ごとの多尺度の細部と、光学的厚みから決まる反射率を使う。
3. **雲の一生を閉形式で持たせる(時間モデルは案 A を採用)。** 時空間の格子にハッシュで対流セルを置く。
   発生時刻と寿命から、塔の成長 → かなとこの展開 → 巻雲への変質と消散を、表示時刻の解析関数として出す。
   決定論と時刻ジャンプへの強さは今のまま保つ。
4. **組織化を上の階層に持たせる。** メソ対流系(数百 km・6–18 h)の段階が子セルの生まれ方を変え、
   点 → 列/群 → 層状域をもつ面へ移る。雲の種類は離散的な切替ではなく、連続した**形態の状態量**から
   描画の値を出して、シームレスに移る。
5. **低軌道で目を引く現象を足す**: 日周期(陸の午後の積乱雲)、夜側の雷光、オーバーシュートトップ、
   かなとこの風上側の鋭い縁と風下側の繊維、層積雲の開いた/閉じたセル、寒気の吹き出しの筋雲、カルマン渦列、
   船跡雲、山岳波、ジェット気流の横縞の巻雲。
6. **状態を持つ GPU シミュレーション(案 B)は、上層の氷だけに絞った任意の段(段 6)として残す。**
   案 A の残存巻雲・層状域が作り物に見えたときに限り着手する。

### 1.2 コードの事実(`c8636ae40`)

- **天気は表示時刻の閉じた関数。** `WeatherModel.weatherAt()`(`src/render/cloud/weather-model.ts`)が
  気圧 → 風 → 上昇流 → 湿度・対流を TSL で組む。雲の発生・成長・消散の**履歴は持たない。**
  対流は 48 km と 24 km のノイズを 2 位相移流で流したもの(`weather-transport.ts`)で、
  「生まれて消える」は模様が流れながら入れ替わることの副産物にすぎない。
- **雲場は 3 成分。** `CloudSample` = 被覆率 `coverage`、雲頂 `cloudTop`(0–15 km)、薄い雲の
  光学的厚み `translucent`(`cloud-field-sample.ts`)。RGBA8 の 1 枚に焼き、A は使っていない。
- **cap 解像度。** 視点中心の正射影 cap の 1 辺は 512 texel(`cloud-cap.ts`)。低軌道の texel は
  200 km で約 9.8 km、400 km で約 12.0 km、500 km で約 12.8 km になる(地平線角 + 雲頂 + 余白 5° の角半径から計算)。
- **不透明な雲は高さ場のレイマーチ**(`opaque-cloud-surface-renderer.ts`)。場の texel より細かい起伏は、
  6 km の勾配ノイズ 1 オクターブ(`CUMULUS_GRAIN_SIZE`)を全球で一律に足す。部分被覆は blue noise の
  ディザで G-buffer へ書く(`CloudShapeEvaluator.opaqueFraction`)。**反射率は定数 0.8**(`CLOUD_ALBEDO`)。
  → V1・V4・V5 の直接の原因。
- **半透明の雲は厚み 0 の殻 2 枚**(`pipeline/cloud-atmosphere-renderer.ts`)。巻雲の殻は高度 15–16 km に固定、
  τ の上限は 0.63(`condensation.ts` の `TRANSLUCENT_LIMIT`)。半透明の積雲の殻は 0–2 km に固定。
  → 光学的に厚いかなとこを上層に置けない。巻雲の高さが緯度でも雲種でも変わらない。
- **かなとこは台風の芯だけ**(`Cyclones.anvilAt`)。普通の積乱雲のかなとこ、残存巻雲、日周期は無い
  (`src/render/cloud/` に日周期の項が無い)。
- **焼き直しの条件**(`generated-cloud-field.ts` の `prepare`): 表示時刻・気候の世代・投影の版の
  どれかが変わると、気圧・気団・移流源 2 枚・対流活発度・雲場を全部焼く。cap は `aim()` の
  緯度・経度・半径が少しでも変われば版を進める(`field-projection.ts`)。
  → 低軌道では毎フレーム全部焼いている。
- **夜側の地表に都市の灯は無い**(`src/` に該当の実装が無い)。

### 1.3 v2 計画が取り消された経緯から引き出す教訓

v2 は、質量保存・相別質量・footprint 面積の会計・GOES/VIIRS 参照との数値照合を合格条件にした。
CPU 導出(約 245 ms)、局所タイル、GPU 読み戻しの一致検査まで積み上げたが、製品の絵に届く前に取り消された。
この提案では次を守る。

- **見た目を先に作り、render-lab の前後撮影で閉じる。** 物理量の収支を合格の門にしない。
- **GPU の閉形式だけで組む。** メインスレッドの CPU 導出、worker、局所タイルの供給系を作らない。
- **1 段ごとに絵が良くなる順に並べる。** 基盤だけで絵が変わらない段を長く続けない。
- 文献の数値は形と時間尺度の**当たり**に使い、最終値は目で合わせる(「調整値」と明記する)。

## 2. 目標(何が見えれば達成か)

低軌道(200–500 km)から見下ろしたとき、次が見える。

| # | 見えるもの |
| --- | --- |
| G1 | 雲の縁と内部に**ディザの砂目が無い**。積雲は 1–5 km の粒として白く抜け、縁は画素の幅で切れる。解像できない細かい雲は、周りを少し白ませる薄さとして見える |

| G3 | **厚い雲ほど白く、薄い雲ほど灰色で下地が透ける**。積乱雲とかなとこの芯がその空でいちばん明るい |

| G6 | **日周期**: 陸では朝は晴れて海岸に霧/層雲、昼前から積雲、午後に積乱雲、夕方以降はかなとこの残骸。海上の対流は明け方に強い。周回ごとに昼側の雲の表情が地方時で違う |

| G9 | 層積雲の甲板に、**開いた/閉じたセル、カルマン渦列、船跡雲**が見える。寒気の吹き出しには**筋雲**が現れ、風下で開いたセルへ移る |

## 3. 時間モデルの比較と採用

### 3.1 案 A — 閉形式の寿命関数(採用)

時空間に格子を切り、各格子点の各時間枠に決定論的なハッシュを取る。そこから、セルが生まれるか、発生時刻、寿命、
強さ、大きさを決める。表示時刻 t における段階 s = (t − 発生時刻) / 寿命 から、形と光学量を**解析的に**出す。
位置は発生後の経過時間ぶん風で運ぶ(下で詳述)。

- 決定論: 同じ表示時刻なら同じ雲になる。時刻ジャンプ・時間の後退・時間加速で履歴が崩れることがない。
- 地表・大気・影の 3 経路が、同じ関数を同じ t で読めば一致する。
- 置き場: `src/render/cloud/`(装置)で、表示時刻を入力とする純粋な TSL と純関数。
  ARCHITECTURE R1/R5 に収まる(捨てても同じものを作り直せる)。
- 弱点: 雲どうしの合体・拡散・外出流による新セルの誘発は、**近傍を探して合成する近似**になる。
  12 時間前に生まれたかなとこの残骸を出すには、過去の時間枠を遡って探す必要があり、その費用が要る
  (§5.3 で「若いセル」と「残骸」に分けて抑える)。

### 3.2 案 B — 状態を持つ GPU シミュレーション(段 6 に条件付きで残す)

液水と氷の雲水量をピンポンのテクスチャに持つ。風で半ラグランジュ移流し、凝結の源・蒸発/昇華/沈降の損失・
拡散を固定のシミュレーション時間刻みで進める。

- 長所: 広がり・合体・ぼやけ・600–1000 km の漂流(熱帯の巻雲系の典型、Luo & Rossow 2004)が自然に出る。
  履歴の効果(古い系の残骸が新しい系にかぶる)も出る。
- 短所:
  - **cap が視点と一緒に動くので、状態は全球格子に持つ必要がある。** 1024×512 の正距円筒で赤道 39 km と粗く、
    低軌道の細部には結局案 A の手続き的な細部が要る。
  - 時刻ジャンプ・時間の後退では履歴を失う。閉形式の平衡状態から再初期化して空回し(スピンアップ)する必要があり、
    その瞬間に絵が跳ぶ。
  - 極端な時間加速では 1 フレームあたりの刻み数が上限を超える。閉形式へ戻す分岐が要る。
  - **ARCHITECTURE との衝突**: 時間をかけて積み上がる値は R1/R5 ではモデル層か視点に置く。
    `render/` に置くなら「スピンアップで作り直せるキャッシュ」とみなす例外を書く必要がある。
  - SPEC「同じ表示時刻を再評価したときの決定性」を「同じ履歴なら同じ」へ弱める変更が要る
    (ユーザーは変更可と回答済み)。
- **不採用(今は)の理由**: 絵の大半(G1–G3, G6–G9)は案 B では良くならない。一方で、上の 3 つの構造変更と
  v2 と同種の「基盤だけが積み上がる」危険を負う。
- **着手する条件**: 段 3–4 の後、案 A の残存巻雲や層状の盾に「円盤の重ね合わせ」らしさが残り、
  パラメータ調整で消せないとき。そのときは**上層の氷だけ**を全球格子で持つ「上層氷の履歴層」とし、
  源は案 A の対流セルの放出量、それ以外(下層・塔・細部)は案 A のままにする(§5.6)。

### 3.3 案 C — 焼いた場を前フレームから移流して積む(不採用)

cap の雲場を前フレームの値から少しずつ移流・減衰させて積む方式。案 B と同じく履歴を持つうえ、
cap の置き直しで履歴が壊れる。視点に依存する履歴は 3 経路と時間の後退で破綻するので採らない。

## 4. 設計の骨格

```
  気候(AnnualClimateMap)
        │
  ① 総観場 WeatherModel(既存, 50–3000 km)  … 気圧・風(下層/中層/上層)・上昇流・湿度・活発度・帯・暖気・陸
        │   + 日周期の強制 D(x, t)(新規, 太陽方向から閉形式)
        ▼
  ② メソ対流系の母集団(新規, 格子 250 km・時間枠 6 h)… 系の段階 S、軸の向き、盾の広がり
        ▼
  ③ 対流セルの母集団(新規, 格子 25 km・時間枠 1 h)… 塔の段階 s、かなとこ、残骸
        ▼
  ④ 形態の状態量(新規)… 下層: 被覆 c・雲頂 H・雲底 B・セル性 κ・活力 ν / 上層: τu・高さ Hu・繊維性 φ・滑らかさ σ
        ▼
  焼いた場 A/B(cap, 512², RGBA16F)+ 塔の目録 C(cap, 512²)
        ▼
  ⑤ 画素ごとの細部(新規)… 種類別の多尺度ノイズ、塔とオーバーシュートの形、縁の幾何、足りない分を半透明へ
        ▼
  不透明な雲頂(G-buffer) / 大気内の殻(半透明の下層・上層) / 雲影   ← 3 経路とも同じ ④⑤ を読む
```

`cloud2.md` の 3 階層(総観 / 雲の母集団 / 格子以下の形)をそのまま受け継ぐ。違いは 3 点ある。
母集団をメソ対流系と対流セルの 2 段に割ること。雲種を離散的な「regime」ではなく連続の状態量で持つこと。
塔を焼かず画素ごとに評価することで、cap の texel(10–13 km)より細かい 2–10 km の塔を出すこと。

## 5. 段ごとの提案

段の順序は「予算を空ける → 見た目 → 一生 → 組織化 → 特徴的な現象 → 条件付きの履歴層」。
各段の終わりで render-lab の前後撮影を比べて閉じる(§9)。

### 段 0. 計測と既存の不具合

- **計測**: デバッグ情報ウィンドウの `GPU_PASS.cloudBake / cloudSurface / cloudAtmosphere / cloudShadow` を、
  render-lab の `earth-low-orbit`・`earth-nadir`・`earth-oblique` と、ゲーム内の等倍・低軌道(400 km)で
  中/高プリセットごとに記録する。これが G10 の基準になる。v2 の記録にある「生成 42.78 ms / 実写 24.63 ms」は
  headless 計測で揺れが大きい(雲なしの基準で 39–79 ms)ので、基準に使わず測り直す。
- **赤道の継ぎ目(V3)の原因を突き止めて直す。** 候補は 3 つ。
  - `Circulation` の帯の境目(帯の中心は 75°, 45°, 15°, …で、0° が境目)
  - `balancedWind` の赤道付近の分岐
  - 2 位相移流の逆追跡が赤道で風向きの反転をまたぐこと

  `cloud-lab` の各中間場(`surfaceHumidity`・`convection`・`upperHumidity` 相当)を赤道付近で見て、
  継ぎ目が最初に現れる場から辿る。
- before の撮影を 2 組撮る(`cloud-before-1`, `cloud-before-2`)。

### 段 1. 焼き込みを間引いて予算を空ける

**1a. 表示時刻の量子化キーを補間する。**

- 焼く時刻を連続の t ではなく、キー時刻 tₖ = k·ΔT(ΔT は下で決める)にする。tₖ と tₖ₊₁ の 2 枚を持ち、
  表示には w = (t − tₖ)/ΔT で補間した値を使う。**表示は t の連続関数のまま**で、同じ t なら同じ絵になる。
  `done/cloud-temporal-lod-removal-plan_2026-09-21.md` で撤去した時間 LOD とは別物である。
  あちらは目標時刻へ丸めてそのまま表示し、実時間あたりの焼き回数に上限を置いていた。
  こちらは丸めず補間し、焼き回数に上限を置かない。
- ΔT は「キーの間に雲が動く距離が texel の半分を超えない」長さにする:
  ΔT = 0.5 × texel 長 / 50 m/s(上層ジェット級の最大風速)。texel 12 km(高度 400 km)なら ΔT = 120 s。
  - 等倍: 120 秒に 1 回の焼き込み(今は毎秒 60 回)
  - 100 倍: 1 秒に 1 回
  - 1 万倍以上: 毎フレーム(今と同じで、それより悪くならない)
- キーの間で動くのは最大 6 km。補間による二重像は texel(12 km)の中に収まって見えない。
  塔(③)は段階を画素ごとに解析で出すので、キーの間でも連続して育つ。

**1b. cap の置き直しにヒステリシスを入れる。**

- 視点の直下点が cap の中心から**角距離 2°** 離れるか、要る半径が今の半径から 5% 外れたときだけ `aim()` する。
  中心がずれる分、`CLOUD_CAP_MARGIN` を 5° から 7° へ広げる(風上を読む余白 5° を食わないため。texel は約 6% 粗くなる)。
  400 km・7.7 km/s では約 30 秒に 1 回になる。
  R5-5「表示を安定させるための前フレームの記憶(ヒステリシス)」に当たる。
- 置き直しの瞬間に 2 キーぶんを焼き直す負荷のとがりは、**cap の二重化**で均す。新しい cap を裏で数フレームかけて
  焼き、揃ったら切り替える。切り替えまでは古い cap を読み続ける(余白の内側なので破綻しない)。
- 見込み: 等倍・低軌道の天気の焼き込みが、毎フレームから数十秒に数回になる。空いた予算は段 3–4 の重い焼き込みに回す。

**1c. 周期の違う場を分ける。**
気圧・気団は数時間の尺度なので、キー間隔を 1a の ΔT ではなく 15 分の固定にして、さらに間引いてよい。
移流と雲場は 1a の ΔT に従う。

### 段 2. 低軌道の見た目

**2a. ディザをやめ、「解像できる形は幾何、解像できない分は半透明」に分ける(V1 → G1)。**

- 不透明な殻は、被覆率を**画素ごとの細部ノイズのしきい値**で切った形として描く(Nubis 流の侵食)。
  縁は画素の幅で切れ、最終段の SMAA/FXAA で均される。G-buffer に部分被覆を書かないので、
  ディザの砂目が消える。
- 細部ノイズの振幅は画素の足跡(`dFdx`/`dFdy`)で弱める。今の `grainAmplitudeForWidth` と同じく、
  2–4 画素で 0 へ渡す。振幅が落ちた分だけ不透明な形の平均被覆が本来の被覆率 c とずれるので、
  **差 c − E[不透明の割合] を下層の半透明の殻が受け持つ**。E[·] はノイズの分布(ほぼ正規)に対する
  smoothstep の期待値で、閉形式で出す。
  - 遠くでは半透明が多く、近くでは不透明が多くなり、**平均の明るさは距離によらず保たれる**
    (SPEC「どの距離からでも破綻しない」)。
- 半透明の積雲の殻の高さを、0–2 km 固定から「雲底 B から雲頂 H」へ変える。
- 不採用: ディザを残して時間方向に積む(TAA)。パイプラインに時間積分が無く、全描画へ影響が広すぎる。
- 不採用: 雲だけ前方合成で描く。不透明な雲頂が G-buffer にあることで、深度・法線・影・大気の手前関係が
  1 つの規約に揃っている。それを捨てる理由にならない。

**2b. 種類別の多尺度の細部(V2・V4 → G2)。**
一律の 6 km 勾配ノイズ 1 オクターブをやめ、形態の状態量(§6)から次を連続に混ぜる。

| 状態 | 細部 |
| --- | --- |
| 積雲(κ 高、ν 高) | Worley F1 の反転(もこもこ)を 3 オクターブ(約 4 / 1.5 / 0.5 km)。活力 ν が高いほど縁が硬く、泡が細かい |
| 層積雲(κ 中) | 10–40 km のセル(閉: セルが雲・境が暗い割れ目、開: セルの縁が雲の輪)+ 1 km の毛羽 |
| 層雲・乱層雲(κ 低) | 起伏 100–300 m の緩いうねりだけ。縁は数 km かけて薄れる |
| かなとこ(σ 高) | 平らな天蓋。風上側の縁は 1–2 km で鋭く切れ、風下側は繊維(上層風に沿って引き伸ばした異方ノイズ)。天蓋の上に弱い重力波の縞(波長 5–15 km、調整値) |
| 巻雲(φ 高) | 上層風の向きに 10:1 程度引き伸ばした繊維。τ が小さいほど繊維が細く途切れる |

- 画素ごとの評価はレイマーチの標本ごとに走るので、オクターブ数は品質設定の段で変える(§7)。

**2c. 光学的厚みから反射率を出す(V5 → G3)。**

- 定数 0.8 をやめ、二流近似(保存散乱)R(τ) = 3(1−g)τ / (4 + 3(1−g)τ)、g = 0.85 を使う
  (τ 5 → 0.36、τ 20 → 0.69、τ 80 → 0.90)。
- τ は状態量から出す: 積雲 5–20、層積雲 5–15、層雲 10–30、乱層雲 30–80、積乱雲 80–150、
  かなとこの芯 20–40 から縁へ減衰、巻雲 0.03–3。
- **τ < 3 の雲は不透明の殻に載せず、全部を 2a の半透明の殻へ回す**(下地が透けるのはこの分)。
  不透明の殻は τ ≥ 3 の雲の反射率を R(τ) で変える(τ 3 で 0.26 の灰色から、τ 100 で 0.92 の白まで)。
- 塔の谷に遮蔽の近似(高さ場の曲率から出す AO、調整値)を入れ、塔が立体に読めるようにする。

**2d. 上層を「高さと厚みを持つ層」へ変える。**

- 巻雲の殻の高度を固定の 15–16 km から、場の上層高さ Hu へ変える。Hu は圏界面(既存 `tropopauseAt`)から
  1–3 km 下を基準に、かなとこは圏界面、古い巻雲ほど下がる(Luo & Rossow 2004「薄れながら下の高度へ移る」)。
- τu の上限 0.63 を外し、かなとこの芯で 20–40 まで持てるようにする。τu が大きい所は 2c の R(τ) で白くなり、
  下の雲を隠す。
- 雲影(`CloudShadowRenderer`)に上層の透過 exp(−τu × 空気量)を掛け、**かなとこが下層雲と地表へ影を落とす**ようにする。
- 地平線の雲頂: 大気内の殻が Hu を読むので、かなとこと圏界面まで立つ塔の高さが縁のシルエットに出る(G7)。

### 段 3. 雲の一生(対流セル)

**3a. セルの母集団。**

- 格子: 球面上のジッタ付き格子(cube-sphere の面座標の 2D 格子)、間隔 L = 25 km(高度 400 km の texel の約 2 倍。
  1–5 km の浅い積雲の粒はセルにせず 2b の細部が受け持つ)。時間枠 T = 1 h。
  格子点 × 時間枠ごとにハッシュ h を取る。
- 発生確率 p = 基底 × 活発度(既存 `convectiveActivity`)× 湿り(既存 `surfaceHumidity` の立ち上がり)×
  上昇流の門(既存 `lift`)× 日周期 D(x, t) × 系の変調 M(②)。
  u₁ < p ならセルが生まれ、発生時刻 = 枠の頭 + u₂·T、寿命・強さ・半径は u₃… から対数正規で振る。
- **位置**: 評価点 x から、枠の中心時刻まで**中層の操舵風**で逆追跡した点 x′ の周りの 3×3 の格子点を探す。
  逆追跡は既存 `windStep` と同じ弦近似を使う。操舵風は下層風と上層風の混合として `WeatherModel` に口を足す。
- 塔の段階 s = (t − 発生)/寿命。普通のセルの段階は Byers & Braham(1949)の 3 段を当たりにする。
  - 積雲期: 0–0.25(10–15 分)。雲頂が雲底から上へ伸び、半径は 1 km → 本来の半径へ。
  - 成熟期: 0.25–0.6(15–30 分)。雲頂が釣り合いの高さ(強いセルは圏界面)に達し、頂部が凍り始める(g ↑)。
    強いセルには**オーバーシュートトップ**を載せる: 天蓋から 1–2 km 突き出た直径 ≤ 15 km のドーム、
    寿命は平均約 8.5 分・最長 30 分。
  - 消散期: 0.6–1。塔が沈み、もこもこが滑らかな繊維へ(ν ↓, g → 1)。
  - 寿命: 普通のセル 30–60 分、強いセル(スーパーセル相当、まれ)1–4 h。
- 形の関数は s = 0 と s = 1 で 0 から/0 へ連続に渡し、**セルが突然現れたり消えたりしない。**

**3b. かなとこと残骸(塔 → かなとこ → 巻雲 → 消散)。**

- 成熟期から、雲頂の高さでかなとこが広がる。
  - 半径: r(τₐ) = r₀ + v·τₐ^0.75。τₐ は成熟からの経過時間。v と指数は重力流の当たりの調整値。
  - 中心: 塔から (上層風 − 操舵風) × τₐ だけ風下へずれる。風上側は鋭く、風下側は繊維(2b)。
- 塔が消えた後、かなとこは次のように変わる。
  - τu は exp(−(t − 塔の終わり)/T_d) で薄れる。T_d = 3–6 h。熱帯では深い対流の減衰に 6–12 h、
    巻雲系全体は 19–30 h(Luo & Rossow 2004)。
  - 繊維性 φ が 0 → 1、滑らかさ σ が 1 → 0 へ移る。
  - 高さ Hu が 1–2 km 下がる。
  - 縁の幅が広がる(ぼやける)。
  - τu が 0.03 を切ったら消える。
- 費用を抑えるため、**若いセル(0–3 h)と残骸(3–12 h)を分けて焼く。**
  - 若いセル: 3 枠 × 9 点 = 27 探索/texel を cap の全解像度で。
  - 残骸: 9 枠 × 9 点 = 81 探索/texel を半解像度(256²)で。残骸は数十 km 以上に広がった滑らかな形なので、半解像度(texel 約 24 km)で足りる。
  - どちらも段 1 のキー時刻でだけ焼く。
- 12 h より古いものと、対流と無関係にその場でできる巻雲(熱帯の巻雲の半分以上、Luo & Rossow 2004)は、
  既存の `upperHumidity` 由来の薄い雲が受け持つ。

**3c. 塔は焼かず、目録として焼いて画素で描く。**

- 塔(2–10 km)は texel(10–13 km)より細かいので、場へ焼くと潰れる。代わりに cap の各 texel に
  「その texel に最も影響する塔」を 1 つ書いた**塔の目録 C** を焼く。
  - 中身: texel 内の位置、半径、発生時刻(キー時刻からの差)、寿命、強さ、ドリフト速度
    (RGBA16F 2 枚。格子間隔 25 km ≈ texel の 2 倍なので、1 texel に 1 塔でほぼ足りる)。
- 画素ごとには周りの 3×3 texel の目録を読み、塔の形(段階 s から高さ・半径・もこもこ)を解析で出して、
  場の雲頂へ max で合成する。位置は「目録の位置 + ドリフト × (t − キー時刻)」で毎フレーム動く。
- 3 経路(不透明の殻・大気内の殻・雲影)は、同じ `CloudShapeEvaluator` の拡張を通して同じ目録を読む。

**3d. 日周期。**

- 各点の地方太陽時 h を、焼き込みに渡す太陽方向から出す(閉形式)。
- 陸: 発生確率に掛ける D(h) を 10 時に立ち上げ、15–17 時で最大(1.8 倍、調整値)、夜は 0.3。
  浅い積雲の被覆を 10–16 時で上げる。
- 海: 振幅を小さく(±20%)、最大を 4–6 時に置く。
  陸の午後最大・海の明け方最大は Yang & Slingo 2001 などの降水日周期の当たり。
- 明け方の海岸と盆地に層雲・霧の被覆を少し足し、10 時までに消す。
- 時間加速で日周期が明滅しないよう、1 フレームで進むシミュレーション時間が 1 h を超えたら、
  D を日平均へ連続に寄せる(SPEC「日周期も中間速度以上では平均化」)。

### 段 4. 組織化(点 → 列/群 → 面)と種類の連続遷移

**4a. メソ対流系の母集団。**

- 格子 250 km、時間枠 6 h、寿命 6–18 h(対数正規)。セルと同じハッシュと逆追跡の方式で置く。
- 発生確率 = 活発度 × 湿り × 系の源の重み。源の重みは次の場所で上がる。
  - 前線の帯(既存 `band`)
  - 海岸線の陸側で午後(海風の収束)
  - 風上斜面(既存 `climate.slope`)
  - 古い系の外出流の弧(4c)
- 段階 S = (t − 発生)/寿命 で、子セルの変調 M と層状の盾を変える。

| 系の段階 S | 子セルの生まれ方 M | 層状の盾 |
| --- | --- | --- |
| 0–0.2 発生 | 系の軸に沿った幅 10–30 km の**列**、または系の中心の半径 30 km の**群**に集中(どちらになるかは鉛直シアの強さで決める。強いと列) | 無し(個々のセルのかなとこだけ) |
| 0.2–0.5 発達 | 列が弧に曲がり、先端(操舵風の前方側)で密度が上がる | かなとこどうしが合わさり、軸の後方(シアの風上側)に幅 100–200 km の層状域が育つ |
| 0.5–0.8 成熟 | 先端の列だけに新しいセル | 盾が最大(面積で 10⁵ km² 級、Maddox 1980 の MCC の目安)。上層風で風下へ長円に伸びる |
| 0.8–1 衰退 | 新しいセルが止まる | 盾だけが残り、3b の残骸と同じ規則で薄れて巻雲になる |

- 層状の盾は系ごとの楕円の場として焼き、下層(乱層雲、H 4–8 km、κ 低)と上層(かなとこ、τu 10–30)の両方へ寄与する。
  列の後ろに層状域が続く配置は、先行する対流線と後方の層状域をもつスコールライン(Houze 1989)の当たり。
- **合体の近似**: 近いかなとこどうしは τu を足すのではなく soft-max(p ノルム、p ≈ 4)で合わせ、
  円盤の重なりに見えない連続した面にする。

**4b. 種類の連続遷移。**
雲種の名前で分岐せず、§6 の状態量(c, H, B, κ, ν, g, τu, Hu, φ, σ)の連続関数として描画の値を出す。
たとえば「積雲 → 雄大積雲 → 積乱雲 → かなとこ → 巻層雲 → 巻雲」は、塔の段階 s と残骸の経過時間から、
H ↑ → g ↑ → σ ↑・τu ↑ → φ ↑・τu ↓ と状態量が動くことで連続に移る。
層積雲の閉じたセル ⇄ 開いたセルは、κ と「雲の厚さ(=霧雨の出やすさ)」から連続に移る。

**4c. 外出流の弧(任意)。** 衰退期の系の周りに、半径が時間とともに広がる弧を置く
(半径 = 20 km + 5 m/s × 衰退からの経過時間、調整値)。その弧の上でセルと次の系の発生確率を上げる。
「古い系の縁から新しい列が立つ」が閉形式のまま出る。

### 段 5. 低軌道で目を引く現象

どれも独立しているので、承認された順に足せる。どれも形態の状態量か細部ノイズへの変調として入れ、新しい描画経路を作らない。

| 現象 | 入れ方 | 値の当たり(調整値) |
| --- | --- | --- |
| 雷光(G8) | 成熟期の塔ごとに 0.1 s の時間枠でハッシュを取り、閃光を決める。不透明の殻の自発光と、下層の殻の散乱光として、半径 10–20 km のガウスで雲を内側から照らす。1 閃光 0.2–0.5 s に 2–4 回の明滅。1 フレームで進むシミュレーション時間が 0.1 s を大きく超える時間加速では出さない | 全球 44 ± 5 閃光/秒、陸:海 ≈ 10:1(Christian et al. 2003)。セルあたり毎分 1–10 回、強いセルは更に多い |
| 層積雲の開/閉セルとポケット | 2b の層積雲のセルを、閉じた板の中に開いたセルの穴(POC)が数百 km の斑で混じる形にする | セル径 10–40 km |
| 寒気の吹き出しの筋雲 | 暖気が負(寒気)・海上・下層風が強い所で、下層風に沿うロール状の異方ノイズ。陸/氷縁からの吹走距離(既存の気団の逆追跡と同じ方式で陸を遡る)が延びるほど開いたセルへ移る | 筋の間隔 2–8 km、筋から開いたセルへ数百 km で移る |
| カルマン渦列 | 層積雲の甲板の中の、逆転層より高い島(島の表: グアダルーペ、カナリア、マデイラ、ヤンマイエン、フアン・フェルナンデス、カーボベルデ等)の風下に、島の座標系で閉形式の渦列(交互の渦をストローハル数 ≈ 0.2 の周期で放出し、風で流す)を置き、甲板の模様を渦の変位で歪める | 渦の間隔比 ≈ 0.28(フォン・カルマン)、要校正 |
| 船跡雲 | 主要航路の折れ線の上で、層積雲の甲板がある所に、幅約 10 km・長さ数百 km の τ 1.5–2 倍の線を、風で流される線分として置く | Twomey 効果による増光 |
| 山岳波雲 | 風上斜面の風下で、風に直交する縞を下層/中層の被覆へ掛ける | 波長 5–25 km |
| ジェット気流の横縞 | 上層風が速い所の巻雲に、流れに直交する縞を掛ける | 間隔 10–30 km、要校正 |

### 段 6(条件付き). 上層氷の履歴層(案 B の限定版)

§3.2 の条件を満たしたときだけ着手する。

- 全球正距円筒 1024×512 の上層氷量 1 枚。シミュレーション時間 10 分刻みで次を回す。
  - 移流: 上層風で半ラグランジュ
  - 源: 案 A の対流セル・系の放出量
  - 損失: exp(−Δt/T_d)
  - 拡散: 繊維性に応じる
- 時刻ジャンプ・後退・1 フレーム 100 刻み超では、閉形式(段 3 の残骸)から再初期化する。
  そのとき 1–2 秒かけて履歴層の寄与を閉形式へ寄せ、跳びを隠す。
- 着手時に要る変更:
  - SPEC の決定性の記述を「同じ履歴なら同じ。時刻ジャンプ後は履歴が満ちるまで閉形式の近似」へ変える
  - ARCHITECTURE の例外(スピンアップで作り直せるキャッシュとして `render/` に置く)を理由付きで書き、報告に挙げる

## 6. データの構成と置き場

### 6.1 焼いた場(cap 512²、キー 2 枚ずつ)

| 名前 | 形式 | 中身 |
| --- | --- | --- |
| 場 A(下層) | RGBA16F | c 被覆率、H 雲頂 [m]、κ セル性 0..1、ν 活力 0..1。雲底 B は湿りから閉形式で出す(持たない) |
| 場 B(上層) | RGBA16F | τu 上層の光学的厚み、Hu 上層の高さ [m]、φ 繊維性、σ 滑らかさ |
| 目録 C₀/C₁ | RGBA16F × 2 | 塔の位置(texel 内)・半径・発生時刻・寿命 / 強さ・ドリフト速度・オーバーシュートの有無 |
| 残骸 | RGBA16F(256²) | 3b の残骸の τu・Hu・φ・σ(場 B へ焼き込み時に合成してもよい) |

メモリ: 512² × 8 B × (A + B + C₀ + C₁) × 2 キー ≈ 16 MiB。cap を二重化すると 32 MiB。

**実写の分布**(`ObservedCloudField`)も同じ A/B を出す。κ・ν・φ・σ は既定値、τu は今の `translucent`、
Hu は圏界面の 2 km 下、目録 C は空にする。

### 6.2 モジュールの置き場(ARCHITECTURE に照らす)

すべて `src/render/cloud/`(装置)に置く。表示時刻と気候だけから決まる閉形式なので、R1/R5 に収まる。
装置どうしの import は `render/` の中で閉じる。

## 11. 規模とリスク

### 規模(相対)

| 段 | 規模 | 絵の変化 |
| --- | --- | --- |
| 0 | 小(計測、継ぎ目の原因調査と修正) | 継ぎ目が消える |
| 1 | 中(キー補間、cap のヒステリシスと二重化) | 変わらない(負荷だけ下がる) |
| 2 | 大(細部・分割・光学・上層) | **最大**。G1–G3, G7 の大半 |
| 3 | 大(格子・セル・残骸・目録・日周期) | G4, G6 |
| 4 | 中(系・盾・連続遷移) | G5 |
| 5 | 現象ごとに小〜中 | G8, G9 |
| 6 | 大(条件付き) | 残骸の自然さ |

### リスクと対策

- **格子が見える**: セルと系が格子の並びに見えるおそれ。ジッタに加えて発生確率の閾値で間引き、
  cube-sphere の面の境目でハッシュが連続になるよう面座標の変換を検査する。
- **探索の費用**: 残骸の遡り(81 探索/texel)が重い。半解像度、キー時刻でだけ焼く、品質段で遡る時間を縮める
  (低: 6 h)、の 3 つで抑える。
- **目録の取りこぼし**: 1 texel に塔が 2 つ入ると片方が消える。格子間隔を texel の約 2 倍(25 km)にし、
  精細の段では 5×5 を読む。
- **キー補間の二重像**: ΔT を texel と最大風速から決め、動く距離が texel の半分を超えないようにする。
- **cap 切り替えの一瞬**: 二重化した cap の切り替えで絵が跳ばないよう、両方の cap で同じ t・同じ閉形式を評価する
  (値は解像度差以内で一致する)。
- **3 経路の不一致**: すべて `CloudShapeEvaluator` の拡張を通し、各経路で独自に式を書かない。
- **v2 と同じ失敗**: 段 2 を段 3 より先に置き、1 段ごとに絵で閉じる。基盤だけの段は段 1 しかない。
