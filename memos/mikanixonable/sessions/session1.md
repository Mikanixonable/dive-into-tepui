# session1 — Devin メインセッションの課題と憲法

このファイルはこのセッション(Devin・SWE-2 High、メインセッション)の運営文書。
作業中と作業待ちの課題を書き、完了したものは削除(記録は LOOP-LOG・引き継ぎメモが担う)。

## ファイル名の規則

- 親セッションは `session<N>.md`(N は開始順の連番)。
- サブエージェントのセッションは `session<N><M>.md`(M は開始順のアルファベット小文字)。
  親が誰か分かるように、子ファイルの先頭にも親ファイル名を書く。
- 作業中と作業待ちだけを書き、完了したものは書かない。

## 憲法(このセッションの振る舞いの規則)

優先度は上から順。ユーザーからの直接の指示はすべてに優先し、衝突したら指示に従う。

### 目的

- 雲のリアリティーを上げる。手段は、物理的・気象学的に正しい、あるいはより代表的な
  教師の選定・データ加工・パラメーターとその重みづけによる評価設計を通した改善であって、
  見た目の印象をそのままコードへ写すことではない(ユーザーの明言)。

### 必須の振る舞い

- タスクがすべて完了するまで自走し、停止しない。区切りごとにこのファイルと
  引き継ぎメモを更新し、判断は事後に報告する。
- フィードバックループで進める。変更は 1 箇所ずつ、採否は実写対比の物差しで決め、
  各ステップを `LOOP-LOG-*.md` へ記録する。
- 責務の分離を守る。大規模構造(帯・晴れ間・低気圧・高気圧・前線)は雲量場/気象
  モデルの責務、細部の織り目は cirrus/cumulus detail evaluator の責務。
- 変更は worktree で行い、devin/dev への統合は検証(typecheck・対応するテスト・
  必要な計測)の通過後。worktree の削除は統合と commit が済んでから。
- `DEVELOP/SPEC/` が振る舞いの正本、`DEVELOP/CODING-RULE.md`・`DEVELOP/ARCHITECTURE.md` が
  書き方の正本。`docs(spec):` は src/ と混ぜない単独 commit。
- **サブエージェントは使わない**(ユーザーの禁止。2026-11-15 に変更。)
- サブエージェントを使わないので `session1s.md` は管理しない。

### 禁止の振る舞い

- 視覚的な違和感をそのまま定数へ写すアドホック修正。
- 採点器を甘くしてスコアを良く見せること、物差しを変えずに「改善」と言うこと。
- devin-run ワーカーの起動(ユーザーの禁止。レート枠を共有して停止した経緯がある)。
- autopilot の利用枠 `SLEEP` は表示された実行主体だけに適用すること。Devin Luna は必ず
  `npm run usage -- --runtime=devin-luna` で確認し、既定の Claude 判定や Claude の `SLEEP` では停止しない。
  (`~/.config/devin/AGENTS.md` にも永続化済み)。
- PR の状態を権威ある情報なしに発言すること。
- git config の変更・force push・確認なしの破壊的操作。
- `memos/` のうち、このセッションの管理範囲(`sessions/`・`handoff_2026-11-15.md`・
  自分が開いた LOOP-LOG 等)以外の書き換え。

## 実施中

- **陸上の雲量と海域別の光学厚を別機構で詰める** — 陸域と海域では低層湿度・
  雲型・tauMid の残差が異なるため、共通の湿度補正を使わない。`MASS_RETURN`
  0.026→0.010 の調整で land deep と temperate-sea tauMid が改善し、step 60 では
  陸面水分の代理 `landFraction × max(cloudinessBias, 0)^2 × 0.3` を加えた。
  この代理は乾燥地と海をほぼ変えず、全体 classes は 0.0657→0.0554。
  temperate-land humidLow は実写と同じ 0.483 になり、cloudFrac は 0.426→0.493
  (実写 0.732)。highlat-land は humidLow 0.480→0.532 (実写 0.632)、
  cloudFrac 0.553→0.701 (0.747) へ近づいた。一方、land の stratocumulus は
  temperate 0.140/実写 0.068、highlat 0.185/0.131 と過剰。
  海上は実質不変: temperate-sea stratocumulus 0.373/0.232・tauMid
  0.467/0.361 が過剰、highlat-sea stratocumulus 0.359/0.367 は一致するが
  tauMid 0.457/0.561 は不足。次は湿度を全球で上げず、陸上の雲型・tau 配分と
  海域別の層積雲の厚みを切り分ける。

## 待ち([]内は優先度)

- [A] **cloud-cells の環境依存** — 雲のリアリティーの観点: 実写では対流の
  細胞の規模・寿命が場所と条件で変わる(暖かい海上は大きく長持ち、陸上は
  小さく短い)。いま生成される粒は全球で同じ性質なので、細かさ・寿命の
  ばらつきが無く見た目が単調。設計 p-cells-env.md、best は step-1
  (index 0.559)。
- [B] **低気圧から遠い中緯度の雲域と台風の螺旋雨帯** — 雲のリアリティーの
  観点: 中緯度の海は低気圧の前線の合間でも海上層積雲で年中曇りがちだが、
  低気圧に依存しない海上層積雲がまだ少ない(temperate-sea cloud 0.790 vs
  実写 0.896)。台風も眼と天蓋はあるが螺旋状の雨帯が欠け、実写で目立つ構造が
  抜けている。band 廃止後はコンマの頭 + 寒気側域で雲量を部分回復し、最新の
  全体 classes は 0.0554。最新の全球場では cycloneFront は低気圧に付随し、
  圧力場から独立した長い帯は再発していない。残るのは雲域不足と雨帯の欠落で、
  それぞれ別機構で扱う。
- [A] **陸上の雲型・tau配分と海域別 tauMid** — 雲のリアリティーの観点:
  陸面水分の追加後、temperate-land の humidLow は実写に合ったが cloudFrac は
  0.493/0.732 と少なく stratocumulus は 0.140/0.068 と多い。highlat-land の
  cloudFrac は 0.701/0.747 まで近づいたが humidLow は 0.532/0.632、stratocumulus
  は 0.185/0.131。temperate-sea は stratocumulus・tauMid が過剰、
  highlat-sea は stratocumulus が一致する一方 tauMid が不足する。次は
  層・厚みの配分を調べ、湿度を全球一律に増やさない。
- [B] **巻雲の型振り分け** — 雲のリアリティーの観点: 実写の巻雲は環境で
  型が変わる(ジェットの筋 streak、波状の鱗 scaly、高気圧の面 veil)が、
  生成は気象条件と結びつかず均質な靄になりがち。CIRRUS_MAX_OPTICAL_DEPTH=3
  は維持する: 上限を上げる候補は step 47 で全て不採用、独立した
  `audit-cirrus-tau3` レポートも見つからなかった。clean audit の巻雲 τ 最大は
  2.02 (量最大 0.821) だが、τ上限だけを上げると検出域が広がり過剰になる。
  次は上限ではなく、雲量の空間配分と気象型との結びつきを改善する。
- [C] **sunset-refine の完遂** — 雲のリアリティーの観点: 夕方の大気の
  色(雲を染める光そのもの)が実写からずれていると、雲の生成が正しくても
  見た目が崩れる。test:render 3 件落ち(sun-transmittance 表の範囲外値・
  夕方の誤差 11%/許容 3%・薄明)。sunset-look ループの再開が必要。
- [C] **フィードバックループを回す** — ユーザー指定の待ちタスク。生成の
  再測→監査→評価の一周を継続して回す運用(tools/cloud-loop.sh で半自動化済み)。
