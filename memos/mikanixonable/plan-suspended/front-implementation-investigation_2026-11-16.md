「前線は低気圧に接続し、時間発展で寒冷前線が温暖前線に追いついて閉塞するのか」
「寒冷前線の両側で雲が進行方向へ非対称に分布するか」をコードから調べた記録。

## 1. 構造 — 前線は「低気圧の部品」ではなく「気団圧縮の診断量」

前線に相当する場 `band` は、低気圧の配置へ直接結び付いた実体ではなく、
気団追跡からの診断として毎フレーム作られる。

### 気団追跡（`src/render/earth-weather/air-mass.ts`）

- 各点から風上へ **36 h・6 刻み**遡る。追跡の風は `WindField.traceFlowAt` —
  気圧の渦成分（大循環の気圧帯の勾配は解析的に差し引く）の釣り合い風
  ＋大循環の平均風＋ロスビー波の摂動＋地形迂回。
- 焼くのは 3 チャンネル: `drift`（出身緯度−現在緯度 [rad]）、追跡風速、
  海上滞在比（fetch）。
- `at()` で `compression = |∇(出身緯度)| − 1`（0.025 rad ≈ 160 km の中心差分
  — この刻みが前線帯の幅を決める）。追跡風が 3–7 m/s に満たない淀みでは
  `trusted` マスクで 1 へ溶かす。

### 帯の診断（`src/render/earth-weather/weather-model.ts`）

```
front     = smoothstep(1.65, 2.0, compression) + updraft×0.15   // 上限1、温帯のみ
rainband  = smoothstep(5, 9, compression)                        // 熱帯のみ
band      = min(front + rainband, 1)
```

- `updraft` は気圧由来の上昇流（0.01–0.04 m/s で 0→1）。圧縮が弱くても
  谷の芯では加算で帯へ届く。
- 温帯/熱帯の切替は緯度ランプ（20°→35°）。
- `band` の効き先: 上昇流へ +0.06 m/s（`bandLift`）、地表湿度へ +0.1
  （`bandHumidity`）、凝結では粒を滑らかに（`bandGrainFade`）・雲頂を持ち上げ
  （`bandTop`）、セル径場では前線粒子 35 km の門（`cell-size.ts`）。

### 低気圧との結び付きは間接的

低気圧は気圧の谷（`cyclones.ts` → `PressureFeature`）として気圧場へ書き込まれ、
釣り合い風の循環が気団を巻き込み、芯のまわりに圧縮の腕が渦巻いて**結果として**
「低気圧の前線」が現れる設計。腕が芯へ絡む様子は写しで実際に見える。
ただし帯が低気圧へ接続しているかを検査・強制する機構はどこにも無い。

## 2. 閉塞 — 一生の進行で駆動されるが、湿度マスクだけ

`low-tracks.ts`: 各低気圧の一生に `occlusion` 0→1（life **0.45→0.75**、
深さの山 0.42 を越えてから追いつき始める）が付く。これが `pressure-feature.ts`
の 3 つの幾何マスクを駆動する（位置・広がりはすべて谷の短軸半径を尺にした倍率、
強さは閉塞の進み × 現在の深さ）:

- **乾いた舌** — 赤道側・やや下流から芯へ入り込む下降流の楔
- **コンマの頭** — 芯の極側を覆う広い層状の雲域（加湿項）
- **閉塞芯** — この内側で暖域の舌が切り離され、暖気流入の加湿が止まる

**前線の線（`band`）自体は閉塞を知らない。** 「寒冷前線が温暖前線に追いつく」
線の再編は表現されず、閉塞は芯まわりの湿度構造としてだけ現れる。
閉塞前線という帯の概念は場に存在しない。

## 3. 寒冷前線の非対称 — 横断方向は実装済み、進行方向は暗黙のみ

前線を横切る方向（暖気側↔寒気側）の非対称は入っている:

- **暖気側**: `warmth > 0`（暖気流入）→ `warmHumidity` 0.6 で地表湿度へ加湿、
  `WARM_TOP` で雲頂も高い。閉塞芯の内側ではこの加湿が切れる
- **寒気側**: `warmth < 0` かつ海上で寒気噴出（MCAO）— 海上滞在比 fetch に応じて
  閉じた細胞（被覆 ~90%）→ 開いた細胞（~50%）へ被覆が落ちる細胞状雲
- **帯の中**: `bandGrainFade` で粒が滑らかになり層状的、`bandTop` で雲頂が高い

一方で**前線の進行方向への非対称は明示的には無い** — `band` は圧縮の稜線上で
左右対称に立つ。実際の寒冷前線の「雲域が進行方向側へ張り出す」ずれは、
`bandHumidity` で湿った空気が輸送で下流へ運ばれる分だけの暗黙の効果。
稜線から風下への幾何的オフセットは無い。

## 4. 「低気圧と無関係な場所で一瞬現れて消える」の原因

観察された症状は設計の副作用として説明できる。4 つの機構が重なる:

1. **圧縮は低気圧の腕でなくても点く** — 高気圧と貿易風のあいだの収束、
   地形による収束、隣り合う渦の循環どうしの合流でも `compression > 1.65` なら
   帯が立つ。緯度ランプ（20–35° 以北）以外に場所の制約は無い。
2. **追跡が「いまの風」で毎フレーム引き直される** — 遡り積分に時間的平滑が無く、
   低気圧が一生を進める・気圧ノイズのエポックが混ぜ替わるたびに圧縮の稜線が
   移動・分裂・消失する → 点滅として見える。
3. **閾値の張り付き** — `smoothstep(1.65, 2.0)` の縁を圧縮がまたぐと帯が出入りする。
   `trusted` マスク（3–7 m/s）を追跡風がまたぐと稜線の区間ごと消える。
4. **上昇流の加算** — `updraft × 0.15` により、圧縮 0.85 でも谷が深まると帯へ
   届き、脈打つ。

なお cloud-lab の「前線」写しが描くのは `compression − 1` の生値
（`tools/cloud-lab/views.ts`、0..8 を白へ）— つまり診断の生の圧縮場であり、
閾値を通した `band` ではない。写し上の明滅は圧縮場そのものの時間変動。

## 5. 修復の方向（未実施）

- **前線を低気圧へ錨付けする** — 帯の強さを、最寄りの中緯度低気圧の方位・半径
  （閉塞マスクと同じ `occlusionFrame` の尺）で門掛けする。圧縮稜線は「渦の腕と
  して説明できる所」だけが前線へ昇格し、孤立した収束は帯にならない。
- **閉塞を `band` へも反映** — occlusion の進みで、芯側の腕を閉塞前線
  （コンマの頭の縁の帯）へ段々付け替える。
- **時間コヒーレンス** — 追跡へ過去の風の履歴（エポック混ぜ替えを跨ぐ指数平滑、
  または複数時刻の trace を評価して混ぜる）を入れて点滅を抑える。
