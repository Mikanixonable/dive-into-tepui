## 1. 偏西風の蛇行(`rossby-wave.ts`)

### 1.1 波が停滞・逆行しない【仕様未達】

SPEC「波の谷と峰は風の中をゆっくり東へ**進むか停滞・逆行し**」に対し、
`WAVE_PHASE_SPEED` は定数 3°/day の東進のみ(rossby-wave.ts:17)。
ロスビー波の位相速度は c = U − β/k² で、短波は東進・長波は停滞〜西退する。

- 影響: ブロッキングが原理的に現れない。`WAVE_DRIFT` は無条件に
  低気圧・高気圧の配置へ足されるので(low-tracks.ts:294,
  anticyclone-tracks.ts:143)、波が止まるべき時期にも谷の錨が東へ流れ続け、
  低気圧がブロッキング高気圧を突き抜ける配置になりうる。
- 改善候補: 位相速度を ~2 週間スケールで変調(低周波成分や epoch 混合)し、
  停滞・逆行を許す。錨づく配置は変更なしで「止まる波に錨づいて止まる」が
  自然に出る。高気圧の「強い蛇行ほどブロッキング」(anticyclone-tracks.ts:106)
  と整合する。

### 1.2 波数が単一(k=5)【改善候補】

実際のロスビー波は k=4〜8 の重ね合わせで、谷の間隔も波束の下流伝播もある。
単一波では谷の間隔が常に 72° で画一。k=5+k=7 程度の重ね合わせで拍・包絡が
生まれ、「位相が発生海域へ揃う時期に多く」の変動がより豊かになる。

### 1.3 振幅が時間的に不変【改善候補】

振幅 = 緯度包絡 × 経度のストームトラック重みのみ(rossby-wave.ts:92-110)で、
時刻への依存が無い。振幅が ~2 週間スケールで盛衰すれば、発生門
(`waveAmplitudeAt` による、low-tracks.ts:206)を通じて低気圧の群発期・
静穏期が自然に出る。

### 1.4 蛇行の見かけ変位が小さい【改善候補】

`MERIDIONAL_SPEED = 4 m/s` では、緯度変位 η ≈ ψ/U ~ 1.5〜2° 程度。
実際の蛇行は ±5〜15° に及ぶ。風の摂動ではなく**緯度変位場 η(λ,φ,t) として
モデル化**し、循環の帯や上層雲の読み位置を η だけずらす方式なら、v' を
大きくせず視認できる蛇行が出せる(S 帯スペクトルの尖り対策で半減させた
経緯 — rossby-wave.ts:29-32 — と両立するはず)。

### 1.5 地表風へ上層と同振幅で加える【改善候補】

`surfaceBackground` と `upperBackground` の両方に同じ摂動を全量加算
(wind-field.ts:77-79)。ロスビー波は上層主体の現象なので、地表側は
減衰(例 ×0.5)させるほうが自然。

### 1.6 ストームトラックは地球地理固定【留意】

bump 表(140°E, −60°, 20°, 30°, 150°)は地球の大陸配置前提。モデルは
surfaceRadius を引数化した汎用天体の作りなので、将来 climate/land 分布から
導く余地として記録。

### 1.7 bump 表と TRACK_AXES の二重管理【コード】

bump 中心が low-tracks.ts の `TRACK_AXES`(low-tracks.ts:127-137)に複製され、
`trackAxisAt` で最近傍を引く。bump を足して TrackAxis を忘れても既存の別海域の
軸へ黙って吸着される(エラーにならない)。TrackAxis を bump 表から生成するか、
距離閾値超過で例外にすべき。

### 1.8 TSL/JS の式の重複【コード】

`trackWeightsAt`(TSL)と `trackWeightAtJs`(JS)の二重実装。
「同じ式」とコメントにあるが自動検査が無い。同様の重複は pressure-feature.ts
の前線式と front-skeleton.ts にもある。二重実装どうしを突き合わせる
回帰テストが無い。

## 2. 低気圧の配置と動き(`low-tracks.ts`, `cyclones.ts`, `tropical-tracks.ts`, `anticyclone-tracks.ts`)

### 2.1 渦の吸収が中緯度低気圧どうしに限られる【仕様未達】

SPEC「近づきすぎた 2 つの渦の中心は併存しない — 熱帯の渦どうし、熱帯の渦と
中緯度の低気圧のあいだでも同じように働く — 転向した熱帯の渦が温帯の低気圧へ
呑まれて終わる姿も、ここから出る」。現状 `absorbedLowAt` は LOW_COUNT 内の
同半球のみ(low-tracks.ts:351)で、`tropicalPlacementAt` は独立に評価
(cyclones.ts:31)。西北太平洋の発生点が固定(12°N,145°E±8°)で枡が 5 つある
ため同一海域に 2 つの眼が並立しうるし、転向台風が温帯低気圧と重なっても
双方残る。**最も明確な仕様との食い違い**。

- 改善候補: 吸収の枠組み(raw 表 → softmax の効き)を troughs 全体へ広げる。
  熱帯側にも peakDepth・presence を持たせれば機構はそのまま使える。

### 2.2 家族(2 次低気圧)が一次の死後にしか生まれない【改善候補】

`onset = primary.onset + primary.lifetime + LOW_HANDOFF_GAP`(low-tracks.ts:193)
は直列。実際の cyclone family では一次が閉塞しながら、寒冷前線の尾の上で
二次が発達し時間的に重なる。`onset = primary.onset + (0.5〜0.7)·lifetime`
程度で重なりを許し、位置も一次の寒冷前線の尾の延長へ置くと自然。

### 2.3 速さ・深さ・大きさが独立乱数【改善候補】

SPEC「深いもの・大きいもの・速いものほど珍しい」。独立に引くと「遅い・浅い・
小さい」等の組合せが均等に出る。発達期に速い爆弾低気圧の相関を入れるなら、
共通の「強度」乱数から 3 量を導く。

### 2.4 進路の折れが決定論的【改善候補】

`turnPoleward` の揺れ ±0.05、折れ点は常に道のりの半ば(courseAt の s=0.5)。
同じ海域の低気圧が毎回同じ弧を描く。折れ点の位置と極向き成分にもう少し幅を。

### 2.5 操縦流との非整合【留意】

低気圧は「錨のドリフト + 自力速度」で動き、モデルの合成風場では運ばれない
(low-tracks.ts:289-294)。ブロッキング高気圧の縁を回る等の相互作用は出ない。
閉じた関数の約束と相性が悪いが、1.1 の位相変調を入れれば錨ごと停滞するので
実質的に解決する。

### 2.6 rank が隣の谷を跨ぐ【改善候補】

16 枡/半球 ÷ 5 谷で rank 0〜3、間隔 20° → rank 3 は下流 85° で隣の谷の
上流側に落ちる(low-tracks.ts:42-44)。結果的に連続した低気圧列になるので
見た目は悪くないが、「谷の下流」という規則の意味が薄れる。発生経度ジッタ
(±0.08 × 72° ≈ ±5.8°)もやや小さく、世代内の発生位置はほぼ確定的。

### 2.7 気圧ノイズが無名の谷を作る【留意】

PRESSURE_NOISE(5300 km, ±18 hPa)は並の低気圧に匹敵する落ち込みを作るが、
前線も進路も持たず循環の移流で運ばれるだけ。「どこにも行かない低気圧」に
見えるかは要観察。

### 2.8 高気圧に世代を超えたブロッキングが無い【改善候補】

寿命 7〜12 日・速度 1.5〜5 m/s は移動性として妥当だが、ブロッキングは
2 週間超かつほぼ停滞。1.1 の位相変調と連動させて「停滞フラグ」を世代乱数から
引くと、波・低・高が揃ったブロッキングイベントが作れる。

### 2.9 PressureFeature 全 37 個を全 texel で評価【コード・性能】

`cyclones.frontAt/eyeAt/anvilAt/pressureAt` は距離に関係なく全渦を足し込む
(cyclones.ts:40-74)。眼・金床・前線・舌・コンマ頭はコンパクトサポート
(~2× 半径)なのに `dot(direction, center)` の早期脱出が無い。余裕を持った
cos 閾値で skip すれば 1 点あたりの実効評価は 37 → 数個に減る。pressureAt は
1/r の裾があるのでカットオフを FEATURE_REACH の 1.5〜2 倍に取れば誤差は
数 % 以内。

### 2.10 `lowPlacementsAt` の track 再計算【コード・性能】

32 枡 × 9 標本 = 288 回 `rawLowPlacementAt` が走り、`lowTrackOf`
(枡・世代・候補で確定的)と `lowWoundOf`(17 段台形積分)を同じ引数で最大
9 回組み直す(low-tracks.ts:324-334)。(index, generation) キーのメモ化で
ほぼ 1/9 に減らせる。

### 2.11 peakDepth の同値対称ケース【コード】

`other.peakDepth < self.peakDepth` では、最深が等しい 2 つが互いを呑んで
双方消える。index タイブレークか片側 `<=` で。

### 2.12 `wound` 計算が low/tropical で重複【コード】

`lowWoundOf` / `tropicalWoundOf` は一生の関数形だけ違う同じ台形積分。
life→(depth, radius, latitude) を返す関数を渡す形に共通化できる。

## 3. 前線の挙動(`pressure-feature.ts`, `front-skeleton.ts`, `air-mass.ts`, `weather-model.ts`)

### 3.1 骨格モデルと気団の境目が独立【構造上の主要課題】

SPEC「前線は気団の境目に立つ」「前線は固定半径の螺旋ではない」。実装は
谷の芯に紐付いた解析的な腕(気団場を見ていない)で、一方で気団追跡の
`compression`(実際の境目の圧縮)は中緯度では `band` に一切使われていない
(`rainband` は熱帯のみ `extratropical.oneMinus()` で門、weather-model.ts:284-286)。
**絵に出る前線と、気団場が実際に作る境目がずれても誰も検知しない。**
寒冷前線後部では寒気の fetch(outbreak)が別座標で効くので、骨格が気団場と
ずれたとき雲が前線の「誤った側」に出うる。

- 改善候補: compression 場を中緯度でも弱く band へ足す、または骨格の強さを
  近傍の compression の存在で門する(骨格が実界から外れたら消える)。

### 3.2 寒冷前線の尾が渦の循環の届く半径で切れる【改善候補】

`coldLength = armReach`(循環風速 < `frontEdgeSpeed`=4 m/s になる外縁、
上限 FEATURE_REACH 2500 km)。実際の寒冷前線は親の循環を離れて亜熱帯まで
数千 km 伸び、停滞前線化する。SPEC「数千キロに及ぶ帯」はぎりぎり。
渦とは独立した「尾の延長」を足すか、気団場の境目へ回すと良い。

### 3.3 閉塞が life 分数で機械的に進む【改善候補】

`occlusion = smoothstep(life, 0.45, 0.75)`(low-tracks.ts:298)。発達の速い系と
遅い系で同じタイミング。一方 `wound`(積算巻き上げ角)は循環の履歴を既に
持っているので、**閉塞を wound の関数にすると「深く巻いた系ほど早く閉塞
する」が自然に出る**。wound は既に計算済みでつなぎ替えは低コスト。

### 3.4 温暖前線前方の層状シールド【改善候補】

実際は暖域の前方数百 km に巻層雲〜高層雲のシールドが先行するが、帯は骨格
中心の対称的な(skew 付き)ガウス(pressure-feature.ts:283-289)。
pre-frontal cirrus として骨格前方側にオフセットして cirrus 量へ足すと、
衛星画像らしい前兆雲が出る。

### 3.5 前線の死滅が低気圧と運命を共にする【留意】

親が埋まると帯も消えるが、実際は残った境目が停滞前線として存続し、次の
低気圧の発生場になる。3.1 の compression 統合か 2.2 の家族配置で代用できる。

### 3.6 楕円谷と前線骨格の座標系が未接続【改善候補】

`chordSquared` は長軸方向に潰した楕円距離、`frontAt` は半径比の円座標
(occlusionFrame)で腕を張る。谷の長軸(前線方向)と腕の向きが独立なので、
伸びた谷に対して骨格が斜めに出ることもありうる。腕の根元を長軸の向きへ
揃えると整合する。

### 3.7 前線定数の二重管理【コード・確実にずれる】

`FRONT_INNER_RADIUS=0.15`、`TAIL_WARM_ONSET/FULL` が pressure-feature.ts と
front-skeleton.ts にそれぞれ直書き(pressure-feature.ts:84-93,
front-skeleton.ts:10-14)。front-skeleton は tools 用だが「TSL と同じ式」と
明記している以上、共通定数化すべき。

### 3.8 `frontAt` は腕 3 本を常に全評価【コード・性能】

`frontKind=0`(高気圧・前線を持たない配置)でも全腕の式を計算してから最後に
0 を掛ける(pressure-feature.ts:350)。`If(frontKind > 0)` で全体を囲むだけで
無駄が減る。

### 3.9 `OCCLUSION_DEPTH` の流用が紛らわしい【コード】

閉塞強度と前線帯強度の両方の正規化に同じ定数を使う
(pressure-feature.ts:217, 347)。値が同じで良いのは偶然なので、前線用は
別名に分けたほうが後の調整で安全。

### 3.10 `elongation` と軸向きが一生不変【改善候補】

`LOW_ELONGATION=1.3` 固定、長軸は常に SW–NE。若い円い低気圧→閉塞した
長い低気圧への時間発展は elongation にも wound にも応答しない。life や
occlusion で伸長・回転させると、閉塞した低気圧の南北に延びた形が自然に出る。

## 4. 横断的な点

- **決定性と時刻関数化の設計は良い**。枡・世代・乱数列で一生を閉じた形に
  しているため、セーブ復帰・時間加速でも同じ空が出る。上記の改善(位相変調・
  家族の重なり・吸収の拡張)はどれもこの枠組みを壊さず入れられる。
- **検証の欠落**。軸整合(TRACK_AXES ↔ bump 表)・JS/TSL 二重実装
  (trackWeight, front-skeleton)・単位換算(vortexSpinOf vs eyeStrengthOf の
  coreBend)に跨る検査が tests/ に無い。同じ式の再実装どうしを突き合わせる
  回帰テストを置くと、定数のずれ系を機械的に防げる。

## 5. 優先度

1. **渦吸収の熱帯・温帯跨ぎ拡張**(2.1) — 明確な仕様未達。
   転向台風が温帯低気圧へ呑まれる姿が出せず、同一海域の眼の並立も起きうる。
2. **波の位相速度変調**(1.1) — ブロッキング・停滞の根幹。高気圧の
   「強い蛇行ほどブロッキング」と連動して、波・低・高が揃ったイベントが作れる。
3. **前線骨格と気団 compression の照合**(3.1) — 構造上の主要課題。
   骨格と実界のずれを検知しないまま雲を描く。
4. **定数の共通管理**(1.7, 3.7) — 安価に潰せる事故の芽。
