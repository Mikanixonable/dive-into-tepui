## 何をしたか

宇宙船設計計画 第8版のうち、**第1巻 F1〜F7 / F11 / R1〜R3** と **第2巻 B3 / B5** を実装した。加えて、この作業の前段として行った計画・予測の負荷改善(統一積分弧 `PredictedArc` への載せ替え)も含む。

骨格をなす方針のうち、この変更で成立したのは3つである。

- **実体は1つ** — 艦艇・軌道基地・敵艦は、すべて `Vessel` である。能力は積んでいる部品から導く
- **物理量は形状の帰結** — 質量・重心・慣性テンソル・投影面積を定数として持たず、形状と搭載物から導出する
- **自動操縦は通信を要する** — 無人機は通信圏の内側にいなければ計画を実行できない

## 第1巻

### F1 断面の幾何 / F2 ロフトの物理量 — `src/physics/`

計画全体で最大の未知であった「複合断面と一般化角錐台の物理量が閉形式で求まるか」を先に確かめ、**求まる**ことを実装で示した。数値積分は一箇所も使っていない。

- `section-moments.ts` — 断面の面積・重心・断面二次モーメント。多角形は shoelace、円/楕円は解析定数。突き合わせで貼った部品は重ならないことを**検査したうえで**和にする(重なる断面は例外を投げる)
- `hull-loft.ts` — 2断面間のロフトの体積・重心・慣性テンソル・側面積・投影面積。線形補間した中間断面の生の積率は高々4次の多項式なので、5点の Boole 則が**厳密**になる
- `inertia-tensor.ts` — 慣性テンソルの代数(平行軸、回転、主慣性モーメント、逆行列)

`section-moments.test.ts`(383行)/`hull-loft.test.ts`(426行)/`inertia-tensor.test.ts` が、正多角形・2048角形の円への収束・円柱と直方体の教科書値・円錐の重心・L字の3つの相異なる主慣性モーメントまで固定している。

### F3 外部トルクの純関数 — `src/physics/`

- `gravity-gradient.ts` — 重力傾斜トルク `τ = 3(μ/r³)(r̂ × I r̂)`。**慣性テンソル全体**を受け取る(非対角成分は答えを数十%動かす)。閉形式 `τ_z = 3μ(Iy − Ix)sinθcosθ/r³` を相対 1e-12 で固定してあり、係数 3 を 1 に変える変異を検出する
- `geomagnetic.ts` — 傾いた双極子としての地球磁場と `m × B`

### F4 `Vessel` への統合

`Ship` / `Player` / `Base` / `Enemy` の4クラスを **`Vessel` 1つ**へ畳んだ。差は `faction` と積んでいる部品だけである。

- `capabilities.ts` — `hasCockpit` / `hasBaseModule` / `canAutopilot` / `isOperable`。**「これは基地か」を表すフラグはどこにも無い**。問いは常に「どの部品を積んでいるか」である
- `part-inventory.ts` — HP と性能値の唯一の出どころ。推力・トルク・冷却・発電・蓄電・消費電力・廃熱をすべて §6-5 の定義どおりに合成する
- どの喪失を記録するかも導出になった — `faction === 'enemy'` なら敵の撃墜、基地モジュールを持つ味方なら何も決めない、持たない味方なら自機喪失

削除: `game-entity/{ship,base,enemy,controllable}.ts`, `player/player.ts`, `active-player-controller.ts`, `active-controllable-controller.ts`。

### F5 搭載要素

`parts.ts` を第8版 §6-1 の一覧へ置き換えた。**エンジンはサイクル×推進剤の対**であり、弾倉と弾薬は別の要素である。姿勢トルクはフライホイール、並進は RCS スラスタ、主推力はエンジンから出る — 推力とトルクを同時に持つ要素は無くなった。

### F6 ツリーと設計データ / F7 質量特性の適用

- `tree.ts` — ノードとエッジのツリー。**閉じてよい**(三角形やはしごが組める)。ノードが自分の位置を、エッジが自分の長さを持ち、`validateTree` が両者の一致を検査する(閉ループはエッジ長だけからは解けない)。0.5m 量子化
- `mass-properties.ts` — 形状から乾燥質量・重心・**積を含む慣性テンソル**・3軸の投影面積を導出。すべて船体局所原点まわりで積んで、最後に一度だけ重心へ移す
- `hull-structure.ts` — 薄肉圧力容器の式による外皮厚。加圧区画は非加圧の下限を下回れない。**加圧供給サイクルの高圧タンクが重くなる**のはここで払われる
- `internal-volume.ts` — §12 の実効体積率表。軸方向に連続しないエッジをまたぐ搭載は拒否する
- `aerodynamics.ts` — **弾道係数が姿勢に依存するようになった**。投影面積を像の**合併**として求めるので、細長い機体は機首を流れに向けたときに抗力が最小になる
- `heat-shield.ts` — 熱シールドは取付面の外向き軸が向いている方向しか守らない。**機首を流れから背けると保護がまるごと落ちる**

姿勢積分(`attitude.ts`)を主慣性モーメント3つから**一般の慣性テンソル**へ拡げた。形状から導いた機体の体軸は主軸ではないので、これが要る。

### R1〜R3 資源・設備 — `src/game/economy/`

DOM にも THREE にも依存しない純データと純関数。

- `resource.ts` / `facility.ts` / `deposit.ts` — 資源表・設備表・産地。**電力は資源ではない**(貯蔵も輸送も規則が違う)ので帳簿に入らず、設備が `powerDraw` と `powerOutput` を持つ
- `producibility.ts` — 生産可能性の判定。要求は `resource` / `facility` / `power` の3つに閉じる。**同じ設備を複数の要素が要求しても、実物は1基なので電力も建造費も1回しか数えない**。判定は帳簿を一切変更しない
- `propellant-compatibility.ts` / `actuator-materials.ts` — 推進剤ごとのタンク材、アクチュエータごとの要求資源

`resource-closure.test.ts` が **設備の連鎖が閉じていること**を検査する。初期資源と初期設備10基から、資源と設備の**両方**について不動点まで前方に閉じ、反復のたびにツィオルコフスキーの式で Δv 能力を出し直して到達できる天体を広げる。電力の検査は「太陽電池に至る経路が初期の発電容量だけで歩けるか」を突く。

## 第2巻

### B3 通信圏 — `src/game/comms/`

- `coverage.ts` — 判定そのもの。DOM/THREE に触れない純関数。地上局から前方に閉じるので、**孤立した中継点はどれだけ強力でも誰も圏内にしない**。到達距離は両端の**小さいほう**で決まる。天体の表面に立つ中継点は、相手が自分の地平線より上にあるかを別途見る(でないと月面基地が月を貫いて裏側を覆う)
- `comm-stations.ts` — 初期の2つの地上局(月面と NRHO)。通信基地の到達距離 2.0e8 m は**地球-月間より短く**、地球低軌道は初期の圏内に入らない
- `comm-network.ts` — 毎フレームの通信網。通信局とは「基地モジュールと通信モジュールを同じ機体に積んでいること」であって、それを表す部品種別は無い

`plan-executor.ts` の `commandLinked` が圏外の挙動を実装する。**始まらないが、始まったものは完遂する** — 圏外では点火も姿勢合わせも起こらないが、走っている燃焼は機上の時計で駆動されるので観測も判断も要さず完遂する。圏外で通り過ぎたノードは**消費されない**。復帰した最初のフレームで過去のノードをまとめて捨て、何個落としたかを告げる — 機体は意図しない軌道にいる。

### B5 設計データ — `src/game/vessel/blueprint*.ts`

- `blueprint-validation.ts` — §4-2 の17種の検査を `BlueprintIssue[]` として返す純関数。断面・連結・接続口の排他・側面口の収まり・隣接口の干渉・トラス混雑・表面RCSの干渉・内容積・タンク材質・姿勢制御の成立・配管の連続・加圧ガス・段・熱シールドの向き・推力軸の重心ずれ・上限
- `blueprint-library.ts` / `blueprint-store.ts` / `blueprint-transfer.ts` — 保管庫・永続化(`tepui.blueprints`、セーブとは別の鍵)・ファイル入出力。**識別子が合わない「設計ファイルではない」と、構造が壊れている「壊れている」を言い分ける**。取り込みは骨格検査に加えて `validateBlueprint` を通し、`error` が1つでもある設計は保管庫に触れる前に拒む

## 影響と注意

- **再突入のバランスが変わっている。**抗力係数を形状と実質量から導出したので抗力が増え、大気減衰と再突入のタイミングが動く
