## 1. 設計判断

### 1-1. 船体は背骨と断面で定義する

宇宙船の形状は、**ノードとエッジからなる背骨**と、**各ノードが持つ断面**で定義する。外皮は、エッジの両端にある2つの断面をつないだ立体（ロフト）として生成する。

エッジから外皮までの距離は定数ではなく、両端のノードの断面寸法によって決まる。したがって、細い部分と太い部分を持つ機体、先細りの機体、段ごとに直径の異なるロケットが、追加の機構なしに作れる。

### 1-2. 断面が分岐方向を決める

各ノードは、断面の表裏に向かう2つの軸方向の接続口と、断面形状ごとに決まる側面の接続口を持つ。側面の口の方向は断面が決め、各ノードが持つ回転位相ぶん回る。

- **多角形の断面** — 各辺の外向き法線の方向に口を持つ。三角形なら3方向、八角形なら8方向である。
- **円の断面** — プレイヤーが分岐数 n を 2・3・4・5・6 から選び、360度を n 等分した方向に口を持つ。分岐数2なら0度と180度、分岐数3なら0度と120度と240度である。
- **楕円の断面** — 長軸の正負2方向に口を持つ。

分岐の角度をプレイヤーが数値で指定する操作は存在しない。角度は断面形状と分岐数と回転位相から決まる。

### 1-3. 結合はすべて平面同士の突き合わせとする

エッジと断面の結合、側面分岐の結合、および断面を組み合わせて複合断面を作るときの結合は、いずれも平面同士の突き合わせとする。曲面同士を滑らかに融合させる処理も、立体同士の重なりを差し引く処理も行わない。

この判断により、外皮の体積・表面積・重心・慣性テンソルがすべて解析式で求まり、部分同士が重なることもない。数値積分も、等値面の三角形分割も不要である。実際のロケットも、段間部と側面ブースターの取り付けはフランジ結合であり、工学的にも自然である。

円の断面に側面の口を設ける場合のみ、その方向の円弧を弦で切り落として平面を作る。切り落としによる断面積と断面二次モーメントの減少は、弓形の解析式を差し引いて厳密に計算する（§2-5）。

### 1-4. 寸法は0.5メートル単位とする

エッジの長さ、および断面の外接円半径は、いずれも0.5メートル単位で指定する。連続値にすると、対称な機体や、断面の揃った段を組むことが困難になる。

### 1-5. 物理量は形状から導出する

質量・重心・慣性テンソル・断面積は定数として持たず、背骨と断面と搭載物から導出する。扁平な機体は実際に回りにくく、非対称な機体は実際に重心がずれる。

### 1-6. 推進剤はタンクから配管を通ってエンジンへ流れる

配管は搭載要素の一つであり、プレイヤーが背骨のエッジに割り当てる。タンクからエンジンまで配管が連続していないエンジンは点火できない。配管には口径ごとの流量上限があり、エンジンの要求流量を満たさない配管は推力を制限する。

### 1-7. 推進剤は登録されたペアからのみ選ぶ

比推力は実測値であり、任意の酸化剤と還元剤の組み合わせに対して定義できない。推進剤は「酸化剤と還元剤のペア」「単推進剤」「固体グレイン」「ハイブリッドの組」として表に登録されたものからのみ選ぶ。表は §6-1 に置く。

### 1-8. 設計と生産を分ける

プレイヤーは、資源を消費せずに設計を作り、名前を付けて保存し、読み込める。実機を得るには、保存した設計を指定して生産する。生産には時間がかかる仕組みを持つが、初期状態ではすべての設計の生産時間を0とする。

## 2. 背骨断面システム

### 2-1. 断面の定義

断面は、1つ以上の**基本断面**を面で貼り合わせた複合体である。

```ts
// src/game/vessel/cross-section.ts
export type PrimitiveShape =
  | { kind: 'circle';   radius: number; branchCount: 2 | 3 | 4 | 5 | 6 }
  | { kind: 'ellipse';  majorRadius: number; minorRadius: number }
  | { kind: 'polygon';  sides: 3 | 4 | 5 | 6 | 8; radius: number }
  | { kind: 'notched';  sides: 6 | 8; radius: number };  // 辺長が 1:2 で交互する切り欠き型

export interface SectionPrimitive {
  readonly id: string;
  readonly shape: PrimitiveShape;
  readonly phaseAngle: number;          // この基本断面の回転位相 [rad]
  readonly attachment: PrimitiveAttachment | null; // null は複合体の根
}

export interface PrimitiveAttachment {
  readonly parentId: string;            // 貼り付け先の基本断面
  readonly parentFaceIndex: number;     // 貼り付け先のどの辺に付けるか
  readonly childFaceIndex: number;      // 自分のどの辺を貼り付けるか
}

export interface CrossSection {
  readonly primitives: readonly SectionPrimitive[];
}
```

- 複合体は木構造である。各基本断面は、親の1つの辺に、自分の1つの辺を重ねて貼り付ける。
- 貼り付ける2つの辺は長さが等しくなければならない。等しくない場合は設計として不正とし、エディタが理由を表示する。
- 貼り合わせ面を共有するため、基本断面同士は重ならない。したがって複合断面の面積は基本断面の面積の和であり、断面二次モーメントは平行軸の定理で合成した和である。
- 円と楕円は辺を持たないため、複合体の根としてのみ使える。子として貼り付けることはできない。

例として、四角形断面の一辺に三角形断面を貼り付けると、五角形の家型の断面になる。四角形の対辺2つに三角形を貼り付ければ、六角形の紡錘型になる。八角形の複数の辺に四角形を貼り付ければ、突起を持つ断面になる。

### 2-2. 基本断面の形状

| 形状 | 寸法パラメータ | 側面の口の数 | 口の方向 |
|---|---|---|---|
| 円 | 半径 | 2・3・4・5・6 から選ぶ | 360度を分岐数で等分した方向 |
| 楕円 | 長半径・短半径 | 2 | 長軸の正負方向 |
| 正三角形 | 外接円半径 | 3 | 各辺の外向き法線 |
| 正方形 | 外接円半径 | 4 | 各辺の外向き法線 |
| 正五角形 | 外接円半径 | 5 | 各辺の外向き法線 |
| 正六角形 | 外接円半径 | 6 | 各辺の外向き法線 |
| 正八角形 | 外接円半径 | 8 | 各辺の外向き法線 |
| 切り欠き六角形 | 外接円半径 | 6 | 各辺の外向き法線 |
| 切り欠き八角形 | 外接円半径 | 8 | 各辺の外向き法線 |

**切り欠き型** — 正多角形の辺の長さがすべて等しいのに対し、切り欠き型は長い辺と短い辺が1対2の比で交互に並ぶ。

- **切り欠き八角形** — 正方形の4つの角を切り落とした形である。長さ2の辺が4つ（元の正方形の辺の残り）と、長さ1の辺が4つ（切り落とした角の断面）を持つ。長い辺の中点に大きな面を確保しつつ、角の張り出しを抑えられる。
- **切り欠き六角形** — 正三角形の3つの角を切り落とした形である。長さ2の辺が3つと、長さ1の辺が3つを持つ。

切り欠き型は、正多角形より広い平面を確保しながら外接円半径を抑えられるため、太陽電池パドルや放熱板のような広い取り付け面を要する部品を並べるのに適する。

### 2-3. 背骨

```ts
// src/game/vessel/skeleton.ts
export interface SkeletonNode {
  readonly id: string;
  readonly pos: Vec3;              // 船体ローカル座標 [m]。0.5 m 単位
  readonly section: CrossSection;
  readonly axis: Vec3;             // 断面の法線（背骨の進行方向）
  readonly phaseAngle: number;     // 断面全体の回転位相 [rad]
}

export type EdgeKind =
  | { kind: 'hull' }                                   // 外皮を作る。内側が内容積になる
  | { kind: 'strut'; radius: number }                  // 外皮を作らない構造材
  | { kind: 'decoupler'; separationImpulse: number };   // 外皮を作らず、切り離せる

export interface SkeletonEdge {
  readonly id: string;
  readonly a: string;
  readonly b: string;
  readonly portA: PortRef;
  readonly portB: PortRef;
  readonly length: number;         // 0.5 m 単位
  readonly kind: EdgeKind;
}

export type PortRef =
  | { kind: 'axial'; sign: 1 | -1 }
  | { kind: 'lateral'; primitiveId: string; faceIndex: number };

export interface VesselSkeleton {
  readonly nodes: readonly SkeletonNode[];
  readonly edges: readonly SkeletonEdge[];
}
```

背骨はグラフであり、閉路を含んでよい。三角形や梯子状に組めば扁平な機体になる。

側面の口の**大きさ**は、その辺の長さと、辺に沿った規定の幅で決まる。側面から分岐するエッジの相手側の断面は、この口に収まる大きさでなければならない。収まらない場合は設計として不正とし、エディタが理由を表示する。

### 2-4. 外皮の生成

`hull` エッジは、両端のノードの断面をつないだ立体を作る。

- 両断面の輪郭を、それぞれ**120点**に等分してサンプリングする。120は3・4・5・6・8のいずれでも割り切れるため、辺数の異なる断面同士でも頂点が一対一に対応する。円と楕円も同じ120点で表す。第三版で用いた60点は八角形を追加したことで不足する（60は8で割り切れない）ため、120点に改める。
- 対応する頂点同士を直線で結び、側面を四角形の帯として張る。
- 両断面の回転位相が異なる場合、頂点の対応は位相差を考慮して、対応する頂点間の距離の総和が最小になる割り当てを選ぶ。これにより外皮がねじれない。
- 複合断面の場合、輪郭は複合体全体の外周である。貼り合わせ面の内側は輪郭に含まれない。

側面の口から分岐するエッジは、口の平面の上に相手側の断面を置き、そこから同じ規則でロフトする。分岐部は平面同士の突き合わせであり、本体の外皮と交差しない。

### 2-5. 断面の面積と断面二次モーメント

基本断面が多角形（正多角形・切り欠き型・複合体の構成要素）である場合、頂点列から以下で厳密に求める。頂点を反時計回りに `(x_i, y_i)`、`i` の次を `i+1` として、

```
cross_i = x_i·y_{i+1} − x_{i+1}·y_i
A   = (1/2)  · Σ cross_i
Cx  = (1/(6A)) · Σ (x_i + x_{i+1}) · cross_i
Cy  = (1/(6A)) · Σ (y_i + y_{i+1}) · cross_i
Ix  = (1/12) · Σ (y_i² + y_i·y_{i+1} + y_{i+1}²) · cross_i
Iy  = (1/12) · Σ (x_i² + x_i·x_{i+1} + x_{i+1}²) · cross_i
Ixy = (1/24) · Σ (x_i·y_{i+1} + 2·x_i·y_i + 2·x_{i+1}·y_{i+1} + x_{i+1}·y_i) · cross_i
```

を求め、平行軸の定理で重心まわりに移す。この式は任意の単純多角形に対して厳密であり、形状ごとの個別の式を持つ必要がない。切り欠き型も、複合断面も、この1つの式で扱える。

**相乗モーメント `Ixy` は0とは限らない。** 複合断面が対称でない場合、断面の主軸は座標軸から回転する。慣性テンソルの計算では `Ixy` を必ず含める。第三版は正多角形と円のみを扱っていたため `Ixy` を常に0として扱えたが、複合断面を導入する以上これは成り立たない。

円と楕円は解析式で求める。

```
円（半径 r）      A = πr²,   Ix = Iy = πr⁴/4,     Ixy = 0
楕円（半径 a, b）  A = πab,   Ix = πab³/4,          Iy = πa³b/4,   Ixy = 0
```

**円に側面の口を設ける場合** — その方向の円弧を弦で切り落とし、平面を作る。切り落とされる弓形の中心角を `θ`、半径を `r` として、

```
弓形の面積        A_seg = (r²/2)·(θ − sin θ)
弓形の重心距離     d_seg = (4r·sin³(θ/2)) / (3·(θ − sin θ))
弓形の断面二次モーメント は θ の閉形式で求まる
```

を円の値から差し引く。分岐数ぶんの弓形を、それぞれの方向で差し引く。切り落とし量は口の幅から決まる。

```
src/physics/section-moments.ts   (純関数)
    polygonArea(vertices) -> number
    polygonCentroid(vertices) -> { x, y }
    polygonSecondMoments(vertices) -> { ix, iy, ixy }   // 重心まわり
    circleSegmentMoments(radius, halfAngle) -> { area, centroidDist, ix, iy }
    sectionMoments(section) -> { area, centroid, ix, iy, ixy }  // 複合断面全体
    sectionOutline(section, sampleCount) -> readonly Vec2[]     // ロフト用の輪郭
```

検証は `tests/physics/section-moments.test.ts` に置く。正n角形の面積と断面二次モーメントが既知の閉形式と一致すること、辺数を増やすと円の値に収束すること、切り欠き八角形が「正方形から4つの直角三角形を引いた値」と一致すること、複合断面の面積が構成要素の和と一致すること、対称な複合断面の `Ixy` が0になり非対称なものは0でないことを固定する。

### 2-6. 立体の物理量

外皮は「断面が軸方向に線形に変化する一般化角錐台」の集まりである。

**エッジ1本の体積** — 長さ `h`、両端の断面積 `A₁` / `A₂`、中間断面の面積 `Am` として

```
V = (h/6)·(A₁ + 4·Am + A₂)
```

輪郭を線形補間するため中間断面は両端の輪郭の平均であり、`Am` はその平均輪郭の面積である。

**慣性テンソル** — 軸に沿った位置 `t ∈ [0, h]` における断面積 `A(t)`、断面二次モーメント `Ix(t)` / `Iy(t)` / `Ixy(t)`、断面重心 `C(t)` は、いずれも `t` の多項式である。したがって

```
I_axial      = ρ ∫ (Ix(t) + Iy(t)) dt
I_transverse = ρ ∫ (I(t) + A(t)·|C(t) − C_ref|²) dt
I_product    = ρ ∫ (Ixy(t) + A(t)·(...)) dt
```

はいずれも多項式の積分として閉形式で求まる。各エッジの慣性テンソルを平行軸の定理で船体重心まわりに移して合成する。

**表面積** — 側面の帯の面積の和に、露出した端面（他のエッジが接続していない断面）を加える。

**参照断面積** — 主軸3方向への投影面積のうち最大値。抗力係数 `bcInv = Cd·A/m` に用いる。

```
src/physics/hull-loft.ts   (純関数)
    loftVolume(sectionA, sectionB, length) -> number
    loftInertia(sectionA, sectionB, length, density) -> InertiaTensor
    loftCentroid(sectionA, sectionB, length) -> number
    loftSurfaceArea(sectionA, sectionB, length) -> number
    loftProjectedArea(sectionA, sectionB, length, axis) -> number
```

検証は `tests/physics/hull-loft.test.ts` に置く。円断面の等断面ロフトが円柱の解析値と一致すること、両端の断面積が等しい角錐台の体積が `A·h` になること、L字に組んだ骨格の慣性主軸が3値とも異なること（すなわちジャニベコフ効果が発生する形状であること）を固定する。


エッジごとに120分割のロフト帯を生成し、露出した端面を蓋で閉じ、全体を1つのジオメトリに結合する。生成は設計が変わったときに1度だけ行う。遠距離では分割数を下げた別のジオメトリを用いる。

## 3. 艦艇と基地の統合

### 3-1. 実体は `Vessel` 一種類のみとする

艦艇と軌道基地は、いずれも「背骨の上に部品が載った物体」であり、物理的な差は積んでいる部品だけである。したがってエンティティのクラスを分けない。

- **軌道基地** = 基地モジュール部品（格納庫・倉庫・生産設備）を積んだ `Vessel`。
- **艦艇** = コックピットと主機を積んだ `Vessel`。
- **無人ブースター** = 自動操縦装置と主機を積み、コックピットを積まない `Vessel`。

「これは基地か」という判定は存在せず、部品の有無から導かれる能力だけを問う。

```ts
// src/game/vessel/capabilities.ts
export function hasCockpit(v: Vessel): boolean;      // 人が操作できる
export function hasAutopilot(v: Vessel): boolean;    // 無人で計画を実行できる
export function hasBaseModule(v: Vessel): boolean;   // 格納・倉庫・生産・設計ができる
export function hasEngine(v: Vessel): boolean;       // 主機を持つ
export function isOperable(v: Vessel): boolean;      // hasCockpit || hasAutopilot
```

操作対象に選べるのは `isOperable` を満たす機体である。設計エディタと生産を開けるのは `hasBaseModule` を満たす機体である。

### 3-2. `Vessel` が持つもの

| フィールド | 内容 |

| `thermal: ThermalSystem` | 熱収支 |
| `propulsion: PropulsionSystem` | 主機・並進RCS（§5） |
| `attitudeControl: AttitudeControlSystem` | 姿勢トルクの配分（§5-2） |
| `stages: readonly VesselStage[]` | 分離可能な段の一覧（§7-1） |
| `parts: AnyPart[]` | 搭載要素。HPと性能の唯一の源 |
| `plan: Plan` / `planExecutor: PlanExecutor` | 軌道計画とその自動実行 |

`EntityManager` は `vessels: Vessel[]` という単一の配列を持つ。操作対象は `ActivePlayerController` が `Vessel | null` として保持する。

## 4. 搭載要素

### 4-1. 一覧

搭載要素は、背骨のノードに取り付ける**外装要素**と、エッジの内容積に収める**内装要素**に分かれる。エッジ自体の種別（外皮・構造材・分離機構）は搭載要素ではなく背骨の性質である。

**外装要素（ノードの接続口に取り付ける）**

| 要素 | 主な性能値 |
|---|---|
| 武器 | 発射速度、1発あたりの威力、初速、給弾の要求量 |
| ドッキングポート | 適合クラス、移送速度 |
| 太陽電池パドル | 面積、発電効率、展開の可否 |
| 放熱板 | 面積、放熱効率、展開の可否 |
| エンジン | 対応推進剤、サイクル、推力、比推力、ジンバル可動角、絞り範囲、再着火回数 |
| RCSスラスタ | 推力、対応推進剤、比推力 |

**内装要素（エッジの内容積に収める）**

| 要素 | 主な性能値 |
|---|---|
| 酸化剤タンク | 対応推進剤、容積、断熱等級、要求与圧 |
| 還元剤タンク | 対応推進剤、容積、断熱等級、要求与圧 |
| イナートガスタンク（球状） | 容積、耐圧、充填ガス種別 |
| RCS推進剤タンク | 対応推進剤、容積 |
| バッテリー | 蓄電容量、最大出力 |
| コックピット | 搭乗人数、必要与圧容積 |
| 自動操縦装置 | 計画実行の可否、消費電力 |
| 弾薬庫 | 収納マガジン数 |
| 配管 | 口径、対応推進剤、最大流量 |
| ペイロード倉庫 | 内容積、最大積載質量、開閉の可否 |
| フライホイール | 最大トルク、最大蓄積角運動量、消費電力 |
| 基地モジュール | 格納数、倉庫容量、生産設備 |

**要件の一覧に対する追加** — 上の一覧には、明示的に挙げられていない3つの要素が含まれる。いずれも本文書が実装対象とする機能の成立に必要である。

- **RCSスラスタ** — RCS推進剤タンクを積む以上、それを噴射する推進器が必要である。タンクは内装、スラスタは外装であり、別の要素として扱う。
- **フライホイール** — 「RCSガスを消費しない姿勢制御」という機能そのものである（§5）。
- **分離機構** — 多段ブースターシステム（§7）の成立に必要である。ただしこれは搭載要素ではなくエッジの種別として扱う。分離はエッジの切断であり、ノードに取り付ける物ではないためである。

### 4-2. 内容積の割り当て

`hull` エッジそれぞれの内容積に、プレイヤーが何を収めるかを指定する。そのエッジのロフト体積が上限である。1つのエッジに複数の内装要素を収めてよく、その体積の和が上限を超えないこと。

| 収容物 | 実効容積の係数 | 備考 |
|---|---|---|
| 極低温タンク（液体水素・液体酸素・液体メタン） | 0.85 | 断熱材のぶん減る |
| 常温貯蔵タンク（ヒドラジン・四酸化二窒素・過酸化水素） | 0.95 | |
| イナートガスタンク（球状） | 0.55 | 球をエッジの内容積に詰めるため、球以外の空間が死ぬ |
| RCS推進剤タンク | 0.95 | |
| ペイロード倉庫・弾薬庫 | 0.90 | 容積と最大積載質量の両方で制限される |
| コックピット | 0.80 | 与圧に必要な構造のぶん減る |
| バッテリー・自動操縦装置・フライホイール | 1.00 | |
| 配管 | 口径から決まる | エッジの長さと口径の断面積の積 |

固体モーターはタンクではなく、エッジそのものである。ケースが構造材を兼ねるため、固体モーターを割り当てたエッジは `hull` エッジ1本がモーター1基に対応する。

**イナートガスタンクが球状である理由** — 内圧に対して最も効率のよい圧力容器は球である。同じ耐圧なら球は円筒より薄い壁で済み、タンク自体の質量が小さい。一方、球は角柱状の内容積に詰めたときの充填率が悪い。この対立が実効容積の係数0.55として現れる。

### 4-3. 推進剤の流路

推進剤はタンクからエンジンへ、配管を通って流れる。

```ts
// src/game/vessel/feed-network.ts
export interface FeedNetwork {
  readonly links: readonly FeedLink[];   // 配管が敷かれたエッジ
}
export interface FeedLink {
  readonly edgeId: string;
  readonly propellantId: string;   // この配管が通す推進剤
  readonly maxFlowRate: number;    // kg/s
}
export function resolveFeed(
  network: FeedNetwork,
  tanks: readonly TankPart[],
  engines: readonly EnginePart[],
): readonly EngineFeedResult[];
```

規則:

- 配管は1本につき1種類の推進剤しか通さない。酸化剤と還元剤を同じエンジンへ送るには、配管が2本必要である。イナートガスも同様に別の配管を要する。
- タンクとエンジンが、同じ推進剤の配管で連続して繋がっていることが点火の条件である。繋がっていないエンジンは点火できず、エディタと飛行中HUDがその旨を表示する。
- 配管の口径から決まる最大流量が、エンジンの要求流量（`推力 / (比推力 × 標準重力加速度)`）を下回る場合、エンジンの推力はその流量で制限される。
- タンクとエンジンが同じエッジの内容積に同居する場合、配管は不要である。
- 分離機構のエッジを配管が跨ぐ場合、分離と同時に配管が切断される。跨ぐことを許すかどうかはプレイヤーが選ぶ。跨ぐ配管を敷けば、側面ブースターのタンクから中央のエンジンへ推進剤を送る運用（クロスフィード）ができ、分離時点で中央段のタンクを満載のまま残せる。
- 外皮のない `strut` エッジにも配管を敷ける。この場合、配管は外部に露出したものとして描画する。

### 4-4. タンクの与圧

液体推進剤のタンクは、推進剤を押し出すために内部を加圧する必要がある。加圧にはイナートガス（ヘリウムまたは窒素）を用いる。

- 消費するガス量は、押し出した推進剤の体積とタンクの与圧の積に比例する。
- 要求与圧はエンジンのサイクルによって決まる。**加圧式エンジンは要求与圧が高く、大量のイナートガスを要する。ポンプ式エンジンは低い与圧で足り、ガスの消費が少ない。** この差が、単純な加圧式と、複雑だが効率のよいポンプ式との設計上の対立になる。
- イナートガスが尽きると、推進剤が残っていてもエンジンは推力を失う。これは実機の失敗様態と同じである。
- 極低温推進剤のタンクは、蒸発した推進剤自身の気体を加圧に用いる方式（自己加圧）も選べる。イナートガスが不要になる代わりに、蒸発損失が増える。

計算は純関数として置く。

```
src/physics/pressurant.ts   (純関数)
    pressurantMassFor(propellantVolume, tankPressure, gasType, temperature) -> number
    remainingBurnTime(pressurantMass, flowRate, tankPressure, gasType) -> number
```

### 4-5. 弾薬の供給

武器は弾薬庫からマガジンの供給を受ける。武器と弾薬庫が同じ段に属していれば供給される。段が異なる場合は供給されない。分離によって弾薬庫を失った武器は、装填済みのマガジンを撃ち尽くした時点で沈黙する。

## 5. 推進系

### 5-1. 3つのシステムの役割

| システム | 役割 | 推進剤 | 比推力 | 特性 |
|---|---|---|---|---|
| **主機（EngineBank）** | 軌道変更のための大きな Δv | 液体・固体・ハイブリッド | 265〜450 s | 推力大。始動と停止にコストがある。固体は停止も再着火もできない |
| **並進RCS（TranslationRcs）** | 近接機動・姿勢制御の補助 | 単推進剤または冷ガス | 70〜230 s | 推力小。船体6方向すべてに出せる。応答は即時 |
| **フライホイール（ReactionWheels）** | 姿勢制御のみ | 消費しない（電力のみ） | — | トルク小・連続。**角運動量が飽和する** |

### 5-2. 姿勢トルクの配分

姿勢トルクを要求する主体は、手動操作と自動操縦の2つである。両者は `AttitudeControlSystem` に要求を出し、どのアクチュエータが出すかはそこが決める。

1. 要求トルク τ のうち、各軸でフライホイールが出せるぶんを出す。出せる条件は、そのホイールの最大トルクを超えないことと、蓄積角運動量 `h` が上限 `hMax` に達していないことの両方である。
2. ホイールが τ_wheel を出すと、反作用として角運動量が `h += -τ_wheel · dt` だけ溜まる。同時に電力を消費する。
3. ホイールで出せなかったぶん、および飽和した軸は、RCSスラスタが出す。RCSは推進剤を消費する。
4. `|h|` が `hMax` の既定割合を超えると**アンローディング**を行う。RCSで外部トルクを与えながらホイールを減速し、`h` を外部に捨てる。自動実行を既定とし、手動実行のボタンをHUDに置く。

この規則により、静穏時は推進剤を消費せずに姿勢を保ち、激しい機動の後は必ずRCS推進剤を消費する、という往復が生まれる。RCS残量が戦闘の資源になる。

### 5-3. 並進推力の選択

- 要求方向が主機の推力軸と一致し、要求の大きさがRCSの最大推力を超える場合は主機を使う。
- それ以外はRCSを使う。
- プレイヤーはHUDで「主機を使わない」「主機のみ」を明示的に選べる。

### 5-4. 推力軸と重心のずれ

主機の推力軸が機体重心を通らない場合、その差からトルクが生じる。この効果は正しく計算する。

設計エディタは、主機の合成推力軸と重心のずれを常に表示し、規定値を超える場合は警告する。飛行中は、ジンバル機構を持つ主機がずれを打ち消す方向に首を振り、打ち消しきれないぶんは `AttitudeControlSystem` が補償する。ジンバルを持たない主機のずれは補償されず、機体が回る。

## 6. 推進剤とエンジン

### 6-1. 推進剤の物性表

比推力は真空値、密度は貯蔵状態の値である。

**液体（酸化剤と還元剤のペア）**

| ペア | 真空比推力 [s] | 混合比 O/F | 平均密度 [kg/m³] | 貯蔵 |
|---|---|---|---|---|
| 液体酸素 / 液体水素 | 450 | 5.5 | 360 | 極低温・蒸発損失大 |
| 液体酸素 / 液体メタン | 370 | 3.5 | 830 | 極低温・蒸発損失中 |
| 液体酸素 / シラン | 330 | 3.0 | 900 | 酸化剤のみ極低温・自己着火 |
| 四酸化二窒素 / モノメチルヒドラジン | 320 | 2.0 | 1200 | 常温・長期貯蔵可・毒性 |
| 過酸化水素 / ケロシン | 310 | 7.0 | 1290 | 常温・徐々に分解 |

**単推進剤（RCS向け）**

| 推進剤 | 比推力 [s] | 密度 [kg/m³] | 特性 |
|---|---|---|---|
| ヒドラジン（触媒分解） | 230 | 1010 | 長期貯蔵で徐々に分解。毒性 |
| 過酸化水素（触媒分解） | 160 | 1400 | 無毒。分解が速い |
| 窒素冷ガス | 70 | 高圧貯蔵 | 最も単純。電力も点火も不要 |

**固体・ハイブリッド**

| 種別 | 比推力 [s] | 密度 [kg/m³] | 特性 |
|---|---|---|---|
| 固体（過塩素酸アンモニウム + 末端水酸基ポリブタジエン + アルミ粉末） | 265 | 1800 | 点火後は停止も絞りも再点火もできない |
| ハイブリッド（ABS樹脂 + 亜酸化窒素） | 300 | 1100 | 絞れる・停止できる・再点火できる。密度で不利 |

**イナートガス**

| ガス | 密度（20 MPa, 常温） | 特性 |
|---|---|---|
| ヘリウム | 33 kg/m³ | 軽く、極低温でも凝縮しない。必要質量が小さい |
| 窒素 | 230 kg/m³ | 安価だが重い。極低温推進剤には使えない |

固体推進剤の燃料成分はアルミ粉末であり、酸化アルミニウムはその燃焼生成物である。ABS樹脂はハイブリッドロケットの固体燃料側であり、亜酸化窒素または液体酸素の酸化剤と組み合わせて使う。

**選択の意味** — 固体は安価で高密度、ただし一度きりであり、使い捨ての帰投用ブースターに適する。液体酸素／液体水素は比推力が最も高いが密度が低く巨大なタンクを要し、蒸発損失があるため長期の待機に向かない。ヒドラジン系は性能が中位だが常温で長期間待機でき、軌道上に置いておくブースターに適する。

### 6-2. エンジンの型式

エンジンは「サイクル（供給方式）」と「対応推進剤」の組で定義する。同じ推進剤でもサイクルが違えば性能が変わる。

| サイクル | 比推力係数 | 推力重量比 | 要求与圧 | 絞り範囲 | 再着火 | 特徴 |
|---|---|---|---|---|---|---|
| 加圧式 | 0.95 | 低 | 高 | 40〜100% | 無制限 | 構造が単純で信頼性が高い。タンクを高圧に耐える厚さにする必要があり、タンク質量とイナートガスの消費が増える |
| 電気ポンプ式 | 0.98 | 中 | 低 | 30〜100% | 無制限 | 電力を消費する。バッテリー容量が燃焼時間を制限する |
| ガス発生器サイクル | 1.00 | 高 | 低 | 60〜100% | 数回 | 標準的な性能 |
| 段階燃焼サイクル | 1.04 | 高 | 低 | 50〜100% | 数回 | 比推力が最も高い。エンジン質量とコストが大きい |
| エキスパンダーサイクル | 1.03 | 低 | 低 | 30〜100% | 無制限 | 液体水素専用。推力が小さく、上段に適する |
| 固体モーター | 1.00 | 最高 | 不要 | 不可 | 不可 | 点火後は停止できない。配管も与圧も要らない |
| ハイブリッドモーター | 1.00 | 中 | 中 | 20〜100% | 無制限 | 酸化剤のみタンクに持つ |

エンジン部品の比推力は `推進剤ペアの比推力 × サイクルの比推力係数` とする。推力と質量はサイクルとサイズから決める。ジンバル可動角もサイクルごとに定める。

### 6-3. ツィオルコフスキーによる燃焼計算

燃焼中は推進剤の消費により質量が減り、加速度が上がる。燃焼時間と点火時刻はツィオルコフスキーの式に基づいて求める。

```
src/physics/tsiolkovsky.ts   (純関数)
    dvFor(m0, mf, isp)               // Δv = Isp·g0·ln(m0/mf)
    massAfterBurn(m0, dv, isp)
    burnTimeFor(dv, m0, thrust, isp) // 推進剤流量 = thrust/(Isp·g0)
    propellantForDv(dv, mDry, isp)
```

一定加速度を仮定すると質量比の大きい機体で点火が遅れてマニューバノードを外すため、質量変化を必ず含める。

段の切り替わりを跨ぐ燃焼は加速度が不連続になり閉形式で扱えない。1つのマニューバノードの燃焼が1つの段の中で完結するよう、設計エディタと計画UIで制約する。

### 6-4. 推進剤の劣化

極低温推進剤は日射に応じた蒸発損失を生じ、断熱材の等級と遮蔽で低減できる。ヒドラジン系は触媒毒による自己分解を生じ、時定数は年単位である。固体推進剤とイナートガスは劣化しない。

劣化の計算は毎フレームでは行わず、残量を読む時点で前回の評価時刻からの経過時間に基づいて一括で計算する。

## 7. 多段ブースターシステム

### 7-1. 段の定義

段は、背骨から `decoupler` エッジを取り除いたときの連結成分である。プレイヤーが段を明示的に区切る操作は存在せず、分離機構を挿すと自動的に分かれる。

```ts
// src/game/vessel/assembly.ts
export interface VesselStage {
  readonly id: string;
  readonly edgeIds: readonly string[];
  readonly hasCockpit: boolean;
  readonly hasAutopilot: boolean;
  readonly dryMass: number;
  readonly propellantMass: number;
}
export function splitStages(skeleton: VesselSkeleton, parts: readonly AnyPart[]): readonly VesselStage[];
```

コックピットまたは自動操縦装置を含む段は、分離後も操作または自動制御の対象になる。どちらも含まない段は、分離後は制御不能な物体として軌道上に残る。

### 7-2. 分離の物理

分離は運動量保存を満たす。分離前の質量を `m_total`、分かれる2つを `m_a` / `m_b`、分離機構の力積から求まる相対速度増分を `Δv_sep` とすると、

```
v_a = v + (m_b / m_total) · Δv_sep
v_b = v − (m_a / m_total) · Δv_sep
```

角運動量も同様に分配する。分離直後の一定時間は、分かれた2つの間の接触判定を無効にする。

分離後、本体は背骨・質量・重心・慣性テンソル・推進剤残量・配管の流路を再計算する。分離機構を跨いでいた配管は切断される。

### 7-3. 燃焼の順序

同時燃焼（並列に束ねたブースター）と逐次燃焼（直列の多段）の両方を許す。設計エディタは分離の順序を並べ替えるリストを持ち、飛行中はその順序に従って次に分離する段をHUDに表示する。

推進剤が尽きた段は分離の候補として提示するが、自動では分離しない。分離は軌道を変えるため、実行はプレイヤーまたは計画の判断に委ねる。

### 7-4. ペイロード

ペイロード倉庫は、軌道上へ運ぶものを収める。

```ts
export type PayloadKind =
  | { kind: 'ammo'; magazines: number }
  | { kind: 'propellant'; propellantId: string; mass: number }
  | { kind: 'part'; partIds: readonly string[] }
  | { kind: 'none' };

export interface PayloadBayPart extends Part {
  readonly type: 'payload_bay';
  readonly volume: number;
  readonly maxMass: number;
  payload: PayloadKind;
}
```

**弾薬をペイロードとして運ぶ運用** — 弾薬マガジンを積んだ無人ブースターを、自動操縦装置による自動操縦で目的の軌道に投入する。到達後、ペイロード倉庫を開いて弾薬を放出すると、既存の補給パッケージと同じ実体が軌道上に生成される。艦艇はそれに接近して回収する。

この運用は機体同士の結合を必要としない。放出された弾薬は独立した物体として軌道を回り、艦艇は既存の接近回収の仕組みでそれを取る。

放出は、プレイヤーの明示的な操作、または軌道計画上の指定時刻に行う。放出時には小さな分離速度を与え、ブースター本体と弾薬が離れる。

### 8-1. 設計データ

設計は `localStorage` の `tepui.blueprints` に保存する。保存・読み込み・複製・削除・改名ができる。既存のセーブデータの入出力と同じ方式でファイルへの書き出しと読み込みも行う。

設計の検証は独立した純関数とし、エディタと生産の両方が同じ関数を呼ぶ。

```ts
// src/game/vessel/blueprint-validation.ts
export interface BlueprintIssue {
  readonly severity: 'error' | 'warning';
  readonly targetId: string;
  readonly message: string;
}
export function validateBlueprint(bp: VesselBlueprint): readonly BlueprintIssue[];
```

検証する内容は、背骨が連結していること、複合断面の貼り合わせ面の長さが一致すること、側面の口から出るエッジの断面が口に収まること、内容積の割り当てがロフト体積を超えないこと、コックピットまたは自動操縦装置を1つ以上持つこと、各エンジンに必要な推進剤の配管が繋がっていること、加圧を要するエンジンにイナートガスが供給されていること、武器を持つ段に弾薬庫があること、推力軸と重心のずれが規定内であること、技術ツリーで未解禁の要素を含まないこと、である。

### 8-2. 生産

生産は、保存した設計を指定し、資源とクレジットを消費して実機を得る操作である。

```ts
export interface ProductionTask {
  readonly id: string;
  readonly blueprintId: string;
  readonly startedAt: number;      // simTime
  readonly finishAt: number;       // simTime
}
```

- 生産コストは、搭載要素ごとの単価と、外皮の表面積に比例する構造費の和とする。
- 生産時間は搭載要素の合計から求めるが、**初期状態では係数を0とし、すべての設計が即座に完成する**。時間のかかる生産は仕組みとして用意し、有効にするのは後の判断とする。
- 生産キューは基地モジュールを持つ機体が保持する。完成した機体はその基地の格納庫に配備される。

### 8-3. 技術ツリー

エンジンの型式、断面形状、推進剤、搭載要素は、技術ツリーの解禁によって使えるようになる。

```ts
// src/game/tech/tech-tree.ts
export interface TechNode {
  readonly id: string;
  readonly name: string;
  readonly description: string;
  readonly cost: number;                    // 研究点
  readonly requires: readonly string[];
  readonly unlocks: readonly string[];
}

```

- 研究点は敵の撃破とステージのクリアで得る。保持は `localStorage` の `tepui.tech` に置き、解禁済みの技術 id の集合と研究点の残高を保存する。
- 初期状態で解禁されているのは、円と正方形の断面、加圧式エンジン、四酸化二窒素／モノメチルヒドラジン、ヒドラジン単推進剤、固体モーター、窒素イナートガス、基本的な配管とタンクである。
- 解禁の対象は、断面形状（三角形・五角形・六角形・八角形・切り欠き六角形・切り欠き八角形・楕円）、円の分岐数の増加、複合断面、エンジンのサイクル（電気ポンプ式・ガス発生器サイクル・段階燃焼サイクル・エキスパンダーサイクル・ハイブリッド）、推進剤ペア、ヘリウムイナートガス、フライホイール、ジンバル機構、大口径の配管、大型の分離機構、ペイロード倉庫、ドッキングポートである。
- 未解禁の要素は設計エディタのパレットに表示するが、選択できず、解禁に必要な技術を表示する。

### 9-2. 骨格モード

左パネルの内容:

| 区画 | ウィジェット | 内容 |
|---|---|---|
| 選択中のノード | 一覧 | このノードの接続口。使用中／空きを表示し、空きをクリックすると新規ノードが生える |
| | `Slider` | 断面全体の回転位相（15度刻みのスナップあり） |
| 選択中のエッジ | `SegmentedControl<EdgeKind>` | 外皮／構造材／分離機構 |
| | `ValueInput` | 長さ（0.5 m 単位。増減ボタンは0.5 m刻み） |
| | `ValueInput` | 構造材の場合の半径、分離機構の場合の分離力積 |
| 全体 | `ToggleSwitch` | YZ平面のミラー編集 |
| | `Button` | 選択中のノード以下を削除 |

操作:

- **ノードの追加** — 選択中のノードの空いている接続口をクリックする。既定の長さのエッジと、同じ断面のノードが生える。生えた先が新しい選択対象になる。3Dビューポート上の接続口を直接クリックしても同じ操作になる。
- **ノードの移動** — エッジの長さを変えることで行う。ノードの座標を直接ドラッグする操作は持たない。位置は接続関係と長さから一意に決まる。
- **削除** — 選択中のノードとその先につながる部分をまとめて削除する。削除の前に、削除される範囲を3Dビューポート上で強調表示する。
- **ミラー編集** — 有効な間、YZ平面の片側で行った操作が反対側にも同時に適用される。
- **元に戻す／やり直す** — 設計データ全体のスナップショットを操作ごとに保持する。上限は50手とする。

### 9-3. 断面モード

左パネルの内容:

| 区画 | ウィジェット | 内容 |

| 複合体の構成 | ツリー表示 | 基本断面の木構造。行を選ぶとその基本断面を編集する |

| | `ValueInput` | 外接円半径（0.5 m 単位） |
| | `ValueInput` | 楕円の短半径（楕円選択時のみ） |
| | `SegmentedControl<2|3|4|5|6>` | 円の分岐数（円選択時のみ） |
| | `Slider` | この基本断面の回転位相 |

### 9-4. 搭載モード

左パネルの内容:

| 区画 | ウィジェット | 内容 |
|---|---|---|
| 要素パレット | 種別ごとのアコーディオン | 外装要素と内装要素の一覧。未解禁のものは選択できず、必要な技術を表示する |

左パネルの内容:

| 区画 | ウィジェット | 内容 |
|---|---|---|
| 敷設する配管 | `ObjectPicker` | 通す推進剤の種別（酸化剤・還元剤・RCS推進剤・イナートガス） |

中央のビューポートは配管表示に切り替わり、推進剤の種別ごとに色分けした線を背骨に沿って描く。エッジをクリックすると、そのエッジに選択中の配管を敷設または撤去する。

### 9-6. 段モード

左パネルに、段の一覧を分離順に並べたリストを置く。各行に段の乾燥質量・推進剤質量・その段の Δv・主機の有無を表示し、上下ボタンで分離順を並べ替える。

3Dビューポートは段の色分け表示に固定する。行を選択すると、その段を強調表示する。分離機構を跨ぐ配管がある場合、その配管を別色で表示する。

全段の Δv の積み上げグラフを表示する。各段の Δv はツィオルコフスキーの式により、その段を点火する時点の総質量と、燃焼終了時の総質量から求める。

### 9-7. 塗装モード

左パネルに、基本色・副色・アクセント色のカラー選択、金属感と粗さのスライダー、および既定の配色プリセットを置く。3Dビューポートに即座に反映する。

### 9-8. データの流れ

```
DesignEditorState (エディタの編集中データ、Undo/Redo のスタックを持つ)
    │  編集操作ごとに
    ▼
VesselBlueprint
    ├─► validateBlueprint()        → 左パネルと3Dビューポートの問題表示
    ├─► sectionMoments()           → 断面モードの性能表示
    ├─► deriveMassProperties()     → 右パネルの質量・重心・慣性
    ├─► resolveFeed()              → 配管モードの診断
    ├─► deriveStages()             → 段モードの一覧と Δv
    ├─► deriveProductionCost()     → 右パネルのコスト
    └─► buildLoftMesh()            → 3Dビューポートの外皮表示
```

性能計算は編集操作のたびに実行する。計算はすべて解析式であり、ノードとエッジの数に対して線形であるため、毎操作の実行で問題にならない。外皮メッシュの生成のみ、編集が一定時間止まってから実行する。

### 9-9. 飛行中のHUD

設計エディタとは別に、飛行中に以下のパネルを置く。いずれも個別に折り畳める。

- **推進系** — 主機・並進RCS・フライホイールの3行。主機は推進剤の種別ごとの残量とイナートガス残量、RCSは残量、フライホイールは蓄積角運動量と上限の比をメーターで表示し、飽和が近い場合は警告色にする。
- **段** — 段の一覧、次に分離する段、段ごとの残 Δv。分離の実行ボタン。
- **ペイロード** — ペイロード倉庫の内容と、放出の実行ボタン。

## 12. 主要な技術的リスク

1. **複合断面の輪郭抽出** — 複合断面の外周は、基本断面の輪郭から貼り合わせ面を除いて連結したものである。貼り合わせ面が完全に一致していることが前提であり、浮動小数点の誤差で隙間や重なりが生じると輪郭が破綻する。辺の長さの一致は設計の検証で保証し、輪郭の連結は頂点の同一性ではなく、貼り合わせの木構造をたどって構成する。
2. **断面をまたぐ頂点の対応** — 辺数の異なる断面や、回転位相の異なる断面をつなぐとき、頂点の対応を誤ると外皮がねじれる。120点への等分と、対応距離の総和を最小にする割り当てで解決するが、両端の位相差が大きい場合や、複合断面と単一断面をつなぐ場合の見た目は確認が必要である。
3. **円の弓形差し引き** — 円に複数の側面の口を設けたとき、隣接する弓形同士が重なる場合がある。分岐数が多く、口の幅が広いときに起きる。重なる設計は検証で拒否する。
4. **描画メッシュの生成コスト** — 背骨から生成するメッシュは実行時生成であり、`WebGPURenderer` はジオメトリを最初の描画時にキャッシュする。生成は設計変更時のみとし、既存メッシュのジオメトリを差し替えない運用を守る必要がある。
5. **配管の探索コスト** — 流路の解決は、タンクとエンジンの組ごとにグラフ上の経路を探すことになる。エッジ数に対して線形になるよう、推進剤の種別ごとに連結成分を1度だけ求め、タンクとエンジンが同じ連結成分に属するかで判定する方式にする。
6. **設計の自由度と性能の破綻** — 断面寸法とエッジ長に上限を設けないと、極端に大きな機体が作れてしまう。ノード数・総質量・最大寸法・複合断面の構成要素数に上限を設け、検証で拒否する。
7. **推力軸のずれによる制御不能** — 側面に非対称にブースターを束ねると、推力軸が重心を大きく外れる。設計エディタでの警告と、ジンバル補償の両方が必要である。補償しきれない設計は生産を拒否する。
8. **保存形式の互換性** — 機体の表現が部品の配列から背骨とアセンブリの構造へ変わるため、旧形式の保存データは既定の設計への読み替え以上のことはできない。読み替え不能な保存データは明示的に拒否し、破損した機体を生成しないこと。
9. **UIの総量** — 設計エディタは6つのモードを持ち、飛行中にも3つのパネルが加わる。既存のパネルへ統合できないかを追加のたびに確認し、置き場の規約に従うこと。
