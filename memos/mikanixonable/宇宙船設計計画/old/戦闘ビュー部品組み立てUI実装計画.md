# 運用ビュー・基地ドック部品組み立て UI 実装計画

## 1. 目的

基地の運用ビューにあるドック区画で、宇宙船へ部品を取り付け・取り外し・交換できる UI を追加する。

宇宙船の組み立ては基地のドック区画でのみ行う。宇宙空間、通常の運用画面、戦闘中の画面、基地のドック外では部品構成を変更できない。ドック区画を開いている間はシミュレーションを一時停止し、確定操作の後に質量・慣性・推力・電力・通信・生存性を再計算する。

従来の「戦闘ビュー」という名称は廃止する。この画面は航行、戦闘、回収、接近、ドッキング、基地への出入りを扱うため、以後は「運用ビュー」と呼ぶ。

## 2. 現状認識

既存コードには、UIを接続するための基盤がある。

- `src/game/vessel/assembly-mode.ts`
  - 部品の取り付け可否、接続条件、取り外し条件を検証する。
- `src/game/vessel/vessel-parts.ts`
  - 部品種別と部品データを定義する。
- `src/game/vessel/vessel-assemblies.ts`
  - 既定艦の部品構成を持つ。
- `src/game/vessel/mass-properties.ts`
  - 構成変更後の質量、重心、慣性テンソルを算出する。
- `src/game/hud/base-view.ts`
  - 基地内での部品確認、修理、補給、倉庫部品との換装を行う。
- `src/game/hud/property-window.ts` / `context-menu.ts`
  - 運用ビュー上の対象選択と操作メニューに再利用できる。

一方、運用ビューと基地ドックには次の機能がまだない。

- 部品スロットまたはハードポイントの選択 UI
- パーツ個別のプロパティーウィンドウ
- 部品の装着プレビュー
- 部品交換を確定・取り消しするトランザクション
- ドックで確定した構成を運用中の艦状態へ反映する経路
- 作業中の資源・電力・姿勢・推進制約の表示

## 3. 船と貨物の分類

### 3.1 コア部品

船は、一つ以上のコア部品を持つ構成として定義する。

- 有人コックピット
- 自動操縦装置

コア部品を一つ以上持つ構成は、単独で操作可能な宇宙船である。両方を持つ構成も許可する。

### 3.2 貨物

コア部品を一つも持たない構成は「船」ではなく「貨物」として扱う。

- 貨物は単独では操作対象にできない。
- 貨物はドッキングできる。
- 貨物は牽引・輸送される対象になれる。
- 貨物は基地のドックへ収容できる。
- コア部品を取り付けると、適用後に操作可能な宇宙船へ昇格する。
- すべてのコア部品を外すと、適用後に貨物へ降格する。

この分類は表示ラベルだけでなく、操作対象選択、自動操縦、ドッキング、セーブ、基地ドックの一覧で共通して使う。

## 4. 初期仕様

### 4.1 開始方法

運用ビューで基地を選択し、基地のドック区画に入ってから、格納中の宇宙船または貨物を選択して開く。

1. 運用ビューで基地を選択する。
2. 基地へドッキングする、または基地のドックへ入る。
3. 基地の「ドック」区画を開く。
4. 格納済みの宇宙船または貨物を選択する。
5. 「組み立て・整備」を選択する。

飛行中、戦闘中、ドック外の対象には組み立て入口を表示しない。運用ビュー上の右クリックメニューから直接組み立てを開始する経路も作らない。

### 4.2 開いている間の状態

- 物理シミュレーション、推力、射撃、姿勢制御、時間加速を停止する。
- カメラの回転・ズームは許可する。
- UI外クリックでは閉じない。変更中の構成を失わないため、閉じる操作は「適用」「破棄」「キャンセル」に限定する。
- `Esc` は未保存変更があれば確認表示を出し、変更がなければ閉じる。
- 機体が破壊された、ドッキング状態が解除された、または対象が消失した場合は編集を破棄して閉じる。

### 4.3 画面構成

運用ビューを背景に残したまま、基地ドック用の次の3領域を重ねる。

```text
┌──────────────────────────────────────────────┐
│ 整備・組み立て          [適用] [破棄] [閉じる] │
├──────────────┬────────────────┬──────────────┤
│ 部品一覧       │ 艦体プレビュー   │ 選択部品情報   │
│ ・船体         │ ・選択ハイライト │ ・性能差分     │
│ ・主機         │ ・装着位置       │ ・必要資源     │
│ ・RCS          │ ・未装着ゴースト │ ・制約/警告     │
│ ・タンク       │                  │ ・交換/取外し  │
└──────────────┴────────────────┴──────────────┘
```

左側には倉庫にある装着可能部品を表示する。中央では艦の接続点を選択し、右側で現在部品・候補部品・差分を比較する。

パーツ個別のプロパティーウィンドウを用意する。完成済みの艦に搭載されたパーツだけでなく、組み立て途中の仮構成に存在するパーツにも同じウィンドウを適用する。仮構成のパーツには「仮構成」「未適用」を明示し、実機へ反映済みの値と混同させない。

表示項目は、パーツ名・種別・個体ID・状態、質量・容積・取付位置・接続先、HP・損傷、推力・トルク・電力・発熱・通信・弾薬・燃料などの固有性能、現在値と仮構成適用後の差分、交換・取り外し・仮装着操作、適用不可の理由とする。既存の `PropertyWindow` のドラッグ、フォーカス、ESCの仕組みを再利用するが、ウィンドウを閉じても編集セッションと仮構成は維持する。

## 5. 操作仕様

### 5.1 接続点の選択

- 艦体をクリックして最寄りのハードポイントを選択する。
- 選択中の接続点をオレンジ色で表示する。
- 接続不可の点は表示するが、候補部品を装着できない理由を提示する。
- 画面上で選びにくい小型部品には、選択中の接続点一覧を併設する。

### 5.2 部品の装着

- 左の部品一覧から部品をクリックする。
- 中央にゴースト表示し、装着後の外形と干渉を表示する。
- 右側に、質量、重心、慣性、推力、トルク、電力、放熱、通信、弾薬、HPの差分を表示する。
- `装着` を押すと編集用の仮構成へ反映する。
- 倉庫部品は仮構成へ移すだけにし、資源消費と在庫確定は「適用」時に行う。

### 5.3 交換・取り外し

- 既存部品を選択すると「交換」「取り外し」を表示する。
- 交換は旧部品を倉庫へ戻し、新部品を仮構成へ移す。
- 取り外しは、必須部品の欠落や接続グラフの分断がない場合だけ許可する。
- 取り外し後に操作不能となる構成、主機・タンク間の配管断絶、制御系喪失などは適用不可とする。

### 5.4 パーツプロパティーウィンドウ

- 完成済みの搭載パーツをクリックすると、そのパーツのプロパティーウィンドウを開く。
- 組み立て途中の仮装着パーツをクリックしても、同じプロパティーウィンドウを開く。
- 仮構成のパーツには「仮装着」「取り外し予定」「交換前」「交換後」などの状態を表示する。
- 現在の実機値と、仮構成を適用した場合の予測値を区別して表示する。
- ウィンドウから交換・取り外し・仮装着を実行できる。
- ウィンドウを閉じても編集セッションは継続する。
- パーツが仮構成から削除された場合は、該当ウィンドウを閉じて選択状態を解除する。

### 5.5 確定と取消

- `適用`: 検証を再実行し、成功した場合だけ艦・倉庫・資源を一括更新する。
- `破棄`: 編集開始時の艦構成と在庫へ戻し、何も変更しない。
- `閉じる`: 未保存変更がなければ閉じる。変更があれば `適用 / 破棄 / キャンセル` を選ばせる。
- 適用中に失敗した場合は、艦構成・倉庫・資源のいずれも変更しない。

## 6. データ設計

### 6.1 編集セッション

`AssemblySession` を新設し、UIが直接 `Vessel` を変更しないようにする。

```ts
interface AssemblySession {
  readonly vesselId: string;
  readonly objectKind: 'vessel' | 'cargo';
  readonly originalParts: readonly Part[];
  readonly originalInventory: readonly Part[];
  draftParts: Part[];
  draftInventory: Part[];
  selectedSlotId: string | null;
  selectedPartId: string | null;
  selectedPropertyPartId: string | null;
  propertyWindowMode: 'live' | 'draft';
  readonly warnings: string[];
  readonly dirty: boolean;
}
```

実際の型は既存の `Vessel`、`Part`、接続グラフの表現に合わせる。`originalParts` と `originalInventory` は編集開始時のスナップショットとして保持する。

パーツ個体の `id` が存在しない既存部品にも対応するため、プロパティーウィンドウの選択キーは単純なパーツ種別ではなく、編集セッション内で生成する安定した `partRef`（搭載スロットまたは倉庫エントリを含む）とする。仮構成で部品を交換しても、旧部品と新部品のウィンドウを取り違えないようにする。

### 6.2 適用処理

適用は次の順序で行う。

1. 仮構成の接続・必須部品・コア部品・干渉を検証
2. 生産・倉庫・資源の必要量を算出
3. 資源・設備・電力の不足を確認
4. 新しい質量特性とアクチュエータ集合を算出
5. 宇宙船または貨物の実行時状態へ反映
6. 倉庫と資源台帳を更新
7. HUD、カメラ、ナビゲーション情報、サウンドを更新

1〜4のどこかで失敗した場合、5以降は実行しない。

## 7. 実装フェーズ

### Phase 1: 整備セッションと適用トランザクション

- `AssemblySession` を実装
- 現在の艦構成・倉庫のスナップショットを取得
- 仮構成を検証するサービスを追加
- 実機パーツと仮構成パーツの両方を参照できるプロパティー表示モデルを追加
- 適用・破棄・再編集をユニットテスト
- 適用失敗時に状態が変化しないことをテスト

### Phase 2: 運用ビューの名称整理と基地ドック入口

- 表示名、ヘルプ文、ヒント、状態ラベルの「戦闘ビュー」を「運用ビュー」へ変更
- 基地ドック区画に組み立て入口を追加
- 飛行中・戦闘中・基地ドック外からの組み立て入口を出さない
- `ViewManager` と `Docking` の停止・再開経路を再利用または整理
- 整備中の射撃、推力、姿勢制御、時間加速を確実に無効化
- `Esc`、外側クリック、対象消失時の扱いを実装

### Phase 3: コア部品と貨物分類

- 有人コックピットと自動操縦装置をコア部品として定義
- 仮構成にコア部品が一つ以上あるかを検証
- コアなしの構成を貨物として表示し、操作対象・自動操縦対象から除外
- 貨物のドッキング、牽引、基地収容を許可
- コア追加による貨物から宇宙船への昇格を反映
- コア除去による宇宙船から貨物への降格を反映

### Phase 4: 2Dの最小UI

- 部品一覧、接続点一覧、選択部品情報を実装
- 実機パーツと仮構成パーツを同じパーツプロパティーウィンドウで表示
- 仮構成、未適用、適用後予測値を明示
- プロパティーウィンドウから交換・取り外し・仮装着を実行
- まずはクリック選択とボタン操作だけで装着・交換・取り外しを可能にする
- 既存の `Button`、`TabBar`、`PropertyWindow`、`OverlayManager` を再利用
- キーボードフォーカス、Tab循環、スクリーンリーダー用ラベルを追加

### Phase 5: 3Dプレビュー

- 部品選択に連動するハイライト
- 装着予定部品のゴースト表示
- 接続点・干渉・外形変化の可視化
- 既存の船体メッシュ・部品描画を再利用

### Phase 6: 性能差分と運用接続

- 質量、重心、慣性テンソル、推力、トルク、電力、放熱、通信、HPの差分表示
- 変更後の操縦性能をHUDへ反映
- 修理・補給・生産と同じ資源台帳へ接続
- セーブデータへの保存とロード

### Phase 7: 操作性改善

- ドラッグ＆ドロップ
- 部品種別フィルタ
- 接続可能部品だけの絞り込み
- 変更履歴と一手戻す/やり直す
- 部品構成を設計図として保存

## 8. 受け入れ条件

- 運用ビューから基地へ入り、基地のドック区画でだけ組み立て UI を開ける。
- 飛行中、戦闘中、基地ドック外では組み立て UI を開けない。
- 表示名に「戦闘ビュー」を使用せず、「運用ビュー」と表示する。
- UIを開いている間、対象が発砲・推進・姿勢変更しない。
- 倉庫部品を選択して、仮構成へ装着・交換・取り外しできる。
- コア部品なしの構成は貨物として表示され、単独の操作対象にできない。
- コア部品を一つ以上持つ構成は宇宙船として操作対象にできる。
- 貨物は単独操作できないが、ドッキングと基地収容ができる。
- 搭載済みパーツと組み立て途中の仮構成パーツの双方に、個別プロパティーウィンドウを開ける。
- 仮構成パーツのプロパティーには、実機値と適用後の予測値が混同しない形で表示される。
- プロパティーウィンドウを閉じても仮構成の編集内容が保持される。
- 必須部品欠落、コア部品欠落、接続グラフ分断、干渉、資源不足、電力不足を適用前に表示できる。
- 適用成功時だけ宇宙船または貨物の実行時性能と倉庫が更新される。
- 適用失敗、破棄、キャンセルでは対象・倉庫・資源が元の状態を保つ。
- UIを閉じて運用へ戻ると、HUDとシミュレーションが正常に再開する。
- セーブして再ロードしても部品構成が一致する。
- 既存の基地ビューでの修理・補給・換装・新造を壊さない。

## 9. 注意点と未決定事項

### 運用中に編集可能とする範囲

初期版では「運用ビューから基地ドックへ入り、編集時は一時停止」とする。基地ドック外でのリアルタイム交換は行わない。

### 外部に露出した部品の見た目

既存の部品メッシュがすべて交換可能な表示に対応しているとは限らない。Phase 4では2D表示を先に成立させ、3Dゴーストは部品ごとに段階導入する。

### 実行中物理状態の反映

質量や慣性の変更は、単に表示値を書き換えるだけでは不十分である。適用時の速度・角速度・角運動量をどう保存するかを決める必要がある。

- 並進速度は維持する
- 姿勢は維持する
- 角運動量を維持するか、角速度を維持するかは仕様決定が必要

初期案では、プレイヤーの納得しやすさを優先して並進速度・姿勢・角速度を維持し、新しい慣性テンソルを次の物理ステップから使う。

### 基地ビューとの共通化

部品の修理・補給・倉庫換装・組み立ては、運用ビュー専用に複製せず、基地ドックと共通のサービス層へ切り出す。UIだけを分け、検証・コスト計算・在庫更新・実行時反映は共通化する。

## 10. 推奨する最初の実装単位

最初から3Dの自由配置を作らず、次の最小縦切りを実装する。

1. 運用ビューから基地ドックへ入り、格納中の宇宙船または貨物の整備UIを開く
2. 現在の部品スロットを一覧表示する
3. 倉庫の同種部品を1つ選び、交換候補として表示する
4. 適用前に差分と検証結果を表示する
5. 適用・破棄・Escキャンセルを実装する
6. 適用後に宇宙船または貨物の性能と倉庫を更新する

## 11. レビュー結果

### 11.1 計画に反映済みの判断

- 組み立て場所を基地ドックに限定し、運用ビュー上の飛行中・戦闘中編集を排除した。
- 画面名称を「運用ビュー」へ変更し、戦闘以外の航行・回収・接近・ドッキングを含む責務に合わせた。
- コア部品の有無を、表示上の分類だけでなく操作対象・自動操縦・ドッキング・セーブに関係するドメイン状態として扱う方針を追加した。
- 実機パーツと仮構成パーツで同じプロパティーウィンドウを使い、実機値と適用後予測値を明確に分ける方針を追加した。

### 11.2 実装時に特に注意する点

- 既存のパーツに個体IDがない場合があるため、プロパティーウィンドウの参照はパーツ種別ではなく、搭載スロット・倉庫エントリを含むセッション内参照キーで管理する。
- プロパティーウィンドウを閉じても仮構成を維持する。外側クリックやESCを、編集セッションの破棄と混同しない。
- コア部品の追加・除去により、対象が宇宙船から貨物、または貨物から宇宙船へ変わる。適用後の操作対象、HUD、ドッキング可否、セーブ形式を同一トランザクションで更新する。
- 基地ドックへの入口、運用ビューの名称変更、パーツプロパティーウィンドウは別々のUI実装に見えるが、適用処理と検証サービスは共通化する。

### 11.3 残る仕様決定

- コア部品を複数持つ場合の操作権限（有人操作、自動操縦、切り替え）
- 貨物をドック内で組み立てる際の操作対象表示と名称規則
- 仮構成パーツの性能値を、現在値・仮構成値・差分の3列で出すか、切替表示にするか
- パーツの損傷・燃料・弾薬など個体状態を交換時に保持するか、倉庫部品の状態へ置き換えるか

## 12. 3D部品集合化とドック作業台

### 12.1 コードベース調査結果

現在の実装は、データ面では部品集合化の途中まで進んでいる。

- `VesselAssembly` は `VesselTree` と `PartPlacement[]` を持ち、配置された `AnyPart` から質量特性、接触形状、能力を導ける。
- `VesselBlueprint` は形状ツリー、部品配置、流路、塗装、分離順を保存できる。
- `buildHullMesh(assembly)` は船体外皮を生成し、外装部品を取付位置へ配置する。ブループリント由来の船はこの経路を使う。
- `assembly-mode.ts` には部品の生産コスト、接続可否、形状ツリー作成など、組み立てに使える純粋ロジックがある。3DスナップはUI側の責務として残されている。
- `BaseView` は搭載部品の修理、同種部品との換装、倉庫表示を提供するが、分解や自由な配置は行わない。
- `Vessel.attachDockedVesselMesh()` はドックに収容した船の完成済み `renderObject` を基地の子オブジェクトにするだけで、ドック内の部品作業台にはなっていない。
- `buildBaseModel()` は中央ハブ、トラス、ドック、タンク、貨物、バルブ、ストラップなどを一つの大型固定モデルとして生成する。基地の `orbitalBaseAssembly()` は存在するが、現状の基地描画には直接使われていない。

したがって、船は「論理部品集合から描画する」経路を持つが、基地は「論理部品集合と固定3Dモデルが二重化」している。今回の要件では、基地も船も、同じ部品配置を正本として3D描画するよう統一する必要がある。

### 12.2 目標アーキテクチャ

`VesselAssembly` を、データ・物理・3D描画・ドック作業台の共通の正本にする。

```text
Assembly / Blueprint
        │
        ├─ PartPlacement と VesselTree
        ├─ 質量・慣性・能力・接触形状
        ├─ PartVisualFactory → 部品ごとの THREE.Object3D
        └─ DockWorkbench → 選択・ドラッグ・スナップ・仮配置
```

新設または拡張する主な層:

- `PartVisualFactory`
  - `AnyPart` と配置コンテキストから、部品単位の `THREE.Object3D` を生成する。
  - 部品の選択ID、部品種別、仮構成状態を `userData` に付与する。
  - 既存 `hull-mesh.ts` の `placeFitting`、パネル生成、ドッキングポート描画を段階的に移す。
- `AssemblyRenderObject`
  - 外皮、トラス、内装・外装部品を部品ID単位の子ノードとして保持する。
  - 配置変更時は該当部品だけを差し替えるか、WebGPUの制約に合わせて安全に全体再生成する。
- `BaseAssembly`
  - 現在 `buildBaseModel()` に埋め込まれているハブ、トラス、ドック、居住区、タンク、貨物、太陽電池、配管を、`VesselTree` と `PartPlacement[]` へ移す。
  - 固定モデルは互換表示または移行用フィクスチャとして残し、新規生成経路では使わない。
- `DockWorkbenchSession`
  - ドック内で完成品を分解し、部品を作業台・倉庫へ移し、他の対象へ仮配置するトランザクションを管理する。
  - 実機の `Vessel` を直接変更せず、船体、基地、倉庫のスナップショットを保持する。

### 12.3 部品単位の3Dモデル化

すべての部品種別について、少なくとも次の描画契約を定義する。

```ts
interface PartVisualContext {
  readonly placement: PartPlacement;
  readonly selected: boolean;
  readonly preview: boolean;
  readonly invalidReason: string | null;
}

interface PartVisual {
  readonly partRef: string;
  readonly object: THREE.Object3D;
  update(context: PartVisualContext): void;
  dispose(): void;
}
```

実装順は、船体ノード・トラス・コックピット・主機・RCS・タンク・ドッキングポート・基地モジュール・ドック・貨物から始める。太陽電池、放熱器、武装、生活設備、装飾はその後に移行する。

部品化に伴い、現在基地モデル内のオレンジ色のバルブ、貨物固定ストラップ、識別タグも、装飾として基地固定モデルへ残すのではなく、対応するタンク・貨物・設備部品の子モデルまたは個別部品として分類する。

### 12.4 ドック作業台の操作

基地のドック区画に、完成品を分解・組み立てる3D作業台を設ける。

1. ドック内の対象（宇宙船、貨物、基地モジュール）を選択する。
2. 部品をクリックして個別プロパティーウィンドウを開く。
3. 部品をドラッグすると、作業台上のゴーストへ移す。
4. 接続可能なスロット、面、エッジをハイライトする。
5. スナップ位置で離すと仮構成へ移動する。
6. 倉庫または別のドック対象から部品をドラッグして、選択中の対象へ仮装着する。
7. `適用` で検証・在庫更新・3D再生成・物理特性再計算を一括実行する。

部品を対象の外へドラッグした場合は、分解候補として扱う。分解先は作業台または基地倉庫であり、宇宙空間へ直接放出する操作は初期版では提供しない。

### 12.5 換装と分解のトランザクション

仮編集状態では、次の操作を同じセッション内で組み合わせられる。

- 船Aから部品を外して倉庫へ送る
- 基地または倉庫から部品を船Aへ装着する
- 船Aの部品を船Bへ移す
- 基地のドック部品を貨物へ装着する
- コア部品を追加して貨物を宇宙船へ昇格する
- コア部品をすべて外して宇宙船を貨物へ降格する

適用前に、対象ごとに次を検証する。

- 接続グラフ、断面、長さ、位相、作業範囲
- 必須部品とコア部品
- 配管、電力、通信、熱、推進、姿勢制御
- ドックの容量、作業台の許容量、部品の物理的干渉
- 部品の所有権と二重使用
- 搭載中の損傷、燃料、弾薬、状態値の引き継ぎ

すべての対象の検証が成功した場合のみ、倉庫、船、基地、資源台帳、セーブデータを一括更新する。失敗時は全対象を元に戻す。

### 12.6 追加実装フェーズ

既存のPhase 5以降に、次を追加する。

#### Phase 5a: 部品描画契約と船の分解可能な描画

- `PartVisualFactory` と `AssemblyRenderObject` を追加
- 船体・トラス・外装部品を部品ID単位の子オブジェクトへ分離
- 既存 `buildHullMesh` の見た目と質量・当たり判定を維持
- 部品選択と個別プロパティーウィンドウを3D子オブジェクトへ接続

#### Phase 5b: 基地モデルのアセンブリ移行

- ドック、ハブ、トラス、タンク、貨物、バルブ、ストラップを個別選択可能にする
- 固定モデルと新モデルを並べた回帰比較を用意する

#### Phase 6a: ドック作業台のドラッグ配置

- ドック区画専用のカメラ・作業平面・レイキャストを追加

#### Phase 6b: 分解・換装の適用サービス

- 複数対象を扱う `DockWorkbenchSession` を実装

#### Phase 7a: 操作性と復旧

- 作業台からの復帰、対象消失、保存失敗時のロールバック
- 大量部品を持つ基地の描画負荷と選択精度の最適化

### 12.7 追加受け入れ条件

- 船と基地が、同じ部品配置データから部品単位の3D子オブジェクトを生成する。
- 船体・基地の主要部品を3D上で個別選択できる。
- 基地固定モデルに埋め込まれていたドック、タンク、貨物、バルブ、ストラップを対応部品として扱える。
- ドック区画でのみ、部品を3Dドラッグして仮配置・換装できる。
- 完成済みの船から部品を外して、基地倉庫または作業台へ分解できる。
- 分解した部品を別の船、貨物、基地の組み立てに使える。
- 同じ部品を複数対象へ同時に割り当てられない。
- 分解・換装・組み立ての適用前に、全対象の接続・コア・資源・物理制約を検証できる。
- 適用成功時だけ、3Dモデル、論理部品、質量特性、倉庫、セーブデータが一致して更新される。
- 適用失敗やキャンセル時に、すべての対象と倉庫が変更前へ戻る。

## 13. ノード・エッジ・外皮の操作と表示

### 13.1 既存の形状表現

現在の形状表現は次の型で実装されている。

- `src/game/vessel/tree.ts` の `TreeNode` は、断面、位置、軸、位相を持つ面である。
- `TreeEdge` は2つのノードを結ぶ区間で、`hull`、`truss`、`decoupler` の種別を持つ。
- `MountPoint` はノードの接続口、`hull` エッジ外表面、トラス上の位置を表す。
- `src/game/vessel/assembly.ts` の `PartPlacement` は、部品を外装位置または内容積へ割り当てる。
- `VesselBlueprint` はツリーと部品配置を保存できる。

したがって、ノードとエッジは単なる描画用メッシュではなく、質量・慣性・内容積・接触形状・搭載位置を導く設計データである。

### 13.2 組み立て中の操作方法

組み立てUIでは、ノードとエッジを最初から数値入力で直接編集するのではなく、部材の突き合わせ結果として生成する。

- 棚から外皮区間、トラス区間、分離機構、搭載部品の3D部材をドラッグする。
- 既存部材の空いている接続口をハイライトする。
- 部材を接続口へ近づけると、断面、位相、長さ、作業範囲を判定してスナップ候補を表示する。
- ドロップして確定すると、部材の両端の口の対からノードを生成し、部材自身からエッジを生成する。
- プレイヤーがノードを自由移動する操作は提供しない。ノードは接続の結果として立つ。
- エッジの長さ、断面、種別は生産した部材の属性で決まり、配置後に任意変形しない。
- 閉じた構造では最後の部材の両端を同時に検証し、長さ・断面・位相が合わない場合は吸着を拒否する。

この方式により、ノードは接続点、エッジは実物の構造部材という意味を保ち、設計データの `treeFromDraft()` へ変換できる。

### 13.3 外皮の表示方法

- `hull` エッジは両端の断面をロフトした外皮帯として描画する。
- 外皮が連続しない露出端は端面で蓋をする。
- `truss` エッジは内容積を持たないため、外皮帯ではなく骨組みとして描画する。
- `decoupler` エッジは外皮を作らず、分離境界と接続部品として表示する。
- 部材を掴んでいる間は、配置先の候補を色付きのゴーストで表示する。
- 検証エラーの対象となったノード、エッジ、部品は赤系の強調表示にする。
- 仮構成の外皮は実機と区別できる半透明または輪郭表示とし、適用前の予測であることを示す。
- 完成後は `Mesh` のジオメトリを直接差し替えず、形状変更時に安全なメッシュ単位で再生成する。

### 13.4 パーツプロパティーウィンドウとの関係

- 外から見える外装部品、ノード、エッジは3D上でクリックできる。
- 内装部品は直接見えないため、収容している `hull` エッジのプロパティーから一覧・選択する。
- ノードのプロパティーには断面、軸、位相、接続口を表示する。
- エッジのプロパティーには種別、長さ、両端ノード、内容積、外皮/骨組みの状態を表示する。
- 部品のプロパティーウィンドウには取付位置、接続先、性能、仮構成値、交換・分解操作を表示する。
- 仮構成中のノード・エッジ・部品にも同じウィンドウを使い、「仮構成」「未適用」を明示する。

### 13.5 既存実装の再利用範囲

このUIは全面的な作り直しではなく、次の既存実装を利用する。

| UI/機能 | 再利用する既存コード | 状態 |
|---|---|---|
| ノード・エッジの形状 | `tree.ts`、`assembly.ts`、`treeFromDraft()` | 基盤あり。3D編集への接続が未実装 |
| 外皮生成 | `hull-shape.ts`、`hull-triangles.ts`、`loft-mesh.ts` | 船で実装済み。基地移行が必要 |
| 外装部品配置 | `hull-mesh.ts` の `mountFrame` / `placeFitting` | 部分実装。選択ID・仮表示を追加 |
| 構成検証 | `blueprint-validation.ts`、`assembly-mode.ts` の `mateVerdict` | 純粋な検証基盤あり |
| 質量・慣性 | `mass-properties.ts`、`hull-structure.ts` | 実装済み。仮構成の再計算へ接続 |
| UI部品 | `PropertyWindow`、`Button`、`TabBar`、`OverlayManager` | 再利用可能 |
| ドック収容 | `Vessel.attachDockedVesselMesh()` | 完成品の表示のみ。作業台へ拡張 |
| 基地3Dモデル | `buildBaseModel()` | 固定モデル。部品集合描画へ移行が必要 |

結論として、ノード・エッジ・外皮のデータモデル、外皮生成、検証、質量計算は既存の部分実装を利用できる。新規に必要なのは、部材の3D個体化、レイキャストとスナップ、部品単位の描画ID、基地の固定モデル移行、複数対象の分解・移送トランザクションである。

この縦切りで、入力停止、状態トランザクション、既存資源・部品ロジックとの接続を先に検証できる。3Dプレビューやドラッグ操作は、その後に追加する。
