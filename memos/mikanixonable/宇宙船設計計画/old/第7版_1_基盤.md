# 基盤 — 機体の実体・形状・物理・推進系

この文書は、宇宙船という物がどう成り立っているかを定める。プレイヤーが機体を設計し、建造し、運用する仕組みは第2巻『設計・建造・資源』が定める。

対象は以下の6つである。

1. 艦艇と軌道基地を単一の実体 `Vessel` に統合する（§4）
2. 搭載要素の型と性能値を定義する（§5）
3. 断面と背骨による形状の定義と、その幾何量の計算（§6〜§9）
4. 形状からの質量特性の導出、カプセルによる接触形状、姿勢依存の空力（§9〜§11）
5. 主機・並進RCS・フライホイール・磁気トルカを分離した推進系と姿勢制御系（§13）
6. 推進剤の種別と、実データに基づくエンジン性能、質量変化を含む燃焼計算（§14）

**この文書は他のどの計画にも依存しない。** ここで定義した実体・形状・搭載要素・推進剤は、そのまま第2巻が土台として使う。

**第2巻との関係** — 第2巻は、プレイヤーが背骨を組んで設計を作り、保存し、資源を消費して生産し、配管を敷き、段に分け、基地を運用し、資源の連鎖を広げる仕組みを定める。本文書は「機体がどう成り立っているか」までを扱い、「プレイヤーがどう作るか」には踏み込まない。したがって本文書の段階では、機体は**既定の設計**として1つ与えられるものであり、それを編集する手段はまだない。

---

## 1. 対象外

設計エディタ、設計の保存と検証、生産と生産可能性、資源と設備の連鎖、推進剤の配管、タンクの与圧、分離機構による多段化、ペイロードの投入、基地モジュールの運用は本文書の対象外である。月面着陸、月面基地、資源採掘、ドッキングポートによる機体の結合、人員も対象外である。

推進剤ごとに定めるタンク材料の要求（§14-1）は物性として登録するにとどめ、その材料が入手できるかどうかの判定は行わない。エンジンのサイクルごとに定める要求与圧（§14-2）も、性能値として定義するにとどめ、イナートガスの消費としては働かない。

## 2. 設計判断

### 2-1. 実体は `Vessel` 一種類のみとする

艦艇と軌道基地を別のクラスとして持たない。両者はいずれも「部品が載った物体」であり、物理的な差は積んでいる部品だけである。「これは基地か」という判定は存在せず、部品の有無から導かれる能力だけを問う。

### 2-2. 質量特性は2つの経路から与えられる

`Vessel` は「搭載要素と形状から質量特性を導出する機体」と「`MassProperties` を直接与えられた機体」の両方を扱う。前者は自勢力の設計した機体であり、後者は敵艦である。敵艦は背骨を持たず、種別ごとに定めた質量・重心・慣性テンソルをそのまま受け取る。`Vessel` の側から見れば、質量特性は「導出された値か、与えられた値か」の別なく同じ1つのフィールドである。

### 2-3. 船体は背骨と断面で定義する

宇宙船の形状は、**ノードとエッジからなる背骨**と、**各ノードが持つ断面**で定義する。外皮は、エッジの両端にある2つの断面をつないだ立体（ロフト）として生成する。

エッジから外皮までの距離は定数ではなく、両端のノードの断面寸法によって決まる。したがって、細い部分と太い部分を持つ機体、先細りの機体、段ごとに直径の異なるロケットが、追加の機構なしに作れる。

### 2-4. 断面が分岐方向を決める

各ノードは、断面の表裏に向かう2つの軸方向の接続口と、断面形状ごとに決まる側面の接続口を持つ。側面の口の方向は断面が決め、各ノードが持つ回転位相ぶん回る。

- **多角形の断面** — 各辺の外向き法線の方向に口を持つ。三角形なら3方向、八角形なら8方向である。
- **円の断面** — 分岐数 n を 2・3・4・5・6 から選び、360度を n 等分した方向に口を持つ。分岐数2なら0度と180度、分岐数3なら0度と120度と240度である。
- **楕円の断面** — 長軸の正負2方向に口を持つ。

分岐の角度を数値で指定する操作は存在しない。角度は断面形状と分岐数と回転位相から決まる。

### 2-5. 結合はすべて平面同士の突き合わせとする

エッジと断面の結合、側面分岐の結合、および断面を組み合わせて複合断面を作るときの結合は、いずれも平面同士の突き合わせとする。曲面同士を滑らかに融合させる処理も、立体同士の重なりを差し引く処理も行わない。

この判断により、外皮の体積・表面積・重心・慣性テンソルがすべて解析式で求まり、部分同士が重なることもない。数値積分も、等値面の三角形分割も不要である。実際のロケットも、段間部と側面ブースターの取り付けはフランジ結合であり、工学的にも自然である。

円の断面に側面の口を設ける場合のみ、その方向の円弧を弦で切り落として平面を作る。切り落としによる断面積と断面二次モーメントの減少は、弓形の解析式を差し引いて厳密に計算する。

### 2-6. 寸法は離散値とする

エッジの長さは 0.5 メートル単位で指定する。断面の外接円半径は、**2.0 メートル未満では 0.25 メートル単位、2.0 メートル以上では 0.5 メートル単位**とする。

半径の刻みを長さより細かくするのは、半径が体積に二乗で効くためである。半径 1.0 メートルのタンクを 1.5 メートルにすると体積は 2.25 倍になり、小型の機体では 0.5 メートル刻みは粗すぎる。大型の機体では相対的な粒度が十分に細かいため 0.5 メートルで足りる。

連続値にしないのは、対称な機体や、断面の揃った段を組むことが困難になるためである。

### 2-7. 物理量は形状から導出する

質量・重心・慣性テンソル・投影面積は定数として持たず、背骨と断面と搭載物から導出する。扁平な機体は実際に回りにくく、非対称な機体は実際に重心がずれる。

### 2-8. 接触形状はカプセルの集合とする

剛体接触と被弾の判定は、機体を1つの球で表すのではなく、**背骨の各エッジに対応するカプセルの集合**で行う。全長数十メートルの細長い機体や扁平な機体を1つの球で表すと、当たり判定が形状とまったく合わない。

カプセルの集合であれば、既存の空間格子による近傍探索をそのまま使え、掃引球の判定をカプセルに拡張するだけで済む。被弾したカプセルから、損傷する搭載要素も自然に決まる。

### 2-9. 推進と姿勢制御は4つの系統に分ける

軌道変更のための大きな Δv、近接機動と姿勢制御の補助、推進剤を消費しない姿勢制御、推進剤も反作用も要らない姿勢制御は、それぞれ推力・比推力・応答性・消費資源・使える領域が異なる。単一のスラスタとして扱わず、主機・並進RCS・フライホイール・磁気トルカの4系統に分ける。姿勢トルクをどのアクチュエータが出すかは、要求を受けた側が決める。

### 2-10. アクチュエータの配置は設計ごとに変わる

RCSスラスタの取り付け位置と噴射方向は、機体ごとに異なる。船体の6方向に1基ずつという配置を前提にしない。姿勢トルクの配分は、任意個・任意配置のスラスタ集合に対して成立する形で定義する。

### 2-11. 推進剤は登録されたペアからのみ選ぶ

比推力は実測値であり、任意の酸化剤と還元剤の組み合わせに対して定義できない。推進剤は「酸化剤と還元剤のペア」「単推進剤」「固体グレイン」「ハイブリッドの組」として表に登録されたものからのみ選ぶ。表は §14-1 に置く。

### 2-12. 性能値は搭載要素が持つ

推力・比推力・トルク・発電量・放熱量・冷却能力を、機体ごとの定数として持たない。すべて搭載要素の性能値の合計として求める。部品を積み替えれば、他に何も書き換えることなく機体の性能が変わる。

### 2-13. 燃焼は質量変化を含めて計算する

燃焼中は推進剤の消費により質量が減り、加速度が上がる。一定加速度を仮定すると、質量比の大きい機体で点火が遅れてマニューバノードを外す。燃焼時間と点火時刻は、必ず質量変化を含む式で求める。

## 3. 用語

| 語 | 意味 |
|---|---|
| 背骨 | ノードとエッジからなるグラフ。機体の形状を定める |
| ノード | 背骨の頂点。断面と回転位相を持つ |
| エッジ | 背骨の辺。両端のノードを結ぶ。外皮・構造材・分離機構のいずれかの種別を持つ |
| 断面 | ノードが持つ形。1つ以上の基本断面を貼り合わせた複合体 |
| 基本断面 | 円・楕円・正多角形・切り欠き型のいずれか |
| 接続口 | ノードが持つ、エッジまたは外装要素を取り付ける場所 |
| 外皮 | エッジの両端の断面をつないだ立体（ロフト）。内側が内容積になる |
| 搭載要素 | 機体に積む部品。外装要素と内装要素に分かれる |
| 既定の設計 | 本文書の段階で唯一存在する設計。編集する手段は第2巻が与える |

## 4. 艦艇と基地の統合

### 4-1. 能力は搭載要素から導く

- **軌道基地** = 基地モジュール部品を積んだ `Vessel`。
- **艦艇** = コックピットと主機を積んだ `Vessel`。
- **無人ブースター** = 自動操縦装置と主機を積み、コックピットを積まない `Vessel`。

```ts
// src/game/vessel/capabilities.ts
export function hasCockpit(v: Vessel): boolean;      // 人が操作できる
export function hasAutopilot(v: Vessel): boolean;    // 無人で計画を実行できる
export function hasBaseModule(v: Vessel): boolean;   // 格納・倉庫・生産・設計ができる
export function hasEngine(v: Vessel): boolean;       // 主機を持つ
export function isOperable(v: Vessel): boolean;      // hasCockpit || hasAutopilot
```

操作対象に選べるのは `isOperable` を満たす機体である。基地ビューを開けるのは `hasBaseModule` を満たす機体である。

### 4-2. `Vessel` が持つもの

| フィールド | 内容 |
|---|---|
| `assembly: VesselAssembly \| null` | 背骨と、その上に配置された搭載要素。敵艦は `null` |
| `massProperties: MassProperties` | 乾燥質量・搭載質量・重心・慣性テンソル・主軸投影面積。`assembly` から導出するか、直接与えられる（§2-2）。変化時のみ再計算する |
| `collisionShape: readonly HullCapsule[]` | 接触形状（§11）。`assembly` から導出する |
| `propellant: PropellantStore` | 推進剤の種別ごとの残量 |
| `power: PowerSystem` | 発電・蓄電・消費 |
| `thermal: ThermalSystem` | 熱収支 |
| `propulsion: PropulsionSystem` | 主機・並進RCS（§13） |
| `attitudeControl: AttitudeControlSystem` | 姿勢トルクの配分（§13-2） |
| `parts: AnyPart[]` | 搭載要素。HPと性能の唯一の源 |
| `plan: Plan` / `planExecutor: PlanExecutor` | 軌道計画とその自動実行 |

`EntityManager` は `vessels: Vessel[]` という単一の配列を持つ。操作対象は `ActivePlayerController` が `Vessel | null` として保持する。

### 4-3. 敵艦の質量特性

敵艦は背骨を持たず、設計データも持たない。種別ごとに定めた `MassProperties`（質量・重心・慣性テンソル・投影面積）をコンストラクタで直接受け取り、それを `massProperties` にそのまま置く。接触形状は単一のカプセル（実質的に球）とする。慣性テンソルの種別ごとの値と表示倍率・当たり半径は、現在の実装の値をそのまま引き継ぐ。

この経路は暫定ではなく、`Vessel` の恒久的な2つ目の入口である。敵艦に設計を持たせない限り、この経路が使われ続ける。

### 4-4. 基地の格納機構

現在 `Base` が持つハッチ位置・ハッチ法線・格納スロット・最大格納数は、基地モジュール部品の性能値として移す。

**ドッキングポートによる機体の結合は実装しない。** したがって格納の判定は現在のまま「一定距離内かつ相対速度が小さい」とし、その距離と相対速度の閾値、およびハッチの位置と法線を、機体の定数からではなく基地モジュール部品から読む形に置き換える。判定の内容そのものは変えない。統合の途中で格納が動かなくなることのないよう、この置き換えは `Vessel` 統合と同じ変更セットで行う。

### 4-5. 表示種別の導出

マップ上の対象種別は、`hasBaseModule`（基地モジュールを持つか）と所属勢力の2軸から導く。

| 条件 | 種別 |
|---|---|
| 基地モジュールを持つ | `'base'` |
| 基地モジュールを持たず、自勢力 | `'player'` |
| 敵対勢力 | `'ship'` |

弾薬ピックアップは `Vessel` ではないため、`'ammo'` はこの導出の外側にそのまま残る。表示ポリシーが持つ自艦・敵・弾薬・基地の4トグルは、この導出の結果に対してそのまま適用でき、変更を要さない。

### 4-6. 配列統合の波及範囲

`vessels` 1本への統合は、配列構成に依存する以下すべてに波及する。

**`EntityManager`**

`all()` / `otherEntities()` / `attractors()` / `sync()` / `syncPlayers()` / `updatePlayers()` / `cleanup()` / `prune()` / `applyVisibility()` / `perfCounts()` / `findPlayer()` / `findEnemy()` / `parkPlayer()` / `removePlayer()` / `addPlayer()` / `addEnemy()` / `addBase()` / `updateBaseEquatorNodes()` / `syncEquatorNodes()`

**その他**

| 対象 | 波及の内容 |
|---|---|
| `Simulator.stepAttitudes` | 5配列の走査を `vessels` を含む構成に改める |
| `ActivePlayerController` | 保持する型と、`vessels` に対する生存掃引・引き継ぎ |
| `Targeter` の `CombatTarget` | 2クラスの合併型を `Vessel` 単一に改める |
| `NavTarget.resolveEntity` | 敵・自艦・基地の順に引く3段の探索を単一の探索に改める |
| `CreativeStage.placeObject` | 4種の作り分けを、積む部品の違いに改める |

## 5. 搭載要素

### 5-1. 一覧

搭載要素は、機体の外側に露出する**外装要素**と、機体の内容積を占める**内装要素**に分かれる。

**外装要素**

| 要素 | 主な性能値 |
|---|---|
| 武器 | 発射速度、1発あたりの威力、初速、給弾の要求量 |
| ドッキングポート | 適合クラス、移送速度 |
| コンテナ接合部 | 保持できるコンテナの規格 |
| 太陽電池パドル | 面積、発電効率、展開の可否 |
| 放熱板 | 面積、放熱効率、展開の可否 |
| エンジン | 対応推進剤、サイクル、推力、比推力、全長、ジンバル可動角、ジンバル速度、絞り範囲、再着火回数、点火1回あたりの推進剤損失、連続燃焼時間の上限 |
| RCSスラスタ | 推力、対応推進剤、比推力 |

**内装要素**

| 要素 | 主な性能値 |
|---|---|
| 酸化剤タンク | 対応推進剤、容積、断熱等級、要求与圧、材料 |
| 還元剤タンク | 対応推進剤、容積、断熱等級、要求与圧、材料 |
| イナートガスタンク（球状） | 容積、耐圧、充填ガス種別 |
| RCS推進剤タンク | 対応推進剤、容積、材料 |
| 水タンク | 容積、遮蔽の厚み |
| バッテリー | 蓄電容量、最大出力 |
| コックピット | 搭乗人数、必要与圧容積 |
| 自動操縦装置 | 計画実行の可否、消費電力 |
| 弾薬庫 | 収納マガジン数 |
| 配管 | 口径、対応推進剤、最大流量 |
| ペイロード倉庫 | 内容積、最大積載質量、開閉の可否 |
| フライホイール | 最大トルク、最大蓄積角運動量、消費電力 |
| 磁気トルカ | 最大磁気モーメント、消費電力 |
| 基地モジュール | 格納数、倉庫容量、生産設備、ハッチ位置、ハッチ法線、格納スロット |
| 重力区画居住施設 | 収容人数、回転半径、回転速度、消費電力 |
| 農場 | 栽培面積、光源の種別、消費電力 |
| 生命維持装置 | 処理できる人数、消費電力、消耗品の消費 |
| ドック | 収容数、収容できる機体の最大寸法 |

**明示的な要件の一覧に含まれない4つの要素** — 上の一覧には、いずれも実装対象とする機能の成立に必要な4つが含まれる。

- **RCSスラスタ** — RCS推進剤タンクを積む以上、それを噴射する推進器が必要である。タンクは内装、スラスタは外装であり、別の要素として扱う。
- **フライホイール** — 推進剤を消費しない姿勢制御そのものである（§13）。
- **磁気トルカ** — フライホイールの角運動量を推進剤ゼロで捨てる手段である（§13-2）。使える領域が限られるため、フライホイールの代替ではなく、フライホイールと対になる要素である。
- **分離機構** — 多段ブースターシステムの成立に必要である。ただしこれは搭載要素ではなく、機体の構造を切断する辺の種別として扱う。分離は接続の切断であり、取り付ける物ではないためである。

**基地の区画** — 重力区画居住施設・農場・生命維持装置・水タンク・ドック・コンテナ接合部は、本文書では**型と性能値の枠だけを定義する**。それぞれの働き（疑似重力、食料生産、閉ループ率、放射線の遮蔽、格納、コンテナの着脱）と、それらが基地の運用にどう効くかは第2巻が定める。

### 5-2. 性能値の合成

機体の性能は、積んでいる搭載要素の性能値から求める。

| 機体の性能 | 求め方 |
|---|---|
| 総推力 | 主機の推力の合計 |
| 総トルク | 姿勢トルクの配分（§13-2）が、要求方向ごとに実際に出せる最大値として答える |
| 推進剤容量 | 推進剤の種別ごとに、対応するタンクの容積と密度の積の合計 |
| 発電量 | 太陽電池パドルの面積・効率・日射から求めた値の合計 |
| 蓄電容量 | バッテリーの容量の合計 |
| 放熱能力 | 放熱板の面積と効率から求めた値の合計 |
| 装甲 | 各要素のHPの合計。コックピットまたは主要構造を失った時点で0とする |

総トルクを単純な合計としないのは、アクチュエータの配置が設計ごとに変わるためである。同じ推力のスラスタでも、モーメントアームの向きによって出せるトルクの方向が異なり、方向によっては打ち消し合う。したがって「この機体のトルクはいくつか」という問いには、方向を指定しない限り答えがない。

推進剤の残量は `PropellantStore` が推進剤の種別ごとに保持し、タンクの容積の合計が上限である。どのタンクから減るかは区別しない。

## 6. 断面

### 6-1. 定義

断面は、1つ以上の**基本断面**を面で貼り合わせた複合体である。

```ts
// src/game/vessel/cross-section.ts
export type PrimitiveShape =
  | { kind: 'circle';   radius: number; branchCount: 2 | 3 | 4 | 5 | 6 }
  | { kind: 'ellipse';  majorRadius: number; minorRadius: number }
  | { kind: 'polygon';  sides: 3 | 4 | 5 | 6 | 8; radius: number }
  | { kind: 'notched';  sides: 6 | 8; radius: number };  // 辺長が 1:2 で交互する切り欠き型

export interface SectionPrimitive {
  readonly id: string;
  readonly shape: PrimitiveShape;
  readonly phaseAngle: number;                      // この基本断面の回転位相 [rad]
  readonly attachment: PrimitiveAttachment | null;  // null は複合体の根
}

export interface PrimitiveAttachment {
  readonly parentId: string;            // 貼り付け先の基本断面
  readonly parentFaceIndex: number;     // 貼り付け先のどの辺に付けるか
  readonly childFaceIndex: number;      // 自分のどの辺を貼り付けるか
}

export interface CrossSection {
  readonly primitives: readonly SectionPrimitive[];
}
```

- 複合体は木構造である。各基本断面は、親の1つの辺に、自分の1つの辺を重ねて貼り付ける。
- 貼り付ける2つの辺は長さが等しくなければならない。等しくない場合は不正な断面とする。
- 貼り合わせ面を共有するため、基本断面同士は重ならない。したがって複合断面の面積は基本断面の面積の和であり、断面二次モーメントは平行軸の定理で合成した和である。
- 円と楕円は辺を持たないため、複合体の根としてのみ使える。子として貼り付けることはできない。

例として、四角形断面の一辺に三角形断面を貼り付けると、五角形の家型の断面になる。四角形の対辺2つに三角形を貼り付ければ、六角形の紡錘型になる。八角形の複数の辺に四角形を貼り付ければ、突起を持つ断面になる。

### 6-2. 基本断面の形状

| 形状 | 寸法パラメータ | 側面の口の数 | 口の方向 |
|---|---|---|---|
| 円 | 半径 | 2・3・4・5・6 から選ぶ | 360度を分岐数で等分した方向 |
| 楕円 | 長半径・短半径 | 2 | 長軸の正負方向 |
| 正三角形 | 外接円半径 | 3 | 各辺の外向き法線 |
| 正方形 | 外接円半径 | 4 | 各辺の外向き法線 |
| 正五角形 | 外接円半径 | 5 | 各辺の外向き法線 |
| 正六角形 | 外接円半径 | 6 | 各辺の外向き法線 |
| 正八角形 | 外接円半径 | 8 | 各辺の外向き法線 |
| 切り欠き六角形 | 外接円半径 | 6 | 各辺の外向き法線 |
| 切り欠き八角形 | 外接円半径 | 8 | 各辺の外向き法線 |

**切り欠き型** — 正多角形の辺の長さがすべて等しいのに対し、切り欠き型は長い辺と短い辺が1対2の比で交互に並ぶ。

- **切り欠き八角形** — 正方形の4つの角を切り落とした形である。長さ2の辺が4つ（元の正方形の辺の残り）と、長さ1の辺が4つ（切り落とした角の断面）を持つ。長い辺の中点に大きな面を確保しつつ、角の張り出しを抑えられる。
- **切り欠き六角形** — 正三角形の3つの角を切り落とした形である。長さ2の辺が3つと、長さ1の辺が3つを持つ。

切り欠き型は、正多角形より広い平面を確保しながら外接円半径を抑えられるため、太陽電池パドルや放熱板のような広い取り付け面を要する部品を並べるのに適する。

### 6-3. 側面の口の大きさ

側面の口は、辺の方向（周方向）と軸方向が張る矩形である。

- **周方向の寸法** — その辺の長さそのもの。
- **軸方向の寸法** — 母断面の外接円半径に `PORT_WIDTH_RATIO`（既定 1.0）を掛けた値。大きな断面には大きな分岐が付けられる。

分岐するエッジの相手側の断面は、その外接円の直径がこの矩形の両方の寸法以下でなければならない。収まらない場合は不正とする。

隣接する辺の口同士は干渉してはならない。多角形では辺が離れているため通常は干渉しないが、円の分岐数が多く口の幅が広い場合には、切り落とす弓形が重なりうる。これも不正とする。

## 7. 背骨

背骨はグラフであり、閉路を含んでよい。三角形や梯子状に組めば扁平な機体になる。

`decoupler` エッジは、分離可能な境界を表す。本文書ではエッジの種別として存在し、外皮を作らないことのみを扱う。分離の動作は第2巻が定める。

### 7-1. 接続口のローカル座標系

各接続口は、その口に固有のローカル座標系を持つ。

- **原点** — 口の平面の中心
- **+Z 軸** — 口の平面の外向き法線
- **+Y 軸** — 口の基準ロール方向。軸方向の口では断面の回転位相が決め、側面の口ではその辺に沿う方向とする
- **+X 軸** — 右手系で決まる

外装の搭載要素は、この座標系に取り付く。**可動部を持つ要素（放熱板の折り畳み、太陽電池パドルの回転、遮蔽の展開、武装の俯仰）は、すべてこの座標系を基準に動く。**取り付け位置を固定座標で持つ要素は存在しない。

弾薬ベルトは武装に付属する内装要素であり、武装を取り付けたノードの接続口の座標系から垂れる。

### 7-2. 内容積の連続性

**軸方向に連なるエッジ同士は断面を共有するため、内容積が連続する。**同じ推進剤を収める限り、軸方向に連なる複数のエッジを1つのタンクとして扱える。

**側面から分岐するエッジの内容積は、母体の内容積と連続しない。**分岐部の付け根は母体の外皮の表面であり、分岐エッジは母体の外側から始まる。母体の内容積は分岐によって欠けることなく、そのまま残る。したがって、母体と分岐にまたがる1つのタンクは作れない。

ノード自身は面であって体積を持たない。3本以上のエッジが集まるノードでも、体積が二重に数えられることはない。

## 8. 断面の面積と断面二次モーメント

基本断面が多角形（正多角形・切り欠き型・複合体の構成要素）である場合、頂点列から以下で厳密に求める。頂点を反時計回りに `(x_i, y_i)`、`i` の次を `i+1` として、

```
cross_i = x_i·y_{i+1} − x_{i+1}·y_i
A   = (1/2)    · Σ cross_i
Cx  = (1/(6A)) · Σ (x_i + x_{i+1}) · cross_i
Cy  = (1/(6A)) · Σ (y_i + y_{i+1}) · cross_i
Ix  = (1/12)   · Σ (y_i² + y_i·y_{i+1} + y_{i+1}²) · cross_i
Iy  = (1/12)   · Σ (x_i² + x_i·x_{i+1} + x_{i+1}²) · cross_i
Ixy = (1/24)   · Σ (x_i·y_{i+1} + 2·x_i·y_i + 2·x_{i+1}·y_{i+1} + x_{i+1}·y_i) · cross_i
```

を求め、平行軸の定理で重心まわりに移す。この式は任意の単純多角形に対して厳密であり、形状ごとの個別の式を持つ必要がない。切り欠き型も、複合断面も、この1つの式で扱える。

**相乗モーメント `Ixy` は0とは限らない。** 複合断面が対称でない場合、断面の主軸は座標軸から回転する。慣性テンソルの計算では `Ixy` を必ず含める。正多角形と円だけであれば `Ixy` は常に0になるが、複合断面を導入する以上これは成り立たない。

円と楕円は解析式で求める。

```
円（半径 r）      A = πr²,   Ix = Iy = πr⁴/4,   Ixy = 0
楕円（半径 a, b）  A = πab,   Ix = πab³/4,        Iy = πa³b/4,   Ixy = 0
```

**円に側面の口を設ける場合** — その方向の円弧を弦で切り落とし、平面を作る。切り落とされる弓形の中心角を `θ`、半径を `r` として、

```
弓形の面積        A_seg = (r²/2)·(θ − sin θ)
弓形の重心距離     d_seg = (4r·sin³(θ/2)) / (3·(θ − sin θ))
弓形の断面二次モーメント は θ の閉形式で求まる
```

を円の値から差し引く。分岐数ぶんの弓形を、それぞれの方向で差し引く。切り落とし量は §6-3 の口の幅から決まる。

```
src/physics/section-moments.ts   (純関数)
    polygonArea(vertices) -> number
    polygonCentroid(vertices) -> { x, y }
    polygonSecondMoments(vertices) -> { ix, iy, ixy }          // 重心まわり
    circleSegmentMoments(radius, halfAngle) -> { area, centroidDist, ix, iy }
    sectionMoments(section) -> { area, centroid, ix, iy, ixy }  // 複合断面全体
    sectionOutline(section, sampleCount) -> readonly Vec2[]     // ロフト用の輪郭
```

検証は `tests/physics/section-moments.test.ts` に置く。正n角形の面積と断面二次モーメントが既知の閉形式と一致すること、辺数を増やすと円の値に収束すること、切り欠き八角形が「正方形から4つの直角三角形を引いた値」と一致すること、複合断面の面積が構成要素の和と一致すること、対称な複合断面の `Ixy` が0になり非対称なものは0でないことを固定する。

## 9. 外皮の生成と立体の物理量

### 9-1. 外皮の生成

`hull` エッジは、両端のノードの断面をつないだ立体を作る。

- 両断面の輪郭を、それぞれ**120点**に等分してサンプリングする。120は3・4・5・6・8のいずれでも割り切れるため、辺数の異なる断面同士でも頂点が一対一に対応する。円と楕円も同じ120点で表す。
- **等分は弧長で行う。**円に側面の口を設けた断面は、円弧と直線が混じった輪郭になる。角度で等分すると直線部の点が疎になり、ロフトの帯の面積が不均一になる。弧長で等分すれば帯の面積が均等になる。
- 対応する頂点同士を直線で結び、側面を四角形の帯として張る。
- 両断面の回転位相が異なる場合、頂点の対応は位相差を考慮して、対応する頂点間の距離の総和が最小になる割り当てを選ぶ。これにより外皮がねじれない。
- 複合断面の場合、輪郭は複合体全体の外周である。貼り合わせ面の内側は輪郭に含まれない。

側面の口から分岐するエッジは、口の平面の上に相手側の断面を置き、そこから同じ規則でロフトする。分岐部は平面同士の突き合わせであり、本体の外皮と交差しない。

### 9-2. 立体の物理量

外皮は「断面が軸方向に線形に変化する一般化角錐台」の集まりである。

**エッジ1本の体積** — 長さ `h`、両端の断面積 `A₁` / `A₂`、中間断面の面積 `Am` として

```
V = (h/6)·(A₁ + 4·Am + A₂)
```

輪郭を線形補間するため中間断面は両端の輪郭の平均であり、`Am` はその平均輪郭の面積である。

**慣性テンソル** — 軸に沿った位置 `t ∈ [0, h]` における断面積 `A(t)`、断面二次モーメント `Ix(t)` / `Iy(t)` / `Ixy(t)`、断面重心 `C(t)` は、いずれも `t` の多項式である。したがって

```
I_axial      = ρ ∫ (Ix(t) + Iy(t)) dt
I_transverse = ρ ∫ (I(t) + A(t)·|C(t) − C_ref|²) dt
I_product    = ρ ∫ (Ixy(t) + A(t)·(...)) dt
```

はいずれも多項式の積分として閉形式で求まる。各エッジの慣性テンソルを平行軸の定理で船体重心まわりに移して合成する。

**表面積** — 側面の帯の面積の和に、露出した端面（他のエッジが接続していない断面）を加える。

**主軸3方向の投影面積** — 空力に用いる（§11-2）。

```
src/physics/hull-loft.ts   (純関数)
    loftVolume(sectionA, sectionB, length) -> number
    loftInertia(sectionA, sectionB, length, density) -> InertiaTensor
    loftCentroid(sectionA, sectionB, length) -> number
    loftSurfaceArea(sectionA, sectionB, length) -> number
    loftProjectedArea(sectionA, sectionB, length, axis) -> number
```

検証は `tests/physics/hull-loft.test.ts` に置く。円断面の等断面ロフトが円柱の解析値と一致すること、両端の断面積が等しい角錐台の体積が `A·h` になること、L字に組んだ骨格の慣性主軸が3値とも異なること（すなわちジャニベコフ効果が発生する形状であること）を固定する。

### 9-3. 外皮の肉厚と構造質量

構造の質量は、外皮の表面積と肉厚から求める。肉厚は区画ごとに決まる。

**内圧を持つ区画（推進剤タンク、イナートガスタンク、水タンク、コックピット、重力区画居住施設）** — 薄肉圧力容器の式による。内圧 `p`、断面の外接円半径 `r`、材料の許容応力 `σ`、溶接効率 `e`、安全率 `k` として

```
t = k · p · r / (σ · e)
```

**内圧を持たない区画（機器区画、貨物区画、ペイロード倉庫）** — 座屈に対する最小肉厚と、製造上の下限肉厚の大きいほうを取る。

この扱いにより、**タンクを大きくすると質量が半径に比例して増える。**内圧の高い加圧式エンジン向けのタンクは、ポンプ式向けのタンクより厚く重い。これが加圧式の単純さと引き換えになる代償として、質量の形で現れる。

材料ごとに比強度（許容応力を密度で割った値）が異なり、アルミ合金・チタン合金・炭素繊維複合材の順に軽くなる。推進剤ごとに使える材料が限られる（§14-1）ため、**推進剤の選択が材料の選択を通じて質量に効く。**

### 9-4. 質量特性の合成

```ts
// src/game/vessel/mass-properties.ts
export interface MassProperties {
  readonly dryMass: number;          // 構造 + 搭載要素の乾燥質量 [kg]
  readonly loadedMass: number;       // 推進剤と貨物を含む総質量 [kg]
  readonly centerOfMass: Vec3;       // 船体ローカル座標
  readonly inertia: InertiaTensor;   // 重心まわり
  readonly principalAreas: Vec3;     // 主軸3方向の投影面積 [m²]
}
export function deriveMassProperties(
  skeleton: VesselSkeleton,
  placements: readonly PartPlacement[],
  propellant: PropellantStore,
): MassProperties;
```

搭載要素はそれぞれの取り付け位置に質点として置く。推進剤はそれを収めるエッジの内容積の重心に置く。推進剤が減れば重心と慣性テンソルが変わるため、質量が一定量変化したときに再計算する。

## 10. 内容積の割り当て

`hull` エッジそれぞれの内容積に、何を収めるかを指定する。そのエッジのロフト体積が上限である。1つのエッジに複数の内装要素を収めてよく、その体積の和が上限を超えないこと。

```ts
// src/game/vessel/assembly.ts
export type PartPlacement =
  | { kind: 'external'; partId: string; nodeId: string; port: PortRef }
  | { kind: 'internal'; partId: string; edgeIds: readonly string[] };

export interface VesselAssembly {
  readonly skeleton: VesselSkeleton;
  readonly placements: readonly PartPlacement[];
}
```

内装要素の `edgeIds` が配列であるのは、軸方向に連なる複数のエッジをまたぐ1つのタンクを作れるためである（§7-2）。連なっていないエッジをまたぐ配置は不正とする。

| 収容物 | 実効容積の係数 | 備考 |
|---|---|---|
| 極低温タンク（液体水素・液体酸素・液体メタン） | 0.85 | 断熱材のぶん減る |
| 常温貯蔵タンク（ヒドラジン・四酸化二窒素・過酸化水素） | 0.95 | |
| イナートガスタンク（球状） | 0.55 | 球をエッジの内容積に詰めるため、球以外の空間が死ぬ |
| RCS推進剤タンク | 0.95 | |
| 水タンク | 0.95 | |
| ペイロード倉庫・弾薬庫 | 0.90 | 容積と最大積載質量の両方で制限される |
| コックピット・重力区画居住施設 | 0.80 | 与圧に必要な構造のぶん減る |
| 農場・生命維持装置・基地モジュール・ドック | 0.85 | 設備の据付に要する空間のぶん減る |
| バッテリー・自動操縦装置・フライホイール・磁気トルカ | 1.00 | |
| 配管 | 口径から決まる | エッジの長さと口径の断面積の積 |

固体モーターはタンクではなく、エッジそのものである。ケースが構造材を兼ねるため、固体モーターを割り当てたエッジは `hull` エッジ1本がモーター1基に対応する。

**イナートガスタンクが球状である理由** — 内圧に対して最も効率のよい圧力容器は球である。同じ耐圧なら球は円筒より薄い壁で済み、タンク自体の質量が小さい。一方、球は角柱状の内容積に詰めたときの充填率が悪い。この対立が実効容積の係数0.55として現れる。

## 11. 接触形状と空力特性

### 11-1. 接触形状

機体の剛体接触と被弾は、**背骨の各エッジに対応するカプセルの集合**で判定する。

```ts
// src/game/vessel/collision-shape.ts
export interface HullCapsule {
  readonly edgeId: string;
  readonly a: Vec3;        // 船体ローカル座標
  readonly b: Vec3;
  readonly radius: number; // 両端の断面の外接円半径の平均
}
export function deriveCapsules(skeleton: VesselSkeleton): readonly HullCapsule[];
```

- `hull` エッジと `strut` エッジがカプセルを持つ。`decoupler` エッジは分離機構そのものであり、両端のカプセルが接するため独自のカプセルを持たない。
- `GameEntity.radius` は**外接球の半径**として残す。空間格子による広域の絞り込みと、天体表面への到達判定はこの球で行う。狭域の判定だけがカプセルになる。
- 判定は、カプセル対球（弾丸、破片、薬莢）とカプセル対カプセル（機体同士）の2種である。既存の掃引球の判定を掃引カプセルに拡張する。

```
src/physics/capsule-contact.ts   (純関数)
    sweptCapsuleSphereToi(capsule, sphereStart, sphereEnd, sphereRadius) -> number | null
    sweptCapsuleCapsuleToi(a0, a1, b0, b1) -> number | null
    closestPointsOnSegments(p0, p1, q0, q1) -> { s: number; t: number }
```

**被弾したカプセルから損傷する搭載要素が決まる。**そのエッジの内容積に収めた内装要素と、そのエッジの両端のノードに取り付けた外装要素が候補になる。機体のどこに当たったかが、何が壊れるかに直結する。

### 11-2. 空力特性

抗力は自由分子流域（低軌道の高度）で働く。この領域では**抗力係数は形状にほとんど依存せず、`Cd ≈ 2.2` である。**形状の差は投影面積として現れる。

したがって `Cd` は 2.2 の定数とし、投影面積のみを形状と姿勢から求める。速度方向の単位ベクトルを機体座標系に移した `v̂` に対して、

```
A(v̂) = |v̂·x̂|·A_x + |v̂·ŷ|·A_y + |v̂·ẑ|·A_z
bcInv = Cd · A(v̂) / m
```

`A_x` / `A_y` / `A_z` は主軸3方向の投影面積であり、設計時に一度求める。この式は直方体に対して厳密であり、それ以外の形状に対しても十分な近似である。

**`bcInv` は姿勢に依存する値になる。**細長い機体を横に向ければ抗力が数倍になり、進行方向に向ければ最小になる。これは再突入と軌道の減衰に直接効き、姿勢を保つことに意味を与える。

同じ投影面積が太陽輻射圧の係数 `srpCoeff = C_R · A(ŝ) / m` にも用いられる。`ŝ` は太陽方向であり、`C_R` は表面の反射特性から決まる定数とする。

## 12. 描画

```
src/render/hull/loft-mesh.ts

```

エッジごとに120分割のロフト帯を生成し、露出した端面を蓋で閉じ、全体を1つのジオメトリに結合する。生成は形状が変わったときに1度だけ行う。遠距離では分割数を下げた別のジオメトリを用いる。

エンジンは性能値として全長を持ち、その長さぶんノズルが機体後端から突き出す。比推力の高いエンジンほどノズルが長い。

**自機のモデルは事前生成アセットからロフト生成に置き換える。**敵艦・破片・薬莢は事前生成アセットのままとする。

## 13. 推進系と姿勢制御系

### 13-1. 4つのシステムの役割

| システム | 役割 | 消費 | 比推力 | 特性 |
|---|---|---|---|---|
| **主機（EngineBank）** | 軌道変更のための大きな Δv | 液体・固体・ハイブリッド推進剤 | 260〜450 s | 推力大。始動と停止にコストがある。固体は停止も再着火もできない |
| **並進RCS（TranslationRcs）** | 近接機動・姿勢制御の補助 | 単推進剤または冷ガス | 70〜230 s | 推力小。応答は即時。出せる方向はスラスタの配置で決まる |
| **フライホイール（ReactionWheels）** | 姿勢制御のみ | 電力のみ | — | トルク小・連続。**角運動量が飽和する** |
| **磁気トルカ（MagneticTorquers）** | 姿勢制御とアンローディング | 電力のみ（微小） | — | トルク極小。**地球磁場のある領域でしか使えない。磁場に平行な軸まわりのトルクは出せない** |

### 13-2. 姿勢トルクの配分

姿勢トルクを要求する主体は、手動操作と自動操縦の2つである。両者は `AttitudeControlSystem` に要求を出し、どのアクチュエータが出すかはそこが決める。

配分は「推進剤を消費しないものを先に使い、足りないぶんを推進剤で埋める」という3段の優先順位で行う。

1. **磁気トルカ** — 推進剤も、ごくわずかな電力しか消費しない。ただし出せるトルクは τ = m × B（m は磁気モーメント、B は地球磁場）であり、B に平行な成分は原理的に出せない。地球磁場のない領域では何も出せない。
2. **フライホイール** — 電力のみを消費する。出せる条件は、そのホイールの最大トルクを超えないことと、蓄積角運動量 h が上限 hMax に達していないことの両方である。ホイールが τ_wheel を出すと、反作用として角運動量が `h += -τ_wheel · dt` だけ溜まる。
3. **RCSスラスタ** — 上の2つで出しきれなかったぶんを出す。推進剤を消費する。

`|h|` が hMax の既定割合を超えると**アンローディング**を行う。外部トルクを与えながらホイールを減速し、h を外部に捨てる。外部トルクは磁気トルカを優先し、磁場が足りないぶんだけRCSが補う。自動実行を既定とし、手動実行のボタンをHUDに置く。

この規則により、地球低軌道では姿勢制御がほぼ無料で成立し、月周辺やラグランジュ点ではアンローディングのたびにRCS推進剤を消費する。活動する領域によって運用の性格が変わる。

### 13-3. 任意配置のアクチュエータに対する配分

RCSスラスタの取り付け位置 r_k と噴射方向 e_k は設計ごとに決まる。推力 F_k で噴いたとき、そのスラスタが機体に与える力は −F_k·e_k、重心まわりのトルクは τ_k = r_k × (−F_k·e_k) である。

要求トルクと要求並進推力を同時に満たす推力の組み合わせ (F_1, …, F_n) は、一般に**劣決定**である。スラスタが6基を超える機体では解が無数にあり、6基未満または配置が偏った機体では厳密解が存在しない。

したがって配分は、**減衰最小二乗**（Tikhonov 正則化した擬似逆行列）で解く。各スラスタの寄与を列に持つ 6×n の行列 A に対し、要求ベクトル b を満たす F を

```
F = Aᵀ (A Aᵀ + λI)⁻¹ b
```

として求める。正則化項 λ は、要求を厳密に満たすことより推力の総量を抑えることを優先する重みであり、そのまま推進剤消費を抑える働きをする。厳密解が存在しない配置でも、最も近い解が得られる。

得られた F_k は 0 以上・そのスラスタの最大推力以下にクランプする。クランプによって要求との差が残る場合、その差はそのまま出せなかったぶんとして扱う（再配分は行わない）。

```ts
// src/physics/attitude-control.ts   (純関数)
export interface TorqueRequest {
  readonly torque: Vec3;          // 要求トルク（機体座標系）
  readonly force: Vec3;           // 要求並進推力（機体座標系）
}
export interface ThrusterSpec {
  readonly position: Vec3;        // 重心からの取り付け位置 r_k
  readonly exhaust: Vec3;         // 噴射方向の単位ベクトル e_k
  readonly maxThrust: number;     // [N]
}
export interface ActuatorSet {
  readonly thrusters: readonly ThrusterSpec[];
  readonly wheels: readonly WheelSpec[];
  readonly torquers: readonly TorquerSpec[];
}
export interface Allocation {
  readonly torquerMoment: Vec3;                // 磁気トルカに与える磁気モーメント
  readonly wheelTorque: Vec3;                  // フライホイールが出すトルク
  readonly thrusterLevels: readonly number[];  // 各スラスタの推力 [N]
  readonly achievedTorque: Vec3;               // 実際に出るトルクの合計
  readonly achievedForce: Vec3;                // 実際に出る並進推力の合計
  readonly powerDraw: number;                  // [W]
}

export function allocateTorque(
  request: TorqueRequest,
  actuators: ActuatorSet,
  wheelState: WheelState,
  magneticField: Vec3 | null,   // 機体座標系での地球磁場。磁場のない領域では null
): Allocation;

export function desaturationRequest(
  wheelState: WheelState,
  hMax: number,
): TorqueRequest | null;
```

`allocateTorque` は3段の優先順位（§13-2）を順に適用し、各段で残った要求を次の段に渡す。磁気トルカの段は τ = m × B を m について解くが、B に平行な成分は解を持たないため、要求トルクの B に垂直な成分だけを扱う。

**アクチュエータ集合は設計から導く。**RCSスラスタの位置と向きは、取り付けた接続口のローカル座標系（§7-1）から決まる。噴射方向はその口の外向き法線である。固定のノズルテーブルは持たない。

### 13-4. 磁場の評価

地球磁場は双極子近似で求める。

```ts
// src/physics/geomagnetic.ts   (純関数)
export function geomagneticField(r: Vec3): Vec3;   // ECI 位置 → 磁束密度 [T]
```

双極子の軸は地球の自転軸から約 11 度傾いており、この傾きを含める。地球から離れるほど磁場は距離の3乗に反比例して弱まり、月周辺やラグランジュ点では磁気トルカが実質的に使えなくなる。この減衰は近似式がそのまま与えるため、「使える領域」を別途定義する必要はない。磁気モーメントと磁場の外積が要求トルクに対して無視できる大きさになった時点で、配分は自動的に次の段へ落ちる。

### 13-5. 重力傾斜トルク

全機体に重力傾斜トルクを適用する。

```ts
// src/physics/gravity-gradient.ts   (純関数)
export function gravityGradientTorque(
  rRel: Vec3,        // 重力源から機体への位置ベクトル
  mu: number,        // 重力源の重力定数
  inertia: Inertia,  // 機体座標系の慣性テンソル
  q: Quat,           // 機体の姿勢
): Vec3;
```

トルクは τ_gg = 3·(μ/r³)·(r̂ × (I·r̂)) である。r̂ は重力源方向の単位ベクトルを機体座標系に回したものであり、I は機体座標系の慣性テンソルである。慣性主軸が等しい機体ではトルクは 0 になり、細長い機体ほど強く、長軸を天底方向に向けようとする。

`Simulator.stepAttitudes` の姿勢積分に外部トルクとして加える。重力源はその位置で最も強く引く天体1つとする。

慣性テンソルを形状から導出する以上、この効果は形状の帰結として現れる。細長い機体を設計すれば、放っておくと天底を向く。姿勢を保つには姿勢制御系が常に働き続けることになり、その消費が低軌道での運用に効く。

### 13-6. 並進推力の選択

- 要求方向が主機の推力軸と一致し、要求の大きさがRCSの最大推力を超える場合は主機を使う。
- それ以外はRCSを使う。
- 要求の大きさが主機の絞り下限を下回る場合もRCSを使う（§13-8）。
- プレイヤーはHUDで「主機を使わない」「主機のみ」を明示的に選べる。

### 13-7. 推力軸と重心のずれ

主機の推力軸が機体重心を通らない場合、その差からトルクが生じる。この効果は正しく計算する。

ジンバル機構を持つ主機は、ずれを打ち消す方向に首を振る。ただしジンバルには可動角に加えて**ジンバル速度**の上限があり、速い姿勢変化には追従できない。追従しきれないぶんと、可動角で打ち消しきれないぶんは `AttitudeControlSystem` が補償する。ジンバルを持たない主機のずれは補償されず、機体が回る。

### 13-8. スロットル操作

主機の出力は**絞り率 0〜100% の連続値**で指定する。加速度による段階指定は持たない。機体の質量と積んだエンジンによって同じ絞り率でも加速度は変わり、燃焼中は質量が減るぶん加速度が上がる。

キー `[1]` 〜 `[4]` は絞り率のプリセットに割り当てる。

| キー | 絞り率 |
|---|---|
| `[1]` | 25% |
| `[2]` | 50% |
| `[3]` | 75% |
| `[4]` | 100% |

エンジンのサイクルごとの絞り下限（§14-2）を下回る指定は下限にクランプし、HUDにクランプされている旨を表示する。下限より低い出力が要るときは、主機ではなく並進RCSを使う。

複数のサイクルのエンジンを混載した機体では、絞り下限はエンジンごとに異なる。下限を下回る絞り率を指定されたエンジンは、下限で噴くのではなく停止する。これにより、絞り率を下げていくとエンジンが1基ずつ落ちていく挙動になる。

### 13-10. 飛行中のHUD

飛行中に**推進系**パネルを置く。個別に折り畳める。主機・並進RCS・フライホイール・磁気トルカの4行を持ち、主機は絞り率と推進剤の種別ごとの残量、RCSは残量、フライホイールは蓄積角運動量と上限の比、磁気トルカは現在の磁場強度に対して出せるトルクの目安をメーターで表示する。フライホイールは飽和が近い場合に警告色にする。アンローディングの手動実行ボタンをこのパネルに置く。

既存のウィジェット（`src/game/hud/widgets/`）のみで構成し、生の `<button>` および `<input>` を直接書かない。既存のパネルへ統合できないかを追加のたびに確認し、置き場の規約に従う。

| 窒素 | 230 kg/m³ | 安価だが重い。極低温推進剤には使えない |

固体推進剤の燃料成分はアルミ粉末であり、酸化アルミニウムはその燃焼生成物である。ABS樹脂はハイブリッドロケットの固体燃料側であり、亜酸化窒素または液体酸素の酸化剤と組み合わせて使う。

**凍結とヒータ電力** — 凝固点を上回る温度を保てない機体では、推進剤が凍る。タンク・バルブ・配管はヒータで加熱し、そのぶんの電力を消費し続ける。常温貯蔵性推進剤ほど凝固点が高く、日陰の長い軌道では維持に電力が要る。極低温推進剤は逆に、日射で蒸発するが凍らない。この対比が、推進剤の選択を電力系の設計と結び付ける。

**シランの位置づけ** — 液体酸素／シランの比推力が液体酸素／メタンより大きく劣るのは、燃焼生成物である二酸化ケイ素が燃焼室とノズルの温度で凝縮相であり、膨張過程で仕事に寄与しないためである。固体推進剤のアルミナと同じ機構であり、比推力が固体モーター並みに落ちる理由もそこにある。同じ理由で二酸化ケイ素がノズルスロートに堆積するため、**連続燃焼時間に上限がある**（§14-2）。この推進剤は、月のレゴリスと水氷だけで生産できる唯一の液体推進剤である。性能は固体モーター並みだが、絞れて停止でき再点火できる。

**選択の意味** — 固体は安価で高密度、ただし一度きりであり、使い捨ての帰投用ブースターに適する。液体酸素／液体水素は比推力が最も高いが密度が低く巨大なタンクを要し、蒸発損失が大きく、点火のたびの損失も大きいため、長期の待機と多数回の点火のどちらにも向かない。ヒドラジン系は性能が中位だが常温で長期間待機でき、軌道上に置いておくブースターに適する。ただし凍結を防ぐ電力と、毒性を扱う設備が要る。

### 14-2. エンジンの型式

エンジンは「サイクル（供給方式）」と「対応推進剤」の組で定義する。同じ推進剤でもサイクルが違えば性能が変わる。

| サイクル | 比推力係数 | 推力重量比 | 要求与圧 [MPa] | 絞り範囲 | 再着火 | 連続燃焼時間の上限 | 特徴 |
|---|---|---|---|---|---|---|---|
| 加圧式 | 0.95 | 低 | 2〜3 | 40〜100% | 無制限 | あり（アブレーティブ冷却） | 構造が単純で信頼性が高い。タンクを高圧に耐える厚さにする必要があり、タンク質量とイナートガスの消費が増える |
| 電気ポンプ式 | 0.98 | 中 | 0.2〜0.4 | 30〜100% | 無制限 | なし | 電力を消費する。バッテリー容量が燃焼時間を制限する |
| ガス発生器サイクル | 1.00 | 高 | 0.2〜0.4 | 60〜100% | 数回 | なし | 標準的な性能 |
| 段階燃焼サイクル | 1.04 | 高 | 0.2〜0.4 | 50〜100% | 数回 | なし | 比推力が最も高い。エンジン質量とコストが大きい |
| エキスパンダーサイクル | 1.03 | 低 | 0.2〜0.4 | 30〜100% | 無制限 | なし | **対応推進剤は極低温のみ。**再生冷却で受け取れる熱量が推力の上限を決め、おおよそ 300 kN を超えられない |
| 固体モーター | 1.00 | 最高 | 不要 | 不可 | 不可 | あり（グレイン量で決まる） | 点火後は停止できない。配管も与圧も要らない |
| ハイブリッドモーター | 1.00 | 中 | 中 | 20〜100% | 無制限 | なし | 酸化剤のみタンクに持つ |

要求与圧の 2〜3 MPa と 0.2〜0.4 MPa の10倍の差が、そのままイナートガスの消費量の差になる。加圧式は構造が単純だが、その単純さの代償をイナートガスタンクの容積と質量で払う。

**エンジンの追加の性能値**

| 性能値 | 内容 |
|---|---|
| 全長 | 真空専用エンジンは膨張比を大きく取るためノズルが長く重い。比推力の高いエンジンほど長い。設計上は機体後端から突き出す長さとして現れる |
| 点火1回あたりの推進剤損失 | 極低温エンジンは点火のたびに配管とポンプを冷却する必要があり（チルダウン）、数キログラムから数十キログラムを捨てる。常温貯蔵性はほぼ0。細かい軌道修正を何度も行う運用では積み上がる |
| 連続燃焼時間の上限 | アブレーティブ冷却の加圧式、および凝縮相を生む推進剤（固体、液体酸素／シラン）に上限がある。再生冷却のポンプ式は上限なし。上限に達したエンジンは強制的に停止し、冷却されるまで再着火できない |
| ジンバル速度 [deg/s] | 可動角に加えて速度を持つ。速い姿勢変化には追従できず、追従しきれないぶんは姿勢制御系が補償する |

エンジン部品の比推力は `推進剤ペアの比推力 × サイクルの比推力係数` とする。推力と質量と全長はサイクルとサイズから決める。ジンバル可動角とジンバル速度もサイクルごとに定める。

### 14-3. ツィオルコフスキーによる燃焼計算

燃焼時間と点火時刻はツィオルコフスキーの式に基づいて求める。

```
src/physics/tsiolkovsky.ts   (純関数)
    dvFor(m0, mf, isp)               // Δv = Isp·g0·ln(m0/mf)
    massAfterBurn(m0, dv, isp)
    burnTimeFor(dv, m0, thrust, isp) // 推進剤流量 = thrust/(Isp·g0)
    propellantForDv(dv, mDry, isp)
```

一定加速度を仮定すると質量比の大きい機体で点火が遅れてマニューバノードを外すため、質量変化を必ず含める。

点火1回あたりの推進剤損失は、燃焼に必要な推進剤とは別に、点火の時点で一括して差し引く。したがって Δv がごく小さいノードでは、損失のほうが燃焼で使う量を上回ることがある。

### 14-4. 推進剤とエンジンの劣化

劣化には性質の異なる3つの形がある。

| 対象 | 劣化の形 | 回復 |
|---|---|---|
| 極低温推進剤 | 日射に応じて蒸発し、**残量が減る**。断熱材の等級と遮蔽で低減できる | しない（補給のみ） |
| ヒドラジン単推進剤スラスタ | 触媒床の活性が累積噴射時間に応じて低下し、**比推力が落ちる**。推進剤自体は密閉容器内で10年以上安定であり、量は減らない | 整備で回復する |
| 固体推進剤・イナートガス・常温貯蔵性の二液推進剤 | 劣化しない | — |

推進剤が減る劣化と、性能が落ちる劣化は別のものである。前者は補給でしか埋まらず、後者は基地での整備で回復する。

劣化の計算は毎フレームでは行わず、残量または比推力を読む時点で前回の評価時刻からの経過時間（または累積噴射時間）に基づいて一括で計算する。

## 17. 主要な技術的リスク

1. **複合断面の輪郭抽出** — 複合断面の外周は、基本断面の輪郭から貼り合わせ面を除いて連結したものである。貼り合わせ面が完全に一致していることが前提であり、浮動小数点の誤差で隙間や重なりが生じると輪郭が破綻する。辺の長さの一致は検証で保証し、輪郭の連結は頂点の同一性ではなく、貼り合わせの木構造をたどって構成する。

2. **断面をまたぐ頂点の対応** — 辺数の異なる断面や、回転位相の異なる断面をつなぐとき、頂点の対応を誤ると外皮がねじれる。弧長による120点への等分と、対応距離の総和を最小にする割り当てで解決するが、両端の位相差が大きい場合や、複合断面と単一断面をつなぐ場合の見た目は確認が必要である。

3. **円の弓形差し引き** — 円に複数の側面の口を設けたとき、隣接する弓形同士が重なる場合がある。分岐数が多く、口の幅が広いときに起きる。重なる構成は検証で拒否する。

4. **減衰最小二乗の正則化重み** — λ が小さすぎると、要求をわずかに良く満たすために対向するスラスタを同時に噴かせ、推進剤を無駄に消費する解が選ばれる。大きすぎると要求トルクを十分に出せない。λ はアクチュエータの規模に依存するため固定値では足りず、行列 A の特異値の大きさに対する相対値として決めること。

5. **アンローディングの発振** — フライホイールの飽和と外部トルクによる角運動量の排出は互いを打ち消す方向に働くため、閾値と排出量の取り方によっては、飽和と排出を短周期で繰り返す状態に落ち込む。排出の開始と終了に別々の閾値を設け、開始した排出は下側の閾値に達するまで続けること。磁気トルカによる排出は極めて遅いため、この往復の周期は軌道周期の程度になる。

6. **磁気トルカで出せない軸** — τ = m × B は B に平行なトルクを出せないため、その軸の要求は原理的に磁気トルカでは満たせない。配分が「磁気トルカで出せる」と誤って判断すると、その軸の姿勢が制御されないまま放置される。B に垂直な成分だけを扱い、平行成分は必ず次の段へ落とすこと。

7. **姿勢制御の要求元の一元化** — 現在は手動操作の経路と自動操縦の経路が、それぞれ機体のトルクを直接書いている。両方を `AttitudeControlSystem` への要求に置き換えないと、片方がフライホイールの角運動量を更新せずにトルクを出すことになり、飽和の計算が合わなくなる。トルクを書く箇所を1つに絞ること。

8. **重力傾斜トルクと時間加速** — 重力傾斜トルクは軌道周期の程度の時定数を持つため、時間加速下では1ステップの姿勢変化が大きくなる。姿勢積分の運動エネルギー射影が発散しないことを、高倍率での長時間の待機で確かめること。

9. **時間加速中の燃焼** — 質量変化を含む燃焼計算は、1ステップが数十秒に達する時間加速下では、ステップ内での質量変化が無視できない。燃焼中のステップは閉形式で質量を進めるか、燃焼の開始と終了の時刻でステップを区切ること。

10. **カプセル判定の費用** — 機体1機がエッジの数だけカプセルを持つため、機体同士の判定は組み合わせになる。外接球による広域の絞り込みを必ず先に通し、球が交わる場合のみカプセル同士を総当たりする。エッジ数の上限が判定の上限を決める。

11. **姿勢依存の `bcInv`** — 毎フレーム速度方向と機体姿勢から投影面積を求めることになる。計算自体は内積3回で済むが、予測軌道の積分でも同じ値が要る。予測は未来の姿勢を持たないため、**予測では現在の姿勢の値を固定して使う**。これは姿勢を保っている機体では正確であり、回転している機体では平均から外れる。再突入の予測が姿勢に依存することを、UI で示す必要がある。

12. **抗力の増加による再突入バランスの変化** — 現在の `bcInv` は、質量の仮定が実際の機体質量と食い違っており、本来より小さい値になっている。形状と実質量から導出すると抗力が増え、大気減衰と再突入のタイミングが変わる。これはステージの敗北条件に直結するため、F7 の時点でステージ側の高度と時間の調整が要る。

13. **推力軸のずれによる制御不能** — 主機を非対称に積むと、推力軸が重心を大きく外れる。ジンバル補償で打ち消しきれない構成は、警告を出したうえで、それでも機体が回ることを許すか拒否するかを決めておくこと。ジンバル速度の上限があるため、可動角が足りていても速い外乱には追従できない。

14. **描画メッシュの生成コスト** — 背骨から生成するメッシュは実行時生成であり、`WebGPURenderer` はジオメトリを最初の描画時にキャッシュする。生成は形状の変更時のみとし、既存メッシュのジオメトリを差し替えない運用を守る必要がある。

15. **保存形式の互換性** — 機体の表現が変わるため、旧形式の保存データは既定の設計への読み替え以上のことはできない。読み替え不能な保存データは明示的に拒否し、破損した機体を生成しないこと。

16. **UIの総量** — 推進系パネルが飛行中のHUDに加わる。既存のパネルへ統合できないかを確認し、置き場の規約に従うこと。飽和の通知音は頻繁に鳴りうるため、連続して鳴らないよう最短間隔を設けること。
