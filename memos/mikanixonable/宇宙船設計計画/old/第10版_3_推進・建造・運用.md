# 宇宙船設計計画 第10版
# 第3巻 — 推進・建造・運用の未実装部分

## 1. この文書の目的

この文書は、現行の宇宙船設計計画と第9版第3巻をコードベースへ照合し、**まだ実装されていない部分だけ**を第10版の実装計画としてまとめたものである。

既に実装済みの純粋計算、データ型、検証、テスト、基地の2D生産・整備UIは本書の作業対象から除外する。既存実装を再利用する箇所は、各項目で明示する。

### 1.1 現在実装済みとして扱うもの

- `Vessel`、`VesselAssembly`、`VesselTree`、`PartPlacement`、`VesselBlueprint`
- ノード・エッジ・断面・接続口のデータモデルと検証
- `deriveMassProperties` による質量、重心、慣性テンソルの導出
- 外皮形状の解析 (`hull-shape.ts`)、三角形化 (`hull-triangles.ts`)、ロフトメッシュ生成 (`loft-mesh.ts`)
- 船のアセンブリからの外皮・外装部品描画 (`buildHullMesh`)
- 接触カプセル、姿勢制御、推進剤、エンジン、推力軸、基地資源、採掘・輸送の基盤
- 部品の生産、基地の生産タブ、格納艦の修理・補給・同種部品換装
- `PropertyWindow`、`Button`、`TabBar`、`OverlayManager` などのUI基盤

### 1.2 本書で実装する未実装部分

1. 「戦闘ビュー」を「運用ビュー」へ名称整理する。
2. 船と基地を部品単位の3Dモデル集合として描画する。
3. 基地ドックに3D作業台を追加する。
4. ドラッグ・スナップで部品を組み立て、換装し、分解する。
5. 分解した部品を倉庫・他の船・基地へ移送して再利用する。
6. 実機部品と仮構成部品に共通の個別プロパティーウィンドウを提供する。
7. コア部品の有無による宇宙船・貨物の分類を実行時へ接続する。
8. 構成変更を物理、HUD、操作対象、セーブへ一括反映する。

## 2. 現状のアーキテクチャと問題

### 2.1 船

船の論理構成はすでに `VesselAssembly` に集約されている。`VesselTree` のノードとエッジから外皮形状・構造質量・接触形状を導き、`PartPlacement` から搭載部品を配置する。

ただし、3D描画は部品単位の選択・移動を前提に整理されていない。`buildHullMesh` はアセンブリから完成した描画オブジェクトを生成するが、ドック作業台で扱うための安定した部品参照ID、仮配置、ゴースト、選択状態が不足している。

### 2.2 基地

基地は論理上 `Vessel` であり、`orbitalBaseAssembly()` も存在する。しかし描画は `buildBaseModel()` の固定大型モデルに依存している。中央ハブ、トラス、ドック、タンク、貨物、バルブ、ストラップなどが一つのモデル生成関数に埋め込まれており、論理部品との1対1対応がない。

この二重化を解消し、基地も船と同じアセンブリ→部品描画経路へ移行する。

### 2.3 現在のドック

`Vessel.attachDockedVesselMesh()` は完成済みの船の `renderObject` を基地の子オブジェクトとして配置する。これは収容表示であり、部品を扱う作業台ではない。

`BaseView` には修理・補給・同種部品の換装があるが、以下は未実装である。

- 3D部品の選択
- 部品のドラッグとスナップ
- 部品の取り外し・分解
- 部品の倉庫への移動
- 別の船・基地・貨物への部品移送
- 複数対象をまとめた一括適用

## 3. 基本仕様

### 3.1 運用ビュー

現在の「戦闘ビュー」という名称を廃止し、航行、戦闘、回収、接近、ドッキング、基地運用を含む画面を「運用ビュー」と呼ぶ。

- 表示ラベル、ヘルプ、ヒント、モードバッジを更新する。
- 組み立ては運用ビュー上の基地ドックからのみ開始する。
- 飛行中、戦闘中、ドック外の対象に組み立て入口を表示しない。
- ドック作業台を開いている間は物理、推力、射撃、姿勢制御、時間加速を停止する。

### 3.2 宇宙船と貨物

次のいずれかのコア部品を一つ以上持つ構成を宇宙船とする。

- 有人コックピット
- 自動操縦装置

コア部品を持たない構成は貨物とする。

- 貨物は単独の操作対象にできない。
- 貨物はドッキング、牽引、輸送、基地収容ができる。
- コア部品を追加すると宇宙船へ昇格する。
- すべてのコア部品を外すと貨物へ降格する。

この分類を、操作対象選択、自動操縦、ドッキング、基地ドック、HUD、セーブへ接続する。

## 4. 部品単位の3D描画

### 4.1 描画契約

`PartVisualFactory` と `AssemblyRenderObject` を追加し、アセンブリから部品単位の `THREE.Object3D` を生成する。

```ts
interface PartVisualContext {
  readonly partRef: string;
  readonly placement: PartPlacement;
  readonly selected: boolean;
  readonly preview: boolean;
  readonly invalidReason: string | null;
}

interface PartVisual {
  readonly partRef: string;
  readonly object: THREE.Object3D;
  update(context: PartVisualContext): void;
  dispose(): void;
}
```

`partRef` はパーツ種別ではなく、搭載スロット、倉庫エントリ、仮構成内の参照を含むセッション内の安定キーとする。既存部品に個体IDが無い場合でも交換前後を取り違えないようにする。

### 4.2 船の移行

- `hull-shape.ts` と `hull-triangles.ts` による外皮生成はそのまま利用する。
- `buildHullMesh` の外皮、トラス、外装部品を、部品参照IDを持つ子オブジェクトへ整理する。
- `mountFrame`、`placeFitting`、パネル生成を部品描画ファクトリから呼べるようにする。
- 部品の選択・仮配置・不正状態・プロパティーウィンドウを子オブジェクトへ接続する。
- 形状が変わった場合、WebGPUの制約に従いジオメトリ差し替えではなく安全なメッシュ再生成を行う。

### 4.3 基地の移行

- `buildBaseModel()` の固定要素を、基地用の `VesselTree` と `PartPlacement[]` へ移す。
- `orbitalBaseAssembly()` から基地の外皮、トラス、居住区、貨物区画、ドック、タンク、太陽電池、配管を生成する。
- 現在固定モデルに埋め込まれたオレンジ色のバルブ、貨物固定ストラップ、識別タグを、対応するタンク・貨物・設備部品の子モデルまたは個別装飾部品として分類する。
- 旧 `buildBaseModel()` は移行期間の比較用フィクスチャとし、新規実行経路では参照しない。
- 固定モデルとアセンブリ描画を並べた回帰比較を作り、位置、寸法、外観、ドック位置を確認する。

## 5. 基地ドック作業台

### 5.1 開始と対象

1. 運用ビューで基地を選択する。
2. 基地のドック区画を開く。
3. 格納済みの宇宙船、貨物、基地部品を選択する。
4. 「組み立て・整備」を開始する。

ドック外の対象を直接編集する経路は作らない。作業台を開くと対象、倉庫、基地部品のスナップショットを作成する。

### 5.2 3D操作

- 部品をクリックすると個別プロパティーウィンドウを開く。
- 倉庫または作業台の部品をドラッグするとゴーストを表示する。
- 接続可能なノードの口、エッジの外表面、トラス上の取付点をハイライトする。
- 部品を近づけた位置で、断面、位相、長さ、作業範囲、干渉を判定する。
- 有効な位置では吸着候補を表示し、ドロップ時に仮構成へ登録する。
- 無効な位置では理由を表示し、仮配置へ登録しない。
- 完成した部品を対象の外へドラッグすると、分解候補として作業台または倉庫へ移す。
- 宇宙空間へ直接放出する操作は初期版では提供しない。

### 5.3 ノード・エッジ・外皮の扱い

ノードとエッジは、プレイヤーが自由に動かす編集対象ではなく、部材の突き合わせ結果から生成する。

- 部材1個がエッジ1本になる。
- 接続口の対がノード1個になる。
- `hull` エッジは両端断面をロフトした外皮帯と露出端の蓋を持つ。
- `truss` エッジは外皮を持たず、断面サイズに応じた骨組みとして描画する。
- `decoupler` エッジは外皮を持たず、分離境界と接続部品として表示する。
- 閉路を作る最後の部材は両端の口を同時に検証し、長さ不一致なら吸着を拒否する。
- 仮構成は半透明または輪郭表示、検証エラーは赤系強調、選択中はオレンジ系強調で表示する。

ノードのプロパティーには断面・軸・位相・接続口、エッジのプロパティーには種別・長さ・両端ノード・内容積・外皮/骨組み状態を表示する。

### 5.4 パーツプロパティーウィンドウ

完成済みの部品と仮構成中の部品で同じウィンドウを使う。

- パーツ名、種別、`partRef`、状態
- 搭載中、倉庫、仮装着、交換前、交換後、取り外し予定
- 質量、容積、取付位置、接続先
- HP、損傷、燃料、弾薬
- 推力、トルク、電力、発熱、通信などの固有性能
- 実機の現在値と仮構成適用後の予測値
- 仮装着、交換、取り外し、分解の操作
- 適用不可の理由

ウィンドウを閉じても編集セッションは継続する。仮構成から部品が削除されたときだけ、そのウィンドウを閉じる。

## 6. 分解・換装・部品移送

### 6.1 仮構成セッション

`DockWorkbenchSession` を新設する。実機を直接変更せず、次を保持する。

- 対象ごとの元のアセンブリ
- 対象ごとの仮アセンブリ
- 基地倉庫の元在庫と仮在庫
- 部品の所有者と `partRef`
- 選択部品、選択ノード、選択エッジ
- プロパティーウィンドウの状態
- 検証警告とエラー

同じセッションで次の操作を組み合わせられる。

- 船Aから部品を外し、倉庫へ送る
- 船Aの部品を船Bへ移す
- 基地から貨物へ部品を取り付ける
- 貨物へコア部品を取り付けて宇宙船へ昇格する
- 宇宙船からコア部品をすべて外して貨物へ降格する

### 6.2 適用時の検証

全対象を一括で検証する。

- 接続グラフ、断面、長さ、位相、作業範囲
- 必須部品とコア部品
- 配管、電力、通信、熱、推進、姿勢制御
- 部品の干渉と二重使用
- ドック容量、作業台容量、所有権
- 損傷、燃料、弾薬など状態値の引き継ぎ

検証成功後にだけ、次を一括更新する。

1. 各対象のアセンブリと部品一覧
2. 質量、重心、慣性、接触形状、能力
3. 基地倉庫と資源台帳
4. 3Dモデル、HUD、操作対象、自動操縦状態
5. セーブデータ

失敗、キャンセル、保存失敗時は全対象を元に戻す。

## 7. 実装フェーズ

### Phase 1: 未接続状態の整理

- 運用ビューへの名称変更
- 組立入口を基地ドック区画だけへ限定
- 現在の2D生産・整備UIと新しい作業台の責務を分離
- `DockWorkbenchSession` の純粋な状態遷移とロールバックテスト

### Phase 2: 船の部品単位描画

- `PartVisualFactory` と `AssemblyRenderObject`
- 船の外皮・トラス・外装部品の部品参照ID
- 3D選択とパーツプロパティーウィンドウ
- 仮構成、ゴースト、検証エラーの表示

### Phase 3: 基地のアセンブリ描画への移行

- 固定 `buildBaseModel()` の要素を基地アセンブリへ移行
- ドック、タンク、貨物、バルブ、ストラップを部品単位化
- 固定モデルとの回帰比較
- 基地の接触形状とドック位置を新アセンブリから導出

### Phase 4: ドラッグ・スナップ作業台

- ドック専用カメラ、作業平面、レイキャスト
- 接続口、エッジ外表面、トラス取付点の選択
- 部材ゴースト、候補ハイライト、スナップ
- ノード・エッジ生成と `treeFromDraft` 接続
- 外皮、トラス、分離機構の仮表示

### Phase 5: 分解・換装・移送

- 対象の外へドラッグした部品の倉庫移動
- 船・基地・貨物間の部品移送
- コア部品による宇宙船/貨物の昇格・降格
- 損傷、燃料、弾薬の状態引き継ぎ
- 一括検証と一括適用

### Phase 6: 実行時統合と保存

- 質量特性、接触形状、推進、姿勢制御、HUDの再同期
- 操作対象と自動操縦可否の再評価
- セーブ形式への仮構成・確定構成・倉庫移動の反映
- 既存セーブとの互換性と破損時の拒否

### Phase 7: 操作性と負荷対策

- undo/redo、変更履歴、部品検索、カテゴリーフィルタ
- 失敗理由の部品単位表示
- 大型基地・大量部品のLOD、インスタンシング、選択精度の改善
- 3D作業台から運用ビューへ戻る復旧経路

## 8. 受け入れ条件

- 船と基地が同じアセンブリ正本から、部品単位の3D子オブジェクトを生成する。
- 船体・基地の主要部品、ノード、エッジを3D上で個別選択できる。
- `hull`、`truss`、`decoupler` が外皮・骨組み・分離境界として区別表示される。
- 組み立ては基地ドック区画でのみ開始できる。
- 部材をドラッグして有効な接続口へスナップできる。
- ノードとエッジが突き合わせ結果から生成される。
- 完成した構成の部品を外して、基地倉庫または作業台へ分解できる。
- 分解した部品を別の船、貨物、基地へ再利用できる。
- 実機と仮構成の両方でパーツプロパティーウィンドウを開ける。
- コア部品なしの構成は貨物として扱われ、単独操作できない。
- 検証成功時だけ、対象、倉庫、資源、3Dモデル、HUD、セーブが更新される。
- 失敗、キャンセル、保存失敗時に全状態が変更前へ戻る。
- 既存の生産、修理、補給、換装、ドッキング、採掘、輸送を壊さない。

## 9. 実装上の注意

- 既存の純粋計算や検証をUIへ複製しない。
- `buildBaseModel()` とアセンブリの二重管理を長期状態として残さない。
- 形状変更時に既存メッシュのジオメトリだけを差し替えない。安全なメッシュ再生成を行う。
- 部品の種別だけで選択状態を管理しない。`partRef` を使う。
- 実機値と仮構成予測値を同じ表示欄へ混在させない。
- 分解によってコア部品が失われる場合、宇宙船から貨物への降格を適用前に表示する。
