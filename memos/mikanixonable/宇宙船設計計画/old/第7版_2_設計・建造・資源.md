# 設計・建造・資源 — 実装計画

## 1. 対象と第1巻との関係

この計画は2巻からなる。

**第1巻『基盤』**は、機体という物がどう成り立っているかを定める。`Vessel` への統合、搭載要素の型と性能値、断面と背骨の幾何、形状からの質量特性の導出、カプセルによる接触形状、姿勢依存の空力、外皮メッシュの生成、内容積の割り当ての規則、推進系の4系統と姿勢トルクの配分、推進剤の物性表とエンジンの型式が、そこに属する。

**第2巻（この文書）**は、プレイヤーがそれをどう作り、運用し、広げるかを定める。対象は次の8つである。

1. 設計データの保存と検証（§4）
2. 生産と生産可能性（§5）
3. 設計エディタ（§6）
4. 分離機構と多段、ペイロード（§7、§8）
5. 配管と推進剤の流路、タンクの与圧、弾薬の供給（§9〜§11）
6. 基地モジュール（§12）
7. 資源と産地、到達可能性、設備の連鎖（§13〜§15）
8. 推進の世代と進行経路（§16、§17）

第1巻が機体の物理を与え、この巻がその上に、設計・建造・経済の層を載せる。以下、§2 前提を除き、記述はすべてこの文書の中で完結する。

## 2. 前提

第1巻で実装済みとして扱うもののうち、この巻が使うものを挙げる。

**`Vessel`** — 艦艇と軌道基地を統合した単一のエンティティクラス。背骨と搭載要素を保持し、質量特性・推進剤・電力・熱・推進系・姿勢制御を持つ。背骨を持たない機体（敵艦）のために、質量特性を直接与える経路も持つ。

**背骨** — 船体の形状は、ノードとエッジからなるグラフ（背骨）と、各ノードが持つ断面で定義される。外皮は、エッジの両端にある2つの断面をつないだ立体（ロフト）として生成される。背骨は閉路を含んでよい。エッジは3つの種別のいずれかを持つ。

```ts
export type EdgeKind =
  | { kind: 'hull' }                                   // 外皮を作る。内側が内容積になる
  | { kind: 'strut'; radius: number }                  // 外皮を作らない構造材
  | { kind: 'decoupler'; separationImpulse: number };  // 外皮を作らず、切り離せる

export interface SkeletonEdge {
  readonly id: string;
  readonly a: string;
  readonly b: string;
  readonly length: number;         // 0.5 m 単位
  readonly kind: EdgeKind;
}

export interface VesselSkeleton {
  readonly nodes: readonly SkeletonNode[];
  readonly edges: readonly SkeletonEdge[];
}
```

**断面と寸法の刻み** — 断面は基本断面（円・楕円・多角形・切り欠き多角形）の貼り合わせで構成される。各ノードは断面の表裏に向かう2つの軸方向の接続口と、断面形状ごとに決まる側面の接続口を持つ。エッジの長さは 0.5 m 単位、断面の外接円半径は 2.0 m 未満で 0.25 m 単位、2.0 m 以上で 0.5 m 単位である。結合はすべて平面同士の突き合わせであり、断面の面積・断面二次モーメント、ロフトの体積・表面積・重心・慣性テンソルはすべて解析式で求まる。

**搭載要素** — 搭載要素は、ノードの接続口に取り付ける**外装要素**（エンジン・RCSスラスタ・武器・太陽電池パドル・放熱板・ドッキングポート）と、`hull` エッジの内容積に収める**内装要素**（各種タンク・バッテリー・コックピット・自動操縦装置・弾薬庫・配管・ペイロード倉庫・フライホイール・磁気トルカ・基地モジュール）に分かれる。エッジの種別は搭載要素ではなく背骨の性質である。1つのエッジに複数の内装要素を収めてよく、実効容積を掛けた体積の和がそのエッジのロフト体積を超えないこと。

**質量特性** — 質量・重心・慣性テンソル・投影面積は定数として持たず、背骨と断面と搭載物から導出される。

**接触形状と空力** — 剛体接触と被弾の判定は、背骨の各エッジに対応するカプセルの集合で行う。空力の投影面積は速度方向と機体姿勢から求まる。

**姿勢制御アクチュエータの配置** — RCSスラスタは任意の個数・任意の位置・任意の向きに取り付けられる。取り付けたノードの接続口の位置と向きから、各スラスタの腕の長さ `r_k` と噴射方向 `exhaust_k` が決まり、そのスラスタが生むトルクは `τ_k = r_k × (−exhaust_k)` である。要求トルクを満たす推力の組み合わせは一般に劣決定であり、その配分は第1巻が解く。この巻はその結果を使うだけである。

**エンジン** — エンジンは「サイクル（供給方式）」と「対応推進剤」の組で定義される。サイクルは加圧式・電気ポンプ式・ガス発生器サイクル・段階燃焼サイクル・エキスパンダーサイクル・固体モーター・ハイブリッドモーターの7種である。エンジンの比推力は `推進剤ペアの比推力 × サイクルの比推力係数` である。エンジンは推力・比推力・絞り範囲・再着火回数に加えて、次の4つを性能値として持つ。

| 性能値 | 内容 | この巻での用途 |
|---|---|---|
| 全長 | ノズル膨張比が大きいほど長い。機体の後端から突き出す長さとして目に見える | 段の外形と分離時の干渉 |
| 点火あたりの推進剤損失 | 始動シーケンスで捨てる分 | 分割したマニューバノードの2つ目に加算する |
| 連続燃焼時間の上限 | 冷却の限界。無制限のものもある | 燃焼の分割の判定 |
| 要求与圧 | タンク入口に要求する圧力。加圧式のみが高い値を要求し、ポンプ式はポンプ入口圧（NPSH）として低い値でよい。固体モーターは与圧も配管も要さない | §10 の与圧計算と推力低下 |

**燃焼計算** — `src/physics/tsiolkovsky.ts` に、質量変化を含む燃焼計算が純関数として置かれている（`dvFor` / `massAfterBurn` / `burnTimeFor` / `propellantForDv`）。推進剤流量は `推力 / (比推力 × 標準重力加速度)` である。

**イナートガスの物性** — 与圧の計算に用いる。

| ガス | 密度（20 MPa, 常温） | 特性 |
|---|---|---|
| ヘリウム | 33 kg/m³ | 軽く、極低温でも凝縮しない。必要質量が小さい |
| 窒素 | 230 kg/m³ | 安価だが重い。極低温推進剤には使えない |

**イナートガスタンクの実効容積** — 内圧に対して最も効率のよい圧力容器は球であり、イナートガスタンクは球状である。同じ耐圧なら球は円筒より薄い壁で済み、タンク自体の質量が小さい。一方、球は角柱状の内容積に詰めたときの充填率が悪い。この対立が、エッジの内容積に対する実効容積の係数 **0.55** として現れる。

**能力の判定** — `hasCockpit` / `hasAutopilot` / `hasBaseModule` / `hasEngine` / `isOperable`。設計の検証と、設計エディタを開ける条件の判定に用いる。

## 3. 設計判断

### 3-1. 設計と生産を分ける

プレイヤーは、資源を消費せずに設計を作り、名前を付けて保存し、読み込める。実機を得るには、保存した設計を指定して生産する。生産には時間がかかる仕組みを持つが、初期状態ではすべての設計の生産時間を0とする。

持っていない推進剤やエンジンを使った設計も、設計としては正当であり、保存できる。制約を受けるのは生産だけである。この扱いによって、設計エディタは**目標を提示する装置**になる。核融合エンジンを積んだ機体を最初から設計でき、それを作るには何が要るのかが一覧として見える。

### 3-2. 段はプレイヤーが区切るのではなく、分離機構から決まる

段を明示的に定義する操作は存在しない。段は、背骨から `decoupler` エッジを取り除いたときの連結成分である。プレイヤーが分離機構を挿すと、その両側が自動的に別の段になる。

### 3-3. 分離は自動では行わない

推進剤が尽きた段は分離の候補として提示するが、自動では分離しない。分離は運動量保存により軌道を変えるため、いつ切り離すかは軌道上の判断であり、実行はプレイヤーまたは軌道計画に委ねる。

### 3-4. 積荷の受け渡しは結合を必要としない

ペイロードの放出は、独立した物体を軌道上に生成する操作である。放出された弾薬は既存の補給パッケージと同じ実体であり、艦艇は既存の接近回収の仕組みでそれを取る。機体同士を結合する仕組みには依存しない。

### 3-5. 推進剤はタンクから配管を通ってエンジンへ流れる

配管は搭載要素の一つであり、背骨のエッジに割り当てられる。タンクからエンジンまで配管が連続していないエンジンは点火できない。配管には口径ごとの流量上限があり、エンジンの要求流量を満たさない配管は推力を制限する。

タンクとエンジンの接続を暗黙に成立させる方式は採らない。配管が明示的な実体としてあることで、側面ブースターから中央段への推進剤の送り（クロスフィード）、分離による流路の切断、流量不足による推力制限といった、多段機の設計上の判断が、いずれも同じ一つの仕組みの帰結として現れる。

### 3-6. 配管の敷設は自動を既定とし、手動はその上書きとする

タンクからエンジンへ配管を通すことには、ほとんどの場合に唯一の正解しかない。選択の余地のない操作をエッジの数だけ繰り返させるのは作業であって遊びではない。

したがって**自動敷設を既定とする**。設計を変更するたびに自動敷設をやり直し、プレイヤーが手で触るのは、選択に意味がある次の場合だけになる。

- クロスフィードを組む
- 口径を絞って軽量化する
- 特定のタンクを特定のエンジンに割り当てる
- 分離機構を跨ぐ配管の可否を決める

手動で敷いた区間は自動敷設の上書きとして差分で保持し、やり直しの対象から外す。

### 3-7. 技術ツリーを持たない

研究点も、前提技術の木も、解禁の状態も実装しない。ある搭載要素を使った設計を生産できるかどうかは、その時点で持っている**資源・設備・電力**だけで決まる。

プレイヤーが使える技術は、**ある資源で作った設備が次の資源を生み、その資源が次の設備を可能にする**という連鎖によって広がる。この構造の要点は、**進行を止めるものが常に物理的な事実である**ことにある。メタンを作れないのは技術が未解禁だからではなく、炭素を持っていないからである。炭素を持っていないのは、月に炭素がないからである。炭素を得るには、炭素のある場所へ行くか、炭素を持つ敵を倒すしかない。

### 3-8. 生産に通貨は使わない

機体と搭載要素の生産に必要なのは、**資源・設備・電力の3つだけである。**通貨は生産の要求に含まれない。作れないものは、金がないから作れないのではなく、材料か設備か電力が足りないから作れない。

クレジットは廃止しない。**基地の市場での資源の売買**に用いる。余った資源を売り、足りない資源を買える。ただし市場で買える量には上限があり、遠方の資源（ヘリウム3、白金族など）は市場に出回らない。**それらは自分で採りに行くしかない。**市場は近距離の資源のやりくりを滑らかにするだけであり、進行の壁を金で越えることはできない。

## 4. 設計データの保存と検証

### 4-1. 設計データ

```ts
// src/game/vessel/blueprint.ts
export interface VesselBlueprint {
  readonly id: string;
  name: string;
  readonly skeleton: VesselSkeleton;
  readonly placements: readonly PartPlacement[];
  readonly feedNetwork: FeedNetwork;    // 配管の敷設（§9）
  readonly paint: PaintScheme;
  readonly stageOrder: readonly string[];
  readonly createdAt: number;
  readonly updatedAt: number;
}
export interface PaintScheme {
  primaryColor: string;
  secondaryColor: string;
  accentColor: string;
  metalness: number;
  roughness: number;
}
```

設計は `localStorage` の `tepui.blueprints` に保存する。保存・読み込み・複製・削除・改名ができる。既存のセーブデータの入出力と同じ方式でファイルへの書き出しと読み込みも行う。

`feedNetwork` のうち自動敷設で導出できる部分は保存しない。保存するのは手動の上書き（`manual: true`）だけであり、残りは設計から毎回導出する。

### 4-2. 検証

設計の検証は独立した純関数とし、エディタと生産の両方が同じ関数を呼ぶ。

```ts
// src/game/vessel/blueprint-validation.ts
export interface BlueprintIssue {
  readonly severity: 'error' | 'warning';
  readonly targetId: string;      // ノード／エッジ／搭載要素の id
  readonly message: string;
}
export function validateBlueprint(bp: VesselBlueprint): readonly BlueprintIssue[];
```

検証する内容:

- 背骨が連結していること
- 複合断面の貼り合わせ面の長さが一致すること
- 側面の口から出るエッジの断面が、口の周方向・軸方向の両方の寸法に収まること
- 隣接する側面の口が干渉しないこと
- 1つの接続口に、エッジと外装要素が同時に割り当てられていないこと
- 内容積の割り当てがロフト体積を超えないこと
- 内装要素がまたぐエッジが軸方向に連なっていること
- 推進剤とタンク材料が適合すること
- コックピットまたは自動操縦装置を1つ以上持つこと
- 推力軸と重心のずれが規定内であること
- ノード数・総質量・最大寸法・複合断面の構成要素数が上限以内であること
- タンクからエンジンまで、要求する推進剤ごとに配管が連続していること
- 加圧を要するエンジンに対し、イナートガスの供給経路があるか、自己加圧の条件を満たすこと
- 武器と弾薬庫が同じ段に属すること
- 回転する重力区画に対し、角運動量を打ち消す手段があること（§12-1）

**生産に必要な資源と設備が揃っているかは、この検証では扱わない。**設計そのものの成立と、それを作れるかどうかは別の問いであり、後者は生産可能性の判定（§5-2）が答える。

## 5. 生産と生産可能性

### 5-1. 生産

生産は、保存した設計を指定し、**資源と設備と電力**を消費して実機を得る操作である。通貨は使わない。

```ts
export interface ProductionTask {
  readonly id: string;
  readonly blueprintId: string;
  readonly startedAt: number;      // simTime
  readonly finishAt: number;       // simTime
}
```

- 消費する資源は、搭載要素ごとの資源コストと、外皮の質量に対応する構造材の和とする。
- 生産時間は搭載要素の合計に**生産時間係数**を掛けて求める。この係数は**セーブデータに含め、ステージごとの既定値を持つ**。既定値は0であり、すべての設計が即座に完成する。係数を後から有効にしても、既存のセーブに影響しない。
- 生産キューは基地モジュールを持つ機体が保持する。完成した機体はその基地のドックに配備される。

### 5-2. 生産可能性

```ts
// src/game/economy/producibility.ts
export interface Requirement {
  readonly kind: 'resource' | 'facility' | 'power';
  readonly id: string;
  readonly needed: number;
  readonly available: number;
}
export function producibility(
  bp: VesselBlueprint,
  ledger: ResourceLedger,
  facilities: readonly string[],
  powerAvailable: number,
): readonly Requirement[];   // 空配列なら生産できる
```

**通貨は引数に含まれない。**生産の可否は資源・設備・電力だけで決まり、クレジットの残高はいかなる形でもこの判定に影響しない。

不足している要求は、設計エディタが「何が足りないか」として表示する。さらに、その資源が**どの設備から作れるか**、その設備が**何を要するか**を `FACILITIES`（§15）から辿って表示する。プレイヤーは足りないものを起点に、必要な連鎖を遡って読める。

`producibility` はタンクを持つ設計に対して材料適合性の表（§13-2）を引き、積む推進剤に適合する材料を在庫が満たすかどうかも要求として列挙する。

## 6. 設計エディタ

基地モジュールを持つ機体の基地ビューに「設計」タブを置く。既存のウィジェット（`src/game/hud/widgets/`）のみで構成し、生の `<button>` および `<input>` を直接書かない。

**モードは4つである。**断面の編集は骨格モードの中で行い、独立したモードにしない。断面はノードの属性であり、ノードを選んだときに左パネルへ編集欄が出れば足りる。段の一覧も独立したモードにせず、右パネルの常設表示に置く。モードが増えるほど、プレイヤーが「今どのモードにいるか」を把握する負担が増える。

右パネルの性能表示は、要素を選択またはホバーしている間、その要素を追加した場合の差分を数値の横に併記する。

### 6-2. 骨格モード

左パネルの内容:

| 区画 | ウィジェット | 内容 |
|---|---|---|

- **ノードの追加** — 選択中のノードの空いている接続口をクリックする。既定の長さのエッジと、同じ断面のノードが生える。生えた先が新しい選択対象になる。3Dビューポート上の接続口を直接クリックしても同じ操作になる。

- **元に戻す／やり直す** — 設計データ全体のスナップショットを操作ごとに保持する。上限は50手とする。

## 7. 分離機構と多段

### 7-1. 段の定義

段は、背骨から `decoupler` エッジを取り除いたときの連結成分である。

```ts
// src/game/vessel/assembly.ts
export interface VesselStage {
  readonly id: string;
  readonly edgeIds: readonly string[];
  readonly hasCockpit: boolean;
  readonly hasAutopilot: boolean;
  readonly dryMass: number;
  readonly propellantMass: number;
}
export function splitStages(skeleton: VesselSkeleton, parts: readonly AnyPart[]): readonly VesselStage[];
```

コックピットまたは自動操縦装置を含む段は、分離後も操作または自動制御の対象になる。どちらも含まない段は、分離後は制御不能な物体として軌道上に残る。

### 7-2. 分離の物理

分離は運動量保存を満たす。分離前の質量を `m_total`、分かれる2つを `m_a` / `m_b`、分離機構の力積から求まる相対速度増分を `Δv_sep` とすると、

```
v_a = v + (m_b / m_total) · Δv_sep
v_b = v − (m_a / m_total) · Δv_sep
```

角運動量も同様に分配する。分離直後の一定時間は、分かれた2つの間の接触判定を無効にする。

分離後、本体は背骨・質量・重心・慣性テンソル・推進剤残量・配管の流路を再計算する。分離機構を跨いでいた配管は切断される。

### 7-3. 燃焼の順序

同時燃焼（並列に束ねたブースター）と逐次燃焼（直列の多段）の両方を許す。段の一覧は分離順に並べ替えられ、飛行中はその順序に従って次に分離する段をHUDに表示する。

推進剤が尽きた段は分離の候補として提示するが、自動では分離しない。

### 7-4. 段を跨ぐ燃焼の判定と分割

段の切り替わりを跨ぐ燃焼は加速度が不連続になり、閉形式の点火時刻計算が成立しない。1つのマニューバノードの燃焼が1つの段の中で完結する必要がある。

**判定式は、そのノードの Δv に対する `propellantForDv(dv, mDry, isp)` が、そのノードを実行する段の推進剤残量を超えるかどうかである。** 超えない場合は何もしない。

超える場合、UIは**禁止するのではなく、ノードを2つに分割することを提案する**。分割は、その段の推進剤で出せる Δv までを1つ目のノードとし、残りを2つ目のノードとする。1つ目の燃焼終了後に段を分離し、2つ目を次の段で実行する。2つ目のノードには、次の段のエンジンの点火あたりの推進剤損失が加算される。

禁止するだけでは、プレイヤーは何をすればよいか分からない。分割案を提示し、受け入れるかどうかを選ばせる。

連続燃焼時間の上限を持つエンジンについても同じ判定を行う。要求される燃焼時間が上限を超える場合、上限までを1つ目のノードとして同じ形で分割を提案する。

## 8. ペイロード

ペイロード倉庫は、軌道上へ運ぶものを収める。エッジの内容積に対する実効容積の係数は 0.90 であり、容積と最大積載質量の両方で制限される。

```ts
export type PayloadKind =
  | { kind: 'ammo'; magazines: number }
  | { kind: 'propellant'; propellantId: string; mass: number }
  | { kind: 'part'; partIds: readonly string[] }
  | { kind: 'none' };

export interface PayloadBayPart extends Part {
  readonly type: 'payload_bay';
  readonly volume: number;
  readonly maxMass: number;
  payload: PayloadKind;
}
```

**弾薬をペイロードとして運ぶ運用** — 弾薬マガジンを積んだ無人ブースターを、自動操縦装置による自動操縦で目的の軌道に投入する。到達後、ペイロード倉庫を開いて弾薬を放出すると、既存の補給パッケージと同じ実体が軌道上に生成される。艦艇はそれに接近して回収する。

この運用は機体同士の結合を必要としない。放出された弾薬は独立した物体として軌道を回り、艦艇は既存の接近回収の仕組みでそれを取る。

放出は、プレイヤーの明示的な操作、または軌道計画上の指定時刻に行う。放出時には小さな分離速度を与え、ブースター本体と弾薬が離れる。

ペイロード倉庫は機体内部の容積であり、機体の外形に現れない。着脱して軌道上に置ける規格化された容器はコンテナ（§12-6）であり、こちらは外装要素として取り付ける。**輸送にはコンテナが向き、投下にはペイロード倉庫が向く。**

## 9. 配管と推進剤の流路

推進剤はタンクからエンジンへ、配管を通って流れる。

```ts
// src/game/vessel/feed-network.ts
export interface FeedNetwork {
  readonly links: readonly FeedLink[];   // 配管が敷かれたエッジ
}
export interface FeedLink {
  readonly edgeId: string;
  readonly propellantId: string;   // この配管が通す推進剤
  readonly diameter: number;       // m
  readonly maxFlowRate: number;    // kg/s
  readonly manual: boolean;        // 手動の上書きか（自動敷設のやり直しで保持される）
}
export function resolveFeed(
  network: FeedNetwork,
  tanks: readonly TankPart[],
  engines: readonly EnginePart[],
): readonly EngineFeedResult[];
```

規則:

- 配管は1本につき1種類の推進剤しか通さない。酸化剤と還元剤を同じエンジンへ送るには、配管が2本必要である。イナートガスも同様に別の配管を要する。
- タンクとエンジンが、同じ推進剤の配管で連続して繋がっていることが点火の条件である。繋がっていないエンジンは点火できず、エディタと飛行中HUDがその旨を表示する。
- 配管の口径から決まる最大流量が、エンジンの要求流量（`推力 / (比推力 × 標準重力加速度)`）を下回る場合、エンジンの推力はその流量で制限される。
- タンクとエンジンが同じエッジの内容積に同居する場合、配管は不要である。
- 分離機構のエッジを配管が跨ぐ場合、分離と同時に配管が切断される。跨ぐことを許すかどうかはプレイヤーが選ぶ。跨ぐ配管を敷けば、側面ブースターのタンクから中央のエンジンへ推進剤を送る運用（クロスフィード）ができ、分離時点で中央段のタンクを満載のまま残せる。
- 外皮のない `strut` エッジにも配管を敷ける。この場合、配管は外部に露出したものとして描画する。

配管がエッジの内容積を占める量は、口径から決まる。エッジの長さと口径の断面積の積である。

### 9-1. 自動敷設

```ts
// src/game/vessel/auto-route.ts
export function autoRouteFeed(
  skeleton: VesselSkeleton,
  placements: readonly PartPlacement[],
  overrides: readonly FeedLink[],   // 手動の上書き（manual: true のもの）
): FeedNetwork;
```

規則:

- 各エンジンに対して、そのエンジンが要求する推進剤（酸化剤・還元剤・イナートガス）ごとに、その推進剤を持つ最も近いタンクから最短経路で配管を通す。距離はエッジの長さの和とする。
- 口径は、そのエンジンの要求流量を満たす最小のものを選ぶ。同じエッジを複数のエンジンが共有する場合、口径は要求流量の和を満たす最小のものになる。
- 既定では分離機構を跨がない。跨がなければ届かないエンジンについては、跨ぐ経路を提示するが敷設はせず、供給なしとして診断に出す。クロスフィードは選択に意味のある判断であり、自動で決めない。
- 手動で敷かれた区間（`manual: true`）は保持し、自動敷設はその上に足りない分だけを敷く。手動の区間だけでエンジンへ届く場合、自動敷設はそのエンジンに対して何もしない。
- 設計を変更するたびに、この関数を呼び直す。エッジ数に対して線形である。

自動敷設の結果は手動の敷設と同じ `FeedNetwork` であり、`resolveFeed` は両者を区別しない。

## 10. タンクの与圧

液体推進剤のタンクは、推進剤を押し出すために内部を加圧する必要がある。加圧にはイナートガス（ヘリウムまたは窒素）を用いる。

- 消費するガス量は、押し出した推進剤の体積とタンクの与圧の積に比例する。
- 要求与圧はエンジンのサイクルによって決まる。**加圧式エンジンは要求与圧が高く、大量のイナートガスを要する。ポンプ式エンジンは低い与圧で足り、ガスの消費が少ない。** この差が、単純な加圧式と、複雑だが効率のよいポンプ式との設計上の対立になる。
- ヘリウムは極低温でも凝縮しないため極低温推進剤に使える。窒素は安価だが重く、極低温推進剤には使えない。

### 10-1. 与圧低下による推力低下

イナートガスが減るとタンクの与圧が下がり、エンジンの推力が下がる。与圧が要求値を下回った時点から、推力を与圧に比例して下げ、下限を割った時点で燃焼を停止する。

- **加圧式**は与圧が燃焼室圧を直接決めるため、影響が大きい。与圧の低下がそのまま推力の低下になる。
- **ポンプ式**はポンプ入口圧（NPSH）が下限を割るとキャビテーションを起こし、そこから急に推力を失う。要求値を上回っている限り影響はない。

イナートガスが尽きると、推進剤が残っていてもエンジンは推力を失う。これは実機の失敗様態と同じである。HUD には加圧ガスの残量と、その残量で燃焼を続けられる残り時間を表示する。

### 10-2. 自己加圧

イナートガスタンクを持たずに済む方式が2つある。どちらも与圧の要求を推進剤自身で満たすため、イナートガスの質量と容積を丸ごと削れる。

- **極低温推進剤の自己加圧** — 蒸発した推進剤自身の気体を加圧に用いる。イナートガスが不要になる代わりに、蒸発損失が増える。
- **亜酸化窒素の自己加圧** — ハイブリッドモーターの酸化剤である亜酸化窒素は蒸気圧が高く、それ自体でタンクを加圧できる。イナートガスタンクが不要になる。低性能なハイブリッドモーターを選ぶ理由の一つがこれであり、機体全体の乾燥質量では加圧式の液体エンジンに対抗しうる。

計算は純関数として置く。

```
src/physics/pressurant.ts   (純関数)
    pressurantMassFor(propellantVolume, tankPressure, gasType, temperature) -> number
    remainingBurnTime(pressurantMass, flowRate, tankPressure, gasType) -> number
    thrustScaleFromPressure(tankPressure, requiredPressure, cycle) -> number
```

## 11. 弾薬の供給

武器は弾薬庫からマガジンの供給を受ける。武器と弾薬庫が同じ段に属していれば供給される。段が異なる場合は供給されない。分離によって弾薬庫を失った武器は、装填済みのマガジンを撃ち尽くした時点で沈黙する。

## 12. 基地モジュール

基地モジュールを持つ機体（軌道基地・月面基地）が積む区画を、搭載要素として定義する。いずれも内装要素であり、`hull` エッジの内容積に収める。

### 12-1. 重力区画居住施設

`hull` エッジ1本を軸として回転する区画である。遠心力で疑似重力を作る。加速度は

```
a = ω² · r        （r は断面の外接円半径、ω は角速度）
```

**回転速度には上限がある。**回転する部屋の中を人が歩くとコリオリ力を受け、内耳の平衡感覚と視覚が食い違って不快感（回転酔い）を生む。この不快感は角速度が上がるほど強くなる。**毎分2回転ならほぼ問題なく、毎分4回転が実用上の限界である。**

この制約から、**現実的な機体寸法で地球重力は作れない。**

| 目標加速度 | 毎分2回転に要する半径 | 毎分4回転に要する半径 |
|---|---|---|
| 地球重力 1 g (9.81 m/s²) | 224 m | 56 m |
| 火星重力 0.38 g (3.71 m/s²) | 85 m | 21 m |
| 月面重力 0.165 g (1.62 m/s²) | 37 m | 9.2 m |

地球重力は毎分4回転でも半径56メートルを要し、断面の外接円半径の上限を大きく超える。**月面重力相当なら毎分4回転で半径9.2メートル、毎分2回転で半径37メートルであり、これは作れる範囲にある。**軌道上の基地に置けるのは低重力までであり、地球重力は得られない。

**回転区画は角運動量を持つ。**角運動量は `L = I·ω` であり、区画が回れば機体全体が反対向きに回る。設計上、次のいずれかを満たさなければならない。

- 逆向きに回る同等の区画を対で持つ
- 同じ角運動量を逆向きに蓄えるフライホイールを持つ

`validateBlueprint`（§4-2）は、回転区画の角運動量の総和と、フライホイールの容量を突き合わせ、打ち消せない設計を error として拒否する。**回転を止めるにも同じ角運動量を処理する必要がある**ため、起動と停止の両方が設計の制約になる。

駆動と軸受は電力を消費する。定常回転では軸受の摩擦ぶんだけであり小さいが、起動には `½·I·ω²` の仕事が要る。

効果は、低重力による健康の劣化を抑えることである。人員の詳細な扱いは延期目標が担う。

| 性能値 | 内容 |
|---|---|
| 回転速度 | 毎分0〜4回転。プレイヤーが設定する |
| 加速度 | `ω²·r` から導出。表示のみ |
| 角運動量 | `I·ω` から導出。打ち消しの検証に使う |
| 定常電力 | 軸受の摩擦。区画の質量に比例 |
| 収容人数 | 床面積から決まる |

### 12-2. 農場

光・水・二酸化炭素を消費し、食料と酸素を生む。

**人1人を養うのに必要な栽培面積はおよそ40〜50平方メートルである。**この面積は、必要な熱量と、栽培可能な作物の面積あたり収量から決まる。

光は2つの方式から選ぶ。

| 方式 | 消費 | 制約 |
|---|---|---|
| 電照 | 栽培面積あたり 300〜400 W。人1人ぶんで 12〜20 kW | 電力さえあればどこでも成立する |
| 太陽光導入 | 導光と追尾の機構の電力のみ | 太陽から遠ざかるほど集光面積が要る。木星では地球の27倍 |

**電照農場は電力の要求が極めて大きい。**居住人数が増えるほど、基地の電力収支に占める農場の比重が上がる。太陽光導入は電力を食わない代わりに、集光機構が機体の外形と姿勢を制約する。

農場は生命維持の閉ループの一部を担う。二酸化炭素を吸って酸素を出すため、生命維持装置の消耗品の消費を減らす（§12-3）。

### 12-3. 生命維持装置

二酸化炭素の除去、酸素の供給、水の再生、温度と湿度の管理を行う。収容人数に比例して電力と消耗品を消費する。

1人あたりの1日の収支はおおよそ次のとおりである。

| 項目 | 量 |
|---|---|
| 酸素の消費 | 0.84 kg |
| 二酸化炭素の排出 | 1.0 kg |
| 飲用水 | 2.5 kg |
| 生活用水（衛生を含む） | 20〜25 kg |
| 食料（乾燥質量） | 0.6 kg |

**閉ループ率が消耗品の補給量を決める。**水の再生だけを行う開ループでは酸素と食料を運び続けることになり、農場と組み合わせて酸素と食料を内部で作れば、補給は損失ぶんだけになる。

| 構成 | 閉ループ率 | 1人1日あたりの補給 |
|---|---|---|
| 生命維持装置のみ | 水 90%、酸素なし | 酸素 0.84 kg + 食料 0.6 kg + 水の損失 |
| 生命維持装置 + 農場 | 水 95%、酸素ほぼ閉 | 損失ぶんのみ |

電力は収容人数あたり 1.5〜2 kW である。これは農場の電照よりは小さいが、常時消費される。

### 12-4. 水タンク

水を貯蔵する。飲用・農場・電解の原料になる。

**水タンクは放射線の遮蔽として働く。**水は水素を多く含み、単位質量あたりの遮蔽性能が金属より高い。遮蔽の能力は放射線が通る経路の面密度（g/cm²）で決まり、水の密度は 1 g/cm³ であるから、面密度はそのまま**タンクの厚み（cm）**になる。

| 対象 | 必要な面密度 | 水の厚み |
|---|---|---|
| 太陽粒子線イベント | 10 g/cm² | 10 cm |
| 銀河宇宙線（実用的な低減） | 20〜30 g/cm² | 20〜30 cm |

**居住区画を水タンクで囲む配置に意味が生まれる。**背骨の配置がそのまま遮蔽の配置になり、居住区画の外周に水タンクを置いた設計は、置かなかった設計より被曝が少ない。核熱推進の炉心に対する遮蔽（§16-3）も同じ仕組みで働き、炉心と居住区画の間に水タンクを挟む配置が有効になる。

遮蔽の評価は、居住区画の各方向について、そこに至る経路上の水タンクの厚みの和を求める形で行う。全方向を囲む必要はなく、**太陽粒子線に対しては1区画だけを厚く囲った退避区画で足りる**（イベントは数時間から数日で終わるため）。銀河宇宙線は常時降り注ぐため、居住区画そのものを囲う必要がある。

### 12-5. ドック

機体を係留する区画である。収容数と、収容できる機体の最大寸法を持つ。

| 性能値 | 内容 |
|---|---|
| 収容数 | 同時に係留できる機体の数 |
| 最大寸法 | 収容できる機体の全長と最大断面半径 |
| 電力 | 係留中の機体への給電。1機あたりの上限を持つ |

係留の判定は、一定距離内かつ相対速度が小さいときに機体を格納するものとする。ドッキングポートによる結合は延期目標が担う。

生産（§5-1）で完成した機体は、その基地のドックに配備される。ドックの収容数を超える生産は、完成した時点で拒否されるのではなく、生産の開始時点で拒否する。

### 12-6. コンテナ接合部とコンテナ

**コンテナ**は規格化された貨物容器である。背骨を持たない小さな独立した物体であり、中身は資源・部品・推進剤のいずれかである。

```ts
export interface ContainerDef {
  readonly id: string;
  readonly size: 1 | 2 | 4;        // 規格の単位数
  readonly volume: number;          // m³
  readonly maxMass: number;         // kg
  contents: ContainerContents;
}
export type ContainerContents =
  | { kind: 'resource'; resourceId: string; mass: number }
  | { kind: 'propellant'; propellantId: string; mass: number }
  | { kind: 'part'; partIds: readonly string[] }
  | { kind: 'empty' };
```

規格の1単位は一辺2.0メートルの立方体とし、容積8 m³、最大積載10トンとする。2単位・4単位はこれを軸方向に連ねたものである。**この寸法は断面の外接円半径の刻み（0.5 m）の整数倍であり、コンテナ接合部を持つ機体の断面と整合する。**

**コンテナ接合部**は外装要素であり、コンテナを1つ保持する。ノードの接続口に取り付ける。

- 保持できるコンテナの規格の単位数を持つ。1単位用の接合部に4単位のコンテナは付かない。
- 保持したコンテナの質量と慣性は、機体の質量特性に加わる。接合部の位置がそのまま重心のずれになるため、**非対称なコンテナの積み方は推力軸のずれを生む。**
- 切り離すと、コンテナは独立した物体として軌道上に残る。小さな分離速度を与える。
- 回収は接合部への再結合による。一定距離内かつ相対速度が小さいときに保持する。

推進剤を積んだコンテナを接合部に保持している間、そのコンテナはタンクと同じく配管の接続先になる。接合部の付いたノードから配管を敷けば、コンテナの推進剤をエンジンへ送れる。切り離すと配管は切断される。

**ペイロード倉庫（§8）との違い。**ペイロード倉庫は機体内部の容積であり、外形に現れず、中身を放出することしかできない。コンテナは外付けで着脱でき、切り離した後も回収して再利用できる。**輸送にはコンテナが向く。**軌道上の基地へ資源を運ぶ運用では、満載のコンテナを接合部ごと切り離して基地のコンテナ接合部が受け取り、空のコンテナを持ち帰る形になる。

### 13-2. 材料適合性 — 推進剤がタンクの金属を要求する

推進剤は、どんな容器にでも入るわけではない。**推進剤の選択は、その推進剤に耐える金属を持っているかどうかに縛られる。**

| 推進剤 | 使える材料 | 理由 |
|---|---|---|
| 液体水素 | チタン合金、特定のステンレス | 水素脆化。ふつうの合金は水素が拡散して脆くなる |
| 四酸化二窒素 | アルミ合金 | **チタンとは応力腐食割れを起こす。**チタン製タンクには入れられない |
| 過酸化水素 | 高純度アルミ、特定のステンレス | 多くの金属と接触すると分解する |
| 液体酸素・液体メタン・シラン | アルミ合金、ステンレス、チタン | 特段の制約はない |
| ヒドラジン | アルミ合金、ステンレス | タンク自体の制約は緩い。**触媒床にイリジウム（白金族）が要る** |

```ts
// src/game/economy/propellant-compatibility.ts
export interface TankMaterialRequirement {
  readonly propellantId: string;
  readonly allowedMaterials: readonly string[];  // 資源 id。いずれか1つで足りる
}
export const TANK_MATERIALS: readonly TankMaterialRequirement[];
```

この適合性は、資源の依存としてそのまま働く。液体水素を積むにはチタンかステンレスが要り、四酸化二窒素を積むにはアルミが要り、その両方を積む機体は両方の金属を要する。**月のレゴリスの電解はチタンとアルミと鉄を同時に生むため、月面の基地はこの層の制約を最初から満たしている。**

**ヒドラジン単推進剤スラスタだけは、月の資源だけでは作れない。**触媒床のイリジウムは白金族であり、白金族は敵のドロップかM型小惑星からしか得られない。姿勢制御と軌道修正に最も扱いやすいこの推進系は、低軌道での戦闘を経るか、小惑星へ出るかしなければ手に入らない。

### 13-3. 産地

| 産地 | 得られる元素 | 手段 |
|---|---|---|
| **月レゴリス** | O, Si, Fe, Ti, Mg, Al | 溶融塩電解。酸素と金属合金が同時に得られる |
| **月南極の永久影** | H₂O（→ H, O） | 氷の採掘 |
| **月の KREEP 岩** | Th, U, 希土類, P | 精錬。産出量は少ない |
| **敵の残骸** | C, N, S, 白金族, 希土類 | 低軌道での戦闘 |
| **近地球小惑星（C型）** | H₂O, C, 有機物 | 採掘 |
| **近地球小惑星（M型）** | Fe, Ni, 白金族, 希土類 | 採掘 |
| **ケレス** | H₂O（大量）, 炭酸塩（C）, アンモニア塩（N） | 採掘。小惑星帯で最も水が豊富 |
| **火星** | CO₂ 大気（C, O）, 水氷, N₂ 大気（2.8%）, Ar 大気（2%） | 大気捕集と採掘 |
| **金星** | N₂ 大気（3.5%）, CO₂ 大気（96%）, 硫酸雲（S） | 大気捕集。着陸はしない |
| **木星大気** | H₂, **He**, ³He | 大気捕集。深い重力井戸からの脱出が課題 |
| **カリスト** | H₂O | 採掘。木星系で放射線が最も弱く、拠点に適する |
| **イオ** | S, SO₂ | 採掘。木星系で放射線が最も強い |
| **タイタン** | CH₄, C₂H₆（C, H）, N₂ 大気 | 採掘と大気捕集。炭素と窒素が事実上無尽蔵 |
| **エウロパ・ガニメデ** | H₂O | 採掘 |

**月には炭素と窒素がない。**これがこの進行全体の出発点にある制約である。月の資源だけで閉じる経路は存在するが、そこで得られる推進剤は性能が限られる。炭素と窒素を得るには、低軌道で敵を倒すか、月を出るしかない。**農場の食料も炭素と窒素を要する**ため、月の資源だけで自立している間、居住人数は補給に縛られる。

**ヘリウムは木星大気からしか大量には得られない。**月のレゴリスにも太陽風起源のヘリウムが含まれるが、濃度が極めて低く、極低温推進剤の与圧に足るほどは採れない。ヘリウム冷ガスという安価で高性能な姿勢制御手段は、木星系に届いてから初めて実用になる。

### 13-4. 希土類と磁気トルカ

姿勢制御には磁気トルカが使える。機体の電磁石が周囲の磁場と作るトルクでフライホイールをアンロードするもので、**推進剤をまったく消費しない。**製造には高性能磁石が要り、そのために**希土類**が要る。希土類は月の KREEP 岩、敵のドロップ、M型小惑星から得られる。

磁気トルカが働くのは磁場のある場所だけである。

| 活動領域 | 磁場 | 姿勢制御の性格 |
|---|---|---|
| 地球低軌道 | 強い | 磁気トルカが使え、アンローディングが事実上無料になる |
| 近直線ハロー軌道・月周辺 | ほぼ無い | フライホイールのアンロードにRCS推進剤を消費する |
| 惑星間・小惑星帯 | ほぼ無い | 同上 |
| 木星系 | 極めて強い | 磁気トルカが使える。ただし放射線帯が厳しい |

**低軌道での活動は姿勢制御が安価であり、月周辺へ出るとRCS推進剤の消費が効いてくる。**同じ機体でも、どこで運用するかによって推進剤の収支が変わる。磁気トルカは電力を消費し、トルクは小さく、磁場に平行な軸まわりのトルクは出せない（3軸のうち1軸が瞬間的に制御できない）。

在庫は基地モジュールを持つ `Vessel` が保持する。輸送はプレイヤーがコンテナまたはペイロード倉庫に積んで運ぶ。

産地は `physics/solar-system.ts` に登録済みの天体に紐づける。`access` が `'atmosphere'` の産地は大気捕集機で採る。着陸を必要としないため、木星・金星・タイタンの大気成分は着陸の実装を待たずに採取できる。**これにより、月面着陸の実装が完了する前に資源進行の後半を成立させられる。**敵のドロップは天体に紐づかないため、別に定める。

### 13-6. 市場

クレジットは基地の市場での資源の売買にのみ用いる。

```ts
// src/game/economy/market.ts
export interface MarketListing {
  readonly resourceId: string;
  readonly buyPrice: number;      // クレジット/kg。プレイヤーが買う値段
  readonly sellPrice: number;     // クレジット/kg。プレイヤーが売る値段
  readonly stockPerCycle: number; // kg。1補充周期あたりに買える上限
}
export function marketOf(base: Base): readonly MarketListing[];
```

市場に並ぶのは、その基地の周辺で流通する資源に限る。**ヘリウム3、白金族、希土類、木星大気由来のヘリウムは、どの市場にも並ばない。**これらは自分で採るしかない。`stockPerCycle` の上限は、市場が進行の代替経路にならないための制約である。金で買えるのは、既に自分で採れる資源のやりくりだけである。

## 14. 到達可能性

### 14-1. Δv が進行そのものである

どこへ行けるかは、機体が出せる Δv で決まる。Δv はツィオルコフスキーの式により、比推力と質量比で決まる。比推力は推進剤で決まり、推進剤は持っている元素で決まる。**したがって、資源の進行と到達可能性の進行は同じものである。**

### 14-2. Δv の表

代表的な区間の Δv を示す。単位は km/s である。

| 区間 | Δv（推進のみ） | Δv（大気制動を使う） |
|---|---|---|
| 月面 → 低月軌道 | 1.9 | — |
| 低月軌道 → 近直線ハロー軌道 | 0.7 | — |
| 月面 → 近直線ハロー軌道 | 2.7 | — |
| 近直線ハロー軌道 → 地球低軌道 | 3.2 | 0.7 |
| 地球低軌道 → 近直線ハロー軌道 | 3.4 | — |
| 地球低軌道 → 到達しやすい近地球小惑星 | 4.5 | — |
| 地球低軌道 → 一般の近地球小惑星 | 6.0 | — |
| 地球低軌道 → 火星周回 | 5.7 | 3.6 |
| 地球低軌道 → 金星周回 | 6.8 | 3.5 |
| 地球低軌道 → ケレス | 9.5 | — |
| 地球低軌道 → 木星系（カリスト） | 11.0 | 6.5 |
| カリスト → イオ | 3.5 | — |
| 地球低軌道 → タイタン | 12.0 | 7.5 |
| 木星大気の捕集 → 木星脱出 | 20.0 | — |

### 14-3. 大気制動 — 熱防護が炭素を要求する

**大気のある天体では、捕獲の Δv がほぼ不要になる。**地球・火星・金星・タイタン・木星がこれにあたる。双曲線軌道のまま大気の上層を通し、空力抵抗で減速して捕獲される。上の表の右列がその値であり、化学推進の到達範囲を1世代ぶん広げるほどの差になる。

代わりに要るのが**熱防護**である。制動の間、機体の前面は高温の衝撃層に晒される。熱防護材は炭素繊維複合材で作るため、**大気制動を使うには炭素が要る。**

| 天体 | 大気の性格 | 熱防護の負担 |
|---|---|---|
| 火星 | 薄い | 軽い。1回の通過で捕獲できず、複数周にわたる |
| 地球 | 中程度 | 中。既存の突入加熱と動圧の実装がそのまま働く |
| タイタン | 厚く低重力 | 軽い。速度が小さいため加熱が穏やか |
| 金星 | 極めて厚い | 重い。突入速度が大きく、加熱が厳しい |
| 木星 | 極めて厚く高重力 | 極めて重い。捕獲は可能だが脱出は別問題である |

```ts
// src/game/economy/thermal-protection.ts
export interface HeatShieldPart {
  readonly area: number;            // m²。防護する前面投影面積
  readonly ablativeMass: number;    // kg。消耗するアブレータの質量
  readonly maxHeatFlux: number;     // W/m²。これを超えると破損する
}
```

大気圏突入の加熱と動圧はすでに実装されており、加熱率と動圧の閾値によって機体が失われる。大気制動は**その仕組みをそのまま使う**。熱防護材を積んでいれば閾値が上がり、積んでいなければ閾値は変わらないまま燃え尽きる。制動の1回ごとに、受けた総熱量に応じて `ablativeMass` が減る。使い切れば防護能力を失い、以後の突入では既定の閾値に戻る。**熱防護材の補充には炭素が要る**ため、炭素の供給地から遠い運用では、大気制動を何回使えるかが計画の一部になる。

熱防護材を積んでいない機体が大気制動を試みた場合の挙動は、現在の再突入とまったく同じである。**新しい失敗の形は増えない。**

炭素を持たない段階では大気制動は使えない。**つまり、月の資源だけで自立している間は、右列の値には手が届かない。**炭素を得ることは、推進剤の性能を上げるだけでなく、Δv の表そのものを書き換える。

### 14-4. 推進系ごとに届く範囲

質量比を現実的な範囲（乾燥質量に対する初期質量が3〜6倍）に置くと、推進系ごとの到達範囲はおおよそ次のようになる。

| 推進系 | 比推力 | 実用的な Δv | 届く範囲 |
|---|---|---|---|
| 固体・貯蔵性化学 | 230〜320 s | 3〜5 km/s | 月面と近直線ハロー軌道、地球低軌道 |
| 液体酸素／シラン | 265 s | 3〜5 km/s | 同上。月の資源だけで作れる |
| 極低温化学（メタン） | 370 s | 5〜7 km/s | 近地球小惑星、火星、金星 |
| 極低温化学（水素） | 450 s | 6〜8 km/s | 火星、金星。蒸発損失のため長期の航行には不利 |
| 核熱推進 | 900 s | 12〜16 km/s | ケレス、木星系 |
| 電気推進 | 3000 s | 30 km/s 以上 | 太陽系内のどこへでも。ただし推力が小さく、時間がかかる |
| 核融合推進 | 10⁴ s 以上 | 100 km/s 以上 | 木星の重力井戸からの脱出 |

## 15. 設備の連鎖

### 15-1. 進行を止める4つの制約

| 制約 | 内容 | 解消の手段 |
|---|---|---|
| **資源** | 必要な元素を持っていない | その元素のある場所へ行く、または敵から得る |
| **設備** | 変換する設備を持っていない | 設備の建設に必要な金属と電力を確保する |
| **電力** | 設備を動かす電力が足りない | 太陽電池を増やす。太陽から遠い場所では原子炉が要る |
| **到達可能性** | その場所へ行くだけの Δv が出せない | より比推力の高い推進系、多段化、または大気制動 |

**この4つは互いに絡み合っている。**遠くへ行くには高い比推力が要り、高い比推力の推進剤には特定の元素が要り、その元素は遠くにしかなく、そこへ行くには電力を生む原子炉が要り、原子炉の燃料もまた特定の場所にしかない。

### 15-2. 設備の定義

設備は、電力を消費して入力資源を出力資源に変換する。設備そのものの建設には金属と電力が要る。**通貨は要らない。**

```ts
// src/game/economy/facility.ts
export interface FacilityDef {
  readonly id: string;
  readonly name: string;
  readonly inputs: readonly { resourceId: string; rate: number }[];   // kg/s
  readonly outputs: readonly { resourceId: string; rate: number }[];  // kg/s
  readonly powerDraw: number;         // W
  readonly buildCost: readonly { resourceId: string; mass: number }[];
  readonly requiresFacility: readonly string[];  // これを作るのに要る別の設備
}
export const FACILITIES: readonly FacilityDef[];
```

`requiresFacility` は技術の前提ではなく、**物理的な前提**である。液化装置がなければ極低温タンクに詰められない、という類の関係だけを表す。

### 15-4. 電力が最初の壁になる

**溶融塩電解は極めて大きな電力を要する。**アルミの電解精錬は工業的に最も電力を食う工程の一つであり、月のレゴリスから金属と酸素を取り出す工程も同様である。

したがって進行の最初の段階は「電力を確保すること」になる。月の南極の高地は日照率が高く、この立地の価値が電力として直接現れる。太陽電池を増やすにはケイ素が要り、ケイ素を得るには電解が要り、電解には電力が要る。**この循環は、最初の小さな設備から徐々に規模を拡大していく形でしか抜けられない。**

太陽から遠ざかると太陽光が弱くなる（木星では地球の27分の1）。外惑星で設備を動かすには原子炉が要る。原子炉の燃料は月の KREEP 岩か M型小惑星から得る。**農場の電照（§12-2）と重水素・ヘリウム3の同位体分離（§15-3）も同じ電力を奪い合う。**居住人数を増やすことと、核融合燃料を作ることは、同じ電力収支の上で競合する。

## 16. 推進の世代

### 16-1. 第1世代 — 貯蔵性化学推進

月の資源と敵のドロップだけで成立する。

| 推進剤 | 比推力 | 必要な元素 | 産地 |
|---|---|---|---|
| 固体（過塩素酸アンモニウム + HTPB + Al） | 265 s | Al, C, H, N, O, Cl | Al は月、C と N はドロップ |
| 液体酸素 / シラン | **265 s** | Si, H, O | **すべて月で得られる** |
| 四酸化二窒素 / モノメチルヒドラジン | 320 s | N, H, O, C。**タンクに Al** | N と C はドロップ |
| ヒドラジン単推進剤 | 230 s | N, H。**触媒床に白金族（Ir）** | ドロップまたはM型小惑星 |
| 窒素冷ガス | 70 s | N | ドロップ |
| ヘリウム冷ガス | 165 s | He | 木星大気 |

**液体酸素／シランは、月の資源だけで作れる唯一の液体推進剤である。**燃焼生成物の二酸化ケイ素が凝縮相であり、膨張過程で仕事に寄与しないため比推力は 265 秒にとどまる。さらに二酸化ケイ素がノズルスロートに堆積するため、**連続燃焼時間に上限がある。**性能は固体モーター並みであり、長い連続噴射はできない。

それでも、外部からの補給がまったくなくても月面と近直線ハロー軌道と地球低軌道の間を往復できる。**これがこの作品の自立の最低線である。**そして、より高性能な推進剤を求めて外へ出る動機でもある。

**冷ガススラスタの2つの選択肢は、この世代の両端にある。**窒素冷ガスは比推力 70 秒と低いが、窒素は敵のドロップで早く手に入る。ヘリウム冷ガスは 165 秒と大幅に高いが、ヘリウムは木星大気からしか大量には採れない。極低温推進剤の与圧のためにヘリウムを積んでいる機体は、それをそのまま冷ガスの推進剤にも使える。

### 16-2. 第2世代 — 極低温化学推進

水と炭素が要る。

| 推進剤 | 比推力 | 必要な元素 | 産地 |
|---|---|---|---|
| 液体酸素 / 液体水素 | 450 s | H, O。**タンクに Ti またはステンレス** | 月の水氷 |
| 液体酸素 / 液体メタン | 370 s | C, H, O | C はドロップ、小惑星、火星、タイタン |

液体酸素／液体水素は月の水だけで作れるが、水素の密度が低いため巨大なタンクが要り、蒸発損失があるため長期の航行に向かない。水素脆化に耐えるタンクが要るため、チタンか特定のステンレスを持っていることが前提になる。液体酸素／液体メタンは密度が高く貯蔵しやすいが、炭素が要る。

**この世代で近地球小惑星と火星に届く。**小惑星からは水と炭素と白金族と希土類が、火星からは炭素と窒素とアルゴンが得られる。**炭素と窒素の供給が敵のドロップから独立する**のが、この世代の最大の意味である。

そして炭素が手に入ることで、**炭素繊維複合材の熱防護材が作れるようになる。**大気制動が使えるようになり、火星・金星・地球の捕獲に要る Δv が大きく下がる。同じ推進系のまま届く範囲が広がるのは、この世代だけの性質である。炭素はまた**農場を可能にする**ため、恒久的な居住が成立するのもこの世代である。

### 16-3. 第3世代 — 核熱推進

固体炉心の原子炉で水素を加熱して噴射する。比推力 900 秒、推力は化学推進に匹敵する。

- 燃料はウランまたはトリウム。月の KREEP 岩、または M型小惑星から得る。
- 作動流体は水素。核分裂の熱で加熱するだけなので、酸化剤を必要としない。**水さえあればどこでも補給できる。**
- 水素を扱うため、タンクにはチタンか特定のステンレスが要る。
- 炉心は重く、乾燥質量が大きい。小型の機体には向かない。
- 放射線遮蔽が要る。乗員のいる区画との間に遮蔽材を置く必要があり、機体の形状が制約を受ける（遮蔽の影の中に居住区を置く配置）。**背骨設計はこの制約を素直に表現でき、水タンク（§12-4）がそのまま遮蔽になる。**

**この世代でケレスと木星系に届く。**ケレスは水が豊富で、核熱推進の補給地として最適である。

### 16-4. 第4世代 — 電気推進

原子炉または大型太陽電池の電力で推進剤を電離・加速する。

| 方式 | 比推力 | 推力 | 推進剤 |
|---|---|---|---|
| ホールスラスタ | 1600 s | 中 | Xe, Ar, Kr |
| イオンエンジン | 3000〜4000 s | 小 | Xe |
| 磁気プラズマ推進 | 5000 s | 小 | Ar, H |

- 推進剤は火星の大気（アルゴン 2%）から、あるいは希ガスの捕集から得る。
- 磁気回路に希土類が要る。磁気トルカと同じ資源の上に載る。
- **推力が極めて小さい。**加速度は 10⁻⁴ m/s² の程度であり、大きな Δv を得るのに数か月から数年かかる。戦闘には使えない。
- 電力が要る。太陽電池は太陽から遠ざかるほど無力になるため、外惑星では原子炉が前提になる。

電気推進は**戦闘用ではなく輸送用**である。ゆっくりでよい大量の物資を運ぶ無人ブースターに積む。これは「戦闘は化学推進、輸送は電気推進」という役割の分化を生み、機体設計の目的が明確に分かれる。コンテナ接合部を並べた電気推進の無人輸送機が、この分化の典型である。

### 16-5. 第5世代 — 核融合推進

重水素とヘリウム3の反応を用いる。比推力 10⁴ 秒以上。

- 重水素は水から分離する。ヘリウム3は木星の大気から捕集する（月のレゴリスにも太陽風起源のヘリウム3が含まれるが、濃度が極めて低く、大量には得られない）。
- **重水素とヘリウム3の反応は中性子をほとんど出さない**（副反応の重水素同士の反応を除く）。荷電粒子が主生成物であるため、磁場で直接噴射方向へ導ける。これが高い比推力の理由である。
- ヘリウム3の同位体分離には極めて大きな電力が要る。原子炉が前提になる。
- 木星の大気を捕集し、その重力井戸から脱出するには 20 km/s 級の Δv が要る。**核融合推進なしにはヘリウム3を持ち帰れず、ヘリウム3なしには核融合推進が作れない。**この循環は、最初の一回だけ核熱推進と電気推進を組み合わせた片道の大型機で破る。

この作品はすでに中性子線ビームを敵への有効な攻撃手段として構想している。核融合の実現は、推進だけでなく武装の世代も変える。

## 20. 技術的リスク

### 20-1. 設備の連鎖が詰まる

ある資源を得るのに必要な設備が、その資源自身を必要とする循環が生じると、進行が止まる。これは**到達可能性の閉包を求める問題であり、テストで機械的に検証できる。**

```ts
// tests/economy/resource-closure.test.ts
// 初期資源の集合から出発し、不動点に達するまで前方に閉じる
function reachableClosure(
  initial: ReadonlySet<string>,          // 資源 id
  facilities: readonly FacilityDef[],
  deposits: readonly DepositDef[],
  reachableBodies: (owned: ReadonlySet<string>) => ReadonlySet<AttractorId>,
): ReadonlySet<string> {
  const owned = new Set(initial);
  for (;;) {
    const before = owned.size;
    // 1. 今の資源で建てられる設備を全て建てる
    for (const f of facilities) {
      if (!f.buildCost.every((c) => owned.has(c.resourceId))) continue;
      if (!f.requiresFacility.every((id) => builtIds.has(id))) continue;
      if (!f.inputs.every((i) => owned.has(i.resourceId))) continue;
      builtIds.add(f.id);
      for (const o of f.outputs) owned.add(o.resourceId);
    }
    // 2. 今の推進剤で届く天体の産地を全て採る
    for (const d of deposits) {
      if (!reachableBodies(owned).has(d.bodyId)) continue;
      owned.add(d.resourceId);
    }
    if (owned.size === before) break;   // 不動点
  }
  return owned;
}
```

テストは、初期資源（月南極の基地が持つ太陽電池・氷採掘機と、その建設に要った金属）から始めてこの閉包を求め、**`RESOURCES` のすべての id が閉包に含まれることを確かめる。**含まれないものがあれば、その資源に至る経路が存在しないということであり、データの誤りである。

`reachableBodies` は、その時点で持っている推進剤の最良の比推力と、現実的な質量比（3〜6）から Δv を求め、§14-2 の表と突き合わせて届く天体を返す。**炭素を持っているかどうかで大気制動の可否が変わるため、この関数は所持資源に依存する。**閉包の反復のたびに再評価する。

### 20-2. 意図した循環と、それを破る質量比

木星大気のヘリウム3は、核融合推進なしには持ち帰れず、核融合推進はヘリウム3を必要とする（§16-5）。これは意図した循環であり、核熱推進と電気推進を組み合わせた片道の大型機で破る設計になっている。

**§20-1 の閉包の検証は、この経路を「破れる」と正しく判定しなければならない。**そのためには、核融合以外の推進で木星大気から脱出できる質量比が実際に存在することを、数値で確かめる必要がある。

```ts
// tests/economy/jupiter-escape.test.ts
const G0 = 9.80665;
const dv = (isp: number, massRatio: number) => isp * G0 * Math.log(massRatio);

// 第1段: 核熱推進（Isp 900 s）で大気圏から脱出速度へ
// 第2段: 電気推進（Isp 3000 s）で惑星間軌道へ
const stage1 = dv(900, 6);     // ≈ 15.8 km/s
const stage2 = dv(3000, 1.5);  // ≈ 11.9 km/s
assert(stage1 + stage2 >= 20_000);
```

第1段が核熱推進でなければならないのは、木星の大気圏内から脱出速度まで加速するのに電気推進の推力（10⁻⁴ m/s²）ではまったく足りないためである。逆に第2段が電気推進でよいのは、重力圏を出た後は時間をかけられるためである。**この役割分担そのものが、テストの構造として表れている。**

### 20-3. 分離後の状態の再構成

分離は背骨・質量・重心・慣性テンソル・推進剤残量・流路のすべてを変える。これらを一箇所で一括して再計算し、どれか一つだけが古い値のまま残ることのないようにする。分離直後の接触判定の無効化も、この再構成と同じ時点で行う。コンテナの切り離しと回収も同じ経路を通す。

### 20-4. 段を跨ぐ燃焼の分割

分割したノードは、段の分離と次の段の点火を挟む。1つ目の燃焼終了時刻・分離時刻・2つ目の点火時刻の3つが、点火あたりの推進剤損失を含めて整合している必要がある。分割の提案を受け入れた時点で3つをまとめて生成し、後から片方だけを編集できないようにする。

### 20-5. 自動敷設の安定性

設計を変更するたびに自動敷設をやり直すため、無関係な編集で配管が別の経路に移ると、プレイヤーには不可解に見える。最短経路が同距離で複数ある場合の順序を、エッジIDによる決定的な規則で固定する。

### 20-6. 手動の上書きと設計変更の衝突

手動で敷いた区間のエッジが削除されたり、種別が変わったりすると、上書きが宙に浮く。参照先を失った上書きは破棄し、破棄したことを診断に出す。黙って消すと、プレイヤーは自分の設定が効いていない理由を追えない。

### 20-7. 配管の探索コスト

流路の解決は、タンクとエンジンの組ごとにグラフ上の経路を探すことになる。エッジ数に対して線形になるよう、推進剤の種別ごとに連結成分を1度だけ求め、タンクとエンジンが同じ連結成分に属するかで判定する方式にする。

### 20-8. クロスフィードと分離順の整合

分離機構を跨ぐ配管は、分離順によっては、まだ燃焼中のエンジンへの供給を断つ。分離順の並べ替えの時点で、その順序で断たれる供給を検出して警告する。

### 20-9. 推力軸のずれによる制御不能

側面に非対称にブースターを束ねると、推力軸が重心を大きく外れる。コンテナを非対称に積んだ場合も同じことが起きる。設計エディタでの警告と、ジンバル補償の両方が必要である。補償しきれない設計は生産を拒否する。

### 20-10. 回転区画の角運動量が機体の姿勢制御と干渉する

重力区画が回っている間、機体は大きな角運動量を持つジャイロになる。打ち消しの対（またはフライホイール）で総和を0にしても、**個々の区画の角運動量は残る**ため、機体の姿勢を変えようとすると章動が生じる。姿勢制御の配分（第1巻）がこれを扱えるかを確かめる必要があり、扱えない場合は、姿勢変更の前に回転を止めることを要求する形にする。回転の起動と停止に要するエネルギーと時間を HUD に表示する。

### 20-11. 保存形式の互換性

設計データ・配管の上書き・基地の在庫・設備・コンテナの内容が保存形式に加わる。読み替え不能な保存データは明示的に拒否し、破損した機体を生成しないこと。

### 20-12. 進行が長すぎる

月面から核融合までの道のりは長い。各段階で何が新しくできるようになるかが明確でないと、進行が作業に感じられる。段階ごとに「新しく届く場所」が増えることを、地図の上で見えるようにする必要がある。**大気制動の解禁（炭素の入手）は Δv の表そのものを書き換えるため、地図上の変化が最も大きい瞬間になる。**ここを見せ場として扱う。

### 20-13. 資源の種類が多すぎる

18種の元素と、そこから作られる推進剤・構造材・熱防護材・食料を合わせると、在庫の一覧が長くなる。用途ごとにまとめて表示し、使わないものは折り畳む必要がある。**市場の画面も同じ問題を持つ**ため、在庫と市場は同じ分類でまとめる。

### 20-14. 電気推進の時間スケール

加速度が 10⁻⁴ m/s² の程度であるため、意味のある Δv を得るのに数か月かかる。この作品は時間加速を持つため成立するが、**時間加速の上限（131072倍）でも数分の実時間がかかる。**電気推進の機体は計画に任せて放置し、他の機体を操作している間に進む、という運用になる。これが成立するかは、複数機体の同時運用の使い勝手に依存する。

### 20-15. 磁気トルカの領域依存が分かりにくい

低軌道では姿勢制御が無料であり、月周辺では推進剤を消費する。**この差は、切り替わった瞬間には見えない。**月へ向かった機体の推進剤が思ったより速く減る、という形でしか現れない。磁気トルカが働いているかどうかを HUD に常時表示し、働かなくなった瞬間に通知を出す必要がある。

### 20-16. UIの総量

設計エディタは4つのモードと右パネルの常設表示を持ち、飛行中に段とペイロードの2つのパネルを加える。基地ビューにも設計・生産・市場・ドック・居住が並ぶ。既存のパネルへ統合できないかを追加のたびに確認し、置き場の規約に従うこと。
