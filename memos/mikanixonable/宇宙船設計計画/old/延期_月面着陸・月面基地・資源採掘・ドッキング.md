# 月面着陸・月面基地・資源採掘・ドッキング — 延期した機能の設計

この文書は、実装費用が大きいため当面の実装対象から外した4つの機能をまとめたものである。いずれも `第三版_宇宙船設計・推進系・多段化.md` の機能が実装済みであることを前提とし、その上に追加する形で設計してある。

1. ドッキングポートによる機体の結合（§1）
2. 月の地形と着陸（§2）
3. 月面基地（§3）
4. 資源採掘・生産・輸送（§4）

依存の順序は、ドッキング → 月の地形 → 着陸 → 月面基地 → 資源経済である。ドッキングのみを先行して実装することはできるが、月面基地は着陸に依存し、資源経済は月面基地とドッキングの両方に依存する。

各機能の実装費用が大きい理由は §5 に挙げる。

## 1. ドッキングポートによる機体の結合

### 1-1. 実現する内容

ドッキングポートを持つ機体同士が接近し、双方のポートの位置・向き・相対速度・相対角速度がすべて捕獲条件を満たしたとき、機体が結合する。結合後は、ポート軸まわりの相対回転（位相角）を任意に変えられ、推進剤とガスを移送でき、電力は結合体全体で1つの収支として計算される。

この機構により、以下が可能になる。

- 軌道上にあらかじめ投入しておいたブースターと合流し、結合してその推進剤で基地へ帰投する。
- 艦艇同士を結合し、推進剤と電力を融通する。
- 軌道基地に艦艇を接舷して格納する。
- 月面基地の区画同士を結合して拡張する（§3）。

### 1-2. ドッキングポート部品

```ts
export interface DockingPortPart extends Part {
  readonly type: 'docking_port';
  readonly portClass: 'small' | 'medium' | 'large'; // 同一クラス同士のみ結合できる
  readonly androgynous: boolean;                    // false の場合 probe と drogue の対でのみ結合
  readonly role: 'probe' | 'drogue' | 'both';
  readonly localPos: Vec3;       // 船体ローカル座標のポート面中心
  readonly localAxis: Vec3;      // ポート面の外向き法線
  readonly localRollRef: Vec3;   // 位相角0を定義する基準方向（localAxis に直交）
  readonly transferRate: number; // 推進剤移送速度 [kg/s]
  readonly powerBridge: boolean; // 電力を橋渡しするか
}
```

ドッキングポートは背骨のノードに装着する。装着できるのは、そのノードの空いている接続口である。ポートの軸はその接続口の方向と一致する。

### 1-3. 捕獲条件

2つのポート A・B が以下をすべて満たすとき、捕獲が成立する。値は `const.ts` に置く。

| 条件 | 内容 |
|---|---|
| 適合 | `portClass` が一致し、`androgynous` 同士、または `probe` と `drogue` の対である |
| 軸方向距離 | ポート面中心間の距離が捕獲距離以内 |
| 横方向ずれ | A の軸に投影したときの横方向オフセットが許容半径以内 |
| 軸の対向 | A の軸と B の軸のなす角が180度から許容角度以内 |
| 接近速度 | 最小値以上・最大値以下。速すぎればラッチが損傷し、遅すぎれば噛まない |
| 横方向相対速度 | 許容値以下 |
| 相対角速度 | 許容値以下 |

捕獲が成立すると、ポート面同士を厳密に一致させる位置と姿勢へ両機を補正する。補正は運動量と角運動量を保存する形で行い、余剰は減衰として捨てる。これはラッチの衝撃吸収に相当する。

条件を満たさずに接触した場合は、通常の剛体接触として処理する。跳ね返り、および相対速度に応じた損傷が生じる。

### 1-4. 結合体

結合した複数の `Vessel` は、1つの剛体として積分する。

```ts
export interface DockingCluster {
  readonly id: string;
  readonly members: readonly Vessel[];
  readonly root: Vessel;                    // 積分の主体。KinematicState と Attitude を持つ
  readonly joints: readonly DockingJoint[];
}
export interface DockingJoint {
  readonly portA: { vesselId: string; partId: string };
  readonly portB: { vesselId: string; partId: string };
  phaseAngle: number;   // ポート軸まわりの相対ロール [rad]
}
```

- 積分は `root` の状態に対してのみ行う。他の構成機体の位置と姿勢はジョイントの連鎖から毎フレーム導出する。
- クラスタの質量・重心・慣性テンソルは、全構成機体のものを平行軸定理で合成する。推進剤が減れば変わるため、質量が一定量変化したときに再計算する。
- クラスタの主機・RCS・フライホイールは全構成機体のものの合計として扱う。主機の推力軸がクラスタ重心を外れる場合、そのぶんのトルクが実際に発生する。
- 同一クラスタの構成機体同士は接触判定を行わない。

### 1-5. 位相角の調整

ジョイントの `phaseAngle` を連続的に変えられる。ポート軸まわりに片側を回すことに相当し、機体全体の姿勢を変えずに構成機体の相対的な向きだけを変える。

- 回転速度に上限があり、電力を消費する。
- 回転させると結合体の慣性テンソルが変わるため、角運動量保存により全体の角速度が変化する。この効果はフライホイールと同じ内部トルクの一種として正しく計算する。
- 用途は、ソーラーパネルを太陽に向ける、ラジエータを日陰に入れる、武装の射界を確保する、着陸脚の向きを揃える、である。

### 1-6. 移送と電力統合

**推進剤とガスの移送** — `powerBridge` を持つジョイントで結ばれた機体の間で移送できる。

- 移送できるのは、送り側と受け側のタンクが同じ推進剤種別に適合している場合のみ。極低温と常温貯蔵性の推進剤は互いに移送できない。
- 移送速度は両ポートの `transferRate` の小さいほうで律速する。
- 移送中は電力を消費する。
- 移送に伴って両機の質量と重心が変わるため、質量特性を更新する。クラスタ全体の重心は移動しないが、慣性テンソルは変わる。

**電力統合** — クラスタは1つの電力系として計算する。発電量は全構成機体のソーラーパネルの合計であり、各パネルの向きと日照は個別に評価したうえで合計する。蓄電容量はバッテリーの合計、消費は全構成機体の合計とする。不足が生じた場合は、優先度の低い消費（生産設備、位相角の回転）から順に停止する。

### 1-7. 分離

結合の解除は、ジョイントを取り除いてクラスタを分割することである。分割後は、分かれた側それぞれが独立した運動状態を持ち、運動量と角運動量が保存されるように速度と角速度を分配する。解除時に小さな分離速度を与える。

### 1-8. ドッキング支援の表示

ドッキングポートを目標に選ぶと、以下を表示する。

- 目標ポートの位置と軸を示すマーカー、および自機ポートとの相対位置。
- 横方向のずれと軸の対向角を示す十字型のインジケータ。
- 相対距離、接近速度、横方向相対速度、相対角速度と、それぞれの許容範囲。
- 捕獲条件を条件ごとに満たしているかどうかの一覧。

### 1-9. モジュール

    captureCorrection(...) -> { stateA, stateB }   // 運動量保存を満たす補正

## 2. 月の地形と着陸

### 2-1. 地形

月の表面は、球面上の高度場として表す。

```
src/physics/terrain/height-field.ts   (純関数)
    heightAt(bodyId, latRad, lonRad) -> number   // 基準球半径からの高度 [m]
    normalAt(bodyId, latRad, lonRad) -> Vec3     // 地形法線（天体固定座標）
    surfacePointAt(bodyId, latRad, lonRad) -> Vec3
```

- 全球は粗い解像度の高度場で表し、機体の周囲のみ細かい格子を生成する。細部は決定的な擬似乱数（`physics/random.ts` の `mulberry32`）で生成し、同じ座標では常に同じ地形になるようにする。
- 座標は天体固定座標（月とともに自転する座標系）で扱う。慣性座標との変換は `Ephemeris` の自転位相を用いる。
- 南極域は永久影クレーターを含むよう地形を構成する。日照の判定は太陽方向に加えて地形の地平線を考慮し、クレーター底部が常に日陰になるようにする。
- 粗い全球データと局所生成の境界で高度が不連続にならないよう、局所生成は全球データを基準面として、その上に細部を加算する形とする。

### 2-2. 地表との接触

高度が一定値を下回った機体に対して、以下を行う。

- 天体固定座標での緯度経度を求め、その点の地形高度と機体各部の高度を比較する。
- 固定脚の接地点それぞれを接触点として扱う。接触点が地形面より下に入った場合、法線方向の反力と接線方向の摩擦を与える。
- 固定脚を持たない部位が地形に接触した場合は損傷を与える。

球面としての天体表面到達判定は、地形を持たない天体に対してのみ適用する。地形を持つ天体では高度場との接触判定に置き換える。

### 2-3. 着陸

接地の瞬間に以下をすべて満たす場合、着陸が成立する。値は `const.ts` に置く。

| 条件 | 内容 |
|---|---|
| 垂直速度 | 接地面法線方向の速度が許容値以下 |
| 水平速度 | 接地面接線方向の速度が許容値以下 |
| 傾斜 | 機体の脚面法線と地形法線のなす角が許容値以下 |
| 角速度 | 許容値以下 |
| 接地脚数 | 固定脚のうち規定数以上が同時に接地 |

いずれかを外れた場合、超過量に応じて固定脚および接触部位に損傷を与える。大きく外れた場合は機体を破壊する。

着陸が成立した機体は着陸状態を持ち、天体固定座標に静止する。静止中は軌道積分を行わず、天体の自転に従って位置と速度を導出する。これにより、静止した機体を数値積分し続けることによる誤差の蓄積（沈み込みまたは浮上）を避ける。

離陸は、主機の推力が機体重量（その天体の表面重力加速度と機体質量の積）を上回った時点で着陸状態を解除し、通常の積分に戻すことで行う。着陸状態への遷移と解除が短時間に繰り返されないよう、遷移条件に履歴を持たせる。

### 2-4. 固定脚

```ts
export interface LandingGearPart extends Part {
  readonly type: 'landing_gear';
  readonly localPos: Vec3;        // 接地点の船体ローカル座標
  readonly strokeLength: number;  // 緩衝行程 [m]
  readonly maxImpactSpeed: number; // 損傷なく吸収できる接地速度 [m/s]
  readonly deployable: boolean;   // 収納できるか
}
```

固定脚は背骨のノードに装着する。3本以上を装着した機体のみ着陸できる。

## 3. 月面基地

月面基地は、固定脚を持ちエンジンを持たない `Vessel` である。艦艇や軌道基地と同じ実体であり、クラスを分けない。

- 着陸状態で天体固定座標に静止し、生産設備部品と基地モジュール部品を積む。
- 生産設備は電力を消費し、入力資源を出力資源へ一定の速度で変換する。
- 電力はソーラーパネルとバッテリーから得る。月の自転周期に伴って日照が変動するため、蓄電容量の設計が運用に影響する。南極の高地は日照率が高く、クレーター底部は常に日陰である。
- 月面基地は複数機を結合して拡張できる。結合はドッキングポート（§1）によって行い、電力は統合され、資源は移送できる。したがって基地の拡張と、軌道上での機体の結合は同一の機構である。

月面基地は設計エディタで設計する。エンジンを積まず固定脚を積んだ設計であり、他の機体と同じ手順で生産する。生産した月面基地は、輸送機で月面まで運ぶか、月面で直接生産する。

## 4. 資源採掘・生産・輸送

### 4-1. 資源

| 資源 | 産地 | 用途 |
|---|---|---|
| 水 | 月の南極の永久影クレーターの採掘 | 電解して液体水素と液体酸素にする |
| 酸素 | 水の電解、レゴリスの還元 | 酸化剤 |
| ケイ素 | レゴリスの精錬 | シラン、構造材 |
| アルミ | レゴリスの精錬 | 固体推進剤の燃料成分、構造材 |
| 炭素 | 低軌道に出現する敵の撃破によるドロップ | メタン、末端水酸基ポリブタジエン、ABS樹脂、ケロシン |
| 窒素 | 低軌道に出現する敵の撃破によるドロップ | ヒドラジン、四酸化二窒素、冷ガス |
| 希少金属 | 敵のドロップ | 高性能なエンジン、フライホイール、電子機器 |

炭素と窒素は月では得られない。したがって、メタン系・ヒドラジン系の推進剤を使い続けるには低軌道での戦闘を継続する必要がある。一方、水とケイ素だけで閉じる経路（液体酸素／液体水素、液体酸素／シラン）が存在するため、戦闘を行わなくても運用は継続できる。

### 4-2. 生産設備

```ts
export interface ProductionPart extends Part {
  readonly type: 'production';
  readonly recipe: ProductionRecipe;
}
export interface ProductionRecipe {
  readonly id: string;
  readonly inputs: readonly { resourceId: string; rate: number }[];   // kg/s
  readonly outputs: readonly { resourceId: string; rate: number }[];  // kg/s
  readonly powerDraw: number;  // W
}
```

設備は、採掘機（レゴリスまたは氷を掘り出す）、電解装置（水を水素と酸素に分ける）、レゴリス精錬炉（ケイ素とアルミと酸素を取り出す）、シラン合成炉、固体グレイン成形機、極低温液化装置である。

### 4-3. 輸送

月面基地で生産した物資を軌道基地へ運ぶ操作は、プレイヤーが行う。自動化された輸送キューは持たない。

1. 月面基地に着陸した機体のペイロード区画または貨物区画に、月面基地の倉庫から資源を積み込む。積み込みは、両者がドッキングポートで結ばれているとき、または着陸接続が成立しているときに行える。
2. 離陸し、月面から目的の軌道への遷移を行う。
3. 軌道基地とドッキングする。
4. 貨物と推進剤を移送する。

貨物の質量は機体の総質量に加算されるため、輸送量を増やすほど必要な Δv に対する推進剤が増える。この関係により、1回の輸送量には設計上の最適点が生じる。輸送そのものが遊びの対象になる。

### 4-4. 軌道基地の軌道

軌道基地は近直線ハロー軌道に置く。

- 初期状態は既存のハロー軌道の生成関数（地球-月 L2 の南方ハロー、大きな面外振幅）から得る。
- この初期状態は線形近似であり、多体重力を含む数値積分に投入すると発散する。したがって軌道基地は維持バーンを行う。近月点通過ごとに数 m/s の維持バーンを軌道計画の自動実行によって行う。
- 維持バーンは推進剤を消費する。軌道基地の維持そのものが資源の消費先になる。

## 5. 実装費用が大きい理由

各機能を当面の実装対象から外した理由を記す。実装に着手する際、以下がそのまま最初に解くべき課題になる。

### 5-1. ドッキング

- 結合体を1つの剛体として積分する仕組みは、既存の単体機体を前提とした積分・接触判定・予測軌道・マーカー表示のすべてに影響する。
- 構成機体それぞれの推進剤消費によって結合体の重心と慣性テンソルが連続的に変化するため、再計算の頻度と姿勢積分の安定性の両立が必要である。
- 捕獲の瞬間の位置と姿勢の補正は、運動量と角運動量を保存しつつ不連続に状態を書き換える処理であり、予測軌道の破棄と再生成を伴う。
- ドッキング支援の表示は、既存のどのマーカーとも異なる新しい種類の表示である。

### 5-2. 月の地形

- 月の全球を実寸で扱うため、全球の高度場を高解像度で保持することはできない。粗い全球データと機体周辺のみの局所生成の組み合わせが必須であり、境界での不連続を避ける補間が要る。
- 地形メッシュの生成と、カメラ距離に応じた解像度の切り替えが必要である。既存の天体は球のみを描画しており、この仕組みを持たない。
- 天体表面への到達判定を球から高度場へ切り替えるため、`physics/attractor.ts` の到達判定に分岐が入る。この関数は全エンティティの毎ステップの判定に使われる。

### 5-3. 着陸

- 静止した機体を数値積分し続けると、重力と反力の釣り合いの誤差が蓄積して沈み込みまたは浮上が生じる。静止状態を積分から外して天体固定座標に固定する扱いが必須である。
- 着陸状態への遷移と解除の条件を明確にしないと、遷移の前後で状態が振動する。
- 固定脚の接地点ごとの接触と、複数点接触時の姿勢の安定は、既存の球同士の剛体接触とは別の処理である。

### 5-4. 資源経済

- 資源・設備・レシピ・在庫・輸送という新しい系統が加わり、既存のクレジットによる購入と併存させる設計判断が要る。
- 月面基地の運用画面、資源の在庫表示、積み込み操作という新しいUIが必要である。
- ドッキングと着陸の両方に依存するため、単独では実装できない。
