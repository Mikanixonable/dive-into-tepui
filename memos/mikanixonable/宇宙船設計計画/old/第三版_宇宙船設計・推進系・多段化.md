## 1. 設計判断

### 1-1. 船体は背骨と断面で定義する

宇宙船の形状は、**ノードとエッジからなる背骨**と、**各ノードが持つ断面**で定義する。外皮は、エッジの両端にある2つの断面をつないだ立体（ロフト）として生成する。

エッジから外皮までの距離は定数ではなく、両端のノードの断面寸法によって決まる。したがって、細い部分と太い部分を持つ機体、先細りの機体、段ごとに直径の異なるロケットが、追加の機構なしに作れる。

### 1-2. 断面の形状が分岐方向を決める

断面は円・楕円・三角形・四角形・五角形・六角形の6種である。断面が多角形である場合、その各辺の外向き法線の方向にエッジを分岐できる。三角形なら3方向、六角形なら6方向である。円は側面への分岐を持たず、楕円は長軸の両方向にのみ分岐できる。

各ノードは回転位相を持ち、分岐方向はその位相ぶん回る。

この規則により、分岐の角度をプレイヤーが数値で指定する必要がなくなる。角度は断面形状と回転位相から決まる。六角形の断面を選べば周囲6方向にブースターを束ねられ、四角形の断面を梯子状に組めば扁平な機体になる。

### 1-3. 結合はすべて平面同士の突き合わせとする

エッジと断面の結合、および側面分岐の結合は、いずれも平面同士の突き合わせ（フランジ結合）とする。曲面同士を滑らかに融合させる処理は行わない。

この判断により、外皮の体積・表面積・重心・慣性テンソルがすべて解析式で求まり、部分同士が重なることもない。数値積分も、等値面の三角形分割も不要である。実際のロケットも、段間部と側面ブースターの取り付けはフランジ結合であり、工学的にも自然である。

### 1-4. 物理量は形状から導出する

質量・重心・慣性テンソル・断面積は定数として持たず、背骨と断面と搭載物から導出する。扁平な機体は実際に回りにくく、非対称な機体は実際に重心がずれる。

### 1-5. 推進剤は登録されたペアからのみ選ぶ

比推力は実測値であり、任意の酸化剤と還元剤の組み合わせに対して定義できない。推進剤は「酸化剤と還元剤のペア」「単推進剤」「固体グレイン」「ハイブリッドの組」として表に登録されたものからのみ選ぶ。表は §5-1 に置く。

### 1-6. 設計と生産を分ける

プレイヤーは、資源を消費せずに設計を作り、名前を付けて保存し、読み込める。実機を得るには、保存した設計を指定して生産する。生産には時間がかかる仕組みを持つが、初期状態ではすべての設計の生産時間を0とする。

## 2. 背骨断面システム

### 2-1. データ構造

```ts
// src/game/vessel/cross-section.ts
export type CrossSectionShape = 'circle' | 'ellipse' | 'triangle' | 'square' | 'pentagon' | 'hexagon';

export interface CrossSection {
  readonly shape: CrossSectionShape;
  readonly majorRadius: number;   // 外接円半径 [m]（円と正多角形はこれのみ使う）
  readonly minorRadius: number;   // 楕円の短半径 [m]（楕円以外は majorRadius と同値）
  readonly phaseAngle: number;    // 断面の回転位相 [rad]
}
```

```ts
// src/game/vessel/skeleton.ts
export interface SkeletonNode {
  readonly id: string;
  readonly pos: Vec3;              // 船体ローカル座標 [m]
  readonly section: CrossSection;
  readonly axis: Vec3;             // 断面の法線（背骨の進行方向）
}

export type EdgeKind =
  | { kind: 'hull' }                                    // 外皮を作る。内側が内容積になる
  | { kind: 'strut'; radius: number }                   // 外皮を作らない構造材
  | { kind: 'decoupler'; separationImpulse: number };    // 外皮を作らず、切り離せる

export interface SkeletonEdge {
  readonly id: string;
  readonly a: string;              // 始点ノード id
  readonly b: string;              // 終点ノード id
  readonly portA: PortRef;         // 始点ノードのどの接続口から出るか
  readonly portB: PortRef;         // 終点ノードのどの接続口へ入るか
  readonly kind: EdgeKind;
}

export type PortRef =
  | { kind: 'axial'; sign: 1 | -1 }   // 断面の表側／裏側
  | { kind: 'lateral'; faceIndex: number }; // 多角形の何番目の辺か

export interface VesselSkeleton {
  readonly nodes: readonly SkeletonNode[];
  readonly edges: readonly SkeletonEdge[];
}
```

背骨はグラフであり、閉路を含んでよい。三角形や梯子状に組めば扁平な機体になる。

### 2-2. 断面ごとの接続口

| 断面 | 軸方向の口 | 側面の口 | 側面の口の方向 |
|---|---|---|---|
| 円 | 2 | 0 | — |
| 楕円 | 2 | 2 | 長軸の正負方向 |
| 三角形 | 2 | 3 | 各辺の外向き法線 |
| 四角形 | 2 | 4 | 各辺の外向き法線 |
| 五角形 | 2 | 5 | 各辺の外向き法線 |
| 六角形 | 2 | 6 | 各辺の外向き法線 |

側面の口の方向は、断面の回転位相ぶん回転する。したがって、六角形の断面で位相を30度回せば、分岐方向が辺の中点から頂点方向へ移る。

側面の口の**大きさ**は、その辺の長さと、辺に沿った規定の幅で決まる。側面から分岐するエッジの相手側の断面は、この口に収まる大きさでなければならない。収まらない場合は設計として不正とし、エディタが理由を表示する。

### 2-3. 外皮の生成

`hull` エッジは、両端のノードの断面をつないだ立体を作る。

- 両断面の輪郭を、それぞれ**60点**に等分してサンプリングする。60は3・4・5・6のいずれでも割り切れるため、辺数の異なる断面同士でも頂点が一対一に対応する。円と楕円も同じ60点で表す。
- 対応する頂点同士を直線で結び、側面を四角形の帯として張る。
- 両断面の回転位相が異なる場合、頂点の対応は位相差を考慮して、対応する頂点間の距離の総和が最小になる割り当てを選ぶ。これにより外皮がねじれない。

側面の口から分岐するエッジは、口の平面の上に相手側の断面を置き、そこから同じ規則でロフトする。分岐部は平面同士の突き合わせであり、本体の外皮と交差しない。

### 2-4. 物理量の導出

外皮は「断面が軸方向に線形に変化する一般化角錐台」の集まりであり、以下がすべて解析式で求まる。

**断面の面積と断面二次モーメント**

| 断面 | 面積 A | 断面二次モーメント |
|---|---|---|
| 円（半径 r） | `πr²` | `Ix = Iy = πr⁴/4` |
| 楕円（半径 a, b） | `πab` | `Ix = πab³/4`, `Iy = πa³b/4` |
| 正n角形（外接円半径 R、辺長 `s = 2R·sin(π/n)`） | `(n/2)·R²·sin(2π/n)` | `Ix = Iy = (A/24)·(6R² − s²)` |

正多角形の断面二次モーメントは重心を通るどの軸についても等しい。

**エッジ1本の体積** — 長さ `h`、両端の断面積 `A₁` / `A₂`、中間断面の面積 `Am` として

```
V = (h/6)·(A₁ + 4·Am + A₂)
```

輪郭を線形補間するため中間断面は両端の輪郭の平均であり、`Am` はその平均輪郭の面積である。

**慣性テンソル** — 軸に沿った位置 `t ∈ [0, h]` における断面積 `A(t)` と断面二次モーメント `I(t)` はいずれも `t` の多項式である。したがって

```
I_axial     = ρ ∫ (Ix(t) + Iy(t)) dt
I_transverse = ρ ∫ (I(t) + A(t)·t²) dt
```

はいずれも多項式の積分として閉形式で求まる。各エッジの慣性テンソルを平行軸定理で船体重心まわりに移して合成する。

**表面積** — 側面の帯の面積の和。露出した端面（他のエッジが接続していない断面）を加える。

**参照断面積** — 主軸3方向への投影面積のうち最大値。抗力係数 `bcInv = Cd·A/m` に用いる。

```
src/physics/hull-loft.ts   (純関数)
    sectionArea(section) -> number
    sectionSecondMoment(section) -> { ix: number; iy: number }
    loftVolume(sectionA, sectionB, length) -> number
    loftInertia(sectionA, sectionB, length, density) -> InertiaTensor
    loftCentroid(sectionA, sectionB, length) -> number   // 始点からの重心位置
    loftSurfaceArea(sectionA, sectionB, length) -> number
    loftProjectedArea(sectionA, sectionB, length, axis) -> number
```

検証は `tests/physics/hull-loft.test.ts` に置く。円断面の等断面ロフトが円柱の解析値と一致すること、正多角形の辺数を増やすと円の値に収束すること、両端の断面積が等しい角錐台の体積が `A·h` になること、L字に組んだ骨格の慣性主軸が3値とも異なること（すなわちジャニベコフ効果が発生する形状であること）を固定する。

### 2-5. 内容積の割り当て

`hull` エッジそれぞれの内容積に、プレイヤーが何を入れるかを指定する。そのエッジのロフト体積が上限である。

| 収容物 | 実効容積の係数 | 備考 |
|---|---|---|
| 極低温タンク（液体水素・液体酸素・液体メタン） | 0.85 | 断熱材のぶん減る |
| 常温貯蔵タンク（ヒドラジン・四酸化二窒素・過酸化水素） | 0.95 | |
| 高圧ガスタンク（冷ガス） | 0.70 | 容器の肉厚のぶん減る |
| 貨物区画・ペイロード区画 | 0.90 | 容積と最大積載質量の両方で制限される |
| 居住区画（コックピット） | 0.80 | 与圧に必要な構造のぶん減る |
| 機器区画 | 1.00 | 電子機器・バッテリー・フライホイールを収める |

固体モーターはタンクではなく、エッジそのものである。ケースが構造材を兼ねるため、固体モーターを割り当てたエッジは `hull` エッジ1本がモーター1基に対応する。

液体推進剤を使うエンジンを持つ区画には、外部配管を自動生成して外観に反映する。プレイヤーは配管を配置しない。

### 2-6. 描画

```
src/render/hull/loft-mesh.ts
    buildLoftMesh(skeleton, lod) -> THREE.BufferGeometry
```

エッジごとに60分割のロフト帯を生成し、露出した端面を蓋で閉じ、全体を1つのジオメトリに結合する。生成は設計が変わったときに1度だけ行う。遠距離では分割数を下げた別のジオメトリを用いる。

`WebGPURenderer` は `Mesh` のジオメトリを最初の描画時にキャッシュするため、生成済みメッシュのジオメトリを差し替えてはならない。設計変更時は `Mesh` ごと作り直す。

## 3. 艦艇と基地の統合

### 3-1. 実体は `Vessel` 一種類のみとする

艦艇と軌道基地は、いずれも「背骨の上に部品が載った物体」であり、物理的な差は積んでいる部品だけである。したがってエンティティのクラスを分けない。

- **軌道基地** = 基地モジュール部品（格納庫・倉庫・生産設備）を積んだ `Vessel`。
- **艦艇** = コックピット部品と主機を積んだ `Vessel`。
- **無人ブースター** = 誘導装置部品と主機を積み、コックピットを積まない `Vessel`。

「これは基地か」という判定は存在せず、部品の有無から導かれる能力だけを問う。

```ts
// src/game/vessel/capabilities.ts
export function hasCockpit(v: Vessel): boolean;      // 人が操作できる
export function hasGuidance(v: Vessel): boolean;     // 無人で計画を実行できる
export function hasBaseModule(v: Vessel): boolean;   // 格納・倉庫・生産・設計ができる
export function hasEngine(v: Vessel): boolean;       // 主機を持つ
export function isOperable(v: Vessel): boolean;      // hasCockpit || hasGuidance
```

操作対象に選べるのは `isOperable` を満たす機体である。設計エディタと生産を開けるのは `hasBaseModule` を満たす機体である。

### 3-2. `Vessel` が持つもの

| フィールド | 内容 |
|---|---|
| `assembly: VesselAssembly` | 背骨と、各エッジ・ノードに割り当てられた部品 |
| `massProperties: MassProperties` | 乾燥質量・搭載質量・重心・慣性テンソル。背骨と搭載物と推進剤残量から導出し、変化時のみ再計算する |
| `propellant: PropellantStore` | 推進剤の種別ごとの残量 |
| `power: PowerSystem` | 発電・蓄電・消費 |
| `thermal: ThermalSystem` | 熱収支 |
| `propulsion: PropulsionSystem` | 主機・並進RCS（§4） |
| `attitudeControl: AttitudeControlSystem` | 姿勢トルクの配分（§4-2） |
| `stages: readonly VesselStage[]` | 分離可能な段の一覧（§6-1） |
| `parts: AnyPart[]` | 部品。HPと性能の唯一の源 |
| `plan: Plan` / `planExecutor: PlanExecutor` | 軌道計画とその自動実行 |

`EntityManager` は `vessels: Vessel[]` という単一の配列を持つ。操作対象は `ActivePlayerController` が `Vessel | null` として保持する。

### 3-3. 部品の種別

```ts
export type PartType =
  | 'cockpit'          // 有人操作
  | 'guidance'         // 無人誘導（計画の自動実行）
  | 'armor'            // 被弾軽減
  | 'shield'           // 可動遮蔽（日除け・被弾遮蔽）
  | 'engine'           // 主機
  | 'rcs_thruster'     // 並進RCS・姿勢RCS
  | 'reaction_wheel'   // フライホイール
  | 'tank'             // 推進剤タンク
  | 'solid_motor'      // 固体モーター
  | 'decoupler'        // 分離機構
  | 'radiator'
  | 'solar_panel'
  | 'battery'
  | 'weapon'
  | 'payload_bay'      // ペイロード区画（§6-4）
  | 'base_module'      // 格納庫・倉庫・生産設備
```

各部品は共通に `id` / `type` / `name` / `dryMass` / `maxHp` / `hp` を持ち、種別ごとの性能値を追加する。機体の総合HPは全部品のHPの和であり、コックピットが失われた時点で0とする。

部品は背骨のノードまたはエッジに割り当てる。ノードに付くのは外部に露出する部品（主機・RCS・ラジエータ・ソーラーパネル・武装・遮蔽・分離機構）であり、エッジの内容積に入るのは内部の部品（タンク・バッテリー・フライホイール・コックピット・ペイロード区画・基地モジュール）である。

## 4. 推進系

### 4-1. 3つのシステムの役割

| システム | 役割 | 推進剤 | 比推力 | 特性 |
|---|---|---|---|---|
| **主機（EngineBank）** | 軌道変更のための大きな Δv | 液体・固体・ハイブリッド | 265〜450 s | 推力大。始動と停止にコストがある。固体は停止も再着火もできない |
| **並進RCS（TranslationRcs）** | 近接機動・姿勢制御の補助 | 単推進剤または冷ガス | 70〜230 s | 推力小。船体6方向すべてに出せる。応答は即時 |
| **フライホイール（ReactionWheels）** | 姿勢制御のみ | 消費しない（電力のみ） | — | トルク小・連続。**角運動量が飽和する** |

### 4-2. 姿勢トルクの配分

姿勢トルクを要求する主体は、手動操作と自動操縦の2つである。両者は `AttitudeControlSystem` に要求を出し、どのアクチュエータが出すかはそこが決める。

1. 要求トルク τ のうち、各軸でフライホイールが出せるぶんを出す。出せる条件は、そのホイールの最大トルクを超えないことと、蓄積角運動量 `h` が上限 `hMax` に達していないことの両方である。
2. ホイールが τ_wheel を出すと、反作用として角運動量が `h += -τ_wheel · dt` だけ溜まる。同時に電力を消費する。
3. ホイールで出せなかったぶん、および飽和した軸は、RCSスラスタが出す。RCSは推進剤を消費する。
4. `|h|` が `hMax` の既定割合を超えると**アンローディング**を行う。RCSで外部トルクを与えながらホイールを減速し、`h` を外部に捨てる。自動実行を既定とし、手動実行のボタンをHUDに置く。

この規則により、静穏時は推進剤を消費せずに姿勢を保ち、激しい機動の後は必ずRCS推進剤を消費する、という往復が生まれる。RCS残量が戦闘の資源になる。

### 4-3. 並進推力の選択

- 要求方向が主機の推力軸と一致し、要求の大きさがRCSの最大推力を超える場合は主機を使う。
- それ以外はRCSを使う。
- プレイヤーはHUDで「主機を使わない」「主機のみ」を明示的に選べる。

### 4-4. 推力軸と重心のずれ

主機の推力軸が機体重心を通らない場合、その差からトルクが生じる。この効果は正しく計算する。

設計エディタは、主機の合成推力軸と重心のずれを常に表示し、規定値を超える場合は警告する。飛行中は、ジンバル機構を持つ主機がずれを打ち消す方向に首を振り、打ち消しきれないぶんは `AttitudeControlSystem` が補償する。ジンバルを持たない主機（固体モーターなど）のずれは補償されず、機体が回る。

### 4-5. モジュール

```

    desaturationTorque(h, hMax, spec) -> Vec3

```

## 5. 推進剤とエンジン

### 5-1. 推進剤の物性表

比推力は真空値、密度は貯蔵状態の値である。

**液体（酸化剤と還元剤のペア）**

| ペア | 真空比推力 [s] | 混合比 O/F | 平均密度 [kg/m³] | 貯蔵 |
|---|---|---|---|---|
| 液体酸素 / 液体水素 | 450 | 5.5 | 360 | 極低温・蒸発損失大 |
| 液体酸素 / 液体メタン | 370 | 3.5 | 830 | 極低温・蒸発損失中 |
| 液体酸素 / シラン | 330 | 3.0 | 900 | 酸化剤のみ極低温・自己着火 |
| 四酸化二窒素 / モノメチルヒドラジン | 320 | 2.0 | 1200 | 常温・長期貯蔵可・毒性 |
| 過酸化水素 / ケロシン | 310 | 7.0 | 1290 | 常温・徐々に分解 |

**単推進剤（RCS向け）**

| 推進剤 | 比推力 [s] | 密度 [kg/m³] | 特性 |
|---|---|---|---|
| ヒドラジン（触媒分解） | 230 | 1010 | 長期貯蔵で徐々に分解。毒性 |
| 過酸化水素（触媒分解） | 160 | 1400 | 無毒。分解が速い |
| 窒素冷ガス | 70 | 高圧貯蔵 | 最も単純。電力も点火も不要 |

**固体・ハイブリッド**

| 種別 | 比推力 [s] | 密度 [kg/m³] | 特性 |
|---|---|---|---|
| 固体（過塩素酸アンモニウム + 末端水酸基ポリブタジエン + アルミ粉末） | 265 | 1800 | 点火後は停止も絞りも再点火もできない |
| ハイブリッド（ABS樹脂 + 亜酸化窒素） | 300 | 1100 | 絞れる・停止できる・再点火できる。密度で不利 |

固体推進剤の燃料成分はアルミ粉末であり、酸化アルミニウムはその燃焼生成物である。ABS樹脂はハイブリッドロケットの固体燃料側であり、亜酸化窒素または液体酸素の酸化剤と組み合わせて使う。

**選択の意味** — 固体は安価で高密度、ただし一度きりであり、使い捨ての帰投用ブースターに適する。液体酸素／液体水素は比推力が最も高いが密度が低く巨大なタンクを要し、蒸発損失があるため長期の待機に向かない。ヒドラジン系は性能が中位だが常温で長期間待機でき、軌道上に置いておくブースターに適する。

### 5-2. エンジンの型式

エンジンは「サイクル（供給方式）」と「対応推進剤」の組で定義する。同じ推進剤でもサイクルが違えば性能が変わる。

| サイクル | 比推力係数 | 推力重量比 | 絞り範囲 | 再着火 | 特徴 |
|---|---|---|---|---|---|
| 加圧式 | 0.95 | 低 | 40〜100% | 無制限 | 構造が単純で信頼性が高い。タンクを高圧に耐える厚さにする必要があり、タンク質量が増える |
| 電気ポンプ式 | 0.98 | 中 | 30〜100% | 無制限 | 電力を消費する。バッテリー容量が燃焼時間を制限する |
| ガス発生器サイクル | 1.00 | 高 | 60〜100% | 数回 | 標準的な性能 |
| 段階燃焼サイクル | 1.04 | 高 | 50〜100% | 数回 | 比推力が最も高い。エンジン質量とコストが大きい |
| エキスパンダーサイクル | 1.03 | 低 | 30〜100% | 無制限 | 液体水素専用。推力が小さく、上段に適する |
| 固体モーター | 1.00 | 最高 | 不可 | 不可 | 点火後は停止できない |
| ハイブリッドモーター | 1.00 | 中 | 20〜100% | 無制限 | 酸化剤のみタンクに持つ |

エンジン部品の性能値は、`推進剤ペアの比推力 × サイクルの比推力係数` を比推力とし、推力と質量はサイクルとサイズから決める。ジンバル可動角もサイクルごとに定める。

### 5-3. ツィオルコフスキーによる燃焼計算

燃焼中は推進剤の消費により質量が減り、加速度が上がる。燃焼時間と点火時刻はツィオルコフスキーの式に基づいて求める。

```
src/physics/tsiolkovsky.ts   (純関数)
    dvFor(m0, mf, isp)               // Δv = Isp·g0·ln(m0/mf)
    massAfterBurn(m0, dv, isp)
    burnTimeFor(dv, m0, thrust, isp) // 推進剤流量 = thrust/(Isp·g0)
    propellantForDv(dv, mDry, isp)
```

一定加速度を仮定すると質量比の大きい機体で点火が遅れてマニューバノードを外すため、質量変化を必ず含める。

段の切り替わりを跨ぐ燃焼は加速度が不連続になり閉形式で扱えない。1つのマニューバノードの燃焼が1つの段の中で完結するよう、設計エディタと計画UIで制約する。

### 5-4. 推進剤の劣化

極低温推進剤は日射に応じた蒸発損失を生じ、断熱材の等級と遮蔽で低減できる。ヒドラジン系は触媒毒による自己分解を生じ、時定数は年単位である。固体推進剤は劣化しない。

劣化の計算は毎フレームでは行わず、残量を読む時点で前回の評価時刻からの経過時間に基づいて一括で計算する。

## 6. 多段ブースターシステム

### 6-1. 段の定義

段は、背骨から `decoupler` エッジを取り除いたときの連結成分である。プレイヤーが段を明示的に区切る操作は存在せず、分離機構を挿すと自動的に分かれる。

```ts
// src/game/vessel/assembly.ts
export interface VesselStage {
  readonly id: string;
  readonly edgeIds: readonly string[];
  readonly hasCockpit: boolean;
  readonly hasGuidance: boolean;
  readonly dryMass: number;
  readonly propellantMass: number;
}
export function splitStages(skeleton: VesselSkeleton, parts: readonly AnyPart[]): readonly VesselStage[];
```

コックピットまたは誘導装置を含む段は、分離後も操作または自動制御の対象になる。どちらも含まない段は、分離後は制御不能な物体として軌道上に残る。

### 6-2. 分離の物理

分離は運動量保存を満たす。分離前の質量を `m_total`、分かれる2つを `m_a` / `m_b`、分離機構の力積から求まる相対速度増分を `Δv_sep` とすると、

```
v_a = v + (m_b / m_total) · Δv_sep
v_b = v − (m_a / m_total) · Δv_sep
```

角運動量も同様に分配する。分離直後の一定時間は、分かれた2つの間の接触判定を無効にする。

分離後、本体は背骨・質量・重心・慣性テンソル・推進剤残量を再計算する。

### 6-3. 燃焼の順序

同時燃焼（並列に束ねたブースター）と逐次燃焼（直列の多段）の両方を許す。設計エディタは分離の順序を並べ替えるリストを持ち、飛行中はその順序に従って次に分離する段をHUDに表示する。

推進剤が尽きた段は分離の候補として提示するが、自動では分離しない。分離は軌道を変えるため、実行はプレイヤーまたは計画の判断に委ねる。

### 6-4. ペイロード

ペイロード区画は、軌道上へ運ぶものを収める。

```ts
export type PayloadKind =
  | { kind: 'ammo'; magazines: number }              // 弾薬（マガジン単位）
  | { kind: 'propellant'; propellantId: string; mass: number }
  | { kind: 'part'; partIds: readonly string[] }     // 部品を倉庫へ運ぶ
  | { kind: 'none' };

export interface PayloadBayPart extends Part {
  readonly type: 'payload_bay';
  readonly volume: number;      // 内容積 [m³]
  readonly maxMass: number;     // 最大積載質量 [kg]
  payload: PayloadKind;
}
```

**弾薬をペイロードとして運ぶ運用** — 弾薬マガジンを積んだ無人ブースターを、誘導装置による自動操縦で目的の軌道に投入する。到達後、ペイロード区画を開いて弾薬を放出すると、既存の補給パッケージと同じ実体が軌道上に生成される。艦艇はそれに接近して回収する。

この運用は機体同士の結合を必要としない。放出された弾薬は独立した物体として軌道を回り、艦艇は既存の接近回収の仕組みでそれを取る。

放出は、プレイヤーの明示的な操作、または軌道計画上の指定時刻に行う。放出時には小さな分離速度を与え、ブースター本体と弾薬が離れる。

## 7. 設計の保存・生産・技術ツリー

### 7-1. 設計データ

```ts
// src/game/vessel/blueprint.ts
export interface VesselBlueprint {
  readonly id: string;
  name: string;
  readonly skeleton: VesselSkeleton;
  readonly partPlacements: readonly PartPlacement[];  // どのノード／エッジに何を付けるか
  readonly contents: readonly EdgeContent[];          // どのエッジに何を収めるか
  readonly paint: PaintScheme;
  readonly stageOrder: readonly string[];             // 分離機構の分離順
  readonly createdAt: number;
  readonly updatedAt: number;
}
export interface PaintScheme {
  primaryColor: string;
  secondaryColor: string;
  accentColor: string;
  metalness: number;
  roughness: number;
}
```

設計は `localStorage` の `tepui.blueprints` に保存する。保存・読み込み・複製・削除・改名ができる。既存のセーブデータの入出力と同じ方式でファイルへの書き出しと読み込みも行う。

設計の検証は独立した純関数とし、エディタと生産の両方が同じ関数を呼ぶ。

```ts
// src/game/vessel/blueprint-validation.ts
export interface BlueprintIssue {
  readonly severity: 'error' | 'warning';
  readonly targetId: string;      // ノード／エッジ／部品の id
  readonly message: string;
}
export function validateBlueprint(bp: VesselBlueprint): readonly BlueprintIssue[];
```

検証する内容は、背骨が連結していること、側面の口から出るエッジの断面が口に収まること、内容積の割り当てがロフト体積を超えないこと、コックピットまたは誘導装置を1つ以上持つこと、各段が主機を持つか持たないかの整合、推力軸と重心のずれが規定内であること、技術ツリーで未解禁の部品を含まないこと、である。

### 7-2. 生産

生産は、保存した設計を指定し、資源とクレジットを消費して実機を得る操作である。

```ts
export interface ProductionTask {
  readonly id: string;
  readonly blueprintId: string;
  readonly startedAt: number;      // simTime
  readonly finishAt: number;       // simTime
}
```

- 生産コストは、部品ごとの単価と、外皮の表面積に比例する構造費の和とする。
- 生産時間は部品の合計から求めるが、**初期状態では係数を0とし、すべての設計が即座に完成する**。時間のかかる生産は仕組みとして用意し、有効にするのは後の判断とする。
- 生産キューは基地モジュールを持つ機体が保持する。完成した機体は、その基地の格納庫に配備される。

### 7-3. 技術ツリー

エンジンの型式、断面形状、推進剤、部品は、技術ツリーの解禁によって使えるようになる。

```ts
// src/game/tech/tech-tree.ts
export interface TechNode {
  readonly id: string;
  readonly name: string;
  readonly description: string;
  readonly cost: number;                        // 研究点
  readonly requires: readonly string[];         // 前提となる技術 id
  readonly unlocks: readonly string[];          // 解禁される部品／推進剤／断面の id
}
export const TECH_TREE: readonly TechNode[];
```

- 研究点は敵の撃破とステージのクリアで得る。保持は `localStorage` の `tepui.tech` に置き、解禁済みの技術 id の集合と研究点の残高を保存する。
- 初期状態で解禁されているのは、円と四角形の断面、加圧式エンジン、四酸化二窒素／モノメチルヒドラジン、ヒドラジン単推進剤、固体モーター、基本的な構造部品である。
- 解禁の対象は、断面形状（三角形・五角形・六角形・楕円）、エンジンのサイクル（電気ポンプ式・ガス発生器サイクル・段階燃焼サイクル・エキスパンダーサイクル・ハイブリッド）、推進剤ペア、フライホイール、ジンバル機構、大型の分離機構、ペイロード区画である。
- 未解禁の部品は設計エディタのパレットに表示するが、選択できず、解禁に必要な技術を表示する。

### 8-2. 骨格モード

左パネルの内容:

| 区画 | ウィジェット | 内容 |
|---|---|---|
| 選択中のノード | `SegmentedControl<CrossSectionShape>` | 断面形状。未解禁の形状は選択できない |
| | `ValueInput` ×2 | 外接円半径、楕円の短半径（楕円選択時のみ表示） |
| | `Slider` | 回転位相（0〜360度、15度刻みのスナップあり） |
| | 一覧 | このノードの接続口。使用中／空きを表示し、空きをクリックすると新規ノードが生える |
| 選択中のエッジ | `SegmentedControl<EdgeKind>` | 外皮／構造材／分離機構 |
| | `ValueInput` | 長さ |
| | `ValueInput` | 構造材の場合の半径、分離機構の場合の分離力積 |
| 全体 | `ToggleSwitch` | YZ平面のミラー編集 |
| | `Button` | 選択中のノード以下を削除 |

操作:

- **ノードの追加** — 選択中のノードの空いている接続口をクリックする。既定の長さのエッジと、同じ断面のノードが生える。生えた先が新しい選択対象になる。3Dビューポート上の接続口を直接クリックしても同じ操作になる。
- **ノードの移動** — エッジの長さを変えることで行う。ノードの座標を直接ドラッグする操作は持たない。位置は接続関係と長さから一意に決まる。
- **削除** — 選択中のノードとその先につながる部分をまとめて削除する。削除の前に、削除される範囲を3Dビューポート上で強調表示する。
- **ミラー編集** — 有効な間、YZ平面の片側で行った操作が反対側にも同時に適用される。ミラーを無効にすると、以後の操作は片側にのみ適用される。
- **元に戻す／やり直す** — 設計データ全体のスナップショットを操作ごとに保持する。上限は50手とする。

3Dビューポートの表示切り替え:

- **骨格** — ノードを球、エッジを線で表示する。接続口を小さな面として表示し、空いている口を強調する。
- **外皮** — 生成される外皮を表示する。選択中の部分を強調する。
- **断面** — 選択中のノードの断面を、その位置に平面として表示する。回転位相と分岐方向が見える。
- **段** — 段ごとに色分けして表示する。分離機構を挿すと色が分かれる。

### 8-3. 搭載モード

左パネルの内容:

| 区画 | ウィジェット | 内容 |
|---|---|---|
| 部品パレット | 種別ごとのアコーディオン | 部品の一覧。未解禁のものは選択できず、必要な技術を表示する |
| 選択中の部品 | 一覧 | 質量・性能値・コスト |
| 選択中のエッジの内容 | `ObjectPicker` | そのエッジに収めるもの（タンク・貨物・機器・ペイロード・空） |
| | `ValueInput` | 推進剤タンクの場合、推進剤の種別と充填率 |
| | 表示 | ロフト体積、実効容積、収容質量 |

操作:

- 部品パレットで部品を選び、3Dビューポート上のノードをクリックすると装着する。装着できないノード（すでに埋まっている、口の向きが合わない）はクリックできず、理由をヒントで示す。
- ホバー中は、装着した場合の外観を半透明で表示し、右パネルの性能に差分を表示する。
- エッジをクリックすると、その内容積の割り当てを編集する。

### 8-4. 塗装モード

左パネルに、基本色・副色・アクセント色のカラー選択、金属感と粗さのスライダー、および既定の配色プリセットを置く。3Dビューポートに即座に反映する。

### 8-5. 段モード

左パネルに、段の一覧を分離順に並べたリストを置く。各行に段の乾燥質量・推進剤質量・その段の Δv・主機の有無を表示し、上下ボタンで分離順を並べ替える。

3Dビューポートは段の色分け表示に固定する。行を選択すると、その段を強調表示する。

全段の Δv の積み上げグラフを表示する。各段の Δv はツィオルコフスキーの式により、その段を点火する時点の総質量と、燃焼終了時の総質量から求める。

### 8-6. データの流れ

```
DesignEditorState (エディタの編集中データ、Undo/Redo のスタックを持つ)
    │  編集操作ごとに
    ▼
VesselBlueprint (検証と性能計算の入力)
    ├─► validateBlueprint()        → 左パネルと3Dビューポートの問題表示
    ├─► deriveMassProperties()     → 右パネルの質量・重心・慣性
    ├─► deriveStages()             → 段モードの一覧と Δv
    ├─► deriveProductionCost()     → 右パネルのコスト
    └─► buildLoftMesh()            → 3Dビューポートの外皮表示
```

性能計算は編集操作のたびに実行する。計算はすべて解析式であり、ノードとエッジの数に対して線形であるため、毎操作の実行で問題にならない。外皮メッシュの生成のみ、編集が一定時間止まってから実行する。

### 8-7. 飛行中のHUD

設計エディタとは別に、飛行中に以下のパネルを置く。いずれも個別に折り畳める。

- **推進系** — 主機・並進RCS・フライホイールの3行。主機は推進剤の種別ごとの残量、RCSは残量、フライホイールは蓄積角運動量と上限の比をメーターで表示し、飽和が近い場合は警告色にする。
- **段** — 段の一覧、次に分離する段、段ごとの残 Δv。分離の実行ボタン。
- **ペイロード** — ペイロード区画の内容と、放出の実行ボタン。

## 11. 主要な技術的リスク

1. **断面をまたぐ頂点の対応** — 辺数の異なる断面や、回転位相の異なる断面をつなぐとき、頂点の対応を誤ると外皮がねじれる。60点への等分と、対応距離の総和を最小にする割り当てで解決するが、両端の位相差が大きい場合の見た目は確認が必要である。
2. **描画メッシュの生成コスト** — 背骨から生成するメッシュは実行時生成であり、`WebGPURenderer` はジオメトリを最初の描画時にキャッシュする。生成は設計変更時のみとし、既存メッシュのジオメトリを差し替えない運用を守る必要がある。
3. **設計の自由度と性能の破綻** — 断面寸法とエッジ長に上限を設けないと、極端に大きな機体が作れてしまう。ノード数・総質量・最大寸法に上限を設け、検証で拒否する。
4. **推力軸のずれによる制御不能** — 側面に非対称にブースターを束ねると、推力軸が重心を大きく外れる。設計エディタでの警告と、ジンバル補償の両方が必要である。補償しきれない設計は生産を拒否する。
5. **保存形式の互換性** — 機体の表現が部品の配列から背骨とアセンブリの構造へ変わるため、旧形式の保存データは既定の設計への読み替え以上のことはできない。読み替え不能な保存データは明示的に拒否し、破損した機体を生成しないこと。
6. **UIの総量** — 設計エディタは4つのモードを持ち、飛行中にも3つのパネルが加わる。既存のパネルへ統合できないかを追加のたびに確認し、置き場の規約に従うこと。
