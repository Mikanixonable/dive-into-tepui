## 第1巻を最初に置く理由

**第1巻は、第2巻と第3巻を並列に進めるための土台である。**第1巻を通した時点で、機体は既定の設計として1つ与えられるものであり、それを編集する手段はまだない。しかし慣性テンソルも接触形状も抗力も形状の帰結になり、推進系は4つに分かれ、推進剤ごとに Δv が変わり、無人機は通信圏の内側でしか動かない。

第1巻の F6（ツリーのデータ構造と設計データの形）・F7（質量特性の適用）と R1〜R3（資源と設備の定義）が済めば、**第2巻と第3巻を同時に進められる。**

## 着手順

第1巻の実装計画（§18）は**2本の独立した系列**からなる。機体の系列 F1〜F13 と、資源の系列 R1〜R3 である。R系は F系にまったく依存せず、**2人が同時に着手できる。**要点は5つである。

**F1・F3・F4・R1 は依存がなく、並行して着手できる。**

**F1（断面の幾何）から着手する。**`src/physics/` に閉じた純関数とテストのみであり、ゲームには一切繋がない。計画全体で最大の未知は「複合断面と一般化角錐台の物理量が閉形式で求まるか」であり、ここが崩れると第1巻の §7〜§10 の設計思想ごと組み直しになる。失敗しても捨てる費用がゼロである段階で先に確かめる。

**F4（`Vessel` への統合）は早く通す。**`Ship` / `Player` / `Base` / `Enemy` の統合を後回しにすると、以降のすべてが複数のクラスに対して同じ変更を繰り返すことになる。

**F7 で抗力と熱シールドを同時に入れる。**抗力係数を形状から導出すると大気減衰と再突入のタイミングが変わり、これはステージの敗北条件に直結する。熱シールドを別の段階に置くと、抗力は増えたのに耐熱は変わらないという状態が続く。

**R1（資源・産地・設備のデータ定義）から資源の系列を始める。**純粋なデータと帳簿であり、他に依存しない。R3 まで通せば、資源の連鎖が「詰まらないこと」まで含めて確かめられている。

## この作品の骨格をなす方針

| 方針 | 内容 |
|---|---|
| 実体は1つ | 艦艇・軌道基地・通信衛星・コンテナ・敵艦は、すべて `Vessel` である。専用のクラスを作らない。能力は積んでいる部品から導く |
| 形状は自由、寸法は離散 | 形はノードとエッジのツリーと、各ノードの断面で決まる。ツリーは閉じてよい。**直径もエッジの長さも 0.5 メートル単位**である |
| 物理量は形状の帰結 | 質量・重心・慣性テンソル・投影面積・接触形状は定数として持たず、形状と搭載物から導出する |
| 結合は平面の突き合わせ | 曲面を融合させず、立体の重なりを差し引かない。すべての幾何量が解析式で求まる |
| 技術ツリーはない | 研究点も前提技術の木もない。使えるものは、手に入れた資源と、それを変換する設備の連鎖によって広がる |
| 通貨はない | 市場もない。すべては**資源・設備・電力**を消費する生産によって賄われる。生産設備そのものの生産にも資源が要る |
| 進行は物理的な事実で止まる | 作れないのは技術が未解禁だからではなく、材料か設備か電力が足りないからである |
| 高性能な計算機が存在しない | 機上で自力にできるのは、時刻で駆動する噴射シーケンスと姿勢の保持まで。自動でのドッキング、軌道の誤差修正、目標の追尾、計画の変更は、観測して判断する処理であり外部からの指令を要する |
| 自動操縦は通信を要する | 無人機は通信モジュールを積み、通信圏の内側にいなければ計画を実行できない。通信網は基地から順に伸び、孤立した中継点は働かない。通信衛星は無人の `Vessel` である |
| 戦域は基地の周りから広がる | 序盤は基地自身が敵を迎え撃つ。掃討したのち、月周回軌道・静止軌道・地球低軌道・L1 へと、Δv と通信圏の両方に従って外へ広がる |
| 設計は戦闘ビューと同じ空間で行う | 全画面のワークベンチを持たない。基地のドックの中で、機体を実寸で見ながら組む。別々に組んだモジュールの結合は、ドッキングと同じ操作である |

## 実装に入る前に想定しておくこと

**再突入のバランスが変わる。**現在の抗力係数は、質量の仮定が実際の機体質量と食い違っており、本来より小さい値になっている。形状と実質量から導出すると抗力が増え、大気減衰と再突入のタイミングが変わる。第1巻 F7 の時点でステージ側の高度と時間の調整が要る。

**スロットル操作の手触りが変わる。**加速度による4段指定を廃し、絞り率 0〜100% の連続値になる。同じキーでも、機体設計によって出る加速度が変わる。

**保存形式に互換性がない。**機体の表現が変わるため、旧形式の保存データは既定の設計への読み替え以上のことはできない。読み替え不能な保存データは明示的に拒否する。

**テストは DOM と THREE に触れられない。**`tsconfig.test.json` の `lib` は `ES2022` のみであり、`include` に個別ファイルを列挙する方式である。物理でないテストは `tests/unit/` を新設して置き、`package.json` に `test:unit` を足して `ci` に組み込む。`game/vessel/` と `game/economy/` の計算部分は、最初から純関数として切り出しておく必要がある。後から分けるのは難しい。
