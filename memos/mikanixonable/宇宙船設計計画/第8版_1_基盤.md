# 基盤 — 機体と資源の土台

この文書は、宇宙船という物がどう成り立っているかを定める。**第2巻と第3巻を並列に進めるための土台であり、最初に実装する。**

対象は以下の8つである。

1. 艦艇と軌道基地を単一の実体 `Vessel` に統合する（§5）
2. 搭載要素の型と性能値を定義する（§6）
3. 断面とツリーによる形状の定義と、その幾何量の計算（§7〜§10）
4. 形状からの質量特性の導出、カプセルによる接触形状、姿勢依存の空力（§10〜§11）
5. 主機・並進RCS・フライホイール・磁気トルカを分離した推進系と姿勢制御系（§14）
6. 推進剤の種別と、実データに基づくエンジン性能、質量変化を含む燃焼計算（§15）
7. 通信と、無人機の自動操縦の前提（§16）
8. 資源・産地・設備のデータ定義と、生産可能性および設備の連鎖の判定（§17）

**この文書は他のどの計画にも依存しない。**

**第2巻・第3巻との関係** — 第2巻『設計・建造・資源』は、プレイヤーがツリーを組んで設計を作り、資源とエネルギーを消費して生産し、配管を敷き、段に分け、基地を運用し、資源の連鎖を広げる仕組みを定める。第3巻『延期目標』は、月の地形と着陸、月面基地、資源の採掘と輸送、人員、テザー式の重力区画、補給の自動化、敵の構成を扱う。

本文書は「機体がどう成り立っているか」と「資源と設備が何であるか」までを扱い、「プレイヤーがどう作り、どう進むか」には踏み込まない。したがって本文書の段階では、機体は**既定の設計**として与えられるものであり、それを編集する手段はまだない。

---

## 1. 対象外

設計と組み立ての操作、設計データの保存と検証、資源の採掘と設備の稼働、生産の処理そのもの、推進剤の配管、タンクの与圧、分離機構による多段化、ペイロードの投入、基地の区画の運用、通信衛星の配備は本文書の対象外である。月面着陸、月面基地、資源採掘、ドッキングポートによる機体の結合、人員、テザー式の重力区画も対象外である。

**通貨は存在しない。**搭載要素は購入するものではなく、資源とエネルギーを消費して生産するものである。本文書は資源と設備が何であるかを §17 に定め、在庫と設備から生産の可否を判定するところまでを持つ。実際に資源を採り、設備を稼働させ、設計から要求を集計して実機を得る処理は第2巻が定める。

推進剤ごとに定めるタンク材料の要求（§15-1）は物性として登録し、その適合性は §17-2 の材料要求として生産可能性の判定に働く。エンジンのサイクルごとに定める要求与圧（§15-3）は、性能値として定義するにとどめ、加圧ガスの消費としては働かない。

## 2. 設計判断

### 2-1. 実体は `Vessel` 一種類のみとする

艦艇・軌道基地・通信衛星・コンテナは、いずれも「部品が載った物体」であり、物理的な差は積んでいる部品だけである。別のクラスとして持たない。「これは基地か」という判定は存在せず、部品の有無から導かれる能力だけを問う。

### 2-2. 質量特性は2つの経路から与えられる

`Vessel` は「搭載要素と形状から質量特性を導出する機体」と「`MassProperties` を直接与えられた機体」の両方を扱う。前者は設計された機体であり、後者は敵艦とコンテナである。`Vessel` の側から見れば、質量特性は「導出された値か、与えられた値か」の別なく同じ1つのフィールドである。

### 2-3. 船体はツリーと断面で定義する

宇宙船の形状は、**ノードとエッジからなるツリー**と、**各ノードが持つ断面**で定義する。外皮は、エッジの両端にある2つの断面をつないだ立体（ロフト）として生成する。

ツリーは**閉じた構造を持ってよい**。三角形や梯子状に組めば扁平な機体になり、環状に閉じれば輪の形になる。

エッジから外皮までの距離は定数ではなく、両端のノードの断面寸法によって決まる。したがって、細い部分と太い部分を持つ機体、先細りの機体、段ごとに直径の異なるロケットが、追加の機構なしに作れる。

### 2-4. 断面が分岐方向を決める

各ノードは、断面の表裏に向かう2つの軸方向の接続口と、断面形状ごとに決まる側面の接続口を持つ。側面の口の方向は断面が決め、各ノードが持つ回転位相ぶん回る。

- **多角形の断面** — 各辺の外向き法線の方向に口を持つ。三角形なら3方向、八角形なら8方向である。
- **円の断面** — 分岐数 n を 2・3・4・5・6 から選び、360度を n 等分した方向に口を持つ。
- **楕円の断面** — 長軸の正負2方向に口を持つ。

分岐の角度を数値で指定する操作は存在しない。角度は断面形状と分岐数と回転位相から決まる。

### 2-5. 結合はすべて平面同士の突き合わせとする

エッジと断面の結合、側面分岐の結合、および断面を組み合わせて複合断面を作るときの結合は、いずれも平面同士の突き合わせとする。曲面同士を滑らかに融合させる処理も、立体同士の重なりを差し引く処理も行わない。

この判断により、外皮の体積・表面積・重心・慣性テンソルがすべて解析式で求まり、部分同士が重なることもない。数値積分も、等値面の三角形分割も不要である。実際のロケットも、段間部と側面ブースターの取り付けはフランジ結合であり、工学的にも自然である。

円の断面に側面の口を設ける場合のみ、その方向の円弧を弦で切り落として平面を作る。切り落としによる断面積と断面二次モーメントの減少は、弓形の解析式を差し引いて厳密に計算する。

### 2-6. 寸法は 0.5 メートル単位とする

**機体の直径は 0.5 メートル単位**である。すなわち断面の外接円**半径**は 0.25 メートル単位であり、直径 1 メートル・2 メートル・3 メートルの円筒が作れる。**エッジの長さも 0.5 メートル単位であり、最小は 0.5 メートルである。**

連続値にしないのは、対称な機体や、断面の揃った段を組むことが困難になるためである。半径の刻みを機体の大小で場合分けする規則は持たない。

**多角形の断面では、外接円直径と実際の幅が異なる。**正方形で外接円直径 1 メートルを指定すると、辺の長さは 0.707 メートルになる。寸法の刻みは外接円半径で揃えたまま、**表示の側で外接円直径・辺の長さ・最大幅の3つを併記する**ことで、この食い違いを埋める。

### 2-7. 物理量は形状から導出する

質量・重心・慣性テンソル・投影面積は定数として持たず、ツリーと断面と搭載物から導出する。扁平な機体は実際に回りにくく、非対称な機体は実際に重心がずれる。

### 2-8. 接触形状はカプセルの集合とする

剛体接触と被弾の判定は、機体を1つの球で表すのではなく、**ツリーの各エッジに対応するカプセルの集合**で行う。全長数十メートルの細長い機体や扁平な機体を1つの球で表すと、当たり判定が形状とまったく合わない。

カプセルの集合であれば、既存の空間格子による近傍探索をそのまま使え、掃引球の判定をカプセルに拡張するだけで済む。被弾したカプセルから、損傷する搭載要素も自然に決まる。

### 2-9. 推進と姿勢制御は4つの系統に分ける

軌道変更のための大きな Δv、近接機動と姿勢制御の補助、推進剤を消費しない姿勢制御、推進剤も反作用も要らない姿勢制御は、それぞれ推力・比推力・応答性・消費資源・使える領域が異なる。単一のスラスタとして扱わず、主機・並進RCS・フライホイール・磁気トルカの4系統に分ける。姿勢トルクをどのアクチュエータが出すかは、要求を受けた側が決める。

### 2-10. アクチュエータの配置はプレイヤーが決める

RCSスラスタの取り付け位置と噴射方向は、機体ごとに異なる。船体の6方向に1基ずつという配置を前提にしない。姿勢トルクの配分は、任意個・任意配置のスラスタ集合に対して成立する形で定義する。

### 2-11. 推進剤は登録されたペアからのみ選ぶ

比推力は実測値であり、任意の酸化剤と還元剤の組み合わせに対して定義できない。推進剤は「酸化剤と還元剤のペア」「単推進剤」「固体グレイン」「ハイブリッドの組」として表に登録されたものからのみ選ぶ。表は §15-1 に置く。

### 2-12. 性能値は搭載要素が持つ

推力・比推力・トルク・発電量・放熱量・冷却能力を、機体ごとの定数として持たない。すべて搭載要素の性能値の合計として求める。部品を積み替えれば、他に何も書き換えることなく機体の性能が変わる。

### 2-13. 燃焼は質量変化を含めて計算する

燃焼中は推進剤の消費により質量が減り、加速度が上がる。一定加速度を仮定すると、質量比の大きい機体で点火が遅れてマニューバノードを外す。燃焼時間と点火時刻は、必ず質量変化を含む式で求める。

### 2-14. 無人の自動操縦は通信を要する

無人の機体が軌道計画を自動で実行するには、通信モジュールを積み、かつ通信圏の内側にいることが要る。圏外に出た機体は計画の実行を止める。有人の機体は通信を要さない。

## 3. 用語

| 語 | 意味 |
|---|---|
| ツリー | ノードとエッジからなるグラフ。機体の形状を定める。閉じた構造を持ってよい |
| ノード | ツリーの頂点。断面と回転位相を持つ |
| エッジ | ツリーの辺。両端のノードを結ぶ。外皮・トラス・分離機構のいずれかの種別を持つ |
| 断面 | ノードが持つ形。1つ以上の基本断面を貼り合わせた複合体 |
| 基本断面 | 円・楕円・正多角形・切り欠き型のいずれか |
| 接続口 | ノードが持つ、エッジまたは外装要素を取り付ける場所 |
| 外皮 | エッジの両端の断面をつないだ立体（ロフト）。内側が内容積になる |
| トラス | 外皮を作らない構造部材。軸に沿った任意の位置に外装要素を取り付けられる |
| 搭載要素 | 機体に積む部品。外装要素と内装要素に分かれる |
| 既定の設計 | 本文書の段階で与えられる設計。編集する手段は第2巻が与える |

## 4. 実体の一覧

`Vessel` として実装されるものを挙げる。専用のクラスを作るものは1つもない。

| 実体 | 積んでいるもの | 質量特性の経路 |
|---|---|---|
| 艦艇 | コックピットと主機 | ツリーから導出 |
| 軌道基地 | 基地モジュール | ツリーから導出 |
| 無人ブースター | 自動操縦装置・通信モジュール・主機 | ツリーから導出 |
| 通信衛星 | 通信モジュール・太陽電池パドル | ツリーから導出 |
| 敵艦 | 種別ごとに定めたもの | 直接与える |
| コンテナ | 中身のみ | 直接与える |

**コンテナはツリーを持たない `Vessel` である。**規格化された貨物容器であり、中身は資源・推進剤・部品のいずれかである。接触形状は単一のカプセル、能力はすべて偽（操作もできず基地でもない）。切り離すと独立した物体として軌道上に残り、機体に保持されている間は質量特性に加わる。コンテナの規格と着脱の運用は第2巻が定める。

## 5. 艦艇と基地の統合

### 5-1. 能力は搭載要素から導く

```ts
// src/game/vessel/capabilities.ts
export function hasCockpit(v: Vessel): boolean;          // 人が乗って操作できる
export function hasCommunication(v: Vessel): boolean;    // 通信モジュールを持つ
export function hasAutopilotUnit(v: Vessel): boolean;    // 自動操縦装置を持つ
export function hasBaseModule(v: Vessel): boolean;       // 格納・倉庫・生産ができる
export function hasEngine(v: Vessel): boolean;           // 主機を持つ

// 無人での計画実行は、装置と通信圏の両方を要する
export function canAutopilot(v: Vessel, coverage: CoverageQuery): boolean;
export function isOperable(v: Vessel, coverage: CoverageQuery): boolean;
```

`isOperable` は `hasCockpit || canAutopilot(...)` である。操作対象に選べるのはこれを満たす機体である。基地の機能を開けるのは `hasBaseModule` を満たす機体である。

`canAutopilot` が通信圏の問い合わせを引数に取るのは、**同じ機体が場所によって自動操縦できたりできなかったりする**ためである。能力は搭載要素だけでは決まらない。詳細は §16 に置く。

### 5-2. `Vessel` が持つもの

| フィールド | 内容 |
|---|---|
| `assembly: VesselAssembly \| null` | ツリーと、その上に配置された搭載要素。敵艦とコンテナは `null` |
| `massProperties: MassProperties` | 乾燥質量・搭載質量・重心・慣性テンソル・主軸投影面積。`assembly` から導出するか、直接与えられる |
| `collisionShape: readonly HullCapsule[]` | 接触形状（§11）。`assembly` から導出する |
| `propellant: PropellantStore` | 推進剤の種別ごとの残量 |
| `power: PowerSystem` | 発電・蓄電・消費 |
| `thermal: ThermalSystem` | 熱収支 |
| `propulsion: PropulsionSystem` | 主機・並進RCS（§14） |
| `attitudeControl: AttitudeControlSystem` | 姿勢トルクの配分（§14-2） |
| `parts: AnyPart[]` | 搭載要素。HPと性能の唯一の源 |
| `plan: Plan` / `planExecutor: PlanExecutor` | 軌道計画とその自動実行 |

`EntityManager` は `vessels: Vessel[]` という単一の配列を持つ。操作対象は `ActivePlayerController` が `Vessel | null` として保持する。

### 5-3. 敵艦とコンテナの質量特性

敵艦とコンテナはツリーを持たず、設計データも持たない。`MassProperties`（質量・重心・慣性テンソル・投影面積）をコンストラクタで直接受け取り、それをそのまま置く。接触形状は単一のカプセルとする。敵艦の慣性テンソルの種別ごとの値と表示倍率・当たり半径は、現在の実装の値をそのまま引き継ぐ。

この経路は暫定ではなく、`Vessel` の恒久的な2つ目の入口である。

### 5-4. 基地の格納機構

現在 `Base` が持つハッチ位置・ハッチ法線・格納スロット・最大格納数は、基地モジュール部品の性能値として移す。

**ドッキングポートによる機体の結合は本文書では実装しない。**したがって格納の判定は現在のまま「一定距離内かつ相対速度が小さい」とし、その距離と相対速度の閾値、およびハッチの位置と法線を、機体の定数からではなく基地モジュール部品から読む形に置き換える。判定の内容そのものは変えない。統合の途中で格納が動かなくなることのないよう、この置き換えは `Vessel` 統合と同じ変更セットで行う。

### 5-5. 表示種別の導出

マップ上の対象種別は、`hasBaseModule` と所属勢力の2軸から導く。

| 条件 | 種別 |
|---|---|
| 基地モジュールを持つ | `'base'` |
| 基地モジュールを持たず、自勢力 | `'player'` |
| 敵対勢力 | `'ship'` |

コンテナと弾薬ピックアップは、いずれも `'ammo'` と同じ「拾える物体」の系統として、この導出の外に置く。表示ポリシーが持つ4トグルはそのまま使える。

### 5-6. 配列統合の波及範囲

`vessels` 1本への統合は、配列構成に依存する以下すべてに波及する。

**`EntityManager`**

`all()` / `otherEntities()` / `attractors()` / `sync()` / `syncPlayers()` / `updatePlayers()` / `cleanup()` / `prune()` / `applyVisibility()` / `perfCounts()` / `findPlayer()` / `findEnemy()` / `parkPlayer()` / `removePlayer()` / `addPlayer()` / `addEnemy()` / `addBase()` / `updateBaseEquatorNodes()` / `syncEquatorNodes()`

**その他**

| 対象 | 波及の内容 |
|---|---|
| `Simulator.stepAttitudes` | 5配列の走査を `vessels` を含む構成に改める |
| `ActivePlayerController` | 保持する型と、`vessels` に対する生存掃引・引き継ぎ |
| `Targeter` の `CombatTarget` | 2クラスの合併型を `Vessel` 単一に改める |
| `NavTarget.resolveEntity` | 敵・自艦・基地の順に引く3段の探索を単一の探索に改める |
| `CreativeStage.placeObject` | 4種の作り分けを、積む部品の違いに改める |

## 6. 搭載要素

### 6-1. 一覧

搭載要素は、機体の外側に露出する**外装要素**と、機体の内容積を占める**内装要素**に分かれる。

**外装要素**

| 要素 | 主な性能値 |
|---|---|
| 武器 | 発射速度、1発あたりの威力、初速、給弾の要求量 |
| エンジン | 対応推進剤、サイクル、推力、比推力、全長、ジンバル可動角、ジンバル速度、絞り範囲、再着火回数、点火1回あたりの推進剤損失、連続燃焼時間の上限 |
| RCSスラスタ | 推力、対応推進剤、比推力 |
| 太陽電池パドル | 面積、発電効率、展開の可否、追尾の可否 |
| 放熱板 | 面積、放熱効率、展開の可否 |
| 戦闘用シールド | 遮蔽する立体角、耐弾性能、可動の可否 |
| 熱シールド | 遮蔽する立体角、アブレータ質量、単位入熱あたりの消耗 |
| 通信モジュール | 到達距離、帯域、消費電力、指向の可否 |
| ロボットアーム | 到達距離、可搬質量 |
| ドッキングポート | 適合クラス、移送速度 |
| コンテナ接合部 | 保持できるコンテナの規格 |

**内装要素**

| 要素 | 主な性能値 |
|---|---|
| 酸化剤タンク | 対応推進剤、容積、断熱等級、要求与圧、材料 |
| 還元剤タンク | 対応推進剤、容積、断熱等級、要求与圧、材料 |
| 加圧ガスタンク（球状） | 容積、耐圧、充填ガス種別 |
| RCS推進剤タンク | 対応推進剤、容積、材料 |
| 水タンク | 容積、遮蔽の厚み |
| バッテリー | 蓄電容量、最大出力 |
| 燃料電池 | 定格出力、効率、水素と酸素の消費、再生の可否 |
| 原子力電池 | 定格出力、半減期による減衰、質量 |
| コックピット | 搭乗人数、必要与圧容積 |
| 自動操縦装置 | 計画実行の可否、消費電力 |
| 弾薬庫 | 収納できる弾薬の数 |
| 弾薬 | 対応する武器、1つあたりの発数、質量 |
| 配管 | 口径、対応推進剤、最大流量 |
| ペイロード倉庫 | 内容積、最大積載質量、開閉の可否 |
| フライホイール | 最大トルク、最大蓄積角運動量、消費電力 |
| 磁気トルカ | 最大磁気モーメント、消費電力 |
| 基地モジュール | 格納数、倉庫容量、生産設備、ハッチ位置、ハッチ法線、格納スロット |
| 農場 | 栽培面積、光源の種別、消費電力、廃熱 |
| 生命維持装置 | 処理できる人数、消費電力、消耗品の消費、廃熱 |
| ドック | 収容数、収容できる機体の最大寸法 |

### 6-2. 弾薬を弾薬庫と分ける理由

**弾薬庫は容器であり、弾薬はその中身である。**両者を1つの部品にすると、「弾薬庫を積めば弾が湧く」ことになり、補給という行為が成立しない。

弾薬は生産され、輸送され、消費される物として扱う。**将来、弾薬の補給をプレイヤーが打ち上げた補給機によるものだけに限る**ため、この分離を最初から持つ。本文書の段階では現在の自動補給を残すが、補給される対象は「弾薬庫」ではなく「弾薬」になる。

### 6-3. 電源の3種

| 種別 | 特性 | 向く場面 |
|---|---|---|
| バッテリー | 蓄えるだけで生まない。充放電の効率が高く、出力が大きい | 日陰の短い軌道、燃焼中の一時的な大電力 |
| 燃料電池 | 水素と酸素から電力と水を作る。効率およそ 60%。電力があれば水を電気分解して**再生**できる | 長い日陰。月の夜。永久影のクレーター |
| 原子力電池 | 放射性同位体の崩壊熱を電力に変える。比出力は小さい（およそ 5 W/kg）が、日射も燃料補給も要らず、半減期に従って緩やかに減衰するだけ | 遠方の無人機、通信衛星、太陽から遠い領域 |

**再生型の燃料電池は、実質的に大容量のバッテリーとして働く。**同じ蓄電量ならバッテリーより軽いが、往復の効率が低く、水素と酸素を貯めるタンクの容積を食う。月面の永久影のように日照が長時間途切れる場所では、この差が効く。

### 6-4. シールドの2種

**戦闘用シールド**は、指定した方向からの被弾を受け止める。接触形状のカプセルの前に立ち、被弾したときに背後の搭載要素の代わりに損傷を受ける。可動のものは向きを変えられ、電力を消費する。**戦闘艦艇はエンジンとタンクを守る必要があるため、推力軸の後方と、タンクを収めたエッジの側面に置くことになる。**

**熱シールド**は、アブレータを消耗して大気圏突入と大気の通過から機体を守る。入熱に応じてアブレータが減り、尽きれば機能を失う。

**熱シールドは大気掠めによる減速を可能にする。**大気の上層をかすめて通過すれば、推進剤を使わずに速度を落とし、遠地点を下げられる。高軌道から低軌道への遷移、および惑星への到達で捕獲の Δv をほぼ不要にする。これは推進剤の節約として大きく、**熱シールドを積むかどうかが軌道計画の選択肢を変える。**

### 6-5. 性能値の合成

機体の性能は、積んでいる搭載要素の性能値から求める。

| 機体の性能 | 求め方 |
|---|---|
| 総推力 | 主機の推力の合計 |
| 総トルク | 姿勢トルクの配分（§14-2）が、要求方向ごとに実際に出せる最大値として答える |
| 推進剤容量 | 推進剤の種別ごとに、対応するタンクの容積と密度の積の合計 |
| 発電量 | 太陽電池パドル・燃料電池・原子力電池の出力の合計 |
| 蓄電容量 | バッテリーの容量と、再生型燃料電池の反応物の量の合計 |
| 放熱能力 | 放熱板の面積と効率から求めた値の合計 |
| 廃熱 | 全搭載要素の消費電力の合計。**電力は最終的にすべて熱になる** |
| 装甲 | 各要素のHPの合計。コックピットまたは主要構造を失った時点で0とする |

**廃熱を明示的に持つ。**消費電力の合計と放熱能力の差が、機体の熱収支の余裕である。電照農場のように大電力を使う区画は、そのまま同じだけの放熱面を要求する。

総トルクを単純な合計としないのは、アクチュエータの配置が設計ごとに変わるためである。同じ推力のスラスタでも、モーメントアームの向きによって出せるトルクの方向が異なり、方向によっては打ち消し合う。したがって「この機体のトルクはいくつか」という問いには、方向を指定しない限り答えがない。

推進剤の残量は `PropellantStore` が推進剤の種別ごとに保持し、タンクの容積の合計が上限である。どのタンクから減るかは区別しない。

## 7. 断面

### 7-1. 定義

断面は、1つ以上の**基本断面**を面で貼り合わせた複合体である。

```ts
// src/game/vessel/cross-section.ts
export type PrimitiveShape =
  | { kind: 'circle';   radius: number; branchCount: 2 | 3 | 4 | 5 | 6 }
  | { kind: 'ellipse';  majorRadius: number; minorRadius: number }
  | { kind: 'polygon';  sides: 3 | 4 | 5 | 6 | 8; radius: number }
  | { kind: 'notched';  sides: 6 | 8; radius: number };  // 辺長が 1:2 で交互する切り欠き型

export interface SectionPrimitive {
  readonly id: string;
  readonly shape: PrimitiveShape;
  readonly phaseAngle: number;                      // この基本断面の回転位相 [rad]
  readonly attachment: PrimitiveAttachment | null;  // null は複合体の根
}

export interface PrimitiveAttachment {
  readonly parentId: string;            // 貼り付け先の基本断面
  readonly parentFaceIndex: number;     // 貼り付け先のどの辺に付けるか
  readonly childFaceIndex: number;      // 自分のどの辺を貼り付けるか
}

export interface CrossSection {
  readonly primitives: readonly SectionPrimitive[];
}
```

- 複合体は木構造である。各基本断面は、親の1つの辺に、自分の1つの辺を重ねて貼り付ける。
- 貼り付ける2つの辺は長さが等しくなければならない。等しくない場合は不正な断面とする。
- 貼り合わせ面を共有するため、基本断面同士は重ならない。したがって複合断面の面積は基本断面の面積の和であり、断面二次モーメントは平行軸の定理で合成した和である。
- 円と楕円は辺を持たないため、複合体の根としてのみ使える。子として貼り付けることはできない。

例として、四角形断面の一辺に三角形断面を貼り付けると、五角形の家型の断面になる。四角形の対辺2つに三角形を貼り付ければ、六角形の紡錘型になる。八角形の複数の辺に四角形を貼り付ければ、突起を持つ断面になる。

### 7-2. 基本断面の形状

**すべての寸法パラメータは 0.25 メートル単位である**（直径にして 0.5 メートル単位）。

| 形状 | 寸法パラメータ | 側面の口の数 | 口の方向 |
|---|---|---|---|
| 円 | 半径 | 2・3・4・5・6 から選ぶ | 360度を分岐数で等分した方向 |
| 楕円 | 長半径・短半径 | 2 | 長軸の正負方向 |
| 正三角形 | 外接円半径 | 3 | 各辺の外向き法線 |
| 正方形 | 外接円半径 | 4 | 各辺の外向き法線 |
| 正五角形 | 外接円半径 | 5 | 各辺の外向き法線 |
| 正六角形 | 外接円半径 | 6 | 各辺の外向き法線 |
| 正八角形 | 外接円半径 | 8 | 各辺の外向き法線 |
| 切り欠き六角形 | 外接円半径 | 6 | 各辺の外向き法線 |
| 切り欠き八角形 | 外接円半径 | 8 | 各辺の外向き法線 |

**切り欠き型** — 正多角形の辺の長さがすべて等しいのに対し、切り欠き型は長い辺と短い辺が1対2の比で交互に並ぶ。

- **切り欠き八角形** — 正方形の4つの角を切り落とした形である。長さ2の辺が4つと、長さ1の辺が4つを持つ。長い辺の中点に大きな面を確保しつつ、角の張り出しを抑えられる。
- **切り欠き六角形** — 正三角形の3つの角を切り落とした形である。長さ2の辺が3つと、長さ1の辺が3つを持つ。

切り欠き型は、正多角形より広い平面を確保しながら外接円半径を抑えられるため、太陽電池パドルや放熱板のような広い取り付け面を要する要素を並べるのに適する。

### 7-3. 側面の口の大きさ

側面の口は、辺の方向（周方向）と軸方向が張る矩形である。

- **周方向の寸法** — その辺の長さそのもの。
- **軸方向の寸法** — 母断面の外接円半径に `PORT_WIDTH_RATIO`（既定 1.0）を掛けた値。大きな断面には大きな分岐が付けられる。

分岐するエッジの相手側の断面は、その外接円の直径がこの矩形の両方の寸法以下でなければならない。収まらない場合は不正とする。

隣接する辺の口同士は干渉してはならない。多角形では辺が離れているため通常は干渉しないが、円の分岐数が多く口の幅が広い場合には、切り落とす弓形が重なりうる。これも不正とする。

## 8. ツリー

```ts
// src/game/vessel/tree.ts
export interface TreeNode {
  readonly id: string;
  readonly pos: Vec3;              // 船体ローカル座標 [m]
  readonly section: CrossSection;
  readonly axis: Vec3;             // 断面の法線（ツリーの進行方向）
  readonly phaseAngle: number;     // 断面全体の回転位相 [rad]

export type EdgeKind =
  | { kind: 'hull' }                                   // 外皮を作る。内側が内容積になる
  | { kind: 'truss'; sectionSize: number }             // 外皮を作らない構造部材
  | { kind: 'decoupler'; separationImpulse: number };  // 外皮を作らず、切り離せる
```

ツリーはグラフであり、**閉じた構造を含んでよい**。三角形や梯子状に組めば扁平な機体になる。

`decoupler` エッジは、分離可能な境界を表す。本文書ではエッジの種別として存在し、外皮を作らないことのみを扱う。分離の動作は第2巻が定める。

### 8-1. トラス

トラスは外皮を作らない構造部材である。軽く、剛性が高く、内容積を持たない。

**トラスには外装要素を軸に沿った任意の位置に取り付けられる。**取り付け位置は、エッジの始点からの距離（0.5 メートル単位）と、軸まわりの角度で指定する。

- **大型の太陽電池パドル**と**大型の放熱板**は、トラスに取り付ける。外皮のノードの接続口は数が限られており、大きな面を何枚も並べられない。トラスは長さのぶんだけ取り付け位置を持つため、面積を稼げる。
- **ロボットアーム**もトラスに取り付ける。到達範囲がトラスの長さに乗る。
- RCSスラスタもトラス上に置ける。重心から遠い位置に置けるため、同じ推力で大きなトルクが得られる。

トラスの質量は、断面の大きさ（`sectionSize`）と長さから求める。

**トラスは完全剛体として扱う。**曲げ剛性・撓み・振動・座屈は計算しない。長いトラスの先に重い放熱板を付けても撓まず、機体は1つの剛体として姿勢積分される。断面の大きさと長さは、質量と慣性テンソルにのみ効く。

**機体が1つの剛体であることは、この巻の姿勢積分の前提である。**索で結ばれた2つの質量が共通重心のまわりを回る系や、角速度の異なる回転部と非回転部を持つ機体は、単一の姿勢と単一の慣性テンソルでは表せない。そうした構造を扱うときは、姿勢の表現を拡張することになる。

### 8-2. 接続口のローカル座標系

各接続口は、その口に固有のローカル座標系を持つ。

- **原点** — 口の平面の中心
- **+Z 軸** — 口の平面の外向き法線
- **+Y 軸** — 口の基準ロール方向。軸方向の口では断面の回転位相が決め、側面の口ではその辺に沿う方向とする
- **+X 軸** — 右手系で決まる

外装の搭載要素は、この座標系に取り付く。**可動部を持つ要素（放熱板の折り畳み、太陽電池パドルの回転と追尾、シールドの展開、武装の俯仰、ロボットアームの関節）は、すべてこの座標系を基準に動く。**取り付け位置を固定座標で持つ要素は存在しない。

弾薬ベルトは武装に付属する内装要素であり、武装を取り付けたノードの接続口の座標系から垂れる。

### 8-3. 外装要素の取り付け位置

外装要素は3つの場所に取り付けられる。

```ts
export type MountPoint =
  | { kind: 'port'; nodeId: string; port: PortRef }                        // ノードの接続口
  | { kind: 'surface'; edgeId: string; along: number; around: number }     // hull エッジの外表面
  | { kind: 'truss'; edgeId: string; along: number; around: number };      // トラス上
```

- **接続口** — エッジと排他である。1つの口にエッジと外装要素を同時に割り当てることはできない。
- **`hull` エッジの外表面** — 軸方向の位置（始点からの距離、0.5 メートル単位）と周方向の角度で指定する。外皮の表面に取り付き、法線は外向きである。エンジンのように軸方向の推力を要するものは向かないが、**RCSスラスタ・小型の放熱板・戦闘用シールド・通信モジュールはここに置ける。**
- **トラス上** — §8-1 のとおり。

**RCSスラスタの位置はプレイヤーが決める。**外表面上のどこにでも置けるため、重心から遠い位置に置いてトルクを稼ぐ、対称に置いて並進のみを出す、といった設計判断がそのまま姿勢制御の性能に現れる。配分の計算は任意配置に対して成立する（§14-3）。

### 8-4. 内容積の連続性

**軸方向に連なるエッジ同士は断面を共有するため、内容積が連続する。**同じ推進剤を収める限り、軸方向に連なる複数のエッジを1つのタンクとして扱える。

**側面から分岐するエッジの内容積は、母体の内容積と連続しない。**分岐部の付け根は母体の外皮の表面であり、分岐エッジは母体の外側から始まる。母体の内容積は分岐によって欠けることなく、そのまま残る。したがって、母体と分岐にまたがる1つのタンクは作れない。

ノード自身は面であって体積を持たない。3本以上のエッジが集まるノードでも、体積が二重に数えられることはない。

## 9. 断面の面積と断面二次モーメント

基本断面が多角形（正多角形・切り欠き型・複合体の構成要素）である場合、頂点列から以下で厳密に求める。頂点を反時計回りに `(x_i, y_i)`、`i` の次を `i+1` として、

```
cross_i = x_i·y_{i+1} − x_{i+1}·y_i
A   = (1/2)    · Σ cross_i
Cx  = (1/(6A)) · Σ (x_i + x_{i+1}) · cross_i
Cy  = (1/(6A)) · Σ (y_i + y_{i+1}) · cross_i
Ix  = (1/12)   · Σ (y_i² + y_i·y_{i+1} + y_{i+1}²) · cross_i
Iy  = (1/12)   · Σ (x_i² + x_i·x_{i+1} + x_{i+1}²) · cross_i
Ixy = (1/24)   · Σ (x_i·y_{i+1} + 2·x_i·y_i + 2·x_{i+1}·y_{i+1} + x_{i+1}·y_i) · cross_i
```

を求め、平行軸の定理で重心まわりに移す。この式は任意の単純多角形に対して厳密であり、形状ごとの個別の式を持つ必要がない。切り欠き型も、複合断面も、この1つの式で扱える。

**相乗モーメント `Ixy` は0とは限らない。** 複合断面が対称でない場合、断面の主軸は座標軸から回転する。慣性テンソルの計算では `Ixy` を必ず含める。

円と楕円は解析式で求める。

```
円（半径 r）      A = πr²,   Ix = Iy = πr⁴/4,   Ixy = 0
楕円（半径 a, b）  A = πab,   Ix = πab³/4,        Iy = πa³b/4,   Ixy = 0
```

**円に側面の口を設ける場合** — その方向の円弧を弦で切り落とし、平面を作る。切り落とされる弓形の中心角を `θ`、半径を `r` として、

```
弓形の面積        A_seg = (r²/2)·(θ − sin θ)
弓形の重心距離     d_seg = (4r·sin³(θ/2)) / (3·(θ − sin θ))
弓形の断面二次モーメント は θ の閉形式で求まる
```

を円の値から差し引く。分岐数ぶんの弓形を、それぞれの方向で差し引く。切り落とし量は §7-3 の口の幅から決まる。

```
src/physics/section-moments.ts   (純関数)
    polygonArea(vertices) -> number
    polygonCentroid(vertices) -> { x, y }
    polygonSecondMoments(vertices) -> { ix, iy, ixy }          // 重心まわり
    circleSegmentMoments(radius, halfAngle) -> { area, centroidDist, ix, iy }
    sectionMoments(section) -> { area, centroid, ix, iy, ixy }  // 複合断面全体
    sectionOutline(section, sampleCount) -> readonly Vec2[]     // ロフト用の輪郭
```

検証は `tests/physics/section-moments.test.ts` に置く。正n角形の面積と断面二次モーメントが既知の閉形式と一致すること、辺数を増やすと円の値に収束すること、切り欠き八角形が「正方形から4つの直角三角形を引いた値」と一致すること、複合断面の面積が構成要素の和と一致すること、対称な複合断面の `Ixy` が0になり非対称なものは0でないことを固定する。

## 10. 外皮の生成と立体の物理量

### 10-1. 外皮の生成

`hull` エッジは、両端のノードの断面をつないだ立体を作る。

- 両断面の輪郭を、それぞれ**120点**に等分してサンプリングする。120は3・4・5・6・8のいずれでも割り切れるため、辺数の異なる断面同士でも頂点が一対一に対応する。円と楕円も同じ120点で表す。
- **等分は弧長で行う。**円に側面の口を設けた断面は、円弧と直線が混じった輪郭になる。角度で等分すると直線部の点が疎になり、ロフトの帯の面積が不均一になる。
- 対応する頂点同士を直線で結び、側面を四角形の帯として張る。
- 両断面の回転位相が異なる場合、頂点の対応は位相差を考慮して、対応する頂点間の距離の総和が最小になる割り当てを選ぶ。これにより外皮がねじれない。
- 複合断面の場合、輪郭は複合体全体の外周である。貼り合わせ面の内側は輪郭に含まれない。

側面の口から分岐するエッジは、口の平面の上に相手側の断面を置き、そこから同じ規則でロフトする。分岐部は平面同士の突き合わせであり、本体の外皮と交差しない。

### 10-2. 立体の物理量

外皮は「断面が軸方向に線形に変化する一般化角錐台」の集まりである。

**エッジ1本の体積** — 長さ `h`、両端の断面積 `A₁` / `A₂`、中間断面の面積 `Am` として

```
V = (h/6)·(A₁ + 4·Am + A₂)
```

輪郭を線形補間するため中間断面は両端の輪郭の平均であり、`Am` はその平均輪郭の面積である。

**慣性テンソル** — 軸に沿った位置 `t ∈ [0, h]` における断面積 `A(t)`、断面二次モーメント `Ix(t)` / `Iy(t)` / `Ixy(t)`、断面重心 `C(t)` は、いずれも `t` の多項式である。したがって

```
I_axial      = ρ ∫ (Ix(t) + Iy(t)) dt
I_transverse = ρ ∫ (I(t) + A(t)·|C(t) − C_ref|²) dt
I_product    = ρ ∫ (Ixy(t) + A(t)·(...)) dt
```

はいずれも多項式の積分として閉形式で求まる。各エッジの慣性テンソルを平行軸の定理で船体重心まわりに移して合成する。

トラスは中実の棒ではないため、断面の大きさに対して質量が小さい。慣性テンソルは、断面の大きさと長さから求めた等価な細い棒として扱う。

**表面積** — 側面の帯の面積の和に、露出した端面（他のエッジが接続していない断面）を加える。

**主軸3方向の投影面積** — 空力に用いる（§11-2）。

```
src/physics/hull-loft.ts   (純関数)
    loftVolume(sectionA, sectionB, length) -> number
    loftInertia(sectionA, sectionB, length, density) -> InertiaTensor
    loftCentroid(sectionA, sectionB, length) -> number
    loftSurfaceArea(sectionA, sectionB, length) -> number
    loftProjectedArea(sectionA, sectionB, length, axis) -> number
```

検証は `tests/physics/hull-loft.test.ts` に置く。円断面の等断面ロフトが円柱の解析値と一致すること、両端の断面積が等しい角錐台の体積が `A·h` になること、L字に組んだツリーの慣性主軸が3値とも異なること（すなわちジャニベコフ効果が発生する形状であること）を固定する。

### 10-3. 外皮の肉厚と構造質量

構造の質量は、外皮の表面積と肉厚から求める。肉厚は区画ごとに決まる。

**内圧を持つ区画（推進剤タンク、加圧ガスタンク、水タンク、コックピット）** — 薄肉圧力容器の式による。内圧 `p`、断面の外接円半径 `r`、材料の許容応力 `σ`、溶接効率 `e`、安全率 `k` として

```
t = k · p · r / (σ · e)
```

**内圧を持たない区画（機器区画、貨物区画、ペイロード倉庫）** — 座屈に対する最小肉厚と、製造上の下限肉厚の大きいほうを取る。

この扱いにより、**タンクを大きくすると質量が半径に比例して増える。**内圧の高い加圧式エンジン向けのタンクは、ポンプ式向けのタンクより厚く重い。これが加圧式の単純さと引き換えになる代償として、質量の形で現れる。

材料ごとに比強度（許容応力を密度で割った値）が異なり、アルミ合金・チタン合金・炭素繊維複合材の順に軽くなる。推進剤ごとに使える材料が限られる（§15-2）ため、**推進剤の選択が材料の選択を通じて質量に効く。**

### 10-4. 質量特性の合成

```ts

  readonly centerOfMass: Vec3;       // 船体ローカル座標
```

搭載要素はそれぞれの取り付け位置に質点として置く。推進剤はそれを収めるエッジの内容積の重心に置く。推進剤が減れば重心と慣性テンソルが変わるため、質量が一定量変化したときに再計算する。

## 11. 接触形状と空力特性

### 11-1. 接触形状

機体の剛体接触と被弾は、**ツリーの各エッジに対応するカプセルの集合**で判定する。

```ts
// src/game/vessel/collision-shape.ts
export interface HullCapsule {
  readonly edgeId: string;
  readonly a: Vec3;        // 船体ローカル座標
  readonly b: Vec3;
  readonly radius: number; // 両端の断面の外接円半径の平均。トラスは断面の大きさ
}
export function deriveCapsules(tree: VesselTree): readonly HullCapsule[];
```

- `hull` エッジと `truss` エッジがカプセルを持つ。`decoupler` エッジは分離機構そのものであり、両端のカプセルが接するため独自のカプセルを持たない。
- `GameEntity.radius` は**外接球の半径**として残す。空間格子による広域の絞り込みと、天体表面への到達判定はこの球で行う。狭域の判定だけがカプセルになる。
- 判定は、カプセル対球（弾丸、破片、薬莢）とカプセル対カプセル（機体同士）の2種である。既存の掃引球の判定を掃引カプセルに拡張する。

```
src/physics/capsule-contact.ts   (純関数)
    sweptCapsuleSphereToi(capsule, sphereStart, sphereEnd, sphereRadius) -> number | null
    sweptCapsuleCapsuleToi(a0, a1, b0, b1) -> number | null
    closestPointsOnSegments(p0, p1, q0, q1) -> { s: number; t: number }
```

**被弾したカプセルから損傷する搭載要素が決まる。**そのエッジの内容積に収めた内装要素と、そのエッジに取り付けた外装要素が候補になる。機体のどこに当たったかが、何が壊れるかに直結する。

**戦闘用シールドは、この判定の前に立つ。**被弾の方向がシールドの遮蔽する立体角の内側であれば、シールドが先に損傷を受け、背後の要素は守られる。シールドを失えば背後がむき出しになる。

### 11-2. 空力特性

抗力は自由分子流域（低軌道の高度）で働く。この領域では**抗力係数は形状にほとんど依存せず、`Cd ≈ 2.2` である。**形状の差は投影面積として現れる。

したがって `Cd` は 2.2 の定数とし、投影面積のみを形状と姿勢から求める。速度方向の単位ベクトルを機体座標系に移した `v̂` に対して、

```
A(v̂) = |v̂·x̂|·A_x + |v̂·ŷ|·A_y + |v̂·ẑ|·A_z
bcInv = Cd · A(v̂) / m
```

`A_x` / `A_y` / `A_z` は主軸3方向の投影面積であり、設計時に一度求める。この式は直方体に対して厳密であり、それ以外の形状に対しても十分な近似である。

**`bcInv` は姿勢に依存する値になる。**細長い機体を横に向ければ抗力が数倍になり、進行方向に向ければ最小になる。これは再突入と軌道の減衰に直接効き、姿勢を保つことに意味を与える。

同じ投影面積が太陽輻射圧の係数 `srpCoeff = C_R · A(ŝ) / m` にも用いられる。

### 11-3. 加熱と熱シールド

加熱率と動圧の閾値は、**搭載した熱シールドから求める。**熱シールドを持たない機体は現在と同じ閾値を持ち、熱シールドを持つ機体はその遮蔽する立体角の内側からの入熱に耐える。

- 入熱に応じてアブレータが減る。減った量は質量から差し引かれる。
- アブレータが尽きた熱シールドは機能を失い、閾値は熱シールドなしの値に戻る。
- 熱シールドの向きが速度方向から外れると、遮蔽されない方向から加熱を受ける。**再突入の姿勢制御に意味が生まれる。**

**抗力係数を形状から導出すると、大気減衰と再突入のタイミングが現在と変わる。**この変更と熱シールドの導入は同じ段階で行う。片方だけを先に入れると、抗力は増えたのに耐熱は変わらないという状態が続く。

| 収容物 | 実効容積の係数 | 備考 |

| 極低温タンク（液体水素・液体酸素・液体メタン・シラン） | 0.85 | 断熱材のぶん減る |

| RCS推進剤タンク | 0.95 | |
| 水タンク | 0.95 | |

固体モーターはタンクではなく、エッジそのものである。ケースが構造材を兼ねるため、固体モーターを割り当てたエッジは `hull` エッジ1本がモーター1基に対応する。

## 13. 描画

```

```

エッジごとに120分割のロフト帯を生成し、露出した端面を蓋で閉じ、全体を1つのジオメトリに結合する。トラスは断面の大きさに応じた骨組みとして描く。生成は形状が変わったときに1度だけ行う。遠距離では分割数を下げた別のジオメトリを用いる。

**自機のモデルは事前生成アセットからロフト生成に置き換える。**敵艦・破片・薬莢は事前生成アセットのままとする。

## 14. 推進系と姿勢制御系

### 14-1. 4つのシステムの役割

| システム | 役割 | 消費 | 比推力 | 特性 |
|---|---|---|---|---|
| **主機（EngineBank）** | 軌道変更のための大きな Δv | 液体・固体・ハイブリッド推進剤 | 260〜450 s | 推力大。始動と停止にコストがある。固体は停止も再着火もできない |
| **並進RCS（TranslationRcs）** | 近接機動・姿勢制御の補助 | 単推進剤または冷ガス | 70〜230 s | 推力小。応答は即時。出せる方向はスラスタの配置で決まる |
| **フライホイール（ReactionWheels）** | 姿勢制御のみ | 電力のみ | — | トルク小・連続。**角運動量が飽和する** |
| **磁気トルカ（MagneticTorquers）** | 姿勢制御とアンローディング | 電力のみ（微小） | — | トルク極小。**地球磁場のある領域でしか使えない。磁場に平行な軸まわりのトルクは出せない** |

### 14-2. 姿勢トルクの配分

姿勢トルクを要求する主体は、手動操作と自動操縦の2つである。両者は `AttitudeControlSystem` に要求を出し、どのアクチュエータが出すかはそこが決める。

配分は「推進剤を消費しないものを先に使い、足りないぶんを推進剤で埋める」という3段の優先順位で行う。

1. **磁気トルカ** — 推進剤も、ごくわずかな電力しか消費しない。ただし出せるトルクは τ = m × B（m は磁気モーメント、B は地球磁場）であり、B に平行な成分は原理的に出せない。地球磁場のない領域では何も出せない。
2. **フライホイール** — 電力のみを消費する。出せる条件は、そのホイールの最大トルクを超えないことと、蓄積角運動量 h が上限 hMax に達していないことの両方である。ホイールが τ_wheel を出すと、反作用として角運動量が `h += -τ_wheel · dt` だけ溜まる。
3. **RCSスラスタ** — 上の2つで出しきれなかったぶんを出す。推進剤を消費する。

`|h|` が hMax の既定割合を超えると**アンローディング**を行う。外部トルクを与えながらホイールを減速し、h を外部に捨てる。外部トルクは磁気トルカを優先し、磁場が足りないぶんだけRCSが補う。自動実行を既定とし、手動実行のボタンをHUDに置く。

この規則により、地球低軌道では姿勢制御がほぼ無料で成立し、月周辺やラグランジュ点ではアンローディングのたびにRCS推進剤を消費する。活動する領域によって運用の性格が変わる。

### 14-3. 任意配置のアクチュエータに対する配分

RCSスラスタの取り付け位置 r_k と噴射方向 e_k は設計ごとに決まる。推力 F_k で噴いたとき、そのスラスタが機体に与える力は −F_k·e_k、重心まわりのトルクは τ_k = r_k × (−F_k·e_k) である。

要求トルクと要求並進推力を同時に満たす推力の組み合わせ (F_1, …, F_n) は、一般に**劣決定**である。スラスタが6基を超える機体では解が無数にあり、6基未満または配置が偏った機体では厳密解が存在しない。

したがって配分は、**減衰最小二乗**（Tikhonov 正則化した擬似逆行列）で解く。各スラスタの寄与を列に持つ 6×n の行列 A に対し、要求ベクトル b を満たす F を

```
F = Aᵀ (A Aᵀ + λI)⁻¹ b
```

として求める。正則化項 λ は、要求を厳密に満たすことより推力の総量を抑えることを優先する重みであり、そのまま推進剤消費を抑える働きをする。厳密解が存在しない配置でも、最も近い解が得られる。

得られた F_k は 0 以上・そのスラスタの最大推力以下にクランプする。クランプによって要求との差が残る場合、その差はそのまま出せなかったぶんとして扱う（再配分は行わない）。

```ts
// src/physics/attitude-control.ts   (純関数)
export interface TorqueRequest {
  readonly torque: Vec3;          // 要求トルク（機体座標系）
  readonly force: Vec3;           // 要求並進推力（機体座標系）
}
export interface ThrusterSpec {
  readonly position: Vec3;        // 重心からの取り付け位置 r_k
  readonly exhaust: Vec3;         // 噴射方向の単位ベクトル e_k
  readonly maxThrust: number;     // [N]
}
export interface ActuatorSet {
  readonly thrusters: readonly ThrusterSpec[];
  readonly wheels: readonly WheelSpec[];
  readonly torquers: readonly TorquerSpec[];
}
export interface Allocation {
  readonly torquerMoment: Vec3;
  readonly wheelTorque: Vec3;
  readonly thrusterLevels: readonly number[];
  readonly achievedTorque: Vec3;
  readonly achievedForce: Vec3;
  readonly powerDraw: number;
}

export function allocateTorque(
  request: TorqueRequest,
  actuators: ActuatorSet,
  wheelState: WheelState,
  magneticField: Vec3 | null,   // 機体座標系での地球磁場。磁場のない領域では null
): Allocation;

export function desaturationRequest(
  wheelState: WheelState,
  hMax: number,
): TorqueRequest | null;
```

**アクチュエータ集合は設計から導く。**RCSスラスタの位置と向きは、取り付け位置（§8-3）から決まる。固定のノズルテーブルは持たない。

### 14-4. 磁場の評価

地球磁場は双極子近似で求める。

```ts
// src/physics/geomagnetic.ts   (純関数)
export function geomagneticField(r: Vec3): Vec3;   // ECI 位置 → 磁束密度 [T]
```

双極子の軸は地球の自転軸から約 11 度傾いており、この傾きを含める。地球から離れるほど磁場は距離の3乗に反比例して弱まり、月周辺やラグランジュ点では磁気トルカが実質的に使えなくなる。この減衰は近似式がそのまま与えるため、「使える領域」を別途定義する必要はない。

### 14-5. 重力傾斜トルク

全機体に重力傾斜トルクを適用する。

```ts
// src/physics/gravity-gradient.ts   (純関数)
export function gravityGradientTorque(
  rRel: Vec3, mu: number, inertia: Inertia, q: Quat,
): Vec3;
```

トルクは τ_gg = 3·(μ/r³)·(r̂ × (I·r̂)) である。慣性主軸が等しい機体ではトルクは 0 になり、細長い機体ほど強く、長軸を天底方向に向けようとする。

`Simulator.stepAttitudes` の姿勢積分に外部トルクとして加える。重力源はその位置で最も強く引く天体1つとする。

慣性テンソルを形状から導出する以上、この効果は形状の帰結として現れる。細長い機体を設計すれば、放っておくと天底を向く。姿勢を保つには姿勢制御系が常に働き続けることになり、その消費が低軌道での運用に効く。

### 14-6. 並進推力の選択

- 要求方向が主機の推力軸と一致し、要求の大きさがRCSの最大推力を超える場合は主機を使う。
- それ以外はRCSを使う。
- 要求の大きさが主機の絞り下限を下回る場合もRCSを使う（§14-8）。
- プレイヤーはHUDで「主機を使わない」「主機のみ」を明示的に選べる。

### 14-7. 推力軸と重心のずれ

主機の推力軸が機体重心を通らない場合、その差からトルクが生じる。この効果は正しく計算する。

ジンバル機構を持つ主機は、ずれを打ち消す方向に首を振る。ただしジンバルには可動角に加えて**ジンバル速度**の上限があり、速い姿勢変化には追従できない。追従しきれないぶんと、可動角で打ち消しきれないぶんは `AttitudeControlSystem` が補償する。ジンバルを持たない主機のずれは補償されず、機体が回る。

**コンテナを非対称に積むと同じことが起きる。**接合部の位置がそのまま重心のずれになる。

### 14-8. スロットル操作

主機の出力は**絞り率 0〜100% の連続値**で指定する。加速度による段階指定は持たない。機体の質量と積んだエンジンによって同じ絞り率でも加速度は変わり、燃焼中は質量が減るぶん加速度が上がる。

キー `[1]` 〜 `[4]` は絞り率のプリセット（25%・50%・75%・100%）に割り当てる。

エンジンのサイクルごとの絞り下限（§15-3）を下回る指定は下限にクランプし、HUDにその旨を表示する。下限より低い出力が要るときは、主機ではなく並進RCSを使う。

複数のサイクルのエンジンを混載した機体では、絞り下限はエンジンごとに異なる。下限を下回る絞り率を指定されたエンジンは、下限で噴くのではなく停止する。絞り率を下げていくとエンジンが1基ずつ落ちていく挙動になる。

### 14-10. 飛行中のHUD

飛行中に**推進系**パネルを置く。個別に折り畳める。主機・並進RCS・フライホイール・磁気トルカの4行を持ち、主機は絞り率と推進剤の種別ごとの残量、RCSは残量、フライホイールは蓄積角運動量と上限の比、磁気トルカは現在の磁場強度に対して出せるトルクの目安をメーターで表示する。アンローディングの手動実行ボタンをこのパネルに置く。

**フライホイールが飽和してRCSに切り替わる瞬間に、短い通知音とヒントを出す。**切り替わりは推進剤の消費が始まる瞬間であり、プレイヤーが知るべき出来事である。逆に、アンローディングが終わってフライホイールに戻る瞬間には通知しない。資源の消費が始まるほうだけを知らせる。

熱収支の余裕（§6-5 の廃熱と放熱能力の差）と、通信圏の内外（§16）も、それぞれ1行として置く。

既存のウィジェット（`src/game/hud/widgets/`）のみで構成し、生の `<button>` および `<input>` を直接書かない。

## 15. 推進剤とエンジン

### 15-1. 成分ごとの物性

**沸点と凝固点は成分ごとに定める。**推進剤のペアに対して1つの温度を与えることはできない。酸化剤と還元剤は別のタンクに入り、それぞれ別の温度帯で保たれるためである。

| 成分 | 沸点 [°C] | 凝固点 [°C] | 密度 [kg/m³] | 貯蔵 |
|---|---|---|---|---|
| 液体水素 | −252.9 | −259.1 | 71 | 極低温 |
| 液体酸素 | −183.0 | −218.8 | 1141 | 極低温 |
| 液体メタン | −161.5 | −182.5 | 423 | 極低温 |
| シラン | −111.9 | −185 | 680 | 極低温（要求は緩い） |
| 亜酸化窒素 | −88.5 | −90.8 | 1220 | 加圧液化 |
| 四酸化二窒素 | 21.2 | −11.2 | 1443 | 常温 |
| モノメチルヒドラジン | 87.5 | −52.4 | 875 | 常温 |
| ヒドラジン | 113.5 | 1.4 | 1010 | 常温 |
| 過酸化水素（98%） | 150.2 | −0.4 | 1450 | 常温 |
| ケロシン | 175〜300 | −47 | 810 | 常温 |
| 窒素 | −195.8 | −210.0 | 高圧気体 | 高圧 |
| ヘリウム | −268.9 | — | 高圧気体 | 高圧 |

**極低温の成分は沸点が管理の対象になる。**沸点を超えれば蒸発し、残量が減る。断熱と遮蔽で損失を抑える。

**常温貯蔵性の成分は凝固点が管理の対象になる。**凝固点を下回れば凍る。タンク・バルブ・配管をヒータで加熱し、そのぶんの電力を消費し続ける。日陰の長い軌道では、ヒドラジン（凝固点 1.4°C）と過酸化水素（−0.4°C）は特に危うい。

**この対比が、推進剤の選択を電力系の設計と結び付ける。**極低温は日射で蒸発するが凍らず、常温貯蔵性は蒸発しないが凍る。

### 15-2. 推進剤の組み合わせ

比推力は真空値である。平均密度は混合比で重み付けした値である。日あたり損失率は日射のある軌道での標準的な断熱を前提とした蒸発損失であり、断熱等級と遮蔽で低減できる。

**液体（酸化剤と還元剤のペア）**

| ペア | 真空比推力 [s] | 混合比 O/F | 平均密度 [kg/m³] | 日あたり損失 [%/day] | タンク材料の要求 | 毒性 |
|---|---|---|---|---|---|---|
| 液体酸素 / 液体水素 | 450 | 5.5 | 360 | 1.5 | 水素脆化に耐える材料。**アルミ合金**または特定のステンレス | なし |
| 液体酸素 / 液体メタン | 370 | 3.5 | 830 | 0.4 | 制約なし | なし |
| 液体酸素 / シラン | 265 | 1.7 | 910 | 0.4 | 制約なし | シランは自然発火性 |
| 四酸化二窒素 / モノメチルヒドラジン | 320 | 1.65 | 1200 | 0 | **チタン不可**（応力腐食割れ）。ステンレスまたはアルミ合金 | 強い。専用設備を要する |
| 過酸化水素 / ケロシン | 310 | 7.0 | 1290 | 0 | 高純度アルミまたは特定のステンレスのみ | 弱い |

**混合比はいずれも化学量論比より燃料過多側にある。**燃焼温度を抑え、平均分子量を下げるためである。液体酸素／シランの化学量論比は `SiH₄ + 2 O₂ → SiO₂ + 2 H₂O` から 2.0 であり、実用値の 1.7 はそのわずかに燃料過多側にあたる。

**単推進剤（RCS向け）**

| 推進剤 | 比推力 [s] | 密度 [kg/m³] | タンク材料の要求 | 毒性 | 特性 |
|---|---|---|---|---|---|
| ヒドラジン（触媒分解） | 230 | 1010 | 制約なし | 強い | 触媒床が累積噴射時間で劣化する |
| 過酸化水素（触媒分解） | 160 | 1450 | 高純度アルミまたは特定のステンレスのみ | 弱い | 無毒に近い |
| ヘリウム冷ガス | 165 | 高圧貯蔵 | 高圧に耐える材料 | なし | 加圧ガスをそのまま使える |
| 窒素冷ガス | 70 | 高圧貯蔵 | 高圧に耐える材料 | なし | 最も単純。安価だが性能が低い |

**固体・ハイブリッド**

| 種別 | 比推力 [s] | 密度 [kg/m³] | 毒性 | 特性 |
|---|---|---|---|---|
| 固体（過塩素酸アンモニウム + 末端水酸基ポリブタジエン + アルミ粉末） | 265 | 1800 | 燃焼生成物に塩化水素 | 点火後は停止も絞りも再点火もできない |
| ハイブリッド（ABS樹脂 + 亜酸化窒素） | 260 | 1100 | なし | **自己加圧できる**。絞れる・停止できる・再点火できる |
| ハイブリッド（ABS樹脂 + 液体酸素） | 305 | 1000 | なし | 絞れる・停止できる・再点火できる |

固体推進剤の燃料成分はアルミ粉末であり、酸化アルミニウムはその燃焼生成物である。ABS樹脂はハイブリッドロケットの固体燃料側である。

**シランの位置づけ** — 液体酸素／シランの比推力が液体酸素／メタンより大きく劣るのは、燃焼生成物である二酸化ケイ素が燃焼室とノズルの温度で凝縮相であり、膨張過程で仕事に寄与しないためである。固体推進剤のアルミナと同じ機構である。同じ理由で二酸化ケイ素がノズルスロートに堆積するため、**連続燃焼時間に上限がある**（§15-3）。

### 15-3. タンクの加圧

推進剤をエンジンへ押し出すには、タンクを加圧する必要がある。方式は3つある。

| 方式 | 対象 | 内容 |
|---|---|---|
| **自己加圧** | 極低温推進剤、亜酸化窒素 | 蒸発した推進剤自身の気体でタンクを加圧する。加圧ガスを積む必要がない代わりに、蒸発損失が増える。**極低温推進剤の既定とする** |
| **窒素加圧** | 常温貯蔵性推進剤 | 窒素を高圧で積む。極低温推進剤には使えない（液体酸素の温度で液化するため） |
| **ヘリウム加圧** | 全般 | 必要質量が窒素の約7分の1で済む。最も軽い |

**ヘリウムは調達が難しい。**地球では天然ガスに伴って産出するが、月と小惑星には鉱床として存在しない。月のレゴリスには太陽風起源のヘリウムが吸着しており、加熱すれば取り出せるものの、濃度は1トンあたり数グラムから数十グラムの桁であり、**得られる量は限られる。**大量に得られるのは木星の大気に到達してからである。

したがって序盤の機体は自己加圧と窒素加圧で組むことになり、**わずかに手に入るヘリウムをどの機体に使うか**が判断になる。全機体をヘリウム加圧にできるのは進行の後半である。

自己加圧は加圧ガスの質量をまるごと省けるが、蒸発損失が増えるため長期の待機には向かない。窒素は安価だが重く、大きなタンクには効く。この3つの選択が、推進剤の選択と貯蔵期間の要求から決まる。

### 15-4. エンジンの型式

エンジンは「サイクル（供給方式）」と「対応推進剤」の組で定義する。

| サイクル | 比推力係数 | 推力重量比 | 要求与圧 [MPa] | 絞り範囲 | 再着火 | 連続燃焼時間の上限 | 特徴 |
|---|---|---|---|---|---|---|---|
| 加圧式 | 0.95 | 低 | 2〜3 | 40〜100% | 無制限 | あり（アブレーティブ冷却） | 構造が単純で信頼性が高い。タンクを高圧に耐える厚さにする必要があり、タンク質量と加圧ガスの消費が増える |
| 電気ポンプ式 | 0.98 | 中 | 0.2〜0.4 | 30〜100% | 無制限 | なし | 電力を消費する。バッテリー容量が燃焼時間を制限する |
| ガス発生器サイクル | 1.00 | 高 | 0.2〜0.4 | 60〜100% | 数回 | なし | 標準的な性能 |
| 段階燃焼サイクル | 1.04 | 高 | 0.2〜0.4 | 50〜100% | 数回 | なし | 比推力が最も高い。エンジン質量と製造の要求が大きい |
| エキスパンダーサイクル | 1.03 | 低 | 0.2〜0.4 | 30〜100% | 無制限 | なし | **対応推進剤は極低温のみ。**再生冷却で受け取れる熱量が推力の上限を決め、おおよそ 300 kN を超えられない |
| 固体モーター | 1.00 | 最高 | 不要 | 不可 | 不可 | あり（グレイン量で決まる） | 点火後は停止できない。配管も加圧も要らない |
| ハイブリッドモーター | 1.00 | 中 | 中 | 20〜100% | 無制限 | なし | 酸化剤のみタンクに持つ |

要求与圧の 2〜3 MPa と 0.2〜0.4 MPa の10倍の差が、そのまま加圧ガスの消費量の差になる。加圧式は構造が単純だが、その単純さの代償を加圧ガスタンクの容積と質量で払う。

**エンジンの追加の性能値**

| 性能値 | 内容 |
|---|---|
| 全長 | 真空専用エンジンは膨張比を大きく取るためノズルが長く重い。比推力の高いエンジンほど長い |
| 点火1回あたりの推進剤損失 | 極低温エンジンは点火のたびに配管とポンプを冷却する必要があり、数キログラムから数十キログラムを捨てる。常温貯蔵性はほぼ0 |
| 連続燃焼時間の上限 | アブレーティブ冷却の加圧式、および凝縮相を生む推進剤（固体、液体酸素／シラン）に上限がある。上限に達したエンジンは強制的に停止し、冷却されるまで再着火できない |
| ジンバル速度 [deg/s] | 可動角に加えて速度を持つ。速い姿勢変化には追従できない |

エンジン部品の比推力は `推進剤ペアの比推力 × サイクルの比推力係数` とする。

### 15-5. ツィオルコフスキーによる燃焼計算

```
src/physics/tsiolkovsky.ts   (純関数)
    dvFor(m0, mf, isp)               // Δv = Isp·g0·ln(m0/mf)
    massAfterBurn(m0, dv, isp)
    burnTimeFor(dv, m0, thrust, isp) // 推進剤流量 = thrust/(Isp·g0)
    propellantForDv(dv, mDry, isp)
```

一定加速度を仮定すると質量比の大きい機体で点火が遅れてマニューバノードを外すため、質量変化を必ず含める。

点火1回あたりの推進剤損失は、燃焼に必要な推進剤とは別に、点火の時点で一括して差し引く。したがって Δv がごく小さいノードでは、損失のほうが燃焼で使う量を上回ることがある。

### 15-6. 推進剤とエンジンの劣化

| 対象 | 劣化の形 | 回復 |
|---|---|---|
| 極低温推進剤 | 沸点を超えて蒸発し、**残量が減る**。断熱材の等級と遮蔽で低減できる。自己加圧を使うとさらに増える | しない（補給のみ） |
| ヒドラジン単推進剤スラスタ | 触媒床の活性が累積噴射時間に応じて低下し、**比推力が落ちる**。推進剤自体は密閉容器内で10年以上安定であり、量は減らない | 整備で回復する |
| 熱シールド | 入熱に応じてアブレータが減る | 交換で回復する |
| 原子力電池 | 半減期に従って出力が下がる | しない |
| 固体推進剤・加圧ガス・常温貯蔵性の二液推進剤 | 劣化しない | — |

推進剤が減る劣化と、性能が落ちる劣化は別のものである。前者は補給でしか埋まらず、後者は基地での整備で回復する。

劣化の計算は毎フレームでは行わず、値を読む時点で前回の評価時刻からの経過時間（または累積噴射時間、累積入熱）に基づいて一括で計算する。

## 16. 自動操縦と通信

**通信圏の判定そのものは第2巻が実装する。**本文書が定めるのは、自動操縦の可否がその判定を引数に取るという形と、圏外に出た機体がどう振る舞うかまでである。

### 16-1. 機上の計算機で何ができるか

**この世界には高性能な計算機が存在しない。**自動操縦装置が自力で行えるのは、あらかじめ決められた時刻に、決められた向きへ、決められた量の噴射を行うことまでである。

| 自力でできること | 外部からの指令が要ること |
|---|---|
| 時刻で駆動する噴射シーケンスの実行 | 自動でのドッキング |
| 姿勢の保持 | 軌道の誤差を見ての修正 |
| 計画済みのマニューバノードの実行 | 目標の捕捉と追尾 |
| | 状況に応じた計画の変更 |

右の列はいずれも**観測して判断する処理**であり、機上の計算機では扱えない。これが、無人機の運用に通信を要求する理由である。

したがって、無人の機体が軌道計画を自動で実行するには、**自動操縦装置を積み、通信モジュールを積み、かつ通信圏の内側にいること**が要る。コックピットを持つ有人の機体はこの制約を受けない。人が乗っていれば、圏外でも判断できる。

```ts
// src/game/vessel/capabilities.ts
export interface CoverageQuery {
  inCoverage(pos: Vec3, moduleRange: number): boolean;
}
export function canAutopilot(v: Vessel, coverage: CoverageQuery): boolean;
```

`CoverageQuery` はこの巻が定める形であり、それを満たす実装は第2巻が置く。**この巻の側は、通信圏がどう決まるかを知らない。**

### 16-2. 圏外に出た機体

圏外に出た無人機は、**実行中の噴射は最後までやり切り、その先の判断を要する行動を止める。**

- **実行中の燃焼は完遂する。**時刻で駆動する噴射シーケンスは機上で完結しており、通信の有無に左右されない。中断すれば意図しない軌道に乗るという意味でも、完遂が正しい。
- 未実行のマニューバノードは消えず、そのまま残る。
- **圏外にいる間に通過したノードは実行されない。**その時刻に噴射すべきかどうかの判断が、機上ではできないためである。
- 姿勢制御は続く。フライホイールと磁気トルカは機体内で完結する。
- 圏内に戻れば、残っているノードから実行を再開する。

圏外に出ることそのものは失敗ではない。しかし通過するはずだった噴射が行われないため、**機体はしばしば意図しない軌道に乗る。**通信圏の穴を通る計画を立てないことが、無人運用の設計の一部になる。

HUDに通信圏の内外を表示する。圏外の無人機は、マップ上で識別できるようにする。

### 16-3. 計算機の性能が上がる余地

進行の後半で、より高性能な計算機を導入する余地がある。高純度のケイ素と希少な金属を要する計算機を作れるようになれば、機上で行える判断の範囲が広がり、通信圏への依存が緩む。どこまで緩めるかは今後の判断であり、本文書は余地があることだけを記す。

## 17. 資源と設備

ここで定めるのは**資源と設備が何であるか**である。どの元素がどこから採れ、どの設備が何を何に変えるのか、そして与えられた在庫と設備でその設計が生産できるのかどうか。それらを**どう使って進むか**——どこまで届き、どの順で経路を開き、月面の電力をどう回すか——は第2巻が定める。

**この層はすべて DOM にも THREE にも依存しない純データと純関数である。**機体の実装を待たずに書け、テストできる。したがって本章は §5〜§16 のどれにも依存せず、機体側の作業と最初から並行して進められる。

**通貨は存在しない。**生産が要求するのは**資源・設備・電力**の3つだけであり、そのいずれも金で迂回できない。

### 17-2. 材料適合性 — 推進剤がタンクの金属を要求する

推進剤は、どんな容器にでも入るわけではない。**推進剤の選択は、その推進剤に耐える金属を持っているかどうかに縛られる。**

| 推進剤 | 使える材料 | 理由 |
|---|---|---|
| 液体水素 | **アルミ合金**、特定のステンレス | 水素脆化。ふつうの合金は水素が拡散して脆くなる。実機のタンクもアルミリチウム合金が主流である |
| 四酸化二窒素 | アルミ合金 | **チタンとは応力腐食割れを起こす。**チタン製タンクには入れられない |
| 過酸化水素 | 高純度アルミ、特定のステンレス | 多くの金属と接触すると分解する |
| 液体酸素・液体メタン・シラン | アルミ合金、ステンレス、チタン | 特段の制約はない |
| ヒドラジン | アルミ合金、ステンレス | タンク自体の制約は緩い。**触媒床にイリジウム（白金族）が要る** |

```ts
// src/game/economy/propellant-compatibility.ts
export interface TankMaterialRequirement {
  readonly propellantId: string;
  readonly allowedMaterials: readonly string[];  // 資源 id。いずれか1つで足りる
}
export const TANK_MATERIALS: readonly TankMaterialRequirement[];
```

この適合性は、資源の依存としてそのまま働く。**アルミは液体水素にも四酸化二窒素にも使える最も汎用な材料であり、月のレゴリスの電解から真っ先に得られる。**月面の基地はこの層の制約を最初から満たしている。

**ヒドラジン単推進剤スラスタだけは、月の資源だけでは作れない。**触媒床のイリジウムは白金族であり、白金族は敵のドロップかM型小惑星からしか得られない。姿勢制御と軌道修正に最も扱いやすいこの推進系は、戦闘を経るか、小惑星へ出るかしなければ手に入らない。

### 17-3. 産地

| 産地 | 得られる元素 | 手段 |
|---|---|---|
| **月レゴリス** | O, Si, Fe, Ti, Mg, Al | 溶融塩電解。酸素と金属の混合物が同時に得られる |
| **月レゴリス（加熱抽出）** | **He**, H, C, N（いずれも微量） | レゴリスを加熱し、太陽風起源の吸着ガスを追い出す。電力を大量に食い、産出は微々たるものである |
| **月のアパタイト** | **F, Cl, P**（Ca₅(PO₄)₃(F,Cl)） | 採掘と分離。**溶融塩電解の媒体となる塩化カルシウムの原料である** |
| **月南極の永久影** | H₂O（→ H, O） | 氷の採掘 |
| **月の KREEP 岩** | Th, U, 希土類, P | 精錬。産出量は少ない |
| **敵の残骸** | C, N, S, Cu, 白金族, 希土類 | 戦闘。地球低軌道に限らず、月周辺・遷移軌道・その他の領域でも得られる |
| **近地球小惑星（C型）** | H₂O, C, 有機物 | 採掘 |
| **近地球小惑星（M型）** | Fe, Ni, Cu, 白金族, 希土類 | 採掘 |
| **ケレス** | H₂O（大量）, 炭酸塩（C）, アンモニア塩（N） | 採掘。小惑星帯で最も水が豊富 |
| **火星** | CO₂ 大気（C, O）, 水氷, N₂ 大気（2.8%）, Ar 大気（2%） | 大気捕集と採掘 |
| **金星** | N₂ 大気（3.5%）, CO₂ 大気（96%）, 硫酸雲（S） | 大気捕集。着陸はしない |
| **木星大気** | H₂, **He**, ³He | 大気捕集。深い重力井戸からの脱出が課題 |
| **カリスト** | H₂O | 採掘。木星系で放射線が最も弱く、拠点に適する |
| **イオ** | S, SO₂ | 採掘。木星系で放射線が最も強い |
| **タイタン** | CH₄, C₂H₆（C, H）, N₂ 大気 | 採掘と大気捕集。炭素と窒素が事実上無尽蔵 |
| **エウロパ・ガニメデ** | H₂O | 採掘 |

**月には炭素と窒素が事実上ない。**これがこの進行全体の出発点にある制約である。レゴリスの加熱抽出で太陽風起源の炭素と窒素も微量に出るが、**農場を回すにも高分子を合成するにも桁が足りず、あくまで補助である。**月の資源だけで閉じる経路は存在するが、そこで得られる推進剤は性能が限られる。実用的な量の炭素と窒素を得るには、敵を倒すか、月を出るしかない。**農場の食料も炭素と窒素を要する**ため、月の資源だけで自立している間、居住人数は補給に縛られる。

**敵は地球低軌道に限らず出現する。**近直線ハロー軌道を含む月周辺でも、月と地球を結ぶ遷移軌道でも、その他の領域でも遭遇しうる。したがって敵のドロップは低軌道でしか得られないものではない。ただし**出現の頻度と敵の強さは領域によって異なり**、同じ資源を得るのに要る戦力も変わる。**基地そのものが襲われうる。**近直線ハロー軌道の基地は月から遠く、そこにあるすべて——ドック、生産設備、在庫——を失いうる以上、防衛は基地の設計の一部である。

**アパタイトの採掘は、レゴリスの電解より先に来る。**溶融塩電解には媒体となる溶融塩そのものが要り、その塩化カルシウムはアパタイトの塩素から作る。氷とレゴリスがあっても、塩がなければ金属は取り出せない。

**ヘリウムは月でも少量得られるが、大量には木星大気からしか得られない。**月のレゴリスには太陽風起源のヘリウムが吸着しており、濃度はレゴリス1トンあたり数グラムから数十グラムの桁である。加熱抽出設備で追い出せるが、**膨大な量のレゴリスを加熱するだけの電力を食い、それでいて産出は数機ぶんの加圧ガスにしかならない。**ヘリウム加圧とヘリウム冷ガスは、序盤では**限られた機体にだけ配る贅沢な選択肢**であり、木星大気に到達して初めて標準の手段になる。

### 17-4. 磁気トルカとフライホイール — 要る資源が違う

姿勢制御には磁気トルカが使える。機体の電磁石が周囲の磁場と作るトルクでフライホイールをアンロードするもので、**推進剤をまったく消費しない。**

**磁気トルカは導線を巻いたコイル（多くは鉄芯入り）であり、永久磁石を使わない。**希土類が要るのは**フライホイールの駆動モーター**のほうである。

| 要素 | 要る資源 | 得られる場所 |
|---|---|---|
| **磁気トルカ** | 導線（アルミまたは銅）＋ 鉄芯 | **アルミと鉄は月のレゴリスから得られる。月の資源だけで作れる。**銅を使えば同じ質量で磁気モーメントが大きくなるが、月にはほぼ無く、M型小惑星か敵のドロップが要る |
| **フライホイール** | 希土類（駆動モーターの永久磁石） | 月の KREEP 岩、敵のドロップ、M型小惑星 |

**この違いは進行の形を決める。**アルミ巻きの磁気トルカは月の資源だけで作れるため、低軌道での姿勢制御は最初から推進剤ゼロで成立する。一方、フライホイールは希土類を待つ。磁場のない月周辺で推進剤を使わずに姿勢を保つ手段は、希土類を手に入れるまで存在しない。

磁気トルカが働くのは磁場のある場所だけである。

| 活動領域 | 磁場 | 姿勢制御の性格 |
|---|---|---|
| 地球低軌道 | 強い | 磁気トルカが使え、アンローディングが事実上無料になる |
| 近直線ハロー軌道・月周辺 | ほぼ無い | フライホイールのアンロードにRCS推進剤を消費する |
| 惑星間・小惑星帯 | ほぼ無い | 同上 |
| 木星系 | 極めて強い | 磁気トルカが使える。ただし放射線帯が厳しい |

**低軌道での活動は姿勢制御が安価であり、月周辺へ出るとRCS推進剤の消費が効いてくる。**同じ機体でも、どこで運用するかによって推進剤の収支が変わる。磁気トルカは電力を消費し、トルクは小さく、磁場に平行な軸まわりのトルクは出せない（3軸のうち1軸が瞬間的に制御できない）。

### 17-5. 進行を止める4つの制約

| 制約 | 内容 | 解消の手段 |
|---|---|---|
| **資源** | 必要な元素を持っていない | その元素のある場所へ行く、または敵から得る |
| **設備** | 変換する設備を持っていない | 設備の建設に必要な資源と電力を確保する |
| **電力** | 設備を動かす電力が足りない | 太陽電池を増やす。太陽から遠い場所では原子炉が要る |
| **到達可能性** | その場所へ行くだけの Δv が出せない | より比推力の高い推進系、多段化、または大気掠め |

**この4つは互いに絡み合っている。**遠くへ行くには高い比推力が要り、高い比推力の推進剤には特定の元素が要り、その元素は遠くにしかなく、そこへ行くには電力を生む原子炉が要り、原子炉の燃料もまた特定の場所にしかない。**通貨で迂回できる辺は1本もない。**

### 17-6. 設備の定義

設備は、電力を消費して入力資源を出力資源に変換する。**設備そのものの建設にも資源と電力が要る。**

```ts
// src/game/economy/facility.ts
export interface FacilityDef {
  readonly id: string;
  readonly name: string;
  // anyOf は「このうちどれか1つ」を表す。原子炉のウランまたはトリウム、電子機器工場の
  // 銅またはアルミのように、同じ役を果たす資源が複数ある工程がある
  readonly inputs: readonly { anyOf: readonly string[]; rate: number }[];   // kg/s
  readonly outputs: readonly { resourceId: string; rate: number }[];        // kg/s
  readonly powerDraw: number;         // W。動かすのに要る電力
  readonly powerOutput: number;       // W。発電設備が出す電力。それ以外は 0
  readonly buildCost: readonly { resourceId: string; mass: number }[];
  readonly requiresFacility: readonly string[];  // これを作るのに要る別の設備
}
export const FACILITIES: readonly FacilityDef[];
```

`requiresFacility` は技術の前提ではなく、**物理的な前提**である。液化装置がなければ極低温タンクに詰められない、圧延機がなければ金属の塊を板にできない、という類の関係だけを表す。

**電力は資源ではなく、`powerDraw` と `powerOutput` の2つの数で表す。**太陽電池アレイと原子炉は `powerOutput` を持ち `outputs` は空である。電力は貯蔵も輸送も資源とは違う規則に従うため、`ResourceLedger` には入れない。基地の電力収支は、稼働している設備の `powerOutput` の総和から `powerDraw` の総和を引いた値である。

**送電網は発電も変換もしない。**永久影の基地が峰の太陽電池アレイの `powerOutput` を受け取れるようにする設備であり、`powerDraw` も `powerOutput` も 0 である。送電網が無いときに永久日照の峰へ置いた発電設備の出力が基地の収支に入らない、という規則は第2巻 §16 が定める。

月面基地は、地球から運ばれた最初の一組を持って始まる。**この一組だけが与えられ、以後のすべては自分で作る。**

| 設備 | 役割 |
|---|---|
| 太陽電池アレイ（永久日照の峰） | 発電（第2巻 §16） |
| 送電網 | 峰から永久影の基地へ電力を送る（第2巻 §16-1） |
| 氷採掘機 | 永久影から水を採る |
| アパタイト採掘機 | アパタイトから F・Cl・P を採る |
| 溶融塩調製炉 | 塩素から塩化カルシウムの溶融塩を作る |
| レゴリス採掘機 | 足下のレゴリスを掻き集める |
| 溶融塩電解炉（小型） | レゴリスから酸素と金属の混合物を取り出す |

**この一組で作れるのは、金属の板と殻と骨組みでできた物だけである。**エンジンも、通信モジュールも、磁気トルカも作れない。それらを作るには、まず**機械工場・電子機器工場・巻線工場**を建てる必要があり、その建設には上の一組が出す金属と、峰から送られてくる電力が要る。

**最初の目標は、機体を作ることではなく、機体を作れる工場を作ることである。**

**採掘と一次処理**

| 設備 | 入力 | 出力 | 電力 | 建設に要るもの |
|---|---|---|---|---|
| レゴリス採掘機 | — | レゴリス | 中 | Fe 2 t, Al 1 t |
| **アパタイト採掘機** | — | アパタイト | 中 | Fe 2 t, Al 1 t, Ti 0.3 t |

| 氷採掘機 | — | H₂O | 中 | Fe 2 t, Al 1 t |
| **レゴリス加熱抽出設備** | レゴリス | **He**, H, C, N（**いずれも微量**） | **極大** | Fe 4 t, Ti 1 t |
| 溶融塩電解炉 | レゴリス, **溶融塩** | O, 金属の混合物 | **大** | Fe 5 t, Ti 2 t, 電子機器 0.2 t |
| **製錬炉** | 金属の混合物 | Al, Fe, Ti, Si, Mg | 大 | Fe 6 t, Ti 2 t |
| 水の電解装置 | H₂O | H, O | 大 | Fe 1 t, Pt族 0.02 t |
| 核燃料精製炉 | KREEP 岩, M型小惑星の鉱石 | U, Th | 大 | Ti 3 t, Pt族 0.1 t |

**レゴリス加熱抽出設備は、電力に対する見返りが最も悪い設備である。**同じ電力を溶融塩電解に回せば数トンの金属が出るところ、この設備が出すのは数キログラムのヘリウムと、それに満たない量の水素・炭素・窒素である。それでも建てる意味があるのは、**ヘリウムが他のどこからも得られないから**である。炭素と窒素については、この設備の産出を当てにして農場や高分子合成を計画してはならない。

**素材の加工**

| 設備 | 入力 | 出力 | 電力 | 建設に要るもの |
|---|---|---|---|---|
| **圧延・成形機** | Al, Fe, Ti, Mg | タンク殻, 外皮パネル, トラス部材 | 中 | Fe 4 t, Ti 1 t |
| **機械工場** | 金属, 部材 | エンジン, ポンプ, バルブ, ジンバル, 軸受 | 中 | Fe 8 t, Ti 3 t, Al 2 t |

### 17-9. 電力が最初の壁になる

**溶融塩電解は極めて大きな電力を要する。**アルミの電解精錬は工業的に最も電力を食う工程の一つであり、月のレゴリスから金属と酸素を取り出す工程も同様である。

したがって進行の最初の段階は「電力を確保すること」になる。太陽電池を増やすにはケイ素が要り、ケイ素を得るには電解が要り、電解には電力が要る。**この循環は、最初の小さな設備から徐々に規模を拡大していく形でしか抜けられない。**

太陽から遠ざかると太陽光が弱くなる（木星では地球の27分の1）。外惑星で設備を動かすには原子炉が要る。原子炉の燃料は月の KREEP 岩か M型小惑星から得る。**農場の電照（第2巻 §14-1）と重水素・ヘリウム3の同位体分離（§17-8）も同じ電力を奪い合う。**居住人数を増やすことと、核融合燃料を作ることは、同じ電力収支の上で競合する。

### 17-12. 設備の連鎖が閉じていることの検証

ある資源を得るのに必要な設備が、その資源自身を必要とする循環が生じると、進行が止まる。これは**到達可能性の閉包を求める問題であり、テストで機械的に検証できる。**

```ts
// tests/unit/resource-closure.test.ts
// 初期資源の集合から出発し、不動点に達するまで前方に閉じる
function reachableClosure(
  initial: ReadonlySet<string>,          // 資源 id
  initialFacilities: ReadonlySet<string>,// §17-7 の最初から持っている設備
  facilities: readonly FacilityDef[],
  deposits: readonly DepositDef[],
  reachableBodies: (owned: ReadonlySet<string>) => ReadonlySet<AttractorId>,
): ReadonlySet<string> {
  const owned = new Set(initial);
  const builtIds = new Set(initialFacilities);
  for (;;) {
    const before = owned.size + builtIds.size;
    // 1. 今の資源で建てられる設備を全て建てる
    for (const f of facilities) {
      if (!f.buildCost.every((c) => owned.has(c.resourceId))) continue;
      if (!f.requiresFacility.every((id) => builtIds.has(id))) continue;
      if (!f.inputs.every((i) => owned.has(i.resourceId))) continue;
      builtIds.add(f.id);
      for (const o of f.outputs) owned.add(o.resourceId);
    }
    // 2. 今の推進剤で届く天体の産地を全て採る
    for (const d of deposits) {
      if (!reachableBodies(owned).has(d.bodyId)) continue;
      owned.add(d.resourceId);
    }
    if (owned.size + builtIds.size === before) break;   // 不動点
  }
  return owned;
}
```

テストは、§17-7 の最初から持っている設備と、それが直ちに産出できる資源から始めてこの閉包を求め、**`RESOURCES` のすべての id が閉包に含まれることを確かめる。**含まれないものがあれば、その資源に至る経路が存在しないということであり、データの誤りである。

**設備そのものが生産の対象であるため、この検証は設備の集合についても閉包を取る。**資源だけを追っていては、「資源はあるが、それを加工する工場を作る手立てがない」という詰まりを見逃す。上の実装が `builtIds` を不動点の判定に含めているのはそのためである。

`reachableBodies` は、その時点で持っている推進剤の最良の比推力と、現実的な質量比（3〜6）から Δv を求め、第2巻 §15-2 の表と突き合わせて届く天体を返す。**炭素を持っているかどうかで大気掠めの可否が変わるため、この関数は所持資源に依存する。**閉包の反復のたびに再評価する。

## 20. 主要な技術的リスク

1. **複合断面の輪郭抽出** — 複合断面の外周は、基本断面の輪郭から貼り合わせ面を除いて連結したものである。貼り合わせ面が完全に一致していることが前提であり、浮動小数点の誤差で隙間や重なりが生じると輪郭が破綻する。辺の長さの一致は検証で保証し、輪郭の連結は頂点の同一性ではなく、貼り合わせの木構造をたどって構成する。

2. **断面をまたぐ頂点の対応** — 辺数の異なる断面や、回転位相の異なる断面をつなぐとき、頂点の対応を誤ると外皮がねじれる。弧長による120点への等分と、対応距離の総和を最小にする割り当てで解決するが、両端の位相差が大きい場合の見た目は確認が必要である。

3. **円の弓形差し引き** — 円に複数の側面の口を設けたとき、隣接する弓形同士が重なる場合がある。分岐数が多く、口の幅が広いときに起きる。重なる構成は検証で拒否する。

4. **減衰最小二乗の正則化重み** — λ が小さすぎると、要求をわずかに良く満たすために対向するスラスタを同時に噴かせ、推進剤を無駄に消費する解が選ばれる。大きすぎると要求トルクを十分に出せない。λ は行列 A の特異値の大きさに対する相対値として決めること。

5. **アンローディングの発振** — 飽和と排出は互いを打ち消す方向に働くため、閾値と排出量の取り方によっては短周期で往復する状態に落ち込む。排出の開始と終了に別々の閾値を設けること。

6. **磁気トルカで出せない軸** — τ = m × B は B に平行なトルクを出せない。B に垂直な成分だけを扱い、平行成分は必ず次の段へ落とすこと。

7. **姿勢制御の要求元の一元化** — 現在は手動操作と自動操縦がそれぞれ機体のトルクを直接書いている。両方を `AttitudeControlSystem` への要求に置き換えないと、フライホイールの角運動量を更新せずにトルクを出すことになり、飽和の計算が合わなくなる。

8. **重力傾斜トルクと時間加速** — 重力傾斜トルクは軌道周期の程度の時定数を持つため、時間加速下では1ステップの姿勢変化が大きくなる。姿勢積分の運動エネルギー射影が発散しないことを、高倍率での長時間の待機で確かめること。

9. **時間加速中の燃焼** — 1ステップが数十秒に達する時間加速下では、ステップ内での質量変化が無視できない。燃焼中のステップは閉形式で質量を進めるか、燃焼の開始と終了の時刻でステップを区切ること。

10. **カプセル判定の費用** — 機体1機がエッジの数だけカプセルを持つため、機体同士の判定は組み合わせになる。外接球による広域の絞り込みを必ず先に通し、球が交わる場合のみカプセル同士を総当たりする。エッジ数の上限が判定の上限を決める。

11. **姿勢依存の `bcInv` と予測** — 予測は未来の姿勢を持たないため、**予測では現在の姿勢の値を固定して使う**。姿勢を保っている機体では正確であり、回転している機体では平均から外れる。再突入の予測が姿勢に依存することを UI で示す必要がある。

12. **抗力の増加による再突入バランスの変化** — 現在の `bcInv` は質量の仮定が実際の機体質量と食い違っており、本来より小さい値になっている。形状と実質量から導出すると抗力が増える。F7 の時点でステージ側の高度と時間の調整が要る。

13. **推力軸のずれによる制御不能** — 主機を非対称に積む、あるいはコンテナを非対称に積むと、推力軸が重心を大きく外れる。ジンバル補償で打ち消しきれない構成は、警告を出したうえで、それでも機体が回ることを許すか拒否するかを決めておくこと。

14. **描画メッシュの生成コスト** — 実行時生成であり、`WebGPURenderer` はジオメトリを最初の描画時にキャッシュする。生成は形状の変更時のみとし、既存メッシュのジオメトリを差し替えない運用を守ること。

15. **通信圏の問い合わせの頻度** — `CoverageQuery` を毎フレーム引くと、判定を実装する側の費用が機体の数だけ積み上がる。通信圏の内外は秒の単位で変わるものでありフレーム単位の精度を要さないため、**問い合わせる側が結果を保持し、数秒ごとに引き直す**形にしておくこと。この巻が判定の中身を持たない以上、頻度を決めるのはこちら側の責任である。

16. **保存形式の互換性** — 機体の表現が変わるため、旧形式の保存データは既定の設計への読み替え以上のことはできない。読み替え不能な保存データは明示的に拒否し、破損した機体を生成しないこと。

17. **テストの制約** — `tsconfig.test.json` の `lib` は `ES2022` のみであり、DOM も THREE も無い。新設する純関数は必ずこの制約の内側に置くこと。`game/vessel/` の計算部分と描画・DOM に触れる部分は最初から分けておかないと、書いたテストがコンパイルできない。

18. **UIの総量** — 推進系パネルと通信圏の表示が飛行中のHUDに加わる。既存のパネルへ統合できないかを確認し、置き場の規約に従うこと。
