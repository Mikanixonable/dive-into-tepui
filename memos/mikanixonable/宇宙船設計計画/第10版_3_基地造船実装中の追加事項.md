# 第10版 第3巻 基地造船実装中の追加事項

作成日: 2026-08-19  
対象: `第10版_3_基地本体カスタム形状作業台実装計画.md` の実装中に判明した追加事項

## 実装方針を変更した事項

- 基地の確定適用は、基地 `Vessel` を別インスタンスへ差し替えず、同じ `Vessel` の `renderObject`、`assembly`、質量特性、カプセル、`BaseCollisionGeometry`、ドック中船のメッシュを更新する方式にした。これにより、アクティブ基地、マーカー、カメラ、他システムが保持する基地参照を壊さない。
- 旧来の固定基地衝突形状は、アセンブリを持たない旧セーブの互換経路として残した。新規基地とカスタム基地は、外皮メッシュとアセンブリ由来の衝突形状を使う。
- `BaseSaveData.dockBindings` は従来の `slotIndex` に加えて、アセンブリ由来の安定 `dockId` を保存する。古い保存値や未知のIDは `slotIndex` と空きスロットへフォールバックする。

## 計画の解釈を具体化した事項

- 初期版では、収容中の船が使っているドックのポート位置・法線・IDを変更できない。基地モジュールのIDも維持する。先に船を発進させれば、そのポートを編集できる。
- 基地のドック部品が持つポートは、基地モジュールのスロットが空の場合の導出元として扱う。既定基地は既存 `base_module.dockSlots` を優先する。
- ノード・エッジ・断面の数値編集は、`VesselAssembly` の不変編集コマンドを通し、外皮、質量、衝突、ドック位置を同じアセンブリから再生成する。ポリゴンメッシュを直接編集するモードは追加していない。
- 新規船下書きは、既定有人アセンブリを初期値として作成し、作業台で編集後に資源・設備・電力・空きドックを検証して建造する。設計を選択しただけで完成船が増える旧経路は復活させていない。

## 実装中に確認した追加課題・判断保留

- 純粋な `DockWorkbenchSession` は基地・格納船・新規下書き、Undo/Redo、履歴を扱うよう拡張したが、現行のDOMランタイム画面はチェックポイント型の確定・取消を主に利用している。作業中の各編集を画面上のUndo/Redoへ接続する作業は別途必要。
- 作業台のステージは既存のゲームカメラへのレイキャストとDOMオーバーレイを再利用している。専用の編集用3Dビューポート、ドラッグ中の連続ゴースト、実画面座標からの自由な深度決定は未導入で、選択したMountPointへのスナップを確定操作として扱う。
- 断面編集UIは現在、最初のプリミティブの主要半径を数値変更する範囲である。複合断面のプリミティブ追加・削除、貼り合わせ面の編集、軸・位相のギズモ操作は編集エンジンに存在するが、UIの追加作業が必要。
- 基地本体を含む作業台のDOM統合テストはまだない。純粋な編集、保存境界、ドックポート導出、衝突半径、既存ユニット回帰で検証している。
- アセンブリ由来の基地衝突は外皮三角形をBVHへ変換し、ワープ時は外接OBBを使う。トラスやノードの外接半径は広域判定へ含めるが、部品個別の精密干渉判定は今後の改善対象。

## 次に確認すること

1. WebGPU上で基地本体を選択し、ノード移動・断面変更・部品取り外し・在庫からのスナップを操作確認する。
2. 収容船がある状態で基地編集を確定し、船のメッシュとドック位置が維持されることを確認する。
3. カスタム基地を保存・再起動し、`dockId` が復元されることを確認する。
4. 必要なら作業台ランタイムを `DockWorkbenchSession` のUndo/Redoへ統合する。
