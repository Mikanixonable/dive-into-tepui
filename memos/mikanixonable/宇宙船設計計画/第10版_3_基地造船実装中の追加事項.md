# 第10版 第3巻 基地造船実装中の追加事項

作成日: 2026-08-19  
対象: `第10版_3_基地本体カスタム形状作業台実装計画.md` の実装中に判明した追加事項

## 実装方針を変更した事項

- 基地の確定適用は、基地 `Vessel` を別インスタンスへ差し替えず、同じ `Vessel` の `renderObject`、`assembly`、質量特性、カプセル、`BaseCollisionGeometry`、ドック中船のメッシュを更新する方式にした。これにより、アクティブ基地、マーカー、カメラ、他システムが保持する基地参照を壊さない。
- 旧来の固定基地衝突形状は、アセンブリを持たない旧セーブの互換経路として残した。新規基地とカスタム基地は、外皮メッシュとアセンブリ由来の衝突形状を使う。
- `BaseSaveData.dockBindings` は従来の `slotIndex` に加えて、アセンブリ由来の安定 `dockId` を保存する。古い保存値や未知のIDは `slotIndex` と空きスロットへフォールバックする。

## 計画の解釈を具体化した事項

- 初期版では、収容中の船が使っているドックのポート位置・法線・IDを変更できない。基地モジュールのIDも維持する。先に船を発進させれば、そのポートを編集できる。
- 基地のドック部品が持つポートは、基地モジュールのスロットが空の場合の導出元として扱う。既定基地は既存 `base_module.dockSlots` を優先する。
- ノード・エッジ・断面の数値編集は、`VesselAssembly` の不変編集コマンドを通し、外皮、質量、衝突、ドック位置を同じアセンブリから再生成する。ポリゴンメッシュを直接編集するモードは追加していない。
- 新規船下書きは、既定有人アセンブリを初期値として作成し、作業台で編集後に資源・設備・電力・空きドックを検証して建造する。設計を選択しただけで完成船が増える旧経路は復活させていない。

## 実装中に確認した追加課題・判断保留

- 純粋な `DockWorkbenchSession` は基地・格納船・新規下書き、Undo/Redo、履歴を扱うよう拡張したが、現行のDOMランタイム画面はチェックポイント型の確定・取消を主に利用している。作業中の各編集を画面上のUndo/Redoへ接続する作業は別途必要。
- 作業台のステージは既存のゲームカメラへのレイキャストとDOMオーバーレイを再利用している。専用の編集用3Dビューポート、ドラッグ中の連続ゴースト、実画面座標からの自由な深度決定は未導入で、選択したMountPointへのスナップを確定操作として扱う。
- 断面編集UIは現在、最初のプリミティブの主要半径を数値変更する範囲である。複合断面のプリミティブ追加・削除、貼り合わせ面の編集、軸・位相のギズモ操作は編集エンジンに存在するが、UIの追加作業が必要。
- 基地本体を含む作業台のDOM統合テストはまだない。純粋な編集、保存境界、ドックポート導出、衝突半径、既存ユニット回帰で検証している。
- アセンブリ由来の基地衝突は外皮三角形をBVHへ変換し、ワープ時は外接OBBを使う。トラスやノードの外接半径は広域判定へ含めるが、部品個別の精密干渉判定は今後の改善対象。

## 次に確認すること

## workspace2統合前レビューで見つかり、修正した不具合

- `Docking.transferWorkbenchPart`: 送り先の適用が成功し送り元の適用が失敗する経路で、
  同じ部品オブジェクトが両方の構成に残っていた(片方への修理・損傷がもう一方へ波及する)。
  送り元が失敗した場合は送り先を元の構成へ戻すよう修正。
- `Docking` の `freePort` ローカル関数: 接続口の外装要素(placements)を見ておらず、
  実際は塞がっているノードの軸方向口を「空き」と誤判定してノード・エッジ追加が
  失敗する経路があった。`assembly-editor.ts` の `occupiedPorts` と同じ判定に揃えた。
- `Docking.buildDraft`: 倉庫から引いた(=生産時にすでに課金済みの)部品を含めて建造費を
  再計算しており、二重課金になっていた。課金対象を `draft.ownedPartIds` に無い部品(既定
  テンプレートの未生産部品)だけに絞った。
- `Docking.removeWorkbenchPart`: 下書きの未所有部品を外したとき、実際には倉庫へ何も
  積んでいないのに「基地倉庫へ移しました」と表示していた。実際の帰結に応じてヒントを
  分けた。
- `Docking.cancelWorkbench`: チェックポイントに無い下書きを破棄する際、`render.object` を
  シーングラフから外さずに `dispose()` していたため、空になったメッシュが基地の子として
  残り続けていた(下書き作成→取消のたびにメッシュが1つ残る)。`removeFromParent()` を
  先に呼ぶよう修正。
- `base-geometry.ts` の `dockPartPorts`: 各アンカーへ配るポート本数(間隔計算に使う `count`)
  を、実際のラウンドロビン配置(`i % anchors.length`)とは異なる逐次配分式で計算していた。
  3辺以上にまたがるドック部品でポート間隔がずれる不具合。ラウンドロビンと同じ配分式へ
  差し替えた。
- `base-module.ts` の `DockedVesselEntry`/`BaseState` が `Vessel` を type-only import して
  いたため、`tests/unit/base-geometry.test.ts` 経由で DOM/Three.js 依存の全チェーンが
  `tsconfig.test.json`(DOM無し構成)に引き込まれ `test:unit` が失敗していた。両インター
  フェースを `V`(既定 `unknown`)で汎化し、`vessel.ts` だけが `Vessel` へ具体化するよう
  修正。これは実装担当者本人が最後のコメントで挙げていた `test:unit` 失敗の原因そのもの。

以上を修正した上で typecheck / `test:unit`(178/178)/ `test:physics`(527/527)/ `build` が
すべて通ることを確認済み。
