# 第9版 — 未確定事項

第1巻から第4巻・決定事項・実装中の追加事項と、`src/` の実装を突き合わせて洗い出した、**まだ決まっていない事項・直すべき事項・価値判断を要する事項・両立しない要求**を置く。

4つに分ける。

- **U — 要件が固まっていない箇所。**実装に入るには決めなければならないが、計画書がまだ答えを持っていないもの。
- **M — 修正すべき箇所。**計画書の記述が実装と食い違っている、または計画書どうしが食い違っているもの。どちらが正しいかを併記する。
- **V — 価値判断が必要な箇所。**技術的にはどちらでも成立し、遊びとしてどうしたいかで決まるもの。推奨を併記する。
- **X — 矛盾点。**計画書の中で両立しない要求が並んでいるもの。

**番号は安定である。**決定を記録するときはこの番号で参照する。項目の削除では番号を詰めない。

各項目は、それ単体を読んで意味が通るように書く。参照した節と実装のファイルを必ず示す。

## U. 要件が固まっていない箇所

### U-1. 搭載要素の性能値が、名前だけあって数値を持たない

第1巻 §6-1 は外装要素11種・内装要素21種の**主な性能値を名前として**挙げるが、**値を1つも定めていない。**実装 `src/game/game-entity/parts.ts` はこの一覧をそのまま型として持ち（`PartType` は33種）、`PART_DEFAULTS` が全項目の既定値を持つが、その既定値は**ほぼすべてが 0** である。

`src/game/vessel/vessel-parts.ts` が実数値を与えているのは、既定の有人艦・敵対機・基地が実際に積む16種だけである。**一度も実数値を与えられていない種別**は次のとおりである。

| 種別 | 未定の性能値 |
|---|---|
| 戦闘用シールド | 遮蔽する立体角、耐弾性能、可動の可否、消費電力 |
| ロボットアーム | 到達距離、可搬質量 |
| ドッキングポート | 適合クラス、移送速度 |
| コンテナ接合部 | 保持できるコンテナの規格 |
| 酸化剤タンク・還元剤タンク・加圧ガスタンク・水タンク | 容積、断熱等級、要求与圧、材料、耐圧 |
| 燃料電池・原子力電池 | 定格出力、効率、消費、半減期 |
| 自動操縦装置 | 消費電力 |
| 配管 | 口径、最大流量 |
| ペイロード倉庫 | 内容積、最大積載質量 |
| 磁気トルカ | 最大磁気モーメント、消費電力 |
| 農場 | 栽培面積、光源、消費電力、廃熱 |
| ドック | 収容数、最大寸法 |

**放置すると何が起きるか。**これらの種別を積んだ設計は `validateBlueprint` を通り、`producibility` も通り、生産できてしまう。しかし積んだ要素は何も出さない — 磁気トルカを積んでもトルクが 0、ペイロード倉庫を積んでも容積が 0 である。**「設計は正当だが機能しない機体」が作れる状態になり、それが不具合なのか設計ミスなのかをプレイヤーが判別できない。**

**決め方の選択肢。**(a) B6（生産）と B8（搭載モード）で、パレットに出す種別だけを順に埋める。(b) 一覧全体を先に埋め、実装が追いつくのを待つ。

**推奨は (a) である。**数値は用途が決まって初めて妥当性を判断できる。ドックの最大寸法は組立モードの枠として画面に出て初めて「大きすぎる／小さすぎる」が分かり、配管の口径はエンジンの要求流量と突き合わせて初めて意味を持つ。**ただし「値が 0 の種別はパレットに出さない」ことを B8 の条件に加える。**そうしないと (a) は「未定のまま出荷される」と区別が付かない。

### U-2. 搭載要素ごとの建造費の表（T-4）

第1巻 §6-1 は搭載要素を定義するが、**それを作るのに要る資源を持たない。**実装は `src/game/economy/producibility.ts` の `BlueprintPart.buildCost` として経路だけを用意しており、`src/game/vessel/vessel-parts.ts` の要素は資源量を1つも申告しない。

**放置すると何が起きるか。**`producibility` は不足を1つも列挙せず、**すべての設計が「生産できる」と答える。**資源の帳簿・産地・設備の連鎖（R1〜R3、テスト込みで実装済み）が、生産の可否に一切影響しない。第2巻 §3-8「進行を止めるものが常に物理的な事実である」という骨格が、実際には何も止めない。

割り当ては第4巻 §5 のとおり **B6** である。同時に、タンク殻の質量（`BlueprintTank.shellMass`）を第1巻 §10-3 の肉厚から導く経路も要る。

### U-3. ヒドラジンの触媒床に要る白金族の質量（T-5）

第1巻 §17-2 はヒドラジンのタンクが白金族（イリジウム）を要求すると定めるが、**要る質量を定めていない。**実装は `producibility` の `Requirement` に `needed: 0` として「量ではなく所持そのものの要求」の形で置いている。

**放置すると何が起きるか。**白金族を 1 グラム持っているだけで、何百基のヒドラジンスラスタでも作れる。第1巻 §17-2 が置いた「ヒドラジン単推進剤スラスタだけは月の資源だけでは作れない」という制約は、**最初の1回の入手で恒久的に解除される。**戦闘またはM型小惑星へ出る動機が1度しか働かない。

割り当ては **B6**。

### U-4. ドックの性能値（第2巻 §14-4）

第2巻 §14-4 はドックの性能値として収容数・最大寸法・電力の3つを挙げるが、**いずれも数値を定めていない。**実装 `src/game/game-entity/parts.ts` の `DockPart` は `capacity: 0` / `maxVesselSize: 0` を既定とし、実数値を与える箇所が無い。

**放置すると何が起きるか。最大寸法は組立モードの作業領域の枠そのものである**（第2巻 §6-1）。枠の寸法が決まらなければ、B7（骨格モード）は「枠を超える設計が枠を突き抜けて見える」という第2巻 §6-1 の中心的な仕掛けを実装できない。第2巻 §14-4 が定める「ドックは拡張できる」も、拡張前後の値がなければ意味を持たない。

**推奨は、既定の軌道基地のドックを直径 6 m × 全長 24 m に置くことである。**理由は、既定の有人艦（全長 4.5 m 級）が余裕をもって入り、第2巻 §14-5 のコンテナ（一辺 2.0 m）を並べて積んだ機体も入り、それでいて「軌道上で結合しなければ作れない構造物」（§6-9）が現実的な設計目標として残るためである。値そのものより、**枠が機体の数倍で頭打ちになることが §6-9 の存在理由を守る**ことが要点である。

### U-5. 通信モジュールの帯域・消費電力・指向

第1巻 §6-1 は通信モジュールの性能値を「到達距離、帯域、消費電力、指向の可否」と定め、第2巻 §13-2 は**到達距離と質量だけ**の4等級表を与える。**帯域・消費電力・指向が何に効くかは、どの巻にも書かれていない。**実装 `CommunicationPart` は `bandwidth` / `powerDraw` / `directional` の3フィールドを持つが、`src/` に読み手が1つも無い。

第2巻 §14-6 は通信基地の電力を「到達距離の2乗に比例する」と定めるが、**比例係数が無い。**実装の通信基地（`COMM_STATION_RANGE = 2.0e8` m）は電力を消費しない。

**放置すると何が起きるか。**通信網の配備が「置けば繋がる」だけの操作になり、等級を選ぶ判断が質量以外に無くなる。第2巻 §13-5 が「序盤から中盤への最も大きな段差」と位置づける通信衛星の配備に、電力収支という第2の制約が掛からない。

**推奨は、消費電力だけを先に定め、帯域と指向は使わないなら §6-1 の一覧から外すことである。**電力は既に `PowerSystem` と熱収支という受け皿があり、到達距離の2乗に比例させるだけで「遠くまで届く中継点は太陽電池も大きい」という形が出る。帯域は同時に何機を管制できるかに使えるが、その規則を定めるまでは名前だけが残る。

### U-6. 戦闘用シールドが被害をどう肩代わりするか

第1巻 §6-4・§11-1 と第2巻 §19-4 は戦闘用シールドを繰り返し扱い、「被弾の方向がシールドの遮蔽する立体角の内側であれば、シールドが先に損傷を受け、背後の要素は守られる」と定める。しかし **`耐弾性能` がどう被害量に効くかの式が無い。**実装 `CombatShieldPart` は `solidAngle` / `ballisticResistance` / `movable` / `powerDraw` を持つが、被害を軽減するコードが `src/` に無い。

**放置すると何が起きるか。**第2巻 §14 の「基地は移動しない戦闘艦艇として働く」「同じ質量の艦艇より重い武装と厚いシールドを積める」という序盤の防衛の骨格が成立しない。基地が自ら戦うこと（決定事項 G-8）は、シールドが実際に効くことに寄っている。

**推奨は、`ballisticResistance` を「この方向から来る被害のうち、シールドが吸収する割合」（0〜1）とし、シールド自身の HP がその吸収分だけ減る形にすることである。**既存の `ArmorPart.damageReduction`（実装済み、既定 0.2）と同じ意味の値を方向付きにしたものであり、`Ship.applyDamageToParts` の枠組みをそのまま使える。

### U-7. フライホイールの飽和とアンローディングの閾値

第1巻 §14-2 は「`|h|` が hMax の既定割合を超えるとアンローディングを行う」と定め、リスク5は「排出の開始と終了に別々の閾値を設けること」と要求するが、**どちらの値も定めていない。**実装には角運動量の蓄積そのものが無く（`maxAngularMomentum: 400` は既定機の部品に書かれているが、`src/` に読み手が無い）、磁気トルカも `src/physics/geomagnetic.ts` の純関数が置かれたまま `src/game/` からの参照を1つも持たない。

**放置すると何が起きるか。**F9 の実装者が2つの閾値を自分で選ぶことになり、第1巻 §17-4 が定める「低軌道では姿勢制御が事実上無料、月周辺ではRCSを消費する」という領域ごとの性格の差が、選んだ値次第で消える。

**推奨は、開始 0.85・終了 0.30 である。**開始が高いのは、通常の運用でアンローディングが頻発しないためであり、終了が低いのは、1回の排出で当分は再発しないだけの余裕を作るためである。この2値の比が大きいほど発振から遠い。

### U-8. 減衰最小二乗の正則化重み λ

第1巻 §14-3 は姿勢トルクの配分を Tikhonov 正則化した擬似逆行列で解くと定め、リスク4は「λ は行列 A の特異値の大きさに対する相対値として決めること」とするが、**相対値そのものが定まっていない。**

**放置すると何が起きるか。**リスク4が書くとおり、小さすぎれば対向するスラスタを同時に噴かせて推進剤を捨て、大きすぎれば要求トルクを出せない。どちらも「機体の設計が悪いのか配分が悪いのか」を切り分けられない形で現れる。

**推奨は λ = (最大特異値 × 1e-3)² である。**特異値の2乗で入るのは `A Aᵀ` の対角に足すためであり、1e-3 は「6基未満または偏った配置で解が無い方向」だけを丸める大きさとして、対称6基配置では実質的に無影響になる。**F9 の検証（第4巻 §7-1）が「対向するスラスタが同時に噴かないこと」を固定する**ため、値の妥当性はテストで確かめられる。

### U-9. モジュールを指し分けられる最小の見かけの直径

第2巻 §19-1 は「画面上の見かけの直径が `MODULE_PICK_MIN_PX` を下回るモジュールは判定の候補から外す」と定めるが、**値が無い。**§22-11 は「近づけば選べたはずのものが選べないことは起きる」ことを認め、ホバー時の強調表示で示す必要があると書く。

**推奨は 12 px である。**既存の `TARGET_LOCK_PICK_PX_SQ`（戦闘ターゲットの選択半径）と同じ桁に置くことで、モジュールを指す操作と機体を指す操作の手触りが揃う。

### U-10. 生産時間係数のステージごとの既定値

第2巻 §5-1 と決定事項 E-3 は、生産時間係数をセーブデータに含め、**ステージごとの既定値を持つ**と定める。既定値は 0（即時完成）である。しかし**ステージごとの値の表が無い。**

**放置すると何が起きるか。**「後から有効にしても既存のセーブに影響しない」という仕組みだけが残り、有効にする条件が誰も決めないまま残る。

**推奨は、当面すべてのステージで 0 に固定し、表を作らないことである。**係数を持つ仕組みは既に用意されており、遊びとして時間を掛けさせたい場面が具体的に見つかるまで、値の表は増やさないほうがよい。

### U-11. 開始時点の役割ごとの人数

第3巻 §7-1 は開始時の総人口を 1000 人と定め、§7-2 は4つの役割（整備士・飛行士・医師・エッセンシャルワーカー）を定めるが、**開始時点で各役割が何人かを定めていない。**同 §7-2 は「通信圏が狭いあいだ、飛行士の人数がそのまま戦力の上限になる」と書き、第2巻 §13-5 は「船団の規模は操縦できる人数で決まる」と書く。**つまり飛行士の初期人数は、序盤の戦闘の規模そのものである。**

**放置すると何が起きるか。**序盤の攻勢が何機の船団になるかが決まらず、機体設計に掛かる圧（往復ぶんを全部積む、§13-5）の強さが調整できない。

**推奨は、飛行士を 12 人に置くことである。**同時に出せる有人機が12機というのは、船団という語が成立する最小の規模であり、かつ1機を失うことが 8% の損耗として重く感じられる大きさである。残りは、エッセンシャルワーカーが `crewRequired` の合計から逆算され、医師が受け持ち上限から逆算され、整備士がその残りになる形が自然である。

### U-12. 人員に関する時間の値

第3巻 §7 は次をいずれも「上限がある」「長い」としか書いていない。**訓練に要する時間**（役割の対ごとに異なるとされる）、**医師1人の受け持ち人数の上限**、**累積被曝の閾値**、**成人までの期間**、**寿命による死亡率**、**出生に要る実効重力の下限**。

**放置すると何が起きるか。**§7-5 の `populationGrowthRate` は「余裕の最も小さいものに従う」と定義されているが、上の値が決まらなければ、人口が増えるのに実時間で何時間掛かるかが決まらない。**時間加速の上限が ×131072 であることを考えると、これは「増えるのが速すぎて実感が無い」と「一生増えない」のどちらにもなりうる。**

**推奨は、まず「1000 人が 2000 人になるまでに要する実時間」を1つ決め、そこから逆算することである。**個々の値を先に決めると、掛け合わせた結果が実時間として妥当かどうかを誰も確かめない。

### U-13. テザー式に必要な姿勢表現の拡張の中身

第3巻 §8-6 と決定事項 G-13 は、テザー式が単一の剛体では表せず「姿勢の表現を拡張することになる」と書く。**拡張の中身は書かれていない。**これは第1巻の姿勢積分（`src/physics/attitude.ts`、単一の `Attitude` と単一の `InertiaTensor`）の前提そのものに触れる。

**放置すると何が起きるか。**第3巻 §11-6 が「この巻で最も大きな作業になる」とする作業の見積もりが立たない。着手して初めて範囲が分かる状態が残る。

**決め方の選択肢。**(a) 機体を複数の剛体と拘束の系として一般化する。(b) 回転部と非回転部の2剛体に限定し、両者を1本の回転継手で結ぶ形だけを扱う。(c) 回転部を「見かけの重力を与える属性」として扱い、物理的には回さない。

**推奨は (b) である。**(a) は汎用だが、既存の `Vessel` の姿勢・接触形状・描画・ドッキングのすべてが単一姿勢を前提としており、費用が第3巻の他の全機能を合わせた規模になる。(c) は §8-5 が定める運用（巻き出しで加速度が下がる、推進中は使えない、姿勢制御で回転面が変わる）を1つも表せない。(b) は序盤のトラス式と中盤のテザー式の両方を同じ形で扱え、テザーの柔軟性だけを剛体近似で捨てる。

### U-14. 敵の構成に用いる構造データの選定基準と写像

第3巻 §10-3・§10-4 は、同梱する構造を「あらかじめ選んだ数十から数百」とし、実寸への写像を「目標とする機体の全長に合わせて一様に拡大する」とし、質量を「形状から独立に与える」と書く。**選定基準・目標全長・質量の与え方のいずれも定まっていない。**

**放置すると何が起きるか。**§10-4 が挙げるとおり、慣性テンソルが構造から決まる以上、敵の旋回性能が個体ごとに変わる。目標全長と質量の与え方が決まらなければ、**既存の戦闘の調整をどこから作り直すかが決まらない。**

**推奨は、質量と全長を `EnemyKind` に相当する数個の階級として先に固定し、構造は形状と接続関係と急所の位置だけに使うことである。**§10-4 自身が「『実在の構造を使う』のは形状と接続関係についてのみ」と書いており、これを階級という形で明示すれば、既存の戦闘の調整が階級ごとに引き継げる。

### V-5. 永久影の放熱板の実効性能をいくつに置くか

第2巻 §16-3 は月の永久影の放熱板の実効性能を **200〜400 W/m²** とし、1人あたり 20 kW に要る面積を 50〜100 m² とする。決定事項 G-12 と第3巻 §5・§7-3 は同じものを **918 W/m²**（`2σ(300⁴ − 40⁴)` の計算値そのもの）とし、1人あたり 22 m² とする。**4倍以上の開きがある。**

**これは単なる誤記ではなく、価値判断である。**第3巻 §7-3 は軌道上について「理論上の黒体放射は 300 K の両面で 900 W/m² を超えるが、実際には作動流体の温度が 275〜300 K にとどまり、太陽光と地球赤外の入熱があり、パネル同士が互いを見込むため、実効値はこの1桁下になる」と自ら書いている。**永久影でも作動流体の温度が下がることとパネル同士が互いを見込むことは同じく起きる。**入熱だけが消える。したがって 918 をそのまま実効値とするのは、同じ文書が軌道上に適用した論法を月面に適用していないということである。

| 選択肢 | 開始時の月面基地が支えられる人数（放熱板 21,800 m²、1人 20 kW） |
|---|---|
| 918 W/m²（1人 22 m²） | 約 1000 人 |
| 400 W/m²（1人 50 m²） | 約 436 人 |
| 200 W/m²（1人 100 m²） | 約 218 人 |

**推奨は 400 W/m² である。**理由は、パネル同士の相互放射と作動流体の温度低下という2つの効果は入熱の有無に依らず効き、918 の半分未満に落ちるのが自然だからである。**この値を採ると、第3巻 §7-1 の初期設備の放熱板 21,800 m² は 1000 人を支えられなくなるため、同じ変更セットで 50,000 m² へ改める必要がある**（X-6 を参照）。数字が大きくなること自体は問題ではない — 一辺 224 m の正方形であり、§7-3 が言う「面積そのものは小さくない」がより強く効くだけである。

| (a) 既定の NRHO 基地に最初から武装・戦闘用シールド・放熱板を積む | G-8 の第1段階が B7 を待たずに遊べる |
| (b) B7 まで待つ | 基地の防衛が長期間、遊びとして存在しない |

**推奨は (a) である。**基地は既に `Vessel` であり、既定の部品一式は `src/game/vessel/vessel-parts.ts` の `baseParts` として存在する。**そこに武器・弾薬庫・戦闘用シールドを足すことは、設計編集の実装とは無関係な数行である。**G-8 が定める「基地は移動しない戦闘艦艇として働く」を、進行の最初の段階で実際に遊べる形にできる。ただし U-6（戦闘用シールドが被害をどう肩代わりするか）を先に決める必要がある。

### V-8. 高性能な計算機がどこまで通信圏の依存を緩めるか

第1巻 §16-3、第2巻 §13-1、決定事項 G-1 はいずれも「進行の後半で、より高性能な計算機を導入する余地を残す」と書き、**「どこまで緩めるかは今後の判断」として明示的に開いている。**

| 選択肢 | 帰結 |
|---|---|
| (a) 軌道の誤差を見ての修正まで | 圏外でもノードを実行できるようになる。通信網は「安全のため」に縮む |
| (b) (a) に加えて自動でのドッキング | 無人の補給網が完全に自律する。通信網の価値がほぼ消える |
| (c) (a) に加えて目標の捕捉と追尾 | 無人での戦闘が成立する。第2巻 §13-5 の「戦闘は序盤は有人でしか行えない」が恒久的に覆る |

**推奨は (a) である。**理由は、通信網の配備が第2巻 §13-5 の言う「序盤から中盤への最も大きな段差」であり、それを後から無効化すると、その段差を越えるために払った費用が回収されないためである。(a) だけでも「圏外を通る計画が破綻しなくなる」という実感のある緩和であり、**圏外でも噴射はできるが、そもそも圏外へ行けと命令する手段が無い**という形は残る。

### V-9. 投影面積に外装要素を算入するか（T-10）

第1巻 §11-2 は主軸3方向の投影面積を空力の唯一の入力と定める。実装 `src/game/vessel/mass-properties.ts` は**エッジからのみ投影面積を作り、外装要素は質点として質量にだけ算入する。**既定の有人艦の放熱板は左右合計 50 m²、太陽電池は 7.2 m² であり、船体全体の投影面積（6.8〜12.5 m²）より大きい。

**算入すると抗力が最大で5倍前後になる。**第1巻リスク12 が予告する「F7 の時点でステージ側の高度と時間の調整が要る」が、そのままもう一度起きる。

| 選択肢 | 帰結 |
|---|---|
| (a) 算入する | 展開した放熱板が抗力と輻射圧に効く。低軌道で放熱板を畳む判断が生まれる |
| (b) 算入しない | 現在の再突入の調整がそのまま生きる。§11-2 の定義から外れたままになる |

**推奨は (a) である。**理由は、放熱板を展開したまま低軌道に居続けることが無償である状態が、第2巻 §14-1 が「設計上の最も強い制約の一つであり、かつ見た目にそのまま現れる」と位置づける放熱板の存在感を打ち消すためである。**ただし F8 の変更セットに、ステージの再突入の閾値の再調整を必ず含める。**割り当ては第4巻 §5 のとおり **F8**。

### V-10. 敵の構成（第3巻 §10）を採るか

第3巻 §10 は敵を実在のタンパク質の立体構造から生成する計画である。§10-4 と §11-8 は、**既存の `EnemyKind` ごとの調整が使えなくなり、戦闘の難易度と手応えを作り直すことになり、実装費用の大半はそこに出る**と書く。

| 選択肢 | 帰結 |
|---|---|
| (a) 既存の敵を置き換える | 種類が構造データベースの規模で増える。既存の戦闘の調整が全部やり直しになる |
| (b) 既存の敵を残し、構造由来の敵を新しい種別として足す | 調整が引き継げる。2種類の敵が同じ空にいる理由が要る |
| (c) 採らない | §10-2 が挙げる「急所を手で置く必要がない」「ドロップが構造から決まる」という利点を失う |

**推奨は (b) である。**理由は、§10-2 が挙げる利点のうち最も強いもの——**含まれるアミノ酸の組成がそのまま炭素・窒素の量になり、金属イオンがそのまま希少金属のドロップになる**——が、資源進行の骨格（炭素と窒素は敵からしか得られない）と一貫するためであり、それは既存の敵を消さなくても得られるからである。**2種類が同じ空にいる理由は、進行の段階で置ける**——序盤の敵は既存の手で組んだもの、中盤以降に現れる敵が構造由来のもの、とすれば、§10-4 が言う「同じ設定で戦って同じように振る舞うことが保証されなくなる」ことが、そのまま「新しい敵が現れた」という体験になる。

## X. 矛盾点

### X-1. 初期設備は「最初の一巡」を担うのに、その半分しか同時に動かせない

第1巻 §17-7 は初期設備10基について「**この一組だけが与えられ、以後のすべては自分で作る**」と定め、§17-8 末尾は「最初の一巡だけを §17-7 の初期設備が担う。したがって §17-7 の一組は、**この循環に現れるすべての入力を最初の一度だけ供給できなければならない**」と定める。

一方、追加タスク T-3 が数えたとおり、**初期設備10基の消費電力の合計は 4200 kW であり、初期の太陽電池アレイの発電 2000 kW の 2.1 倍である。**

**両立しない要求である。**「一巡を担う」は10基が一組として働くことを含意するが、電力は半分しか賄えない。T-3 自身は「設備を順番に動かせば進めるため、それ自体は直す必要がない」と結論しているが、**§17-7 と §17-8 の本文はどこにも「順番に動かす」と書いていない。**

**放置すると何が起きるか。**B13（生産設備の稼働）の実装者が、初期設備を同時稼働させる前提で電力収支を組み、開始直後に電力不足で全設備が止まる状態を「不具合」として扱う。あるいは逆に、発電を 4200 kW へ引き上げて §17-9 の「電力が最初の壁になる」を無効化する。

**推奨は、§17-7 に「初期設備は同時には動かせない。どれを動かすかを選ぶことが、最初の意思決定である」と明記することである。**これは §17-9 の設計思想の言い換えであり、値を変えずに矛盾を解消できる。**あわせて B13 に、電力不足時の停止順をプレイヤーが決められることを要求する**——第2巻 §20 の B13 の検証項目は既に「電力不足時の停止順」を挙げており、その停止順が自動で決まるのか選べるのかが、この節の帰結として決まる。

### X-2. 通信基地の到達距離の制約が、初期状態だけの条件として書かれていない

変更事項 C-8 と第2巻 §14-6 は、通信基地の到達距離を「**地球-月間（約 38 万キロメートル）より短い**」と定め、その根拠を「基地側が地球まで届くと、機体側の等級だけで地球低軌道が圏内になってしまう」とする。

一方、第2巻 §13-2 の通信モジュールの等級表は**大型 2,000,000 km** と**深宇宙用 5 AU** を含み、これらは進行に伴って誰でも作れるようになる搭載要素である。C-8 は「通信基地は別種の搭載要素ではなく、到達距離の大きい通信モジュールを積んだ基地である」と定める。**したがって、大型の通信モジュールを基地に積み替えた時点で、C-8 の条件は破れる。**

**両立しない要求である。**C-8 は制約を恒久的な性質として書いているが、成り立つのは初期状態だけである。

**放置すると何が起きるか。**「通信基地の到達距離は 38 万 km 未満」を不変条件として実装した者が、大型モジュールを基地に積む操作を拒否する。あるいは C-8 を読まなかった者が基地に深宇宙用モジュールを積める設計を通し、**通信衛星の配備という遊びが1手で消える。**

**推奨は、C-8 と §14-6 を「初期の通信基地が積む通信モジュールの到達距離」の条件として書き直すことである。**進行に伴って基地の到達距離が伸びること自体は正しい進行であり、禁じるべきものではない。禁じるべきは**開始時点で地球低軌道が圏内になること**だけである。

### X-3. 敵艦は質量特性の直接指定なのか、ツリーを持つのか

第1巻 §5-3 は、敵艦とコンテナについて「ツリーを持たず、設計データも持たない。`MassProperties` をコンストラクタで直接受け取る」「**この経路は暫定ではなく、`Vessel` の恒久的な2つ目の入口である**」と定める。第1巻 §13 も「敵艦・破片・薬莢は事前生成アセットのままとする」と定める。

第3巻 §10-3 は、敵の生成手順の第2段階として「主鎖の折れ曲がりから、**機体のツリー（ノードとエッジ）を構成する**。残基1つがノード1つに、ペプチド結合がエッジ1本に対応する」と定める。第2巻 §19-5 は「敵対勢力の機体 — **ツリーを持つなら**モジュールの判定は働き、モジュールのウィンドウも開く」と、両方の可能性を残した書き方をする。

**両立しない要求である。**第3巻 §10 を実装した時点で、敵艦は §5-3 が定める「恒久的な2つ目の入口」の住人ではなくなる。

**放置すると何が起きるか。**T-12（V-1）の判断がこれに引きずられる。`hostileAssembly` を消す判断は §5-3 に従えば正しく、第3巻 §10 に従えば誤りである。**どちらを採るかを決めないまま T-12 を決めることはできない。**

**推奨は、§5-3 の「恒久的な2つ目の入口」を**コンテナのみ**の性質として書き直すことである。**コンテナは第2巻 §14-5 が「ツリーを持たない `Vessel` として実装する」と明示的に定めており、これは進行によって変わらない。敵艦は V-10 で (b) を採るなら「既存の敵は直接指定、構造由来の敵はツリー」の両方が並び、(a) を採るならツリーのみになる。いずれにせよ**敵艦は §5-3 が言う恒久的な性質を持たない。**

### X-4. 敵のドロップは種別ごとの表か、構造から決まるものか

第1巻 §17-10 は `EnemyDropDef` を「`enemyKind` ごとに、資源 id と質量の範囲を並べたもの」として定め、実装 `src/game/economy/deposit.ts` の `ENEMY_DROPS` はその形である。

第3巻 §10-2 は「**ドロップする資源が構造から決まる。**含まれるアミノ酸の組成がそのまま炭素・窒素の量になり、結合している金属イオンがそのまま希少金属のドロップになる」と定め、これを「炭素と窒素が敵からしか得られないという資源設計と、敵がタンパク質でできているという設定が一貫する」ことの根拠に挙げる。

**両立しない要求である。**構造から決まるなら `enemyKind` ごとの表は不要であり、表があるなら構造から決まっていない。

**放置すると何が起きるか。**B13（敵のドロップ）が `ENEMY_DROPS` の表を前提に実装され、第3巻 §10 がその表を無効化する。§10-2 が挙げる利点のうち最も強いものが失われる。

**推奨は、`EnemyDropDef` を「構造から導いた組成を、その敵の種別に対して固定した結果」として位置づけることである。**表そのものは残る——実行時に構造を数え上げる必要はなく、変換ツール（第3巻 §10-5 の `tools/convert-structures.mjs`）が構造から組成を計算して表に焼き込めばよい。**そうすれば B13 の実装は表を読むままでよく、第3巻 §10 は表の作り方を変えるだけになる。**この位置づけを第1巻 §17-10 に明記する。

### X-5. 熱シールドは加熱を防ぐが、抗力を生まない

第1巻 §11-2 は抗力係数を `Cd = 2.2` の定数とし、「形状の差は投影面積として現れる」と定める。§11-3 は熱シールドについて「遮蔽する立体角の内側からの入熱に耐える」「熱シールドの向きが速度方向から外れると、遮蔽されない方向から加熱を受ける」と定めるが、**熱シールドが投影面積に寄与するとは書いていない。**実装も、外装要素は投影面積に一切寄与しない（V-9）。

第2巻 §15-3 は「双曲線軌道のまま大気の上層を通し、**空力抵抗で減速して捕獲される**」運用を定め、これに要るのが熱シールドであるとする。

**両立しない要求である。**大気掠めは、大きな面を進行方向へ向けて抗力を稼ぐ運用である。熱シールドが抗力に寄与しないなら、熱シールドを積んだ機体と積まない機体で減速量が同じになり、**熱シールドは「同じ減速を、壊れずに耐えられる」ためだけの部品になる。**第2巻 §15-2 の Δv 表の右列（近直線ハロー軌道→地球低軌道が 3.2 → 0.7 km/s）は、抗力そのものが機体の設計に依存しないことを前提にすれば成立するが、そのとき「熱シールドを積むかどうかが軌道計画の選択肢を変える」（第1巻 §6-4）の意味は「耐えられるかどうか」だけに縮む。

**推奨は、熱シールドを投影面積に算入することである**（V-9 の (a) と同じ変更セット）。**そうすれば「大きな熱シールドを積むほど速く減速でき、そのぶんアブレータの消耗も速い」という釣り合いが自動的に出る。**現在の書き方は、その釣り合いを持たないまま「熱シールドを積むと Δv が下がる」という結果だけを表に書いており、原因が実装のどこにも無い。

### X-6. 初期の放熱板の面積が、開始人口を支えられない

第3巻 §7-1 の初期設備の表は、月面基地の放熱板を **21,800 m²** とし、「21.8 m²/人 として 1000人」を支えるとする。この 21.8 m²/人 は、決定事項 G-12 の実効性能 918 W/m² と1人あたり 20 kW から出た値である。

同じ第3巻 §7-3 は、1人あたりの発熱を **14〜22 kW** の幅で示す。第2巻 §16-3 は永久影の実効性能を **200〜400 W/m²** とし、1人あたり 20 kW に **50〜100 m²** を要するとする。

**両立しない要求である。**§16-3 の値を採ると、21,800 m² が支えるのは 218〜436 人であり、**開始人口 1000 人は初日から放熱の上限を超えている。**§7-3 は「現在の人口が上限を上回っている間、超過量に比例した速度で人口が減る」と定めるため、**ゲーム開始と同時に人口が減り始める。**

**放置すると何が起きるか。**第3巻 §7 を実装した時点で、開始直後に人口が減る。原因が「初期設備が足りない」のか「実効性能の値が違う」のかは、どちらの節を読んだかで答えが変わる。

**推奨は、V-5 で 400 W/m² を採り、§7-1 の初期放熱板を 50,000 m² へ改めることである。**一辺 224 m の正方形であり、§7-3 が言う「面積そのものは小さくない。人口を増やせば、そのぶん敷く面積が要る」がより強く効くだけで、設計思想は損なわれない。**同時に、初期設備の4つの値（栽培面積・生命維持・居住容積・放熱板）が「ちょうど 1000 人を支える」ことを、5つの制約（§7-3）すべてについてテストで固定する。**§7-1 は「開始時の人口は上限に等しく、余裕がない」と定めており、**この等式が破れていないことは機械的に確かめられる性質である。**

### X-7. 再突入の成否は姿勢に依存するのに、予測は姿勢を固定する

第1巻 §11-2 は `bcInv` を姿勢依存の値とし、「細長い機体を横に向ければ抗力が数倍になり、進行方向に向ければ最小になる。**これは再突入と軌道の減衰に直接効き**、姿勢を保つことに意味を与える」と定める。§11-3 は「熱シールドの向きが速度方向から外れると、遮蔽されない方向から加熱を受ける。**再突入の姿勢制御に意味が生まれる**」と定める。

一方、第1巻リスク11 は「予測は未来の姿勢を持たないため、**予測では現在の姿勢の値を固定して使う**。姿勢を保っている機体では正確であり、回転している機体では平均から外れる」と定める。

**両立しない要求である。**再突入の成否が姿勢制御の結果に依存するなら、**姿勢を固定した予測は、姿勢制御をこれから行う機体の未来を予測できない。**予測された軌道が「熱シールドを速度方向に向け続けた場合」を示しているのか「いまの姿勢のまま回転せずに落ちた場合」を示しているのかが、同じ線から読み取れない。

**放置すると何が起きるか。**予測された再突入の高度と時刻を見て計画を立てたプレイヤーが、実際にはその通りにならない経験を繰り返す。リスク11 は「再突入の予測が姿勢に依存することを UI で示す必要がある」と書くが、**示したところで、正しい予測は依然として存在しない。**

**推奨は、予測の空力を「主軸3方向の投影面積の平均」で行い、姿勢に依存させないことである。**理由は、姿勢を固定した予測は「いまの姿勢を保ち続ける」という**プレイヤーが選んでいない仮定**を勝手に置くのに対し、平均は「姿勢について何も仮定しない」という中立な仮定だからである。**実際の積分は姿勢依存のまま残す。**そのうえで、予測と実際のずれを「姿勢を保てば予測より落ちにくく、回せば予測より速く落ちる」という一方向の性質として UI に書けば、姿勢制御に意味を与えるという §11-2・§11-3 の目的は損なわれない。

### X-8. トラスは完全剛体だが、回転部と非回転部は分けなければならない

決定事項 D-3 と第1巻 §8-1 は「**トラスは完全剛体として扱う。**長いトラスの先に重い放熱板を付けても撓まず、**機体は1つの剛体として姿勢積分される**」と定める。第2巻 §2 も同じことを繰り返す。

第3巻 §8-1 は、序盤のトラス式の重力区画を「トラス構造で結び、回転半径は数十メートル」と定める。§8-6 は「序盤のトラス式はこの問題を持たない。トラスは剛体であるため、**機体を単一の剛体のまま扱える。回転部と非回転部を分けることは依然として必要だが**、テザーの柔軟性は扱わずに済む」と書く。

**両立しない要求である。**「回転部と非回転部を分ける」ことは、**その2つが異なる角速度を持つ**ということであり、それは単一の姿勢と単一の慣性テンソルで表せない。§8-6 の一文は自分自身で矛盾している——柔軟性が無いことと、角速度が2つあることは別の問題である。

**放置すると何が起きるか。**「序盤のトラス式は既存の姿勢積分のまま実装できる」と読んだ実装者が着手し、回転継手のところで詰まる。第3巻 §12 の依存の順序は「テザー式の重力区画」を最後に置いており、トラス式がそれより早く来ることは前提になっていない。

**推奨は、第3巻 §8-6 を「トラス式もテザー式も、回転部と非回転部の角速度が異なる以上、姿勢の表現の拡張を要する。トラス式が省けるのは**索の柔軟性と長さの変化**だけである」と書き直すことである。**そのうえで、U-13 で推奨した (b)（回転部と非回転部の2剛体を1本の回転継手で結ぶ形）を採れば、**トラス式とテザー式の両方が同じ拡張の上に載る。**費用は前倒しになるが、2回払うことはなくなる。
