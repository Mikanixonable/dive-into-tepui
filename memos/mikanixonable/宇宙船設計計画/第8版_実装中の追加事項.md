## 追加タスク

### T-1. 姿勢積分を非対角成分を持つ慣性テンソルに対応させる（F6 または F7）

`physics/attitude.ts` の `Attitude.inertia` は主慣性モーメント3つを並べた `Vec3` であり、`stepAttitude` はオイラーの運動方程式を**慣性主軸系で**積分する。この形は機体座標系が慣性主軸系と一致していることを前提とする。

第1巻 §9 は断面の慣性乗積 `Ixy` を明示的に扱い、非対称な複合断面では 0 にならないと定めている。§10 はロフトから立体の慣性テンソルを導く。したがって形状から導出した慣性テンソルは一般に非対角成分を持ち、機体座標系は慣性主軸系ではない。

質問事項 Q-1 の決定に従って、`stepAttitude` と `gravityGradientTorque` の引数の型を改める作業が要る。`gravityGradientTorque` は現在 `principalInertia: Vec3` を受け取っている。

### T-2. 産出する設備の無い資源を解消する（R3 の後）

`superconductor`（ヘリウム同位体分離装置の建設に要る）と `chlorine`（過塩素酸塩合成炉の入力）は、第1巻 §17-8 のどの設備の出力にも現れない。塩素はアパタイトから出るが溶融塩の塩化カルシウムに化けるため、単体としては取り出されない。`xenon`（電気推進の推進剤）には §17-3 に産地が無い。

これらは §17-12 の閉包検査が捕まえる対象そのものであり、**検査を先に通してから、どこに設備または産地を足すかを決める。**先回りしてデータを足すと、検査が何も検出しないまま素通りしてしまう。

### T-3. 閉包の検証に電力の実現可能性を加える（§17-12）

第1巻 §17-12 の閉包は資源と設備の到達可能性だけを見ており、電力を見ていない。一方 §17-9 は電力を進行の最初の壁と位置づけている。

**初期設備10基の消費合計は 4200 kW であり、初期の太陽電池アレイの発電 2000 kW の 2.1 倍である。**初期基地は自分の設備の半分しか同時に動かせない。これは §17-9 の設計思想どおりであり、設備を順番に動かせば進めるため、それ自体は直す必要がない。

検査すべきなのは別の性質である。**太陽電池アレイは `solar-panel` さえあれば何基でも建てられるため、`solar-panel` が到達可能になった時点で発電容量は事実上無制限になる。したがって詰まりうるのは `solar-panel` に到達するまでの経路だけであり、その経路上のすべての設備の消費電力が初期発電容量以下でなければならない。**現在の値では、初期発電を単体で超えるのは 10 MW 級の3設備（レゴリス加熱抽出設備・重水素分離装置・ヘリウム同位体分離装置）だけであり、いずれもこの経路には現れない。

**§17-12 にこの検査を加える。**

### T-4. 搭載要素ごとの建造費の表を定める（F5 または第2巻）

第1巻 §6-1 は搭載要素の性能値だけを定めており、**それを作るのに要る資源を持たない。**生産可能性の判定は、設計が申告する `BlueprintPart.buildCost`（1つあたりの資源量）を積み上げる形で経路だけを用意してある。表そのものを埋めるのは、`parts.ts` を §6-1 の一覧に置き換える F5、または第2巻の生産の実装である。

タンク殻の質量も同じく設計側の申告（`BlueprintTank.shellMass`）としてある。§10-3 の肉厚から導くのは F6 の仕事である。

### T-5. ヒドラジンの触媒床に要る白金族の質量を定める

第1巻 §17-2 はヒドラジンのタンクが白金族を要求することを定めるが、**要る質量を定めていない。**生産可能性の判定はこれを「量ではなく所持そのものの要求」として `needed: 0` で表している。この意味は `Requirement` の宣言にコメントで明記してあるが、質量が決まればふつうの資源要求に変えられる。

### T-6. `kerosene` の産出経路を決めるか、登録から外す

第1巻 §17-1 は炭素の用途としてケロシンを挙げるが、§17-8 にケロシンを産出する設備が無く、§15 の推進剤の組にも現れない。産出経路を定めるか、資源の一覧から外すかを決める。

## 質問事項

### Q-1. 非対角成分を持つ慣性テンソルをどちらの形で扱うか

第1巻 §9 と §10 は、形状から導出される慣性テンソルが一般に非対角成分（慣性乗積）を持つことを前提としている。平たい梯子状の配置や側面に取り付けたブースターは、まさにそれを生む形である。一方 `physics/attitude.ts` の姿勢積分は慣性主軸系のオイラー方程式であり、対角成分3つしか受け取らない。取りうる形は2つある。

**案A — 慣性テンソルを対角化し、主軸への回転を機体が持つ。**主慣性モーメント3つと、機体座標系から慣性主軸系への回転クォータニオンを保持する。姿勢積分は現在のまま使える。

**案B — 姿勢積分を対称テンソルに一般化する。**`I ω̇ = τ − ω × (I ω)` を毎ステップ 3×3 の求解で解く。機体座標系ひとつで完結する。

**推奨は案Bである。**理由は3つある。第一に、慣性主軸の向きは推進剤の非対称な消費と多段の分離によって刻々と変わるため、案Aでも結局は毎フレーム対角化することになる。第二に、推力の作用点・RCSの位置・接触カプセル・メッシュ・搭載要素の配置はすべて機体座標系で表されており、座標系を2つ持つより1つで通すほうが単純である。第三に、費用が小さい。対称 3×3 の求解は20演算程度であり、`stepAttitude` が既に行っている RK4 と運動エネルギー射影に対して無視できる。ジャンイベコフ効果を安定させている運動エネルギー射影も `T = ½ωᵀIω` としてそのまま一般化できる。

この判断は F6・F7・F9 の実装に先立って要る。

**決定: 案B を採る。**実装の点検で、非対角成分を落とすことの影響が定量的に測られた。家型断面（対称軸を 0.4 rad 傾けた、§7-1 が例に挙げている形そのもの）の 12 メートルのロフトは `ixx = 425320` / `iyy = 418849` / `izz = 18754` / `ixy = -3143` を持つ。低軌道・天底 0.6 rad の姿勢で重力傾斜トルクを求めると、完全なテンソルでは `τz = -1.5801e-2`、対角成分だけでは `τz = -1.1470e-2` となり、**相対誤差は 27.4%** である。

`ixy` は `ixx` の 0.7% でしかない。それが 27% に増幅されるのは、`τz` が `(Iy − Ix)` という**打ち消し合いの差**で決まるためである。慣性主軸がほぼ揃った細長い機体ほど、この差は小さくなり、慣性乗積の相対的な重みは大きくなる。**非対角成分を落とすことは、自由な形状を許すというこの計画の前提そのものと両立しない。**

### Q-2. 断面とロフトの型を `src/physics/` に置くか `src/game/vessel/` に置くか

第1巻 §9 と §10-2 は、断面の型を `src/game/vessel/cross-section.ts` に、物理量の純関数を `src/physics/section-moments.ts` / `hull-loft.ts` に置くとしている。実装では型も `src/physics/section-moments.ts` に置いてある。`src/physics/` の関数がその型を引数に取る以上、型が `src/game/` にあると `physics/` から `game/` への依存が生まれ、**`tsconfig.test.json` が DOM 無しでこれを解けなくなる**ためである。

**推奨は現状のまま `src/physics/` に置くことである。**断面は「面積と断面二次モーメントを持つ平面図形」であって、機体に固有の概念ではない。`src/game/vessel/` からは再 export すればよい。決めたら §9 と §10-2 のファイル一覧を直す。

## 変更事項

### C-1. 地磁気の双極子軸の方位は ECI に固定する（第1巻 §14-5）

地球の磁気双極子軸は地球とともに自転し、その方位は地表の経度と結びついている。実装した `geomagneticField(r)` は時刻を取らず、双極子軸を自転軸から 11 度だけ春分点側へ倒した ECI 上の固定方向に置く。

**この近似で足りる理由**は、磁気トルカが受ける磁場の変化は機体の公転（低軌道で約90分）が支配的であり、双極子軸の自転（1恒星日）はそれより1桁遅いためである。方位の固定によって生じる誤差は、傾き角 11 度の2倍を上限とする方向のずれに留まり、磁束密度の大きさには実質的に効かない。

**計画書 §14-5 に、この近似とその根拠を明記すること。**現在の §14-5 は署名に時刻を含めておらず、固定であることが読み取れない。

### C-2. `FacilityDef` は発電と「A または B」の入力を表せる形にする（第1巻 §17-6、改訂済み）

第1巻 §17-8 は原子炉と太陽電池アレイの出力を「電力」としているが、`FacilityDef.outputs` は資源しか持てなかった。§17-9 が電力を進行の最初の壁と位置づけている以上、これを表せないデータ構造では §17 全体が成立しない。また原子炉のウランまたはトリウム、電子機器工場の銅またはアルミのように、同じ役を果たす資源が複数ある工程を `inputs` が表せなかった。

**§17-6 を改訂済み。**`powerDraw`（消費 [W]）と `powerOutput`（発電 [W]）の2つを持ち、`inputs` の各要素は `{ anyOf: ResourceId[]; rate: number }` とする。電力は資源ではないので `ResourceLedger` には入れない。送電網は発電も変換もしないので両方 0 である。

### C-3. 初期設備にレゴリス採掘機を加える（第1巻 §17-7、改訂済み）

改訂前の §17-7 の初期設備9基には、レゴリスを産出する設備が無かった。一方その9基に含まれる溶融塩電解炉はレゴリスを入力に要する。§17-8 のレゴリス採掘機は鉄2トンとアルミ1トンで建つが、その鉄とアルミは電解と製錬を経ないと出ない。**字義どおりに読むと、最初の一巡が始まらない。**

**§17-7 を改訂済み。**レゴリス採掘機を初期設備に加えて10基とし、§17-8 の循環の説明にもレゴリスを明記した。

### C-5. 断面重心は多項式ではない（第1巻 §10-2、改訂済み）

改訂前の §10-2 は「断面積 `A(t)`、断面二次モーメント `Ix(t)`/`Iy(t)`/`Ixy(t)`、断面重心 `C(t)` は、いずれも `t` の多項式である」としていた。**断面重心は多項式ではない。**`C(t) = M(t)/A(t)` であり、2次を2次で割った有理関数である。

**結論そのものは正しい。**積分に現れるのは `I(t) + A(t)·|C(t) − C_ref|²` の形だけであり、展開すると平行軸の定理が逆向きに畳まれて原点まわりの生モーメントへ戻るためである。被積分関数はすべて4次以下の多項式になり、閉形式で積分できる。

**実装上の帰結が1つある。**積分は一貫して原点まわりの生モーメントで行い、重心への移動は最後に1回だけ行わなければならない。重心まわりの値を積分しようとすると被積分関数が有理関数になり、閉形式が壊れる。§10-2 を改訂済み。

### C-4. `PORT_WIDTH_RATIO` は `src/physics/` に置く（第1巻 §19）

第1巻 §19 は `PORT_WIDTH_RATIO` を `game/const.ts` に追加するとしている。この値は円断面が側面の口で切り落とす弦の長さを半径に対する比で与えるものであり、断面の面積と断面二次モーメントの計算そのものに要る。`src/physics/` は `game/const.ts` を読めないため、`src/physics/section-moments.ts` に置いてある。**§19 の表からこの行を外す。**

なお既定値 1.0 は、分岐数6の口が互いにちょうど接する上限であり、このとき円断面は正六角形と厳密に一致する（半径 r の円に長さ r の弦は 60 度を張り、6本でちょうど 360 度になる）。§7-3 の「弓形が重なるのは不正」という制約と整合する唯一の解釈である。
