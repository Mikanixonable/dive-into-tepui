# 推進系と推進剤 — 実装計画

この文書は、以下の4つをこのリポジトリに追加するための計画である。

1. 艦艇と軌道基地を単一の実体 `Vessel` に統合する（§3）
2. 搭載要素の型と性能値を定義する（§4）
3. 主機・並進RCS・フライホイールを分離した推進系（§5）
4. 推進剤の種別と、実データに基づくエンジン性能、質量変化を含む燃焼計算（§6）

**この文書は他のどの計画にも依存しない。** 機体の形状は既存の実装のまま扱い、質量・慣性テンソル・推力は搭載要素の合計として求める。ここで定義した搭載要素の型と推進剤の物性は、そのまま後続の2巻が土台として使う。

**後続の2巻との関係** — 第2巻は機体形状を背骨と断面で定義し、質量・重心・慣性テンソル・断面積を形状の帰結として導出する。本文書が定義する搭載要素を「背骨のどのノードに取り付け、どのエッジの内容積に収めるか」は第2巻の担当であり、本文書は取り付け位置を一切扱わない。第3巻は推進剤の配管、タンクの与圧、多段分離、ペイロードを扱う。したがって、エンジンのサイクルごとに定める要求与圧（§6-2）が実際の設計上の制約として意味を持つのは、第3巻でイナートガスと配管が実装されてからである。本文書の段階では、要求与圧はエンジンの型式が持つ性能値として定義されるにとどまる。

---

## 1. 対象外

機体形状の定義、外皮の生成、設計エディタ、設計の保存と生産、資源と生産可能性、推進剤の配管、タンクの与圧、多段分離、ペイロードは本文書の対象外である。月面着陸、月面基地、資源採掘、ドッキングポートによる機体の結合も対象外である。

---

## 2. 設計判断

### 2-1. 実体は `Vessel` 一種類のみとする

艦艇と軌道基地を別のクラスとして持たない。両者はいずれも「部品が載った物体」であり、物理的な差は積んでいる部品だけである。「これは基地か」という判定は存在せず、部品の有無から導かれる能力だけを問う。

### 2-2. 推進は3つの系統に分ける

軌道変更のための大きな Δv、近接機動と姿勢制御の補助、推進剤を消費しない姿勢制御は、それぞれ推力・比推力・応答性・消費資源が異なる。単一のスラスタとして扱わず、主機・並進RCS・フライホイールの3系統に分ける。姿勢トルクをどのアクチュエータが出すかは、要求を受けた側が決める。

### 2-3. 推進剤は登録されたペアからのみ選ぶ

比推力は実測値であり、任意の酸化剤と還元剤の組み合わせに対して定義できない。推進剤は「酸化剤と還元剤のペア」「単推進剤」「固体グレイン」「ハイブリッドの組」として表に登録されたものからのみ選ぶ。表は §6-1 に置く。

### 2-4. 性能値は搭載要素が持つ

推力・比推力・トルク・発電量・放熱量・冷却能力を、機体ごとの定数として持たない。すべて搭載要素の性能値の合計として求める。部品を積み替えれば、他に何も書き換えることなく機体の性能が変わる。

### 2-5. 燃焼は質量変化を含めて計算する

燃焼中は推進剤の消費により質量が減り、加速度が上がる。一定加速度を仮定すると、質量比の大きい機体で点火が遅れてマニューバノードを外す。燃焼時間と点火時刻は、必ず質量変化を含む式で求める。

## 3. 艦艇と基地の統合

### 3-1. 能力は搭載要素から導く

- **軌道基地** = 基地モジュール部品（格納庫・倉庫・生産設備）を積んだ `Vessel`。
- **艦艇** = コックピットと主機を積んだ `Vessel`。
- **無人ブースター** = 自動操縦装置と主機を積み、コックピットを積まない `Vessel`。

```ts
// src/game/vessel/capabilities.ts
export function hasCockpit(v: Vessel): boolean;      // 人が操作できる
export function hasAutopilot(v: Vessel): boolean;    // 無人で計画を実行できる
export function hasBaseModule(v: Vessel): boolean;   // 格納・倉庫・生産・設計ができる
export function hasEngine(v: Vessel): boolean;       // 主機を持つ
export function isOperable(v: Vessel): boolean;      // hasCockpit || hasAutopilot
```

操作対象に選べるのは `isOperable` を満たす機体である。基地ビューを開けるのは `hasBaseModule` を満たす機体である。

### 3-2. `Vessel` が持つもの

| フィールド | 内容 |
|---|---|
| `massProperties: MassProperties` | 乾燥質量・搭載質量・重心・慣性テンソル。搭載物と推進剤残量から導出し、変化時のみ再計算する |
| `propellant: PropellantStore` | 推進剤の種別ごとの残量 |
| `power: PowerSystem` | 発電・蓄電・消費 |
| `thermal: ThermalSystem` | 熱収支 |
| `propulsion: PropulsionSystem` | 主機・並進RCS（§5） |
| `attitudeControl: AttitudeControlSystem` | 姿勢トルクの配分（§5-2） |
| `parts: AnyPart[]` | 搭載要素。HPと性能の唯一の源 |
| `plan: Plan` / `planExecutor: PlanExecutor` | 軌道計画とその自動実行 |

`EntityManager` は `vessels: Vessel[]` という単一の配列を持つ。操作対象は `ActivePlayerController` が `Vessel | null` として保持する。

## 4. 搭載要素

### 4-1. 一覧

搭載要素は、機体の外側に露出する**外装要素**と、機体の内容積を占める**内装要素**に分かれる。

**外装要素**

| 要素 | 主な性能値 |
|---|---|
| 武器 | 発射速度、1発あたりの威力、初速、給弾の要求量 |
| ドッキングポート | 適合クラス、移送速度 |
| 太陽電池パドル | 面積、発電効率、展開の可否 |
| 放熱板 | 面積、放熱効率、展開の可否 |
| エンジン | 対応推進剤、サイクル、推力、比推力、ジンバル可動角、絞り範囲、再着火回数 |
| RCSスラスタ | 推力、対応推進剤、比推力 |

**内装要素**

| 要素 | 主な性能値 |
|---|---|
| 酸化剤タンク | 対応推進剤、容積、断熱等級、要求与圧 |
| 還元剤タンク | 対応推進剤、容積、断熱等級、要求与圧 |
| イナートガスタンク（球状） | 容積、耐圧、充填ガス種別 |
| RCS推進剤タンク | 対応推進剤、容積 |
| バッテリー | 蓄電容量、最大出力 |
| コックピット | 搭乗人数、必要与圧容積 |
| 自動操縦装置 | 計画実行の可否、消費電力 |
| 弾薬庫 | 収納マガジン数 |
| 配管 | 口径、対応推進剤、最大流量 |
| ペイロード倉庫 | 内容積、最大積載質量、開閉の可否 |
| フライホイール | 最大トルク、最大蓄積角運動量、消費電力 |
| 基地モジュール | 格納数、倉庫容量、生産設備 |

**要件の一覧に対する追加** — 上の一覧には、明示的に挙げられていない3つの要素が含まれる。いずれも実装対象とする機能の成立に必要である。

- **RCSスラスタ** — RCS推進剤タンクを積む以上、それを噴射する推進器が必要である。タンクは内装、スラスタは外装であり、別の要素として扱う。
- **フライホイール** — 「RCSガスを消費しない姿勢制御」という機能そのものである（§5）。
- **分離機構** — 多段ブースターシステムの成立に必要である。ただしこれは搭載要素ではなく、機体の構造を切断する辺の種別として扱う。分離は接続の切断であり、取り付ける物ではないためである。詳細は第3巻が扱う。

### 4-2. 性能値の合成

機体の性能は、積んでいる搭載要素の性能値から求める。

| 機体の性能 | 求め方 |
|---|---|
| 総推力 | 主機の推力の合計 |
| 総トルク | フライホイールの最大トルクと、RCSスラスタの推力とモーメントアームの積の合計 |
| 推進剤容量 | 推進剤の種別ごとに、対応するタンクの容積と密度の積の合計 |
| 発電量 | 太陽電池パドルの面積・効率・日射から求めた値の合計 |
| 蓄電容量 | バッテリーの容量の合計 |
| 放熱能力 | 放熱板の面積と効率から求めた値の合計 |
| 装甲 | 各要素のHPの合計。コックピットまたは主要構造を失った時点で0とする |

推進剤の残量は `PropellantStore` が推進剤の種別ごとに保持し、タンクの容積の合計が上限である。どのタンクから減るかは区別しない。

## 5. 推進系

### 5-1. 3つのシステムの役割

| システム | 役割 | 推進剤 | 比推力 | 特性 |
|---|---|---|---|---|
| **主機（EngineBank）** | 軌道変更のための大きな Δv | 液体・固体・ハイブリッド | 265〜450 s | 推力大。始動と停止にコストがある。固体は停止も再着火もできない |
| **並進RCS（TranslationRcs）** | 近接機動・姿勢制御の補助 | 単推進剤または冷ガス | 70〜230 s | 推力小。船体6方向すべてに出せる。応答は即時 |
| **フライホイール（ReactionWheels）** | 姿勢制御のみ | 消費しない（電力のみ） | — | トルク小・連続。**角運動量が飽和する** |

### 5-2. 姿勢トルクの配分

姿勢トルクを要求する主体は、手動操作と自動操縦の2つである。両者は `AttitudeControlSystem` に要求を出し、どのアクチュエータが出すかはそこが決める。

1. 要求トルク τ のうち、各軸でフライホイールが出せるぶんを出す。出せる条件は、そのホイールの最大トルクを超えないことと、蓄積角運動量 `h` が上限 `hMax` に達していないことの両方である。
2. ホイールが τ_wheel を出すと、反作用として角運動量が `h += -τ_wheel · dt` だけ溜まる。同時に電力を消費する。
3. ホイールで出せなかったぶん、および飽和した軸は、RCSスラスタが出す。RCSは推進剤を消費する。
4. `|h|` が `hMax` の既定割合を超えると**アンローディング**を行う。RCSで外部トルクを与えながらホイールを減速し、`h` を外部に捨てる。自動実行を既定とし、手動実行のボタンをHUDに置く。

この規則により、静穏時は推進剤を消費せずに姿勢を保ち、激しい機動の後は必ずRCS推進剤を消費する、という往復が生まれる。RCS残量が戦闘の資源になる。

### 5-3. 並進推力の選択

- 要求方向が主機の推力軸と一致し、要求の大きさがRCSの最大推力を超える場合は主機を使う。
- それ以外はRCSを使う。
- プレイヤーはHUDで「主機を使わない」「主機のみ」を明示的に選べる。

### 5-4. 推力軸と重心のずれ

主機の推力軸が機体重心を通らない場合、その差からトルクが生じる。この効果は正しく計算する。

ジンバル機構を持つ主機は、ずれを打ち消す方向に首を振る。打ち消しきれないぶんは `AttitudeControlSystem` が補償する。ジンバルを持たない主機のずれは補償されず、機体が回る。

### 5-5. モジュール

```
src/physics/attitude-control.ts        (純関数)
    allocateTorque(request, wheelState, wheelSpec, rcsSpec) -> { wheel, rcs, powerDraw }
    desaturationTorque(h, hMax, spec) -> Vec3
src/physics/thrust-alignment.ts        (純関数)
    resultantThrust(engines, throttles) -> { force: Vec3; torqueAboutCom: Vec3 }
    gimbalCorrection(engines, desiredForce, com) -> readonly GimbalAngle[]
src/game/vessel/attitude-control-system.ts
src/game/vessel/propulsion-system.ts
```

### 5-6. 飛行中のHUD

飛行中に**推進系**パネルを置く。個別に折り畳める。主機・並進RCS・フライホイールの3行を持ち、主機は推進剤の種別ごとの残量とイナートガス残量、RCSは残量、フライホイールは蓄積角運動量と上限の比をメーターで表示し、飽和が近い場合は警告色にする。アンローディングの手動実行ボタンをこのパネルに置く。

既存のウィジェット（`src/game/hud/widgets/`）のみで構成し、生の `<button>` および `<input>` を直接書かない。既存のパネルへ統合できないかを追加のたびに確認し、置き場の規約に従う。

## 6. 推進剤とエンジン

### 6-1. 推進剤の物性表

比推力は真空値、密度は貯蔵状態の値である。

**液体（酸化剤と還元剤のペア）**

| ペア | 真空比推力 [s] | 混合比 O/F | 平均密度 [kg/m³] | 貯蔵 |
|---|---|---|---|---|
| 液体酸素 / 液体水素 | 450 | 5.5 | 360 | 極低温・蒸発損失大 |
| 液体酸素 / 液体メタン | 370 | 3.5 | 830 | 極低温・蒸発損失中 |
| 液体酸素 / シラン | 330 | 3.0 | 900 | 酸化剤のみ極低温・自己着火 |
| 四酸化二窒素 / モノメチルヒドラジン | 320 | 2.0 | 1200 | 常温・長期貯蔵可・毒性 |
| 過酸化水素 / ケロシン | 310 | 7.0 | 1290 | 常温・徐々に分解 |

**単推進剤（RCS向け）**

| 推進剤 | 比推力 [s] | 密度 [kg/m³] | 特性 |
|---|---|---|---|
| ヒドラジン（触媒分解） | 230 | 1010 | 長期貯蔵で徐々に分解。毒性 |
| 過酸化水素（触媒分解） | 160 | 1400 | 無毒。分解が速い |
| 窒素冷ガス | 70 | 高圧貯蔵 | 最も単純。電力も点火も不要 |

**固体・ハイブリッド**

| 種別 | 比推力 [s] | 密度 [kg/m³] | 特性 |
|---|---|---|---|
| 固体（過塩素酸アンモニウム + 末端水酸基ポリブタジエン + アルミ粉末） | 265 | 1800 | 点火後は停止も絞りも再点火もできない |
| ハイブリッド（ABS樹脂 + 亜酸化窒素） | 300 | 1100 | 絞れる・停止できる・再点火できる。密度で不利 |

**イナートガス**

| ガス | 密度（20 MPa, 常温） | 特性 |
|---|---|---|
| ヘリウム | 33 kg/m³ | 軽く、極低温でも凝縮しない。必要質量が小さい |
| 窒素 | 230 kg/m³ | 安価だが重い。極低温推進剤には使えない |

固体推進剤の燃料成分はアルミ粉末であり、酸化アルミニウムはその燃焼生成物である。ABS樹脂はハイブリッドロケットの固体燃料側であり、亜酸化窒素または液体酸素の酸化剤と組み合わせて使う。

**選択の意味** — 固体は安価で高密度、ただし一度きりであり、使い捨ての帰投用ブースターに適する。液体酸素／液体水素は比推力が最も高いが密度が低く巨大なタンクを要し、蒸発損失があるため長期の待機に向かない。ヒドラジン系は性能が中位だが常温で長期間待機でき、軌道上に置いておくブースターに適する。

### 6-2. エンジンの型式

エンジンは「サイクル（供給方式）」と「対応推進剤」の組で定義する。同じ推進剤でもサイクルが違えば性能が変わる。

| サイクル | 比推力係数 | 推力重量比 | 要求与圧 | 絞り範囲 | 再着火 | 特徴 |
|---|---|---|---|---|---|---|
| 加圧式 | 0.95 | 低 | 高 | 40〜100% | 無制限 | 構造が単純で信頼性が高い。タンクを高圧に耐える厚さにする必要があり、タンク質量とイナートガスの消費が増える |
| 電気ポンプ式 | 0.98 | 中 | 低 | 30〜100% | 無制限 | 電力を消費する。バッテリー容量が燃焼時間を制限する |
| ガス発生器サイクル | 1.00 | 高 | 低 | 60〜100% | 数回 | 標準的な性能 |
| 段階燃焼サイクル | 1.04 | 高 | 低 | 50〜100% | 数回 | 比推力が最も高い。エンジン質量とコストが大きい |
| エキスパンダーサイクル | 1.03 | 低 | 低 | 30〜100% | 無制限 | 液体水素専用。推力が小さく、上段に適する |
| 固体モーター | 1.00 | 最高 | 不要 | 不可 | 不可 | 点火後は停止できない。配管も与圧も要らない |
| ハイブリッドモーター | 1.00 | 中 | 中 | 20〜100% | 無制限 | 酸化剤のみタンクに持つ |

エンジン部品の比推力は `推進剤ペアの比推力 × サイクルの比推力係数` とする。推力と質量はサイクルとサイズから決める。ジンバル可動角もサイクルごとに定める。

### 6-3. ツィオルコフスキーによる燃焼計算

燃焼時間と点火時刻はツィオルコフスキーの式に基づいて求める。

```
src/physics/tsiolkovsky.ts   (純関数)
    dvFor(m0, mf, isp)               // Δv = Isp·g0·ln(m0/mf)
    massAfterBurn(m0, dv, isp)
    burnTimeFor(dv, m0, thrust, isp) // 推進剤流量 = thrust/(Isp·g0)
    propellantForDv(dv, mDry, isp)
```

一定加速度を仮定すると質量比の大きい機体で点火が遅れてマニューバノードを外すため、質量変化を必ず含める。

### 6-4. 推進剤の劣化

極低温推進剤は日射に応じた蒸発損失を生じ、断熱材の等級と遮蔽で低減できる。ヒドラジン系は触媒毒による自己分解を生じ、時定数は年単位である。固体推進剤とイナートガスは劣化しない。

劣化の計算は毎フレームでは行わず、残量を読む時点で前回の評価時刻からの経過時間に基づいて一括で計算する。

## 7. 段階的な実装計画

各段階は、それ単体で遊べる状態で区切る。

| 段階 | 内容 | 依存 | 検証 |
|---|---|---|---|
| **S1** | `Vessel` への統合（§3）。艦艇と軌道基地を単一クラスにし、能力を搭載要素から導出する。推進系はこの段階では変更しない | なし | 既存の全ステージが動作すること |
| **S2** | 搭載要素の一覧と性能値の合成（§4）。`parts.ts` を §4-1 の一覧に置き換え、機体の性能定数を要素の合計に差し替える | S1 | 既定の構成の総推力・総トルク・総容量が `const.ts` の定数と一致すること |
| **S3** | 推進系の分離（§5-1〜5-2、§5-5）。主機・並進RCS・フライホイールの3系統と、姿勢トルクの配分・飽和・アンローディング | S2 | `attitude-control.test.ts` |

## 9. 主要な技術的リスク

1. **アンローディングの発振** — フライホイールの飽和とRCSによる角運動量の排出は互いを打ち消す方向に働くため、閾値と排出量の取り方によっては、飽和と排出を短周期で繰り返す状態に落ち込む。排出の開始と終了に別々の閾値を設け、開始した排出は下側の閾値に達するまで続けること。

2. **姿勢制御の要求元の一元化** — 現在は手動操作の経路と自動操縦の経路が、それぞれ機体のトルクを直接書いている。両方を `AttitudeControlSystem` への要求に置き換えないと、片方がフライホイールの角運動量を更新せずにトルクを出すことになり、飽和の計算が合わなくなる。トルクを書く箇所を1つに絞ること。

3. **時間加速中の燃焼** — 質量変化を含む燃焼計算は、1ステップが数十秒に達する時間加速下では、ステップ内での質量変化が無視できない。燃焼中のステップは閉形式で質量を進めるか、燃焼の開始と終了の時刻でステップを区切ること。

4. **推力軸のずれによる制御不能** — 主機を非対称に積むと、推力軸が重心を大きく外れる。ジンバル補償で打ち消しきれない構成は、警告を出したうえで、それでも機体が回ることを許すか拒否するかを決めておくこと。

5. **保存形式の互換性** — 機体の表現が変わるため、旧形式の保存データは既定の構成への読み替え以上のことはできない。読み替え不能な保存データは明示的に拒否し、破損した機体を生成しないこと。

6. **UIの総量** — 推進系パネルが飛行中のHUDに加わる。既存のパネルへ統合できないかを確認し、置き場の規約に従うこと。
