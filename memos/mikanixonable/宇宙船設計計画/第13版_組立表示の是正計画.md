# 第13版 組立表示の是正計画

## 1. 何が起きているか

報告された不具合は2つだが、原因は1つである。

- 部品の配置を確定してもゴーストが消えるだけで、その部品が艦の上に現れない。
- すでに搭載された部品を取り外せない。

**編集結果が実メッシュへ反映される経路が、下書きにしか無い。** 下書きは `syncDraftRenders`
(docking.ts:568-586)がセッションの assembly を見て `AssemblyRenderObject` を組み直す。基地と
格納艦にはこれに当たるものがなく、対象の実メッシュは `Vessel.renderObject` そのもの
(docking.ts:475)で、組み直されるのは確定を押した先の `applyTargetAssembly`(docking.ts:698-716)
だけである。`buildHullMesh` の呼び出しはリポジトリ全体で assembly-render-object.ts:65 の1箇所しか
ない。

取り外せないのはこの帰結である。取り外し自体は実装されており、唯一の経路は「3Dで搭載済み部品を
掴み、取付先の無い場所でクリックして離す」(assembly-drag-controller.ts:314-317)。だがセッション上
から消えても実メッシュは組み直されず、さらに `heldOriginal` が null に戻るため docking.ts:515 が
掴んだとき隠した元メッシュを再表示してしまう。外したはずの部品が画面に残るので、失敗したように
しか見えない。パネルに取り外しボタンは無く、この経路の案内も画面上に無い。

同じ原因から、報告されていない破綻が2つ出ている。

- セッション中に付けた部品は実メッシュに無いので `pickAt` が拾えず、付け直しも取り外しもできない。
- セッション中に外した部品は実メッシュに残っているので掴めてしまい、`applyPick` の照合が空振り
  して無反応になる(docking.ts:459-463)。

### 調査中に判明した、報告外の2件

**下書きの鏡像は毎フレーム作り直されている。** 判定は `assembly !== draft.renderedAssembly` の
参照比較(docking.ts:580)だが、`session.getTarget` が `cloneTarget` → `cloneAssembly` で
ディープコピーを返すため(dock-workbench.ts:148-149)、参照は常に不一致になる。編集していなくても
毎フレーム `buildHullMesh` が走る。hull-mesh.ts の冒頭は「生成は形状が変わったときに1度だけ」と
書いており、今の呼ばれ方はその前提を破っている。

**解放漏れがある。** `AssemblyRenderObject.dispose`(assembly-render-object.ts:79-82)は部品
ビジュアルだけを解放し、`buildHullMesh` が作る外皮メッシュの geometry/material は
`partVisualRef` を持たないため対象から漏れる。毎フレーム再生成と組み合わさり、下書きタブを開いて
いる間ずっと積み上がる。

この2件は基地・格納艦へ同じ仕組みを広げる前に直す必要がある。広げてから直すと、基地という
下書きより大きい対象で同じ浪費と漏れを一度作ることになる。

## 2. 方針

**編集中のすべての対象に、セッションが所有する表示用の鏡像を持たせる。実艦のメッシュは編集中だけ
隠す。** 今は下書きだけがこの形で、基地・格納艦だけが「実艦のメッシュを直接見せ、確定まで
組み直さない」例外になっている。例外の側を無くして全対象を揃える。

逆向き(確定前に実艦のメッシュを差し替える)を採らない理由は、**取消の責務が増えるから**である。
今の `cancelAssembly` が「セッションを捨てるだけ」で済んでいるのは、実艦に一切触れていないから
であり、鏡像で見せる限りその不変条件は保たれる。

鏡像は `VesselAssembly` だけで組める(`Vessel` 依存なし)。位置は既存の `placeAtDockSlot` /
`targetPose`(docking.ts:534-547)がそのまま使え、新しい座標計算は要らない。確定経路
(`replaceAssembly` / `commitDockedAssembly`)は変更不要である。

### 訂正

当初「掴み中に実メッシュを隠す仕掛け(`heldOriginal` / `hideHeldOriginal` / `syncHeldOriginal` /
`setPartMeshVisible`)は丸ごと不要になる」と見たが、これは誤りだった。掴んでいる間もセッション上は
艦に載ったままで、外れるのは離した瞬間である(`release` が `workbench.remove` を呼ぶ)。隠す仕組み
自体は残り、**隠す相手が実メッシュから鏡像へ移る**。ただし鏡像は `visuals: Map<partRef, ...>` を
既に持つので、木を traverse する `setPartMeshVisible` と、前回隠した分を戻す巻き戻し帳簿は不要に
なる。

## 3. 要件

R1・R2・R4 は互いに独立で並行できる。R3 は R1・R2 の後。R5 は最後。

### R1 鏡像を作り直す条件を正す

`getTarget` / `targetsSnapshot` のディープコピーを廃し、セッション内部の値をそのまま返す。
参照比較(docking.ts:580)が本来の意図どおり効くようになり、編集が無ければ組み直さない。

根拠: `VesselAssembly` / `VesselTree` / `TreeNode` / `TreeEdge` / `PartPlacement` / `CrossSection`
は骨格が完全に readonly(assembly.ts:7-14, tree.ts:37-77, section-moments.ts:39-41)。唯一の書き手
である assembly-editor の10コマンドはすべて純粋で、in-place 変更は1つも無い。src 全体に
`tree.nodes` / `tree.edges` / `placements` への破壊的操作は無い。`getTarget` の呼び出し7箇所の
うち6箇所は純粋な読み取り。CLAUDE.md の「基本データ型は不変であり、防御的コピーは不要」に
そのまま乗る。

**必ず手当てすること**: `buildDraft`(docking.ts:789-799)がセッションの assembly をそのまま
`createBlueprint` → `new Vessel` へ渡している。`placement.part` は可変オブジェクトであり
(parts.ts:36-46 の `hp`/`maxHp` は非 readonly)、実機の `PartInventory` に入って hp が変化する。
今はたまたま `getTarget` のクローンがこれを防いでいる。クローンを廃す以上、この呼び出しを
`snapshotBeforeBuild` と同じ「実機へ渡す口」へ通す。責務としてもその方が筋で、「実機へ渡す値
だけを複製する」境界が1箇所に揃う。

残すクローン: コンストラクタ(dock-workbench.ts:85-87)、`snapshotBeforeBuild`、在庫 part の
出し入れ(:217-219, :275, :285)。いずれも可変な part が実機とセッションで同じオブジェクトに
なるのを防ぐためであり、理由がある。なお `snapshotBeforeBuild` の `cloneSnapshot(this.snapshot())`
は `snapshot()` が既に深いコピーを返すので二重であり、片方を削れる。

### R2 解放漏れを塞ぐ

`AssemblyRenderObject.dispose` が木全体を歩き、`userData.ownsGeometry` / `ownsMaterial` の印が
立っているものだけを解放するようにする。`GameEntity.dispose` が同じ処理を既に持つので、共通の
関数へ括り出して両者が呼ぶ形にする(`/add-feature` の「既存を探し、再利用可能な形で1箇所に
置き、既存側も置き換える」)。

### R3 鏡像を全対象へ広げる

- `DraftEntry` が持つ鏡像を、下書き専用ではなく**全対象が持つもの**へ一般化する。
  `syncDraftRenders` は `syncTargetRenders` になる。
- 実艦のメッシュを編集中だけ隠す。**基地本体は毎フレーム書き直しが要る** — `syncVessel` が
  毎フレーム `renderObject.visible` を引き直す(vessel.ts:1091)ため、docking の sync を
  `syncVessels` の後に置いて毎フレーム書く(`revealTargetStructure` が既にその形)。
  **格納艦は逆で、一度書けば持続する代わり戻すのも明示的に必要** — `parkVessel` で
  `entities.vessels` から外れており `syncVessel` は二度と走らない。
- ワイヤーフレームを鏡像側へ持たせる。`buildHullMesh` はワイヤーフレームを作らない
  (作るのは `buildVesselWireframe`)ので、持たせないとノード/エッジのピックが死ぬ。
  `revealTargetStructure` は残るが所有者が鏡像へ移る。
- `pickAt` が raycast する root を鏡像にする。`targetRenderRoot`(docking.ts:470-478)の
  実質1行で済む。これで報告外の破綻2件(付けた部品が掴めない/外した部品が掴めて無反応)が
  同時に消える。
- 掴み中の非表示を鏡像の `visuals` 経由にする。`setPartMeshVisible` と巻き戻し帳簿
  (`shownHeldOriginal`)は不要になる。`applyPick` が root を受け取る引数も消える。
- 基地本体の鏡像には `userData['workbenchDraft'] = true` の印を付ける。`replaceAssembly` は
  この印の子を dispose 対象から除く(vessel.ts:634-635)ため、付けないと確定時に取り違える。

### R4 取り外しをUIから到達可能にする

部品棚の隣に「搭載済み」区画を置き、行をクリックすると倉庫へ戻す。倉庫一覧が「押すと掴む」なのに
対し「押すと外す」で対になる。`AssemblySelection` は二値(node/edge)の形のまま触らない — part を
足すと分岐4箇所(assembly-panel.ts:357, 360-362, 405, 542)に手が入り、しかも同じクリックが
`beginDrag` も呼ぶ(docking.ts:464-467)ため「掴み上げ」と「選択」の両立という別の判断が要る。

`DockWorkbenchController.remove`(dock-workbench-controller.ts:86-90)が既にあり未使用なので、
実装ではなく到達路を足すだけになる。ただし `session.removePlacement`(dock-workbench.ts:208-220)は
`validate()` を通していないため、**基地から `base_module` を黙って外せてしまう**。取り外しも検証を
通し、拒まれたら巻き戻す(`applyAssemblyEdit` の 196-206 と同じ形)。

再構築キーは在庫 id ではなく `targetId` + placements の part.id 列にする — 対象間の移動では在庫が
変わらないので、在庫キーのままだと搭載済み一覧が更新されない。

規約(DESIGN-RULES.md): 行は `Button`(生の要素を作らない)、状態は `.on`/`.pressed`/`.disabled` の
3つのみで新設しない、CSS 文字列にリテラルの色や px を書かず `var(--…)` を使う、タップ寸法は
`--hit-target-min`、区画追加後に `win.reclamp()`。再利用できるのは `PART_TYPE_LABELS` /
`formatPartMeta`(inventory-labels.ts)、`partSearchText`、既存の `.asm-panel-group-title` /
`.asm-panel-group-rows` / `.asm-panel-part-row` / `.asm-panel-empty`。

## 4. 検証

`npm run typecheck` は常に。`npm run test:unit`(R1 が dock-workbench の分離を触るため必須)。
`src/physics/` を触らない見込みなので `npm run test:physics` は変更が及んだ場合のみ。
`npm run build`。

R1 には回帰試験を足す: 編集していない対象について `getTarget` が同じ参照を返すこと(鏡像が
組み直されない条件そのもの)と、`buildDraft` の口を通った値が実機と part を共有しないこと。

## 5. 範囲外

- 鏡像に映るのは形状と外装要素だけで、内装要素は元から描かれない(`hull-mesh.ts` の方針)。
  これは今回変えない。
- 部材(構造材)を確定した後の見え方は R3 で部品と同じく直るが、部材の両端を既存ポートへ
  留める(閉じた構造を組む)ことは引き続きできない。CLAUDE.md の「実装されていないもの」に
  残る。
