# 宇宙船設計計画 — 索引

宇宙船の設計・推進・建造・資源・運用に関する実装計画を4巻に分けて置く。**第1巻から第3巻の順序は実装の順序である。**各巻はそれ単体で読んで実装に入れるように書いてある。第4巻は、実装が進んだ現在を出発点として、残っている段階の依存を引き直した作業計画である。

## 第1巻を最初に置く理由

**第1巻は、第2巻と第3巻を並列に進めるための土台である。**第1巻を通した時点で、機体は既定の設計として1つ与えられるものであり、それを編集する手段はまだない。しかし慣性テンソルも接触形状も抗力も形状の帰結になり、推進系は4つに分かれ、推進剤ごとに Δv が変わり、無人機は通信圏の内側でしか動かない。

第1巻の F6（ツリーのデータ構造と設計データの形）・F7（質量特性の適用）と R1〜R3（資源と設備の定義）が済めば、**第2巻と第3巻を同時に進められる。**

## 着手順

**各巻の段階表は、何も実装されていない状態を出発点として依存を引いている。**実装が進んだ現在どこから着手できるかは、依存を引き直した**第4巻 §6 が持つ。**この節はその概要であり、判断の根拠と段階ごとの検証手段は第4巻にある。

**F12（ロフトメッシュの生成）・B6（生産）・F9（姿勢制御系の分離）を並行して始める。**3つは互いに依存せず、それぞれが別の壁を崩す。F12 は設計を編集する組立モード（B7）と、飛行中にモジュールを指すプロパティーウィンドウ（B17）の両方を開く。B6 は設計データと資源の帳簿を初めて到達可能なコードにする。F9 は機体の系列でこれ以上先へ進む唯一の道である。

**B1（分離の物理）と F8（接触形状のカプセル化）は、上の3本と並行できる。**通信パネルと、通信圏の判定のフレーム内記憶（T-14）は、どれとも独立にいつでも置ける。

## この作品の骨格をなす方針

| 方針 | 内容 |
|---|---|
| 実体は1つ | 艦艇・軌道基地・通信衛星・コンテナ・敵艦は、すべて `Vessel` である。専用のクラスを作らない。能力は積んでいる部品から導く |
| 形状は自由、寸法は離散 | 形はノードとエッジのツリーと、各ノードの断面で決まる。ツリーは閉じてよい。**直径もエッジの長さも 0.5 メートル単位**である |
| 物理量は形状の帰結 | 質量・重心・慣性テンソル・投影面積・接触形状は定数として持たず、形状と搭載物から導出する |
| 結合は平面の突き合わせ | 曲面を融合させず、立体の重なりを差し引かない。すべての幾何量が解析式で求まる |
| 技術ツリーはない | 研究点も前提技術の木もない。使えるものは、手に入れた資源と、それを変換する設備の連鎖によって広がる |
| 通貨はない | 市場もない。すべては**資源・設備・電力**を消費する生産によって賄われる。生産設備そのものの生産にも資源が要る |
| 進行は物理的な事実で止まる | 作れないのは技術が未解禁だからではなく、材料か設備か電力が足りないからである |
| 高性能な計算機が存在しない | 機上で自力にできるのは、時刻で駆動する噴射シーケンスと姿勢の保持まで。自動でのドッキング、軌道の誤差修正、目標の追尾、計画の変更は、観測して判断する処理であり外部からの指令を要する |
| 自動操縦は通信を要する | 無人機は通信モジュールを積み、通信圏の内側にいなければ計画を実行できない。通信網は基地から順に伸び、孤立した中継点は働かない。通信衛星は無人の `Vessel` である |
| 戦域は基地の周りから広がる | 序盤は基地自身が敵を迎え撃つ。掃討したのち、月周回軌道・静止軌道・地球低軌道・L1 へと、Δv と通信圏の両方に従って外へ広がる |
| 設計は基地の戦闘ビューの中で行う | 専用のビューも全画面のワークベンチも持たない。**入口はドックモジュールを持つ基地を操作対象にすることである。**その基地の戦闘ビューに組立モードの開閉が現れ、開いている間だけ左右のレールへ編集パネルが加わり、作業領域の枠が線として空間に現れる。機体は周囲の基地や係留中の他機と同じ縮尺・同じ空間に実寸で置かれる。別々に組んだモジュールの結合は、ドッキングと同じ操作である |
| 指せる粒度は見えている粒度 | 戦闘ビューでは機体が実寸で描かれ搭載要素が見えているため、右クリックはモジュール単位で答える。**操作モジュール（コックピット・基地モジュール）を指すことが、機体全体を指すことである。**マップビューでは機体は1つのマーカーであり、右クリックは機体単位である |

**設計の場所と、指せる粒度は、同じ1つの判断から出ている。**形も損傷も、実寸の3D空間でしか判断できない。一覧と数値の画面でしか扱えないものは形を持たず、どこが壊れているかも持たない。全画面の `BaseView` が扱うのは、既に存在する機体と物——格納した艦艇、搭載部品の付け替え、在庫と生産キュー——であり、これから作る形も、いま飛んでいる機体の内訳も、そこには置かない。

## 実装に入る前に想定しておくこと

**スロットル操作の手触りが変わる。**加速度による4段指定を廃し、絞り率 0〜100% の連続値になる。同じキーでも、機体設計によって出る加速度が変わる。第1巻 F10 の時点で起きる。

**保存形式に機体ごとの設計が加わる。**設計を編集できるようになるまで、保存データは既定の設計への読み替えしかできない。読み替え不能な保存データは明示的に拒否する。設計・手動で上書きした配管・段の分離順・資源在庫・建設済み設備を保存に含めるのは第2巻の生産と組立モードの段階である。
