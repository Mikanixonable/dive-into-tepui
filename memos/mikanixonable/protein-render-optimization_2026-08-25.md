# タンパク質の描画・更新の軽量化(2026-08-25)

`744a5d8f`(`0cabea14` / `e46f2d13` / `a5d4f026` / `cd65a720` のマージ)として実施した内容と、
そのとき採った数字・判断の記録。**次に何をすべきか**を最後に置く。

## 何が重かったか

タンパク質敵が居るとき、フレーム時間は **リボン表示の draw call 数**に消えていた。
リボンは二次構造の区間ごとに `THREE.Mesh` を作っており、6n2y では 1 体あたり 989 個。
`cpuRenderMs ≒ mesh 数 × 約 10µs` で説明が付いた(6n2y 989→13.9ms、8ruc 656→6.0ms、5i4r 344→2.9ms)。
分子模型表示が 35,043 原子を 118 個の InstancedMesh に畳んで 2.5ms で済んでいたことが、
**頂点数ではなく mesh 数が効いている**ことの証拠だった。

区間ごとに mesh を分けるために付けていた `userData.proteinComponent` /
`proteinSecondaryKind` は、リポジトリのどこからも読まれていなかった。

## 採らなかった判断と、その理由

**表面(シルエット)の間引きも mesh 統合も入れない。** PyMOL 移行は表面を重くしなかった
(6n2y は 285,457 → 239,866 頂点)。シルエットとリボンの p95 の差は最大 +1.30ms で、
目標に置いた +2ms 以内に収まっている。

表面 mesh の統合(22→1)を見送ったのは、表面が `transparent` かつ `depthWrite:false` で描かれる
ため。three は半透明をオブジェクト単位で奥から手前へ並べて描くので、畳むとその並べ替えが効かなくなり、
混ざる順序が三角形の並び順任せになる。得られるのは 1 体あたり 21 draw call(0.3ms 未満)で、
**半透明の見え方が変わる危険に見合わない。** 不透明なリボンを統合した `a5d4f026` とはここが違う。

**ジオメトリ LOD(断面の分割数を距離で落とす)も入れていない。** 支配的だったのが mesh 数だったため。

## 分かっている副作用

`render-lab` の publication ケースだけ、被写体がわずかに小さく・ずれて写る。このケースは回転させた
状態の `Box3.setFromObject` から構図を決めており、989 個の小 mesh を回転して union した箱より、
鎖ごとに統合した mesh を回転した箱のほうが大きくなる(AABB の粒度)。**ジオメトリは同一**で、
頂点数・三角形数・無回転のバウンディングボックスは統合前後で完全に一致する。

ゲームへの影響は無い。`Enemy` の当たり半径は `proteinRibbonCollision.outerRadius` を優先し、
衝突用リボンは統合していない。フォールバックの `Box3` も構築時は無回転なので値が変わらない。

## 次に効くのは何か

**分子模型(molecular)表示が、いま最も重い経路。** 実測(p95 / max):

| ケース | prepass | forward |
| --- | --- | --- |
| 6n2y molecular 1 体 | 3.30 / 6.50 | 7.80 / 32.10 |
| 8ruc molecular 1 体 | 2.80 / 16.60 | 5.80 / 23.70 |
| 5i4r molecular 10 体 | 6.60 / 6.80 | 6.00 / 11.80 |
| 1mbn molecular 20 体 | 2.70 / 2.90 | 2.40 / 53.70 |

draw call は 118 と少ないので、**draw call ではなく頂点処理・インスタンス数が支配的なはず**
(6n2y で 35,043 原子 × 球 99 頂点 ≒ 347 万頂点)。**ただしこれは未確認の推測** — ヘッドレスでは
`timestamp-query` が使えず GPU 時間を採れていない。

着手するなら次の順:

1. **実機で GPU 時間を採る**(`npm run dev` + `[F3]`)。`0cabea14` で影パスも枠に入ったので、
   パスごとの内訳が読める。分子模型が頂点処理律速かどうかを推測ではなく数字で決める。
2. 頂点処理律速だと確かめられたら、**原子球の分割数(現状 10×8 固定)を投影サイズで落とす**か、
   遠距離で原子を間引く。`src/render/screen-lod.ts` に天体用の投影サイズ計算がある。
3. `max` の突出(1mbn 20 体 forward で 53.7ms)は平均・p95 に現れないスパイク。原因が別
   (生成・GC・シェーダのコンパイル)の可能性があるので**分けて調べる。**
