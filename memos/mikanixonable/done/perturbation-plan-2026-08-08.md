# 摂動モデル拡張の実装計画 — 太陽輻射圧・固体地球潮汐・月の J2

作成日: 2026-08-08
対象リポジトリ: dive-into-tepui2

## 0. この文書の前提(単体で読むための背景)

### 0.1 対象プロジェクト

dive-into-tepui2 は、地球低軌道を舞台とする TypeScript 製の軌道力学シューティングゲームである。物理演算は `src/physics/` 配下に純関数として実装され、THREE.js と DOM に一切依存しない。シミュレーション状態は ECI(地球中心慣性座標系、Y 軸 = 北極、単位は m と m/s)で保持される。

### 0.2 拡張前の加速度モデル(2026-08-08 時点)

質点にかかる加速度の合成は `src/physics/dynamics.ts` のモジュール内私有関数 `accel(r, v, bodies, bcInv)` が唯一の定義箇所であり、以下の 4 項のみを含む。

1. **全登録天体の点質量重力** — `src/physics/attractor.ts` の `attractorAccel(r, body)` を、引数 `bodies` の全要素について加算する。`bodies` は `Ephemeris.attractorsAt(t)` が返す `Attractor[]` で、要素は `SOLAR_SYSTEM` の宣言順に地球・月・木星・太陽の 4 天体である。各項は `μ[(r_b − r)/|r_b − r|³ − r_b/|r_b|³]` の形をとり、第 2 項が「ECI 原点(地球)自身がその天体に引かれて加速する」非慣性補正にあたる。
2. **地球の J2 帯状調和項** — 同ファイルの公開関数 `j2Accel(r)`。定数 `J2_EARTH = 1.08262668e-3` を使い、極軸を Y 軸に固定してハードコードされている。他天体には適用されない。
3. **大気抵抗** — `src/physics/atmosphere.ts` の `dragAccel(r, v, bcInv)`。地球のみが大気を持ち、Vallado の区分指数密度テーブル(高度 0〜1000 km)と地球自転に共回転する大気を仮定する。`bcInv` は弾道係数の逆数 `Cd·A/m` [m²/kg] で、エンティティ種別ごとに `src/game/const.ts` が定数を持つ(艦艇 `SHIP_BCINV = 3.3e-3`、弾丸 `BULLET_BCINV = 2e-4`、小破片 `SMALL_DEBRIS_BCINV = 8e-3`)。
4. **推力** — `stepDynamicsRK4` の引数 `thrust: Vec3 | null` が非 null のときのみ加算される。

積分器は固定ステップの古典的 RK4(`stepOrbitRK4`)である。刻み幅は呼び出し側が決め、`src/physics/attractor.ts` の `localOrbitPeriod(r, bodies)`(最も強く引く天体まわりの円軌道周期)を固定分割数で割った値を使う。

### 0.3 本計画が追加する 3 項

本計画は上記 4 項に対して以下の 3 項を追加する。

- **太陽輻射圧 (Solar Radiation Pressure、以下 SRP)**
- **固体地球潮汐 (Solid Earth Tide)**
- **月の J2 帯状調和項**

## 1. 太陽輻射圧 (SRP)

### 1.1 物理

太陽から放射される光子が宇宙機表面に運動量を与えることによる加速度である。太陽からの距離の 2 乗に反比例し、宇宙機の面積質量比に比例する。大気抵抗と異なり真空中でも作用するため、**大気抵抗がゼロになる高軌道・ラグランジュ点領域では、宇宙機に働く唯一の非重力摂動になる。**

### 1.2 採用するモデル: キャノンボールモデル

宇宙機を反射率一定の球とみなし、姿勢に依存せず太陽 - 宇宙機を結ぶ直線方向に力が働くとする最も標準的なモデルである。加速度は次式で与えられる。

```
a_SRP = ν · P_0 · (AU / d)² · C_R · (A / m) · ŝ
```

各記号の定義は以下のとおり。

| 記号 | 意味 | 値・出典 |
|---|---|---|
| `P_0` | 1 天文単位における太陽輻射圧 | `4.56e-6` N/m²(文献値 4.556〜4.557e-6 Pa) |
| `AU` | 1 天文単位 | `1.495978707e11` m(`SOLAR_SYSTEM.earth.orbit` の半長軸と同値) |
| `d` | 太陽中心から宇宙機までの距離 | ECI では `|r − r_sun|` |
| `C_R` | 輻射圧係数 | 完全吸収体(黒体)で 1、完全反射体で 2。宇宙機は 1.2〜1.5 を採る |
| `A / m` | 断面積質量比 | [m²/kg] |
| `ŝ` | 太陽から宇宙機へ向かう単位ベクトル | `normalize(r − r_sun)` |
| `ν` | 影関数 (shadow function) | 日照 1、本影 0、半影はその中間 |

`C_R` と `A / m` は常に積としてのみ現れるため、**両者を別々に持たず `C_R · A / m` [m²/kg] を 1 つのエンティティ属性として持つ。** これは既存の `bcInv`(`Cd · A / m`)と完全に同じ構造であり、実装上も同じ扱いにできる。

### 1.3 影関数

本プロジェクトには `src/physics/shadow.ts` に `sunlitFactor(r, sunDir, penumbra)` が既に存在する。これは地球を円柱とみなし、影側で地球半径からの距離に応じて `penumbra` [m] の幅で 0→1 へ線形にぼかす関数である。

**この既存関数をそのまま SRP の影関数として使う。** 円錐影(本影・半影を太陽の有限角径から厳密に解く)に置き換えることは行わない。理由は 2 つある。

- 円柱影と円錐影の差は地球近傍で高度数十 km 相当の影境界のずれにとどまり、SRP 自体が本計画の 3 項の中で最も小さい加速度である以上、その内部の精度差はさらに小さい。
- `sunlitFactor` は既にゲーム側の日照判定(`EnvironmentScene` の照明、`RadiatorSystem.solarLoad`、`PowerSystem`)で使われている。SRP だけが別の影判定を持つと、「日照している」の答えがモジュールによって食い違う。

ただし `sunlitFactor` は**地球の影しか扱わない**(内部で `R_EARTH` を直接参照している)。月の影による日食は考慮されない。月近傍で運用する段階になった時点で、この関数を「任意の遮蔽天体に対する日照率」へ一般化する判断が必要になる。本計画ではその一般化を行わず、制約として記録するにとどめる。

### 1.4 加速度の大きさ(検算)

自機の値で見積もる。`src/game/const.ts` の `PLAYER_MASS = 1000` [kg]、`SHIP_BCINV = 3.3e-3` のコメントが記す断面積 `A ≈ 12` m²、`C_R = 1.3` を採ると、

```
C_R · A / m = 1.3 × 12 / 1000 = 1.56e-2 [m²/kg]
a_SRP = 4.56e-6 × 1.56e-2 ≈ 7.1e-8 [m/s²]
```

比較対象として、高度 420 km における大気抵抗を同じ条件で計算する。密度テーブルより `ρ(420 km) ≈ 2.65e-12` kg/m³、軌道速度 `v ≈ 7660` m/s、`SHIP_BCINV = 3.3e-3` として

```
a_drag = 0.5 × 2.65e-12 × 7660² × 3.3e-3 ≈ 2.6e-7 [m/s²]
```

したがって**高度 420 km では SRP は大気抵抗の約 1/4 にとどまる。** 一方、地球 - 月 L1 点(地心距離約 3.2e8 m)では大気抵抗は完全にゼロであり、SRP は上記の値のまま変わらない。**SRP を追加する意義は低軌道ではなくラグランジュ点・月遷移軌道の領域にある。**

### 1.5 既知の不整合(実装前に解消すること)

`src/game/const.ts` の `SHIP_BCINV = 3.3e-3` に付されたコメントは「Cd≈2.2, A≈12m², m≈8t」と記している。これは `2.2 × 12 / 8000 = 3.3e-3` として整合する。しかし同ファイルの `PLAYER_MASS = 1000` [kg] は 8 t ではなく 1 t である。すなわち**弾道係数が仮定する質量と、実際に運動方程式で使われる質量が 8 倍食い違っている。**

SRP 係数を新設する際、同じ断面積と質量から `C_R · A / m` を導くことになるため、この食い違いをそのまま持ち込むと 2 つの非重力摂動が別々の質量を仮定する状態になる。実装の第一歩として、`SHIP_BCINV` を `PLAYER_MASS` と整合する値へ改めるか、`PLAYER_MASS` を 8000 に改めるかを決定する。**どちらが正しいかはゲームバランス上の判断であり、コードからは決まらない。** 質量を変更すると `PlayerThrottle` の加速度(`totalThrust / mass`)と `CollisionPhysics` の換算質量が同時に変わるため、`PLAYER_MASS` 側を動かす場合は影響範囲が広い。断面積 12 m² は機体モデルの実寸から見て過大であり、`SHIP_BCINV` 側を実寸に合わせて再計算する方が波及が小さいと判断する。

### 1.6 実装

#### 1.6.1 新規ファイル `src/physics/srp.ts`

```
// 太陽輻射圧によるキャノンボールモデルの加速度。宇宙機を反射率一定の球とみなし、
// 太陽 - 宇宙機を結ぶ直線方向にのみ力が働くとする。
// srpCoeff は輻射圧係数と断面積質量比の積 C_R·A/m [m²/kg]。0 なら寄与ゼロ。
export function srpAccel(r: Vec3, sun: Attractor, srpCoeff: number, sunlit: number): Vec3
```

引数として `Attractor` 型の太陽そのものを受け取る。`dynamics.ts` の `accel` は既に `bodies: readonly Attractor[]` を持っているため、そこから id が `'sun'` の要素を引いて渡せばよく、新しい引数経路を作る必要がない。

定数 `P_0` と `AU` はこのファイル内に置く。`AU` は `SOLAR_SYSTEM.earth.orbit` の半長軸と数値的に一致するが、**両者は意味が異なる**(天文単位の定義値と、地球軌道の半長軸の実測値がたまたま近い)ため、`solar-system.ts` から取らず独立した定数として定義する。

#### 1.6.2 エンティティ属性の追加

`src/game/dynamic/dynamic-entity/dynamic-entity.ts` の `DynamicEntity` に `bcInv` と並べて `srpCoeff` を追加する。既定値は 0(SRP を受けない)とし、`Ship` が艦艇用の値を、`DebrisPiece` / `Ammo` が破片用の値を上書きする。弾丸(`Bullet`)は寿命が数秒であり SRP の影響が完全に無視できるため 0 のままとする。

対応する定数を `src/game/const.ts` に追加する。命名は `bcInv` の定数群(`SHIP_BCINV` 等)に合わせ、`SHIP_SRP_COEFF` / `SMALL_DEBRIS_SRP_COEFF` とする。

#### 1.6.3 `dynamics.ts` の変更

`accel` と `stepDynamicsRK4` の双方に `srpCoeff: number` を追加する。`accel` の内部で太陽を `bodies` から引き、`shadow.ts` の `sunlitFactor` を呼んで影関数を得たうえで `srpAccel` を加算する。

`sunlitFactor` の第 3 引数 `penumbra` [m] はゲーム側の表現上の値であり `src/physics/` が知ってよい値ではないため、**`stepDynamicsRK4` の引数として呼び出し側から渡す。** これは `bcInv` や大気圏突入高度と同じ扱いである。

`stepDynamicsRK4` の呼び出し元は 3 箇所である。いずれも新しい引数を渡すよう変更する。

- `src/game/dynamic/dynamic-entity/dynamic-entity.ts` の `DynamicEntity.stepSim`(実機の積分)
- `src/game/dynamic/dynamic-entity/dynamic-entity.ts` の `DynamicEntity.stepPrediction`(予測軌道)
- `src/game/plan/plan-arc.ts`(軌道計画の弧)

軌道計画の弧は自機の軌道のみを扱うため、`SHIP_BCINV` を使っているのと同様に `SHIP_SRP_COEFF` を使う。

### 1.7 テスト

`tests/physics/srp.test.ts` を新設し、以下を検証する。

- `srpCoeff = 0` で加速度が厳密にゼロベクトルであること。
- `sunlit = 0`(本影中)で加速度が厳密にゼロベクトルであること。
- 加速度の向きが太陽から宇宙機へ向かう方向と一致すること(内積が正、外積の大きさがゼロ)。
- 地球軌道上(太陽距離 1 AU)で `srpCoeff = 1` のときの大きさが `P_0` に一致すること(逆 2 乗則の基準点の検証)。
- 太陽距離を 2 倍にしたとき加速度が 1/4 になること。

## 2. 固体地球潮汐 (Solid Earth Tide)

### 2.1 物理

月と太陽が地球に及ぼす潮汐力によって地球自身が弾性変形し、その変形が地球の重力場を変える。宇宙機はこの「変形した地球」の重力場を感じる。潮汐力そのもの(月と太陽が宇宙機を直接引く力)は `attractorAccel` の非慣性補正項として**既に完全に実装済み**であり、本節が追加するのは**地球の変形が生む追加ポテンシャル**のみである。この区別を取り違えると二重計上になる。

### 2.2 定式化(導出付き)

潮汐を起こす天体 j(地心距離 `s`、重力定数 `GM_j`)が地球表面に及ぼす 2 次の起潮ポテンシャルは、地心距離 `r` の点で

```
V_2(r) = (GM_j / s) · (r / s)² · P_2(cos θ)
```

である。ここで `θ` は位置ベクトル `r` と天体方向 `s` のなす角、`P_2(x) = (3x² − 1) / 2` はルジャンドル多項式である。

地球がこれに応答して変形した結果、地球外部に生じる追加ポテンシャルは、2 次の Love 数 `k_2` を用いて次のように書ける。次数 n の項は地球外部で `(R_E / r)^(n+1)` として減衰するため、n = 2 では `(R_E / r)³` である。

```
ΔU(r) = k_2 · V_2(R_E) · (R_E / r)³
      = k_2 · (GM_j / s) · (R_E / s)² · (R_E / r)³ · P_2(cos θ)
      = k_2 · GM_j · R_E⁵ / (s³ r³) · P_2(u)     ただし u = r̂ · ŝ
```

加速度は `a = ∇ΔU` である。`K = k_2 · GM_j · R_E⁵ / s³` と置き、`ΔU = K · r⁻³ · (3u² − 1)/2` を勾配する。

`u = (r · ŝ) / r` より `∇u = (ŝ − u r̂) / r` であるから、

```
∇ΔU = K r⁻³ · 3u · (ŝ − u r̂)/r  +  (3u² − 1)/2 · K · (−3 r⁻⁴ r̂)
     = (K / r⁴) [ 3u ŝ − 3u² r̂ − (3/2)(3u² − 1) r̂ ]
     = (K / r⁴) [ 3u ŝ + (3/2 − 15u²/2) r̂ ]
```

したがって最終形は次式となる。

```
a_tide = (k_2 · GM_j · R_E⁵) / (s³ · r⁴) · [ ((3 − 15u²) / 2) · r̂  +  3u · ŝ ]
```

これは Montenbruck & Gill "Satellite Orbits: Models, Methods and Applications" が与える 2 次固体潮汐加速度の標準形と一致する。上記の導出を実装コメントに残さず、**この最終形のみを実装する**(コメント方針により導出過程はコードに書かない。導出は本文書が保持する)。

### 2.3 定数

| 記号 | 値 | 出典・注記 |
|---|---|---|
| `k_2` | `0.30` | IERS Conventions (2010) の公称値は `0.3077 + 0.0036i`。虚部は非弾性による位相遅れを表し、実装しない。周波数依存補正も実装しない |
| `R_E` | `6.378137e6` m | 既存の `R_EARTH_EQ`(赤道半径)を使う。`R_EARTH`(平均半径)ではない |
| `GM_j` | 月 `4.9048695e12`、太陽 `1.32712440018e20` | 既存の `MU_MOON` / `MU_SUN` |

起潮天体は**月と太陽の 2 つのみ**とする。木星の寄与は `GM/s³` の比で月の約 1e-8 であり、単精度以下の量である。

### 2.4 加速度の大きさ(検算)

高度 420 km(`r = 6.798e6` m)における月による寄与を計算する。

```
K_moon = 0.30 × 4.9048695e12 × (6.378137e6)⁵ / (3.844e8)³
       = 0.30 × 4.9048695e12 × 1.0556e34 / 5.680e25
       ≈ 2.73e20
K_moon / r⁴ = 2.73e20 / 2.136e27 ≈ 1.28e-7
```

角括弧内の係数は `u = 0` で 1.5、`u = ±1` で −6 の範囲をとるため、月による加速度は `1.9e-7` 〜 `7.7e-7` m/s² である。太陽の寄与は `GM/s³` の比で月の約 0.46 倍なので、合計の最大は約 `1.1e-6` m/s² となる。

別経路で検算する。潮汐による地球の実効 J2 変動は `k_2 · (M_moon / M_E) · (R_E / s)³ ≈ 0.30 × 0.0123 × 4.57e-6 ≈ 1.7e-8` であり、`J2_EARTH = 1.08e-3` に対する比は `1.6e-5` である。高度 420 km の J2 加速度は `1.23e-2` m/s² であるから、潮汐加速度は `1.23e-2 × 1.6e-5 ≈ 2.0e-7` m/s² となり、上の下限値と一致する。

### 2.5 観測可能性についての率直な評価

**固体地球潮汐は、本プロジェクトのプレイヤーが知覚できる効果を生まない。**

高度 420 km における中心重力は約 `8.6` m/s² であり、固体潮汐加速度はその約 `1e-7` 倍である。実際の宇宙測地学において固体地球潮汐が問題になるのは、衛星レーザー測距が cm 級の軌道決定精度を要求するからであり、本プロジェクトが扱う戦闘・ランデブーのスケール(m 〜 km)では完全に埋没する。

この項の追加は、**「軌道力学的な正確さそのものを目的とする」という価値判断に基づく場合にのみ意味を持つ。** ゲーム体験への寄与を期待して実装すべきものではない。実装コストは小さい(純関数 1 つ、約 15 行)ため、その前提を共有したうえで進めるなら妨げはない。

なお、`dev.md` に記載のある「地球の潮汐力による軌道傾斜角変化」という表現が指す現象は、**月・太陽が宇宙機を直接引く第三体摂動**(既実装)であって本節の固体潮汐ではない可能性が高い。軌道傾斜角の変化として実際に効くのはほぼ全て第三体摂動の側である。要求の意図がそちらであった場合、本節の実装は不要になる。**実装前にこの点を確認することを推奨する。**

### 2.6 実装

#### 2.6.1 新規ファイル `src/physics/tide.ts`

```
// 起潮天体による地球の弾性変形が生む追加重力加速度(2次の固体潮汐)。
// 起潮天体が宇宙機を直接引く力は attractor.ts の attractorAccel が担うので、
// ここには含まれない。
export function solidTideAccel(r: Vec3, raiser: Attractor, k2: number): Vec3
```

`k2` を引数にするか定数にするかは、`k_2` が地球固有の物性値であることから**モジュール定数とする**。ただし関数名と定数名の双方に地球固有であることを明示する(`SOLID_TIDE_K2_EARTH`)。他天体の固体潮汐は本計画の範囲外である。

#### 2.6.2 `dynamics.ts` の変更

`accel` の内部で `bodies` から月と太陽を引き、それぞれについて `solidTideAccel` を呼んで加算する。**地球は ECI 原点に固定されているため、`r` をそのまま渡してよい**(地心相対位置に変換する必要がない)。この前提は `attractor.ts` の `Attractor` 型のコメントが明記している不変条件であり、崩れた場合は本実装も同時に見直す必要がある。

`stepDynamicsRK4` の引数は増えない(全エンティティに一律に効くため、エンティティごとの係数を持たない)。

## 3. 月の J2 帯状調和項

### 3.1 物理

月は自転と固体潮汐により扁平しており、その扁平が生む重力場の非球対称性が月周回軌道に昇交点歳差と近点移動を生じさせる。**本計画の 3 項の中で、これが唯一プレイヤーに知覚可能な効果を生む。**

### 3.2 定数

GRAIL ミッションによる測定値を採用する。

| 記号 | 値 | 注記 |
|---|---|---|
| `J2_MOON` | `203.3e-6` | **非正規化**係数 |
| `C22_MOON` | `22.4e-6` | **非正規化**係数。J2 の約 1/9 |
| 重力場の基準半径 | `1.7380e6` m | **既存の `R_MOON = 1.7374e6` とは異なる値である** |
| `GM_moon` | `4.9048695e12` m³/s² | 既存の `MU_MOON` |

これらは月の主軸座標系 (principal axis frame) で定義される。この座標系では `C21`、`S21`、`S22` が恒等的にゼロになる。

**基準半径について注意する。** GRAIL の係数は基準半径 1738.0 km に対して定義されているが、`src/physics/solar-system.ts` の `R_MOON` は 1737.4 km(平均地形半径)である。両者は 0.6 km 異なる。摂動加速度は基準半径の 2 乗に比例するため、`R_MOON` を流用すると 0.07% の系統誤差が入る。誤差自体は小さいが、**「衝突判定に使う表面半径」と「重力場モデルの基準半径」は別の量である**から、`Attractor` には別のフィールドとして持たせる。この区別を省くと、将来 `R_MOON` を地形データに合わせて更新した瞬間に重力場が静かにずれる。

**係数の正規化について注意する。** 上記は非正規化 (unnormalized) 係数である。GRAIL の配布ファイルや多くの重力場モデルは正規化 (normalized, `C̄nm`) 係数を収録しており、値が桁違いになる。本計画の §3.5 / §3.6.2 に示す加速度の式は非正規化係数を前提とする。**将来係数を外部データから更新する場合、正規化の別を必ず確認する。** 定数名に `_UNNORM` を含めるなどして取り違えを防ぐことを推奨する。

### 3.3 加速度の大きさ(検算)

高度 100 km の低月軌道(`r = 1.838e6` m)における J2 加速度を計算する。

```
a_J2 ≈ 1.5 · J2 · GM_moon · R_moon² / r⁴
     = 1.5 × 203.3e-6 × 4.9048695e12 × (1.738e6)² / (1.838e6)⁴
     = 1.4957e9 × 3.0206e12 / 1.1411e25
     ≈ 3.96e-4 [m/s²]
```

同地点の中心重力は `4.9048695e12 / (1.838e6)² ≈ 1.452` m/s² であるから、相対比は `2.7e-4` である。

比較として、高度 420 km の地球周回軌道における地球 J2 の相対比は `1.5 × 1.08e-3 × (6378/6798)² ≈ 1.43e-3` である。**すなわち低月軌道における月 J2 の相対的な効き方は、低地球軌道における地球 J2 の約 1/5 であり、同じ桁の現象である。** 昇交点歳差として数日から数週間のスケールで明確に観測できる。

#### 3.3.1 地球による第三体摂動との比較

低月軌道では地球の第三体摂動も効く。これは `attractorAccel` として既に実装済みである。両者の大小関係は高度によって逆転するため、境界を求めておく。

月周回軌道にある宇宙機が受ける地球からの差動(潮汐)加速度は、月中心からの距離 `r`、地球 - 月距離 `d` として `a ≈ 2 · GM_earth · r / d³` である。高度 100 km では

```
a_earth3rd = 2 × 3.986e14 × 1.838e6 / (3.844e8)³ ≈ 2.6e-5 [m/s²]
```

月 J2 の `3.96e-4` m/s² に対して約 1/15 である。**高度 100 km の低月軌道では月 J2 が地球第三体摂動より 15 倍強く、支配的である。**

両者は距離依存性が逆(月 J2 は `r⁻⁴`、地球第三体は `r¹`)なので、`1.5 · J2 · GM_moon · R_moon² / r⁴ = 2 · GM_earth · r / d³` を解くと `r ≈ 3.17e6` m、すなわち**高度約 1,430 km で両者が拮抗する。** これより低ければ月 J2 が、高ければ地球第三体摂動が支配する。

### 3.4 最大の実装課題: 月の自転軸の向き

**月の J2 を正しく実装するには、月の自転軸(主軸座標系の極)の ECI における向きが必要である。本プロジェクトはこれを現在まったく持っていない。** これが本計画で最も実装量の大きい部分である。

#### 3.4.1 既存の関数を流用してはならない理由

`src/physics/ephemeris.ts` は `orbitNormalAt(id, t)` と `orbitRotationAt(id, t)` を持つ。これらは**月の公転軌道面の法線**を返すものであり、**月の自転軸ではない。**

月の自転軸は公転軌道法線から約 6.69° 傾いている。誤って公転法線を自転軸として使うと、J2 摂動の方向が 6.69° ずれ、昇交点歳差率に 20% 程度の系統誤差が入る。**この取り違えは容易に起こり、かつテストしなければ気付けない。**

#### 3.4.2 カッシーニの法則による自転軸の構成

月の自転はカッシーニの法則を満たす状態(カッシーニ状態)にある。3 つの法則のうち本実装に必要なのは第 2・第 3 法則である。

- **第 2 法則**: 月の赤道面は黄道面に対して一定角 `1°32′`(= 1.543°)傾く。
- **第 3 法則**: 月の自転軸、公転軌道法線、黄道極は常に同一平面内にあり、自転軸は黄道極を挟んで公転軌道法線の反対側にある。

月の公転軌道傾斜角は黄道に対し `5°09′`(= 5.145°)であるから、自転軸と公転法線のなす角は `1.543° + 5.145° = 6.688°` となる。両者は黄道極まわりを 18.6 年周期(月の交点後退周期)で共に歳差する。

したがって自転軸は次の手順で構成できる。

1. 黄道極 `p̂_ecl` を得る。`src/physics/ecliptic.ts` の `ECL_POLE_ECI` として既に存在する。
2. 時刻 `t` における月の公転軌道法線 `n̂_orb` を得る。`Ephemeris.orbitNormalAt('moon', t)` として既に存在する。
3. `p̂_ecl` から `n̂_orb` へ向かう向きを正として、`p̂_ecl` を `n̂_orb` の反対側へ `1.543°` 回転させる。回転軸は `normalize(cross(p̂_ecl, n̂_orb))` である。

この構成は既存の関数 2 つの合成で済み、新しい軌道要素や歳差モデルを一切必要としない。18.6 年の歳差は `orbitNormalAt` が既に含んでいるため、自転軸の歳差も自動的に追従する。

`n̂_orb` と `p̂_ecl` がほぼ平行になる特異点(外積がゼロに近づく)は、月の軌道傾斜角が 5.145° で一定である以上発生しない。ただし将来この関数を他天体へ一般化する場合には特異点処理が必要になる。

### 3.5 J2 加速度関数の一般化

現在の `src/physics/dynamics.ts` の `j2Accel(r)` は、極軸を Y 軸に固定し、地球の `MU_EARTH` / `R_EARTH_EQ` / `J2_EARTH` をハードコードしている。これを任意の天体・任意の極方向へ一般化する。

一般化した式は次のとおりである。極方向の単位ベクトルを `p̂`、天体中心からの相対位置を `r`、`u = (r̂ · p̂)` として、

```
a_J2 = k · [ (1 − 5u²) · r  +  2 · (r · p̂) · p̂ ]
       ただし k = −(3/2) · J2 · μ · R_ref² / |r|⁵
```

この式が現在の Y 軸固定実装と厳密に一致することは、`p̂ = (0, 1, 0)` を代入すれば確かめられる。そのとき `(r · p̂) = r_y` であり、Y 成分は `k · [r_y(1 − 5u²) + 2r_y] = k · r_y · (3 − 5u²)` となって、現在の実装の `k * r.y * (3 - f)`(`f = 5r_y²/r²`)に一致する。X・Z 成分も同様に一致する。

**この一致は必ずテストで機械的に検証する。** 一般化は既存の地球 J2 の挙動を変えてはならず、`npm run test:physics` の既存の J2 昇交点歳差テスト(高度 420 km・傾斜角 51.6° で約 −5°/日)がそのまま通ることが最低条件である。

### 3.6 C22(赤道の楕円性)を含めるべきか — 地球との決定的な違い

**「J2 だけを実装する」という判断は、地球に対しては妥当だが、月に対しては妥当でない。** この非対称性が月の重力場を扱ううえで最も重要な事実であり、実装方針を左右する。

2 次の重力場係数のうち、`J2`(= `−C20`、極方向の扁平)と `C22`(赤道断面の楕円性)の比を両天体で比較する。

| 天体 | `J2` | `C22` | `J2 / C22` |
|---|---|---|---|
| 地球 | `1.0826e-3` | `1.574e-6` | **約 690** |
| 月 | `203.3e-6` | `22.4e-6` | **約 9** |

地球では `J2` が `C22` の約 690 倍あるため、`J2` のみを取って他の 2 次項を捨てる近似が非常によく効く。地球の重力場は事実上「回転対称な扁平」である。

**月ではその比が約 9 しかない。** 月の重力場は回転対称からのずれが大きく、`J2` だけを取ると 2 次項の中で 1 割強を占める寄与を落とすことになる。文献上も、月周回軌道の臨界傾斜角の解析では `J2` と `C22` の両方が必要とされ、`J2` のみを含めた場合と両方を含めた場合とで固定点の性質そのもの(傾斜角と近点引数が同時に一定に保たれるかどうか)が変わることが示されている。

さらに広い文脈として、低月軌道は**マスコン(質量集中)による強い非球対称性のため、ほとんどの円軌道が力学的に不安定**であることが知られている。実際の月周回ミッションの軌道決定では 100 次程度までの球面調和展開が使われ、GRAIL による重力場モデルは 660 次まで求められている。**「月の重力場を正確に扱う」ことを本気で追求すると、J2 と C22 で止まる地点は存在しない。**

#### 3.6.1 判断

以上を踏まえた本計画の方針は次のとおりである。

- **`J2` と `C22` は一組として実装する。** `C22` を落とすことは、地球で `J2` を落とすことに近い水準の近似になる。「月の J2 摂動を追加した」と言いながら 2 次項の 1 割強を捨てるのは、正確さを目的とする本計画の趣旨と整合しない。
- **3 次以上の項とマスコンには踏み込まない。** ゲームとして必要な精度は「低月軌道が定性的に正しく歳差する」ことであり、実際の軌道決定精度ではない。この線引きは明示的な設計判断として記録する。
- 結果として得られるのは「回転対称でない 2 次の重力場」であり、**マスコンによる低月軌道の不安定性は再現されない。** 本プロジェクトの月周回軌道は現実より安定に振る舞う。これは意図した割り切りである。

#### 3.6.2 C22 の実装に必要な追加要素

`C22` を含めるには、極方向に加えて**主軸座標系の X 軸(月の最小慣性モーメント軸 = 長軸)方向**が必要になる。

月は潮汐固定されているため長軸は概ね地球を向く。得られた長軸方向を極方向に対して直交化(Gram-Schmidt)すれば主軸座標系が完成する。すなわち月の主軸座標系は、**極方向(カッシーニの法則、§3.4.2)と長軸方向の 2 本**で決まる。

**`C22` は `cos 2λ` の 2 回対称性を持つため、長軸の「どちら向きか」は結果に影響しない。** 軸の向き(直線としての方向)だけが必要であり、地球側か反対側かを区別する必要はない。

長軸方向の取り方には §3.6.3 に示す未決の選択がある。

#### 3.6.3 長軸方向は平均黄経で取る(決定済み)

**潮汐固定された天体は一様に自転する。** したがってその本初子午線(長軸)が慣性空間で指す方向は**平均黄経**に追従する。一方、地球 - 月を結ぶ方向は**真黄経**に追従する。両者の差が経度方向の光学秤動であり、その大きさは中心差(equation of center)`≈ 2e sin M` で、月の離心率 `e = 0.0549` に対して**最大約 6.3°** に達する。

すなわち「長軸 = 地球方向」という近似は、最大 6.3° の系統誤差を含む。`C22` のポテンシャルは `cos 2λ` に比例するため、経度の誤差は 2 倍されて位相に効き、**`C22` 項に最大 20% 程度の誤差**を与える。`C22` は 2 次項全体の約 1 割であるから、2 次摂動全体としては最大 2% 程度の誤差になる。

選択肢は 3 つある。

| 選択肢 | 取り方 | 本初子午線に対する誤差 | 実装コスト |
|---|---|---|---|
| (a) 平均黄経 | 平均黄経 `L` から面内角 `u = L − Ω` を組む | ほぼ 0(物理的に正しい) | `src/physics/kepler-orbit.ts` に平均角版の基底を返す関数を追加する必要がある |
| (b) 平均要素の真方向 | `Ephemeris.orbitRotationAt('moon', t)` の x̂ をそのまま使う | 最大 約 6.3° | 既存関数をそのまま呼ぶだけ |
| (c) 実位置方向 | `normalize(negate(positionOf('moon', t)))` | 最大 約 6.3° + 1.4° | 既存関数をそのまま呼ぶだけ |

`src/physics/kepler-orbit.ts` の `keplerOrbitRotation` は面内角を `u = ν + argp`(真近点角 `ν`)として組んでいるため、選択肢 (b) に該当する。選択肢 (c) はさらに周期摂動項ぶん(主に出差 1.274°)ずれるため、(b) より劣り採用しない。

**推奨は (a) である。** 潮汐固定天体の自転を一様回転として扱うことは近似ではなく物理そのものであり、(b) は「一様自転する天体の子午線を非一様な公転角で追う」という誤りを含む。追加コストは `kepler-orbit.ts` に平均角から基底を組む関数を 1 つ足すことのみで、既存の `keplerOrbitRotation` と大部分を共有できる。

**この選択は本計画で未決であり、実装着手前に決定する。**

#### 3.6.4 物理秤動を扱わないこと

月には上記の光学秤動(見かけ)とは別に、実際に自転軸と自転速度が振動する物理秤動が存在する。振幅は経度方向で 0.03° 程度と小さく、**本計画では扱わない。** これは明示的な割り切りとして記録する。

2 次・2 階の項を含めた加速度は、`J2` の項に次を加算した形になる。単位ベクトル `x̂`(長軸)、`ŷ = cross(p̂, x̂)`、`p̂`(極)で張る主軸座標系において、相対位置の成分を `(x, y, z)`(`z` が極方向)とすると、`C22` によるポテンシャルは

```
U_22 = 3 · C22 · μ · R_ref² · (x² − y²) / r⁵
```

であり、その勾配が加速度になる。実装は主軸座標系で成分計算し、結果を ECI へ戻す形が最も見通しがよい。

### 3.7 実装

#### 3.7.1 `src/physics/dynamics.ts` の変更

`j2Accel(r)` を次の形へ一般化する。ファイル冒頭のモジュールコメントも「地球 J2 摂動」から対象天体を限定しない記述へ改める。

```
// 帯状調和 J2 による摂動加速度。rRel は天体中心からの相対位置、pole は自転軸の単位ベクトル。
export function j2Accel(rRel: Vec3, mu: number, refRadius: number, j2: number, pole: Vec3): Vec3
```

`J2_EARTH` は `dynamics.ts` に残す(`src/game/creative/ship-placer-panel.ts` が太陽同期軌道の傾斜角を導出するために読んでおり、積分器と同じ係数を参照する必要がある)。`J2_MOON` は月の静的事実であるから `src/physics/solar-system.ts` に置き、`CelestialBodyDef` の衛星バリアントへ任意項目として追加する。

**`CelestialBodyDef` へ J2 を持たせる設計を採る。** 天体ごとの `if` 分岐を `dynamics.ts` に書くのではなく、天体定義が「自分は J2 を持つか、いくつか」を宣言し、`accel` はそれを一様に読む。これは `Ephemeris` が「name-specific branch を持たず、すべて `SOLAR_SYSTEM[id].kind` で分岐する」という既存の設計方針と一致する。地球の J2 も同じ仕組みに載せられるが、地球は ECI 原点に固定されており極が Y 軸である特殊性があるため、**地球も含めて一様に扱う**ことで分岐を消す。

#### 3.7.2 `src/physics/ephemeris.ts` の変更

自転軸を返す公開メソッドを追加する。

```
// 天体 id の自転軸(主軸座標系の極)の ECI 単位ベクトル。
spinAxisAt(id: AttractorId, t: number): Vec3
```

地球は Y 軸固定(`v3(0, 1, 0)`)を返す。月はカッシーニの法則(§3.4.2)による構成を返す。木星と太陽は本計画では J2 を持たないため、自転軸を要求されない。ただしメソッドの戻り値型を `Vec3 | null` にして「自転軸を定義しない天体」を表現するか、全天体に何らかの軸を返すかは設計判断である。**`Attractor` 型に `spinAxis` と `j2` を含める方が呼び出し側が単純になる**(`attractorsAt(t)` が既に全天体分を組み立てているため、そこで一度だけ解決すればよく、`accel` が `Ephemeris` を参照する必要がなくなる)。この方針を採る。

すなわち `Attractor` 型を次のように拡張する。

```
export type Attractor = {
  readonly id: AttractorId;
  readonly mu: number;
  readonly radius: number;
  readonly state: OrbitState;
  readonly j2: number;        // 帯状調和 J2 係数。0 なら扁平を考慮しない
  readonly j2Radius: number;  // J2 の基準半径 [m]
  readonly spinAxis: Vec3;    // 自転軸の ECI 単位ベクトル
};
```

`attractorsAt(t)` はこの 3 つを埋めて返す。`dynamics.ts` の `accel` は `bodies` をループする際に `body.j2 !== 0` の天体について `j2Accel` を呼ぶ。**これにより天体名による分岐が `dynamics.ts` から完全に消える。**

なお `Attractor` を構築している箇所は `attractorsAt` のみではない可能性があるため、型を広げた時点で `npm run typecheck` が未対応箇所を列挙する。テストコード内で `Attractor` を手組みしている箇所も同様に修正が要る。

#### 3.7.3 月中心相対位置の受け渡し

`j2Accel` は天体中心からの相対位置を取る。地球は ECI 原点にあるため `r` をそのまま渡せるが、月は原点にないため `sub(r, body.state.r)` が必要である。`accel` のループ内でこの減算を行う。

### 3.8 テスト

`tests/physics/dynamics.test.ts` を拡張し、以下を検証する。

- **回帰保護**: `pole = (0, 1, 0)`、地球のパラメータを与えた `j2Accel` が、一般化前の Y 軸固定実装と機械精度で一致すること。既存の「高度 420 km・傾斜角 51.6° で昇交点歳差 約 −5°/日」テストがそのまま通ること。
- **極方向の回転不変性**: 位置ベクトルと極ベクトルを同一の回転で回したとき、加速度も同じ回転で写ること。極を Y 軸に固定していた実装では検証できなかった性質であり、一般化が正しいことの中心的な証拠になる。
- **月の自転軸**: `spinAxisAt('moon', t)` が返すベクトルと黄道極のなす角が全時刻で `1.543° ± 0.01°` であること(カッシーニ第 2 法則)。
- **カッシーニ第 3 法則**: 自転軸・公転軌道法線・黄道極の 3 ベクトルが同一平面上にあること(スカラー三重積がゼロ)。かつ自転軸と公転法線のなす角が `6.688° ± 0.01°` であること。
- **月 J2 の昇交点歳差**: 高度 100 km・傾斜角 90° の低月軌道を 1 日積分し、昇交点赤経の変化率が理論値と一致すること。理論値は `dΩ/dt = −(3/2) · J2 · (R/p)² · n · cos i` から求める(傾斜角 90° では `cos i = 0` となり歳差しないため、テストには傾斜角 45° など `cos i ≠ 0` の軌道を使う)。
- **加速度の大きさ**: 高度 100 km の低月軌道で月 J2 加速度が `3.96e-4 ± 5%` m/s² であること(§3.3 の検算値のピン留め)。

#### 3.10.1 【未決】`Attractor` への重力場データの持たせ方

§3.7.2 では `Attractor` に `j2` / `j2Radius` / `spinAxis` を平坦に追加する案を示したが、`C22` を加えると長軸方向も必要になり、フィールドが 5 つに増える。ここで問題になるのは、**太陽と木星は 2 次重力場モデルを持たないにもかかわらず、型としては極方向と長軸方向を要求されてしまう**点である。意味のない単位ベクトルを埋めることになる。

代替案は、2 次重力場を 1 つの入れ子オブジェクトにまとめ、持たない天体は `null` とすることである。

```
export type Degree2Gravity = {
  readonly j2: number;
  readonly c22: number;       // 0 なら軸対称
  readonly refRadius: number; // 係数が定義された基準半径 [m](表面半径とは別物)
  readonly pole: Vec3;        // 自転軸の単位ベクトル(ECI)
  readonly longAxis: Vec3;    // 主軸座標系の長軸の単位ベクトル(ECI)。c22 === 0 のとき未使用
};

export type Attractor = {
  // 既存のフィールド
  readonly degree2: Degree2Gravity | null; // null なら質点として扱う
};
```

この形なら「2 次重力場を持つかどうか」が型で表現され、`dynamics.ts` の `accel` は `if (body.degree2 !== null)` の 1 分岐だけで済む。**推奨はこちらである。**

いずれの案でも `Attractor` を構築している既存箇所すべての修正が要る。確認済みの構築点は以下である。

- `src/physics/ephemeris.ts` の `attractorsAt`(本体)
- `src/game/celestial/environment-scene.ts` の `EARTH_ATTRACTOR`(ハードコードされた地球の `Attractor`)
- `tests/physics/dynamics.test.ts`、`tests/physics/attractor.test.ts`、`tests/physics/elements.test.ts`、`tests/physics/kepler-orbit.test.ts`

#### 3.10.2 【未決】`C22` をどう検証するか

`J2` は「昇交点歳差率 `dΩ/dt = −(3/2) · J2 · (R/p)² · n · cos i`」という閉じた解析式を持つため、積分結果と突き合わせるテストが書ける。**`C22` にはこれに相当する単純な永年変化率が存在しない**(軸対称性を破るため、経度に依存した周期的な効果が主になる)。

したがって `C22` の検証には別のオラクルが必要である。推奨は**ポテンシャルの数値勾配との突き合わせ**である。すなわち `U_22 = 3 · C22 · μ · R_ref² · (x² − y²) / r⁵` をスカラー関数として別に実装し、中心差分で数値微分した結果と、実装した解析的加速度が機械精度に近い範囲で一致することを確認する。この方式は解析式の導出ミスと符号ミスの両方を捕まえられる。

併せて以下も検証する。

- 長軸方向を 90° 回した位置で `C22` 項の符号が反転すること(2 回対称性)。
- 極方向から見て `C22` 項が経度について 2 周期の変化を示すこと。
- `c22 = 0` のとき結果が `J2` のみの場合と厳密に一致すること。

#### 3.10.3 影響しないと判断した箇所(実装者が迷わないための明示)

- **`strongestAttractor` と `localOrbitPeriod` は変更しない。** どちらも `attractorAccel`(質点重力)だけで判断する。`J2` / `C22` は「どの天体が支配的か」も「軌道運動の時間スケール」も変えないため、これらに 2 次項を混ぜる理由がない。
- **`elementsAround` は変更しない。** 状態ベクトルから接触軌道要素を出す計算であり、重力場の形には依存しない。
- **予測軌道 (`DynamicEntity.stepPrediction`) と軌道計画の弧 (`plan-arc.ts`) は変更不要で自動的に追従する。** どちらも `stepDynamicsRK4` に `bodies` を渡しており、2 次重力場は `Attractor` に載るため、引数の追加なしに反映される。

#### 3.10.4 性能に関する確認事項

`src/physics/ephemeris.ts` の冒頭コメントは「メモ化はしない — 呼び出し順に依存する隠れた制約を作らず、毎回すべてを素直に評価する」と明記しており、実際に `attractorsAt(t)` は呼ばれるたびに太陽系の合成を最初から評価する。この呼び出しは `DynamicEntity.stepSim` からエンティティごと・積分ステップごとに走る。

**`CLAUDE.md` には「`Ephemeris` が直前の参照をメモ化するので共有値が回収される」という趣旨の記述があるが、これはコードと一致していない。** 本計画の実装と同じ変更セットで `CLAUDE.md` のこの記述を修正する。

極方向(カッシーニの構成)と長軸方向を `attractorsAt` の中で毎回計算すると、三角関数と外積がそのぶん増える。ただし `attractorsAt` は既に月の周期摂動級数(34 項)を評価しており、追加分はその一部にすぎない。**推測で最適化せず、まず素直に実装して `?perf=1` で計測する。** 問題が出た場合の対処は、`src/physics/` への可変スクラッチの再導入ではなく(それは意図的に撤去された設計判断である)、`Ephemeris` 側でのメモ化の是非を改めて設計判断として扱うことである。

## 5. 性能への影響

`accel` は RK4 の各段(k1〜k4)で呼ばれるため、1 積分ステップあたり 4 回評価される。これが全エンティティ分、さらに予測軌道と軌道計画の弧の分だけ走る。

追加される計算量は 1 回の `accel` あたり以下である。

- 月の J2: 減算 1 回と `j2Accel` 1 回。地球の J2 が既に毎回走っているため、増分はその 2 倍以下。
- SRP: 平方根 1 回、除算数回、`sunlitFactor` 1 回(内積 1・平方根 1)。
- 固体潮汐: 2 天体分の `solidTideAccel`。各々 `r⁻⁴` と `s⁻³` の計算で平方根 2 回程度。

いずれも既存の `attractorAccel` を 4 天体分ループしている現在のコストと同じ桁であり、`accel` 全体で最大 2 倍程度の増加を見込む。

`CLAUDE.md` に記録された既存の計測値では、`stepOrbitRK4` は 1 ステップあたり約 2190 ns、典型的な約 400 エンティティで update フェーズ全体が約 5 ms である。`accel` の倍化はこのうち積分部分のみに効くため、フレーム時間の増加は 1 ms 前後と見積もる。**実測せずに最適化しないこと。** 問題が出た場合の対処は、`src/physics/` に可変スクラッチを再導入することではなく(それは意図的に撤去された設計判断である)、物理 LOD の導入である。

固体潮汐と SRP は地球近傍で中心重力の 1e-7 倍しかないため、**遠方のデブリや弾丸に対しては計算を省いてよい。** ただしその判定を入れること自体がコストになるため、`srpCoeff = 0` / `j2 = 0` という既定値による早期リターンで済ませ、明示的な距離判定は入れない。

## 7. 3 項の効果の要約

高度 420 km の地球周回軌道および高度 100 km の低月軌道における、各摂動の加速度の大きさを 1 つの表にまとめる。中心重力に対する比を併記する。

| 項目 | 高度 420 km 地球周回 | 高度 100 km 低月軌道 | 実装状態 |
|---|---|---|---|
| 中心重力 | `8.6` m/s² | `1.45` m/s² | 実装済 |
| 地球 J2 | `1.2e-2` m/s²(比 `1.4e-3`) | — | 実装済 |
| 大気抵抗(艦艇) | `2.6e-7` m/s² | 0(大気なし) | 実装済 |
| 第三体 — 地球 | — | `2.6e-5` m/s² | 実装済 |
| 第三体 — 月・太陽・木星 | 実装済 | — | 実装済 |
| **月 J2** | — | **`4.0e-4` m/s²(比 `2.7e-4`)** | **本計画** |
| **月 C22** | — | **月 J2 の約 1/9** | **本計画** |
| **太陽輻射圧** | `7.1e-8` m/s² | `7.1e-8` m/s² | **本計画** |
| **固体地球潮汐** | `2e-7` 〜 `1.1e-6` m/s² | 無視可能 | **本計画** |

この表から読み取るべき結論は以下の 4 点である。

1. **月の J2 のみがプレイヤーに知覚可能な効果を生む。** 低月軌道における相対的な効き方は低地球軌道における地球 J2 の約 1/5 であり、昇交点歳差として数日スケールで観測できる。高度 100 km では地球の第三体摂動より 15 倍強く、支配的である(拮抗する高度は約 1,430 km)。
2. **月については J2 と C22 を一組として扱う必要がある。** `J2 / C22` の比は地球で約 690、月で約 9 であり、地球で成り立つ「J2 だけ取れば十分」という近似が月では成り立たない。J2 のみで止めると、Orbiter が抱えているのと同じ「実装したが月には効かない」状態になる。
3. **太陽輻射圧は地球近傍では無意味に近いが、ラグランジュ点領域では唯一残る非重力摂動になる。** 大気抵抗がゼロになり固体潮汐も距離の 4 乗で消えるため、そこでは相対的に支配的である。`dev.md` が掲げるハロー軌道・低エネルギー遷移の領域へ進む前提として意味がある。
4. **固体地球潮汐は中心重力の約 1e-7 であり、本プロジェクトのスケールでは知覚できない。** 実装は「正確さそのものを目的とする」価値判断に基づく場合にのみ正当化される。実装コストは小さいため、その前提を共有したうえで進めるなら妨げはない。
