## 1. 現状(2026-08-09 時点のコードの事実)

- 登録済み天体は **太陽・地球・月・木星の4体**(`src/physics/solar-system.ts` の
  `SOLAR_SYSTEM`)。
- 天体IDは閉じた文字列リテラル union(`src/physics/attractor.ts` の
  `StarId`/`PlanetId`/`SatelliteId`)。IDを1つ追加すると、コンパイルエラーで登録を
  強制されるレジストリが **3つ**ある:
  1. `SOLAR_SYSTEM`(solar-system.ts、`satisfies Record<AttractorId, CelestialBodyDef>`)
  2. `CELESTIAL_BODIES`(game/celestial/celestial-registry.ts、`Record<AttractorId, …>`)
  3. `LAGRANGE_DEFAULT_AMPLITUDE_KM`(game/creative/ship-placer-panel.ts:110、
     `Record<OrbitingId, {ax, az}>` — ハロー軌道の既定振幅を天体ごとにゲーム定数で要求する)
  それ以外(マップの参照軌道線、`SphereBody` の表示距離定数、テスト、文書)は型で
  強制されず手作業で足す。天体の日本語表示名(`hud/frame-labels.ts` の `ATTRACTOR_NAMES`、
  `focus-markers.ts` の `LABEL_NAMES`、`FRAME_ITEMS`)はいずれも `CELESTIAL_BODIES` からの
  `Object.fromEntries` 導出なので、名前の追加作業は `CELESTIAL_BODIES` の1箇所で足りる。
- 惑星の軌道は `planet-orbit.ts` の `PlanetOrbit`(Standish 型: ケプラー要素+
  世紀あたり永年変化率 deg/Julian-century。**近日点移動 ϖ̇・昇交点移動 Ω̇・軌道傾斜変化 İ は
  この rate がそのまま表現する**)。衛星は `satellite-orbit.ts`(二体ケプラー+太陽摂動の
  周期項テーブル+実測の歳差率)。合成は `ephemeris.ts` の `Ephemeris`
  (恒星→惑星系重心→惑星/衛星の3段パイプライン、地球を ECI 原点に厳密固定)。
- 軌道評価の基準面は `kepler-orbit.ts` が `ECL_POLE`/`Q_ECL_TO_ECI` 等を直接使う形で
  **黄道面に固定**されている(kepler-orbit.ts:93-129)。この基準面は位置だけでなく
  軌道法線・回転座標系・ラグランジュ点(`ephemeris.ts:145-166`)にも波及する。
- 自転軸は `Degree2GravityDef` の中の `PoleModel`(`'eciPole'` = 地球、`'cassini'` = 月)
  としてのみ存在する。**「見た目の自転」を持つのは地球だけ**(`earth-body.ts`)。
  `SphereBody` は `sync` 末尾で `mesh.lookAt(地球方向)` を無条件に呼び、月の潮汐固定を
  姿勢上書きで表現している(sphere-body.ts:53-58)。
- マップビューでの天体表示は `sphere-body.ts` の `SphereBody`
  (広域視点では実位置・実半径、戦闘視点では圧縮表示距離 `visDist × radius/trueDist` で
  真の視角を保つ)。太陽は `b23469a` で実位置・実半径表示に変更済み。
- 参照軌道線(静止軌道・月・木星)は `environment-scene.ts` に**個別フィールドとして
  ハードコード**されており、データ駆動ではない。
- `Ephemeris.attractorsAt(t)` は**重力積分専用の窓ではない**。遮蔽判定
  (map-picker.ts:123 の `isOccluded`)、表面接触(`hitCelestialBody` — checkLoss/
  予測打ち切り/計画線打ち切り)、中心天体解決(`strongestAttractor` — HUD の軌道要素
  表示・赤道交点マーカー)、積分刻み(`localOrbitPeriod`)、クリエイティブモードの
  基準天体解決(creative-stage.ts:279、非 null アサーション付き)がすべて同じ配列を読む。

## 2. 要件定義

### 2.1 機能要件

- **R-1 惑星**: 水星・金星・火星・土星・天王星・海王星を追加する(地球・木星は実装済み)。
  軌道は JPL Standish の近似ケプラー要素+永年変化率(§5.1 の数表)で実装する。
  この表の ϖ̇・Ω̇・İ には惑星間摂動と(DE 暦フィット由来の)相対論効果による**近日点移動・
  軌道面移動が既に含まれている**ため、rate をそのまま `PlanetOrbit` に載せることが
  「近日点移動・軌道面移動の科学的に正確な実装」そのものになる。
- **R-2 準惑星・大型小惑星**: 冥王星・ケレス・エリス・マケマケ・ハウメア・ベスタ・パラスを
  追加する。軌道は JPL SBDB の単一エポック接触軌道要素+平均運動(永年変化率の公開値は
  存在しないため rate は 0 とする。§5.2)。
- **R-3 主要衛星**: ガリレオ衛星4(イオ・エウロパ・ガニメデ・カリスト)、タイタン、
  トリトン(逆行)、フォボス・ダイモスを追加する。軌道は親惑星赤道面基準の
  円〜低離心率ケプラー軌道(§5.3、基準面の実装は D-3b)。月のような摂動周期項テーブルは
  持たない(該当する公開理論を要素化するコストに対して視覚的効果がないため)。
- **R-4 彗星**: ハレー彗星(e=0.967)とエンケ彗星(e=0.848)を追加する。既存の楕円
  ケプラーソルバの適用範囲内(e<0.98)に収まる天体のみを対象とし、放物線・双曲線軌道は
  非目標とする(§2.3 N-2)。
- **R-5 小惑星群**: メインベルト(Kirkwood gap を再現した a 分布)と木星トロヤ群
  (L4/L5 周りの秤動)を、**表示専用の統計点群**(seed 固定の決定論的生成、各点が
  自前の円軌道要素を持ち時刻 t で評価)として追加する。個々の点は `AttractorId` を
  持たず、フォーカス・ピック・重力の対象にならない。
- **R-6 ラグランジュ点**: 既存の `lagrangeAt` が全公転天体(`OrbitingId`)の L1〜L5 を
  自動生成済み。新惑星・新衛星を登録すると太陽-惑星系・惑星-衛星系のラグランジュ点
  ラベルが自動的に増える。追加実装は不要だが、ラベル数の爆発への UI 対策を行う(D-9)。
- **R-7 自転軸傾斜・自転**: 全惑星+主要衛星に IAU WGCCRE の pole モデル
  (α0・δ0・W の一次式、出典は NAIF `pck00011.tpc`)を実装し、メッシュの自転軸の傾きと
  自転位相(テクスチャの回転)を天文学的に正しくする(D-6)。
- **R-8 環**: 土星の環(D/C/B/カッシーニの間隙/A/F、§5.4 の実寸)をテクスチャ付き
  annulus メッシュで、天王星・海王星の環を細い簡易 annulus で描画する。環の面は
  各惑星の赤道面(= pole モデルが定義する面)に一致させる。
- **R-9 実寸・実位置**: すべての天体をマップビューでは実位置・実半径で表示する
  (太陽の `b23469a` 実装と同方式)。戦闘ビューでは D-8 の方針で表示する。
- **R-10 マップ統合**: 追加した天体(点群を除く)は既存機構に自動で乗る —
  フォーカスラベル(`focus-markers.ts`、自動生成)、座標系選択(`frame.ts` の `FRAMES`、
  自動生成)、オブジェクト一覧(`ObjectListPanel`)、プロパティウィンドウ、
  クリエイティブモードの基準天体選択。**これらは登録だけで機能することを受け入れ条件とする。**
- **R-11 参照軌道線**: 全惑星の公転軌道線をマップビューに表示する。現行の
  ハードコード方式(`environment-scene.ts` の個別フィールド)を廃止し、
  `SOLAR_SYSTEM` から自動生成するデータ駆動方式に書き換える(D-5)。

### 2.2 非機能要件

- **NF-1 性能**: 追加後も `update` フェーズの増分が現行実測(~400 エンティティで約5ms)
  に対して 1ms を超えないこと。達成手段は D-1(重力積分の対象を固定)と D-2(t 単位
  メモ化)。
- **NF-2 精度の定義**: 「科学的に正確」とは**モデルの内部整合性**を指す。
  ゲームの simTime エポック(`SIM_EPOCH_UTC`)は遠未来の年であり、Standish 表の
  有効期間(Table 1: 1800–2050AD)の外にある。また月の初期位相は毎ゲームランダムである
  (`Ephemeris` の `phaseOffsets`)。したがって**実在の日付の実際の空を再現することは
  目標ではなく**、軌道要素・永年変化率・自転軸・寸法が出典値と一致し、相互の幾何関係
  (軌道面・歳差・共鳴・天体間の相対黄経)が正しいことを「正確」と定義する。
  要素のエポック(J2000)は simTime=0 に対応させる(具体的手順は §5.1 エポック整合)。
- **NF-3 バンドルサイズ**: テクスチャ追加による `docs/` 配信物の増分は 30MB 以下とする。
  達成手段は解像度の階層化(D-7: 地球・月のみ 8K、他惑星は 2K、準惑星・衛星は
  単色または手続き生成)。
- **NF-4 型安全**: 新天体は既存の閉じた union に追加し、3つのレジストリ(§1)の
  コンパイル強制を維持する。小惑星点群だけが例外(D-4)。
- **NF-5 セーブ互換**: 天体 ID の追加で旧セーブが壊れないこと。実態:
  `save-data.ts:227` の `phaseOffsets` は `Partial<Record<AttractorId, number>>` なので
  新 ID は欠落として扱われ位相 0 にフォールバックする(ephemeris.ts:72)。
  `SAVE_VERSION` の更新は不要。ただし土星が重力源に入るぶん、旧スナップショットから
  復元した軌道の将来は保存時点の予測と厳密には一致しなくなる — 仕様として受け入れる。

### 2.3 非目標(明示的にやらないこと)

- **N-1**: 数百〜数千の小惑星を個別の `AttractorId` として登録すること。文字列リテラル
  union と `Record` 強制の設計が破綻する。点群は表示専用の別系統とする。
- **N-2**: 放物線・双曲線軌道(e≥0.98)の彗星・恒星間天体。既存の楕円ケプラーソルバと
  `OrbitLine`(e≥0.98 で描画拒否)の適用範囲外であり、universal variable 定式化の
  追加実装が必要になる。将来拡張の欄(§8)に記録するに留める。
- **N-3**: 木星・土星以外の天体を重力源にすること。判断基準は D-1。
- **N-4**: 全エンティティが外惑星圏へ航行する遊びの成立(ゲームプレイ設計)。本計画は
  天体の存在・表示・(木星・土星の)重力までを扱い、ステージ設計は扱わない。
- **N-5**: 分点歳差(25,772年周期)。ECI 自体の定義に関わるため既存方針
  (`ecliptic.ts`: 傾斜角固定)を維持する。
- **N-6**: 土星の環の影・環による遮蔽など高度なライティング。環は自己表示のみ。

## 3. アーキテクチャ上の設計判断

### D-1 重力積分の窓と天体レジストリの分離(最重要の構造判断)

`CelestialBodyDef` に `gravitySource: boolean` を追加する。ただし
**`Ephemeris.attractorsAt(t)` の返り値は全登録天体のまま変えない**。§1 に列挙した通り、
この配列は遮蔽判定・表面接触・中心天体解決・積分刻み・クリエイティブモードの基準天体
解決の共通窓であり、これらはいずれも「そこに天体があるか」の問いで重力源かどうかとは
無関係だから(絞ると、火星の裏のラベルが選べる/火星周回艦の HUD が太陽中心表示になる/
表示専用天体を艦がすり抜ける/creative-stage.ts:279 の非 null アサーションで落ちる、の
4系統が同時に壊れる)。

代わりに**重力積分だけが別の窓を使う**: `Ephemeris.gravityAttractorsAt(t)`
(`gravitySource: true` のみを返す)を新設し、これを引くのは
`DynamicEntity.stepActual` / `DynamicEntity.stepPredicted`(Predictor 経由)/
`PlanArc.update` の3経路のみとする。`dynamics.ts` の `totalAccel` は RK4 の4ステージ×
全エンティティで配列を舐めるため、重力側だけは要素数を5体に固定する必要がある。

- **重力源(`gravitySource: true`)**: 太陽・地球・月・木星・土星の5体。
- **選定基準**: 「その天体の近傍にプレイヤーが存在しうるか」。地球近傍への加速度寄与では
  判定**しない** — ECI は地球と共に自由落下する非慣性系なので寄与は潮汐差分項
  `μ[(r_b−r)/|r_b−r|³ − r_b/|r_b|³]`(attractor.ts の `attractorAccel`)であり、
  この式では地心 6.4e8 m での寄与は木星 6.5e-10、土星 1.1e-11、海王星 6e-14 m/s² と
  **既存の木星ですら太陽輻射圧(~7e-8 m/s²)より2桁以上小さい**。木星・土星を重力源に
  残す理由は地球近傍の物理ではなく、クリエイティブモードで木星系・土星系(ラグランジュ点
  含む)に艦を置いたときに局所力学が成立することにある。
- **不変条件**: クリエイティブモードの基準天体・ラグランジュ系として選択可能な天体は
  必ず `gravitySource: true`。`ship-placer-panel.ts` の基準天体リスト生成をこのフラグで
  フィルタする(選ばせてから拒否しない、という同パネルの既存規約に合わせる)。
  ガリレオ衛星等を将来プレイ対象にする場合は該当衛星のフラグを true に倒す(この一括
  判断を1ビットに集約するのがフラグの意図)。
- **テストへの影響**: `attractorsAt` の返り値順序に依存するアサーションは2箇所ある —
  `tests/physics/ephemeris.test.ts:207`(id 列の deepEqual)と
  `tests/physics/attractor.test.ts:127-131`(`attractors[2]`/`[3]` の**添字直参照**)。
  後者は天体挿入で静かに別天体を指すため、`find(b => b.id === …)` へ書き換えてから
  天体を足す。

### D-2 `Ephemeris` の t 単位メモ化(B-2/B-3 の解消)

キャッシュは **`planetHelioState`(惑星ごと)と `satelliteRelState`(衛星ごと)の2層**に
置く。`helioStateOf` に置いても衛星経路(ephemeris.ts:122 が `planetHelioState` を直接
呼ぶ)がバイパスするため効かない。ガリレオ衛星4体を足すと `attractorsAt` 1回で
木星の `planetHelioState`(内部で4衛星の `satelliteRelState` を含む重心補正)が5回
評価される構造が、このキャッシュ位置なら1回に落ちる。

- **エントリ数**: 1 ではなく**直近 t の4エントリ程度のリング**にする。
  `plan-arc.ts:143,147` が同一ループ内で `t` と `t + dt/2` を交互に引き、
  `predictor.ts:71` がエンティティごとに異なる先端時刻を引くため、1エントリでは
  主要経路でヒット率が 0 になる。
- **正しさの形**: 「同一 t のキーに一致したときのみヒットし、ミス時は常に再計算して
  正しい値を返す」。`ephemeris.ts:5` の「呼び出し順に依存する隠れた制約を作らない」
  方針とはこの形で両立する(ヒットしなくても結果は変わらない)。
- **`setPhaseOffsets`(ephemeris.ts:65-68)はキャッシュを破棄する**。現行の
  「メモ化を持たないため無効化は不要」というコメントを破棄する旨に書き換える
  (`game.ts:319` のセーブロード経路が踏む)。
- **`attractorsAt`/`gravityAttractorsAt` 自体にも同じ t リングキャッシュ**を持たせ、
  返り値配列を同一参照で返す。**呼び出し側が配列を破壊しない規約**をコメントで明記する
  (既存呼び出しは全数 read-only であることを P0 で確認する)。
- **位置づけ**: これは単なる性能改善ではなく **D-9/R-10 の前提条件**である。
  `map-picker.ts:123` はピック候補ごとに `attractorsAt` を呼んでおり、候補が 150 件規模に
  なる本計画ではメモ化なしでは成立しない。
- `game-entity.ts:90-91` の stale コメントは、この変更で実装と一致する内容に書き直す。
- テスト: `ephemeris.test.ts` に「同一 t の連続呼び出しが同一参照を返す」「異なる t で
  正しく再計算される」「`setPhaseOffsets` 後に古い値を返さない」の3点を追加する。

### D-3 軌道モデルの追加(型の拡張)

- **惑星**: `PlanetId` に `'mercury' | 'venus' | 'mars' | 'saturn' | 'uranus' | 'neptune'`
  を追加。§5.1 Table 1 の値を登録する。**`planetOrbit` の引数 `periodSec` は
  `lRateDegPerCentury` に置き換える**(planet-orbit.ts:12-25 は現在 `lRate = 2π/periodSec`
  で組んでおり、Table 1 の L̇ を渡す口がない。現行木星の周期由来 lRate は Table 1 の
  L̇ = 3034.74612775 deg/Cy と5桁目で食い違う — 100年で 0.13°。他の rate 列と単位系を
  揃え、既存の地球・木星も同表の L̇ へ差し替える)。
- **準惑星**: 冥王星以下も `PlanetId` として扱う(`kind: 'planet'` は「太陽を回る天体」の
  意味であり、IAU の惑星定義とは独立 — solar-system.ts:57-75 の `kind` は中心が恒星か
  惑星かの dispatch にしか使われていない)。rate は全て 0。
- **彗星**: `kind: 'comet'` を新設**しない**。彗星も太陽周回の固定要素天体であり
  `kind: 'planet'` + rate 0 で表現できる。分類を増やすと `ephemeris.ts` の kind dispatch に
  分岐が増えるだけで得る物がない。彗星であることは表示側(`CELESTIAL_BODIES` の見た目)
  だけが知る。
- **衛星**: `SatelliteId` に8衛星を追加。`kind: 'satellite'`、`planet` フィールドに
  親惑星 id。摂動項テーブルは空配列。トリトンは**海王星赤道面基準で i = 156.885°** の
  逆行軌道として登録する(§5.3 の表と同じ基準面。黄道基準では約 130° になり値が変わる
  ことに注意)。`stateFromOrbitalElements` が i>90° を特別扱いせず正しく扱えることを
  テストで確認する。
- **ケプラーソルバの高離心率対応**: Newton 反復の実体は `elements.ts:82-91` の
  `eccentricAnomalyFromMean`(初期値 E=M、最大50回)。**e>0.8 のとき初期値を E₀=π に
  切り替える**(高離心率で M≈0 付近の収束が遅くなる既知の問題への標準対策)。この関数は
  全軌道評価の共通経路なので、既存の低離心率ケースの結果が変わらないこと(往復精度
  テスト)も同時に確認する。テストは `tests/physics/elements.test.ts` に置き、新規テスト
  ファイルを作る場合は `tests/physics/index.ts` への登録を忘れない。

### D-3b 衛星の基準面(親赤道面)の実装 — `kepler-orbit.ts` の責務

衛星の軌道面を親惑星の赤道面基準にする変更は `satellite-orbit.ts` では**閉じない**。
基準面は `kepler-orbit.ts:93-129`(`normalFromAngles`/`directionFromAngles`/
`rotationFromAngles`/`keplerOrbitState`)が `ECL_POLE`/`Q_ECL_TO_ECI` を直接使う形で
黄道面に固定されており、この3関数は `Ephemeris` の `orbitFrameRotationAt`/
`orbitNormalAt`/`lagrangeAt`/`frameTransformAt` が読む。位置評価だけを回すと、
回転座標系(「木星-イオ回転系」)・軌道法線・ラグランジュ点が黄道基準のまま残る
不整合になる。

- `KeplerOrbit` に基準面を表す `basisToEci: Quat`(既定 = 黄道基準、`Q_ECL_TO_ECI`
  相当)を持たせ、上記の全関数がこれを経由するよう**1箇所で**書き換える。
- 衛星の要素は「親の赤道面基準」のまま登録し、`Ephemeris` が親の pole モデル
  (P2 の成果、D-6)から `basisToEci` を組む。位置・軌道法線・回転基準系・L 点が
  同じ基準面を共有する。
- **月は既定(黄道基準、i=5.145°)のまま変更しない**(既存の摂動テーブル・カッシーニ
  実装・テストすべてが黄道基準で書かれており、正しく動いている)。
- **数値ガード**: `satelliteState`(satellite-orbit.ts:115-125)は二体解を黄道の
  (λ, β, r) に分解して周期項を重ねる構造で、`rho0 = hypot(x,y)` 除算があるため
  黄道極付近を通る軌道で速度が NaN になる。**周期項テーブルが空の衛星はこの分解を
  通さず二体解をそのまま返す早期 return を置く**(親赤道基準の天王星系衛星を将来
  足した場合にこの経路を踏むため)。

### D-4 小惑星点群(表示専用の新系統)

`src/game/celestial/asteroid-field.ts`(新規)に、`AttractorId` 系とは完全に独立した
点群クラスを作る。

- **生成**: seed 固定の擬似乱数で決定論的に生成(セーブ不要・毎回同一)。
  メインベルト 4000 点: a を 2.0–3.4 AU に分布させ、Kirkwood gap
  (a = 2.06 / 2.50 / 2.82 / 3.28 AU — 4:1, 3:1, 5:2, 2:1 共鳴)の近傍をガウス状に除去。
  e は 0–0.25、i は 0–20° に分布。トロヤ群 各 800 点: 木星と同じ a、L4/L5 から経度
  ±30° の秤動幅で分布(観測される群全体の広がり ~70–80° と個々の秤動振幅数°〜35° に
  整合)。
- **位置評価**: 各点は {a, e, i, Ω, ϖ, L₀} を持ち、平均運動で L を進めて楕円ケプラー解を
  評価する。**評価はマップビュー表示中のみ**(`update` 冒頭で `overviewMode` を見て
  早期 return — 戦闘ビューでは見えないものを計算しない)。コストの実態: 1点あたり
  Newton 反復込みで三角関数 10〜14 回、5600 点で 6〜8 万回/frame。V8 の実測オーダー
  (20–50ns/回)では 1.5–4ms になりうるため、受け入れ条件は固定値ではなく
  「`?perf=1` で実測し、マップ表示中の増分が 2ms を超える場合は点数を半減する」とする。
  CPU 側で行い、TSL/GPU 化はしない(前例がなく導入コストが見合わない)。
- **描画**: `THREE.InstancedMesh`(小さな三角形1枚 × 5600 インスタンス、
  `frustumCulled = false`)。`instanceMatrix` を `sync` で in-place 更新。
  WebGPU の `THREE.Points` サイズ不能の制約を回避する。このプロジェクト初の
  InstancedMesh 使用となるため、WebGPU レンダラーでの最小動作確認をフェーズ冒頭に
  置き、不成立なら星と同様の三角形バッチ(単一 BufferGeometry)にフォールバックする。
  マップビュー専用(`overviewMode` で `visible` 切替)。
- **重力・ピック・フォーカス**: 一切対象外。`MapPickable` にも載せない。

### D-5 参照軌道線のデータ駆動化(リファクタリング)

`environment-scene.ts` の `geoLine`/`moonLine`/`jupiterLine` 個別フィールド方式を廃止し、
`SOLAR_SYSTEM` の全公転天体(+静止軌道の特例)から `OrbitLine[]` を自動生成する。

- 各天体の線は `orbitalElementsOf(stateOf(id, t), 中心天体)` で毎フレーム要素を出す。
  中心天体が太陽の場合は木星線の既存実装(`jupiterOrbitElements`: `stateOf('sun', t)` から
  都度 `Attractor` を組む)と同じパターンを共通化する。衛星の線は親惑星中心。
- 高離心率の彗星(ハレー e=0.967)は `OrbitLine` の e≥0.98 ガードの内側なので描ける。
  ただし近日点付近の頂点密度のため `densifyNear` を近日点に渡す。
- 色は既存の参照線色を流用し、線の本数分の `OrbitLine`(2048 頂点 × 24.6KB × ~25本
  ≈ 620KB)はメモリ上許容。
- 表示のオン/オフ: 惑星線は常時表示、衛星線は「その惑星系にフォーカスしているとき」
  のみ表示(マップを木星にフォーカスするとガリレオ衛星の線が現れる)。全惑星+全衛星の
  線を同時に描くと内側太陽系がラベルと線で潰れるための措置。判定は `OverviewCamera` の
  フォーカス id とその親子関係(`SOLAR_SYSTEM` の `planet` フィールド)から導出する。
- この変更は「参照線の所有者」という責務境界の確定なので、同じ変更セットで
  `.claude/skills/refactor-fixed/SKILL.md` を書き換える。

### D-6 自転軸傾斜・自転(IAU pole モデル)

**`PoleModel` を `Degree2GravityDef` の外へ出し、`CelestialBodyDef` 直下の
`pole?: PoleModel`(省略時は自転軸を持たない)へ移す。** 自転軸は重力場の属性ではない。
現行の置き場所(solar-system.ts:45-55、`Degree2GravityDef` の中)のままだと
(a) 表示専用天体に pole を定義するには `Degree2Gravity` を偽装する必要があり、
(b) 衛星の基準面(D-3b)が親の pole を参照できず、
(c) `equator-node-markers.ts:58` の `center.degree2?.pole` が火星等で未定義になり
火星周回艦の赤道交点マーカーが出ない。`Degree2GravityDef` は係数と基準半径だけを持ち、
pole は本体から読む。**表示専用天体は pole のみを持ち `degree2` は持たない**
(重力源でない天体は `dynamics.ts` の総和ループに入らないため、J2 を持たせても
評価されず意味がない)。

`PoleModel` に第3の variant `'iau'` を追加する:
`{ kind: 'iau', ra0Deg, ra1Deg, dec0Deg, dec1Deg, w0Deg, wRateDegPerDay }`
(ICRF 赤道座標の pole 赤経・赤緯の一次式と自転位相 W の一次式。出典 NAIF
`pck00011.tpc`)。

- **ICRF→ECI 変換は新規に書かない**: `ecliptic.ts:15` の module-private `stdToEci`
  (標準赤道座標 (X=春分点, Z=北極) → ECI の軸置換 `(xs, zs, −ys)`)を export し、
  `raDecToEci(raDeg, decDeg)` から呼ぶ(軸置換の定義元を2箇所に増やさない)。
  検算: std 単位ベクトル (cosδcosα, cosδsinα, sinδ) → ECI (cosδcosα, sinδ, −cosδsinα)。
- **`SphereBody` の姿勢は「自転軸(ECI 単位ベクトル)+自転位相 W(rad)」からのみ
  組む**。現行の `sync` 末尾の `mesh.lookAt(地球方向)`(sphere-body.ts:53-58、月の
  潮汐固定のための姿勢上書き)は削除する — quaternion を書いても最後の `lookAt` が
  消すため共存できない。月はカッシーニ状態の自転軸(既存 `'cassini'` を維持)と
  同期回転の位相(平均黄経方向 — `ephemeris.ts:200` の `keplerOrbitMeanDirection` と
  同じ量)から W を導き、他天体と同じ1本の経路に乗せる。
- 地球(`earth-body.ts`)の既存自転実装は変えない(既に正しい)。
- 効果: 天王星の横倒し(α0=257.311°, δ0=−15.175° → 軌道面から 97.8°)、土星の環の
  傾き(α0=40.589°, δ0=83.537° → 26.7°)が実データから自動的に出る。
- pole の置き場所変更は責務境界の確定なので `.claude/skills/refactor-fixed/SKILL.md` を
  同じ変更セットで書き換える。

### D-8 カメラ・スケール戦略

- **B-1 の修正(far のズーム連動化)**:
  `far = clamp(dist × OVERVIEW_CAMERA_FAR_RATIO, OVERVIEW_CAMERA_FAR_MIN, OVERVIEW_CAMERA_FAR_MAX)`、
  `FAR_RATIO = 100`、`FAR_MIN = 1.5e10`(現行 far 値 — 最小ズーム `dist = 1e5` でも
  月 3.8e8 m・星球シェルが far の外に出ないための下限)、`FAR_MAX = 1e13`。
  near/far 比が 1e5 を超えるのは far が下限に張り付く近距離域だけで、そこでは near が
  十分小さく 24bit 深度で破綻しない。実装: `near` getter と同様に各サブカメラに `far`
  getter を生やし(`camera-system.ts:186` が `active.near` を読む構造に合わせ、
  `CombatCameraSystem` 側は固定値を返す)、`CameraSystem.sync` が毎フレーム書く。
- **星球・天球グリッドとの分離**: `environment-scene.ts:98-101` は星球シェルを
  `overviewCamera.camera.far * 0.9 / 3.5e7` でスケールしており、far を可変にすると
  星空の殻半径が毎フレーム変わる。星球・天球グリッド(`celestial-grid.ts`)の殻半径は
  far ではなく専用定数(現行の 1.5e10 相当)に固定し、far との結合を切る。同時に
  同行のリテラル `3.5e7` を `render/stars.ts` の `STAR_SHELL_RADIUS` 参照へ直す。
- **f32 ジッター**: 頂点座標は floating origin 補正後も遠方天体では実質絶対値
  (海王星 4.5e12 m → f32 ulp ≈ 540km)。ただし (a) 天体球は `position` に1点書くだけで
  頂点は局所座標、(b) 軌道線の頂点は中心天体相対(`OrbitLine` の設計)で太陽中心軌道でも
  ulp は軌道半径の 2⁻²³ ≈ 0.01% 未満、のためマップズームで視認されるジッターは
  発生しない見込み。**フェーズ受け入れ時に海王星フォーカスで目視確認し、問題が出た
  場合のみ「マップビュー専用のカメラ基準 floating origin」を追加検討する**
  (先回り実装はしない)。
- **深度**: 遠方天体は既存の方針(解析遮蔽 `occlusion.ts` + `renderOrder`)を維持。
  環だけは惑星本体との前後関係が必要なので `depthTest: true` / `depthWrite: false` +
  惑星本体より大きい `renderOrder` とする。
- **戦闘ビューでの表示**: 惑星は LEO から肉眼で「明るい星」として見える
  (金星 −4等、木星 −2等)。`SphereBody` の圧縮表示(visDist 方式)は視直径が
  ピクセル未満になり意味がないため、戦闘ビューの惑星は**星シェルと同じカメラ追従
  シェル上の輝点スプライト**として描く。実装は `SphereBody` に分岐を足すのではなく
  `CelestialBody` の別実装 `PointBody` として登録する — `visDist`(圧縮表示距離)は
  月のように戦闘ビューで実体として見える天体だけの概念であり、輝点表示の天体は
  持たない。位置は `positionOf` の実方向、明るさは等級に応じた3段階のスプライト
  サイズ。月・太陽は既存実装を維持。

### D-9 ラベル・UI の爆発対策

天体 25体 × (本体+L1..5) = 150 ラベルは `focus-markers.ts` の自動生成をそのまま
通すとマップが潰れ、ピック候補ごとの `attractorsAt` 呼び出し(D-2 参照)も膨らむ。

- `CelestialBodyDef` に `lagrangeLabels: boolean` を追加し、ラグランジュ点ラベルを
  主要系(月・木星・土星)に限定する。準惑星・衛星・彗星の L 点は生成しない
  (物理的には存在するが、質量比が小さく実用上無意味)。**フラグは2箇所を絞る**:
  `LABEL_NAMES` の生成(focus-markers.ts:29-33)と `update(t)` 内の `lagrangeAt`
  ループ(focus-markers.ts:56-59)は別々に `ORBITING_IDS` を回っており、ラベルだけ
  止めても 24 天体分の `lagrangeAt`(1天体あたり `positionOf` 2回+
  `orbitFrameRotationAt`)が毎フレーム走り続ける。
- 天体本体のラベルは全数生成するが、`FocusMarkers` の表示を**カメラのズーム距離に
  応じた階層フィルタ**にする: 引いた視点では惑星+太陽のみ、惑星にフォーカスすると
  その系の衛星・L 点が現れる(D-5 の衛星線と同じ判定を共有)。
- `ObjectListPanel` の天体セクションはデフォルト閉(既存挙動)のまま全数を列挙する。
- 座標系選択(`FRAMES` → `FRAME_ITEMS`)は全天体分生成されるが、UI のプルダウンが
  50 項目超になるため、よく使う系(地球・月・太陽+フォーカス中の系)だけ出す
  フィルタを入れる。この UI 詳細はフェーズ 7 で確定する。
- `LAGRANGE_DEFAULT_AMPLITUDE_KM`(ship-placer-panel.ts:110)は
  `Record<OrbitingId, …>` のため天体追加ごとに既定振幅定数(現在は
  `game/const.ts` の `CREATIVE_HALO_*` 系)を要求する。24 天体分の定数を手で用意する
  実態にないため、**`Partial<Record<OrbitingId, …>>` + 系の主天体間距離からの導出
  (既定値 = 距離 × 一定比)に置き換える**。ただし基準天体リスト自体を
  `gravitySource: true` に絞る(D-1 の不変条件)ため、実際に振幅が要るのは
  月・木星・土星のみで、既存定数の意味は変わらない。

#### エポック整合(P1 の最初の作業 — B-4 の解消)

現行の地球エントリは `l0Deg = 178.13895…`(solar-system.ts:34)で、J2000 の Standish 値
100.46457166 に対し **+77.674°** シフトされている(ゲーム開始時に太陽を +X 方向 =
昼側に置くための表示アンカー)。木星は J2000 値のままなので、太陽-地球-木星の相対幾何は
既に約 78° ずれている。6惑星を追加する前にこれを解消する:

- **全天体の `l0Deg` を J2000 の Standish 値に統一**し、「開始時刻を昼側に置く」選択は
  `Ephemeris` が全天体共通に評価時刻へ加える定数オフセット **`EPOCH_T_OFFSET` [s]**
  として表現する(平均黄経だけのシフトと違い、永年変化率にも一様に効くため厳密。
  月のランダム位相 `phaseOffsets` とは独立に共存する)。
- オフセット量は「t=0 で地球の真黄経が π(太陽が +X)」の条件から一度だけ逆算して
  定数に書く。`EARTH_L0_DEG` 定数は削除する(改名・痕跡を残さない規約に従う)。
- 受け入れ: `ephemeris.test.ts` に「t=0 で地球の日心真黄経が π」「地球と木星の日心
  平均黄経差が J2000 の Standish 値の差と一致」の2点を追加。

## 7. 検証方針

- 各フェーズで `npm run typecheck`(常時)+ `npm run test:physics`(physics/ を
  触るフェーズ: P0, P1, P2, P4, P5, P6)。
- 追加するテストの型: 公転周期のケプラー第3法則一致、既知の幾何値
  (環の傾き・逆行・GR 込み近日点移動率・エポック整合)のピン留め、高離心率ソルバの
  往復精度、リファクタの非破壊性(月の既存テスト無変更通過)。理論値のない箇所は
  既存方針通り「実測値をゆるいマージンでピン留め」。
- 実行時確認(ヘッドレス検証 /verify)はユーザーが求めたときのみ。フェーズ受け入れの
  「見える」系条件は `npm run dev` での目視を想定する。

  木星系・土星系の放射線帯等の環境要素。

- 準惑星の手続き生成テクスチャ(`earth-color.ts` 方式の横展開)。
- マップビュー専用のカメラ基準 floating origin(D-8 のジッターが実際に視認された場合)。
