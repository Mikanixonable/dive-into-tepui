# タンパク質の立体化を PyMOL へ移す(完了・2026-08-25)

自前の PDB/mmCIF パース・二次構造判定・共有結合推定・分子表面生成をすべて PyMOL(open-source)へ
置き換えた。原構造の mmCIF はリポジトリへ取り込み、生成はネットワークへ出ない。

## 実測の結果

| | 置き換え前 | 置き換え後 |
| --- | --- | --- |
| structure アセット 4件の合計 | 124.5 MB | 34.8 MB |
| 6N2Y の表面メッシュ | 285,457 頂点 / 570,596 三角形 | 239,866 頂点 / 480,009 三角形 |
| 1MBN の表面メッシュ | 21,084 頂点 / 42,140 三角形 | 10,076 頂点 / 20,140 三角形 |
| `tools/protein-builder/` の行数 | — | 827 行削除 / 約 450 行追加 |
| 4件の生成時間 | — | 約 14 秒 |

二次構造の判定が寄託注釈から座標由来へ変わり、割合が動いた。ミオグロビンは helix 77.1%→79.7%、
ATP合成酵素は 58.6%→54.3%、RuBisCO は 39.7%→39.6%、5I4R は 37.6%→35.4%。
mmCIF を入力にしたことで、5I4R は残基 1113→1123、8RUC は 2356→2360 と、読み取れる残基が増えた。

## 決めたこと

- **原構造は全件 mmCIF に統一した。** PyMOL から entity 番号(`protein.definition.json` の構成要素が
  参照する固定値)と label_asym_id 由来の鎖名を一様に取れるため、PDB 形式のための分岐が消える。
  entity 番号は4件とも既存の定義と一致した。
- **リボンの生成と three.js の描画は変えていない。** 断面の意匠は PyMOL の標準表現に無い。
- **内容ハッシュは JS 側が正本のまま。** `validate-protein-motion.mjs` が JS で再計算して照合するため、
  Python は解析だけを行い、アセットの確定は JS の入口が行う。
- **非ポリマー原子は、最も近いポリマー原子と同じ鎖へ束ねる。** 著者が与えた鎖 ID は結合先と対応
  しないことがあり、8RUC の CAP が本来の鎖の Cα から 46 Å 離れる。
- **表面メッシュは原構造の座標のまま置く。** 読み手が `coordinateFrame.centeredAt` を引く既存の
  約束に合わせた。
- **溶媒排除表面を採った。** 溶媒接触表面より位相が健全で、6N2Y の境界辺は 652 に対し 11 だった。
- **表面の検証は、境界辺と非多様体辺の合計に許容量(全辺の 1/10000)を置く形にした。** 溶媒排除表面は
  狭い隙間で自分自身に接するため、辺の共有が2枚に収まらない箇所が必ず残る。退化三角形と不正な
  添字は従来どおり 0 を要求する。`surface_quality` を上げると三角形は4倍になるが不整箇所は増える。
- **弾性ネットワークの固有値は、小さい系では密行列で厳密に解く。** 反復解法のシフト反転は
  ゼロモード近傍で条件が悪く、ミオグロビンで相対残差 2.3e-2 まで悪化していた(密行列では 5.2e-14)。

## 確認したこと

- `npm run ci`(型検査・生成の再現性・アセット検証・649 テスト・本番ビルド・ブラウザスモーク)
- `npm run protein:generate-structure:check` が4件とも差分なし(ビット単位で再現する)
- `npm run render-lab:shot` で4タンパク質のリボン・表面・分子模型・論文調を目視。破綻なし
- 原子数は 5I4R・6N2Y・8RUC が置き換え前と一致。1MBN だけ 1260→1259(ヘム鉄に配位した `OH` を
  溶媒として除いたため)

## 未確定の案

- `tools/protein-builder/build-protein.py` と `blender-export-protein.py`、config の `molecularNodes` /
  `externalTool`、`npm run protein:author` は Blender/Molecular Nodes で GLB を作る別経路として残っている。
  この経路を残すかどうかは決めていない。
- `tools/protein-builder/annotate-protein-hashes.mjs` は、生成側がハッシュを付けるようになったため
  npm script からは参照されない補修用ツールになっている。
- 表面の解像度はサイズの都合による制約から外れた。`surfaceQuality` を上げる余地はあるが、
  三角形数に見合う見た目の向上があるかは確かめていない。
