# 太陽系天体暦システム実装計画

## 目的

このゲームは、軌道力学ゲームとしてだけでなく、現実の天体配置を初期条件とする軌道シミュレータとして利用される可能性がある。

天体暦システムは、次の二つの時代で高い精度を持つことを目的とする。

- 現代を中心とする期間
- 西暦20000年を中心とする遠未来期間

開始時刻はソースコードに対応する天体位置を直接記述せず、天文時刻から天体暦を評価して求める。ゲーム実行時には長期数値積分を行わず、事前生成された天体暦多項式を評価する。

天体暦は以下を保証する。

- 同じ開始時刻と暦データから常に同じ配置を得る
- 天体の位置と速度を同一モデルから求める
- 開始時刻を変更しても手作業による天体位置修正を必要としない
- 天体暦の出典、座標系、時刻系、精度、生成器バージョンを追跡できる
- 有効期間外の黙示的な外挿を行わない
- セーブデータを将来のバージョンでも再現できる
- ゲーム起動時に長時間の数値積分を行わない

## 精度プロファイル

天体暦は、一つのモデルを全時代に無理に適用せず、用途別の精度プロファイルを持つ。

### 現代高精度プロファイル

識別子：

```text
modern-de440
```

対象期間：

```text
1550-01-01 TDB ～ 2650-01-01 TDB
```

基準データ：

- JPL DE440
- NAIF SPICE SPK
- NAIF PCK
- Leap Seconds Kernel
- Earth Orientation Parameters
- 必要に応じてJPL惑星衛星暦

DE440は現代の観測データに対してDE441より高精度であり、現代付近の軌道シミュレーションにはDE440を使用する。[JPL DE440/441](https://ssd.jpl.nasa.gov/doc/de440_de441.html)

このプロファイルでは以下を扱う。

- 太陽
- 水星
- 金星
- 地球
- 月
- 火星
- 木星
- 土星
- 天王星
- 海王星
- Pluto
- 利用可能な高精度衛星暦を持つ主要衛星
- 現代の地球自転および天体姿勢

現代付近ではUTC入力を受け付ける。UTCはLeap Seconds Kernelを通じてTAI、TT、TDBへ変換する。地表基準座標が必要な場合はUT1とEarth Orientation Parametersを利用する。

### 遠未来長期プロファイル

識別子：

```text
far-future-20000
```

対象期間：

```text
16000-01-01 TDB ～ 22000-01-01 TDB
```

高精度中心期間：

```text
19500-01-01 TDB ～ 20500-01-01 TDB
```

基準データ：

- JPL DE441
- DE441終端状態から生成した長期数値積分
- 太陽系主要天体の相互重力
- 主要な相対論補正
- 太陽J2
- 主要小惑星摂動
- 地球・月の分離積分
- 長期月軌道・潮汐モデル

DE441の公開範囲は西暦17191年までである。西暦20000年付近の暦は、DE441終端状態を初期条件として生成する独自の長期数値積分となる。

遠未来の暦は「観測により確定された西暦20000年の真の配置」ではなく、「DE441と明示された力学モデルから得られた、数値的に一貫した長期予測」である。

遠未来ではUTC、UT1、地球の実際の自転角を予測できない。そのため、軌道計算にはTDBを使用し、地球自転は作中の一様回転時刻として別に定義する。

## 時刻モデル

### 内部時刻

天体力学の内部時刻にはTDBを使用する。

```ts
type JulianDateTdb = number;
```

SPICE互換の時刻表現として、J2000 TDBからの経過秒も提供する。

```ts
type EphemerisTime = number;
```

変換式：

```text
ET = (JD_TDB − 2451545.0) × 86400
```

西暦20115年5月14日06:00:00 TDBは以下となる。

```text
JD_TDB                 = 9,068,045.75
J2000からの日数        = 6,616,500.75日
J2000からの秒数        = 571,665,664,800秒
J2000からのユリウス世紀 = 181.1499178645
DE441終端からの期間    = 約2,924.1047年
```

### 入力形式

```ts
type AstronomicalEpoch = {
  calendar: 'proleptic-gregorian';
  timeScale: 'UTC' | 'TT' | 'TDB';
  year: number;
  month: number;
  day: number;
  hour: number;
  minute: number;
  second: number;
};
```

現代高精度プロファイルではUTC、TT、TDBを受け付ける。

遠未来長期プロファイルではTTまたはTDBを受け付ける。遠未来のUTC入力は、作中暦ラベルとしてのみ扱い、物理時刻へ暗黙変換しない。

### シミュレーション時刻

```ts
absoluteJdTdb = scenarioEpochJdTdb + simTimeSec / 86400;
```

HUD表示時刻、計画表示時刻、天体暦時刻、セーブ時刻は同一のシナリオ元期を参照する。

## 座標系

基準座標系は太陽系重心ICRF/J2000とする。

天体暦データは以下を返す。

```ts
type BarycentricState = {
  r: Vec3; // m
  v: Vec3; // m/s
};
```

ゲームの地球中心ECI状態は次式で求める。

```text
rECI(body) = rBary(body) − rBary(earth)
vECI(body) = vBary(body) − vBary(earth)
```

ICRFではZ軸が北極方向である。ゲームではY軸が北極方向なので、一つの明示的な固定回転で変換する。

浮動原点は天体暦から独立させる。天体暦は倍精度の絶対状態を返し、描画直前にプレイヤー位置を引く。

## システム構成

```text
AstronomicalClock
        ↓ JD_TDB
EphemerisProfile
        ↓
EphemerisPackLoader
        ↓
ChebyshevEphemerisEvaluator
        ↓ barycentric state
OriginAndAxisTransform
        ↓ game ECI state
CelestialDynamics / Renderer / Planner
```

### `AstronomicalClock`

責務：

- 暦日からJulian Dateへの変換
- UTC、TAI、TT、TDBの変換
- シナリオ元期と`simTime`の合成
- 有効期間の検査
- HUD用作中暦の生成

Unix秒やJavaScriptの`Date`を天体力学の内部表現に使用しない。

### `EphemerisProfile`

```ts
type EphemerisProfile = {
  id: string;
  sourceModel: string;
  validStartJdTdb: number;
  validEndJdTdb: number;
  highAccuracyStartJdTdb: number;
  highAccuracyEndJdTdb: number;
  supportedBodies: readonly AttractorId[];
  packVersion: string;
};
```

開始時刻と要求精度からプロファイルを選択する。

選択規則：

- 1550～2650年で現代精度を要求する場合は`modern-de440`
- 16000～22000年では`far-future-20000`
- プロファイル有効期間外ではエラー
- 一つのシミュレーション中にプロファイルを自動切り替えない

シミュレーション途中のプロファイル切り替えは、位置・速度の微小な不連続を発生させ得るため禁止する。

### `EphemerisPackLoader`

必要な日時を含む天体暦パックを読み込む。

```ts
interface EphemerisPackLoader {
  load(
    profileId: string,
    startJdTdb: number,
    endJdTdb: number,
  ): Promise<EphemerisPack>;
}
```

パックはシナリオ開始時刻を中心とした有限期間を持つ。

ゲーム本編には必要な期間を静的アセットとして同梱する。任意時刻を選択できる軌道シミュレータモードでは、年代別パックを遅延ロードする。

### `ChebyshevEphemerisEvaluator`

NAIF SPK Type 2と同じ考え方で、位置をChebyshev多項式として保持し、速度は解析微分する。[NAIF SPK types](https://naif.jpl.nasa.gov/pub/naif/self_training/individual_docs/A8_making_an_spk.pdf)

```ts
interface AbsoluteEphemeris {
  barycentricStateOf(
    id: AttractorId,
    jdTdb: number,
  ): BarycentricState;
}
```

評価手順：

1. 対応区間を索引から取得
2. 時刻を`[-1, 1]`へ正規化
3. Clenshaw法でX/Y/Zを評価
4. Chebyshev係数を解析微分して速度を評価
5. SI単位へ変換
6. 精度・有効期間を検査

## 天体暦データの生成

### 現代高精度パック

生成ツールはDE440 SPKを読み取り、シナリオに必要な期間をゲーム用形式へ変換する。

変換ではDE440を再積分しない。DE440の状態を直接評価して、指定誤差以内となるChebyshev係数へ再近似する。

主要衛星についてJPL衛星SPKが利用可能な場合は、同じ処理で惑星相対状態を格納する。

### 遠未来マスター暦

遠未来マスター暦はオフラインで生成する。

積分対象：

- 太陽
- 水星
- 金星
- 地球
- 月
- 火星
- 木星
- 土星
- 天王星
- 海王星
- Pluto
- Ceres
- Vesta
- Pallas
- 必要な追加小惑星または小惑星リング

力学モデル：

- 全対象天体間のニュートン重力
- 太陽による1PN相対論補正
- 太陽J2
- 地球と月の独立重心運動
- 月の潮汐散逸
- 地球の潮汐散逸
- 月の物理秤動に必要なモデル
- DE441との比較で有意となる追加項

基準積分器には高精度適応積分器を使う。別方式の積分器による独立検算も行う。

生成範囲：

```text
16000-01-01 TDB ～ 22000-01-01 TDB
```

DE441内の16000～17191年では、独自積分結果をDE441と比較する。DE441終端から22000年までは同一状態を連続的に積分する。

## 西暦20000年付近の精度調整

遠未来モデルは、DE441内部で2924.1047年間の擬似外挿試験を行って調整する。

検証例：

```text
14000年のDE441状態
        ↓ 独自モデルで2924.1047年積分
16924.1047年の予測
        ↓
同時刻のDE441と比較
```

同様の検証を複数元期で行う。

```text
10000 → 12924
11000 → 13924
12000 → 14924
13000 → 15924
14000 → 16924
```

各試験で以下を計算する。

- 太陽系重心位置誤差
- 地球相対位置誤差
- 速度誤差
- 地球から見た角度誤差
- 軌道長半径誤差
- 離心率誤差
- 軌道面法線誤差
- 月距離誤差
- Earth–Moon L1/L2位置誤差

その結果を基に、力学モデルと積分設定を確定する。

西暦20000年の予測誤差は、数値補間誤差と物理モデル不確かさを分けて表示する。

```ts
type EphemerisAccuracy = {
  representationErrorM: number;
  numericalIntegrationErrorM: number;
  estimatedModelErrorM: number | null;
};
```

正解データが存在しない遠未来で、モデル誤差を数値補間誤差と混同しない。

## 天体衛星の扱い

### 月

月は独立したN体積分対象とする。

現在のランダム位相は完全に廃止する。

地球‐月系では以下を同じ暦から得る。

- 月の位置・速度
- Earth–Moon barycenter
- 月軌道面
- ラグランジュ点
- 月影
- 太陽・地球・月の相対配置

### 他惑星の主要衛星

現代高精度プロファイルでは利用可能なJPL衛星暦を使う。

遠未来長期プロファイルでは、高精度衛星暦の有効範囲が不足するため、以下の優先順位で扱う。

1. 共鳴を含む専用解析モデル
2. 永年摂動を含む平均要素モデル
3. 元期付きケプラー要素
4. 精度情報付き近似配置

位相はすべて開始時刻から決定的に計算し、乱数を使用しない。

## 天体姿勢

天体中心位置と天体姿勢を別システムにする。

```ts
interface BodyOrientationSource {
  orientationAt(
    id: AttractorId,
    jdTdb: number,
  ): BodyOrientation;
}
```

### 現代

- IAU回転モデル
- PCK
- 地球についてはUT1とEOP
- 月については高精度物理秤動

### 西暦20000年付近

- 長期自転軸歳差モデル
- 作中の一様回転時刻
- 潮汐ロック衛星の平均同期回転
- 予測不能な地球の実UT1は使用しない

遠未来の地表経度と太陽方向の関係は、作中モデルによる値であることをメタデータに記録する。

## パック形式

```ts
type EphemerisPackManifest = {
  formatVersion: number;
  packId: string;
  profileId: string;
  sourceDescription: string;
  sourceHashes: Record<string, string>;
  generatorVersion: string;
  frame: 'ICRF-J2000';
  timeScale: 'TDB';
  validStartJdTdb: number;
  validEndJdTdb: number;
  bodies: readonly BodyPackMetadata[];
  validationReportHash: string;
};
```

バイナリ本体には以下を格納する。

- 天体ID
- 区間開始時刻
- 区間長
- Chebyshev次数
- X/Y/Z係数
- 単位スケール
- 区間ごとの最大近似誤差

位置係数だけを保存し、速度係数は保存しない。速度は位置多項式の微分から得ることで、位置と速度の整合性を保証する。

## パック分割

### ゲーム本編

ゲームの開始時刻と最大プレイ期間が既知の場合、必要期間だけを一つのパックとして同梱する。

例：

```text
開始前1日 ～ 開始後10年
```

### 軌道シミュレータモード

任意開始時刻と長期間の時間移動に対応する場合、暦を年代チャンクに分割する。

例：

```text
modern-de440/2000-2010.bin
modern-de440/2010-2020.bin
far-future-20000/19950-20000.bin
far-future-20000/20000-20050.bin
```

必要チャンクだけを遅延ロードする。時間ワープがチャンク終端へ近づいた時点で次のチャンクを先読みする。

通信できない構成では、選択可能な開始期間に対応するチャンクをアプリへ同梱する。

## 実行時性能

Chebyshev次数を12、主要天体数を12とした場合、1時刻の評価はおよそ次の規模になる。

```text
約1,200～2,000浮動小数点演算
計算量 O(B × D)
B = 天体数
D = 多項式次数
```

60 fpsで全主要天体を毎フレーム更新しても、およそ12万演算/秒である。

同一時刻の結果はキャッシュするため、物理、描画、HUD、軌道計画から同時に参照されても再評価しない。

ゲーム開始時の負荷は以下だけになる。

- マニフェスト読込
- 必要なバイナリチャンク読込
- 開始時刻の区間索引
- 数千回未満の浮動小数点演算

CPU負荷は実質的に無視でき、起動時間は主にアセットの読込時間で決まる。

## データ量

月を4日区間、次数12、位置3軸、Float64で格納した場合、月単体の概算は以下となる。

```text
約28.5 KiB/年
```

惑星は月より長い区間で近似できる。適応分割後の全主要天体パックは、概算として以下を目標にする。

```text
1年     50～300 KiB
10年    0.5～3 MiB
100年   5～30 MiB
```

実際のデータ量は、指定誤差を満たす最小区間と最小次数を生成ツールが探索して決定する。固定区間長を全天体へ強制しない。

## 検証要件

### 現代高精度プロファイル

DE440から抽出したランダム時刻で比較する。

検証項目：

- 位置
- 速度
- 地球相対位置
- 地球から見た方向
- 月距離
- ラグランジュ点
- 天体姿勢
- パック区間境界の連続性

目標とする表現誤差：

```text
主要惑星位置   10 m以下
月位置          1 m以下
主要惑星速度    0.1 mm/s以下
月速度          0.1 mm/s以下
```

これはDE440そのものの観測誤差ではなく、DE440をゲーム用パックへ変換する際の追加誤差上限である。

### 遠未来長期プロファイル

以下を分離して検証する。

- 数値積分収束誤差
- Chebyshev表現誤差
- DE441内部での2924年間擬似外挿誤差
- 異なる積分器間の差
- 保存量のドリフト
- 地球‐月系の長期位相差

西暦20000年付近の暦パック自体の表現誤差は以下を目標とする。

```text
主要惑星位置   1 km以下
月位置         100 m以下
```

物理モデルの予測誤差は別途検証レポートに記載し、表現誤差の値で代用しない。

## セーブデータ

セーブには以下を保存する。

```ts
type SavedEphemerisContext = {
  epochJdTdb: number;
  profileId: string;
  packId: string;
  packHash: string;
  generatorVersion: string;
  orientationModelId: string;

```

ロード時には同じ暦パックを使用する。利用不能な場合は、異なる暦で継続せず互換性エラーを表示する。

## エラー処理

以下では計算を継続しない。

- 指定時刻がプロファイル有効期間外
- 必要天体がパックに存在しない
- パックのチェックサム不一致
- セーブが要求する暦パックが存在しない
- 補間誤差上限が要求精度を超える
- UTCからTDBへの変換データが現代プロファイルで不足する

遠未来のUTC、未対応衛星、モデル不確かさについては、黙って現代向け公式を外挿せず、精度区分を明示する。

## 実装順序

1. TDB、TT、UTC、Julian Dateを扱う天文時刻層を実装する。
2. 太陽系重心ICRF状態を返す`AbsoluteEphemeris`を定義する。
3. Chebyshev評価器と解析微分を実装する。
4. DE440から現代高精度パックを生成する。
5. 現代のDE440一致試験を実装する。
6. DE441から長期積分の境界状態を抽出する。
7. 遠未来長期積分器と独立検算器を構築する。
8. DE441内部で2924年間の擬似外挿試験を実施する。
9. 16000～22000年の長期マスター暦を生成する。
10. 西暦20000年付近の遠未来パックを生成する。
11. 天体姿勢システムを公転暦から分離する。
12. ゲーム、軌道計画、影、ラグランジュ点を新しい暦APIへ接続する。
13. 月を含む全ランダム位相と旧`EPOCH_T_OFFSET`を削除する。
14. パックIDと元期をセーブデータへ追加する。
15. 軌道シミュレータ向けの年代チャンク読込を実装する。
16. 現代・西暦20000年の双方について精度、性能、データ量をCIで検証する。
