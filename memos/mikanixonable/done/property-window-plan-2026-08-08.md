# プロパティウィンドウ 実装方針 (2026-08-08)

軌道オブジェクトの右クリックメニューをプロパティ表示付きのウィンドウへ拡張し、あわせて
マップビューの SHIP STATUS を廃止する。本書は着手前の合意事項をまとめたもので、実装後は
`CLAUDE.md` / `DEVELOP/SPEC.md` へ反映して本書は破棄する。

## 1. 目的

- マップビューで、軌道上の各オブジェクトの状態を右クリックから参照できるようにする。
- マップビューの SHIP STATUS ウィンドウを廃止し、常設パネルの占有面積を減らす。
- 参照したいウィンドウを画面上の好きな位置へ動かし、複数を並べて比較できるようにする。

## 2. 確定した決定

| 論点 | 決定 |
| --- | --- |
| `ContextMenu` の改名 | **しない。** 汎用ポップアップとして名前も責務も維持する |
| プロパティウィンドウの位置づけ | `MapPicker` が開くものだけを指す新概念。`ViewBadge`/`NodeGizmo`/`Targeter`/`NavTarget` は無変更 |
| 「モーダル」という呼称 | **使わない。** 背後の操作をブロックしないため。既存の `#hud-modal-shield` / `body.hud-modal-open`(DockView)と語が衝突する |
| 複数同時表示 | クリップ状態のウィンドウのみ複数存続できる。既定は1枚 |
| 戦闘ビューの SHIP STATUS | **残す。** ビューと船が1対1で対応するため常設が正しい |
| マップビューの SHIP STATUS | 廃止する |

## 3. 用語

- **プロパティウィンドウ** — 軌道オブジェクトを右クリックしたときに開く、プロパティ表示と
  操作項目を持つウィンドウ。ドラッグで移動できる。
- **一時ウィンドウ** — クリップされていない状態。画面に高々1枚しか存在しない。
- **クリップ** — ウィンドウを自動クローズの対象外にする状態。複数を同時に存続させられる。

## 4. 画面ごとの表示方針

### 戦闘ビュー
現状維持。SHIP STATUS / ORBIT / TARGET / CONTACTS はすべて常設のまま。敵・基地の右クリックは
`Targeter` / `NavTarget` が扱う従来のメニューのままとし、プロパティウィンドウは持ち込まない。

### マップビュー
SHIP STATUS(`#hud-status`)を非表示にする。艦固有の情報は艦を右クリックして参照する。

**ただし時間加速と NODE WARP の2項目は例外**とし、グローバルステータスバー
(`#hud-globalstatus`、現在は MET のみ)へ移設する。理由:

- どちらも艦のプロパティではなく `SimSpeedManager` が持つグローバルな値で、どの艦を右クリック
  しても同じ値が出る。
- マップビューは `[,]`/`[.]` のワープと `[N]` の自動ワープを最も使う場所であり、現在の倍率が
  見えないのは実用上成立しない。
- 現在この2項目は `#hud-status` にしか無く、マップビューで SHIP STATUS を消すと参照手段が
  完全に失われる。
- `DEVELOP/SPEC.md` §1 は既に「画面上部のスタッツパネルが自動ワープの残り実時間を表示する」と
  記述しており、実装(左下の SHIP STATUS)と食い違っている。移設すれば文書側が正しくなる。

移設後、SHIP STATUS に残るのは RCS制動 / 並進出力 / 微調整 / 進行方向ホールド / 視点のRCS追従 /
弾薬。いずれも操作中の艦とカメラの状態で、戦闘ビューでのみ意味を持つ。

## 5. プロパティウィンドウの仕様

### 5.1 状態と生存期間

**オブジェクト1つにつきウィンドウは高々1枚。** 既にウィンドウを持つオブジェクトを右クリック
したら、新規に開かず既存のものをクリック位置へ移動して最前面に出す。これで同一オブジェクトの
重複を構造的に排除する。

| | 一時ウィンドウ | クリップ済みウィンドウ |
| --- | --- | --- |
| 同時に存在できる枚数 | 1枚(新規に開くと前のは閉じる) | 制限なし |
| 外側の pointerdown | 閉じる | 閉じない |
| 操作項目のクリック | 閉じる | 閉じない(「削除」を除く) |
| キーボードショートカット | 効く | 効かない |
| ✕ ボタン | あり | あり |

クリップ状態・非クリップ状態のどちらも、以下では必ず閉じる。

- ✕ ボタンを押したとき
- 対象が消滅したとき(艦の撃破、弾薬の回収、基地の削除)
- マップビューを離れるとき(`ViewManager` の遷移)
- 「削除」を実行したとき(対象が消えるため)

**位置は保存しない。** 閉じて再度開いたら右クリック位置に戻る。一時ウィンドウは閉じるたびに
破棄されるので自然にこの挙動になる。

### 5.2 クリップ

**ウィンドウ隅のクリップボタンを押したときだけ**クリップ状態が反転する。クリップ中はボタンの
色を変えて状態を示す(色は `theme.ts` の既存定数を使い、新しい色を作らない)。

ドラッグや操作項目のクリックでは自動的にクリップしない。したがって一時ウィンドウは、
ドラッグして移動させたあとでも外側をクリックすれば閉じる。残したいときは明示的にクリップする。

### 5.3 ドラッグ

- **ハンドルはヘッダ部に限定する。** 操作項目の上でドラッグして離すと誤って選択が発火するため。
- クリック/ドラッグの判定閾値は既存の `CLICK_MOVE_THRESHOLD`(6px、`Input.pushIfClick` が使用)を
  流用する。新しい閾値を作らない。
- ドラッグ中にポインタがウィンドウ外へ出るので `setPointerCapture` を使う。使わないと capture 段階の
  外側 pointerdown 検出に拾われて閉じるか、ドラッグが途切れる。
- 位置は既存の純粋関数 `clampOverlayPosition`(`src/game/hud/layout.ts`)を通してビューポート内に
  収める。`tests/physics/hud-layout.test.ts` を拡張してドラッグ後の位置も検証する。
- `window.resize` 時はドラッグ位置を保ったまま再クランプする。

### 5.4 重なり順

`.ctx-menu` は現在 `document.body` 直下・`z-index: 11` 固定で、`#hud` の帯管理の外にある。
複数枚が並ぶので前後関係の規則が要る。

**z-index を増やさず DOM の順序で解決する。** 最前面に出すときは `appendChild` で末尾へ移動
するだけでよい(同一 z-index の兄弟は DOM 順で決まる)。`dom.ts` の重なり順コメントに
プロパティウィンドウの帯を追記する。

### 5.5 毎フレームの同期

残弾・温度・距離は毎フレーム変わるため、開いている全ウィンドウを毎フレーム同期する経路が要る
(`MapPicker.sync` から)。

**`innerHTML` の総書き換えは禁止。** 操作項目のクリックリスナ、✕ ボタン、クリップトグルの
リスナがすべて飛ぶ。値の要素だけを差分更新する(`ObjectListPanel` / `StageStatusPanel` が
同じ理由で採っている方式)。

現在の `ContextMenu.open()` は開いた瞬間に `innerHTML` を組んで以後更新しないので、この点だけは
既存実装をそのまま流用できない。

## 6. 種別ごとのプロパティ

`ObjectPickable['kind']` の9種に対する表示内容。

| kind | プロパティ |
| --- | --- |
| `player` | 名前 / 操作対象か / 計画追従 / 装甲 / 温度 / 電力 / 弾薬 / 基準天体・高度・速度・AP・PE・INC・PRD |
| `ship`(敵) | 名前 / 装甲 / 距離 / 接近速度 / 相対速度 / 軌道要素一式 / 自機軌道面との相対傾斜角 |
| `base` | 名前 / 所持金 / 格納艦数 / 距離 / 軌道要素一式 |
| `ammo` | 距離 / 軌道要素一式 |
| `body` | 表示名 / 種別(恒星・惑星・衛星) / μ / 半径 / 自機からの距離 / 公転天体ならその軌道要素 |
| `apsis` | Pe か Ap / 高度 / 通過時刻 |
| `relnode` / `eqnode` | AN か DN / 対象名 / 通過時刻 |
| `empty-space` | プロパティなし(従来のメニューのまま) |

操作項目は現在の `MapPicker.itemsFor` の内容をそのまま引き継ぐ。

## 7. 既存実装の再利用(必須)

軌道要素一式・敵の距離・接近速度・相対速度・相対傾斜角は、**`HudPanels` の ORBIT / TARGET
パネルが既に同じ導出を持っている**。プロパティウィンドウ側で書き直すと3箇所目になる。

`/add-feature` の手順どおり、共通の導出を再利用可能な形で切り出し、**既存の `HudPanels` 側も
その呼び出しに置き換えるところまでを同じ変更セットで行う**。

## 8. 責務配置

- **`ContextMenu`**(`hud/context-menu.ts`) — 汎用ポップアップ。無変更。
- **プロパティウィンドウ** — 新規。DOM とドラッグ・クリップ・差分更新を持つ。プロパティの
  「値の導出」は持たない(表示専用)。
- **`MapPicker`** — どのオブジェクトにどのウィンドウが開いているかを所有し、毎フレーム同期し、
  ライフサイクル(対象消滅・ビュー離脱)を管理する。種別ごとのプロパティ組み立てもここ
  (既に `handlers` で種別ごとの `itemsFor`/`run` を持っているため、同じ場所に収まる)。
- **`ViewManager`** — マップビューを離れるときに全ウィンドウを閉じるよう `MapPicker` へ通知する
  (既に `MapPicker.close()` を呼ぶ経路がある)。

## 10. 実装順序

各段階で `npm run typecheck` を通し、コミットを分ける。

1. 時間加速 / NODE WARP をグローバルステータスバーへ移設する(単独で意味のある変更)。
2. `HudPanels` の軌道要素・相対情報の導出を共通化し、既存側を置き換える。
3. プロパティウィンドウを新設する(表示と ✕ のみ。ドラッグ・クリップなし)。
   `MapPicker` の右クリックをこちらへ差し替え、毎フレーム同期とライフサイクルを繋ぐ。
4. ドラッグを追加する。`clampOverlayPosition` を流用し `hud-layout.test.ts` を拡張する。
5. クリップを追加する。自動クローズの除外、ショートカットの限定、重なり順を実装する。
6. マップビューで SHIP STATUS を非表示にする(最後に行う。それまでは並存させて比較できる)。
