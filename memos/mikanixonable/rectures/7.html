Dive into Tepui
雲レンダリングシステムの詳細解説

惑星規模のプロシージャル大気循環力学から、GPU 正射影キャップへの動的ベイク、そして不透明表面レイマーチング・大気散乱光路積分・動的雲影の3重描画パイプラインまで。WebGPU (TSL) で構築された雲システムの全容を、パラグラフライティングの原則に基づき解説する。

1. システム概観と全体パイプライン

Dive into Tepui の雲システムは、地上付近から静止軌道に至る超広域な視点移動をシームレスかつ高精細に描画することを主目的として設計されている。地上を歩行・航行する際の局所的な立体雲から、宇宙から地球を見下ろす際の巨大な台風や前線帯までを同一の枠組みで表現するため、当システムは「気象力学シミュレーション」「視点追随型テクスチャベイク」「3系統の分業レンダリング」の3層構造を採用している。

1
視線追随とキャップ配置
CloudPresentation.aim() がカメラ直下点（Subpoint）と天体距離 $\rho$ から視野領域を覆う OrthographicCap の角半径と基底ベクトルを毎フレーム更新する。
2
気象計算と凝結ベイク
WeatherModel が風・気圧・水蒸気を解き、condense() が被覆率・雲頂高度・薄い雲に変換。結果を BakedField が 512×512 RGBA テクスチャへ焼く。
3
3系統の並行レンダリング
焼成された単一の雲場テクスチャから、CloudShapeEvaluator の共通評価規則を通して「不透明表面」「大気散乱」「雲影」へ同時に展開・描画される。

2. 気象モデルと水蒸気力学: WeatherModel

気象モデルは、天体固定座標系の空間単位方向ベクトルと時刻を受け取り、決定論的に気圧偏差・風向・風速・上昇流・湿度を導出する TSL 計算グラフである。src/render/cloud/weather-model.ts に実装された WeatherModel は、CPU のシミュレーションループを介さず、シェーダの閉じた関数として空間位置から直接物理量を評価する。

WeatherSample の主要フィールドと役割

フィールド 型 物理的意味と役割
pressure FloatNode 平年からの気圧偏差 [hPa]。等圧線の勾配から地衡風・旋衡風を解き、気圧の谷で強い上昇流を励起する。
surfaceWind Vec2Node 地表の風ベクトル（東向き $u$、北向き $v$）[m/s]。水蒸気の風上バックトラッキング移流に使用。
lift FloatNode 鉛直上昇流速度 [m/s]。低気圧の中心で強く狭く上昇し、高気圧で広く弱く下降（沈降）する。
surfaceHumidity FloatNode 地表付近の相対湿度 [0..1]。凝結して厚い積雲を形成する主因となる。
upperHumidity FloatNode 対流圏上部の湿度 [0..1]。薄い巻雲や靄の光学的厚みへ変換される。
convection Vec2Node 高周波対流セル。$x$ 成分が細胞の芯（雲の粒）、$y$ 成分が細胞の境界（網目）を表す。
convectiveActivity FloatNode 対流の活発度 [0..1]。日射・海面水温・大気安定度に応じて粒立ちの強さを決定。
band FloatNode 温帯前線帯や熱帯収束帯の帯状集中度 [0..1]。雲頂を一気に押し上げる。

気象場の骨格は、赤道から極への大気循環（Circulation）、偏西風の長波蛇行（RossbyWave）、熱帯低気圧（Cyclones）の重ね合わせで決まる。風向に沿って過去の位置を遡るラグランジュ的バックトラッキング（WeatherTransport）によって海洋からの水蒸気供給と前線形成がリアルに再現される。

3. 雲凝結アルゴリズム: condense()

気象条件から視覚的な雲のパラメータを導く中核が、src/render/cloud/condensation.ts の condense() 純粋関数である。湿度と対流強度の関係を非線形に圧縮し、厚い積雲の被覆率、雲頂の高度分布、および上層巻雲の光学的厚みへと変換する。

3.1 被覆率 (coverage) のガンマ分布モデル

被覆率は、単なるしきい値ステップではなく、雲粒密度の空間的なゆらぎをガンマ分布で混合した代数的裾野を持つ伝達関数によって算出される。指数関数的な減少 $\exp(-t^2)$ を用いた場合、台風の芯や前線のような高湿度域で被覆率が 1.0 に急峻に張り付き、8bit テクスチャ内で階調が飽和して一様な白い台地になってしまう。 

// condensation.ts より抜粋: ガンマ分布による被覆率の階調保持
const excess = max(moistened.sub(COVERAGE_ONSET), 0).div(COVERAGE_WIDTH);
// (1 + excess^2 / 2)^(-2) による代数的な裾野
const clear = excess.mul(excess).div(COVERAGE_DISPERSION).add(1).pow(COVERAGE_DISPERSION).reciprocal();
const coverage = clear.oneMinus();
視覚的利点: この設計により、被覆率が最大でも 0.93 付近で緩やかに寝るため、前線の芯や渦巻きの内部でもテクセル値が飽和せず、積雲の塊や微細な起伏の濃淡が美しく保存される。

3.2 雲頂高度 (cloudTop) の多峰合成

雲頂高度は、3つの異なる大気物理機構（層状雲、積乱雲の塔、サイクロン天蓋）の競合（max）として決定される：

  • 層状の雲 (layered): 上昇流 lift と暖気流入 warmth が押し上げる高さ（1〜7 km）。ロジスティック関数により低気圧の中心でも一様な平坦面にならず対流起伏が残る。
  • 対流の塔 (tower): 対流セルの芯 grain が強い場所で、湿潤かつ上昇流域（rising）にのみ、圏界面（最大 15〜17 km）に向かって二乗則で突き抜ける塔を立てる。高気圧の吹きおろし地域では門（TOWER_LIFT_GATE）が閉じて塔の発生が抑制される。
  • 金床雲 (anvil): 眼を持つ渦の中心部において、圏界面直下に広がる平坦な天蓋として展開する。

求まった雲頂高度は、孤立した小さな雲が不自然に高くならないよう、被覆率 coverage に応じて雲底（1,000 m）へ向けてスケールダウン（scaledCloudTop）される。

4. 雲場のベイクと正射影キャップ: FieldProjection & CloudField

惑星全体の雲を均一な解像度で保持すると、低軌道や地上視点で見下ろした際にテクセルが粗大化し、解像度が破綻する。Dive into Tepui では、視点中心の領域を動的にカバーする正射影キャップ（OrthographicCap）を採用し、GPU レンダーターゲットに毎フレーム必要領域をベイクする。

正射影 UV 導出式の一元化

キャップの幾何学は src/render/cloud/field-projection.ts の orthographicCapUv() 関数で厳密に一元化されている。ベイク側（GPU書き込み）とサンプリング側（レンダラー読み出し）が同一の数式を共有するため、視線がどれほど激しく動いても雲と影の位置が1画素たりともずれることはない。 

// field-projection.ts: 共有される正射影 UV 変換式
export function orthographicCapUv(
  direction: Vec3Node, east: Vec3Node, north: Vec3Node, sinRadius: FloatNode,
): Vec2Node {
  const plane = vec2(dot(direction, east), dot(direction, north)).div(sinRadius);
  return vec2(plane.x, plane.y.negate()).mul(0.5).add(0.5);
}

テクスチャのチャンネル割り当ては CloudSample の型定義と完全に一致しており、R に被覆率（0..1）、G に 15,000m で正規化した雲頂高度、B に上層の光学的厚み（translucent）が格納される。

5. 3系統の描画サブシステム

ベイクされた雲場は、役割の全く異なる3つのレンダラーへと配られる。この分業により、超長距離の軌道上景観から大気突入時の光学的表現までが、無駄のない最適な計算負荷で実現されている。

① 不透明積雲表面 Opaque

OpaqueCloudSurfaceRenderer

厚い積雲の上面を、球殻メッシュ＋シェーダ内レイマーチ（等間隔探索＋二分探索）で不透明なサーフェスとして描く。

  • 幾何 LOD: 見かけピクセル径に応じた球メッシュ分割段（0〜4段）
  • Blue Noise ディザ: 被覆率に応じた確率的二値化による滑らかな網目エッジ
  • 微小粒度ノイズ: 6km周期のノイズを画面微分（Nyquist）でエイリアシング抑制
  • PBR 出力: 勾配差分法による正確な法線（normalNode）と深度（depthNode）

② 大気統合レイヤー Atmosphere

AtmosphereCloudLayers & CloudAtmosphereRenderer

上層の巻雲（15.5km）と半透明積雲（1.0km）を、大気散乱（レイリー／ミー散乱）の光路積分へ挟み込む。

  • 同心球殻モデル: 視線と球殻の交点を光学イベントとして検出
  • Beer-Lambert 則: 鉛直光学的厚み $\tau$ とエアマス $M$ による透過率減衰
  • Front-to-Back 合成: 大気散乱光・背景透過率と雲透過率の順序保存合成

③ 動的雲影 Shadow

CloudShadowRenderer

太陽方向への光路に沿って雲層をマルチタップサンプリングし、地表・大気・機体への直射光減衰マスクを算出。

  • 光路消散積分: 6タップ（SHADOW_TAPS）による高速レイサンプリング
  • ステップブラー: タップ間を2倍のぼかし幅で補間し、影の縞抜けを防止
  • 完全同期: 雲表面と同じ雲頂・被覆率定義を参照し、影と実体が一致

不透明表面レイマーチの内部アルゴリズム（marchedSurface）

OpaqueCloudSurfaceRenderer のフラグメントシェーダは、球殻の入射点 entry から地表までの光路長 marchEnd を計算し、固定刻み数（標準6回）で進めながら clearanceAt() を評価する。空間点が雲頂高度の内側に入った瞬間を検知すると、その直前・直後の区間に対して3回の二分探索（refine）を実行し、微小な起伏の境界を高精度に絞り込む。 

// opaque-cloud-surface-renderer.ts より抜粋: 雲頂法線の勾配差分算出
const here = topAt(up);
// 東と北へ粒の半波長ぶん微小角度を振った雲頂との差分
const slopeEast = topAt(normalize(up.add(east.mul(this.gradientAngle)))).sub(here).div(this.gradientAngle);
const slopeNorth = topAt(normalize(up.add(north.mul(this.gradientAngle)))).sub(here).div(this.gradientAngle);
// 接平面の傾きから法線ベクトルを正規化
return normalize(up.sub(east.mul(slopeEast)).sub(north.mul(slopeNorth)));

法線計算において「雲頂の交点中心距離」ではなく「その方向の雲頂高度を引き直した値（here）」を基準点とすることで、レイマーチの食い込み誤差が法線の傾きに下駄として乗る現象を防ぎ、惑星のリム際（地平線境界）で夜側の雲が不自然に光るアーティファクトを完全に排除している。

6. 整合性の担保: CloudShapeEvaluator

3つの異なるレンダラーが別々のシェーダパスで雲を描くアーキテクチャにおいて最も致命的な問題は、しきい値や雲頂高度の計算式が食い違うことによる「影の形と雲の形が合わない」「大気中の半透明雲が不透明雲と重なった際に境界が二重化する」といった不整合である。

単一責任の原則: src/render/cloud/cloud-shape-evaluator.ts の CloudShapeEvaluator は GPU 資源を一切所有せず、純粋な計算ノード関数（ディザ帯変換・実効雲頂・鉛直柱光学的厚み）のみを提供し、すべてのレンダラーがこのクラスの式を共通利用する。
提供関数 入力パラメータ 出力ノード 利用先と効果
opaqueFraction(coverage, grain) 被覆率, 雲粒ノイズ 不透明割合 [0..1] 不透明表面のディザリング判定、雲影の消散判定。雲の有無の境界が両者で完全一致。
cloudTop(fieldTop, grain) 正規化雲頂, 雲粒ノイズ 実効雲頂 [0..1] 不透明表面のレイマーチ交点、雲影の遮蔽高度。雲の頂上と影を落とす頂上が一致。
columnOpticalDepth(coverage) 被覆率 鉛直光学的厚み $\tau$ 大気統合レイヤーの積雲透過率。不透明雲の縁と大気中の散乱光が自然に繋がる。
