# 第2講：main.ts と Launcher――起動・周回遷移・フレームループ

第1講ではコードベース全体の幹を整理しました。
今回は、その幹の起点である `src/main.ts` と `src/launcher/launcher.ts` を読み解いていきます。

```text
ブラウザがページを開く
  ↓
main.ts が読み込まれる
  ↓
1. 設定・WebGPUキャンバス・HUD・音声・セーブ装置を準備する
  ↓
2. それらを束ねて Launcher を作る
  ↓
3. Launcher が初期ステージの Run を起動する (Run.create / Run.resume)
  ↓
4. requestAnimationFrame で毎フレーム run.frame() を回す
```

今回の目標は、細部の描画シェーダや物理式を追うことではなく、
**「ページ寿命で生きる装置」と「1ランで死ぬゲームモデル」の境界** を明確に理解することです。

---

# 1. main.ts は何をするファイルか

`src/main.ts` は、ゲームの進行ルールを実装するファイルではありません。
このファイルの主な役割は次の4つです。

1. **ページ寿命の装置（`PageDevices`）を生成する**
   - WebGPU キャンバスと `GameScene`（描画装置）
   - `UserSettings`（グラフィックス・音声・HUD設定）
   - `HudShell`, `MarkerDevice`, `PauseMenu`（DOM UI）
   - `AudioEngine`, `Bgm`（音声・BGM再生）
   - `SaveSlots`, `SnapshotService`, `AutoSave`（セーブ・ロード機構）
2. **周回遷移役（`Launcher`）を配線する**
   - ステージ選択、リトライ、タイトル復帰、スロット切替
3. **フレームループ（`startAnimationLoop`）を駆動する**
   - `requestAnimationFrame` で毎フレームの経過時間 `dt` とビューポート矩形を計測
   - 現在アクティブな `Run` に対して `run.frame()` を呼び出す
4. **ラン外の外部ポートを処理する**
   - ゲーム内で消費されなかった入力エッジ（クイックセーブ、セーブブラウザ、リスタート等）を外部へ渡す

```text
main.ts   = ページ全体の設備工場（設定・キャンバス・スピーカー・配線）
Launcher  = ステージ選択・出撃・セーブ復元の司令塔
Run       = 出撃した1回分のゲームセッション（1ラン）
```

---

# 2. 起動シーケンス：main() の流れ

`main.ts` のエントリーポイント `main()` は、次のように順序正しく非同期初期化を進めます。

```ts
async function main(): Promise<void> {
  // 1. 設定の復元とテーマの適用
  const settings = new UserSettings(browserSettingStorage());
  applyThemeVariables(themePresetOf(settings.hudThemePreset.current));

  // 2. WebGPU キャンバスの初期化 (ローディング表示下で実行)
  const gameScene = await initScene(settings.graphics.current);

  // 3. HUD、音声、セーブ装置の生成
  const hud = new Hud(new HudShell(), ...);
  const audioEngine = new AudioEngine();
  const saveSlots = await SaveSlots.create(new LocalStorageSaveStore());

  // 4. Launcher の構築
  const launcher = new Launcher(pageDevices, saveSlots, ...);

  // 5. 初期ステージの起動
  await launcher.launchInitialStage();

  // 6. 描画ループの開始
  startAnimationLoop(launcher, gameScene, settings, ...);
}
```

# 3. アニメーションループと外部ポート

毎フレーム実行される `animate(now)` 関数は、次のような構造を持っています。

```ts
function animate(now: number) {
  const dt = (now - lastTime) / 1000;
  lastTime = now;

  const viewport = browserViewport();
  gameScene.syncFrame(viewport, settings.graphics.current, ...);

  const run = launcher.current;
  if (run === null) {
    // ステージ遷移中などはランが存在しないため、次フレームを予約して抜ける
    requestAnimationFrame(animate);
    return;
  }

  // ランにフレームを回させ、未消費のエッジを外部ポートで受け取る
  run.frame(dt, now, viewport, [
    {
      feature: 'snapshot',
      commands: [gameCommand(K.manualSave.code), gameCommand(K.openSaveBrowser.code)],
      handleCommand: command => snapshotControls.handleCommand(command.id, run.snapshot),
    },
    {
      feature: 'launcher',
      isEnabled: () => !run.game.activeStage.isPlaying,
      commands: [gameCommand(K.restart.code)],
      handleCommand: command => launcher.handleCommand(command.id),
    },
  ]);

  requestAnimationFrame(animate);
}
```

### なぜ外部ポートが必要なのか？
例えばプレイヤーが「F5キー（手動セーブ）」や「Rキー（リトライ）」を押したとき、
その処理はゲーム内の自機や敵の物理運動とは無関係な「ゲームの外側の関心事」です。
ゲーム側が消費しなかったキー操作を外部ポートが受け取ることで、
**「ゲーム進行」と「セーブ・周回管理」の関心事が美しく分離** されています。
