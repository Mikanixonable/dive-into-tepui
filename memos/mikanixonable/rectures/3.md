# 第3講：入力解釈と進行――生イベントから命令・操舵量への変換

第1講・第2講では、起動処理とフレームループ（`Run.frame`）の全体像を学びました。
今回は、プレイヤーのキーボードやマウス操作がどのように解釈され、ゲーム内モデルへ伝わるのかを読み解きます。

```text
ブラウザの生イベント (keydown / pointermove)
  ↓
Input (フレーム間のイベントバッファ)
  ↓
1. 入力解釈位相 (GamePresentation.interpretInput)
  ├─ PilotControls (連続操舵量: スロットル、ピッチ・ヨー・ロール)
  ├─ CommandQueue (不連続命令: 射撃、兵装切替、ターゲット選択、加減速)
  └─ 視点操作 (CameraSystem の回転・ズーム)
  ↓
2. モデル進行 (game.advance)
  ├─ 先頭で CommandQueue を適用 (ポーズ中も命令は消化)
  ├─ DynamicSystem.update で PilotControls に従いスラスター推力を積分
  └─ 未消費のエッジを外部ポート (クイックセーブ・リスタート) へ返却
```

今回の目標は次の3つです。

1. **なぜブラウザの生イベントを直接 `Game` で処理してはいけないのか（単方向フローの理由）**
2. **「連続量（PilotControls）」と「不連続命令（CommandQueue）」の分離**
3. **ゲーム内入力と外部ポート（周回・セーブ操作）の優先順位**

---

# 1. 生イベントを直接ゲームで使わない理由

JavaScript でよくある初心者向けの実装は、`window.addEventListener('keydown', e => ship.x += 10)` のように、イベントリスナーの中で直接キャラクターの位置を書き換えてしまうパターンです。

しかし、本格的なゲームでこれをやると以下の深刻な問題が発生します。

- **ディスプレイのリフレッシュレートと入力タイミングの衝突**: イベントはフレームと無関係に非同期で飛んでくるため、1フレームの間に3回呼ばれたり0回だったりして挙動がブレる。
- **リプレイ・同期・セーブの不可能性**: 「何フレーム目にどのキーが押されたか」を記録できないため、セーブ復元やテスト自動化が不可能になる。
- **操作権限の無視**: メニューを開いてポーズしている最中や、自機が撃墜された後でもキーが反応してしまう。

Dive into Tepui では、**「生イベントを一旦バッファし、フレームの先頭で現在の状況（ポーズ中か、どの自機を選択中か）に応じて解釈し、命令に変換する」** という二段構えをとっています。

---

# 2. PilotControls（連続量）と CommandQueue（不連続命令）

入力解釈（`src/game/presentation/input-phase/game-input-phase.ts`）は、入力を明確に2つの形式へ分類して出力します。

### 1. PilotControls（操縦量・連続入力）
- **対象**: スロットル（前進推力）、姿勢制御（ピッチ・ヨー・ロール）、並進スラスター
- **性質**: フレームごとに押し続けられている強さ $[0, 1]$ または $[-1, 1]$ を持つ連続量。
- **行き先**: `DynamicSystem` 内の自機実体へ渡され、スラスタの燃料消費と力学積分（加速度 $\rightarrow$ 速度 $\rightarrow$ 位置）に使われます。

### 2. CommandQueue（ゲームコマンド・不連続入力）
- **対象**: 主砲発射、ミサイル発射、ターゲット切替、軌道計画マニューバノードの追加、時間倍率変更
- **性質**: キーを押した瞬間（立ち上がりエッジ）に1度だけ発行される命令。
- **行き先**: `game.advance()` の先頭で適用されます。ポーズ中であっても「ポーズ解除」や「軌道計画の編集」コマンドは適用されます。

---

# 3. 未消費エッジと外部ポート

プレイヤーが押したキーが、現在のゲーム状態では使われないことがあります。
例えば：
- 通常飛行中に「F5（クイックセーブ）」を押した
- 自機が撃破されてリザルト画面が出ている時に「R（再出撃）」を押した
- 設定画面を開くために「Esc」を押した

これらは `Run.frame()` の戻り値として外側へ返され、`src/main.ts` が登録した **外部ポート（External Ports）** が優先順に従って拾い上げます。これにより、ゲーム進行モデルがセーブファイルや画面遷移の面倒を見る必要が完全になくなっています。
