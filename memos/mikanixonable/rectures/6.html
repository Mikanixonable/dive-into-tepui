Dive into Tepui のシステム概観

コード現状の読み取り。主要なアクター/サブシステムを6つに絞り、何をやり取りし、どの状態を所有するかをまとめる。

全体の流れ

ページ起動時に main.ts が、ランをまたいで生きる設定・セーブ・描画・HUD・音声の装置を組み、Launcher に渡す。Launcher はステージを選び、Run.create または Run.resume で1ランを起こす。

ブラウザ入力 + 設定 + viewport
  │
  ▼
1. 入力の解釈（GamePresentation / GameInputPhase）
  │  CommandQueue、PilotControls、視点操作
  ▼
2. 進行（Game / Stage / DynamicSystem / Simulator）
  │  simTime、エンティティ、ステージ、RunEventLog
  ▼
3. 導出（表示窓・カメラ・予測・選択候補）
  │  表示時刻、CameraFrame、HUD/マーカー/音の宣言
  ▼
4. 装置同期・描画（render / hud / marker / audio）

src/run/run.ts の Run.frame がこの順序を所有する。ゲーム側で消費されなかった押下エッジは、進行後にセーブ・ラン遷移・デバッグ用の外部ポートへ渡される。モデルを書き換える命令は CommandQueue に積まれ、次の進行位相の先頭で適用される。

1. ページ寿命の組み立て役

main.ts / Launcher / settings / launcher/save

責務

ページ全体で1つだけ必要なものを生成し、現在のランを開始・終了・再開・交換する。main.ts は設定、GameScene、HUD、マーカー、音声、セーブ関連を生成して PageDevices に束ねる。Launcher はステージ選択、タイトル復帰、再出撃、スナップショットのロード、スロット切替を担う。

やりとり

  • URL、ステージ選択、スロットから StageClass と開始元期を決める。
  • Run.create / Run.resume に装置、設定、進行状況の読み取り役を渡す。
  • Run の SnapshotSource を SnapshotService / AutoSave へ渡す。
  • ステージ決着の RunEventLog を読み、解放状況更新と結果画面表示へつなぐ。

管理する状態

Launcher の現在の Run・起動ステージ・遷移中フラグ、UserSettings の描画/音声/HUD設定、SaveSlots の索引・スナップショット、AutoSave の実時間基準を持つ。艦・敵・simTime は持たない。

根拠: src/main.ts:192-243、src/launcher/launcher.ts:46-188、src/settings/user-settings.ts:27-95、src/launcher/save/snapshot-service.ts:15-81

2. フレームの交通整理役

Run

責務

1ランの Game（モデル）と GamePresentation（表示導出）を組み合わせ、毎フレームの位相と呼び出し順を固定する。dt は最大0.1秒に丸められ、nowMs と viewport が下流へ渡る。

やりとり

  1. interpretInput で命令と操作量を作る。
  2. game.advance でモデルを進める。
  3. 表示窓・カメラ・出来事・予測需要を導出する。
  4. progressReader.update で保存可能な進行後状態を外部へ見せる。
  5. sync、render で装置を更新する。

管理する状態

モデルと表示導出の所有関係、破棄済みフラグ、描画設定への参照、フレーム計測と保存用の読み取り口を持つ。艦や敵を更新するのではなく、誰に何を渡すかだけを持つオーケストレータである。

根拠: src/run/run.ts:1-28、src/run/run.ts:94-178

3. 1ランの進行モデル

Game / Stage / DynamicSystem

責務

捨てると再構成できないゲーム内状態を持ち、命令と操作量で進行を確定する。Game は天体系、動的物体、時間倍率、操作対象、ステージ、計画ノード規則、視点、出来事ログを束ねる。

やりとり

  • 入力解釈から CommandQueue と PilotControls を受ける。
  • advance の先頭で出来事を空にし、命令を適用する。ポーズ中も命令は適用する。
  • SimSpeedManager が倍率を決め、Stage.update が湧き・勝敗・ステージ固有状態を更新する。
  • DynamicSystem.update が自律推力、操作対象の指令、敵AI、積分を処理する。
  • 一回きりの変化は RunEventLog に記録し、表示側が通知・音・エフェクトへ変換する。

管理する状態

DynamicSystem の simTime・全エンティティ・pending spawn・ID採番器、SimSpeedManager、ControlSelection、Stage の勝敗/スコア/補給/ステージ固有状態、PlanNodeRules を持つ。これらは SerializedGame.progress に直列化される。

根拠: src/game/game.ts:25-69、src/game/game.ts:152-251、src/game/dynamic/dynamic-system.ts:59-136、src/game/stages/stage.ts:107-182

4. 天体系と物理計算

CelestialSystem / physics / Simulator

責務

天体の階層、暦、運動、参照座標系、重力源・大気天体の索引を提供する。physics/ は THREE や DOM を知らない計算層で、CelestialSystem はその値をゲーム側と表示側へ提供する。

やりとり

  • Game.create/deserialize が元期から星系を構築し、暦を天体運動へ結び付ける。
  • Simulator が天体窓を使い、個体の重力、大気、表面接触をサブステップで解く。
  • Predictor が動的物体と天体系を読み、表示要求ぶん予測を伸ばす。
  • 表示導出が stateAt、参照フレーム、軌道ガイド、天体マーカーを読む。

管理する状態

天体の親子階層、origin、epoch、暦、運動一覧、参照フレーム、軌道ガイド、天体ビュー/GPU資源を持つ。ただし進行時刻 simTime の正本は天体系ではなく DynamicSystem 内の Simulator である。天体系は指定時刻の状態を答える。

根拠: src/game/celestial/celestial-system.ts:85-169、src/game/celestial/celestial-system.ts:296-416、src/game/dynamic/simulator.ts:28-166

5. 入力と表示の導出

GamePresentation / GameInputPhase / DisplayPhase

責務

ブラウザ入力をモデルの命令/操作量へ変換し、モデルの結果を表示宣言へ変換する。モデルを直接描画せず、モデルの正本も直接書き換えない。

やりとり

  • Input → rawGameInputAdapter → GameInputRouter → feature port。
  • PilotInput が PilotControls を組み、所有者の命令を CommandQueue へ積む。
  • DisplayWindowManager と FrameAnchors が表示時刻/座標系/カメラを確定する。
  • trajectoryDemand を Game.extendPredictions へ渡し、予測を更新する。
  • 天体、動的物体、計画、HUD、マーカー、効果音、通知を各装置の語彙へ写す。

管理する状態

Viewer がビュー、カメラ、航法ターゲット、軌道ガイド、実体表示、軌道基準、予測パネルを所有し、セーブ対象になる。表示側は直近の CameraFrame、表示窓、ピック候補、マーカー宣言、UI音キュー、一時エフェクトなどの導出キャッシュを持つ。

根拠: src/game/game-presentation.ts:75-126、src/game/runtime/game-input-phase.ts:20-94、src/game/runtime/display-phase.ts:17-91、src/game/viewer/viewer.ts:17-105

6. 外部装置

render / hud / marker / audio

責務

ゲームの意味を進めず、そのフレームに見せる・鳴らすべき内容をGPU、DOM、マーカー、WebAudioへ同期する。ページ寿命の装置は main.ts で一度だけ作られる。

やりとり

  • GameScene / RenderPipeline がカメラ、表示時刻、描画設定、Three.jsオブジェクトを同期して描画する。
  • Hud が HudPanelViewModels、ビュー、トースト、モーダル状態をDOMへ反映する。
  • MarkerDevice が MarkerDeclaration を投影し、重なりを解決する。
  • Bgm / WorldSfx / UiSfx が音の宣言を前フレームとの差分として鳴らす。

管理する状態

GPU renderer/scene/pipeline、DOMレイヤとパネル、マーカー群、AudioContext/BGM conductor、viewport、外部資源のキャッシュを持つ。艦のHP、敵の生死、勝敗、simTime は持たない。

根拠: src/run/page-devices.ts:1-18、src/render/scene.ts:11-73、src/game/hud/hud.ts:34-159、src/audio/audio-engine.ts:1-63

状態の所有関係

状態正本他へ渡る形寿命
描画品質・配色・音量・HUD共通選択UserSettings現在値 + callback/購読ページ/セーブをまたぐ
艦・敵・弾・simTimeDynamicSystem / Simulator読み取り面、SerializedDynamicSystem1ラン、セーブに入る
勝敗・スコア・補給・波StageStageOutcome、イベント、SerializedStage1ラン、セーブに入る
視点・ターゲット・カメラ選択Viewer命令 + 読み取り面、SerializedViewer1ラン、セーブに入る
直近の一回きりの変化RunEventLogrecent を表示導出が読む1進行ステップ
予測・表示窓・ピック候補・マーカーPredictor / GamePresentation装置への宣言毎フレーム再導出
GPU・DOM・音声資源GameScene / Hud / AudioEnginesync / renderページまたはラン

情報の流れは「入力を命令へ変える → 進行モデルが正本を更新する → 表示導出が読み取り面から宣言を作る → 外部装置が同期する」で閉じている。Game と装置の間に GamePresentation があるため、描画・DOM・音声はゲーム進行の正本を直接書き換えない。
