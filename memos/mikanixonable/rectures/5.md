# 第5講：コードベースを読む4本の軸――指令・時間・未来・保存

第4講では、`src/game/` 以下の全体を見渡し、`DynamicSystem` や `CelestialSystem`、`Simulator` といった各サブシステムの担当領域を地図にしました。

今回は、さらに一歩進んでコードの「設計の意図」に踏み込みます。
何十個ものファイルをただ順番に眺めるのではなく、このゲームの設計を支えている **4本の中心軸** を押さえることで、コードベース全体の構造が驚くほどクリアに見えるようになります。

```text
第1の軸：指令（Command）  第2の軸：時間（Time）   第3の軸：未来（Future）  第4の軸：保存（Save）
       │                       │                      │                     │
       ▼                       ▼                      ▼                     ▼
入力を誰へ渡すか？      ルールと物理をどう繋ぐ？ 軌道予測をどう計算する？ 状態をどう保存・再開する？
（ControlSelection）     （Stage / Simulator）  （Plan / Predictor）   （Snapshot / SaveSlots）
```

この4本が理解できると、新しい機能を追加したりバグを調査したりするときに、次のような判断が自分自身で下せるようになります。

- 「このデータの『正本（マスターデータ）』は誰が持っているか？」
- 「この値は『現在の実体』なのか、『派生した計算結果』なのか、『未来の予測』なのか？」
- 「新機能を足すとき、どこに責務を持たせるべきか？」

---

# 1. 第1の軸：指令（Command）――入力を誰へ渡すか

プレイヤーがキーボードやゲームパッドを操作したとき、その入力は誰に向けられたものかを厳密に決定する軸です。

- **`ControlSelection` (`src/game/control-selection.ts`)**:
  現在プレイヤーがフォーカスしている自機エンティティの ID を保持します。自機が複数編成されているステージでは、Tab キー等で操作対象を瞬時に切り替えることができます。
- **`PilotControls`**:
  選択された自機実体へ毎フレーム渡され、その自機のスラスター推力・姿勢制御ノズル（RCS）のみを点火させます。選択されていない味方艦は、自律AI（自動編隊維持や迎撃）モードへフォールバックします。

---

# 2. 第2の軸：時間（Time）――実時間と物理時間の乖離

ゲームには「ディスプレイの実時間（`nowMs`, `dt`）」と「ゲーム内宇宙の物理時間（`simTime`, `simDt`）」という2つのまったく異なる時間が流れています。

- **`SimSpeedManager` (`src/game/sim-speed-manager.ts`)**:
  プレイヤーの倍率変更要求（一時停止 0x、通常 1x、早送り 3x / 10x）を管理し、1フレームに進めるべきシミュレーション時間 `simDt` を計算します。
- **サブステップ物理積分 (`Simulator`)**:
  軌道力学では、速度が秒速7kmを超える超高速移動を行うため、フレームレートが落ちた時に1ステップで大きく動かすと惑星を突き抜けてしまいます。`Simulator` は `simDt` を微小なサブステップ（例: 0.02秒単位）に細かく刻んでルンゲ＝クッタ法などの高精度積分を行い、数値誤差の蓄積を防ぎます。

---

# 3. 第3の軸：未来（Future）――軌道計画と予測演算

宇宙飛行では、「いまエンジンを噴射した結果、30分後にどの軌道へ乗るか」を事前に予測できなければ目的地（宇宙ステーションや月）へ到達できません。

- **`Plan` (`src/game/plan/plan.ts`)**:
  プレイヤーが作成したマニューバノード（何分何秒後に、どの方向へ、どれだけの $\Delta v$ を噴射するかという計画）を保持します。
- **`Predictor` (`src/game/dynamic/predictor.ts`)**:
  現在の自機位置・速度から、計画された噴射を反映した未来の軌跡を数十ステップ〜数千ステップ先まで仮想的に高速積分し、未来の軌道楕円・近地点・遠地点・目標天体との会合点（インターセクト）を導出します。

---

# 4. 第4の軸：保存（Save）――ステートレスとシリアライズ

「セーブしてゲームを終了し、明日再開する」あるいは「別スロットへセーブを複製する」ための機構です。

- **進行モデルの直列化 (`SerializedGame.progress`)**:
  `Game` クラスの内部状態（`simTime`、全動的エンティティの座標・速度・質量・燃料、天体系元期、ステージ進捗スコア）は、すべてプレーンな JSON 構造体へシリアライズ可能な形で設計されています。
- **`SnapshotService` & `SaveSlots`**:
  ゲームの実行を一切止めずに現在のスナップショットを採取し、ブラウザの LocalStorage や IndexedDB へ不揮発保存します。ロード時は `Run.resume()` にそのデータを渡すだけで、1フレームで完全に同一の物理状態が復元されます。
