# 積雲のボリュームレイマーチ化 実装計画

## 目的

現在の積雲は、方向ごとの `coverage` と `cloudTop` から一枚の不透明な雲頂面を作っているため、
coverage や雲頂高度の等値線が地形の等高線のように見える。雲を連続した密度場として視線方向へ積分し、
雲頂面に依存しない厚み・透過・散乱を実現する。

## 決めたこと

- 近距離・中距離・遠距離を含む全距離で、ボリューム表現を正本にする。
- 既存の2D雲場を入力として使い、coverage・cloudTop・高度方向プロファイルから連続密度を求める。
  3Dテクスチャを新規アセットとして導入しない。
- 不透明 G-buffer の雲頂面を廃止し、雲をボリュームの前方合成として描画する。
- カメラ描画・大気散乱・太陽影は同じ密度評価を共有する。
- 品質より物理的な一貫性を優先し、標準設定での負荷は実測して品質設定へ反映する。
- 実装は専用 worktree のサブエージェントへ委譲し、統合と最終判断は workspace3 で行う。

## 達成目標

- 雲の深度・色・法線相当の見え方に、雲頂高度や coverage の等値線に沿った帯が現れない。
- 視線方向・視距離・昼夜境界にかかわらず、雲の厚みと透過が連続する。
- カメラからの雲、大気越しの雲、雲影が同じ表示時刻の同じ密度場と整合する。
- 遠距離では細部が安定して縮退し、LOD 境界で雲が飛んだり二重に見えたりしない。
- `npm run typecheck`、`npm run test:render`、render-lab の撮影検証が通る。
- 変更範囲の責務分割・コメント・重複実装が `DEVELOP/CODING-RULE.md` に適合する。

## 手順

### 手順1. 仕様と密度モデルの確定

#### 目的

実装に先立ち、雲の見え方を「一枚の表面」ではなく「高度方向に密度を持つ体積」として固定する。

#### 変更が必要な箇所

| ファイル | 変更内容 |
| --- | --- |
| `DEVELOP/SPEC/RENDERING.md` | 雲に厚み・連続性・同一密度場の要件を追加済み。 |
| `memos/mikanixonable/volumetric-cloud-raymarch-plan_2026-09-09.md` | 実装判断・達成条件・リスクを保持する。 |

#### 達成条件と検証

仕様に「雲頂面を重ねない連続体積」「カメラ・大気・影の整合」が記載され、コード変更前に密度モデルの入力と出力が説明できることを確認する。

### 手順2. 共有密度評価の実装

#### 目的

既存の2D場を coverage・雲頂高度・高度方向の密度へ変換する責務を、描画経路から分離する。

#### 変更が必要な箇所

| ファイル | 変更内容 |
| --- | --- |
| `src/render/cloud/cumulus-shape.ts` | 表面高度へ coverage を掛ける責務を廃止し、体積密度・光学深度の共通入力を定義する。 |
| `src/render/cloud/condensation.ts` | 既存場から高度方向密度を得るために必要な値を、連続な雲底・雲頂・厚みとして提供する。 |
| `src/render/cloud/volumetric-density.ts` (新規) | 方向・高度・粒・視距離幅から密度を評価する共有ノードを実装する。 |
| `tests/render/*` | density の境界、晴天、雲頂、粒の縮退を検証するケースを追加する。 |

#### 達成条件と検証

同じ入力に対し、カメラ・大気・影から同じ密度評価を呼べること。coverage が 0 の柱は透過し、coverage が高い柱は高度方向に連続した密度を持ち、雲頂位置で密度が段階的に切れないことを render テストと `npm run typecheck` で確認する。

### 手順3. カメラ向けボリューム描画への置換

#### 目的

一方向一枚の不透明な雲頂面を廃止し、雲の底から上端までの視線区間を積分する。

#### 変更が必要な箇所

| ファイル | 変更内容 |
| --- | --- |
| `src/render/cumulus-shell.ts` | 不透明 G-buffer の表面交差探索を廃止し、ボリュームの透過・散乱を描く描画物へ置換する。既存の詳細度設定はサンプル密度へ対応させる。 |
| `src/render/pipeline/atmosphere-layer.ts` | カメラから見たボリュームの合成順と、天体・地表・艦艇との遮蔽を整理する。 |
| `src/game/celestial/celestial-entity/point-entity.ts` | 雲の表示状態・LOD・時刻同期を新しい描画物へ接続する。 |
| `src/render/graphics-settings.ts` | 既存の積雲詳細度をボリュームサンプル品質へ対応させる。 |
| `src/render/pipeline/render-pipeline.ts` | 不透明雲を前提にした登録・描画順を更新する。 |

#### 達成条件と検証

深度・法線・影の境界を一枚の雲頂面から生成するコードがなくなり、視線に沿った透過率と散乱が出力されることを検索で確認する。`npm run typecheck`、`npm run test:render`、`npm run render-lab:shot` を実行し、地球の正面・斜め・リム・昼夜境界で帯状模様、二重描画、黒化がないことを確認する。

### 手順4. 大気中の雲散乱の統合

#### 目的

現在の固定半径シェルによる半透明積雲を、カメラ向けボリュームと同じ密度場の積分へ統一する。

#### 変更が必要な箇所

| ファイル | 変更内容 |
| --- | --- |
| `src/render/pipeline/cloud-scattering.ts` | 固定シェルの代表点評価を廃止し、視線区間の密度から散乱・透過を評価する。 |
| `src/render/pipeline/atmosphere-layer.ts` | 雲と大気の積分順、blue noise の適用範囲、雲の二重積分を整理する。 |
| `src/game/celestial/celestial-entity/point-entity.ts` | 大気パスへ渡す雲の入力を共有密度場へ変更する。 |

#### 達成条件と検証

不透明雲を無効にしても、半透明シェルだけが同じ等高線を再表示しないこと。`npm run test:render` と render-lab で、雲が大気に霞み、昼夜境界で高い雲が残り、視線の長さに応じて透過が連続することを確認する。

### 手順5. 雲影の統合

#### 目的

雲影だけが高さマップの別解釈になる状態を廃止し、太陽光路を共有密度場で積分する。

#### 変更が必要な箇所

| ファイル | 変更内容 |
| --- | --- |
| `src/render/pipeline/shadow/cumulus-shadow.ts` | `opaqueFraction` と雲頂の一点判定を廃止し、太陽光路の密度積分から透過率を求める。 |
| `src/render/pipeline/shadow/shadow-pass.ts` | 新しい積雲影の入力幅・LOD・適用順を接続する。 |
| `src/render/pipeline/shadow/shadow-select.ts` | 表示・品質設定との条件を新しい雲描画物へ合わせる。 |
| `src/game/celestial/celestial-system.ts` | 雲場と時刻の同期を維持したまま、新しい影入力を渡す。 |
| `src/game/celestial/celestial-entity/point-entity.ts` | 影へ渡す雲の状態を更新する。 |

#### 達成条件と検証

雲影の幅・濃さ・境界が、カメラから見た雲の密度分布と一致すること。`npm run typecheck`、`npm run test:render`、太陽高度を変えた render-lab 撮影で、影に雲頂の等高線やサンプル段が出ないことを確認する。

### 手順6. 品質設定・LOD・アセット寿命の整理

#### 目的

全距離のボリューム描画を実用的な品質設定へ収め、テクスチャ・密度場・描画物の所有権を整理する。

#### 変更が必要な箇所

| ファイル | 変更内容 |
| --- | --- |
| `src/render/cumulus-shell.ts` | 詳細度に応じたサンプル数・粒の振幅・フィールド幅を整理する。 |
| `src/render/cloud/baked-field.ts` | 必要なフィルタリング、mipmap、解像度選択を密度サンプリングに合わせる。 |
| `src/render/cloud/generated-cloud-field.ts` | 全距離の入力場としての解像度・更新・破棄を検証する。 |
| `src/render/graphics-settings.ts` | 品質設定の名称と意味をボリューム品質へ揃える。 |
| `src/render/pipeline/cloud-scattering.ts` | 画面 footprint に応じたサンプル品質と縮退を統一する。 |

#### 達成条件と検証

品質設定の切り替えで雲の位置や濃さが飛ばず、遠距離で高周波ノイズがモアレにならないこと。各設定の render-lab 撮影、`npm run typecheck`、`npm run test:render` を通す。標準設定のフレーム時間を変更前後で計測し、実測値を最終報告へ記載する。

### 手順7. リファクタリングと最終検証

#### 目的

ボリューム化の実装後に責務の重複、旧表面方式の残骸、過剰なコメントや未説明の公開関数を整理する。

#### 変更が必要な箇所

手順2〜6で触った `src/render/cloud/`、`src/render/pipeline/`、`src/render/cumulus-shell.ts`、および接続を変更した `src/game/celestial/` を対象にする。仕様文書と既存のユーザー変更は対象外とする。

#### 達成条件と検証

`opaqueFraction` を雲の表面高度へ掛ける実装、旧固定シェルだけを使う積雲経路、同じ密度式の重複実装が残っていないことを検索と差分レビューで確認する。`npm run typecheck`、`npm run test:render`、必要な render-lab 撮影を再実行する。

## 見積り

見積りは、実装後に標準設定の画面解像度と GPU 実測を得て更新する。初期の試算は、視線方向の `S_view` サンプル、太陽光路の `S_shadow` サンプル、大気の `S_atmosphere` サンプルを各ピクセルで評価するため、追加密度評価費用を

```text
追加時間/frame ≈ pixelCount × (S_view + S_shadow × shadowReceivers + S_atmosphere) × densityCost
```

で測る。品質設定ごとのサンプル数を確定値として書くのは、GPU実測後とする。

## リスクと落とし穴

| リスク | 影響 | 露見する場所 |
| --- | --- | --- |
| ボリュームを大気パスへ移した際に地表・艦艇との深度順が崩れる | 雲が地表の後ろへ回る、または艦艇を誤って隠す | 手順3・4の render-lab、ブラウザログ |
| カメラ・大気・影が別々の密度式を持つ | 雲影や輪郭がずれる | 手順4・5の昼夜・低太陽高度撮影 |
| レイマーチのサンプル数不足 | 透明度の段差、リムの帯、ちらつき | 手順3・4の coarse/standard 撮影 |
| 既存 blue noise を密度境界へ誤適用する | 雲や影が時間的にちらつく、影が飛ぶ | 手順3・4・5の連続フレーム確認 |
| 2D場の解像度・mipmap不足 | 遠距離でモアレや地球規模の帯が残る | 手順6の距離別撮影 |
| 旧 CumulusShell と新ボリュームを同時に描く | 雲が二重に濃くなる、輪郭が太る | 手順3・4の不透明/半透明切り替え確認 |
| 密度場の所有権が `point-entity` や配線層へ漏れる | 時刻・姿勢の不整合、破棄漏れ | 手順7の責務レビュー |
| 全距離ボリューム化で標準設定が重くなる | WebGPU のフレーム落ち | 手順6のフレーム時間計測 |
