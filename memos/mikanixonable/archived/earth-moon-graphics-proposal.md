# 地球・月グラフィック向上要件案

## 背景と意図

舞台は文明崩壊後の氷河期にある地球・月系である。目標は単なる高精細化ではなく、実寸・実時刻・実太陽方向を使う現在の軌道シミュレーションと整合し、周回中に「光、空気、水、氷、地形が同じ物理条件へ反応している」と感じられる景観を作ることにある。

都市夜景は不要であり、地表の暗さ、氷床、雲、オーロラ、薄明、月面地形を主要な視覚情報とする。科学可視化ではなくゲーム映像なので、物理的な依存関係を守りつつ、露出と細部は可読性のために限定的に調整する。

## 現状

- 地球表面は8Kカラー画像と8K雲画像を1枚の高分割球へ合成している。
- 雲は固定画像で、影はUVを一定量ずらした近似である。
- 大気は地表の簡易Beer–Lambertもやと、加算合成の単一リム球である。
- 夕焼けは太陽角に応じた固定オレンジ色の補間で、波長別散乱ではない。
- オーロラはCPUで毎フレーム頂点と色を更新する4枚の帯である。
- 月は8Kカラー画像をLambert陰影する64×32球で、標高・法線・クレーター自己影はない。
- near 2 m、far数千万m、24bit深度、浮動原点のため、地表近傍に別シェルを重ねると地平線付近でz-fightingしやすい。

## 要件判断

### 採用

1. **物理ベース大気**

   Rayleigh散乱、Mie散乱、オゾン吸収、太陽直達光の減衰を単一の大気モデルで扱う。地表から宇宙まで連続し、青空、薄明、地球縁の大気、夜側へ回り込む薄明を同じ式から得る。現在の固定色リムと地表もやは置換する。

2. **夕焼け・薄明**

   独立したオレンジ色エフェクトではなく、大気散乱の結果として生成する。太陽高度による黄・橙・赤・紫の遷移、地球影、オゾンによる青紫成分を含める。

3. **雲の移流、立体感、影**

   雲画像を低層・高層の2層へ分け、地球固定座標上で異なる速度の東西移流と緩い変形を行う。雲高度から太陽方向へ地表投影して影を求め、固定UVオフセットを廃止する。雲の自己陰影と前方散乱は簡易近似でよい。

4. **地形・法線・地形影**

   標高マップと法線マップを導入する。遠景では法線による陰影、近景では視差または頂点変位を使う。山岳の長い影は太陽高度が低い場合に限定した地形シャドウ近似を追加する。

5. **海面反射**

   海マスク、Fresnel反射、太陽の鏡面反射、粗さ、波法線を導入する。宇宙視点で重要なサングリントを再現する。氷結した海域は海面BRDFから氷雪BRDFへ遷移させる。

6. **地表の材質差**

   海、雪氷、裸地、岩、森林・植生をマスクで分け、粗さ・Fresnel・拡散反射を変える。単一の「異方性反射」ではなく、必要な地表だけへ方向性を与える。植生には弱いhotspot/後方散乱、海には波方向由来の異方性、雪には強い前方散乱を使う。

7. **氷河期と季節変化**

   現代の季節画像を切り替えるのではなく、軸傾斜・太陽赤緯・緯度・高度・海陸から積雪ポテンシャルを計算する。文明崩壊後の基準状態として恒常的に拡大した氷床・海氷を置き、その上へ季節変動を加える。植生は現代より縮小し、積雪・低温域では抑制する。

8. **オーロラの再構築**

   固定緯度リングを廃止し、磁極を中心とする楕円状オーロラオーバル、局所時依存、途切れ、複数カーテン、鉛直方向の色分離を表現する。下層の緑、上層・高エネルギー域の赤、限定的な青紫を持たせる。動きはCPU頂点書換えではなくシェーダ内ノイズとテクスチャスクロールを基本とする。

9. **月面地形とクレーター影**

   月の標高・法線・粗さマップを導入し、低い太陽高度でクレーター縁と山地が長い影を作るようにする。遠景は法線/ホライズンマップ、近景は頂点変位または限定的なparallax occlusionを用いる。

10. **露出と色管理**

    太陽、昼側地球、夜側、月面を同時に扱えるHDR線形照明とトーンマッピングを明示設定する。カメラの自動露出はゆっくり変化させ、ビュー切替で明滅しないようヒステリシスを持たせる。

### 修正して採用

- **「厚みのある連続的大気圏」**は多数の透明球殻では実装しない。現行の深度精度では帯状ノイズとz-fightingを生むため、解析的レイ積分または事前計算LUTを使う単一大気パスとする。
- **「季節による植生」**は日々変化する動的植生シミュレーションにしない。月〜季節スケールの補間マスクとし、氷河期設定を優先する。
- **「地形に基づく影」**は全球リアルタイムシャドウマップにしない。地球規模では精度・コストが不釣り合いなため、法線、地平線遮蔽、低太陽角専用の近似を組み合わせる。
- **「大気の反射」**は独立項として扱わず、散乱と地表・雲からの多重散乱近似へ統合する。

### 延期または廃止

- 全球の流体気象シミュレーションは対象外。雲は決定論的な移流・変形で十分とする。
- 全球の地形を実寸ポリゴン変位する方式は廃止。頂点数、深度精度、メモリ消費に対して視覚効果が小さい。
- フルスペクトル大気計算は延期し、RGBまたは少数波長の近似を採用する。
- パストレーシング、雲の完全な多重散乱、月面全域のリアルタイムレイトレース影は対象外。
- 人工光、都市、航空灯火、稼働中の文明由来エフェクトは追加しない。

## 追加要件

- 日食・月食時に、地球大気を通った赤い光が月面へ届くこと。
- 地球の球形による雲・大気・地表の正しい遮蔽と、昼夜境界の一致。
- 極域の海氷、棚氷、氷河、季節積雪を別の粗さ・反射特性で表現すること。
- 雲頂が夕日を受け、地表が夜へ入った後もしばらく明るく見えること。
- 月の地球照を弱く表現すること。地球の位相と距離に連動させる。
- 地球と月で光源方向、食、表示時刻を共有し、未来表示でも矛盾しないこと。
- 乱数表現はシード固定とし、同じシミュレーション時刻で同じ画像を返すこと。

## 推奨アーキテクチャ

### 地球表面パス

1枚の地球メッシュ上で、以下を線形空間で合成する。

```text
surface = BRDF(material, normal, sun, view)
cloudShadow = projectCloudToSurface(cloudHeight, sunDirection)
terrainShadow = horizonOcclusion(sunDirection)
direct = surface * cloudShadow * terrainShadow
final = atmosphereTransmittance * direct + atmosphereInscatter
```

カラー、標高、法線、海、氷雪、植生、粗さは別マップまたはチャンネルパックしたテクスチャとする。1024×768分割球は過剰なので、法線・変位方式を決めた後に適正分割へ下げる。

### 大気パス

Bruneton型または同等の事前計算LUTを第一候補とする。透過、単散乱、多重散乱近似をLUT化し、カメラが大気外・内部のどちらでも同じモデルを評価する。WebGPU/TSLでLUT生成が不安定な場合は、オフライン生成したLUTを読み込む。

### 雲パス

当面は地表と同じシェーダ内で疑似高度を持つ2層サンプリングとし、別メッシュを増やさない。近距離で立体雲が必要になった段階で、画面占有領域を限定した低ステップレイマーチへ移行する。

### オーロラパス

少数のカーテンメッシュへ、磁気座標、磁気地方時、時間ノイズを入力する。頂点位置は低頻度更新、細かな揺らぎと発光はGPUで計算する。加算合成は維持するが、露出に応じた上限を設ける。

### 月面パス

月専用の `CelestialSurface` 派生または専用ノード材質を作る。標高から生成した法線とホライズンマップを基本とし、距離に応じて低分割球、法線陰影、高分割変位を切り替える。

## 実装順序

1. HDR線形パイプライン、トーンマッピング、露出を固定する。
2. 地球/月の材質入力を整理し、法線・粗さ・海・氷雪マスクを導入する。
3. LUT大気を導入し、現行もや・固定夕焼け・リムを置換する。
4. 雲の2層移流と物理的な雲影を導入する。
5. 海のFresnel反射とサングリント、地表BRDFを導入する。
6. 地球の標高法線・地形遮蔽、月のクレーター陰影を導入する。
7. 氷河期基準マスクと季節変化を導入する。
8. オーロラを磁気オーバル方式へ置換する。
9. 月食の赤色光、地球照、近距離用LODを追加する。

各段階を独立に比較可能にし、一度に全面置換しない。

## 実行可能性

| 項目 | 実行可能性 | 主なリスク |
|---|---|---|
| LUT大気・夕焼け | 高 | TSL/WebGPUでのLUTサンプリングと色管理 |
| 雲移流・雲影 | 高 | シーム、極域のUV歪み、時間ワープ時の速度 |
| 海面反射・地表BRDF | 高 | 過剰なサングリント、テクスチャ入力不足 |
| 標高法線・月面クレーター陰影 | 高 | データ容量、近距離LODのポッピング |
| 地形の長距離自己影 | 中 | 全球精度と性能の両立 |
| 季節・氷河期変化 | 中〜高 | 気候的説得力のある基準データ作成 |
| リアルなオーロラ | 中〜高 | 磁場モデルと芸術的可読性の調整 |
| 立体雲レイマーチ | 中 | GPU負荷、透明合成、低性能端末 |
| フル物理気象・多重散乱 | 低 | ゲームの目的に対して過大 |

## 非機能要件

### 性能

- 目標解像度1920×1080で、地球が画面の大半を占める最悪条件でも描画予算を定める。
- デスクトップ基準で追加GPU時間を通常3 ms以内、最悪6 ms以内とする。
- 大気レイ積分はLUT中心、雲レイマーチは品質設定と画面占有率で制御する。
- 8Kテクスチャを無条件に常駐させず、用途別解像度、チャンネルパック、可能ならGPU圧縮を使う。
- CPUでの全球頂点更新を毎フレーム行わない。時間依存の細部はGPUへ移す。

### 精度と一貫性

- 太陽方向、自転、季節、食はエフェクトごとに再計算せず、共通uniformから得る。
- 浮動原点と距離圧縮下でも、照明計算は真の天体位置・方向を使う。
- warp変更で雲やオーロラが瞬間移動しない。視覚時間へ上限付き追従または連続位相を使う。
- 大気・雲・海・地表で色空間を統一し、sRGB画像を線形値として誤使用しない。

### 品質と検証

- 太陽高度、位相角、季節、カメラ高度を固定した画像回帰シーンを用意する。
- 基準ケースは昼側、薄明、夜側、低軌道地平線、全球遠景、日食、月食、満月、半月、月の低太陽角とする。
- NASA等の画像は露出・波長・画像処理を確認し、絶対輝度の基準と外観参考を区別する。
- 物理純関数、大気交差、雲影投影、季節係数にはDOM/THREE非依存テストを作る。
- WebGPU未対応・低性能環境では品質段階を落とし、黒画面にしない。

### 保守性・データ

- `earth.ts`を表面、大気、雲、オーロラ、季節のモジュールへ分割する。
- 調整値と物理定数を分離し、単位・出典・適用範囲をコメントする。
- 外部データには出典、ライセンス、加工手順、再生成スクリプトを付ける。
- 品質設定は共通プリセットにまとめ、個別の隠し係数を増やさない。

## 完了条件

- 宇宙、低軌道、大気縁で大気が連続し、独立した明るい輪に見えない。
- 夕焼けが太陽高度と光路長から生じ、昼夜境界と一致する。
- 雲が連続移動し、影の方向と距離が太陽・雲高度に一致する。
- 海のサングリント、雪氷、植生、裸地が同じ照明下で異なる材質に見える。
- 氷河期の基準景観と季節変化が両立し、都市夜景が存在しない。
- オーロラが固定リングではなく磁気オーバルとカーテンに見える。
- 月のクレーターと山地が低太陽角で形を読み取れる影を作る。
- マップビューと戦闘ビューで太陽方向、位相、食、季節が矛盾しない。
- 品質プリセットを下げても主要な昼夜・大気・材質差が保持される。
