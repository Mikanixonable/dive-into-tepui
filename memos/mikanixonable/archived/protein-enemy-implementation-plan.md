# タンパク質型敵 実装計画

## 1. 目的

5I4Rタンパク質型敵を、単なる高精細モデルではなく、部位・錯体・分子修飾・構造運動が戦闘ルールに結び付く敵へ拡張する。

完成時に、プレイヤーが次の因果関係を画面から理解できる状態を目指す。

1. 活性部位が発光して攻撃を予告する。
2. 球は敵の中心ではなく活性部位から発射される。
3. 活性部位や結合界面を狙うと、対応する機能が停止する。
4. 錯体の解離や分子修飾によって、外見と攻撃パターンが変化する。
5. 構造安定性または核心部を破壊すると撃破となる。

Molecular NodesとBlenderは、開発時にGLBと意味情報JSONを生成するオフライン・コンパイラとしてのみ使用する。ゲーム実行時にはPDB/mmCIF解析、DSSP、Ribbon生成、Molecular Nodes、Blenderを含めない。

## 2. 設計原則

- GLBには描画に必要な形状、マテリアル、morph target、アンカーを保存する。
- JSONにはChain、Entity、部位、HP、作用、修飾、ゲーム上の役割を保存する。
- 生物学的事実とゲーム設定を区別し、出典・推定・ゲーム指定を記録する。
- 原子単位の処理はビルド時に終わらせ、実行時は部位アンカーと簡易コライダーを扱う。
- ブラウン振動で毎フレームメッシュを再生成しない。
- 通常の敵処理との互換性のため、敵全体の`hp/maxHp`は維持する。
- タンパク質固有状態は`Enemy`へ直接詰め込まず、専用コンポーネントへ分離する。
- エフェクトは必ずゲーム上の状態を伝える。装飾だけの発光パターンを増やさない。

## 3. 対象範囲

### 対象

- 5I4RのMolecular Nodesによるオフラインモデル生成
- GLBと意味情報JSONの読込
- 活性部位・結合界面・核心部のアンカー
- 部位別HPと機能停止
- 活性部位からの射撃
- 錯体の段階変化と解離
- OU過程とmorph targetによる構造運動
- PBR光沢、発光、損傷表現
- 分子修飾とリガンド着脱
- タンパク質専用HUD
- セーブ・ロード
- LODと性能検証

### 初期対象外

- ゲーム中の原子レベル分子動力学計算
- 毎フレームのRibbon再生成
- 残基ごとの物理コライダー
- 5I4Rと関係のないDNAの付加
- BlenderまたはMolecular Nodesのランタイム同梱
- すべてのタンパク質へ自動的に正しいゲームルールを割り当てること

## 6. 意味情報スキーマ

初期スキーマは次を基準とする。

```json
{
  "schemaVersion": 1,
  "id": "pdb-5i4r",
  "source": {
    "pdbId": "5I4R",
    "structureFile": "source.cif"
  },
  "components": [
    {
      "id": "component-a",
      "chains": ["A", "E"],
      "entities": [1],
      "role": "game-assigned-role"
    }
  ],
  "sites": [
    {
      "id": "primary-active-site",
      "type": "active",
      "source": "author",
      "residues": ["A:42", "A:87"],
      "anchor": "site_primary_active",
      "position": [0, 0, 0],
      "forward": [0, 0, 1],
      "radius": 1.8,
      "maxHp": 40,
      "damageMultiplier": 1.5,
      "actions": ["plasma-burst"]
    }
  ],
  "modificationSlots": [],
  "motion": {
    "morphTargets": 4,
    "ouTheta": 1.2,
    "ouSigma": 0.08
  }
}
```

`source`は以下のいずれかとする。

- `author`: mmCIFまたは原論文に明示されている。
- `computed`: リガンド距離や構造解析から算出した。
- `game`: ゲームデザイン上追加した。

EntityやChainの生物学的役割は自動推定せず、出典を確認したうえで`protein.config.json`に明示する。

## 7. 体力と部位破壊

### 7.1 状態モデル

タンパク質型敵には、敵全体の構造安定性と部位別HPを持たせる。

```ts
type ProteinPhase = 'intact' | 'exposed' | 'dissociated' | 'critical';

interface ProteinHealthPool {
  hp: number;
  maxHp: number;
}

interface ProteinSiteState extends ProteinHealthPool {
  id: string;
  disabled: boolean;
}

interface ProteinCombatState {
  integrity: ProteinHealthPool;
  sites: ProteinSiteState[];
  phase: ProteinPhase;
}
```

### 7.2 ダメージ経路

```text
弾丸と敵全体のバウンディング球が接触
  ↓
impact pointを敵ローカル座標へ変換
  ↓
site sphere/capsuleの内側か判定
  ├─ 該当する → 部位HPへダメージ
  └─ 該当しない → 構造安定性へダメージ
  ↓
部位停止・フェーズ遷移・撃破判定
```

同時に複数部位へ該当した場合は、中心までの正規化距離が最小の部位を選ぶ。初期実装では1発を複数部位へ分配しない。

### 7.3 HP表示

- 既存のTARGETパネルには構造安定性を表示する。
- タンパク質型をロック中だけ、主要部位を最大3本表示する。
- 部位を狙っているときは、対象部位名と残HPを強調する。
- 部位が停止したら、HP 0だけでなく「射撃停止」「結合解除」などの結果を表示する。

## 8. 活性部位からの射撃

現在の敵中心からの発射を、GLBアンカーまたはJSONの局所座標へ置き換える。

### 発射状態

```text
idle → charging → firing → cooling → idle
```

- `idle`: 通常表示。
- `charging`: emissiveを増加し、周囲から粒子を集める。
- `firing`: アンカー位置から弾とマズルエフェクトを生成する。
- `cooling`: 発光を減衰し、一時的に再発射を禁止する。
- 対応する部位HPが0なら`disabled`となり、射撃しない。

発射方向は従来の見越し射撃を正本とする。アンカーの`forward`は、発射演出の向きと、見越し方向が不正な場合のフォールバックに使う。

## 9. 錯体とフェーズ戦

### フェーズ案

| フェーズ | 条件 | ゲーム状態 | 見た目 |
|---|---|---|---|
| Intact | 初期状態 | 高防御、規則的射撃 | Chain間の結合線が安定 |
| Exposed | 結合界面を1つ破壊 | 活性部位の被害倍率増加、射撃強化 | 部位露出、発光増加 |
| Dissociated | 必須界面を破壊 | 構成要素が分離し、複数方向から行動 | Chain/Entityが離れる |
| Critical | 核心部が閾値以下 | 高頻度だが不安定な攻撃 | 振動増幅、内部発光 |

解離は一度に全メッシュを爆散させない。GLB内で構成要素を別ノードとして持ち、フェーズ遷移時に局所位置を補間する。必要な構成要素だけ短時間の小型敵または攻撃ノードとして扱う。

## 10. 分子修飾

分子修飾はアンカーへアタッチする表示メッシュと、ゲーム状態の組み合わせにする。

| 修飾 | 表現 | 効果候補 |
|---|---|---|
| リン酸化 | 小さな発光基 | 発射速度・旋回速度上昇 |
| 糖鎖 | 分岐メッシュ | 部位への被害軽減、ロック妨害 |
| リガンド・金属結合 | 球または小分子 | 特殊弾・チャージ攻撃を有効化 |
| ユビキチン様修飾 | 小型タンパク質 | 時間経過弱体化または分解予告 |
| 脱修飾 | アタッチ物の離脱 | バフ解除、弱点露出 |

実際の5I4Rに存在しない修飾は`source: game`として明示する。

## 11. DNA・RNA

5I4RにDNAを直接追加することは初期計画へ含めない。構造に存在しないDNAを付けると、生物学的表示とゲーム上の創作の境界が不明瞭になるためである。

核酸表現は将来、次のどちらかで導入する。

1. DNA/RNA結合構造を持つ別のPDBエントリから専用敵を作る。
2. 5I4R派生の架空個体として明示し、核酸をゲーム用カーゴとして追加する。

核酸型では、DNA/RNAを装飾ではなく、シールド、切断可能部位、修復対象、召喚源などの戦闘機構へ結び付ける。

## 12. ブラウン振動と構造運動

### 12.1 三層構成

| 層 | 方法 | 負荷 | 当たり判定への反映 |
|---|---|---:|---|
| 全体揺動 | OU過程による微小並進・回転 | 極小 | 原則なし |
| 構造振動 | 4〜8個のmorph targetをOU過程で合成 | 小 | 原則なし |
| 機能運動 | 制御アニメーション、ノード移動 | 小 | 必要なアンカーのみ反映 |

単純Brownian motionは無制限に漂流するため、平均姿勢へ戻るOrnstein–Uhlenbeck過程を使う。乱数状態はセーブ対象とするか、敵IDと時刻から再現可能にする。

### 12.2 LOD

- 近距離: 全morph target、活性部位エフェクト、構成要素運動。
- 中距離: morph target数または更新頻度を削減。
- 遠距離: rigid transformのみ。
- マップビュー: 構造運動を停止。

毎フレームのGeometry生成、Spline再計算、Ribbon再構築は禁止する。

## 13. 材質と光沢

GLBのPBRマテリアルを基礎とし、実行時に状態連動パラメータを加える。

- 通常Ribbonは低〜中光沢とする。
- 活性部位はemissiveと輪郭発光を持つ。
- 結合界面は薄いパルスまたはエネルギー線で接続する。
- 糖鎖・リガンド・核酸は粗さを変え、本体と判別できるようにする。
- 損傷時は粗さ、明滅、色の不安定さを増やす。
- 臨界状態では内部から光が漏れる表現を加える。

全面を均一に強く光らせず、重要部位の視認性を優先する。

## 14. VFXと音

追加するVFX:

- 活性部位チャージ
- 活性部位マズルフラッシュ
- 部位被弾時の局所フラッシュ
- 分子流入・流出粒子
- Chain間の結合線
- リガンド結合時のリング波
- 修飾の付加・脱離
- 錯体解離
- 臨界振動と内部発光
- Chain単位の撃破残光

追加する音の役割:

- チャージ開始を事前に伝える音。
- 活性部位停止を伝える短い機能停止音。
- 結合界面破壊を伝える低い解離音。
- 臨界フェーズへの遷移を伝える持続音。

色・動き・音は同じ状態を示すよう統一する。

## 15. 段階実装

### Phase 0: 基準値と移行境界

作業:

- 現在の5I4R敵の描画負荷、頂点数、ドローコール、生成時間を記録する。
- 現行の色切り替え、スポーン、セーブ、射撃、被弾の回帰条件を整理する。
- 新旧モデルを切り替えられる開発用フラグを用意する方針を決める。

完了条件:

- 新実装の性能と挙動を比較できる基準が記録されている。

### Phase 1: 最小アセットパイプライン

作業:

- Blender CLIとMolecular Nodesで`source.cif`を読み込む。
- Cartoon/Ribbonを生成し、Geometry Nodesを評価済みメッシュへ変換する。
- Chain/Entityごとのノードまたはマテリアルグループを作る。
- `model.glb`と最小`protein.json`を生成する。
- スキーマ検証とGLB/JSONのID整合性検査を追加する。

完了条件:

- 1コマンドで5I4RのGLBとJSONを再生成できる。
- ゲーム本体を起動せず生成物を検証できる。

### Phase 2: ランタイム読込

作業:

- `ProteinAssetLoader`を追加する。
- 非同期読込中の表示、失敗時の既存モデルへのフォールバックを定義する。
- Chain/B-Factor/Entity着色の維持方法を確定する。
- 既存の`pdb-5i4r` EnemyKindから新アセットを選べるようにする。

完了条件:

- クリエイティブステージから新5I4Rをスポーンできる。
- 従来敵の描画・スポーンに変化がない。

### Phase 3: 部位と複数HP

作業:

- `ProteinCombatState`と部位状態を実装する。
- 敵の広域球判定後に部位コライダーを解決する。
- 部位HP、構造安定性、被害倍率、機能停止を実装する。
- TARGETパネルへ主要部位を表示する。
- セーブデータへフェーズ、構造HP、部位HPを追加する。

完了条件:

- 活性部位と通常部への命中で異なるHPが減る。
- 部位破壊がセーブ・ロード後も維持される。
- 旧セーブは全快の部位状態として読み込める。

### Phase 4: 活性部位射撃

作業:

- 発射アンカーの局所座標をワールド座標へ変換する。
- チャージ、発射、冷却状態を実装する。
- 弾、マズルフラッシュ、音をアンカーから生成する。
- 活性部位停止時に対応攻撃を無効化する。

完了条件:

- 敵が中心ではなく活性部位から射撃する。
- プレイヤーが予告を見て回避できる。
- 活性部位を破壊すると射撃が停止または弱体化する。

### Phase 5: 光沢と構造運動

作業:

- PBR光沢、粗さ、emissiveを調整する。
- rigid OU揺動を実装する。
- 4〜8個のmorph targetをOU過程で駆動する。
- LODに応じた更新停止・低頻度化を実装する。
- morph中のアンカーずれを評価し、必要ならボーンまたはアンカー用変形を追加する。

完了条件:

- 構造が永久に変形・漂流しない。
- 遠距離やマップビューで不要な更新が止まる。
- 活性部位と発射位置が視覚的に乖離しない。

### Phase 6: 錯体フェーズ

作業:

- 結合界面HPを追加する。
- Intact、Exposed、Dissociated、Criticalの遷移を実装する。
- 構成要素の分離アニメーションと攻撃変化を追加する。
- 解離要素を小型敵にする場合の所有権、スコア、デスポーンを定義する。

完了条件:

- 部位破壊の順序によって戦闘展開が変わる。
- フェーズ遷移が色、動き、音、HUDから判断できる。

### Phase 7: 分子修飾

作業:

- 修飾スロットと状態遷移を実装する。
- 修飾メッシュの表示切り替えを追加する。
- 修飾による攻撃、防御、回復、ターゲット性の変化を追加する。
- 修飾の付加・脱離VFXを実装する。

完了条件:

- 少なくとも1種類の修飾が外見とゲーム能力の両方を変える。
- 修飾状態がセーブ・ロードされる。

### Phase 8: 核酸型への拡張

作業:

- DNA/RNA結合構造を持つ候補PDBを選ぶ。
- 核酸を独立コンポーネントとして出力する。
- 切断、修復、シールドなどの専用ゲームルールを設計する。

完了条件:

- 核酸が装飾ではなく攻略対象として機能する。
- 生物学的構造とゲーム上の創作がメタデータ上で区別される。

## 17. テスト計画

### ビルド時検証

- GLBとJSONの`proteinId`が一致する。
- JSONがスキーマに適合する。
- すべてのsite anchorがGLB内に存在する。
- 半径、HP、座標にNaNや負数がない。
- Chain/Entity参照がsource.cifに存在する。
- LODとmorph targetの頂点対応が正しい。

### 単体テスト

- ワールド座標と部位ローカル座標の変換。
- 部位コライダー選択。
- 部位HPと構造HPのダメージ振り分け。
- フェーズ遷移条件。
- OU過程が有限範囲に留まること。
- 修飾による能力倍率。
- 旧セーブからの既定値移行。

### ブラウザスモークテスト

- 5I4Rをスポーンできる。
- Chain/B-Factor/Entity表示を切り替えられる。
- 活性部位から弾が出る。
- 部位を破壊すると攻撃が止まる。
- セーブ後に再開して部位状態が維持される。
- 通常敵の射撃・被弾・撃破が回帰していない。

### 視覚レビュー

- αヘリックスとβシートの形状が一般的なCartoon表示と一致する。
- 活性部位が通常部から判別できる。
- 光沢がプラスチック状に強すぎない。
- ブラウン振動で構造が崩れて見えない。
- 発射位置が活性部位から外れない。
- フェーズ変化を説明なしでも識別できる。

## 18. 性能方針

- 近距離の高詳細タンパク質は少数に制限する。
- LODごとに頂点数、ドローコール、morph target数を記録する。
- 部位判定は原子数に比例させず、site数に比例させる。
- 毎フレームの一時配列、Geometry、Material生成を避ける。
- 同一タンパク質のGeometryとMaterialは可能な範囲で共有する。
- 非表示・遠距離・マップビューではmorphと部位VFXを止める。
- 実装前後で`tools/perf-probe.mjs`相当の計測を行う。

## 19. リスクと対策

| リスク | 対策 |
|---|---|
| Molecular NodesまたはBlender更新で生成結果が変わる | バージョン固定、生成物検証、再生成手順を文書化 |
| GLBで独自属性が失われる | 重要な意味情報はJSONを正本にする |
| morph targetとアンカーがずれる | 揺動を小さくするか、アンカー用ボーン・変形を焼く |
| 複数HPでUIが煩雑になる | 主要部位を最大3本に絞り、結果を機能名で表示 |
| 生物学的意味を誤って割り当てる | `author/computed/game`を必須化し、自動推定しない |
| 高詳細モデルが多数出現して重くなる | LOD、共有、遠距離停止、同時出現数制御 |
| タンパク質固有処理がEnemyを肥大化させる | `ProteinRuntime`へ委譲し、EnemyKind分岐を入口に限定 |
| セーブ互換性が壊れる | 任意フィールドと`schemaVersion`を使い、旧データを既定値へ移行 |

## 20. コードレビュー観点

- タンパク質処理が通常敵のロジックへ漏れていないか。
- GLBとJSONの責務が混ざっていないか。
- 生物学的属性とゲーム設定を同一視していないか。
- HPの正本が複数箇所にできていないか。
- 部位破壊後に射撃やVFXだけが残らないか。
- セーブ・ロードでフェーズと修飾が完全に復元されるか。
- morph更新がゲーム内時刻と描画時刻のどちらに従うべきか明示されているか。
- 時間加速によって射撃数やOU運動が不整合にならないか。
- MaterialやGeometryを個体ごとに不要に複製していないか。
- 失敗時に既存5I4Rへ安全にフォールバックできるか。

## 21. 推奨する最初の実装単位

最初のマイルストーンは、以下を一続きで完成させる。

1. 5I4Rから`model.glb + protein.json`を生成する。
2. ゲームでGLBを読み込んでスポーンする。
3. 手動指定した1つの活性部位を発光させる。
4. その活性部位から予告付きで弾を発射する。
5. 活性部位に専用HPを持たせ、破壊すると射撃を停止する。
6. セーブ・ロードと通常敵の回帰テストを通す。

この単位が完成すれば、タンパク質構造が外見だけでなく戦闘ルールとして機能する。その後にmorph、錯体解離、修飾を追加する。

## 22. 優先順位

1. 活性部位からの予告付き射撃。
2. 部位HPと機能停止。
3. 錯体解離によるフェーズ変化。
4. 活性部位・結合界面の発光と光沢。
5. OU過程とmorph targetによる構造振動。
6. 分子修飾。
7. DNA/RNAを持つ別敵。
8. 厳密な分子動力学軌跡。

最終的な評価基準は、形状の精細さだけではなく、「どこが攻撃しているか」「どこを壊せば何が止まるか」「錯体が変化した結果、次に何が起きるか」をプレイヤーが画面から理解できることである。
