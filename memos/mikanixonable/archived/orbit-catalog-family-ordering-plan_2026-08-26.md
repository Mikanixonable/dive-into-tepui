# 周期軌道カタログの族並び順を連続性で組み直す(2026-08-26)

## 目的

軌道ガイドの族が、族に沿って連続に変化しない。地球-月 L1 ハロー北で顕著で、族の位置 0.46
あたりで月にいちばん近い軌道に達したあと、0.58 を超えたところから軌道が L1 側へ戻り、続いて
長楕円状の大きな軌道が並ぶ。

原因は取得側にある。JPL の `periodic_orbits.api` は族のメンバーを**ヤコビ定数 C の昇順**で
返すが、`tools/fetch-orbit-catalog.mjs` はこれを「族に沿った連続順」と見なして、その添字で
等間隔に 30 件へ間引いている。L1 ハロー族は NRHO 域で C が2回折り返すため、C 昇順に並べると
族の3つの区間が交互に混ざる。地球-月 L1 ハロー北の生データ 5731 件では、添字 4421〜4936
(C ∈ [2.9978, 3.0041]、全体の約 9%)で1行おきに別区間の軌道が現れる:

```
4607 x=0.86133 z=0.18490 C=2.999507 T=2.3798
4608 x=0.88629 z=0.19552 C=2.999536 T=2.0544
4609 x=0.92637 z=0.22071 C=2.999541 T=1.8094
4610 x=0.86120 z=0.18482 C=2.999556 T=2.3818   ← 4607 の続き
4611 x=0.88644 z=0.19557 C=2.999565 T=2.0528   ← 4608 の続き
```

月の位置座標との齟齬ではない。回転座標系への写像は実際の月位置と公転面法線から組んでおり、
族の並び順には関与しない。

修正後は、焼き込まれた族が `DEVELOP/SPEC/MAP.md`「ガイド線の正確さ」の要求 —「族に沿って形が
連続に変わる」— を満たす。族の位置を 0 から 1 へ動かしたとき、軌道の形が一方向へ単調に変化し、
途中で L1 側へ戻ったり別形状の軌道が割り込んだりしない。

## 決めたこと

**A. 並べ替えは貪欲最近傍による鎖の再構成で行う。**(実施済み)
6次元の初期状態ベクトル `[x, y, z, vx, vy, vz]` の距離を尺度に、起点の**両側へ**伸ばして1本の
鎖を作る。片方向にしか伸ばさないと、起点が族の途中にあったときに一方の端で行き止まり、そこから
反対側へ跳んで並びが壊れる(地球-月 axial-L1 で鎖の 43.2% と 93.2% に跳びが出た。両方向に
直したところ 50.0% の1箇所だけになった)。両方向に伸ばすなら起点はどこでもよいので、C 最大から
組み直す再試行は入れていない。並べ替えた並びは、総弦長が元の C 順より短いときだけ採る。

**B. 採否は「総弦長が C 順より短いか」で決め、C 順への差し戻しは事実上起きない。**(実施済み)
当初は「最大ステップ ≤ 中央値の 8 倍」を採否の基準にしていたが、これは測るものを間違えていた。
JPL の刻みが疎な区間では、並びが正しくても大きなステップが何十本も連続して現れる(sun-earth
halo-L1-N の 95.1〜95.5%、earth-moon lpo-E の 6.9〜12.8%)。この基準では、正しく並んだ族まで
交錯したままの C 順へ差し戻していた(250 族中 37 族)。

**C. 断絶の検出は「大きなステップが 1〜2 本だけ孤立しているか」で行い、警告に留める。**(実施済み)
中央値の 8 倍を超えるステップが連続する塊のうち、長さ 2 以下のものだけを断絶と数える。疎な刻みは
塊が長く、繋がらない枝の境目は孤立する。断絶が残った族も並びは採る — 各枝の内部は連続に並び、
交錯した C 順より必ず良いため。

**D. 間引きは6次元状態ベクトルの累積弦長で等間隔に取る。**(ユーザー判断)
鎖を組むのと同じ尺度を使う。位置だけで測ると、NRHO 域のように形が小さいまま周期が急変する
区間の刻みが粗くなる。両端は必ず含める。

**E. 再取得は 7 系すべてを回す。**(ユーザー判断)

**F. `familyVisualS`(`src/physics/orbit-guide.ts:181`)を廃し、族の位置をメンバー添字へ
そのまま対応させる。**
この関数は「焼き込み元データの並び順の疎密」を打ち消すために、周期とヤコビ定数を正規化した
空間での弧長で族の位置を測り直している。D により間引きの時点で見た目の変化量が等間隔になる
ため、この測り直しは補正ではなく歪みになる。とくに C が折り返す族では、折り返し区間へ不相応に
多くの目盛りが割り当てられる。

**根拠と、覆されたときに変わる手順**: `DEVELOP/SPEC/MAP.md` の「族に沿った位置の値そのものが、
焼き込み元データの並び順に対して均等である必要はない」は、均等に**見える**ことだけを要求して
いる。D を入れれば添字がそのまま均等なので要求を満たす。覆す(関数を残す)なら手順4を落とし、
代わりに `familyVisualS` の尺度を焼き込み点列の幾何距離へ変える手順に差し替える。

## 残っている判断

- **族の端の外れ値を落とすか。** `saturn-enceladus longp-L4`・`longp-L5` は先頭の1件だけが
  族から外れており、間引きが先頭を必ず含めるため、族の位置 0 に形の違う線が1本出る。端の
  断絶に限って落とす手当ては入れていない(2/250 族なので、警告に留めた)。

## 残っている判断

- **1本に繋がらない 12 族をどう扱うか。** API が1つの族として返すデータが、互いに繋がらない
  枝に分かれている。各枝の内部は連続に並ぶので、族の位置を動かすと1箇所で形が飛ぶ。
  枝ごとに別の族として出す手当ては入れていない。
- **焼き込みで族の途中に穴が開く 3 族。** `jupiter-europa axial-L3`(4 件)・
  `mars-phobos axial-L1`(9 件)・`mars-phobos axial-L2`(8 件)で、族の端以外に主星・副星へ
  衝突するメンバーが残り、個別に除外されている。`DEVELOP/SPEC/MAP.md`「族の途中に穴を
  開けない」に反する。いずれも上の「繋がらない族」と重なっており、枝の扱いを決めれば同時に
  解消する見込み。
- **族の使える区間が狭い族のメンバー数。** 間引きは衝突判定より前に行われるため、族の大半が
  天体へ衝突する族ほど残るメンバーが薄くなる。`earth-moon halo-L1-N` は 30 件中 5 件が残る
  (L1 ハロー族は NRHO 域を過ぎると近月点が月半径を割り、族の末端は月への衝突で終わるため)。
  焼き込みメンバーの合計は 5990 → 5813(-3.0%)。衝突判定を取得側へ移して、使える区間の中で
  間引き直す手当ては入れていない。
