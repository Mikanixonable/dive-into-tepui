# 計画 04 — やり直しと導入: 撤退、詰みの検知、援護、自己ベスト、最初の3分

コードのスナップショット: `bbe81c893`

## 目的

負けても次をやりたくなる導線と、入口で心が折れない導入を作る。

- **詰みからの出口が無い。** ステージ2で燃料を使い切ってモルニヤ軌道の敵に届かなくなると、勝ちも
  負けもしないまま漂い続ける。決着前に使えるのは ESC の「タイトル画面に戻る」だけで、同じ
  ステージをやり直すにはステージ選択から選び直すしかない。
- **やり直しの価値が見えない。** 自己ベストを記録していないので、何度遊んでも前より良かったかが
  分からない。ステージ00の負けの画面は「撃破 N/出現 M 機」で、生き延びるほど出現数が増えて
  比率が悪く見える。喪失理由の文は何が起きたかを言うだけで、次に何を避ければよいかを言わない。
- **連敗に救いが無い。** 同じステージで負け続けても、条件はずっと同じ。
- **入口が分からない。** タイトルに推奨の入口が無い。ステージ0の初期補給は 75〜225 m 先にあり、
  弾 0 から始まるので、拾うまで撃てない。

### SPEC へ追記・置換する文面(手順 1 で書く)

**GAME.md 6「ラン遷移」に足す:**

> - **撤退**: 勝敗判定を行うステージでは、決着前でも ESC メニューの「撤退して再出撃」で、その
>   ランを敗北として終え、結果画面を経ずに同じステージを最初から始め直せる。撤退したランは
>   自己ベストの記録に数えない。
> - **詰みの提案**: 決着前に次のいずれかが 20 秒続いたら、ヒントで撤退を提案する(「打つ手が
>   無いなら ESC → 撤退して再出撃」)。提案は1ランに1回まで。
>   - 弾が尽き(マガジンも装填中の弾も 0)、軌道上に弾薬補給が無い。
>   - 主推進と RCS の燃料が両方尽き、交戦圏の中に敵がいない。
>   - 操作できる艦がいない。
> - **援護**: 同じステージで続けて 3 回負けると、結果画面に「援護つきで再出撃」を足す。援護つきの
>   ランは、開始直後に自機のそばへ弾薬補給を2個投入する。援護つきの勝利もアンロックに数える。
>   勝つか、別のステージを始めると、連敗の数は 0 に戻る。連敗の数はページを閉じると消える。
> - **自己ベスト**: 結果画面に、そのステージの自己ベストとの差を出す。比べる値はステージごとに
>   決める — ステージ0は撃墜数、ステージ00は到達波数、ステージ1・2はミッション時間(短いほど
>   良い。勝利のときだけ比べる)。ベストを更新したら「自己ベスト更新」と出す。
> - 結果画面には、そのランで軌道上に残ったデブリの数も出す(撃破デブリは天体に落ちるまで漂い
>   続けるので、撃墜の重さの尺度になる)。
> - 敗北の結果画面は、喪失理由の下に、次に避けるべきことを1行で添える(例: 再突入で焼失 →
>   「近地点を大気の上へ保て」)。

**GAME.md 2.3「ステージ00」に足す:** 「敗北の結果画面では到達波数を主に出し、撃破数を添える。」

**GAME.md 1「起動とステージ選択」に足す:** 「ステージ0の行には『はじめての人へ』の印を添え、

## 決めたこと

| 決めたこと | 根拠 | 覆されたときに変わる手順 |
| --- | --- | --- |
| 撤退は結果画面を経ずにすぐ始め直す | やり直しは速いほど冷めない。撤退は詰みからの脱出口なので、反省の画面を挟まない | 手順 2 |
| 詰みの判定時間は 20 秒、提案は1ランに1回 | 弾切れは補給を探して取りに行く間にも成り立つので、短すぎると誤報が増える。何度も出すと煽りになる | 手順 3 の定数 |
| 援護は「弾薬補給 2 個の投入」だけにし、敵の弱体化はしない | 敵の同時発砲上限は `enemy-fire-controller.ts` の定数で、ステージから変える経路が無い。通すには進行の深い所まで引数を足すことになる。補給の投入なら既存の台本投入で済む | 手順 4 |
| 連敗の数は保存しない | 援護の提案は、その場の流れに対するもの。ページを閉じた後にまで持ち越す理由が無い | 手順 4 |
| 自己ベストはセーブデータのステージ履歴に持つ | ステージ履歴はすでにクリア回数を持つ。セーブデータ(歴史線)ごとに分かれるのが自然 | 手順 5 |
| ステージ0の行を最初に出す | ステージ0は弾 0 から補給を拾わせる、実戦の形をした練習になっている | 手順 7 |

## 達成目標

1. ステージ2の途中で ESC →「撤退して再出撃」を押すと、結果画面を経ずにステージ2が最初から
   始まる。その後にページを再読み込みしても、撤退前のランへは戻らない。
2. 弾を撃ち尽くし、補給も無い状態で 20 秒待つと、撤退を勧めるヒントが1回だけ出る。
3. 同じステージで3連敗すると、結果画面に「援護つきで再出撃」が出る。押すと、自機のそばに
   弾薬補給が2個ある状態で始まる。
4. ステージ0を2回遊ぶと、2回目の結果画面に1回目の撃墜数との差が出る。上回れば「自己ベスト更新」
   と出る。別のセーブデータに切り替えると、ベストは別になる。
5. ステージ00の敗北画面の先頭に到達波数が出る。どの結果画面にも「軌道上のデブリ N 個」が出る。
6. 喪失理由ごとに、次に避けるべきことの1行が出る。
7. タイトルのステージモードのタブで、ステージ0の行が「はじめての人へ」の印つきで最初に出る。
8. `npm run typecheck`・`npm run test:game`・`npm run test:launcher` が通る。

## リスクと落とし穴

| リスク | 影響 | 露見する場所 |
| --- | --- | --- |
| 撤退で `noteRunEnded` を呼び忘れる | 「始め直したはずが、自動セーブから同じランが再開される」 | 手順 2(テストで当てる) |

| 援護の投入を自動セーブの開始より後に行う | 開始直後の自動セーブに補給が入らず、再読み込みで援護が消える | 手順 4(`applyAssist` を `autoSave.beginRun` より前に呼ぶ) |
