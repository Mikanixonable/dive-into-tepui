# 計画 02 — 手応え: 撃墜と喪失の一瞬の止め、逆光の散布界を見せる

コードのスナップショット: `bbe81c893`

## 目的

km 単位で撃ち合うこのゲームでは、敵は画面上でマーカーの大きさにしか見えず、撃墜も被弾も
「光った気がする」で終わる。シューティングでは気づいたらやられていることが多く、大事な一瞬を
止めれば何が当たったかが分かる。さらに、散布界が逆光で開き、順光で締まる規則は良い駆け引き
なのに、画面のどこにも出ていないので、知らなければ存在しないのと同じになっている。

この計画では次の3つを入れる。

1. 撃墜の瞬間と自機喪失の瞬間に、ゲーム世界の時間を短く遅くする(撃墜ストップ)。
2. 自機が被弾したときに、画面を短く揺らす。
3. 機首方向のボアサイトマーカーに、いまの散布界の倍率を出す。

**対象外**: 撃破の爆発の段階・敵マーカーの命中表示・効果音の優先順位は SPEC で定まり
(`bbe81c893`)、別の作業で `src/game/flash-presenter.ts`・`src/render/billboard.ts` を実装中。
この計画ではこの2ファイルに触らない。

### SPEC へ追記する文面(手順 1 で書く)

**COMBAT.md「戦闘エフェクト」に節を足す(「撃破の爆発」の後):**

> ### 撃墜の止め
> - 自機を除く艦が撃破(弾・剛体接触による破壊)された瞬間と、自機を喪失した瞬間は、ゲーム世界の
>   時間の進みを短い間だけ遅くする。撃破は実時間 0.25 秒のあいだ 0.2 倍、自機の喪失は実時間
>   0.6 秒のあいだ 0.1 倍に落とし、終わりに向けて等倍へ戻す。
> - 遅くなるのはゲーム世界の時間だけである。カメラの操作・HUD・効果音・ステージの残り時間や波の
>   タイマーは実時間で進む。
> - 時間加速が ×1 のときだけ働く。一時停止中・建造中は働かない。止めの最中に次の撃破が起きたら、
>   残りの長い方へ揃え、足し合わせて延ばすことはしない。
> - これは見せ方の演出であり、止めている間も物理の規則は変わらない(遅く進むだけ)。

**CAMERA.md に節を足す(「5. ガンサイトズーム」の後):**

> ## 6. 被弾の揺れ
> - 戦闘ビューで操作中の自機が弾を受けたとき、視点を短く揺らす。揺れは最初が最も大きく、
>   0.3 秒で収まる。向きには小さな無作為さを持たせる。
> - 揺れるのは表示だけで、照準・ガンサイト・機首の向きは揺れない。
> - 揺れの大きさは、ガンサイトズーム中は小さくする(画角が狭いほど同じ揺れが大きく見えるため)。
> - 設定で切れる(画面の揺れが苦手な人のため)。

**MARKERS.md「狙いの印(戦闘ビュー)」に項を足す:**

> - **ボアサイトマーカー(機首方向)**: 自機の機首方向に常設し、ラベルに残弾・ベルト・砲口初速を
>   添える。散布界が逆光で通常より広がっているあいだは、ラベルにその倍率を「GLARE ×1.6」のように
>   添え、マーカーを警告の色にする。太陽を背にして散布界が締まっているあいだは「SUN ×0.5」と
>   添え、良い状態の色にする。倍率が 0.9〜1.1 の間は何も添えない。

## 決めたこと

| 決めたこと | 根拠 | 覆されたときに変わる手順 |
| --- | --- | --- |
| 遅くするのは `simDt` だけで、ステージに渡す `dt`(実時間)は遅くしない | ステージ0の残り時間は `dt` で減るので、`dt` まで遅くすると撃墜するたびに 0.25 × (1 − 0.2) = 0.2 秒もらえる。30 機落とせば 6 秒、120 秒の 5% の得になり、スコアアタックの公平さを崩す | 手順 2 |
| 撃墜は 0.25 秒・0.2 倍、喪失は 0.6 秒・0.1 倍 | 撃墜は連続で起きるので短く。喪失は1回きりで、何にやられたかを見せる時間を取る | 手順 2 の定数だけ |
| 画面の揺れは自機の被弾にだけ使い、撃墜には使わない | 真空では衝撃が伝わらない。自機の被弾なら「艦体が揺さぶられた」として理屈が立つ | 手順 3 |
| 散布界の表示はボアサイトのラベルと色にとどめ、円などの図形は描かない | 機首の常設表示自体が未確定の案(MARKERS.md「未確定の案」)で、図形を増やすと照準を覆う | 手順 4 |

## 達成目標

1. 開発サーバの `?stage=1` で敵を撃墜した瞬間、デブリと閃光が 0.25 秒ほどゆっくり動いてから
   通常の速さへ戻る。その間もマウスでカメラを回せる。
2. ステージ0の残り時間の減り方が、撃墜の有無で変わらない(撃墜の前後で `残り時間` の表示が
   実時間どおり減る)。
3. 自機喪失の瞬間に 0.6 秒の止めが入り、その後に結果画面が出る。
4. ワープ ×2 以上・一時停止中・建造中に撃墜が起きても止めは入らない。
5. 自機の被弾で画面が揺れ、設定で切ると揺れない。
6. 太陽へ機首を向けるとボアサイトのラベルに `GLARE ×` が出て、背にすると `SUN ×` が出る。
7. `npm run typecheck`・`npm run test:game` が通る。

### 手順 2. 撃墜ストップ

**目的**: 撃墜と喪失の一瞬を止める。ゲーム世界の時間の倍率を、表示側が決めて進行へ渡す。

**変更が必要な箇所**

| ファイル | すること |
| --- | --- |
| `src/game/kill-stop.ts`(新規) | `KillStop` クラス。`observe(events: readonly RunEvent[], simSpeed: number, paused: boolean)` で `enemyDied`(`cause === 'killed'`)と `shipExploded`(自機)を拾い、残り時間と倍率を立てる。`advance(realDt)` で残りを減らす。`worldTimeScale: number` を返す(終わり 30% の区間で等倍へ線形に戻す)。重なりは残りの長い方へ揃える |
| `src/game/game.ts:203` `advance` と `:246` `advanceSimulation` | 引数 `worldTimeScale: number` を足し、`simDt = dt * simSpeed * worldTimeScale` にする。`activeStage.update(dt, …)` へ渡す `dt` は変えない |
| `src/game/game-presentation.ts` | `KillStop` を持ち、`presentProgress()` の中で `game.events.recent` と `simSpeedManager.simSpeed`・`isPaused` を渡して `observe` する。`interpretInput(dt, …)` の先頭で `advance(dt)` する。読み口 `worldTimeScale` を足す |
| `src/run/run.ts:175` `advanceFrame` | `game.advance(dt, …, presentation.worldTimeScale)` に変える |
| `src/game/run-events.ts:90` `shipExploded` | いまは自機と敵の区別が無い。`owner: 'player' \| 'enemy'` を足す |
| `src/game/player/player-effects.ts:32` | `shipExploded` の記録へ `owner: 'player'` を足す |
| `src/game/dynamic/dynamic-entity/enemy-reactions.ts:119` | `shipExploded` の記録へ `owner: 'enemy'` を足す |
| `tests/game/kill-stop.test.ts`(新規) | 撃墜 1 回で 0.25 秒後に倍率 1 へ戻ること、0.1 秒後の2回目で延長されないこと、`simSpeed !== 1` と `paused` では倍率 1 のままのこと |

**達成条件と検証**

- `npm run typecheck`・`npm run test:game` が通る。
- `grep -n "worldTimeScale" src -r` で、`run.ts`・`game.ts`・`game-presentation.ts`・`kill-stop.ts`
  の 4 ファイルだけに出る。
- 達成目標 1〜4 を開発サーバで目で見る。ステージ0では、撃墜の直前と 1 秒後の「残り時間」の差が
  1 秒であることを見る。

## リスクと落とし穴

| リスク | 影響 | 露見する場所 |
| --- | --- | --- |
| ステージへ渡す `dt` まで遅くしてしまう | ステージ0の残り時間が撃墜のたびに延びる | 手順 2(達成目標 2 の目視) |
| 止めをワープ中に効かせる | 自動ワープの残り時間の見積りが狂い、出来事への自動ワープが目標を行き過ぎる | 手順 2(`simSpeed !== 1` のテスト) |
| 止めの倍率を `KillStop` が読む前のフレームで使う(出来事は進行の後に積まれる) | 撃墜の1フレーム後から止まる。60 fps で 17 ms の遅れなので見た目は問題ないが、テストが撃墜と同フレームを期待すると落ちる | 手順 2(テストは「次のフレームから」を期待する) |
| `shipExploded` の記録箇所を `owner` の付け忘れのまま残す | 型検査で落ちる(必須の項目にするので無言では壊れない)。任意の項目にすると、敵の撃破でも喪失用の 0.6 秒が入る | 手順 2(`owner` は必須にする) |
| 揺れを照準の計算まで掛ける | 揺れのたびに LEAD マーカーと弾道がぶれ、当たらなくなる | 手順 3(✛ のずれを目視) |
| ボアサイトのラベル行が増えて、近接時のまとめ表示や画面端の矢印と重なる | ラベルが読めなくなる | 手順 4(太陽を画面端に置いた状態で目視) |
| 別作業で実装中の `flash-presenter.ts` と競合する | マージで衝突する | 手順 2(`KillStop` は `flash-presenter.ts` に触らずに置く) |
