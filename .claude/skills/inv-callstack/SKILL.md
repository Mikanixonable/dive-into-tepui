# 逆向きの呼び出し依存木の調査

呼び出し関係の正本は **コードだけ**。この手順は、必要になった時点でコードから読み取って提示する
ためのもので、結果は既定では会話にだけ出す。

**書き始める前に `.claude/skills/CODE-SNAPSHOT.md` を読む。** 図の形(罫線・注記の3枠・引数の
書き方)と、文書へ残すときの規則はそこが正本で、`/callstack` と共通である。

## 1. まず調査範囲をユーザーに問う

**全体の依存木を出力しない。** 書き始める前に次の2つを確定させる:

- **中心** — どの関数/メソッド/モジュールを木の根に置くか。
- **深さ** — 呼び出し元を何段まで遡るか。per-frame の入口まで遡り切るのか、直接の呼び出し元
  だけでよいのか。

ユーザーの指示から一意に決まらないなら、選択肢を示して問う。既定値を勝手に置かない。

## 2. 呼び出し元を集める

識別子で走査し、**走査した範囲を出力に明記する。** `src/` だけを見て「参照 0 件」と書かない —
`tests/` は `src/physics/` を直接コンパイルしており、そこからしか呼ばれない API がある。

拾ったものを仕分ける。木に載せるのは呼び出しだけ:

- **呼び出し** — 木に載せる。
- **再輸出・import だけ・型としての参照** — 木に載せない。数が意味を持つなら図の外へ。
- **間接呼び出し** — コールバック・インターフェース越しのディスパッチは識別子の走査に出ない。
  中心が渡される場所と実装が差し込まれる場所を探して木に載せ、間接であることを書く。

呼び出し元が広範に散っていて見当が付かないなら、走査だけをサブエージェントへ配る(`/delegate`)。
**仕分けと木の組み立ては配らない** — 判断そのものが仕事になる。

## 3. 各ノードで確かめること

木に載せる1行ごとに、次を押さえてから書く。埋まらないものは図に書かない(推測を書かない):

- **どのファイル/クラスの何という関数か。**
- **走る条件と頻度** — per-frame か、エッジ(入力・生成・破棄)か。`simSpeed` や `phase` で
  回数が 0 回にも n 回にもなるなら、その条件。
- **そのノードが中心に何をさせているか** — 呼び出し元ごとに渡すものや期待する答えが違うなら、
  それが結論になる。責務が中心の外へ漏れている印である。

## 4. 出力する

`CODE-SNAPSHOT.md` 1章の形で書く。根は中心に置いた関数(完全な署名)、子は呼び出し元。
深さは1章で確定させた範囲で打ち切り、網羅性より範囲内の正確さを優先する。

文書へ残すのは**保存先を指定されたときだけ**で、そのときは commit hash を明記する
(`CODE-SNAPSHOT.md` 2章)。

## 5. 気づいたことは報告する

遡る過程で見つけた不整合(同じ判断を呼び出し元ごとに別々に持っている、呼ばれていない API、
同じ対象を2度通る経路)は、勝手に直さず報告する。修正するかはユーザーが決める。
