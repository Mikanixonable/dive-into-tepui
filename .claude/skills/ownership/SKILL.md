# 保持関係・状態の正本の調査

所有関係の正本は **コードだけ**。この手順は、必要になった時点でコードから読み取って提示する
ためのもので、結果を文書として残さない(残せば次の変更で腐る)。

## 1. まず調査範囲をユーザーに問う

**全体の保持木を出力しない。** 知りたいのはたいてい特定のクラスの周辺 —「この状態は誰のものか」
「このインスタンスは誰が作ったか」— であって、根から葉まで並べたものではない。書き始める前に
次の2つを確定させる:

- **対象** — どのクラス/モジュール/状態を中心に見るか。
- **深さ** — 保持木を上(誰が持っているか)へ何段、下(何を持っているか)へ何段辿るか。
  参照共有・キャッシュまで含めるか。

ユーザーの指示から一意に決まらないなら、選択肢を示して問う。既定値を勝手に置かない。

## 2. 「所有」と「参照」を分けて読む

- **所有** = そこで `new` され、寿命を握っている(`dispose` を呼ぶ責任がある)。
- **参照共有** = 他所で `new` されたものを受け取って保持しているだけ。所有権は移らない。

コンストラクタ引数で受け取っているだけのものを所有として数えない。両者を混ぜると
「誰が壊すのか」が読めなくなる。

## 3. 「正本」と「導出値」を分けて読む

- **正本(source of truth)** — その値を決めている唯一の場所。
- **導出値・メモ化・キャッシュ** — 正本から計算できるもの。所有関係としては扱わず、区別して
  示し、**何を契機に無効化されるか**を併記する。

## 4. 出力の形

指定された範囲に応じて、必要なものだけを示す。全部を毎回出さない。

- **保持木** — `new` した側を親とするインデント木。
- **参照共有** — 「所有者 / 参照している側」の対応表。
- **状態の正本** — 「状態 / 正本の所有者 / 誰が書き換えるか」の表。独立した責務が同時に
  切り替わっているだけの組み合わせは、分かれていることに意味があるので節を分けて説明する。
- **正本でないもの** — 導出値・キャッシュと、その無効化の契機。

## 5. 気づいたことは報告する

辿る過程で見つけた不整合(正本の二重化、無効化されないキャッシュ、所有者不明のインスタンス、
`dispose` されない資源)は、勝手に直さず報告する。修正するかはユーザーが決める。
