# サブエージェントへ配る

**エージェントは cold start で、このリポジトリの文脈を何も持たない。渡さなかった規約・仕様・判断は、
無いものとして働く。** 配った結果がどうなるかは、ほぼ渡す指示で決まる。

配るべきかどうかの判断は CLAUDE.md「サブエージェントは自分から使う」。ここにあるのは配り方だけ。

## 1. 範囲を分ける

- **ファイル群を重複なく分ける。** 同じファイルを複数のエージェントへ配らない — 競合する。
- **依存のある作業を並行させない。** 先に来るものを終え、その結果を確認してから次を配る。
- 重複なく分けられないなら、**配らずに自分でやる。**

## 2. 渡す指示に必ず含める

- **目的と、受け取りたい成果物の形** — 結論だけか、差分か。
- **担当範囲** — 対象のファイルを列挙し、**その外側を1文字も変えないこと。**
- **読ませるもの** — 編集させるなら `DEVELOP/CODING-RULE.md` を読んでから書くこと。該当する
  `DEVELOP/SPEC/` のファイルと、通すべき SKILL(`/ui-design` など)も名指しする。
- **検証** — 担当分について `npm run typecheck`(`src/physics/` を触るなら `npm run test:physics` も)を
  自分で通してから報告すること。
- **報告に含めるもの** — 触ったファイル、判断した箇所、直さずに残したもの。

## 3. 書かせないもの

- **`DEVELOP/SPEC/` と `memos/`。** 前者はユーザーと合意して自分で書く文書、後者は人間が管理して
  いる領域。
- **判断そのもの。** 仕様の分岐・共通化の可否・ユーザーへ問うべきことに行き当たったら、**その場で
  決めさせず報告させる。** cold start のエージェントは、判断に必要な文脈を持っていない。

## 4. 受け取ったら、配った側がレビューする

**エージェントの報告は成果物ではない。差分が成果物。** 報告を読んで終わりにしない。

1. **差分を自分で読む。** 報告と実際の差分は食い違う。`git diff` で全部見る。
2. **`DEVELOP/CODING-RULE.md` を自分で当てる。** 文脈を持たないエージェントは規約違反を持ち込む —
   重複実装、旧実装・旧名の残骸、要求していないデバッグコードや過剰実装、コメント規約からの逸脱。
3. **担当範囲の外を触っていないか確認する。**
4. **検証を自分でもう一度通す。** エージェントの「通りました」を根拠にしない。
5. **直すか、差し戻すか、自分で書き直すかを決める。** 規約に通らないものをそのまま重ねない。

**ユーザーへ伝えるのは、エージェントの報告ではなく、自分で確認した事実。** 自分で見ていないことを
成果として報告しない。
