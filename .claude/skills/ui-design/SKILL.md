# UI/デザイン変更の手順

**規約の全文はここに書かない。** 正本は2つ — **UI がどう振舞い、どう見えるべきか**は
`DEVELOP/SPEC/UI-DESIGN.md`、**それをコードでどう書くか**は `DEVELOP/CODING-RULE.md` 1.12。
このファイルは「どう手順を踏むか」と「よくある誤り」だけを持つ。

## 1. 該当する節を読む

見た目・配置・操作に関わる変更(パネルの追加、ボタンの追加、色/寸法の変更、開閉挙動の変更、
タッチ対応)の前に必ず通す。触る箇所に対応する節を確認する:

| やろうとしていること | 見る節 |
| --- | --- |
| 色・文字サイズ・角丸・余白・トランジションを決める | UI-DESIGN §2 トークン |
| 押せる/切り替えられる/入力できる要素を足す | UI-DESIGN §3 ウィジェット |
| モーダル・ポップアップ・ウィンドウを開く/閉じる | UI-DESIGN §4 オーバーレイ |
| パネルをどこに置くか決める、レスポンシブ対応する | UI-DESIGN §5 レイアウト |
| タッチでの到達性を確保する | UI-DESIGN §6 タッチ |
| 既存のパネルに手を入れる | UI-DESIGN §8 HUD の画面・パネル一覧 |
| CSS を書く、メディアクエリを足す、値をコードから読む | CODING-RULE 1.12 CSS の書き方 |

**画面から見える挙動を変えるなら、それは仕様変更。** `/modify-feature` の手順で
`DEVELOP/SPEC/UI-DESIGN.md`(および影響する他の SPEC/ ファイル)を先に更新する。
見た目を変えずに実装だけ直すなら、SPEC/ は更新しない。

## 2. 既存のウィジェット/トークンに同じものが無いか探す

新しい対話要素・新しい色・新しい寸法を書き始める前に:

1. 既存のウィジェット10種(ボタン/トグルスイッチ/セグメントコントロール/ホールドボタン/
   閉じるボタン/値入力/メーター/タブバー/スライダー/開閉トグル)に、やりたいことを
   果たせるものが無いか確認する。無ければ **追加実装せず既存を呼ぶ** か、最小限の引数拡張で
   足りないか検討する。
2. 既存のトークン(色・文字サイズ・角丸・余白・トランジション段)に要る値が無いか確認する。
   無い値が本当に要るなら、それを汎用値としてトークンへ上げるか、その場限りのローカル定数に
   留めるかを UI-DESIGN §2 の基準で見極める。
3. モーダル/ポップアップ/ウィンドウを開くなら、コンテキストメニュー(使い捨て)とプロパティ
   ウィンドウ(継続観察)のどちらの役割かを先に決める — 迷ったら「右クリックした対象に
   プロパティがあるか」で判断する(UI-DESIGN §4)。

## 3. 置き場4種のどれに属するかを決めてから組む

新しいパネル/表示を作る前に、レール/常設計器/中央モーダル/画面固定バッジのどれに属するかを
決める(UI-DESIGN §5)。決まらないまま絶対座標を書き始めない — 迷ったら「動かせる/畳める/
レイアウトに参加すべきか」で判断し、参加すべきならレールか常設計器へ、一点固定でよいものだけ
画面固定バッジにする。

## 4. タッチでの到達性を確認する

- 新しい操作がキーボード/マウス専用になっていないか(タップ・長押し・ドラッグのどれかで
  到達できるか)を確認する。到達できないなら、タップ可能な代替 UI を足す。
- タップ領域の確保と、画面投影してから距離でヒット判定するピック処理の半径は、どちらも既存の
  仕組みを経由する(UI-DESIGN §6)。固定値を新しく書き起こさない。

## よくある誤り

いずれも既存実装を素通りして書き始めたときに出る。該当したら、正本の節へ戻って直す。

| 誤り | 戻る先 |
| --- | --- |
| 色/寸法を CSS にリテラルで書く。逆に、JS が組み立てるインラインスタイルまでカスタムプロパティ経由にしようとする | CODING-RULE 1.12 |
| `vh` を単独で書く | CODING-RULE 1.12 |
| ブレークポイントの閾値を参照側へ書き写す。幅クラスを起動時にキャッシュする | CODING-RULE 1.12 |
| オーバーレイの管理へ登録せず、自分で `document`/`window` に `keydown`/`pointerdown` を張る | UI-DESIGN §4・§7-2 |
| コンテキストメニューとプロパティウィンドウを、役割でなく既存コードの見た目で選ぶ | UI-DESIGN §4 |
| 新しい状態クラス名を作る(点灯/押下中/無効で表せないか疑わない) | UI-DESIGN §3・§7-4 |
| 2値の ON/OFF にセグメントコントロールを使う | UI-DESIGN §3 |
| 入力欄の `keydown` を止め忘れる | UI-DESIGN §3 |

## 5. 完了判定

- `DEVELOP/SPEC/UI-DESIGN.md` §7「やってはいけないことの一覧」と `DEVELOP/CODING-RULE.md` 1.12 を
  自分の変更範囲に当て、新しい違反を増やしていないか確認する(既存の違反をゼロにすることまでは
  求めない — それは別の変更セットで直すべき既存の gap であり、自分の変更が原因でないかだけを
  確かめる)。
- 加えて `npm run typecheck`。触っていない層の回帰テストは走らせない。
