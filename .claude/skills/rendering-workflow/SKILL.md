# 描画の作業手順

**何をどう見せるべきかは `DEVELOP/SPEC/RENDERING.md`(UI は `SPEC/UI-DESIGN.md`)が正本。**
ここに置くのは、それをこの基盤の上で書くときに踏む地雷と、目で確かめるときの手順だけ。

## 1. 描画基盤(WebGPU 上の three.js)の制約

- ループ状に閉じた線や、点のサイズ指定は使えない。線は端点を重ねて手動で閉じた普通の折れ線として
  描き、点のような表示は三角形ベースのスプライトで代用する。
- 加算合成のマテリアルは透過を明示しないと効かない。
- **頂点データやインスタンスの変換は、確保済みのバッファへ直接書き込んで更新する。** ジオメトリや
  その属性そのものを差し替えても、描画には反映されず古い内容のまま描かれ続ける
  — 例外も警告も出ないので、「変えたのに絵が変わらない」ときは真っ先にここを疑う。
- **特定の GPU 側の処理に失敗すると、例外は出ないまま画面がまるごと黒くなる**(そのフレームの
  描画命令全体が無効になるため)。原因の手がかりはブラウザ側のログにしか出ない。
- 視錐台の外を描画しない仕組み(カリング)は基本的に有効なまま使う。無効化してよいのは、カメラに
  追従して常に画面内に留まる球殻(星・天球グリッド)、頂点バッファを直接書き換えていて包含球が
  自動更新されない線(軌道線・軌跡線)、インスタンスが共有ジオメトリの包含球よりはるかに広い
  範囲へ散らばる描画(点群など)に限る。

## 2. 目で確かめる

| 見たいもの | 使うもの |
| --- | --- |
| 描画単体の比較・調整 | `npm run render-lab`(http://localhost:8082) |
| 画像として残す・差分を見る | `npm run render-lab:shot`(`.render-lab/shots/`) |
| ゲームの中での見え方 | `npm run dev` |
| 実行時例外の有無まで込みで | `/verify` |

**`npm run render-lab:shot` は実写テクスチャの読み込みを待たない。** 撮影は読み込み完了を待たずに
フレームを読み出すため、実写テクスチャを貼った天体は模様のない単色として写る。**単色で写ることは
壊れた印ではない。** テクスチャの内容・経度の合わせ方をここで目視検証することはできない
(ジオメトリの大きさ・位置・陰影・レイヤ分けは検証できる)。貼り方(経度原点・UV)を確かめたいなら、
描画ではなくジオメトリの `uv` と `position` を直接突き合わせる。

ヘッドレスでの撮影には GPU 関連の特別な起動オプションが必要で、不安定なため複数回の試行が要る
ことがある。失敗が続くときは、環境ではなく描画そのものが黒くなっていないかを 1 節で切り分ける。

## 3. 書き終えたら

- `npm run typecheck`。
- **見た目を変えたなら、変えた対象が写る画像を1枚は撮る。** 「動いたはず」で閉じない。
- **見え方の仕様そのものを変えたなら、コードより先に `DEVELOP/SPEC/RENDERING.md` を直す**
  (`/modify-feature`)。実装に合わせて後から書き足さない。
