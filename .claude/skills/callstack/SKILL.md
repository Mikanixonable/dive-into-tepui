# 呼び出し依存木の調査

呼び出し順の正本は **コードだけ**。この手順は、必要になった時点でコードから読み取って提示する
ためのもので、結果を文書として残さない(残せば次の変更で腐る)。

## 1. まず調査範囲をユーザーに問う

**全体の依存木を出力しない。** 数百行の木を渡されても読めないし、知りたいのはたいてい特定の
モジュールの周辺だけである。書き始める前に、次の2つを確定させる:

- **対象** — どのモジュール/クラス/関数を中心に見るか。
- **深さ** — その中心から何段まで辿るか。呼び出し元(上流)と呼び出し先(下流)のどちらを、
  どこまで見たいか。

ユーザーの指示から一意に決まらないなら、選択肢を示して問う。既定値を勝手に置かない。

## 2. 起点を決めて辿る

per-frame の入口は `src/main.ts` の rAF ループ → `src/game/game.ts` の `update` / `sync` /
`render` の3相。指定された対象がこの経路のどこに現れるかを探し、そこから指定された深さだけ辿る。

- 対象が per-frame 経路の外(コンストラクタ、DOM イベント、入力エッジ)にあるなら、その旨と
  実際の起点を報告する。
- 典型的な関数名は `update*` / `sync*` だが、そうでないものもある(`behave` / `checkLoss` /
  `cleanup` / `resolve` / `advance` / `step*`)。名前ではなく呼び出し関係で辿る。

## 3. 出力の形

インデントした木で示す。`main/foo` が `game.bar` と `game.bra` をこの順で呼び、`game.bar` が
`game.brabra` を呼ぶなら:

```
- main/foo()
  - game.bar()
    - game.brabra()
  - game.bra()
```

- **引数は省略する。** 追いたいのは呼び出し順であって、データの流れではない。
- **値を計算して返すだけの副作用のない関数は除外する。** 呼び出し順に影響しない。
- `overviewMode` / `phase` / `paused` などで per-frame の呼び出し回数が 0 回にも 1 回にもなる
  分岐は、`// 条件` として付記する。
- 多少簡略化してよい。網羅性より、指定された範囲が正確であることを優先する。

## 4. 気づいたことは報告する

辿る過程で見つけた不整合(呼ばれない関数、`update` から `sync` を呼んでいる、フェーズの
取り違え)は、勝手に直さず報告する。修正するかはユーザーが決める。
