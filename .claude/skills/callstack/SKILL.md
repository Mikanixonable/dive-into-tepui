# 呼び出し依存木の調査

呼び出し順の正本は **コードだけ**。この手順は、必要になった時点でコードから読み取って提示する
ためのもので、結果は既定では会話にだけ出す。

**書き始める前に `.claude/skills/CODE-SNAPSHOT.md` を読む。** 図の形(罫線・注記の3枠・引数の
書き方)と、文書へ残すときの規則はそこが正本で、`/inv-callstack` と共通である。

## 1. まず調査範囲をユーザーに問う

**全体の依存木を出力しない。** 数百行の木を渡されても読めないし、知りたいのはたいてい特定の
モジュールの周辺だけである。書き始める前に次の2つを確定させる:

- **中心** — どの関数/メソッド/モジュールを木の根に置くか。per-frame の全体像が要るなら根は
  `game.update` などの相の入口になるが、それを勝手に既定にしない。
- **深さ** — 呼び出し先を何段まで辿るか。

ユーザーの指示から一意に決まらないなら、選択肢を示して問う。既定値を勝手に置かない。
**中心へ至る経路(誰がそれを呼ぶか)が知りたいのなら、辿る向きが逆なので `/inv-callstack`。**

## 2. 呼び出し先を辿る

per-frame の入口は `src/main.ts` の rAF ループ → `src/game/game.ts` の `update` / `sync` /
`render` の3相。中心がこの経路のどこに現れるかを確かめ、そこから指定された深さだけ辿る。

- 中心が per-frame 経路の外(コンストラクタ、DOM イベント、入力エッジ)にあるなら、その旨と
  実際の起点を報告する。
- 典型的な関数名は `update*` / `sync*` だが、そうでないものもある(`behave` / `checkLoss` /
  `cleanup` / `resolve` / `advance` / `step*`)。名前ではなく呼び出し関係で辿る。
- **値を計算して返すだけの副作用のない関数は木に載せない。** 呼び出し順に影響しない。

## 3. 各ノードで確かめること

木に載せる1行ごとに、次を押さえてから書く。埋まらないものは図に書かない(推測を書かない):

- **どのファイル/クラスの何という関数か。**
- **走る条件と頻度** — 毎フレーム1回か、毎 substep か、`view` / `phase` / `paused` /
  `simSpeed` で 0 回にも n 回にもなるのか。
- **兄弟との順序** — 同じ親から呼ばれるものは、**コード上の呼び出し順どおりに並べる。**
  順方向の木で兄弟の並びは情報であり、並べ替えてはいけない。

## 4. 出力する

`CODE-SNAPSHOT.md` 1章の形で書く。根は中心に置いた関数(完全な署名)、子は呼び出し先。
深さは1章で確定させた範囲で打ち切り、網羅性より範囲内の正確さを優先する。

文書へ残すのは**保存先を指定されたときだけ**で、そのときは commit hash を明記する
(`CODE-SNAPSHOT.md` 2章)。

## 5. 気づいたことは報告する

辿る過程で見つけた不整合(呼ばれない関数、`update` から `sync` を呼んでいる、フェーズの
取り違え)は、勝手に直さず報告する。修正するかはユーザーが決める。
